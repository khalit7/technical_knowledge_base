# Operating instructions for agent sessions in this repo

This repository is the home of Khalid's Technical knowledge base. **It is the source of truth.** Each page is one interactive HTML file built here and read on the public site built from `main` by GitHub Actions: https://khalit7.github.io/technical_knowledge_base/ (Khalid reads it; only he can push). Notion keeps the same tree as an index: each Notion page is one link to its site page, plus its video and child pages. Nothing is copied from Notion into this repo; Notion holds no knowledge.

## Layout

| Folder | What it is |
|---|---|
| `technical_knowledge_base/` | The knowledge base, laid out exactly like the Notion tree: one folder per Notion heading (`models_and_training/`, ...), one folder per page inside it, a child page's folder inside its parent's. Names are snake_case slugs of the Notion titles; each folder's README and `pages.json` give the exact title and Notion id. |
| `technical_knowledge_base/pages.json` | Manifest of every page: path, title, Notion id, parent or section, status (`html_only` for every page; `not_migrated` only on the Papers and Tech news container entries, which have no page of their own), video, optional `aliases`, and for every topic page `prereqs`: the ids of its strict prerequisites, which drive the learning map on the site's landing page. |
| `technical_knowledge_base/OWNERS.md` | Which page owns each concept; every other page links to the owner instead of re-teaching it. |
| `audit/` | `open_items.md`: polish leftovers still open from the finished layout rollout (phone-only items dropped 2026-11-22: Khalid reads on a laptop and a tablet). |
| `.github/workflows/site.yml` | Builds and deploys the reading site on every push to main. |
| `html_utils/` | Runtime only: `checkpage.sh`, `tabshot.mjs`, `clipcheck.mjs`, `tex2mathml.mjs`, `sync_status.py` (what is left to publish), `audit_pages.mjs`/`.py` (what each page gives a reader: reading minutes, visuals), `ledger.py` (condense without losing knowledge), `check_times.py` (reading times quoted for other pages; `--fix`), `whats_new.py` (the landing page's What's new block and the Tech news and Papers index pages), `learning_map.py` (checks `prereqs` and lays out the learning map; `check` before every push) and `check_learning_map.mjs` (the map in a browser, after changing the map's code), `verify_layout.mjs` (a page against the layout rules: splits, stages, step lists, autoplay), `build_site.py` (the public reading site, see `sync-kb-github/site.md`) with `app_icon.svg` and its render `app_icon.png` (the site's icon as an app), `kb_buddy.js`, `kb_buddy_loader.js` and `apply_buddy.py` (the AI buddy, below), `buddy_test.mjs` (the buddy end to end in Chromium and in WebKit, Safari's engine, with Claude and GitHub faked; run before pushing any buddy change), `kb_changes.py` (the page changes Khalid kept in the AI buddy, read from `khalit7/kb-notes` as a bundle to fold into the pages; each folded change gets `data-kb-edit="<id>"` on its element; run only when he asks), `cloud_setup.sh` (sets up a cloud sandbox for the weekly routine). The page look lives in the template's `01_head.html`; built pages carry their own copy. How pages are built lives in the `explainer-page` skill. |
| `.claude/skills/` | Only the four skills below. Real folders, no symlinks. The third-party HyperFrames skills the video workflow uses are vendored inside `explainer-video/vendor/`; unused ones were removed (reinstall with `npx hyperframes skills update <name>` then `explainer-video/scripts/vendor_skills.sh <name>`). Everything learned about how Khalid wants pages built (reader, page kinds, animation types, local runs, resource safety, briefs, lessons) lives in `explainer-page/`; narration scripts and voice envs in `explainer-video/narration/`. |

A page folder holds `index.html` (the whole page, built), `README.md`, `src/` (`build.sh`, `parts/`, `README.md`, `viz_ideas.md`, `ledger.json`, data scripts, `inputs/`), `img/` if it uses images and, if it has one, `video/` (the HyperFrames project; renders are not committed).

## Skills (the only procedures that touch the knowledge base from here)
- `explainer-page`: teach a subject as an interactive page: a new topic (root plus children) from a few lines of what Khalid wants to learn, a child page, a paper, a tech-news issue, or a rebuild or migration.
- `explainer-video`: a narrated video of a page (HyperFrames + Chatterbox Turbo).
- `sync-kb-github`: publish: check, commit and push (the site deploys from main); keep each Notion page a link page.
- `update-kb`: the periodic update. Reads the last-updated date from Notion (Source freshness, row "Technical KB"), researches everything since, writes that window's tech-news issue, integrates durable knowledge into the owning pages, adds papers, publishes, and moves the date forward.

No knowledge-base skills live in Notion any more (deleted 2026-10-19); Notion's Instructions page and the weekly Monday routine point here.

## The AI buddy
Every page carries a small loader (written into its head part by `apply_buddy.py`) that loads the shared `kb_buddy.js`, published at the site root by `build_site.py`, on every page; editing `kb_buddy.js` needs no page rebuild. Its toolbar is the only thing a page gets (the landing page gets it too, from `build_site.py`; it docks at the top or the bottom, and starts small, with Ask and sync, until + makes it full, which each device remembers): on a device without a Claude key or a sync key (a GitHub token), the toolbar's Claude and sync buttons say "Claude key" and "Sync key" ("Fix Claude key", "Fix sync key" when the key was refused) and open that field in Settings. Without a Claude key there is no AI on a page at all: a selection is a plain one, conversations (their dots, notes, highlights and the Conversations button), Tom Riddle's diary and Claude's notebook replies are hidden, and only the tools that do not use Claude stay. The buddy also keeps where Khalid is reading (page, tab, place; the synced setting `kb.last`), so the landing page's Continue reading opens that place on any device. It gives pens, highlights and marks with threaded answers citing the page's sentences (a conversation on the page looks like a chat, as on claude.ai: Khalid's messages and drawings in tinted bubbles on the right, Claude's replies and sketches in the page's own font; only the notebook and Tom Riddle's diary are handwritten), Ask on the toolbar (a question about the page, not about one passage: a new conversation each time, in a card under the toolbar that can be dragged anywhere and stays open beside a note on a passage, listed in Conversations; on the landing page, a question about the whole knowledge base answered from its pages), a notebook, knowledge-base search, and on request a rewritten block or an added visual. Claude answers only when Khalid taps Send (new marks or ink) or presses Enter in a typed box; only Tom Riddle's diary answers by itself. Each conversation carries only its own thread (the notebook remembers its last 12 exchanges). x closes a conversation (a passage's folds to its numbered dot) and, in full screen, goes back to where it was opened; Delete is in full screen; the chips under an answer show while its follow-up box has the cursor (not while an answer is being written, unless he types), and the selection's Ask box shows its question box and chips (the Sketch and paragraph rows once it has the cursor). Where there is no margin beside the text, a highlight's conversation has no dot: tapping the highlight opens it. Changes made just before a page is left are sent by the next page's sync. The reader's key stays in the browser; notes sync to the private repo `khalit7/kb-notes`, which no workflow reads except `kb_changes.py` when Khalid asks. Build rules for it: `explainer-page/build/scaffold.md`.

Khalid reads on a laptop (Chrome) and an iPad, where he opens the site from the Home Screen (the site build adds a manifest and an icon so it installs as an app): Safari clears a site's saved data (the key, the token, notes not yet synced) after about a week without a visit, except for a site opened from the Home Screen. A buddy change is checked with `node html_utils/buddy_test.mjs` (both engines must pass: the iPad runs WebKit, and Chrome alone has missed its bugs), then on the live site in Chrome with his real key.

## Khalid's preferences
- **Ask, don't assume**, when a decision is his.
- **The goal of every page: understand the subject deeply in the least time** (`explainer-page/teaching/teaching-contract.md`, agreed 2026-10-23). A visual beside every core idea, chosen by what the concept is (static diagram, stepper, animation only when the change is the point, before/after like the DeepSeek MLA explainer, a 3D stage only when depth carries information and speeds up or firms up understanding, real image); nothing decorative. **Split layout everywhere** (2026-11-06): a section with a visual is text on the left, the visual on the right; a section without one is full width; 2D by default, 3D only when it is useful, never because it looks good (2026-11-19); animations are explained step by step on the left and play by themselves once in view, stopping when the reader takes a control. Length is judged per page and condensing never loses important information (knowledge ledger). He reads to understand, not to memorise: no quizzes or flashcards.
- **Looks matter** (2026-10-29): a page that looks visually good is easier to read. The template theme and the "How a visual should look" rules carry it; real images are never forced, but are always included when they show something new.
- Root `Topic: *` pages are short comparisons plus definitions; details live on child pages; one page owns each concept and the others link to it.
- Do not launch a multi-agent Workflow without his explicit opt-in; plain subagents are fine, about four at a time.

## Writing
No em-dashes anywhere: prose, HTML, captions, commit messages. Commas, colons, semicolons, parentheses; `--` for ranges.

## Setup on a new machine
`uv sync` (page data scripts), `cd html_utils && NPM_CONFIG_USERCONFIG= npm ci` (page checks), `cd html_utils && npx playwright install chromium webkit` (the buddy test's browsers; WebKit's system libraries: `html_utils/README.md`), and for videos `.claude/skills/explainer-video/narration/install.md`.

## Git
`git pull` first, always. Commit after a meaningful unit of work; push to main. Never commit MP4s, PDFs or files over about 5 MB.
