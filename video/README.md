# video

Everything needed to turn a knowledge base page into a narrated explainer.

The written page in Notion stays canonical. A video is a derived representation
of it, and it may not claim anything the page does not.

## What is here

| Path | What it is |
|---|---|
| `common/style.py` | the visual system: palette with fixed colour semantics, type scale, shared shapes |
| `common/scene.py` | the base scene: narration-driven pacing, and the only three transitions allowed |
| `scripts/<episode>.py` | the narration, as a dict of beat to speaker turns |
| `scenes/<episode>.py` | the animation, keyed to the same beats |
| `tts/render.py` | VibeVoice, one WAV per beat plus `durations.json` |
| `tts/bakeoff.py` | the same thirty seconds through each candidate voice, for choosing by ear |
| `build.py` | voice, then animation, then the encode Notion will accept |
| `tools/check_references.py` | every line that points at the screen, and the frame it points at |
| `voices/` | reference clips, one per speaker (not in git) |
| `out/` | everything generated (not in git) |

## Build an episode

```bash
uv sync --group tts --group video     # once

uv run video/build.py tech_news_2026_09_07_short --skip-tts --quality l  # silent preview
uv run video/build.py tech_news_2026_09_07_short                         # the real thing
```

Both halves are uv dependency groups, so there is nothing to activate and
nothing to point at. `build.py` requests both on every call, because asking for
one at a time makes uv uninstall the other.

Without the voice render the scene estimates each beat from its word count, so
a silent preview is right about layout and roughly right about pacing. Publish
only from a real render.

## Writing an episode

The craft rules live in the Notion skill **Produce technical explainer video**,
which is canonical. The short version, because these are the parts the code
depends on:

- One narrator (A) carries the episode. A second voice (B) plays the listener,
  three to five times in eight minutes, never as a co-host.
- Beats are keyed identically in the script and the scene. The scene never
  guesses how long a line takes; it asks.
- Numbers are spelled the way they should be said. Text to speech reads
  "3.22x" and "Z.ai" badly.
- There is no `wipe()`. Beats change by morph, by parking the old object at the
  edge, or by dimming it. `common/scene.py` deliberately offers nothing else.
- Every figure traces to the canonical page. Nothing is invented for shape.

## Voice

`vibevoice/VibeVoice-7B-hf`, the Transformers-native conversion of Microsoft
VibeVoice. It is built for expressive long-form multi-speaker dialogue, which is
exactly this job, and `transformers.models.vibevoice` is present in transformers
5.17.0, so no reconstruction of the withdrawn upstream inference code is needed.

Notes that cost time to learn:

- The original `microsoft/VibeVoice-1.5B` repo does **not** load through
  `AutoProcessor`. Its `config.json` predates the Transformers port and still
  says `decoder_config` where the implementation expects `text_config`, so it
  fails validation with a hidden-size mismatch. Use the `-hf` repo.
- Reference clips come from the model's own published sample voices. Do not
  clone a real person's voice without Khalid's explicit say-so.
- The model card says an audible "generated by AI" disclaimer and an inaudible
  watermark are applied. Check the first render for the audible one: if it is
  present in the Transformers path it has to be handled before publishing.
- Chatterbox (Resemble AI) is the fallback if VibeVoice disappoints in the ear.
  Install it with `--no-deps` against the cu128 torch: `chatterbox-tts` 0.1.7
  pins `torch==2.6.0`, which predates Blackwell support, and installing that
  pin gives a working import with a GPU that never engages.

Decide between voices by listening to `tts/bakeoff.py` output, not by reading
benchmark tables.

## Delivering to Notion

`build.py` encodes to the profile that fits: 30 fps, constant rate factor 28,
mono audio at 48 kbit/s, which put a four and a half minute 1080p episode at
4.52 MiB against the workspace's 5 MiB cap. Thirty frames a second is enough
because the animation is fades, writes and camera moves rather than motion.

Upload with the content type `application/mp4`, which is what the `.mp4`
extension implies. `video/mp4` is rejected. The block renders as a player when
written as `<video src="file-upload://ID">Caption</video>`.

## This machine

- cairo, pango, ffmpeg and a TeX distribution are installed system-wide; the
  apt line is at the bottom of `pyproject.toml`.
- `Tex` and `MathTex` now work, but prefer Pango `Text` and `Paragraph` unless
  the content is genuinely an equation.
- Two RTX 5090s, 32 GB each, compute capability 12.0, driver 590.48.01. Use the
  CUDA 12.8 torch wheels.
- The voice render is the only GPU stage. Everything else is CPU, so a silent
  preview can be built while the GPUs are busy.
