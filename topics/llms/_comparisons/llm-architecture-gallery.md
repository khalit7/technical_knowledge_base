# LLM Architecture Gallery (rasbt) and the architectural deltas that matter

### The resource

- **Gallery**: [sebastianraschka.com/llm-architecture-gallery](https://sebastianraschka.com/llm-architecture-gallery/) (reference site, ~45 min for a first pass over the models you care about), metadata repo at [github.com/rasbt/llm-architecture-gallery](https://github.com/rasbt/llm-architecture-gallery) (repo, ~15 min): a `models.yml` of per-model fact sheets, Apache 2.0.
- **Companion article**: [The Big LLM Architecture Comparison](https://magazine.sebastianraschka.com/p/the-big-llm-architecture-comparison) (1h), the written walkthrough of the same material.
A side-by-side reference of 70+ open(-ish) model architectures, a diagram per model plus a fact sheet: total and active parameters, decoder type (dense, sparse MoE, or dense/sparse *hybrid*), attention mechanism and layer mix, context length, **KV-cache bytes per token** (its most useful headline number), positional encoding, licence, and links to configs and tech reports. Coverage runs from DeepSeek V3/V3.2/V4/V4.1, Kimi K2-K3, GLM-4.5-5, Qwen3-3.8, MiniMax M2-M3, Mistral Large 3, Llama 4, gpt-oss and Gemma 3/4, down to OLMo, Phi-4, SmolLM3, and exotic entries (Nemotron 3 Nano, Kimi Linear, INTELLECT-3).

Read the KV-cache figure first: it is `2 times layers times kv_heads times head_dim times bytes_per_element`, folding attention variant, layer count and storage precision into one number you multiply by target context length and concurrency to get the memory your serving fleet actually needs. Two models with the same parameter count can differ on it by an order of magnitude, and that difference, not the parameter count, decides whether long context is affordable.

Make it the first stop whenever a new open model drops: the diagram plus the KV-cache and MoE numbers tell you 80% of what changed.

### Key architectural deltas across modern open models

The GPT-2-style decoder transformer is still recognisably the skeleton. Almost every change since is about memory and compute efficiency rather than modelling power, and they concentrate in four places: how attention is computed and cached, how the FFN is made sparse, where normalisation sits, and how position is encoded. None is free, so each below is stated as a change with what it buys and what it costs.

#### 1. Attention

- **MHA to GQA (grouped-query attention).** Query heads are divided into groups, each sharing one key/value head, so distinct K/V projections fall from the head count to the group count. The KV cache is sized by KV heads, so 8-way grouping cuts the cache and per-token memory traffic by 8, and decode is memory-bandwidth-bound, making that close to a linear speedup at long context. It costs expressivity: query heads in a group can no longer attend along independent key subspaces, a small quality loss usually recovered by training with GQA from the start rather than converting afterwards. The extreme, one shared KV head for all queries (MQA), saves more and degrades more. GQA was the 2023-2024 default and remains the baseline in Llama 3 and 4, Qwen3, Gemma and gpt-oss.
- **MLA (multi-head latent attention).** Instead of caching keys and values per head, project them jointly into a single low-rank latent vector, cache only that, and up-project back to per-head keys and values inside the attention call. The cache shrinks by roughly an order of magnitude against MHA and materially against GQA, and DeepSeek's ablations report quality at or slightly above MHA at equal cache size, which is the unusual part: most cache reductions cost quality. It costs compute and complexity. Every attention call pays two extra projections, trading arithmetic (cheap and parallel) for memory traffic (scarce during decode), the right trade on current hardware. And RoPE cannot be applied to the compressed latent, since rotating before compression does not survive the up-projection, so MLA carries a small separate decoupled RoPE key dimension alongside it. That makes the kernels fussier than GQA's, which is why MLA support lagged in serving stacks. Used in DeepSeek V2/V3/R1 and Kimi K2.
- **Local/global mixing (sliding-window layers).** Most layers attend only within a fixed window of recent tokens, with a full-attention layer inserted periodically, at ratios such as 5:1 in Gemma 3 or 3:1 elsewhere. Windowed layers need cache only for the window, so total cache stops growing with context length for most layers. Quality loss is negligible on most workloads because the global layers still route information across the whole sequence. The cost is that information must travel through those global layers, so the ratio is a real hyperparameter: retrieval-style long-context tasks, where an exact token far back must be recovered, are the workload most sensitive to it.
- **Trained sparse attention.** A lightweight learned indexer scores candidate keys or blocks of keys per query, and full attention is computed only over the selected top-k, so cost per token becomes roughly linear in the selected count rather than quadratic in the context. This is what made 1M-token contexts economical in 2026: DeepSeek V3.2's DSA, V4's compressed CSA/HCA (which drops KV cache to about 2% of vanilla), MiniMax M3's MSA, and Qwen's QSA, which selects at micro-block rather than individual-token granularity because block-level gathers are far friendlier to memory hardware than scattered token-level ones. It costs: the indexer is itself trained and runs on every query, selection is a hard decision that can miss the one token that mattered, and it has to be trained in rather than bolted on, so it is not a post-hoc optimisation.
- **Linear and hybrid attention.** Replace softmax attention in most layers with a recurrent update to a fixed-size state, so per-token cost is constant and no KV cache grows with context, then interleave periodic full-attention layers (roughly 1 in 4) to restore exact recall. Qwen3-Next's Gated DeltaNet, Moonshot's Kimi Delta Attention, and Mamba-2 hybrids such as NVIDIA's Nemotron Nano and IBM Granite 4 all take this shape, pushing KV cache per token from hundreds of KiB down to a few KiB. The cost is inherent to the fixed-size state: it is a lossy summary, so anything not written into it is unrecoverable, and pure linear models are measurably worse at exact retrieval. The hybrid exists because the full-attention layers buy that capability back, and the mixing ratio is the dial between memory footprint and recall fidelity. See [Mamba: Linear-Time Sequence Modeling with Selective State Spaces](../../../papers/2023-12_mamba/summary.md) for the state-space formulation underneath.

#### 2. MoE configuration

Each block's feed-forward network becomes many expert FFNs plus a router that activates a few per token, decoupling capacity from per-token compute. The trend runs from few big experts (Mixtral 8x7B with top-2 of 8, Grok 2 with 8) to many small ones at high sparsity, usually with a shared always-on expert: DeepSeek V3 runs 256 routed experts with 8 active plus 1 shared, Kimi K2 384, K3 896 with 16 active, while Qwen3 uses 128 with no shared expert. Several models keep the first blocks dense (V3, GLM-4.5), because early-layer representations are barely differentiated and routing on them is near-random and destabilising.

**Multi-token prediction (MTP)** heads are increasingly standard alongside this: extra output heads trained to predict the token after next, and the one after that. In training they densify the learning signal per position; at inference they act as a built-in draft model for speculative decoding, so the speedup arrives without a separate small model to maintain. The cost is a modest number of extra parameters and a more involved loss.

Why fine-grained sparsity wins and what it costs, plus routing, load balancing, capacity factors, expert parallelism and what breaks at inference, is in [Mixture-of-Experts (MoE) models](../moe-models.md) (15 min read · +3h 25m resources).

#### 3. Normalisation

RMSNorm is universal: it rescales by the root mean square of the activations and drops LayerNorm's mean subtraction and bias, which removes one reduction and a set of parameters at no measured quality cost. The interesting differences are placement and extras.

- **Pre-norm** (normalise the input to each sublayer) is the default. It keeps a clean unnormalised identity path down the residual stream, which is what makes deep models trainable without learning-rate warmup tricks. Its known cost is that residual-stream magnitudes grow with depth.
- **Post-norm variants.** OLMo 2 normalises each sublayer's output before it is added back to the residual stream rather than normalising its input, which damps what each block injects and is reported to improve loss stability. Gemma 3 normalises both before and after each block, taking the stability of both placements for an extra norm per sublayer, negligible next to the matmuls.
- **QK-norm.** RMSNorm on the query and key vectors before the attention dot product (in most implementations before RoPE). This bounds attention-logit magnitude, which otherwise grows steadily during training and produces the classic bf16 attention overflow and loss spike. It spread from OLMo 2 and Gemma to most 2025-and-later models and is close to free insurance; MiniMax M2 applies it per head. Cost: two extra normalisations per attention layer.

#### 4. Positional encoding

RoPE is near-universal: it rotates query and key vectors by an angle proportional to absolute position, with a different frequency per dimension pair, so the dot product between two tokens depends only on their relative distance. Everything below is about a model trained at one context length having to work at another.

- **Base and interpolation scaling (YaRN and relatives).** Raising RoPE's frequency base, or interpolating position indices, stretches the rotations so a longer context falls inside the range of angles the model saw in training. YaRN does this per frequency band rather than uniformly, leaving the high-frequency dimensions that encode short-range order alone and stretching the low-frequency ones that encode long-range position. It buys context extension with a short continued-training phase; blunt uniform interpolation costs short-range precision, the failure mode YaRN was designed around.
- **Partial RoPE.** Rotate only a fraction of each head's dimensions and leave the rest position-free, so those dimensions match on content alone. This empirically extrapolates better beyond the trained length, at the cost of some positional resolution.
- **NoPE on a subset of layers.** No positional encoding at all in some layers. A causal decoder can still infer ordering from the attention mask, and layers with no positional bias extrapolate past the training length far more gracefully, since no rotation runs off the end of its trained range. Pure NoPE is weaker on short-range ordering, so it is mixed: SmolLM3 makes every fourth layer NoPE, and several 2026 models interleave RoPE and NoPE layers.
- **iRoPE (Llama 4).** Interleaves local RoPE layers with global layers that carry no positional encoding, plus inference-time attention temperature scaling, aimed squarely at length generalisation rather than at cache size.

#### 5. Stack shape: depth reuse, and the encoder-decoder return

Two September 2026 releases changed something the four sections above quietly assume, that a model is one causal decoder stack executed once per token.

- **Recurrent depth (looped transformers).** Rather than adding layers, reuse them: activations are looped back through the same blocks, so serial depth per token decouples from parameter count. GPT-6 Astra is assumed to work this way, and the **Recurrent Looped Transformer** specification is the first published account of the family, pairing a causal encoder that builds a global KV memory with a decoder carrying its full state, final output and layerwise sliding-window cache included, across the prompt and response boundary with no reset, for unbounded temporal depth at fixed per-token compute. It buys compute without parameter memory, which makes the model cheaper to host. It costs recurrent state that the serving stack must carry between requests, and shorter visible reasoning traces, a real loss to chain-of-thought monitorability. The specification ships with no trained weights, no efficiency measurements and no quality results, so this is a shape to recognise on a card rather than a recipe to copy.
- **Encoder-decoder at frontier scale.** DeepSeek V4.1-Flash is 552B split into a 20-layer causal encoder and a 20-layer decoder, activating 8B during prefill and 16B during decode. The argument is not T5's quality one: encoding the prompt once into a shared representation, combined with cross-layer sparse attention with index reuse, hierarchical retrieval and FP4 cache storage, gets the KV cache to **890 bytes per token**, a quarter of V4-Flash's HBM footprint and an eighth of its SSD footprint. T5Gemma is the other current encoder-decoder line, at small scale and built by adapting decoder checkpoints rather than pretraining. Note what this does to rule 1 below.

### How to read a new model card in 30 seconds

1. **Total versus active parameters.** The ratio is the sparsity; the total is the memory floor you must provision, the active count sets latency and price per token. They predict different things and are routinely conflated, and the active count is no longer guaranteed to be a single number: an encoder-decoder can activate one figure during prefill and another during decode.
2. **Attention type and layer mix.** Quadratic, hybrid or trained-sparse, and in what proportion. This is how cost scales with context, which matters more than the headline context number.
3. **KV cache per token, multiplied by target context and concurrency.** "Does long context actually fit", answered in gigabytes.
4. **Experts: routed, active, shared.** Determines routing style, how much expert parallelism you need to make per-expert batches efficient, and how much skewed traffic will hurt.
5. **Licence, and whether base weights shipped, not just instruct.** Base weights decide whether you can do your own post-training at all.
