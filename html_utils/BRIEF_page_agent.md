# Brief: build one knowledge base page as an HTML-only page

For a subagent that builds one page. The orchestrating session (running the `create-interactive-html` skill) gives you the page title, Notion URL and the page folder `technical_knowledge_base/<section>/<topic>/[<child>/]`. Work only in that folder. Never write to Notion; read-only Notion calls are fine (load the tools with ToolSearch).

## Step 0: save the page
If the page is still in its old written form in Notion, fetch it and save the full fetched text, verbatim, to `src/live.md` (a large fetch is saved to a file by the tool: copy it with a script, never retype it). This is the knowledge the HTML must carry; the coverage check runs against it. Report whether it has child pages, databases or a video, with their exact tags: they stay on the page, so the HTML links them rather than replacing them. Read all of it. If the page is already HTML-only, its knowledge is the current `index.html` plus `src/`.

## The model (Khalid's decisions)
- The page text is deleted. The HTML becomes the ONLY source of information on the page, so it is self-contained and loses no knowledge. A deep dive or provider page owns its details: nothing is cut, only said once and clearly. If child pages own some details, link to them rather than repeating them.
- A root `Topic: *` page is mainly a comparison between things and the definitions needed for it: its Reading tab is as short as possible while still self-sufficient. Details move to child pages first (move, then cut).
- Frame of tabs, always: (a) **Reading**, first and open by default: the explanation interleaved with the visualisations needed to understand it as you read. (b) **One tab per standalone visualisation** that deserves room of its own (none is fine). (c) **Further reading**, last: related knowledge base pages and the best resources, every one a working link (`target="_blank" rel="noopener noreferrer"`; Notion pages as `https://app.notion.com/p/<id>`) with its time estimate.
- Every specific fact carries its source inline as a link; derived numbers show their formula; illustrative or fitted inputs are labelled; nothing is invented. Mark claims you cannot source as unconfirmed.
- **Animations are wanted.** Khalid's favourite visual is the DeepSeek MLA explainer: one input animated step by step, with a toggle running the same animation for the method it replaced, drawn to scale, a caption per step, running counters, play/pause/step/scrub/speed, animating only on screen and in the visible tab, starting paused under `prefers-reduced-motion`. Where the page explains a mechanism that replaced an earlier one, or a process in steps, build at least one such before/after animation if it genuinely teaches more than a static view. Examples: `technical_knowledge_base/models_and_training/topic_llms/deepseek/src/parts/18_js_mlx.js`, `.../anthropic_claude_family/src/parts/12_js_sim.js`, the attention ladder in `.../llm_architecture_gallery/src/parts/`.
- Khalid removed price-history, business-ledger, training-bill and compute-across-generations tabs from DeepSeek; do not build those kinds of tab unless the page truly centres on them.

## Read first
1. `.claude/skills/create-interactive-html/SKILL.md` (constraints: one self-contained file; no network, CDN or web fonts; light and dark via `prefers-color-scheme` with colours as CSS variables; phone width with no sideways page scroll; storage in try/catch; no em-dashes anywhere; maths without external libraries; each tab's charts drawn when the tab opens; under about 300 KB).
2. `html_utils/interactive-html-ideas.md`: section 1 is every idea built or rejected so far (reuse what worked, avoid rejected patterns); section 2 is the Methodology for choosing visualisations with all its rules.
3. Finished examples to match in look and mechanics: every folder under `technical_knowledge_base/models_and_training/topic_llms/` (start with `anthropic_claude_family/src/`: its `build.sh` is the reference). Shared data: `technical_knowledge_base/models_and_training/topic_llms/src/data/aa_snapshot.json` (Artificial Analysis Intelligence Index v4.3; `aa_cost_per_index_task` is cost per index task) and `release_history.json`.
4. **Fail-safe build (required).** Every JS part goes in its own `<script>` element; the tab wiring is its own last script; include the hidden error box and global error handler exactly as in `html_utils/templates/05z_errbox.js.html`, with the `<div id="jsErr" hidden ...>` that `build.sh` emits before it (see `html_utils/templates/build.sh.example`). Never put a literal backslash-n through `echo` in `build.sh`; keep such snippets in part files and `cat` them. `src/build.sh` writes `../index.html`.

## Steps
1. **Decide the visualisations** by following the Methodology: list what the text needs to be understood; research ideas by fetching the page's own sources, other primary sources (announcements, technical reports, model cards and config.json files, API docs, licences), explainers and trackers (Artificial Analysis, LMArena, Epoch, METR, Raschka's gallery, Hugging Face blogs). Score the candidates, decide tab versus inline, recompute every default you plan to reproduce in `src/recompute.py`, and write `src/viz_ideas.md` (ranked ideas with scores, data and formulas with URLs, inspiration, placement, rejected ones and why, and what the methodology lacked for this page). Keep small fetched inputs (configs, text extracts) in `src/inputs/`; never commit PDFs or files over about 1 MB.
2. **Build** the Reading tab, the chosen tabs and Further reading in `src/parts/` plus `src/build.sh`, and `src/README.md`. Where a default reproduces a published figure, show a "defaults reproduce X (source)" line saying independently or by construction; say plainly where it does not reproduce.
3. **Check:** `sh html_utils/checkpage.sh <page folder>` must end `fail=0` with `emdash 0` and `errbox 1`; look at the screenshots in `<page folder>/.shots/` and fix problems; exercise every control with a script (no NaN, undefined or errors). If you saved `src/live.md`, write `src/coverage.json`: every distinct fact, number, mechanism step, caveat and source link in it with where the HTML carries it, or why dropped (only genuine duplication, or a stale claim with its correction). Fix stale claims against current sources as you go.

## Reply with
Child pages, databases or video found (with exact tags); the tabs and Reading outline; the visualisations built and why each earns its place (and rejected ones); which defaults reproduce which figures; coverage counts; stale claims corrected; anything you could not source; reading length; file size; check results.
