# html_utils

Runtime tools the knowledge base pages are checked and published with. How pages are built (and why) lives in the `explainer-page` skill (`.claude/skills/explainer-page/`); videos in `explainer-video`; publishing in `sync-kb-github`.

| File | What it does |
|---|---|
| `checkpage.sh <page folder>` | Checks a built page (run `sh <page>/src/build.sh` first): every tab in light at 920 and 1400 px and dark at 390 px, errors, sideways scroll, clipping, em-dashes; screenshots in `<page>/.shots/`. Must end `fail=0`, `emdash 0`, `errbox 1`, `ask 0`, `buddy 1` (the AI buddy loader, exactly once), `clipped 0`. |
| `verify_layout.mjs <page folder> <shots dir>` | The lead's check of the 2026-11-06 layout rules: visuals inside splits, two columns at 1400 px, every 3D stage autoplays once in view and never under reduced motion, step lists as long as their stages. Ends `problems N` (must be 0); "(check autoplay)" lines are information. Shots go outside the repo. |
| `tabshot.mjs`, `clipcheck.mjs` | Screenshots per tab and the clipping check, used by `checkpage.sh`. |
| `tex2mathml.mjs` | Converts LaTeX to MathML at build time for maths pages. |
| `sync_status.py` | What is left to publish: failed builds, uncommitted pages, unpushed commits, Notion pages not yet link pages. `--no-build` is safe while agents edit. |
| `page_finalize.py`, `paper_finalize.py` | Publish: mark `html_only` and commit each page's own files with `pages.json` (then push). |
| `audit_pages.mjs`, `audit_pages.py` | Measure every page from the rendered DOM: core and closed-detail minutes, visuals inline and in tabs; `--concepts` flags concepts taught on several pages. |
| `ledger.py` | The knowledge ledger: `init` drafts a page's units, `check` proves no non-fat unit was lost in a rebuild. |
| `check_times.py` | Lists reading times quoted for other pages that no longer match those pages' headers (`--page` for one page; `--fix` rewrites the unambiguous ones). |
| `build_site.py` | Builds the reading site (GitHub Pages) from every page, with links rewritten and `p/<id>/` redirects. |
| `learning_map.py`, `check_learning_map.mjs` | The home page's learning map from the strict `prereqs` in `pages.json`: `learning_map.py check` validates the graph (the build fails on an error); the `.mjs` builds to a scratch folder and checks the map in a browser. |
| `whats_new.py` | The home page's first block, What's new (the latest tech-news issue and the newest papers), and the Tech news and Papers index pages; `whats_new.py check` validates the data each card needs (the build fails on a problem). |
| `apply_look.py` | Writes the template's reading-site look as one marked `kb-look` style block into pages built before 2026-10-29; rerun with `--all` after changing the look in the template's `01_head.html`. |
| `kb_buddy.js`, `kb_buddy_loader.js`, `apply_buddy.py` | The AI buddy, on every page since 2026-11-19 (piloted on the Attention Is All You Need page from 2026-11-18); it replaced Ask Claude (`kb_ask.js`, `apply_ask.py`, deleted). Pages carry only `kb_buddy_loader.js`, written by `apply_buddy.py` (`<page>...`, `--template`, `--all`, `--check`, `--remove`; it also strips any old Ask Claude block) as the marked `kb-buddy` block in the head part; the loader fetches the shared `kb_buddy.js` (published by `build_site.py` as `kb_buddy.js` at the site root, its address and a version stamp written into each loader) when a Claude key is saved or the reader taps "AI buddy", so readers without a key download nothing and editing `kb_buddy.js` needs no page rebuild (editing the loader does: `--all`, then rebuild every page). `checkpage.sh` fails a page without exactly one loader or with Ask Claude. Claude's generated visuals are split sections (explanation left, visual right) in a sandboxed frame; 2D by default when the reader does not say, always 3D when they ask for it; for 3D the frame gets the page's own renderer (S3: the page's inline copy, else `kb_s3.js`, the template's `25_js_s3.js` published by `build_site.py` at the site root) and the page's stage styles. The buddy is a **toolbar** docked to an edge of the screen (top by default; dragged by its grip it snaps to any edge; it can be made small): Read (no pen; selecting text there opens a small Ask box, and the answer comes as a note beside the passage, which is highlighted), pen, highlighter, eraser, Text (tap anywhere in the notebook and type there), six colours, two widths, Undo, a **Claude** switch (on: Claude reads after a pause set in Settings, 1, 2, 3 (default), 5, 8 or 12 s, typing twice that; off, or "Never" in Settings: marks are only notes and Send asks), the **Notebook** and Settings. **On the page**, with a pen chosen, the Apple Pencil and the mouse write while fingers keep scrolling and working the page; marks are SVG paths pinned to the element they were drawn on (child-index path, offset, width then), so they follow reflow, resizing and tabs; Claude's replies are sticky notes right by them (under a highlight, beside a drawing; fold to a dot, move, delete); each note is the thread about its marks: tapping the marks opens it, and a box at its foot asks a follow-up. Since 2026-11-20: the **Notebook** (with its Text tool) and the **overview** are switched off (`NB_OFF` in `kb_buddy.js`) while Khalid rethinks them; their data stays saved and synced, and the gear still opens Settings. Notes work like a chat (the question shows at once with a thinking line until the answer), carry two picture buttons (Sketch in note; Add to page), and expand to full screen or resize from their corner. The quiet section nudges were removed (2026-11-20). The **Notebook** (full screen clear of the toolbar, or floating) is ruled pages one under another: write with the Pencil, a finger or the mouse (two fingers scroll) or, with the Text tool, tap anywhere and type there (typing is the chat; Enter sends); Claude gets the new ink close up and the notebook page with free spots lettered on it, picks one or a fresh page inserted right after the one being written on, and writes there in a handwriting face, with sketches and an arrow to an earlier mark when useful. Everything is kept in the browser's IndexedDB (notebook, page marks, notes, History). With every message Claude gets the tab and section, the text in view, the controls' values, the highlight, and an image of the screen rebuilt in the browser from the page's DOM, canvases and SVGs, with the marks and notes on it. On request Claude changes the page for the reader: `rewrite_block` rewrites a text block in place (a tag switches back to the original) and `add_visual` adds an interactive visual after a block in a sandboxed iframe that cannot reach the page, its storage or the keys; each change is a synced record, listed under Page changes in the overview to keep or discard. Since 2026-11-20 the editing loop: also `insert_text`, `hide_block` and `move_block` (Hide and the arrows also work directly from a selection, the lasso or a hover handle); every change keeps up to 6 versions, and its badge opens a change bar that refines it in one tap (shorter, simpler, deeper, example, try again, two versions, or your own words), shows what changed against the original or the version before, and keeps, removes or undoes it with the whole request (its highlight and note go with it, with an Undo); the Changes panel reviews them all and shows the page as written. Visuals: a guard in each frame reports errors, a blank drawing (judged only once in view) and the part the reader points at; `window.kit` draws in the page's colours with touch-sized controls; a visual made in this browser that fails is repaired out of sight (`patch_visual`, Sonnet, at most twice per version), else dropped back to the version before or shown with Try to fix it and Remove; "Point at a part" says which part a refinement is about. After a rebuild of the page: a change whose id the page carries as `data-kb-edit` (put there when it is folded in, see `kb_changes.py`) or a rewrite the page now says word for word is cleared; a rewrite whose block changed since shows the page's new text, marked Needs a look (use Claude's version, keep the page's, or ask Claude to merge). Failures (2026-11-20): a request that sends nothing for 75 s is stopped; errors read plainly; a question that fails keeps its note, question and highlight with "Not answered" and Try again (asked again the way it was asked); a reply cut off midway keeps its text and says so (the marker is never sent back to Claude). On touch screens the toolbar, note and notebook buttons are touch-sized (the toolbar stays one row at iPad widths); a floating notebook stays clear of the toolbar and a dragged note stays on screen; notes and highlights pinned to a block shared by every tab (the breadcrumb, the tab bar) stay on the tab they were made on. Web access (a Settings switch, on by default): the API's server-side `web_search_20260209` and `web_fetch_20260209` tools, at most 3 uses each per question, when the page and the knowledge base are not enough; a paused server turn is resumed; web sources become link chips (http(s) only, escaped, new tab); page-changing tools run only when the reader's own words ask for a change, so web content can never change the page; an account without web access is retried once without the tools. Same key and model as Ask Claude. `apply_buddy.py <page folder>` writes it as one marked `<script id="kb-buddy">` block into the part that closes the head; rebuild after. `audit_pages.mjs` ignores it. Since 2026-11-19 also: a lasso (select marks or notebook writing to move, resize, delete or ask about), a Text tool, scratch-out to erase and hold-to-snap shapes, smooth ink with a hover dot, pinch zoom in the notebook, a "?" that sends at once, one-tap prompts under every Ask box, named colour meanings, notes that never overlap with Resolve and connector lines, an overview of every mark and note (Marks), notebook search and page thumbnails (Pages), citations (the page goes to Claude as a cached document of blocks; each citation is a numbered chip that jumps to the passage), and the whole knowledge base as tools (search_kb uses the site's Pagefind index, else `kb_index.json`; read_kb_page fetches a page; Claude names pages as [[title]], shown as links). `build_site.py` writes `kb_index.json` (path, title, id, prereqs, headings, summary per page) at the site root. Sync (2026-11-19): every mark, note thread, notebook page, stroke, typed note or reply, handwriting reading and History entry is a record (id, updatedAt, deleted marker) in IndexedDB `recs`, migrated from the older per-page bundle on first run; with a fine-grained GitHub token in Settings (Contents read and write on `khalit7/kb-notes` only) they sync through that private repo as `pages/<page path>.json` plus `settings.json`, merged record by record (newer wins), with retry when a save is rejected; a cloud on the toolbar shows the state. The Claude key, the token, the toolbar's and window's places, the current tool and History pictures stay on each device. Marks keep their element's opening text and find their place again after a rebuild; the rest are listed as unanchored in Marks. No knowledge-base workflow reads the notes repo; `kb_changes.py` reads it only when Khalid asks. |
| `kb_changes.py` | The page changes Khalid marked Keep in the AI buddy, read from the private notes repo `khalit7/kb-notes` (through `gh api`, or `--notes <clone>`), as a Markdown bundle per page (or `--json`): what each change replaced, what was asked, and the version shown, with how to fold it into the page's `src/parts` (in the page's own style) and the `data-kb-edit="<id>"` attribute to put on the element that carries it, after which the buddy clears the record. `--page <part of path>`, `--all` (also changes not kept), `--out <file>`. Run only when Khalid asks. |
| `cloud_setup.sh` | Sets up a cloud sandbox (the weekly routine) to build and check pages. |

Setup: `cd html_utils && NPM_CONFIG_USERCONFIG= npm ci` (puppeteer with its own Chrome).
