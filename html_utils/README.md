# html_utils

Runtime tools the knowledge base pages are checked and published with. How pages are built (and why) lives in the `explainer-page` skill (`.claude/skills/explainer-page/`); videos in `explainer-video`; publishing in `sync-kb-github`.

| File | What it does |
|---|---|
| `checkpage.sh <page folder>` | Checks a built page (run `bash <page>/src/build.sh` first): every tab in light at 920 and 1400 px and dark at 390 px, errors, sideways scroll, clipping, em-dashes; screenshots in `<page>/.shots/`. Must end `fail=0`, `emdash 0`, `errbox 1`, `buddy 1` (the AI buddy loader, exactly once), `clipped 0`. |
| `verify_layout.mjs <page folder> <shots dir>` | The lead's check of the 2026-11-06 layout rules: visuals inside splits, two columns at 1400 px, every 3D stage autoplays once in view and never under reduced motion, step lists as long as their stages. Ends `problems N` (must be 0); "(check autoplay)" lines are information. Shots go outside the repo. |
| `tabshot.mjs`, `clipcheck.mjs` | Screenshots per tab and the clipping check, used by `checkpage.sh`. |
| `tex2mathml.mjs` | Converts LaTeX to MathML at build time for maths pages. |
| `sync_status.py` | What is left to publish: failed builds, uncommitted pages, unpushed commits. `--no-build` is safe while agents edit. |
| `audit_pages.mjs`, `audit_pages.py` | Measure every page from the rendered DOM: core and closed-detail minutes, visuals inline and in tabs; `--concepts` flags concepts taught on several pages. |
| `ledger.py` | The knowledge ledger: `init` drafts a page's units, `check` proves no non-fat unit was lost in a rebuild. |
| `check_times.py` | Lists reading times quoted for other pages that no longer match those pages' headers (`--page` for one page; `--fix` rewrites the unambiguous ones). |
| `build_site.py`, `app_icon.svg`, `app_icon.png` | Builds the reading site (GitHub Pages) from every page, with links rewritten and `p/<id>/` redirects. The site installs as an app (Add to Home Screen on an iPad): the build writes `manifest.webmanifest` and copies `app_icon.png` (the render of `app_icon.svg`: open the SVG at 512 by 512 in a headless browser and screenshot it) to the site root and links both from every page. It also puts the AI buddy on the landing page and each page's display title in `<meta name="kb-title">` (for Continue reading). |
| `learning_map.py`, `check_learning_map.mjs` | The home page's learning map from the strict `prereqs` in `pages.json`: `learning_map.py check` validates the graph (the build fails on an error); the `.mjs` builds to a scratch folder and checks the map in a browser. |
| `whats_new.py` | The home page's first block, What's new (the latest tech-news issue and the newest papers), and the Tech news and Papers index pages; `whats_new.py check` validates the data each card needs (the build fails on a problem). |
| `kb_buddy.js`, `kb_buddy_loader.js`, `apply_buddy.py` | The AI buddy, on every page. Pages carry only the small loader (the marked `kb-buddy` block, written by `apply_buddy.py`: `<page>...`, `--all`, `--check`); it loads the shared `kb_buddy.js` (published at the site root by `build_site.py`) on every page, so editing `kb_buddy.js` needs no page rebuild. What it is: a toolbar over the page, and nothing else on it: pens, highlighter, lasso and text, whose marks stay pinned to the page; sticky-note chats beside them that cite the page's sentences and can search the knowledge base and the web; Ask, a conversation about the page (a card under the toolbar that can be dragged, a new one each time, carrying only its own thread; on the landing page, about the whole knowledge base); Send for new marks or ink (nothing is sent by itself except in Tom Riddle's diary); a Conversations overview; a handwritten notebook with the Tom Riddle diary; page edits on request (rewrite a block, add a visual as a split section), each kept or discarded. Without a Claude key or a sync key (a GitHub token) the toolbar's Claude and sync buttons say "Claude key" and "Sync key" ("Fix Claude key" and "Fix sync key" when the key was refused) and open that field in Settings. Everything syncs across devices through the private repo `khalit7/kb-notes` with a GitHub token from Settings; the Claude key stays in the browser. |
| `buddy_test.mjs` | The AI buddy end to end, in Chromium and in WebKit (Safari's engine, what the iPad runs), with Claude and GitHub faked and a local server over the repo: `node html_utils/buddy_test.mjs` (or `... chromium`, `... webkit`). One line per check; every check must pass in both engines before a change to `kb_buddy.js` is pushed. |
| `kb_reader.js`, `kb_reader.css`, `kb_reader_sw.js`, `lib/pdfjs/`, `reader_test.mjs` | The paper reader: the original paper with the AI buddy on it. Every paper page has `"reader": {"arxiv": "<id>v<n>"}` in `pages.json` (pinned to a version; `whats_new.py check`, run by the site build, fails a paper whose `paper.json` has an arXiv id without it) and gets `paper/`: the PDF, fetched by the browser from arXiv (the site keeps no copy), drawn by pdf.js 6.5.438 (legacy build, vendored in `lib/pdfjs/` with its fonts, character maps, colour profiles and image decoders), its text layer grouped into paragraphs so the buddy can cite and anchor them; the buddy makes no page changes there (`data-kb-noedit`). The site bar of the paper's page links Original paper; `paper/pdf/` (the address while there was also an HTML view) redirects to `paper/`. Offline: the PDF and the reader's files go into Cache Storage on the first visit, and `paper/sw.js` (from `kb_reader_sw.js`, scoped to the reader, GET to this site and arxiv.org only, so the Claude and GitHub calls never pass through it) serves them with no network. `node html_utils/reader_test.mjs` (or `... chromium`, `... webkit`) checks it at laptop and iPad sizes (needs the network for arXiv; Claude faked). |
| `kb_changes.py` | The page changes Khalid marked Keep in the AI buddy, read from the private notes repo `khalit7/kb-notes` (through `gh api`, or `--notes <clone>`), as a Markdown bundle per page (or `--json`): what each change replaced, what was asked, and the version shown, with how to fold it into the page's `src/parts` (in the page's own style) and the `data-kb-edit="<id>"` attribute to put on the element that carries it, after which the buddy clears the record. `--page <part of path>`, `--all` (also changes not kept), `--out <file>`. Run only when Khalid asks. |
| `cloud_setup.sh` | Sets up a cloud sandbox (the weekly routine) to build and check pages. |

Setup: `cd html_utils && NPM_CONFIG_USERCONFIG= npm ci` (puppeteer with its own Chrome, and Playwright for the buddy test), then `npx playwright install chromium webkit` (the buddy test's two browsers, kept in `~/.cache/ms-playwright`). On Ubuntu 22.04 WebKit also needs four system libraries (`libavif13`, `libgav1-0`, `libyuv0`, `libgstreamer-plugins-bad1.0-0`): `sudo npx playwright install-deps webkit`. Without root: `apt-get download` those four packages, unpack each with `dpkg -x`, and copy their `.so` files into `~/.cache/ms-playwright/webkit-*/minibrowser-wpe/sys/lib/` (again after a Playwright upgrade, which brings a new `webkit-*` folder).
