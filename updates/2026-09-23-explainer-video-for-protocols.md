# 2026-09-23: explainer video for protocols

A single addition: the topic overview video for [Topic: protocols](../topics/protocols/summary.md), plus the one gloss the page gained while it was being made.

**[new] A narrated explainer video is attached to **[Topic: protocols](../topics/protocols/summary.md)**.** Seven minutes eighteen seconds, 1080p30, one narrator with a second voice asking the viewer's question twice. It is a topic overview, so it names the whole board before explaining any of it, and this is the second of the two kinds: a mental model rather than a comparison, because nothing on this page competes with anything else on it. REST against gRPC against GraphQL would be a comparison video, and a much smaller one than a page running from how bytes move on a wire to how an agent drives a microscope. So the organising question is not which protocol, it is which layer, and the map is a stack: transport at the base, then TLS and PKI, then HTTP and streams, then RPC and APIs, then auth, and agent protocols on top. Six layers, every one of them already running under your service whether or not anybody chose it, and each one solving the problem the layer below it left behind.

The stack is drawn top to bottom, because that is the only order a stack can be drawn in, and then climbed from the bottom. Transport is read as failure modes rather than as a specification: throughput is window over round-trip time, so one stream caps near 5 Gbps and a 140 GB checkpoint is a concurrency problem rather than a bandwidth one, which is why NCCL opens sixteen sockets per peer on AWS, and DNS breaks in ways that look like everything else. TLS and PKI is the layer being rebuilt underneath you, drawn as two bars sharing a baseline: post-quantum hybrid key exchange is past 60 percent of client traffic and about 10 percent of origins, because browsers ship it and update themselves while somebody has to upgrade a server, and certificate lifetimes fall to 47 days by 2029. HTTP is one bug fixed twice, and that bug is the gloss the page gained. The streaming beat is one question rather than a wire format, who is allowed to talk, which is what actually decides SSE against WebSockets. And RPC is three answers with one use and one catch each, where the catch that costs money is that a gRPC channel is a single long-lived HTTP/2 connection, so an L4 balancer pins every call to one backend.

The top of the stack is the part this knowledge base exists for. MCP is JSON-RPC between a host, one client per connection, and servers exposing tools. What it buys is that a server written once plugs into every harness, and the 2026-07-28 revision made the core stateless so an ordinary gateway can route and cache a request. What it costs is not a bug anybody can patch: every tool result is untrusted text arriving inside the model's context, which is the whole prompt-injection surface. A2A sits beside it, agent to agent rather than agent to tool. Then the number that says how small a contract MCP really is, Stanford's Paper2Agent in Nature, 74 of 100 computational biology papers turned into working MCP servers with no manual intervention, and the second voice asks the question the viewer is already forming, which is what went wrong in the other 26. Not the protocol and not the model: the knowledge needed to run the code was never in the repository. Auth closes the tour, because MCP made every AI engineer an OAuth integrator and the spec bans token passthrough for the confused-deputy reason, so the answer is structural, credentials outside the cell and approvals outside the chat. It closes on the page's own movement rather than a recap: the bottom of the stack is about as solved as networking gets, the top is not two years old and is already driving microscopes and liquid handlers through Anthropic's Model Hardware Standard, and the thing that breaks has changed kind, from a dropped packet you retried and forgot to a tool result you did not write.
