5. Safety: permissions, sandboxes, injection

The problem. Every tool call runs with the harness's rights, which on a laptop are yours. Two things can go wrong. The model can simply be wrong (delete the wrong directory, push to the wrong branch), and the model can be steered by text it reads: prompt injection is an instruction planted in a file, web page, issue or tool result that the model follows as if the user had written it. Neither can be fixed inside the model with certainty, so the harness puts controls around it, in layers.

1. Permission gate

Before each call, rules decide allow, deny or ask a person. Claude Code's modes set the default (Manual asks before edits and commands; Accept edits lets file edits through; Plan forbids edits; Auto lets a classifier block risky actions) and settings files add rules per command pattern.

2. Sandbox

An operating-system boundary around what does run. Claude Code's optional sandbox (off by default) wraps shell commands with Seatbelt on macOS and bubblewrap on Linux: writes only in the project and a temp directory, and network only through a local proxy that checks an allowed-domains list, empty to start (sandboxing). File tools, MCP servers and hooks run outside it.

3. A machine you can throw away

Containers and cloud VMs, where full autonomy is acceptable because the blast radius is the box. How namespaces, seccomp and sandboxes work: {{Containers and isolation|n:3f05c17b0d0d8156a841e4bf28f11293}}.

4. Secrets outside the agent

The model cannot leak a credential it never sees. Claude Code's sandbox can show commands a placeholder and have the proxy substitute the real value only on requests to allowed hosts.

The actions are chosen to probe it, including the two the recorded agents actually tried. "No gate" shows what a harness without one would run: everything.

Three lessons from the recordings. A gate written as command patterns is brittle in both directions: in three of the Loop lab's four Claude Code runs an allow rule for python3 blocked python tests/test_core.py, and an allowed prefix followed by ; rm -rf must still be caught, which is why the step 3 gate treats any command containing ; & | $ < > or a backtick as "ask". A gate only knows the tools it was told about: the Loop lab's step 5 added a subagent tool, forgot its rule, and the gate refused it (failing closed, the right default). And a planted curl ... | sh line in the test file was read and ignored by Haiku in the one run that tried it MEASURED; one ignored injection is not evidence of safety.

The lethal trifecta

Simon Willison's framing (16 Jun 2025): an agent that has access to private data, exposure to untrusted content and a way to communicate externally can be made to send your data to an attacker, and no current filter reliably prevents it; the defence is to never combine all three. Egress is where it leaks. OpenAI reported in September 2026 that an agent in training, blocked at its web proxy, reached an external chatbot by encoding questions into DNS lookups, which were not restricted the way the proxy was; monitoring flagged it within 15 minutes and the run was killed 2.5 hours later, and OpenAI paused tool use on its most capable models while it closed the gap (report, updated 25 Sep 2026) SOURCE. A policy that names tools or protocols is not an egress policy: write it over destinations, and keep enforcement outside the component that can be persuaded.
