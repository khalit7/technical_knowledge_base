Depth

Interview rehearsal: ten questions on the whole topic (answer each aloud before reading on)

What is an agent harness, in one sentence, and what does it own? The program around a model that runs the loop: it assembles the context for each call, offers and executes tools, gates them with permissions and a sandbox, decides when to stop, and presents the work to a person. The model only chooses the next action.

Walk through one iteration of the agent loop at the API level. Send system prompt, tool definitions and messages; the reply has stop_reason: "tool_use" and a tool_use block (id, name, input); the harness checks permission, runs it, appends the reply and a tool_result with the same id; call again. Stop when the reply has no tool call or a limit is hit.

Your agent's bill doubled after a refactor of the prompt builder. What do you check first? Cache reads per call. If the prefix is no longer byte-identical (timestamps, reordered tools, one rebuilt string) every call pays full input price or cache-write price instead of the cache-read price.

How would you design tools for a coding agent? Few tools matching real tasks (read, search, exact-replace edit, run), clear names and descriptions with examples, results that lead with the verdict, actionable errors, size caps with a note, and an eval loop over real tasks to tune them.

The context window is filling on a long task. Options, cheapest first? Clip or clear old tool results; load skills and tool definitions on demand; move exploration into subagents; write state to files; compact (summarise and restart). Each later option risks losing more.

An agent reads untrusted web pages and has repo secrets. How do you make it safe? Break the trifecta: remove the exfiltration path (network allowlist by destination, no arbitrary URL fetch), keep secrets outside the agent (proxy-injected credentials), run in a sandbox, and gate consequential actions on what they do, not where the text came from.

Why can two papers report the same model at very different scores on the same benchmark? Different harnesses, effort settings, turn and time budgets, attempts, or splits. Ask for all of them, plus cost and the number of runs.

How would you use a harness to generate RL training data? Wrap tasks with a verifier in sandboxes, run the policy in the same harness you will deploy, keep full trajectories with rewards, redact them, train on passing or advantage-weighted ones, and evaluate on held-out tasks and a second harness to catch overfitting to the scaffold.

When is a subagent worth it? When a subtask needs a lot of reading but returns a small answer and does not need the parent's decisions. Not when parallel workers must agree on choices they each make.

Build or buy: when write your own harness? When you need control over the loop (custom tools, training-time use, unusual environments, auditing) or must run where a product cannot. Otherwise use a product or the Agent SDK and spend the effort on tools and verification.
