4. Control: stopping, planning, delegating, running long

When does it stop? In the loop above, the model stops by replying without a tool call (the API marks it end_turn). A harness adds hard limits the model cannot talk its way past: a maximum number of turns, a token or dollar budget, a wall-clock timeout, and the user's interrupt (in Claude Code, Esc stops the running tool call; a message typed while it works is read before its next step). The two classic failures are opposites: stopping too early (declaring victory without checking) and never stopping (looping on the same failing approach). Anthropic's long-running harness lists premature completion and marking features done without proper testing among the failures it was built to fix (26 Nov 2025).

Verification is the feedback signal. The replayed run ran the tests before editing and again after; that second run is why its summary can be trusted. The harness can enforce this instead of hoping for it: a hook is the harness running your code at a fixed point in the loop. Claude Code documents 32 hook events, among them PreToolUse, PostToolUse, Stop and PreCompact; a PreToolUse hook that exits with code 2 blocks the call whatever the model wanted (hooks, read 5 Oct 2026). A rule that must hold every time belongs in a hook, not in the prompt.

Planning. A plan mode lets the model read but not change anything until a person approves a plan; a todo list is a tool whose only effect is to keep a visible checklist in the context, which keeps long tasks on track and gives the human something to supervise. One recorded surprise: Claude Code's plan mode run with --model haiku had every call answered by Sonnet 5.5, according to the per-call model field MEASURED; the pages read do not document it, so check the model field rather than the flag.

Subagents. Section 3's context lever doubles as a control structure: the parent hands a well-scoped question ("find every caller of X") to a fresh loop and gets back a conclusion. It pays when the exploration is big and the answer small; it hurts when the subagents need each other's decisions, which is the multi-agent debate the frameworks root covers ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}). Accounting trap from the recordings: the CLI's result.usage leaves out the subagent's calls, while result.modelUsage includes them MEASURED.

Long-running and background agents. Past one context window, the agent needs state outside the window and a fresh start. Anthropic's design splits the work: an initializer agent sets up the environment, a progress log and a feature list (every feature initially marked failing), and each later session reads them, implements one feature, tests it, commits and updates the log. The same idea explains cloud and background agents: the session runs in a managed machine, and its output lands as a branch or pull request for review rather than as edits you watch.
