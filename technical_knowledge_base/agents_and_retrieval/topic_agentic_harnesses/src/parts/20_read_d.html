6. The products, and how they differ

Every coding harness runs the loop of section 1. They differ in the choices around it, and five questions place any of them:

Where does it run?

Your terminal (Claude Code, Codex CLI, Gemini CLI, opencode, Aider), your editor (Cursor, GitHub Copilot's agent mode, Cline), a cloud machine that returns a pull request (Devin, Codex cloud, Claude Code on the web), or a resident daemon that listens on your messaging apps (OpenClaw, Hermes Agent). Where it runs decides what you can still check: an edit as it lands, a pull request afterwards, or an action already taken.

Which models?

Tied to one vendor's models, or model-agnostic through a gateway. Tied harnesses can tune prompts and tools to their models; agnostic ones carry an edit format and prompt per model.

How contained by default?

Ask-before-acting, an OS sandbox on by default, or a disposable VM per task (section 5).

How extensible?

Memory files, skills, hooks, subagents, MCP servers, plugins: which exist, and which are code rather than prompts.

Can you read it?

Open-source harnesses (OpenHands, Aider, opencode, Codex CLI, Gemini CLI, SWE-agent and mini-SWE-agent) are the only ones whose loop you can read line by line; Claude Code's behaviour is visible through its recorded streams, which is how the labs on this page study it.

Versions, licences, defaults and dates change monthly, so they live in one place, checked against primary sources: the {{Harness atlas|#t-atlas}} (23 harnesses on nine axes, with a side-by-side compare and a chooser). Three child pages take products apart: {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}}; {{Other coding harnesses|n:3c65c17b0d0d819fa3cefdcd2ccff2f7}} (Codex, Gemini CLI, opencode, Aider, OpenHands and mini-SWE-agent compared by design choice, read from source and run on the same task); {{Personal agents|n:3c75c17b0d0d81bf9462fbeb09593e1c}} (resident and computer-use agents, OpenClaw and Hermes Agent).

7. Measuring and training: the score belongs to the pair

An agent benchmark scores a system: the model, the harness, its settings (reasoning effort, turn and time limits) and the environment. Change the harness and the same weights score differently, and, more often, cost differently. On published runs (the {{Harness atlas|#t-atlas}}'s "The harness changes the score", from {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}}): Arena's HarnessTax study moved success by about 2 points on SWE-bench Lite and 5 on Terminal-Bench 2.0 across three harnesses, while Claude Code cost about twice the minimal four-tool harness Pi per attempt on SWE-bench Lite SOURCE. In a controlled run on {{Harnesses for training and evaluation|n:3f15c17b0d0d815ea579d6c80065aa36}}, the harness moved Qwen3-4B by +50 points and Claude Haiku 4.5 by none MEASURED: a small model is far more sensitive to its harness than a strong one; the bill is sensitive for both.

The same loop trains models. A trajectory, the recorded stream of every request, tool call, result and token count, is what you grade when the final answer is not enough ({{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}). In reinforcement learning terms the task and its repository are the starting state, tool calls are actions, tool results are observations, and a verifier such as the test suite gives the reward: a harness is an RL environment, and a model learns the tools, formats and context habits of the harness it was trained in. If the harness moves the score and the bill, a loop can also search over harnesses; the catch is that a loop tuned on the score it reports overfits it.
