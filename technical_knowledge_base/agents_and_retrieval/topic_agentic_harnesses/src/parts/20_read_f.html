6. The products, and how they differ

Every coding harness runs the loop of section 1. They differ in the choices around it, and five questions place any of them:

Where does it run?

Your terminal (Claude Code, Codex CLI, Gemini CLI, opencode, Aider), your editor (Cursor, GitHub Copilot's agent mode, Cline), a cloud machine that returns a pull request (Devin, Codex cloud, Claude Code on the web), or a resident daemon that listens on your messaging apps (personal agents such as OpenClaw and Hermes Agent). Where it runs decides what you can still check: an edit as it lands, a pull request afterwards, or an action already taken.

Which models?

Tied to one vendor's models, or model-agnostic through a gateway. Tied harnesses can tune prompts and tools to their models; agnostic ones carry an edit format and prompt per model.

How contained by default?

Ask-before-acting, an OS sandbox on by default, or a disposable VM per task (section 5).

How extensible?

Memory files, skills, hooks, subagents, MCP servers, plugins: which exist, and which are code rather than prompts.

Can you read it?

Open-source harnesses (OpenHands, Aider, opencode, Codex CLI, Gemini CLI, SWE-agent and mini-SWE-agent) are the only ones whose loop you can read line by line; Claude Code's behaviour is visible through its recorded streams, which is how the labs on this page study it.

Versions, licences, defaults and dates for each product change monthly, so they live in one place, checked against primary sources: the {{Harness atlas|#t-atlas}}.

7. Measuring harnesses: the score belongs to the pair

The problem. An agent benchmark scores a system: the model, the harness, its settings (reasoning effort, turn and time limits) and the environment. Change the harness and the same weights score differently, and, more often, cost differently. The evidence, as checked on the {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}} page: Arena's HarnessTax study (16 Sep 2026) ran seven models in three harnesses on 30 tasks each from SWE-bench Lite and Terminal-Bench 2.0; the harness moved success by about 2 points on the first and 5 on the second, while Claude Code cost about twice the minimal four-tool harness Pi on SWE-bench Lite. On harness-sensitive benchmarks the score itself moves: a checked state-machine runbook lifted one model from 83.1% to 92.1% on Terminal-Bench 2.1, but it was developed on the very tasks it was scored on SOURCE.

How to check a harness claim. To compare models, fix the harness (fixed-harness boards such as HAL or a mini-SWE-agent column exist for this reason); to compare harnesses, fix the model and the effort. Report cost beside the score. Run more than once: three identical Haiku runs above differed in calls and cost. And keep a held-out split that no prompt or harness change was tuned on: in HarnessDev's evolution runs, the score the harness author could see moved in the same direction as the held-out score in only 34 of 64 version changes ({{HarnessDev|n:3d45c17b0d0d81cd9883f783840e013f}}).

Trajectories. The JSONL stream these labs record, every request, tool call, result and token count, is a trajectory. It is what you grade when the final answer is not enough (did the agent edit the tests? run them?), which is the subject of {{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}, and it is the raw material of the next section.
