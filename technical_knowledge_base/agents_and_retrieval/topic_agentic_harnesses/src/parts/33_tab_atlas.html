What this tab is: every harness you will meet, on the same axes

You have seen what a harness is from the inside: {{the Loop lab|#t-loop}} builds one in under 200 lines and {{the Trace and context lab|#t-trace}} opens up real Claude Code sessions. This tab steps back and lays out the finished products: the harnesses an engineer meets in October 2026, each described on the same nine axes from its own documentation, repository or changelog, read on 2026-10-05. Then it asks two questions the products raise: does the harness change the score a model gets on a benchmark (yes, and by how much is measured below), and how are harnesses used to train models.

The nine axes, each answering one design question you will face when you {{build your own|#t-loop}}:

Open source

Can you read and change the loop? The licence decides whether you can fork it or only configure it.

Models

One vendor's models only, or any model through an API key or a gateway such as LiteLLM or OpenRouter.

Loop design

One loop; a plan mode (the agent may read but not change anything until you approve a plan); subagents (child loops with their own context window); parallel or background agents.

Edit format

How a change to a file is expressed: exact-string replace, search/replace blocks, a patch, a unified diff, a whole new file, or just shell commands. {{Compared on one real edit below|#atl-s4}}.

Context

What fills the window: a memory file read at startup (AGENTS.md, CLAUDE.md, GEMINI.md), a repo map (a compressed outline of the code), compaction (summarising old turns), skills (instructions loaded on demand).

Permissions and sandbox

Who approves an action (approval modes, allow and deny rules) and what contains it when nobody does: an OS sandbox (Seatbelt on macOS, Landlock or bubblewrap on Linux), a container, or a cloud VM.

Extensibility

MCP servers (tools from other programs, {{protocol on its own page|n:3c65c17b0d0d813f9695dc4175c44cbb}}), hooks (your code runs before or after each tool call), plugins, custom commands, an SDK.

Where it runs

Your terminal, your editor, a cloud machine you hand tasks to, CI (a GitHub Action), chat apps.

Pricing

Free with your own key, a subscription, usage-based credits, or enterprise. Prices change monthly: each cell carries the date it was read.

Two words used everywhere below
Harness and scaffold mean the same thing in practice: the program around the model. Benchmark papers say scaffold; product pages say agent; this page says harness. A tag in the atlas (green when present) is the compiler's summary of the cell, for filtering; the cell's text and its source link are the evidence, so read those before deciding anything.

Edit formats: one fix, six ways

The running example's second bug is one line in textstats/core.py: top_words sorts by count only, so ties come out in arbitrary order instead of alphabetically. The fix is to sort by (-count, word). Every harness has to get that one-line change from the model's text into the file, and the six families of edit format in the atlas do it differently. Pick one to see exactly what the model must write.







Characters are counted from the text shown; tokens are approximated as characters divided by 4 (labelled approximate: real counts depend on the tokenizer). Formats follow each harness's documentation: Claude Code's Edit tool ({{tools reference|https://code.claude.com/docs/en/tools-reference}}), Aider's SEARCH/REPLACE and unified-diff formats ({{edit formats|https://aider.chat/docs/more/edit-formats.html}}), Codex's apply_patch ({{openai/codex|https://github.com/openai/codex}}), mini-SWE-agent's shell-only actions ({{README|https://github.com/SWE-agent/mini-swe-agent}}).


Why it matters: the edit format is where models fail most mechanically. An exact-replace fails loudly when the old text is not unique or whitespace differs, which the model can repair on the next turn; a whole-file rewrite cannot fail to apply but costs output tokens in proportion to the file and can silently drop code; a shell sed needs regex escaping and behaves differently on macOS and Linux (the stock mini-SWE-agent prompt sets exactly that trap when the host is a Mac and the commands run in Linux: see below). The {{Loop lab|#t-loop}} builds the exact-replace version step by step.







The harness changes the score


A benchmark score belongs to a pair: a model inside a harness, at a setting (effort, turn limit, cost cap). Change only the harness and the number moves. How much depends on the benchmark, and the evidence comes from three kinds of source, kept apart in the chart: public leaderboards that list the agent beside the model, a controlled study that ran every pair on the same tasks, and vendors' own launch figures.

A tiny experiment that failed, and what it teaches


The plan was to run the running example in mini-SWE-agent with the same model as the Claude Code runs, to add a third harness to the comparison above. mini-SWE-agent (version 2.4.6, its stock text-based prompts unchanged, commands run in a python:3.13-slim container) normally calls a model through an API key; this page has only a subscription, so an adapter sent each step to claude -p with every Claude Code tool switched off, the transcript flattened into one text prompt. It did not work, and the way it failed is the lesson.






In  of  replies Haiku wrote its command and then kept going, inventing the command's output and its own next moves; mini-SWE-agent correctly rejected  of them for containing more than one action, and one call ran for  seconds writing  tokens of imagined session. The run was stopped by hand under this page's shared budget, with the code unchanged and the tests still failing.


The lesson: the action boundary belongs to the API, not the prompt

A real tool-calling API ends the model's turn at the tool call (stop_reason: "tool_use"), so the model never gets to write the result. A text protocol needs a stop sequence at the end of the action block to do the same; claude -p exposes none, so this adapter had nothing to stop on. That is why mini-SWE-agent 2.x recommends tool calls over its text mode, why {{the Loop lab|#t-loop}} met the same invented "result" text with its own text protocol, and why the published mini-SWE-agent numbers (run through APIs) are not in question here. A second, smaller trap appeared before any model call: the stock prompt fills in the host's operating system, so on a Mac host it tells the model to use BSD sed -i '' inside a Linux container; the adapter passed the container's own uname instead.






Harnesses for training: the harness becomes the environment


To train a model to act, reinforcement learning (RL, {{Topic: rl|n:3c65c17b0d0d8195a6c6c11ad093c16e}}) needs an environment: something the model can act in, that answers each action, and that says at the end how well it did. For software tasks the environment is built from exactly the parts of a harness: a container with the repository at the commit before the fix, a task statement (a real issue, or one written from the fix or from an injected bug), a harness that turns the model's text into tool calls inside the container, and a verifier: the tests that must flip from failing to passing, and the ones that must stay green. The reward is usually 1 if they do and 0 if not.










The same task, the running example, in both modes. Illustrative: the four rollouts and their rewards are made up to show the arithmetic; the group-relative advantage is the GRPO formula (reward minus the group mean, divided by the group's standard deviation), as used by DeepSWE and Polar below.

Trajectories as training data


Every harness run leaves a trajectory: the full list of messages, tool calls and results, exactly what {{the Trace and context lab|#t-trace}} records. Filtered for success, trajectories are supervised training data (SWE-smith collected them with SWE-agent; Kimi-Dev adapted its model to an agent harness with 5,000 public ones). {{Terminal-Universe|n:3d45c17b0d0d814abc07fde424e09a31}} goes one step further: it replays the file operations recorded in 359,593 public trajectories to rebuild their workspaces, keeping 37,273 as task-sufficient environments, and finds that re-solving recovered tasks beats imitating the source trajectories (52.1 against 36.7 on Terminal-Bench 2.1). Two infrastructure papers show the scale: {{DSec|n:3e95c17b0d0d81bd927be047bb0d7b0b}} (DeepSeek) runs about 3 million sandboxes a day for agentic RL, and {{EnvHarness|n:3c65c17b0d0d81e88ab9c396a160f813}} wraps frozen environments in composable stages that adapt them to the policy's weaknesses while keeping the original verifier.


Go deeper: {{Harnesses for training and evaluation|n:3f15c17b0d0d815ea579d6c80065aa36}} builds an RL environment from zero (its Environment lab tab) and turns recorded rollouts into training data step by step (its Rollout to dataset tab); {{Containers and isolation|n:3f05c17b0d0d8156a841e4bf28f11293}} for how the sandbox works at the OS level; {{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}} for grading trajectories rather than final answers; {{Topic: llm-training-and-post-training|n:3c65c17b0d0d81b6876ee72b7056793b}} for where agentic RL sits among the training stages; {{Schrodinger's Code Repository|n:3e95c17b0d0d81e8b0e0e99acbeb9713}} for whether SWE-bench scores are memorised.







Self-improving harnesses


If the harness moves the score this much, can a model write or tune its own harness? A run of 2026 papers tries, each with its own paper page in this knowledge base. Read them as one line of work: a loop (an "auto-research" or evolution loop) proposes harness changes, scores them on tasks, keeps the better ones. The recurring catch is where the score comes from: gains measured on the tasks the loop was tuned on shrink on held-out tasks, and a harness tuned for one model can collapse under another.
