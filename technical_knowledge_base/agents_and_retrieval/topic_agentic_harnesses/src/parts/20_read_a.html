1. The loop: a model call, a tool call, repeat

A model call. A language model is a function from text to text. The text goes in as tokens (word pieces, about four characters of English each), and the model generates new tokens one at a time until it decides to stop. It keeps no memory between calls: to "continue a conversation", the caller sends the whole conversation again every time. The maximum it can read in one call is its context window (200,000 tokens for Claude Haiku 4.5, as the CLI's own result record reports MEASURED).

A tool call. A tool is a function the harness offers the model, described by a name, a sentence of description and a JSON schema for its arguments, for example Bash {command} or Read {file_path}. Instead of answering in prose, the model can reply with a structured tool call: on the Anthropic API a tool_use block with stop_reason: "tool_use"; on OpenAI's, a function_call item. The harness runs the function and sends the output back as a tool result in the next request. Put the call in a loop and you have an agent:

messages = [system prompt, task]
while True:
  reply = model(messages, tools)
  if reply has no tool call: break   # the model says it is done
  result = run(reply.tool_call)   # after a permission check
  messages += [reply, result]

That is the whole core; what makes a harness good is everything around those six lines. The one rule the loop cannot do without is the action boundary: the model's turn must end at its action, or the model writes the tool's result itself, as Haiku did in the {{Loop lab|#t-loop}} when nothing stopped it. A provider's tool-calling API enforces the boundary; a text protocol must enforce it with a stop sequence ({{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}} section 2).

Claude Code's loop, 12 model calls in seven stretches

  1. Enter. The harness sends the system prompt, six tool definitions and the task. The window already holds 13,242 tokens on the first call, before the model has read a single file: the fixed cost of this harness (section 3).
  2. Calls 1 to 6: looking around. find, ls, the test file, the package, __init__.py, core.py. Reading a file puts its whole text into the history: by call 6 the request is 14,775 tokens.
  3. Call 7: an error, returned as is. python tests/test_core.py gets command not found: python back as an ordinary error result, and the model reads it like any other result.
  4. Call 8: the tests run. python3 shows both failures, 2 failed: the information the single call never had.
  5. Calls 9 and 10: two exact-string edits to the library: one keeps apostrophes inside words, one breaks ties alphabetically.
  6. Call 11: the tests again. 0 failed.
  7. Call 12: done. No tool call: the model answers in text, so the loop ends. Twelve model calls, 31 seconds, about $0.039 at list prices; both bugs fixed, verified by the tests MEASURED.
  1. Step 0: no loop. The source file is pasted into one prompt: 635 input tokens. The model never sees the tests.
  2. One answer. Haiku 4.5 replies in 7.9 seconds with 731 output tokens (475 of them thinking) and fixes the tie-breaking in top_words.
  3. Graded afterwards. One test still fails MEASURED: nothing in the prompt said apostrophes must survive, and the model had no way to run anything and find out.

Nothing was wrong with the model: it was missing information that only running the code could give it. The loop spent six calls finding its way around, recovered from one error and fixed both bugs in two edits.

Where the loop and tool calling came from
ReAct (Yao et al., October 2022) interleaved free-text thoughts with actions and observations in one prompted loop, and beat reasoning-only and acting-only baselines; every modern agent loop descends from it ({{ReAct paper page|n:3c65c17b0d0d816b9a24c28de8f08ea8}}). Toolformer (Schick et al., February 2023) showed a model teaching itself API calls from a few demonstrations, and OpenAI announced on 13 June 2023 (archived post) that its 0613 models "have been fine-tuned" to detect when a function should be called and to answer with JSON matching its signature SOURCE. Models call tools reliably because they are trained to. Both request shapes, Anthropic Messages and OpenAI Responses, are laid side by side in the {{Loop lab|#t-loop}}'s API section.
