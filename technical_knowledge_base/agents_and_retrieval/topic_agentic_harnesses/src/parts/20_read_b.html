2. Tools: the agent's only hands and eyes

The model can only act through the tools it is given, and it only learns about the world through what those tools return. A coding harness therefore needs, at minimum, a way to look (read, list, search), a way to change things (edit or write a file) and a way to check (run a command, above all the tests); Claude Code's docs group its built-in tools into file operations, search, execution, web and code intelligence, plus tools for subagents and questions to the user (docs); our recorded runs passed six: Read, Edit, Write, Bash, Grep, Glob. The SWE-agent paper (Yang et al., May 2024) named the tool set the agent-computer interface (ACI): the same model scored differently depending on how its file viewer, search and edit commands were shaped, and with an interface designed for it reached 12.5% on SWE-bench, then the state of the art (arXiv 2405.15793) SOURCE.

Where harnesses differ. At one end, mini-SWE-agent's only tool is bash, it does not use the model's tool-calling interface at all, and its README reports more than 74% on SWE-bench Verified with a strong model behind it (README, read 5 Oct 2026) SOURCE. At the other, Claude Code ships dozens of dedicated tools. With a strong model a shell is a universal tool; dedicated tools earn their place by being cheaper, safer to gate, or easier to verify. And every definition is input the model reads on every call: Claude Code's first call on Haiku 4.5 measured 6,653 tokens with no tools, 13,219 with the six above and 21,140 with its default set MEASURED (the {{Trace and context lab|#t-trace}}, Context lab 1). Tools from outside the harness arrive through MCP, the protocol by which a harness discovers and calls external tool servers ({{MCP page|n:3c65c17b0d0d813f9695dc4175c44cbb}}); Claude Code defers their definitions behind a tool search ({{Claude Code|n:3c65c17b0d0d81db9c7fc54987c1ab65}} section 10).

3. Context: what the model sees on each call

The model knows only what is in the request. Each call, the harness assembles it from four kinds of material, in this order: the system prompt, the tool definitions, memory files loaded at start (Claude Code reads CLAUDE.md, and also AGENTS.md, the cross-vendor convention other harnesses use), and the history: the task, every earlier reply, every tool call and every tool result. The first three are a fixed prefix; the history grows by one reply and one result per turn. The window bar in section 1's replay is exactly this: 13,242 tokens of prefix on call 1, 17,155 tokens by call 12 MEASURED.

Anthropic calls the work context engineering, "the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference", because as the window fills the model's ability to recall what is in it decreases (29 Sep 2025). The levers, cheapest first, each owned by a section of {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}: prompt caching and the order of the request (2), clipping tool output (3), compaction (4), memory files and skills loaded on demand (5), subagents with their own window (6), notes outside the window (7), memory layers such as Mem0, Graphiti and Letta (8), and context rot as the window fills (9).

The one lever every harness comparison needs: prompt caching. The prefix repeats on every call, so providers cache it: a cache read on Haiku 4.5 costs $0.10 per million tokens against $1 for fresh input. In the replayed run 177,132 of 181,145 input tokens were cache reads; billed as fresh input the same run would have cost about $0.195 instead of $0.039 (derived: same tokens, list prices) MEASURED. Caching works only if the prefix stays byte-identical, which is why a home-made harness that resends its transcript as one growing block of text got 0 cache reads in the {{Loop lab|#t-loop}} and, in section 7, cost twice what Claude Code cost for the same result.

Research on memory that this root only points to: read-time memory curation ({{Just-in-Time Memory|n:3e95c17b0d0d818f89b3f066f816727b}}), a second model that reminds the agent of what it dropped ({{Proactive Memory Agent|n:3e25c17b0d0d81ce85e0c6d82f6beb4c}}), and why skills help and when they misfire ({{Demystifying Agent Skills|n:3c65c17b0d0d81249a3cf5fda4de5d92}}). Retrieval is {{rag-and-retrieval|n:3c65c17b0d0d81b89145c37dfe8a3b0b}}.
