2. Tools: the agent's hands and eyes

The problem. The model can only act through the tools it is given, and it only learns about the world through what those tools return. A coding harness therefore needs, at minimum, a way to look (read a file, list or search files), a way to change things (edit or write a file) and a way to check (run a command, above all the tests). Claude Code's docs group its built-in tools into file operations, search, execution, web and code intelligence, plus tools for subagents and questions to the user (docs). Our recorded runs passed six: Read, Edit, Write, Bash, Grep, Glob.

Tools are an interface designed for a very literal user. The SWE-agent paper (Yang et al., May 2024) named this the agent-computer interface (ACI): the same model scored differently depending on how its file viewer, search and edit commands were shaped, and with an interface designed for it reached 12.5% on SWE-bench, then the state of the art (arXiv 2405.15793) SOURCE. Anthropic's tool-writing guide (11 Sep 2025) lists the rules that followed: choose few tools that match real tasks rather than wrapping every API endpoint; namespace them; return meaningful context, not internal ids; keep responses token-efficient ("For Claude Code, we restrict tool responses to 25,000 tokens by default"); and treat the description as a prompt, because it is one.

Names and descriptions

The model picks a tool from its name and description alone. Overlapping tools (three ways to search) cost tokens on every call and invite the wrong choice.

Errors the model can act on

"command not found: python" told our run exactly what to change. "Error 1" would not have. Exit codes and the failing line belong in the result.

Output size

The Loop lab made the test runner noisy on purpose: the verdict sat at lines 92 to 95 of about 240, and a naive head-and-tail cut removed it. Put the verdict first, clip the rest, say what was clipped MEASURED.

Edit format

How the model writes a change: the whole file, search-and-replace blocks, or a unified diff. Aider documents six formats and picks one per model (edit formats). Claude Code's Edit replaces an exact old_string with a new_string, as the recorded edits show.

The minimal end of the range. mini-SWE-agent's agent class is "some 100 lines of python", its only tool is bash, it does not use the model's tool-calling interface at all, and its README reports more than 74% on SWE-bench Verified (README, read 5 Oct 2026; the score depends on the model behind it) SOURCE. With a strong model, a shell is a universal tool; dedicated tools earn their place by being cheaper, safer to gate, or easier to verify.

The cost. Every tool definition is input the model reads on every call. Claude Code's first call on Haiku 4.5 measured 6,653 tokens with no tools, 13,219 with the six above and 21,140 with its default set MEASURED (the {{Trace and context lab|#t-trace}}, Context lab 1). Tools from outside the harness arrive through MCP, the protocol by which a harness discovers and calls external tool servers ({{MCP page|n:3c65c17b0d0d813f9695dc4175c44cbb}}); Claude Code now defers MCP tool definitions and loads them on demand through a tool search, because a few servers can add thousands of tokens of definitions.

Go deeper: the Loop lab's steps 1 to 4 add read, test, edit and output clipping one at a time, each recorded; the frameworks root shows how six libraries declare the same tools.
