Permission gate decisions

The root Loop lab builds a permission gate in its step 3 (deny rules first, then allow rules, unmatched = ask, and ask = deny when nobody is at a terminal). This tab runs that gate's real check(), with no model, on a fixed set of actions: the task's own legitimate work plus a few clearly-dangerous ones. Every verdict is the gate's actual output; nothing was executed. This is the {{root's Loop lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} gate table reused, not a re-recording.

The column that teaches the lesson is depends on: what each verdict actually rests on. A deny list names the dangerous actions its author thought of; the fail-closed default (unmatched = deny) catches the ones nobody foresaw. A gate that defaulted to allow would protect you only against the words on the list.
