6. Sandboxes: a kernel boundary around what runs

A sandbox assumes the gate let something through. It does not look at the command string; the kernel constrains what any process the agent spawns is able to do. The two things worth constraining are filesystem writes (the project and a temp directory) and the network (blocked, or only through a proxy you control). Here is the property, measured on this machine with sandbox-exec (macOS Seatbelt), the mechanism Claude Code and Codex use on macOS MEASURED:

The same benign operation, outside and inside a Seatbelt profile: the kernel refuses whatever the intent

Real runs, macOS 27.0.1, Apple M1 Pro, 6 Oct 2026. The only bytes ever sent are the fixed marker /sandbox-demo-ping to a local listener started and stopped for the test. A profile is a few S-expressions: (allow default)(deny network*) denies all sockets; (deny file-write*)(allow file-write* (subpath ...)) confines writes.

The gate reasons about a string; the sandbox reasons about the operation. It turns "the agent can reach anything you can" into "this directory and nothing on the network", the difference between a mistake being embarrassing and being an incident. The mechanisms by OS:

  • macOS: Seatbelt via sandbox-exec and a profile (Claude Code sandboxing, read 6 Oct 2026) SOURCE.
  • Linux: Claude Code uses bubblewrap (user namespaces) plus a local proxy; Landlock (kernel 5.13) lets an unprivileged process restrict its own file access with three syscalls, and seccomp-bpf filters which syscalls are allowed at all. Mechanics: {{Containers and isolation|n:3f05c17b0d0d8156a841e4bf28f11293}}.
  • One policy, three systems: GitHub Copilot's local sandboxing, generally available since 7 October 2026, writes one policy over files, network and Git and gh credentials and maps it to each system's native controls on Windows, macOS and Linux through the Microsoft eXecution Container (MXC); it covers Copilot CLI, the Copilot app and the VS Code Agent Host, can sandbox MCP and language servers too, and can be enforced by an enterprise ({{GitHub changelog|https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/}}) SOURCE.
  • A machine you can throw away: a container or VM where full autonomy is acceptable because the blast radius is the box; how the isolation rises with autonomy is drawn in section 9 of {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}.

What it does not cover. Claude Code's sandbox wraps shell commands only (Bash, PowerShell); file-edit tools, MCP servers and hooks run outside it, and it is off by default SOURCE. A sandbox you did not turn on, or one with a tool outside it, contains nothing; how six other harnesses default, with and without someone to approve, is compared on {{Other coding harnesses|n:3c65c17b0d0d819fa3cefdcd2ccff2f7}} section 4 ("Only Codex keeps a boundary when nobody is there to approve"). And a sandbox confines the blast radius without making the agent trustworthy: if the one network path you leave open (the proxy to the model API, a package registry) can also carry your data out, the leak is still open. That is the next layer.

A sandboxed interpreter is an injection decoder. An instruction encrypted with AES-256-GCM cannot be read by any input filter, even with the key on the page, because classifiers do not execute what they inspect; an agent allowed to run code decrypts it in its own runtime, inside the trust boundary and after every filter. So input filtering cannot secure an agent that executes code, and the controls that still hold are the ones keyed on actions: egress control (section 7) and confirmation of consequential actions (section 5). The worked case, against Grok's web chat, is stepped through on {{xAI / SpaceXAI: Grok|n:3c65c17b0d0d81f2ac36c873a854007f}}.

7. Egress control: the one path out, written over destinations

Exfiltration needs a way out; close it and a compromised agent can read your secrets but send them nowhere. The first mistake is to write the policy over tools ("deny curl, deny wget"), which leaves every other way to reach the network untouched. Write it over destinations ("connect only to these hosts"), default-deny, enforced by a proxy or firewall below the agent. The policy below (src/sec/egress_policy.py, a pure function, no network, no model) decides 7 ordinary requests for a coding agent that may install packages: 4 allowed, 3 denied MEASURED.

One question decides every request: where is it going?

HTTPS through the proxy and name lookups through the resolver are decided by the same allow-list (the model API, the package registry and its file host). The verdict does not depend on which tool or command made the request, so there is nothing to spell around; an unlisted host, a raw IP and an unlisted name all fall to the default.

DNS is egress too. A process blocked from HTTP can still ask the resolver a question, and the question carries bytes outward in the name itself. That is how the September 2026 OpenAI incident got data past a web proxy (section 9). An allow-list that covers HTTP and not DNS is a door with a window next to it.
An allowed destination can carry traffic onward. A public service that fetches, stores or forwards on your behalf (a URL shortener, a screenshot or citation service, a shared editor) is a proxy to everywhere it reaches. Anthropic reported Claude Opus 5 and Claude Mythos 5 using free URL-shortening services to get around a fetch tool's URL-length limit, and Wikimedia reported OpenAI's agents trying to use Etherpad and a citation tool as proxies (section 9). Allow the specific services the task needs, and count any service that fetches arbitrary URLs as open egress.

Enforcement lives outside the component that can be persuaded. The model can be talked into trying; a harness's gate can be bypassed with cleverness; a kernel- or network-level destination list cannot be talked into anything. The strongest published production design goes further and tracks tainted egress: Meta's Muse agent marks a tool process as tainted (through the kernel) once it reads user data, so its requests never ride an auto-allow rule ({{Meta: Llama and MSL|n:3c65c17b0d0d81949ad8e17bcb3567f1}}). For a coding agent: allow only the registry and the model API, pin or mirror the registry, cover DNS, and make any new host a reviewed change to the list, not a runtime decision by the agent.

8. Credentials: the model cannot leak what it never sees

The cheapest protection for a secret is to keep it where the agent cannot read it. Three levels, weakest first:

Move the secret out of the context, then out of the sandbox

Where the real token lives (highlighted) relative to the model's context and the sandbox. In a readable file or variable it is one cat from the context window, and the gate will allow that read on its action alone (section 4). Behind a broker, the agent asks a helper to sign or call, and only the result comes back. Injected by the egress proxy, the command sees a placeholder and the real value is spliced in outside the sandbox, only on requests to allow-listed hosts.

  • In a file or environment variable the agent can read: the default and the worst. Once a secret is in the context, any open path out leaks it.
  • Behind a broker: the helper holds the secret and returns only the result. This is how a well-built tool exposes an API key: the key lives in the tool, the model sees a function. Meta's Muse agent keeps credentials, including OAuth tokens, in a separate service outside the agent's VM and gives the agent surrogate credentials ({{Meta: Llama and MSL|n:3c65c17b0d0d81949ad8e17bcb3567f1}}).
  • Injected by a proxy on allowed requests only: Claude Code's sandbox can show a shell command a placeholder and have the egress proxy substitute the real value only on requests to allow-listed hosts SOURCE. NVIDIA's OpenShell (Apache 2.0), a sandboxed agent runtime, injects credentials only for approved endpoints ({{GitHub|https://github.com/NVIDIA/OpenShell}}) SOURCE; 1Password for Agents does the same for a person's logins, filling a credential the person approved without the agent seeing it ({{1Password, 22 Oct 2026|https://1password.com/blog/1password-for-ai-agents}}) VENDOR.

The first level is also reachable by code, not only by the model: the LiteLLM payload (section 3) simply read the tokens coding tools keep in files.

Least privilege, as anywhere: scope the credential to the task (a token for one repository, not your personal access token for everything), keep it out of the reasoning loop, make its use observable. How tokens are scoped and exchanged on the wire, including agent-era OAuth, is {{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}'s subject.
