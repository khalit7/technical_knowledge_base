Common mistakes

"Codex works with any OpenAI-compatible server."
Only with servers that speak the Responses API. Chat completions support was removed (wire_api = "chat" is an error). Use a Responses-capable server or a translating gateway, as section 2 did.
Running gemini -p and wondering why nothing was edited.
Headless Gemini CLI denies anything that would need approval. Pass --yolo or --approval-mode auto_edit, ideally inside -s.
Adding a local model to opencode without limit.context.
Auto-compaction never fires for it, and the session fails when the window fills.
Letting a text-protocol model run without a stop at the action.
It writes the observation too, and believes it (section 1). Use native tool calls or a stop sequence; a client-side cut only stops you acting on the invention.
Treating "the model stopped calling tools" as "the task is done".
opencode and Codex both ended our runs on a prose reply with the tests still failing. Verify with the tests, as Aider's --auto-test does, before reporting success.
Comparing harnesses from one run each.
Our tables are one run per setting on one task with a 4B model: enough to see mechanisms, not to rank products. Fix the model and effort, repeat runs, report cost beside the score.

Interview questions

What is the action boundary, and who enforces it?
The point where the model must stop generating so the harness can run the action and return the real result. With native tool calls the inference server enforces it (the reply ends with a tool-call finish reason); with text actions the harness must, by a stop sequence or by training plus the chat template. Without it, the model writes invented results.
mini-SWE-agent runs every command in a fresh subprocess. Why, and what does it cost?
Independent actions make sandboxing a one-line swap (docker exec) and runs easy to parallelise and replay. The cost: no persistent shell state, so cd and export must be repeated in each command.
Compare three compaction designs.
Codex: summarise at 90% of the window, keep recent user messages (server-side for OpenAI models). Gemini CLI: at 50%, summarise the oldest 70% into a state snapshot, then a second call critiques it. opencode: at the usable window, keep a recent tail of 25% (2k to 15k tokens) verbatim. Earlier and two-pass costs tokens but keeps more working room and a better summary.
How would you sandbox an agent's shell on macOS and on Linux?
macOS: Seatbelt profiles via sandbox-exec, deny by default, write only to the workspace, network off (Codex, Gemini CLI -s). Linux: bubblewrap for the file system plus seccomp for the network (Codex), or a container. Keep it on in headless mode, where nobody approves.
SEARCH/REPLACE text, a str_replace tool, or a patch grammar?
Text blocks work with any model and batch many edits in one reply but need a parser and a format per model. A str_replace tool is simple and exact but fails on whitespace drift unless the harness adds matchers (opencode has nine, Gemini CLI four). A patch grammar (Codex) is compact for multi-file changes and can be enforced at decoding time, but the model must be trained on it.
Your agent repeats the same failing tool call. What do you add?
Detection in the harness: identical-call counting (Gemini CLI after 5, opencode after 3), then a nudge, then a stop or a question to the user; a step limit as the last resort. Also look at the tool: a clearer error message or a smaller schema may remove the cause (Codex's justification rule in section 2).
How does Aider decide what to show the model of a repository it cannot fit?
tree-sitter tags, a file graph weighted by identifier references, personalised PageRank toward the files in the chat and the names in the message, then a binary search for the most ranked definitions that fit the token budget. See the Repo map lab tab.
