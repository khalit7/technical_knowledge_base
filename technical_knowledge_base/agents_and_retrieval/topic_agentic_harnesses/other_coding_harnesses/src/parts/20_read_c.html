3. Gemini CLI (Google): guard rails around the loop

What it is. Google's open-source (Apache-2.0) terminal agent for Gemini models, announced 25 June 2025 ({{Google blog|https://blog.google/technology/developers/introducing-gemini-cli-open-source-ai-agent/}}). Read here: v0.62.0, the stable release of 29 September 2026. One fact changes who can use it: since 18 June 2026 Gemini CLI no longer serves the free Code Assist tier or Google AI Pro and Ultra subscribers, who were moved to the new Antigravity CLI; it remains for paid Gemini API keys, Code Assist Standard and Enterprise, and Vertex AI ({{Google Developers Blog, 19 May 2026|https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli}}). The repository's README and quota page still describe the old free tier below a banner announcing the change.

Loop
Split in two: GeminiClient runs one streamed model turn (compress if needed, check for loops, pick a model, stream), and the caller runs the tools and sends results back; in headless mode that caller is a while (true) in {{nonInteractiveCli.ts|gm:packages/cli/src/nonInteractiveCli.ts#L311-L330}}. A reply with no tool call ends the run. Session turns are unlimited by default (maxSessionTurns -1). Tools run in parallel by default; every tool schema gets an injected wait_for_previous argument the model sets to serialise a call, and file edits always run one at a time ({{scheduler.ts|gm:packages/core/src/scheduler/scheduler.ts#L561-L578}}).
Loop detection
The guard Codex lacks: the same tool call five times in a row, or a 50-character chunk of text repeated ten times, counts as a loop; after 30 turns a separate model call also checks for "unproductive" loops every 5 to 15 turns and needs 0.9 confidence. The first detection injects a nudge, the second stops the turn ({{loopDetectionService.ts|gm:packages/core/src/services/loopDetectionService.ts#L29-L65}}).
Tools
About 17 reach the model in a default interactive session (15 in our headless run): read_file, list_directory, glob, grep_search (ripgrep), replace, write_file, run_shell_command, web_fetch, google_web_search, write_todos, invoke_agent (subagents), activate_skill and others ({{config.ts|gm:packages/core/src/config/config.ts#L4008-L4125}}). Two often-listed tools are not model-visible in this version: read_many_files serves only the @file syntax, and save_memory is gone: the prompt tells the model to edit GEMINI.md with the ordinary file tools. Shell output over 40,000 characters is saved to a file and truncated; read_file stops at 2,000 lines.
Edits
replace(file_path, instruction, old_string, new_string, allow_multiple) tries four matchers in turn: exact; "flexible" (each line compared with its whitespace trimmed, the replacement re-indented); a regular expression with \s* between tokens; then a fuzzy sliding window that accepts a weighted Levenshtein distance of up to 10% of the search length ({{edit.ts|gm:packages/core/src/tools/edit.ts#L67-L69}}). The second-model "edit correction" that older write-ups describe still exists but is off by default (disableLLMCorrection: true, {{config.ts|gm:packages/core/src/config/config.ts#L1141}}).
Context
GEMINI.md files from ~/.gemini, then from each trusted root up to the git root; a GEMINI.md in a subdirectory is loaded only when a tool first touches that directory, and files can @import others five levels deep. Compression starts when a prompt reaches 50% of the window: the oldest 70% of the history becomes an XML <state_snapshot>, then a second "probe" call asks the model to critique and improve its own summary ({{chatCompressionService.ts|gm:packages/core/src/context/chatCompressionService.ts#L332-L410}}). Two calls per compression, at half the window: Google trades tokens for a better summary.
Safety
Approval modes default, auto_edit, plan and yolo, decided by TOML policy files: read-only tools are allowed, edits and the shell ask ({{write.toml|gm:packages/core/src/policy/policies/write.toml#L52-L55}}). Headless runs have nobody to ask, so the engine's default is deny: gemini -p without --yolo or --approval-mode auto_edit cannot edit or run anything ({{policy-engine.ts|gm:packages/core/src/policy/policy-engine.ts#L298-L301}}). The sandbox is off by default; -s relaunches the whole CLI inside macOS Seatbelt (profile permissive-open: writes only to the project, temp and cache folders, network open), or Docker, Podman, gVisor or LXC on Linux ({{sandbox.ts|gm:packages/cli/src/utils/sandbox.ts#L121-L130}}).
Extend
MCP servers, hooks (11 events: BeforeTool, AfterTool, BeforeModel, AfterModel, PreCompress and others), skills, subagents (local and remote over A2A), and extensions: a folder with a gemini-extension.json that bundles MCP servers, context files, commands, hooks and skills, installed from a GitHub URL.
Our run MEASURED

Gemini CLI speaks only the Gemini API, so the local model sat behind the same LiteLLM gateway, which also serves Gemini-style generateContent routes. Getting there took three fixes that teach something. Setting GOOGLE_GEMINI_BASE_URL makes the CLI pick its "gateway" sign-in type, which its own validator then rejects ("Invalid auth method selected"; {{auth.ts|gm:packages/cli/src/config/auth.ts#L10-L48}}); choosing the API-key sign-in in the settings keeps the custom base URL. In a folder it does not trust, the CLI printed "Approval mode overridden to "default" because the current folder is not trusted", which in headless mode means every edit is denied, --yolo or not. And its HTTP client waits only 60 seconds for response headers ({{fetch.ts|gm:packages/core/src/utils/fetch.ts#L33-L34}}) and retries a failed request up to 10 times ({{retry.ts|gm:packages/core/src/utils/retry.ts#L20}}): against a slow shared local server, each retry piled another 11,000-token prompt onto the server, and on our first attempt the overlap crashed it. We serialised every request in our proxy and ran it again.

The run itself: 6 calls inside Seatbelt. The first request was the largest of all six harnesses: 32,924 characters of system prompt and 15 tools in 17,722 characters, 11,452 tokens (counted afterwards with the model's own chat template, because the gateway's stream carried no usage; the same count reproduces the server's numbers on the opencode run exactly). The model's first reply made four tool calls at once (a topic note, a directory listing and two file reads), fixed top_words with replace, ran the tests, saw one failure left, and then returned an empty reply, which ends the loop. One bug of two fixed.

What to steal. Detect loops in the harness, cheaply first (identical calls) and with a model only later; make headless mode deny by default; and when you compress, keep the newest part verbatim.
