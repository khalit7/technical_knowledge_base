3. How an edit is applied: the format and the matcher ladder

An edit names text to find and text to put in its place. Models copy the "find" text imperfectly (indentation, trailing spaces, typographic quotes), so each harness tries a matcher ladder, ever looser ways to find it, and differs in what it does when every rung fails. That second choice decided two of our runs.

From nine fallbacks to none: how hard each harness tries to find the text, and what it says when it cannot

One square per matcher, tried left to right until one finds a unique match; on the right, what the model is told when none does. Read from source at the pinned versions (links below).

  • Codex apply_patch: exact, then ignoring trailing spaces, then trimmed, then with typographic dashes and quotes mapped to ASCII ({{seek_sequence.rs|cx:codex-rs/apply-patch/src/seek_sequence.rs#L39-L110}}). The first match wins, and a hunk is searched for only after its @@ line.
  • Gemini CLI replace: exact; "flexible" (each line compared with its whitespace trimmed, the replacement re-indented); a regular expression with \s* between tokens; then a fuzzy sliding window accepting a weighted Levenshtein distance of up to 10% of the search length ({{edit.ts|gm:packages/core/src/tools/edit.ts#L67-L69}}). The second-model "edit correction" older write-ups describe exists but is off by default (disableLLMCorrection: true, {{config.ts|gm:packages/core/src/config/config.ts#L1141}}).
  • opencode edit: nine matchers: exact, line-trimmed, block-anchor (first and last line fixed, the middle scored by Levenshtein similarity, threshold 0.65), whitespace-normalised, indentation-flexible, escape-normalised, trimmed-boundary, context-aware and multi-occurrence ({{edit.ts|oc:packages/opencode/src/tool/edit.ts#L682-L737}}); a comment credits Cline and Gemini CLI for the ideas. After each edit, language-server diagnostics for the file are appended to the tool result, so the model sees a type error in the same turn.
  • Aider SEARCH/REPLACE: exact, or after small fixes (leading whitespace, a stray blank line, ... elision); the edit-distance matcher many describe sits after an unconditional return and never runs ({{editblock_coder.py 157 to 187|ai:aider/coders/editblock_coder.py#L157-L187}}). A block that fails comes back with a "Did you mean" snippet of the closest lines.
  • OpenHands file_editor str_replace: old_str must match once; the only retry strips surrounding whitespace ({{editor.py|oh:openhands-tools/openhands/tools/file_editor/editor.py#L200-L242}}). The tool also does view, create, insert and undo_edit.
  • mini-SWE-agent: no edit tool; files are edited with sed and heredocs, as the prompt teaches. A pattern that matches nothing exits 0 and prints nothing.

What the recordings show MEASURED. OpenHands' model found both bugs, then sent str_replace five times with an old_str indented one level too deep and missing two of the docstring's three closing quotes; each came back "No replacement was performed, old_str ... did not appear verbatim", a clear error the model could not act on, until our 30-iteration cap. mini-SWE-agent's model ran sed -i 's/return sorted(counts.items(), key=lambda kv: -kv[1])[:n]/.../' six times: in sed's pattern language [1] and [:n] are character classes, not literal brackets, so nothing matched, sed exited 0, and the model never learned why. A loud refusal at least tells the model something; a silent no-op tells it nothing. This is the agent-computer-interface argument (tools designed for a model as the user: {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}' section 5): a bash-only harness relies on the model knowing sed; strong models do, a 4B model did not.

Forgiving has a cost too: on a 4B model's unified diffs, Aider's udiff applier applied 8 of 10 where git apply refused almost all, but 6 of those 8 failed the check (Building a harness, its "Edit format bench" tab, which also ran Codex's matcher and saw a model put the line it was changing on the @@ line, so the line to remove could never be found).

The @@ line names a context anchor, not line numbers, so a patch survives small shifts in the file.

Aider's edit formats, and what whole-file against diff cost on our task

Aider picks the format per model: diff (SEARCH/REPLACE), whole (reprint the file), udiff, diff-fenced, a V4A patch format like Codex's, and editor-* variants for architect mode ({{edit formats|https://aider.chat/docs/more/edit-formats.html}}); an unknown model, such as a local one, defaults to whole ({{models.py|ai:aider/models.py#L129}}). With whole our model reprinted core.py with both fixes at once (3 calls, 42 s); its first request was 879 prompt tokens against 2,655 for diff, because the SEARCH/REPLACE instructions and worked examples are long (5,407 characters of system prompt against 1,191). With diff (7 calls, 138 s) it fixed top_words, Aider committed and ran the tests, sent back the one remaining failure, and the model fixed tokenize; two calls wrote commit messages and two identical calls summarised the history.
