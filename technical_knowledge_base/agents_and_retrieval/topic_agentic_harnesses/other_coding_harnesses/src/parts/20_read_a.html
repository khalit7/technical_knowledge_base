1. How the model writes an action: tool calls or text

Five of the six send tool definitions (name, description, JSON schema) and get back a structured call; the API ends the reply there with a finish reason (tool_calls in the OpenAI format, tool_use in Anthropic's), so the inference server enforces the action boundary. Aider, and mini-SWE-agent's opt-in text mode, use text actions instead: Aider's SEARCH/REPLACE blocks, or exactly one ```mswea_bash_command block per reply, found by a {{regex|ms:src/minisweagent/models/litellm_textbased_model.py#L8}}. Text works with any model that writes text, which is why Aider chose it in 2023, before OpenAI shipped function calling on 13 June 2023 ({{OpenAI|https://openai.com/index/function-calling-and-other-api-updates/}}). The cost: now the harness must stop the model at its action. Why and how is {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}' section 2; here is what each choice did on our task.

Aider does not need the stop: its protocol is "reply once, with the edits", so the model never waits for an observation inside a reply. A loop that does (run ls, see the listing, decide) needs a server-side stop: a stop sequence, or the chat template's end-of-turn token, which an open model emits after an action because it was trained to. claude -p, the only route to Claude here (a subscription, no API key), has no stop-sequence option. So mini-SWE-agent's text mode ran with Claude Haiku 4.5 twice through a small adapter: reply passed through untouched, and reply cut right after the first action block.

What it buys. A client-side cut stops the harness from acting on invented output; it does not stop the model from believing it. Only a real message list with a server-side stop does. Aider, whose protocol needs no observation inside a reply, fixed both bugs through the same adapter in 3 calls and 25 s (section 3). The local 4B model never invented output in text mode: it ran behind a chat server whose template ends the turn with an end-of-turn token after one action, so training plus the template gave the boundary, not the harness. The parent's Loop lab met the same wall (Haiku once ran on for 95,162 characters until the harness kept only the text up to the first action).


The cost on the tool-call side is schema surface: every optional field with a rule attached is one more way for a weak model to fail. Codex gave our local model 12 tools; on its first call the model filled the optional justification argument of exec_command with an empty string, Codex answered "justification requires an explicit sandbox_permissions" ({{handlers/mod.rs line 101|cx:codex-rs/core/src/tools/handlers/mod.rs#L95-L105}}), and the model resent the same call three more times. OpenHands injects a required security_risk field into every tool that changes something; our model once misspelt it security_rika, which the schema rejected.
