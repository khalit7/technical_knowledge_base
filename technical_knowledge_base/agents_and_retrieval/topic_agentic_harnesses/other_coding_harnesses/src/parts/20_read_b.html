2. What stops the loop, and what catches a loop that will not stop

Three of the six end when a reply has no tool call (Codex, Gemini CLI, opencode), with no step cap by default. OpenHands ends on a finish tool or plain text, caps at 500 iterations, and answers an empty reply with "Please use a tool to proceed with the task." mini-SWE-agent ends when a command's output starts with the line COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT and exits 0 (the check is on the output, not the command text: {{local.py 45 to 56|ms:src/minisweagent/environments/local.py#L45-L56}}). Aider has no agent loop: one reply, its edits applied, then lint and tests, and at most 3 "reflected" retries carrying the errors ({{base_coder.py 924 to 945|ai:aider/coders/base_coder.py#L924-L945}}); the human is the outer loop.

The guards differ more than the stop rules. Gemini CLI counts the same tool call five times in a row, or a 50-character chunk of text repeated ten times, as a loop; after 30 turns a separate model call checks for "unproductive" loops every 5 to 15 turns and needs 0.9 confidence; the first detection injects a nudge, the second stops the turn ({{loopDetectionService.ts|gm:packages/core/src/services/loopDetectionService.ts#L29-L65}}). opencode's doom-loop guard turns three identical tool calls in a row into a permission question ({{processor.ts|oc:packages/opencode/src/session/processor.ts#L29-L379}}). OpenHands' stuck detector scans the last 20 events for repeated action and observation pairs, nudges once, then stops. mini-SWE-agent ends a run after three consecutive format errors and at a $3 cost limit. Codex has none: nothing stops a repeating call.

How each recorded run ended: the stop rule decided more outcomes than the model did

One square per model call, in order MEASURED, classified from the recordings by src/derive_ends.py: acted and got a real result; acted and got an error or a refusal; acted with a sed that exited 0 and printed nothing (a silent no-op); replied with prose or nothing; a side call (session title, commit message, history summary); a subagent's call. The end reason is on the right. Codex: four refused calls, then prose hit the 2,048-token cap. Gemini CLI: an empty reply ends the loop. opencode: prose describing the fix, no edit call. OpenHands: our 30-iteration cap. mini-SWE-agent (tool calls): three replies in a row with no tool call. Click a row to open the run call by call.

What it buys. "A reply with no tool call means done" is cheap and model-agnostic, but it cannot tell finishing from explaining: opencode and Codex both ended our runs on prose with both tests still failing, and Gemini CLI on an empty reply with one left. Aider's rule is the opposite, the harness runs the tests (--auto-test) and feeds back only the failure, and it was the only one to finish. A stop rule that consults a verifier is worth more than a smarter model here; the general case is {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}' section 10. And a guard needs a cheap first stage: Codex's repeated justification call (section 1) is exactly what opencode's three-in-a-row rule or Gemini CLI's five-in-a-row rule would have caught.

Each loop, read from source
Codex CLI
run_turn samples the model, runs any tool calls, sends their output back and repeats; a reply with no tool call ends the turn, unless a Stop hook objects and injects a continuation ({{turn.rs 150 to 170|cx:codex-rs/core/src/session/turn.rs#L150-L170}}). There is no step or turn limit; when the window fills mid-task it compacts and keeps going ({{lines 601 to 650|cx:codex-rs/core/src/session/turn.rs#L601-L650}}). Every request allows parallel tool calls; a read-write lock lets tools that declare themselves parallel-safe run together ({{parallel.rs|cx:codex-rs/core/src/tools/parallel.rs#L205-L209}}).
Gemini CLI
Split in two: GeminiClient runs one streamed model turn (compress if needed, check for loops, pick a model, stream), and the caller runs the tools and sends results back; in headless mode that caller is a while (true) in {{nonInteractiveCli.ts|gm:packages/cli/src/nonInteractiveCli.ts#L311-L330}}. Session turns are unlimited by default (maxSessionTurns -1). Tools run in parallel by default; every tool schema gets an injected wait_for_previous argument the model sets to serialise a call, and file edits always run one at a time ({{scheduler.ts|gm:packages/core/src/scheduler/scheduler.ts#L561-L578}}).
opencode
runLoop reloads the session's messages from its database on every pass, makes one streamed model call, runs the tool calls, and stops when the last reply has no tool call ({{prompt.ts|oc:packages/opencode/src/session/prompt.ts#L1081-L1130}}). No step limit unless an agent sets steps. Malformed calls are repaired: wrong-case tool names are fixed; unknown ones go to a hidden invalid tool that returns an error instead of crashing the turn.
Aider
Coder.run() takes one user message; run_one() sends it, applies the edits in the reply, commits, runs the linter and (if asked) the tests, and if anything failed sends a "reflected" message with the errors. The model never calls a tool, and shell commands it suggests in a ```bash block need an explicit yes: --yes-always answers no to them ({{io.py|ai:aider/io.py#L866-L867}}).
OpenHands SDK
A Conversation owns a list of typed events (messages, actions, observations, condensations), and LocalConversation._run() repeats: check status, check the stuck detector, call agent.step(), check confirmation, budget and the iteration cap ({{local_conversation.py|oh:openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L1917-L2045}}). Because state is an event log, a conversation can be persisted, resumed and replayed.
mini-SWE-agent
DefaultAgent.run() renders two messages (system, task), then repeats step() = execute_actions(query()) until a message with role exit appears ({{default.py 88 to 128|ms:src/minisweagent/agents/default.py#L88-L128}}). The whole agent class is 190 lines at v2.4.6 (the README still says "some 100 lines"). Limits: steps unlimited by default, cost limit $3, three consecutive format errors ({{lines 26 to 33|ms:src/minisweagent/agents/default.py#L26-L33}}). Control flow is by exceptions: a format error, a limit or a submission each raises, and its message is appended to the history.
