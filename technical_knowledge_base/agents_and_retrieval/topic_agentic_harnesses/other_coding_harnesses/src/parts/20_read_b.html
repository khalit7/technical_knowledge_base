2. Codex CLI (OpenAI): the operating system is the boundary

What it is. OpenAI's terminal coding agent, Apache-2.0. It launched in April 2025 written in TypeScript; on 30 May 2025 OpenAI announced it was going native, and the CLI is now a Rust workspace, codex-rs ({{discussion #1174|https://github.com/openai/codex/discussions/1174}}). 127,966 GitHub stars on 6 October 2026 ({{GitHub API|https://api.github.com/repos/openai/codex}}). "Codex" is also a cloud service and part of the ChatGPT desktop app (section 9); its documentation moved from developers.openai.com to {{learn.chatgpt.com/codex|https://learn.chatgpt.com/codex}}. Read here: tag rust-v0.160.1, released 5 October 2026.

Loop
run_turn samples the model, runs any tool calls, sends their output back, and repeats; a reply with no tool call ends the turn, unless a Stop hook objects and injects a continuation ({{turn.rs 150 to 170|cx:codex-rs/core/src/session/turn.rs#L150-L170}}). There is no step or turn limit; when the window fills mid-task it compacts and keeps going ({{lines 601 to 650|cx:codex-rs/core/src/session/turn.rs#L601-L650}}). Every request allows parallel tool calls; a read-write lock lets tools that declare themselves parallel-safe run together ({{parallel.rs|cx:codex-rs/core/src/tools/parallel.rs#L205-L209}}). It speaks only the Responses API: wire_api = "chat" is now a config error ({{model-provider-info|cx:codex-rs/model-provider-info/src/lib.rs#L97-L131}}).
Tools
For OpenAI's own models a test pins the default set: exec_command and write_stdin (a shell, with long-running processes on a pseudo-terminal), update_plan, request_user_input, apply_patch, view_image, tool_search (which loads MCP and multi-agent tools on demand) and web_search ({{prompt_caching.rs|cx:codex-rs/core/tests/suite/prompt_caching.rs#L268-L279}}). Tool output kept in history is cut to the model's limit (10,000 tokens for bundled models) plus 20%, keeping head and tail ({{history.rs|cx:codex-rs/core/src/context_manager/history.rs#L546-L554}}).
Edits
apply_patch is not a JSON function: it is a freeform tool whose input is constrained by a 19-line Lark grammar, so the model writes raw patch text that the server forces to parse ({{apply_patch.lark|cx:codex-rs/core/assets/tools/apply_patch.lark}}). Context lines are matched exactly, then ignoring trailing spaces, then trimmed, then with typographic dashes and quotes mapped to ASCII ({{seek_sequence.rs|cx:codex-rs/apply-patch/src/seek_sequence.rs#L39-L110}}).
Context
Instructions are per model; an unknown model gets the 20,903-byte fallback prompt ({{model_info.rs|cx:codex-rs/models-manager/src/model_info.rs#L98-L157}}). AGENTS.md: one file per directory from the git root down to the working directory (an AGENTS.override.md wins in its directory), 32 KiB in total ({{agents_md.rs|cx:codex-rs/core/src/agents_md.rs#L1-L18}}). Compaction at 90% of the window: OpenAI models compact on the server; others get a 426-byte "CONTEXT CHECKPOINT COMPACTION" prompt and a rebuilt history of the summary plus the most recent user messages ({{compact prompt|cx:codex-rs/prompts/templates/compact/prompt.md}}).
Safety
Two independent dials: a sandbox mode (read-only by default, workspace-write for a trusted folder, danger-full-access) and an approval policy (on-request by default, never, or granular) ({{config_toml.rs|cx:codex-rs/config/src/config_toml.rs#L826-L856}}). On macOS the sandbox is Seatbelt (sandbox-exec with four .sbpl profiles, deny by default); on Linux, bubblewrap for files plus seccomp for the network, with Landlock kept only as a deprecated fallback ({{linux-sandbox|cx:codex-rs/linux-sandbox/src/lib.rs#L1-L5}}). In workspace-write the network stays off unless you enable it. There is no longer a hard-coded list of safe commands: Starlark execpolicy rules decide allow, prompt or forbid, and the built-in "dangerous" check only knows forced rm ({{is_dangerous_command.rs|cx:codex-rs/shell-command/src/command_safety/is_dangerous_command.rs#L123-L151}}). codex exec (headless) forces the approval policy to never, so the sandbox is all that stands between the model and your machine ({{exec|cx:codex-rs/exec/src/lib.rs#L574-L576}}).
Extend
Hooks (12 events, including PreToolUse, PermissionRequest, PreCompact and Stop), MCP servers as a client, plugins, skills, subagents (up to 6 threads), and Python and TypeScript SDKs that drive the CLI over JSON lines. The codex mcp-server subcommand was removed in rust-v0.154.0 ({{release notes|https://github.com/openai/codex/releases/tag/rust-v0.154.0}}).

Our run MEASURED

Codex cannot talk to a chat-completions server, so the local model sat behind a LiteLLM gateway that translates the Responses API into chat completions (the {{Gateways and routing|n:3f15c17b0d0d81e4a964c129a3e520ae}} page covers gateways). Codex gave the unknown model 12 tools, among them five multi-agent tools and three "goal" tools, but no apply_patch: unknown models are expected to call apply_patch through the shell. On its first call the model filled the optional justification argument of exec_command, with an empty string; Codex answered with an error, "justification requires an explicit sandbox_permissions" ({{handlers/mod.rs line 101|cx:codex-rs/core/src/tools/handlers/mod.rs#L95-L105}}). The model resent the same call three more times, then wrote prose until it hit the 2,048-token output cap, and with no tool call the turn ended: 5 calls, 47,636 input tokens, tests still failing. Codex's own usage report and our proxy's sum agree to the token. Nothing in Codex stops a repeating call; Gemini CLI and opencode both would (sections 3 and 4).

What to steal. Put the real boundary in the operating system and keep it on in headless mode; then the prompt does not have to be trusted. And keep tool schemas small: every optional field with a rule attached is a way for a weaker model to fail.
