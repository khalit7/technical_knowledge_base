What this tab is: Aider's repository map, computed for real

A coding agent has to know what is in a repository before it can change it, but a repository does not fit in a prompt. There are three answers in use. Search on demand: the model runs grep, glob and read itself, one call at a time (Claude Code, Codex, opencode, mini-SWE-agent). An embedding index: chunks of code are turned into vectors and the closest ones to the question are retrieved (Cursor). A ranked summary sent up front: Aider's repository map, which this tab opens up. Aider was built in 2023 for models with small windows and no tool calls, so it could not let the model search; it had to choose for it.

Everything below is Aider 0.86.2's own RepoMap class run on a real repository, the source of mini-SWE-agent v2.4.6 (59 Python files under src/minisweagent/; paths shown without that prefix). Nothing is simulated: the ranks are the PageRank values Aider computed, the map text is what Aider would put in the prompt. Script: src/repomap_lab.py.

How the map is built, in five steps

  1. Tags. tree-sitter parses every file into tags: each definition (a class, function or method name, with its line) and each reference (a use of a name).
  2. A graph of files. For every name that is both defined and referenced, an edge runs from each file that uses it to each file that defines it. Its weight is mul × √(number of uses), where mul starts at 1 and is multiplied by 10 if your message mentions the name, by 10 if the name is a long (8 or more characters) snake_case, kebab-case or camelCase name, by 0.1 if it starts with an underscore, by 0.1 if more than five files define it, and by 50 if the using file is in the chat ({{repomap.py lines 487 to 514|https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py#L487-L514}}).
  3. Personalised PageRank. PageRank (the random-surfer score) runs on that graph. "Personalised" means the surfer restarts not uniformly but at files you care about: each file in the chat, each file whose name you typed, and each file whose path contains a word you typed gets 100/N added to its restart weight (N = number of files; here 100/59 = 1.69) ({{lines 383 to 445|https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py#L383-L445}}).
  4. Rank flows to definitions. Each file's rank is split across its outgoing edges by weight and summed per (defining file, name), so the map lists the most important definitions, not just files. Files already in the chat are skipped: their full text is sent anyway.
  5. Fit the budget. A binary search finds how many ranked definitions fit the token budget (--map-tokens, default 1,024 when the model's window is unknown, as for a local model) and stops once the map is within 15 percent of it, above or below ({{lines 676 to 703|https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py#L676-L703}}). That is why a 2,048-token budget produced a 2,233-token map below.

What the three runs show


With nothing in the chat, generic utilities win: utils/serialize.py (rank 0.130), whose recursive_merge is called from many files, tops the list. Adding agents/default.py to the chat gives it the restart weight and multiplies its outgoing edges by 50, so the files it uses (agents/interactive.py, exceptions.py) climb. The message "Make DockerEnvironment retry when docker exec times out" pulls in environments/docker.py twice over (its stem matches "docker", and so does a path component) and also models/utils/retry.py, only because the ordinary word "retry" equals that file's name. Name matching is cheap and blunt: it cannot tell a word from an intent.

Why this matters when you build a harness


    

  • It costs no model calls. The map is computed locally by a parser and a graph library, then paid for as input tokens on each request; agentic search pays a model call per grep.
    • 

  • It goes stale in the other direction. The map is recomputed when files change (Aider's --map-refresh), but it can only rank what the parser sees: strings, configs and dynamic dispatch carry no tags.
    • 

  • Agentic search won for strong models. Every tool-calling harness on this page lets the model search instead. Aider's idea survives as a cheap first message: a few hundred tokens of "what is where" before the first grep.
