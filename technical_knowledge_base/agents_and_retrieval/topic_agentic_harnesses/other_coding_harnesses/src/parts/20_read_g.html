7. mini-SWE-agent: the smallest loop that scores

Where it comes from. In 2024 the SWE-agent paper argued that an agent's tools are an interface to design, an agent-computer interface (ACI): a file viewer that shows 100 lines at a time, a search that lists only the files with matches, an edit command whose linter rejects syntactically broken edits ({{SWE-agent ACI|https://swe-agent.com/latest/background/aci/}}; {{paper|https://arxiv.org/abs/2405.15793}}). The paper framed those guard rails as a trade-off: whether one helps "depends on how well it reduces common model errors compared to whether such restrictions hamper models' preferred workflows". A year later the same team released mini-SWE-agent and wrote that "as LMs have become more capable, a lot of this is not needed at all" ({{README|https://github.com/SWE-agent/mini-swe-agent}}). SWE-agent itself is now in maintenance-only mode and its README recommends mini-SWE-agent. Read here: v2.4.6, MIT.

Loop
DefaultAgent.run() renders two messages (system, task), then repeats step() = execute_actions(query()) until a message with role exit appears ({{default.py 88 to 128|ms:src/minisweagent/agents/default.py#L88-L128}}). The whole agent class is 190 lines at this version; the README still says "some 100 lines". Limits: steps unlimited by default, cost limit $3, three consecutive format errors end the run ({{lines 26 to 33|ms:src/minisweagent/agents/default.py#L26-L33}}). Control flow is by exceptions: a format error, a limit or a submission each raises, and its message is appended to the history.
Actions
One tool, bash(command), run as a fresh subprocess each time, so cd and export do not persist between steps ({{local.py|ms:src/minisweagent/environments/local.py#L13-L56}}). That is a deliberate trade: every action is independent, so sandboxing is "literally just switch out subprocess.run with docker exec", and a run is trivial to parallelise. Version 2 made native tool calling the default; the version 1 style (one ```mswea_bash_command block in text, found by a regular expression) is now the opt-in textbased model class. Files are edited with sed and heredocs, as the prompt teaches.
Ending
The run ends when a command's output starts with the line COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT and exits 0; the check is on the output, not on the command text ({{local.py 45 to 56|ms:src/minisweagent/environments/local.py#L45-L56}}).
Context
None, on purpose. The history is linear: every step appends and the whole list is sent each time, so the trajectory is exactly the prompt, which makes runs easy to read and to train on. Long outputs are cut in the observation template (over 10,000 characters: the first and last 5,000). No memory file, no compaction: a run that overflows the window fails.
Safety
The mini command asks before each command unless you pass --yolo, and runs on your machine; Docker, Podman, Singularity and bubblewrap environments are one setting away. A free local model crashes the run unless cost tracking is set to ignore_errors, because a computed cost of zero counts as an error.
Why it matters for benchmarks

Because it adds almost nothing, mini-SWE-agent is the fixed harness against which models are compared. SWE-bench's leaderboard has a "Bash Only" view, described as runs "in the mini-SWE-agent environment, so scores compare models rather than harnesses" ({{swebench.com|https://www.swebench.com/}}); its README reports scores above 74% on SWE-bench Verified. The old note's "about 65%" is out of date. How much the harness moves a score is the subject of the parent topic's section 7 and the {{Coding benchmarks|n:3ef5c17b0d0d81bfa09ad4ba5eef0c4e}} page.

Our runs MEASURED

With the local 4B model, both modes found the top_words bug and both failed for the same reason: the edit. In tool-calling mode the model ran sed -i 's/return sorted(counts.items(), key=lambda kv: -kv[1])[:n]/.../' six times. In sed's pattern language [1] and [:n] are character classes, not literal brackets, so the pattern matched nothing; sed exited 0 and printed nothing, the tests kept failing, and the model kept retrying until three replies in a row had no tool call (23 calls, 86,231 input tokens). In text mode it escaped [1] but not [:n]: the same silent no-op. It then "verified" with its own check, top_words('a a b b c c', 2), which prints [('a', 2), ('b', 2)] even with the bug, because Counter keeps first-seen order, and submitted (6 calls). Both runs ended with both tests failing. The two Claude runs are section 1's.

This is the agent-computer-interface argument in one recording: an edit tool that refuses when its search text does not match (str_replace in OpenHands, edit in opencode, replace in Gemini CLI) turns a silent failure into an error the model can read. A bash-only harness relies on the model knowing sed; strong models do, a 4B model did not.

What to steal. Start your own harness here: one tool, a linear history, a submit signal in the environment, a sandbox by swapping one call. Add a mechanism only when a recorded failure asks for it.
