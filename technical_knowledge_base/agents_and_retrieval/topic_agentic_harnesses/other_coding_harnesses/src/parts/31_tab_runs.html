What this tab is: one task, every harness, the wire in between

Each harness on this page was run on the same small task: the running example of the parent topic, a two-file Python package textstats with two planted bugs (a regular expression that splits "don't" into two words, and a sort that ignores alphabetical order on ties), and the prompt "The tests in this repository fail. Find out why and fix the code so they pass. Do not edit the tests."

Instead of reading each harness's own log format, every model request went through a small logging proxy, so all runs are shown the same way: what the harness sent (system prompt, tool schemas, the conversation) and what the model answered (text, tool calls, token counts). For the Claude runs the "model" is claude -p with every Claude Code tool switched off, and the log is our adapter's.

Read these numbers as a demonstration, not a benchmark

One task, mostly one run per setting, and a small local model (Qwen3-4B-Instruct-2507, 4-bit, on an Apple M1 Pro, shared with other jobs, so seconds are not comparable between runs). A 4B model fails in ways a frontier model does not; that is the point here: the failures show what each harness does when the model goes wrong. For how much a harness moves a strong model's score, see the {{Harness atlas|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} tab of the parent topic.
