5. Aider: no tools, no loop, and it worked best

What it is. A terminal pair-programmer, first released in May 2023, Apache-2.0, Python. It predates function calling, and it still does not use it. Development has slowed but not stopped: the latest GitHub release is v0.86.0 (9 August 2025), but tags v0.86.1 and v0.86.2 exist, PyPI's latest is 0.86.2 (12 February 2026), and the last commit to main is from 22 May 2026 ({{PyPI|https://pypi.org/project/aider-chat/}}, {{tags|https://github.com/Aider-AI/aider/tags}}). Read here: main at 5dc9490 (its code for the parts cited matches 0.86.2, which is what we ran).

Loop
There is no agent loop. Coder.run() takes one user message; run_one() sends it, applies the edits in the reply, commits, runs the linter and (if asked) the tests, and if anything failed it sends a "reflected" message with the errors, at most 3 times ({{base_coder.py 924 to 945|ai:aider/coders/base_coder.py#L924-L945}}). The human is the outer loop. The model never calls a tool, and shell commands it suggests in a ```bash block need an explicit yes: --yes-always answers no to them ({{io.py|ai:aider/io.py#L866-L867}}).
Edits
The reply carries the edits as text, in an edit format chosen per model: diff (SEARCH/REPLACE blocks, below), whole (reprint the file), udiff, diff-fenced, a V4A patch format like Codex's, and editor-* variants for architect mode ({{edit formats|https://aider.chat/docs/more/edit-formats.html}}). An unknown model, such as a local one, defaults to whole ({{models.py|ai:aider/models.py#L129}}). SEARCH text must match exactly or after small fixes (leading whitespace, a stray blank line, ... elision); the edit-distance matcher many describe sits after an unconditional return and never runs ({{editblock_coder.py 157 to 187|ai:aider/coders/editblock_coder.py#L157-L187}}). A block that fails comes back with a "Did you mean" snippet of the closest lines.
Context
Files you add are sent in full; everything else is summarised by the repository map, a PageRank over the files' definitions and references, cut to a token budget (1,024 by default for an unknown model). The {{Repo map lab|#t-map}} tab runs it for real. Older chat is summarised by a background call ("*Briefly* summarize this partial conversation about programming") once it passes a budget. No memory file is read automatically: conventions are a file you add with --read.
Safety
No sandbox. The safety net is git: dirty files are committed first, every applied edit becomes its own commit with a model-written message, and /undo checks out the previous version of the changed files and soft-resets that commit ({{git docs|https://aider.chat/docs/git.html}}).
Extend
No MCP, hooks, plugins or subagents. Architect mode (one model plans, an editor model writes the edits), watch mode (AI comments in your editor's files), and a Python scripting API.

Our runs MEASURED

Aider was the only harness that fixed both bugs with the local 4B model, in both formats we tried. With diff (7 calls, 138 s): the model first named the file it needed, Aider added the files it mentioned, the model fixed top_words, Aider committed and ran the tests (--auto-test), sent back the one remaining failure as a reflection, and the model fixed tokenize. Two calls wrote commit messages and two identical calls summarised the history. With whole (3 calls, 42 s) the model reprinted core.py with both fixes at once; its first request was 879 prompt tokens against 2,655 for diff, because the SEARCH/REPLACE instructions and worked examples are long (5,407 characters of system prompt against 1,191). Through the claude -p adapter, Claude Haiku 4.5 fixed both bugs in 3 calls and 25 s: Aider's protocol needs no observation inside a reply, so the missing stop sequence of section 1 never mattered.

What to steal. When the model is weak or the channel is plain text, do not run an open-ended loop: give it the right files, ask for one structured answer, verify with tests, and feed back only the failure. And make every change a commit.
