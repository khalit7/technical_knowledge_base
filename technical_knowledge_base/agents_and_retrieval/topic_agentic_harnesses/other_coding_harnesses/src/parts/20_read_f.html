The harness as a server. opencode runs everything behind an HTTP API: opencode serve starts a headless server, the terminal UI starts the same server in a worker thread and talks to it, and even opencode run boots a local server first ({{serve.ts|oc:packages/opencode/src/cli/cmd/serve.ts#L6-L24}}). At this version the UI is TypeScript on OpenTUI and SolidJS, and the repository has no Go (older write-ups describe a Go/Bubble Tea UI). The split is what lets one session be driven from the terminal, a desktop app, an editor or a script. OpenHands gets the same from its event log: a conversation is typed events, so it can be persisted, replayed, condensed and served.

What a sub-agent buys, recorded. Our opencode run delegated twice to the explore subagent, which ran in its own 5-tool context (3,091 tokens on its first call) and found the bug in top_words; the main agent then answered in prose ("update the sorting key to include alphabetical ordering for ties") without calling edit, and the loop ended (section 2). Delegation kept the main context small; it did not make the model act. When to delegate at all is {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}'s subject.

7. Where the loop runs: your terminal, a cloud agent, or a loop you rent

The same loop also runs on someone else's machine, and that moves what you can check: an edit as it lands (terminal), a pull request afterwards (cloud agent), or only the permission policy (hosted loop).

The further the loop moves from you, the less of the harness you can see; the permission policy is what you keep

Which parts of the harness run in your process (top) and which on the provider's side (bottom) for each shape. Terminal: the six on this page. Cloud agent: Codex cloud, Jules. Hosted loop: OpenAI's Agents API, Claude Managed Agents.

Codex cloud gives each task its own workspace (a container with your repository checked out, a setup script, a default "universal" image, agent internet access off by default) and keeps running while your computer sleeps; codex cloud exec --attempts 1-4 runs best-of-N and codex apply brings a result home ({{Codex cloud|https://learn.chatgpt.com/codex/cloud}}, {{CLI reference|https://learn.chatgpt.com/codex/cli/reference}}, {{environments|https://learn.chatgpt.com/codex/cloud/environments}}). The pattern: interactive work in the terminal, a fleet of parallel attempts for small, well-specified fixes. Jules (Google) clones a GitHub repository into a cloud VM, writes a plan for you to approve, makes the change and opens a pull request ({{jules.google|https://jules.google/}}). With a hosted loop the parts of the harness that most change behaviour (context policy, compaction, the loop itself) leave your process; Anthropic's ant beta:sessions connect attaches a terminal to a running Managed Agents session to watch it and approve or deny tool calls.
