6. OpenHands: an agent as an event log

What it is. The open platform formerly called OpenDevin ({{arXiv 2407.16741|https://arxiv.org/abs/2407.16741}}), MIT. In 2026 it split: the flagship repository now headlines "Agent Canvas", a self-hosted control centre that can run OpenHands, Claude Code, Codex or Gemini CLI, while the agent itself lives in the Software Agent SDK ({{OpenHands/software-agent-sdk|https://github.com/OpenHands/software-agent-sdk}}). Read and run here: SDK v1.53.0 (5 October 2026), the part you would build on.

Loop
A Conversation owns a list of typed events (messages, actions, observations, condensations), and LocalConversation._run() repeats: check status, check the stuck detector, call agent.step(), check confirmation, budget and the iteration cap of 500 ({{local_conversation.py|oh:openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L1917-L2045}}). The run ends when the model calls the finish tool or answers in plain text. An empty reply does not end it: the SDK injects "Please use a tool to proceed with the task." A stuck detector scans the last 20 events for repeated action and observation pairs, nudges once, then stops. Because state is an event log, a conversation can be persisted, resumed and replayed.
Tools
The default coding preset gives terminal (a tmux session; output over 30,000 characters is cut in the middle and saved to a file), file_editor, task_tracker, plus the built-ins finish and think: five tools ({{default preset|oh:openhands-tools/openhands/tools/preset/default.py}}). Every tool schema gets two injected fields, summary and, for tools that change something, security_risk ({{tool.py|oh:openhands-sdk/openhands/sdk/tool/tool.py#L712-L731}}), so the model must classify the risk of its own action on every call.
Edits
file_editor in the str_replace_editor style: view, create, str_replace, insert, undo_edit. old_str must match once; the only retry strips surrounding whitespace ({{editor.py|oh:openhands-tools/openhands/tools/file_editor/editor.py#L200-L242}}).
Context
The system prompt is assembled from Python sections (28,492 bytes of static text, with dynamic repository, skills and date sections). The condenser in the default preset keeps the first 4 events and a recent tail, and has a model summarise the middle once the history passes 80 events or the token cap, into a state summary with fields such as COMPLETED, PENDING, CODE_STATE and TESTS ({{llm_summarizing_condenser.py|oh:openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L554-L562}}). A bare Agent has no condenser, and AGENTS.md or CLAUDE.md are ignored unless load_project_skills=True.
Safety
Confirmation policy NeverConfirm by default; ConfirmRisky asks at HIGH risk and for UNKNOWN. The LLMSecurityAnalyzer does no analysis of its own: it returns the security_risk value the acting model wrote into its own call ({{llm_analyzer.py|oh:openhands-sdk/openhands/sdk/security/llm_analyzer.py#L20-L29}}), so the agent grades itself; a regex analyser for patterns such as rm -rf exists as a second layer. LocalWorkspace runs commands on your machine; isolation comes from DockerWorkspace, which starts an agent-server container and drives it over HTTP.
Extend
MCP, hooks with Claude Code's event names (PreToolUse, PostToolUse, UserPromptSubmit, SessionStart, SessionEnd, Stop), skills in the SKILL.md format, plugins, subagents, and an agent server with a REST and WebSocket API.
Our run MEASURED

The SDK ran inside a Docker container we started, with its local workspace in there and the iteration cap lowered from 500 to 30. The first request carried 15,228 characters of system prompt and 17,056 characters of tool definitions (the task_tracker description alone is 5,051 characters), 7,196 tokens. The model filled security_risk on every call (LOW to read, MEDIUM for pip install pytest, which it ran inside the container when pytest was missing, although the test file runs with plain python3), and once misspelt it as security_rika, which the schema rejected. It found both bugs, then tried str_replace five times with an old_str that was indented one level too deep and had lost two of the docstring's three closing quotes. Each attempt came back with "No replacement was performed, old_str ... did not appear verbatim", a clear error the model could not act on: it viewed the file again, thought, and repeated, until the 30-iteration cap stopped the run with both tests failing (30 calls, 322,241 input tokens, the most of any run, because the whole event history is resent each step).

What to steal. Store the conversation as typed events, not as a prompt string: persistence, replay and condensation all fall out of it. And do not let the acting model be its own security reviewer.
