The page in one screen

A harness is the program around a language model that makes it an agent: it sends the model a prompt, reads back an action, runs it, sends back the result, and repeats until a stop condition. The parent topic builds one from scratch and takes Claude Code apart (Topic: agentic-harnesses, tabs Loop lab and Trace and context lab; then Claude Code, taken apart, its own child page). This page reads six other harnesses whose source is public, at pinned versions, and runs each on the same task, so you can see which decisions they made differently and what each decision costs.

The three findings worth remembering

1. The action boundary is the harness's job. When the model writes its action as text, something must stop it right after the action, or it will write the result too, and invent it. Section 1 shows Claude doing exactly that, recorded.

2. Defaults decide safety. The six span the whole range, from an OS sandbox on by default (Codex) to allow-everything with no sandbox (opencode) to "git is the undo button" (Aider). Same loop, very different blast radius.

3. Small models break on harness details, not on the task. A 4-billion-parameter local model located the top_words bug in most harnesses, but fixed both bugs only in Aider, and one in Gemini CLI. Elsewhere it failed on an optional tool argument it filled wrongly (Codex), a turn that ended on prose (opencode), a sed pattern that silently matched nothing (mini-SWE-agent) and an edit string with the wrong indentation (OpenHands). The harness decides whether such slips are visible and recoverable.

1. Two ways to ask a model for an action, and the boundary between them

Every harness on this page must get an action out of the model (run this command, change these lines) and feed back an observation (what the command printed). There are two ways to do it, and the difference explains more failures than any other design choice.

Native tool calls

The harness sends tool definitions (a name, a description, a JSON schema for the arguments) with the request. The model answers with a structured tool_calls item and the API ends the reply there, marking it with a finish reason (tool_calls in the OpenAI format, tool_use in Anthropic's). The inference server enforces the boundary: the model cannot write the result of its own call, because generation has stopped. Codex, Gemini CLI, opencode, OpenHands and mini-SWE-agent's default mode work this way.

Text actions

The model writes the action inside its prose in an agreed format, and the harness finds it with a regular expression: Aider's SEARCH/REPLACE blocks, or mini-SWE-agent's text mode, which wants exactly one ```mswea_bash_command block per reply (regex). This works with any model that writes text, which is why Aider chose it in 2023, before OpenAI shipped function calling on 13 June 2023 (OpenAI). But now the harness must stop the model at the action.

Aider does not need that stop: its whole protocol is "reply once, with the edits"; the model never waits for an observation inside a reply. A loop that does need observations (run ls, see the listing, decide) must end generation right after the action (Building a harness measures every way a turn ends, in its "Stop lab" tab). With a model API you pass a stop sequence, a string at which the server stops generating; with an open model the chat template's end-of-turn token usually does it, because the model was trained to stop after a tool call. claude -p, the only way this page could reach Claude (a subscription, no API key), has no stop-sequence option. So we ran mini-SWE-agent's text mode with Claude Haiku 4.5 twice, through a small adapter that puts claude -p behind an OpenAI-style endpoint: once passing the reply through untouched, once cutting it right after the first action block.

Without the cut, Haiku wrote one action and then kept going: it invented the command's output, wrote its next thought, the next action, the next output, up to  action blocks in one reply, ending with "All tests passed!" and the submit command. mini-SWE-agent's parser refused every reply with more than one block ("Expected exactly 1 action"),  times in  calls, and the run finally ended on a reply whose single action was the submit command. No file was changed; both tests still failed.


With the cut, every command that ran was one the model asked for and every observation was real, yet the run also ended with no edit: the model wrote its invented exchange before its first action ("The core.py file appears to be empty", a file it never read), so the cut kept that reasoning, and the last reply claimed the tests passed and submitted. The cut text was thrown away, but it was still generated and paid for:  output tokens for  calls.


The lesson for your own harness: a client-side cut stops the harness from acting on invented output; it does not stop the model from believing it. The fix is structural: a real message list with roles and a server-side stop (native tool calls, or a stop sequence), which is exactly what claude -p with tools off cannot give. The parent topic's Loop lab tab met the same wall (its step 1 and the fix in step 1b: Haiku invented its tool result, once running on for 95,162 characters, until the harness kept only the text up to the first action). Aider, whose protocol needs no observation inside a reply, fixed both bugs through the same adapter in  (section 5).


Drill. Why did the local 4B model not invent output in mini-SWE-agent's text mode, through the same text protocol?
It ran behind a real chat-completions server: Qwen's chat template ends the assistant turn with an end-of-turn token, and the model was trained to emit it after a single action, so generation stopped at the right place without any stop sequence. The boundary came from training plus the template, not from the harness.






2. Codex CLI (OpenAI): the operating system is the boundary


What it is. OpenAI's terminal coding agent, Apache-2.0. It launched in April 2025 written in TypeScript; on 30 May 2025 OpenAI announced it was going native, and the CLI is now a Rust workspace, codex-rs (discussion #1174). 127,966 GitHub stars on 6 October 2026 (GitHub API). "Codex" is also a cloud service and part of the ChatGPT desktop app (section 9); its documentation moved from developers.openai.com to learn.chatgpt.com/codex. Read here: tag rust-v0.160.1, released 5 October 2026.




Loop
run_turn samples the model, runs any tool calls, sends their output back, and repeats; a reply with no tool call ends the turn, unless a Stop hook objects and injects a continuation (turn.rs 150 to 170). There is no step or turn limit; when the window fills mid-task it compacts and keeps going (lines 601 to 650). Every request allows parallel tool calls; a read-write lock lets tools that declare themselves parallel-safe run together (parallel.rs). It speaks only the Responses API: wire_api = "chat" is now a config error (model-provider-info).


Tools
For OpenAI's own models a test pins the default set: exec_command and write_stdin (a shell, with long-running processes on a pseudo-terminal), update_plan, request_user_input, apply_patch, view_image, tool_search (which loads MCP and multi-agent tools on demand) and web_search (prompt_caching.rs). Tool output kept in history is cut to the model's limit (10,000 tokens for bundled models) plus 20%, keeping head and tail (history.rs).


Edits
apply_patch is not a JSON function: it is a freeform tool whose input is constrained by a 19-line Lark grammar, so the model writes raw patch text that the server forces to parse (apply_patch.lark). Context lines are matched exactly, then ignoring trailing spaces, then trimmed, then with typographic dashes and quotes mapped to ASCII (seek_sequence.rs). The first match wins, and a hunk is searched for only after its @@ line: Building a harness: the loop, tool calling, edit formats, stop conditions, its "Edit format bench" tab, ran this matcher on recorded edits and saw a model put the line it was changing on the @@ line, so the line to remove could never be found.


Context
Instructions are per model; an unknown model gets the 20,903-byte fallback prompt (model_info.rs). AGENTS.md: one file per directory from the git root down to the working directory (an AGENTS.override.md wins in its directory), 32 KiB in total (agents_md.rs). Compaction at 90% of the window: OpenAI models compact on the server; others get a 426-byte "CONTEXT CHECKPOINT COMPACTION" prompt and a rebuilt history of the summary plus the most recent user messages (compact prompt).


Safety
Two independent dials: a sandbox mode (read-only by default, workspace-write for a trusted folder, danger-full-access) and an approval policy (on-request by default, never, or granular) (config_toml.rs). On macOS the sandbox is Seatbelt (sandbox-exec with four .sbpl profiles, deny by default); on Linux, bubblewrap for files plus seccomp for the network, with Landlock kept only as a deprecated fallback (linux-sandbox). In workspace-write the network stays off unless you enable it. There is no longer a hard-coded list of safe commands: Starlark execpolicy rules decide allow, prompt or forbid, and the built-in "dangerous" check only knows forced rm (is_dangerous_command.rs). codex exec (headless) forces the approval policy to never, so the sandbox is all that stands between the model and your machine (exec). Why both dials are needed is the subject of Agent security.


Extend
Hooks (12 events, including PreToolUse, PermissionRequest, PreCompact and Stop), MCP servers as a client, plugins, skills, subagents (up to 6 threads), and Python and TypeScript SDKs that drive the CLI over JSON lines. The codex mcp-server subcommand was removed in rust-v0.154.0 (release notes).

Our run MEASURED


Codex cannot talk to a chat-completions server, so the local model sat behind a LiteLLM gateway that translates the Responses API into chat completions (the Gateways and routing page covers gateways). Codex gave the unknown model 12 tools, among them five multi-agent tools and three "goal" tools, but no apply_patch: unknown models are expected to call apply_patch through the shell. On its first call the model filled the optional justification argument of exec_command, with an empty string; Codex answered with an error, "justification requires an explicit sandbox_permissions" (handlers/mod.rs line 101). The model resent the same call three more times, then wrote prose until it hit the 2,048-token output cap, and with no tool call the turn ended: 5 calls, 47,636 input tokens, tests still failing. Codex's own usage report and our proxy's sum agree to the token. Nothing in Codex stops a repeating call; Gemini CLI and opencode both would (sections 3 and 4).


What to steal. Put the real boundary in the operating system and keep it on in headless mode; then the prompt does not have to be trusted. And keep tool schemas small: every optional field with a rule attached is a way for a weaker model to fail.






3. Gemini CLI (Google): guard rails around the loop


What it is. Google's open-source (Apache-2.0) terminal agent for Gemini models, announced 25 June 2025 (Google blog). Read here: v0.62.0, the stable release of 29 September 2026. One fact changes who can use it: since 18 June 2026 Gemini CLI no longer serves the free Code Assist tier or Google AI Pro and Ultra subscribers, who were moved to the new Antigravity CLI; it remains for paid Gemini API keys, Code Assist Standard and Enterprise, and Vertex AI (Google Developers Blog, 19 May 2026). The repository's README and quota page still describe the old free tier below a banner announcing the change.




Loop
Split in two: GeminiClient runs one streamed model turn (compress if needed, check for loops, pick a model, stream), and the caller runs the tools and sends results back; in headless mode that caller is a while (true) in nonInteractiveCli.ts. A reply with no tool call ends the run. Session turns are unlimited by default (maxSessionTurns -1). Tools run in parallel by default; every tool schema gets an injected wait_for_previous argument the model sets to serialise a call, and file edits always run one at a time (scheduler.ts).


Loop detection
The guard Codex lacks: the same tool call five times in a row, or a 50-character chunk of text repeated ten times, counts as a loop; after 30 turns a separate model call also checks for "unproductive" loops every 5 to 15 turns and needs 0.9 confidence. The first detection injects a nudge, the second stops the turn (loopDetectionService.ts).


Tools
About 17 reach the model in a default interactive session (15 in our headless run): read_file, list_directory, glob, grep_search (ripgrep), replace, write_file, run_shell_command, web_fetch, google_web_search, write_todos, invoke_agent (subagents), activate_skill and others (config.ts). Two often-listed tools are not model-visible in this version: read_many_files serves only the @file syntax, and save_memory is gone: the prompt tells the model to edit GEMINI.md with the ordinary file tools. Shell output over 40,000 characters is saved to a file and truncated; read_file stops at 2,000 lines.


Edits
replace(file_path, instruction, old_string, new_string, allow_multiple) tries four matchers in turn: exact; "flexible" (each line compared with its whitespace trimmed, the replacement re-indented); a regular expression with \s* between tokens; then a fuzzy sliding window that accepts a weighted Levenshtein distance of up to 10% of the search length (edit.ts). The second-model "edit correction" that older write-ups describe still exists but is off by default (disableLLMCorrection: true, config.ts).


Context
GEMINI.md files from ~/.gemini, then from each trusted root up to the git root; a GEMINI.md in a subdirectory is loaded only when a tool first touches that directory, and files can @import others five levels deep. Compression starts when a prompt reaches 50% of the window: the oldest 70% of the history becomes an XML <state_snapshot>, then a second "probe" call asks the model to critique and improve its own summary (chatCompressionService.ts). Two calls per compression, at half the window: Google trades tokens for a better summary.


Safety
Approval modes default, auto_edit, plan and yolo, decided by TOML policy files: read-only tools are allowed, edits and the shell ask (write.toml). Headless runs have nobody to ask, so the engine's default is deny: gemini -p without --yolo or --approval-mode auto_edit cannot edit or run anything (policy-engine.ts). The sandbox is off by default; -s relaunches the whole CLI inside macOS Seatbelt (profile permissive-open: writes only to the project, temp and cache folders, network open), or Docker, Podman, gVisor or LXC on Linux (sandbox.ts).


Extend
MCP servers, hooks (11 events: BeforeTool, AfterTool, BeforeModel, AfterModel, PreCompress and others), skills, subagents (local and remote over A2A), and extensions: a folder with a gemini-extension.json that bundles MCP servers, context files, commands, hooks and skills, installed from a GitHub URL.




Our run MEASURED


Gemini CLI speaks only the Gemini API, so the local model sat behind the same LiteLLM gateway, which also serves Gemini-style generateContent routes. Getting there took three fixes that teach something. Setting GOOGLE_GEMINI_BASE_URL makes the CLI pick its "gateway" sign-in type, which its own validator then rejects ("Invalid auth method selected"; auth.ts); choosing the API-key sign-in in the settings keeps the custom base URL. In a folder it does not trust, the CLI printed "Approval mode overridden to "default" because the current folder is not trusted", which in headless mode means every edit is denied, --yolo or not. And its HTTP client waits only 60 seconds for response headers (fetch.ts) and retries a failed request up to 10 times (retry.ts): against a slow shared local server, each retry piled another 11,000-token prompt onto the server, and on our first attempt the overlap crashed it. We serialised every request in our proxy and ran it again.


The run itself: 6 calls inside Seatbelt. The first request was the largest of all six harnesses: 32,924 characters of system prompt and 15 tools in 17,722 characters, 11,452 tokens (counted afterwards with the model's own chat template, because the gateway's stream carried no usage; the same count reproduces the server's numbers on the opencode run exactly). The model's first reply made four tool calls at once (a topic note, a directory listing and two file reads), fixed top_words with replace, ran the tests, saw one failure left, and then returned an empty reply, which ends the loop. One bug of two fixed.


What to steal. Detect loops in the harness, cheaply first (identical calls) and with a model only later; make headless mode deny by default; and when you compress, keep the newest part verbatim.






4. opencode: the harness as a server, any model behind it


What it is. An MIT-licensed, provider-agnostic coding agent with a terminal UI, a desktop app and IDE integrations, made by Anomaly (the repository moved from sst/opencode to anomalyco/opencode). 211,898 GitHub stars on 6 October 2026; the site claims "over 16M developers every month" (vendor figure) (GitHub API, opencode.ai). Read here: v1.18.34, 30 September 2026.




Architecture
Everything runs behind an HTTP API: opencode serve starts a headless server, the terminal UI starts the same server in a worker thread and talks to it, and even opencode run boots a local server first (serve.ts). Older write-ups describe a Go/Bubble Tea terminal UI; at this version the UI is TypeScript on OpenTUI and SolidJS, and the repository has no Go. The client/server split is what lets one session be driven from the terminal, a desktop app, an editor or a script.


Loop
runLoop reloads the session's messages from its database on every pass, makes one streamed model call, runs the tool calls, and stops when the last reply has no tool call (prompt.ts). No step limit unless an agent sets steps. A doom-loop guard: three identical tool calls in a row raise a permission question (processor.ts). Malformed calls are repaired (wrong-case tool names are fixed; unknown ones go to a hidden invalid tool that returns an error instead of crashing the turn).


Per model
The system prompt is chosen by matching the model id: anthropic.txt for Claude, gemini.txt, codex.txt, beast.txt for older GPT models, and default.txt (8,528 bytes) for anything else, such as our local model (system.ts). The tools also depend on the model: ids containing gpt- get a Codex-style apply_patch instead of edit and write (registry.ts). A provider-agnostic harness has to carry a dialect per model family.


Edits
edit(filePath, oldString, newString, replaceAll) tries nine matchers in order and takes the first that finds a unique match: exact, line-trimmed, block-anchor (first and last line fixed, the middle scored by Levenshtein similarity, threshold 0.65), whitespace-normalised, indentation-flexible, escape-normalised, trimmed-boundary, context-aware and multi-occurrence (edit.ts). A comment credits Cline and Gemini CLI for the ideas. After each edit, language-server diagnostics for the file are appended to the tool result, so the model sees a type error in the same turn.


Context
Project instructions: the first of AGENTS.md, CLAUDE.md, CONTEXT.md found between the working directory and the project root (and ~/.claude/CLAUDE.md globally), plus nested AGENTS.md files attached when the read tool opens a file below them. Compaction summarises the older part when the last turn's tokens reach the usable window, keeping a recent tail of 25% of it (clamped to 2,000 to 15,000 tokens) (compaction.ts). Two traps: compaction is silently off for a custom model with no limit.context in the config, and the cheap "prune old tool outputs" step is off by default. Tool output is cut at 2,000 lines or 50 KB, with the full text saved to a file.


Safety
Rules of the form permission, pattern, action (allow, ask, deny); the last matching rule wins. Defaults allow almost everything: only reading .env files, touching paths outside the project and doom loops ask (agent.ts). Shell commands are parsed with tree-sitter so an "always allow" can be stored as a prefix such as git checkout *. There is no OS sandbox. In opencode run, any question is rejected unless you pass --auto.


Extend
JavaScript plugins with hooks such as tool.execute.before, permission.ask and experimental.session.compacting; MCP servers; skills (it also reads .claude/skills); custom agents and subagents (task tool, built-in general and explore).




Which subscriptions work
Anthropic's terms let subscription (OAuth) credentials be used only by Claude Code and Anthropic's own apps (legal and compliance). opencode removed its Claude Pro/Max login plugin in v1.3.0 (22 March 2026; release), after a January 2026 issue reported the login broken (issue #7410); Claude now works in opencode with an API key. ChatGPT Plus and Pro, GitHub Copilot and GitLab Duo logins do work (providers doc). The old page's "OpenAI now sponsors the project" has no primary source and is dropped.


Our run MEASURED


opencode has no sandbox, so we ran it inside a throwaway Docker container (our addition). Its first request was large: 9,602 characters of system prompt and 21,144 characters of tool definitions for 10 tools (the bash description alone is 4,628 characters), 7,247 prompt tokens before the model had read a file (Codex's, at 9,210, and Gemini CLI's, at 11,452, were larger). A separate call generated the session title. The 4B model delegated twice to the explore subagent (its own 5-tool context, 3,091 tokens), found the bug in top_words, and then answered in prose describing the fix ("update the sorting key to include alphabetical ordering for ties") without calling edit. A reply without a tool call ends the loop, so the run stopped after 13 calls with both tests failing. The harness did what it promises; the model's habit of explaining instead of acting is exactly what a "no tool call means done" rule cannot tell apart from finishing.


What to steal. Run the agent as a server with a typed API and let every interface be a client. Keep a prompt and tool set per model family. Append diagnostics to edit results so the model sees breakage at once.






5. Aider: no tools, no loop, and it worked best


What it is. A terminal pair-programmer, first released in May 2023, Apache-2.0, Python. It predates function calling, and it still does not use it. Development has slowed but not stopped: the latest GitHub release is v0.86.0 (9 August 2025), but tags v0.86.1 and v0.86.2 exist, PyPI's latest is 0.86.2 (12 February 2026), and the last commit to main is from 22 May 2026 (PyPI, tags). Read here: main at 5dc9490 (its code for the parts cited matches 0.86.2, which is what we ran).




Loop
There is no agent loop. Coder.run() takes one user message; run_one() sends it, applies the edits in the reply, commits, runs the linter and (if asked) the tests, and if anything failed it sends a "reflected" message with the errors, at most 3 times (base_coder.py 924 to 945). The human is the outer loop. The model never calls a tool, and shell commands it suggests in a ```bash block need an explicit yes: --yes-always answers no to them (io.py).


Edits
The reply carries the edits as text, in an edit format chosen per model: diff (SEARCH/REPLACE blocks, below), whole (reprint the file), udiff, diff-fenced, a V4A patch format like Codex's, and editor-* variants for architect mode (edit formats). An unknown model, such as a local one, defaults to whole (models.py). SEARCH text must match exactly or after small fixes (leading whitespace, a stray blank line, ... elision); the edit-distance matcher many describe sits after an unconditional return and never runs (editblock_coder.py 157 to 187). A block that fails comes back with a "Did you mean" snippet of the closest lines. Forgiving has a cost: on a 4B model's unified diffs, Aider's udiff applier applied 8 of 10 where git apply refused almost all, but 6 of those 8 failed the check (measured on Building a harness: the loop, tool calling, edit formats, stop conditions, its "Edit format bench" tab).


Context
Files you add are sent in full; everything else is summarised by the repository map, a PageRank over the files' definitions and references, cut to a token budget (1,024 by default for an unknown model). The Repo map lab tab runs it for real. Older chat is summarised by a background call ("*Briefly* summarize this partial conversation about programming") once it passes a budget. No memory file is read automatically: conventions are a file you add with --read.


Safety
No sandbox. The safety net is git: dirty files are committed first, every applied edit becomes its own commit with a model-written message, and /undo checks out the previous version of the changed files and soft-resets that commit (git docs).


Extend
No MCP, hooks, plugins or subagents. Architect mode (one model plans, an editor model writes the edits), watch mode (AI comments in your editor's files), and a Python scripting API.

Aider was the only harness that fixed both bugs with the local 4B model, in both formats we tried. What to steal. When the model is weak or the channel is plain text, do not run an open-ended loop: give it the right files, ask for one structured answer, verify with tests, and feed back only the failure. And make every change a commit.






6. OpenHands: an agent as an event log


What it is. The open platform formerly called OpenDevin (arXiv 2407.16741), MIT. In 2026 it split: the flagship repository now headlines "Agent Canvas", a self-hosted control centre that can run OpenHands, Claude Code, Codex or Gemini CLI, while the agent itself lives in the Software Agent SDK (OpenHands/software-agent-sdk). Read and run here: SDK v1.53.0 (5 October 2026), the part you would build on.




Loop
A Conversation owns a list of typed events (messages, actions, observations, condensations), and LocalConversation._run() repeats: check status, check the stuck detector, call agent.step(), check confirmation, budget and the iteration cap of 500 (local_conversation.py). The run ends when the model calls the finish tool or answers in plain text. An empty reply does not end it: the SDK injects "Please use a tool to proceed with the task." A stuck detector scans the last 20 events for repeated action and observation pairs, nudges once, then stops. Because state is an event log, a conversation can be persisted, resumed and replayed.


Tools
The default coding preset gives terminal (a tmux session; output over 30,000 characters is cut in the middle and saved to a file), file_editor, task_tracker, plus the built-ins finish and think: five tools (default preset). Every tool schema gets two injected fields, summary and, for tools that change something, security_risk (tool.py), so the model must classify the risk of its own action on every call.


Edits
file_editor in the str_replace_editor style: view, create, str_replace, insert, undo_edit. old_str must match once; the only retry strips surrounding whitespace (editor.py).


Context
The system prompt is assembled from Python sections (28,492 bytes of static text, with dynamic repository, skills and date sections). The condenser in the default preset keeps the first 4 events and a recent tail, and has a model summarise the middle once the history passes 80 events or the token cap, into a state summary with fields such as COMPLETED, PENDING, CODE_STATE and TESTS (llm_summarizing_condenser.py). A bare Agent has no condenser, and AGENTS.md or CLAUDE.md are ignored unless load_project_skills=True.


Safety
Confirmation policy NeverConfirm by default; ConfirmRisky asks at HIGH risk and for UNKNOWN. The LLMSecurityAnalyzer does no analysis of its own: it returns the security_risk value the acting model wrote into its own call (llm_analyzer.py), so the agent grades itself; a regex analyser for patterns such as rm -rf exists as a second layer. LocalWorkspace runs commands on your machine; isolation comes from DockerWorkspace, which starts an agent-server container and drives it over HTTP.


Extend
MCP, hooks with Claude Code's event names (PreToolUse, PostToolUse, UserPromptSubmit, SessionStart, SessionEnd, Stop), skills in the SKILL.md format, plugins, subagents, and an agent server with a REST and WebSocket API.




Our run MEASURED


The SDK ran inside a Docker container we started, with its local workspace in there and the iteration cap lowered from 500 to 30. The first request carried 15,228 characters of system prompt and 17,056 characters of tool definitions (the task_tracker description alone is 5,051 characters), 7,196 tokens. The model filled security_risk on every call (LOW to read, MEDIUM for pip install pytest, which it ran inside the container when pytest was missing, although the test file runs with plain python3), and once misspelt it as security_rika, which the schema rejected. It found both bugs, then tried str_replace five times with an old_str that was indented one level too deep and had lost two of the docstring's three closing quotes. Each attempt came back with "No replacement was performed, old_str ... did not appear verbatim", a clear error the model could not act on: it viewed the file again, thought, and repeated, until the 30-iteration cap stopped the run with both tests failing (30 calls, 322,241 input tokens, the most of any run, because the whole event history is resent each step).


What to steal. Store the conversation as typed events, not as a prompt string: persistence, replay and condensation all fall out of it. And do not let the acting model be its own security reviewer.






7. mini-SWE-agent: the smallest loop that scores


Where it comes from. In 2024 the SWE-agent paper argued that an agent's tools are an interface to design, an agent-computer interface (ACI): a file viewer that shows 100 lines at a time, a search that lists only the files with matches, an edit command whose linter rejects syntactically broken edits (SWE-agent ACI; paper). The paper framed those guard rails as a trade-off: whether one helps "depends on how well it reduces common model errors compared to whether such restrictions hamper models' preferred workflows". A year later the same team released mini-SWE-agent and wrote that "as LMs have become more capable, a lot of this is not needed at all" (README). SWE-agent itself is now in maintenance-only mode and its README recommends mini-SWE-agent. Read here: v2.4.6, MIT.




Loop
DefaultAgent.run() renders two messages (system, task), then repeats step() = execute_actions(query()) until a message with role exit appears (default.py 88 to 128). The whole agent class is 190 lines at this version; the README still says "some 100 lines". Limits: steps unlimited by default, cost limit $3, three consecutive format errors end the run (lines 26 to 33). Control flow is by exceptions: a format error, a limit or a submission each raises, and its message is appended to the history.


Actions
One tool, bash(command), run as a fresh subprocess each time, so cd and export do not persist between steps (local.py). That is a deliberate trade: every action is independent, so sandboxing is "literally just switch out subprocess.run with docker exec", and a run is trivial to parallelise. Version 2 made native tool calling the default; the version 1 style (one ```mswea_bash_command block in text, found by a regular expression) is now the opt-in textbased model class. Files are edited with sed and heredocs, as the prompt teaches.


Ending
The run ends when a command's output starts with the line COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT and exits 0; the check is on the output, not on the command text (local.py 45 to 56).


Context
None, on purpose. The history is linear: every step appends and the whole list is sent each time, so the trajectory is exactly the prompt, which makes runs easy to read and to train on. Long outputs are cut in the observation template (over 10,000 characters: the first and last 5,000). No memory file, no compaction: a run that overflows the window fails.


Safety
The mini command asks before each command unless you pass --yolo, and runs on your machine; Docker, Podman, Singularity and bubblewrap environments are one setting away. A free local model crashes the run unless cost tracking is set to ignore_errors, because a computed cost of zero counts as an error.




Why it matters for benchmarks


Because it adds almost nothing, mini-SWE-agent is the fixed harness against which models are compared. SWE-bench's leaderboard has a "Bash Only" view, described as runs "in the mini-SWE-agent environment, so scores compare models rather than harnesses" (swebench.com); its README reports scores above 74% on SWE-bench Verified. The old note's "about 65%" is out of date. How much the harness moves a score is the subject of the parent topic's section 7 and the Coding benchmarks page.


Our runs MEASURED


With the local 4B model, both modes found the top_words bug and both failed for the same reason: the edit. In tool-calling mode the model ran sed -i 's/return sorted(counts.items(), key=lambda kv: -kv[1])[:n]/.../' six times. In sed's pattern language [1] and [:n] are character classes, not literal brackets, so the pattern matched nothing; sed exited 0 and printed nothing, the tests kept failing, and the model kept retrying until three replies in a row had no tool call (23 calls, 86,231 input tokens). In text mode it escaped [1] but not [:n]: the same silent no-op. It then "verified" with its own check, top_words('a a b b c c', 2), which prints [('a', 2), ('b', 2)] even with the bug, because Counter keeps first-seen order, and submitted (6 calls). Both runs ended with both tests failing. The two Claude runs are section 1's.


This is the agent-computer-interface argument in one recording: an edit tool that refuses when its search text does not match (str_replace in OpenHands, edit in opencode, replace in Gemini CLI) turns a silent failure into an error the model can read. A bash-only harness relies on the model knowing sed; strong models do, a 4B model did not.


What to steal. Start your own harness here: one tool, a linear history, a submit signal in the environment, a sandbox by swapping one call. Add a mechanism only when a recorded failure asks for it.

Why the simplest protocol won here. An agent loop hands a weak model many decisions (which tool, which arguments, when to stop), and each is a chance to slip. Aider takes most of them away: its repository map and file-mention rule pick what the model reads, the model answers once with edits, and the harness, not the model, runs the tests and returns only the failure. With a strong model the balance changes: mini-SWE-agent's bash-only loop scores above 74% on SWE-bench Verified with frontier models (section 7), and the parent topic's Harness atlas tab shows how far the harness moves strong models' scores.

The local server's prompt cache made the repeated prefix fast to process; it did not make it smaller. Common mistakes


"Codex works with any OpenAI-compatible server."
Only with servers that speak the Responses API. Chat completions support was removed (wire_api = "chat" is an error). Use a Responses-capable server or a translating gateway, as section 2 did.


Running gemini -p and wondering why nothing was edited.
Headless Gemini CLI denies anything that would need approval. Pass --yolo or --approval-mode auto_edit, ideally inside -s.


Adding a local model to opencode without limit.context.
Auto-compaction never fires for it, and the session fails when the window fills.


Letting a text-protocol model run without a stop at the action.
It writes the observation too, and believes it (section 1). Use native tool calls or a stop sequence; a client-side cut only stops you acting on the invention.


Treating "the model stopped calling tools" as "the task is done".
opencode and Codex both ended our runs on a prose reply with the tests still failing. Verify with the tests, as Aider's --auto-test does, before reporting success.


Comparing harnesses from one run each.
Our tables are one run per setting on one task with a 4B model: enough to see mechanisms, not to rank products. Fix the model and effort, repeat runs, report cost beside the score.



Interview questions


What is the action boundary, and who enforces it?
The point where the model must stop generating so the harness can run the action and return the real result. With native tool calls the inference server enforces it (the reply ends with a tool-call finish reason); with text actions the harness must, by a stop sequence or by training plus the chat template. Without it, the model writes invented results.


mini-SWE-agent runs every command in a fresh subprocess. Why, and what does it cost?
Independent actions make sandboxing a one-line swap (docker exec) and runs easy to parallelise and replay. The cost: no persistent shell state, so cd and export must be repeated in each command.


Compare three compaction designs.
Codex: summarise at 90% of the window, keep recent user messages (server-side for OpenAI models). Gemini CLI: at 50%, summarise the oldest 70% into a state snapshot, then a second call critiques it. opencode: at the usable window, keep a recent tail of 25% (2k to 15k tokens) verbatim. Earlier and two-pass costs tokens but keeps more working room and a better summary.


How would you sandbox an agent's shell on macOS and on Linux?
macOS: Seatbelt profiles via sandbox-exec, deny by default, write only to the workspace, network off (Codex, Gemini CLI -s). Linux: bubblewrap for the file system plus seccomp for the network (Codex), or a container. Keep it on in headless mode, where nobody approves.


SEARCH/REPLACE text, a str_replace tool, or a patch grammar?
Text blocks work with any model and batch many edits in one reply but need a parser and a format per model. A str_replace tool is simple and exact but fails on whitespace drift unless the harness adds matchers (opencode has nine, Gemini CLI four). A patch grammar (Codex) is compact for multi-file changes and can be enforced at decoding time, but the model must be trained on it.


Your agent repeats the same failing tool call. What do you add?
Detection in the harness: identical-call counting (Gemini CLI after 5, opencode after 3), then a nudge, then a stop or a question to the user; a step limit as the last resort. Also look at the tool: a clearer error message or a smaller schema may remove the cause (Codex's justification rule in section 2).


How does Aider decide what to show the model of a repository it cannot fit?
tree-sitter tags, a file graph weighted by identifier references, personalised PageRank toward the files in the chat and the names in the message, then a binary search for the most ranked definitions that fit the token budget. See the Repo map lab tab.

What this tab is: Aider's repository map, computed for real


A coding agent has to know what is in a repository before it can change it, but a repository does not fit in a prompt. There are three answers in use. Search on demand: the model runs grep, glob and read itself, one call at a time (Claude Code, Codex, opencode, mini-SWE-agent). An embedding index: chunks of code are turned into vectors and the closest ones to the question are retrieved (Cursor). A ranked summary sent up front: Aider's repository map, which this tab opens up. Aider was built in 2023 for models with small windows and no tool calls, so it could not let the model search; it had to choose for it.


Everything below is Aider 0.86.2's own RepoMap class run on a real repository, the source of mini-SWE-agent v2.4.6 (59 Python files under src/minisweagent/; paths shown without that prefix). Nothing is simulated: the ranks are the PageRank values Aider computed, the map text is what Aider would put in the prompt. Script: src/repomap_lab.py.



How the map is built, in five steps


    

  1. Tags. tree-sitter parses every file into tags: each definition (a class, function or method name, with its line) and each reference (a use of a name).
    2. 

  2. A graph of files. For every name that is both defined and referenced, an edge runs from each file that uses it to each file that defines it. Its weight is mul × √(number of uses), where mul starts at 1 and is multiplied by 10 if your message mentions the name, by 10 if the name is a long (8 or more characters) snake_case, kebab-case or camelCase name, by 0.1 if it starts with an underscore, by 0.1 if more than five files define it, and by 50 if the using file is in the chat (repomap.py lines 487 to 514).
    3. 

  3. Personalised PageRank. PageRank (the random-surfer score) runs on that graph. "Personalised" means the surfer restarts not uniformly but at files you care about: each file in the chat, each file whose name you typed, and each file whose path contains a word you typed gets 100/N added to its restart weight (N = number of files; here 100/59 = 1.69) (lines 383 to 445).
    4. 

  4. Rank flows to definitions. Each file's rank is split across its outgoing edges by weight and summed per (defining file, name), so the map lists the most important definitions, not just files. Files already in the chat are skipped: their full text is sent anyway.
    5. 

  5. Fit the budget. A binary search finds how many ranked definitions fit the token budget (--map-tokens, default 1,024 when the model's window is unknown, as for a local model) and stops once the map is within 15 percent of it, above or below (lines 676 to 703). That is why a 2,048-token budget produced a 2,233-token map below.

Why this matters when you build a harness


    

  • It costs no model calls. The map is computed locally by a parser and a graph library, then paid for as input tokens on each request; agentic search pays a model call per grep.
    • 

  • It goes stale in the other direction. The map is recomputed when files change (Aider's --map-refresh), but it can only rank what the parser sees: strings, configs and dynamic dispatch carry no tags.
    • 

  • Agentic search won for strong models. Every tool-calling harness on this page lets the model search instead. Aider's idea survives as a cheap first message: a few hundred tokens of "what is where" before the first grep.
