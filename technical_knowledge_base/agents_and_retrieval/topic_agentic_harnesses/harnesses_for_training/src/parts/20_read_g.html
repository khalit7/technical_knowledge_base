6. Trajectories as training data: format, redact, filter

A trajectory is the full record of a rollout: every request, reply, tool call, tool result and token count. It is three things at once: an evaluation record (what did the agent do?), supervised training data (imitate the good ones), and RL data (weight each one by its advantage). Turning a pile of recordings into a dataset takes four steps, each shown on this page's own rollouts in the {{Rollout to dataset|#t-traj}} tab.

1. Normalise to one format. Every harness logs differently: our own loop wrote one line per call, the Claude Agent SDK wrote its message objects, Claude Code wrote stream-json. The formats trainers read:

FormatShapeHow it says "train on this"
OpenAI supervised fine-tuningJSONL, one {"messages": [...], "tools": [...]} per line; assistant tool_calls with arguments as a JSON string; tool messages with tool_call_id ({{guide|https://developers.openai.com/api/docs/guides/supervised-fine-tuning}})Per assistant message "weight": 0 or 1, "Controls whether the assistant message is trained against" ({{OpenAPI spec|https://github.com/openai/openai-openapi/blob/manual_spec/openapi.yaml}}; not on the guide page)
Hugging Face chat templateThe same messages rendered by the model's own Jinja templateapply_chat_template(..., return_assistant_tokens_mask=True), only for templates that mark assistant text with {% generation %} (transformers v5.18.0); TRL's assistant_only_loss needs the same markers and patches known templates such as Qwen3 ({{TRL docs|https://huggingface.co/docs/trl/main/en/sft_trainer}})
ShareGPT style"conversations": [{"from": ..., "value": ...}] with roles human, gpt, function_call, observation, system"The gpt and function will be learned by the model" ({{LLaMA-Factory data README|https://github.com/hiyouga/LLaMA-Factory/blob/main/data/README.md}})
Token-level (RL)Token ids, sampled log-probabilities, a loss mask, a reward or advantageThe mask of section 5

One personal agent already writes the third format: Hermes Agent can export its runs as ShareGPT-style trajectories, live at v0.21.5; the Atropos and Tinker training integrations it shipped in March 2026 releases are gone at v0.21.5, so the export is a dataset source, not a training loop ({{Personal agents: OpenClaw, Hermes Agent, and how they differ from coding harnesses|n:3c75c17b0d0d81bf9462fbeb09593e1c}}, section 3).

A detail that bites: tool-call arguments stored as a JSON string in one format and an object in another render differently through a template, so training text and inference text disagree; Nebius's trajectory release warns about exactly this ({{SWE-rebench-openhands-trajectories card|https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories}}).

2. Redact. Trajectories carry whatever the machine showed the agent. Ours contained the scratch folder's path (which includes the account name) in every Claude Code file-tool call, session and message ids, the Claude Agent SDK's list of the account's installed skills and commands in its first record, and model replies with em-dashes. The redactor keeps a whitelist of fields, maps the workspace to /work, replaces the user name, git identity and any e-mail address, and then refuses to write a file if a forbidden string survives (counts in the {{Rollout to dataset|#t-traj}} tab). A sibling page's recording shows why the git identity is on the list: a model copied the machine's name and e-mail into a git config command it tried to run ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}). We found no OpenAI or Anthropic guidance specific to scrubbing fine-tuning data; treat secrets and personal data in trajectories like any other training data.

3. Filter. The simplest way to learn from rollouts is to keep the successful ones and fine-tune on them: rejection sampling fine-tuning, the agentic version of STaR ({{arXiv 2203.14465|https://arxiv.org/abs/2203.14465}}), RFT ({{arXiv 2308.01825|https://arxiv.org/abs/2308.01825}}) and ReST-EM ({{arXiv 2312.06585|https://arxiv.org/abs/2312.06585}}). Two published agent cases:

  • SWE-Gym fine-tuned on 491 trajectories that resolved their task (sampled from GPT-4o and Claude 3.5 Sonnet in OpenHands): the 32B model went from 7.0 to 20.6% on SWE-bench Verified ({{arXiv 2412.21139|https://arxiv.org/abs/2412.21139}}).
  • SWE-smith ran SWE-agent with Claude 3.7 Sonnet on its synthetic tasks: 6,457 of 17,906 attempts resolved (36%), capped at 3 per task to 5,016 trajectories, and SWE-agent-LM-32B reached 40.2% Pass@1 on Verified ({{arXiv 2504.21798|https://arxiv.org/abs/2504.21798}}). The cap matters: without it, easy tasks that succeed every time dominate the data.

On our rollouts the filter is where section 3 comes back: filtering on the tests the agent could see would keep trajectories, filtering on the hidden verifier . The difference, trajectories, is a supervised dataset that teaches the too-loose regular expression on purpose.

4. Imitate, or re-solve? A recorded trajectory from another agent (or another harness) teaches that agent's habits. Terminal-Universe rebuilt workspaces from 359,593 public trajectories and compared imitating the source trajectories with having a teacher re-solve the recovered tasks: re-solving reached 52.1 on Terminal-Bench 2.1, imitation 36.7, below the 47.0 base model ({{Terminal-Universe|n:3d45c17b0d0d814abc07fde424e09a31}}; the page notes the gain is distillation from a stronger teacher as much as an environment effect). Public trajectory sets to look at: {{nebius/SWE-agent-trajectories|https://huggingface.co/datasets/nebius/SWE-agent-trajectories}} (80,036 trajectories, 13,389 resolved), {{SWE-bench/SWE-smith-trajectories|https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories}}, {{nebius/SWE-rebench-openhands-trajectories|https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories}} (67,074, 32,161 successful).
