The idea in one screen

The harness that runs an agent is also the ruler that scores it and the gym that trains it, so every harness choice (its tools, how it shows results, when it stops, which checks it trusts) becomes part of the score in evaluation and part of the skill in training.

A harness is the program around a model that turns its text into actions: it sends the request, runs the tool calls the model asks for, feeds the results back and decides when to stop (the parent, {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}, builds one in its Loop lab). As a product it is the agent you use (Claude Code, Codex); this page is about its other jobs. Fig. 1 is one episode of textstats-gym, the environment built for this page, and what its record is used for.

Fig. 1, step by step: one recorded rollout (Haiku 4.5, bash only, task T01)

  1. Reset. A fresh copy of the library gets the planted bug for task T01 (contractions split into two words), and a new python:3.13-slim container starts with no network, the workspace mounted at /work. The harness sends the model its system prompt, its one bash tool and the issue: word_count("don't stop") returns 3 but should return 2.
  2. Act, observe (calls 1 to 5). The policy writes a tool call; the harness runs it in the container and returns the clipped output as the next observation: ls -la /work, find, cat tests/test_core.py, cat textstats/core.py, then the tests, which print FAIL test_apostrophes_kept. Each call re-reads the whole conversation: 1,290 input tokens on call 1, 3,022 on call 5.
  3. Edit and re-test (calls 6 to 8). A sed command changes the word pattern from [a-z]+ to [a-z']+, a cat confirms it, and the visible tests all pass.
  4. Stop. Call 9 has no tool call, so the harness ends the episode. What it kept is the trajectory: 17 events (9 calls, 8 observations), 25,604 input tokens read in all.
  5. Verify. The verifier copies only textstats/ out of the workspace, ignores its tests and runs 20 checks in a fresh read-only container: 19 pass, and the held-out h_apos_quotes fails ('quoted' keeps its quotation marks). Binary reward 0, partial 0.95; the agent's own tests would have paid 1 (section 3).
  6. Four uses of one record. Ruler: the reward, averaged over tasks, scores the model and the harness (sections 1, 3). Gym: rewards in a group become advantages; only the tokens the model sampled get loss; new weights go back to the policy (sections 2, 4, 5). Dataset: the trajectory is redacted, converted and kept if it passed, so whichever verifier filters it decides what is imitated (section 6). Search: edit the harness, re-score, keep the best; on a noisy ruler the measured gain runs ahead of the true one (section 7).

The setup, used on every section. textstats-gym: ten bug-fixing tasks on a 60-line Python library, each with a hidden verifier that runs in a fresh container with no network. Two models: Qwen3-4B-Instruct-2507 (4-bit, local on an Apple M1 Pro) and Claude Haiku 4.5 (subscription). Four harnesses: bash only (one shell tool), file tools (list, read with line numbers, replace exact text, run tests), the same file tools without line numbers (one detail changed), and Claude Code itself. Harnesses are compared within each model; the two models are never compared as if they were the same thing.

What the rollouts showed
  • The harness moved the small model's success a lot and the strong model's little. Qwen3-4B passed the verifier in of its rollouts with bash only and with file tools; Haiku 4.5 stayed between and in all four harnesses, while its input tokens per rollout differed -fold (section 1).
  • The verifier decides what "solved" means. rollouts passed every test the agent could see and still failed the hidden checks; of them wrote the same plausible but too-loose regular expression (section 3).
  • Most groups carry no learning signal. With a pass/fail reward, of the local model's groups and of Haiku's had every rollout score the same, so their GRPO advantages are all zero (section 4).
  • Only a minority of a trajectory's tokens are the model's. of the local model's tokens are ones it sampled; the rest are prompt, tool output and template, and must be masked out of the loss. Re-rendering the trajectory through the chat template also adds tokens it never produced (section 5).
You need
  • The agent loop: model call, tool call, result, repeat (the parent's Loop lab, or {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}} section 1).
  • Policy gradients with a group baseline: GRPO ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}} section 3). Section 4 applies it; it does not derive it.
New terms
  • Scaffold: evaluation papers' word for the harness; scaffold sensitivity, how far the score moves when only it changes.
  • FAIL_TO_PASS / PASS_TO_PASS: checks the fix must flip, and checks it must not break.
  • Loss mask: which tokens of a trajectory enter the loss; token-in, token-out, training on the ids the engine sampled.
  • Rejection sampling fine-tuning: keep the passing trajectories, imitate them.
  • Winner's curse: the best of many noisy scores overstates its true value.
