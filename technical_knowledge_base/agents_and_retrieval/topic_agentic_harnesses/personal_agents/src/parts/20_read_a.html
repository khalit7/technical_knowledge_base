In one screen

A personal agent runs the same loop as a coding harness, but nobody starts it, nobody watches it, and much of what it does cannot be undone; so the engineering moves out of the loop, into what wakes it, how it sees what it acts on, and a gate in plain code that keeps irreversible actions for you to approve.

The resident agent on one page: where text enters, where actions leave, and where the gate sits. The bottom row is where an irreversible action ends up.

The loop in the middle is {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}'s; the memory tiers are {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}'s (section 8); injection, sandboxes and credentials are {{Agent security|n:3f15c17b0d0d81ad9fb7d1dd74217335}}'s. This page owns the rest: triggers, acting on a screen, the failure modes, the gate by undo class, and the products as published.

You need the agent loop (call the model, run the tool it asks for, append the result, repeat) from {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}, and prompt injection from {{Agent security|n:3f15c17b0d0d81ad9fb7d1dd74217335}} (section 2).

Resident: always running and started by events, not by you (a coding harness is invoked).
Gateway: the one long-lived process that owns every chat channel and session.
Heartbeat: a timer that wakes the agent to check a short checklist.
Computer use: acting through a screen: screenshots in, mouse and keyboard actions out.
Accessibility tree: the page as named elements (role, name), the structure screen readers use.
Grounding: turning "click Thursday 10:00" into the right element or pixel.
Steer: deliver a message that arrives mid-run before the model's next decision.
Action class: what it would take to undo an action: read, reversible, memory, irreversible.
Coding harness (Claude Code, Codex CLI)Personal agent (OpenClaw, Hermes Agent)
How a run startsYou start a sessionA message, a timer (heartbeat), a scheduled job or a webhook
How long state livesOne session, plus memory files you keepMonths: a searchable session history, memory files the agent itself edits, a profile of you
What it acts onA repository and a terminalYour accounts: chat, mail, calendar, browser, sometimes payments and devices
Who is watchingUsually you, at the terminalOften nobody: a heartbeat or a scheduled job runs while you sleep
Who writes into its contextMostly you, plus files you chose to openAnyone who can send you a message or an email: the input channel is open to third parties by design
What checks the workTests, compiler, CI, a diff you reviewUsually nothing automatic: "was my inbox handled well?" has no test suite
UndoGit: nearly everything is revertibleA sent message, a booking or a payment usually cannot be taken back
PermissionsPer-tool approval inside a session you watchStanding access to live accounts, granted once at setup
