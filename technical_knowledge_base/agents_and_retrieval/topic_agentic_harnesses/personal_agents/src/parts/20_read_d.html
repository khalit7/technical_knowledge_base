3. Hermes Agent, taken apart

Read at release v0.21.5 (git tag v2026.9.24, commit f97608f, 24 Sep 2026): its docs live in the repository under website/docs/. The release notes of v0.2.0 (12 Mar 2026) say it went "from a small internal project to a full-featured AI agent platform" in "just over two weeks"; that release already shipped the messaging gateway DOCUMENTED.

One agent class, many front doors

The architecture page's first design principle: "One AIAgent class serves CLI, gateway, ACP, batch, and API server. Platform differences live in the entry point, not the agent." (run_agent.py is now a facade; the loop lives in agent/conversation_loop.py.) Around it: a tool registry the architecture page counts as "70+ registered tools across ~28 toolsets" while the tools reference at the same tag says "~100 tools"; terminal commands can run on 7 backends (local, Docker, SSH, Daytona, Modal, Singularity, Vercel Sandbox); the gateway has "25+ platform adapters"; and "SQLite-based session storage with FTS5 full-text search" where sessions keep a parent/child lineage across compressions DOCUMENTED ({{architecture|https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/developer-guide/architecture.md}}). Memory providers and context engines are plugins, one of each active at a time.

The learning loop: skills it writes for itself

The problem it attacks. A resident agent repeats the same chores for months. A coding harness forgets how it solved something when the session ends unless you write a skill by hand; Hermes tries to write and maintain them itself.

  1. Two kinds of note. "memory stores small durable facts that should always be in context, while skills store longer procedures that should load only when relevant." MEMORY.md is capped at 2,200 characters (about 800 tokens) and USER.md at 1,375 (about 500), both injected into the system prompt; memory "does not auto-compact" DOCUMENTED ({{memory|https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/features/memory.md}}).
  2. Two triggers for writing a skill. The system prompt asks the agent to record a workflow worth repeating, one where it hit dead ends, or one the user corrected, with the skill_manage tool. Separately, after a turn that used at least creation_nudge_interval tool iterations (default 10), the agent forks a copy of itself in a background thread that replays the conversation and asks whether any skill or memory should be saved or updated (up to 16 iterations, same model by default; the source notes "the fork costs ~30K tokens / event"; skipped for scheduled jobs and interrupted turns) SOURCE (agent/turn_finalizer.py, agent/background_review.py).
  3. Patching in use. skill_manage can create, patch, delete and write files; targeted patches are preferred; every change is appended to ~/.hermes/skills/.curator_ledger.jsonl.
  4. A curator for the pile. hermes curator tracks how often each agent-created skill is viewed, used and patched and moves unused ones active to stale (14 days) to archived (30 days; archived, never deleted), checked at most every 168 hours when the agent has been idle 2 hours. Merging overlapping skills with a model is off by default ("a full curation sweep typically takes 50-100 API calls"). Pinned skills and skills used by scheduled jobs are never touched DOCUMENTED ({{curator|https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/features/curator.md}}).
  5. Review before commit, if you ask for it. With skills.write_approval: true every skill write is staged under ~/.hermes/pending/skills/ for /skills pending, /skills diff, /skills approve; memory has the same switch. Both are off by default; so is scanning the agent's own new skills for risky content, because "the agent can run the same code via terminal() ungated" (config comment) SOURCE.

What it costs, and how to check it. Each background review is another model call over the whole conversation; a skill written from one lucky run can encode the wrong lesson, and a memory file the agent edits is a place where text it read can persist into every later prompt (the reason Hermes scans memory entries for injection and exfiltration patterns before accepting them). The check is the ledger: read what the agent wrote and why. The research version of this idea, agents that improve their own harness, belongs to {{Harnesses for training|n:3f15c17b0d0d815ea579d6c80065aa36}}.

Never-ending context, scheduled work, trajectories

  • Compression runs at two levels: a gateway safety net at 85% of the window before a message is handled, and the agent's own compressor at a threshold of 0.50 of the window, raised to 0.75 for windows under 512K tokens and capped at 256,000 tokens. It first clears old tool outputs over 200 characters, keeps the first 3 messages and a recent tail, and summarises the middle with an auxiliary model into fixed headings (Goal, Constraints and Preferences, Progress, Key Decisions, Relevant Files, Next Steps, Critical Context) SOURCE (agent/context_compressor.py; the docs' own worked example of 100,000 tokens for a 200K window ignores the 0.75 floor in the code, which gives 150,000). {{Context engineering|n:3f15c17b0d0d811292cee46514370431}} owns compaction in general.
  • Searching old sessions: the session_search tool runs FTS5 queries over ~/.hermes/state.db and "return[s] actual messages from the DB, no LLM summarization"; section 5 tests whether a model uses such a tool when it should.
  • Scheduled jobs are "first-class agent tasks (not shell tasks)": each runs in a fresh session, can attach skills, and delivers to any platform; "Cron-run sessions cannot recursively create more cron jobs." DOCUMENTED
  • Trajectories: sessions export as ShareGPT-format JSONL "for use as training data, debugging artifacts, and reinforcement learning datasets". The first releases (March 2026) also shipped Atropos RL environments and an optional Tinker training path; at v0.21.5 neither is in the dependency list or the source tree SOURCE. Trajectories as training data belong to {{Harnesses for training|n:3f15c17b0d0d815ea579d6c80065aa36}}.
  • Moving from OpenClaw: hermes claw migrate imports persona, memory (daily notes merged into MEMORY.md), skills, model settings, MCP servers, channel tokens and allowlists, always with a preview and a backup; API keys only with --migrate-secrets, and only from an allowlist; heartbeat, cron jobs, plugins and hooks are archived, not imported DOCUMENTED ({{migration guide|https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/guides/migrate-from-openclaw.md}}).
