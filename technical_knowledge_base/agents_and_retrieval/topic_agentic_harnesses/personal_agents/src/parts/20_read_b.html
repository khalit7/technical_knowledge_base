1. Resident: what wakes the agent, and where the event goes

A personal agent should act when an email arrives at 07:40 or when you text it from a bus, and notice on its own that a bill is due. So the loop lives inside a program that is always running and turns events into runs. Step through one illustrative day, met by both shapes:

Illustrative schedule (not a recording): the same six events, met by an invoked harness (top) and a resident agent (bottom).

The pieces, in the order a message meets them (OpenClaw's names; Hermes Agent has the same shapes):

  1. Channel adapter: speaks one platform's protocol and turns a message into an event (OpenClaw uses Baileys for WhatsApp and grammY for Telegram; it lists more than 20 channels, from Discord and iMessage to Signal, Slack and Teams) DOCUMENTED.
  2. Gateway: "A single long-lived Gateway owns all messaging surfaces", one per host; apps, CLI and web UI talk to it over a WebSocket on 127.0.0.1:18789 by default DOCUMENTED ({{architecture|https://docs.openclaw.ai/concepts/architecture}}).
  3. Trigger: a message (from you or from anyone else), a heartbeat (OpenClaw's default every 30 minutes, or 1 hour when it reuses an Anthropic subscription login; a reply of NO_REPLY means nothing needed attention and is dropped), a scheduled job (cron) or a webhook DOCUMENTED ({{heartbeat|https://docs.openclaw.ai/gateway/heartbeat}}). Hermes treats scheduled jobs as "first-class agent tasks (not shell tasks)": each runs in a fresh session, can attach skills and delivers to any platform, and "Cron-run sessions cannot recursively create more cron jobs."
  4. Session routing: which history an event joins. OpenClaw's defaults: all direct messages share one main session, each group chat gets its own, each scheduled job starts fresh, each webhook is isolated. The docs warn: "If multiple people can message your agent, enable DM isolation. Without it, all users share the same conversation context, so Alice's private messages would be visible to Bob" (dmScope: per-channel-peer, the recommended value) DOCUMENTED ({{sessions|https://docs.openclaw.ai/concepts/session}}).
  5. Agent runtime: the loop, with tools, a system prompt assembled from files, and compaction. This is the part a coding harness already is; OpenClaw can hand a turn to Claude Code or Codex as the runtime (section 8).
  6. Delivery: the reply goes back out on a channel; heartbeat alerts go to your own direct messages by default.

What it costs. A process that must stay up (a laptop that sleeps misses its heartbeats; people use a small server); a model call on every heartbeat even when nothing happened (hence checklists answered with one token, and the longer interval on a subscription login); and an open door: a gateway listening on a port, and channels that let anyone who knows your number put text in front of the model (sections 6 and 9).

Predict: a heartbeat fires every 30 minutes and its checklist prompt is about 3,000 tokens. Roughly how many input tokens a day does the heartbeat alone send, before anything is found?
48 heartbeats x 3,000 = 144,000 tokens a day, every day, for nothing found. Whether it matters depends on caching: a stable prefix (system prompt and checklist unchanged between ticks) is read from the prompt cache at a tenth of the input price on Anthropic models, but only if the cache entry is still alive; a 5-minute cache entry has expired by the next 30-minute tick, a 1-hour one has not, and a prefix shorter than the model's minimum (4,096 tokens on Haiku 4.5) is never cached at all ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}, section 2, owns the cache rules). The 3,000-token prompt is an assumption for the drill.
