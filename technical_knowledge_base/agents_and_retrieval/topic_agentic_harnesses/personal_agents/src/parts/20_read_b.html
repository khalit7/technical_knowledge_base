1. From invoked to resident: the pieces, from zero

The problem. An agent loop (call the model, run the tool it asks for, append the result, repeat until it stops) needs something to start it. In a coding harness that something is you, typing in a terminal. A personal agent should act when an email arrives at 07:40 or when you text it from a bus, and should notice on its own that a bill is due. So the loop has to live inside a program that is always running and that turns events from the outside world into runs.

The pieces, in the order a message meets them (names as OpenClaw uses them; Hermes Agent has the same shapes, section 3):

  1. Channel adapter: code that speaks one messaging platform's protocol and turns an incoming message into an event (OpenClaw uses the Baileys library for WhatsApp and grammY for Telegram). OpenClaw lists more than 20 channels, from Discord and iMessage to Signal, Slack and Teams DOCUMENTED.
  2. Gateway: one long-lived process that owns every channel and every session. In OpenClaw, "A single long-lived Gateway owns all messaging surfaces", there is one per host, and the apps, CLI and web UI talk to it over a WebSocket on 127.0.0.1:18789 by default DOCUMENTED ({{architecture|https://docs.openclaw.ai/concepts/architecture}}).
  3. Trigger: what starts a run. Four kinds: a message from you (or from someone else), a heartbeat (a timer that wakes the agent to check a short checklist; OpenClaw's default is every 30 minutes, or 1 hour when it reuses an Anthropic subscription login, and a reply of NO_REPLY means nothing needed attention and is dropped), a scheduled job (cron), and a webhook DOCUMENTED ({{heartbeat|https://docs.openclaw.ai/gateway/heartbeat}}).
  4. Session routing: which conversation history an event joins. OpenClaw's defaults: all direct messages share one main session, each group chat gets its own, each scheduled job starts a fresh session, each webhook is isolated. The docs warn: "If multiple people can message your agent, enable DM isolation. Without it, all users share the same conversation context, so Alice's private messages would be visible to Bob" (setting dmScope: per-channel-peer, the recommended value) DOCUMENTED ({{sessions|https://docs.openclaw.ai/concepts/session}}).
  5. Agent runtime: the loop itself, with tools, a system prompt assembled from files, and compaction when the window fills. This is the part a coding harness already is; OpenClaw can even hand a turn to Claude Code or Codex as the runtime (section 2).
  6. Delivery: the reply goes back out on a channel; heartbeat alerts go to your own direct messages by default.

What it costs. A process that must stay up (a laptop that sleeps misses its heartbeats; people use a small server), a model call on every heartbeat even when nothing happened (the reason heartbeats are checklists answered with one token, and why OpenClaw lengthens the interval on a subscription login), and an open door: a gateway listening on a network port, and channels that let anyone who knows your number put text in front of the model. Sections 6 to 8 are about that door.

Predict: a heartbeat fires every 30 minutes and its checklist prompt is about 3,000 tokens. Roughly how many input tokens a day does the heartbeat alone send, before anything is found?
48 heartbeats x 3,000 = 144,000 tokens a day, every day, for nothing found. Whether it matters depends on caching: a stable prefix (system prompt and checklist unchanged between ticks) is read from the prompt cache at a tenth of the input price on Anthropic models, but only if the cache entry is still alive; a 5-minute cache entry has expired by the next 30-minute tick, a 1-hour one has not, and a prefix shorter than the model's minimum (4,096 tokens on Haiku 4.5) is never cached at all ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}, section 2, owns the cache rules). The 3,000-token prompt is an assumption for the drill.
