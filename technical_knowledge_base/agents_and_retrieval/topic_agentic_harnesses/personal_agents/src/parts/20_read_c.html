2. Acting on a screen: computer-use and browser agents

Mail and calendars have APIs; the garage's booking form has only a screen. A computer-use agent runs the same loop with a screen as its one tool: the harness returns a screenshot, the model answers with an action at pixel coordinates, the harness performs it and returns the next screenshot. A browser agent may read the page as an accessibility tree instead. Here is one real page seen both ways: a fake booking form written for this page, rendered and read by headless Chrome (src/cu/capture.mjs), with the task "book Thursday 10:00".

The same page as an accessibility tree (Chrome's, flattened with a ref per node)










What the measurement shows. A screenshot action names a place; a tree action names an element. When a cookie banner loaded after the screenshot was taken, everything moved down 49 px, and the click at the remembered point (300, 230) landed on Thu 8 Oct, 08:30: a plausible, silent, wrong booking (measured with document.elementFromPoint on the second render). Real agents take a fresh screenshot after every action precisely to catch this; the failure is a page that changes between looking and clicking, and a model that does not look again.


The screen as a tool, in Anthropic's version (docs read 24 Oct 2026, toolset computer_toolset_20260801; {{computer use tool|https://platform.claude.com/docs/en/docs/agents-and-tools/tool-use/computer-use-tool}}) DOCUMENTED:


    

  • 17 member tools: screenshot, zoom (a region at full resolution), left_click at a coordinate, right, middle, double and triple clicks, left_click_drag, mouse_move, button down and up, cursor_position, scroll, type, key, hold_key, wait.
    • 

  • Coordinates live in the image you sent. "Claude returns coordinates in the pixel space of the image it receives, keep the scale factor you used so you can map those coordinates back to your screen." The API does not downscale: newer models accept up to 2,576 px on the long edge and 4,784 visual tokens (⌈width / 28⌉ x ⌈height / 28⌉, about 3.75 megapixels), earlier ones 1,568 px and about 1.15 megapixels. A macOS Retina capture has "a device pixel ratio of 2, so the image is twice the resolution of the logical screen coordinates": forget the factor and every click lands at twice its intended position.
    • 

  • Resolution. "For general desktop tasks, use 1024x768 or 1280x720; for web applications, use 1280x800 or 1366x768", and nothing above 1920x1080.
    • 

  • Cost. Screenshots are "roughly 1,000-1,800 input tokens each", so a 50-step task carries 50,000 to 90,000 tokens of screenshots before any text (50 x 1,000 and 50 x 1,800; derived). This page's 600 x 440 form is ⌈600/28⌉ x ⌈440/28⌉ = 22 x 16 = 352 visual tokens by the formula above.
    • 



The tree, in Microsoft's Playwright MCP server: "Uses Playwright's accessibility tree, not pixel-based input", "No vision models needed", and its click takes a target: "Exact target element reference from the page snapshot" ({{playwright-mcp|https://github.com/microsoft/playwright-mcp}}). Meta's Muse made the same choice for its browsing sub-agent, which "sees an accessibility tree snapshot of the page, not the raw DOM" (section 8).

Grounding is the hard part. SeeAct (Zheng et al., Ohio State, Jan 2024; {{arXiv 2401.01614|https://arxiv.org/abs/2401.01614}}) separated planning from grounding: GPT-4V could "successfully complete 51.1 of the tasks on live websites if we manually ground its textual plans", but "grounding still remains a major challenge", with a substantial gap to oracle grounding even for its best strategy, which combined the HTML structure with the screenshot. Anthropic's own list of limitations names the other two habits that matter for a personal agent: "Claude sometimes acts as if its actions succeeded without explicitly checking their results", and "instructions on webpages or contained in images might override your instructions". Scores on OSWorld and its relatives, with their step budgets and the ways they were gamed, belong to {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}} (Computer use section).
