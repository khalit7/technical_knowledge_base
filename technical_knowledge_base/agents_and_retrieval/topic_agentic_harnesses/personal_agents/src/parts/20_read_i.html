Interview rehearsal

What is the difference between a coding harness and a personal agent, in one minute?
Same agent loop; different boundary. A personal agent is resident (gateway daemon, triggers from messages, heartbeats and schedules), holds standing access to live accounts, reads text from anyone who can message you, often acts with nobody watching, has no test suite to verify its work and little undo. So the engineering moves to session routing, memory tiers, mid-run message policy, and enforcement outside the model: a code gate by action class and trigger, out-of-band approvals, credentials it never sees, sandboxes.
Design the approval flow for an agent that can send email and pay bills.
Classify actions: read, reversible (draft, calendar), irreversible (send, pay). Reads run; reversible changes run with an undo record; irreversible ones become pending requests in a queue rendered by the app, not the chat, showing the exact payload and the conversation that led to it; unattended runs (heartbeat, cron) cannot create irreversible requests at all, only drafts and a message to the owner. Pending requests expire, can be withdrawn by the agent, and are invalidated by a newer message in the same conversation. Payment credentials live in a separate service that substitutes them on the way out for allowed payees only.
A user sends a correction while the agent is mid-task. What should happen?
Deliver it at the next tool boundary, before the next model call (steer), or abort and restart with it (interrupt); never queue it behind the current run if the run can take irreversible actions. Do not kill a running tool mid-write. OpenClaw steers by default and skips unstarted sequential calls; Hermes redirects by default.
How would you give a never-ending assistant memory?
Tiers: a small capped profile in every prompt, a searchable store of past sessions (full-text, with stemming, or embeddings) used through a tool and, for known patterns, retrieved by the harness, procedures as skills loaded on demand, and compaction of the live session. Then test whether retrieval actually happens: a cheap model may never call the search tool unless told when to.
How do you evaluate a personal agent with no verifier?
Scenario suites on fake accounts with checks on actions, not prose (OpenClaw's ten-scenario pack: reminders, approvals denied, no fake progress, no secret leaks); counters for irreversible actions taken without approval and for corrections that arrived too late; trajectory review with a rubric ({{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}).
Your agent must book things on websites with no API. Screenshot or accessibility tree?
The tree wherever the site exposes one: an action names an element, observations are short text, and a layout shift does not move the target (section 2's 49 px banner booked the wrong slot by coordinates). Keep screenshots for what has no tree (canvas widgets, desktop apps, remote desktops), send them at a known scale and map coordinates back, take a fresh one after every action, and put the final "Confirm" behind the gate as an irreversible action.
