Compaction lab: eight recorded sessions, four summaries

Everything here is read from the recordings made for this page (Claude Code 2.1.290, Claude Haiku 4.5, 6 Oct 2026). Section 4 of the Reading tab tells the story; this tab is the evidence, call by call. How the sessions were driven:

claude -p --input-format stream-json --output-format stream-json --verbose \
  --no-session-persistence --setting-sources project --strict-mcp-config \
  --model haiku --permission-mode acceptEdits --tools "Read,Edit,Write,Bash,Grep,Glob" \
  --allowedTools "Bash(python3:*)" "Bash(python:*)" "Bash(ls:*)" "Bash(cat:*)" \
  --append-system-prompt "Never use the em-dash character." [--autocompact 100000]

# then, on standard input, one JSON line per user turn, each sent after the previous turn's result record:
{"type":"user","message":{"role":"user","content":"Before we start, note two things ... Do not edit the tests."}}
{"type":"user","message":{"role":"user","content":"/context"}}
{"type":"user","message":{"role":"user","content":"/compact"}}
{"type":"user","message":{"role":"user","content":"/context"}}
{"type":"user","message":{"role":"user","content":"Without using any tools, answer from memory ..."}}

/context and /compact are commands, not prompts: /context answers without a model call (its turn costs nothing), /compact runs the summarising call inside Claude Code and emits a compact_boundary record with the token counts before and after. The automatic sessions used the same driver with one task message that also asked for five 75 KB log files to be read in full.

One column per model call of the main loop, to scale (cache read, cache write, fresh input). Dashed red line: a compaction; grey: the recall question.

What each compaction cost




"Compaction turn" is the change in the CLI's total_cost_usd across the /compact turn (manual) or, for the automatic run, the input of the hidden summarising call derived as the session's modelUsage input minus every streamed call. "First call after" is the next model call's cache read and cache write: the startup prefix is read back, the summary is written as a new prefix.
