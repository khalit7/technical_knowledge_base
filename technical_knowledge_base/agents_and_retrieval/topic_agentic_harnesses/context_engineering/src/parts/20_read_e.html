5. Memory files and skills: always loaded against loaded when needed

Some instructions must reach every task (how to run the tests, what never to touch); others matter for one kind of task (how to write release notes). Anything in the startup context is paid on every call and competes for attention; anything outside must be found. Memory files are plain text loaded into every session: Claude Code reads CLAUDE.md (and, per its docs, AGENTS.md, the cross-vendor name). Skills use progressive disclosure: a folder with a SKILL.md whose short description sits in the startup context; the body is read only when the model calls the Skill tool, and files it links only if needed (the three levels in Anthropic's Equipping agents for the real world with Agent Skills, 16 Oct 2025). Load order and rule syntax belong to {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}}; here only the window cost.

The same 3,834 bytes cost about 1,000 tokens as CLAUDE.md and about 40 as a skill

A 40-rule release-notes procedure as a project CLAUDE.md, and separately as .claude/skills/release-notes/SKILL.md with a one-sentence description; startup context from /context in fresh sessions (Claude Code 2.1.290, Haiku 4.5; tools Read, Edit, Write, Bash, Grep, Glob, Skill). The skill row includes the descriptions of 14 skills that ship with Claude Code (about 1.7k tokens).

Asked to "Write the release notes for textstats version 0.2", Haiku called the Skill tool on its first call, and the next call wrote 1,361 new tokens to the cache: the body, prefixed with the skill's base directory, delivered as a message in the history MEASURED. It then followed the procedure (ran the tests, listed the public functions, ended with "Reviewed-by: (pending)"). Enabling the Skill tool also changed the tool list, so that session's first call found nothing cached and wrote all 15,584 tokens: section 2's rule again.

6. Subagents: a second window for the reading

Some subtasks read a lot and answer briefly: "which module defines a class?" over a whole package. Done in the main loop, every file read stays in the main history. A subagent is a second agent loop with its own fresh window: the parent writes it a task, it reads, and only its final text returns as one tool result. Measured on a 30-module Python package (121 KB) with "Read every module in service/ in full ... which module defines a class, and which module has the largest number of functions?", twice without the Agent tool and twice told to delegate to one general-purpose subagent (Haiku 4.5 throughout).

A subagent keeps the parent's window at a quarter, and processes two to three times the tokens

Per run: tokens in the main loop's last request (what the parent carries forward), in the subagent's last request, and all input processed in the session (from the result's per-model usage); API-price equivalent of the whole session beside each run.

Without a subagent Haiku read all 30 files in one turn of parallel Reads and the main window ended at 62,442 and 64,533 tokens; with one, at 16,351 and 16,409, while the subagent's own window grew to 43,503 and 52,694 and then disappeared MEASURED. Cost was about the same ($0.130 and $0.134 against $0.134 and $0.139) because nearly all of it was cache reads; on a question one grep answers, the subagent only added cost: $0.057 against $0.020, 2.8x MEASURED.

So a subagent buys isolation, not savings: the parent's later calls stay small, its attention is not spent on 46,000 tokens of code it no longer needs, and it compacts later. Anthropic's guidance has subagents return "a condensed, distilled summary" of about 1,000 to 2,000 tokens (29 Sep 2025). Two traps: the subagent sees nothing of the parent's history, so the task message must carry everything; and the CLI's result.usage leaves the subagent's calls out while modelUsage includes them (measured on the parent page). When several agents must make decisions that agree, isolation becomes a coordination problem: {{Multi-agent patterns|n:3c65c17b0d0d8194a306c37803387bf3}} owns that.

7. Notes outside the window: state that survives

A task longer than one window or one session must leave its state where the next window can read it, and the history is not that place: compaction rewrites it and a new session starts without it.

  • Progress files and handoff notes. Anthropic's long-running harness has an initializer agent write a feature list (every feature initially failing) and a progress log; each later session reads them, does one feature, tests it, commits and updates the log (26 Nov 2025). Git history is part of the note.
  • Todo lists as recitation. Manus has the agent rewrite a todo.md as it goes, keeping the plan in the most recent part of the context, where it is least likely to be lost (18 Jul 2025); Claude Code's TodoWrite tool plays the same role.
  • A memory directory as a tool. The Claude API's memory tool (memory_20250818) gives the model file commands (view, create, str_replace, insert, delete, rename) on a /memories directory your application stores, with system-prompt text telling it to check the directory first and assume the window may be reset at any moment (memory tool, read 6 Oct 2026). On Anthropic's own evaluation, memory tool plus context editing improved performance by 39% over baseline, context editing alone by 29% (29 Sep 2025; vendor-reported).
  • The file system as context. Keep a pointer instead of the content: a path, a URL, a query. Manus calls the file system "the ultimate context" and makes every compression restorable this way; Anthropic calls it just-in-time context.

Who curates, and when. {{Just-in-Time Memory|n:3e95c17b0d0d818f89b3f066f816727b}} (Salesforce, 23 Sep 2026) curates an agent's memory at read time, once the task is known: untrained read-time curation beat untrained write-time memory in 15 of 17 comparisons, though most of the headline +16 points comes from RL training. {{Proactive Memory Agent|n:3e25c17b0d0d81ce85e0c6d82f6beb4c}} (Meta AI, 9 Jul 2026) runs a second model beside the agent that keeps a small memory bank and injects reminders: Sonnet 4.5 went from 37.6% to 45.9% on Terminal-Bench 2.0 with an Opus 4.6 memory agent, single runs.
