4. Compaction, forced on purpose

Clearing keeps single results small, but the history still grows by every reply and action. Compaction replaces it: the harness asks a model to summarise the conversation, then starts a fresh window with the startup context, the summary and whatever it chooses to carry over. The designs, from crudest to most engineered:

  1. Drop the oldest turns (a sliding window): free; silently loses the task statement unless it is pinned.
  2. Clear old tool results (section 3): "one of the safest lightest touch forms of compaction" (Anthropic, 29 Sep 2025).
  3. Summarise everything into one structured message and restart from it.
  4. Summarise the older part, keep the recent tail verbatim. Claude Code 2.1.290 does this: every compaction record here carries a "preserved segment" of five messages MEASURED; the JetBrains summariser kept the last 10 turns. The common choice; Codex triggers at 90% of the window and other harnesses at other thresholds, read from source on {{Other coding harnesses|n:3c65c17b0d0d819fa3cefdcd2ccff2f7}}.
  5. On the provider's side or inside the model: the Claude API's compact_20260112 edit summarises past a trigger (150,000 input tokens by default); trained compressors and models that rewrite their own context go further (closed block below).

Forcing Claude Code to compact (the parent's sessions never came near 200K). Manual: a script keeps one claude -p --input-format stream-json session open and sends the task, then /compact, then a question. Automatic: --autocompact 100000 shrinks the window Claude Code compacts against to its 100K minimum, and the task reads five 75 KB logs (CLAUDE_CODE_AUTOCOMPACT_PCT_OVERRIDE=16 as well left the buffer at 33k: size, not the percentage, triggered it MEASURED). Each first message also said "the reviewer for this change is Ilse Marten, and the ticket number is TS-4471", and the folder's CLAUDE.md held "Release codename: KESTREL."; afterwards each session was asked, tools forbidden, to recall them, quote what the test runner first printed, and say what it changed.

Compaction cuts the request to a fifth; without it the same task grows call by call

One column per model call, to scale: the tokens its request held (cache read + cache write + fresh), from the recordings. The summarising call itself is hidden from the stream and drawn as the dashed marker. "No compaction" is a different run of the same task, so its path differs: recorded sessions are paths, not samples.

What happened. The three manual compactions took 18,968, 17,969 and 18,390 tokens down to 2,258, 2,357 and 2,472 in 23 to 32 seconds, and the turn that ran each cost $0.015 to $0.021 at list price MEASURED. The automatic one first failed ("too_few_groups": right after the five parallel reads there was only one exchange to summarise), let the next call go out at 126,531 tokens, then succeeded: 127,242 down to 1,971 in 27.7 seconds. That summarising call read about 127,959 tokens, 113,729 of them fresh rather than from cache (derived: the session's modelUsage input minus every streamed call), about $0.12: on a big history the summary is a large cost of its own. The first call after every compaction read the startup prefix (about 12,200 tokens) from cache and wrote the rest again: the summary is a new prefix.

Recall after the task, judged by hand against the recordings; hover a score for the reason. One run of each: what can happen, not rates.

What survived. The chat facts survived every compaction: the summary has a section "All user messages" that copies them. The CLAUDE.md codename survived too, not through the summary: Claude Code re-reads the project CLAUDE.md from disk after compacting. The change survived, with code snippets. What went was verbatim tool output: all three uncompacted controls said correctly that the runner printed only "FAIL" lines and no assertion message; of the three manual compactions, two said they no longer had it and one confidently quoted its own later diagnostic output as what the tests printed. The large uncompacted run, at 130K tokens, put a maintainer note in two log files when it was in one.

Compaction on the provider's side and inside the model: the API, trained compressors, models that manage their own context


Server-side. The Claude API's compact_20260112 edit (beta header compact-2026-01-12) summarises when the prompt passes a trigger, 150,000 input tokens by default and at least 50,000, takes your own instructions for the summary, and returns a compaction block that replaces everything before it; a newer on-demand form (beta compact-2026-09-04) is now the recommended one (compaction docs, read 6 Oct 2026).


Trained compressors. Cognition describes fine-tuning a smaller model whose only job is compressing history (12 Jun 2025); {{End-to-End Context Compression at Scale|n:3d45c17b0d0d81eb90a8d70a5ce84d19}} (the Latent Context Language Models paper) compresses the context into soft tokens inside the model. A lighter hybrid keeps the text summary and adds what it loses: REMORY trains a small network to append a bounded run of soft memory tokens after the summary so a frozen model continues as it would with the full history; on SummHay it approached the full-context joint score with 5.2% of the input positions, and Qwen3.8-27B and GLM-5.3-Flash repeated fewer tool outputs and made fewer tool errors on BrowseComp and Terminal-Bench 2.1 ({{REMORY (arXiv 2610.11287)|https://arxiv.org/abs/2610.11287}}).


The model manages its own context. A Context Language Model (CLM) is given its context as a file it may rewrite without restriction, so what to keep becomes model behaviour, and several agents' contexts become several files. Built zero-shot from existing models, CLMs beat the best harness-side strategies the authors compared: 11.4% higher accuracy with 21.5% fewer FLOPs on BrowseComp-Plus, 5% higher scores with 59% fewer FLOPs on 12-hour EdgeBench. The policy can be taught: evolved natural-language instructions added up to 35.9 points on a held-out context-management task, and online RL raised Qwen3.5-9B on BrowseComp-Plus by 47.6% over its untrained start with 12% fewer FLOPs, though a summary harness trained the same way ends within noise of it, so the trained advantage is mainly cost ({{Context Language Models|n:3fe5c17b0d0d8118b076cd2bacb61c0d}}; {{arXiv 2609.37725|https://arxiv.org/abs/2609.37725}}; not the Latent Context Language Models above). Training any compacting agent has a credit problem: one trajectory spans several sessions, and broadcasting one trajectory-level advantage to every session cannot tell which helped; Mosaic shapes each session's advantage by its estimated contribution and beat broadcasting on BrowseComp with Qwen3.5-4B, in compaction and subagent-forking runs, using fewer sessions ({{Mosaic (arXiv 2610.22174)|https://arxiv.org/abs/2610.22174}}).
