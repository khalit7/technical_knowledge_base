Cache lab: what a prompt cache reads, writes and charges, call by call

This simulator applies Anthropic's documented caching rules (section 2 of the Reading tab) to an agent session you configure: the request is a row of blocks in the order tools, system, messages; a cache entry is written at each breakpoint and keyed on the exact prefix up to it; a read looks back at most 20 block positions from each breakpoint for an unexpired entry; a prefix below the model's minimum is not cached; entries expire after 5 minutes or 1 hour without use. Prices are the list prices of the chosen model. It is a model of the rules, not of Anthropic's servers: block sizes are inputs you set, and the first preset's are taken from the recorded runs.

What the presets teach

  • One growing text block (the parent's Loop lab harness): the transcript is a single block whose content changes every call, so no prefix ever matches past the system prompt; once past the minimum it is written in full every call.
  • 25 blocks per turn: a turn with many separate blocks (for example a harness that splits each tool result into several text blocks) pushes the previous turn's entry out of the 20-position lookback, and the automatic breakpoint finds nothing to read. A second breakpoint at the end of the system prompt limits the damage to the history; placing one at the start of each turn would fix it.
  • Pauses longer than the lifetime: with 5-minute entries and 6-minute gaps every call rewrites everything; the 1-hour lifetime costs more per write and wins as soon as a session pauses.
