8. Context rot: recall decays before the window is full

The problem. A window of 200,000 tokens does not mean the model uses 200,000 tokens equally well. Context rot is the name that stuck for the drop: "as the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases" (Anthropic, 29 Sep 2025). For an agent it is the reason to keep the window lean even when it is far from full, and the reason the levers above are worth their trouble.

How it is measured. A needle test hides a fact in long filler at a chosen depth and asks for it back. The classic version saturates: a needle that repeats the question's words is a text search. Harder versions remove the shared words (the model must match by meaning), or ask for something that needs several lines (a value assigned five times, where only the last counts). The benchmarks are reviewed on {{Long-context and multimodal benchmarks|n:3ef5c17b0d0d810bb4dfc98919c9be8a}}; the Needle lab runs small versions of all three on real code.

Right answers per task and haystack length, Claude Haiku 4.5 (top) and a local 4B model (bottom; local model on Apple M1 Pro, a different and much smaller model). Lengths are measured prompt tokens. Recorded 6 Oct 2026.

Claude Haiku 4.5 found the literal needle in all 20 cases and the non-literal one in all 20, from 2,201 to 113,710 tokens MEASURED. Tracking was the weak task: 28 of 32 right, and the four misses (at 2K, 16K, 16K and 64K tokens) all named an earlier assignment instead of the last; at 64K and 120K, four of the nine replies that listed the assignments found only four of the five, and still named the right final value. Within these lengths the errors did not grow with length: this run does not show rot for Haiku, and says only that lookup is easy and keeping order is not.

The local 4B model (Qwen3-4B-Instruct-2507, 4-bit, on the shared mlx_lm.server) found the literal needle in all 13 cases, from 781 to 11,622 tokens (its tokenizer counts the same code in fewer tokens than Claude's). Asked directly "In which city is the Semperoper?" it answered Dresden. With the same fact as a comment inside 1K to 12K tokens of code, it answered Dresden in 4 of 13 cases and otherwise named Berlin, Boston, San Francisco, Seattle or Portland MEASURED: the code in front of it pushed aside knowledge it has. Drew Breunig calls this context distraction, "when a context grows so long that the model over-focuses on the context, neglecting what it learned during training" (22 Jun 2025); here it took only 781 tokens. On tracking it scored 10 of 20 with no trend in length (0 of 5 at the shortest, 5 of 5 at about 5,700 tokens), every miss naming an earlier assignment: a capability limit at any length, not rot.

What this means for a harness. The literature finds the same shape at scale: position matters (the middle of a long context is recalled worst), literal lookup holds while everything else degrades, and distractors make it worse (see the Needle lab's notes). An agent's context is the worst case on all three counts: the facts it needs are scattered through tool results, rarely share the question's words, and sit among near-duplicates (the same file read twice, five similar test runs). The large uncompacted session of section 4 is a small instance: at 130K tokens it placed a note in two log files when it was in one. Keeping the window small is not only about cost.
