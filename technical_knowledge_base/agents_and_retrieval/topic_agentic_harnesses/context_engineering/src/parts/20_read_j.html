9. Context rot: recall decays before the window is full

A 200,000-token window does not mean 200,000 tokens used equally well. Context rot is the name that stuck: "as the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases" (Anthropic, 29 Sep 2025). A needle test hides one fact at a chosen depth in long filler and asks for it back. Here the haystack is real Python (files of the Python 3.9 standard library in a fixed shuffled order, cut to each length) and three needles are each hard in a different way:

  • Literal: RELEASE_PORT = 8371 # port of the textstats release box; "What value is RELEASE_PORT set to in the file above?" shares the needle's words: a lookup.
  • Non-literal (in the style of NoLiMa): # Ops note: the textstats release box sits in the rack right next to the Semperoper.; "In which city is the textstats release box located? Use what the file says plus general knowledge." The answer, Dresden, is not in the file: find the line by meaning and add one known fact.
  • State tracking: RETRY_LIMIT = N assigned five times at random depths; "What is the value of RETRY_LIMIT at the end of the file?" needs all five, in order.

Lookup holds to 114K tokens; keeping order fails at any length, and a small model ignores what it knows

Recorded 6 Oct 2026; results in src/inputs/needle_*.json.

Claude Haiku 4.5 found the literal needle in all 20 cases and the non-literal one in all 20, from 2,201 to 113,710 tokens MEASURED. Tracking was 28 of 32: the four misses (at 2K, 16K, 16K and 64K tokens) all named an earlier assignment, and at 64K and 120K four of the nine replies that listed the assignments found only four of the five yet named the right final value. Errors did not grow with length: this run shows no rot for Haiku at these lengths, only that lookup is easy and keeping order is not.

The local 4B model found the literal needle in all 13 cases from 781 to 11,622 tokens (its tokenizer counts the same code in fewer tokens). Asked directly "In which city is the Semperoper?" it answered Dresden; with the same fact as a comment inside 1K to 12K tokens of code it answered Dresden in 4 of 13 cases and otherwise Berlin, Boston, San Francisco, Seattle or Portland MEASURED: the code pushed aside knowledge it has. Drew Breunig calls this context distraction, "when a context grows so long that the model over-focuses on the context, neglecting what it learned during training" (22 Jun 2025); here it took only 781 tokens. Tracking: 10 of 20 with no trend in length (0 of 5 at the shortest, 5 of 5 at about 5,700 tokens): a capability limit, not rot.

At scale the literature finds the same shape: position matters (the 75.8% to 53.8% "lost in the middle" figures are on {{Agentic retrieval|n:3c65c17b0d0d8105a68cfb504ed4b0e8}}); literal lookup saturates while tracking and non-literal tasks degrade (RULER's GPT-4, advertised at 128K, was effective to 64K; NoLiMa took GPT-4o from 99.3% to 69.7% at 32K; both on {{Long-context and multimodal benchmarks|n:3ef5c17b0d0d810bb4dfc98919c9be8a}}); and Chroma's "Context Rot" report (Hong, Troynikov and Huber, 14 Jul 2025) found performance falling with input length on 18 models even on simple tasks, faster with distractors and with needles less similar to the question. Why effective context is shorter than the window is {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}}'s subject. An agent's context is the worst case: the facts it needs are scattered through tool results, rarely share the question's words, and sit among near-duplicates; section 4's 130K-token session that put a note in two log files is a small instance, and the reason to keep the window lean.
