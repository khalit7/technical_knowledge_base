In one screen

A language model reads nothing between calls. Every time an agent asks it for the next step, the harness (the program around the model) builds one request from scratch and the model sees exactly that request and nothing else. Context engineering is deciding what goes into that request, in what order, and what is left out, so that the model has what it needs, the bill stays small, and the request fits.

The parent page's {{section 3|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} (Reading tab, "Context: what the model sees on each call") lists the levers; its {{Trace and context lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} measures the startup context, the caching bill and a budget model on 22 recorded runs. This page goes one level down: how each lever works, what it costs, and what it breaks, with every lever pulled on purpose in a recorded run.

One call of Claude Code with six tools on Claude Haiku 4.5, from /context in a recorded session (sizes are its own estimates, in tokens). The order is the order of the request; section 2 explains why it is this order.

The running example
The same tiny Python library as the parent page, textstats, with two planted bugs and the task "The tests in this repository fail. Find out why and fix the code so they pass. Do not edit the tests." Some experiments add things to it: five 75 KB log files, a 30-module service package, a skill, a CLAUDE.md. Every run is Claude Code 2.1.290 in headless mode (claude -p) on a Claude subscription, recorded on 6 October 2026, redacted, and kept in this page's src/recordings/. Dollar figures are the CLI's total_cost_usd: what the same tokens would cost at Anthropic's list prices, not what the subscription paid.

1. The window is a budget

Tokens. Models read and write tokens, pieces of words; English prose runs about four characters per token, code and logs fewer. The context window is the most tokens one request may hold, prompt and reply together: 200,000 for Claude Haiku 4.5 and 1,000,000 for Sonnet 5.5 as Claude Code configures them (model configuration, read 5 Oct 2026). A request that does not fit is refused: "Prompt is too long" is what came back when this page sent Haiku a 491 KB log in one piece MEASURED.

What fills it before you type. Claude Code's /context command prints the window's contents by category, and it works in headless mode without calling the model, so it costs nothing. In a fresh session with six tools it reported 12.6k tokens: 6.3k of system prompt and 6.3k of tool definitions MEASURED. The first real call of the same configuration read 13,320 input tokens, so /context's figures are estimates within about 6% here. The parent's Trace and context lab breaks the same startup context down by tool set (13,242 tokens on 2.1.289); the figures agree.

Four numbers make the budget. The startup context S (system prompt, tool definitions, memory files, environment), the growth per call g (the model's last reply plus the tool result it triggered), a reply reserve (room the model needs to answer; Claude Code reports a 32,000-token output cap for Haiku 4.5), and a buffer before the harness acts. With the auto-compact window set to 100K, /context showed a 33k "Autocompact buffer", a third of the window kept free MEASURED. The parent's Trace and context lab turns S, g and the number of calls into a cost model checked against its recordings; it is not rebuilt here.

Predict, then reveal. A session read five log files of 75 KB each in one turn (five parallel Read calls). The window is 200K. Did the next call fit?
Yes: the next call held 126,544 tokens, 112,953 of them new, and at the end /context said 130.7k of 200k MEASURED. Five files of 75 KB are about 113,000 tokens of log, so a sixth would have taken it near the limit in one step. Harnesses check the budget between calls, and one turn of parallel tool calls can add more than the whole buffer.
