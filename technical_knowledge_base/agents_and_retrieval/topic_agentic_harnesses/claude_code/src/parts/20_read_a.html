Claude Code in one screen

Claude Code is Claude in a loop with tools, and everything it adds around that loop is one of two kinds: context, text the model reads and may ignore (CLAUDE.md files, skills, a hook's printed hint, a subagent's prompt), or enforcement, code the harness runs on every tool call whatever the model decides (hooks that exit 2, deny, ask and allow rules, the permission mode, the sandbox). Knowing which kind a feature is tells you whether it can be relied on.

Context goes into every request; every tool call passes the enforcement chain

One turn of the loop in Claude Code 2.1.290. Purple: what is assembled into each request (the model may follow it or not). Blue: the checks a tool call passes in order; the first one that decides ends the chain. Numbers are the section that takes each part apart. Not to scale.

You need: what a harness is and the loop written from zero ({{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}, its Reading tab and Loop lab), and tool calling at the protocol level ({{Building a harness: the loop, tool calling, edit formats, stop conditions|n:3c65c17b0d0d817ca14fc32338707c2f}}). This page assumes both and asks one narrower question per mechanism: what exactly does Claude Code do here, and what do the documentation and a real recording say?

Permission mode
the session-wide default for calls no rule decides: Manual, acceptEdits, plan, auto, dontAsk, bypassPermissions.
Rule
Tool or Tool(specifier) in an allow, ask or deny list.
Hook
your program, run by the harness at a named event; exit code 2 blocks.
Memory file
CLAUDE.md and its relatives: Markdown concatenated into the context.
Skill
a folder with SKILL.md: its description always in context, its body only when invoked.
Subagent, fork
a second loop with its own window started by the Agent tool; a fork inherits the whole conversation.
Headless run
claude -p: one task, JSON records out, exit.
Compaction
replacing older conversation with a summary when the window fills.
