1. The loop, as Claude Code runs it

The loop is the parent page's: call the model, run the tools it asks for, append the results, repeat until a reply asks for none; Anthropic calls the phases "gather context, take action, and verify results", which "blend together" ({{How Claude Code works|https://code.claude.com/docs/en/how-claude-code-works}}) DOCS. Five behaviours only show in a recording.

A reply can hold several tool calls, but the harness decides whether they run together. Predict before you toggle: three python3 -c scripts that each sleep 2 s, and three plain sleep 2 commands, each trio asked for in one reply. Do both take about 2 s?

The scripts ran one after another: A from 930.00 to 932.01 seconds, B from 932.11 to 934.12, C from 934.19 to 936.19 (clock seconds modulo 1,000, printed by each command) MEASURED. The three sleep 2 calls all returned within 0.04 s of each other, 3.0 s after the reply finished streaming: they ran together MEASURED. The harness can tell sleep has no side effects and a python3 -c script might, so the old rule "read-only tools in parallel, mutating tools serially" holds for Bash; the docs state only that PostToolUse hooks "fire concurrently when Claude makes parallel tool calls" and a PostToolBatch hook runs once the batch has resolved ({{hooks reference|https://code.claude.com/docs/en/hooks}}) DOCS.

Execution does not wait for the whole reply. In the second half of that run, ls returned its result (at 9.82 s) before the model had finished streaming the next call, cat README.md (9.88 s): a call can start as soon as its block of the reply is complete. The sibling {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}} (section 4) saw the same with edits on Sonnet 5.5: the first of two Edits ran 0.78 s before the second had finished streaming.

A turn is not a model call. With --max-turns 2 the run made two model calls, stopped before the third, and reported num_turns: 3 with subtype error_max_turns MEASURED (section 11; the parent's {{Trace and context lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} shows the same mismatch). When you budget an agent by turns, test what your version counts.

Messages can join a running turn. In the terminal a message typed while Claude works is queued and read before its next step; Esc stops the running tool; ctrl+enter interrupts and sends the queue DOCS. Headless, through --input-format stream-json, two messages written to stdin at once produced a single result record: the reply after the first tool call answered the first question and went on to the second MEASURED (run stream). What a hard interrupt leaves behind (a rejected tool_result with is_error, then a result with subtype error_during_execution) is recorded through the Agent SDK on {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}, section 4.

Errors stay in the loop. Every failure in the recordings came back as an ordinary tool result marked is_error: a refused permission, a missing file, a non-unique edit string, a timed-out command (exit 143). The model decides what to do next; the harness never retries on its own.
