9. Headless runs: -p, the stream, the result

claude -p "task" runs one task without the interactive screen and exits: 0 on success, non-zero when the run fails, 143 on SIGTERM ({{headless|https://code.claude.com/docs/en/headless}}) DOCS. It is how Claude Code is used in CI, in scripts and in every recording on these pages. --output-format picks text, json (one final object) or stream-json (one JSON record per line as things happen; needs --verbose, and --include-partial-messages adds the raw API stream). Headless runs and trust
A -p run never shows the workspace trust dialog, so a repository's hooks, env, apiKeyHelper and .mcp.json servers are used anyway, while its permissions.allow rules are not (section 3) DOCS. The docs recommend --bare for scripts and CI: it skips discovery of hooks, skills, plugins, MCP servers, auto memory and CLAUDE.md, and "will become the default for -p in a future release". It also reads only an API key or an apiKeyHelper passed with --settings, never OAuth, so it cannot run on a subscription login; the runs on this page instead pass --setting-sources project --strict-mcp-config and a throw-away directory.

Some slash commands work headless too. claude -p "/context" prints the window by category without calling the model (cost 0), and /compact runs inside a --input-format stream-json session, emitting a compact_boundary record whose preserved segment keeps the last 5 messages verbatim MEASURED; both are recorded on {{Context engineering: window budgets, caching, compaction, memory files, subagents|n:3f15c17b0d0d811292cee46514370431}}, its "Compaction lab" tab. --system-prompt-snapshot (new in 2.1.290, on by default) records the system prompt on the first request and resends it verbatim until the conversation is compacted DOCS.

Other headless flags worth knowing: --json-schema for validated structured output (the frameworks root measured it: a tool named StructuredOutput, {{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}); --permission-prompt-tool to route approvals to an MCP tool; --permission-prompts none (2.1.259) to deny every prompt outright; --fallback-model; --no-session-persistence; --restricted (2.1.248) for evaluation harnesses, which removes command-running tools and ignores user and project settings.

10. Settings that matter, and the September 2026 controls, checked

Precedence, highest first: managed settings (set by an organisation), command-line flags, .claude/settings.local.json, .claude/settings.json, ~/.claude/settings.json. 11. Where the SDK begins

The Claude Agent SDK (Python claude-agent-sdk, TypeScript @anthropic-ai/claude-agent-sdk; renamed from the Claude Code SDK on 29 September 2025) runs this same loop, tools, permission system, hooks and MCP support as a library: your code supplies the prompt, the options and callbacks instead of a terminal. It drives a bundled copy of the CLI (version 0.2.163 bundled Claude Code 2.1.286 on 5 October), so everything on this page applies, with two differences that bite: hooks and permission prompts become Python or TypeScript callbacks, and unless you pass strict_mcp_config=True with explicit setting sources, a subscription login loads your connected apps as tools (measured by the frameworks root) MEASURED. The library, its options and its deployment patterns are owned by {{Claude Agent SDK: the Claude Code loop as a library|n:3c65c17b0d0d813b960fd9857118fbd2}}; when to use it instead of a framework is on {{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}.
