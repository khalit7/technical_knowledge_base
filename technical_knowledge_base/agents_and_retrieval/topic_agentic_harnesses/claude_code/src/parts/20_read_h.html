9. Context: what fills the window, and what survives compaction

Everything in sections 2 to 7 lands in one window: the system prompt and tool definitions, the memory files, the skill listing, MCP tool names, and then the conversation with every tool result. claude -p "/context" prints the window by category without calling the model (cost 0) MEASURED; the parent's {{Trace and context lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} measures what each part costs at startup. Two design choices keep that window cheap and stable. --system-prompt-snapshot (on by default) records the system prompt on the first request and resends it verbatim until the conversation is compacted DOCS, so the cached prefix does not change under the session. And the large, rarely needed parts load on demand: skill bodies (section 6), nested memory files (section 5), MCP tool definitions (section 10).

When the window fills, auto-compaction replaces the conversation: "It clears older tool outputs first, then summarizes the conversation if needed" ({{how Claude Code works|https://code.claude.com/docs/en/how-claude-code-works}}) DOCS. What comes back afterwards is decided by where each piece lives:

What lives on disk is re-read; what lived only in the conversation survives as a summary

Before and after a compaction, blocks not to scale. Green: survives intact (re-read from disk, re-attached or kept verbatim); amber: survives only as the summary; grey dashed: gone until something loads it again.

  • Re-read from disk: after /compact the project-root CLAUDE.md is re-read from disk; nested files and path rules load again on demand ({{memory|https://code.claude.com/docs/en/memory}}) DOCS.
  • Re-attached: the most recent invocation of each skill, up to 5,000 tokens each and 25,000 in total ({{skills|https://code.claude.com/docs/en/skills}}) DOCS.
  • Kept verbatim: /compact also runs inside a --input-format stream-json session, emitting a compact_boundary record whose preserved segment keeps the last 5 messages verbatim MEASURED; forced compactions are recorded on {{Context engineering: window budgets, caching, compaction, memory files, subagents|n:3f15c17b0d0d811292cee46514370431}}, its section 4.
  • Re-read files and the threshold: the context window explorer adds that up to five of the most recently modified files are re-read (a file over 5,000 tokens comes back only as a path), and the model configuration page that compaction runs by default when the conversation reaches the model's context limit, at about 967K tokens for models with a native 1M window such as Sonnet 5.5 (both read 5 Oct 2026 for the parent page's Trace and context lab) DOCS.
  • Idle compaction: the terminal also compacts a conversation over 200K tokens left for about 54 minutes, before its one-hour prompt cache expires, so the next message does not reprocess it all ("idleCompaction": false turns it off; {{changelog|https://code.claude.com/docs/en/changelog}}) DOCS.

The design consequence, in the docs' words: "Put persistent rules in CLAUDE.md rather than relying on conversation history"; a "Compact Instructions" section in CLAUDE.md, or /compact with a focus, steers what the summary keeps DOCS. Why compaction, caching and subagents are the three levers of any agent's window, and their arithmetic, is owned by {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}.

10. MCP servers: where they are configured and how their tools arrive

An MCP server is a separate process or remote service whose tools Claude Code offers the model next to the built-in ones; the protocol is owned by {{MCP|n:3c65c17b0d0d813f9695dc4175c44cbb}}. What Claude Code adds is configuration, naming, loading and limits. Facts from the {{MCP docs|https://code.claude.com/docs/en/mcp}} and {{permissions|https://code.claude.com/docs/en/permissions}}, read 24 October 2026 (a later version than the recordings) DOCS:

ScopeLoads inStored in
Local (the default for claude mcp add)this project, only for you~/.claude.json
Projectthis project, shared through version control.mcp.json at the project root
Userall your projects~/.claude.json
  • Precedence: local, then project, then user, then plugin-provided servers, then claude.ai connectors, with managedMcpServers above all; "The entire server entry from that source is used; fields are not merged across scopes."
  • Managed servers: administrators ship servers to every user with a managed-mcp.json file or the managedMcpServers managed setting (the setting needs Claude Code 2.1.259 or later), and restrict the rest with allowedMcpServers and deniedMcpServers.
  • Trust: interactively, Claude Code asks before using project-scoped servers from .mcp.json; in claude -p and Agent SDK sessions it "can't show that prompt: it loads project-scoped servers without asking". The recordings pass --strict-mcp-config so only servers named on the command line load.
  • Transports: stdio servers run as local processes; HTTP is the recommended remote transport; SSE is deprecated. ${VAR} and ${VAR:-default} expand inside .mcp.json.
  • Names and rules: a tool is named mcp__<server>__<tool>. mcp__puppeteer or mcp__puppeteer__* matches every tool of that server; an allow glob needs the literal mcp__<server>__ prefix, while a deny of mcp__* removes every MCP tool from context.
  • Tool search: by default only tool names and server instructions load at session start, and a definition loads when Claude searches for it, so "adding more MCP servers has minimal impact on your context window". ENABLE_TOOL_SEARCH=auto loads tools upfront while their definitions total under 10% of the window; false loads all upfront; alwaysLoad exempts one server.
  • Output caps: a warning above 10,000 tokens of MCP tool output and a 25,000-token limit by default (MAX_MCP_OUTPUT_TOKENS raises it); successful text over 50,000 characters is saved to a file, the same pattern as Bash in section 2.

The reverse direction also exists: claude mcp serve (in the 2.1.290 CLI help) runs Claude Code itself as an MCP server.

11. Headless runs: -p, the stream, the result

claude -p "task" runs one task without the interactive screen and exits: 0 on success, non-zero when the run fails, 143 on SIGTERM ({{headless|https://code.claude.com/docs/en/headless}}) DOCS. --output-format picks text, json (one final object) or stream-json (one JSON record per line as things happen; needs --verbose, and --include-partial-messages adds the raw API stream). 13. Where the SDK begins

The Claude Agent SDK (Python claude-agent-sdk, TypeScript @anthropic-ai/claude-agent-sdk; renamed from the Claude Code SDK on 29 September 2025) runs this same loop, tools, permission system, hooks and MCP support as a library: your code supplies the prompt, the options and callbacks instead of a terminal. It drives a bundled copy of the CLI (0.2.163 bundled Claude Code 2.1.286 on 5 October), so this page applies, with three differences that bite: hooks and permission prompts become Python or TypeScript callbacks, and unless you pass strict_mcp_config=True with explicit setting sources, a subscription login loads your connected apps as tools (measured by the frameworks root) MEASURED. And the SDK's system_prompt=None means an empty system prompt, not Claude Code's (the Python SDK passes --system-prompt ""), so the Claude Code preset must be asked for explicitly ({{Claude Agent SDK|n:3c65c17b0d0d813b960fd9857118fbd2}}, its section 3). The library, its options and its deployment patterns are owned by {{Claude Agent SDK: the Claude Code loop as a library|n:3c65c17b0d0d813b960fd9857118fbd2}}; when to use it instead of a framework is on {{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}.
