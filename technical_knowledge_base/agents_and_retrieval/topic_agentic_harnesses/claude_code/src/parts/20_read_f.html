5. Memory files: what loads, in what order, and when

Memory files are Markdown files of instructions that Claude Code puts into the context for you: CLAUDE.md and its relatives. They are not memory in the database sense; they are text paid for on every call, delivered "as a user message after the system prompt, not as part of the system prompt itself" ({{memory|https://code.claude.com/docs/en/memory}}) DOCS. The documented rules:

  • Locations, broadest first: managed policy (/Library/Application Support/ClaudeCode/CLAUDE.md on macOS, /etc/claude-code/CLAUDE.md on Linux), user (~/.claude/CLAUDE.md), project (./CLAUDE.md or ./.claude/CLAUDE.md), local (./CLAUDE.local.md, meant to be git-ignored), and rules in .claude/rules/*.md.
  • Concatenated, not overridden: files in the working directory and every directory above it load at launch, ordered from the filesystem root down, CLAUDE.local.md after CLAUDE.md in each directory; if two instructions contradict each other, "Claude may pick one arbitrarily".
  • On demand: CLAUDE.md files in subdirectories, and rules with a paths: list in their frontmatter, load only when Claude reads, writes or edits a matching file.
  • Imports: @path inside a CLAUDE.md pulls in another file at launch, relative to the importing file, at most four hops deep. Imports organise a file; they do not save context.
  • AGENTS.md (the cross-tool convention other agents read) is read since 2.1.277, but by default only when there is no CLAUDE.md or CLAUDE.local.md at or above the working directory; a /config setting can load both.
  • Auto memory is the other half: notes Claude writes itself under ~/.claude/projects/<project>/memory/, whose index MEMORY.md loads at every start up to 200 lines or 25 KB. Subagents do not get it.
  • Size advice: under 200 lines per file; a file over 4 MiB is skipped. After /compact the project-root CLAUDE.md is re-read from disk; nested files and path rules load again on demand.

Eight canaries

To check the order rather than trust it, one recording planted eight files, each containing one unique word ("Canary: ALPHA-ROOT" and so on), then asked Haiku, with only the Read tool, to list every canary in its context, read textstats/core.py, and list them again (run memory). Step through what happened.

Every outcome matched the documentation MEASURED: four files at launch (the parent directory's CLAUDE.md, the project CLAUDE.md, its import and the rule without paths), two after the Read (the subdirectory's CLAUDE.md and the path-scoped rule), and two never. CLAUDE.local.md stayed out because these runs pass --setting-sources project, and "CLAUDE.local.md is skipped if you exclude local from --setting-sources"; AGENTS.md stayed out because a CLAUDE.md existed. The parent-directory canary is the one to remember: a CLAUDE.md anywhere above your project, in a home directory or a monorepo root, is in every session started below it.

A memory file is context, not configuration
The parent's trace lab measured a four-line CLAUDE.md stating the test command: 184 more tokens per call, and two of three Haiku runs used it while the third explored anyway ({{Trace and context lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}) MEASURED. Instructions there are followed most of the time; anything that must hold every time is a hook or a permission rule (sections 3 and 4).

6. Skills: a description now, the body on demand

A skill is a folder with a SKILL.md: YAML frontmatter (a name and a description of when to use it) and Markdown instructions, plus any scripts or reference files it needs. Claude Code follows the Agent Skills open standard; custom slash commands in .claude/commands/ have been merged into skills ({{skills|https://code.claude.com/docs/en/skills}}) DOCS. The design is progressive disclosure: only the name and description sit in context from the start; the body loads when the skill is invoked, through the Skill tool or by you typing /name, and then stays in the conversation.

  • Budget: each description is cut at 1,536 characters in the listing, and the whole listing gets 1% of the context window; past that, descriptions of the least-used skills are dropped (names stay) DOCS.
  • Control: disable-model-invocation: true keeps a skill out of Claude's view (you invoke it); user-invocable: false the opposite; allowed-tools pre-approves tools for the turn that invokes it; context: fork runs it in a fresh subagent; paths loads it only near matching files; !`command` in the body runs a shell command first and inlines its output.
  • After compaction the most recent invocation of each skill is re-attached, up to 5,000 tokens each and 25,000 in total.

Canary: KILO-SKILLBODY ..."), 329 tokens written to the cache on the next call. The skill told it to run python3 tests/test_core.py, and it did, first time; the run fixed both bugs in 9 model calls.
