2. Tools: what each one returns, and where it stops

A tool is a function the harness offers the model: a name, a description and a JSON schema for its arguments, sent with every request. The model replies with a tool call; the harness checks permission, runs the function and sends back the output as text, which costs input tokens on every later call. So two questions decide how a tool behaves in practice: what exactly comes back, and what happens when the honest answer would be huge.

The built-in set in 2.1.290

The tools reference lists 46 built-in tools for this version, far more than the "small, sharp toolset" of the old page ({{tools reference|https://code.claude.com/docs/en/tools-reference}}) DOCS. A session gets a subset, and three defaults surprise people:

  • No Glob or Grep on macOS, Linux and WSL by default. Claude searches with find and grep through Bash instead; in Claude's shell those run embedded copies of bfs and ugrep, so searches reach your hooks and permission rules as Bash calls. Naming Glob or Grep in --tools or --allowedTools brings them back DOCS. The parent's recording with --tools default on this Mac listed 29 tools and neither of the two MEASURED.
  • No TodoWrite by default. It is replaced by TaskCreate, TaskGet, TaskList and TaskUpdate, and since 2.1.268 those four are offered by default only on older models (Claude 3.x, Opus 4 to 4.7, Sonnet 4 to 4.6, Haiku 4.5); "On newer models, Claude keeps track of multi-step work without a written checklist" DOCS. The old page's "TodoWrite keeps the model honest" is out of date.
  • The subagent tool is called Agent, renamed from Task in 2.1.63, with Task(...) kept as an alias in rules ({{subagents|https://code.claude.com/docs/en/sub-agents}}) DOCS. The init record of a headless run still lists it as Task while the model's calls say Agent MEASURED.

Eighteen calls, one per behaviour

To see the return values rather than describe them, one recording gave Haiku a script: eighteen tool calls, one per message, each probing one rule, and "do not retry, just move on" (run tools). Step through it. The bar under each step is the size of the next request, to scale, so you can watch what each result adds to the window.

Two lessons for any harness
Every cap is a decision about what the model will never see, so the cap must say so. Claude Code does it well for Bash (a file path and a preview, so the model can read on) and for the oversized Read (an error that names the way out), and in this recording did not do it for the token-capped Read, where the model got 61% of a file and believed it had all of it. Second, the harness knows more than it tells: the tool_use_result metadata in the stream (line counts, truncation flags, structured patches) never reaches the model. When you build your own, decide which of those facts belong in the text.

Other documented limits, not exercised here: WebFetch caches 15 minutes, fails after 5 minutes (300 s since 2.1.268), refuses localhost, and passes the page through a second model call with your extraction prompt, so it is lossy by design; WebSearch is capped at 200 calls a session; background Bash commands in unattended sessions get 30 minutes, up to 2 hours; BASH_MAX_OUTPUT_LENGTH defaults to 30,000 with a ceiling of 150,000, and the bashOutputMaxChars setting raises the inline ceiling to 128,000 ({{tools reference|https://code.claude.com/docs/en/tools-reference}}) DOCS.
