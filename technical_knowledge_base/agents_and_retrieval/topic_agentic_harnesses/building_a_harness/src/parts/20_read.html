The idea in one sentenceA harness is a loop that sends the model a request, lets its turn end exactly at the action it asks for, runs that action somewhere safe, hands back a result the model can act on, and stops only when the work is verified or a limit is hit; every engineering decision is one of those steps, and each fails in a way you can measure.

Every decision on this page sits on one turn of the loop

One turn of the harness this page builds (src/harness/native.py), with the section that measures each step and one number from the recordings beside it. The highlighted step, the action boundary, is the one most easily got wrong without noticing. The loop itself, built from zero in seven recorded steps, is the parent page's {{Loop lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}; this page takes each step apart.

You need: the agent loop (model call, tool call, result, repeat), as in section 1 of {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}. Native tool calling: tools sent as JSON Schema in the request, calls returned as typed data, not parsed from prose.
Action boundary: the point where the model's turn must end, right after it asks for an action.
Agent-computer interface (ACI): tools, their results and errors, designed for a model as the user.
Edit format and applier: how the model writes a code change, and the program that applies it.
Verifier: a check the harness runs itself (tests, a build) before it accepts "done".
Stop rule: what ends the loop: the model's own stop, a verifier, a cap or a loop detector.

MEASURED: runs recorded on 6 October 2026 (Claude through the Claude Code CLI 2.1.289; Qwen3 4B Instruct 2507 in 4-bit on mlx-lm 0.32.0, Apple M1 Pro) or the parent page's of 5 October.
