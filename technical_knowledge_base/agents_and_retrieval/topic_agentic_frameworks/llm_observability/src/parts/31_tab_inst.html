One run, eight instrumentations

The recorded local-model run of the running example ( model calls, 7 tool calls), replayed byte for byte from a small server that answers with the recorded responses, through the same Python loop instrumented eight ways. Tools ran for real on a fresh copy of the repository each time, so results were identical. Every span was written to a file by an extra exporter and sent to the self-hosted Langfuse. Where openai-v2 put content

Findings

  • Only the hand-written version and Pydantic AI produced one trace with an invoke_agent root and execute_tool children; Langfuse then typed them as agent, generation and tool observations.
  • openai-v2 2.4b0 misses the required gen_ai.provider.name (it writes the older gen_ai.system) and has no content by default; with its content switch on, the messages went to log events rather than span attributes, which a traces-only backend never receives.
  • OpenLLMetry wrote the newer GenAI names, including gen_ai.usage.cache_read.input_tokens, plus its own extras (gen_ai.openai.api_base, the server's system_fingerprint, which here named the server's OS version).
  • Pydantic AI put run totals on its agent span as gen_ai.aggregated_usage.*, so a backend summing gen_ai.usage.* over all spans does not double count, and records the full message history on the agent span (pydantic_ai.all_messages).
