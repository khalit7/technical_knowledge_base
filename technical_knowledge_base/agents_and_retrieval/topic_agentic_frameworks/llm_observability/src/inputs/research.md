# LLM observability fact check (read 2026-10-06)

## 1. Langfuse

- Licence MIT: CONFIRMED, with carve-out. LICENSE: "All content that resides under the 'ee/', 'web/src/ee/', and/or 'worker/src/ee/' directories ... is licensed under the license defined in 'ee/LICENSE'." Rest is MIT Expat. https://github.com/langfuse/langfuse/blob/main/LICENSE (read 2026-10-06). Self-hosting docs mark some features "(EE)" (Organization Creators, Instance Management API, UI Customization).
- Acquisition: CONFIRMED. "ClickHouse has acquired Langfuse, the leading open-source platform for LLM observability, evaluations, and prompt management." https://clickhouse.com/blog/clickhouse-acquires-langfuse-open-source-llm-observability (2026-01-16; announced with ClickHouse's $400M Series D). Langfuse "stays open source and self-hostable".
- Latest release: CONFIRMED v4.53.0, 2026-10-06 (v4.52.0 same day, v4.51.0 2026-10-05). https://github.com/langfuse/langfuse/releases
- v4 GA: "Langfuse v4 is live on Langfuse Cloud and generally available for self-hosted deployments" https://langfuse.com/changelog/2026-08-17-langfuse-v4 (2026-08-17). "Langfuse Cloud becomes v4-only on November 16, 2026". "Langfuse v3 will receive security patches until end of January 2027." (upgrade guide)
- Self-hosting stack: CORRECTED (same four components, v4 not v3). https://langfuse.com/self-hosting shows "Version: v4": PostgreSQL ("Transactional data"), Redis/Valkey ("Cache and job queue"), ClickHouse ("Observability data"), S3/Blob Storage ("Raw events and multi-modal attachments"), plus Web and Worker containers. v4 minimums: "ClickHouse 25.12 minimum, 26.4 recommended", "PostgreSQL 15 minimum, 16 recommended", "Redis 7.0 minimum, 7.2 recommended". https://langfuse.com/self-hosting/upgrade/upgrade-guides/upgrade-v3-to-v4
- What changed in v4 (upgrade guide, read 2026-10-06): "observations-first data model built on a new, wide, and (mostly) immutable ClickHouse table"; tables `events_full` ("the immutable, full-fidelity event table") and `events_core` ("a lightweight, query-optimized projection"); "Traces are represented as root spans within the same table instead of a separate entity." Ingestion: "the legacy batch ingestion endpoints are replaced by OpenTelemetry-based ingestion"; `POST /api/public/ingestion`, `/api/public/traces`, `/api/public/spans` return 404 in default `events_only` mode. Needs "Langfuse Python v4 or JavaScript v5 SDK" or external OTel instrumentation (GA discussion https://github.com/orgs/langfuse/discussions/14157).
- SDK v4 (Python): "thin layer on top of the official OpenTelemetry client"; v4 no longer exports all spans: default filter keeps Langfuse SDK spans, spans with `gen_ai.*` attributes, and known LLM instrumentation scopes (override with `should_export_span`). `propagate_attributes()` replaces `update_current_trace()`: "correlating attributes (user_id, session_id, metadata, tags) propagate to every observation rather than living only on the trace". `start_span()/start_generation()` -> `start_observation(as_type=...)`. https://langfuse.com/docs/observability/sdk/upgrade-path/python-v3-to-v4
- Python SDK on PyPI: langfuse 4.17.0, uploaded 2026-10-05 (pypi.org JSON API).
- Data model: CONFIRMED. Traces ("a single request or operation"), observations ("the individual steps"), sessions, users, scores. https://langfuse.com/docs/observability/data-model. Observation types, exact list: event, span, generation, agent, tool, chain, retriever, evaluator, embedding, guardrail. https://langfuse.com/docs/observability/features/observation-types
- OTLP endpoint: CONFIRMED `/api/public/otel` (traces signal `/api/public/otel/v1/traces`), Basic auth with base64 `pk-lf-...:sk-lf-...`, header `x-langfuse-ingestion-version: 4`. https://langfuse.com/integrations/native/opentelemetry
- Property mapping (same page): type <- `langfuse.observation.type`, `gen_ai.operation.name`, model fallback, default "span"; model <- `langfuse.observation.model.name`, `gen_ai.request.model`, `gen_ai.response.model`, `llm.model_name`, `model`; input <- `langfuse.observation.input`, `gen_ai.prompt`, `input.value` (OpenInference), `mlflow.spanInputs`, `gen_ai.tool.call.arguments`; output <- `...output`, `gen_ai.completion`, `output.value`, `gen_ai.tool.call.result`; usage <- `langfuse.observation.usage_details`, `gen_ai.usage.*`, `llm.token_count.*`; cost <- `langfuse.observation.cost_details`, `gen_ai.usage.cost`.
- Cost: CONFIRMED. Matches the generation's `model` to a model definition (regex match pattern, e.g. `(?i)^(gpt-4-0125-preview)$`; user-defined models take priority), multiplies prices per usage type. Usage keys are "separate, non-overlapping bucket[s]: each token must be counted in exactly one key" (examples `input`, `output`, `cache_read_input_tokens`, `input_cached_tokens`, `audio_tokens`, `reasoning_tokens`). Pricing tiers: conditions on usage thresholds (e.g. `input > 200000`), model parameters, metadata. https://langfuse.com/docs/observability/features/token-and-cost-tracking
- Anthropic 1-hour cache writes: PARTLY CONFIRMED. The docs page does not mention it. GitHub issue #17450 (open, 2026-09-14): "The default Claude prices use `input_cache_creation_1h` and `input_cache_creation_5m`", while the Python LangChain callback emits `input_ephemeral_1h_input_tokens`, so those get no price. So default prices do have separate 1h/5m cache-write keys, but one integration mislabels them. https://github.com/langfuse/langfuse/issues/17450
- Masking: CONFIRMED, client side. JS/TS `mask: ({ data }) => ...`; Python v4 hook `mask_otel_spans` ("receives read-only snapshots of one OpenTelemetry export batch and returns sparse patches"), runs at export stage and only affects spans exported by this Langfuse client. https://langfuse.com/docs/observability/features/masking
- Sampling: CONFIRMED. `sample_rate` (Py) / `sampleRate` (JS) or `LANGFUSE_SAMPLE_RATE`, 0..1, default 1; "The SDK samples on the trace level meaning that if a trace is sampled, all observations and scores within that trace will be sampled as well." https://langfuse.com/docs/observability/features/sampling
- LLM-as-a-judge: CONFIRMED with v4 change. Online: "Run evaluators on individual observations within your traces"; offline: "Run evaluators on controlled test datasets". "Observation-level evaluators are the recommended target for live production data; trace-level evaluators are deprecated." On Cloud, trace-level evaluators stop after 2026-11-16. https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge (read 2026-10-06). Python v4 removed `DatasetItemClient.run()`: "use Experiment SDK instead".
- Prompt labels: CONFIRMED. "Labels can be used to assign prompts to environments (staging, production) ..."; "When using a prompt without specifying a label, Langfuse will serve the version with the `production` label."; "The `latest` label points to the most recently created version". https://langfuse.com/docs/prompt-management/features/prompt-version-control
- LiteLLM: CONFIRMED both callbacks, CORRECTED on what "langfuse" does now. `langfuse` callback: requires `langfuse>=4.7,<5` and "exports traces through LiteLLM's own OpenTelemetry pipeline to Langfuse's OTLP endpoint"; the page says "we recommend using the `langfuse_otel` preset ... better span quality, lower latency, and native OpenTelemetry semantics." https://docs.litellm.ai/docs/observability/langfuse_integration . `langfuse_otel` preset: endpoint from `LANGFUSE_OTEL_HOST` then `LANGFUSE_HOST` with "/api/public/otel" appended; spans carry `gen_ai.*` plus `langfuse.observation.type` = "generation", usage and cost. https://docs.litellm.ai/docs/observability/opentelemetry_v2 . Config: `litellm.callbacks = ["langfuse_otel"]` or proxy `litellm_settings: callbacks: ["langfuse_otel"]`. litellm on PyPI: 1.104.0 (2026-10-03).

## 3. Braintrust

- Experiment = data + task + scores: CONFIRMED (docs now say "Evaluators" = scorers and classifiers). Data: "The examples you evaluate, including inputs and optional expected outputs or metadata." Task: "The behavior you evaluate, such as a single LLM call, a retrieval pipeline, or a multi-step agent." Evaluators: "Scorers measure quality with numeric scores, while classifiers assign labels". https://www.braintrust.dev/docs/evaluate (read 2026-10-06)
- Online scoring: CONFIRMED. "Evaluations run asynchronously in the background without adding latency to your application"; sampling rate is "the percentage of matching traces that Braintrust scores". Idle timeout before scoring a trace defaults to 30 s (per search summary). https://www.braintrust.dev/docs/evaluate/score-online
- OTel ingestion: CONFIRMED. `OTEL_EXPORTER_OTLP_ENDPOINT=https://api.braintrust.dev/otel` (traces `.../otel/v1/traces`; EU `api-eu.braintrust.dev`), headers `Authorization=Bearer <key>, x-bt-parent=project_id:<id>`. https://www.braintrust.dev/docs/integrations/sdk-integrations/opentelemetry
- Self-hosting: CONFIRMED hybrid, Enterprise only. "Self-hosting is only available on the Enterprise plan." You run the data plane (Braintrust API, PostgreSQL, Redis, object storage, Brainstore query engine) on AWS/GCP/Azure via Terraform; Braintrust runs the control plane (web UI, auth, metadata). Browser and SDKs talk directly to your data plane. https://www.braintrust.dev/docs/admin/self-hosting
