The idea in one screen

Several agents beat one when the work is independent reading that does not fit one context, and the split, the brief and the check are fixed before they start; for anything else one agent is cheaper and as good.

You need the single agent loop ({{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}) and what fills a context window and what caching does to the bill ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}, sections 1 and 2). How a harness isolates a subagent's context is that page's section 6 and {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}} section 7; this page is about the patterns built on top.   2. One agent. One model decides every step and sees everything it has read, in one growing context; each call resends it all, so tokens grow with the square of the steps (section 9). Sections 2 and 3.
  3. Orchestrator-workers. A lead model decides how to split, whom to start and when to stop; each worker sees only its brief and its own reading, the lead only briefs and reports. A start-up context per worker, but every context stays small. Claude Code subagents (the Agent tool), Anthropic's Research system, a LangGraph supervisor written as tool calls. Section 3.
  4. Agents as tools. A manager model keeps the conversation and calls each specialist like a function; a specialist sees only the input the manager wrote for it, and the manager writes the reply. OpenAI Agents SDK Agent.as_tool; Claude Code subagents seen from the lead. Section 6.
  5. Handoff. The current agent calls a transfer tool and the receiver owns the conversation, seeing the whole history under its own instructions and tools. One active agent at a time, no merge, nothing in parallel, so a second transfer in the same reply is ignored. OpenAI Agents SDK handoffs (transfer_to_<agent>), langgraph-swarm. Section 6.
  6. Fan-out workflow. Your code fixes the split and the merge; each call sees its slice, pasted in. One call per slice, no lead, no exploration: the cheapest parallel design when the split is known. asyncio.gather, LangGraph Send, the parent page's "parallelisation" workflow. Section 4.
  7. Parallel writers. The same split applied to writing: each writer sees the spec, not the other's code, so the halves can disagree on names where they meet. Section 7.
  8. Voting and debate. Voting (self-consistency, Wang et al. 2022): k independent samples, and code takes the most common answer; no prompt grows. Debate (Du et al. 2023, three agents, two rounds): in round 2 each solver also sees every other solver's answer and reasoning, so solvers times rounds calls with growing prompts. Section 8.
  9. Blackboard. Nobody decides: each agent claims the next unclaimed piece from a shared store and sees its own work plus what it reads there. Work balances itself, and nothing filters what gets posted. Hearsay-II (1971 to 1976), Claude Code agent teams' task list, Agora's Git graph, Anthropic's FLT proof graph. Section 5.

The rule the measurements support
Split reading across agents when the material does not fit comfortably in one context window, and let code do the splitting if you know the split in advance. Keep writing of one artefact with one agent, or fix the interface before the writers start. Say exactly what counts before you split: parallel workers drew the boundary of the task differently from run to run (from no extra reports to 170), a second opinion from the same model confirmed them all, and a sharper brief removed them for less than the check cost.

1. Terms, and the two families

Every pattern starts from one agent loop: each model call sends the whole conversation so far (its context) and gets back tool requests or an answer; the most one call accepts is the context window (200,000 tokens for Claude Haiku 4.5, the model of every Claude run here).

Multi-agent system
several model loops (agents) on one job.
Lead
a loop that starts others (also orchestrator, supervisor).
Worker
a loop started by a lead (also subagent), given a brief (the text that starts its conversation), returning a report (its final answer).
Context isolation
a worker's reading and dead ends stay in its own context; the lead receives only the report. The price: a start-up context per worker, duplicated reading, and lost detail at the report boundary.
Workflow
your code decides the steps and calls a model at fixed points.
Agentic pattern
a model decides the steps (how to split, whom to call next).
Handoff
passing the conversation itself to another agent, which carries on in its place.
Blackboard
a shared store every agent reads and writes; nobody assigns work.
Voting, debate, judge
sample one question several times and take the majority; let solvers read each other and revise; have one call pick among answers.

Two families hide in Fig. 1. Fan-out, voting and a fixed pipeline are workflows that happen to call a model several times; in the lead and the triage agent a model decides. Anthropic drew this line in December 2024 (workflows are "orchestrated through predefined code paths", agents "dynamically direct their own processes and tool usage", in {{Building effective agents|https://www.anthropic.com/engineering/building-effective-agents}}); the parent page's section 1 compares its five workflow patterns.
