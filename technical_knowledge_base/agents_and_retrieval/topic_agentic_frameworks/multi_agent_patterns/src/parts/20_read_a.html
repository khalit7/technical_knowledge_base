In one screen

An agent is a model in a loop: the model asks for a tool, the program around it (the harness) runs the tool and pastes the result back, and this repeats until the model answers. A multi-agent system runs several such loops on one job. Every multi-agent pattern is an answer to two questions: who decides what happens next (code you wrote, or a model), and who sees what (does each loop get the whole history, or only a short brief and its own work).

The parent page measured the case against: on a small bug fix, a lead agent with two subagents cost several times a single agent and scored the same ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, tab Orchestration lab, part "One agent or several"). The rule the measurements support
Split reading across agents when the material does not fit comfortably in one context window, and let code do the splitting if you know the split in advance. Keep writing of one artefact with one agent, or fix the interface before the writers start. Say exactly what counts before you split: parallel workers drew the boundary of the task differently from run to run (from no extra reports to 170), a second opinion from the same model confirmed them all, and a sharper brief removed them for less than the check cost.

1. From one loop to several

Start from one agent loop. Each model call sends the whole conversation so far (system prompt, tool definitions, every message and tool result) and gets back either tool requests or a final answer. Everything the call sends is its context; the most a model accepts in one call is its context window (200,000 tokens for Claude Haiku 4.5, the model of every Claude run here). The loop itself is the subject of {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}; what goes into the context is {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}.

Several loops need four new words. A lead (or orchestrator, or supervisor) is a loop that starts others. A worker (or subagent) is a loop started by a lead, given a brief (the text that starts its conversation) and returning a report (its final answer). Context isolation means a worker's reading and dead ends stay in its own context; the lead receives only the report. A handoff passes the conversation itself to another agent, which carries on in its place. Pick a pattern to see its shape:

Two families hide in that list. In a workflow your code decides the steps: fan-out, voting and a fixed pipeline are workflows that happen to call a model several times. In an agentic pattern a model decides: the lead chooses how to split, the triage agent chooses whom to hand to. Anthropic drew this line in December 2024 (workflows are "orchestrated through predefined code paths", agents "dynamically direct their own processes and tool usage", in {{Building effective agents|https://www.anthropic.com/engineering/building-effective-agents}}); the parent page's section 1 compares its five workflow patterns.
