9. Token and quality accounting

Every comparison on this page reduces to a few sums. Start with the audit's bill, per design, split by what each token was:

Reading the bill. The single agent's tokens are mostly cache reads, and they are cheap. The orchestrator and the fan-out workflow write each worker's modules to the cache once (six fresh contexts instead of one growing one), and every worker thinks before answering: output is the largest single item in both. The blackboard designs cost most: every agent makes several model calls per module (claim, read, post each findings line), each re-sending its growing history, and the check round starts six more loops.

Why the shapes differ. Each call resends its loop's whole context, so

tokens processed = ∑calls (context sent by that call)
context
start-up prompt + tool definitions + every message so far in that loop

A loop of T calls that starts at S tokens and adds g per call processes about T·S + g·T2/2: the sum grows with the square of the steps. Split the same reading across k isolated workers and the square term shrinks to about g·T2/(2k), while every worker pays its own start-up and the lead adds its calls. That is the argument for isolation in one line, and why it lost on the small bug fix: when T is small the square term is small, and only the extra start-ups remain.

Prompt caching changes which term costs money: a token re-sent from cache costs a tenth of a fresh one on Haiku 4.5, so the growing re-reads are cheap and the bill is set by what is new (content written to the cache for the first time, and output, including hidden thinking).

cost = pin·fresh + pwrite·written + pread·cached + pout·output
The prices behind the cost view

Haiku 4.5: $1 fresh, $2 written (1-hour cache; $1.25 for 5-minute), $0.10 cached, $5 output, per million tokens (list prices read 5 Oct 2026). Claude Code writes its cache with the one-hour lifetime at twice the input price ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}, section 2). For the fan-out workflow output dominates partly because its repeated prompts were cache hits (section 4).

Quality is counted the same way: recall (planted bugs found out of 16) and precision against the key (planted bugs out of everything reported). A design that reports 186 items to find 16 has perfect recall and a precision under 10%; someone has to read the other 170 and decide which of them matter.
