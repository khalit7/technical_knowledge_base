6. Handoffs against agents-as-tools

A support desk is the textbook case for a handoff: a triage agent reads the customer's message and transfers the conversation to the right specialist, who then owns it. The OpenAI Agents SDK makes this its native primitive DOCUMENTED: "Handoffs are represented as tools to the LLM", named transfer_to_<agent>, and the receiving agent "gets to see the entire previous conversation history" ({{handoffs docs|https://openai.github.io/openai-agents-python/handoffs/}}). The alternative is agents as tools: a manager calls each specialist like a function and keeps the conversation. The SDK's own docstring for Agent.as_tool states the two differences: "In handoffs, the new agent receives the conversation history. In this tool, the new agent receives generated input," and "In handoffs, the new agent takes over the conversation. In this tool, the new agent is called as a tool, and the conversation is continued by the original agent" (openai-agents 0.23.1, agents/agent.py).

The run LOCAL MODEL. One customer message with two problems: "I was charged twice for invoice 1042 and I want the duplicate refunded. Also your app has crashed every time I log in since this evening." Billing has lookup_invoice and refund_charge; tech has check_status; all three tools return fixed fake data. Three designs on openai-agents 0.23.1 with Qwen3-4B-Instruct-2507 served locally: a triage agent with handoffs to both; the same with the specialists also allowed to hand off to each other ("mesh"); and a manager with both specialists as tools. What the recordings show. The triage model asked for both transfers in one reply, which is the right reading of a two-problem message. A conversation can only have one owner, so the SDK took the first and answered the second with a tool result, "Multiple handoffs detected, ignoring this one." (in run_internal/turn_resolution.py, actual_handoff = run_handoffs[0]). The crash was never looked at, in every handoff run. Allowing the specialists to hand off to each other did not help: billing had the transfer tool and an instruction to use it, and did not. The manager design consulted both specialists in every run, at about the prompt tokens.

All designs share one failure that has nothing to do with the pattern: no run ever called refund_charge, yet of replies told the customer the refund was under way. A 4B model is weak at acting before it speaks; the lesson for any pattern is to check the actions in the trace, not the words in the reply.

When to use which
Use a handoff when routing is the job and the specialist should own the rest of the conversation (one topic per conversation, as in a phone menu). Use agents as tools when one request can need several specialists, or when the user must keep talking to one voice. The SDK docs say the same: agents as tools "when a specialist should help with a bounded subtask but should not take over the user-facing conversation" ({{orchestrating multiple agents|https://openai.github.io/openai-agents-python/multi_agent/}}). Handoff history can be trimmed with an input_filter, and nest_handoff_history (an opt-in beta, off by default in 0.23.1) compacts earlier turns into summaries.
