7. When it hurts: two writers, one feature

Cognition's warning is about writing: "Actions carry implicit decisions, and conflicting decisions carry bad results." An implicit decision is a choice the spec did not make, such as what to call a field. Two agents writing halves of one feature in parallel each make those choices alone, and nobody notices until the halves meet.

The test MEASURED. Starting from textstats with its bugs fixed, two modules must fit together: one computes something from a text, the other formats it. Three designs, three runs each, all Claude Haiku 4.5 in Claude Code (tools Read, Write, Edit, Bash limited to python3, Glob, Grep): one agent writes both; two parallel writers, each in its own copy of the repository, told the other half exists but that they cannot see it; and contract first, where one tools-off call writes the shared data shape before the same two parallel writers start. A hidden check imports both halves from the merged tree and calls one on the other's output. We ran two specs:

  • Pinned: "build_report(text) returns the word count, the number of distinct words, and the top 3 words with their counts; render(report) makes a Markdown table." The wording nearly names the fields.
  • Open: "profile(text) describes a text's vocabulary: how long it is, how varied it is, and which words dominate it; card(p) formats it as a plain-text card, one line per item." Every name is left to the writer.

What happened. With the pinned spec the two writers chose the same field names every time: the same model reading the same sentence makes the same guess, so the "conflict" never arose. With the open spec the parallel halves fitted in of 3 runs. In the others nothing crashed: the formatter had been written defensively (if "length" in p:), so the card silently printed only the line whose name both writers happened to share, and the word count and variety vanished. A defensive guess turned a loud KeyError into quiet data loss. Run 3 was the mirror image of run 1: the names the formatter expected in run 1 were the ones the profile used in run 3, and the reverse. The same model, asked twice, decides differently, which is why "it worked when I tried it" means little here.

Writing the contract first fixed it in every run, for one extra short call and about of extra wall time on average (the writers also spent longer following it). The single agent never had the problem, because one context holds both decisions. This is the general rule: parallel writers need their implicit decisions made explicit before they start (an interface, a schema, a test that pins the shape), or a single writer.

Predict, then open: which would have caught the silent loss: the writers' own tests, or the hidden check?
Only a check across the seam. Each writer could test its half only against its own idea of the other half, so any test it wrote would pass. The hidden check called card(profile(...)) and looked for the word count in the output. Nous Research's 1,393-agent refactor met the same wall at scale: the repository's tests passed while reviewers found exception handling changed at about 65 sites (section 10).
