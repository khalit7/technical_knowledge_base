Common mistakes

Splitting a task that fits in one context
Each worker pays a full start-up context (about 13,000 tokens in Claude Code) and often re-reads what the lead read. The parent page's bug fix cost as much with subagents, for the same result.
Using a lead model to make a split you already know
If the pieces are files, rows or documents you can list, split them in code and fan out (section 4). A lead earns its cost only when finding the split is part of the job.
Trusting a merge that only concatenates
A lead that pastes worker reports together passes through whatever each worker decided to include. One orchestrator run here reported 43 items for 16 planted bugs, because one worker also flagged unchecked ratios.
Checking a model with the same model
Haiku checkers kept all 186 findings of one board run, whether shown the auditor's reasoning or not (section 5): they share its reading of the brief. Fix the brief, or use a verifier that does not share the judgement (tests, an answer key, Lean, a person).
Parallel writers without a contract
Two halves written apart fit only when the spec happens to name everything. A defensive reader (if key in p) turns the mismatch into silent data loss (section 7).
Expecting a handoff to handle two requests
A conversation has one owner at a time. The OpenAI Agents SDK keeps the first transfer and answers the rest with "Multiple handoffs detected, ignoring this one." Use agents as tools when one message can need two specialists (section 6).
Calling debate a win without a voting baseline
Compare against majority voting over the same number of independent samples, at equal tokens. Most published gains attributed to debate shrink against that baseline (section 8).
Reading the agent's own summary as coverage
The single agent reported a "comprehensive audit of all 48 modules" after reading half of them partially. Check coverage from the trace (which files were read, how much of each), not from the report.
Summing result.usage for cost
In Claude Code, result.usage leaves out subagent calls; result.modelUsage and total_cost_usd include them ({{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}}, section 7).

Interview questions

When does a multi-agent system beat a single agent?
When the material exceeds what one context holds well and splits into independent pieces (wide reading: research, audits, review). The win is coverage and wall time, bought with several times the tokens. It loses when the task fits one context or the pieces must agree on decisions.
What is context isolation, and what does it cost?
Each worker reads in its own window and returns only a report, so no loop has to hold everything. It costs a start-up context per worker, duplicated reading, and lost detail at the report boundary.
Handoff or agent-as-tool?
Handoff when the specialist should own the rest of the conversation and sees the full history; agent-as-tool when the manager keeps the conversation and the specialist answers one bounded, self-contained question from a generated input.
Why can tokens processed grow with the square of the steps?
Each call resends the whole history, so call t sends about S + g·t tokens; summed over T calls that is T·S + g·T²/2. Isolation divides the square term by the number of workers. Caching makes the re-sent part cheap per token but not free.
How would you verify a multi-agent system's output?
Measure recall and precision against a labelled set; check across seams (call one part on another's output); re-derive findings blind or with a non-model verifier; inspect per-agent traces for coverage. Do not use an agent's own confidence or summary.
Debate or voting?
Start with voting: it is cheaper per round, needs no prompt growth, and at equal budget it accounts for most of the gains attributed to debate in published comparisons. Add debate only if it beats voting on your data.
How do agents coordinate without a lead?
Through a shared store with atomic operations: claim a task with a lock or an exclusive create, post results, read others'. Claude Code agent teams use file-locked task claims; Agora uses a Git graph with cross-verification.
Design a research assistant that reads 500 documents.
A fan-out workflow if the documents are known: code splits them, parallel calls extract per document, code merges, a check step verifies each extracted claim blind. Add a lead only if what to read next depends on what was found. Trace every agent; report recall and precision on a labelled sample; budget tokens per worker.
