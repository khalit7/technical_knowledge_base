7. Sessions: resume, fork, and putting files back

A session is the saved conversation of one Claude Code process: a JSONL file under ~/.claude/projects/<encoded cwd>/ (or $CLAUDE_CONFIG_DIR/projects/). The SDK reaches it four ways ({{sessions|https://code.claude.com/docs/en/agent-sdk/sessions}}) DOCS: keep the process open (ClaudeSDKClient); continue_conversation=True (the most recent session in that directory, no id needed); resume="<id>"; or resume plus fork_session=True (a copy under a new id), optionally cut at a message with resume_session_at. Helpers list, read, rename and tag sessions (list_sessions(), get_session_messages()), and a session_store mirrors every transcript line to storage you choose, so a fresh container can resume a session written by another (the "hybrid" hosting pattern, section 10). Run s4 in section 2 showed resume and fork; a long session still compacts as Claude Code does (taught on {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}).

File checkpointing is the undo button. With enable_file_checkpointing=True (and extra_args={"replay-user-messages": None} so user messages come back with their ids), Claude Code backs up each file before its built-in Write, Edit or NotebookEdit tools change it, and client.rewind_files(user_message_id) restores the files to that point. Bash changes and subagent edits are not tracked ({{file checkpointing|https://code.claude.com/docs/en/agent-sdk/file-checkpointing}}) DOCS; by the same logic, edits made by your own in-process tools are not either (our reading of the docs, not run).

Run s9 MEASURED: tests before the agent "2 failed"; after the agent (Read, Edit and Bash, acceptEdits, one exact allow rule) "0 failed"; after rewind_files() to the prompt's checkpoint "2 failed" again, with one 457-byte backup written under ~/.claude/file-history/<session id>/. Rewinding restores files, not the conversation: the model still remembers its fix. (The same run shows Haiku making six refused attempts to test in other forms, python instead of python3 and inline scripts, while python3 tests/test_core.py 2>&1 || true was allowed: Claude Code checks each part of a compound command separately, as its refusals say ("contains multiple operations. The following part requires approval"). The run cost $0.0773 against $0.0215 for s1.)

8. Structured output: a schema, enforced by a tool

output_format={"type": "json_schema", "schema": {...}} asks for a final answer that matches a JSON schema; the result message carries it parsed in structured_output. The SDK passes the schema as --json-schema, and Claude Code adds a tool named StructuredOutput whose input is the answer SOURCE MEASURED. 9. Cost and usage: what the numbers mean


Every result message carries total_cost_usd and, per model, model_usage (input, output, cache read and cache write tokens, and a cost). The docs are blunt: these "are client-side estimates, not authoritative billing data", computed "from a price table bundled at build time"; "Do not bill end users or trigger financial decisions from these fields" ({{cost tracking|https://code.claude.com/docs/en/agent-sdk/cost-tracking}}) DOCS. On a subscription, as here, nothing is billed per token: the figure is what the same tokens would cost at API list prices.




total_cost_usd of each recorded run (s4: the last reported total, which includes all four phases). Every one reproduces exactly as model_usage tokens x list prices (Haiku 4.5 $1 input, $5 output, $0.10 cache read, $2 per million for 1-hour cache writes; Sonnet 5.5 $2, $10, $0.20, $4), with one twist: in s5 the subagent's cache writes match only at the 5-minute price ($1.25), the main thread's at the 1-hour price, as the Claude Code child also found.

The connector pitfall, counted


With a claude.ai login, an SDK run that leaves strict_mcp_config off can be given the account's connected apps as MCP tools. We measured it with a one-word task ("Reply OK.", Haiku 4.5, tools=[], setting_sources=[], one turn), keeping only counts: no tool or server name was stored anywhere MEASURED.




Input tokens of the single model call (fresh + cache write + cache read). Same machine, same account, 6 October 2026; batch 1 and batch 2 were minutes apart.


Two lessons. The cost: one "OK" cost $0.257 at list prices instead of $0.0008, because 128,296 tokens of tool definitions were written to the 1-hour cache. And the non-determinism: the identical non-strict call loaded nothing in batch 1, 165 tools in batch 2, and 122 tools (with our own server present) a minute later; connectors connect while the session starts, so how many arrive before the first call varies. We did not find out more than that. With strict_mcp_config=True it was 0 extra servers every time (3 of 3). The frameworks root met the same pitfall in its first SDK run.
