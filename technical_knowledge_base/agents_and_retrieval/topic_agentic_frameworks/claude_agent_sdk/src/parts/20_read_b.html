2. Two ways in: query() and ClaudeSDKClient

query() starts one Claude Code process, sends the prompt and yields messages until the result. The prompt is a string or an async iterator of user messages (streaming input), which the docs call "the preferred way": the string form lacks image attachments, queued messages, interruption and natural multi-turn conversation ({{streaming vs single message|https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode}}) DOCS. Our runs with a permission callback stream the prompt as a one-message iterator, as the docs' examples do. What comes back is the conversation plus a final ResultMessage carrying subtype, total_cost_usd, usage, model_usage and permission_denials (section 9 says how to read them).

Reference: every message class your loop receives

The messages your loop receives (types.py, 0.2.163) SOURCE: SystemMessage (the init record with model, tools, permission mode and Claude Code version; also permission_denied and progress notices), AssistantMessage (one per content block, all blocks of one model call sharing a message_id), UserMessage (tool results), Task*Message (subagent started, progress, finished), RateLimitEvent, and the final ResultMessage with subtype, num_turns, total_cost_usd, usage, model_usage, permission_denials and structured_output. With include_partial_messages=True you also get the raw token stream.

query() is not stateless. Every call writes its conversation to ~/.claude/projects/<encoded working directory>/<session id>.jsonl ({{sessions|https://code.claude.com/docs/en/agent-sdk/sessions}}) DOCS; our recordings left 15 session transcripts there (9 KB to 567 KB; the two largest came from the connector measurements of section 9), plus two subagent transcripts in a subfolder of run s5's session; we measured and deleted them MEASURED. In a container that file is lost on restart; on a shared host it is a data-retention question. TypeScript has persistSession: false; Python 0.2.163 has no such option (its extra_args can pass the command line's --no-session-persistence flag: not run here).

ClaudeSDKClient (Python only; TypeScript uses a streaming prompt and continue) keeps one Claude Code process open: client.query() sends the next turn, receive_response() reads until that turn's result, and between turns you can call get_context_usage(), interrupt(), set_permission_mode(), set_model() or rewind_files() SOURCE. Run s4 (section 7) used it for two turns, then resumed and forked the saved session. Interrupting a running turn is recorded on {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}: the SDK's interrupt() made Claude Code write a refused tool result and end with error_during_execution.

3. Options, and the defaults that bite

ClaudeAgentOptions has 49 fields in Python 0.2.163; TypeScript's Options has 69 (it adds, among others, persistSession, abortController, spawnClaudeCodeProcess, managedSettings and dialog hooks) SOURCE. Most become one flag of the child (model to --model, max_turns to --max-turns); subagents, skills and hook ids go in the initialize request instead. The {{Options lab|#t-opts}} rebuilds the mapping from _build_command() so you can see the exact command for any choice, checked against the commands our runs started. What matters is what you get when you set nothing:

Same task, same model: options set on purpose against the defaults

Run s1 passes our four tools, a short system prompt, a hook and a callback; run s3 passes only isolation (setting_sources=[], strict_mcp_config=True) and a one-line system prompt in place of the empty default, so it gets Claude Code's 29 default tools, permission mode default and nobody to answer "ask". The first call grew from 1,390 tokens with our prompt and tools to 14,703 with the defaults; both runs ended "success" MEASURED.

Predict, then open: what did s3's six refusals look like, and why did it still report success?
The run ended with subtype: "success" after 14 model calls, but 6 of its 16 tool calls were refused: 3 Bash calls ("This command requires approval", including the plain python3 tests/test_core.py) and all 3 edits ("Claude requested permissions to write to /work/textstats/core.py, but you haven't granted it yet."). Nobody was there to answer "ask", so ask became deny. Its final answer found both bugs and asked: "Please approve the file edits". Tests after: 2 failed. Cost: 247,863 input tokens processed, $0.0867 at list prices, against $0.0215 for run s1, which fixed both bugs MEASURED. subtype says the loop ended normally, not that the task was done: check permission_denials and run your own test.

The four defaults to know by heart SOURCE DOCS:

  • System prompt: empty. system_prompt=None sends --system-prompt "". Since v0.1.0 "The SDK no longer uses Claude Code's system prompt by default"; ask for it with {"type": "preset", "preset": "claude_code"}, optionally with "append" ({{migration guide|https://code.claude.com/docs/en/agent-sdk/migration-guide}}). It costs context: about 6,200 tokens on Haiku in the frameworks root's runs (7,612 against 1,388).
  • Tools: Claude Code's whole default set. tools=None adds no flag, so you get the default list; ours had 29 tools (Read, Edit, Write, Bash, WebFetch, WebSearch, Skill, the subagent tool and the task tools among them; Glob and Grep absent, as {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}} found on macOS) MEASURED. tools=[] removes them all.
  • Settings: everything on the machine. setting_sources=None reads user, project and local settings, "matching the CLI": your ~/.claude/settings.json, its hooks, CLAUDE.md files, skills and commands. Pass [] to isolate.
  • Outside MCP servers: allowed. Without strict_mcp_config=True, servers from .mcp.json, settings and plugins load, and with a claude.ai login so do the account's connectors, which the docs list among things "read regardless of settingSources" ({{Claude Code features in the SDK|https://code.claude.com/docs/en/agent-sdk/claude-code-features}}). Section 9 shows one call that cost 128,306 input tokens because of it.

The fix is a decision about who answers "ask": a mode (acceptEdits approves file edits and simple file commands in the working directory; dontAsk turns every unresolved ask into a deny, which makes an allow-list exact), allow rules (allowed_tools=["Bash(python3 tests/test_core.py)"]), or your own can_use_tool. Section 5 shows the order in which these are consulted. A service-ready start passes setting_sources=[], strict_mcp_config=True, an explicit tool list and one of those answers (the Options lab's last preset).
