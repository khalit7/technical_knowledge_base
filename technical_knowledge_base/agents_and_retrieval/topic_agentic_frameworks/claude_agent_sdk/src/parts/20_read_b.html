2. Two ways in: query() and ClaudeSDKClient

query() starts one Claude Code process, sends the prompt and yields messages until the result. The prompt is either a string or an async iterator of user messages (streaming input). The docs call streaming input "the preferred way" and list what the string form lacks: image attachments, queued messages, interruption and natural multi-turn conversation ({{streaming vs single message|https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode}}) DOCS. All our runs that use a permission callback stream the prompt as a one-message iterator, as the docs' examples do.

The messages your loop receives, by Python class: SystemMessage (the init record with model, tools, permission mode and Claude Code version; also permission_denied and progress notices), AssistantMessage (one per content block: thinking, text or a tool call, all blocks of one model call sharing a message_id), UserMessage (tool results), Task*Message (subagent started, progress, finished), RateLimitEvent, and the final ResultMessage with subtype, num_turns, total_cost_usd, usage, model_usage, permission_denials and structured_output (types.py, 0.2.163) SOURCE. With include_partial_messages=True you also get the raw token stream.

query() is not stateless. Every call writes its conversation to ~/.claude/projects/<encoded working directory>/<session id>.jsonl ({{sessions|https://code.claude.com/docs/en/agent-sdk/sessions}}) DOCS; our recordings left 15 session transcripts there (9 KB to 567 KB; the two largest came from the connector measurements of section 9), plus two subagent transcripts in a subfolder of run s5's session; we measured and deleted them MEASURED. TypeScript has persistSession: false; Python 0.2.163 has no such option (its extra_args can pass the command line's --no-session-persistence flag: not run here).

ClaudeSDKClient (Python only; TypeScript uses a streaming prompt and continue) keeps one Claude Code process open: client.query() sends the next turn, receive_response() reads until that turn's result, and between turns you can call get_context_usage(), interrupt(), set_permission_mode(), set_model() or rewind_files() SOURCE. Run s4 used it for two turns, then started two more processes from the saved session: one with resume, one with resume plus fork_session.

Run s4, Haiku 4.5, our four tools. "Reported" is the result message's total_cost_usd; "own" is the difference from the previous phase. Same session id after resume, a new one after the fork.

What the run shows MEASURED: (1) the second turn remembered the first without our code sending any history: the history lives in the Claude Code process; (2) total_cost_usd and model_usage are running totals, across turns of one client and across later processes that resume the session, while usage covers only the last turn; the docs say so: "A call that resumes a session also counts the session's earlier spend" ({{cost tracking|https://code.claude.com/docs/en/agent-sdk/cost-tracking}}) DOCS; (3) the fork answered from the full history ("Both failures have been fixed") under a new session id, so the original session can continue separately. The context report after turn 1 split 2,572 tokens into system prompt 56, MCP tools 258 (list_files 51, read_file 58, edit_file 96, run_tests 53) and messages 2,258, with autocompaction set for 167,000 of Haiku's 200,000.

Interrupting a running turn is recorded on {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}: the SDK's interrupt() made Claude Code write a refused tool result and end with error_during_execution.

The mapping is in _build_command(); the {{Options lab|#t-opts}} rebuilds it so you can see the exact command for any choice, checked against the commands our runs actually started. Four defaults deserve to be known by heart SOURCE DOCS:

  • System prompt: empty. system_prompt=None sends --system-prompt "". Since v0.1.0 "The SDK no longer uses Claude Code's system prompt by default"; ask for it with {"type": "preset", "preset": "claude_code"}, optionally with "append" ({{migration guide|https://code.claude.com/docs/en/agent-sdk/migration-guide}}).
  • Tools: Claude Code's whole default set. tools=None adds no flag, so you get the default list; ours had 29 tools (Read, Edit, Write, Bash, WebFetch, WebSearch, Skill, the subagent tool and the task tools among them; Glob and Grep absent, as {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}} found on macOS) MEASURED. tools=[] removes them all.
  • Settings: everything on the machine. setting_sources=None reads user, project and local settings, "matching the CLI": your ~/.claude/settings.json, its hooks, CLAUDE.md files, skills and commands. A short-lived v0.1.0 change to load nothing "was briefly changed ... and then reverted" (same page). Pass [] to isolate (Python 0.1.59 and earlier treated [] as "not given").
  • Outside MCP servers: allowed. Without strict_mcp_config=True, servers from .mcp.json, settings and plugins load, and with a claude.ai login so do the account's connectors, which the docs list among things "read regardless of settingSources" ({{Claude Code features in the SDK|https://code.claude.com/docs/en/agent-sdk/claude-code-features}}). Section 9 shows what that did to one call.
Predict, then open: run s3 gives the textstats task to query() with only isolation added: Claude Code's default tools, the empty system prompt, permission mode default, no permission callback. Do the tests pass?
No. The run ended with subtype: "success" after 14 model calls, but 6 of its 16 tool calls were refused: 3 Bash calls ("This command requires approval", including the plain python3 tests/test_core.py) and all 3 edits ("Claude requested permissions to write to /work/textstats/core.py, but you haven't granted it yet."). Nobody was there to answer "ask", so ask became deny. Its final answer found both bugs and asked: "Please approve the file edits". Tests after: 2 failed. Cost: 247,863 input tokens processed, $0.0867 at list prices, against $0.0215 for run s1, which fixed both bugs MEASURED. Check permission_denials and your own test, never only subtype.

The fix is a decision about who answers "ask": a mode (acceptEdits approves file edits and simple file commands in the working directory; dontAsk turns every unresolved ask into a deny, which makes an allow-list exact), allow rules (allowed_tools=["Bash(python3 tests/test_core.py)"]), or your own can_use_tool.
