5. Permissions and hooks: your code in the decision

Every tool call passes a permission check run by the Claude Code process. The SDK docs give the order: (1) hooks, (2) deny rules ("even in bypassPermissions mode"), (3) ask rules (these go to your callback even in bypass mode), (4) the permission mode, (5) allow rules (including calls a tool approves on its own, such as reading a file in the working directory), (6) your can_use_tool callback; in dontAsk mode step 6 is skipped and the call is denied ({{configure permissions|https://code.claude.com/docs/en/agent-sdk/permissions}}) DOCS. Two consequences: "Auto-approved tools never reach canUseTool", so a callback is not an audit log (use a PreToolUse hook for that); and a hook that returns allow still cannot override a deny rule. The SDK source adds that a PreToolUse hook returning allow "also skips" the callback, and setting can_use_tool makes the SDK pass --permission-prompt-tool stdio so the questions come down the pipe SOURCE.

One step per tool call, in the order the model made them, from the three recordings. The stage that settled each call is read from the recording (hook output, callback log, refusal text); stages before it were passed, stages after it never ran. s1 and s2 use our four tools with a hook that allows the two read-only tools; s3 uses Claude Code's built-in tools with no hook and no callback.

The callback. async def can_use_tool(tool_name, input, context) returns PermissionResultAllow(updated_input=..., updated_permissions=...) or PermissionResultDeny(message=..., interrupt=False); context carries the tool-use id, a suggested rule, the blocked path, a reason and a ready-made prompt sentence (title) for a human approval screen SOURCE. Run s2 asked for a fix and a new regression test in tests/, while our callback made tests/ read-only with the message "tests/ is read-only for this agent. Describe the test you would add in your final reply instead." The model received that sentence as an error tool result, did not try another route, and ended: "I was unable to edit the test file as it's read-only. However, I have successfully fixed the code." Tests passed and the test file was unchanged MEASURED. The callback can also wait as long as you like (for a human on Slack, say); for very long waits the docs suggest a hook that returns defer so the process can exit and the session resume later ({{user input|https://code.claude.com/docs/en/agent-sdk/user-input}}) DOCS.

Hooks as callbacks. hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[fn])]} registers fn; the SDK gives each function an id (hook_0, hook_1) in the initialize request and the Claude Code process calls it back with hook_callback SOURCE MEASURED. A PreToolUse callback can answer permissionDecision allow, deny, ask or defer, rewrite the input (updatedInput) or add context; PostToolUse can replace the tool's output. Several matchers on one event run concurrently, so do not rely on their order (docstring of hooks, 0.2.163). Python supports 10 events (PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SubagentStart, SubagentStop, PreCompact, Notification, PermissionRequest); TypeScript supports 33, including SessionStart, SessionEnd, PostCompact and PermissionDenied; in Python, SessionStart and SessionEnd exist only as shell hooks in settings files ({{hooks|https://code.claude.com/docs/en/agent-sdk/hooks}}) DOCS SOURCE. Shell hooks from settings files also run if setting_sources loads them. What each event means, and a hook that blocks, are on {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}} (section Hooks).

Callbacks are policy, not a sandbox

A permission callback sees the tool's arguments, not what a command will do: python3 -c "..." passes any rule written about file paths. Run the agent where it cannot hurt you (the sandbox option for Bash, a container, a VM); the hosting docs compare sandbox-runtime, Docker, gVisor and Firecracker VMs ({{secure deployment|https://code.claude.com/docs/en/agent-sdk/secure-deployment}}) DOCS. Gate and sandbox design are taught on {{Agent security|n:3f15c17b0d0d81ad9fb7d1dd74217335}} and {{Containers and isolation|n:3f05c17b0d0d8156a841e4bf28f11293}}.

6. Subagents defined in code

A subagent is a second agent loop with its own system prompt, tools, model and context window; the main agent starts one through the Agent tool (the init record still lists it as Task, an alias kept for compatibility) and receives only its final message ({{subagents|https://code.claude.com/docs/en/agent-sdk/subagents}}) DOCS MEASURED. In the SDK you define them with agents={"test-runner": AgentDefinition(...)}: description (when to use it) and prompt are required; tools, disallowedTools, model, skills, memory, mcpServers, initialPrompt, maxTurns, background, effort and permissionMode are optional (Python keeps the camelCase spelling of the wire format) SOURCE. The docs add: subagents run in the background by default; the only thing the parent passes is the Agent tool's prompt string, not its history; defaults allow 3 levels of nesting and 20 concurrent subagents, with no spend limit unless you set max_budget_usd DOCS.

Run s5 (Sonnet 5.5 as the main agent, told to delegate every test run to a Haiku test-runner with only Bash, maxTurns=4, background=False; permission mode acceptEdits with the single allow rule Bash(python3 tests/test_core.py)) MEASURED:

  • The first delegation went wrong in an instructive way. The subagent ran the allowed command, got the failures, then asked for more detail three times with variants (-v 2>&1, python3 -m pytest ..., a redirect to a file); each was refused because an allow rule matches the command it names, not its relatives. It hit its 4-turn cap with no report, and Claude Code told the main agent: "this agent stopped at its 4-turn limit before finishing ... Send the agent a message (SendMessage)". The main agent tried; SendMessage was "disabled for this session". It then read the files itself with one read-only shell command, made both edits, and delegated again; the second subagent ran one command and reported "0 failed".
  • Cost split by model in model_usage: Haiku $0.0228, Sonnet $0.0625, total $0.0852. The result's usage counted 33,906 input tokens, model_usage 65,602: usage leaves the subagent out, as the docs' table says ("Excluded. Counts only the top-level agent loop").
  • The subagent messages arrive in your stream with parent_tool_use_id set to the Agent call's id, plus task_started, task_progress and task_notification system messages; text and thinking of subagents are forwarded only with forward_subagent_text=True SOURCE.

When several agents help and when they hurt is the subject of {{Multi-agent patterns|n:3c65c17b0d0d8194a306c37803387bf3}}; subagents as a context-isolation tool, with a measured window saving, are on {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}.
