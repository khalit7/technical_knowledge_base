Wire lab: the conversation between your program and Claude Code

Every line that crossed the pipe in two recorded runs of the same task, replayed in order. On the left, your Python process (the SDK and your callbacks); on the right, the Claude Code process it started. s1 gives Claude Code someone to talk to: four in-process tools, a PreToolUse and a PostToolUse hook, and a can_use_tool callback. s3 gives it the defaults: built-in tools and no callbacks, so after initialize the pipe only flows one way, and every question Claude Code would have asked becomes a refusal (Reading, section 3). Captured by a stand-in for the binary that copies each line to a log before passing it on (src/code/wire.py), then redacted.

sYour process (SDK)Claude Code


Shown: the JSON body of the current line, shortened to 700 characters. Kept out: thinking-progress and session-state notices, rate-limit events, and from the initialize answer everything but the permission mode, the hook flag, the session state and the built-in agent names (it also carries the account, the model list and local paths). Times are seconds since the stand-in started.




What each control message means




SubtypeDirectionMeaning



initializeyou to Claude CodeFirst line: hook callback ids per event and matcher, subagent definitions, skill filter. The answer lists commands, agents, the permission mode.


mcp_messageClaude Code to youA JSON-RPC message for an MCP server living in your process: initialize, tools/list, tools/call.


hook_callbackClaude Code to youRun hook hook_N with this input; your answer can allow, deny, rewrite or add context.


can_use_toolClaude Code to youA tool call nothing else settled: allow (optionally with changed input) or deny with a message.


interrupt, set_permission_mode, set_model, rewind_files, get_context_usageyou to Claude CodeControl a running session (not in these two runs; get_context_usage and rewind_files are in s4 and s9).
