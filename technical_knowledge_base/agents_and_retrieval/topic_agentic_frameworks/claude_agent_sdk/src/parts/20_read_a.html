The SDK in one screen

The Claude Agent SDK lets your own Python or TypeScript program run the agent that powers Claude Code: the same loop, tools, permission system, context management and sessions. It is not a reimplementation. When your code calls query(), the SDK starts the Claude Code program itself as a child process and talks to it in lines of JSON; your functions (permission checks, hooks, your own tools) are called back over that same pipe SOURCE MEASURED.

The agent loop (model call, tool call, tool result, repeat until the model stops) is taught from zero on {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} (tab Loop lab), and Claude Code as a product, with its permission rule syntax, hook events, memory files and headless runs, is taken apart on {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}}. This page owns the library: what your code controls, what it costs, and how it differs from the frameworks compared on {{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}.

Three things to remember
  1. The SDK is a command-line builder plus a callback server. Everything Claude Code does still happens in the Claude Code process; read {{Claude Code, taken apart|n:3c65c17b0d0d81db9c7fc54987c1ab65}} to know what that process does.
  2. Defaults are not safe defaults: with nothing set, the system prompt is empty, the tool list is Claude Code's full default set, every settings file on the machine is read, and in a subscription login the account's connected apps can join the tool list. Pass every option on purpose (section 3).
  3. "success" is not "done": our bare run ended with subtype: "success", six refused tool calls and both tests still failing (section 3).

1. What the SDK is: your program starting Claude Code

The problem it solves. Claude Code is a terminal program. If you want its agent inside your own service (a support bot, a code-review job, an internal research agent), you can either rebuild the loop, tools, permissions and context management yourself (the {{Loop lab|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} on the harnesses root shows what that takes) or drive Claude Code from code. Anthropic first shipped the second option as the Claude Code SDK and renamed it the Claude Agent SDK on 29 September 2025, because "the agent harness that powers Claude Code ... can power many other types of agents, too" ({{Anthropic, Thariq Shihipar, 29 Sep 2025|https://claude.com/resources/articles/building-agents-with-the-claude-agent-sdk}}) DOCS. Packages: Python claude-agent-sdk (first release 0.1.0 on 28 September 2025 UTC, MIT licence for the Python wrapper per its PyPI classifier) and TypeScript @anthropic-ai/claude-agent-sdk (0.1.0 on 29 September 2025; its package says "All rights reserved", use under Anthropic's legal agreements) ({{PyPI|https://pypi.org/project/claude-agent-sdk/}}, {{npm|https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk}}) DOCS.

How it works. The Python wheel carries a whole Claude Code binary (_bundled/claude, 225,167,728 bytes on macOS arm64 for 0.2.163, which pins Claude Code 2.1.286); the TypeScript package pulls a platform package with its own binary (233,211,568 bytes, Claude Code 2.1.291 for SDK 0.3.291: the TypeScript version 0.3.N ships Claude Code 2.1.N) MEASURED. The Python transport looks for the bundled binary first, then claude on the PATH, then a few fixed install locations; cli_path overrides all of that (_internal/transport/subprocess_cli.py, 0.2.163) SOURCE. It then starts the binary with --output-format stream-json --verbose --input-format stream-json plus one flag per option you set, sets CLAUDE_CODE_ENTRYPOINT=sdk-py and CLAUDE_AGENT_SDK_VERSION in its environment, and from then on both sides write one JSON object per line: your prompt and your answers go down the child's standard input, messages and questions come back on its standard output. The docs say the same: "When your code calls query(), the SDK spawns a separate claude CLI process and talks to it over stdio", and "One agent session maps to one subprocess" ({{Hosting the Agent SDK|https://code.claude.com/docs/en/agent-sdk/hosting}}) DOCS.

Drawn from the recorded wire of run s1 (Haiku 4.5, our four tools, a hook and a permission callback): the counts are its real traffic. The Wire lab tab replays all 83 lines one by one, next to a run where nobody answers.

Two kinds of lines share the pipe. Messages are the conversation: the system/init record, assistant messages (thinking, text, tool calls), user messages (tool results) and the final result. Control messages are the side channel: a control_request with a request id and a control_response that echoes it. Your process sends initialize (with the ids of your hook callbacks and your subagent definitions), interrupt, set_permission_mode, set_model, rewind_files, get_context_usage and a few MCP management requests; the Claude Code process sends can_use_tool, hook_callback and mcp_message (a JSON-RPC message for an MCP server that lives inside your process) SOURCE. In run s1 the Claude Code process asked our process 28 questions in 15.8 seconds: 14 hook calls, 4 permission questions and 10 MCP messages (initialize, the initialized notification, the tool list, 7 tool calls) MEASURED.

What this means in practice

Your callbacks are in the critical path of every tool call: a slow can_use_tool or hook slows the agent, and an exception in one comes back to Claude Code as an error response. The model, the context window, compaction, the tool implementations of Read, Edit and Bash, and the session file all live in the child process; your process sees them only as messages. The answer to "how does the SDK do X" is almost always "Claude Code does X; the SDK passes a flag". An infrastructure analogy from the old version of this page still helps: Claude Code is a managed runtime in which hooks are middleware, subagents are worker processes with private memory, MCP is the driver interface, permissions are the security policy and skills are lazy-loaded configuration.

Predict: you run 50 agents at once with the SDK on one machine. How many Claude Code processes are running?
Fifty: one per session. (We did not check whether a subagent starts a further process; the session files show each subagent writing its own transcript inside the parent session's folder, section 6.) The hosting docs suggest planning "1 GiB RAM, 5 GiB disk, and 1 CPU per agent" as "a floor, not the ceiling" ({{hosting|https://code.claude.com/docs/en/agent-sdk/hosting}}) DOCS. This is the main operational difference from a library such as Pydantic AI, where an agent is an object in your process.
