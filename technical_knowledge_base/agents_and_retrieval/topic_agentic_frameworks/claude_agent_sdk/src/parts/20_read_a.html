The SDK in one screen

The Claude Agent SDK does not reimplement Claude Code: your program starts the Claude Code binary as a child process, turns your options into its command-line flags, and answers its questions (permission checks, hooks, your own tools) as JSON lines on the same pipe. Everything else, the loop, the context, compaction, the built-in tools and the session file, stays in the child.

Three processes, one pipe: Claude Code does the work, your code is called back

Run s1 (Haiku 4.5, our four tools, a hook and a permission callback), counted from its recorded wire: 30 lines down stdin, 53 up stdout, of which 28 were questions to your process. Section 1 replays all 83 lines.

1. What the SDK is: your program starting Claude Code

The problem. Claude Code is a terminal program. To put its agent inside your own service (a support bot, a code-review job, a research agent) you either rebuild the loop, tools, permissions and context management yourself ({{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}} shows what that takes) or drive Claude Code from code. Anthropic shipped the second option as the Claude Code SDK and renamed it the Claude Agent SDK on 29 September 2025, because "the agent harness that powers Claude Code ... can power many other types of agents, too" ({{Anthropic, Thariq Shihipar, 29 Sep 2025|https://claude.com/resources/articles/building-agents-with-the-claude-agent-sdk}}) DOCS.

How it works. The Python wheel carries a whole Claude Code binary (_bundled/claude, 225,167,728 bytes on macOS arm64 for 0.2.163, which pins Claude Code 2.1.286); the TypeScript package pulls a platform package with its own binary (233,211,568 bytes, Claude Code 2.1.291 for SDK 0.3.291: the TypeScript version 0.3.N ships Claude Code 2.1.N) MEASURED. The SDK starts it with --output-format stream-json --verbose --input-format stream-json plus one flag per option you set, and sets CLAUDE_CODE_ENTRYPOINT=sdk-py and CLAUDE_AGENT_SDK_VERSION in its environment; from then on both sides write one JSON object per line. The docs: "One agent session maps to one subprocess" ({{Hosting the Agent SDK|https://code.claude.com/docs/en/agent-sdk/hosting}}) DOCS.

Two kinds of lines share the pipe. Messages are the conversation: the system/init record, assistant messages, tool results and the final result. Control messages are the side channel: your process sends initialize (your hook callback ids and subagent definitions), interrupt, set_permission_mode and a few more; the Claude Code process sends can_use_tool, hook_callback and mcp_message (a JSON-RPC message for an MCP server inside your process) SOURCE. In run s1 the Claude Code process asked our process 28 questions in 15.8 seconds: 14 hook calls, 4 permission questions and 10 MCP messages (initialize, the initialized notification, the tool list, 7 tool calls) MEASURED.

Every line that crossed the pipe, captured by a stand-in for the binary that copies each line to a log before passing it on (src/code/wire.py), then redacted. s1: 83 lines; s3: 64 lines, only 2 of them from your process (the prompt and initialize), so every question Claude Code would have asked became a refusal. Times are seconds since the stand-in started (what was left out: the depth block below).




What follows. Your callbacks are in the critical path of every tool call: a slow can_use_tool or hook slows the agent, and an exception in one comes back to Claude Code as an error response. The model, the context window, compaction, the tool implementations of Read, Edit and Bash, and the session file all live in the child; your process sees them only as messages. So the answer to "how does the SDK do X" is almost always "Claude Code does X; the SDK passes a flag".


Predict: you run 50 agents at once with the SDK on one machine. How many Claude Code processes are running?
Fifty: one per session. (We did not check whether a subagent starts a further process; the session files show each subagent writing its own transcript inside the parent session's folder, section 6.) The hosting docs suggest planning "1 GiB RAM, 5 GiB disk, and 1 CPU per agent" as "a floor, not the ceiling" ({{hosting|https://code.claude.com/docs/en/agent-sdk/hosting}}) DOCS. This is the main operational difference from a library such as Pydantic AI, where an agent is an object in your process.


Depth: how the binary is found, every control message, and the old page's analogy


The Python transport looks for the bundled binary first, then claude on the PATH, then a few fixed install locations; cli_path overrides all of that (_internal/transport/subprocess_cli.py, 0.2.163) SOURCE. The docs say it plainly: "When your code calls query(), the SDK spawns a separate claude CLI process and talks to it over stdio" ({{hosting|https://code.claude.com/docs/en/agent-sdk/hosting}}).

An infrastructure analogy from the old version of this page still helps: Claude Code is a managed runtime in which hooks are middleware, subagents are worker processes with private memory, MCP is the driver interface, permissions are the security policy and skills are lazy-loaded configuration.
