10. Deployment, authentication, and the alternatives

Authentication. The SDK reads an API key (ANTHROPIC_API_KEY) or a cloud provider switch: CLAUDE_CODE_USE_BEDROCK=1, CLAUDE_CODE_USE_VERTEX=1, CLAUDE_CODE_USE_FOUNDRY=1, CLAUDE_CODE_USE_ANTHROPIC_AWS=1 (Claude Platform on AWS) ({{overview|https://code.claude.com/docs/en/agent-sdk/overview}}) DOCS. Our recordings ran on a personal Claude subscription (the init record says apiKeySource: "none"), which is fine for personal experiments; a product is a different matter: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." (same page) DOCS.

Hosting patterns. Because "One agent session maps to one subprocess" that "owns a shell, a working directory, and session files on disk", the hosting page lists four patterns ({{hosting|https://code.claude.com/docs/en/agent-sdk/hosting}}) DOCS:

PatternShapeFits
EphemeralA container per task, destroyed at the end"bug investigation and fix, invoice and receipt extraction, document translation"
Long-runningPersistent containers, often several SDK processes eachemail agents, chat bots, per-user site builders
HybridEphemeral containers that load the session from a SessionStore and write it back ("the store is required")conversations that sit idle between turns
Multi-agent containerSeveral SDK processes in one containeragents that must collaborate closely

Sizing starts at "1 GiB RAM, 5 GiB disk, and 1 CPU per agent"; a small container costs "roughly $0.05 per hour, while a single long agent session can spend dollars in tokens"; pin a session to one container by hashing its id; the subprocess needs outbound HTTPS to the API and "does not listen on the network". For several customers on one host the docs ask for setting_sources=[], CLAUDE_CODE_DISABLE_AUTO_MEMORY=1, a separate CLAUDE_CONFIG_DIR and working directory per tenant, and per-tenant egress rules; "Do not rely on default query() options for multi-tenant isolation." Known gaps: no top-level session timeout, memory growth in long sessions, no per-subagent deadline DOCS.

Observability. "The SDK does not produce telemetry of its own": set CLAUDE_CODE_ENABLE_TELEMETRY=1 and OpenTelemetry exporters in the child's environment and Claude Code emits metrics, log events and (beta) spans named claude_code.interaction, claude_code.llm_request, claude_code.tool; the SDK passes the active trace context down so they join your trace ({{observability|https://code.claude.com/docs/en/agent-sdk/observability}}) DOCS. The span tree was recorded on the frameworks root ({{Production stack|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab) and is taken further on {{LLM observability|n:3c65c17b0d0d81fe82c0c6e9360afec4}}, whose measurements of Claude Code (2.1.291) carry over because the SDK starts Claude Code itself: a TRACEPARENT in the environment of a -p run parents claude_code.interaction under the caller's span, and Bash subprocesses inherit it; and user.email, user.id, user.account_uuid, user.account_id and organization.id are on every span by default (45 of 45), so filter them before traces leave your network MEASURED.

Python or TypeScript. Run s8 is run s1 rewritten in TypeScript (zod schemas, the same hook and callback) MEASURED: same fix, 6 model calls, $0.0247. Its first call was 1,566 tokens against 1,390 in Python, because the TypeScript package bundled the newer Claude Code (2.1.291 against 2.1.286): the context belongs to the binary, not to the language. Differences that matter: TypeScript has 33 hook events to Python's 10, persistSession, an AbortController, and 69 options; Python has ClaudeSDKClient; TypeScript's env replaces the child's environment while Python's merges into it ({{subagents|https://code.claude.com/docs/en/agent-sdk/subagents}}) DOCS.

The OpenAI Agents SDK, Pydantic AI, smolagents and Google ADK are read from source on {{Typed agent libraries|n:3f15c17b0d0d819fba89f9ec88feb859}}; the same task in six frameworks, side by side with real runs, is the root's {{Same agent, six ways|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab. Choose the Claude Agent SDK when the job is work on a computer (code, files, shell, research) and Claude is the model you want; you inherit compaction, permissions, subagents and sessions instead of writing them, and you pay with a large process per session, Claude Code's own context (the first call grew from 1,390 tokens with our prompt and tools to 14,703 with the defaults, section 3) and no control over the loop. Choose a typed loop when you need provider choice, a loop you own, or agents that are objects in your process.

11. The old page, claim by claim

The previous version of this page (Notion, last edited 22 Sep 2026) was checked against the docs, the 0.2.163 source and our runs. Every claim, with its fate:

Common mistakes

Trusting subtype: "success"
It means the loop ended normally, not that the task was done. Run s3 succeeded with six refused calls and failing tests. Check permission_denials and run your own verification.
Leaving setting_sources and strict_mcp_config at their defaults in a service
Defaults read every settings file, hook, CLAUDE.md and skill on the machine and, with a claude.ai login, the account's connectors (128,306 tokens in one measured call). Pass setting_sources=[], strict_mcp_config=True and an explicit tool list.
Expecting Claude Code's system prompt
The default system prompt is empty since v0.1.0. Ask for {"type": "preset", "preset": "claude_code"} if you want Claude Code's behaviour, and measure the context it adds (about 6,200 tokens on Haiku in the root's runs: 7,612 against 1,388).
Using can_use_tool as an audit log
Calls allowed by a mode, an allow rule or a hook never reach it. Log in a PreToolUse hook, which runs for every call.
Writing allow rules for the command you expect
Bash(python3 tests/test_core.py) refused python3 tests/test_core.py -v 2>&1 and two other variants in s5, and python tests/test_core.py plus four inline test scripts in s9; each refusal is a wasted model call. Prefer a tool of your own (run_tests) over a shell rule when the action is known.
Summing total_cost_usd over turns or resumed runs
It is already a running total (s4). Take differences, or use usage per turn, deduplicated by message_id; and never bill customers from it.
Treating query() as stateless
Each call writes a session transcript to the home directory. In a container that is lost on restart; on a shared host it is a data-retention question. Use session_store, a per-tenant CLAUDE_CONFIG_DIR, or turn persistence off.
Shipping a product on a subscription login
Not allowed without approval; products use API keys or a cloud provider.

Interview questions

How does the Claude Agent SDK call your Python tool if the agent runs in another process?
The SDK registers an MCP server of type sdk in the Claude Code process's MCP config; when the model calls the tool, Claude Code sends a control_request of subtype mcp_message carrying a JSON-RPC tools/call down stdout; the SDK runs your function and answers with a control_response on stdin. No socket, no extra process.
In what order is a tool call checked, and where does your callback sit?
Hooks, deny rules, ask rules, permission mode, allow rules, then can_use_tool. The callback only sees calls nothing earlier settled; in dontAsk mode it is skipped and the call denied.
An agent built with the SDK reports success but did nothing. What do you check?
permission_denials in the result, the init record's permissionMode and tool list, whether anything answers "ask" (a mode, allow rules or a callback), then the transcript.
How would you compute the cost of one turn of a long session?
Difference of consecutive total_cost_usd values, or price that turn's usage (deduplicated by message id) plus subagents from model_usage differences. Remember it is an estimate.
When would you pick the Agent SDK over LangGraph, and over Managed Agents?
Over LangGraph ({{LangChain and LangGraph|n:3c65c17b0d0d81529358c996382224ac}}): when the work needs a computer and Claude Code's loop is good enough, and you do not need your own control flow or provider choice. Over Managed Agents: when the agent must run on your filesystem, network and audit trail, or you need hooks, plan mode and in-process tools.
How do you isolate tenants?
One process and working directory per session, setting_sources=[], strict_mcp_config=True, auto memory off, a per-tenant CLAUDE_CONFIG_DIR, a sandbox or container, egress rules, and credentials injected by a proxy rather than given to the agent.
