6. Gateways

Once more than one team or one provider is involved, every agent needs the same plumbing around each model call: credentials, a request format per provider, retries when a provider returns 429 (rate limited) or 5xx (server error), a fallback model when one is down, a timeout, a spend limit and a log line. A gateway (an LLM proxy) does all of it in one place: your code calls one OpenAI-shaped endpoint, and model choice, keys and spend become configuration instead of code. The two poles: LiteLLM, self-hosted, one endpoint over "100+ LLM providers" with virtual keys, budgets and a router (repo; the old page notes Khalid runs it at work), and OpenRouter, managed, one key and one bill over "400+ AI models" (FAQ) SOURCE; they compose, since LiteLLM can use OpenRouter as one more upstream. On 19 Aug 2026 OpenRouter announced it is "joining forces with Stripe", subject to closing conditions, with no price disclosed (announcement) SOURCE.

The cross-cutting risk is a fallback you never evaluated: the same prompt behaves differently on another provider's model, so during an outage the agent keeps answering, worse, and nothing errors. Run your evals against every model in the fallback chain (section 7) and tag each trace with the model that actually answered.

7. Observability and evals

You cannot debug an agent from log lines: you need to see which call saw what. Every tool converges on one data model. A trace is one run; it holds a tree of spans (timed units of work: a model call, a tool call, a subagent), each with attributes such as the model, token counts and cost. OpenTelemetry's GenAI semantic conventions standardise the names (gen_ai.operation.name with invoke_agent, chat or execute_tool, gen_ai.usage.input_tokens and so on); they are still marked "Development" (semantic-conventions-genai, read 6 Oct 2026) SOURCE. Backends (Langfuse, LangSmith, Braintrust, Arize Phoenix) differ by what they put first, tracing or evals, and all accept OpenTelemetry.

Evals in the loop close the circle: score a sample of production traces with rules and model judges, turn the interesting ones into dataset items, and run that dataset before every prompt, model or framework change; attribute cost per run, user and feature from the spans and reconcile it against the gateway's spend records. The Production stack's eval gate does this on recorded runs of the running example, with no model in the loop.

9. Hosted runtimes: buying the loop

The far end of the axis: the vendor runs the loop, the sandbox and the session on its servers, and you send a task and receive events. Claude Managed Agents is a "pre-built, configurable agent harness that runs in managed infrastructure", in public beta since 8 April 2026 (overview), with permission policies always_allow, always_ask and (since 10 Sep 2026) auto (permission policies). OpenAI's Agents API entered public beta on 10 Sep 2026: a "managed Codex harness while OpenAI handles session orchestration, context compaction, and recovery" (changelog) SOURCE. It builds on the Responses API (March 2025), which already ran built-in tools on OpenAI's side. What you trade: no loop to operate, durable sessions and sandboxes included; in exchange, control flow and prompts are the vendor's (factors 2 and 8 of the twelve in section 10), the spans between your request and your result are whatever the vendor exports, your data and tools run where the vendor runs them, and moving to another model means moving off the product.
