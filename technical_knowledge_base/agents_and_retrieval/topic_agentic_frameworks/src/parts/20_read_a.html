1. Workflows or agents: who picks the next step?

Anthropic's Building effective agents (Erik Schluntz and Barry Zhang, 19 Dec 2024) SOURCE draws the line every framework sits on. A workflow is a system where model calls and tools are "orchestrated through predefined code paths"; an agent is one where models "dynamically direct their own processes and tool usage". The same post names five workflow patterns, the shapes most production "agents" really are:

  • Prompt chaining: a fixed sequence of calls, each reading the last one's output, with code checks (gates) between them.
  • Routing: one call classifies the input and sends it to a specialised prompt or model.
  • Parallelisation: independent calls at once, merged by code (sectioning), or the same call several times and a vote.
  • Orchestrator-workers: a model writes the plan at run time, workers carry out the pieces, a model combines them.
  • Evaluator-optimizer: one call produces, another critiques, until the critic is satisfied or a round limit hits.

The chain's cost and time are known in advance and every step is auditable, but it can only do what its author foresaw (it pasted core.py in because the author knew the bug was there). The agent found the files itself, tripped over a directory read, ran the tests, edited twice and verified, and processed many times more tokens for a similar result. Of the six designs in the lab, only routing (6 of 6 hidden checks, 55.7 s) and the evaluator-optimizer (6 of 6, 262.7 s) passed every hidden correctness check; the others passed 5 of 6 and the unfixed code 3 MEASURED. Both carried more knowledge of what "correct" means, a specialist prompt or an edge-case reviewer: information and verification bought correctness, not the shape of the graph.

Choose a workflow when the steps are known, cost and latency must be bounded, an auditor will ask why each step ran, or the model is weak at choosing. Choose an agent when the number and kind of steps depend on what is found: debugging, research, anything open-ended. Anthropic's advice is "the simplest solution possible, and only increasing complexity when needed"; most real systems mix the two.

2. The orchestration schools

Orchestration libraries differ less in what they can do (all of them can call tools in a loop) than in what they make you describe: a graph, a cast of roles, a typed function, or the options of a finished agent. One paragraph each, with what it costs you; the comparison table above puts them side by side.

Graph and state machine: LangGraph, LlamaIndex Workflows

LangGraph models an application as a StateGraph: a typed state object, nodes that are plain functions returning updates to it, and edges (fixed, or functions that route on the state). Its reason to exist is the checkpointer of section 3. LangChain's create_agent runs on it (LangChain blog, 1.0 of both on 22 October 2025) SOURCE. LlamaIndex Workflows is the event-driven version: "an event-driven, step-based way to control the execution flow" (docs), where steps react to typed events instead of declared edges. Costs you: ceremony (state schema, nodes, edges, compile) for what may be a 15-line loop, and a large dependency. Pays when: runs must survive crashes, pause for people, branch and merge. Super-steps, checkpointers, interrupts, LangChain's Runnables and when a graph beats a plain loop, each measured: {{LangChain and LangGraph|n:3c65c17b0d0d81529358c996382224ac}}.

Roles and crews: CrewAI, AutoGen, AG2, Microsoft Agent Framework

This school has no child page; this section owns it. CrewAI describes a system as agents with a required role, goal and backstory, tasks assigned to them, and a sequential or hierarchical process; for fixed pipelines it adds event-driven Flows (docs) SOURCE. The prompts are generated from those fields, which makes a system quick to sketch and hard to control precisely. AutoGen made multi-agent work a conversation between agents; its repository now says "AutoGen is now in maintenance mode" and names the Microsoft Agent Framework as its successor, which Microsoft describes as "the next generation of both Semantic Kernel and AutoGen" (AutoGen, Microsoft Learn); its 1.0 releases for Python and .NET were tagged on 2 April 2026 SOURCE. AG2 continues the AutoGen line separately ("AG2 (formerly AutoGen)", repo). Costs you: prompts you did not write and many model calls spent on agents talking to each other. Pays when: the problem really is several roles, and you value speed of sketching over control. The versions checked are in the closed table of {{Typed agent libraries|n:3f15c17b0d0d819fba89f9ec88feb859}}.

Minimal typed loops: Pydantic AI, OpenAI Agents SDK, smolagents, Google ADK

The same small shape: an Agent object with instructions and tools, and a run function that loops. What distinguishes them: Pydantic AI validates results against an output_type and sends a ModelRetry back to the model as a retry prompt; the OpenAI Agents SDK adds handoffs, guardrails and sessions, with tracing to OpenAI's dashboard "enabled by default" (docs); smolagents changes the action language, its CodeAgent writing Python that is executed (the CodeAct paper reports "up to 20% higher success rate" than JSON actions, Wang et al., 2024), so it needs a sandbox; Google ADK is "available in Python, TypeScript, Go, Java, and Kotlin" and speaks A2A (adk.dev) SOURCE. Costs you: prompt inflation, tokens you never wrote. On the same task and tools the first request ran from 385 tokens (LangGraph) to 2,231 (smolagents, its own code-action system prompt), against the plain loop's 397 MEASURED; the table above has each. Pays when: you would otherwise hand-roll and want typed tools and results for little code. Each library read from its source and run, compared axis by axis: {{Typed agent libraries|n:3f15c17b0d0d819fba89f9ec88feb859}}.

Harness as a library: the Claude Agent SDK

The Claude Code SDK was renamed the Claude Agent SDK on 29 September 2025 (Anthropic) SOURCE. It ships Claude Code's whole loop as a library: your program starts the Claude Code binary and answers its questions on a pipe. You configure an agent rather than assemble one. Costs you: Claude models only, and Claude Code's own context (the table's first-call sizes); without strict_mcp_config=True a subscription run also loaded the account's connectors, well over 100,000 tokens of tool definitions MEASURED. Pays when: the job is work on a computer (files, shell, code) and you want a mature loop with compaction and permissions without writing them.
