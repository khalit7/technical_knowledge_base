2. The orchestration schools

Orchestration libraries differ less in what they can do (all of them can call tools in a loop) than in what they make you describe: a graph, a cast of roles, a typed function, or nothing at all. Four schools, one honest paragraph each, with what each costs you. Versions are those installed on 5 October 2026 by the {{Same agent|#t-same}} tab MEASURED.

Graph and state machine: LangGraph, LlamaIndex Workflows

LangGraph (1.2.13) models an application as a StateGraph: a typed state object, nodes that are plain functions returning updates to it, and edges (fixed, or functions that route on the state). Its reason to exist is the checkpointer of section 3: state saved after every step, so resume, human interrupts and time travel come with it. LangChain 1.0 and LangGraph 1.0 shipped together on 22 October 2025, and LangChain's create_agent "uses LangGraph under the hood" with "middleware" hooks around each model call (LangChain blog) SOURCE; the older create_react_agent now prints a deprecation warning MEASURED. LlamaIndex Workflows is the event-driven version: "an event-driven, step-based way to control the execution flow" (docs), where steps react to typed events instead of declared edges. Costs you: ceremony (state schema, nodes, edges, compile) for what may be a 15-line loop, a large dependency, and a history of breaking changes before 1.0. Pays when: runs must survive crashes, pause for people, branch and merge.

Roles and crews: CrewAI, AutoGen, AG2, Microsoft Agent Framework

CrewAI describes a system as agents with a required role, goal and backstory, tasks assigned to them, and a sequential or hierarchical process; for fixed pipelines it adds event-driven Flows (docs) SOURCE. The prompts are generated from those fields, which makes a system quick to sketch and hard to control precisely. AutoGen made multi-agent work a conversation between agents; its repository now says "AutoGen is now in maintenance mode" and names the Microsoft Agent Framework as its successor, which Microsoft describes as "the next generation of both Semantic Kernel and AutoGen" (AutoGen, Microsoft Learn); its 1.0 releases for Python and .NET were tagged on 2 April 2026 SOURCE. AG2 continues the AutoGen line separately ("AG2 (formerly AutoGen)", repo). Costs you: prompts you did not write and many model calls spent on agents talking to each other. Pays when: the problem really is several roles, and you value speed of sketching over control.

Minimal typed loops: Pydantic AI, OpenAI Agents SDK, smolagents, Google ADK

The same small shape: an Agent object with instructions and tools, and a run function that loops. Pydantic AI (2.54.0) builds tool schemas from function signatures, validates results against an output_type, and sends a ModelRetry message back to the model as a retry prompt (docs). The OpenAI Agents SDK (0.23.1) is "a production-ready upgrade" of the Swarm experiment with agents, tools, handoffs, guardrails and sessions; tracing to OpenAI's dashboard "is enabled by default", and non-OpenAI models run through a LiteLLM adapter (docs). smolagents (1.26.0) changes the action language: its CodeAgent writes Python that is executed, so several tool calls and a loop fit in one step (the CodeAct paper reports "up to 20% higher success rate" than JSON actions, Wang et al., 2024); executing model-written code needs a sandbox, and its executors are local, Docker, E2B, Modal and Blaxel (the WebAssembly executor was removed in 1.26.0, release notes). Google ADK is "available in Python, TypeScript, Go, Java, and Kotlin", speaks A2A (the agent-to-agent protocol, now a Linux Foundation project) and deploys to Google Cloud (adk.dev) SOURCE. Costs you: prompt inflation and an abstraction between you and the request. Same task, same four tools, a local 4B model: the plain loop's first request was 397 tokens, LangGraph 385, the OpenAI Agents SDK 491, Pydantic AI 507 (it adds an output tool), smolagents 2,231 (its own code-action system prompt) MEASURED. Pays when: you would otherwise hand-roll and want typed tools and results for little code.

Harness as a library: the Claude Agent SDK

The Claude Code SDK was renamed the Claude Agent SDK on 29 September 2025 (Anthropic) SOURCE. It ships Claude Code's whole loop as a library: query() for one task, ClaudeSDKClient for a session, custom tools through @tool and an in-process MCP server, hooks, programmatic subagents and a can_use_tool permission callback (Python reference). You configure an agent rather than assemble one. Costs you: Claude models only, and Claude Code's own context: with the same four tools on Haiku 4.5 the first request was 1,388 tokens with our own short system prompt, 7,602 with Claude Code's preset prompt, 12,992 with its built-in tools; and without strict_mcp_config=True a subscription run also loaded the account's connectors, well over 100,000 tokens of tool definitions MEASURED. Version 0.2.163 runs its own bundled Claude Code (2.1.286). Pays when: the job is work on a computer (files, shell, code) and you want a mature loop with compaction and permissions without writing them.

Predict: which school gives you crash recovery without extra work?
The graph runtimes (LangGraph's checkpointer). The minimal loops give you sessions (history), which is not the same as resuming a half-finished run. The Claude Agent SDK can resume a session, and a hosted runtime keeps sessions on the vendor's side.
