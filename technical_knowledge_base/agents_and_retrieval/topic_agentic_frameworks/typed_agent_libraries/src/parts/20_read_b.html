2. Typed output: where the schema travels

The second promise is the result: you declare a type, and the run returns an instance of it or fails. The parent root lists three ways to get there ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, Reading, section 4). The difference between them is where the schema travels, and so who is responsible for the reply fitting it:

  • Prompted: the schema is pasted into the instructions as text. The model may follow it. The library parses the reply and validates it.
  • Tool-forced: the schema becomes the parameters of a tool (Pydantic AI's final_result, ADK's set_model_response, Claude Code's StructuredOutput), and the request says a tool call is required. Tool-calling models are trained to fill tool arguments.
  • Native: the schema goes in a separate request field, response_format on OpenAI-style servers or output_config.format on Anthropic's API, and the server constrains decoding: at every step it masks the tokens that would break the schema, so the reply is valid by construction. Anthropic's docs describe "constrained sampling with compiled grammar artifacts", with extra latency the first time a schema is used and grammars "cached for 24 hours from last use" ({{structured outputs|https://platform.claude.com/docs/en/build-with-claude/structured-outputs}}, read 6 Oct 2026).

The catch in the native route is in its first word: it relies on the server. The local server used on these pages, mlx_lm.server 0.32.0, reads a fixed list of request fields (server.py, lines 1159 to 1194 and 1614) and response_format and tool_choice are not among them: both are silently ignored. Many self-hosted servers differ here ({{vLLM|https://docs.vllm.ai/en/latest/features/structured_outputs.html}}, {{SGLang|https://docs.sglang.ai/advanced_features/structured_outputs.html}} and {{llama.cpp|https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md}} document grammar-constrained JSON), so this is a property of the server, not of local models.
