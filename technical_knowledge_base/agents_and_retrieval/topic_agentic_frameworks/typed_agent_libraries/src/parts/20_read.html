The page in one screen

An agent loop is a program that sends a model a conversation plus a list of tools, runs whatever tool call comes back, appends the result, and asks again until the model stops calling tools. The parent topic writes that loop by hand and then in six frameworks ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, tab Same agent, six ways). This page takes the four typed agent libraries from that comparison and goes one level down: libraries whose main promise is that you write ordinary typed Python functions and classes, and the library turns them into tool schemas on the way out and into validated objects on the way back.

The three findings worth remembering

1. The schema has to reach the model. The three "native" routes (Pydantic AI's NativeOutput, the Agents SDK's output_type, ADK's output_schema) put the schema in a request field the local server never reads: The same model given the schema as a tool or as text: Section 2.

2. Valid is not right. Constrained decoding made every reply parse (), yet the content checks still miss: A validator that can see the inputs catches what a schema cannot (section 3).

3. Every mechanism is a tool call. Pydantic AI's result (final_result), ADK's (set_model_response), Claude Code's (StructuredOutput), the Agents SDK's handoffs (transfer_to_fixer) and ADK's transfers (transfer_to_agent) are all ordinary tools on the wire. The libraries differ in what they wrap around those calls: validation and retries, guardrails, an executor, sessions and state.
