5. smolagents: the action is a program

The idea. The other three libraries let the model emit one JSON tool call per action. Hugging Face's smolagents makes its main agent, CodeAgent, emit Python instead: the tools are exposed as Python functions, the model writes a short program that calls them (with loops, variables and arithmetic), the library executes it, and the printed output comes back as the observation. The argument is from the CodeAct paper, which reports "up to 20% higher success rate" for code actions than for JSON or text actions across 17 models ({{Wang et al., 2024|https://arxiv.org/abs/2402.01030}}). A ToolCallingAgent with ordinary JSON tool calls exists too.

How the loop works, and where it stops the model

Each step the model writes a "Thought:" and a code block between <code> and </code> (the default tags). The request carries stop sequences "Observation:", "Calling tools:" and the closing tag (agents.py), so generation ends right after the code: the model cannot write its own "Observation:" and invent the result, which is the action-boundary failure the harness pages recorded ({{Other coding harnesses|n:3c65c17b0d0d819fa3cefdcd2ccff2f7}}, section 1). The run ends when the code calls final_answer(value), or after max_steps=20. There is no output schema: final_answer takes any object, and final_answer_checks (a list of functions that may reject it) is the hook for validation.

The local executor is a rule set, not a sandbox

By default the code runs in LocalPythonExecutor, an interpreter written in Python that walks the program's syntax tree and refuses what its rules do not allow: imports outside an allow-list (eleven standard modules by default: collections, datetime, itertools, math, queue, random, re, stat, statistics, time, unicodedata; utils.py, line 49), builtins it does not expose, access to double-underscore attributes, and loops past a cap. Its own docstring says: "It is not a security sandbox: for isolated execution of untrusted code, use a remote executor" (local_python_executor.py, line 1688). What the parent's runs found

On the running example with the local 4B model, smolagents fixed 0 of 8 runs, with code actions and with JSON tool calls ({{Same agent, six ways|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}). Two causes are in the source: the CodeAgent's own system prompt made its first request 2,231 tokens against 385 to 507 for the others, and past tool calls go back into the history as plain text, "Calling tools:\n" + str([...]) (memory.py, line 106), rather than as native tool-call messages, so a small model imitates the text and the parser rejects it. A strong model copes; a small local one does not. Option use_structured_outputs_internally=True asks the provider to constrain each step to a JSON object holding the thought and the code, which helps only where the server enforces response formats (section 2 shows the local server here does not).
