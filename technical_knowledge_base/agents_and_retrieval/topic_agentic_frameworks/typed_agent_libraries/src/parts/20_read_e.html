5. Handoffs and transfers are tools

A handoff passes the whole conversation to another agent, which then owns it. Neither library adds new machinery for it. In the Agents SDK each agent in handoffs=[...] becomes a tool named transfer_to_ plus the agent's name, described as "Handoff to the name agent to handle the request." plus its handoff_description (handoffs/__init__.py, line 214); its output is {"assistant": "fixer"}, and the next request goes out with the new agent's instructions and tools and, by default, "the entire previous conversation history" ({{handoffs docs|https://openai.github.io/openai-agents-python/handoffs/}}). In ADK an agent with sub_agents gets one transfer_to_agent(agent_name, transfer_reason) tool whose agent_name is an enum of the valid names, so the model cannot invent one (tools/transfer_to_agent_tool.py): one tool instead of one per target.

Fig. 4 replays the recorded run, request by request, on the running example (local model, greedy MEASURED): a triage agent with two handoffs (a fixer with the four tools, an explainer with read-only tools), or ADK's coordinator with the same two as sub_agents.

  1. Request 1: the triage agent speaks. It is offered only two tools, transfer_to_fixer and transfer_to_explainer; the system and user messages go to the model.
  2. The model calls transfer_to_fixer({}). To the model a handoff is one more function; the tool's output is {"assistant": "fixer"}.
  3. The speaker changes and the history comes along. Request 2 carries the fixer's instructions and tools with all 4 messages so far (system, user, the transfer call, its result).
  4. The fixer works. Requests 2 to 5 call list_files, read_file twice and edit_file; each round adds two messages to the history the model is sent.
  5. A reply with no tool call ends the run. Request 6 is text: last agent fixer, 6 requests (the sampled run took 6 as well), tests still fail.
  1. Request 1: the coordinator speaks. Its first request offered only transfer_to_agent, whose agent_name is an enum of the valid sub-agent names.
  2. The model calls transfer_to_agent({"agent_name": "fixer"}). One tool for every target instead of one tool per target.
  3. The fixer takes over. Later requests carried the fixer's instructions and tools (and transfer_to_agent, so it could pass the conversation on again), with the history so far.
  4. The fixer works. Requests 2 to 5 call list_files, read_file twice and edit_file, the history growing two messages a round.
  5. A reply with no function call ends the run. Request 6 is text; 6 requests, tests still fail.

Two source details matter once a reply can hand off to more than one agent: if the model calls several handoff tools in one reply, only the first runs and the others get "Multiple handoffs detected, ignoring this one." (run_internal/turn_resolution.py); an input_filter can cut the history, and the opt-in nest_handoff_history (off by default, "Opt-in beta") summarises it, with the warning that "Nesting does not redact sensitive data" (run_config.py, line 378). What handing off costs against calling an agent as a tool (a two-problem message lost its second problem after a handoff) is measured in section 6 of {{Multi-agent patterns|n:3c65c17b0d0d8194a306c37803387bf3}}, which owns when several agents help.
