7. The role-based contrast: CrewAI and Microsoft Agent Framework

The four libraries above ask you for functions and types. The role-based school asks for characters: CrewAI agents need a role, a goal and a backstory, tasks are assigned to them, and a sequential or hierarchical process runs the crew, with event-driven Flows for fixed pipelines ({{CrewAI docs|https://docs.crewai.com/}}; crewai 1.15.23 on PyPI, 28 Sep 2026). The library writes the prompts from those fields. Microsoft Agent Framework (agent-framework 1.20.0 on PyPI, 2 Oct 2026) is "the next generation of both Semantic Kernel and AutoGen", with agents, typed graph workflows and checkpointing ({{Microsoft Learn|https://learn.microsoft.com/en-us/agent-framework/overview/}}). The difference that matters for this page: in a role-based library the prompt is generated from a persona, so the typed parts (tools, outputs) are a smaller share of what decides behaviour. The parent root compares the schools ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, Reading, section 2); neither was run here.

8. Choosing between them

Pydantic AI

When the result is data another program consumes and you want the type checker, validators and retries on your side. Model-agnostic, explicit history, the most control over output. Bring your own persistence.

OpenAI Agents SDK

When the shape is a few specialised agents that pass a conversation along, with guardrails, on OpenAI or any Chat Completions server. Decide about tracing first; it is on by default.

smolagents

When the work is computation over tool results (loops, arithmetic, many small calls) and the model is strong. Run the code in a remote executor. Avoid it with small local models.

Google ADK

When you want a runtime rather than a loop: sessions with scoped state, workflow agents, A2A and a deployment path, especially on Google Cloud or with Gemini. Set the call cap.

Or none of them. All four are thin over the same loop. With the same small model, the parent's plain loop fixed the running example in 3 of 4 runs, LangGraph in 4 of 4, Pydantic AI and smolagents in none cleanly, and section 2 shows the library choice mattered less than whether the server honoured the request's structured-output field. A library earns its place when you use what it adds: validation and retries, handoffs and guardrails, an executor, sessions and state. If you use none of that, the loop you can read is the better choice (the 12-factor argument on the root, "Own your control flow").

9. Common mistakes and interview questions

Trusting NativeOutput or output_type on a server you have not checked
The schema moves from the prompt into response_format. If the server drops that field (the local mlx-lm server here does, silently), the model never sees the schema. Section 2 measured it. Test once with a schema the model could not guess.
Validating shape and calling it done
A valid Triage can name a function that does not exist. Content checks with access to the real inputs (Pydantic AI's output validators with deps, smolagents' final_answer_checks) catch what a schema cannot.
Leaving retries at the default
Pydantic AI gives one output retry, the Agents SDK none. One retry is too few for a small model and silent retries hide drift: set the budget and count retries in your metrics.
Treating a parallel guardrail as a gate
The agent's first call runs while the check runs. Anything with side effects needs a blocking guardrail or a tool guardrail.
Shipping traces you did not mean to
The Agents SDK exports traces with inputs and outputs by default when an OpenAI key is present. Decide per deployment.
Authorising os in the smolagents local executor
That turns the rule set into the host. Use a remote executor for anything you would not run yourself.
Exposing an ADK agent over A2A without reading its card
The generated card lists every tool by name and description.

Interview questions

Name three ways to get structured output from a model and their guarantees.
Prompted (schema in the instructions, parse the text: no guarantee), tool-forced (the schema as a tool's parameters, the model must call it: trained behaviour, validate and retry), native constrained decoding (the server masks tokens that would break the schema: valid by construction, content still unchecked). Constrained decoding needs the server to support it.
How does a handoff differ from calling an agent as a tool?
A handoff transfers the conversation: the new agent replies to the user and owns the rest of the run. An agent as a tool runs a sub-agent on a sub-task and returns its result to the caller, which stays in charge. In the Agents SDK both are tools on the wire; the difference is what happens after the call.
Why does the OpenAI Agents SDK mark a parameter with a default as required?
Strict schemas need every property in required and additionalProperties: false; strictness lets the provider constrain the arguments. The default stays in Python and the model always sends a value.
Why are code actions risky and what do you do about it?
The model's program runs with your process's rights unless isolated. An interpreter with allow-lists reduces mistakes but is not a boundary; run the code in a container or a remote sandbox with no secrets and limited network.
Where does an ADK agent keep data that another agent in a SequentialAgent needs?
In session state, written by output_key (or a tool's state_delta) and read with {key} in the next agent's instruction; the change is recorded on an event.
