The ownership split, in one paragraph
What the model sees in one call (budgets, caching, compaction, memory files, subagents) is context engineering and belongs to the harnesses topic. A memory layer is a separate store a framework plugs in, with its own write and read policy, and belongs here. Retrieval is the read path both reuse. The three meet in one design question: who curates, and when: the harness at write time (Mem0, Graphiti), the model in the hot path (Letta, the memory tool), or a curator at read time ({{Just-in-Time Memory|n:3e95c17b0d0d818f89b3f066f816727b}}).

Checking a memory layer before you trust it

  1. Write a question set like section 5's on your own data, with all five abilities, and keep the full-history baseline in it while history fits.
  2. Measure evidence before answers. Log what the memory put in the prompt; if the evidence is not there, no reader model will fix it.
  3. Read the store after every session for a while: duplicates, wrong dates and wrongly closed facts are visible long before they cause a wrong answer.
  4. Log write failures loudly. An extraction that fails to parse must be an alert, not an empty list.
  5. Swap the writer model and rerun: here the same library with a 4B writer lost episodes the Haiku writer did not.

Common mistakes

"Memory layer X scores 90% on LOCOMO, so it is the best."
Ask who ran it, with which answer model, at what retrieval budget, on which version, and against full context. On the {{Published numbers|#t-bench}} tab the same product spans 58.44% to 80.32% on the same benchmark.
"Mem0 updates and deletes outdated memories."
The 2025 paper and Mem0 1.x did. The open-source library since 2.0.0 is ADD-only; its docs: "Nothing is overwritten or deleted." Old and new versions are both stored and the retrieval ranking has to sort them out.
"A temporal graph knows when facts changed."
It knows when a model said they changed. Invalidation is an LLM judgement per new fact; here it closed a past measurement because a later one existed, and could never close facts it had failed to date.
"Give the agent a search tool and it will remember."
Only if it decides to search. The small model here mostly answered from what was already in its prompt; the sibling page {{Personal agents|n:3c75c17b0d0d81bf9462fbeb09593e1c}} measured Haiku never searching until one sentence of instruction told it to.
"Replaying old chat logs into a memory layer recreates the memory."
Not with dates: the Mem0 open-source add() has no timestamp ("Platform-only"), so every replayed message is dated today and every "yesterday" resolves to the wrong day. Graphiti takes a reference_time per episode; Letta stamps messages when they arrive.
"Memory saves tokens."
Per answer, yes; per conversation, writing costs model calls (one per session for Mem0, several per episode for Graphiti). Below tens of thousands of tokens of history, pasting it all is cheaper and more accurate.

Interview questions

Design memory for a support assistant used by a million users.
Scope memories per user (and per account); write in the background after each conversation, not in the hot path; store short facts with source message ids and dates; read with hybrid search (embeddings plus BM25) and a small top-k; keep raw transcripts for audit and re-extraction; resolve conflicts explicitly (latest wins with history kept, or validity windows); evaluate with a LongMemEval-style set including abstention and knowledge updates; let users see and delete what is stored.
The user says "I moved from Austin to Seattle". What should each design store?
Paper-style fact memory: update "lives in Austin" to "lives in Seattle" (history lost unless logged). Mem0 2.x: add "moved to Seattle" beside "lives in Austin" and rely on ranking. Temporal graph: close the LIVES_IN Austin edge at the move date, open LIVES_IN Seattle. Self-managed: the model edits its core block if it notices. Only the graph answers "where did I live in March" directly.
How do you know whether a wrong answer is a memory failure or a model failure?
Check whether the evidence reached the prompt. If not, the write or read policy failed (never written, written wrongly, or not retrieved); if it did, the reader failed. This page's evidence column separates the two without any model.
Why can adding memory make an assistant worse?
Stale or duplicated facts outrank current ones, wrong dates get repeated with confidence, and retrieved snippets crowd out the instruction. Without a "say you don't know" rule, a memory layer also turns abstention questions into confident wrong answers built from near misses.
What is bi-temporal modelling, and why does an agent memory need it?
Two time axes per fact: when it was true in the world (valid_at, invalid_at) and when the system learnt or retired it (created_at, expired_at). An agent needs the first to answer "what was true then" and the second to audit and replay what it knew when it acted.
