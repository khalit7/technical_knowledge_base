2. Fact memory: Mem0, the paper and the library

The idea. Store what was learnt, not what was said: a model reads the conversation and writes short, self-contained sentences ("Sam's tests run with python3 -m pytest -q"), each embedded as a vector. Before an answer, the question is embedded too and the closest sentences are pasted into the prompt. Reading is one search, a few milliseconds, and the prompt grows by a few hundred tokens instead of the whole history.

The hard part is change. When Sam says "we moved to pytest", the old sentence "tests run with test_core.py" is now wrong. Mem0's answer changed in 2026:

The paper (Apr 2025) and Mem0 1.x

Two phases (Chhikara et al., {{arXiv 2504.19413|https://arxiv.org/abs/2504.19413}}, section 2.1). Extraction: a model sees the new message pair, a running summary and the last m = 10 messages, and lists candidate facts. Update: for each candidate, the s = 10 most similar stored memories are retrieved and a model picks one operation by tool call: ADD, UPDATE ("augmentation of existing memories with complementary information"), DELETE ("removal of memories contradicted by new information") or NOOP. All with GPT-4o-mini. The store holds the current truth; the past is gone (a history table logs the edits).

The library since v2.0.0 (16 Apr 2026), run here at 2.2.1

"Single-pass, ADD-only": one call per add(), "No separate UPDATE/DELETE pass ... Hash-based deduplication prevents exact duplicates; ranking at retrieval time handles the rest" ({{v2.0.0 release|https://github.com/mem0ai/mem0/releases/tag/v2.0.0}}). The call sees the 10 stored memories most similar to the new messages (their ids replaced by small integers, "anti-hallucination"), the last 10 messages of the scope, and an observation date ({{main.py, _add_to_vector_store|m0:mem0/memory/main.py#L881-L1060}}). Old and new facts both stay; the docs: "Nothing is overwritten or deleted" ({{memory evaluation|https://docs.mem0.ai/core-concepts/memory-evaluation}}).

Reading in 2.2.1 is hybrid ({{_search_vector_store|m0:mem0/memory/main.py#L1642-L1745}}, {{score_and_rank|m0:mem0/utils/scoring.py#L60-L140}}): a vector search over-fetches max(4 × k, 60) candidates; a BM25 keyword search runs on spaCy-lemmatised text; named entities in the question boost memories linked to the same entity; candidates whose cosine similarity is under 0.1 are dropped, and the rest are ranked by

score = (cos + bm25̂ + entity boost) / (1 + 1bm25 + 0.5entity)
cos
cosine similarity of question and memory embeddings (here bge-small-en-v1.5, 384 dimensions)
bm25̂
BM25 score squashed into 0 to 1 by a sigmoid whose midpoint depends on query length
divisor
1 plus 1 if any BM25 hit, plus the entity weight (0.5) if any entity hit, so a memory found by all three signals can reach 1.0

Two things the open-source library cannot do that its paper and platform can
Dates. add() takes a timestamp argument documented as "Platform-only temporal parameter. Not supported in OSS." The extraction prompt's "Observation Date", the anchor for "yesterday" and "last week", is therefore the machine's current date. In live use that is right; when you import an old history it is wrong for every message. This run simulated live use by setting the prompt's date to each session's date (the patch is in src/code/run_mem0.py). Prompt size. The extraction system prompt alone is tokens (counted with the Qwen3 tokenizer), larger than the shared local model server's safe limit, so the library's writes here used Haiku; the local 4B model ran the paper loop instead.
