3. Temporal graph: Zep and Graphiti

The idea. Facts are relations between things: Sam uses OpenRouter, Priya manages Sam. Store them as a graph whose nodes are entities (Sam, OpenRouter, Priya) and whose edges are facts, each carrying the time it became true and, once something contradicts it, the time it stopped. Nothing is deleted: "LiteLLM is the gateway" stays in the graph, closed on 15 September, so the graph can answer both "what now" and "what before".

Who is who. Zep (the company) published the design (Rasmussen et al., {{arXiv 2501.13956|https://arxiv.org/abs/2501.13956}}, 20 Jan 2025); its open-source engine is Graphiti (Apache-2.0, 31,489 GitHub stars on 6 Oct 2026). Zep stopped maintaining its self-hosted Community Edition on 2 April 2025 ({{announcement|https://blog.getzep.com/announcing-a-new-direction-for-zeps-open-source-strategy/}}); Zep Cloud now runs on a proprietary engine. Graphiti 0.30.2 needs a graph database: Neo4j, FalkorDB, Amazon Neptune, or the embedded Kuzu, which is deprecated ("the upstream Kuzu project is no longer maintained") and here failed on the first episode ('KuzuDriver' object has no attribute '_database'); this run used FalkorDB 4.22 in Docker.

Four timestamps per fact

The paper's model is bi-temporal: "t'_created and t'_expired ... monitor when facts are created or invalidated in the system, while t_valid and t_invalid track the temporal range during which facts held true." In Graphiti's edge they are created_at, expired_at, valid_at and invalid_at. The first pair is the database's clock; the second is the world's. In this replay they differ visibly: every closed edge has expired_at 6 October 2026 (the day the run happened) but invalid_at in September (the session date that contradicted it), which is exactly the distinction the design exists for.

Invalidation is a model's judgement. For each new edge, Graphiti finds similar existing edges and asks a model, in one prompt, which are duplicates and which the new fact contradicts ({{prompts/dedupe_edges.py|gr:graphiti_core/prompts/dedupe_edges.py#L43-L100}}). Code then closes each contradicted edge by setting its invalid_at to the new edge's valid_at, provided the old edge started earlier ({{resolve_edge_contradictions|gr:graphiti_core/utils/maintenance/edge_operations.py#L538-L573}}). An edge with no valid_at (the model could not date it) is never closed by that rule.

Reading. Graphiti.search combines cosine similarity over edge embeddings with BM25 full-text search and merges the two lists by reciprocal rank fusion; the paper adds breadth-first graph search and rerankers (maximal marginal relevance, distance from a centre node, episode mentions, a cross-encoder). Only edges come back, so a detail that ended up in an entity's summary rather than on an edge is invisible to this search.
