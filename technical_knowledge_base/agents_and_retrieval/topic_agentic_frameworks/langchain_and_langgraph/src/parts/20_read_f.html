10. The store: memory across threads

A checkpoint belongs to one thread: a new conversation starts empty. What should carry over (a user's preferences, facts about a project) goes in a store: "LangGraph stores provide cross-thread long-term memory, complementing per-thread checkpointer persistence" ({{docs|https://docs.langchain.com/oss/python/langgraph/stores}}). A store is a key-value database whose keys live in namespaces, tuples such as ("users", user_id, "prefs"); you pass it to compile(store=...) and a node receives it as an argument. 11. Deployment: LangSmith Deployment and the Agent Server

Everything above runs in your own process with your own database, and you own the parts a checkpointer does not do: a process to run each graph, a queue, something that notices a dead run and resumes it, and an HTTP API. LangChain sells those as a service. Names changed in October 2025: "LangGraph Platform is now LangSmith Deployment and LangGraph Studio is now LangSmith Studio" ({{LangSmith changelog, 13 to 17 Oct 2025|https://docs.langchain.com/langsmith/changelog}}); the server formerly called LangGraph Server is now the Agent Server, "built on the concept of assistants" with "built-in persistence and a task queue" ({{docs|https://docs.langchain.com/langsmith/agent-server}}), and "you do not need to implement or configure checkpointers or stores manually" when using it. Studio is a visual debugger over a running graph's threads, checkpoints and interrupts. Prices change; on 6 October 2026 the pricing page listed a Plus plan at $39 per seat per month with one small deployment included, and usage-metered compute beyond it ({{pricing|https://www.langchain.com/pricing}}; read through a summarising fetch, so treat the figures as indicative). Hosted agent runtimes in general (Claude Managed Agents, the OpenAI Agents API) are compared on the parent's {{Production stack|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab.

12. The criticisms, checked, and when LangGraph earns its keep

The criticism of LangChain is old, specific and mostly about the pre-1.0 package:

  • Abstraction tax. Max Woolf, 14 Jul 2023: "The problem with LangChain is that it makes simple things relatively complex" ({{minimaxir.com|https://minimaxir.com/2023/07/langchain-problem/}}). Octomind (Fabian Both; the page is undated, the first archived copy is from 14 Jun 2024; the site is gone): "We used LangChain in production for over 12 months, starting in early 2023 then removing it in 2024", and "in hindsight, we would've been better off long-term without a framework" ({{archived copy|https://web.archive.org/web/20240614031027/https://www.octomind.dev/blog/why-we-no-longer-use-langchain-for-building-our-ai-agents}}). Both target prompt templates, output parsers and LCEL chains, which 1.0 moved to langchain-classic; neither discusses LangGraph.
  • Hidden prompts. Hamel Husain, 14 Feb 2024: the prompts a framework sends are "the fastest way to understand how they work" ({{hamel.dev|https://hamel.dev/blog/posts/prompt/}}). Anthropic, 19 Dec 2024: frameworks "often create extra layers of abstraction that can obscure the underlying prompts and responses, making them harder to debug" ({{Building effective agents|https://www.anthropic.com/engineering/building-effective-agents}}). The first version of that page named "LangGraph from LangChain" first among the frameworks it meant ({{archived 20 Dec 2024|https://web.archive.org/web/20241220084614/https://www.anthropic.com/research/building-effective-agents}}); the current one names others. The cure is unchanged: log the literal request, as section 9 does.
  • Graph ceremony. For a linear tool loop a schema, nodes, edges and compile() are overhead over a loop you can write in thirty lines; the parent's {{Same agent, six ways|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab shows the same agent in both styles.
  • Churn. The 0.x years broke APIs often. Since October 2025 the promise is "no breaking changes until 2.0", and 1.0 is a long-term-support line until 2.0 ships ({{release policy|https://docs.langchain.com/oss/python/release-policy}}); a year in, no 2.x exists, while defaults still move inside 1.x (the recursion limit went from 25 to 10,000 in 1.1.0, section 3).

Two critiques this page adds from its own runs: the reducer error leaves a thread unreadable until repaired (section 3), and resuming re-executes the interrupted node and its wrapper (sections 6 and 8), which is correct but surprises everyone once.

When LangGraph earns its keep
  • Runs long enough that a crash or deploy mid-run must not lose paid work (pending writes saved the finished diagnosis in section 5).
  • Approvals that wait hours or days: interrupt plus checkpoint, resumable from any process.
  • Real branching: parallel fan-out with merge rules, wait-for-all joins, loops with limits, map-reduce over a list known only at run time. If you have hand-built a DAG engine over model calls, this is that engine plus persistence, streaming and rewind.
  • You want inspection: every intermediate state is a row you can read, diff and fork.

If none applies, a plain loop over provider calls behind a gateway such as {{LiteLLM|n:3f15c17b0d0d81e4a964c129a3e520ae}}, with {{tracing|n:3c65c17b0d0d81fe82c0c6e9360afec4}}, is the simpler system; and if you only need a typed agent loop, the {{typed agent libraries|n:3f15c17b0d0d819fba89f9ec88feb859}} are lighter.
