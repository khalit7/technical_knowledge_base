10. The store: memory across threads

A checkpoint belongs to one thread: a new conversation starts empty. What should carry over (a user's preferences, facts about a project) goes in a store: "LangGraph stores provide cross-thread long-term memory, complementing per-thread checkpointer persistence" ({{docs|https://docs.langchain.com/oss/python/langgraph/stores}}). A store is a key-value database whose keys live in namespaces, tuples such as ("users", user_id, "prefs"); pass it to compile(store=...) and a node receives it as an argument. Backends: InMemoryStore for tests; PostgresStore, MongoDBStore, RedisStore or UpstashStore for production; with an index configuration (an embedding function, its dimensions, the fields to embed) store.search(namespace, query=...) does semantic search (docs; not run here, it needs an embedding model). A store keeps exactly what your node writes. What to remember, what to do when a new fact contradicts an old one, and when to retrieve are a design problem of their own, which memory-layer libraries (Mem0, Zep's Graphiti, Letta) hand to a model; they are compared in {{Context engineering|n:3f15c17b0d0d8170a200ce4476385ff5}}, section 8 (agent memory), which absorbed the old Agent memory layers page.

11. Deployment: the Agent Server

Everything above runs in your process with your database, and you own what a checkpointer does not do: a process per graph, a queue, something that notices a dead run and resumes it, an HTTP API. LangChain sells those as LangSmith Deployment (formerly LangGraph Platform). Its server, the Agent Server (formerly LangGraph Server), is "built on the concept of assistants" with "built-in persistence and a task queue", and with it "you do not need to implement or configure checkpointers or stores manually" ({{docs|https://docs.langchain.com/langsmith/agent-server}}). LangSmith Studio (formerly LangGraph Studio) is a visual debugger over a running graph's threads, checkpoints and interrupts. Plans and prices are in the dated table below. Hosted agent runtimes in general (Claude Managed Agents, the OpenAI Agents API) are compared on the parent's {{Production stack|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab.

12. When a graph beats a plain loop, and the criticisms checked

The {{root's|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} thirty-line loop and a LangGraph graph do the same work while nothing goes wrong. The difference is what you would otherwise have to build:

If none applies, a plain loop over provider calls behind a gateway such as LiteLLM ({{Gateways and routing|n:3f15c17b0d0d81e4a964c129a3e520ae}}), with tracing ({{LLM observability|n:3c65c17b0d0d81fe82c0c6e9360afec4}}), is the simpler system; if you only need a typed agent loop, the four libraries in {{Typed agent libraries|n:3f15c17b0d0d819fba89f9ec88feb859}} are lighter; for a finished harness (tools, permissions, hooks, sessions) rather than a graph you assemble, the {{Claude Agent SDK|n:3c65c17b0d0d813b960fd9857118fbd2}} runs Claude Code's own loop as a library.

The criticisms are old, specific and mostly about the pre-1.0 package:

  • Abstraction tax. Max Woolf, 14 Jul 2023: "The problem with LangChain is that it makes simple things relatively complex" ({{minimaxir.com|https://minimaxir.com/2023/07/langchain-problem/}}). Octomind (Fabian Both; undated, first archived 14 Jun 2024; the site is gone): "We used LangChain in production for over 12 months, starting in early 2023 then removing it in 2024", and "in hindsight, we would've been better off long-term without a framework" ({{archived copy|https://web.archive.org/web/20240614031027/https://www.octomind.dev/blog/why-we-no-longer-use-langchain-for-building-our-ai-agents}}). Both target prompt templates, output parsers and LCEL chains, which 1.0 moved to langchain-classic; neither discusses LangGraph. Section 1 measures what is left of the tax: about 0.2 ms and four extra stack frames per call.
  • Hidden prompts. Hamel Husain, 14 Feb 2024: the prompts a framework sends are "the fastest way to understand how they work" ({{hamel.dev|https://hamel.dev/blog/posts/prompt/}}). Anthropic, 19 Dec 2024: frameworks "often create extra layers of abstraction that can obscure the underlying prompts and responses, making them harder to debug" ({{Building effective agents|https://www.anthropic.com/engineering/building-effective-agents}}); its first version named "LangGraph from LangChain" first among the frameworks it meant ({{archived 20 Dec 2024|https://web.archive.org/web/20241220084614/https://www.anthropic.com/research/building-effective-agents}}), the current one names others. The cure is unchanged: log the literal request, as section 9 does.
  • Graph ceremony. For a linear tool loop, a schema, nodes, edges and compile() are overhead; the parent's {{Same agent, six ways|n:3c65c17b0d0d81ab8432c54d65b7f8c7}} tab shows the same agent in both styles.
  • Churn. The 0.x years broke APIs often. Since October 2025 the promise is "no breaking changes until 2.0", and 1.0 is a long-term-support line until 2.0 ships ({{release policy|https://docs.langchain.com/oss/python/release-policy}}); a year in no 2.x exists, while defaults still move inside 1.x (the recursion limit, section 3).
  • Two this page adds from its runs: the reducer error leaves a thread unreadable until repaired (section 3), and resuming re-executes the interrupted node and its wrapper (sections 6 and 8), which is correct but surprises everyone once.
