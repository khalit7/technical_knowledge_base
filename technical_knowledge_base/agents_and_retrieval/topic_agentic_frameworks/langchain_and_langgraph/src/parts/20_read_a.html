The idea in one picture

LangGraph runs your program as rounds of parallel steps over one shared state and saves a checkpoint of that state at the barrier after every round; surviving a crash, waiting days for a person and rewinding are all that checkpoint. LangChain 1.x is the thin layer above: one interface for models, tools and retrievers, and a ready agent loop that compiles to a LangGraph graph.

Everything durable happens at the barrier between super-steps

Read top to bottom. LangChain's create_agent builds a StateGraph; compile() turns any graph into a Pregel runtime that loops plan (which nodes are triggered), execute (all of them in parallel, each against the state as of the step start) and update (merge their writes through the reducers). Each finished task's output is saved as a pending write, and each update saves a checkpoint under the run's thread_id. Resume, whether after a SIGKILL or after a person answers an interrupt(), is just loading the last checkpoint and planning again.

You need the agent loop itself, written by hand in {{Building a harness|n:3c65c17b0d0d817ca14fc32338707c2f}}, and the root's workflows against agents ({{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, Reading). Nothing else.

    1. LangChain 1.x: one interface for every building block

    Since 1.0 (October 2025) the langchain package is an agent library, create_agent plus middleware (section 9), built on the interfaces in langchain-core. The pre-1.0 chains, retrievers and indexes moved to langchain-classic; on 1.4.3, import langchain.chains raises ModuleNotFoundError and from langchain_classic.chains import RetrievalQA works MEASURED. LangGraph does not need LangChain at all: its README says it "can be used without LangChain", and every graph in sections 2 to 8 imports only langgraph.

    Everything is a Runnable. A prompt template, a chat model, an output parser, a retriever, a tool, and any chain built from them implement one interface, Runnable: invoke (one input), batch (a list, run concurrently), stream, the async ainvoke, and wrappers such as with_retry and with_fallbacks. LCEL, the LangChain Expression Language (August 2023, "a declarative way to truly compose chains", {{LangChain|https://www.langchain.com/blog/langchain-expression-language}}), is the | operator over Runnables: prompt | model | parser builds a RunnableSequence whose invoke feeds each step's output to the next.
