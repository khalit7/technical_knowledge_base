The idea in one screen

An embedding model is a transformer plus a pooling step that maps any text to one vector of fixed length, trained with a contrastive loss so that a query and the passage that answers it point the same way; which model works for you is decided on your own labelled queries with paired statistics, not by a leaderboard.

The query and the document go through the same model separately and meet only at the cosine

The section that owns each part is marked on the figure. Query: the shortest SciFact test claim; document: its labelled abstract (both real, from section 1's stepper). The document side runs once, at indexing; the query side runs per search.

You need: InfoNCE as a softmax over a line-up of candidates ({{Contrastive and self-supervised learning|n:3c65c17b0d0d811db6a7d02d0ee7215c}}, section "InfoNCE, the workhorse loss"), nDCG@10 and bootstrap intervals ({{Evaluation metrics|n:3c65c17b0d0d81a29acef722e842a29b}}), and the parent {{Topic: rag-and-retrieval|n:3c65c17b0d0d81b89145c37dfe8a3b0b}} for where retrieval sits in a pipeline. The running example: SciFact ({{5,183 scientific abstracts and 300 test claims|n:3c65c17b0d0d81b89145c37dfe8a3b0b}}) and NFCorpus (3,633 medical documents and 323 test queries).

Bi-encoder
query and document encoded separately by one model, compared by one dot product; this page's subject.
Pooling
collapsing the per-token outputs into one vector: the first token (CLS), the mean, or the last token.
In-batch negative
another query's positive in the same training batch, used as a free wrong answer.
Hard, false negative
a mined wrong answer that looks right; one that is in fact relevant but unlabelled.
Temperature τ
divides the cosines before the softmax; 0.05 by default in sentence-transformers.
Asymmetric prompt
a prefix or instruction added to the query side only (or a different one per side).
Matryoshka
training so that the first m numbers of the vector are a usable embedding on their own.
MTEB
the Massive Text Embedding Benchmark: one protocol, many tasks, a leaderboard by the mean.
Paired bootstrap
resampling the same queries for two models to get an interval for their difference.
How to read the numbers
measured here: run on an Apple M1 Pro (16 GB, shared with other jobs) on the running example with a script in this page's src/scripts; relevance numbers (nDCG@10, recall) are deterministic and do not depend on the machine. published: a paper, model card or results repository, with its date. derived: computed from numbers shown, with the formula. nDCG@10 scores how high the relevant documents sit in the top 10 (1 is perfect); recall@100 is the share of relevant documents anywhere in the top 100.

1. One vector per text: a transformer, a pooling step, a normalisation

Why one vector. Relevance belongs to a pair, but a corpus has millions of documents and a query arrives in real time. A bi-encoder computes every document vector once, at indexing; a query then costs one model pass plus dot products. A cross-encoder reads query and document together (more accurate, nothing precomputable), so it can only reorder a short list; it is owned by {{Rerankers and late interaction|n:3f85c17b0d0d813fba53fc883f8a2c8f}}, as is late interaction (ColBERT: one small vector per token). The two steps after the transformer. The transformer returns one vector per token. Pooling keeps one: CLS (the first token; bge-small, gte-modernbert), mean (average of the real tokens, padding ignored; all-MiniLM-L6, e5-small-v2) or last token (Qwen3-Embedding: in a decoder only the last token has seen the whole text). Normalisation divides by the length, so a dot product is a cosine (section 2; gte-modernbert ships without this step). The pooling is fixed by training, written in the model's 1_Pooling/config.json and modules.json: read them before writing your own inference. Step through one real claim:

Two details that bite people who write their own inference: the CLS branch takes the first real token (argmax on the mask), so left padding is handled; the last-token branch finds the last real token from the mask, so a decoder embedder works with either padding side.
