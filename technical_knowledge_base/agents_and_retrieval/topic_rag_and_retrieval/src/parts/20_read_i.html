Common mistakes

Tuning the generator when the evidence never arrived
A better model or prompt moves only g. Check first whether the evidence was in the prompt; if not, nothing downstream can find it. And the reverse: on the measured SciFact run the search was fine and the generator lost 82 of 92 failures (section 6).
Reporting one end-to-end number
It cannot say which stage failed. Report r, p and g, and a confusion of labels: the 1.7 B model's 0 correct CONTRADICT answers were invisible in "51% accuracy".
Assuming hybrid search always helps
Equal-weight RRF lifted models close to BM25 and hurt the two clearly stronger ones (gte-modernbert 0.767 to 0.763, ColBERT-small 0.743 to 0.731). Measure; weight the stronger retriever, with the weight chosen on held-out queries.
Adding a reranker without checking it beats the first stage
The 22 M MiniLM cross-encoder pulls the fused SciFact list from 0.724 to 0.689 at K 100; Qwen3-Reranker lifts it to 0.782 at K 20. And no reranker can rescue a passage outside its K.
Comparing chunkers at a fixed number of chunks
Bigger chunks send more text, so they win at a fixed k almost by definition. Compare at an equal token budget, where 512-token windows lose to paragraph-aware chunks (45.9% against 64.5%).
Confusing ANN recall with retrieval recall
An index can return 100% of the exact top 10 while the system finds only 84.5% of the labelled abstracts. Tune the index on the first, judge the system on the second.
Dot product on vectors the model did not normalise; one threshold for every model
gte-modernbert loses 0.027 nDCG@10 on SciFact with a raw dot product. Cosine ranges differ by model (bge-small random pairs near 0.56, MiniLM near 0.10): tune thresholds per model.
Binary quantization without rescoring; truncating a model not trained for it
Binary codes alone keep 67% of Qwen3's exact top 10; rescoring 100 restores 99%. int8 with a float query is nearly free. Halving bge-small's dimensions loses 6%, a quarter 19%.
Filtering after the search, or enforcing access in the prompt
A post-filter at 10% visibility returns 1.73 results of 10; a rule in the system prompt leaked the restricted fact in 17 of 18 answers. Filter inside the search, at retrieval.
Benchmarking a store that never used its index
Qdrant's server scans exactly below its 10,000 KB thresholds; Milvus Lite and Qdrant's local mode always scan. Test at production size, on the server you will run.
Timing stages in isolation
Embedding took 49 ms alone and 428 ms inside the full request on a shared GPU. Time the whole path.
A semantic answer cache on near-duplicate questions
Claims that differ by one word can have opposite answers and higher cosine than paraphrases; 57% of cache hits at 0.95 returned the opposite claim's answer.
Tuning anything on the test set, including the prompt
Fusion weights, rerank depth and the answer prompt are knobs; choose them on a tuning split, report the test once. The first SciFact prompt scored 23 of 188 with gold abstracts; the one chosen on training claims 112.
"Long context killed RAG", "agents are always better", "GraphRAG is better RAG"
Each answers a class of question the pipeline cannot, at a price (section 7). For lookups over a large corpus, hybrid search with a reranker is still the cheapest and best measured.
