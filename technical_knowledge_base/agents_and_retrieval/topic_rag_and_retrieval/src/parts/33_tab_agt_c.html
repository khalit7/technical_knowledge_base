Replay a trajectory: the same question, pipeline against agent

A trajectory is everything an agent did on one question: each thought, each search query, each set of results, the answer. These are the recorded runs, replayed step by step; nothing is re-generated in the page. Switch between the pipeline, the agent loop and decomposition on the same question to see where the evidence comes from, and watch the token counter: every agent step re-sends the whole conversation so far.

Prompt tokens per generator call (light: billed; dark: actually computed, the rest came from the prompt cache)

The questions in the replay are chosen by a fixed rule over the 4B runs, not for a story: the first test question where the agent is right and the pipeline wrong, the first where the reverse happens, a comparison both get right, one where the agent spends all four searches and still fails, one only decomposition gets, and a second agent win. The failures are as instructive as the wins: a loop can search for the wrong entity, repeat a search, or stop early with a plausible guess.

Tokens per step: why agent loops get expensive

A chat model has no memory between calls: each step of the loop sends the system prompt, the question and every earlier thought and observation again. If each step adds about the same number of tokens a, call t carries about t·a tokens and a loop of T calls bills about a·T(T+1)/2: quadratic in the number of steps. A prompt cache (llama.cpp's here; prompt caching at the API providers) stores the attention keys and values of a prefix it has already processed, so only the new tokens are computed; providers bill cached tokens at a discount, not for free. The serving side of this is on {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}.

Measured on the 4B runs: the prompt carried into the loop's calls grows from 172 tokens at the first call to 613, 1,077, 1,565 and 2,047 at the fifth, while the prompt cache keeps the tokens actually computed at each call near 450 to 530 (the new observation plus the model's last step). A question that ends in two calls bills 820 input tokens; one that uses all five bills 5,370, 6.5 times as much. And the long trajectories are the failures: the 29 questions that used all four searches score F1 0.18, against 0.673 for the 112 that stopped after two. Repeating a query (36 questions) or losing the format (3 questions; 17 for the 1.7B) is how a small model wastes its budget. A step cap does not just bound cost; past two or three searches, more steps here mostly meant the model was lost.
