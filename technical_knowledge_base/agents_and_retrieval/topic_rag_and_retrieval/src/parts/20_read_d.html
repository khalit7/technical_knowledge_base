5. Who decides what to read

Everything above is a fixed pipeline: the engineer decided in advance to search once, with the user's words, and to pass the top k on. Naive RAG embeds the question, takes the top k and generates; advanced RAG adds the designer's rewrite, hybrid, filter and rerank stages; agentic retrieval lets the model decide at run time, with search as a tool it may call zero or more times with queries it writes itself (the reason-then-act loop of ReAct; "deep research" products are the same loop with a budget of minutes). Why long context does not replace retrieval: every query pays for every token. With illustrative prices of $3 per million input tokens, $0.30 cached and $15 output, a 1-million-token corpus, a 500-token question and a 500-token answer, RAG with 10 chunks of 400 tokens costs $0.021; the whole corpus in the window $3.009 uncached (143 times) and $0.309 cached (15 times) derived. Prefill alone takes seconds (Qwen3-1.7B needs 9.3 s for 7,611 prompt tokens here). Long context wins for a small corpus read once; retrieval wins on cost, latency, scale beyond the window and per-user access control, and the two compose: retrieve, then read generously. The shape transfers to frontier models (loops pay only when the model can plan searches); the absolute F1 of small local models does not. KV-cache sizing and effective context are {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}}.

6. After launch

Once users arrive the system is judged on what no notebook evaluation measures, and every fix that holds lives in the index and the search, not the prompt. One line each; {{RAG in production|n:3f85c17b0d0d81aa9ba9c0ceac9e28c1}} owns them all.

ConcernThe lesson, measured
FreshnessThe lag from a source change to a searchable chunk is a sum (detect, queue, parse, embed, write, visible), and the slowest term is usually not the one people tune. How documents are chunked decides what a revision costs: on ten revised arXiv papers whose revisions changed 15.0% of the words, fixed 200-word windows re-embedded 75.8% of the words, structure-aware chunks 49.2%.
Model upgradesThe vectors of two models cannot share an index even at the same dimension: halfway through a backfill from MiniLM to bge-small, nDCG@10 falls to 0.374 to 0.379 from 0.645 and 0.713. Build the new index beside the old one, then switch.
Access and tenantsFilter by tenant and permission inside the search (section 1), then check the engine's plans: with prepared statements PostgreSQL reused one generic HNSW plan across users and a user allowed 2.1% of the corpus got 0.96 rows of 10.
LatencyTime the whole request, under the real sharing of hardware: embedding the query took 49 ms alone and 428 ms inside the full request, because three models share one GPU; the whole request 2,981 ms, of which 2,114 ms the generator's first token.
CachesA prompt (prefix) cache is safe and large (4,149 ms for the first call, 73 ms after); a semantic answer cache breaks on near-duplicates with opposite meanings: at a threshold of 0.95, 57% of hits returned the opposite claim's answer.
Cost$0.0012 per query at list prices for a hosted stack (1 million queries a month), generation 62% and reranking 36%: the reranker reads 30 passages where the generator reads 5.
InjectionRetrieved text is read as text: an instruction planted in a public document was followed in 6 of 6 cases with a plain prompt. Defences are {{Agent security|n:3f15c17b0d0d81ad9fb7d1dd74217335}}'s.

7. The tools

A retrieval system is a stack of separate choices: a parser, a framework or your own code to chunk and wire the steps, an embedding model, an ANN index inside a vector store (or a library such as FAISS), a keyword engine, a reranker and an evaluation tool. A vector store wraps an index with storage, metadata and filtering. The {{Tool map|#t-map}} is a dated atlas of each layer (owner, licence, latest release, status, the algorithm it actually runs, when to choose it), a "which store" chooser and a timeline. Its measured lesson: the defaults differ more than the algorithms. Given the same SciFact bge-small vectors and nothing changed, hnswlib (ef 10) returns 0.876 of the exact top 10, FAISS IVF (nprobe 1) 0.420, LanceDB's default IVF_PQ index about 0.59, Chroma 0.996 to 0.998, and Qdrant's local mode and Milvus Lite 1.000 because they never build an index; one knob each recovers nearly everything. Framework defaults bite the same way: LlamaIndex returns 2 chunks unless told otherwise, and LangChain's text splitter cuts 4,000 characters while MiniLM reads only its first 256 tokens.

In one line each: pgvector when the data already lives in PostgreSQL and fits one server; Qdrant, Weaviate or Milvus as dedicated engines with in-graph filtering and built-in hybrid search; Elasticsearch or OpenSearch when BM25 is already there; FAISS as a library for experiments and exact baselines; a managed service when nobody can operate a database. For models, shortlist open ones you can measure locally (Qwen3-Embedding, bge, gte) against hosted ones (OpenAI, Gemini, Voyage, Cohere) on your own golden set; for evaluation, ranx or pytrec_eval for retrieval metrics, and RAGAS, DeepEval or TruLens for judged ones, by way of {{RAG and retrieval evaluation|n:3ef5c17b0d0d8194a914d1843ee26f13}}.
