7. DiskANN and Vamana: the graph on SSD

HNSW wants the full vectors and the links in RAM: hundreds of gigabytes at a billion 128-dimension vectors. DiskANN (Subramanya et al., NeurIPS 2019) keeps only small PQ codes in RAM to steer the walk, and stores on SSD, per node, "its full precision vector x_i followed by the identities of its ≤ R neighbors" (Section 3.2). Each hop is one random SSD read, and the full vector that arrives re-scores the candidate for free. Its headline: a billion SIFT vectors on one workstation with 64 GB of RAM, "> 5000 queries a second with < 3ms mean latency and 95%+ 1-recall@1" on 16 cores (published, authors' runs, 2019).

One hop is one SSD read, if a node fits in a sector

The graph is Vamana: one layer, built in two passes from a random start graph, with one new knob α in its pruning rule RobustPrune: keep the closest remaining candidate p*, drop every p′ with α · d(p*, p′) ≤ d(p, p′), repeat (Algorithm 2). At α = 1 this is HNSW's heuristic; α > 1 prunes less, keeping edges that cut the distance to the query by a factor α per hop: fewer hops, which matters when each hop is an SSD read. Search keeps L candidates and expands until all are expanded (Algorithm 1), fetching the W best at once on SSD (beam width 2 to 8).

The paper's words on α (provenance)

"both HNSW and NSG have no tunable parameter alpha and implicitly use alpha = 1" (Section 2.4); with α > 1 "the distance to the query decrease[s] by a multiplicative factor of α" at each hop.

Not run here: the official DiskANN (its Python wheels are Linux x86_64 and Windows only; the current code is Rust). 8. ScaNN: quantize for ranking, not for reconstruction

PQ's codebooks reconstruct each vector as faithfully as possible, but for inner-product search the error along the vector's own direction matters more: it moves its score for every similar query. Anisotropic vector quantization (Guo et al., ICML 2020), the core of Google's ScaNN, weights that parallel residual by a factor η more (η = 4.125 at threshold T = 0.2) and reports better recall than reconstruction loss at the same bit rate on Glove-1.2M (published, authors' runs). Measured here on SciFact measured here, it did not beat plain reconstruction at equal code size (@@scann_ani_256@@ against @@scann_iso_256@@ at 256 bytes, @@scann_ani_64@@ against @@scann_iso_64@@ at 64), and with reordering both reached the same recall: measure a published trick on your own vectors before paying for it.
