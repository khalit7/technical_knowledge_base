4. Quantization: storing each vector in fewer bytes

IVF reduces how many vectors a query touches; quantization reduces how many bytes each one takes, so more fit in memory and each comparison reads less. A 1,024-dimension float32 vector is 4,096 bytes; at 100 million vectors that is 410 GB before any index. Six ways to store fewer bytes, from gentle to aggressive:

FamilyWhat is stored per vectorbytes (d = 1,024)How distance is computed
float16each number in 16 bits2,048as float32, after conversion

Product quantization (PQ), m sub-vectorsm one-byte ids of learned sub-vector centroidsm (8 to 256)m table look-ups and additions

Product quantization (Jégou, Douze and Schmid, TPAMI 2011), concretely: cut each 1,024-number vector into m = 16 sub-vectors of 64 numbers; for each of the 16 positions learn, with k-means, a codebook of 256 centroids (8 bits); store the vector as 16 bytes, the id of the nearest centroid at each position. The codebooks (256 × d floats in total, 1 MB for d = 1,024) are shared by the whole collection. At query time the query is not quantized: each of its 16 sub-vectors is compared with that position's 256 centroids once, giving a 16 × 256 distance table, and any stored vector's approximate score is the sum of the 16 entries its code picks. Per candidate the work drops from d multiply-adds over 4d bytes to m additions over m bytes. The stepper in section 5 shows the table and one candidate's 16 bytes on a real index.

score(q, x) ≈ ∑j=1..m Tj[ codej(x) ],   Tj[c] = qj · centroidj,c
m
sub-vectors per vector, one byte each
Tj
row j of the m × 256 table, built once per query

Leaving the query unquantized is asymmetric distance computation (ADC), which the paper shows beats quantizing the query too.

Rescoring is not free
It needs the full vectors somewhere: in RAM (then compression saved scan bandwidth, not memory), on SSD, read for the shortlist only (DiskANN's design, section 7), or in object storage. Count it in the memory budget (section 11).

5. IVF-PQ, residuals and rescoring

The classic billion-scale recipe combines both ideas: IVF picks the cells, PQ compresses what is inside them (Jégou et al. call it IVFADC). One refinement: PQ encodes the residual, the vector minus its cell's centroid, which is smaller and so quantizes with less error; for inner product the score is then the query·centroid term plus the table sum. The general shape: candidates cheap, final ranking exact
Every compressed index ends the same way: a cheap approximate stage generates candidates and an exact stage re-ranks a short list. ScaNN calls it "reorder", LanceDB "refine_factor", FAISS "IndexRefine", Qdrant "rescore"; DiskANN reads the full vector from SSD during the walk. It is the cross-encoder-after-retriever pattern one level down ({{Rerankers and late interaction|n:3f85c17b0d0d813fba53fc883f8a2c8f}}).
