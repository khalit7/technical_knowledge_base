The idea in one screen

Exact search reads every stored vector for every query; an index answers the same question by reading less: only a few k-means cells (IVF), only the nodes a graph walk passes (HNSW, Vamana), or everything but in a few bytes each, then a short list rescored exactly (PQ, int8, RaBitQ). What it gives up is recall against exact search, and it pays in memory and build and update cost.

1. The job, and the scorecard

k-nearest-neighbour search (kNN): given a query q and N stored vectors, return the k most similar. With unit-length vectors, cosine, inner product and Euclidean distance rank in the same order (|a − b|2 = 2 − 2 a·b), which is why every index here uses inner product; on unnormalised vectors inner product favours long vectors, so build with the metric the model was trained for. Approximate nearest neighbour search (ANN) accepts some wrong members of the top k for far less work. Its score, ANN recall@k, is the share of the true top k (from exact search on the same vectors) that the index returns, averaged over queries. It is not the parent page's retrieval recall against human labels; it only measures how faithfully the index imitates exact search, and it is always quoted with a cost, because any index is fast at low recall.

Predict: an index that returns 90% of the exact top 10 on SciFact. How much of exact search's nDCG@10 (answer quality against human labels) does it keep?

The neighbours an index misses are usually the borderline ones (ranks 8 to 10), which are rarely the labelled answer. Below about 0.8, quality falls fast.

The last points of recall barely move answer quality; below 0.8 it falls

So chasing ANN recall from 0.99 to 0.999 is usually wasted latency for retrieval-augmented generation, where a reranker and a language model sit downstream; measure relevance on your own labelled queries before buying the last points. The reverse is dangerous: some defaults land far lower (the parent's Tool map: LanceDB's default IVF-PQ 0.59, FAISS IVF at nprobe 1 0.42, SciFact with bge-small). To measure recall yourself: compute a few hundred real queries' exact top k once with a flat scan, and compare every setting against it.
