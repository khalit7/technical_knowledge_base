9. Filtered search: where indexes break

Real queries come with conditions: "chunks of this paper", "documents this user may read", "published this year". A filtered (or hybrid) vector search must return the k nearest vectors among those that pass the filter. Two properties of the filter decide which strategy works:

  • Selectivity: the share of rows that pass. "Own paper" in QASPER keeps @@filt_q_share@@% of the 6,463 chunks (about 23).
  • Correlation with the query: whether the rows that pass are the ones near the query anyway. A question's own paper is correlated (its best chunks are near the question); a randomly chosen other paper of the same size is not; a filter on a different collection than the query came from is anti-correlated.

Four strategies

StrategyHowFails when
Pre-filterfind the passing rows with an ordinary index (B-tree, bitmap), then exact search over themthe filter keeps many rows (then it is a big exact scan)
Post-filterANN search for k′ > k results, drop those that failthe filter is selective or anti-correlated: few of the k′ pass
In-graph filterwalk the graph as usual, but only passing nodes enter the resultsselective filters: the walk must visit most of the graph to collect k passing nodes
Predicate-aware graphwalk only (or mostly) through passing nodes, with extra links so they stay connected: ACORN, Qdrant's payload links, Filtered-DiskANNbuild cost and memory for the extra links

What production systems do
pgvector 0.8 added iterative index scans (keep walking until enough rows pass), measured on the Search and vector databases page. Qdrant plans per segment from a cardinality estimate and uses payload links. Weaviate's default filter strategy is ACORN since v1.34. The NeurIPS'23 Big-ANN filtered track (YFCC 10M CLIP vectors, queries with one or two tags) was won by ParlayANN at 37,902 queries per second at recall@10 ≥ 0.9, more than 11 times the FAISS baseline, using per-tag indexes for common tags and plain lists for rare ones (arXiv 2409.17424, independent benchmark). Multi-tenancy (one index with a tenant filter, or one index per tenant) is this problem with a very selective, perfectly correlated filter; {{RAG in production|n:3f85c17b0d0d81aa9ba9c0ceac9e28c1}} covers it as an access-control question.
