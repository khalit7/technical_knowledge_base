The real database: PostgreSQL row-level security on SciFact

The 5,183 SciFact abstracts with bge-small vectors in pgvector (Docker), one constructed group per abstract, and the 300 test claims asked as each user (top 10). Recall is against the exact top 10 among the abstracts that user may read. measured here, deterministic (no timing).

Modes: unfiltered = the shared index with no access check (what a prompt-level rule would receive); RLS, fresh plan = the policy, planned per query; RLS, reused plan = one connection with the driver's prepared statements, so the plan chosen for the first user (an HNSW scan) serves everyone; RLS, HNSW forced = sequential scans, bitmap scans and sorts disabled, ef_search 40; + relaxed / strict = pgvector 0.8 iterative scans; exact = index scans off; owner = the table owner with RLS enabled but not forced.

Why the reused plan returns too few rows



The HNSW index scan hands rows over in distance order and stops after ef_search (40) candidates; the policy runs as a Filter on each row, and "Rows Removed by Filter" are gone for good. For a user who may read 2% of the rows, about 1 of 40 candidates passes. A fresh plan sees the selective policy and uses the B-tree on the group column, then sorts the passing rows exactly.
