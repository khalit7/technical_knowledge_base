The idea in one screen

After launch a RAG system is judged on what no notebook evaluation measures: how stale the index is, what a user can retrieve that they may not read, how long each request waits and what it costs. The fixes that hold are built into the index and the search, never left to the prompt or the model's good behaviour.

Two paths share one index; the time goes to the generator, the money to the generator and the reranker

The write path turns each changed document into vectors (minutes); the read path answers one question (seconds). The bars are one request on the running example: time measured end to end on this laptop (p50 of 40 claims × 3 passes: embed @@e2e_embed_p50@@ ms, search @@e2e_search_p50@@ ms, rerank 30 candidates @@e2e_rerank_p50@@ ms, generator to first token @@e2e_ttft_p50@@ ms; whole request @@e2e_wall_to_first_token_p50@@ ms), cost from published list prices for an equivalent hosted stack (section 9: @@co_total@@ per query, generation @@co_gen_share@@%, reranking @@co_rerank_share@@%). The access filter sits inside the search (highlighted), the one place no prompt wording or injected text can undo.

Write path, read path
ingestion (detect a change, parse, chunk, embed, index) and answering (embed the question, search, rerank, generate).
Freshness lag
time from a change at the source until the new text is retrievable and the old text is not.
Backfill, dual index
re-embedding the whole corpus with a new model; building it beside the old index and switching atomically.
Tombstone
a deleted vector that a graph index marks and skips instead of removing.
ACL, RLS
access control list (who may read a document); PostgreSQL row-level security, a policy the database adds to every query.
Tenant
a customer whose data must never mix with another's.
TTFT, prefill
time to first token; the model reading the whole prompt before it can write.
Semantic cache
serves the answer of the nearest earlier question above a similarity threshold.
Golden set, power
fixed labelled questions run on every change; the share of runs in which a real change is detected.
Indirect prompt injection
instructions planted in a document that retrieval puts in the model's input.

The numbers. measured here: run for this page on an Apple M1 Pro (10 CPU cores, 16 GB, MPS and Metal for the models, Docker for PostgreSQL) on the topic's running example, SciFact (5,183 scientific abstracts, 300 test claims), with the load average recorded for every timing; relevance and leak counts are deterministic. published: a vendor's or paper's figure, dated. constructed: one small fictional corpus for prompt-rule and planted-instruction tests. Laptop milliseconds do not transfer to a server GPU; the ratios between stages do.
