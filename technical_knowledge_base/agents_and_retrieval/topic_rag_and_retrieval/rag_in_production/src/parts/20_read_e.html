Invalidation. Put the index version into every result and answer key, so a re-index or model switch invalidates everything at once; tag entries with the source document ids, so a change or deletion (section 4) evicts exactly the entries built from it; add a time-to-live so nothing outlives the freshness target. 9. Cost per query

A request pays for each stage it uses; the corpus pays once to be embedded, then for what changes, and for storage every month. Spread the monthly costs over the month's queries:

cost = embed + rerank + generate + (re-embedding + storage) ÷ queries
embed
query tokens × embedding price
rerank
(query tokens × K + K × chunk tokens) × price, Voyage's counting rule (the query is billed once per candidate), or a price per request
generate
uncached input tokens × input price + cached prefix tokens × cached price + output tokens × output price

A worked example (published list prices, table below): 1 million queries a month over 10 million chunks of 256 tokens; text-embedding-3-small (1,536 dimensions); Voyage rerank-3 on K = 30 candidates (@@rerank_tok@@ tokens per query); gpt-5-mini reading k = 5 chunks plus a cached 300-token system prompt (@@gen_in_tok@@ input tokens, 200 output); vectors at Pinecone's storage price (@@co_gb@@ GB of float32 vectors).

The hosted reranker costs more than half as much as the model, because it reads 30 passages where the model reads 5

The vector database's bill is mostly not in this formula (read units, replicas and minimums are billed separately and depend on the store).
