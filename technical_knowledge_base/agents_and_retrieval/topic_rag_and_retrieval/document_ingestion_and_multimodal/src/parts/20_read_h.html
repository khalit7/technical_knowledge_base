Interview rehearsal: ingest 5 million mixed documents for an enterprise assistant with citations and per-user permissions
  1. Intake: a queue of (document id, version, ACL) events from each source; a file hash skips unchanged files.
  2. Triage per page: text-layer quality check; born-digital pages to a fast layout-aware parser on CPU workers, broken or scanned pages to an OCR or VLM-OCR pool on GPUs; spreadsheets read natively, not as images.
  3. Elements, not strings: keep type, page, bounding box and heading path; tables as HTML with a row serialisation; figures with captions, and VLM descriptions for figure-heavy collections.
  4. Chunk by structure; hash chunks; embed only new hashes, keyed by model version; write vectors and metadata (ACL, tenant, dates) to a store that filters inside the search; delete chunks whose hashes vanished in the same transaction.
  5. Optional visual index for slide decks and reports with charts: page-image embeddings (ColPali family) fused with text results, if you can afford about 30 times the vector storage and a multi-vector index.
  6. Evaluate on a golden set built from the original files, per document type; track parse failures, OCR share and pages per second as production metrics; re-parse by parser version when a parser improves.
