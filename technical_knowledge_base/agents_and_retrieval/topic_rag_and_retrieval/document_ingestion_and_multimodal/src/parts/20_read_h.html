7. Metadata: what every chunk must carry

The problem. Retrieval returns chunks, not documents. Once a chunk is separated from its file, three later jobs need facts only the parser had: a citation ("page 4 of the 2020 annual report, section 3.2") the user can check, a filter ("only contracts signed after 2024", "only documents this user may read") applied inside the search, and an update (find and replace every chunk of a file that changed). If the ingestion stage throws these away, nothing downstream can recover them.

How it works. Store each chunk as a record, not as a string. A record that serves all three jobs, with the fields filled from the running example (a paragraph of QASPER paper 1909.00175 parsed by Docling; the field names are this page's choice, not a standard):



Real values from Docling 2.138.0's structured output for this PDF (page, bounding box in PDF points with the origin at the bottom left, heading, element type), hashes computed by src/scripts/make_record.py; the acl value is illustrative. Docling reported this paragraph's heading as "3.1 Datasets and Settings" without its parent "3"; rebuilding the full path from heading numbers is a small post-processing step.


    

  • Source and version: a stable document id, the URL or path, the version or content hash of the whole file and the time it was parsed. Without the version, a citation can point at text that no longer exists.
    • 

  • Location: page number and, where the parser gives it, the bounding box. A viewer can then open the page and highlight the passage, which is how a user checks a citation in seconds.
    • 

  • Structure: the heading path ("4 Experiments > 4.2 Results") and the element type (paragraph, table, caption, list). Prepending the heading path to the text that is embedded is a cheap way to give a chunk its context; the {{retrieval pipeline page|n:3c65c17b0d0d819899fde889e1e8b782}} covers contextual prefixes.
    • 

  • Filters and permissions: dates, authors, document type, tenant and access-control list. These must be indexed fields so the vector store can filter inside the search; {{RAG in production|n:3f85c17b0d0d81aa9ba9c0ceac9e28c1}} shows why enforcing access in the prompt instead leaks.
    • 

  • Ingestion facts: parser name and version, whether OCR was used and its confidence. When a parser upgrade fixes a bug, these say which documents to re-parse.
    • 



Cost. A few hundred bytes per chunk, small next to a 1,024-dimension float32 vector (4,096 bytes). How to check it: sample twenty retrieved chunks and try to open each cited page from the metadata alone.
