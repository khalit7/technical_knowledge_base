2. Rule-based text extraction: geometry and heuristics

How it works. A rule-based extractor reads the text layer and rebuilds words, lines and blocks from coordinates, with no learned model. The steps are the same everywhere, only the rules differ:

  1. Characters to lines: glyphs whose boxes overlap vertically and sit close horizontally join a line; a gap wider than some fraction of a character's width becomes a space.
  2. Lines to blocks: lines close together vertically, and aligned, join a block (a paragraph, a caption, a column fragment).
  3. Blocks to an order: some rule sorts the blocks. This is where multi-column pages fail.

pdfminer.six makes all three explicit as parameters (pdfminer/layout.py, pdfminer.six 20260107, lines 48 to 90, defaults shown):

class LAParams:
    line_overlap = 0.5  # overlap, relative to the smaller char height, to share a line
    char_margin  = 2.0  # chars closer than 2 char widths join the same line
    line_margin  = 0.5  # lines closer than 0.5 line heights join the same box
    word_margin  = 0.1  # a gap over 0.1 char widths inserts a space
    boxes_flow   = 0.5  # -1: order boxes by x only ... +1: by y only; None: no grouping

Comments condensed from the docstring at lines 50 to 74. With boxes_flow set, LTLayoutContainer.analyze (lines 907 to 937) merges the closest pair of boxes again and again into a tree (group_textboxes, line 814) and reads the tree in order; with None it sorts boxes top to bottom, left to right.

The other tools make different choices: pypdf (6.20.1) emits text in content-stream order with line breaks where the text matrix jumps; PyMuPDF (1.28.2) get_text() also keeps stream order unless you pass sort=True, which sorts blocks by their top then left coordinate (PyMuPDF text recipes); pdfplumber (0.11.10) clusters pdfminer's characters into lines with its own tolerances (x_tolerance 3 points by default) and reads them top to bottom across the whole page width; poppler's pdftotext (26.02) runs its own column detection; pymupdf4llm (1.28.2) adds heuristics on top of PyMuPDF for headings (font size), tables (ruling lines) and Markdown output, and on this machine also called RapidOCR on pages it judged to be images.

Cost. Milliseconds per page and no model download, so the right first stage for clean born-digital files. When it matters. Single-column, text-only PDFs with good fonts come out nearly perfect. Two columns, running headers, footnotes, tables and scans are where the rules break, and the next part measures how often.
