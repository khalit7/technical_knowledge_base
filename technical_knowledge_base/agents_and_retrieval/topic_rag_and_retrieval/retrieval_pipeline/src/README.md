# src: The retrieval pipeline: chunking, query rewriting, hybrid search, filtering

Build: `$RAG_SCRATCH/venv/bin/python -I -B exp/make_data.py && python3 build_facts.py && sh build.sh` writes `../index.html` from `parts/`. `make_data.py` turns `out/*.json` (and the root Pipeline lab's `src/pipe/out/*.json`) into `parts/22_rp_data.js` (what the JavaScript reads); `build_facts.py` writes `facts.json`, and numbers in the prose are written `@@key@@` and filled from it by `build.sh`, so prose and data cannot disagree.

Checks: `node check_stages.mjs [shots dir]` (every 3D stage plays when scrolled into view, steps to its last step, one step-list item per step, none moves under reduced motion, flows stop off screen, splits are two columns at 1400 px), `python3 check_data.py` (embedded data equal the recorded files; every fact filled and present; numbers shared with the root lab equal the root's files; root numbers quoted in prose present in its files; privacy and hygiene over the folder), `RAG_SCRATCH=... node check_js.mjs` (the JavaScript chunkers equal the root's Python `chunkers.py` on both workbench papers, 18 configurations), `python3 make_e2e.py` then `node check_page.mjs ../index.html <shots dir>` (every control at 390 px dark and 920 px light; puppeteer from html_utils via createRequire; npm with `NPM_CONFIG_USERCONFIG` pointing at an empty file), and `sh html_utils/checkpage.sh <this page folder>` from the repo root.

Shape: a child page of Topic: rag-and-retrieval (method `.claude/skills/explainer-page/page-kinds/topic-child.md`): Reading in pipeline order (the idea in one screen with the hero, chunking, BM25, learned sparse, fusion, the query, filters, duplicates, the prompt, measuring, depth) and Further reading; the three former lab tabs are inline since 2026-10-24. Prefix `rp` for ids, classes and data keys; storage key `rp-tab`. It is the deep version of the root's Pipeline lab: it reuses that lab's scripts, chunk files, vectors, generator caches and extra reranker scores, and never re-measures a number the root owns (it reproduces the shared ones exactly; `check_data.py` enforces it). Reranking is left to the rerankers child; filtered vector search to the vector indexes child; access control to the production child; the BM25 formula from zero to Search and vector databases (2.1 links its section 4; overlap fix 2026-10-19).
