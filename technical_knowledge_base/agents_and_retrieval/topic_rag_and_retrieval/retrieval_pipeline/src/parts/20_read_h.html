9. Common mistakes

Sizing chunks in characters for a model that counts tokens
LangChain's default is 4,000 characters measured with len; with all-MiniLM-L6-v2 only @@trunc_c4000_minilm_seen@@ of that text reaches the vector, silently. Build the splitter from the embedder's tokenizer (§1.1).
Believing the default separators cut at sentences
They are blank line, newline, space, nothing: a long paragraph is cut between two words. Add ". " or use structure-aware splitting (§1.2, §1.4).
Dropping overlapping neighbours as duplicates
The neighbour is what completes a cut paragraph: dropping it took QASPER from @@ov_plain@@ to @@ov_drop@@ found; merging overlapping spans gave @@ov_merge@@ (§7.3).
Tuning k1, b, the fusion weight or k on the test queries
The best BM25 pair on SciFact test claims claims @@bm_sf_besttest@@; chosen on training claims it scores @@bm_sf_tuned@@, no better than the default. Choose on one split, report on another.
Adding BM25 and cosine scores with equal weight
BM25's scale wins and the dense half is ignored (@@raw05_sf_q@@, near BM25's @@bm_sf_def@@). Normalise, or learn the weight, or use ranks (§4.1).
Tuning the fusion weight when a reranker follows
The reranker reorders the candidates anyway; after it, RRF and tuned z-score fusion land within a point (§4.5). Spend the effort on rerank depth.
Ignoring what the BM25 tokenizer does to identifiers and negations
The default pattern drops one-character tokens ("Type 1" loses the 1; "IL-6" becomes "il") and the stopword list removes "not" (§2.3).
Filtering after the search or after fusion
A post-filter returns about K · s results and often none; filter inside each retriever's search, then fuse (§6.2).
Turning on MMR because diversity sounds good
It hurt on every set here, including the multi-hop one (§7.2). It helps only when near-duplicates crowd the list.
Trusting an extracted filter without checking it
Here the generator added a month (December) to every request that only named a year, and the filter then removed the right paper for most of them. Keep an extracted value only if the request states it, check it against the real field values, and fall back to no filter when it does not match (§5.2).
Accepting citations without resolving and checking them
Parse every citation, resolve it to a chunk, and at least string-match a quote (§8.3); an unresolvable citation is a wrong answer.

10. Interview questions, short answers

How would you choose a chunking strategy for a new corpus?
Get a few hundred questions with located evidence. Split on the documents' own structure first (headings, paragraphs), cap the size in the embedder's tokens, and compare candidates on "evidence intact" and on retrieval at an equal token budget, never at an equal number of chunks. Try small-to-big (index sentences or paragraphs, return the paragraph) before tuning sizes.
Why does RRF work without calibration, and when would you not use it?
It uses ranks, so the two score scales never meet, and it rewards agreement, which is a strong signal (documents in both top 10s were relevant 13 to 28 times as often as single-list ones on SciFact). It discards score margins; with no reranker and labelled queries to learn a weight, normalised score fusion did about 1 to 1.6 points better here. With a strong reranker after it, RRF is enough.
BM25 or dense for queries with product codes?
Run both and fuse. Check the BM25 tokenizer keeps the codes intact (a two-character pattern drops "X1" pieces; hyphens split). A router is only worth it if it beats fusion on labelled queries; here a learned router did not.
Design a multi-tenant RAG search for 10,000 customers. Where do permissions go?
Tenant id and ACL groups as typed metadata on every chunk, enforced as a filter inside both the BM25 and the vector search (or row-level security in the database), never in the prompt. Choose shared index plus filter or index per tenant by tenant size: tiny tenants make post-filtering useless and filtered ANN slow, so check the engine's filtered-search strategy (iterative scans, ACORN-style traversal, exact scan below a threshold) and measure recall for the smallest tenant. Re-index a document's chunks when its permissions change.
Your RAG answers cite the wrong document. How do you debug it?
Split the failure: was the right chunk retrieved (recall at the rerank depth), did it reach the prompt (rank after reranking against the budget), and did the model use it (an oracle run with only the right chunk)? Then check the citation plumbing: labels the model can repeat, parse rate, resolution to chunks, quote match.
When is query rewriting worth its latency?
Always for chat follow-ups (they are not queries without the history). Otherwise measure: HyDE helped one embedder and hurt another here; multi-query did nothing and step-back and decomposition hurt; a rewrite costs a generator call (0.3 to 2.2 s per query here, depending on how much it writes), more than the whole retrieval.
What is late chunking and what does it need?
Embed the whole document with a long-context, mean-pooling embedder, then average token vectors per chunk span, so each chunk vector sees the document. It needs mean pooling and a long context; published gains are large for weak embedders and small for strong ones, and within a single document (where every chunk shares the same context) it hurt here.

11. How this was measured, and the limits

Machine: Apple M1 Pro (8 performance and 2 efficiency cores, 16 GB unified memory), PyTorch MPS and llama.cpp Metal, October 2026, shared with other agents. Relevance numbers (nDCG, recall, found-within-budget) are deterministic and do not depend on the machine; the few timings are labelled with their load. Data and models: the root's running example (src/data/README.md there) and its precomputed vectors, runs and reranker scores; this page added nomic-ai/modernbert-embed-base (late chunking) and opensearch-neural-sparse-encoding-doc-v3-distill (learned sparse), revisions and sha256 in the shared SETUP notes. Generator: Qwen3-1.7B Q4_K_M in llama-server, temperature 0, seed 0, thinking off, answers cached by exact prompt. Libraries read at pinned versions: langchain-text-splitters 1.1.3, langchain-core 1.6.10, llama-index-core 0.14.25, bm25s 0.3.13, pgvector v0.8.7 README, pySBD 0.3.4.

What transfers: the shapes (structure-aware chunks beat fixed windows at equal budget; post-filters lose results in proportion to selectivity; fusion matters less after a reranker; tuning on test inflates) are properties of the methods. What does not: the exact numbers belong to these corpora (scientific abstracts and NLP papers, mostly one relevant document per SciFact claim), these embedders and a 1.7 B generator, which is weak at CONTRADICT; a larger generator changes the prompt-assembly numbers. Not run here: HTML and code splitting (no such corpus in the running example), BGE-M3's sparse head, LLM routers (on the agentic page), and contextual prefixes beyond the root's run.
