9. What a graph costs, and when it pays

Indexing cost is a sum over LLM calls, each billed for its whole prompt. For graphrag's standard method, per text unit of c tokens:

Tin ≈ (P + c) + (P + c + o1 + 34)     Tout ≈ o1 + o2
P
the extraction prompt's fixed instructions and examples: @@pt_graphrag_extract_graph@@ tokens measured
c
the chunk (1,200 by default)
o1, o2
tokens the model writes in the extraction and the gleaning call (34 = the gleaning message); measured here with Qwen3-1.7B on 125-token paragraphs: @@x17_toutpp@@ for both calls together measured

plus one summarisation call per entity seen in two or more chunks, one report call per community (prompt @@pt_graphrag_community_report@@ tokens plus up to 8,000 of context), and the embeddings. The {{Cost calculator|#t-grcost}} adds these up with every assumption visible. The one published itemised bill: on MuSiQue's 11,656 passages, HippoRAG 2's authors measured indexing input / output tokens of 115.5 M / 36.1 M for GraphRAG, 68.5 M / 18.3 M for LightRAG and 9.2 M / 3.0 M for HippoRAG 2, and 277, 235 and 99.5 minutes, with Llama-3.3-70B ({{arXiv 2502.14802 v2, Table 12|https://arxiv.org/abs/2502.14802}}) published: about 9,900 input tokens per passage for GraphRAG derived: 115.5 M / 11,656. Queries cost too: 10.7 s per question for GraphRAG and 13.3 s for LightRAG against 0.3 s for dense retrieval in the same table.

When a graph pays. When (a) the questions are global or relational, not lookups; (b) the corpus is stable, so the index is built once and read many times (updates re-extract and re-cluster; LightRAG and graphrag's incremental methods reduce, not remove, this); (c) entities are what the corpus is about (people, companies, products, cases), so extraction finds real relations; and (d) someone owns entity resolution. When any of these fails, the cheaper rungs win: hybrid search with a reranker for lookups, the agent loop for occasional multi-hop questions (the root's Agentic lab), an NLP-indexed graph with query-time LLM work (the LazyGraphRAG shape) for occasional global questions, and SQL for anything that is already a table.
