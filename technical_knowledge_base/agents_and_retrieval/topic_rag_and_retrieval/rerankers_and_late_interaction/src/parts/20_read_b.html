2. Cross-encoders, read in the code

The architecture. A BERT-style cross-encoder takes one sequence, [CLS] query [SEP] document [SEP], with a segment id of 0 on the query part and 1 on the document part, runs it through the encoder (6 layers for MiniLM-L6, 24 for bge-reranker-v2-m3), takes the final vector of the [CLS] token, and maps it to one number with a small head. That number is the relevance logit (an unbounded score; higher means more relevant). This is exactly the 2019 recipe of Nogueira and Cho: "we feed the query as sentence A and the passage text as sentence B", the query cut to 64 tokens and the pair to 512, and "the [CLS] vector as input to a single layer neural network". They reranked BM25's top 1,000 on MS MARCO and moved MRR@10 on the dev set from 16.7 (BM25) to 36.5 (BERT Large) (Table 1; published, independent academic, 2019).

3. How cross-encoders are trained

The data. Almost every open English reranker starts from MS MARCO passage ranking: 8,841,823 passages from Bing results and 1,010,916 anonymised questions (Bajaj et al., v3), with 532,761 training relevance labels and official training triples (query, positive, negative): 39,780,811 in the small file (dataset page, read 2026-10-14). Labels are sparse: usually one marked passage per question, so many "negatives" are relevant passages nobody marked (false negatives).

Three losses, in the order they appeared.

  1. Pointwise: binary cross-entropy on each (query, passage, label), as Nogueira and Cho did: the model learns "is this passage relevant", one pair at a time.
  2. Hard negatives: negatives taken from a retriever's top results (BM25's top 1,000 in 2019, a dense retriever's later) rather than at random. A random abstract about cardiology is trivially irrelevant to a claim about MDA5; the abstract about RIG-I signalling that mentions MDA5 but does not support the claim is what the model must learn to rank second.
  3. Distillation (section 7): the student learns a stronger teacher's scores instead of 0/1 labels. The sentence-transformers MS MARCO cross-encoders were trained this way: "we use knowledge distillation with a small & fast model and learn the logits scores from the teacher ensemble" (BERT-base, BERT-large, ALBERT-large, from Hofstätter et al., 2020); the training script's loss is a pointwise mean squared error on the ensemble's logits (examples/training/ms_marco/train_cross-encoder_kd.py in sentence-transformers v2.2.2). The model card itself only says it "was trained on the MS Marco Passage Ranking task", so which script produced the released checkpoint is not stated: unconfirmed.

The model card's own table (published, vendor, read 2026-10-14) shows the size trade: MiniLM-L6-v2 74.30 nDCG@10 on TREC DL 2019 and 39.01 MRR@10 on MS MARCO dev at 1,800 documents/s on a V100, against 74.31 and 39.02 at 960 documents/s for the 12-layer version: half the layers cost nothing measurable there.
