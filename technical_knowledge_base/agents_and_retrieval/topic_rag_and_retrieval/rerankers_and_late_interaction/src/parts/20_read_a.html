The idea in one screen

A first stage must score every document, so it summarises each one before the query exists; a reranker spends real compute on only the top K by reading query and document together. Late interaction and learned sparse vectors are the middle points: they keep more of the document, still precomputed.

Fig. 1: the more a scorer lets the query meet the document, the less it can precompute. Four scorers side by side; orange is the query and where it meets the document, white is what is stored before any query exists.

  1. Bi-encoder: apart, then one dot product. The abstract is encoded on its own, offline, into 1 vector (4,096 bytes for Qwen3-Embedding's 1,024 float32 numbers); the claim is encoded on its own at query time; per candidate they meet in 1 dot product. SciFact nDCG@10: @@de_ndcg@@ alone.
  2. Learned sparse (SPLADE): weighted words. A model writes a weight for about @@sp_nnz_d@@ vocabulary terms per abstract, kept in an inverted index (bars: the 20 heaviest terms of a real abstract, section 10; purple ones are not in its text). A candidate's score is a sum over the terms it shares with the query. @@sp_ndcg@@ alone (in-domain, section 10).
  3. Late interaction (ColBERT): one vector per token. Each abstract stores @@cb_tok_mean_r@@ token vectors of 96 numbers, @@cb_bytes_doc@@ bytes; each query token finds its best document token (MaxSim, about @@ms_mflop@@ MFLOP per candidate). @@cb_ndcg@@ alone, @@cb_rr_hy20@@ reranking. Which token matches which is drawn schematically here; Fig. 4 in section 8 has the real matches.
  4. Cross-encoder: one pass over both. Query and document go through every layer together (glass plates), so every query token reads every document token. Nothing is stored; each candidate costs a full forward pass, @@gf_ce@@ GFLOP (MiniLM) to @@gf_qw@@ (Qwen3-Reranker). @@hy_qw_k20@@ reranking the hybrid top 20.
  5. The trade. All four, with storage per abstract drawn to scale as the white blocks at the back (4,096, about @@sp_bytes_doc@@, @@cb_bytes_doc@@ and 0 bytes). Left: more precomputed, cheaper per candidate, can scan the corpus. Right: more query-document interaction, dearer, top K only.

1. Why a second stage

A first stage looks at every document for every query, so it can only afford a cheap comparison. A bi-encoder encodes query and document separately: documents once, offline; a query costs one pass plus N dot products. Its weakness is the same fact: the document vector was fixed before the query existed, so about a thousand numbers must summarise everything the document might be asked. BM25 is cheaper still and only counts shared words. A cross-encoder puts query and document in one input, so every query token attends to every document token in every layer: it sees "MDA5" in the claim next to "RIG-I, MDA5, and LGP2" in the abstract, rather than two summaries. Nothing can be precomputed, so it runs only on the top K. Fig. 2 follows one real pair both ways.

Fig. 2: the bi-encoder ranks the right abstract 7th; reading the pair together puts it 1st.

  1. Two separate texts. Claim 1180 (front, orange) and the abstract that supports it (back; its first 48 tokens drawn).
  2. Offline, once per corpus. The abstract goes through the encoder (glass plate) on its own and is summarised into one vector of 1,024 numbers (Qwen3-Embedding keeps the final state of the last token), stored with the other 5,183 before any query exists.
  3. At query time. The claim goes through the same encoder on its own: one model pass per query, one more vector.
  4. One dot product. Two unit vectors meet once: cosine @@be_cos@@. The model never saw the two texts together; work per candidate is one dot product of 1,024 numbers.
  5. Ranked by cosine. The claim's top 10 by cosine: the relevant abstract (green) ranks @@be_rank@@; five near-miss abstracts about RIG-I and MDA5 score higher.
  1. One input sequence. [CLS] claim [SEP] abstract [SEP], @@be_ntok@@ tokens; the claim has segment id 0 (orange), the abstract 1 (first 48 abstract tokens drawn).
  2. Every layer attends over all tokens. MiniLM-L6's six layers (glass plates) run self-attention over all @@be_ntok@@ tokens, so claim tokens read abstract tokens directly. Streams: each claim token's two strongest abstract targets in the last layer (mean of @@be_heads@@ heads), denser for more attention.
  3. The strongest targets are the words that matter. The lifted abstract tokens. On average @@be_share@@% of a claim token's attention lands on abstract tokens.
  4. One number out. The final [CLS] vector goes through dense, tanh and one linear layer: logit @@be_ce@@.
  5. Repeated for every candidate. 10 passes for the top 10, nothing precomputed; scored this way the relevant abstract (green) ranks 1st.

FLOP per pair ≈ 2 × (parameters outside the embedding table) × tokens  (+ an attention term in tokens²)

A SciFact pair is about @@tok_ce@@ tokens for MiniLM: @@gf_ce@@ GFLOP. Qwen3-Reranker also reads its chat template (@@tok_qw@@ tokens) through 0.44 B non-embedding parameters: @@gf_qw@@ GFLOP per pair, @@gf_ratio@@ times more. Measured pairs per second give an achieved @@tf_ce@@, @@tf_bge@@ and @@tf_qw@@ TFLOP/s for the three models on this GPU (third-party estimates put the M1 Pro 16-core GPU's float32 peak at about 5.2 TFLOP/s; Apple does not publish it).
