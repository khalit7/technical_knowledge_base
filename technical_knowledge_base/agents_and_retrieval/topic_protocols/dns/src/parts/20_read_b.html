DNS in one screen

About 45 minutes for the prose, about 55 with the recordings, tables and interview answers. It starts from zero and defines every term where it first appears (all of them are in the Glossary); each section can be read on its own. This page is the depth behind section 2 of {{Topic: protocols|n:3c65c17b0d0d81ec9355f4eecd6eed02}}, which gives the overview in five minutes. Everything marked measured was recorded for this page on 5 October 2026, either on a private DNS tree built in containers on an Apple M1 Pro laptop (Docker Desktop, Linux 5.10; Unbound 1.25.2, CoreDNS 1.12.4, glibc 2.41, musl 1.2.6, dig 9.20.29) or with about twenty-five read-only public lookups; illustrative marks a picture of a shape rather than data, and derived numbers show their formula.

DNS (the Domain Name System) turns a name such as api.anthropic.com into the records a program needs, mostly IP addresses. It is a tree of servers that each know one part of the answer, and almost every answer is cached for a number of seconds the owner chose. Nearly every DNS problem you will debug is one of four things: the answer is cached somewhere you did not expect, one name was turned into many queries, one lost packet cost a fixed timeout, or the wrong server was asked.

The running example. The root page follows one streaming request to an LLM API. Before the first byte of that request leaves your machine, the client must turn the API's name into an address. Here the API is api.llm.test on a private DNS tree built for this page (a root zone, the top-level domain test., and the zone llm.test., each served by a real DNS server in a container, with a real recursive resolver in front), because the laptop this page was recorded on answers every ordinary public DNS packet with a local filter, so public walks cannot be observed from it (the root's {{Failure lab|n:3c65c17b0d0d81ec9355f4eecd6eed02}} tab shows the filter as its "A TLS error caused by DNS" case). The real api.anthropic.com appears wherever a public lookup tells the story better; those were sent over encrypted DNS to a public resolver, with its certificate checked, which the filter does not touch.
