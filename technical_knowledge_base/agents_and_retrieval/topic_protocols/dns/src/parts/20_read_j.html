8. Cloud resolvers and managed DNS (AWS as the example)

The VPC resolver. Every AWS VPC has a built-in recursive resolver (Route 53 Resolver, newer pages call it the VPC Resolver) at the VPC's base address plus two (10.0.0.2 for 10.0.0.0/16) and at 169.254.169.253 ({{AWS VPC DNS|https://docs.aws.amazon.com/vpc/latest/userguide/AmazonDNS-concepts.html}}). It answers private hosted zones, public names and the VPC's own instance names; the VPC needs enableDnsSupport (and enableDnsHostnames for instance names).

  • A hard packet limit. Each instance may send at most 1,024 packets per second to link-local services in total, DNS, the metadata service and time sync together, and the limit cannot be raised (same page). Excess packets are dropped, so the symptom is the stub's timeout, not an error. A dense Kubernetes node whose pods all talk to the VPC resolver, each external lookup multiplied by eight (section 7), reaches it; NodeLocal DNSCache and fewer search-list misses are the remedies. corrected The old page said "per ENI"; the documentation states the quota for link-local traffic in aggregate.
  • Split horizon. A private hosted zone answers only inside the VPCs associated with it, so the same name can mean different things inside and outside (the Failure lab's "Wrong resolver" case is this shape). Resolver endpoints forward queries between a VPC and on-premises DNS in both directions and are billed per endpoint and per query, a common surprise on the bill.
  • Query logs are off until you turn them on: Resolver query logging needs a logging configuration associated with the VPC, and cached answers are not logged ({{AWS|https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/resolver-query-logs.html}}). It is the native way to spot exfiltration (section 10) and runaway lookups.

Route 53 as an authoritative service. Health checks probe every 30 seconds by default, or every 10 with fast checks, and mark an endpoint unhealthy after 3 failures by default ({{HealthCheckConfig|https://docs.aws.amazon.com/Route53/latest/APIReference/API_HealthCheckConfig.html}}). Health checkers live on the internet, so they cannot probe private addresses; for a private resource, health-check a CloudWatch alarm instead ({{AWS|https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/health-checks-types.html}}). Routing policies choose which answer a client gets: weighted, latency-based, failover, geolocation, and multivalue (up to eight healthy records per answer; {{AWS|https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/routing-policy-multivalue.html}}). All of them act only when a resolver asks again, so a failover is as fast as the record's TTL plus the health check's detection time, never faster: with 30-second checks, 3 failures and a 60-second TTL, clients can keep the dead address for about 90 + 60 = 150 seconds (derived).
