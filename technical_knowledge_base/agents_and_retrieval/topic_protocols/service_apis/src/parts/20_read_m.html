The common shape, and the running example's: REST and SSE at the public edge because every client can speak it; gRPC behind the gateway because both ends are yours and the calls are many; a translating hop in between (your API server, Envoy transcoding, or a model gateway). vLLM and SGLang serve OpenAI-compatible REST first because ecosystem compatibility beats wire efficiency at the edge; their gRPC modes exist for the gateway-to-engine hop, where a router sends many requests and needs health, cancellation and streaming without JSON parsing.

Not carried from the old page because they could not be confirmed from a primary source today: that Ray's internals and the Milvus database use gRPC (only the Ray Serve proxy above is confirmed), and the statements about AWS API Gateway and Lambda not supporting gRPC. ALB's gRPC support is confirmed (section 8).
