9. Browsers, gateways and the gRPC family

The problem. A browser's fetch cannot read HTTP trailers and cannot control HTTP/2 framing, so it cannot speak gRPC as section 4 recorded it. Neither can many HTTP/1.1-only proxies, serverless platforms or third-party developers with only curl. Four answers exist; you will meet all of them.

gRPC-Web

The same messages with the trailers moved into the body: a final length-prefixed frame whose flag byte has its top bit set (0x80) carries grpc-status as text. Works over HTTP/1.1; unary and server streaming only; a proxy (Envoy's grpc_web filter) translates to real gRPC ({{PROTOCOL-WEB.md|https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-WEB.md}}).

Connect

A protocol and libraries (a CNCF sandbox project, per {{connectrpc.com|https://connectrpc.com/}}): same .proto files, but a unary call is a plain POST /package.Service/Method with application/json or application/proto, a Connect-Protocol-Version: 1 header and Connect-Timeout-Ms for the deadline; errors use ordinary HTTP status codes with a JSON body. Unary and server streaming work over HTTP/1.1; bidirectional streaming needs HTTP/2 ({{Connect protocol|https://connectrpc.com/docs/protocol/}}). curl-able, which is the point.

HTTP/JSON transcoding

Annotate each RPC with the REST shape it should also have, and a gateway (Envoy's JSON transcoder, grpc-gateway) serves both: option (google.api.http) = { post: "/v1/{parent=publishers/*}/books" body: "book" }. Google's rule is that APIs "must" provide this for every RPC except bidirectional streaming ({{AIP-127|https://google.aip.dev/127}}). The open-source {{grpc-gateway|https://github.com/grpc-ecosystem/grpc-gateway}} does the same from the annotations.

tRPC (not related)

Despite the name, tRPC shares nothing with gRPC: no protobuf, no HTTP/2 requirement, no code generation. It is a TypeScript library where the client imports the server router's type, giving "fully typesafe APIs without schemas or code generation"; on the wire it is ordinary HTTP with JSON, with request batching and subscriptions ({{tRPC README|https://github.com/trpc/trpc}}, v11.19.0 on 16 September 2026).

Use tRPC for a TypeScript product whose only client is its own front end (the dashboards of ML products are often this); put REST or gRPC at any boundary another team or language must cross. ML serving itself never uses it.
