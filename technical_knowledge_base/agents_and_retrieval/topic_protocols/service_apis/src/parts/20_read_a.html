Service APIs in one screen

When you send the root page's request, POST /v1/messages with "What colour is the sky?", one program does not answer it. The front door checks your key, a router picks a GPU replica, an inference server generates tokens, and telemetry goes to a collector. Each arrow between those programs is an API call: an agreed way for one program to ask another to do something over the network. This page is about the arrows: what goes on the wire, how a call gives up, what its errors mean, and how calls get spread over many copies of a service.

The running example, behind the front door

Outside: REST and SSE, because anyone with curl must be able to call it. Inside: gRPC, because both ends are yours and the calls are many, typed and streaming. The labels are the ports and protocols real systems use (sources in section 12); the lab on this page builds the middle two hops and records every byte.

The ten things to remember
  1. gRPC is HTTP/2 underneath: every call is a POST /package.Service/Method stream, each message has a 5-byte prefix, and the result arrives in trailers (grpc-status) after the body. Section 4 shows the recorded frames.
  2. Protobuf sends field numbers, not names: the running request is 49 bytes against 117 in JSON (measured). Never reuse a field number: an old reader silently misreads it (section 3, measured).
  3. gRPC sets no deadline by default. Set one on every call and pass the remaining time on; without that, a GPU kept generating tokens for a user who left after (section 5, measured).
  4. Status codes say who failed and whether a retry is safe. Retries are off unless a service config turns them on, and the deadline covers every attempt (section 6).
  5. One gRPC channel keeps one long-lived connection. An L4 balancer chooses once per connection, so all 30 calls went to one replica; an L7 balancer chose per call, 10/10/10 (section 8, measured).
  6. The default client policy, pick_first, also sends everything to one address even when it knows three. Ask for round_robin or use a proxy (section 8, measured).
  7. New replicas stay idle behind an L4 balancer until clients reconnect; MAX_CONNECTION_AGE forces that (section 8 and the {{Balancer lab|#t-lb}}).
  8. Browsers cannot speak gRPC's trailers: gRPC-Web, Connect and HTTP/JSON transcoding exist for that (section 9).
  9. GraphQL turns one query into many backend calls: 141 database calls for one innocent query, 4 with batching (section 10, measured).
  10. ML serving speaks all of these: OpenAI-compatible REST at the edge, gRPC into Triton, vLLM's new gRPC mode, OTLP telemetry, and a gRPC side channel that lets a gateway route by KV cache (section 12).
