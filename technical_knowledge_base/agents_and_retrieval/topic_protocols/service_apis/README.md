# Service APIs: REST, gRPC, GraphQL and load balancing

Notion: https://app.notion.com/p/3c65c17b0d0d81cb88a3f1f63e85f27b (child of Topic: protocols)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). How programs call each other behind an LLM API, taught from zero on the root's streaming request: what an API style decides, REST as practised (Fielding, Richardson levels, custom methods, long-running operations, OpenAPI, QUERY), protobuf byte by byte (varints, wire types, zigzag, packed fields, schema evolution with measured silent failures, tensors in four encodings), gRPC on HTTP/2 (path, te: trailers, 5-byte prefix, trailers and trailers-only, four call shapes, channels), deadlines and cancellation (four measured endings of one abandoned request), the 17 status codes with 11 failures recorded as the client sees them, retries (policy, transparent, hedging, throttling), connections (keepalive and a reproduced too_many_pings GOAWAY, connection age, limits, health, reflection), load balancing at L4, L7 and in the client (measured 30/0/0 against 10/10/10, the pick_first trap, scale-up timelines, KV-cache-aware inference gateways), gRPC-Web, Connect, transcoding and tRPC, GraphQL (measured N+1, cost limits, GitHub's limits, status codes), JSON-RPC 2.0, where each lives in ML serving (vLLM's new gRPC mode, SGLang, Triton, TF Serving, Ray Serve, OTLP), a debugging table, drills and interview questions. Every exchange recorded locally on 2026-10-05 (`src/raw/`, rerun with `src/run_all.sh`). Tabs: Reading, One gRPC call (every HTTP/2 frame of three calls, protobuf decoded), Balancer lab (the same calls through four balancing setups while a replica joins), Further reading. Rebuilds the old page "RPC and API styles: REST, gRPC, GraphQL" (kept verbatim in `../src/read/old/`, every fact mapped in `src/coverage.json`); no child pages, databases or video.
