- **Agent protocols**. **MCP** (Model Context Protocol, Anthropic, November 2024) is how one agent reaches tools and context: JSON-RPC 2.0 between a **host**, one **client** per connection, and **servers** exposing *tools*, *resources* and *prompts*, over **stdio** or **Streamable HTTP**, with remote servers authenticating as OAuth 2.1 resource servers holding audience-bound tokens. The 2026-07-28 revision made the core stateless, so an ordinary gateway can route and cache a request, and moved optional features into a formal extensions framework. What MCP buys is that a server written once plugs into every harness; what it costs is that every tool result is untrusted text arriving inside the model's context, which is the whole prompt-injection surface. Deep dive: <mention-page url="https://app.notion.com/p/3c65c17b0d0d813f9695dc4175c44cbb">Model Context Protocol (MCP)</mention-page>. **A2A** (Agent2Agent, Google-origin, under the Linux Foundation since June 2025, v1.x with 150+ member organisations) solves the neighbouring problem, delegation between agents that are opaque to each other, where neither side sees the other's tools, prompts, or internal state. An agent publishes an **Agent Card**, a JSON document at a well-known URL describing its skills, endpoints, and authentication requirements; a client discovers it, opens a task with an explicit lifecycle (submitted, working, input-required, completed, failed), and receives updates over JSON-RPC on HTTP with SSE for streaming. MCP is agent-to-tool, A2A is agent-to-agent; they complement rather than compete. The rest of the 2025 alphabet soup consolidated into A2A. IBM's **ACP** (Agent Communication Protocol) merged into it, and Cisco-led **AGNTCY** (an agent directory plus an identity scheme plus its own REST-flavoured **Agent Connect Protocol**, confusingly abbreviated ACP as well, and unrelated again to Zed's Agent Client Protocol for editors in <mention-page url="https://app.notion.com/p/3c65c17b0d0d81d881a8fe98b4cff7bb"/>) moved under the Linux Foundation and archived its ACP SDK in April 2026. **A third shape arrived in 2026 and it is neither agent-to-tool nor agent-to-agent.** The **Universal Commerce Protocol (UCP)**, co-developed by Shopify with Google and supported by Etsy, Target, Walmart and Wayfair, is agent-to-merchant: a standard by which an agent discovers what a merchant can do, negotiates a transaction, and hands back the parts it cannot complete. Four design decisions are worth knowing because they generalise past commerce. **Discovery is a well-known path**: both merchants and agents publish capability profiles at `/.well-known/ucp`, and **negotiation is the intersection of the two profiles**, so a merchant implements only what it supports and an agent degrades predictably rather than failing. **Extensions use reverse-domain naming** (`com.loyaltyprovider.points`), so a domain-specific capability needs no central approval, which is how MCP's extensions framework should be read as well. The protocol is **layered** into a shopping service holding the core primitives, capabilities for major areas such as Checkout and Orders, and extensions for domain schemas, each versioned independently so a core revision does not break a niche capability. And it has an **explicit incompleteness state**: a checkout moves through `incomplete`, `requires_escalation` and `ready_for_complete`, and where the agent hits a capability gap the **Embedded Checkout Protocol** opens a JSON-RPC 2.0 channel so a human buyer finishes the transaction in the merchant's own interface. That last mechanism has the widest application and is the part MCP has no answer to: an MCP tool call succeeds or fails, with the failure landing in the model's context as text, whereas UCP treats "an agent cannot finish this and a person must" as a first-class protocol state with a transport attached. Anything with irreversible actions, which is the standing problem for the Model Hardware Standard and the consumer MCP surfaces below, needs that state. Payment is negotiated from both sides, with merchants expressing payment-provider preferences and agents declaring available credentials, and handlers varying with cart contents, location and amount. The protocol itself was published in January 2026; what is new is the adoption. In September 2026 **Meta's Muse began searching the Shopify catalogue and completing purchases through Shop Pay over UCP**, default-enabled across Shopify stores, and **Amazon blocked Muse the next day** using standards it does not apply to its own shopping agent, which is the first open instance of an agent-commerce standard being used as a competitive boundary rather than an interoperability one. [Shopify Engineering](https://shopify.engineering/UCP) (25 min) **MCP servers can be generated rather than written, at a 74% success rate.** Stanford's Paper2Agent (Nature, September 2026) converts a research paper plus its repository into a working agent exposed as MCP tools, one that reproduces the paper's results and runs the same analysis on new data, and it succeeded on **74 of 100 computational biology papers with no manual intervention**. Both halves of that number are informative. The 74% says a tool schema plus a transport is a small enough contract that a model can fill it from a repository, a real vindication of MCP's design. The failing 26% is where the **operational knowledge** needed to actually run the code is absent from the repository, living instead in issue threads, undocumented environment assumptions and the authors' heads, exactly the gap named by the Repo-To-Skill work recorded on <mention-page url="https://app.notion.com/p/3c65c17b0d0d81d881a8fe98b4cff7bb"/>. The bottleneck is therefore neither the protocol nor the model, it is whether the source repository can be made to run. [Nature](https://www.nature.com/articles/s41586-026-11044-y), [MarkTechPost](https://www.marktechpost.com/2026/09/16/stanford-researchers-release-paper2agent-turning-research-papers-into-ai-agents-that-reproduce-results-and-run-on-new-data/) (10 min) Practical takeaway: build tool access on MCP, watch A2A for cross-organisation federation, and ignore the rest unless a platform forces it on you.
- **Agent-to-instrument**: Anthropic's **Model Hardware Standard (MHS)**, research preview opened 27 August 2026, is a shared specification for letting agents drive physical laboratory and manufacturing equipment: microscopes, liquid handlers, robotic arms, optical benches. It works with any device exposing a programmable interface, is model-agnostic, and is reachable by any harness over standard protocols including MCP, so it is a device-abstraction layer above MCP rather than a competing transport. Reported early results: a drug-discovery run with real-time error handling at Genentech, an imaging experiment compressed from weeks to a day at HHMI Janelia, and laser stabilisation on QuEra's quantum computers going from 58% to 99.3%. Anthropic intends to open-source it, and the first preview is limited to selected research labs and advanced manufacturers. The interesting protocol question is the trust boundary: MCP's failure modes (prompt injection, confused deputy) are documented in <mention-page url="https://app.notion.com/p/3c65c17b0d0d813f9695dc4175c44cbb">Model Context Protocol (MCP)</mention-page> and are recoverable, whereas an agent driving a liquid handler issues irreversible physical actions, the same standing-authority problem the personal-agents page raises for resident agents. [Anthropic](https://www.anthropic.com/news/model-hardware-standard-research-preview) (10 min), [CNBC](https://www.cnbc.com/2026/08/27/anthropic-pushes-into-physical-world-with-new-standard-to-help-ai-agents-operate-machines.html) (8 min) The same boundary now exists on a consumer surface: **Google Home MCP** entered early access in September 2026, letting agents query device state and command home devices, and requiring a Premium Advanced subscription and a Cloud project. It is the first consumer-device MCP surface from a major vendor, and the trust boundary is again the notable part: physical device state in, physically irreversible actions out, the property that makes the personal-agent category hard, now on a protocol surface anyone can connect an agent to.
