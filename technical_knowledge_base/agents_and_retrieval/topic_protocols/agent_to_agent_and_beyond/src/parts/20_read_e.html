6. One meaning, three wire formats, and versions

Version 1.0 defines the operations once and maps them onto three bindings (spec sections 5, 9 to 11): JSON-RPC 2.0 over HTTP with SSE for streams, gRPC (protobuf over HTTP/2, {{Service APIs|n:3c65c17b0d0d81cb88a3f1f63e85f27b}}), and HTTP+JSON, a REST style whose URLs come from the same protobuf service. An agent offering several "MUST" behave identically on all (section 5.1). The same blocking request over the two HTTP bindings Team B's card lists cost within a few percent of each other in bytes; the real difference is operational: JSON-RPC answers every A2A error with HTTP 200 and an error object, while HTTP+JSON uses status codes (a missing task is a real 404, section 7). A dashboard counting 4xx and 5xx sees JSON-RPC failures as successes: alert on the error object, or pick the binding your load balancers and monitors understand.

Versions. Clients "MUST" send A2A-Version: 1.0 on every request (section 3.6), and an empty or missing header means 0.3. Recorded: 9.9 gave -32009 A2A version '9.9' is not supported by this handler. Expected version '1.0'., and an empty header was read as '0.3' and refused the same way, so old clients that never send the header are treated as 0.3 clients.

Naming on the wire in 1.0: the protobuf model as JSON with camelCase fields and enum values as full names (TASK_STATE_INPUT_REQUIRED, ROLE_USER); the 0.3 kind field is gone, and an object's type is the key that wraps it: {"task": ...}, {"statusUpdate": ...}, {"artifactUpdate": ...} (spec sections 5.5, A.2.1). 0.3 used method names like message/send, a kind on every part and event, and lower-case roles such as "user"; a 0.3 request to a 1.0-only endpoint gave -32601 Method not found (recorded). The SDK can serve both on one endpoint (enable_v0_3_compat=True).




Version skew in the wild
UCP's own A2A binding page in its 2026-08-25 release still shows 0.3-style requests ("method": "message/send", "kind": "message", an X-A2A-Extensions header) ({{UCP checkout, A2A binding|https://github.com/Universal-Commerce-Protocol/ucp/blob/v2026-08-25/docs/specification/shopping/checkout/a2a.md}}), while A2A 1.0 names the header A2A-Extensions (spec section 3.2.6). A 1.0-only agent rejects those requests: when two "A2A" systems cannot talk, check the version header and the method names first.
