11. Debugging and choosing

From symptom to layer

Start from what you see, find the layer, run the one command that confirms it. The order is roughly the order of the request: a failure early in the path hides everything after it. The {{Failure lab|#t-fail}} reproduces 39 of these failures on the running request, and each child page has its own symptom table.

Which protocol when

You need toUseBecause
Serve a public API to arbitrary clientsHTTPS + JSON (REST style), SSE for streamingEvery language and proxy understands it
Stream tokens to a browser or appSSEPlain HTTP, one direction, survives proxies when configured
Let the user interrupt (voice, realtime)WebSockets (or WebRTC for audio from a device)Both directions at any time
Tell another system that a long job finishedWebhook (signed, idempotent consumer), or a queue inside your own systemsNo connection held open for hours
Call internal services at high rategRPC with deadlinesTyped, compact, streaming, cancellation across hops
Move a big checkpoint over a long pathMany parallel TCP streams (multipart upload)One stream is capped by window over RTT and per-flow limits
Move tensors between GPUsNCCL over NVLink and RDMANo kernel, no copies, microsecond latency
Give an agent toolsMCP (stdio locally, Streamable HTTP remotely)Write a tool once, any host can use it
Delegate a task to someone else's agentA2ADiscovery, task lifecycle and streaming between opaque agents
