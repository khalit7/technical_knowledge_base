Words used below. A packet is one unit the network carries (a few hundred to about 1,500 bytes). A port is a number that picks the program on a machine; an address plus a port is one end of a connection. A round trip (RTT) is the time for a message to go and an answer to come back: every protocol step that must wait for an answer costs one. A handshake is the exchange that sets a connection up before any request can go. A stream is one request and its answer inside a shared connection; a frame is one labelled piece of a stream. The Reading tab defines each one properly.

1. The request and the answer, as bytes

The app sends a POST to /v1/messages with a JSON body; the server answers 200 with content-type: text/event-stream and then sends Server-Sent Events (SSE): small text blocks, each an event: line, a data: line and a blank line (WHATWG HTML Standard, section 9.2). The event names and JSON shapes follow Anthropic's Messages API streaming format, trimmed to message_start, one content_block_delta per token, and message_stop. No model runs: the five tokens are fixed, the first comes after (standing in for the model reading the prompt) and the rest apart, so every run sends the same bytes.







Each mark is one recv() call returning bytes to the app over plain HTTP/1.1 (port 8080, no encryption), so the timing is the server's, not the network's. Source: raw/h1_arrivals.json.

5. TLS 1.2 against TLS 1.3: counting round trips


The same client and server, forced to TLS 1.2 and then to TLS 1.3, over the emulated 50 ms path. Every message below was logged by OpenSSL itself as it went out or came in. TLS 1.2 needs two round trips before the request can go; TLS 1.3 needs one, because the client sends its key share in its very first message instead of waiting to be told which one to use.
