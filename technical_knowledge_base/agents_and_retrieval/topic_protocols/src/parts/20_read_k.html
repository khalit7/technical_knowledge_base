Ten interview questions, with short answers

1. What happens between calling an LLM API and seeing the first token?
The client resolves the host name with DNS (cached, or one round trip to a resolver), opens a TCP connection (one round trip), runs the TLS 1.3 handshake (one round trip; certificate checked against the trust store), sends the HTTP POST, and the server answers 200 with an SSE stream whose first event follows the model's prefill. About four round trips before the server even starts, which is why clients reuse connections and why HTTP/3 merges the TCP and TLS round trips.
2. TCP or UDP?
TCP gives an ordered, reliable byte stream with flow and congestion control, at the cost of a handshake and head-of-line blocking. UDP gives single datagrams with no guarantees and no setup. Use TCP unless late data is useless (voice, games) or you build your own reliability on top, as QUIC does.
3. Why does one upload between regions use a fraction of a 10 Gbit/s link?
A sender may have one window of unacknowledged data in flight per round trip, so throughput is at most window / RTT. Filling 10 Gbit/s at 100 ms needs 125 MB in flight (the bandwidth-delay product). Small windows, losses and per-flow caps (5 Gbit/s on AWS outside a placement group) all bite; the fix is parallel streams.
4. HTTP/1.1 vs HTTP/2 vs HTTP/3?
Same semantics, different wire formats. 1.1 sends one request at a time per connection; 2 multiplexes many streams over one TCP connection but a lost packet stalls them all; 3 runs over QUIC so a loss stalls only its own stream, and connection plus encryption setup takes one round trip instead of two.
5. What does TLS protect, and what does it leak?
It protects content (confidentiality and integrity) and proves the server's identity. It does not hide the IP addresses, the server name in the ClientHello (unless Encrypted Client Hello is used), or the sizes and timing of records, which for token streams can reveal token lengths.
6. How does the client know it is talking to the real server?
The server sends a certificate chain to a root in the client's trust store, the certificate names the host dialled, and the server signs the handshake transcript with the certificate's private key (CertificateVerify). A man in the middle can relay the certificate but cannot produce that signature.
7. 401 vs 403, and 502 vs 504?
401: not authenticated, because credentials are absent or invalid; 403: authenticated but not allowed. 502: a proxy got an invalid response or a closed connection from upstream; 504: a proxy gave up waiting for upstream. Both 5xx come from a hop in front of the server, so find which hop.
8. How would you stream tokens to a browser, and what breaks in production?
SSE over HTTP: text/event-stream, one event per token, a final event marking completion. In production: buffering proxies (disable buffering, no compression), idle timeouts during long thinking (heartbeat comments, raise timeouts you own), errors after the 200 (send them as events), and dropped streams (detect the missing final event and retry with an idempotency key).
9. API key, OAuth, JWT: what is each for?
An API key identifies an account to a service and suits backend-to-provider calls. OAuth lets an app or agent act for a user with a scoped, short-lived token the user approved; PKCE stops intercepted codes from being redeemed. A JWT is one token format a server can verify offline; check signature with a pinned algorithm, issuer, audience and expiry, and accept that it cannot be revoked early.
10. What are the risks of giving an agent MCP tools?
Every tool result is untrusted text in the model's context, so a web page or issue comment can carry instructions (indirect prompt injection); with private data, untrusted input and an outbound channel together, that becomes exfiltration. At the protocol level, a proxying server can be a confused deputy, and forwarding tokens not issued to the server (token passthrough) is forbidden by the spec. Mitigate with least-privilege scopes, audience-bound tokens, approval outside the conversation for irreversible actions, and removing one leg of the trifecta.
