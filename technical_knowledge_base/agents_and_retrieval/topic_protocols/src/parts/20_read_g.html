9. Auth: who is calling, and may they do this?

TLS proved the server's identity to the client; the API now needs the reverse. Two questions, often confused: authentication (who are you?) and authorization (what may you do?). A 401 means the first failed, a 403 the second. The credentials differ in what they prove, whether a thief can use them, and how long they live:

The agent-era twist. An agent holds credentials and decides what to do with them from text it reads, some written by strangers (section 10). Auth cannot stop an agent being talked into misusing a credential it legitimately holds; it can decide how much each credential is worth when that happens. Three rules follow: least privilege (read-only scopes unless it must write, separate scopes for destructive actions); audience binding (a token issued for one tool server must not work anywhere else); no token passthrough (a server that receives a token never forwards it upstream; it obtains its own, by token exchange). For actions that cannot be undone, a human approval outside the conversation, which text arriving through a tool cannot fake.
