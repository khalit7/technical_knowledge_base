7. Service APIs: REST, gRPC, GraphQL behind the front door

The problem. Behind POST /v1/messages the API calls its own services: authentication, rate limiting, a tokenizer, a router that picks a GPU replica, the inference server, billing. Those calls happen thousands of times a second between programs written by different teams in different languages. They need an agreed shape, speed, and a way to give up together when the user has gone.

REST: resources and HTTP verbs

An architectural style from Roy Fielding's 2000 thesis ({{chapter 5|https://www.ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm}}): name things as resources with URLs, act on them with the standard methods and status codes, keep the server stateless between requests. In practice "REST" means JSON over HTTP with sensible URLs. Anyone with curl can call it, proxies understand it, and caches can store it. Right for public APIs, including LLM APIs.

gRPC: typed remote calls over HTTP/2

You declare services and messages in a .proto file; tools generate client and server code in a dozen languages; calls travel as compact binary protobuf over HTTP/2, with four modes: one request one response, server streaming, client streaming, and both ways. Right for internal service-to-service calls where you own both ends, and common in inference stacks (NVIDIA Triton and OpenTelemetry's exporter speak it).

GraphQL: the client chooses the shape

One endpoint and a typed schema; the client sends a query naming exactly the fields it wants, across related objects, in one round trip. Right when many different front ends read the same data (GitHub's public API). Costs: hard to cache (every request is a POST), and one query can fan out into many backend calls. Rarely the right tool for ML serving.

Why protobuf is small. JSON repeats every field name in every message; protobuf sends a field number and a compact value. The encoding guide's own example, a message whose field 1 holds 150, is the three bytes 08 96 01: 08 says "field 1, a variable-length integer", 96 01 is 150 in 7-bit groups ({{Protocol Buffers encoding|https://protobuf.dev/programming-guides/encoding/}}). This page's script serialised exactly that with the protobuf library and got 08 96 01, against 13 bytes for the JSON {"value":150} (measured, protobuf 7.36.2). Because fields are numbered, an old reader skips fields it does not know, which is what lets services evolve without breaking each other, as long as nobody reuses a field number.

Deadlines: giving up together

The user closes the chat tab. Without coordination, the API server, the router and the inference server keep working on an answer nobody will read, and on a GPU that is real money. gRPC's answer is the deadline: the caller says "I will wait until time T", every hop passes the remaining time on to the calls it makes, and any hop past the deadline stops and returns DEADLINE_EXCEEDED. The {{gRPC docs|https://grpc.io/docs/guides/deadlines/}} put the trap plainly: "By default, gRPC does not set a deadline which means it is possible for a client to end up waiting for a response effectively forever." Set one on every call. With HTTP the equivalent is a timeout on every client plus cancelling downstream work when the incoming connection closes.

Load balancing: L4 and L7

A load balancer spreads requests over replicas. An L4 (transport-level) balancer picks a backend per connection and then forwards bytes without reading them. An L7 (HTTP-level) balancer reads each request and can pick a backend per request, route on paths or headers, and retry. The difference bites with gRPC and HTTP/2: a client keeps one long-lived connection and sends every call over it, so an L4 balancer sends all of that client's traffic to one replica while the others idle ({{gRPC blog on load balancing|https://grpc.io/blog/grpc-load-balancing/}}). The fixes are an L7 balancer that understands HTTP/2 (Envoy, a cloud L7 balancer in gRPC mode, a service mesh) or client-side balancing over the list of replicas. LLM serving adds its own twist: routers that send a conversation back to the replica that already holds its KV cache, which only an L7 router that reads the request can do.
