12. QUIC: TCP's job, rebuilt on UDP

The problem. TCP plus TLS has three costs that could not be fixed inside TCP. A new connection pays a round trip for TCP and another for TLS 1.3 before the request leaves. All streams of an HTTP/2 connection share one ordered byte stream, so one loss stalls them all (section 4). And TCP is ossified: firewalls, NATs and load balancers parse its headers and drop what they do not recognise, and it lives in operating-system kernels that update slowly, so new TCP features take a decade to deploy, if ever. QUIC ({{RFC 9000|https://www.rfc-editor.org/rfc/rfc9000}}, May 2021, started at Google) moves the transport into a library on top of UDP and encrypts almost everything so middleboxes cannot ossify it again.

How it works

  • One handshake for transport and encryption. TLS 1.3 runs inside QUIC's own packets ({{RFC 9001|https://www.rfc-editor.org/rfc/rfc9001}}), so the connection is ready after one round trip. A client returning to a server can send its request in the very first flight (0-RTT), but that data can be replayed by an attacker who records it ({{RFC 9001 s9.2|https://www.rfc-editor.org/rfc/rfc9001#section-9.2}}): use it only for requests that are safe to repeat. The root's {{On the wire|n:3c65c17b0d0d81ec9355f4eecd6eed02}} tab measured cold, resumed and 0-RTT connections.
  • Streams, each with its own order and flow control. A lost packet holds up only the streams whose data it carried; other streams keep delivering.
  • Packet numbers are never reused. A retransmission goes in a new packet with a new number, so an acknowledgement is never ambiguous about which copy arrived, which makes RTT samples clean ({{RFC 9002 s4.2|https://www.rfc-editor.org/rfc/rfc9002#section-4.2}}). ACK frames list ranges of received packets, like SACK without a size limit. A packet is declared lost when three later packets are acknowledged, or after 9/8 of an RTT ({{RFC 9002 s6.1|https://www.rfc-editor.org/rfc/rfc9002#section-6.1}}), and the congestion controller the RFC describes is close to TCP's NewReno ({{RFC 9002 s7|https://www.rfc-editor.org/rfc/rfc9002#section-7}}); implementations may plug in others.
  • Connections are named by connection IDs, not addresses, so they survive a change of address or port (connection migration, {{RFC 9000 s9|https://www.rfc-editor.org/rfc/rfc9000#section-9}}). The peer checks that the new path really reaches you (PATH_CHALLENGE and PATH_RESPONSE) before trusting it.
  • No amplification. Until it has validated the client's address, a server may send at most three times the bytes it has received ({{RFC 9000 s8.1|https://www.rfc-editor.org/rfc/rfc9000#section-8.1}}), which is one reason the client pads its first datagram to 1,200 bytes: it buys the server room for its certificate.

The QUIC run is real: aioquic 1.3.0 on loopback, a client and a small echo server, every UDP datagram logged with its size and source port, and both endpoints' qlog (QUIC's standard event log) recording the packet types and frames inside (src/meas/quic_migrate.py). Midway the client moves to a new UDP socket, which is what a NAT rebinding or a switch from Wi-Fi to mobile looks like to the server. The TCP side is drawn from the specification, not recorded: changing the source port means a different 5-tuple, which matches no socket at the server.

Costs, and when not to use it

QUIC runs in user space, encrypting and acknowledging every packet itself, so it spends more CPU per byte than kernel TCP with its offloads; some networks block or throttle UDP 443, so every client keeps a TCP fallback (it learns a server speaks HTTP/3 from an alt-svc header or a DNS HTTPS record, then races or falls back). And it hides its headers from network operators who used to read TCP's to debug ({{RFC 9312|https://www.rfc-editor.org/rfc/rfc9312}} discusses what remains visible). Inside a data centre on a clean network, kernel TCP is usually cheaper and simpler; between your own services, gRPC and most inference servers still use HTTP/2 over TCP. QUIC v2 ({{RFC 9369|https://www.rfc-editor.org/rfc/rfc9369}}, 2023) changes nothing functional; it exists so that middleboxes do not hard-code version 1. {{RFC 9221|https://www.rfc-editor.org/rfc/rfc9221}} adds unreliable datagrams inside a QUIC connection, for media and tunnels.

Debugging QUIC. Packet captures show only encrypted payloads; use the endpoints' logs instead: qlog files (aioquic, quic-go, Chrome's chrome://net-export) or SSLKEYLOGFILE to decrypt a capture in Wireshark. Symptom "HTTP/3 fast at home, slow or falling back in the office": UDP 443 blocked. This laptop's curl 8.7.1 has no HTTP/3 support at all, which the root page also notes.
