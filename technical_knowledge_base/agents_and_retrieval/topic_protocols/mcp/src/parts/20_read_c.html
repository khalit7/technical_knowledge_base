3. What a server offers, and what the client offers back

The three server primitives differ by who decides to use them, which is the single most useful way to remember them ({{server features|https://modelcontextprotocol.io/specification/2026-07-28/server}}):

PrimitiveControlled byMethodsckpt-tools example
ToolsThe model: it decides to call themtools/list, tools/calllist_checkpoints, evaluate_checkpoint, delete_checkpoint
ResourcesThe application: it decides what to read into context (a file picker, an attachment)resources/list, resources/templates/list, resources/readckpt://{run}/config, the run's YAML config
PromptsThe user: picked explicitly, often as a slash commandprompts/list, prompts/getpick_best(run)

Tools in depth

A tool definition has a name, an optional display title, a description written for the model, an inputSchema (JSON Schema, 2020-12 by default) and optionally an outputSchema and annotations. In the Python SDK you write none of the schemas by hand: the type hints are the schema. def list_checkpoints(run: str) -> list[Checkpoint] produced this input schema and a matching output schema with the four Checkpoint fields:

{"type":"object","properties":{"run":{"title":"Run","type":"string"}},"required":["run"],"title":"list_checkpointsArguments"}

Two copies of every structured result. With an output schema, the result carries structuredContent (JSON a program can use) and, for backward compatibility, the same data as text in content, which is what most hosts show the model. For three checkpoints the SDK sent three pretty-printed text blocks plus the structured copy: 818 bytes of result body for about 200 bytes of facts (measured). Every byte of content becomes model input tokens, so return short, task-shaped results and paginate.

Annotations are claims, not guarantees. readOnlyHint, destructiveHint, idempotentHint and openWorldHint (talks to the outside world) tell a host how careful to be: ckpt-tools marks delete_checkpoint destructive and idempotent. The specification is blunt: "clients MUST consider tool annotations to be untrusted unless they come from trusted servers" ({{tools|https://modelcontextprotocol.io/specification/2026-07-28/server/tools}}). A malicious server can mark a destructive tool read-only.

Names collide across servers. Tool names are only unique within one server (SHOULD be 1 to 128 characters of letters, digits, _ - .). Two servers that both offer search must be told apart by the host, for example by prefixing a server identifier; serverInfo.name is not unique and should not be used for this.

State without sessions. A shopping cart, an open browser or a database transaction spans several calls. With no session, the server returns an explicit handle (basket_id: "bsk_a1b2c3") and takes it back as an ordinary argument; the model carries it forward. The specification's advice: a handle is a name, not a password, so check on every call that it belongs to the caller; make it random; state its lifetime in the tool description; return a clear tool error when it has expired so the model can start again ({{stateful tools|https://modelcontextprotocol.io/specification/2026-07-28/server/tools#stateful-tools}}).

Order matters for cost. Servers SHOULD return tools/list in a deterministic order, because hosts paste the list into the model request, and a reordered list breaks the model provider's prompt cache.

Utilities

  • Progress: a request that carries a progressToken in _meta may receive notifications/progress before its result. ckpt-tools' evaluate_checkpoint sent three, which turned its HTTP reply into an event stream (section 4).
  • Cancellation: on stdio the client sends notifications/cancelled with the request id; on Streamable HTTP it simply closes that request's response stream. Either way the server must stop sending anything for that request.
  • Pagination: list results may carry nextCursor; the client sends it back as cursor.
  • Completion: argument autocompletion for prompts and resource templates.
  • Caching (new): list and read results carry ttlMs (how long the answer stays fresh) and cacheScope ("public": shareable by intermediaries; "private": only within the caller's authorization). ckpt-tools sends ttlMs: 300000, cacheScope: "public" on tools/list.
  • Logging: notifications/message, deprecated; log to stderr (stdio) or use OpenTelemetry.
  • Subscriptions (new): one long-lived subscriptions/listen request whose response stream delivers only the change notices the client opted into (toolsListChanged, resourceSubscriptions, ...). It replaced the old HTTP GET stream and resources/subscribe.
