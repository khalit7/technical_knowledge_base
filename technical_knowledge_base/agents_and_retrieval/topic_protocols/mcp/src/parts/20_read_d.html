4. The two transports

A transport (the specification also says binding) defines how messages are framed and delivered, how cancellation is signalled, and where request metadata lives. It never changes what the messages mean ({{transports|https://modelcontextprotocol.io/specification/2026-07-28/basic/transports}}).

stdio: a child process and two pipes

The host starts the server as a subprocess. The client writes one JSON-RPC message per line to the server's standard input; the server writes one per line to standard output. Messages must not contain raw newlines (JSON escapes them as \n). There is no network, no port and no authentication: the server runs as the user, with the environment the host gives it, which is also where its credentials come from (the authorization framework explicitly does not apply to stdio, {{stdio|https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio}}).

  • stdout is the protocol channel. The server "MUST NOT write anything to its stdout that is not a valid MCP message". Logs go to stderr, which the client may show or ignore. One stray print() corrupts the stream: the root page's {{Failure lab|n:3c65c17b0d0d81ec9355f4eecd6eed02}} case "MCP over stdio: stdout pollution" shows a hand-written server whose debug print glued itself to a response, which the client then dropped and timed out on.
  • Shutdown: the client closes the server's stdin, waits, then sends SIGTERM and finally SIGKILL. A server should exit when stdin reaches end of file.
  • Crash: the client restarts the process. Because the protocol is stateless, in-flight requests are simply lost and can be retried.
  • The same newline-delimited framing is recommended for custom transports over Unix sockets or TCP.

Streamable HTTP: one POST per message

The server exposes one URL, the MCP endpoint (for example https://mcp.example.com/mcp). Every client message is its own HTTP POST with Accept: application/json, text/event-stream. The server answers each request either with one JSON object or with a server-sent events (SSE) stream scoped to that request, carrying progress notifications and then the final response ({{Streamable HTTP|https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http}}; SSE itself is taught on {{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}).

Headers that mirror the body. Every POST carries MCP-Protocol-Version, Mcp-Method and, for tools/call, resources/read and prompts/get, Mcp-Name. They exist so an ordinary load balancer, gateway or firewall can route, rate-limit or block by tool without parsing JSON. A tool may also ask for an argument to be copied into a header with x-mcp-header (for example a region, so a gateway can route to the right cluster); sensitive values must not be marked this way, since intermediaries see headers. Because two components could disagree about which copy is true (a gateway allows by header, the server executes by body), servers MUST reject a mismatch with 400 and -32020 HeaderMismatch.

Three of these deserve a word. The Origin check stops a web page you happen to visit from calling a server on your laptop: browsers attach Origin to cross-site requests, and the specification requires a 403 for an invalid one. The Host check (421 Misdirected Request) stops DNS rebinding, where an attacker's domain is made to resolve to 127.0.0.1 after the page loads ({{DNS|n:3c65c17b0d0d812387d8f92b546f07af}} explains the trick); the specification also says local servers should bind to 127.0.0.1, not 0.0.0.0. And a header that names an older protocol version was not treated as a header mismatch: this dual-era server took it as a legacy request and asked for a session ID. Intermediaries that route on headers should therefore reject versions older than 2026-07-28, as the specification advises, rather than trust unvalidated headers.


Behind a proxy. Servers SHOULD send X-Accel-Buffering: no on event streams so nginx-style proxies pass events immediately (the legacy recording shows the header). Long-lived streams (subscriptions/listen) should send a comment line : now and then so idle timeouts do not cut them. Streams are not resumable any more: Last-Event-ID was removed, and a broken stream loses its request, which the client re-sends with a new id.

Warm: median and 90th percentile of 300 calls on an open client. Bytes: one warm call, request and response on the wire including HTTP headers (TCP tap) or the pipe lines (tee). What the numbers say: on one machine every transport answers in one to three milliseconds, far below a model call's hundreds of milliseconds, so transport choice is about deployment, not speed. stdio's cost is the process start (and a process per user per server); HTTP's is the network, TLS and authorization you must add to leave the laptop. The legacy session mode pays an extra round trip at the start (initialize, then the initialized notice, then the GET stream) and SSE framing on every reply.


Choosing
stdio when the server works on the user's own files and accounts (a code editor's tools, a local database) and should run with exactly the user's rights. Streamable HTTP when many users or agents share one server, when the data lives in a service, or when credentials must stay off the user's machine. The deprecated 2024-11-05 HTTP+SSE transport (two endpoints: a GET stream and a POST URL) should not be used for anything new.
