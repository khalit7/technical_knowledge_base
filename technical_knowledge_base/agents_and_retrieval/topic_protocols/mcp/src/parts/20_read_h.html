8. Security: where trust breaks, and what holds it

MCP connects a system that follows instructions written in text (the model) to systems that act (tools). Most of its security problems follow from two facts in section 1: whatever a tool returns becomes part of the model's context, and whatever a server says about its tools shapes what the model does. The protocol can carry the right signals (consent, audiences, annotations), but the decisions are the host's. The clearest way to organise the risks is by who the attacker is.

AttackerRiskWhat holds
Whoever wrote content a tool reads (a web page, an issue, an email, a file)Indirect prompt injection: instructions hidden in data reach the model as if they were part of the task. Becomes data theft when one agent has private data, untrusted content and a way to send data out: Simon Willison's "lethal trifecta" ({{16 June 2025|https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/}}). The root page records the bytes of such a tool result ({{Topic: protocols, section 9|n:3c65c17b0d0d81ec9355f4eecd6eed02}}).Remove a leg of the trifecta for each task: scope the tools a session can see, keep secrets out of reach, restrict where data can be sent. Confirm consequential actions with the user, showing the exact arguments. No filter reliably detects injected text; design as if it gets through.
The server itself (malicious, compromised or updated)Tool poisoning: instructions hidden in a tool's description, which the model reads but users rarely do (named by Invariant Labs, {{1 April 2025|https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks}}). Rug pull: a definition that changes after the user approved it. False annotations: a destructive tool marked read-only. And a local server is a program running with your rights.Install servers like any dependency: from known publishers, pinned versions. Show users full tool descriptions; record a hash of each approved definition and ask again when it changes (listChanged notices and ttlMs tell a host when to re-check). Treat annotations from untrusted servers as untrusted (the specification's MUST). Run local servers in a sandbox or container with only the files and network they need.
A web page in the user's browserReaching a server on localhost: by cross-site requests or DNS rebinding. The real case: MCP Inspector, the official debugging tool, let unauthenticated requests to its local proxy launch commands over stdio; CVE-2025-49596, fixed in 0.14.1 ({{NVD|https://nvd.nist.gov/vuln/detail/CVE-2025-49596}}, CVSS 4.0 score 9.4).Validate Origin and Host (the SDK does by default: 403 and 421 in section 4), bind to 127.0.0.1, require a token even on localhost, or use stdio, which has no listening socket at all.
A malicious remote server, against the clientHostile metadata: OAuth URLs and endpoints come from the server, so a client that opens or fetches them carelessly can be led to internal addresses (server-side request forgery, for example a cloud metadata endpoint) or, with unsafe URL handling, to running commands. The real case: mcp-remote, a widely used bridge, was open to OS command injection from a crafted authorization_endpoint; CVE-2025-6514 ({{NVD|https://nvd.nist.gov/vuln/detail/CVE-2025-6514}}, CVSS 3.1 score 9.6).Accept only https: URLs for OAuth endpoints (loopback excepted in development); open authorization URLs only through the system browser, never a shell; for clients running on servers, block private and link-local addresses when fetching metadata; validate the issuer of every metadata document (section 7).
A malicious client or a network intermediaryConfused deputy: an MCP server that proxies a third-party API with one shared OAuth client can be tricked into using a user's earlier consent for an attacker's client. Token passthrough. Forged state: a tampered requestState or a guessed state handle. Header and body disagreeing so a gateway allows one thing and the server does another.Per-client consent recorded by the proxy server, exact redirect URI matching; audience-bound tokens, no passthrough; integrity-protected requestState (the SDK's default; a forgery was rejected in section 5) and handles bound to the authenticated user; reject header mismatches (-32020, measured in section 4).

The specification's {{security best practices|https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices}} page treats the protocol-level items in depth: confused deputy, token passthrough, SSRF, state handle hijacking (the 2026-07-28 replacement for the old "session hijacking"), local server compromise, OAuth URL validation, stdio in proxy setups, mix-up attacks, localhost redirect impersonation, CIMD trust and scope minimisation.

A defensive checklist for a host

  • Show which servers and tools are active, and show tool inputs before sensitive calls; the specification asks for a human able to deny any tool call.
  • Expose per task only the tools the task needs; do not combine tools that read private data with tools that read untrusted content and tools that send data out, unless a human approves each outbound action.
  • Give each server its own credentials with the least scope, from the environment or OAuth, never the user's master tokens; prefer short-lived tokens.
  • Run local servers with restricted file system and network access; show the exact command before adding a server from a one-click link.
  • Pin and diff tool definitions; prefix tool names by server to avoid collisions.
  • Log every tool call with its arguments and result size, so an incident can be reconstructed; set time limits on tool calls.
  • Treat irreversible actions (deleting, paying, sending, moving hardware) as a different class: confirmation outside the conversation, so text in the context cannot approve them. The root page's note on agents driving instruments makes the same point.

"Session hijacking" is now state handle hijacking in the 2026-07-28 best practices, since sessions are gone. The old page's statement that statelessness "removes much of this class" is half right: guessable session IDs are gone, but guessable handles take their place.
