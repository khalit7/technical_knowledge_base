The idea in one screen

MCP is a small JSON-RPC contract between an AI application (the host) and the programs that give it tools and data (servers): the model never speaks it, the host translates and decides, and since revision 2026-07-28 every request carries everything about itself, so a remote server is an ordinary stateless web service protected as an OAuth resource server.

The model sees tool definitions; the host runs one client per server and holds the policy

The running example, ckpt-tools, is a server an ML team might run so an agent can list, evaluate and delete training checkpoints (its checkpoint table is illustrative; nothing is deleted). Numbers 1 to 4 are one tool call (section 1). The blue arrows are MCP; the arrow to the model is the model API's own tool format. A server sees only the requests sent to it, never the conversation and never other servers.

You need HTTP requests, status codes and proxies ({{HTTP|n:3c65c17b0d0d811bb035fa3f158b0889}}), server-sent events ({{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}) and OAuth 2.1 with PKCE ({{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}), only for sections 4 and 7. Labels: measured means recorded on this page's laptop (Apple M1 Pro, macOS 27, Python 3.13, official Python SDK mcp 2.3.0, and 1.30.0 for the legacy side) on 5 October 2026, scripts in src/lab/; all servers ran on 127.0.0.1 and no model was called, so wherever a model or a user would decide something, the decision is scripted and labelled.

MCP in one screen (eight questions, short answers, where each is taught)
QuestionShort answerSection
What does the model actually see?Never MCP. The host turns MCP tool definitions into the model API's tool list, and tool results into tool-result blocks.1
What travels?JSON-RPC requests, results, errors and notifications; since 2026-07-28 every request carries its protocol version and the client's capabilities in _meta.2
Local or remote?stdio for a server on your machine (no network, credentials from the environment); Streamable HTTP for a shared remote server (OAuth, load balancers, gateways).4
Why the 2026 redesign?Sessions pinned a client to one replica. Measured here: a round-robin balancer in front of two replicas broke 20 of 20 old-style calls and 0 of 20 new-style calls, once the replicas shared the key that seals request state.5
Will old and new interoperate?A dual-era client talks to anything; a modern-only client cannot talk to a legacy server and a legacy client cannot talk to a modern-only one. All 9 pairings were run.6
How is a remote server protected?A 401 points the client to the server's metadata, then to its authorization server; authorization code with PKCE; a token bound to that one server (RFC 8707); never passed through.7
What is the real risk?Text from tools is untrusted input in the model's context; servers are code you run; descriptions and annotations are claims, not guarantees.8
How do I build one?Python SDK 2.3.0: decorate typed functions; test in process; serve stdio first; add Streamable HTTP, auth and a shared state key to deploy.9, 10
