HTTP is the language your code and an LLM API speak: a request ("do this to that thing") and a response ("here is the result, and here is what you may do with it"). The meaning of that language has been stable for decades. What changed, three times, is how the words are cut into bytes on the wire, and every change was made to stop one slow or lost thing from holding up everything behind it.

The running example. A chat app sends "What colour is the sky?" as one streaming request, POST /v1/messages with a 117-byte JSON body, and the answer comes back as five tokens, one every 50 ms after a 120 ms wait that stands in for the model reading the prompt. The server is the root page's stand-in (its {{On the wire|n:3c65c17b0d0d81ec9355f4eecd6eed02}} tab built it), run here with a few extra knobs: a longer think time, keep-alive pings, injected errors. No model runs and no real API is called, except one read-only request to three public LLM hosts in section 10.

What does a request mean?A method (POST, GET), a target, header fields and maybe a body. The method says whether a retry is safe: GET yes, POST (every LLM generation) no.2
Why three versions?HTTP/1.1 sends text, one request at a time per connection. HTTP/2 cuts requests into binary frames that share one connection and compresses headers. HTTP/3 does the same over QUIC so one lost packet only stalls its own request.4 to 6
What does each version cost in bytes?measured The running request's headers: 160 bytes of text every time on HTTP/1.1; 69 then 7 bytes on HTTP/2 (HPACK remembers them); 59 then 9 on HTTP/3 (QPACK, plus a one-off copy on a side stream).5, 6
Who is between me and the model?Usually several HTTP proxies: an SDK, maybe a corporate proxy, a CDN, a load balancer, an ingress. Each can rewrite the request, buffer the stream, and cut it with its own timeout. All three public LLM APIs answered through a front proxy today.7, 10
Why do long generations die?The smallest timeout on the path wins. Most are idle timeouts that every streamed byte resets, so streaming plus keep-alive pings keeps a slow answer alive; some (Google Cloud's 30 s backend timeout, API Gateway's 29 s) count the whole response and streaming does not help.8, {{Timeout chain|#t-chain}}
When is a retry safe?When the server provably did not start (connection refused, HTTP/2 REFUSED_STREAM or a GOAWAY above your stream, 425 Too Early) or the method is idempotent. A read timeout on a POST is not safe, yet both official Python SDKs retry it: measured the server ran the request three times.9
Five things to remember
  1. Meaning (RFC 9110) and wire format (RFC 9112, 9113, 9114) are specified separately: your code sees the meaning, your latency and your proxies see the wire.
  2. Every version fixed one kind of head-of-line blocking: HTTP/1.1 requests queue behind each other on a connection, HTTP/2 streams queue behind a lost TCP packet, HTTP/3 removes that.
  3. A proxy is a full HTTP participant: it re-parses, rewrites, re-frames and times out. Two parsers that disagree about where a message ends are a security hole (request smuggling).
  4. Know every timeout on the path and whether it counts silence or total time.
  5. Retries are a protocol question first: did the server start the work? If you cannot know, you need an idempotency key.

1. A message, piece by piece

The problem. Two programs that have never met need to agree on what is being asked, about which thing, with what extra conditions, and where the request ends. HTTP's answer is a message: a start line, a list of header fields (name, colon, value), a blank line, and an optional body. The program that sends requests is the client; the one that answers is the server, and the server that actually owns the resource (here, the model API) is the origin. Everything in between that receives a message and sends it on is an intermediary; each leg between two of them is a hop.

The URL, split. https://api.llm.test/v1/messages has a scheme (https: HTTP over TLS, default port 443), an authority (api.llm.test, the host and an optional port) and a path (/v1/messages), optionally followed by a query (?limit=20). HTTP/1.1 puts the path in the start line and the authority in the Host field; HTTP/2 and HTTP/3 carry all of them as pseudo-headers (:method, :scheme, :authority, :path), fields whose names start with a colon. One server can host many names, which is why Host is mandatory: an HTTP/1.1 request without it gets 400 (RFC 9112 section 3.2; measured both nginx and hypercorn answered 400, section 7).

Where does the body end? A connection is a byte stream with no built-in boundaries, so every HTTP version must say where a body stops. HTTP/1.1 has three ways: a Content-Length (the request above: 117), chunked transfer coding (the response above: each piece prefixed by its size in hexadecimal, ending with a zero-size chunk), or closing the connection. HTTP/2 and HTTP/3 instead put the body in DATA frames and mark the last one with an end-of-stream flag. Getting this boundary wrong is the root of the worst HTTP bugs (request smuggling).
