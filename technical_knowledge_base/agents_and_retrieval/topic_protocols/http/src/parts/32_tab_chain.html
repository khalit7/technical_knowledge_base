Timeout chain: which hop ends a long generation?

Pick what sits on the path and what the model does; the lab replays the bytes the client would receive and runs every hop's timer against them. The first timer to fire ends the request. Does the model match reality?

The same model, run on the cases measured for the Reading (nginx 1.31.6 with a 2 s idle timeout, curl and httpx against the lab server), predicts each outcome independently; the measurement is not an input.

model Assumptions, stated: the server sends the response head the moment it accepts a streamed request (the lab server does; most streaming APIs do) and nothing else until the first token, unless pings are on; an idle timer starts when the request is sent and restarts on every byte; a first-byte timer stops when the head arrives; a total timer never restarts. Real hops add detail this leaves out: connect and TLS timeouts, keep-alive races, proxies that buffer and so delay bytes to the next hop, and retries by intermediaries.
