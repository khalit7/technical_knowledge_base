The idea in one screen

HTTP is one fixed meaning (a method on a resource, header fields, a body, a status) carried by three wire formats, and re-sent by every proxy on the path: HTTP/1.1, 2 and 3 differ only in how they stop one slow or lost thing from holding up the rest, and whether a long LLM answer arrives is decided by the smallest timer on the path and by whether a failed request was provably never started.

One request, one meaning, re-framed and re-timed on every hop

illustrative path, with each hop's documented default (sources in section 9). The meaning at the top is identical on every hop; the wire format is chosen per connection (5 to 7); every box is a full HTTP participant that re-parses, rewrites, buffers and can answer with its own error (8). Here the first timer to fire on 60 s of silence is nginx's or the load balancer's, whatever the SDK allows.

You need TCP and QUIC as transports ({{Networking foundations|n:3c65c17b0d0d8117b21dcb9041879564}}) and, for https, the TLS handshake that picks the HTTP version (ALPN, {{TLS and certificates|n:3c65c17b0d0d8105a37ff2d2f602a421}}). The whole stack on one request is {{Topic: protocols|n:3c65c17b0d0d81ec9355f4eecd6eed02}}; this page owns HTTP in depth. The running example: a chat app sends "What colour is the sky?" as one streaming POST /v1/messages with a 117-byte JSON body; five tokens come back, one every 50 ms after a 120 ms wait standing in for the model. The server is the root page's stand-in LLM API (its {{On the wire|n:3c65c17b0d0d81ec9355f4eecd6eed02}} tab built it), with extra knobs: think time, keep-alive pings, injected errors. Stream, frame
one request and its response inside a shared HTTP/2 or 3 connection; the typed, length-prefixed pieces it travels in
Head-of-line blocking
one slow or lost item holding up everything queued behind it
Idle vs total timeout
a timer every byte resets, against one that counts the whole response
Idempotency key
a unique id on a POST so the server can recognise a retry and return the stored result
HTTP in one screen (six questions, short answers, where each is taught)
QuestionShort answerSection
What does a request mean?A method, a target, header fields, maybe a body. The method says whether a retry is safe: GET yes, POST (every LLM generation) no.2
Why three versions?HTTP/1.1 sends text, one response at a time per connection. HTTP/2 cuts requests into binary frames that share one connection and compresses headers. HTTP/3 does the same over QUIC, so one lost packet stalls only its own request.5 to 7
What does each cost in bytes?measured The running request's headers: 160 bytes of text every time on HTTP/1.1; 69 then 7 bytes on HTTP/2 (HPACK remembers them); 59 then 9 on HTTP/3 (QPACK, plus a one-off copy on a side stream).6, 7
Who is between me and the model?Usually several proxies (an SDK, a corporate proxy, a CDN, a load balancer, an ingress), each able to rewrite, buffer and cut the stream. All three public LLM APIs answered through a front proxy.8, 11
Why do long generations die?The smallest timeout on the path wins. Idle timeouts are reset by every streamed byte, so streaming plus pings keeps a slow answer alive; total timeouts (Google Cloud's 30 s backend timeout, API Gateway's 29 s) are not.9
When is a retry safe?When the server provably did not start (connection refused, REFUSED_STREAM, a stream above GOAWAY, 425 Too Early) or the method is idempotent. A read timeout on a POST is not safe, yet both official Python SDKs retry it: measured the server ran the request three times.10
