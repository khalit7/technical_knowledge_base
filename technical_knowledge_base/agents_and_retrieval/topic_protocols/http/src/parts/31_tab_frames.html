Frame by frame: the running request on HTTP/1.1, HTTP/2 and HTTP/3

Every unit that crossed the connection when the running request was sent, recorded from the bytes themselves and decoded field by field. On HTTP/2 and HTTP/3 the same connection then carried the request a second time and twice more at once, so you can watch the header tables fill and the streams interleave. Step through, or tap any line in the list.

How to read it. ▶ client to server, ◀ server to client; times in ms from the first byte sent. HTTP/2 frames were parsed from the bytes the h2 library wrote to and read from the TLS socket (RFC 9113 section 4.1 frame layout); header blocks were decoded by src/lab/hpack_parse.py, which reports each field's representation and checks its result against the hpack library. HTTP/3 frames were split from the bytes on each QUIC stream as aioquic sent and received them (RFC 9114 section 7.1); QPACK field lines are classified by RFC 9204 section 4.5 (names are not repeated here because QPACK references them by index). HTTP/1.1 is the root page's plain-text recording, cut where each recv() returned. What this cannot show: TCP segments, TLS records and QUIC packets below the frames (packet capture needs root here); the root's {{On the wire|n:3c65c17b0d0d81ec9355f4eecd6eed02}} tab sizes those.
