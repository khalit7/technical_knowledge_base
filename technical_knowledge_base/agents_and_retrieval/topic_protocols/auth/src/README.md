## Shape and why
Child page method (Part B of `html_utils/methods/topic_pages.md`): Reading organised by the subject's own logic (words, the credential kinds from simplest to most bound, then delegation, then the agent era, then debugging and interviews), one tab per standalone visual. Departure: the reader asked to be taught from zero, so sections 1 to 3 cover basics a specialist page would skip; each section stands alone and opens with the problem it solves.

## The lab (`lab/`)
All on 127.0.0.1, ports 30601 to 30614 (this page's range 30600 to 30699); keys live only in the scratch `KEYDIR`.
| File | What |
|---|---|
| `as_server.py` | OAuth 2.1 AS: RFC 8414 metadata, code + PKCE S256 with RFC 9207 iss, CIMD client ids, refresh rotation with reuse detection, client credentials (Basic, private_key_jwt), device grant, token exchange, DPoP, introspection, revocation. Simulated user alice auto-approves; device interval 1 s |
| `mcp_server.py` | MCP server on the official Python SDK 2.3.0 in resource-server mode; tools read_file, inbox_passthrough (the anti-pattern, lab only), inbox_exchange |
| `upstream.py` | mail API (strict and naive checks), DPoP-protected notes API |
| `cimd_host.py` | HTTPS host for the client's metadata document (throwaway CA) |
| `tap.py` | byte-recording TCP proxy in front of the AS, MCP server and upstream |
| `run_sdk_flow.py` | the SDK client (OAuthClientProvider with a CIMD URL); phases A to E |
| `run_flows.py` | scripted flows R, P, V, C, D, W |
| `jwt_cases.py` | the twelve JWT cases, both verifiers, algorithm sizes and timings, weak-secret guessing rate |
| `small_calcs.py` | SigV4 against botocore's test vectors, PKCE (RFC 7636 appendix B), lab API key, device user-code entropy |
| `fetch_inputs.py` | public inputs into `../inputs/` (read-only GETs) |
| `keys.py`, `start.sh`, `stop.sh`, `common.py` | keys, start and stop (stop kills only the PIDs start recorded) |
Outputs: `lab/out/*.json` (embedded byte for byte; access-token JWTs in the wire log are shortened by `make_data.py`).

## What could not be seen or was simulated
- The browser and the user: a script fetched the authorization URL; the AS approved as alice. No login page, no consent page.
- The AS's fetch of the client metadata document went over TLS and was not tapped (described, not shown).
- The CIMD URL uses `https://localhost:30613` with a throwaway CA; the spec requires HTTPS, which this honours, but the CA is local.
- The naive JWT verifier's `jku` "fetch" and `kid` file read are dictionary lookups (nothing left the machine).
- Timings are one laptop (Apple M1 Pro), one core, Python.

## Findings worth passing on
- MCP Python SDK 2.3.0: `AuthSettings.validate_token_resource` is off unless set (warning; default True promised for 3.0). The SDK client still sends `redirect_uri` in the token request (dropped in OAuth 2.1 draft-16). The SDK server answers a token-less request with `error="invalid_token"` (RFC 6750 s3.1 says SHOULD NOT include an error code then).
- Microsoft's common OIDC discovery document (fetched 2026-10-05) has no `code_challenge_methods_supported`: an MCP client following 2026-07-28 literally must refuse to proceed.
- Google's discovery document still advertises `response_type=token` and PKCE `plain`.
- The MCP spec cites CIMD draft -00 and OAuth 2.1 draft -13; current are -02 (2026-07-06) and -16 (2026-09-03).
