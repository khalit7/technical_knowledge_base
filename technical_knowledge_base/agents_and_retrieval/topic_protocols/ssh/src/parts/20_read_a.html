The idea in one screen

SSH is one encrypted TCP connection in which the server first proves who it is with its host key, you then prove who you are with a key or certificate, and any number of independent channels (a shell, a file copy, a tunnel) then share that pipe. Every cluster pattern on this page is a way of nesting or reusing those channels: ProxyJump runs a second, end-to-end SSH session inside a channel of the first, ControlMaster lets later commands open channels on a pipe that is already authenticated, and port forwarding carries TCP connections as channels.

One login to a GPU node behind a bastion: the bastion carries the node's session as one channel, and reads none of it.

The lab this page was recorded on: a laptop, a bastion published on 127.0.0.1:30922, and two compute nodes on an internal network the laptop cannot route to (gpu-node-01 runs a token-protected stand-in for Jupyter; gpu-node-02 plays an old login node). Each session has the same three layers (section 1): transport (key exchange and host key), user authentication, connection (channels).

Seven rules this page records

1. Never click through a changed host key; use host certificates where nodes churn (3, 4). 2. ProxyJump, not agent forwarding (6). 3. Turn on ControlMaster: [[mux_n]] ms to [[mux_reuse]] ms per command (7). 4. Loopback is shared by every user of a node: serve notebooks on a private Unix socket (8). 5. Short-lived certificates beat authorized_keys at scale (4). 6. Post-quantum key exchange is already the default and costs nothing measurable (11). 7. Patch, and keep port 22 off the internet: pre-authentication bugs ignore your keys (12).

New terms on this page
bastion, jump host
The one machine reachable from outside, through which you reach the private network: a hardened machine whose one job is to let authenticated people through.
host key
The server's long-term key pair; proves the server's identity in every key exchange.
known_hosts
The client's list of host keys it trusts (trust on first use), or @cert-authority lines.
TOFU
Trust on first use: accept a key the first time, insist on it afterwards.
authorized_keys
The server-side list of user public keys allowed to log in to an account.
agent
ssh-agent: holds decrypted private keys and signs on request over a Unix socket.
certificate (SSH)
A public key plus key ID, principals, validity and options, signed by a CA key; not X.509.
principal
A name a certificate is valid for: a user account (user certificates) or a host name (host certificates).
KRL
Key revocation list: a compact file of revoked keys and certificate serials.
channel
One independent stream inside an SSH connection: session, direct-tcpip, forwarded-tcpip, agent, X11.
ProxyJump
Reach a host through another by tunnelling a second, end-to-end SSH session through a direct-tcpip channel.
ControlMaster
Connection multiplexing: later clients reuse one authenticated connection through a control socket.
session identifier
The hash of the first key exchange; signatures in user authentication cover it, binding them to one connection.
strict KEX
OpenSSH 9.6's fix for Terrapin: no unexpected handshake messages, sequence numbers reset at each key exchange.
hybrid key exchange
A classic and a post-quantum exchange run together, the secret derived from both, so it is at least as strong as either.
How this page was recorded
SSH (Secure Shell, protocol version 2) runs on TCP, by default on port 22, and the implementation almost everyone uses is OpenSSH (client ssh, server sshd); the current release is 10.5, of 11 August 2026 ({{OpenSSH release notes|https://www.openssh.com/releasenotes.html}}). The laptop client is OpenSSH 10.3p1 (macOS); the bastion and gpu-node-01 run OpenSSH 10.5p1 (Alpine edge), gpu-node-02 runs Alpine 3.20's patched 9.7p1, configured with no post-quantum key exchange to play an old node. The lab account is called dev, a second local user alice. Every ssh call used -F with the lab's own config, so no personal key or known_hosts was touched; private keys never left the lab directory. An observer was simulated with a small relay on the laptop that decodes the SSH packets until encryption starts (no packet capture tool was used, so nothing below the TCP payload is shown). Where a delay is stated, 40 ms was added to the bastion's outward link with tc netem. Installing Jupyter adds nothing to the protocol story, so the notebook is a token-protected Python web server. Logs are verbatim except that the lab directory is written $LAB and the laptop's name laptop; -vvv logs are trimmed of per-packet lines; addresses such as 172.21.0.2 are the containers' private network. Scripts and raw outputs: src/lab/, src/raw/; rerun with src/run_all.sh.
