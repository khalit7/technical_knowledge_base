Glossary

AEAD
Authenticated encryption with associated data: a cipher that encrypts and adds a tag detecting any change (AES-GCM, ChaCha20-Poly1305).
ALPN
Application-Layer Protocol Negotiation: the ClientHello extension that picks http/1.1, h2 or h3 inside the handshake.
ACME
Automatic Certificate Management Environment (RFC 8555): the API for getting certificates; ARI (RFC 9773) adds suggested renewal windows.
CA, root, intermediate
Certificate authority; a root is a self-signed CA certificate in a trust store; an intermediate is a CA certificate signed by a root that issues leaves.
CAA
DNS record naming which CAs may issue for a domain (RFC 8659).
Certificate Transparency, SCT
Public append-only logs of every public certificate; an SCT is a log's signed promise, embedded in the certificate.
CertificateVerify, Finished
The signature over the handshake transcript with the certificate's key; the HMAC over the transcript proving both sides saw the same handshake.
Cross-signing
One CA certificate signed by another CA as well, so older clients can still build a path to a root they know.
DV, OV, EV
Domain, organisation and extended validation levels of a certificate; only domain control matters technically.
ECH
Encrypted Client Hello (RFC 9849): encrypts the real SNI and ALPN under a key published in DNS.
EKU
Extended Key Usage: what a certificate may be used for (serverAuth, clientAuth).
Forward secrecy
Past sessions stay secret even if long-term keys leak later; from ephemeral key exchange.
HelloRetryRequest
The server's request for a new ClientHello with a key share for another group; costs a round trip.
HKDF
HMAC-based key derivation function: turns the shared secret and the transcript hash into all TLS keys.
Hybrid key exchange
A classical and a post-quantum exchange run together, both mixed into the secret (X25519MLKEM768).
KEM, ML-KEM
Key encapsulation mechanism; ML-KEM (FIPS 203) is the lattice-based post-quantum one.
KeyUpdate
TLS 1.3 message that moves a direction to a new key without a new handshake.
ML-DSA, SLH-DSA
Post-quantum signature standards (FIPS 204, FIPS 205).
MPIC
Multi-perspective issuance corroboration: CAs validate from several network locations.
MTC
Merkle Tree Certificates: batches signed once, handshakes carry an inclusion proof; the planned path to post-quantum authentication.
mTLS
Mutual TLS: the client also presents a certificate and signs the transcript.
OCSP, CRL, stapling
Online status query; published revocation list; server-attached OCSP answer.
PSK, session ticket
Pre-shared key from an earlier session, carried in an opaque ticket, used for resumption.
SAN
Subject Alternative Name: the names (DNS, IP, URI) a certificate is valid for; the only place hostnames are checked.
SNI
Server Name Indication: the host name in the ClientHello, in clear unless ECH is used.
SPIFFE, SVID, SPIRE
Workload identity standard (a URI), the certificate carrying it, and the reference issuer.
Trust store
The set of root certificates a client trusts; differs per OS, browser and runtime.
0-RTT, early data
Application data sent in the first flight of a resumed connection; replayable.
