TLS in one screen

Your code sends POST /v1/messages with an API key and a user's words. Between your laptop and the API sit a Wi-Fi router, an internet provider, maybe a corporate proxy and several cloud hops; any of them could read those bytes, change them, or pretend to be the API. TLS (Transport Layer Security) is the layer that stops all three. It runs on top of TCP (or inside QUIC for HTTP/3), under HTTP, and it is the "S" in HTTPS. The current version is TLS 1.3, re-published in July 2026 as {{RFC 9846|https://www.rfc-editor.org/rfc/rfc9846}}, which replaced RFC 8446 (and TLS 1.2's RFC 5246).

Confidentiality

Nobody in between can read the request or the streamed tokens. Done with a symmetric cipher keyed by a secret the two ends agree on in public (section 1).

Integrity

Any changed, dropped or reordered byte is detected and the connection fails. Done with authenticated encryption: every record carries a tag.

Authentication

The client knows it reached the real api.anthropic.com: the server proves it holds the private key named in a certificate that a trusted authority signed (sections 4 and 5). With mutual TLS the client proves it too (section 7).

What to remember

  1. Two handshakes before the first byte. A new HTTPS connection costs TCP's round trip plus one for TLS 1.3 (two for TLS 1.2). Reuse connections: on this machine a request on a kept-alive connection took 0.05 ms against 1.4 ms with a fresh handshake, even with no network delay at all (section 10).
  2. Forward secrecy is built in. Every connection agrees on a fresh key; stealing the server's long-term key later does not unlock recorded traffic.
  3. A certificate binds a name to a public key, signed by a certificate authority (CA) your trust store already trusts. The client checks the signatures up to that root, the dates, and that the name it dialled is in the certificate's subject alternative names.
  4. Most TLS outages are certificate operations: expiry, a missing intermediate, a trust store that lacks a root, a clock that is wrong. Public certificates now last at most 200 days, falling to 47 by March 2029, so renewal must be automatic (ACME, section 5).
  5. 0-RTT early data can be replayed. Recorded here: one captured request replayed to nginx produced three more billed generations (section 3). Never accept a generation or a tool call as early data.
  6. Post-quantum key exchange is already on: 10 of the 12 public endpoints probed here (Anthropic, OpenAI, Google, Hugging Face and others) negotiated the hybrid X25519MLKEM768. Post-quantum certificates are years away because their signatures are large (section 8).
  7. Never "fix" a certificate error by disabling verification. Serve the full chain, or add the right CA to the right trust store; which variable each client reads is measured in section 9.
