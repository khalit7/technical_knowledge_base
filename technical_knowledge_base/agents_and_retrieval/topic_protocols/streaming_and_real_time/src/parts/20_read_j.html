What changed from the old pages

This page replaces two old written pages, "Real-time and event delivery: WebSockets, SSE, webhooks, long polling" and "WebSocket protocol (RFC 6455) in depth" (both last edited 2026-09-22, kept verbatim in the root's src/read/old/). Every fact was checked; src/coverage.json lists where each one lives now. Corrections and changes:

  • "RFC 6455 (STD 34) ... an Internet Standard". It is a Proposed Standard with no STD number ({{RFC Editor metadata|https://www.rfc-editor.org/rfc/rfc6455.json}}; the root's Protocol atlas made the same correction).
  • "WebTransport ... flagged in Firefox, absent in Safari ... worth watching rather than adopting now". The browser API is Baseline since March 2026: Chrome 97, Firefox 114, Safari 26.4 (MDN). The IETF protocol document is still a draft (revision 16).
  • "WebSockets over HTTP/3 (RFC 9220): no major browser or server has shipped" and the RFC 8441 browser versions (Chrome 67, Firefox 65, Safari 14.1): not confirmed today from a primary source; dropped, and the page says support was not checked.
  • "GPT-Live-1 (September 2026) ... full duplex over all four transports at $0.05 per minute". Partly confirmed: OpenAI's realtime docs point to a separate full-duplex model, gpt-live-1, with its own WebSocket endpoint. The date, the price and the transports other than WebSocket were not confirmed and are not stated.
  • "Roughly 300 KB of memory per connection" for permessage-deflate with context takeover: confirmed as 316 KiB at zlib's defaults by the websockets library's own measurements, which also show its default settings use 64 KiB.
  • "2 to 10 KB per idle connection ... 500k idle connections on a 16 GB node" and "scale out at 70 to 80 percent": no source found; dropped.
  • OpenAI-style data: [DONE] sentinel (unconfirmed on the root): confirmed in the OpenAI Python SDK and in vLLM's OpenAI-compatible server source.
  • Stripe retries "up to 3 days" (unconfirmed on the root): confirmed in Stripe's docs ("up to three days with an exponential back off in live mode").
  • "Respond 2xx fast (<~5-10 s)": no source gives that number. Stripe says "quickly ... before any complex logic"; Standard Webhooks recommends senders wait 15 to 30 s.
  • "1012, 1013 IANA-registered": confirmed, and 1014 (bad gateway) too.
  • EventSource auto-reconnect: true, and more than the old page said: it also reconnects after a stream ends normally (measured), so servers end it with 204 or clients close it.
  • "Interactive ML tooling rides on WebSockets: Jupyter, TensorBoard, Ray dashboard, Gradio, Streamlit, vLLM and Triton demo frontends": only Jupyter's kernel channels are kept, as an example; the rest were not checked.
  • "SameSite=Lax defaults (Chrome since 2020) block CSWSH incidentally" and Firefox's Total Cookie Protection: not checked today; the page recommends SameSite and Origin checks without relying on browser defaults.
  • Meteor DDP: confirmed against its specification (messages sub, added, changed, removed, ready, method, result, updated); "minimongo" and the list of modern sync engines are kept only as names.

Glossary

At least once: a delivery promise that allows duplicates but not loss; the receiver must deduplicate.
Backpressure: a slow consumer making a fast producer wait, instead of an unbounded queue growing.
Barge-in: the user speaking over a voice agent, which must stop and listen.
Close code: the 2-byte reason in a WebSocket close frame; 1006 is never sent, only reported locally.
Comment line: an SSE line starting with a colon; ignored by parsers, used as a keep-alive.
Context takeover: permessage-deflate keeping its compression state across messages.
CSWSH: cross-site WebSocket hijacking; another site's page using the user's cookies on your socket.
Cursor: a position the client sends back ("after event 3") so no event is missed between requests.
Datagram: a message sent once, with no retransmission or ordering.
Event (SSE): lines of field: value ended by a blank line.
EventSource: the browser's built-in SSE client; GET only, no custom headers, reconnects by itself.
Frame: the unit a WebSocket sends: a 2 to 14 byte header and a payload.
Heartbeat: traffic sent only to prove a connection is alive and keep middleboxes from closing it.
HMAC: a hash keyed by a shared secret; proves who sent a message and that it was not changed.
Idle timeout: a middlebox closing a connection that carried no bytes for some time.
Last-Event-ID: the header a reconnecting EventSource sends with the last id it saw.
Long polling: a request the server holds until it has news.
Masking: XOR of each client frame with a random 4-byte key, against cache poisoning.
Opcode: the 4-bit frame type: text, binary, continuation, close, ping, pong.
permessage-deflate: the WebSocket compression extension (RFC 7692).
Ping and pong: WebSocket control frames for heartbeats; a pong echoes the ping's bytes.
Polling: asking for news on a timer.
RST_STREAM: the HTTP/2 frame that cancels one stream without closing the connection.
Server push: getting data from server to client when the server has it, not when the client asks.
Server-Sent Events (SSE): a text/event-stream HTTP response that stays open and carries events.
SSRF: server-side request forgery; making a server fetch an internal URL for you.
Subprotocol: the application format inside a WebSocket, agreed by Sec-WebSocket-Protocol.
Sync engine: a client subscribing to a query and receiving diffs that keep a local copy current.
Thin payload: a webhook that says "X changed" and lets the receiver fetch X's current state.
Webhook: an HTTP POST a provider sends to your URL when an event happens.
WebRTC: the browser's real-time media stack, over UDP with jitter buffers and codecs such as Opus.
WebSocket: an HTTP/1.1 request upgraded (101) into a two-way message channel.
WebTransport: streams and datagrams for web pages over HTTP/3.
