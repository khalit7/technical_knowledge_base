MaxText 2: the model, and the running example inside it

The shape of the code. Transformer () is a Flax NNX module (MaxText "migrated to Flax NNX from Linen" in June 2026, ). It owns the token embedding and an NNXDecoder (layers/nnx_decoders.py, 2,943 lines) that embeds, runs the layers, applies the final norm and computes the logits. Which layer it runs is a config value, decoder_block, one of 25 DecoderBlockType values (), each mapped to a class in its family's file under models/: DecoderBlockType.GPT3: [gpt3.Gpt3DecoderLayer] (). The layers run inside jax.lax.scan over weights stacked on a layer axis, each call wrapped in jax.checkpoint with the configured remat policy (; section Scan and remat).

Attention is chosen at trace time. AttentionOp.apply_attention () uses plain dot-product attention (an einsum, a mask, a softmax, an einsum) when attention=dot_product, and also when attention=autoselected during decoding, for sequences under 128, or when the hardware is CPU (). Otherwise flash means the splash attention Pallas kernel on TPU (; the {{Pallas kernels|n:3fa5c17b0d0d817699fcf65d085402e7}} child page reads it) and cudnn_flash_te means Transformer Engine's cuDNN kernel on GPU. So the CPU runs on this page exercise every line of MaxText except the TPU kernels.

The running example as a MaxText model measured

The root's running example is GPT-2 shaped: pre-LayerNorm with biases, learned positions, biased projections, GELU MLP, untied head. MaxText's gpt3 block is the same family. These overrides on top of base.yml describe it:

decoder_block=gpt3 base_emb_dim=128 base_num_query_heads=4 base_num_kv_heads=4 head_dim=32
base_mlp_dim=512 base_num_decoder_layers=4 vocab_size=65 max_target_length=128
trainable_position_size=128 mlp_activations=[gelu] logits_via_embedding=false fused_qkv=false
enable_dropout=false dtype=float32 attention=dot_product normalization_layer_epsilon=1e-5

MaxText builds it with 826,368 parameters, the running example's count exactly, in 21 arrays instead of the running example's 69 because the four layers are stacked. Copying the running example's initial weights in (runs/lc_fwd.py) and running MaxText's forward pass on the first training batch (32 × 128 characters) gives logits within of the root's plain-JAX twin, and a loss of against the running example's .   • Layout. PyTorch stores a linear weight as [out, in]; MaxText's DenseGeneral as [in, out...] with the output split into named axes ([embed, heads, kv]). Transpose, then reshape.
  • Stacking. With scan_layers=true every per-layer weight gains a layers axis at position param_scan_axis = 1 (), so four [128, 128] query weights become one [128, 4, 4, 32] array. Checkpoint converters exist for this reason.
  • An offset scale. Gpt3LayerNorm initialises its scale to zeros () and multiplies by scale + 1 (). Copy PyTorch's weight unchanged and every LayerNorm doubles its output. Subtract 1. (It also means weight decay pulls this scale toward 1, not toward 0.)
  • The activation. mlp_activations=[gelu] resolves to getattr(jax.nn, "gelu") (), and jax.nn.gelu defaults to the tanh approximation, while the running example (like PyTorch) uses the exact erf form. No MaxText flag spells exact GELU. Against the exact-GELU running example the logits differ by up to ; switch the twin to tanh GELU and the difference falls to , float32 rounding. The whole gap is the activation.

One thing that looks different and is not: MaxText divides the query by √head_dim right after the projection () where the running example divides the scores; the product is the same. Both runs set matmul_precision=highest (no effect on CPU, where float32 dots are exact float32). What transfers to TPU: every conversion above. What does not: on TPU the default precision runs float32 matmuls in bfloat16 passes, so a TPU comparison needs highest or a looser tolerance.
