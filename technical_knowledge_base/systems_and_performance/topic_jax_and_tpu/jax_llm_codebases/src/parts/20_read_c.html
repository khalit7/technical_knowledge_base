2. The model, with the running example inside it

Transformer () is a Flax NNX module (MaxText "migrated to Flax NNX from Linen" in June 2026, ) owning the token embedding and an NNXDecoder (layers/nnx_decoders.py, 2,943 lines). Which layer it runs is a config value, decoder_block, one of 25 DecoderBlockType values () each mapped to a class: DecoderBlockType.GPT3: [gpt3.Gpt3DecoderLayer] (). The layers run inside jax.lax.scan over stacked weights, each wrapped in jax.checkpoint with the configured remat policy (; section 5). Attention is also chosen at trace time, by attention= and the hardware.

The running example as a MaxText model measured. The root's model is GPT-2 shaped (pre-LayerNorm with biases, learned positions, GELU MLP, untied head), the family of MaxText's gpt3 block. These overrides describe it:

decoder_block=gpt3 base_emb_dim=128 base_num_query_heads=4 base_num_kv_heads=4 head_dim=32
base_mlp_dim=512 base_num_decoder_layers=4 vocab_size=65 max_target_length=128
trainable_position_size=128 mlp_activations=[gelu] logits_via_embedding=false fused_qkv=false
enable_dropout=false dtype=float32 attention=dot_product normalization_layer_epsilon=1e-5

MaxText builds 826,368 parameters, the running example's count exactly, in 21 arrays instead of 69 because the four layers are stacked. With the running example's initial weights copied in (runs/lc_fwd.py), MaxText's forward pass on the first batch (32 × 128 characters) gives logits within of the plain-JAX twin, loss against . Four conversions got it there: transpose to [in, out] with named output axes, stack the layers on axis 1, store each LayerNorm scale as its offset from 1 (copied unchanged, every LayerNorm silently doubles its output), and accept tanh GELU. Pick a tensor on the figure:

Fig. 2, step by step: one tensor from PyTorch to MaxText

  1. PyTorch. Four separate tensors blocks.{0..3}.attn.wq.weight, each [128 out, 128 in]: nn.Linear stores the output dimension first and computes x @ W.T. The highlighted row is output 3.
  2. Layout: transpose. PyTorch stores a linear weight [out, in]; MaxText's DenseGeneral stores [in, out...] and computes x @ W, like Flax and the plain-JAX twin. The rows are now the input (embed) dimension and output 3 is a column.
  3. Name the output axes. The 128 outputs are 4 heads of 32: reshape to [embed, heads, kv] = [128, 4, 32]. Each colour is one head; nothing moves in memory.
  4. Stack the layers. With scan_layers=true each per-layer weight gains a layers axis at param_scan_axis = 1 (): four [128, 128] query weights become one [128, 4, 4, 32] array, the tensor MaxText created at decoder.layers.self_attention.query.kernel. This is why checkpoint converters exist.
  5. The bias follows. wq.bias [128] per layer becomes [heads, layers, kv] = [4, 4, 32]. With every tensor converted, MaxText's forward pass on the first batch gives logits within of the tanh-GELU twin.
  1. PyTorch. blocks.{0..3}.ln1.weight, four vectors of 128 ones at initialisation; the output is normalised x weight + bias.
  2. An offset scale: subtract 1. Gpt3LayerNorm initialises its scale to zeros () and multiplies by scale + 1 (), so the stored value is the offset from 1: 1.0 becomes 0.0.
  3. Stack on axis 1: [norm, layers] = [128, 4], path decoder.layers.pre_self_attention_norm.scale.
  4. Forget the subtraction: copy PyTorch's weight unchanged and every LayerNorm doubles its output (scale 1.0 + 1). The model runs, the loss is wrong, nothing errors. Only a logits check catches it. Weight decay also pulls this scale toward 1, not 0.
  1. PyTorch. blocks.{0..3}.mlp.fc1.weight, four [512 out, 128 in] matrices.
  2. Transpose to [embed, mlp] = [128, 512].
  3. Stack on axis 1: [embed, layers, mlp] = [128, 4, 512], path decoder.layers.mlp.wi.kernel, logical names ("embed", "layers", "mlp"): the same names the Llama weights carry in section 3.
  4. The activation is not a tensor. mlp_activations=[gelu] resolves to getattr(jax.nn, "gelu") (), the tanh approximation; the running example uses exact erf GELU, and no MaxText flag spells it. Against exact GELU the logits differ by up to ; with a tanh-GELU twin the gap falls to , float32 rounding.

Logits against the exact-GELU running example differed by 7.0e-5: enough to fail a tight equivalence test, small for training. MaxText divides the query by √head_dim right after the projection () where the running example divides the scores; the product is the same. Both runs set matmul_precision=highest (no effect on CPU). What transfers to TPU: every conversion above. What does not: on TPU the default precision runs float32 matmuls in bfloat16 passes, so a TPU comparison needs highest or a looser tolerance.
