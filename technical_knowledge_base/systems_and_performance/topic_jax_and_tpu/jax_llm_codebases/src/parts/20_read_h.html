The real errors you will meet, and the fix for each

Overriding a model file's key on the command line

ValueError: Keys ['base_emb_dim'] are overridden by both model config and CLI/kwargs with different values.This is not allowed, unless setting `override_model_config=True`.

Drop model_name and set every shape key yourself, or pass override_model_config=True knowingly.

Parallelism degrees that do not multiply to the device count

Parsing succeeds; the error comes when the mesh is built. Leave exactly one ICI degree at -1 and let it absorb the rest.


A dimension the mesh cannot divide
IndivisibleError: ... spec=P('fsdp', 'tensor') ... implies that array axis 1 is partitioned 4 times, but the dimension size is 65
Pad the vocabulary (and head counts) to multiples of the axis sizes you will use; 128 or 256 for the vocabulary.


Installing MaxText main with the Tunix release
ImportError: cannot import name 'diffusion' from 'tunix.sft' (unknown location)
Install both from MaxText's requirement files.


Leaving adamw_mask empty with RMSNorm-style scales
Biases, norm scales and embeddings get weight decay. For the gpt3 block the scale is an offset, so decay pulls it toward 1; for scales stored directly (RMSNorm models) it pulls them toward 0. Set the mask explicitly.


Reading FLOPs from cost_analysis() of a scanned program
XLA counts the loop body once: 7.40 GFLOP for the scanned step against 28.90 GFLOP unrolled, same computation.




Design question: GRPO fine-tuning of an 8B dense model on one v5p-64 slice. What do you build?
MaxText's model with Tunix's GRPO learner (what MaxText's RL entry point does), versions pinned together. Trainer: FSDP over the slice's ICI, bfloat16 activations, float32 master weights, remat_policy chosen by compiling a step and reading memory. Rollout: vLLM TPU; start colocated on the full slice (simplest, no weight sync), move to a split (for example 48 chips training, 16 generating) if generation dominates step time. Consider LoRA to cut memory and weight-sync volume. Checkpoint asynchronously with the data iterator state. Validate with a tiny config on CPU first (this page's method), then a short run measured against MFU with a stated FLOP count.


Design question: two teams report 45% and 40% MFU for the same run. How?
Different FLOP counts. MaxText halved attention FLOPs for causal masking in July 2025; its own table's Llama 3.1 8B row is 45.46% under the old count and 40.41% under the new one. Also check whether recomputation or the embedding is counted, and the peak FLOP/s used.


Design question: what breaks bitwise reproducibility when resuming?
A data loader that cannot seek (or reshuffles), PRNG keys not saved, a different number of hosts or a different mesh (reductions in a different order; Levanter's README says so), restoring into different shardings (the training stack page measured a 3e-6 drift), and nondeterministic kernels.


Design question: Levanter's named axes against MaxText's logical rules?
Levanter: the model's own axis names, mapped by a dictionary, separately for parameters and compute; operations name their axes, so shape bugs fail at trace time. MaxText: positional arrays with logical names attached, an ordered rule list with fallbacks (the two embed rules), more machinery for many parallelism kinds. Same compiler underneath.
