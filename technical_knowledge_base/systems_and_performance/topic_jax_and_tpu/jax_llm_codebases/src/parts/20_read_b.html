MaxText 1: the configuration is the program's input

The problem. One codebase trains a 0.6B Qwen on 8 chips and a 671B DeepSeek on thousands, with dozens of parallelism, memory and kernel choices. PyTorch codebases solve this with argument parsers (Megatron's arguments.py has hundreds of flags) or TOML job files (torchtitan). MaxText's answer is a layered YAML that becomes a validated object, read by the model and the train step while they are traced.

How it works. pyconfig.initialize () builds one configuration in this order, later layers winning:

  1. configs/base.yml: 1,669 lines, 828 top-level keys, every default with a comment.
  2. configs/models/<model_name>.yml if model_name is set (86 model files): shapes, activations, tokenizer, sometimes extra sharding rules.
  3. Command-line key=value pairs and Python keyword arguments.
  4. Environment variables named M_<KEY> ().

Then a pydantic class, MaxTextConfig (), with 907 fields validates types and ranges and derives the values the code actually reads: emb_dim from base_emb_dim, global_batch_size_to_train_on from per_device_batch_size times the device count. The logical axis rules are merged by hand instead of by OmegaConf (): a rule in a model file replaces every base rule with the same logical name. The degrees set to -1, such as ici_fsdp_parallelism, are only resolved later, when the mesh is built.

# runs/lc_cfg.py (abridged): MaxText's own parser on CPU, 8 simulated devices
from maxtext.configs import pyconfig
from maxtext.utils import maxtext_utils
cfg = pyconfig.initialize([sys.argv[0], BASE],               # BASE = src/maxtext/configs/base.yml
                          model_name="llama2-7b", hardware="cpu", skip_jax_distributed_system=True,
                          run_name="lc_cfg", enable_checkpointing=False, base_output_directory=OUTDIR)
mesh = maxtext_utils.get_mesh_from_config(cfg)

Predict: model_name=llama2-7b base_emb_dim=128. What does MaxText do?
It refuses. validate_no_keys_overridden_twice () raises ValueError: Keys ['base_emb_dim'] are overridden by both model config and CLI/kwargs with different values.This is not allowed, unless setting `override_model_config=True`. (the missing space is in the source). With override_model_config=True the command line wins and you get a 128-wide model with Llama 2 7B's 32 heads of 128: a shape no checkpoint will load into. The rule protects you from fine-tuning a model you did not mean to build.

The cost. A typo is caught (remat_polcy=full raises ValueError: 'remat_polcy' not in 'emb_dim', 'mlp_dim', ... followed by every valid key), but a valid key with a surprising default is not. Three defaults that matter if you copy MaxText's numbers into another codebase: learning_rate: 3.e-5 (a fine-tuning value), adam_b2: 0.95 (optax and PyTorch default to 0.999), and adamw_mask: [], which decays every parameter including biases, norm scales and embeddings. The {{Config explorer|#t-lccfg}} tab has 81 flags with their line, default, comment and value per model file.

How to check. log_config (true by default, ) logs every resolved key at start-up; in Python, cfg.get_keys() returns them. Diff two runs' resolved configs, not their command lines.
