In PyTorch you learn large-model training by reading Megatron-LM or torchtitan: a config system, a model written once, a parallelism layer, a train loop, checkpointing. JAX has the same few codebases, and they are where everything on the other pages of this topic meets: Flax NNX modules, optax, orbax, grain and above all a sharding scheme that never appears in the model code. This page reads the three that matter in October 2026 at pinned commits, quoting file and line, and runs what runs on a laptop CPU.

The root page's {{Reading tab, section 7|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}} lists the codebases and MaxText's own MFU table, and its {{Tool map|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}} (tab "Tool map") dates every library and its lineage. This page goes inside them. Everything marked measured ran here on an Apple M1 Pro CPU (jax 0.11.2, shared machine at load 30 to 60, low priority, 4 threads): MaxText at main 1a95d1e5 (2026-10-15), Tunix at v0.1.7 (2026-06-09), Levanter at Marin main 1290cfb5 (2026-10-15, lib/levanter). How to read a production JAX codebase

Every LLM trainer, in PyTorch or JAX, has the same five boxes. The topic's running example (a 826,368-parameter character model in {{the root's src/data|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}}) has them in 268 lines, model_jax.py plus common.py; MaxText has them in 213,293 lines of Python. Reading a large codebase is finding these five boxes and then the one or two ideas it adds to each.

What is different from PyTorch is the middle three boxes. In Megatron or torchtitan, the model code calls the parallelism layer (a ColumnParallelLinear, a DTensor placement), and the train loop runs eagerly, one Python call per op. In JAX:

  • The model never mentions devices. Each weight and activation carries logical axis names (embed, mlp, heads); a table in the config, the logical axis rules, maps names to mesh axes. Changing from FSDP to FSDP plus tensor parallelism is a config change.
  • The train step is one compiled program. Python runs once, while jax.jit traces it; every later step calls the compiled executable. A codebase's Python is the recipe for building that program, so reading it is reading what ends up inside one XLA computation. The {{One train step|#t-lcstep}} tab shows this with MaxText's real step: 1,063 MaxText Python calls in step 0, none in step 1.
  • Configuration is data. Shapes, parallelism degrees, remat policy and attention kernel are fields; the code reads them while tracing. That is why MaxText's YAML has 828 top-level keys and is the first thing to learn.

The {{Codebase map|#t-lcmap}} tab puts the three repositories side by side, box by box, with sizes and the key symbols at their lines.
