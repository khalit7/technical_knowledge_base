MaxText 4: the train step

PyTorch first. A PyTorch step mutates objects: loss.backward() fills .grad, clip_grad_norm_ rescales it, optimizer.step() updates parameters in place. MaxText's train_step () is a pure function from (state, batch) to (new state, metrics), and the in-place update is recovered by buffer donation.

  1. state = nnx.merge(model, state) (): the jitted function receives a Flax NNX graph definition (static) and a pytree of arrays, and rebuilds the TrainStateNNX module (model plus nnx.Optimizer) inside the trace. This is the split/merge pattern the {{training stack|n:3c65c17b0d0d817ea0ace9a2ca8677ec}} page explains.
  2. The model is split into trainable nnx.Param leaves and the rest, and jax.value_and_grad(diff_wrapper, argnums=(0, 1), has_aux=True) () differentiates a wrapper that merges them back and calls loss_fn (): forward, cross-entropy over non-padding tokens, auxiliary losses (MoE load balance, z-loss, multi-token prediction) when configured.
  3. Gradients are cast to grad_dtype, clipped by global norm (), and applied with state.apply_gradients(grads) (), which calls the optax chain.
  4. Metrics (loss, raw and clipped gradient norm, parameter norm) are returned as arrays, so logging them never forces a device-to-host copy inside the step.

jit_train_step () wraps it in jax.jit with explicit in_shardings and out_shardings (from the logical rules) and donate_argnums = 0 (): the old state's buffers are reused for the new state, which is what keeps peak memory at one copy of parameters and optimizer state.

MaxText 5: scan over layers, and what remat keeps

Scan. With scan_layers: true () the decoder runs one traced layer inside jax.lax.scan over stacked weights, so the program, the compile time and the HLO stop growing with depth. PyTorch has no counterpart in eager mode; under torch.compile the closest is compiling one block and reusing it. The {{JAX core|n:3c65c17b0d0d81b7a0d1faba6cef5561}} page measures scan against a Python loop; the {{training stack|n:3c65c17b0d0d817ea0ace9a2ca8677ec}} page shows nnx.scan.

Remat. Each scanned layer is wrapped in jax.checkpoint(layer_fn, policy=policy) (). The policy comes from remat_policy (, default full) through get_remat_policy (): full keeps only each layer's input and recomputes everything in the backward pass; the others keep named intermediates, using the names layers attach with checkpoint_name (query_proj, key_proj, value_proj, out_proj, mlpwi, mlpwo, context; for example ). minimal () keeps every projection output; the *_offloaded policies move them to host memory. PyTorch's counterpart is torch.utils.checkpoint with a selective-checkpoint policy.

Predict: for the running example's train step, compiled by MaxText, which remat policy needs the most temporary memory, and which does the most FLOPs?
minimal keeps the most (149.7 MB of XLA temporaries against 100.1 MB for full) and full recomputes the most (28.90 GFLOP against 24.61 GFLOP with the layers unrolled). The table has the rest.

What transfers. The ordering of memory against recompute, and the bit-identical results, transfer to TPU and GPU. The sizes do not: on TPU the activations are bfloat16 (dtype), the sequence is thousands of tokens, and the memory that matters is HBM per chip; choose the policy that fits in HBM with the fewest recomputed FLOPs. The {{TPU programming and performance|n:3c65c17b0d0d8129b0a5fd82e44ecf6e}} page does that arithmetic for real chips.

Checkpoints. MaxText writes them with Orbax's newer v1 API (from orbax.checkpoint import v1 as ocp, ; ocp.training.Checkpointer, ), asynchronously by default (), every 10,000 steps (), and resumes automatically: "If there is already a checkpoint for this run_name, we load the latest entire checkpoint" (). Not run here (every run on this page sets enable_checkpointing=false); the {{training stack|n:3c65c17b0d0d817ea0ace9a2ca8677ec}} page runs Orbax itself.

MaxText 6: how MFU is counted, and what the published table used

Model FLOPs utilisation (MFU) is the model's FLOPs per step divided by step time and peak FLOP/s; the {{Performance math|n:3c65c17b0d0d81faad1ef390b0e54d08}} page derives it. MaxText's count is calculate_tflops_training_per_device (): every weight matmul, 2 FLOPs per multiply-add, times 3 for forward plus backward ("multiply by 3 to account for 1 forward pass + 2 backward passes", ), plus attention's score and value products, halved for the causal mask since July 2025 (causal_attention_flops = noncausal_attention_flops / 2, ; the docs, ). It counts the output projection but not the embedding lookup, and never counts recomputation, so remat lowers MFU without changing the count.

On the running example's step this count is 21.14 GFLOP (19.53 in weight matmuls, 1.61 in attention); XLA's cost analysis of the same model's value_and_grad reports 23.69 (the {{JAX core|n:3c65c17b0d0d81b7a0d1faba6cef5561}} page's measurement), because XLA counts the full, unmasked attention, the elementwise work and the softmax. MFU uses the first number on purpose: it does not depend on the implementation.
