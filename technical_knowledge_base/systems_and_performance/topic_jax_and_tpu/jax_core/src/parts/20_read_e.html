6. Autodiff: JVP, VJP, and reverse mode as linearize then transpose

Near a point x, a differentiable f from n numbers to m numbers behaves like a linear map, its m x n Jacobian J. Autodiff never builds J; it applies it in one of two directions:

Forward mode: JVP

jax.jvp(f, (x,), (v,)) returns f(x) and J v: push a direction v (a "tangent") from the inputs to the outputs, alongside the ordinary computation. PyTorch: torch.func.jvp; dual numbers.

Reverse mode: VJP

y, f_vjp = jax.vjp(f, x), then f_vjp(u) returns uT J: pull a weighting u of the outputs (a "cotangent") back to the inputs. For a scalar loss, u = 1 gives the gradient. PyTorch: loss.backward(), torch.func.vjp.

One JVP and one VJP each cost a small constant times one forward pass, so a full Jacobian costs n JVPs (one per input) or m VJPs (one per output): forward mode wins with few inputs, reverse mode with few outputs.

How JAX gets reverse mode: linearize, then transpose


PyTorch records a tape of operations and runs each one's backward function. JAX derives reverse mode from forward mode in two steps ({{Radul et al., You Only Linearize Once (2022)|https://arxiv.org/abs/2204.10923}}). Linearize: run the forward computation once with a LinearizeTrace, computing each primal value now and recording the tangent computation (which is linear) into a separate jaxpr; values it needs from the forward pass, such as an activation to multiply by, become that jaxpr's constants, the residuals. Transpose: run the linear jaxpr backwards, replacing every linear primitive by its transpose: a matmul by x becomes a matmul by xT, a broadcast becomes a sum, a sum a broadcast, an addition sends its cotangent to both inputs. What reverse mode keeps in memory




Residuals are reverse mode's memory bill: everything the backward pass needs from the forward pass, alive until used. MLP rows: block 0 on 4 tokens; model rows: the whole loss on one batch (32 x 128 characters).
