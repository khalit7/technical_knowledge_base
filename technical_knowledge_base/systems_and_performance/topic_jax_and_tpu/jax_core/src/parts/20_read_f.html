8. Pytrees in depth: registration, static data and the jit cache

The root's {{Transforms lab|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}} (section 7) explores the running example's parameter pytree and what counts as a leaf. This section is about your own classes, and the one property that causes most surprises: the tree structure, including its static data, is part of the jit cache key.

Three ways to make a class a pytree

A pytree node type needs two functions: flatten (object to children plus auxiliary data, the static part) and unflatten (back). measured here (run_pytree.py):

class Linear:                                      # (a) by hand
    def __init__(self, w, b, name): ...
jax.tree_util.register_pytree_node(Linear,
    lambda m: ((m.w, m.b), m.name),               # children, aux data
    lambda name, ch: Linear(ch[0], ch[1], name))

@jax.tree_util.register_dataclass                 # (b) a dataclass: static fields are aux data
@dataclasses.dataclass
class LayerNorm:
    scale: jax.Array
    bias: jax.Array
    eps: float = dataclasses.field(metadata=dict(static=True), default=1e-5)

class Adam(NamedTuple):                           # (c) NamedTuples are pytrees already
    mu: dict; nu: dict; count: jax.Array

The treedef prints the aux data inside the node (Linear[fc1], LayerNorm[(1e-05,)]), and key paths name each leaf (.scale, .mu['w']), which is what optax masks, orbax checkpoints and sharding rules match on. A hand-registered class without key functions gets flat-index paths; register_pytree_with_keys or a dataclass gives names. Flax NNX modules and Equinox modules are registered the same way, with the static parts (layer sizes, activation functions) as aux data; the {{training stack|n:3c65c17b0d0d817ea0ace9a2ca8677ec}} page covers nnx.split and Equinox's filtered transformations built on this.

Arrays are traced, so new values hit the cache; aux data is compared by value and baked into the program, so a new eps is a new program. Put hyperparameters that change every step (a learning rate on a schedule) in a leaf, not in static fields.

Typed keys are the recommended form ({{JEP 9263|https://docs.jax.dev/en/latest/jep/9263-typed-keys.html}}): arithmetic on a key is a bug, a batch of keys has the batch shape and nothing else, and the implementation travels with the dtype. jax.random.key_data and wrap_key_data convert both ways (round trip exact: ), for checkpointing or interop.


Threefry: a hash, not a generator


The default generator is Threefry-2x32, a counter-based PRNG from {{Salmon et al. (2011), Parallel random numbers: as easy as 1, 2, 3|http://www.thesalmons.org/john/random123/papers/random123sc11.pdf}}: random bits are a keyed hash of a counter, bits[i] = threefry(key, i), built from 32-bit additions, rotations and XORs. There is no state to advance, so any element of any array can be computed independently, on any device, in any order: that is what makes sharded random numbers cheap and reproducible. source the rotation constants and key schedule (0x1BD11BDA is Threefish's parity constant):




In the jaxpr, jax.random.normal(key, (3,)) is a random_bits equation followed by float tricks (shift right 9, OR with the exponent of 1.0, subtract 1: a uniform in [0, 1)) and erf_inv; the Threefry rounds themselves appear only after lowering ( calls to a threefry2x32 function in this program's StableHLO).


Why split(key)[i] equals fold_in(key, i)


The root page observed this as a coincidence. The source says why: source in partitionable mode (the default since JAX 0.5.0), split hashes the counters (0, i) with the key, and fold_in(key, i) hashes the seed made from i, which is the same pair.

10. Writing a new primitive, one rule at a time


When you need this. Almost never: a custom_jvp or custom_vjp (section 6) covers new derivatives, jax.pure_callback calls host Python, jax.ffi calls compiled C++ or CUDA through XLA's foreign function interface, and {{Pallas|n:3fa5c17b0d0d817699fcf65d085402e7}} writes kernels. A primitive is what those are built from, and writing one is the best way to see what every transformation needs. The example is multiply_add(x, y, z) = x * y + z from JAX's own {{primitives guide|https://docs.jax.dev/en/latest/601/jax-primitives.html}}, written against the public extension modules of jax 0.11.2.


Each rule unlocks a transformation (real results after each step)












The rules, in the order they unlock things: impl (eager evaluation), abstract evaluation (shapes and dtypes: tracing, so make_jaxpr), lowering (StableHLO: jit), JVP (forward mode), transpose (reverse mode, because grad is linearize then transpose; section 5), batching (vmap). Each is a dictionary entry keyed by the primitive: ad.primitive_jvps, ad.primitive_transposes, batching.primitive_batchers, and the lowering registry (this process:  platform-independent lowerings, plus  CPU-,  CUDA- and  TPU-specific ones). The finished primitive's gradient program shows the transpose rule at work: the backward pass is itself a multiply_add.




Its jit lowers to two StableHLO ops, because the lowering rule traced the impl (mlir.lower_fun): stablehlo.multiply and stablehlo.add. A real primitive (a new matmul variant, a collective) would emit its own ops or a custom call.
