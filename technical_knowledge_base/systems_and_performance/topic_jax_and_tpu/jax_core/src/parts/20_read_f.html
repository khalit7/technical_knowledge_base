7. Custom derivative rules: custom_jvp and custom_vjp

Autodiff differentiates the program you wrote, not the function you meant. A formula that is correct in exact arithmetic can have a derivative program that overflows, divides by zero or multiplies infinity by zero, and some programs (a while_loop solver) cannot be reverse-differentiated at all. PyTorch's answer is torch.autograd.Function with a hand-written backward; JAX has two decorators.

jax.custom_jvp (the default)

You write the JVP rule (primal out, tangent out), linear in the tangents. JAX linearizes and transposes it for reverse mode, so the function works under jvp, grad, vmap and jit alike.

jax.custom_vjp

You write a forward that returns residuals and a backward that maps output cotangents to input cotangents, like PyTorch's forward/backward. Use it when the backward should be a different computation (implicit differentiation, saving memory, clipping). It gives up forward mode.

8. vmap: batch tracers and batching rules, no loop


Under jax.vmap, each array is a BatchTracer holding the batched value and batch_dim, the index of the mapped axis (or "not mapped" for arguments the whole batch shares). Every primitive goes to its batching rule, which receives the values with their batch dims and returns one primitive application on the whole batch plus the batch dim of the result. This process has  batching rules registered (dot_general's is ). axis_name, and pmap as its old multi-device twin


Naming the mapped axis lets per-example code talk to the rest of the batch with the same collectives shard_map uses across devices. measured here: normalize(v) = v / lax.psum(v.sum(), axis_name="b"), written for one example and vmapped with axis_name="b" over rows 1, 2, 3, 4 (3 columns each), gave first entries  (each divided by the batch total 30), and the psum over the batch axis became a plain psum[axes=(0,)] reduction on the batched array. The same mechanism computes batch statistics from per-example code: Flax NNX's BatchNorm takes an axis_name and averages with lax.pmean over it (flax 0.12.10). jax.pmap was this idea mapped onto devices: one mapped axis, one device per element, collectives by axis name. It is history you meet in old code: since JAX 0.8.0 (2025-10-15) it has been "in maintenance mode", implemented over jit and shard_map, and 0.10.0 (2026-04-16) removed the old implementation (JAX changelog, as read on the root page); new code uses jit with shardings or jax.shard_map ({{Sharding and scale|n:3c65c17b0d0d8125b084e6720cc66b3d}}).


How to check: jax.make_jaxpr(jax.vmap(f)) should show batched primitives and no per-example loop; a select_n where you expected a cond means a batched predicate (section 5).
