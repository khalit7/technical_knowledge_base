2. Tracing: abstract values, interpreters, and how transformations nest

One Python function has to become several programs: a compiled one (jit), one that also computes derivatives (grad), one that works on a batch (vmap), and any composition of these. PyTorch's eager mode cannot do this, because it only ever sees one operation at a time on real numbers. JAX runs your Python on tracers and lets an interpreter decide what each operation means.

Abstract values

An abstract value (aval) describes a set of possible arrays: everything about an array except its numbers. For arrays it is a ShapedArray: shape, dtype, weak type, sharding and a few layout fields (expanded in the source block below), exactly what a compiled program may depend on. jax.typeof(x) gives the aval of anything measured here:

ShapedArray's fields in the source

sharding is the logical layout over a mesh; manual_axis_type records, inside shard_map, over which mesh axes a value varies or is still unreduced (a sum not yet taken); memory_space and layout describe where and how the buffer sits.

Shapes are part of the aval, so they are known while tracing: x.shape[0] is a plain Python int inside a jitted function, and no shape may depend on data. A typed PRNG key is an array whose dtype is a key type (key<fry>, section 10).

Traces, tracers, and one call through three of them

A trace is an interpreter with one method that matters, process_primitive(primitive, tracers, params). A tracer belongs to one trace and carries an aval plus whatever its interpreter needs. Every jnp or lax function ends in Primitive.bind, which hands the operation to the current trace, held in a thread-local context rather than in the data. Each transforming trace keeps a parent_trace: it computes what it needs and binds the resulting operations on its parent, with the parent set as current. The pinned source has classes that derive directly from Trace; the five you meet every day:

Cost. Tracing is Python: every primitive goes through bind and one process_primitive per nested transformation, so tracing time grows with (primitive calls) x (nesting depth). It is paid once per jit cache miss (next section), which is why it hurts only when something retraces and why large models scan over layers (section 5). How to check: jax.make_jaxpr(f)(*args) shows the program; print(x) inside f shows the tracer, once, at trace time; jax_check_tracer_leaks finds tracers that escaped (slow, debugging only).

History: levels before December 2024, and which Autodidax to read
Before December 2024 this dispatch was decided by levels: every trace had a level on a global stack ("main traces"), every tracer remembered its level, and bind picked the highest level among its arguments. JAX 0.4.36 (2024-12-05) replaced it: source the CHANGELOG says the release "lands 'stackless' ... trace dispatch purely a function of context rather than a function of both context and data. This let us delete a lot of machinery for managing data-dependent tracing: levels, sublevels, post_process_call, new_base_main, custom_bind". The original {{Autodidax|https://docs.jax.dev/en/latest/autodidax.html}} still builds the level stack (its MainTrace(level, ...)); {{Autodidax2, part 1|https://docs.jax.dev/en/latest/autodidax2_part1.html}} rebuilds the current, context-based design. Read the second to match today's source.







3. jit and its cache: trace once per key, then run the compiled program


jax.jit(f) returns a wrapper. On each call a C++ fast path builds a cache key from the arguments and looks it up; on a miss, Python traces f (section 2), lowers the jaxpr and asks XLA to compile it, then stores the executable. Three rows teach the rules. A Python float passed as an ordinary argument is traced as a weakly typed ~float32[], so a new value is data, not a new program; the same float marked static compiles once per value. A new lambda per step is a function never seen before, so every step compiles. And a global changed between calls gives a stale answer, not a recompile: it was read once, while tracing, and baked in as a constant. In practice: pad to a few bucket shapes instead of feeding ragged lengths; mark an argument static only when it changes the program (a flag, a layer count); jit once, outside the loop; pass anything that varies as an argument. To watch a running job: jax.config.update("jax_explain_cache_misses", True) logs every miss with its reason (the table's explanations are that log), and jax_log_compiles logs each compile.



Static and traced values; side effects run once


While tracing, a value is either static (known to Python now: shapes, dtypes, Python numbers the function closes over, static arguments) or traced (known only when the compiled program runs). Python may branch on static values freely, and the branch taken is baked into the program; a Python if on a traced value has no value to test and raises TracerBoolConversionError, and a shape that depends on data raises ConcretizationTypeError (section 5 gives the primitives that replace both). For the same reason a jitted function must be pure: its Python body runs only while tracing, so anything done on the side happens once. measured by the root's Transforms lab (run_basics.py), one jitted function called three times:


log, count = [], [0]
@jax.jit
def f_side(x):
    count[0] += 1                  # Python side effect
    log.append(x)                  # keeps a reference to a tracer
    jax.debug.print("debug.print sees x[0] = {v}", v=x[0])
    return x * 2
for i in range(3): f_side(jnp.full(4, float(i)))


After 3 calls: count was 1, log held 1 entry, a JitTracer(~float32[4]), and jax.debug.print printed 3 times. Using the saved tracer later raised UnexpectedTracerError (a tracer leak). Inside jit, x + np.random.rand() returned the same number on three calls (NumPy drew once, while tracing) and x + time.time() the same value on two calls 50 ms apart. Safe ways to look inside: jax.debug.print, jax.debug.callback, or returning values as extra outputs (has_aux).
