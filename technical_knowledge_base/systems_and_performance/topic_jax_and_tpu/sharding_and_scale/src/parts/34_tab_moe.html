In a mixture-of-experts layer each token goes to a few of many expert MLPs. Put one expert per device and tokens must travel to their experts and back: two all-to-alls per layer. Here it is written in JAX, run on the running example's tokens, and compared with what propagation emits for the same maths.

The setup (src/runs/ss_moe.py): the 4,096 tokens of the running example's batch 0, taken after block 0 and the next LayerNorm ([4,096, 128]), 512 on each of 8 devices; a router [128, 8] and 8 expert MLPs (128 → 256 → 128, exact GELU), one per device. The router and experts are new seeded weights, illustrative, not trained: the routing is lopsided (expert 6 is wanted by 120 to 150 of each device's 512 tokens, expert 1 by 21 to 35), which makes capacity visible. Each device routes its own tokens (Switch Transformer's groups); capacity C = ⌈capacity factor × 512 × k / 8⌉ tokens per expert per device; tokens over capacity are dropped (the layer outputs 0 for them, the residual stream carries them). Top-1 is Switch's routing ({{Switch Transformers paper page|n:3c65c17b0d0d81a8b541c9babbf40c94}}), top-2 GShard's and Mixtral's ({{Mixtral paper page|n:3c65c17b0d0d81eba72af0ac91ddc6b3}}).

The code that ran



all_to_all(x, axis, split_axis=0, concat_axis=0, tiled=True) cuts this device's [8, C, 128] block along the expert dimension, sends slice e to device e, and stacks what arrives along the same dimension: afterwards dimension 0 means "which device it came from". The second all-to-all is the exact inverse. The backward pass transposes each all-to-all into another all-to-all (3 in the compiled gradient program, plus a small all-reduce for the router's replicated weights).


What production code does differently


    

  • No fixed capacity. Padding every expert to C wastes compute and drops tokens. MaxText's default is capacity_factor: -1.0 # ... no dropping by default () and it sends exactly the tokens each expert needs with jax.lax.ragged_all_to_all (; the primitive at ), then runs the experts as one grouped matmul (megablox).
    • 

  • Load balancing. A router trained with an auxiliary balance loss (or DeepSeek's bias term) evens out the columns above; untrained, it does not.
    • 

  • Experts per device. With more experts than devices each device holds several; with fewer, an expert is sharded over several devices (tensor parallelism inside the expert).
