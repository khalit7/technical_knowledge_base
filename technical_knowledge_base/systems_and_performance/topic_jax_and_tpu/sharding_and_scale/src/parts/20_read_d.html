4. Explicit mode on the whole running example

The problem it solves. In Auto mode a bad layout costs you nothing at trace time and a lot at run time: the compiler quietly inserts whatever collective makes the program correct. Explicit mode moves the decision to trace time. Each operation has a rule mapping input shardings to an output sharding; when the rule cannot decide, or would need communication you did not ask for, tracing stops with a ShardingTypeError. The JAX guide states the intent: the rules "prefer to error and require annotation rather than falling back to arbitrarily chosen defaults", to "get important parallelism decisions in your face, rather than hide them" ({{JAX docs, Distributed arrays and automatic parallelization|https://docs.jax.dev/en/latest/parallel.html}}, read 2026-10-15).

What it costs, measured. The running example's loss and gradient, traced on an Explicit mesh exactly as written for Auto mode, then with the smallest change each error asks for. Step through the attempts for each layout; every message is pasted from the run (src/runs/ss_explicit.py, the forward is model_jax.apply written out with hooks).

Each error names the one decision JAX will not guess

Layout

Three lessons from the ladder. First, even plain data parallelism needs one annotation: the embedding lookup tok_emb[idx] is a gather whose output layout JAX will not guess, so you write tok_emb.at[idx].get(out_sharding=P('data', None, None)) (). Second, FSDP in Explicit mode is literally written out: jax.reshard(w, P()) before each use is the all-gather, and the gradient comes back with the weight's own sharding (float32[128@data,512]), because the transpose of a reshard is a reshard. Adding arrays split on the same axis along different dimensions is refused for the same reason, with the same fix. Third, Megatron's row-parallel matmul is the textbook ambiguous case: both operands are split along the summed dimension, so the result is a partial sum on every device, and you must say whether you want it summed and where (jnp.einsum(..., out_sharding=P('data', None, None)), ). After the fixes, data parallel compiles to the same single all-reduce of 3,305,476 bytes as the root lab's Auto-mode layout, tensor parallel to 17 all-reduces (loss and gradient only, no optimizer here), and every loss is within 4.8e-7 of one device.

JAX also has unreduced types, where "the logical value equals the distributed sum of the physical shards' values along that axis", for delaying a reduction (shown as f32[8,16]{U:X} in the guide). Not run here: the guide marks the details as still to come.

5. shard_map: per-device code, collectives as JAX calls

When no layout rule gives the communication you want, you write it. jax.shard_map(f, mesh=mesh, in_specs=..., out_specs=...) () cuts each input by its spec, runs f once per device on the local block, and assembles the outputs by out_specs. Inside f shapes are per device and the mapped axes are Manual: nothing crosses a wire unless you call a collective, by axis name.

The shape of every shard_map: split by in_specs, run per device, communicate by name, reassemble by out_specs
