You know how PyTorch spreads a model over GPUs: you pick a wrapper (DDP, FSDP2, a tensor-parallel plan) or a DTensor placement, and it owns the communication. JAX works the other way round. You write the program for one device, say how a few arrays are laid out over a grid of devices, and the compiler writes the communication. This page is about what the compiler actually does with that, how to take control when it does the wrong thing, and how to choose the layout for a real model on a real TPU slice.

The root page's {{Sharding lab|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}} (tab "Sharding lab") already teaches the three objects (Mesh, PartitionSpec, NamedSharding), the five collectives with their ring costs, a PartitionSpec playground and six layouts of the running example. Read it first if P('data', None) is new to you. This page goes one level down: the propagation algorithms, explicit mode, every strategy including context, pipeline and expert parallelism, cost models checked against the compiler, mesh choice for a slice, and multi-process runs. Everything marked measured ran here on an Apple M1 Pro CPU with 8 simulated devices (XLA_FLAGS=--xla_force_host_platform_device_count=8, jax 0.11.2). The compiled programs, the collectives and their sizes, the memory figures and the losses are real and deterministic. Speeds are not: a "collective" between simulated devices is a memory copy, so no timing here says anything about a TPU. TPU numbers are published by Google, and arithmetic on them is labelled derived.

Reading time: about 23 minutes for this tab, plus about 10 for its tables, code and folded answers; each lab tab adds 7 to 12 minutes.

The three ideas the rest of the page builds on
  1. Communication is a consequence of layout. Change one PartitionSpec and a different set of collectives appears in the compiled program; the Python code does not change. So you read communication off the compiled HLO, never off the code.
  2. Someone must decide the layout of every intermediate array. In Auto mode the compiler's propagation decides; in Explicit mode the type system decides and asks you when it cannot; inside shard_map you decide by hand. Most of this page is about choosing among the three.
  3. The formulas work. For data parallel, FSDP, HSDP and tensor parallel, a two-line formula predicts the compiler's byte count within 0.4% at both model sizes (section Collective costs). That is what makes a mesh designable on paper before you rent a slice.
