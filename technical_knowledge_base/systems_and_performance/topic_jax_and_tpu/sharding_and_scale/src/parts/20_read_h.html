12. Many hosts: one program, many controllers

The model. A TPU slice larger than one host (one VM with a few chips attached) runs one Python process per host, all executing the same script: JAX is multi-controller. The JAX guide: "All processes (usually) run the same Python script", and "it's crucial that all processes with participating devices run the same computation in the same order", a rule that is "mostly unchecked", so a mismatch hangs ({{JAX docs, multi-controller JAX|https://docs.jax.dev/en/latest/multi_process.html}}, read 2026-10-15). The PyTorch picture is close: torchrun starts one process per GPU and you call init_process_group; JAX starts one process per host and you call jax.distributed.initialize() (), which on Cloud TPU, Slurm or Kubernetes needs no arguments. After it, jax.devices() lists every chip of every host (the global devices) and jax.local_devices() this host's (also called addressable). A jitted function over a global array is still one SPMD program; the difference from one host is only that a process can touch the shards on its own devices and nothing else.

Run here. JAX runs the same thing on CPU with several processes on one machine, so this page does it for real: 2 processes, each owning 4 simulated devices, connected by jax.distributed over localhost (collectives between processes use gloo, the default CPU implementation, ). Each process loads only its 16 of the batch's 32 rows and builds the global batch with jax.make_array_from_process_local_data (), then both run the running example's data-parallel train step for 20 steps. measured

On a real slice

  • Data. Each host reads only its shard of the data. The data loader's job is to give host h the rows that its devices hold under the batch sharding; make_array_from_process_local_data assembles the global array without communication. Deterministic, checkpointable per-host loading with grain is on the {{training stack|n:3c65c17b0d0d817ea0ace9a2ca8677ec}} page.
  • Checkpoints and logging. Orbax writes and restores sharded arrays from every host (training stack page). Logging only from jax.process_index() == 0 is fine; putting a device_put or a jitted call under that condition is not: the guide warns it "would lead to a deadlock as only process 0 initiates the collective communication".
  • Across slices. Multislice jobs add the data-centre network between slices; MaxText's dcn_*_parallelism settings put data parallelism there (section 11).
