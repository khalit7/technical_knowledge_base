Many hosts: one program, many controllers

The model. A TPU slice larger than one host (one VM with a few chips attached) runs one Python process per host, all executing the same script: JAX is multi-controller. The JAX guide: "All processes (usually) run the same Python script", and "it's crucial that all processes with participating devices run the same computation in the same order", a rule that is "mostly unchecked", so a mismatch hangs ({{JAX docs, multi-controller JAX|https://docs.jax.dev/en/latest/multi_process.html}}, read 2026-10-15). The PyTorch picture is close: torchrun starts one process per GPU and you call init_process_group; JAX starts one process per host and you call jax.distributed.initialize() (), which on Cloud TPU, Slurm or Kubernetes needs no arguments. After it, jax.devices() lists every chip of every host (the global devices) and jax.local_devices() this host's (also called addressable). A jitted function over a global array is still one SPMD program; the difference from one host is only that a process can touch the shards on its own devices and nothing else. Google's own Gemini runs used the other model, a single controller: "the 'single controller' programming model of Jax and Pathways allows a single Python process to orchestrate the entire training run" ({{Gemini 1 report, arXiv 2312.11805, section 3|https://arxiv.org/abs/2312.11805}}); Pathways is not open source.
