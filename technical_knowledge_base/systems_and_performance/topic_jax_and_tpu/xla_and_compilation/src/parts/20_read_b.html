The idea in one screen

jax.jit hands XLA the whole train step as one program, so the compiler decides everything before the first step runs: which operations share a kernel, where every array sits in memory, and which compiled executable a later call reuses. Almost every JAX performance surprise (a slow first call, a step that keeps recompiling, a copy you did not ask for, memory that does not fit) is one of those decisions, and every one of them can be read in what XLA dumps.

One train step on its way down: six forms, one plug, and the levers you hold

Left: the running example's whole train step (forward, backward, AdamW) at each stage: 3,411 jaxpr equations, 5,318 StableHLO operations, 4,932 HLO instructions, then 817 kernels (783 fusions, 33 matmuls, 1 copy) and a planned peak of 374.4 MB measured here. Right: the levers this page explains, each beside the stage it acts on. A hit in the in-memory cache skips every stage above the executable; a hit on disk skips only XLA's compile (section 8).

You need: tracing and what a jaxpr is ({{JAX core|n:3c65c17b0d0d81b7a0d1faba6cef5561}}), and the root's {{Compiler lab|n:3c65c17b0d0d81ecbc04eea6aa45ea1a#t-xla}} (five forms, fusion of one MLP block, donation, remat policies), which this page goes deeper than. Elsewhere: the sharding passes and collectives on {{Sharding and scale|n:3c65c17b0d0d8125b084e6720cc66b3d}}, the TPU's memory hierarchy on {{TPU programming and performance|n:3c65c17b0d0d8129b0a5fd82e44ecf6e}}, hand-written kernels on {{Pallas kernels|n:3fa5c17b0d0d817699fcf65d085402e7}}.

jaxpr
JAX's own program: one equation per primitive, recorded by tracing.
StableHLO
the versioned, portable compiler format JAX lowers to (an MLIR dialect).
PJRT
the C API between JAX and a device plugin (CPU, CUDA, TPU).
HLO
XLA's internal program, one instruction per line, free to change at any commit; "optimised HLO" is what the passes leave.
Pass
one rewrite of the whole HLO module (simplify, deduplicate, choose layouts, fuse).
Fusion
several operations compiled into one kernel, so their intermediates never reach memory.
Layout
the order an array's dimensions sit in memory; on TPU also the tiles it is cut into.
Buffer assignment
XLA's plan for every byte of the step, fixed before it runs.
Donation
letting an output reuse an input's buffer (donate_argnums).
Recompile
a cache miss: trace, lower and compile again.
How to read the evidence
measured here Apple M1 Pro, CPU only, JAX , on the running example (the tiny 4-layer character model of Topic: jax-and-tpu, 826,368 parameters, batch 32 x 128). Counts, programs and memory plans are deterministic; times are rough (a shared machine, 1-minute load 35 to 60) and labelled. read in source JAX at tag jax-v0.11.2 and XLA at commit 91888df6 (the one that tag pins), file and line found by pattern in a script. Google docs written by the makers. not run here GPU and TPU behaviour, read rather than measured: there is no GPU or TPU on this machine, and XLA's TPU compiler is not open source at all (it ships inside libtpu), so no TPU pass list can be quoted.
Why this page counts 817 kernels and the root's Compiler lab 816 (a reconciliation)

The 817 kernels here are the top-level instructions that do work: 783 fusions, 33 matrix multiplies and one copy. The root's Compiler lab counts the same way and prints 816 for its undonated step (783 fusions and 33 matrix multiplies); the donated step here adds the one copy. An earlier version of the root's lab printed 1,057, because its counter also walked the 241 tiny computations that tell each reduction how to combine two values (an add or a maximum, reached through to_apply=); those are not kernels.
