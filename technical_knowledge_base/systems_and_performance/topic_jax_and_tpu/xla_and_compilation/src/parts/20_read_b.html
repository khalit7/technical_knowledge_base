You write jax.jit(train_step), the first call takes seconds and every later call is fast. This page follows that first call all the way down: from your Python function to a jaxpr (JAX's own program), to StableHLO (a portable compiler format), across PJRT (the plug between JAX and a device), through XLA (the compiler, Accelerated Linear Algebra) pass by pass, to machine code; then back up to what you control: fusion, memory, caches, ahead-of-time export, recompiles, profiles and flags. It assumes you know PyTorch well and have read the root page's {{Compiler lab|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}} overview, which this page goes deeper than. Reading time about minutes (words outside code, tables and widgets at 200 a minute; the folded answers and the tables add about ).

The big difference sits in the first row. Dynamo keeps PyTorch's eager meaning and compiles whatever it can; JAX insists the function is pure, gets the whole step as one program, or raises an error. Everything below follows from having the whole step: XLA can fuse across the forward and backward pass, plan every byte before running, and cache the result by a key it can compute.
