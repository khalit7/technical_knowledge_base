Profile reader

One train step of the running example as the profiler recorded it: a jax.profiler.trace of five steps on an Apple M1 Pro, CPU only, converted with xprof 2.23.2 and scrubbed of the host name (src/lab/profile_lab.py). Every kernel is joined to the fusion it ran (its phase and model function, from the {{Fusion explorer|#t-xpfuse}}). Timings are measured on a shared machine at low priority (1-minute load given below) and vary from run to run; the structure does not. Which xprof view answers which question: {{Reading, section 11|#t-read}}.

Rows are threads: Python (the main thread, waiting in block_until_ready), the PJRT client that dispatches, and the XLA:CPU worker pool (10 threads: the thread-count flags have no measurable effect here, as the setup notes record). Only events of at least us are drawn ( of ). On a GPU or TPU the device has its own rows, one per stream or core, and the host rows show only dispatch.
