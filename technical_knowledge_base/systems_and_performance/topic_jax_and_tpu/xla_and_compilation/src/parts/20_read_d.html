3. XLA's HLO and its pass pipeline

HLO (High Level Operations) is XLA's own program form. A module holds computations: the ENTRY computation is the program, and the others are called from it (fusion bodies, loop bodies, the two-argument functions that tell a reduction how to combine values). Each line is one instruction. One line of the optimised attention block, taken apart:

%dot.4 = f32[4096,128]{1,0} dot(%param_0, %param_1), lhs_contracting_dims={1}, rhs_contracting_dims={0}
 name     shape (dtype[dims])  opcode   operands          attributes: which dimensions are summed over
                       {1,0} = layout: dimension 1 is fastest-varying in memory (row-major)

The shape [4096,128] is the batch of 32 x 128 characters flattened by a pass called dot_decomposer, which puts every matmul into one canonical form. On a TPU the same line would carry a tiled layout such as {1,0:T(8,128)(2,1)} and possibly a memory space S(1), which XLA's docs gloss as "this array lives in VMEM (on a TPU)" (docs/shapes.md) Google docs; section 5 explains tiles.

The same program, pass by pass: CSE removes the duplicates, the library rewrite and fusion collapse the rest

Bars: top-level instructions after each pass that changed the text (a fusion counts as one), the current stretch highlighted; the line: how many of them are fusions measured here. Each pass's diff, opcode by opcode, is in the {{Pass diff viewer|#t-xppass}}.

Passes. XLA optimises by running passes: each reads the whole module and rewrites it (simplify algebra, remove duplicates, choose layouts, fuse, insert copies). Passes are grouped into pipelines; a pipeline wrapped in HloPassFix repeats until nothing changes, which is why the dumps show algsimp, dce and reshape-mover six times in a row. Each backend assembles its own pipeline: cpu_compiler.cc has AddPass calls naming pass classes, gpu_compiler.cc with its fusion pipeline naming , and classes appear in both read in source. The TPU pipeline lives in the closed libtpu.

Predict before you step through the passes: which single pass removes the most instructions from the train step before fusion?
cse, from to instructions. The step computes the global gradient norm twice (once inside clip_by_global_norm, once for logging), one square, sum and add per parameter array each time, and broadcasts the same scalars into each of the 69 optimiser updates. Tracing records all of it; CSE keeps one copy. Its header: "Identical constants and identical instructions with the same operands are commoned" (hlo_cse.h:32).

The chart on the right replays the pipeline on two real programs, grouped into the seven stretches below; the numbers in the steps are the train step's, and the counters follow the program you pick.

  1. Canonicalise and inline. dot_decomposer puts every matmul into one canonical form, adding reshapes and transposes around each (4,993 to 5,368 instructions), and call-inliner pastes the nested jits JAX lowered as private functions into their callers.
  2. Simplify to a fixed point. algsimp, dce and reshape-mover (with constant folding) repeat to a fixed point. tree_reduction_rewriter adds 134 reduce-windows along the way (section 4 says why).
  3. Fold transposes, then CSE. transpose-folding lets dots read their inputs transposed; common-subexpression elimination then removes the duplicates tracing recorded, from 4,681 to 3,758 instructions, the largest drop before fusion.
  4. Choose layouts. layout-assignment gives every array one memory order and adds 88 copies where a producer and a consumer disagree; reshape-decomposer turns 142 reshapes into free bitcasts (section 5).
  5. Hand work to the library (CPU only). dot-library-rewriter wraps matmuls and many reductions into 173 YNNPACK library fusions (kCustom).
  6. Fuse. fusion takes the module from 3,677 to 2,006 instructions, and fusion-wrapper wraps every leftover operation in a one-operation fusion: 799 fusions.
  7. Clean up, copy, schedule. CSE, algsimp and dce run once more, copy-insertion adds the copies aliasing needs, and the scheduled module is left with 1,784 instructions, 783 of them fusions.
