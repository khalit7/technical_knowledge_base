3. Reading other people's code: Linen and Equinox

Most JAX model code written before 2025 is Flax Linen (MaxText migrated to NNX only in mid 2026, per the root's Reading tab); much research code is Equinox. What differs is where each keeps its state, which this table says in one screen; the root's Training lab runs the same block in NNX, Linen, Equinox and Haiku against PyTorch, and its Tool map has their status (Haiku in maintenance mode, Linen maintained but not recommended for new code).

Two habits carry over. In Linen code look for init/apply, the collection names, mutable= and rngs= at every call site: the train step carries params, batch_stats and the optimiser state as three separate trees (often bundled in flax.training.train_state.TrainState). In Equinox code the model is itself the pytree, so look for the eqx.filter_* transforms. nnx.bridge.ToNNX and ToLinen wrap one in the other, which is how a codebase migrates one module at a time (Flax's bridge guide; source ).

Linen in detail, with the errors you meet (measured)

A Linen module is a frozen dataclass of hyperparameters. variables = model.init(rngs, x) runs it once to create every array, grouped into collections; model.apply(variables, x) runs it as a pure function. A block with Dense, BatchNorm, Dropout and sow (a test module in src/runs/ts_linen_eqx.py):

class LBlock(nn.Module):
    d_ff: int = 512
    @nn.compact
    def __call__(self, x, train: bool):
        h = nn.Dense(self.d_ff)(x)                 # input width read from x at init time
        h = nn.BatchNorm(use_running_average=not train, momentum=0.9)(h)
        h = nn.gelu(h, approximate=False)
        self.sow("intermediates", "hidden_mean", h.mean())
        h = nn.Dropout(0.1, deterministic=not train)(h)
        return nn.Dense(x.shape[-1])(h)
  • init returned the collections : params is what the optimiser sees; batch_stats is the running mean and variance. @nn.compact defines submodules inline and infers input sizes from the first input, so there is no d_in anywhere, unlike NNX and PyTorch.
  • Training mode updates batch_stats, so the collection must be declared mutable; apply then returns (y, updates) and you merge the updates yourself. Forgetting it measured:
  • Dropout needs an RNG passed per call (rngs={"dropout": key}); without it:
  • mutable=["batch_stats", "intermediates"] returned ; the running mean moved by up to in one call; the sown value is in updates["intermediates"]. Parameters never come out of apply: they are only an input.
  • Bridging. nnx.bridge.ToNNX(linen_module, rngs=...) plus nnx.bridge.lazy_init runs a Linen module inside NNX; its state became measured. nnx.bridge.ToLinen goes the other way.
Equinox in detail: frozen modules, non-array leaves, filtered transforms (measured)

An eqx.Module is a frozen dataclass registered as a pytree: its fields are its leaves. There is no split; you pass the model itself to transformations. Three consequences, measured on a two-layer MLP holding jax.nn.gelu as a field:

  • Frozen. model.fc1 = ... raises : . Changes are made out of place: eqx.tree_at(lambda m: m.fc1.bias, model, new) returns a new model (bias sum became ; the original is untouched).
  • Not every leaf is an array. The function field is a leaf too, so plain jax.jit on a function taking the model fails:
    eqx.filter_jit treats array leaves as traced and everything else as static, and runs (). eqx.filter_grad differentiates only floating-point arrays: the gradient had array leaves. The general tool is params, static = eqx.partition(model, eqx.is_array) and eqx.combine(params, static) ( and leaves here), the Equinox spelling of NNX's split and merge.
  • Layers act on one example (eqx.nn.Linear maps a vector); you jax.vmap over the batch. Its weight is [out, in] like PyTorch ( for 128 to 512). Stateful layers (BatchNorm) keep their running statistics in a separate eqx.nn.State object that the call takes and returns: make_with_state built a and each call returned a new one.
