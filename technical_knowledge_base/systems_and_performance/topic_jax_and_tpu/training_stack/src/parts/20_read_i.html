Checklists and provenance

Pre-flight checklist: the mistakes that give a different run with no error
  • State and RNG. A pure jax.jit step that does not return nnx.state(model) reuses the same dropout mask every step (section 1). Filters must end with ... on a model with any non-Param state. A module shared twice is a "Duplicate Param" in tree mode.
  • Recompiles. Adding an attribute, rebuilding a submodule or flipping a Python flag stored on the module changes the graphdef and recompiles (section 2); so does rebuilding the optimiser with a new Python learning rate (one compile per value, section 4).
  • Linen and Equinox. Every training apply needs mutable=["batch_stats"] and rngs={"dropout": key}, and you merge the returned updates; plain jax.jit on an Equinox model holding a function fails: use eqx.filter_jit (section 3).
  • optax. Under MultiSteps a schedule written for 10,000 updates and a loop of 10,000 micro-batches with k = 4 reaches only a quarter of the schedule. optax.contrib.muon orthogonalises embeddings and the head unless told not to (section 4).
  • orbax. Save model state (with RNG), optimiser state and the data iterator in one checkpoint; parameters alone silently restart warmup, zero the moments, re-read the first batches and repeat the masks. BestN for a loss needs reverse=True; with 0.12.7 set best_fn too or metrics are not persisted; call wait_until_finished() before exiting. Expect bitwise resumes only into the saved shardings (section 5).
  • grain. Batch in the MapDataset before to_iter_dataset(), keep filters after mp_prefetch, and resume with the same worker count (section 6).
  • Sharding. With eager sharding (default in 0.12) an annotated model needs a mesh in scope: "An auto mesh context or metadata is required if creating a variable with annotation out_sharding=..." (section 2).
  • Metrics. No loss.item() per step; accumulate with nnx.metrics and read every N steps (section 8).
Interview rehearsal: two questions that combine the sections
Why does NNX store RNG keys in the model, and what breaks if you forget them in a checkpoint?
JAX has no global generator; a key plus a counter per stream makes randomness explicit state that transforms can carry and checkpoints can save. Without it a resumed run repeats the dropout masks of the first steps: a different run, silently.
Your resumed run's loss differs from the original from the first step. What do you check?
If the first resumed loss differs, the forward pass saw different inputs or weights: the data iterator position, or the RNG streams. If the first loss matches and then drifts: the optimiser state (moments, step count, schedule). If it matches for many steps then drifts very slowly: a different compiled program changing reduction order: another mesh, or the same mesh with the state restored into its annotated shardings rather than the ones the compiler had given it (section 5).
Design: design the checkpointing for a 2-week run of a 70B model on a TPU pod that is preempted a few times a day.
Save one checkpoint item for model state, one for optimiser state, one for each host's data iterator and a JSON item for the step and config; async, sharded, each host writing its own shards (orbax OCDBT). Two tiers: local checkpoints every few minutes of work to host RAM disk, replicated across slices so a replaced slice can be refilled, and persistent ones to Cloud Storage every hour or so (orbax's emergency manager is built for this, still experimental); keep the latest plus a few by evaluation loss, and some at fixed periods for analysis. Make data order a function of (seed, step) and keep the worker count fixed. Measure: time the save call blocks the step, write bandwidth, restore time, and test a real kill and resume in staging, comparing losses for 100 steps. Restoring onto a different slice shape works (restore into the new shardings) but will not be bitwise.
What changed from the old Notion page (corrections)

This page reuses the old Notion page "Flax NNX, optax, orbax: the training stack" (Notion 3c65c17b0d0d817ea0ace9a2ca8677ec, saved verbatim in src/live.md). Every claim was checked against the pinned sources and runs here; the full list is in src/coverage.md. The corrections:

  • "nnx.split(model) ... ckptr.save(path, state); restore into nnx.state(...)": correct, but saving only the model state loses the optimiser, RNG and data position; measured consequences in section 5.
  • "Per-parameter behaviour: optax.multi_transform": now optax.partition; multi_transform remains as a backwards-compatible alias in optax 0.2.8.
  • "Use ocp.CheckpointManager for rotation/retention": still right, but max_to_keep and best_fn are marked deprecated in orbax-checkpoint 0.12.7 in favour of preservation_policy and save_decision_policy.
  • "@nnx.jit ... donates internally": not shown by anything run here, and nnx.jit takes donate_argnums/donate_argnames like jax.jit; dropped.
  • "There is no .train()/.eval() global mode": NNX modules do have model.train() and model.eval(), which set deterministic / use_running_average on every submodule (measured in section 1).
  • "EMA (optax.ema), SAM, Lion, Muon, apply-if-finite are all stock transformations": Lion, EMA and apply_if_finite are in core optax; SAM and Muon are in optax.contrib, and Muon's default applies to embeddings too (section 4).
  • "NNX ... interops via flax.nnx.bridge": verified (ToNNX, ToLinen, lazy_init, section 3). New since the old page: graph mode versus tree mode, eager sharding, and the planned switch to tree mode by default (section 1).
