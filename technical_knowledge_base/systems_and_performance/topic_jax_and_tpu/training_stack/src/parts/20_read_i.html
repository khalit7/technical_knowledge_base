Common mistakes

Calling a pure jax.jit step without returning the RNG state
The dropout counter advances inside the trace and the result is thrown away: the same mask every step, no error (section 1, measured). Use nnx.jit, or return nnx.state(model) from the jitted function and use it next call.
Changing the module's structure inside the training loop
Adding an attribute, rebuilding a submodule or flipping a Python flag stored on the module changes the graphdef, and every changed graphdef is a new compile (section 2: the trace count went from 1 to 2 on one added Param). Keep per-step values in Variables or pass them as arguments.
Non-exhaustive filters
nnx.split(model, nnx.Param) on a model with any other state raises "Non-exhaustive filters, got a non-empty remainder" (section 1). End the filter list with ....
Tied weights in tree mode
A module referenced twice is a "Duplicate Param" in tree mode (section 1). Pin graph mode, or tie by computing the head from the embedding's array instead of sharing the module.
Linen: training without mutable or without a dropout key
"Cannot update variable "mean" in "/BatchNorm_0" because collection "batch_stats" is immutable" and "Dropout_0 needs PRNG for "dropout"" (section 3). Every training apply needs mutable=["batch_stats"] and rngs={"dropout": key}, and you must merge the returned updates.
Equinox: jax.jit on a model holding a function
"Error interpreting argument ... as an abstract array. The problematic value is of type <class 'function'>" (section 3). Use eqx.filter_jit / eqx.filter_grad, or partition the model first.
Rebuilding the optimiser to change the learning rate
A new Python float is a new constant: one compile per value (3 traces for 3 values, section 4). Inject it with inject_hyperparams, or make it a schedule of the step.
Logging steps wrongly under MultiSteps
The optimiser's step count and schedules advance once per k calls. A schedule written for 10,000 updates and a loop of 10,000 micro-batches with k = 4 only reaches a quarter of the schedule.
Muon on the embeddings
optax.contrib.muon orthogonalises every 2-D leaf by default, embeddings and output head included (section 4). Pass muon_weight_dimension_numbers to keep them on Adam.
Saving parameters only
The run restarts warmup, zeroes Adam's moments, re-reads the first batches and repeats the dropout masks; the loss is off from the first resumed step with no error (section 5). Save model state (including RNG), optimiser state and the data iterator in one checkpoint.
best_mode="min" becomes reverse=True
Moving to orbax's preservation policies, BestN(get_metric_fn=loss, n=2) without reverse=True keeps the two worst checkpoints, because it keeps the last n after sorting (section 5).
Expecting a bitwise resume on a mesh while restoring into the annotated shardings
After the first jitted step the compiler had re-sharded of state leaves; restoring into a freshly built model's shardings compiles a different step and the run drifts by rounding (section 5). Restore into the saved shardings, or pin the state's shardings in the step.
Using BestN without best_fn
With orbax-checkpoint 0.12.7 the metrics are only written to disk when best_fn is set; after a restart old checkpoints have no metrics and are never cleaned up (section 5).
Exiting before the async save finishes
save() returns while the write continues; call mngr.wait_until_finished() (or close()) before the process ends.
Batching inside the workers, or changing the worker count on resume
Batch in the MapDataset before to_iter_dataset(); keep filters after mp_prefetch; and resume with the same worker count, because the iterator state is per worker (KeyError: 'next_index' otherwise; section 6).
Annotated parameters with no mesh
With eager sharding (default in 0.12) "An auto mesh context or metadata is required if creating a variable with annotation out_sharding=..." (section 2). Create the model under jax.set_mesh(mesh), or turn eager sharding off for single-device tests.
loss.item() every step
A host sync per step stalls asynchronous dispatch. Accumulate with nnx.metrics in the step and read every N steps (section 8).

Interview questions

What is a graphdef, and why is it hashable?
The static structure of an NNX object graph: node types, attribute names, static attribute values and where each Variable sits, with no arrays. NNX transforms pass it to jax.jit as a static argument, so it must be hashable; it becomes part of the compile-cache key. Same structure, same compiled program, whatever the weights.
Why does NNX store RNG keys in the model, and what breaks if you forget them in a checkpoint?
JAX has no global generator; a key plus a counter per stream makes randomness explicit state that transforms can carry and checkpoints can save. Without it a resumed run repeats the dropout masks of the first steps: a different run, silently.
How do you implement gradient accumulation in JAX, and what does it cost?
optax.MultiSteps(tx, k), or a lax.scan over micro-batches inside one jitted step that sums gradients. MultiSteps costs one extra parameter-sized accumulator and k jitted calls per update; the scan version keeps it in one program and lets XLA overlap, at the cost of a fixed k at compile time.
Why scan over layers?
The traced program and the compile time stop growing with depth (one block body, measured constant at 4 to 16 layers), and it composes with remat and pipelining. Costs: identical layer structure, no cross-layer fusion, a fixed loop overhead that made it slower to compile than unrolling at 4 tiny layers here.
Your resumed run's loss differs from the original from the first step. What do you check?
If the first resumed loss differs, the forward pass saw different inputs or weights: the data iterator position, or the RNG streams. If the first loss matches and then drifts: the optimiser state (moments, step count, schedule). If it matches for many steps then drifts very slowly: a different compiled program changing reduction order: another mesh, or the same mesh with the state restored into its annotated shardings rather than the ones the compiler had given it (section 5).
Linen versus NNX: what changed and why?
Linen modules hold no arrays and use init/apply with named collections and explicit mutable and rngs; NNX modules own Variables like PyTorch and NNX transforms split and merge them. NNX removes the collection ceremony and lazy shape inference at the cost of explicit input sizes and an object-to-pytree conversion at every transform.
Design: design the checkpointing for a 2-week run of a 70B model on a TPU pod that is preempted a few times a day.
Save one checkpoint item for model state, one for optimiser state, one for each host's data iterator and a JSON item for the step and config; async, sharded, each host writing its own shards (orbax OCDBT). Two tiers: local checkpoints every few minutes of work to host RAM disk, replicated across slices so a replaced slice can be refilled, and persistent ones to Cloud Storage every hour or so (orbax's emergency manager is built for this, still experimental); keep the latest plus a few by evaluation loss, and some at fixed periods for analysis. Make data order a function of (seed, step) and keep the worker count fixed. Measure: time the save call blocks the step, write bandwidth, restore time, and test a real kill and resume in staging, comparing losses for 100 steps. Restoring onto a different slice shape works (restore into the new shardings) but will not be bitwise.

What changed from the old page

This page reuses the old Notion page "Flax NNX, optax, orbax: the training stack" (Notion 3c65c17b0d0d817ea0ace9a2ca8677ec, saved verbatim in src/live.md). Every claim was checked against the pinned sources and runs here; the full list is in src/coverage.md. The corrections:

  • "nnx.split(model) ... ckptr.save(path, state); restore into nnx.state(...)": correct, but saving only the model state loses the optimiser, RNG and data position; measured consequences in section 5.
  • "Per-parameter behaviour: optax.multi_transform": now optax.partition; multi_transform remains as a backwards-compatible alias in optax 0.2.8.
  • "Use ocp.CheckpointManager for rotation/retention": still right, but max_to_keep and best_fn are marked deprecated in orbax-checkpoint 0.12.7 in favour of preservation_policy and save_decision_policy.
  • "@nnx.jit ... donates internally": not shown by anything run here, and nnx.jit takes donate_argnums/donate_argnames like jax.jit; dropped.
  • "There is no .train()/.eval() global mode": NNX modules do have model.train() and model.eval(), which set deterministic / use_running_average on every submodule (measured in section 1).
  • "EMA (optax.ema), SAM, Lion, Muon, apply-if-finite are all stock transformations": Lion, EMA and apply_if_finite are in core optax; SAM and Muon are in optax.contrib, and Muon's default applies to embeddings too (section 4).
  • "NNX ... interops via flax.nnx.bridge": verified (ToNNX, ToLinen, lazy_init, section 3). New since the old page: graph mode versus tree mode, eager sharding, and the planned switch to tree mode by default (section 1).
