A JAX training run is one compiled, pure step function applied to a pytree of state; Flax NNX turns your model object into that pytree, optax is a pair of pure functions over it, orbax writes it to disk, and grain makes the data position a few integers inside it. So the run you resume is the same run only when every piece of state that decides the next step (parameters, optimiser moments and step count, random streams, data position) went into the checkpoint.

One training step: everything that decides step t + 1 is state you can name, save and restore

The graphdef (the model's structure) is the only part not saved: it is rebuilt from your code and keys the compile cache, so the same structure reuses one compiled step. Section numbers on the figure point to where each box is explained; every number on this page was measured on the running example below.

You need: jax.jit, jax.grad, pytrees and PRNG keys ({{JAX core|n:3c65c17b0d0d81b7a0d1faba6cef5561}}), and a PyTorch training loop, which the table below maps onto this stack. New terms:

Variable: a typed box holding one array of an NNX module (nnx.Param, nnx.RngKey, ...).
graphdef: the module's structure with no arrays; static and hashable.
filter: a rule selecting Variables by type or path (nnx.Param, ...).
GradientTransformation: optax's (init, update) pair of pure functions.
CheckpointManager: orbax's object that saves, keeps and restores numbered steps.
MapDataset: grain's random-access dataset, record i computed from i and a seed.

Provenance: versions, machine, and what this page does not repeat

Every number was measured on an Apple M1 Pro CPU with jax 0.11.2, flax 0.12.10, optax 0.2.8, orbax-checkpoint 0.12.7, grain 0.2.18, equinox 0.13.8, dm-haiku 0.0.17, jmp 0.0.4 and torch 2.14.1, unless it is labelled published; the machine was shared with other jobs (1-minute load average 30 to 57 during these runs).
