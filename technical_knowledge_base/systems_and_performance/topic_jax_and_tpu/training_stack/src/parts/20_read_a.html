JAX gives you arrays and transformations of pure functions; four libraries turn that into a training run: Flax NNX holds the model, optax updates it, orbax saves it and grain feeds it. The parent page, {{Topic: jax-and-tpu|n:3c65c17b0d0d81ecbc04eea6aa45ea1a}}, introduced each in its Training lab tab (modules split into graphdef and state, an optax chain builder checked against the library, a checkpoint resumed bit for bit, bfloat16 with a float32 master copy). This page goes one level down: how each library holds state, what each call costs, which defaults bite, and how to check a training run is the run you meant.

The stack in four sentences
An NNX module is a Python object whose arrays live in typed Variables; every JAX transformation sees it as two things, a static, hashable graphdef (the structure, which keys the compile cache) and a state (a pytree of arrays). An optax optimiser is a pair of pure functions over pytrees, built by chaining small transformations, so its state is just more arrays. An orbax checkpoint is any pytree written shard by shard, asynchronously, restorable into whatever shapes and shardings you hand it. A grain pipeline computes every record from its index and a seed, so the loader's whole position is a few integers that go into the same checkpoint.

Every number below was measured on an Apple M1 Pro CPU with jax 0.11.2, flax 0.12.10, optax 0.2.8, orbax-checkpoint 0.12.7, grain 0.2.18, equinox 0.13.8, dm-haiku 0.0.17, jmp 0.0.4 and torch 2.14.1, unless it is labelled published. measured means run here; derived computed from measured or published numbers with the formula shown; published from a source, dated. Losses, equalities, counts and shapes are deterministic and transfer to any backend; times were taken on a machine shared with other jobs (1-minute load average 30 to 57 during these runs) and say nothing about TPUs or GPUs.
