1. Flax NNX: where the state lives

jax.jit, jax.grad and jax.vmap transform pure functions of pytrees (nested lists, tuples and dicts whose leaves are arrays). A PyTorch-style model is an object that owns its weights and changes them in place. Flax NNX keeps the object, so model code reads like PyTorch, and converts it to a pytree at every transformation boundary.

Variables: typed boxes for every array

Every array an NNX module owns sits in an nnx.Variable, and the subclass says what kind of state it is. PyTorch has two kinds (parameters the optimiser sees, buffers it does not); NNX has as many as you like, and every API that moves state takes a filter over them.

split: one object becomes a graphdef and states

graphdef, state = nnx.split(model) walks the object graph. The graphdef records every node (module, list, Variable) and every non-array attribute; the state is a pytree of the arrays, keyed by path. nnx.merge(graphdef, state) builds an equivalent object; nnx.update(model, state) writes arrays back into an existing one. With filters, nnx.split(model, f1, f2, ...) returns one state per filter: a filter is a Variable type, a path predicate (nnx.PathContains("kernel")), a combination (nnx.All, nnx.Any, nnx.Not), or ... for "everything else". It is how you say "differentiate the Params only", "decay only the kernels", "vectorise the stacked layers, broadcast the rest".

With dropout the answer is two: the dropout stream's RngKey and RngCount; the 69 others are Params. Each Variable goes to the first filter that matches it, and the filters must cover every leaf: forgetting ... raises "Non-exhaustive filters".

The graphdef of the running example has 170 nodes and 571 attributes, against 69 state leaves measured. Its static attributes include things a PyTorch user would never think of as part of the model: in_features, use_bias, dtype, param_dtype, precision, the dot_general function itself. That is the point: everything in the graphdef is a compile-time constant. Two models built with different seeds have graphdefs and equal hashes, so nnx.jit reuses one compiled program for both; change any static attribute and the graphdef, the cache key and the program all change (section 2).

Randomness is state: nnx.Rngs


PyTorch draws dropout masks from a global generator that advances by itself. JAX has no global generator: a random function takes a key and returns the same numbers for the same key. NNX stores a key and a counter per stream (params, dropout, ...) inside the model; each draw folds the counter into the key and increments it. Measured on the running example with dropout measured:




The third row is a real bug pattern: split once, call a pure jax.jit function with the state and never return the new state. The counter advances inside the trace, the advanced value is dropped, and every step gets the same dropout mask, with no error. nnx.jit avoids it by writing the updated state back into your object; with raw jax.jit return nnx.state(model) and use it next time. model.eval() sets deterministic=True on every Dropout (and use_running_average on BatchNorm), like PyTorch's.

Shared modules: graph mode and tree mode


The running example with its output head tied to the token embedding holds one Embed referenced twice. A pytree cannot express sharing: each leaf appears once. Graph mode tracks object identity, stores the shared array once and restores the sharing on merge; tree mode treats modules as plain pytrees and refuses duplicates ("Duplicate Param"). In flax 0.12.10 graph mode is  by default and graph updates  (, ); every API takes graph=. On the tied model graph mode splits into  leaves and  parameters (the untied count minus the 128 x 65 head) measured.


The defaults are planned to change
Flax's design note FLIP 5310 plans to make tree mode the default; shared modules and nnx.grad's Params-only default then go away. Code that ties weights by sharing a module, or relies on that default, should pin nnx.set_graph_mode(True) or use nnx.compat.*. Not yet the default at 0.12.10 measured.


FLIP 5310 in its own words, and the tree-mode error on the tied model
"Tree Mode NNX" (dated Mar 4, 2026, in the pinned clone) says: "The goal will be to have the default value for nnx_graph_mode and nnx_graph_updates to be set to False" (). Under tree mode, shared references, prefix filters (StateAxes, DiffState, StateSharding) and structure changes inside transforms go away, and nnx.grad returns gradients of the input's own type ().
Pin graph mode, or tie by computing the head from the embedding's array instead of sharing the module.
