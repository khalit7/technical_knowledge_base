1. Flax NNX: where the state lives

The problem. jax.jit, jax.grad and jax.vmap transform pure functions of pytrees (nested lists, tuples and dicts whose leaves are arrays). A PyTorch-style model is an object that owns its weights and changes them in place. Flax NNX keeps the object, so model code reads like PyTorch, and converts it to a pytree at every transformation boundary.

Variables: typed boxes for every array

Every array an NNX module owns sits in an nnx.Variable, and the subclass says what kind of state it is. PyTorch has two kinds (parameters, which the optimiser sees, and buffers, which it does not); NNX has as many as you like, and every API that moves state takes a filter over them.

graphdef and state: the running example taken apart

graphdef, state = nnx.split(model) walks the object graph. The graphdef records every node (module, list, variable) and every non-array attribute; the state is a pytree of the arrays, keyed by path. nnx.merge(graphdef, state) builds an equivalent object, and nnx.update(model, state) writes arrays back into an existing one. The static attributes include things a PyTorch user would never think of as part of the model: in_features, use_bias, dtype, param_dtype, precision, the dot_general function itself, and the running example's own h and dh. That is the point: everything in the graphdef is a compile-time constant. Two models built with different seeds have graphdefs and equal hashes, so nnx.jit reuses one compiled program for both; change any static attribute and the graphdef, the cache key and the program all change (section 2).

Filters: splitting state into groups

nnx.split(model, f1, f2, ...) returns one state per filter. A filter is a Variable type, a path predicate (nnx.PathContains("kernel")), a combination (nnx.All, nnx.Any, nnx.Not), or ... for "everything else". It is how you say "differentiate the Params only", "decay only the kernels", "vectorise the stacked layers, broadcast the rest". Randomness is state: nnx.Rngs

PyTorch draws dropout masks from a global generator that advances by itself. JAX has no global generator: a random function takes a key and returns the same numbers for the same key ({{JAX core|n:3c65c17b0d0d81b7a0d1faba6cef5561}}, section 9). NNX stores a key and a counter per stream (params, dropout, ...) inside the model; each draw folds the counter into the key and increments it. Measured on the running example with dropout added measured:

The third row is a real bug pattern: split the model once, close over the graphdef, call a pure jax.jit function with the state and never return the new state. The counter advances inside the trace, but the advanced value is dropped, so every step gets the same dropout mask. Nothing errors. nnx.jit avoids it by writing the updated state back into your object after the call; with raw jax.jit you must return nnx.state(model) and use it next time (fourth row). model.eval() sets deterministic=True on every Dropout (and use_running_average on BatchNorm), like PyTorch's model.eval(); the eval output equals the same weights in the dropout-free model exactly (largest difference ).

Graph mode and tree mode

An object graph can share: the running example with its output head tied to the token embedding holds one Embed referenced twice. PyTorch handles this naturally (two attributes, one tensor). A pytree cannot express sharing: each leaf appears once. NNX has two modes. Graph mode tracks object identity, stores the shared array once and restores the sharing on merge. Tree mode treats modules as plain pytrees and refuses duplicates. In flax 0.12.10 the defaults are graph mode and graph updates (, ), and every API takes graph=. The defaults are planned to change
Flax's design note FLIP 5310 "Tree Mode NNX" (dated Mar 4, 2026, in the pinned clone) says: "The goal will be to have the default value for nnx_graph_mode and nnx_graph_updates to be set to False" (). Under tree mode, shared references, prefix filters (StateAxes, DiffState, StateSharding) and structure changes inside transforms go away, and nnx.grad stops defaulting to Params only and returns gradients of the input's own type (). Code that ties weights by sharing a module, or relies on nnx.grad's default filter, should pin nnx.set_graph_mode(True) or use nnx.compat.*. Not yet the default at 0.12.10 measured.
