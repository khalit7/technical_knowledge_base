## Corrections and refinements to statements elsewhere in the topic (suggested, not edited)
- Root `src/data/README.md` and FACTS "setup": "Adam divides each update by the running root-mean-square of the gradient: a gradient of pure float noise is normalised into steps as large as the learning rate". Measured here: with eps = 1e-8 and key-bias gradients near 2e-11, each Adam update is about lr x g / eps (about 2e-6 at lr 1e-3, roughly 450 times smaller than lr). The key biases still drift most at 500 steps because nothing restores them (zero true gradient, no weight decay), so the noise accumulates; after 100 steps they differ by 7.2e-5 while other weights agree to 3.6e-7 (`runs/out/ladder_float32.json`).
- Root README: "the extra 1e-6 [in PyTorch's clip formula] changes the scale by about one part in a million, the size of float32 rounding". True in float32 (training with PyTorch's formula in JAX stays within 2e-6 of PyTorch, `hunt.json` clip_eps). In float64 it is one of two visible remaining differences: switching the JAX twin to PyTorch's formula reduces the 100-step loss gap from 5.5e-8 to 1.4e-8 (`ladder_float64.json`). The larger one is Adam's lr / eps amplification of last-bit gradient differences on tiny gradients (one-step gap 1.8e-12 = gradient gap 6.7e-16 x about 2,000, within a factor 1.4).
- The root's `equiv.json` reports loss PyTorch vs JAX 0.0 at batch 0; the jitted value_and_grad path used here gives 4.8e-7 (1 ulp at 4.21). Both are rounding; not a contradiction, but worth knowing that "0.0" depends on the code path.
- Flax NNX's `nnx.LayerNorm` uses `use_fast_variance=True` by default (flax/nnx/nn/normalization.py:515 at v0.12.10). The root's NNX twin therefore computes the variance differently from PyTorch; on this model it is harmless (logits within 8.3e-7), but the root's README lists only the epsilon difference for LayerNorm.
