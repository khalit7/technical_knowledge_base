2. Propagation: annotate a few arrays, the compiler does the rest

How it works. You write the single-device program and annotate some arrays: the inputs (by passing sharded arrays, or in_shardings to jax.jit), the outputs (out_shardings), and if you need to, a few intermediates with jax.lax.with_sharding_constraint(x, sharding). The compiler then does two jobs. Sharding propagation gives every other array a sharding, by pushing the known ones through each operation (a matmul whose input rows are split on data produces output rows split on data). The SPMD partitioner then rewrites the program into the one program every device runs on its own shard (SPMD: single program, multiple data), and wherever an operation needs data laid out differently from how it is, inserts a collective: an operation in which a group of devices exchange data. The design is GSPMD ({{Xu et al. 2021|https://arxiv.org/abs/2105.04663}}); since JAX 0.7.0 the propagation step is done by default by its successor Shardy, and both hand over to the same partitioner (XLA's source shows the switch, section 7). PyTorch has no counterpart for whole programs: DTensor decides operator by operator at run time, and torch.compile does not re-plan the communication.

The cost. You do not see the communication in your code. It appears only in the compiled program, so checking it is part of the job: jax.jit(f).lower(*args).compile().as_text() and search for all-reduce, all-gather, reduce-scatter, all-to-all, collective-permute. That is exactly how every number on this tab was obtained.

Read the playground like this. Three rules explain almost every row. (1) If both operands are split along the dimension that is summed over (x columns and W rows on the same axis: P(None,'model') @ P('model',None)), each device computes a partial sum and the compiler adds them with an all-reduce: this is Megatron's row-parallel layer. (2) If one operand is split along the summed dimension and the other is not, the compiler all-gathers the split one first. (3) If you ask for an output layout the matmul does not produce, it adds an all-gather (to replicate), an all-to-all (to move a split from one dimension to another) or a collective-permute (to swap which device holds which block). Left to itself ("compiler's choice"), it picks an output layout that needs no communication whenever one exists.

Ring costs derived for an array of N bytes: in a ring all-gather each device forwards n − 1 blocks of N/n; a ring all-reduce is a reduce-scatter followed by an all-gather, so twice that. The scaling book states the same costs as time: an AllGather or ReduceScatter takes "Data volume / bandwidth · (Axis − 1)/Axis" and an AllReduce twice that ({{How to Scale Your Model, part 3, 2025-02-04|https://jax-ml.github.io/scaling-book/sharding/}}).
