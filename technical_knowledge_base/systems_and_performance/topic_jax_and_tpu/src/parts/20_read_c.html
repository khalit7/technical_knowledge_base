3. What the compiler does

A jitted function passes through four forms, each printable: the jaxpr (jax.make_jaxpr(f)(x)); StableHLO, a versioned, portable operation set in MLIR and the hand-off point between frameworks and compilers (PyTorch's TPU and Trainium backends emit it too; jax.jit(f).lower(x).as_text()); optimised HLO after XLA's passes (.compile().as_text()); and machine code (LLVM for CPUs, GPU kernels, some through Triton, or the TPU backend).

The running example's train step through the pipeline: thousands of operations become about 800 kernels

The passes that matter to you, each defined once:

  • Fusion: a chain of elementwise operations (often with the reduction after it) becomes one kernel, so intermediates never make a round trip to HBM. The whole step, backward and optimiser included, is one program to fuse across, which is why a JAX step is usually fast without hand-written kernels.
  • Layout assignment (which dimension is contiguous, padding to the hardware's tiles), algebraic simplification, and buffer assignment, which lets arrays with non-overlapping lifetimes share memory; compiled.memory_analysis() reports its result before anything runs.
  • Donation: jax.jit(step, donate_argnums=0) promises the old parameters and optimiser state are dead, so the new ones reuse their buffers instead of a second copy existing. Flax's nnx.jit donates nothing unless asked.
  • Rematerialisation: jax.checkpoint (alias jax.remat) recomputes activations in the backward pass instead of storing them; policies choose what to keep. PyTorch: activation checkpointing.

Compile time is real time. A large step's first call can take seconds to minutes; the executable is cached in memory, and a persistent compilation cache (jax.config.update("jax_compilation_cache_dir", ...)) keeps it across runs. Long Python loops multiply compile time, which is why layers are stacked and run with lax.scan.

Against torch.compile. TorchDynamo reads Python bytecode, captures what it can, and at anything it cannot handle inserts a graph break that runs eagerly. JAX never reads your Python: Python control flow is resolved while tracing or is an error. One graph or none, no silent fallback ({{torch.compile from the user's side|n:3c65c17b0d0d8123a232d75bd7339ecb}} owns the PyTorch side).

Two measurements on the running example

compiled.cost_analysis() counts a loop body once: the step written with lax.scan reports 6.39 GFLOP against 23.71 for the unrolled step measured (Compiler lab), so multiply by the trip count yourself. Flax's donation spelling is @nnx.jit(donate_argnames=("model", "optimizer")) (flax 0.12.10, nnx/transforms/compilation.py:317-318).
