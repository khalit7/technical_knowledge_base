2. The functional model and the transformations

Tracing. When a transformation meets your function, JAX calls it once with tracers: stand-ins that carry an abstract value (shape and dtype, no numbers) and record every array operation into a jaxpr, a small typed program of primitives. Python itself (loops, helper functions, arithmetic on shapes) runs to completion and leaves no trace. Every transformation is then an interpreter over that program, which explains the rest:

  • jax.jit(f) compiles the jaxpr with XLA and caches the executable under the call's signature: argument shapes and dtypes, plus any argument marked static, whose Python value is baked in. A new signature means a new trace and a new compile; shapes are always static, so variable lengths are padded and masked. PyTorch: torch.compile, but all or nothing.
  • jax.grad(f), jax.value_and_grad(f) return a function computing the gradient of a scalar f, with exactly the structure of the parameters: no .grad attributes, no zero_grad(). PyTorch: loss.backward(), but as a function; jax.lax.stop_gradient is detach().
  • jax.vmap(f) turns a function for one example into one for a batch by rewriting each primitive into its batched form. Per-example gradients are vmap(grad(loss), in_axes=(None, 0)). PyTorch: torch.func.vmap, which ports the idea.

The discipline follows from tracing. Arrays are immutable (x = x.at[0].set(1.0) returns a new array; under jit it becomes an in-place write). A Python if on a traced value is an error and a Python loop is unrolled, so compiled code uses jax.lax.cond, jnp.where, jax.lax.scan and while_loop. Randomness is a value: a key (jax.random.key(0)) is split into a fresh subkey for every use, and the same key always gives the same numbers. And a pytree (nested lists, tuples, dicts and registered classes with arrays at the leaves) holds parameters, gradients and optimiser state alike: jax.tree.map(lambda p, g: p - lr * g, params, grads) is a complete SGD step, replacing model.parameters(), state_dict() and parameter groups.

Predict: a jitted function contains print("step", x). You call it three times with arrays of the same shape. What appears?

One line, showing a tracer. The body runs only while tracing; the second and third calls hit the cache and Python never runs. Use jax.debug.print for values at run time.

import jax, jax.numpy as jnp

@jax.jit
def f(x):
    print("step", x)
    return x * 2

for _ in range(3):
    f(jnp.ones(4))
step JitTracer(float32[4])

Inputs with their abstract values, one primitive per line, no Python left. The GELU became tanh and a cube because jax.nn.gelu defaults to the tanh approximation (approximate=True) while PyTorch's nn.GELU defaults to the exact form (approximate='none'). Nested transformations: each primitive is handled by the current trace, held in a context (core.trace_ctx); tracing has been "stackless" since jax 0.4.36 (December 2024), so explanations of trace levels and MainTrace, including part 1 of Autodidax, describe machinery that no longer exists, and an inner jit prints as jit, where older posts show pjit. Loops: lax.scan is how layers, RNNs and decode loops are written, and much faster to compile than an unrolled loop; fori_loop and while_loop with a dynamic trip count are not reverse-differentiable. Flax's nnx.Rngs does the key splitting inside models.
