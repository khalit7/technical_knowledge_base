4. The training stack

JAX itself has no layers, optimisers or checkpoints. Four libraries supply them, each a separate install, and together they are what Google calls the JAX AI stack ({{docs.jaxstack.ai|https://docs.jaxstack.ai/}}). Versions are the latest on PyPI on 2026-10-15.

PyTorchJAX stackThe difference that matters
nn.ModuleFlax NNX (flax 0.12.10): nnx.Module, nnx.Linear(d_in, d_out, rngs=rngs)Feels like PyTorch: modules hold their parameters as attributes (nnx.Param) and are built eagerly. To enter a JAX transformation a module is split into a static graphdef (its structure) and a state pytree (its arrays) and merged back after; nnx.jit and nnx.value_and_grad do this for you.
torch.optim.AdamWoptax (0.2.8): optax.adamw(...)An optimiser is a pair of pure functions, init(params) and update(grads, state, params), returning updates you apply. Clipping, schedules, weight-decay masks, accumulation (MultiSteps) and EMA are links in optax.chain(...), not subclasses; a schedule is just a function of the step.
torch.save, DCPorbax (orbax-checkpoint 0.12.7)Asynchronous and sharded by default: each host writes its own shards and restores straight into a target sharding; the counterpart of torch.distributed.checkpoint, but the default path.
DataLoadergrain (0.2.18)Deterministic shuffling and an iterator whose position is saved with the checkpoint, so a preempted run resumes mid-epoch on exactly the next batch.

Which neural-network library. Flax's own docs: "Flax NNX is an evolution of the previous Flax Linen API", "new users are encouraged to use Flax NNX", and Linen "is not going to be deprecated in the near future as most of Flax users still rely on this API" ({{Flax docs|https://flax.readthedocs.io/en/latest/}}). Linen modules hold no state: model.init(key, x) returns a parameter dict and model.apply(params, x) runs it, so most JAX code written before 2025 reads like that. Equinox (0.13.8) makes a model itself a pytree, minimal and popular in research. Haiku: "As of July 2023 Google DeepMind recommends that new projects adopt Flax instead of Haiku"; it is in maintenance mode, bug fixes and JAX compatibility only, though still released (0.0.17, 2026-07-27) ({{Haiku README|https://github.com/google-deepmind/dm-haiku}}). For a PyTorch user writing new code: NNX, and learn to read Linen.

Mixed precision. The common recipe is the same as in PyTorch, written explicitly: float32 master parameters and optimiser state, a bf16 copy for the forward and backward matmuls, float32 for reductions such as softmax and the loss. On TPUs bf16 is native and no loss scaling is needed.

A whole train step, in the running example's JAX twin:

import jax, optax
from flax import nnx
import common as C, model_nnx as M                # the running example (src/data)

model = M.make_model(C.CFG)                       # built eagerly, like an nn.Module
optimizer = M.make_optimizer(model, C.CFG)        # nnx.Optimizer(model, optax chain, wrt=nnx.Param)

@nnx.jit                                          # one compiled program: forward, backward, update
def train_step(model, optimizer, x, y):
    def loss_fn(model):
        logits = model(x)                         # [B, T, vocab]
        return optax.softmax_cross_entropy_with_integer_labels(logits, y).mean()
    loss, grads = nnx.value_and_grad(loss_fn)(model)   # grads mirror the parameters
    optimizer.update(model, grads)                # zero_grad + backward + step, in one call
    return loss

params = nnx.state(model, nnx.Param)
print("parameters:", sum(p.size for p in jax.tree.leaves(params)))
for step in range(3):
    x, y = C.batch(step)                          # int32 [32, 128]: the batches PyTorch reads too
    print(step, x.shape, float(train_step(model, optimizer, x, y)))

Ran with jax 0.11.2 and flax 0.12.10 on Apple M1 Pro (CPU); output as printed. The model and optimiser come from src/data/model_nnx.py (AdamW with warmup, global-norm clipping and weight decay on weight matrices only); float(...) forces a host sync, fine for three steps and a mistake in a real loop.
