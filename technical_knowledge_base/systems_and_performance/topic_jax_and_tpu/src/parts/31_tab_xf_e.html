9. vmap: write it for one example, run it on a batch

The problem. Many computations are easiest to write for one example: one sequence's loss, one query against one key, one sample's gradient. Batching them by hand means adding a leading dimension everywhere and getting every transpose right; a Python loop over examples is slow. jax.vmap(f, in_axes=...) does the rewrite for you: it traces f with batch tracers that remember which dimension is the batch, and replaces each primitive with its batched form through that primitive's batching rule. No loop survives into the program. in_axes gives the batched dimension of each argument (None for an argument shared by the whole batch); out_axes places it in the output.

The MLP on one token, then vmapped over the 4,096 tokens of a batch

jax.make_jaxpr(mlp)(p, x_one)                           # x_one: f32[128], one token
jax.make_jaxpr(jax.vmap(mlp, in_axes=(None, 0)))(p, x)  # x: f32[4096,128], 32 x 128 tokens; p shared

Per-example gradients of the running example


Ordinary training needs the batch-mean gradient, but some methods need one gradient per example: differentially private SGD clips each example's gradient norm before averaging, and data-attribution methods score examples by their gradients. In PyTorch the plain way is a loop of backward() calls; torch.func.vmap with torch.func.grad ports JAX's approach. Here all four ways computed the 32 per-example gradients of the running example's loss (32 sequences of 128 characters, 826,368 parameters each, so  of gradients):

Why vmap wins here. The loop runs 32 small programs, each with matrix products of one sequence; the vmapped program runs one program whose matrix products carry the batch, which keeps the hardware busy and pays dispatch overhead once. 10. Inside: every transformation is an interpreter


JAX's core is small. Each transformation is a trace object (an interpreter) with one method that matters, process_primitive. Every jnp or lax call ends in Primitive.bind, which hands the operation to whichever trace is current. Transformations nest by stacking traces: under jit(vmap(grad(f))), grad's trace handles an operation first and calls the operation again on its parent (vmap's), which calls it on jit's, which records it. Section 1's tracer table showed exactly that nesting.
