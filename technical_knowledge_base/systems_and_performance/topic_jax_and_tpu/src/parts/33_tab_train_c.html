2. optax: an optimiser is a pair of pure functions

The problem. torch.optim.AdamW is an object that holds the moment estimates and writes into the parameters in step(); parameter groups carry per-group settings such as "no weight decay on biases", and a separate scheduler object changes the learning rate. Under jit nothing may be mutated, so optax splits the optimiser into data and functions.

How it works. An optax GradientTransformation is two pure functions: init(params) returns the optimiser state (a pytree, for Adam the step count and the two moment trees), and update(grads, state, params) returns (updates, new_state). You add the updates yourself with optax.apply_updates(params, updates), a plain sum. Bigger optimisers are optax.chain(...) of small transformations, and that is literally how optax.adamw is written: chain(scale_by_adam(b1, b2, eps), add_decayed_weights(weight_decay, mask), scale_by_learning_rate(learning_rate)) ({{alias.py:724-727|https://github.com/google-deepmind/optax/blob/107e9ad20ca62bcbee1a8c016daab71c690a678c/optax/_src/alias.py#L598-L727}} at optax v0.2.8). A mask (a pytree of booleans, or a function returning one) replaces parameter groups, and a learning-rate schedule is just a function of the step count.

Checked against torch.optim.AdamW on the same gradients

Both libraries implement decoupled weight decay (Loshchilov and Hutter). PyTorch shrinks the weights first, then takes the Adam step: param.mul_(1 - lr * weight_decay), then param.addcdiv_(exp_avg, denom, value=-step_size) with denom = sqrt(v) / sqrt(1 - b2^t) + eps ({{torch/optim/adam.py:419, 544-546|https://github.com/pytorch/pytorch/blob/v2.14.1/torch/optim/adam.py#L419}}, torch 2.14.1). optax adds weight_decay * p to the Adam direction and multiplies the sum by -lr ({{transform.py:300|https://github.com/google-deepmind/optax/blob/107e9ad20ca62bcbee1a8c016daab71c690a678c/optax/_src/transform.py#L300}}, {{_adding.py:72-73|https://github.com/google-deepmind/optax/blob/107e9ad20ca62bcbee1a8c016daab71c690a678c/optax/transforms/_adding.py#L72}}). Same algebra, different rounding order. To test only the optimisers, both were fed the same 50 gradients: the running example's real gradients on training batches 0 to 49, all taken at the initial weights.
