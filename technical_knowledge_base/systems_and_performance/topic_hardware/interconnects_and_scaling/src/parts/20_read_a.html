1. In one screen

A training run on many GPUs is many copies of one computation that must keep agreeing: after every step their gradients are summed, and when a model is split, partial results are passed between GPUs inside every layer. The wires that carry these bytes form a ladder: each rung reaches more GPUs and is roughly an order of magnitude slower than the one above. Which kind of parallelism you can afford is decided by which rung its traffic has to cross.

Bandwidth per GPU, each direction, H100 generation unless named. HBM: 3.35 TB/s ({{H100 page|https://www.nvidia.com/en-us/data-center/h100/}}). NVLink 4: "900 GB/sec total" per H100 over 18 links ({{Hopper in depth|https://developer.nvidia.com/blog/nvidia-hopper-architecture-in-depth/}}), 450 each way; NVLink 5 on Blackwell 1.8 TB/s total ({{NVLink page|https://www.nvidia.com/en-us/data-center/nvlink/}}). PCIe 5.0 x16: 63 GB/s each way (32 GT/s per lane, 128b/130b encoding). One 400 Gb/s network card (NIC) per GPU: 50 GB/s each way; an AWS p5 server has 3,200 Gb/s for its 8 H100s ({{AWS P5|https://aws.amazon.com/ec2/instance-types/p5/}}). vendor spec

2. The two numbers of every link: latency and bandwidth

The problem. "NVLink is 450 GB/s" sounds like a single speed, but a 1 KB message over it does not take 2 nanoseconds. Before any byte moves, software has to post the request, the hardware has to set up the transfer, the first bits have to travel and the receiver has to notice they arrived. That fixed cost is paid per message, whatever its size.

How it works. The standard model, used by MPI and NCCL designers alike, charges a message of m bytes

t(m) = α + m / β
α
latency: start-up time per message (microseconds)
β
bandwidth: bytes per second once the data flows, in one direction

It is called the alpha-beta model (or Hockney model). Its most useful consequence is the half-bandwidth size n½ = α × β: a message of that size spends as long starting as it spends flowing, so it reaches half the link's bandwidth. Below it, latency dominates and more bandwidth hardly helps; above it, bandwidth dominates.

α for NVLink, InfiniBand and RoCE: 64-byte end-to-end latencies DeepSeek measured on its H800 cluster ({{Zhao et al. 2025, Table 5|https://arxiv.org/html/2505.09343}}) independent. The laptop row is measured here: two processes exchanging messages through PyTorch's Gloo library over the loopback network (section 7 has the full data). Rows marked "assumed" have no published latency I could find.

What it means for training. A fast link is only fast for big messages. NVLink's n½ is about 1.5 MB; to use it well, collectives must move megabytes at a time. This is why PyTorch's DistributedDataParallel groups gradients into buckets (25 MiB by default) instead of sending each layer's gradient on its own, and why NCCL switches algorithms by message size (section 7). It is also why a tensor-parallel all-reduce of a single decoded token (8 KB for a 4,096-wide model) is latency-bound on any link: the bytes are trivial, the start-up cost is not.

Predict first. Per direction, NVLink 4 is 9 times a 400 Gb/s NIC (450 against 50 GB/s). For a 64 KB message, how much faster is NVLink, using the α values above?
NVLink: 3.33 µs + 65,536 / 450 GB/s = 3.48 µs. NIC: 2.8 µs + 65,536 / 50 GB/s = 4.11 µs. Ratio 1.18 derived. At this size both are almost pure latency; the 9 times only appears for messages far above n½.

Per direction, or both added? Vendors usually print the sum of both directions: "900 GB/s" for NVLink 4 is 450 each way; "1.8 TB/s" for NVLink 5 is 900 each way; the "128 GB/s" AMD prints for PCIe 5.0 x16 ({{MI300X data sheet|https://www.amd.com/content/dam/amd/en/documents/instinct-tech-docs/data-sheets/amd-instinct-mi300x-data-sheet.pdf}}) is 64 each way before encoding overhead. Network speeds are quoted in bits per second, per direction: 400 Gb/s is 50 GB/s each way. Every number on this page is per direction unless it says otherwise, because an all-reduce sends and receives at once and is limited by one direction.

Correction to a common comparison
NVIDIA's own pages compare NVLink's two-direction total with PCIe's: "7x the bandwidth of PCIe Gen 5" ({{Hopper in depth|https://developer.nvidia.com/blog/nvidia-hopper-architecture-in-depth/}}), "over 14x" for NVLink 5 ({{GB200 NVL72 blog|https://developer.nvidia.com/blog/nvidia-gb200-nvl72-delivers-trillion-parameter-llm-training-and-real-time-inference/}}). Per direction the H100 ratio is 450 against 64, also 7 times. The old version of this page called a PCIe 5.0 pair "two orders below NVLink"; it is under one order (7 times per direction, 14 times against NVLink's two-direction total). The sibling page {{GPU architecture|n:3c65c17b0d0d810682aae39bd614ec64}} carries the same correction.
