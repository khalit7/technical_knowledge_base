3. PCIe: the bus every device sits on

The problem. A GPU is a card plugged into a computer. The CPU has to send it work and data, the network card has to reach its memory, and on cards without NVLink, GPUs have to reach each other. All of that goes over PCI Express (PCIe).

How it works. A PCIe link is a bundle of lanes; each lane is two pairs of wires, one per direction, so a link sends and receives at the same time. A GPU slot has 16 lanes ("x16"). Each generation doubled the rate per lane. Data on the wire is wrapped in an encoding that costs a little: 8b/10b (20% overhead) until 2.0, 128b/130b (1.5%) from 3.0, and from 6.0 a new scheme with four voltage levels per symbol (PAM4) and fixed-size packets (FLITs) with error correction, carrying 242 useful bytes in every 256.

What sits on it in a GPU server. In an 8-GPU HGX server the GPUs, their network cards and NVMe drives hang off PCIe switches that connect to the two CPUs. Two features matter for training. Peer-to-peer lets one GPU read another's memory over PCIe without staging through CPU memory. GPUDirect RDMA lets a network card read and write GPU memory directly, so gradients leave the server without a copy into CPU memory; it works best when the NIC and GPU share a PCIe switch, which is why HGX boards pair each GPU with its own NIC. The NCCL 2.27 notes give a current example of PCIe being the limit: ConnectX-8 NICs and Blackwell GPUs speak PCIe 6.0, enough for 800 Gb/s, "However, Grace CPUs currently only support PCIe Gen5, which limits throughput to 400 Gb/s" when traffic goes through the CPU ({{NCCL 2.27 blog|https://developer.nvidia.com/blog/enabling-fast-inference-and-resilient-training-with-nccl-2-27/}}).

Consumer cards. GeForce cards from the RTX 4090 on have no NVLink, so two RTX 5090s in one workstation talk over PCIe 5.0: 63 GB/s each way, about a seventh of an H100's NVLink. The parent page's drill works the consequence: the 8B's gradient all-reduce between two such cards takes about 255 ms derived: 16.06 GB / 63 GB/s, ring with n = 2.

4. NVLink and NVSwitch: the scale-up domain

The problem. Tensor parallelism exchanges activations several times per layer, so GPUs splitting one model need bandwidth near their memory's, far beyond PCIe. Wiring every GPU to every other with fat links does not scale: with 8 GPUs each would need 7 links, each carrying only a seventh of its total.

How it works. NVLink is NVIDIA's GPU-to-GPU link: many lanes of fast serial wires, grouped into links. Since the A100, the links go not to other GPUs but to NVSwitch chips, so any GPU can send to any other at its full NVLink bandwidth, and all can do so at once. The set of GPUs joined this way is the NVLink domain (or scale-up domain). Inside it, GPUs can also load and store each other's memory directly, like one bigger GPU with slower remote memory.

Why a switch and not a mesh. NVIDIA's own comparison: without NVSwitch, each of 8 GPUs "must split the same 900 GB/s connectivity into seven dedicated 128 GB/s point-to-point connections", while through NVSwitch any pair gets the full 900 ({{NVIDIA, Aug 2024|https://developer.nvidia.com/blog/nvidia-nvlink-and-nvidia-nvswitch-supercharge-large-language-model-inference/}}). AMD's MI300X takes the mesh route: 7 Infinity Fabric links of 128 GB/s (both directions) join each GPU directly to the other 7 on the board ({{MI300X data sheet|https://www.amd.com/content/dam/amd/en/documents/instinct-tech-docs/data-sheets/amd-instinct-mi300x-data-sheet.pdf}}). A mesh is cheaper and has no switch hop, but a single pair of GPUs only ever gets one link, 64 GB/s each way; collectives must be written to use all 7 links at once to see the 448 GB/s total. SemiAnalysis attributes NVIDIA's lead in their single-node collective tests to exactly this, "450GByte/s NVLink switched topology with in-network reduction (NVLS), compared to MI300X's 7x64GByte/s xGMI point-to-point topology" ({{SemiAnalysis, Dec 2024|https://semianalysis.com/2024/12/22/mi300x-vs-h100-vs-h200-benchmark-part-1-training/}}) independent.

The NVL72 rack. GB200 NVL72 puts 72 Blackwell GPUs (and 36 Grace CPUs) in one NVLink domain. Nine switch trays, each with two NVLink switch chips of 72 ports, connect all 18 links of every GPU: "Each NVLink switch tray delivers 144 NVLink ports at 100 GB so the nine switches fully connect each of the 18 NVLink ports on every one of the 72 Blackwell GPUs", through "a copper cable cartridge" rather than optics; 72 × 1.8 TB/s gives the 130 TB/s headline ({{GB200 NVL72 blog|https://developer.nvidia.com/blog/nvidia-gb200-nvl72-delivers-trillion-parameter-llm-training-and-real-time-inference/}}, {{DGX GB200 user guide|https://docs.nvidia.com/dgx/dgxgb200-user-guide/hardware.html}}). The point is the domain size: tensor or expert parallelism of up to 72 instead of 8 at NVLink speed, which large mixture-of-experts models use.

In-switch reduction (NVLink SHARP). Third-generation NVSwitch (Hopper) and later can add numbers inside the switch: GPUs send their data in, the switch sums it and multicasts the result back. NVIDIA: "In-fabric multicast and reductions provide up to 2x throughput gain while significantly reducing latency for small block size collectives" ({{Hopper in depth|https://developer.nvidia.com/blog/nvidia-hopper-architecture-in-depth/}}). NCCL calls the algorithm NVLS (since version 2.17, {{NCCL environment variables|https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html}}). Section 7 shows why the gain is close to 2: each GPU sends its buffer once instead of nearly twice.

Other scale-up fabrics. Google's TPUs join chips directly in a torus over ICI, without switches; the sibling page {{TPUs and other accelerators|n:3c65c17b0d0d8151bbc2e0ceea196187}} owns it. NVLink-C2C joins a Grace CPU to its GPUs at 900 GB/s ({{GB200 NVL72 blog|https://developer.nvidia.com/blog/nvidia-gb200-nvl72-delivers-trillion-parameter-llm-training-and-real-time-inference/}}). UALink is an open scale-up standard: its 1.0 specification defines 200 Gb/s lanes, 800 Gb/s per four-lane station and "up to 1024 endpoints" with load/store semantics ({{UALink Consortium, May 2025|https://ualinkconsortium.org/blog/ualink-200g-1-0-specification-overview-802/}}); AMD's Helios rack carries it over Ethernet (parent page, Chip atlas).
