1. The two numbers of every link: latency and bandwidth

Predict first. Per direction, NVLink 4 is 9 times a 400 Gb/s NIC (450 against 50 GB/s). For a 64 KB message, how much faster is NVLink?
NVLink: 3.33 µs + 65,536 / 450 GB/s = 3.48 µs. NIC: 2.8 µs + 65,536 / 50 GB/s = 4.11 µs. Ratio 1.18 derived. At this size both are almost pure latency; the 9 times only appears for messages far above n½.

Before any byte moves, software posts the request, the hardware sets up the transfer, the first bits travel and the receiver notices they arrived. That fixed cost is paid per message, whatever its size. The standard model, used by MPI and NCCL designers alike (the alpha-beta or Hockney model), charges a message of m bytes

t(m) = α + m / β
α
latency: start-up time per message (microseconds)
β
bandwidth: bytes per second once the data flows, in one direction

A fast link is only fast for big messages: effective bandwidth climbs to β only past n½

The half-bandwidth size n½ = α × β is where a message spends as long starting as flowing, so it reaches half the link's bandwidth (the dots on the curves). NVLink's n½ is about 1.5 MB. This is why PyTorch's DistributedDataParallel groups gradients into buckets (25 MiB by default), why NCCL switches algorithms by message size (section 7), and why a tensor-parallel all-reduce of one decoded token (8 KB for a 4,096-wide model) is latency-bound on any link.

α for NVLink, InfiniBand and RoCE: 64-byte end-to-end latencies DeepSeek measured on its H800 cluster ({{Zhao et al. 2025, Table 5|https://arxiv.org/html/2505.09343}}) independent. The laptop row is measured here: two processes exchanging messages through PyTorch's Gloo library over the loopback network (section 7). Rows marked "assumed" have no published latency I could find.

Per direction, always. Vendors usually print both directions added: "900 GB/s" for NVLink 4 is 450 each way, "1.8 TB/s" for NVLink 5 is 900, the "128 GB/s" AMD prints for PCIe 5.0 x16 ({{MI300X data sheet|https://www.amd.com/content/dam/amd/en/documents/instinct-tech-docs/data-sheets/amd-instinct-mi300x-data-sheet.pdf}}) is 64 before encoding. Network speeds are bits per second per direction: 400 Gb/s is 50 GB/s each way. This page uses per direction throughout, because an all-reduce sends and receives at once.

Correction to a common comparison
NVIDIA's own pages compare NVLink's two-direction total with PCIe's: "7x the bandwidth of PCIe Gen 5" ({{Hopper in depth|https://developer.nvidia.com/blog/nvidia-hopper-architecture-in-depth/}}), "over 14x" for NVLink 5 ({{GB200 NVL72 blog|https://developer.nvidia.com/blog/nvidia-gb200-nvl72-delivers-trillion-parameter-llm-training-and-real-time-inference/}}). Per direction the H100 ratio is 450 against 64, also 7 times. The old version of this page called a PCIe 5.0 pair "two orders below NVLink"; it is under one order (7 times per direction, 14 times against NVLink's two-direction total), as {{GPU architecture|n:3c65c17b0d0d810682aae39bd614ec64}} also notes.

2. PCIe: the bus every device sits on

A GPU is a card in a computer: the CPU sends it work, the NIC reaches its memory, and GPUs without NVLink reach each other, all over PCI Express. A link is a bundle of lanes, each two pairs of wires, one per direction; a GPU slot has 16 ("x16"). Each generation doubled the rate per lane (rung 3 in the hero figure).

What sits on it in a GPU server. In an 8-GPU HGX server the GPUs, their NICs and NVMe drives hang off PCIe switches that connect to the two CPUs. Peer-to-peer lets one GPU read another's memory over PCIe without staging through CPU memory. GPUDirect RDMA lets a NIC read and write GPU memory directly, so gradients leave the server without a copy into CPU memory; it works best when the NIC and GPU share a PCIe switch, which is why HGX boards pair each GPU with its own NIC. PCIe can still be the limit: ConnectX-8 NICs and Blackwell GPUs speak PCIe 6.0, enough for 800 Gb/s, "However, Grace CPUs currently only support PCIe Gen5, which limits throughput to 400 Gb/s" when traffic goes through the CPU ({{NCCL 2.27 blog|https://developer.nvidia.com/blog/enabling-fast-inference-and-resilient-training-with-nccl-2-27/}}).

Consumer cards. GeForce cards from the RTX 4090 on have no NVLink, so two RTX 5090s talk over PCIe 5.0: 63 GB/s each way, about a seventh of an H100's NVLink. The 8B's gradient all-reduce between two such cards takes about 255 ms derived: 16.06 GB / 63 GB/s, ring with n = 2.

Encodings and provenance of the PCIe table (1 min)

Data on the wire is wrapped in an encoding that costs a little: 8b/10b (20% overhead) until 2.0, 128b/130b (1.5%) from 3.0, and from 6.0 a new scheme with four voltage levels per symbol (PAM4) and fixed-size packets (FLITs) with error correction, carrying 242 useful bytes in every 256.
