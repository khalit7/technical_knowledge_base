5. The roofline and MFU: which resource runs out

Each chip has two speeds, peak FLOP/s and memory bandwidth; each operation needs a certain number of FLOPs per byte it moves, and that number says which speed it gets. This is the page's core idea in one formula:

time ≈ max( FLOPs / peak FLOP/s , bytes / bandwidth )
AI
Arithmetic intensity: FLOPs per byte moved, a property of the operation and its shapes
ridge
peak FLOP/s / bandwidth: below it the operation is memory-bound, above it compute-bound (the roofline)

The batch is the intensity. A linear layer reading bf16 weights does about one FLOP per byte per token that shares the weight read: decode at batch 1 sits near 1, a training step with thousands of tokens per sequence far right of every ridge, and elementwise operations below 1 on every chip ever made (which is why they are fused). The ridge stopped rising at BF16
It doubled from A100 (153) to H100 (295) and then fell slightly on B200 (281), because Blackwell grew bandwidth (3.35 to 8 TB/s) as fast as BF16 FLOPS; announced Rubin falls further, to 182 (4 PF BF16 dense over the Rubin blog's 22 TB/s of HBM4; 208 with the Vera Rubin NVL72 page's 19.2 TB/s). It keeps rising only in the new formats: B200 at FP8 is 562.5, at FP4 1,125. Low precision makes an operation more compute-hungry per byte, which is why low precision and big batches go together. (The old notes said the ridge "rises every generation".)

MFU: how far below the roof a run sits. Model FLOPs utilisation = tokens per second × 6N / (chips × dense peak in the matmuls' format). Counting recomputed FLOPs too gives hardware FLOPs utilisation (HFU), which flatters. Llama 3 405B on 16,384 H100s reported 400 TFLOP/s per GPU and 41% MFU (400 / 989.5 = 40.4% recomputed), 43% on 8,192 GPUs and 38% at 131,072-token sequences ({{Llama 3, Table 4|https://arxiv.org/html/2407.21783v3}}): around 40% is what a very well tuned dense run at scale reaches. For the running example at 40% MFU the step's arithmetic takes 64 s on one H100, 8.0 s on 8 and 1.0 s on 64 derived; the {{Performance calculator|#t-calc}} adds memory and communication and finds 1.17 s on 64 GPUs with hybrid sharding (34% MFU) but 1.95 s with flat FSDP across all 64 (20%). The difference is the network (section 6).

Attention adds FLOPs beyond 6N at long context; the {{Performance calculator|#t-calc}} counts them as PaLM's 12LHQT, the full score square (the convention of published MFUs), while a causal kernel does about half.
