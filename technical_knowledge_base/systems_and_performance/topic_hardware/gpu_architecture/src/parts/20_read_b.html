2. The SM: what is inside, and why

The choice behind it. A CPU core spends its area making one thread fast (big caches, branch prediction, out-of-order execution); an SM spends it on arithmetic lanes and on storage for many threads, so the arithmetic never waits on memory that answers in hundreds of cycles. Fig. 2 builds an H100 SM, then changes generation. Predict, then watch: what grows from A100 to H100, and what appears on B200 / B300?

  1. Four identical quadrants. Each quadrant (sub-partition) has a warp scheduler with 16 warp slots, which picks one warp each cycle and issues its next instruction to 32 lanes at once; a 64 KB slice of the register file (16K 32-bit registers); its arithmetic lanes ("CUDA cores": 32 FP32 lanes on Hopper); and its own tensor core.
  2. One block of SRAM, and the TMA. The four share 256 KB of SRAM, split at launch between an L1 cache (filled by hardware) and shared memory (filled by the program, up to 228 KB), plus load/store units and, from Hopper on, the TMA copy engine (section 8), drawn filling it.
  3. Our tile's accumulators: a quarter of the registers. Its running sums are 128 × 128 FP32 numbers, 64 KB, 16 KB in each quadrant's slice: a quarter of the SM's register file, held for the whole tile.
  4. A100: half the lanes, a smaller store, no TMA. Lanes per quadrant double from 16 to 32 between the A100 and the H100; the A100's SRAM is 192 KB (up to 164 KB shared), and its asynchronous copies are issued by threads, one per 16 bytes.
  5. B200 / B300: a fifth memory. Blackwell datacenter parts keep Hopper's quadrants and add tensor memory (TMEM), 256 KB per SM that only the tensor cores use. The accumulators move there, and the register file is free for other work.
  6. RTX 5090: the same quadrants, less around them. The consumer Blackwell SM has half the shared store (128 KB, up to 100 KB shared), no TMEM, and room for 48 resident warps (12 per scheduler) instead of 64.

Drawn to the counts, not to silicon area. Each SRAM slab's length is to scale of 256 KB.

Why the register file is the largest memory in the SM. 256 KB of registers per SM is more than the 228 KB of shared memory an H100 kernel can use; across 132 SMs that is 33.0 MiB 132 × 256 KiB, two thirds of the size of the 50 MB L2. Every resident warp keeps all its registers there all the time, so switching from a stalled warp to a ready one costs nothing: no state is saved or restored, unlike a CPU context switch. That free switch is the latency-hiding trick of section 3, and the register file's size is what pays for it.

Where the accumulators live. On Ampere and Hopper they live in registers (128 per thread for a 128-thread block); Blackwell's tensor memory exists to take them out (section 8).
