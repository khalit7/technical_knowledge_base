# Performance math: FLOPs, memory, MFU, tokens per second, costing a run

Notion: https://app.notion.com/p/3c65c17b0d0d81faad1ef390b0e54d08 (child of Topic: hardware)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). The arithmetic behind the parent's Performance calculator, derived from zero with Llama 3.1 8B as the running example: 6ND and every correction to it (embedding, attention at long context, causal masking, FlashAttention's backward, MoE), counted by PyTorch on the real 8B and 70B models on the meta device; bytes per parameter for every training and inference recipe; activation memory derived (Korthikanti et al.'s 34sbh) and counted (49 bytes per token per hidden unit for Llama's reference code, plus FP32 logits), with a before/after animation of one step's memory under plain attention, FlashAttention and full recompute; recomputation and HFU (1.24x counted, PaLM's 57.8% rebuilt); MFU worked through on MT-NLG, PaLM, Llama 3 and DeepSeek-V3; MFU measured on this laptop's M1 Pro GPU and predicted operator by operator, projected onto an H100; prefill, decode and cost per million tokens; communication bytes per parallelism; costing a run and serving capacity; mistakes, drills and interview questions. Tabs: Reading, FLOP and memory ledger, Run and serving planner, Further reading. Rebuilds the old page "Performance math: the arithmetic before every run" (saved in `src/live.md`, mapped in `src/coverage.json`). No child pages, databases or video. No NVIDIA GPU was available: measurements are the M1 Pro's, labelled.
