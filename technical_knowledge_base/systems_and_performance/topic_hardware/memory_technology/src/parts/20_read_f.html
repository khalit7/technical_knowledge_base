5. Capacity against bandwidth: the tiers, and CXL

Bandwidth comes from many short wires; capacity comes from many dies. Both compete for the space next to the processor. An HBM stack holds at most 16 dies (64 GB at the standard die size), and each stack needs its own wide interface along the edge of the GPU die, so only so many stacks fit:

Going further from the die (board, CPU socket, a CXL device, another node, an SSD) buys capacity cheaply, but the wires get longer, fewer and slower. From HBM down to the host link the bandwidth drops about 26× on an H100 (3,350 against 128 GB/s, and that 128 is both directions together), so anything that crosses PCIe once per step must be small or overlapped with compute (section 7). The network to another node (50 GB/s for a 400 Gb/s NIC) is slower again, which is why parallelism is chosen around the network ({{Interconnects and scaling|n:3c65c17b0d0d81808563fd41fb163af0}}).

Unified memory blurs one rung
Apple's M1 Pro has one pool of LPDDR5 shared by CPU and GPU: no copy, no PCIe, but only 200 GB/s. NVIDIA's GH200 joins a Grace CPU and a Hopper GPU with a 900 GB/s coherent NVLink-C2C link, "7X faster than PCIe Gen5", sharing one page table for up to 624 GB of CPU and GPU memory ({{NVIDIA GH200|https://www.nvidia.com/en-us/data-center/grace-hopper-superchip/}}). Coherent does not mean equally fast: the GPU still reads its own HBM much faster than the CPU's LPDDR5X.

CXL: memory on PCIe wires

CXL (Compute Express Link) adds a rung between a CPU's own DRAM and the SSD. Its CXL.mem protocol "maps device memory to the system address space": a last-level cache miss to a CXL address becomes a request on a CXL port that brings back the cache line, with no page fault and no DMA. It runs over PCIe's electrical interface with its own low-latency link layer; with PCIe 5.0 a bidirectional x8 CXL port at a 2:1 read:write ratio matches one DDR5-4800 channel (38.4 GB/s, derived). CXL 1.1 attaches a device directly, 2.0 adds switch-based pooling, 3.0 standardises switch-less pooling and more bandwidth. The price is latency: Intel measures 25 ns per round-trip port traversal, about 70 ns end to end over NUMA-local DRAM; a pool shared by 8 to 16 sockets adds 70 to 90 ns, rack-scale pooling more than 180 ns.

Why anyone pays it: in Azure's clusters up to 25% of DRAM was stranded (cores all rented, memory left over), DRAM "can be 50% of server cost", and pooling it over CXL cut DRAM cost by 7% with performance within 1 to 5% of local memory over 158 workloads ({{Li et al., Pond, ASPLOS 2023|https://arxiv.org/abs/2203.00241}}, sections 1 and 2) published, Microsoft. For an ML engineer CXL is so far a CPU-side tier: it enlarges host memory, the rung offload uses (section 7), and a GPU reaches it only through the host. The capacity-bandwidth trade is the same at every rung: more bytes, further away, fewer of them per second.
