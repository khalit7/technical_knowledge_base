7. Offload and tiering: using the slower rungs on purpose

State that does not fit in HBM can live one rung down (CPU memory, then NVMe) and be brought in when needed. That pays only if the move costs less than what it saves, or hides behind compute. The arithmetic is always bytes / bandwidth of the slower link:

All derived: bytes / bandwidth. C2C's 900 GB/s is split evenly between directions here (an assumption); PCIe Gen5 x16 is 128 GB/s both directions on the {{H100 page|https://www.nvidia.com/en-us/data-center/h100/}}; the 50% utilisation is illustrative, and the prefill count ignores attention FLOPs, which only make recomputing slower. The SSD figure is the median of three sequential reads of a 4 GiB file with the page cache bypassed measured here.

Training: ZeRO-Offload and ZeRO-Infinity. The optimizer step touches each parameter's state once per step, so keeping the state in CPU memory (or NVMe) and running the update there costs one transfer per step. ZeRO-Infinity puts GPU, CPU and NVMe memory behind one interface and reports over 25 petaflops on 512 V100s (40% of peak) for models far beyond GPU memory ({{Rajbhandari et al. 2021|https://arxiv.org/abs/2104.07857}}). At 1.5 s per direction, offloading the 8B model's optimizer pays only when a step already takes seconds (large batches) or the alternative is not training at all; over a GH200-style coherent link it takes a fifth of a second. With GPUs to spare, sharding (ZeRO, FSDP) is usually cheaper: {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}.

Inference: weights and KV offload. FlexGen ran OPT-175B on a single 16 GB GPU by streaming weights and cache from CPU memory and disk, reaching 1 token per second with an effective batch of 144: throughput, not latency ({{Sheng et al. 2023|https://arxiv.org/abs/2303.06865}}). For the KV cache the table shows why offload wins: reloading a 32K conversation's cache over PCIe takes 168 ms, recomputing it about 9 s. So paused conversations' caches belong in CPU memory or on SSD, reloaded when the user returns. Offload buys capacity with time; it is the right trade only when the transfer overlaps compute or replaces something slower.

The SSD, measured: sequential against random reads

A 4 GiB file of random bytes, written and read with F_NOCACHE so neither the write nor the reads leave pages in memory; one reader, one request at a time (queue depth 1), so small random reads are latency-bound. The first attempt, before the write path also bypassed the cache, read 9.2 to 11.0 GB/s because the just-written pages were still in memory (out/ssd_cached_attempt.txt): storage numbers must bypass the page cache ({{Storage and file systems|n:3f05c17b0d0d8141be7acc1313570cbf}} explains it).
