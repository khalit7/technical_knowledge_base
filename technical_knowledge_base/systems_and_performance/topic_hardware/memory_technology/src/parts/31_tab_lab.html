Everything on this tab was run on this laptop: the Apple M1 Pro's 16-core GPU through custom Metal kernels in MLX, and its internal SSD. Each GPU experiment ran 7 timed trials after 2 warm-ups, in three separate runs; the line is the median of the three run medians and the bars their spread. Every kernel was checked against NumPy before it was timed. measured here

1. How fast, and how slow, at each size

Bandwidth: 65,536 threads reading a buffer of the given size over and over (coalesced 16-byte loads). Latency: the time of one read when each read depends on the previous one (a single thread chasing a random pointer cycle, one 128-byte line per hop; launch overhead removed by timing two chain lengths and taking the difference).

2. Random blocks: why access size matters

512 MB read in blocks of a given size at random positions; consecutive threads read consecutive 16-byte pieces of the same block. The y axis counts only the useful bytes.

3. One decode attention step against the KV cache

MLX's fused scaled_dot_product_attention for one new token (32 query heads of 128, FP16) against a cache of 1K to 128K tokens with 32 KV heads (MHA, like Llama 2), 8 (GQA, like Llama 3.1 8B) or 1 (MQA). One layer only; a whole model repeats this per layer.

4. The SSD, the bottom rung

A 4 GiB file of random bytes, written and read with F_NOCACHE so neither the write nor the reads leave pages in memory; one reader, one request at a time (queue depth 1). The first attempt, before the write path also bypassed the cache, read 9.2 to 11.0 GB/s because the just-written pages were still in memory (out/ssd_cached_attempt.txt).

What transfers to an NVIDIA GPU, and what does not

TransfersThe shape: bandwidth falls in steps as the working set outgrows each cache; latency rises in steps; Little's law links them; scattered small reads waste most of the bandwidth; decode attention time follows cache bytes when the kernel is good. Luo et al. measured the same staircase in cycles on A100, H800 and RTX 4090 independent.
Does not transferThe numbers. An H100 has 50 MB of L2 instead of 256 KB plus a 24 MB SLC, and 3.35 TB/s of HBM instead of 200 GB/s of LPDDR5. MLX's attention kernel is not FlashAttention or vLLM's; its MHA and MQA results describe this kernel, not the hardware's limit.
Not measuredNo GPU performance counters (Instruments) were read, so cache levels are inferred from the curves; HBM, GDDR and NVLink were not run here (no NVIDIA GPU was available).
