5. AMD Instinct: eight GPUs without a switch, and ROCm

The bet. AMD builds the same kind of machine as NVIDIA (a GPU: many cores, thousands of threads, caches) and competes on memory per GPU and on price, while its software, ROCm, catches up with CUDA. The chip itself, from the CU up (8 compute chiplets of 38 enabled CUs on MI300X, 64-thread wavefronts, the MI300X and MI355X peaks reproduced, what chiplets cost), is taught on {{GPU architecture, section 13|n:3c65c17b0d0d810682aae39bd614ec64}}. What differs at the system level is how GPUs join, and what changes in your code.

Eight GPUs without a switch. An NVIDIA HGX server joins its 8 GPUs through NVSwitch chips, so any GPU can send to any other at full NVLink speed. AMD's 8-GPU board instead gives every GPU 7 Infinity Fabric links, one straight to each other GPU, "to form a fully connected 8-GPU system": 7 × 128 GB/s = 896 GB/s aggregate on MI300X (64 GB/s each way per link), 7 × 153.6 = 1,075.2 GB/s on MI355X. A collective that uses all 7 links at once (an all-reduce, an all-to-all) sees the aggregate; a copy between two GPUs sees one link, a seventh of it. On the MI355X generation the scale-up domain stops at 8. AMD's answer for 72 is the Helios rack: 72 MI455X joined by UALink over Ethernet, 3.6 TB/s per GPU, which AMD calls "a reference design, not a product for sale" that partners build ({{AMD MI400|https://www.amd.com/en/products/accelerators/instinct/mi400.html}}).

Eight GPUs, 28 direct links: an all-reduce sees all 7 of a GPU's links, a copy between two GPUs sees one

The NVIDIA HGX board: every GPU has its NVLinks into the NVSwitch chips, so any pair talks at a GPU's full NVLink bandwidth. The AMD 8-GPU board: no switch, one Infinity Fabric link per pair, 8 × 7 / 2 = 28 links derived. Link rates are AMD's (MI300X 64 GB/s each way per link; MI355X 153.6 GB/s per link, aggregate), from the CDNA 3 and CDNA 4 white papers. Schematic, not to scale.

Helios: shipping status (dated, October 2026)

Production shipments began in September 2026, first to OpenAI, Meta, Microsoft, Oracle and Anthropic, ramping through the first half of 2027; AMD gave no volumes or service dates, so this is shipping, not broad availability ({{Lisa Su at the OCP Global Summit, Oct 12 2026|https://convergedigest.com/amd-lisa-su-ocp-helios-shipping-verano-192-core/}}).

What it means for your training code. Mostly nothing, by design: "PyTorch for HIP intentionally reuses the existing torch.cuda interfaces", so .to('cuda'), torch.cuda.synchronize() and the rest run unchanged on a ROCm build (check torch.version.hip) ({{PyTorch HIP notes|https://docs.pytorch.org/docs/2.14/notes/hip.html}}); collectives go through RCCL, AMD's NCCL; Triton supports "AMD GPUs (ROCm 6.2+)" ({{Triton README|https://github.com/triton-lang/triton}}); CUDA C++ is translated by HIPIFY. The cost is everything below the framework: custom CUDA kernels, libraries that ship only CUDA builds, and tuning. An independent test in December 2024 found BF16 matmuls on MI300X reaching about 620 of its 1,307 peak TFLOPS against about 720 of 989.5 on H100, and wrote that "MI300X performance is held back by AMD software" ({{SemiAnalysis, Dec 22 2024|https://newsletter.semianalysis.com/p/mi300x-vs-h100-vs-h200-benchmark-part-1-training}}); ROCm has had two major versions since, so re-measure before you decide.

Porting a kernel: CDNA 3 and 4 run 64-thread wavefronts, so code written for 32 lanes breaks silently; CDNA 5 adds Wave32 (GPU architecture, section 13). ROCm, HIP and the current ROCm 10 release from the programmer's side: section 9, "Other GPUs", of {{Topic: cuda-and-gpu-programming|n:3c65c17b0d0d81c39f34d5e070d783c1}}. Every AMD part's peaks, memory and price beside NVIDIA's: the root's "Chip atlas" tab.

6. AWS Trainium: systolic arrays you can program, on AWS only

The bet. Vertical integration: AWS designs the chip (through its Annapurna Labs team), the links, the SDK and the data centre, and rents it below the price of GPUs with NVIDIA's margin. You can only get it as an AWS instance.

A NeuronCore is a small TPU core: one 128 × 128 systolic array, helper engines and a scratchpad

Inside a NeuronCore. A Trainium2 chip has 8 NeuronCores; each is "a fully-independent heterogenous compute unit" with four engines and its own scratchpad ({{NeuronCore-v3|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-hardware/neuron-core-v3.html}}):

Tensor engineA systolic array: "a grid of 128x128 processing elements" at 2.4 GHz. You load a stationary tile, then stream a moving tile across it ("LoadStationary", "MultiplyMoving"): the same weight-stationary idea as section 1. 79 bf16 TFLOPS per core; for fp8 each cell does two multiplies, which looks like a 256 × 128 array.
Vector engineOperations where each output depends on many inputs (layer norm, pooling).
Scalar engineElementwise work: activations, exponentials.
GpSimd engine"Eight fully-programmable 512-bit wide vector processors" that run C code for custom operators.
SBUF and PSUM28 MiB of software-managed SRAM per core, laid out as 128 partitions (one per row of the array), plus a 2 MiB buffer for partial sums. Like a TPU, no cache: the compiler or your kernel moves data.
Sources for the NeuronCore

Sources: {{Trainium2 architecture guide for NKI|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/guides/architecture/trainium2_arch.html}}; {{Trainium2|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-hardware/trainium2.html}} and {{Trainium3|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-hardware/trainium3.html}} pages, all fetched 2026-10-05.

Check the peak. 128 × 128 cells × 2 FLOPs × 2.4 GHz = 78.6 TFLOPS per core, matching the docs' 79; × 8 cores = 629 TFLOPS, but the chip page says 667 derived. The 6% gap is not explained in the docs (perhaps a different clock); the page shows it rather than hiding it.

Chips into machines. A Trn2 instance has 16 Trainium2 chips "connected using a 4x4, 2D Torus topology" over NeuronLink (1,024 GB/s per chip inside the instance), and a Trn2 UltraServer joins 4 instances, 64 chips, with chips at the same position linked in rings (256 GB/s more per chip): a small TPU-like torus ({{Trn2 architecture|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-hardware/trn2-arch.html}}). Trainium3 changes course: its UltraServers (64 or 144 chips) use switches, "replacing the previous 2D-torus architecture" with all-to-all connectivity ({{Trn3 architecture|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-hardware/trn3-arch.html}}). At scale: Project Rainier, "nearly half a million Trainium2 chips" across several US data centres, built for Anthropic ({{Amazon, Oct 29 2025|https://www.aboutamazon.com/news/aws/aws-project-rainier-ai-trainium-chips-compute-cluster}}).

Trainium3 link bandwidth: the docs disagree (depth)

The docs give three different per-chip link figures for Trainium3 (2.56 TB/s, 2,048 GiB/s, and 704 GB/s from the listed PCIe links), so no single number is quoted here.

What it means for your training code. Three ways in. The main one is TorchNeuron, a native PyTorch device, open source under Apache 2.0 and in public beta since 20 October 2026 on Trainium2 and Trainium3: "Change .to('cuda') to .to('neuron')" ({{PyTorch on Neuron|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/frameworks/torch/index.html}}), run eagerly, or compile with torch.compile(backend="neuron"), which captures the graph with Dynamo and lowers it through Torch-MLIR to StableHLO for the Neuron compiler; DDP, FSDP2, tensor and pipeline parallelism and DTensor work, while the first release skips dynamic shapes, sparse tensors and NestedTensor ({{PyTorch blog, Oct 20 2026|https://pytorch.org/blog/introducing-torchneuron-native-pytorch-backend-for-aws-trainium/}}). The older path is built on PyTorch/XLA (lazy tensors, whole graphs compiled ahead of time, so static shapes matter, as on a TPU), and JAX runs through a plugin in beta. Custom kernels are written in NKI, a Python kernel language "similar to numpy and Triton" whose tiles are bounded by the hardware: the first dimension is the partition dimension (at most 128), and a matmul's stationary tile is at most 128 × 128 and its moving tile 128 × 512 ({{NKI|https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/get-started/about/index.html}}). Anthropic says it writes "low-level kernels that allow us to directly interface with the Trainium silicon" ({{Anthropic, Nov 22 2024|https://www.anthropic.com/news/anthropic-amazon-trainium}}). Inferentia is the inference-only sibling on the same SDK.
