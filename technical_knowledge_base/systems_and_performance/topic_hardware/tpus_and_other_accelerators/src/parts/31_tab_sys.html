One matrix multiply, X (M × K) times W (K × N), on a weight-stationary systolic array of side R. Change the shape and the array and watch utilisation, the number of tiles and the reads per multiply-add. Section 1 of the Reading tab explains the mechanism; this tab is for trying shapes.

Try: the running example on 128 and on 256 (both near 100%); then "Decode, 8 tokens" (the array waits on weight loading); then K = N = 130 (padding); then the attention preset on a 256 array.

Utilisation against matrix size

Utilisation = useful multiply-adds / (R2 × cycles) from the tiled model in src/sim/systolic.py, with weights double-buffered and shifted in one row per cycle (an assumption taken from TPU v1, which needed 256 cycles per tile; Google does not publish the load rate of later MXUs). Real chips add HBM bandwidth limits, several arrays per chip and compiler choices this model leaves out; it shows the shape effects only.

Watch a small tile cycle by cycle

For shapes that fit a small array, the page's simulator runs every cell, every cycle. Pick a shape: each cell is coloured when it does a multiply-add, and the result is checked against a plain matrix multiply.
