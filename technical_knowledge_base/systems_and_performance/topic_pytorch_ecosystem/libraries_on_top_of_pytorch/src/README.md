## Experiments (`exp/`), all deterministic (no timing, no bench lock)

The running example is imported from the root's `src/model/` (`exp/common.py` adds it to the path). Shared venv of the topic (torch 2.14.1, transformers 5.19.0, accelerate 1.15.0, lightning 2.6.6, peft 0.21.2, trl 1.15.0), Apple M1 Pro, CPU. `LIB_SCRATCH` points at a scratch folder for Trainer and Lightning output.

| Script | Output | What |
|---|---|---|
| `defaults_lab.py` | `inputs/defaults_lab.json` | 150 steps through a plain loop, the HF Trainer (matched, then one default at a time, then all), Lightning (default, clip), Accelerate: per-step loss, pre-clip gradient norm, learning rate, probe loss every 10 steps, optimizer objects |
| `accum_lab.py` | `inputs/accum_lab.json` | 8 rows with unequal real tokens: full batch vs mean of means vs token-weighted; the gradient each library computes under 4-step accumulation; 100-step probe curves |
| `hf_checks.py` | `inputs/hf_checks.json` | `attn_implementation` default and eager / sdpa / flex_attention on CPU and MPS, forward, backward and inference; `num_items_in_batch` arithmetic; decay-parameter names on the running example |
| `apitrace.py` | (module) | `sys.setprofile` tracer of calls from library code into torch, with the wrapped function's real name and first-seen order |
| `calls_trace.py single` | `inputs/calls_single.json` | Traces of plain, HF Trainer (matched and defaults), Accelerate, Lightning |
| `run_dist.sh` + `calls_trace.py <mode>` | `inputs/calls_<mode>.json` | 2 processes, gloo, ports 29561 to 29563: Accelerate DDP, HF Trainer DDP, Lightning DDP and FSDP2 (ModelParallelStrategy), DeepSpeed ZeRO 0 to 3 with and without the default clipping |
| `titan/ttrun.py`, `titan/libcfg.py`, `titan/run_titan.sh` | logs in scratch, `inputs/calls_titan_*.json` | torchtitan 0.3.0's own trainer on CPU with four patches (documented in `ttrun.py`), configs derived from `llama3_debugmodel`; ports 29564 to 29566 |
| `titan/summarize.py` | `inputs/titan.json` | Losses and grad norms parsed from the logs; the FlexAttention-vs-dense-mask check |
| `rerun_traces.sh` | all trace inputs | Re-runs every trace in order |

DeepSpeed 0.19.7 is used from an overlay folder (`pip install --target <dir> --no-deps deepspeed==0.19.7 hjson py-cpuinfo msgpack pydantic pydantic-core annotated-types typing-inspection einops`, with `DS_BUILD_OPS=0`) and `DS_ACCELERATOR=cpu`. torchtitan runs from a shallow clone of the v0.3.0 tag (it needs `tests/assets`) with tyro, torchdata, torch_checkpointing, spmd_types 0.2.3, einops and tensorboard in a second overlay folder (its pinned `datasets<4.8` is not installed; the shared venv's datasets 5.1.0 worked).

Rebuild: run the scripts with the shared venv's python, then `python3 build_data.py; sh build.sh; python3 check_data.py; node check_page.mjs ../index.html <shots dir>` (the last also checks that nothing plays before the reader acts, with and without reduced motion); `python3 html_utils/ledger.py check <page>` from the repo root.

## The 2026-10-23 rebuild to the teaching contract (editing only, no new runs)
This page owns the library landscape on top of PyTorch (HF transformers, Accelerate, PEFT, TRL; Lightning; torchtune; torchtitan; DeepSpeed and Megatron as libraries) and which one for which job. Mechanisms are linked to their owners: parallelism forms to Distributed Training, the PyTorch APIs to Distributed PyTorch, LoRA to PEFT, SFT/DPO/RL methods to Alignment and RL for LLMs.
- **Top**: the core idea in one sentence; a new hero (`23_lib_hero.js`), a static annotated diagram of four families by level of hand-over (config tools, post-training trainers, trainers that run the loop, helpers that keep your loop) with every column ending in PyTorch's calls, and the defaults that change the loss in the page's highlight colour; "You need" (root, Distributed Training, Distributed PyTorch, PEFT, Alignment); new terms; the duty matrix (the comparison) with the same highlight; the three results.
- **Tabs folded into Reading**: the Defaults lab (one mechanism: a default moves the curve) is now inline in section 2 beside the claim, its run table closed; the Chooser tab's porting checklist went to section 2 and the chooser itself became section 10, "Which library for which job", the concept this page owns. What calls what stays a tab: a dataset view used by sections 4 to 7.
- **No autoplay**: template `21_js_rd_common.js`; mode switches and run selects reset to step 0 instead of playing.
- **Closed depth**: source-line tables, the v5 changes beyond dtype, the Trainer's per-step calls and Accelerate's FSDP2 grouping, TRL's source lines, Lightning's strategy table and SIGTERM broadcast, torchtitan's CPU patches, SAC policy and trace, DeepSpeed's memory and traffic detail, Axolotl and Unsloth in source, NeMo/Composer/Monarch, the GPU-transfer table, the accumulation history.
- **Deleted as fat**: wind-ups, definitions of batch, optimiser step, schedule, clipping, sampler and rank (known to the reader), the common-mistakes and interview blocks (each restated a core claim; the two units they alone held, float32 master weights and the profiler hint, moved into sections 4 and 5), the defaults bar chart (the lab chart and its closed table carry the same numbers), the "nothing changed" line under the acquisition (the acquisition itself is volatile and stays in the root's section 9).
- **Numbers written statically** where the ledger needs them (median and first gradient norm, the 0.601 swing, 3.30068, 25.5 / 12.7 MB, 40 tensors, 178 and 297 calls, 4.41105 and 4.40925); `check_data.py` now checks every one against `inputs/`.
