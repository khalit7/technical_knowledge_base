7. DeepSpeed ZeRO against FSDP2

Both shard the training state across data-parallel ranks so each holds a slice (the forms and their memory maths are {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}'s; FSDP2's internals {{Distributed PyTorch|n:3c65c17b0d0d815e85aff8decd8f35ab}}'s). As libraries they differ in who owns the step: DeepSpeed hands you an engine that replaces backward and step; FSDP2 is a function that marks modules and leaves your loop alone.

DeepSpeed: an engine owns the step
import deepspeed deepspeed.init_distributed(dist_backend="gloo") conf = {"train_micro_batch_size_per_gpu": 8, "zero_optimization": {"stage": 3}, "gradient_clipping": 0.0} # else 1.0 eng, opt, _, _ = deepspeed.initialize( model=model, optimizer=make_optimizer(model), config=conf) for x, y in batches: _, loss = eng(x, y) eng.backward(loss) # not loss.backward() eng.step() # clip, step, zero_grad
FSDP2: a function marks modules, your loop stays
from torch.distributed.fsdp import fully_shard from torch.distributed.device_mesh import init_device_mesh mesh = init_device_mesh("cpu", (2,)) for block in model.blocks: fully_shard(block, mesh=mesh) fully_shard(model, mesh=mesh) opt = make_optimizer(model) # on DTensor shards for x, y in batches: _, loss = model(x, y) loss.backward() opt.step(); opt.zero_grad()

Highlighted: where each takes over. The FSDP2 code is the root's Distributed lab recipe (its mesh= is needed on macOS).

measured on Apple M1 Pro, CPU, 2 processes, gloo (src/exp/calls_trace.py). Reference: PyTorch DDP's 3.80137, 3.09551, 3.16247. DDP's and FSDP2's own collectives are issued inside PyTorch, so they do not appear here; the root's Distributed lab counts them (FSDP2: 14 per step at world 2).

  • Same maths. With clipping off, every stage reproduces DDP's losses to five decimals: ZeRO is a memory layout, not a different optimiser.
  • The default clip shows up in the third loss. Without a gradient_clipping key, 0.19.7 clips at 1.0 and the third loss becomes 3.30068 instead of 3.16247, while the second moves only in the fifth decimal. Adam's first update is almost independent of the gradient's scale (with fresh moments, m/√v is the sign of each gradient entry, up to eps), so clipping step 0 barely matters; from the second update on, the moments mix two gradients scaled by different factors, and the path changes. The same config gave the unclipped result on 0.19.2 and earlier: pin versions and write every setting you rely on into the config.

When each. FSDP2 is in PyTorch: it composes with DTensor, tensor and pipeline parallelism, torch.compile and DCP, and is what Accelerate, Lightning, TRL and torchtitan call. DeepSpeed (a PyTorch Foundation project since May 2025) brings its own engine with offload of parameters and optimiser state to CPU memory and NVMe drives, its own optimisers and kernels, and long-standing integrations (HF Trainer via Accelerate, Megatron-DeepSpeed): pick it when you need those, or inherit it from a recipe. Mixing engines mixes their assumptions about who calls backward, clips and scales the loss (the Trainer turns its own accumulation scaling off under DeepSpeed, {{trainer.py L2096 to L2099|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/trainer.py#L2096-L2099}}).

Memory and traffic: state halves, small tensors stay whole, ZeRO-3 talks from Python (measured detail)

How it ran: DeepSpeed 0.19.7 from its released source with DS_ACCELERATOR=cpu, which selects its CPU accelerator and the gloo backend when oneCCL is absent ({{cpu_accelerator.py L31 to L34|https://github.com/deepspeedai/DeepSpeed/blob/v0.19.7/accelerator/cpu_accelerator.py#L31-L34}}); PyTorch's own AdamW was passed in, so no DeepSpeed C++ operator was built.

  • Optimiser state halves from stage 1 on: AdamW's two moment tensors, 25.5 MB per rank at stage 0, 12.7 MB at stages 1 to 3 on 2 ranks.
  • ZeRO-3 does not shard small tensors. Parameters under stage3_param_persistence_threshold (default 100,000 elements, {{zero/config.py L229|https://github.com/deepspeedai/DeepSpeed/blob/v0.19.7/deepspeed/runtime/zero/config.py#L229}}) stay whole on every rank: 40 of the running example's 52 tensors (norms, biases, both embeddings, and the 65,536-element attention output matrices); only the 12 larger block matrices are partitioned. It saves gathering many tiny tensors at the cost of a little memory.
  • ZeRO-3 talks a lot from Python. In 3 steps DeepSpeed called all_gather_into_tensor 178 times (parameters fetched before each module's forward and again for backward) and Tensor.item() 297 times, mostly in a helper that checks lists agree across ranks (get_lst_from_rank0, {{zero/utils.py|https://github.com/deepspeedai/DeepSpeed/blob/v0.19.7/deepspeed/runtime/zero/utils.py}}). On a GPU every .item() waits for the device.
