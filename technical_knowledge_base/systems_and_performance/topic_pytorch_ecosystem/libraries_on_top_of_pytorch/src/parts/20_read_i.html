8. Config-driven fine-tuning: Axolotl, Unsloth, LLaMA-Factory

These tools answer "fine-tune model X on my data" with a configuration file instead of a loop (the top band of the hero). Underneath they are the Hugging Face stack: transformers models, PEFT adapters, TRL or Trainer loops, Accelerate for several GPUs. Their value is the recipe surface (chat templates, packing, LoRA and QLoRA, preference and RL trainers, day-one support for new open models) and, for Unsloth, faster kernels.

  • Axolotl 0.20.0 (2026-09-30): a YAML file becomes TrainingArguments plus a trainer class, a transformers.Trainer with mixins (its DPO, KTO, ORPO, GRPO and reward trainers subclass TRL's). Only settings present in the YAML are passed on, so an absent max_grad_norm means the Trainer's 1.0; its own defaults differ from the Trainer's in two places that move the curve: lr_scheduler: cosine (Trainer: linear) and prompt tokens masked out of the loss (train_on_inputs: false).
  • Unsloth (read at 2026.10.3) makes LoRA and full fine-tuning faster on one GPU by replacing transformers' forward methods with its own at import time, which call hand-written Triton kernels. The model you train is not the transformers code you read, it needs a GPU, and it caps the transformers versions it accepts.
  • LLaMA-Factory 0.9.5 (2026-05-30): the same idea with a web UI as well as YAML, also built on transformers, PEFT and TRL (version and date from PyPI, read 2026-10-13; not read further here).
A config tool fixes the whole stack under you
Axolotl 0.20.0 pins transformers==5.17.0 and torch>=2.13.0,<=2.14.0 (Requires-Dist of 0.20.0), so it would downgrade this page's transformers 5.19.0 and torch 2.14.1; Unsloth 2026.10.3 caps transformers at 5.17.0. Give each its own environment, or you change the stack under your other code. Neither was run here for that reason; both were read from their released wheels.
Axolotl and Unsloth in their source (file and line)

Axolotl. AxolotlTrainer is a transformers.Trainer with mixins for packing, schedulers, optimisers, checkpoint saving, offloading and distributed parallelism; its DPO, KTO, ORPO, GRPO and reward trainers subclass TRL's (wheel 0.20.0: core/trainers/base.py L101 to L111, core/trainers/trl.py, core/trainers/grpo/trainer.py). Only settings present in the YAML are passed on (core/builders/base.py L698). It keeps adamw_torch_fused and weight decay 0 (utils/schemas/training.py L143, L162, L184, L304). Sample packing (several examples in one row, attention kept per example) is off unless sample_packing: true.

Unsloth (2026.10.5 on PyPI the day of writing). For Llama, for example, LlamaAttention.forward, LlamaSdpaAttention.forward, LlamaFlashAttention2.forward, LlamaDecoderLayer.forward, LlamaModel.forward, LlamaForCausalLM.forward and PeftModelForCausalLM.forward are reassigned (unsloth/models/llama.py L2595 to L2601), and the replacements call kernels for cross-entropy, RMSNorm and LayerNorm, RoPE, SwiGLU and GeGLU, the LoRA MLP and NF4 dequantisation (41 @triton.jit functions in unsloth/kernels/). A transformers upgrade can break or silently bypass a patch, which is why the 2026.10.3 wheel accepts transformers 4.52.4 to 5.17.0 only, minus nine listed versions in between (its Requires-Dist). Without a GPU it stops ("Unsloth cannot find any torch accelerator? You need a GPU.", device_type.py L108). On Apple Silicon it has a separate path through Apple's MLX framework (unsloth_zoo.mlx, device_type.py L39 to L47), not through PyTorch. How such kernels plug into PyTorch properly is {{Extending PyTorch|n:3f85c17b0d0d8158a7addcd3d601d72a}}'s subject.

9. Megatron Core, and who is alive

  • Megatron Core 0.19.2 (NVIDIA): GPU-optimised building blocks for the largest runs: tensor-parallel layers, pipeline schedules, a distributed optimiser, fused kernels through Transformer Engine. It carries three data-parallel implementations side by side: its own DistributedDataParallel over contiguous gradient buffers, its own megatron_fsdp, and a wrapper around PyTorch's FSDP2 (wheel 0.19.2: megatron/core/distributed/). Expects NVIDIA GPUs; not run here. Tensor parallelism itself is {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}'s.
  • torchtune: "no longer actively maintained" since 2025-07-15 ({{issue 2883|https://github.com/meta-pytorch/torchtune/issues/2883}}); last release 0.6.1. torchforge: development paused, "LLM training at PyTorch is being consolidated in torchtitan". Both live in the meta-pytorch organisation; torchtitan is pytorch/torchtitan.
NeMo, Composer, Monarch (status as read 2026-10-12)
  • NeMo: the NVIDIA/NeMo repository now points to NVIDIA-NeMo/Speech and "pivoted to focus on audio, speech, and multimodal LLMs"; nemo-toolkit 3.0.0 is speech only after the split. LLM training at NVIDIA goes through Megatron Core and its NeMo-branded recipes.
  • Composer (MosaicML, then Databricks): last release 0.32.1 on 2025-07-26; quiet. Its StreamingDataset is still used for sharded data in object stores.
  • Monarch (single-controller distributed programming, torchmonarch 0.7.0 on 2026-10-10): active, in meta-pytorch.
