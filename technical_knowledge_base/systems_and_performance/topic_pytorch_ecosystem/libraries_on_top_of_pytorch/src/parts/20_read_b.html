1. The loop every library runs

Before comparing libraries, write the loop they all run. Each word defined here is used on the rest of the page.

Batch and micro-batchThe rows fed to one forward call. If a batch does not fit in memory you split it into micro-batches and add up their gradients before stepping: gradient accumulation.
Optimizer stepopt.step() updates every parameter from its .grad. One step per (accumulated) batch.
Learning-rate scheduleA function of the step number that sets the optimizer's learning rate: constant, linear decay to zero, warmup then cosine, and so on.
Gradient clippingIf the length (L2 norm) of all gradients together exceeds a limit, scale them all down to that length. torch.nn.utils.clip_grad_norm_.
SamplerThe object that decides which rows go in which batch: in order, shuffled, or one slice per process.
Rank and worldWith several processes training one model, each is a rank; the world size is how many there are. Data parallel = every rank runs the same step on different rows and averages gradients.

The plain loop, on the running example. Copy it next to the root's src/model/model.py and run it with any Python that has PyTorch 2.14:

import torch from model import GPTConfig, make_model, get_batch, make_optimizer torch.set_num_threads(2) cfg = GPTConfig() # 4 layers, d_model 256, batch 8 x 64 characters model = make_model(cfg) # seeded: the same weights on every run opt = make_optimizer(model) # AdamW lr 6e-4, betas (0.9, 0.95), weight decay 0.1 on matrices for step in range(3): x, y = get_batch(cfg, step) # batch k is the same on every run _, loss = model(x, y) # forward + mean cross-entropy loss.backward() # gradients into .grad opt.step() # update opt.zero_grad(set_to_none=True) # free the gradients print(step, round(loss.item(), 5)) # 0 3.80137 # 1 3.18793 # 2 3.16783

Output recorded on Apple M1 Pro, CPU, 2 threads, torch 2.14.1 (src/exp/defaults_lab.py, which runs it for 150 steps). That is the whole of what a library automates; everything else is defaults, logging, checkpointing and distribution.

Predict: the Hugging Face Trainer runs this same model on the same 8-row batches, with its defaults. Are its first three losses 3.80137, 3.18793, 3.16783?
None of them with its defaults: it shuffles the rows (so step 0 sees a different batch: 3.78405), clips, and uses its own AdamW at lr 5e-5 with betas (0.9, 0.999) and a linear decay; recorded 3.78405, 3.47902, 3.31911. With three settings changed (train_sampling_strategy="sequential", max_grad_norm=0, and your own optimizer with a constant schedule) it gives exactly 3.80137, 3.18793, 3.16783, as do Accelerate and Lightning measured on Apple M1 Pro, CPU.

The matched Trainer call, the one that reproduces the plain loop (from src/exp/defaults_lab.py):

from transformers import Trainer, TrainingArguments args = TrainingArguments(output_dir="out", max_steps=150, per_device_train_batch_size=8, use_cpu=True, report_to=[], save_strategy="no", train_sampling_strategy="sequential", # default "random": RandomSampler max_grad_norm=0.0) # default 1.0: clipping on opt = make_optimizer(model) # default: AdamW lr 5e-5, betas (0.9, 0.999), wd 0 const = torch.optim.lr_scheduler.LambdaLR(opt, lambda s: 1.0) # default: linear decay to 0 Trainer(model=model, args=args, train_dataset=rows, optimizers=(opt, const)).train()

The model must return a dict with a loss key (a ten-line subclass of the running example does it); rows is a dataset of {"input_ids", "labels"} rows in the plain loop's order.
