The running example trained for 150 steps, one optimizer step per batch of 8 windows of 64 characters, through a plain loop, the Hugging Face Trainer 5.19.0, Lightning 2.6.6 and Accelerate 1.15.0. The Trainer is first matched to the plain loop setting by setting, then has one default restored at a time, then all of them. Every curve is a real run measured on Apple M1 Pro, CPU, 2 threads, torch 2.14.1, deterministic (seeded weights and batches); src/exp/defaults_lab.py.

Before and after: the plain loop against one library setting, step by step

Probe loss: the mean loss on batches 10,000 to 10,003 of the same text, read after step 1 and every 10 steps (a fixed yardstick, since a shuffled run sees different training batches at each step). Training loss: the loss of each step's own batch, averaged over the last 10 steps. Gradient norm: before clipping. The chips add more runs to the chart; the animation always draws the plain loop and the selected setting.

Reading it
  • Three rows are exactly the plain loop: the matched Trainer, Lightning with defaults, Accelerate. A library on its own changes nothing.
  • The Trainer with clipping and Lightning with gradient_clip_val=1.0 agree with each other (both call torch.nn.utils.clip_grad_norm_), and both differ from the plain loop.
  • The optimizer defaults are the biggest single swing, mostly the 12 times smaller learning rate (5e-5 against 6e-4): "all defaults, lr 6e-4" recovers most of the gap. Defaults are tuned for fine-tuning pretrained weights, not training from scratch.
  • A toy run: which way each default moves the loss here is not advice. The measured fact is that each one moves it.
