0. In one screen

A training library is code that runs the training loop for you: it fetches batches, calls your model, calls backward(), clips, steps the optimizer and the learning-rate schedule, logs, saves, and spreads the work over several processes. Underneath, every one of them calls the same PyTorch pieces you would call yourself. So two questions decide everything: which of those duties do you hand over, and what does the library do by default when you do not say.

The parent page, {{Topic: pytorch-ecosystem|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}}, gives the map (its section 9 and its {{Ecosystem map|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}} tab: 42 libraries with statuses, licences and what each calls in core, and the same training step entered through five doors). This page goes one level down: it runs the topic's running example (a 3,186,944-parameter character-level GPT, defined once in the root's src/model/) through each library and reads the libraries' source at pinned versions.

Three results the rest of the page explains
  • Matched settings, identical losses. With every setting equal to the plain loop, the HF Trainer, Accelerate and Lightning give the same 150-step loss curve to all five printed decimals, and DeepSpeed ZeRO stages 0 to 3 give the same losses as PyTorch's DDP on 2 processes measured on Apple M1 Pro, CPU. The libraries add no maths; they add defaults.
  • Defaults move the curve. The Trainer's default clipping at norm 1.0 was active on 145 of 150 steps of the running example, and DeepSpeed changed its own clipping default from off to 1.0 in version 0.19.3 (July 2026): the same script gives a different second-step loss before and after that upgrade (section 2, {{Defaults lab|#t-dflt}}).
  • Loss averaging is a choice. With 4 micro-batches holding 124, 10, 90 and 13 real tokens, "divide each micro-batch's mean by 4" gives a gradient 59% away (relative error) from the full batch's; Accelerate, Lightning and the Trainer with a model that takes no **kwargs all do this, while the Trainer with a Hugging Face model and torchtitan divide by the token count and match (section 3).
