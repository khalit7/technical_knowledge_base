4. The Hugging Face stack: transformers, Trainer, Accelerate, PEFT, TRL

Five layers, each usable alone (the left column of the hero): transformers holds model definitions and loads weights from the Hub; the Trainer (inside transformers) runs the loop; Accelerate sits under the Trainer and turns one process into many (DDP, FSDP2, DeepSpeed, Megatron); PEFT injects adapters such as LoRA into any model; TRL holds the post-training trainers (SFT, DPO, GRPO, reward models), each a subclass of the Trainer.

transformers v5: the change that alters training

Version 5.0.0 came out on 2026-01-26 and 5.19.0 on 2026-10-06 (PyPI, as recorded by the root's Ecosystem map). It is PyTorch only (TensorFlow and Flax are sunset; JAX is left to partner libraries). The change that silently alters a ported script is the load dtype: "We have updated the default dtype for all models loaded with from_pretrained to be auto" ({{v5.0.0 release notes|https://github.com/huggingface/transformers/releases/tag/v5.0.0}}); v4 loaded in float32 unless told. At 5.19.0, dtype=None becomes "auto" ({{modeling_utils.py L4104 to L4105|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L4104-L4105}}), so a bf16 checkpoint trains in bf16 parameters and full fine-tuning updates bf16 weights directly. Pass dtype=torch.float32 (and use autocast) if you want float32 master weights.

The rest of v5: attention registry, quantisation, tokenizers, Trainer, serving (from the {{v5 announcement|https://huggingface.co/blog/transformers-v5}} and release notes)
  • Attention is pluggable. Each model keeps its eager attention in its own file; SDPA, FlashAttention and FlexAttention live in one registry, AttentionInterface. At 5.19.0 its keys are flash_attention_2, flash_attention_3, flash_attention_4, flex_attention, paged|eager and sdpa ({{modeling_utils.py L5118 to L5125|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L5118-L5125}}); the default is "sdpa", falling back to eager when a model cannot use it ({{L1850 to L1886|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L1850-L1886}}). attn_implementation="flex_attention" is real, and run here on a tiny Llama:
  • Quantisation is "a first-class citizen" (announcement): quantised checkpoints and configs such as bitsandbytes and torchao load through the same from_pretrained; the formats themselves are on {{Quantization and Precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}}.
  • Tokenizers: the fast/slow split is gone, the Rust tokenizers backend is the default, encode_plus is deprecated and apply_chat_template returns a BatchEncoding.
  • Trainer: report_to defaults to "none"; a new weight-loading API; reworked initialisation "to support scaled pre-training and different parallelism schemes" (announcement).
  • Serving: transformers serve (an OpenAI-compatible server), continuous batching and paged attention; and transformers model files run as a backend inside vLLM and SGLang (announcement). Serving itself is {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}.

Accelerate: your loop, distributed

accelerator.prepare(model, optimizer, dataloader) returns wrapped objects and accelerator.backward(loss) replaces loss.backward(); the loop stays yours. On 2 processes here the model came back as torch.nn.parallel.DistributedDataParallel ({{accelerator.py L2060|https://github.com/huggingface/accelerate/blob/v1.15.0/src/accelerate/accelerator.py#L2060}}) and gave rank 0 the DDP reference losses 3.80137, 3.09551, 3.16247 measured, CPU, 2 processes, gloo.

What the Trainer calls each step, and how Accelerate wraps FSDP2 (source and trace)

For the Trainer (settings matched to the plain loop) one step is: the Accelerate dataloader's __next__, Module.train, the forward, Accelerator.backward calling Tensor.backward, clip_grad_norm_, Adam.step through Accelerate's optimizer wrapper, LRScheduler.step, Module.zero_grad (the {{What calls what|#t-calls}} tab has the recorded order). Two calls you did not ask for:

  • clip_grad_norm_ is called on every step even with max_grad_norm=0: the Trainer then calls it with an infinite limit to log the gradient norm ({{trainer.py L2741 to L2756|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/trainer.py#L2741-L2756}}). One norm over all gradients per step, for a log line.
  • A torch.isnan and a torch.isinf on the loss each step (logging_nan_inf_filter, {{L1895 to L1900|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/trainer.py#L1895-L1900}}): on a GPU, a reduction whose result the logging path later reads.

With an FSDP plugin and fsdp_version: 2, Accelerate's fsdp2_prepare_model calls PyTorch's fully_shard on every module the auto-wrap policy picks (bottom up), then on the input embedding, then on one group of [final norm, output embedding] with reshard_after_forward=False ("re-gather would be unhideable"), then on the root ({{fsdp_utils.py L851 to L885|https://github.com/huggingface/accelerate/blob/v1.15.0/src/accelerate/utils/fsdp_utils.py#L851-L885}}): the same grouping torchtitan uses for its last layers (root's Distributed lab). On a CPU-only machine Accelerate ignores the FSDP plugin and returns DDP (the root's Ecosystem map measured it), so FSDP2 through Accelerate was not run here.

PEFT and TRL

PEFT wraps chosen nn.Linear layers of any model: LoRA rank 8 on the running example's four block matrices trains 131,072 of 3,186,944 parameters (4.1%, root's Ecosystem map); the method is {{PEFT|n:3c65c17b0d0d81eba08eef56b3e3b4eb}}'s. TRL's SFTTrainer, DPOTrainer, GRPOTrainer and RewardTrainer all subclass transformers.Trainer, so every Trainer default applies, plus TRL's own: gradient_checkpointing=True, bf16 (when fp16 is not set), and a learning rate of 2e-5 for SFT and 1e-6 for DPO and GRPO. What those methods do is {{Alignment|n:3c65c17b0d0d81d5bed7e608d4061c7a}}'s and {{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}'s subject.

TRL's defaults in its source (1.15.0, file and line)

The trainers subclass transformers.Trainer through trl.trainer.base_trainer._BaseTrainer; the configs subclass TrainingArguments, turn on gradient checkpointing and bf16 and log every 10 steps ({{base_config.py L54 to L72 in 1.15.0|https://github.com/huggingface/trl/blob/v1.15.0/trl/trainer/base_config.py#L54-L72}}); the learning rates are set at sft_config.py L133, dpo_config.py L149 and grpo_config.py L411.

The same model class, two different trainings
A GRPOTrainer with its config left alone computes in bf16, checkpoints activations, clips at 1.0 and uses lr 1e-6 with a linear decay; the same model in a plain Trainer computes in the checkpoint's dtype, keeps activations, clips at 1.0 and uses lr 5e-5. Write the settings you rely on into your config, every time.
