4. The Hugging Face stack: transformers, Trainer, Accelerate, PEFT, TRL

Five layers, each usable alone: transformers holds model definitions and loads weights from the Hub; the Trainer (inside transformers) runs the loop; Accelerate sits under the Trainer and turns one process into many (DDP, FSDP2, DeepSpeed, Megatron); PEFT injects adapters such as LoRA into any model; TRL holds post-training trainers (SFT, DPO, GRPO, reward models), each a subclass of the Trainer.

transformers v5: what changed

Version 5.0.0 came out on 2026-01-26, and 5.19.0 on 2026-10-06 (PyPI, as recorded by the root's {{Ecosystem map|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}}). From the {{v5 announcement|https://huggingface.co/blog/transformers-v5}} and the {{v5.0.0 release notes|https://github.com/huggingface/transformers/releases/tag/v5.0.0}}, checked against the 5.19.0 source where marked:

  • PyTorch only. TensorFlow and Flax support is sunset; JAX compatibility is left to partner libraries.
  • Attention is pluggable. Each model keeps its eager attention in its own file; SDPA, FlashAttention and FlexAttention live in one registry, AttentionInterface. At 5.19.0 its keys are ({{modeling_utils.py L5118 to L5125|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L5118-L5125}}); the default is "sdpa", falling back to eager when a model cannot use it ({{L1850 to L1886|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L1850-L1886}}). attn_implementation="flex_attention" is real, and run here on a tiny Llama:
  • Weights load in the dtype they were saved in. "We have updated the default dtype for all models loaded with from_pretrained to be auto" (release notes); v4 loaded in float32 unless told. At 5.19.0, dtype=None becomes "auto" ({{modeling_utils.py L4104 to L4105|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/modeling_utils.py#L4104-L4105}}). A bf16 checkpoint now trains in bf16 parameters unless you pass dtype=torch.float32, a silent precision change for anyone porting a v4 script.
  • Quantization is "a first-class citizen" (announcement): quantized checkpoints and configs such as bitsandbytes and torchao load through the same from_pretrained; the formats themselves are on {{Quantization and Precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}}.
  • Tokenizers: the fast/slow split is gone, the Rust tokenizers backend is the default, encode_plus is deprecated and apply_chat_template returns a BatchEncoding.
  • Trainer: report_to defaults to "none"; a new weight-loading API; reworked initialisation "to support scaled pre-training and different parallelism schemes" (announcement).
  • Serving: transformers serve (an OpenAI-compatible server), continuous batching and paged attention; and transformers model files run as a backend inside vLLM and SGLang (announcement). Serving itself is {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}.

What the Trainer calls in PyTorch, in order

The {{What calls what|#t-calls}} tab records every call that crosses from a library into PyTorch while the running example trains for 3 steps. For the Trainer (settings matched to the plain loop) one step is: the Accelerate dataloader's __next__, Module.train, the forward, Accelerator.backward calling Tensor.backward, clip_grad_norm_, Adam.step through Accelerate's optimizer wrapper, LRScheduler.step, Module.zero_grad. Two things stand out:

  • clip_grad_norm_ is called on every step even with max_grad_norm=0: the Trainer then calls it with an infinite limit to log the gradient norm ({{trainer.py L2741 to L2756|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/trainer.py#L2741-L2756}}). One norm over all gradients per step, for a log line.
  • There is a torch.isnan and a torch.isinf on the loss each step (logging_nan_inf_filter, {{L1895 to L1900|https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/trainer.py#L1895-L1900}}): on a GPU, a reduction whose result the logging path later reads.

Accelerate

accelerator.prepare(model, optimizer, dataloader) returns wrapped objects; on 2 processes here the model came back as torch.nn.parallel.DistributedDataParallel (constructed at {{accelerator.py L2060|https://github.com/huggingface/accelerate/blob/v1.15.0/src/accelerate/accelerator.py#L2060}}) and gave rank 0 the DDP reference losses 3.80137, 3.09551, 3.16247 measured, CPU, 2 processes, gloo. With an FSDP plugin and fsdp_version: 2, its fsdp2_prepare_model calls PyTorch's fully_shard on every module the auto-wrap policy picks (bottom up), then on the input embedding, then on one group of [final norm, output embedding] with reshard_after_forward=False ("re-gather would be unhideable"), then on the root ({{fsdp_utils.py L851 to L885|https://github.com/huggingface/accelerate/blob/v1.15.0/src/accelerate/utils/fsdp_utils.py#L851-L885}}). That is the same grouping torchtitan uses for its last layers (root's {{Distributed lab|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}}). On a CPU-only machine Accelerate ignores the FSDP plugin and returns DDP (the root's {{Ecosystem map|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}} measured it), so FSDP2 through Accelerate was not run here.

PEFT and TRL, briefly

PEFT wraps chosen nn.Linear layers of any model; on the running example, LoRA rank 8 on the four block matrices trains 131,072 of 3,186,944 parameters (4.1%, measured by the root's Ecosystem map). Methods and memory: {{PEFT|n:3c65c17b0d0d81eba08eef56b3e3b4eb}}. TRL's SFTTrainer, DPOTrainer, GRPOTrainer and RewardTrainer all subclass transformers.Trainer through trl.trainer.base_trainer._BaseTrainer, so every Trainer default above applies, plus TRL's own: its configs subclass TrainingArguments and turn on gradient_checkpointing=True and bf16 (when fp16 is not set), log every 10 steps ({{base_config.py L54 to L72 in 1.15.0|https://github.com/huggingface/trl/blob/v1.15.0/trl/trainer/base_config.py#L54-L72}}), and lower the learning rate to 2e-5 for SFT and 1e-6 for DPO and GRPO (sft_config.py L133, dpo_config.py L149, grpo_config.py L411). Recipes: {{Topic: llm-training-and-post-training|n:3c65c17b0d0d81b6876ee72b7056793b}}.

The same model class, two different trainings
A GRPOTrainer with its config left alone computes in bf16, checkpoints activations, clips at 1.0 and uses lr 1e-6 with a linear decay; the same model in a plain Trainer computes in the checkpoint's dtype, keeps activations, clips at 1.0 and uses lr 5e-5. Write the settings you rely on into your config, every time.
