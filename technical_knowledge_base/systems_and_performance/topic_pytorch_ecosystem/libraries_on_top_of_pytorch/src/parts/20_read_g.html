6. torchtitan: PyTorch's own training codebase

torchtitan (pytorch/torchtitan, release 0.3.0 on 2026-09-03) is the PyTorch team's reference for training large models with PyTorch's native pieces: FSDP2, tensor, pipeline, context and expert parallelism on one DeviceMesh, torch.compile, float8 and MX formats, distributed checkpointing. It is a codebase to read and fork, not a framework to configure: the model, the loss and the loop are short files you are expected to edit. Since the end of torchtune (2025) and the pause of torchforge, PyTorch-native LLM training is being consolidated here (root, section 9).

Configs are Python. At 0.3.0 a configuration is a function returning a Trainer.Config dataclass, registered in a model's config_registry.py (for example llama3_debugmodel), and overridden from the command line by tyro (--training.steps 3). --module may also name your own module, which is how this page added CPU configs without touching torchtitan (src/exp/titan/libcfg.py).

Running it on a Mac CPU: what broke, and the smallest patch for each

1. ModuleNotFoundError: No module named 'triton'Importing any model imports models/common/decoder.py -> moe.py -> token_dispatcher.py -> distributed/minimal_async_ep/kernels.py, whose line 10 is import triton; Triton ships Linux wheels only. Patch: replace that one module with a stub whose functions raise (the dense model never calls them). Putting a fake triton package on the path instead breaks PyTorch itself, which then believes Triton is installed.
2. module 'torch.mps' has no attribute 'set_device'The device comes from torch._utils._get_available_device_type() or "cuda" ({{tools/utils.py L55|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/tools/utils.py#L55}}), MPS here, and is then driven through CUDA-style calls. Patch: report "cpu", give torch.cpu the memory functions the monitor calls (returning zeros), drop barrier(device_ids=...), which otherwise placed the barrier tensor on MPS.
3. FlexAttention does not support backward on CPUEvery Llama 3 flavour defaults to attn_backend="flex" ({{llama3/__init__.py L369 to L371|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/models/llama3/__init__.py#L369-L371}}), and SDPA is refused: "sdpa is no longer supported for language models; positions are always available so use flex, flex_flash, or varlen" ({{config_utils.py L97 to L101|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/models/common/config_utils.py#L97-L101}}), because language models always use a block-causal mask built from per-document positions. Patch: evaluate the same BlockMask's mask_mod densely and call SDPA with it. Checked in forward on the first calls:
4. Cannot use ReduceOp.PREMUL_SUM with GlooOnly with 2 processes: torchtitan sets FSDP2's gradient divide factor to 1.0 (it divides by the global token count itself, section 3), and FSDP2 then reduce-scatters with PREMUL_SUM(1/1), which gloo lacks. Patch: ask FSDP2 for a plain SUM (its force_sum_reduction_for_comms path), followed by a division by 1.0: the same numbers.

Patches in src/exp/titan/ttrun.py; everything else (trainer, parallelisms, loss, optimizer, schedule, clipping, activation checkpointing) is torchtitan 0.3.0's own code from the tagged repository, which also supplies the debug tokenizer and the c4_test data. Settings changed for CPU speed only: sequence 256 instead of 2048, 10 steps, seed 0 (the debug config leaves it unset, so two runs initialise differently). Not run here: compile, float8, TP, PP, CP, EP (GPU kernels, or more processes than this page needs).

measured on Apple M1 Pro, CPU, torchtitan's logged global loss. Two processes read different shards of c4_test, so their curve is not step-for-step comparable with one process even at the same global batch of 4 sequences.

  • bf16 by default, even on one rank. parallelize_llama always calls apply_fsdp_to_decoder, "with shard_degree=1 it is a no-op for the all-gather but still installs the MixedPrecisionPolicy" ({{parallelize.py L69 to L90|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/models/llama3/parallelize.py#L69-L90}}): parameters are cast to bfloat16 for compute, gradients reduced in float32. The attention check above sees bf16 inputs on a single process. Setting mixed_precision_param="float32" moved the losses in the third or fourth decimal (table).
  • Activation checkpointing does not change the maths. No checkpointing, full, and the debug config's selective policy gave identical losses to five decimals: checkpointing trades memory for recompute, never results (memory is {{Making training fast|n:3c65c17b0d0d810d9e1fdf9ec942c20d}}'s subject).
  • The loss is chunked. The debug config wraps the loss in ChunkedLossWrapper: hidden states are split into 8 chunks along the sequence and each chunk runs lm_head, the loss and its own backward(), so the full logits never exist at once ({{loss.py L567 to L610|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/components/loss.py#L567-L610}}). The trace counted 8 backward calls from the loss wrapper per step plus 1 from the trainer.

Selective activation checkpointing in torchtitan 0.3.0 (verified)

The old page said torchtitan offers "none / selective (op or layer) / full". At 0.3.0 the choices are none, full, selective and memory-budget ({{activation_checkpoint.py L329 to L337|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/distributed/activation_checkpoint.py#L329-L337}}), and selective is per operator only; the per-layer option is gone. The per-op policy wraps each transformer block with create_selective_checkpoint_contexts and decides per ATen call: save the outputs of expensive ops (the SDPA variants, FlexAttention, aten.linear, aten.max for float8 scaling, topk for MoE routing, Inductor-compiled regions, and the communication ops reduce_scatter_tensor and all_to_all_single), recompute everything else, and of the matrix multiplies save only every second one (a counter of mm/linear calls; MoE router shapes are always recomputed) ({{L31 to L70, L185 to L288|https://github.com/pytorch/torchtitan/blob/v0.3.0/torchtitan/distributed/activation_checkpoint.py#L185-L288}}). memory-budget hands the trade-off to torch.compile's partitioner by setting torch._functorch.config.activation_memory_budget (default 0.5 there), and requires compile.

What it calls in PyTorch (trace, 2 processes): init_process_group, init_device_mesh, checkpoint_wrapper on the 6 blocks, fully_shard 9 times, set_gradient_divide_factor(1.0) on every FSDP module; then per step an all-reduce of the token count, set_requires_gradient_sync toggled around the chunked loss, clip_grad_norm_ through its own DTensor-aware version that calls DTensor.full_tensor() on the norm, AdamW.step, LRScheduler.step. The full ordered list is in {{What calls what|#t-calls}}.
