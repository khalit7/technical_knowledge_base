3.5 retain_graph, create_graph and double backward

Backward frees each node's saved tensors as soon as the node has run, which is why backward's memory falls as it goes. A second backward() through the same graph therefore fails: With retain_graph=True the saved tensors stay, and since gradients accumulate, two backwards on (w**2).sum() at w = [1, 2, 3] gave then .

create_graph=True goes further: backward itself is recorded, so the gradient is a tensor with its own grad_fn and can be differentiated again. For y = ∑x3 at x = [1, 2, 3]: first gradient (grad_fn MulBackward0, requires grad), second = 6x. Without it the gradient does not require grad and differentiating it fails with the familiar "does not require grad" error. This is how gradient penalties (WGAN-GP, input-gradient regularizers) and Hessian-vector products work. The cost is real: on a small MLP, forward plus one gradient took aten calls; forward, gradient with create_graph, the penalty and its backward took measured, aten calls counted by a dispatch mode.

3.6 Writing your own backward: torch.autograd.Function

When you want a different gradient than the one autograd would derive (a numerically safer formula, a fused kernel, a straight-through estimator), subclass torch.autograd.Function. The current style keeps forward free of the context and saves in a separate setup_context, which is what lets the function work with torch.func transforms:

class MyGelu(torch.autograd.Function): @staticmethod def forward(x): # no ctx here return 0.5 * x * (1 + torch.tanh(0.7978845608 * (x + 0.044715 * x ** 3))) @staticmethod def setup_context(ctx, inputs, output): (x,) = inputs ctx.save_for_backward(x) # goes through SavedVariable: version-checked @staticmethod def backward(ctx, g): (x,) = ctx.saved_tensors u = 0.7978845608 * (x + 0.044715 * x ** 3) t = torch.tanh(u) du = 0.7978845608 * (1 + 3 * 0.044715 * x ** 2) return g * (0.5 * (1 + t) + 0.5 * x * (1 - t ** 2) * du) x = torch.randn(6, dtype=torch.float64, requires_grad=True) torch.autograd.gradcheck(MyGelu.apply, (x,)) # finite differences in float64 torch.autograd.gradgradcheck(MyGelu.apply, (x,)) # its backward is differentiable too

gradcheck compares your backward with finite differences, column by column of the Jacobian; use float64, or rounding drowns the comparison. A backward that forgets the second term of the product rule fails at once: gradgradcheck does the same for the backward's own gradient. If your backward is written with operations autograd cannot differentiate (an external kernel), decorate it with @once_differentiable: then its output does not require grad and asking for a second derivative fails loudly () instead of silently returning a wrong one. Other context methods: ctx.needs_input_grad (skip work for inputs that need no gradient), ctx.mark_dirty (the forward wrote an input in place), ctx.mark_non_differentiable (integer outputs such as indices). For an operator that must also survive torch.compile and export as a single node, prefer torch.library.custom_op with register_autograd ({{Extending PyTorch|n:3f85c17b0d0d8158a7addcd3d601d72a}}).

3.8 Turning gradients off: no_grad, set_grad_enabled, inference_mode

So: no_grad and set_grad_enabled(False) are the same switch (the second takes a bool, handy for set_grad_enabled(is_train)); enable_grad turns it back on inside; inference_mode also removes the autograd and view-tracking keys (2.3) and produces inference tensors that can never enter autograd later. Use inference_mode for serving and for evaluation whose outputs you never train on; no_grad for anything inside a training loop (EMA updates, metrics on tensors you may reuse).

3.9 Saved-tensor hooks and activation checkpointing

The problem. The saved tensors of 3.1 are the activation memory that limits batch size and sequence length. Two tools trade something else for it.

Saved-tensor hooks (torch.autograd.graph.saved_tensors_hooks(pack, unpack)) intercept every tensor a node saves: pack may return anything (a CPU copy, a compressed version, a file name), and unpack must give the tensor back in backward. torch.autograd.graph.save_on_cpu() is the built-in pair that copies saved tensors to host memory. Activation checkpointing (torch.utils.checkpoint.checkpoint(fn, x, use_reentrant=False)) saves only the region's input and reruns the region during backward when a node first asks for a tensor it did not keep.
