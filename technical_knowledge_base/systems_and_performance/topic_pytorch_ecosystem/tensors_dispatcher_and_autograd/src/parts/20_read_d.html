2.6 Autocast: mixed precision as a dispatch key

How it works. torch.autocast(device, dtype) removes that device's Autocast key from the excluded set. From then on, every operator reaches the Autocast key first, and for most of them the slot is a fallthrough. Operators on the lower_precision_fp list (matrix multiplies, convolutions, attention, linear) get a kernel that casts their floating-point inputs to the autocast dtype; operators on the fp32 list (losses, norms, reductions that lose accuracy) cast to float32. Weights stay float32: the casts are new tensors each time.

Mind the difference: autocast does not make "the model" bf16; it makes chosen ops bf16, and everything else runs in whatever dtype reaches it.

2.7 Functionalization: removing mutation for compilers

The problem. Compilers and graph exporters want pure functions: no in-place writes, no aliasing, so they can reorder and fuse freely. Python code is full of add_, views and x[...] = y. Functionalization is a dispatch key (Functionalize, with a real kernel for aten operators and a boxed fallback for the rest) that wraps tensors and replays every mutation as an out-of-place op, regenerating views from their base. torch.compile's AOTAutograd stage uses it. 2.8 Meta and fake tensors: running a model without data

A meta tensor has sizes, strides and a dtype but no storage; its kernels (the Meta key) only compute output metadata. Built under with torch.device("meta"), the running example has parameters and allocates nothing; a forward returns logits of shape , and loss.item() fails: This is how you build a model too big for one machine and then materialize it shard by shard (to_empty plus your own initialization).

Gotcha, measured: materializing breaks tied weights

A FakeTensor is the same idea with a device attached: a tensor subclass that dispatches at the Python key (its keys include Python and PythonTLSSnapshot, table in 2.3) and answers every operator with metadata only. Under FakeTensorMode the running example ran forward and backward: logits , loss a FakeTensor on device cpu, and blocks.0.mlp.fc.weight.grad of shape , with no arithmetic done. torch.compile traces your model this way. One more measured trap: calling make_model (which ends in .to(device)) inside FakeTensorMode failed with , because moving a fake parameter swaps tensors in place and a tied parameter is held by two modules; building with GPT(cfg) directly worked.
