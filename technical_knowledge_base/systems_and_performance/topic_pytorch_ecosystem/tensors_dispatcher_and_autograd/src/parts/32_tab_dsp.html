Dispatcher walker

Two ways to watch the dispatcher on real calls, both recorded with torch 2.14.1 on the CPU (src/exp/dispatch.py). A is ground truth: a custom operator with a logging kernel at every key, so the record is literally the list of kernels the dispatcher ran, in order, each with the key set it was handed. B is real aten operators, which cannot be instrumented key by key from Python: there the route is reconstructed from the measured key sets, thread state and dispatch tables, and checked against what a TorchFunctionMode saw at the top and a TorchDispatchMode saw at the Python key.

A. One call, key by key: compare two situations

The op: tda::scale(Tensor x) -> Tensor, defined with torch.library.Library("tda", "DEF"); Python kernels registered with with_keyset=True at AutocastCPU (casts to the autocast dtype and calls the op with AutocastCPU excluded, as ATen's autocast wrappers do), AutogradCPU (redispatches below autograd under _AutoDispatchBelowAutograd, as generated autograd kernels do), ADInplaceOrView, CPU and Meta. The TorchDispatchMode row appears when a mode is active. Keys shown struck through never ran; the reason is beside them.

B. Real aten calls in four contexts

Things to try

  • Left "input requires grad", right "under torch.no_grad()": identical walks. The difference is inside the autograd kernel (it reads grad mode), not in the route.
  • Left "plain CPU tensor", right "inside a TorchDispatchMode": the mode's Python key sits below autograd and ADInplaceOrView, so a mode sees calls after autograd has recorded them.
  • In B, F.linear under training against under inference_mode: what the Python key sees changes from t, addmm to linear.
  • In B, torch.mm under autocast: two _to_copy casts appear before the bf16 mm; x.view under autocast is untouched (view is not on the list).
