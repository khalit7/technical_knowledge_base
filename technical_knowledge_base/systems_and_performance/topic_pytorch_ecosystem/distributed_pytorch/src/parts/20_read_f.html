6. Tensor and sequence parallelism: parallelize_module and its plan

Tensor parallelism (TP) splits the weight matrices inside a layer across ranks that all see the same batch (the Megatron split and its maths: {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}, section 5, and the {{Megatron-LM paper page|n:3c65c17b0d0d8133ae92fbe90a1f308e}}). PyTorch's API is parallelize_module(module, mesh, plan), where the plan maps submodule names to styles: ColwiseParallel (shard the weight's output dimension: each rank computes some output features), RowwiseParallel (shard the input dimension: each rank produces a Partial sum, then an all-reduce), SequenceParallel and PrepareModuleInput (convert a module's inputs between placements). Each style turns the module's parameters into DTensors and installs hooks that convert inputs and outputs.

Making attention splittable. The running example fuses q, k and v into one qkv projection, which cannot be column-split blindly (the parent lab found rank 0 got all of q and half of k); torchtitan's models use separate wq, wk, wv. Here each block's attention was swapped at run time for an equivalent module with separate q, k, v built from the same weights, whose forward uses as many heads as its local shard holds (src/exp/dpt_parts.py; the model file is unchanged). With 2 ranks each holds 2 of the 4 heads; losses equal one process at every step (3.801371, 3.187931, 3.167831) and gradients agree to 2.1e-6.

The plan decides the communication: 24 all-reduces or 16. Colwise on q, k and v separately means each wraps the same input in its own DTensor, and in backward each sends its own input-gradient all-reduce: 3 per attention instead of 1. Wrapping the attention input once ("attn": PrepareModuleInput(input_layouts=Replicate(), desired_input_layouts=Replicate(), use_local_output=False)) makes q, k and v share one DTensor input, whose gradients add up locally before a single all-reduce. Recorded per step: 24 all-reduces of 524,288 bytes with the first plan, 16 with the second (8 in forward: one after each attention and MLP of 4 blocks; 8 in backward). Same losses, same gradients, one third less communication.

Sequence parallelism turns each all-reduce into a reduce-scatter and an all-gather, and halves the tokens between them

Sequence parallelism: stop duplicating the cheap parts

Under TP, everything between the matrix multiplies (LayerNorms, the residual stream, dropout) runs on the full activation on every rank. Sequence parallelism (Korthikanti et al. 2022, arXiv 2205.05198) splits those along the sequence instead, which is free because they work token by token: each all-reduce becomes a reduce-scatter (each rank keeps its half of the tokens, summed) followed later by an all-gather (rebuild the full sequence before the next matrix multiply). In the plan, the LayerNorms get SequenceParallel(), the row-wise projections output Shard(1) (the sequence dimension), and PrepareModuleInput gathers the attention's and the MLP's inputs back to Replicate() (src/exp/tp_sp.py). The same block, before and after, recorded on 2 processes:

The animation, step by step: one block's forward on 2 ranks

  1. Block input. Both ranks hold the whole activation, 8 sequences × 64 tokens × 256 (recorded ln1 input, local shape (8, 64, 256), a plain tensor). The same numbers sit in two memories.
  2. LayerNorm, duplicated. Both ranks normalise all 64 tokens: the same work done twice, and the same activation saved twice for backward.
  3. Attention, split by heads. Each rank computes its 2 of the 4 heads for all 64 tokens (q, k, v weights local [128, 256] of [256, 256]).
  4. Output projection: a Partial sum. Each rank multiplies its heads by its rows of proj: a full-shape (8, 64, 256) result that is only part of the sum.
  5. All-reduce. One all-reduce of 524,288 bytes adds the two partial sums; both ranks again hold the whole activation.
  6. Residual and LayerNorm, duplicated again. Add to the residual stream and normalise, on both ranks, for all tokens.
  7. MLP up-projection, split by hidden units. Each rank computes 512 of the 1,024 hidden units for every token; GELU works on its half alone.
  8. MLP down-projection: a Partial sum. Again a full-shape partial result on each rank.
  9. All-reduce. The second all-reduce of the block. Per training step of the whole model: 16 all-reduces (8 in forward, 8 in backward), recorded.
  1. Block input, split along the sequence. Rank 0 holds tokens 0 to 31, rank 1 tokens 32 to 63 (recorded ln1 input: S(1), local shape (8, 32, 256)). Half the memory.
  2. LayerNorm on half the tokens. LayerNorm works token by token, so each rank normalises only its own 32 tokens: half the work, half the saved activation.
  3. All-gather. Attention needs every token: one all-gather (262,144 bytes in per rank) rebuilds the full (8, 64, 256) input on both ranks (recorded attention input: R, (8, 64, 256)).
  4. Attention, split by heads. As under TP: 2 of 4 heads per rank, all tokens.
  5. Output projection: a Partial sum. A full-shape partial result on each rank, as before.
  6. Reduce-scatter instead of all-reduce. Sum the partials and keep only your half of the tokens (recorded attention output: S(1), (8, 32, 256)). Gloo runs it as an all-reduce of the full tensor; NCCL moves half the bytes.
  7. Residual and LayerNorm on half the tokens. No duplication: each rank updates its own 32 tokens of the residual stream.
  8. All-gather. Rebuild the full sequence for the MLP.
  9. MLP up-projection. 512 of 1,024 hidden units per rank, all tokens.
  10. MLP down-projection: a Partial sum. A full-shape partial result.
  11. Reduce-scatter. Back to half the tokens per rank. Per training step of the whole model: 18 all-gathers and 16 reduce-scatters (recorded), against TP's 16 all-reduces.

What the recording says: the all-reduces become pairs of all-gathers (262,144 bytes in per rank: half the activation) and reduce-scatters (gloo runs them as all-reduces of the full 524,288 bytes; NCCL would move half). In ring terms the bytes per step are about the same as TP's (34 halves of 262,144 bytes, 8.9 MB, against 16 all-reduces costing 524,288 bytes each on 2 ranks, 8.4 MB), because an all-reduce is a reduce-scatter plus an all-gather; the gain is memory and work. Saved activations per rank fell from 22.17 MB to 20.06 MB here (one process: 47.41 MB): small, because on this model the LayerNorm and residual activations are a small part of what is saved. On long sequences and many layers it is the saving that makes TP + SP + selective recomputation fit (Korthikanti et al., Table 2; on {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}, section 5).

Predict: in TP + SP, what does a LayerNorm's weight gradient need at the end of backward?
An all-reduce. Each rank computed the LayerNorm on its own half of the tokens, so each holds a Partial gradient of the (replicated) weight. SequenceParallel makes the weight a Replicate DTensor, and DTensor reduces its Partial gradient for you: the gradients matched one process to 1.7e-6. Under plain TP the LayerNorm saw all tokens on every rank and no reduction was needed.
