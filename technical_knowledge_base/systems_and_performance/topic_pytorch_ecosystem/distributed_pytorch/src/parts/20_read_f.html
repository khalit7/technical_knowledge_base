6. Tensor and sequence parallelism on the running example's block

Tensor parallelism (TP) splits the weight matrices inside a layer across ranks that all see the same batch. torch.distributed.tensor.parallel.parallelize_module(module, mesh, plan) takes a plan, a dict from submodule names to styles: ColwiseParallel (shard the weight's output dimension: each rank computes some output features), RowwiseParallel (shard the input dimension: each rank produces a Partial sum, then an all-reduce), SequenceParallel and PrepareModuleInput (convert a module's inputs between placements). Each style rewrites the module's parameters into DTensors and installs hooks that convert inputs and outputs. The maths of the Megatron split is on the {{Megatron-LM paper page|n:3c65c17b0d0d8133ae92fbe90a1f308e}} and {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}; the lab tab (section 8) ran it on the MLPs and showed that the running example's fused qkv projection cannot be column-split blindly (rank 0 got all of q and half of k).

Making attention splittable. torchtitan's models use separate wq, wk, wv Linears. Here each block's attention was swapped at run time for an equivalent module with separate q, k, v built from the same weights, whose forward uses as many heads as its local shard holds (src/exp/dpt_parts.py; the model file is unchanged). With 2 ranks each holds 2 of the 4 heads; losses equal one process at every step (3.801371, 3.187931, 3.167831) and gradients agree to 2.1e-6.

The plan decides the communication: 24 all-reduces or 16

Colwise on q, k and v separately means each wraps the same input in its own DTensor, and in backward each sends its own input-gradient all-reduce: 3 per attention instead of 1. Wrapping the attention input once ("attn": PrepareModuleInput(input_layouts=Replicate(), desired_input_layouts=Replicate(), use_local_output=False)) makes q, k and v share one DTensor input, whose gradients add up locally before a single all-reduce. Recorded per step: 24 all-reduces of 524,288 bytes with the first plan, 16 with the second (8 in forward: one after each attention and MLP of 4 blocks; 8 in backward). Same losses, same gradients, one third less communication.

Sequence parallelism: stop duplicating the cheap parts

Under TP, everything between the matrix multiplies (LayerNorms, the residual stream, dropout) runs on the full activation on every rank: duplicated work and duplicated memory. Sequence parallelism (Korthikanti et al. 2022, arXiv 2205.05198) splits those along the sequence instead, which is free because LayerNorm and the residual add work token by token. Each all-reduce becomes a reduce-scatter (leave each rank its half of the tokens, summed) followed later by an all-gather (rebuild the full sequence before the next matrix multiply). Measured, 2 CPU processes, gloo.

What the recording says: the all-reduces disappear and become pairs of all-gathers (262,144 bytes in per rank: half the activation) and reduce-scatters (gloo runs them as all-reduces of the full 524,288 bytes; NCCL would move half). In ring terms the bytes per step are about the same as TP's (34 halves of 262,144 bytes, 8.9 MB, against 16 all-reduces costing 524,288 bytes each on 2 ranks, 8.4 MB), because an all-reduce is a reduce-scatter plus an all-gather; the gain is memory and work. Saved activations per rank fell from 22.17 MB to 20.06 MB here (one process: 47.41 MB): small, because on this model the LayerNorm and residual activations are a small part of what is saved. On a model with long sequences and many layers, Korthikanti et al. report the saving that makes TP + SP + selective recomputation fit (their Table 2; on {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}).

Predict: in TP + SP, what does a LayerNorm's weight gradient need at the end of backward?
An all-reduce. Each rank computed the LayerNorm on its own half of the tokens, so each holds a Partial gradient of the (replicated) weight. SequenceParallel makes the weight a Replicate DTensor, and DTensor reduces its Partial gradient for you: the gradients matched one process to 1.7e-6. Under plain TP the LayerNorm saw all tokens on every rank and no reduction was needed.
