3. Autograd: the graph built during forward

Autograd applies the chain rule automatically. During forward, the autograd kernel of each operator (section 2) adds a node to a graph (MmBackward0 for a matrix multiply) and keeps the forward tensors its gradient formula needs, the saved tensors. loss.backward() walks the graph from the loss to the parameters; AccumulateGrad nodes add into each parameter's .grad, and each node's saved tensors are freed once it has run.

The fact the rest of the topic builds on: what fills memory in training is the saved tensors, and they grow with batch size and sequence length while the weights do not. One forward of the running example builds 187 nodes (135 operators plus 52 AccumulateGrad, one per parameter tensor) and keeps 34.76 MB, against 12.75 MB of parameters measured on Apple M1 Pro. Activation checkpointing (torch.utils.checkpoint.checkpoint(fn, x, use_reentrant=False)) trades that memory for compute by keeping only a region's input and re-running the region in backward; per block, backward recomputed 112 calls, not a whole forward, because the non-reentrant variant stops once it has rebuilt what backward asked for. Pass use_reentrant=False: at 2.14.1 leaving it out still runs the older reentrant variant ({{checkpoint.py L635 to L647|https://github.com/pytorch/pytorch/blob/v2.14.1/torch/utils/checkpoint.py#L635-L647}}).

A gradient autograd cannot derive goes in a torch.autograd.Function with its own forward and backward, checked with torch.autograd.gradcheck in float64; an operator that must also work under torch.compile is better a torch.library.custom_op with register_autograd (section 8).
