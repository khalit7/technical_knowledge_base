4. Recompiles and dynamic shapes

The problem. Sizes are guarded like everything else. A model that sees a new sequence length, a short last batch or a different learning rate passed as a Python number fails a guard and compiles again, at a cost of seconds each time. Compiling for "any size" instead makes kernels that cannot specialise on the size (no fully unrolled loops, extra index arithmetic) and adds symbolic reasoning to every compile.

How it works. By default Dynamo compiles the first call with every size static (a constant). When a size guard fails, automatic dynamic shapes (automatic_dynamic_shapes, on by default, config.py L188) recompiles with the dimension that changed replaced by a symbol (s75 below) whose value is read at run time; guards on that symbol are inequalities instead of equalities. Two exceptions are built in: sizes 0 and 1 stay specialised (a dimension of 1 broadcasts, so code valid for "any n" may be wrong for 1; this is 0/1 specialisation), and parameters' shapes are always static (force_parameter_static_shapes). Unbacked symbols: sizes that come from data


A symbol from an input size is backed: at compile time there is a real example value (a hint) to answer questions like "is s75 > 1?". A symbol from .item() or nonzero() is unbacked: its value exists only when the graph runs. Dynamo breaks on both by default; with capture_scalar_outputs or capture_dynamic_output_shape_ops it keeps them in the graph as u0, and any branch on them must be answered without a value. At 2.14.1 slicing by an unbacked size needed no help: Dynamo added the runtime asserts u1 >= 0 and u1 <= 64 itself. torch._check(n >= 0); torch._check(n <= idx.shape[1]) moves the same asserts to your line and tells the compiler facts it can reuse; it is the fix when a branch cannot be decided ("Could not guard on data-dependent expression", the error in section 3). torch.cond is the fix when you really need both branches.


How to check. TORCH_LOGS=recompiles names the failing guard for every recompile; TORCH_LOGS=dynamic shows each symbol as it is created ("create_symbol s75 = 32 for L['idx'].size()[1] [2, int_oo]", recorded) and every guard on it; torch.compiler.set_stance("fail_on_recompile") makes a test fail on any recompile.
