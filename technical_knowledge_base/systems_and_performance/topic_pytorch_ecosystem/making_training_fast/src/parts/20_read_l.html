11. torchao: fewer bits for weights, activations and gradients

The problem. Every number in the running example is a 32-bit float. Fewer bits means less memory, less data moved and, on hardware with matching instructions, faster matmuls. torchao (pip install torchao, 0.18.0 here, released 2026-08-03) is PyTorch's library for that, for inference and for training. The formats themselves (int8, int4, float8 E4M3 and E5M2, the MX block formats) belong to {{Quantization and Precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}}; this section is about the PyTorch side: what torchao does to a model, what ran on this machine, and what needs which GPU.

How it works. quantize_(model, config) walks the model and replaces each nn.Linear's weight with a tensor subclass (a Python class that wraps the low-bit data and its scales and intercepts every op on it; the {{Extending PyTorch child|n:3f85c17b0d0d8158a7addcd3d601d72a}} shows how subclasses are built). The module code is unchanged; when F.linear reaches the subclass, it dispatches to a quantized kernel or dequantizes. Because it is a subclass, it composes with torch.compile, FSDP2 and DTensor.

Low-precision training: float8 and MX

float8 training (torchao.float8.convert_to_float8_training(model)) swaps each Linear for a Float8Linear that casts its inputs, weights and output gradients to float8 with a scale per tensor (or per row), runs the matmul in float8 on the tensor cores and keeps the master weights in higher precision. Published: up to 1.5 times the throughput at 512 GPUs on a 405B model vendor, torchao README ({{torchao|https://github.com/pytorch/ao}}). It needs float8 tensor cores: compute capability 8.9 or newer (Ada, Hopper, Blackwell), or AMD MI300; torchao's dynamic float8 inference config asserts exactly that ("requires CUDA compute capability ≥8.9 or MI300+ or XPU", reproduced as the error on this CPU).

What can run here is the numerics: Float8LinearConfig(emulate=True) performs the same casts and scales and emulates the float8 matmul in float32. It shows whether float8 rounding hurts this model, nothing about speed.

MX formats (MXFP8, MXFP4; and NVIDIA's NVFP4) put one shared scale on every block of 32 (MX) or 16 (NVFP4) values, so outliers cost less precision than with one scale per tensor. In torchao 0.18.0 they live in torchao.prototype.mx_formats (MXDynamicActivationMXWeightConfig, NVFP4DynamicActivationNVFP4WeightConfig; listed from the installed package) and target Blackwell's block-scaled tensor cores. Not run here: no Blackwell GPU, and no CPU emulation was attempted.

Quantization-aware training (QAT)

The idea. Quantizing after training rounds weights the model never saw rounded. QAT fine-tunes with fake quantization: the forward pass rounds weights to the target grid (then back to float), the backward pass treats the rounding as identity, so the weights learn to sit where rounding hurts least. In torchao: quantize_(m, QATConfig(base_config, step="prepare")), train, then quantize_(m, QATConfig(base_config, step="convert")).

Other torchao pieces, by name

torchao.optim.AdamW8bit and AdamW4bit (optimizer state in 8 or 4 bits: the 8 bytes per parameter of section 7 shrink to about 2 or 1), CPUOffloadOptimizer (state and the step on the CPU), sparsify_ for 2:4 sparsity on GPUs that accelerate it. All present in 0.18.0 checked; not run here.
