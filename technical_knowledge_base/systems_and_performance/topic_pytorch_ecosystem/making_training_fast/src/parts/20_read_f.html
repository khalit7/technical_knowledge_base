11. Attention kernels: SDPA backends, FlexAttention, variable length

Written out (the running example's attn="manual"), attention builds a sequence × sequence matrix of scores per head, softmaxes it and keeps it for backward: double the context, four times the memory. The fix, from {{FlashAttention|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}, computes attention in tiles and keeps only the output plus one number per row (the log of the softmax's sum, logsumexp), recomputing the tiles in backward, so memory becomes linear in sequence length ({{Writing kernels|n:3c65c17b0d0d81b9ab89c1bb7238cb6c}} owns how the kernel does it; the attention designs themselves are on {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}).

A fused kernel keeps 32 times less for backward at 2,048 positions, and the gap grows with T² (one attention call, 8 heads of 64)

measured on Apple M1 Pro, float32, PyTorch 2.14.1, deterministic: unique storages passed to autograd's saved-tensor hooks, q, k and v excluded (src/exp/attn_backends.py).

On the CPU, SDPA ran the flash-style CPU kernel and kept the output and one logsumexp per row and head: 4.3 MB at 2,048 positions, growing linearly (0.5 MB at 256). Written out, the same attention kept the 8 × T × T softmax: 138.4 MB at 2,048, 32 times more. On MPS, SDPA with gradients takes the math path and keeps the T × T matrix too (142.6 MB): there is no memory-efficient attention for training on Apple GPUs in PyTorch 2.14.1.

SDPA: one function, several kernels. F.scaled_dot_product_attention (SDPA) checks the inputs against each backend's constraints in a fixed priority order and runs the first that qualifies. CUDA tries flash, efficient, math, cuDNN (cuDNN first on Hopper and Blackwell with recent cuDNN), and an arbitrary attn_mask or a float32 input rules flash out; the CPU tries a flash-style kernel, then math; MPS always runs math. Measured here: on the CPU the flash kernel took every case except dropout; on MPS forcing a backend changes nothing; bfloat16 is less exact (largest error 8.1e-3 against 8.4e-7 for float32). Check which ran: profile one call and read the op name (aten::_scaled_dot_product_flash_attention, ..._efficient_attention, ..._cudnn_attention, ..._attention_math), or force one with sdpa_kernel([SDPBackend.FLASH_ATTENTION]), which raises instead of falling back silently.

FlexAttention: attention variants as two small functions. Sliding windows, packed documents, prefix-LM masks, relative biases and soft-capping used to mean a custom kernel or the math path. FlexAttention (torch.nn.attention.flex_attention, prototype in 2.5) takes two Python functions: score_mod(score, b, h, q_idx, kv_idx) changes one score (add a bias, cap it), and mask_mod(b, h, q_idx, kv_idx) says whether query q_idx may see key kv_idx. create_block_mask evaluates the mask once per tile of 128 × 128 (the default block size, flex_attention.py L444) and stores, per row of tiles, which tiles are fully allowed, partly allowed (the kernel applies the mask inside) or empty (the kernel skips them). That BlockMask is where the speed comes from.

What the BlockMask buys, counted here (deterministic): at 4,096 positions a causal mask leaves 48.4% of the 128 × 128 tiles empty, a 128-token sliding window 93.8%, four packed documents 81.0%. On MPS (compiled) its largest error against float64 was 8.5e-7, the size of SDPA's own. At 4,096 positions it did not win on time: sliding window 16.9 ms against 17.4 ms for SDPA with a dense boolean mask (a tie), four documents 54.5 ms against 17.6 ms, causal 148 ms against 7.69 ms for SDPA with is_causal. Its cost tracks the tiles it visits, as designed; the per-tile kernel is just slower than Apple's fused SDPA. The 2.13 release notes' "up to ~12x speedup over SDPA on sparse patterns" on MPS vendor did not reproduce on this M1 Pro in float32 (other chips, dtypes and sizes not tried). On GPUs the authors report 90% of FlashAttention-2 forward and 85% backward vendor, PyTorch team, 2024 ({{FlexAttention blog|https://pytorch.org/blog/flexattention/}}).

from torch.nn.attention.flex_attention import flex_attention, create_block_mask doc = document_id_per_position # (T,) int tensor, 0,0,0,1,1,2,... def doc_causal(b, h, q, k): return (doc[q] == doc[k]) & (q >= k) bm = create_block_mask(doc_causal, None, None, T, T) # once per shape; reuse it flex = torch.compile(flex_attention) # eager mode materialises the full score matrix out = flex(q, k, v, block_mask=bm)
What FlexAttention does not do on this Mac at 2.14.1
  • No backward on CPU or MPS: "FlexAttention does not support backward on CPU" (and on MPS) when an input requires grad (flex_attention.py L2204 to 2219) reproduced; on CUDA (or XPU or HPU) it trains.
  • No compiled kernel on a Mac CPU: Inductor's CPU template needs AVX2 and refuses sys.platform == "darwin" (flex_cpu.py L31 to 40); "torch.compile on current platform is not supported for CPU" reproduced. Eager works and is exact but materialises the scores.
  • MPS compiles it to a Metal kernel (since 2.13, {{release notes|https://github.com/pytorch/pytorch/releases/tag/v2.13.0}}), inference only. On NVIDIA GPUs Inductor generates Triton kernels, with an optional FlashAttention-4 backend since 2.11 ({{2.11 release notes|https://github.com/pytorch/pytorch/releases/tag/v2.11.0}}).

Variable-length attention (not usable here)

Packing several sequences into one row avoids padding; the mask then has to stop sequences seeing each other. Two ways: a document mask in FlexAttention (above), or torch.nn.attention.varlen.varlen_attn(q, k, v, cu_seq_q, cu_seq_k, max_q, max_k) (added in 2.10), which takes all sequences concatenated as (total tokens, heads, head size) plus cumulative lengths, like flash_attn_varlen_func. At 2.14.1 it calls aten._flash_attention_forward or cuDNN, both CUDA kernels (torch/nn/attention/varlen.py L54, L139). Called here: CPU "NotImplementedError: Could not run 'aten::_flash_attention_forward' with arguments from the 'CPU' backend."; MPS "NotImplementedError: The operator 'aten::_flash_attention_forward' is not currently implemented for the MPS device." measured.
