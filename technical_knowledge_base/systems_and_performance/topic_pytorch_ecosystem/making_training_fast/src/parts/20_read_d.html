7. The loop the levers plug into

Every lever changes one line of the same loop, whose own rules decide whether a fix is correct. nn.Module adds bookkeeping, not a new machine: assigning an nn.Parameter to a module attribute registers a parameter (a leaf tensor with requires_grad=True that optimisers update), assigning a module registers a sub-module, and register_buffer registers a buffer (saved, not trained; persistent=False keeps it out of the state_dict). parameters(), .to(), state_dict() and train()/eval() walk that tree, and a state_dict is names over storages.

A tied weight is one Parameter under two names: parameters() counts it once, the state_dict twice

The running example ties its output head to its token embedding (head.weight is tok.weight). parameters() de-duplicates by object, the state_dict does not, so parameters() counts 52 tensors and the state_dict 53 (3,197,952 elements against 3,186,944) measured. Consequences: safetensors refuses to save the shared storage, two different values loaded under the two names leave the later one, and to_empty unties them (details below).

One optimizer step with accumulation, float16 and clipping, line by line (step through it)

measured on the running example, CPU, PyTorch 2.14.1 (recorded by the sibling {{Tensors, the dispatcher and autograd|n:3f85c17b0d0d81138595c1c6cd52f795}}, its exp/module_loop.py): four micro-batches of 2 with each loss divided by 4 gave the same gradient as one batch of 8 (norm 11.1032); without the division the norm was 44.41, exactly 4.00 times too large. clip_grad_norm_ returned the norm before clipping (11.1032 at step 0). zero_grad freed 12,747,776 bytes of gradients.

Three rules follow. Gradients accumulate into .grad across backwards, so micro-batch losses must be divided by their number; this is also a memory lever, because activations scale with the micro-batch while the gradient is that of the whole batch (section 8). A GradScaler's gradients must be unscaled before clipping, or you clip a gradient 65,536 times too large and the threshold means nothing. Log the norm clip_grad_norm_ returns: it is the cheapest training-health signal you have.

Determinism. Seed with torch.manual_seed and make the data order a function of the step, as get_batch(cfg, step) does (it made the first three losses identical across a plain loop and three frameworks on the root's {{Ecosystem map|n:3c65c17b0d0d8150aa65ca44b6ed2fd5}} tab). In short: CPU with a fixed thread count was bit-for-bit repeatable; 1 against 4 threads differed in the last bits (max parameter difference 1.46e-06); MPS was not bit-repeatable even with use_deterministic_algorithms(True), which raised nothing measured.

Forward hooks (measured)

register_forward_pre_hook sees a module's inputs before forward, register_forward_hook its inputs and output after; both may replace them. They are the standard way to read activations without editing the model: one hook per block of the running example, one batch, collected the output standard deviation per block, 0.0495, 0.0659, 0.0799 and 0.0924 measured, the residual stream growing block by block as expected at initialisation. Determinism, run by run (measured)

The thread count changes the order of floating-point sums, hence the last bits. On CUDA, use_deterministic_algorithms(True) swaps in deterministic kernels where they exist and raises a RuntimeError for operations without one, and torch.backends.cudnn.benchmark = False stops cuDNN from picking algorithms by timing (not run here).
