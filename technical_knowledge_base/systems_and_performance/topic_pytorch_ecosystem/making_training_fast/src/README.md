## Experiments (`exp/`, PyTorch 2.14.1 and torchao 0.18.0 in the topic's shared venv, Apple M1 Pro)

The running example is imported from the root's `src/model/` (`exp/common.py` adds it to the path); nothing is redefined. `exp/variants.py` runs its forward plain, checkpointed, with two selective-checkpointing policies, or with the fused loss, calling the model's own submodules (all give the same loss and gradients; checked).

Deterministic (no lock needed):

| Script | Output | What |
|---|---|---|
| `probe_api.py` | `inputs/probe_api.json` | Which APIs exist at 2.14.1 and torchao 0.18.0 |
| `mem_step.py` | `inputs/mem_step.json` | Memory by category over one step (memory profiler), saved bytes, ATen calls per phase; 3 configs x up to 6 variants |
| `attn_backends.py` | `inputs/attn_backends.json` | Which SDPA kernel ran, forcing each backend, error vs float64, saved bytes vs T |
| `flex_lab.py` | `inputs/flex_lab.json` | BlockMask counts for 4 masks x 3 lengths; FlexAttention correctness on CPU (eager) and MPS (compiled); backward and compile failures |
| `torchao_lab.py` | `inputs/torchao_lab.json` | PTQ configs (bytes, loss, errors), float8 emulated training, QAT against PTQ |
| `saved_formula.py` | `inputs/saved_formula.json` | Saved tensors of one block by shape; the per-block formula checked on 5 configs |
| `budget.py` | `inputs/budget.json` | torch.compile activation memory budget 1.0 to 0.0: saved bytes |
| `varlen_probe.py` | `inputs/varlen.json` | varlen_attn on CPU and MPS (error messages) |

Not run here (copied): `inputs/loop_module.json`, `loop_dataloader.json` and `loop_sources.json` are the sibling Tensors, the dispatcher and autograd's recorded `inputs/module.json`, `dataloader.json` and two quotes of its `sources.json` (its `exp/module_loop.py` and `exp/dataloader.py`, torch 2.14.1, same machine), absorbed on 2026-10-23. `derive_mfu.py` derives the MFU of section 3 from recorded inputs (no run).

Rebuild: run the scripts with the shared venv's python (`FST_SCRATCH` = a scratch directory for the raw traces), then `python3 build_data.py; python3 derive_mfu.py; sh build.sh; python3 check_data.py; node check_page.mjs ../index.html <shots dir>`.

## The 2026-10-23 rebuild: what changed and why

Rebuilt to the teaching contract (`.claude/skills/explainer-page/teaching/teaching-contract.md`); editing and recomposition only, no new runs.

- **Top**: the core idea in one sentence; a new static hero (one step of the larger variant as two bars, time by phase on MPS and memory at the peak by category, every lever of the page bracketed under the part it shrinks with its section number); "You need"; new terms; the three ideas. The old "In one screen" grid of script-written answers became a closed block of static answers.
- **Lab tabs moved inline** beside the claim each proves: the Profiler trace (two real traces on one clock) into section 3, the Attention lab (BlockMask before/after sweep) into section 11. The Memory budget calculator stays a tab: it serves sections 8 to 10 at once. Tabs went from five to three.
- **Absorbed** from the sibling Tensors, the dispatcher and autograd (its section 4 closed blocks), with its recorded data: Module registration, state_dict and tied weights (new static diagram), the loop line by line (new stepper: accumulation, unscale before clip, clipping, GradScaler, zero_grad), determinism, DataLoader seeding, the float16 underflow counts (new before/after figure of float16's range against the gradients, unscaled and scaled). New section 7 "The loop the levers plug into"; seeding in section 4's closed block; the GradScaler in section 6.
- **Added**: MFU of the hunt, derived from recorded inputs (`derive_mfu.py`: 51% to 62% on MPS, 42% to 50% on CPU, against the measured float32 matmul rate); CUDA graphs named as the launch-bound lever with links to torch.compile and Streams, CUDA graphs and multi-GPU; bars for the compile memory budget (were a sentence).
- **Owned elsewhere, now linked**: the checkpoint mechanism (non-reentrant hooks, early stop) to Tensors, the dispatcher and autograd; FLOPs, peaks and MFU arithmetic to Performance math; formats to Quantization and Precision.
- **Script-written result paragraphs became static text** (same numbers, from the rendered page), so the ledger can see them; the scripts keep drawing the figures.
- **Closed**: measurement provenance of each figure ("Measured on Apple M1 Pro: how"), profiler options, memory tools by device, SDPA backend tables and FA3/FA4, FlexAttention measured tables, varlen, QAT against PTQ, MX and other torchao pieces, the transfer table, mistakes (14) and interview rehearsal (13).
- **No autoplay**: the template `RD.anim`; a scripted check scrolled the whole page and found every player on step 0, paused.
- **Deleted as fat** (22 ledger units, each with a note): headings with "The problem." wind-ups, restatements, pointers to and instructions for the removed tabs.

## Length judgement

| | Before (audit 2026-10-23) | After |
|---|---|---|
| Reading, core (230 words a minute) | 39.0 min | 32.4 min |
| Reading, closed details | 2.6 min | 19.2 min |
| Other tabs, core | trace 2.6 + attention lab 3.1 + memory budget 2.8 = 8.6 min | memory budget 2.8 min |
| Core total, excluding Further reading | 47.6 min | 35.2 min |
| Visuals in Reading (audit count of SVG and canvas) | 2 (plus 3 in tabs) | 8; counting bar charts and steppers, 19 figures inline |

Why 32 minutes is right: the page teaches a method (measure, fix one thing, measure) and twelve levers, each with its measured number, picture and when-to-use, plus the loop that every lever edits (absorbed, about 3 minutes); every core ledger unit is needed to choose or check a lever. What made the old page long (provenance captions, backend tables, measured tables per mask and config, mistakes and interview answers) is now closed and optional, which is why the closed time grew.
