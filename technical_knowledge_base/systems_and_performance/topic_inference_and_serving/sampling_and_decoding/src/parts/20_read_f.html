5. Constrained decoding: JSON schemas and grammars

Constrained (or structured) decoding guarantees that the output matches a format, a JSON schema, a regular expression or a context-free grammar, by masking every token that would break it at every step: an engine compiles the constraint to an automaton over the tokenizer's vocabulary, tracks the automaton's state as tokens are emitted, and before the sampler runs sets every disallowed logit to −∞. The running example: Qwen2.5-0.5B-Instruct, greedy, asked to extract {"name": string, "age": integer} from one sentence. Its favourite first token is a Markdown fence, which no JSON parser accepts.

The sampler (greedy here) then runs on the masked distribution as usual.

The mask changes size at every step, and that is what makes it expensive or cheap. Inside a string almost anything is allowed; at a structural position only a handful of tokens are.

The toy grammar and how the masks were computed

The grammar is a regular expression, with whitespace capped at two characters between JSON tokens:

\{[ \n]{0,2}"name"[ \n]{0,2}:[ \n]{0,2}"[A-Za-z .\-]{1,40}"[ \n]{0,2},[ \n]{0,2}"age"[ \n]{0,2}:[ \n]{0,2}(0|[1-9][0-9]{0,2})[ \n]{0,2}\}

At every step each of the 151,665 tokenizer strings was checked with the regex package's partial matching: a token is allowed when the text so far plus the token can still complete a match (src/make_data.py json). That is a brute-force check of the whole vocabulary at every step; the engines below exist to avoid it.

Grammar-constrained tool-call parsing is standard in serving stacks.

What the mask costs in quality
  • It guarantees the format, not the content. When the model wanted a token you masked, the rest of the answer is conditioned on text it would not have written (0.0004% at step 2 above). Schema design (field order, letting the model think before the JSON) mitigates it. The size of the effect is disputed: {{Tam et al., 2024|https://arxiv.org/abs/2408.02442}} report "a significant decline in LLMs reasoning abilities under format restrictions"; the Outlines team re-ran their tasks with matched prompts and found structured generation slightly better (GSM8K 0.78 against 0.77, Last Letter 0.77 against 0.73, Shuffled Objects 0.44 against 0.41: {{.txt, "Say what you mean"|https://blog.dottxt.ai/say-what-you-mean.html}}).
  • Whitespace and token boundaries are the classic bugs. A token can straddle a grammar boundary (": closes a key and starts the colon), whitespace rules decide which tokenisations are reachable (steps 2 and 10 above), and an unbounded whitespace rule lets a model emit spaces forever.
