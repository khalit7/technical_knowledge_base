Closed reasoning APIs fix the sampler for you
The knobs on this page are mainly for open models you serve yourself; on the large closed reasoning APIs the provider fixes sampling. Claude 4.7 and later models accept only the default values: with API version 2023-06-01 any non-default temperature, top_p or top_k "returns a 400 error" ({{Anthropic, Opus 5.5 migration guide|https://platform.claude.com/docs/en/models/opus-5-5/migration-guide}}), and API version 2026-10-21 (21 October 2026) removes the three parameters altogether: sending one returns 400 "even at the parameter's default value", and a request samples at the defaults, temperature 1.0. On an older model that still honoured a lowered temperature, such as Sonnet 4.6, the new version loses that effect and "No other setting replaces it"; such a request has to stay on 2023-06-01 ({{migration guide|https://platform.claude.com/docs/en/api/migration-2026-10-21}}). OpenAI's reasoning models other than GPT-6 Astra do not support temperature, top_p, presence_penalty, frequency_penalty, logprobs or logit_bias; GPT-6 Astra supports temperature and top_p ({{Azure OpenAI reasoning docs, 21 September 2026|https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/reasoning}}). What stays in the caller's hands on those APIs is the output's shape (structured outputs, section 5) and how much it thinks, not the sampler.

7. Built on sampling (owned elsewhere)

  • Self-consistency and best-of-n sample n answers and return the majority answer ({{Wang et al., 2022|https://arxiv.org/abs/2203.11171}}) or the one a verifier or reward model rates highest; best-of-n is also a baseline alignment method and a reward-hacking amplifier ({{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}}). The maths of pass@k, voting and best-of-n, with a sampling lab: {{Test-time compute and reasoning|n:4035c17b0d0d813f9fb2d62cff1f09ef}}, sections 2 and 3.
  • Speculative decoding drafts several tokens cheaply (a draft model, n-gram lookup, or extra heads such as Medusa and EAGLE) and verifies them in one target pass with an acceptance rule that leaves the output distribution exactly the target's, so every sampler on this page works unchanged. The rule, every kind of drafter and the batch size where it stops paying: {{Speculative decoding|n:3f35c17b0d0d81e086fde85940ebac1c}}.
  • Test-time compute scaling, longer chains of thought and parallel sampling with a verifier, is the decoding-side half of the reasoning-model story; the training-side half (RL with verifiable rewards) is on {{Alignment: SFT, RLHF, DPO Family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}.

Text watermarking is the one technique built on sampling that this page owns. The sampler's random draw is replaced by a choice that a secret key and the preceding tokens decide, so each pick is still drawn from the model's distribution and the text reads the same, but many such picks together carry a statistical signal a key holder can test for. Google DeepMind's SynthID-Text does this with tournament sampling ({{Dathathri et al., Nature 2024|https://www.nature.com/articles/s41586-024-08025-4}}); Claude's watermark, announced 14 August 2026, "is a version of the SynthID-Text approach" and "only changes the source of the randomness used to pick among words" ({{Anthropic|https://www.anthropic.com/news/claude-text-watermark}}). Its limits follow from the mechanism: few acceptable word choices (code, tightly constrained or factual text) leave little signal, short samples detect poorly, and a complete rewrite removes it; detection is a key holder's API in private preview, not a public detector.
