Which engine is faster depends on the model, the GPU, the precision, the prompt length, the per-user speed you promise and the date of the build. The one place both are run by a third party on the same model and GPUs is SemiAnalysis InferenceX, a continuously running benchmark ({{repository|https://github.com/SemiAnalysisAI/InferenceX}}, {{dashboard|https://inferencex.semianalysis.com/inference}}) independent. Of the models it lists, only DeepSeek-V4-Pro has single-node runs of both vLLM and SGLang; those runs are below, read from its public API on 2026-10-08.

Read the chart as a trade-off curve: each point is one run at one concurrency; to the right, each user gets more tokens per second; up, each GPU produces more tokens in total. An engine is better where its upper-right envelope (the line) is higher at the per-user speed you need.

What this comparison can and cannot say
  • Different builds and dates. The vLLM runs used v0.25.0 to v0.25.1 or nightly images from July to September 2026; the SGLang runs used nightly images from late June and July 2026 (shown per row). Both engines have released several versions since (vLLM v0.31.0, SGLang v0.5.21).
  • Different recipes. Each engine ran with its own tensor, expert and data-parallel choices (TP and EP columns), so a row at the same concurrency can compare different numbers of GPUs per replica; the envelopes, which take each engine's best configuration, are the fairer reading.
  • One model. DeepSeek-V4-Pro is a 1.6-trillion-parameter mixture of experts with a long-context attention design; results on a dense 8B or 70B model can differ completely.
  • No prefix reuse. These are single-turn random prompts, so nothing here exercises the radix cache or cache-aware scheduling, where section 3 of the Reading found the two caches equal.
