The real SGLang engine, release v0.5.21, running on an Apple M1 Pro laptop through its MLX backend: the same scheduler, radix cache, overlap loop and grammar backend that run on GPUs, with Apple's MLX doing the forward pass. Every number on this tab was measured here on 2026-10-08 and 2026-10-09 measured on Apple M1 Pro; what transfers to datacenter GPUs is said at the end.

Set-up

  • Machine: Apple M1 Pro, 16 GB unified memory, shared with other jobs (load average at the start of the runs; every configuration repeated, spread shown).
  • SGLang v0.5.21 (tag commit e00930c5, 2026-09-29), installed from source with the srt_mps extra and Rust extensions off (SGLANG_BUILD_RUST_EXTS=none): PyTorch 2.13.0, MLX 0.32.3, MLX-LM 0.32.0, XGrammar 0.2.7, Transformers 5.12.1. There is no macOS wheel on PyPI.
  • Two patches from upstream, both in src/m1/: the start-up fix of {{PR #41314|https://github.com/sgl-project/sglang/pull/41314}} (merged after the tag) and the cache fix of {{PR #42542|https://github.com/sgl-project/sglang/pull/42542}} (open). Without the first the server does not start; without the second, cache hits can return the wrong text (below).
  • Model: Qwen3-0.6B (Qwen/Qwen3-0.6B at commit c1899de2) quantized here to 4 bits, group size 64, with MLX-LM 0.32.0, the root's model store. KV pool: 114,688 bytes per token at 16 bits.
  • Server: SGLANG_USE_MLX=1 python -m sglang.launch_server --model-path <model> --disable-cuda-graph --port 8120 --enable-metrics plus --chunked-prefill-size 4096 --max-running-requests 8 and the flags of each experiment; a fresh server per run. Both settings work around the Apple backend: each running request gets its own contiguous KV buffer of 4,096 tokens per layer (448 MiB for this model, {{model_runner.py L258|https://github.com/sgl-project/sglang/blob/v0.5.21/python/sglang/srt/hardware_backend/mlx/model_runner.py#L258}}); and with 512-token prefill chunks, any burst of 840-token prompts crashed the server with [METAL] Command buffer execution failed: Insufficient Memory inside _async_extend_batch, every time and with 6 GB free, while the same bursts of 8 to 32 requests ran cleanly with chunks of 4,096 (a third bug, not reported upstream as of this writing). Client: src/m1/exp.py over the native /generate endpoint with token ids cut from WikiText-2, greedy, streaming; time to first token (TTFT) is the arrival of the first streamed chunk.

What transfers to a datacenter GPU

  • Transfers: which tokens are cached and reused (the scheduler and tree are the same code), the ordering effects of the queue policies, the correctness test, the fact that a grammar adds per-step CPU work.
  • Does not transfer: the absolute times. A 0.6B model on a laptop GPU makes the forward pass short and the Python scheduler's share large, so CPU-side effects (overlap, grammar masks) look bigger here than on an H100 serving a 70B model; prefill costs far more per token here than on a GPU, so cache hits save more seconds here. The MLX backend also lacks paged attention: it copies a cached prefix out of the pool into a per-request cache ({{model_runner.py|https://github.com/sgl-project/sglang/blob/v0.5.21/python/sglang/srt/hardware_backend/mlx/model_runner.py}}).
