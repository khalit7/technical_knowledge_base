1. The promise and its bill: SLOs, goodput, capacity, cost per token

The promise, in numbers. The running example promises p99 TTFT within 2 s and mean TPOT within 50 ms. TTFT (time to first token) is queueing plus prefill, from request sent to first token received. TPOT (time per output token) is one request's mean gap after that, (end-to-end latency − TTFT) / (output tokens − 1); ITL (inter-token latency) is every individual gap, a distribution. Two targets, because they fail for different reasons: TTFT when requests queue or prompts are long, TPOT when batches are too large or a long prefill interrupts decoding.

Capacity is goodput, not peak throughput. DistServe's goodput is the maximum request rate at which a target fraction of requests (say 90%) meets the SLOs, per GPU ({{DistServe, OSDI 2024|https://arxiv.org/abs/2401.09670}}). Past that rate raw throughput stays about flat while goodput collapses, because every extra request only waits (the parent's {{Engine bench|n:3c65c17b0d0d81c08b3bc95ff45c7b13}} measures the bend). The parent's {{Capacity planner|n:3c65c17b0d0d81c08b3bc95ff45c7b13}} (its step model fitted to MLPerf runs) finds that one H200 serves 2.11 requests per second within both targets (at that load TTFT p99 1.05 s, TPOT 46.8 ms), so 20 requests a second at peak need ⌈20 / 2.11⌉ = 10 H200s. The 50 ms TPOT target, not memory, sets that number: relaxing it to 100 ms cuts the fleet to 8. derived by the parent's planner

Predict: the 10-GPU fleet is sized for the peak and paid for all day. An API charges $0.40 per million tokens. At what average traffic, as a share of the peak, does the fleet become as cheap as the API?
About 67%. The fleet costs the same every hour; the API's bill grows with traffic. At the peak the fleet serves 20 × 2,300 × 3,600 = 165.6 million tokens an hour, which the API would charge $66.24 for; the fleet's $44.70 equals the API's bill at 44.70 / 66.24 = 67% of the peak. derived Drag the slider below to see the crossing.

A fleet sized for the peak is cheap per token only when it is busy

Self-hosted: 10 H200s at $4.47 an hour each (DigitalOcean on demand, 2026-10-08) = $44.70 an hour, whatever the traffic. API: $0.40 per million input and output tokens, the cheapest provider OpenRouter listed for Llama 3.1 70B on 2026-10-08. Tokens are blended input and output, 2,300 per request. What moves the answer. At 50% of the peak the fleet is 35% dearer than the API per token; self-hosting wins with high and steady utilization, reserved or cheaper GPUs (DigitalOcean's 12-month H200 price is $3.40), traffic with heavy prefix reuse, a model or fine-tune no provider hosts, or data that cannot leave your network. An autoscaler (section 3) attacks the denominator differently: it stops paying for the night, so the same peak costs fewer GPU-hours. Depth: where the 2.11 comes from, and what the planner varies

The parent's planner computes, for one copy of the model, the memory each GPU spends, how many sequences fit, how long each engine step takes at a given mix of prefill and decode, and the steady-state TTFT p99 and mean TPOT at each arrival rate; it takes the highest rate that meets both targets. Its two engine constants are fitted to published MLPerf runs, with the residuals shown on its tab. A simpler bound that this page's autoscaling simulator uses: a request holds one of 32 sequence slots for its prefill (0.42 s) plus 300 tokens at 46.8 ms (14.5 s), so one replica completes 32 / 14.5 = 2.2 requests a second at most; goodput (2.11) sits just below it because queueing near the limit pushes TTFT past the target.
