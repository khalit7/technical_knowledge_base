Why the gain shrinks as the batch grows, as a cost model you can move, checked against real llama-server runs at 1 to 16 users on the laptop, and carried to an H100 with the parent's calibrated step model.

speed-up(B) = E[tokens per step] × t(B, 1) / ( k · tdraft(B) + t(B, k + 1) )
B
sequences decoding together (users in the batch)
t(B, n)
one target pass over n tokens for each of B sequences
E[tokens per step]
(1 − αk+1)/(1 − α), or a measured acceptance length

The measured runs

llama-server (llama.cpp b11146, Metal) serving Qwen3-4B Q4_K_M with 16 slots, and 1, 2, 4, 8 and then 16 closed-loop clients in turn, each sending a different prompt from a mixed pool of 16 (code, explanations, stories, lists), greedy, 192 tokens per answer. Three servers: no draft; the Qwen3-0.6B Q4_K_M draft (--spec-type draft-simple, k = 3, the default); and the same draft under llama-server's --spec-synth-len 4.5 benchmarking mode (k = 4), which runs the real draft but accepts guesses at random so the mean acceptance length is fixed at 4.5 (its output text is not valid). Idle slots do no work, so one 16-slot server serves every user count. The whole sweep ran twice per server; the machine was shared, so the load average is recorded with each run and the spread between the two sweeps is shown.
