Local inference means running a language model on a machine you own (a laptop, a desktop with one or two gaming GPUs, a phone) for yourself or a handful of people. The datacenter pages ask how to serve thousands of users per GPU at the lowest cost. Here the questions flip: does the model fit in my memory, how fast does it stream for me, how much quality did shrinking it cost, and which program should run it?

The parent page, {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}, explains prefill, decode and the KV cache from zero; this page uses those words. In one line each: prefill reads the whole prompt in one pass; decode then produces one token per pass; the KV cache holds the keys and values every earlier token produced, so decode does not recompute them; TTFT (time to first token) is how long you wait before text appears, and tokens per second (or its inverse, TPOT, time per output token) is how fast it streams after that.

1. How fast it streams
bytes per token / bandwidth

With one user, every token reads all the weights once. Speed is set by memory bandwidth, not by arithmetic (section 1).

2. Whether it fits
weights + KV cache + buffers

The weights must sit in memory the GPU can read fast: VRAM on a graphics card, unified memory on a Mac (section 2).

3. What shrinking costs
quantization

Storing weights in 4 bits instead of 16 makes the model 3 to 4 times smaller, faster (by less than that on a small GPU, section 1), and a little worse. How much worse is measurable (sections 3 and 4).

4. Which program
llama.cpp, MLX, Ollama, LM Studio

All four sit on two engines: ggml (llama.cpp) and MLX. The wrappers add model management and hide knobs (sections 5 to 7).

The stack

Every local program sits on one of two numerical engines. Knowing which one tells you which file format it reads and which knobs exist underneath its interface.

Apps and wrappers
Ollama (Go server, model registry, runs its own runner processes) · LM Studio (desktop app, closed source)
LM Studio (its MLX engine) · Ollama on Macs (MLX path: section 7)
Server (HTTP, OpenAI-compatible)
llama-server: slots, continuous batching, prompt cache, metrics
mlx_lm.server: batched decode, prompt cache
Engine
libllama (C/C++): model graphs, KV cache, sampling
mlx-lm (Python): models, generation, quantization
Kernels
ggml: CPU (NEON, AVX), Metal, CUDA, Vulkan, ROCm/HIP, SYCL
MLX (Apple's array framework): Metal, CPU
File format
GGUF: one file, weights in block-quantized types plus tokenizer and chat template
safetensors with MLX's group-wise scales and biases
