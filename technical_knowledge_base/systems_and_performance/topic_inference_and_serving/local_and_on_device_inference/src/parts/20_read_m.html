11. Phones, the browser, and on-device formats

A phone is the same problem with a smaller budget: a few GB of memory shared with everything else, less bandwidth than a laptop (Apple publishes 120 GB/s for the base M4 chip and no iPhone figures), a battery and a thermal limit, and usually an NPU (a neural processing unit: fixed-function matrix hardware that runs integer and low-precision maths efficiently, if the model was compiled for it). The bandwidth rule still sets the decode ceiling, which is why Apple's on-device model is about 3 billion parameters at 2 bits per weight. On-device runtimes bring their own file formats, usually compiled for a back end (layer 3 of section 3). None of this was run here.

Is the Neural Engine worth it for an LLM? For energy, yes. MacPaw ran Liquid AI's LFM2.5-2.6B entirely on an M4 Pro's Neural Engine through Core AI, the framework macOS 27 adds for finer control than Core ML. Plain decoding there managed 32.2 tokens per second against 81.5 for MLX 8-bit on the GPU; with tree-shaped speculative decoding it reached 136.9 against 144.9 for MLX 8-bit with DSpark, at about 21 W of system power against 57 W, and across the Macs tested it used 2.6 to 3.4 times less energy per request than that GPU baseline ({{MacPaw research|https://research.macpaw.com/projects/neural-engine}}, undated, read 2026-10-26, vendor). The Neural Engine wins on watts, not speed, and only once speculation hides its slow single steps.
