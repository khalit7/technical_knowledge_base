Quant ladder: size, speed and quality of every GGUF type, measured

Each point is one file made here with llama-quantize (llama.cpp b11146) from an F16 conversion of the released weights, then measured three ways on the same laptop: size (bits per weight = tensor bytes × 8 / values stored, as llama-bench reports them; Qwen3-1.7B's GGUF stores its embedding and output matrices separately, as its checkpoint does, MLX once (Reading section 3)), speed (llama-bench: reading a 512-token prompt and generating 128 tokens, 5 repetitions each, Metal, flash attention on) and quality against the F16 file on the first 40 windows of 512 tokens of WikiText-2 (test split), scoring the last 255 tokens of each window (llama-perplexity --kl-divergence). Measured here, Apple M1 Pro, ; the load average during each run is in the table.

Three quality measures. Perplexity (PPL) is exp of the average negative log-probability the model gives the true next token: lower is better, but quantization noise can lower it by luck on one text. KL divergence (KLD) compares the whole next-token distribution of the quantized model with the F16 model's, token by token: it is 0 only if they agree exactly, and it is what llama.cpp's own tool reports for comparing a quantized file with its source (llama-perplexity --kl-divergence). Same top token is how often both models' most likely next token is the same: what greedy decoding would see.
