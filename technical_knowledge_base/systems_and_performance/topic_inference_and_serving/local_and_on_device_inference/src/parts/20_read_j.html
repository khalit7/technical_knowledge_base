8. Ollama and LM Studio: what the wrappers add

llama-server is one process for one model, started with flags you have to know. Ollama and LM Studio let you type a model name and chat: they manage downloads, start and stop engines on demand, and pick defaults. The cost is that the defaults are theirs.

Ollama: a Go server that launches engines

Ollama is a Go server that keeps a model store and runs each model in a separate runner: upstream llama-server for GGUF, and since v0.40.0 its own MLX runner by default on Apple silicon.

The scheduler's two runner paths, with sources (depth)

Ollama (MIT licence) is a Go program: ollama serve listens on 127.0.0.1:11434, keeps a model store of layers addressed by hash (like a container registry; a Modelfile names a base model plus a template and parameters), and runs each loaded model in a separate runner process. Read at v0.40.1 (commit cf2a313a, 7 October 2026; the latest release is v0.40.2 of 8 October), the scheduler has two runner paths (server/sched.go L535 to L598):

  • GGUF models: upstream llama.cpp's own llama-server as a subprocess, built from a pinned version (LLAMA_CPP_VERSION = b11351) with Ollama's compatibility patches (llama/README.md); llama-server "auto-detects GPU layers (-ngl), thread count (-t), and flash attention" (llm/llama_server.go L1 to L14).
  • MLX models on Apple silicon: Ollama's mlxrunner, on a pinned MLX commit. Since v0.40.0 (25 September 2026) "Models run on MLX on Apple Silicon by default" when the architecture is supported ({{release notes|https://github.com/ollama/ollama/releases}}).
Correction to the old page

The old page said Ollama "runs its own ggml-based engine for new models while still using llama.cpp kernels underneath". That was true from v0.7.0 (May 2025, {{"Ollama's new engine for multimodal models"|https://ollama.com/blog/multimodal-models}}) and is not how v0.40 is built: GGUF goes to upstream llama-server, and Apple silicon prefers MLX. Between them, v0.19.0 (March 2026) put MLX in preview ({{Ollama blog, 30 March 2026|https://ollama.com/blog/mlx}}) and v0.30.0 (May 2026) moved more of the work back onto llama.cpp ("improved compatibility and performance using llama.cpp").

Ollama adds a registry, load-on-demand with a keep-alive, and cloud models; and it decides these for you:

What Ollama adds, in full (depth)

What Ollama adds: the registry (ollama pull qwen3:4b), model lifecycle (load on first request, unload after a keep-alive, up to 3 models per GPU loaded at once), its own API plus OpenAI- and Anthropic-compatible endpoints, and cloud models (a :cloud tag routes the same local API to Ollama's hosted GPUs, since v0.12.0, September 2025; {{Ollama blog|https://ollama.com/blog/cloud-models}}). LM Studio

LM Studio is a closed-source desktop app on the same two engines (llama.cpp for GGUF, mlx-engine on Macs), with a headless mode, llmster. Not run here.

LM Studio's engines (depth)

A closed-source desktop app (free for work use since 8 July 2025, {{LM Studio blog|https://lmstudio.ai/blog/free-for-work}}) with two engines: llama.cpp for GGUF ("llama.cpp runtime 2.50.0 (upstream b11337)" in 0.4.26) and its open-source mlx-engine on Apple silicon. Since 0.4.0 its core also runs headless as llmster (lms daemon up, lms server start) with parallel requests and continuous batching. Not run here: it is a GUI install. vendor docs

LM Studio's versions and defaults (depth)

Version 0.4.0 (28 January 2026) split out llmster and added parallel requests with continuous batching through llama.cpp; 0.4.2 brought batching to MLX; 0.4.1 added an Anthropic-compatible /v1/messages endpoint ({{0.4.0 blog|https://lmstudio.ai/blog/0.4.0}}, {{changelog|https://lmstudio.ai/changelog/lmstudio}}). Models load just in time on the first request and unload after 60 idle minutes by default ({{TTL docs|https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict}}). Latest: 0.4.26 (8 October 2026).
