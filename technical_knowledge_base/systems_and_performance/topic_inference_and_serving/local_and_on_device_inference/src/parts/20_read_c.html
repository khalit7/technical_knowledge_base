2. Will it fit? Weights, cache and buffers

The model must sit in memory the GPU reads fast: its own VRAM on a graphics card (32 GB on an RTX 5090), or on a Mac the unified memory the CPU and GPU share, of which macOS lets the GPU use only part. Three things need room:

memory ≈ weights + KV cache + buffers
weights
parameters × bits per weight / 8 (Qwen3-4B at Q4_K_M: 4.02 billion × bits measured, about 2.5 GB)
KV cache
bytes per token × context × slots, where bytes per token = 2 × layers × KV heads × head size × bytes per value
buffers
scratch for one step's activations, a few hundred MB for small models (llama.cpp prints its compute buffer at start)

The cache can outweigh the model (the hero above): Qwen3-4B keeps 2 × 36 × 8 × 128 × 2 = 147,456 bytes per token in F16, so its full 40,960-token context costs 6.0 GB, more than twice the 2.5 GB of Q4_K_M weights. Long contexts are paid in memory first and speed second. Two remedies: a quantised cache (-ctk q8_0 -ctv q8_0 halves it; the {{batching sibling|n:3c65c17b0d0d819db53bd2c48909e5b2}} measured no perplexity change at q8_0 on Qwen3-1.7B), and a context no longer than you need.

macOS lets the GPU use of this laptop's 16 GB (measured), and llama-server's --fit shrinks unset settings until the plan fits.

When it does not fit

  • Partial offload. -ngl N puts only N layers on the GPU; the rest run on the CPU at the CPU's bandwidth. On a PC that is system RAM at tens of GB/s, many times below a GPU's; on a Mac the CPU shares the memory but pulls less of it ( against tokens per second, section 1).
  • Mixture-of-experts models read only a few experts per token, so keeping the experts in system RAM (--n-cpu-moe N or --cpu-moe) and attention and shared layers on the GPU costs less than offloading a dense model of the same size.
  • Memory-mapped files. llama.cpp maps the GGUF file (section 3), so a model larger than RAM still loads and its pages are read from disk as needed: a loading trick, not a way to run fast.
