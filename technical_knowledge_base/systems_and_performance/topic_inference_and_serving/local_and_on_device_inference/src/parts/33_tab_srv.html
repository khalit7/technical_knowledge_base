llama-server lab: every run behind sections 5 to 7

Each experiment started its own server on this laptop (port range 8170 to 8179, stopped as soon as its run ended), held the shared bench lock, and recorded the one-minute load average before and after. Measured here, Apple M1 Pro, llama.cpp build 11146, Qwen3-1.7B Q4_K_M (the store's Unsloth file, 1.11 GB) unless noted. Scripts: src/scripts/srvlab.py, ollamalab.py, mlxjob.sh.

1. Defaults: what a bare llama-server -m model.gguf chooses

2. Slots sweep: 8 users against 1, 2, 4 and 8 slots

3. Split against unified KV: one 2,925-token prompt, 4 slots, 8,192 tokens of cache

4. Context shift: asking for 1,500 tokens in a 512-token slot

5. Cache reuse: a document removed from the middle of the prompt

6. Router mode: three models, one loaded at a time

7. /metrics after one request

8. Ollama 0.40.1 against llama-server, same file

9. CPU against GPU on the same chip
