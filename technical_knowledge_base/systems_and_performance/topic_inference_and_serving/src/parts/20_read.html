Inference is running a trained model to get an answer. Serving is doing that for many people at once, over a network, fast enough that nobody waits too long, and cheaply enough to pay for. This page teaches it from zero by following one chat request through a serving engine, then a thousand of them.

The running example. A chat assistant built on Llama 3.1 70B (70.6 billion parameters, 80 layers; {{config.json|https://huggingface.co/unsloth/Meta-Llama-3.1-70B/blob/main/config.json}}, an open mirror of Meta's gated repository), stored in FP8 (one byte per weight) on NVIDIA H200 GPUs (141 GB of memory at 4.8 TB/s, {{NVIDIA|https://www.nvidia.com/en-us/data-center/h200/}}). Every request carries a 2,000-token prompt whose first 1,000 tokens are the same system prompt, and gets a 300-token answer. It is the same deployment the {{Capacity planner|#t-plan}} opens with, so every number here can be checked there. A token is the unit the model reads and writes, a word or a piece of one (about three quarters of an English word on average).

One request, from text in to text out

Times are derived from the {{Capacity planner|#t-plan}}'s step model for this deployment, alone on one H200 (step time = the larger of bytes read / (bandwidth × 0.8) and FLOPs / (FP8 peak × 0.345), plus 2.5 ms; the two efficiencies are fitted to MLPerf runs on that tab). Prefill and decode are drawn on different time scales: the 299 decode steps after the first token take about 15 times as long as the prefill.

Five numbers describe everything that follows. The first two are what a user feels, the third is what the owner pays for, the fourth is what runs out, the fifth is the bill.

TTFT
0.42 s

Time to first token: from sending the request to seeing the first word. Mostly the prefill, plus any time spent waiting in the queue.

TPOT
21.6 ms

Time per output token after the first (also called inter-token latency, ITL): how fast the answer streams. 21.6 ms is 46 tokens a second, faster than anyone reads.

Throughput
46 → 2,982 tok/s

Output tokens per second for the whole GPU: one user alone, against 141 users decoding together (section 3). Same GPU, 64 times the work.

KV cache
320 KiB / token

Memory each token of each conversation occupies while it is active (section 2). It decides how many users fit at once.

Cost
$0.54 / M tokens

Blended over input and output for this deployment at $4.47 per H200-hour (section 10), against $0.40 from the cheapest API provider.

All five are derived for the running example from the {{Capacity planner|#t-plan}} (the throughput pair and the 141 users come from its memory budget and step model; the cost from its fleet sizing at 20 requests per second, both latency targets met). The same quantities measured here on a laptop are on the {{Engine bench|#t-bench}} tab.
