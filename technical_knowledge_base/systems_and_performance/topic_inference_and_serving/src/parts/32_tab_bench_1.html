Engine bench

Real serving engines, run on a real machine, measured the way you would measure your own deployment. Every number on this tab was produced on this laptop on : llama.cpp and MLX on the laptop's GPU, and vLLM on its CPU inside Docker. The point is not the absolute numbers (a datacenter GPU is 20 to 100 times faster); it is the shapes: how speed changes with prompt length, with context, with batch size, with load, with quantization, and where the curves bend.

What was measured here, and what was not
Measured on an Apple M1 Pro (16-core GPU, 16 GB of memory shared by CPU and GPU, about 140 to 160 GB/s of memory bandwidth as measured on the {{Topic: hardware|n:3c65c17b0d0d8118beeefaed56da6f8e}} page): Models: the Qwen3 family at 0.6B, 1.7B and 4B parameters (one tokenizer, so the small one can draft for the big one). Every measurement was repeated (3 to 5 times for kernel benchmarks, 2 to 3 seeds for load tests) and the spread is shown; the laptop was shared with other jobs, so each run records the one-minute load average (from to on 10 cores).
Not run here: any NVIDIA or AMD GPU; SGLang (its CPU backend targets Intel Xeon processors with AMX instructions and ships x86 images only; see the note in Engines side by side); TensorRT-LLM (NVIDIA only). Published GPU numbers live on the {{Capacity planner|#t-plan}} tab, labelled as vendor or independent.
