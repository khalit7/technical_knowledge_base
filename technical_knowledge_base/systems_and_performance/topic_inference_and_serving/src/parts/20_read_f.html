5. The engines

A serving engine is the program that does everything above: an OpenAI-compatible HTTP front end, a tokenizer, the scheduler, the cache manager and a model runner that calls GPU kernels. Engines share sections 2 to 4 and differ in hardware, model coverage and what they optimise. Versions: latest GitHub releases on 2026-10-08 (SGLang and TensorRT-LLM were not run here).

Defaults quoted from source at the tagged versions (vLLM v0.31.0, TensorRT-LLM v1.2.1 llm_args.py, SGLang v0.5.21) and from the help output of the versions run on the {{Engine bench|#t-bench}} (llama-server 0.5.0, mlx_lm.server 0.32.0). The MLPerf observation is a count over the {{Capacity planner|#t-plan}}'s extract of single-node LLM results, v5.1 to v6.1: most NVIDIA rows list TensorRT or TensorRT-LLM, the AMD rows mostly vLLM.

Above the engines sits a layer that routes across replicas and nodes: NVIDIA {{Dynamo|https://github.com/ai-dynamo/dynamo}} (1.0 on 2026-03-13; engine-agnostic over vLLM, SGLang or TensorRT-LLM; disaggregation and KV-aware routing), {{llm-d|https://llm-d.ai/}} (Kubernetes-native around vLLM, a CNCF Sandbox project), {{KServe|https://kserve.github.io/website/}} and {{Ray Serve|https://docs.ray.io/en/latest/serve/llm/index.html}} (general model serving that runs these engines), and {{Triton Inference Server|https://github.com/triton-inference-server/server}} (NVIDIA's multi-framework server, still the choice for a mixed zoo of classic ML and LLMs; its dynamic batching is not continuous batching, which it delegates to a TensorRT-LLM or vLLM backend). On a desktop, {{LM Studio|https://lmstudio.ai/}} puts a GUI over llama.cpp and MLX.

Choosing. Start from the hardware and the model, not from a benchmark chart:

  • Datacenter GPUs, a popular open model, an API this afternoon: vLLM, the widest model and chip support; most cloud stacks wrap it.
  • A large MoE across many GPUs, or agents resending long prefixes: SGLang or vLLM; SGLang published the most detailed expert-parallel recipe (DeepSeek-V3 on 96 H100s, 22,282 output tokens per second per node, {{LMSYS, 2025-05-05|https://lmsys.org/blog/2025-05-05-large-scale-ep/}}, vendor).
  • NVIDIA only, one model, every last percent: TensorRT-LLM (or NIM containers on it), at the price of lock-in.
  • A laptop, desktop, phone or CPU server: llama.cpp or Ollama; on a Mac also MLX. Measured here, the two decode alike alone (196 and 199 tokens per second at 4 bits), but under overload mlx_lm.server ran out of GPU memory and its generation thread died while llama-server queued and slowed measured here.
