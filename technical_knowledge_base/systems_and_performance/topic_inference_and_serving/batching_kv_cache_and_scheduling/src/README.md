## Rebuild
```
python3 -I evict/gen_evict.py <traces> evict/out/evict_grid.json; python3 -I evict/gen_frag.py <traces> evict/out/frag.json
python3 -I evict/gen_anim.py <traces> evict/out/evict_anim.json
python3 -I sched/check/regress.py; M1_LONG_AT=1.629 python3 -I sched/gen_sched.py
python3 -I exp/summarize.py <raw results>; python3 -I kvc/summarize.py <taskA.json> <taskB.json>
python3 -I gen_data.py; sh build.sh; python3 -I check_data.py; node check_ui.mjs <shots dir>
```
vLLM checks need a Python with torch and vLLM's requirements, `PYTHONPATH=<vllm v0.31.0 source>`, `VLLM_TARGET_DEVICE=cpu`,
`VLLM_MODEL_DIR=<folder with Qwen3-0.6B config.json>` (and `VLLM_ALLOW_LONG_MAX_MODEL_LEN=1` for vllm_evict.py).

## Findings worth keeping
- vLLM's priority queue breaks ties by comparing request ids as strings; a step in which the only request needing a block preempted itself is an empty step (the parent's simulator would have rejected the request). Both mirrored in `bksched.py`.
- Mooncake's arXiv Table 1 does not reproduce exactly on the released trace (2 to 6 points higher, same shape); the report's mean input (7,590) differs from the file's (8,590). FAST'25 Fig. 9 labels reproduce within 1 to 4 points.
- Random KV eviction that drops the first tokens (attention sinks) collapses (perplexity 927 against 17.04 at 25% kept); with the first 4 kept it is the proper control (23.71), a fair floor on continuation but useless on retrieval (5.6% against 91.7% for a shared SnapKV selection). Per-head selections free 0% of 16-token blocks in place.
- llama.cpp q4_0 KV cache raised Qwen3-1.7B's perplexity by 28% (15.18 to 19.42); q8_0 changed nothing.
