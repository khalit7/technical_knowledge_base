2. Pickle: a checkpoint that is a program

The problem. For years the default way to save a PyTorch model was torch.save, which writes Python's pickle format, and the Hugging Face files named pytorch_model.bin are exactly that. Pickle can save any Python object, which sounds like a feature until you see how: a pickle is not data, it is a program for a small stack machine, and loading it runs the program.

How it works. The pickle machine reads one-byte opcodes. Most push values (a string, an integer) onto a stack. Two are the point: GLOBAL imports any module.name and pushes it, and REDUCE pops a callable and an argument tuple and calls it. That is how a tensor is rebuilt (call torch._utils._rebuild_tensor_v2 with the storage and shape) and equally how a file can call os.system. Python's own documentation says it plainly: "The pickle module is not secure. Only unpickle data you trust. It is possible to construct malicious pickle data which will execute arbitrary code during unpickling" ({{pickle docs|https://docs.python.org/3/library/pickle.html}}).

Since PyTorch 1.6 a .pt or .bin file is a zip archive ({{torch.save docs|https://pytorch.org/docs/stable/generated/torch.save.html}}): a small data.pkl program plus one raw file per storage. The mitigation that failed, and the ones that hold

  • weights_only=True swaps the pickle machine for a restricted one that only allows an allowlist of globals (tensor rebuild functions, plain containers). PyTorch 2.6 made it the default on 2025-01-29, calling it a backward-compatibility-breaking change ({{PyTorch 2.6 blog|https://pytorch.org/blog/pytorch2-6/}}).
  • It was bypassed. {{CVE-2025-32434|https://github.com/advisories/GHSA-53q9-r3pm-6pq6}} (published 2025-04-17/18, CVSS v4 9.3, critical): remote code execution through torch.load even with weights_only=True, in every PyTorch before 2.6.0. So for years the recommended safe path was not safe.
  • Libraries now refuse. transformers 4.52.0 (2025-05-20) added check_torch_load_is_safe(): on PyTorch older than 2.6 it raises instead of loading a .bin, and its message adds "This version restriction does not apply when loading files with safetensors" ({{source|https://github.com/huggingface/transformers/blob/main/src/transformers/utils/import_utils.py}}).
  • Real attacks exist. JFrog found "around 100" malicious models on the Hugging Face Hub, one opening a reverse shell (2024-02-27, {{JFrog|https://jfrog.com/blog/data-scientists-targeted-by-malicious-hugging-face-ml-models-with-silent-backdoor/}}). ReversingLabs' "nullifAI" (2025-02-06) found two models whose pickles were packed with 7z and deliberately broken after the payload, so the Hub's Picklescan missed them ({{ReversingLabs|https://www.reversinglabs.com/blog/rl-identifies-malware-ml-model-hosted-on-hugging-face}}). The Hub lists each pickle's imports without executing it and says this "is not 100% foolproof" ({{Hub docs|https://huggingface.co/docs/hub/security-pickle}}).
  • Not only PyTorch. Keras models could carry code in Lambda layers ({{CVE-2024-3660|https://nvd.nist.gov/vuln/detail/CVE-2024-3660}}, fixed in Keras 2.13 with safe_mode), and {{CVE-2025-1550|https://nvd.nist.gov/vuln/detail/CVE-2025-1550}} ran code through load_model even with safe_mode=True (fixed in Keras 3.9.0).
The rule
Treat a pickle checkpoint from anyone you do not trust as an executable. Prefer the safetensors files in the same repo; if only a .bin exists, convert it inside a throwaway sandbox (a container with no credentials and no network), never on your workstation.
