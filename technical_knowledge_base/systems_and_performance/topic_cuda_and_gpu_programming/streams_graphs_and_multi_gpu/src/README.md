# Streams, CUDA graphs and multi-GPU programming: sources, scripts, outputs

- `build.sh`: assembles `../index.html` from `parts/` (Reading `20_read_a.html` to `20_read_j.html`; JS `21` the skill template `RD` (never autoplays), `22` data generated by `recompute.py`, `23` static charts and text from data, `24` training-step model and its animation, `25` launch-overhead animation, `26` the step calculator (closed block in section 6), `27` the static figures added 2026-10-23 (hero, event ordering, peer access, a hang, async TP); `39_tab_more.html` Further reading; every JS part in its own script, `99_js_tabs.js` last, storage key `cuda-sg-tab`).
- `run_all.sh`: reproduces everything. Needs Docker with kb-gpu-lab:1 (Dockerfile in `../../src/compile/image/`), `TORCHPY` (a Python with torch 2.14.1) and `METALPY` (a Python with pyobjc-framework-Metal 12.x), both outside the repo.
- `cuda/kernels/s1..s5`: copy/compute pipeline with pinned memory, streams, priorities and events; CUDA graphs (capture, instantiate, replay, `cudaGraphExecUpdate`, a conditional WHILE node with `cudaGraphSetConditional`); peer access and IPC; the DDP pattern by hand with NCCL on a second stream; legacy against per-thread default stream. `cuda/compile_all.sh` runs inside the container; `cuda/out/`: build and run logs (each run stops with error 35, no driver), ptxas reports and SASS of the graph kernels for sm_90a and sm_100a, PTX, the runtime symbols each default-stream mode calls, header excerpts (graph node types, conditional types, capture modes, update results, NCCL API and config fields), and which `NCCL_*` variables the library contains.
- `torch/ddp_overlap.py` (+ `run3.sh`): real DDP on 2 CPU processes with Gloo, comm-hook timestamps per bucket, overlap against `no_sync()` plus serial all-reduces, 3 runs. `torch/ddp_profile.py`: torch.profiler events of one DDP step. `torch/mps_launch.py`: eager PyTorch on MPS, sync each against sync once. `torch/extract_source.py`: DDP bucket defaults, Inductor CUDA-graph knobs and skip reasons, `make_graphed_callables` defaults, read from the installed PyTorch 2.14.1. Outputs in `torch/out/`.
- `m1/metal_launch.py`: 200 dependent kernels on the M1 Pro GPU four ways (wait each, queued, one command buffer, indirect command buffer replay); `m1/metal_concurrency.py`: 8 one-threadgroup kernels on one queue, eight queues, one concurrent encoder; `m1/run3.sh` runs both and the MPS script 3 times. Outputs in `m1/out/`.
- `inputs/`: excerpts kept as evidence (Megatron-LM's CUDA_DEVICE_MAX_CONNECTIONS comments, DeepEP's README on dropping NVSHMEM, DeepSeek-V3's 20-of-132-SMs sentences).
- `recompute.py`: parses every raw output, medians, the launch model fitted to NVIDIA's 2019 figures, the copy-pipeline model and the training-step model; writes `out/data.json` and `parts/22_js_sg_data.js` (window.SG). `fill_sgv.py` writes data values into every `data-sgv` element of the Reading parts; `check_embed.py` verifies the page embeds exactly `out/data.json`, the 79 tagged values match, and nothing private leaks. `check/check_page.mjs`: puppeteer, every control (closed blocks opened) at 390 px dark and 920 px light, no animation moves before the reader acts, the page's step model against the Python one, the launch model against NVIDIA's figures, animation end states. `ledger.json`: the knowledge ledger (`python3 html_utils/ledger.py check`).
- `viz_ideas.md`: visuals built and rejected. `coverage.json`: the root's and siblings' claims this page had to reconcile (no old page existed).

Shape: `.claude/skills/explainer-page/page-kinds/topic-child.md`. Departures: no `live.md` (a new page, no old Notion text).
