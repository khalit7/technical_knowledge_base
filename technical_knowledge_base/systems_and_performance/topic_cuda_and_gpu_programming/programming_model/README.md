# The CUDA programming model: threads, warps, blocks, launches, occupancy

Notion: https://app.notion.com/p/3c65c17b0d0d8162865eec15d9dae87e (child of Topic: cuda-and-gpu-programming)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). How you tell a GPU what to run, taught from zero around one running example (scaling and row-summing a 4,096 x 4,096 matrix of attention scores): a complete CUDA program with its real SASS, indexing and which threads form a warp (interactive), warp-level functions and the compiler's own warp-aggregated atomics, synchronisation from a warp to the whole grid (a race animated with and without `__syncthreads`, measured on a real GPU, and how `grid.sync()` is built), launch configuration, `__launch_bounds__` against spills on four targets, occupancy and waves (NVIDIA's A100 example animated, a measured staircase), the error model with real error output, the memory API, what a launch costs, the same kernels from Numba, CuPy and PyTorch extensions, and the Metal equivalents. Tabs: Reading, Launch planner (occupancy, limiter, suggested block size and waves for the page's real kernels on A100, H100, B200 and RTX 5090, checked against NVIDIA's `cuda_occupancy.h` on 1,155 of 1,155 values), Further reading. No NVIDIA GPU was available: NVIDIA facts come from real compiler output (CUDA 13.4.2) and programs run without a GPU, documentation and published measurements; measurements are on the Apple M1 Pro GPU and labelled. Rebuilds the old written page (verbatim in `src/live.md`, 37 facts accounted for in `src/coverage.json`); no child pages, databases or video.
