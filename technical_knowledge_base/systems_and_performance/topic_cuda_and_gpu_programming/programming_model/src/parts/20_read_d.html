2. How each thread finds its data: indexing

The problem. All threads run the same code, so the only thing that makes thread 77,000 different from thread 3 is a handful of read-only built-in variables. Turning them into "my element" is the first thing every kernel does.

Limits from the {{CUDA Programming Guide, Table 30|https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/compute-capabilities.html}} (v13.4.2, updated Sep 10, 2026), identical for every compute capability it lists. Shapes are dim3 values: dim3 block(32, 8) is 32 × 8 = 256 threads.

Three patterns cover almost every kernel

// 1 one thread per element (the host launches ceil(n / block) blocks)
int i = blockIdx.x * blockDim.x + threadIdx.x;
if (i < n) y[i] = a * x[i];

// 2 grid-stride loop: any grid size covers any n
for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += gridDim.x * blockDim.x)
  y[i] = a * x[i];

// 3 a 2D grid over a matrix: x walks columns, so neighbouring threads touch neighbouring addresses
int c = blockIdx.x * blockDim.x + threadIdx.x, r = blockIdx.y * blockDim.y + threadIdx.y;
if (r < rows && c < cols) y[r * cols + c] = a * x[r * cols + c];
// host: dim3 block(32, 8); dim3 grid((cols + 31) / 32, (rows + 7) / 8);

All three are in src/cuda/kernels/p1_index.cu and compile for all four targets. On sm_90a, ptxas gives the one-per-element and 2D kernels 10 registers per thread and the grid-stride kernel 14 (it carries the loop) compiled here. For the running example, the 4,096 × 4,096 scores take pattern 3 with a 128 by 512 grid of 32 × 8 blocks, or pattern 1 on the flattened 16,777,216 elements: for an elementwise step the shape does not matter as long as consecutive threads touch consecutive addresses.

Why the grid-stride loop is worth knowing. The grid size no longer depends on n: you can launch exactly as many blocks as fit on the GPU at once and let each thread do several elements (a persistent grid), run with one block of one thread to debug serially, and let per-thread setup (loading a constant, computing a base pointer) happen once per thread instead of once per element. Mark Harris's {{"CUDA Pro Tip: Write Flexible Kernels with Grid-Stride Loops"|https://developer.nvidia.com/blog/cuda-pro-tip-write-flexible-kernels-grid-stride-loops/}} (NVIDIA, 2013) is the classic reference published. It does not remove the tail effect of section 5: the last iteration is still uneven.

Integer overflow. int stops at 231−1 = 2,147,483,647. A tensor of 16 × 32 × 4,096 × 4,096 attention scores has 8,589,934,592 elements, so blockIdx.x * blockDim.x + threadIdx.x computed in int wraps around silently derived. Use 64-bit arithmetic ((long long)blockIdx.x * blockDim.x, or size_t) whenever an index can pass two billion.

Which threads form a warp

The hardware groups a block's threads into warps of 32 by a single linear thread id: "the first index x moves the fastest, followed by y and then z", and "each warp contains threads of consecutive, increasing thread IDs with the first warp containing thread 0" ({{Programming Guide 2.3.2|https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html}}; {{3.2, Hardware Implementation|https://docs.nvidia.com/cuda/cuda-programming-guide/03-advanced/advanced-kernel-programming.html}}). So the linear id is x + y·Dx + z·Dx·Dy, and warp w holds linear ids 32w to 32w+31. The block's shape therefore decides which matrix elements one warp touches together. Each cell is one thread of the block placed on the matrix element it handles (columns across, rows down), coloured by warp. Click a cell to see that thread's numbers. Sectors: the 32-byte pieces of memory one warp's load touches, if the rows start 32-byte aligned and are more than a block wide derived: rows touched × ceil(columns per row × 4 B / 32 B).

32 × 8, 16 × 16 and 8 × 32 all touch 4 sectors per warp load, every byte used; narrower than 8 columns, sectors are half empty and the same load costs 8, then 32 sectors. Why sectors are the unit, and what it costs, is the subject of {{GPU memory hierarchy|n:3c65c17b0d0d814a8edef7bd21c303d3}} (coalescing). The rule to keep: make threadIdx.x walk the contiguous dimension.
