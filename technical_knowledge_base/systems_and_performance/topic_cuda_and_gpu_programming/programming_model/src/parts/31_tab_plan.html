Launch planner

Pick a GPU and a kernel, then a block size and a problem size: the planner shows how many blocks fit on one SM and which resource stops more from fitting, the occupancy for every block size, the block size CUDA's occupancy API would suggest, and how many waves the grid needs. The presets are this page's kernels with their real ptxas -v reports (CUDA 13.4.2) compiled here; "Custom" lets you type your own.

How the numbers are computed, and checked
Blocks per SM follow NVIDIA's cuda_occupancy.h (CUDA 13.4.2), ported line by line: registers are allocated per warp in units of 256 and split over 4 SM sub-partitions; each block uses its shared memory plus 1 KB reserved by the system, rounded up to 128 bytes, against the SM's maximum carveout; plus the warp limit, the block-slot limit and the barrier limit; per-SM limits from the {{CUDA Programming Guide, Tables 30 and 31|https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/compute-capabilities.html}}. The suggested block size follows cudaOccMaxPotentialOccupancyBlockSize: from 1,024 down, the first block size reaching the highest number of resident threads. For the presets, the header itself was compiled and run without a GPU: it agrees with this page on . Waves = ceil(grid / (SMs × blocks per SM)) derived; they assume every block takes the same time. SM counts: A100 108, H100 SXM 132 (NVIDIA architecture blogs), B200 148 (independent measurement paper, arXiv 2512.02189), RTX 5090 170 (NVIDIA whitepaper). Occupancy is not speed: see section 5 of the Reading tab.
