1. A complete CUDA program, line by line

The problem. The CPU (the host) and the GPU (the device) have separate memories and run separate code. A CUDA program is ordinary C++ for the host plus functions marked to run on the device, and it must move data across, start the work, wait for it and move results back. Here is the whole of it for the elementwise step, y = a * x on a million floats. It is a real file, compiled here with nvcc for sm_90a (H100) compiled here.

__global__ void scale(const float* x, float* y, float a, int n) {   // runs on the GPU
  int i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < n) y[i] = a * x[i];
}
int main() {
  const int n = 1 << 20;                                 // 1,048,576 elements
  std::vector<float> hx(n), hy(n);                       // host arrays
  float *dx, *dy;                                        // device pointers: not usable on the CPU
  CUDA_CHECK(cudaMalloc(&dx, n * sizeof(float)));        // 1 allocate GPU memory
  CUDA_CHECK(cudaMalloc(&dy, n * sizeof(float)));
  CUDA_CHECK(cudaMemcpy(dx, hx.data(), n * sizeof(float), cudaMemcpyHostToDevice));  // 2 copy in
  int block = 256, grid = (n + block - 1) / block;       // 3 choose the launch: 4,096 blocks of 256
  scale<<<grid, block>>>(dx, dy, 2.0f, n);               // 4 launch (returns at once)
  CUDA_CHECK(cudaGetLastError());                        //   was the launch itself valid?
  CUDA_CHECK(cudaMemcpy(hy.data(), dy, n * sizeof(float), cudaMemcpyDeviceToHost));  // 5 copy out (waits)
  // 6 compare hy with 2 * hx on the CPU;  7 cudaFree(dx); cudaFree(dy);
}

Full source with the CUDA_CHECK macro and the CPU check: src/cuda/host/first_program.cu. Compiled with exit code 0; run in the container, which has no GPU or driver, it stopped at its first CUDA call (line 19, the first cudaMalloc) with CUDA driver version is insufficient for CUDA runtime version, exactly as the error check is meant to. Compiling needs no GPU; running does.

The three function markers. __global__ marks a kernel: it runs on the device and is launched from the host (it returns void; results go through pointers). __device__ marks a helper that runs on the device and is called only from device code. __host__ __device__ compiles a function for both sides, the usual way to share small maths (the {{CUDA Programming Guide, section 2.1|https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/intro-to-cuda-cpp.html}} vendor doc). nvcc splits the file: host code goes to the normal C++ compiler, device code to NVIDIA's compiler, and the device machine code is embedded in the executable ({{The compiler stack|n:3f05c17b0d0d81ddbc00fac9e8a2ff89}} has the details).

The launch. scale<<<grid, block>>>(...) is the execution configuration: grid blocks of block threads each, here 4,096 × 256 = 1,048,576 threads, one per element. Two more optional arguments follow: bytes of dynamic shared memory per block and the stream to queue on, <<<grid, block, smemBytes, stream>>>. "Kernel launches are asynchronous with respect to the host thread" (Programming Guide, 2.1.4): the call queues the work and returns. That is why step 5 is where the program waits: "The cudaMemcpy API is synchronous. That is, it does not return until the copy has completed" (2.1.3.2), and a copy queued after the kernel on the same stream starts only after the kernel ends.

What the GPU actually runs. Below is the real SASS (the GPU's machine code) ptxas produced for scale on sm_90a, the whole kernel. Read it once: it shows that the "thread index" is just two special registers and one multiply-add.



S2R R0, SR_TID.X and S2UR UR4, SR_CTAID.X read threadIdx.x and blockIdx.x from special registers; LDC R7, c[0x0][RZ] loads blockDim.x from the constant bank where the launch put it; IMAD is the index; ISETP and @P0 EXIT are the bounds check (threads past n simply exit); c[0x0][0x210] and up are the kernel's arguments, also delivered in the constant bank; LDG, FMUL, STG are the load, multiply and store. Each instruction is issued once per warp of 32 threads. compiled here


Predict: n = 1,000,000 and block = 256. How many threads does the launch start, and how many do no work?




grid = ceil(1,000,000 / 256) = 3,907 blocks, so 3,907 × 256 = 1,000,192 threads derived. The last 192 fail i < n and exit at once. Without that check they would read and write past the end of the arrays: the classic first-kernel bug (section 6).
