The idea in one screen

You write the code of one thread; a launch runs it on a grid of blocks, each block split into warps of 32 threads that issue together. Each thread computes its own index to find its data; threads cooperate only inside a warp or a block; and the GPU places as many blocks on each SM as registers and shared memory allow (occupancy), running the rest in waves.

One launch, unpacked: every level has its own way to cooperate and its own place on the chip

The running example's launch scale<<<4096, 256>>>: a grid of 4,096 blocks, each block 256 threads = 8 warps, each warp 32 lanes. The thread highlighted in blue is blockIdx.x 9, threadIdx.x 37 (warp 1, lane 5), so its element is i = 9 × 256 + 37 = 2,341 derived. Under each level: how its threads talk, and where it runs.

You need: nothing beyond C or Python and the idea of a matrix in memory. What an SM physically contains and why a GPU needs thousands of threads to hide latency are on {{GPU architecture|n:3c65c17b0d0d810682aae39bd614ec64}} (sections 2 and 3); this page is how you program it.

Host, device
the CPU with its memory; the GPU with its own memory.
Kernel
a __global__ function: runs on the device, launched from the host.
Grid, block, thread
a launch is a grid of blocks; a block (up to 1,024 threads) runs on one SM and its threads can share memory and wait for each other.
Warp, lane
32 consecutive threads of a block, issued as one instruction; a lane is a thread's position (0 to 31) in its warp.
SM
streaming multiprocessor, the GPU's core: 108 on an A100, 132 on an H100.
Occupancy
warps resident on an SM divided by the most it can hold.
Wave
one round of blocks filling every SM; a grid needs ceil(blocks / (SMs × blocks per SM)) of them.

The running example. Attention scores s, a 4,096 by 4,096 float32 matrix, need an elementwise step (scale every score, e = a * s) and a reduction (the sum of each row) on the way to a softmax. The elementwise step teaches launches and indexing; the reduction forces threads to cooperate, which teaches warps, shared memory, barriers and atomics. The parent, {{Topic: cuda-and-gpu-programming|n:3c65c17b0d0d81c39f34d5e070d783c1}}, follows the whole softmax and attention from PyTorch down to the instructions; this page owns the model underneath.
