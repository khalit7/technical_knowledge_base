5. NVRTC: compiling while the program runs

Sometimes the kernel does not exist until the program runs: its shapes, data types or the operation itself are only known then. NVRTC is NVIDIA's library for that case: "It accepts CUDA C++ source code in character string form and creates handles that can be used to obtain the GPU executable code", without spawning nvcc or needing it installed ({{NVRTC 13.4 documentation|https://docs.nvidia.com/cuda/nvrtc/index.html}}) documented. Ask for --gpu-architecture=sm_90a and you get a cubin; ask for compute_90a and you get PTX for the driver to finish. You then load the result with the driver API (cuModuleLoadData or cuLibraryLoadData) and launch it; that last part needs a GPU and is not run here.

Who uses it: PyTorch's jiterator (torch.cuda.jiterator) inlines your elementwise expression into a kernel template and compiles it through NVRTC ({{aten/src/ATen/native/cuda/jit_utils.cpp|https://github.com/pytorch/pytorch/blob/v2.14.0/aten/src/ATen/native/cuda/jit_utils.cpp}}); CuPy's RawKernel uses NVRTC by default and caches binaries under $HOME/.cupy/kernel_cache/ ({{CuPy RawKernel|https://docs.cupy.dev/en/stable/reference/generated/cupy.RawKernel.html}}). Triton does not: it writes PTX itself and runs the ptxas binary it ships.

6. Inline PTX: naming one exact instruction from C++


asm("instruction %0, %1;" : "=r"(out) : "r"(in)); puts one PTX instruction into CUDA C++. The constraint letters give the operand's register type: h .u16, r .u32, l .u64, q .u128, f .f32, d .f64; n is an immediate integer and "=" marks an output. asm volatile stops the compiler deleting or moving it, and a "memory" clobber stops it moving memory accesses across it ({{Inline PTX Assembly in CUDA|https://docs.nvidia.com/cuda/inline-ptx-assembly/index.html}}) documented. You need it for three things: instructions CUDA C++ has no function for (wgmma and tcgen05, which is why the parent page's Hopper and Blackwell kernels are mostly asm), registers it cannot name, and forcing one variant of an instruction. The hardware has one fast exponential, MUFU.EX2 (2x on the special function unit). expf wraps it in a careful range reduction so the result is accurate to 2 ulp (units in the last place); __expf multiplies by log2e and calls it, with three extra instructions that keep tiny results out of the denormal range, and its error grows with the input: 2 + floor(|1.173 x|) ulp ({{CUDA Programming Guide, mathematical functions|https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/mathematical-functions.html}}) documented; inline ex2.approx.ftz drops even those; -use_fast_math turns every expf in the file into the shortest form. FlashAttention-style kernels use the fast form on purpose and fold log2e into the softmax scale, so the multiply disappears too.
