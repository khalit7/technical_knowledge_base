The idea in one screen

Every road to an NVIDIA GPU ends the same way: PTX, assembled by ptxas into SASS for one GPU generation. The compilers above it differ only in what they capture (one hand-written kernel, or a whole traced graph) and what they decide on the way down (which operations share a kernel, how a tile is split over threads); ptxas then decides registers and instruction order, and the driver decides which image in the binary runs.

What is real here
Every listing, error message, file size and log was produced by the real tools: CUDA 13.4.2 (nvcc, ptxas, cuobjdump, nvdisasm, NVRTC, tileiras) and torch 2.14.1 with Triton 3.8.0, in the Docker image kb-gpu-lab:1 on an Apple M1 Pro laptop. There is no NVIDIA GPU, so nothing here ran on one: compiling needs no GPU, running does. torch.compile ran on the CPU, where Inductor writes C++; its GPU code (Triton) was generated without a device by the method of the {{Triton and Gluon|n:3c65c17b0d0d81729d15ed4d1a4461b3}} page. SASS: the machine code one GPU generation executes.
PTX: a virtual, documented assembly language for an idealised GPU.
ptxas: the assembler, really an optimising compiler, from PTX to SASS.
cubin: an ELF file holding SASS; a fat binary holds several cubins and PTX images.
compute capability (CC): a GPU's instruction-set version, 9.0 for the H100.
fusion: putting several operations in one kernel, so intermediates never go to memory.
FX graph, guard, graph break: what torch.compile captures, when it may reuse it, and where capture stopped (section 8).
Why an ML engineer needs this
  • "no kernel image is available for execution on the device", a slow first step on a new GPU, a wheel that will not load on a B300: all are about which images a binary carries and what the driver does with them (section 5).
  • Is my kernel using tensor cores, vector loads, no spills? Only the SASS answers that; PTX can mislead, because ptxas rewrites a lot (sections 3 and 4).
  • Why did torch.compile or XLA make one kernel here and two there? Fusion decisions, and where capture stopped (sections 1 and 8).
