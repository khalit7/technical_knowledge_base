# Topic: cuda-and-gpu-programming

Notion: https://app.notion.com/p/3c65c17b0d0d81c39f34d5e070d783c1
Site: https://khalit7.github.io/technical_knowledge_base/systems_and_performance/topic_cuda_and_gpu_programming/

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; `src/README.md` records the 2026-10-23 rebuild). The map of the topic, following one operation (softmax of attention scores, then a multiply by V) from PyTorch down to the instructions: one call from dispatch to execution, every optimisation lever with the limit it attacks and the child that owns it, the thread model and memory ladder as definitions, the running example unfused and fused, five ways to get a kernel, tensor cores by generation, compiling, profiling and checking, other GPUs, and the eight children in reading order. Tabs: Reading (`src/read/`), GPU simulator (`src/sim/`: divergence, occupancy validated against NVIDIA's cuda_occupancy.h, latency hiding), Compiler explorer (`src/compile/`: real CUDA 13.4.2 and Triton 3.8.0 output, PTX and SASS for sm_80, sm_90a, sm_100a and sm_120, built in a Docker image without a GPU; raw cubins and dumps are git-ignored and regenerated by `run_all.sh`), Kernel lab (`src/lab/`: softmax fused into a matmul and attention, as Metal kernels timed on the Apple M1 Pro GPU and as Triton kernels checked with the interpreter; the softmax and matmul ladders it also ran are taught on Writing kernels), Further reading.
No NVIDIA GPU was available: measurements are on the Apple M1 Pro GPU and labelled; NVIDIA behaviour is from compiler output, documentation and published measurements, each labelled. The old written root and its six children are saved verbatim in `src/read/old/` and checked in `src/read/coverage.md`.
