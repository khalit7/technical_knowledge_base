8. FP8 and FP4: the low-precision paths

What the formats are (E4M3, E5M2, E2M1, the MX and NVFP4 block formats) and how much each generation's tensor cores gain from them is on {{Topic: hardware|n:3c65c17b0d0d8118beeefaed56da6f8e}} (numeric formats) and {{numerical computing|n:3f05c17b0d0d81d6af0be4a9a2edba8d}}. PyTorch notes in the same file that "cuBLAS only started supporting row-wise scaling in version 12.9, and only for compute capability 9.0+. In other cases we use CUTLASS."

Why the block recipe exists: DeepSeek-V3 trained in FP8 on H800s with activations scaled per 1 × 128 tile ("per token per 128 channels") and weights per 128 × 128 block, and found that "the accumulation precision of FP8 GEMM on NVIDIA H800 GPUs is limited to retaining around 14 bits"; with K = 4,096 that gave "a maximum relative error of nearly 2%" in their test. Their fix: every NC = 128 elements of K, copy the tensor-core partial sums to FP32 registers and accumulate there ("promotion to CUDA Cores") ({{DeepSeek-V3 report, section 3.3|https://arxiv.org/html/2412.19437v2}}) independent. That is a mainloop change no library offered at the time, which is why it was a custom kernel ({{DeepGEMM|https://github.com/deepseek-ai/DeepGEMM}}) before it was a cuBLAS scale mode; the report itself is summarised on the {{DeepSeek-V3 paper page|n:3c65c17b0d0d815fb8dac9ba1e35ab81}}. Blackwell's block-scaled instructions move the per-block scaling into the tensor core itself.

Common mistakes

Treating column-major cuBLAS like row-major PyTorch
The call succeeds and computes the wrong thing (or the transpose). Compute YT = WTXT by swapping the operands, as in section 2; check against torch.matmul on small sizes first.
Shapes that defeat the heuristic
Dimensions not divisible by 8 (16 bytes of FP16/BF16) block the vectorised and TMA paths; a tile count just past a multiple of the SM count wastes a wave. Pad vocabulary and hidden sizes to multiples of 64 or 128; compare against a padded shape before blaming the library. On the M1, MLX's library GEMM loses 4.9% when N goes from 4,096 to 4,095 (median of 3 runs) measured on M1 Pro; the effect on NVIDIA GPUs, where alignment decides whether TMA and 16-byte vector paths are usable, is not measured here not run here. A decode-shaped GEMM (M = 8 rows) is a different problem altogether: it reads the 32 MiB weight matrix for almost no arithmetic, and the M1 library call streamed it at only 67.5 GB/s against the 146 to 163 GB/s that plain copies reach on the same GPU ({{GPU memory hierarchy|n:3c65c17b0d0d814a8edef7bd21c303d3}}).
Expecting a Hopper kernel to run on an RTX 5090 or a B200
wgmma code compiled for sm_90a runs only on compute capability 9.0. Check what a wheel contains with cuobjdump -lelf before renting a GPU for it.
Starving cuBLASLt of workspace
A small workspace removes split-K and some Stream-K algorithms from the heuristic's list without any error. When comparing libraries, give each the same workspace.
Timing the first call
cuDNN runtime-fusion plans and Triton or CuTe DSL kernels compile on first use; cuBLAS loads modules lazily. Warm up, then time (the method is on {{Profiling and correctness|n:3c65c17b0d0d813da895ffee55b0457c}}).
Trusting FP8 accumulation over a long K
Section 8: tensor-core FP8 accumulation on Hopper keeps about 14 bits; use libraries that promote partial sums to FP32 or test your kernel's error against an FP32 reference at the real K.

How to check what ran

  • Kernel names in Nsight Systems or torch.profiler: sm90_xmma_gemm_... (cuBLAS on Hopper), cutlass::... (CUTLASS inside a library), triton_... (Inductor), splitKreduce_kernel (cuBLAS chose split-K).
  • What a binary contains: cuobjdump -lelf (which architectures), cuobjdump -sass and a grep for HMMA, HGMMA, UTCHMMA, UTMALDG, as in this page's {{Instruction atlas|#t-atlas}}.
  • Which SDPA backend: force one with torch.nn.attention.sdpa_kernel and compare times and kernel names against the default.

Interview questions, with short answers

Why can't you just write a fast GEMM in CUDA in an afternoon?
Peak needs on-chip tiling with swizzled layouts, the generation's tensor-core instruction with its operand layouts, an asynchronous multi-stage pipeline, warp specialisation on Hopper/Blackwell, a schedule matched to the SM count, and a fused epilogue. Each changes per generation; cuBLAS ships 52,148 kernels in its Lt library alone.
What is the difference between cuBLAS and cuBLASLt?
Same kernels; Lt exposes descriptors, a ranked heuristic list, a workspace, epilogues (bias, ReLU, GELU and their gradients) and FP8/FP4 scale modes. PyTorch uses classic cuBLAS for mm by default and Lt for addmm with a 1-D bias and for scaled matmuls.
mma.sync vs wgmma vs tcgen05?
One warp, operands and accumulators in registers (Ampere on); four warps, async, operands from shared memory by descriptor, accumulators in registers (Hopper only); one thread, async, operands from shared memory, accumulators in tensor memory, optionally across two SMs (datacenter Blackwell). The RTX 5090 uses the first.
What does TMA buy over cp.async?
One instruction from one thread moves a whole multi-dimensional tile with hardware address generation, swizzling, out-of-bounds fill and byte-counted completion on an mbarrier, optionally multicast to a cluster; the other warps are free for math.
What is wave quantization and what fixes it?
Tiles run in waves of one per SM; a tile count just above a multiple of the SM count leaves the last wave mostly idle (108 vs 117 tiles on an A100 halves throughput in NVIDIA's example). Fixes: a different tile shape, split-K, Stream-K, or padding the problem.
What is a CuTe layout?
A shape and a stride, a function from coordinates to offsets with the leftmost mode fastest; composition, complement, divide and product build tiles, thread mappings, swizzled shared memory and instruction fragments from it.
Why did DeepSeek-V3 need a custom FP8 GEMM?
Per-128-element block scaling and FP32 promotion of tensor-core partial sums every 128 elements of K, because Hopper's FP8 accumulation keeps about 14 bits. That changes the mainloop, which no library exposed then.
