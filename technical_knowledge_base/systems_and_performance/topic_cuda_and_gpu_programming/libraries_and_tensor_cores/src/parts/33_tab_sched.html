GEMM scheduler: tiles, waves, split-K and Stream-K on real SM counts

Lay one GEMM's output tiles onto a GPU's SMs under four schedules (section 3 of the Reading tab explains them). The unit of work is one MAC-loop iteration: one K slice of 64 for one output tile; time is counted in iterations, so the chart shows how evenly the work is spread, not seconds. Partial-sum traffic is counted separately in bytes (FP32 partial tiles written and read back). It is a model derived: it ignores the epilogue, the fix-up's own time, memory bandwidth and clock differences, which real libraries also weigh. SM counts are vendor figures (A100 108, H100 SXM 132, B200 148, RTX 5090 170).

Each row is an SM, time runs left to right; colour is the output tile, so a tile split between SMs shows the same colour on two rows. Presets 1 and 2 reproduce NVIDIA's wave-quantization example by construction (108 and 117 tiles on an A100); the halving of throughput NVIDIA reports there is their measurement, not this model's.
