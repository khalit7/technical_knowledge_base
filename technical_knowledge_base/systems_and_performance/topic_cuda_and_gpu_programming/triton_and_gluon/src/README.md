# Triton and Gluon: sources, scripts, outputs

`sh build.sh` writes `../index.html` from `parts/`. `sh run_all.sh` reproduces every output (Docker and the `kb-gpu-lab:1` image from `../../src/compile/image/Dockerfile`; CUDA 13.4.2 tools, Triton 3.8.0, CPU PyTorch 2.14.1; image id `sha256:072ecc4d24a3...`). No NVIDIA or AMD GPU was used anywhere.

## Code (`code/`)
- `kernels_tg.py`: the page's Triton kernels (vector add, row softmax, tutorial-03 matmul, FlashAttention forward with causal option, a tensor-descriptor matmul with optional warp specialisation). Shown verbatim on the page.
- `interp_tg.py`: runs them with `TRITON_INTERPRET=1` on the CPU against PyTorch, plus two mistakes (non-power-of-two block, block shorter than the row) -> `out/interp.json`.
- `compile_tg.py`: `triton.compile` with an explicit `GPUTarget` for sm_80, sm_90a, sm_100a, sm_120, gfx942, gfx950; every stage to `out/ir/`, resource usage and instruction counts (cuobjdump) -> `out/compile.json`. `main`: the page's kernels, three vector-add specialisations, TMA matmuls. `sweep`: tutorial 03's 16 CUDA configurations, num_stages 1 to 6, num_warps 1 to 16 (4 GPUs), softmax BLOCK x num_warps (sm_90a).
- `gluon_tg.py`: Gluon tutorial 02's memcpy for R = 1 to 16 (sm_100a, sm_90a), Triton's own `to_linear_layout` for 8 layouts, a Gluon vector add -> `out/gluon.json`.
- `passes_tg.py`: `MLIR_ENABLE_DUMP=1` for the matmul (sm_90a, sm_80) and the vector add (sm_90a): every pass, whether it changed the IR, and the snapshots the page shows -> `out/passes.json`.
- `inductor_tg.py`: real Inductor output for two small graphs via `cpu_backend = "triton"` (a stand-in driver answers the target query; the kernels cannot execute without a Triton CPU back end) -> `out/inductor/`.
- `recompute.py`: the Python reference for every derived number (grouped ordering, the shared-memory rule, MMA counts per K step, occupancy, layout bases, causal fraction) -> `out/expected.json`; asserts the rule and the bases against the compiled and printed data.
- `build_data.py`: `out/` -> `parts/22_js_data.js` (`window.TGD`), with IR excerpts (layout lines plus the lines carrying the discussed operations; debug locations removed).

## Checks (`check/`)
- `check_embed.py`: the page embeds exactly today's data; 21 hand-written prose numbers agree with it.
- `check_js.mjs`: the page's JavaScript against `recompute.py`: occupancy 136/136, shared memory 88/88, layout bases 8/8 (equal to Triton's printed bases), grouped counts 162/162.
- `check_ui.mjs`: every control in every tab at 390 px dark and 920 px light; no errors, NaN, undefined or sideways scroll.

## Inputs
- `inputs/gluon_tutorial02_published.json`: the GB200 throughputs and the instruction table printed in Gluon tutorial 02 (v3.8.0), copied by hand.
- `inputs/triton_3.8.0_release_notes.md`: the release body from the GitHub API (2026-10-05).

## Departures from the child-page method
- No measured timings at all: Triton has no Metal back end and no NVIDIA GPU was available. The evidence is the interpreter (correctness) and real compiler output (what the code becomes), labelled "compiled here".
- One before/after animation per mechanism that replaced another (scalar against vector loads; row-major against grouped order); the pipeline and online-softmax animations already exist on siblings and are linked.

cubins, LLVM IR, SASS dumps, AMDGCN and the large PTX files in `out/ir/` (about 10 MB).
