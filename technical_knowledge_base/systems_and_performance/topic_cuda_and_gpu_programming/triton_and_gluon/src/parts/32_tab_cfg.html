What an autotuning configuration costs before it ever runs. Every configuration of Triton tutorial 03's matmul, and two sweeps, compiled for four NVIDIA GPUs: registers, spills, shared memory, whether it can launch, and how many programs fit on one SM.

Compiled with Triton 3.8.0 for FP16 inputs (the tutorial's last 8 configurations are labelled for FP8 inputs; compiled here with FP16, so their shared memory is twice an FP8 build's). Registers and stack from cuobjdump -res-usage; shared memory is Triton's metadata.shared, the number the launcher checks. Blocks per SM: NVIDIA's occupancy rules (cuda_occupancy.h, as ported and validated on the parent page) with the per-SM limits of the CUDA Programming Guide v13.4.2, Tables 30 and 31, and the 1 KB per block the system reserves; Blackwell's tensor memory (512 columns per SM, 128 used per program here) is not modelled. Nothing was timed: which configuration is fastest needs a GPU.
