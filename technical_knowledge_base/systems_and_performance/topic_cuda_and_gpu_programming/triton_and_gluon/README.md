# Triton and Gluon: block-level kernels, autotuning, what the compiler does

Notion: https://app.notion.com/p/3c65c17b0d0d81729d15ed4d1a4461b3 (child of Topic: cuda-and-gpu-programming)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Triton from zero for a PyTorch user who has never written a kernel: programs over blocks, the vector add (a before/after animation of one program's 1,024 elements through the compiler's layout passes, aligned against unaligned and n = 992 against n = 1,000), the fused softmax and the register cliff (28 compiles), the tutorial-03 matmul with grouped ordering (animation reproducing the tutorial's 90 against 54 tiles) and one `tl.dot` becoming six different tensor-core instructions (sm_80, sm_90a, sm_100a, sm_120, gfx942, gfx950), FlashAttention forward with causal masking, num_warps and num_stages (an exact shared-memory rule found from the compiled sizes), TMA tensor descriptors and warp specialisation, autotuning as implemented, every compiler stage and all 73 passes (MLIR dumps, before/after for accelerate-matmul and pipeline), layouts and linear layouts, real Inductor-generated Triton, Gluon (tutorial 02 recompiled), AMD and the CUDA Tile IR incubator (a correction), mistakes and interview questions. Tabs: Reading, Compiler stages (4 kernels x 6 GPUs x 6 stages), Config explorer (tutorial 03's configurations and sweeps: registers, spills, shared memory, launchability, occupancy), Layout explorer (any blocked layout, checked against Triton's own `to_linear_layout`), Further reading. Rebuilds the old written page "Triton" (saved in `src/live.md`, mapped in `src/coverage.json`); no child pages, databases or video. No GPU was used: kernels are checked with Triton 3.8.0's interpreter and compiled without a device in the `kb-gpu-lab:1` image.
