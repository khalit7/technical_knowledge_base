# Compiler explorer tab (t-compile): sources, scripts, outputs

Everything here is real compiler output. Nothing was run on an NVIDIA GPU (none was available): compiling needs no GPU.

- `image/Dockerfile`: the `kb-gpu-lab:1` image (CUDA toolkit for Linux arm64/sbsa from `nvidia/cuda:*-devel-ubuntu24.04`, plus CPU PyTorch and Triton in a venv). Versions and the image digest are in `out/versions.json`.
- `kernels/*.cu`: the CUDA C++ ladder (vector add, naive and tiled matmul, warp-shuffle reduction, row softmax, WMMA, FP8 `mma.sync`, Hopper `wgmma`, Blackwell `tcgen05`, TMA plus cluster, and the register-pressure ladder).
- `triton/kernels_tl.py`: the same operations in Triton; `triton/compile_triton.py` compiles them for each target without a GPU; `triton/interp_check.py` runs them on the CPU with `TRITON_INTERPRET=1` against PyTorch.
- `occ/occ_check.cpp`: NVIDIA's own occupancy calculator (`cuda_occupancy.h`, host-only) evaluated for every kernel x target x block size, to validate the page's occupancy function (`occ/occ.py` is the Python reference the page's JavaScript was ported from).
- `compile_all.sh`: runs inside the container; writes `out/`.
- `build_data.py` (+ `parse_lib.py`): turns `out/` into `../parts/32_js_cmp_0data.js` (the only data the page embeds) and checks it.
- `run_all.sh`: reproduces everything (needs Docker and the image).
- `check_embed.py`: confirms the built page embeds exactly the recorded outputs and that numbers in the prose match the data.
- `viz_ideas.md`: visual ideas built and rejected.

Not committed (see `.gitignore`, about 25 MB, regenerated by `run_all.sh`): cubins, the fat-binary object, `cuobjdump -sass` dumps (the committed `*.sassline.txt` from `nvdisasm -gi` hold the same instructions with source lines), Triton's LLVM IR, and the PTX and SASS of the register-pressure ladder `k10_spill` (its ptxas reports are committed; its numbers are in the page data).
Findings recorded here: FP8 `mma.sync` is native (QMMA) only on sm_120 and emulated (F2FP + 2 HMMA) on sm_90a and sm_100a; wgmma compiles only for sm_90a, tcgen05 only for sm_100a; TMA plus clusters compile for sm_90a, sm_100a and sm_120; Triton's `tl.dot` on FP32 uses TF32 tensor cores by default; Triton chose HMMA / HGMMA / UTCHMMA per target for the same source; the page's occupancy function agrees with NVIDIA's `cuda_occupancy.h` on all 1,988 cases.
