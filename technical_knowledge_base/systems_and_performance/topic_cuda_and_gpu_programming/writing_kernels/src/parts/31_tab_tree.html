Reduce and scan, animated

One input of 16 numbers, six ways to combine them on a toy GPU: warps of 4 lanes (a real warp has 32) and shared memory with 4 banks (a real GPU has 32), so every effect fits on a phone screen at the same proportions. Pick a method; each step shows which threads work (arrows from the value they read to the value they write), which lanes of an issued warp sit idle, and how many shared-memory transactions the step costs. Then switch method and play the same input again.

Try: play Interleaved (R1) and watch the idle lanes counter climb: whole warps issue for one working lane. Switch to Strided (R2): no idle lanes, but the worst bank conflict becomes 4-way. Sequential (R3) fixes both. Warp shuffle needs one barrier instead of four. Then the scans: Hillis-Steele does 49 additions where Blelloch does 30, in half the steps.

All six on the same input

Totals over all steps. Additions: useful adds. Active lanes: lane-steps doing work. Idle lanes: lanes of issued warps with nothing to do (divergence). Barriers: __syncthreads() after each shared-memory step. Shuffles: warp shuffle instructions. Shared-memory transactions: per warp and per access (read source, read destination, write destination), the largest number of distinct addresses in one bank, summed; a value above the number of warp requests means bank conflicts. The counts come from the page's model, checked against an independent Python implementation (src/tree_model.py). The reductions end with the sum, 48, in element 0; Hillis-Steele with the inclusive scan; Blelloch with the exclusive scan (shifted by one, starting at 0). Section 1 and 2 of the Reading tab measure the real kernels.
