# GPU memory hierarchy: coalescing, shared memory, bank conflicts, registers and spills

Notion: https://app.notion.com/p/3c65c17b0d0d814a8edef7bd21c303d3 (child of Topic: cuda-and-gpu-programming)
Site: https://khalit7.github.io/technical_knowledge_base/systems_and_performance/topic_cuda_and_gpu_programming/memory_hierarchy/

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Rebuilt 2026-10-23 to the teaching contract. The programmer's side of GPU memory, opening with the core idea and a hero ladder of the memory spaces: 1 global loads as 32-byte sectors (a pattern widget with the M1 stride measurements, and a before/after animation of one warp's load: AoS/SoA, misaligned/aligned, 4-byte/16-byte), 2 L1, L2, the read-only path and launch order for L2 reuse, 3 tiling through shared memory (before/after animation), declaring and sizing it, 4 banks (a bank widget with plain, padded and XOR layouts), wide accesses and swizzles, 5 registers, a register-cap sweep and arrays that fall into local memory, 6 constant memory, 7 asynchronous copies (LDGSTS compiled, a 1-to-4-stage pipeline animation), 8 pinned, mapped and managed host memory, 9 judging one kernel; depth (cache operators, L2 persistence, the M1 roofline with placed kernels and a calculator, interview rehearsal) in closed blocks. Tabs: Reading, Memory instructions (every kernel's ptxas report and memory instructions), Further reading. No child pages, databases or video. No NVIDIA GPU was available: NVIDIA evidence is real CUDA 13.4.2 compiler output and NVIDIA's documentation; measurements are the M1 Pro's, labelled.
