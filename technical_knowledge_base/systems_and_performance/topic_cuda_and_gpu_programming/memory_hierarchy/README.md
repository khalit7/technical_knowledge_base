Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Rebuilt 2026-10-23 to the teaching contract; split layout and five 3D stages 2026-11-10. The programmer's side of GPU memory, opening with the core idea and a 3D hero ladder of the memory spaces (Fig. 1): 1 global loads as 32-byte sectors (Fig. 2, one warp's load in 3D: coalesced, struct field, misaligned, float4, random gather; a pattern widget with the M1 stride measurements), 2 L1, L2, the read-only path and launch order for L2 reuse, 3 tiling through shared memory (Fig. 3, 3D), declaring and sizing it, 4 banks (Fig. 4, conflicts as towers in 3D; a bank widget with plain, padded and XOR layouts), wide accesses and swizzles, 5 registers, a register-cap sweep and arrays that fall into local memory, 6 constant memory, 7 asynchronous copies (LDGSTS compiled; Fig. 5, 1 to 4 stages in 3D, and a timeline widget), 8 pinned, mapped and managed host memory, 9 judging one kernel; depth (cache operators, L2 persistence, the M1 roofline with placed kernels and a calculator, interview rehearsal) in closed blocks. Tabs: Reading, Memory instructions (every kernel's ptxas report and memory instructions), Further reading. No child pages, databases or video. No NVIDIA GPU was available: NVIDIA evidence is real CUDA 13.4.2 compiler output and NVIDIA's documentation; measurements are the M1 Pro's, labelled.
