CUDA Programming Guide v13.4.2 (pages "Last updated on Sep 10, 2026"), https://docs.nvidia.com/cuda/cuda-programming-guide/
- 02-basics/writing-cuda-kernels.html 2.3.4.1: "Global memory is accessed via 32-byte memory transactions. When a CUDA thread requests a word of data from global memory, the relevant warp coalesces the memory requests from all the threads in that warp into the number of memory transactions necessary to satisfy the request"
- same, 2.3.4.2: "Shared memory has 32 banks that are organized such that successive 32-bit words map to successive banks. Each bank has a bandwidth of 32 bits per clock cycle."
- same, 2.3.3.4: "Arrays for which it cannot determine that they are indexed with constant quantities, Large structures or arrays that would consume too much register space, Any variable if the kernel uses more registers than available, that is register spilling." / "local memory is organized such that consecutive 32-bit words are accessed by consecutive thread IDs. Accesses are therefore fully coalesced as long as all threads in a warp access the same relative address"
- same, 2.3.3.5: "Constant memory is small relative to other memories, typically 64KB per device."
- 03-advanced/advanced-kernel-programming.html: "Kernels relying on shared memory allocations over 48 KB per block are architecture-specific. As such they must use dynamic shared memory rather than statically-sized arrays and require an explicit opt-in using cudaFuncSetAttribute" / "for devices of compute capability 12.0, which have a maximum shared memory capacity of 100KB, setting the carveout to 50% will result in 64KB of shared memory, not 50KB, because devices of compute capability 12.0 support shared memory sizes of 0, 8, 16, 32, 64, and 100."
- 04-special-topics/async-copies.html 4.12.1: "Copying 4 or 8 bytes always happens in the so called L1 ACCESS mode, in which case data is also cached in the L1, while copying 16-bytes enables the L1 BYPASS mode, in which case the L1 is not polluted." / "This not only reduces register usage by copying the data directly to shared memory, but also ensures all loads from global memory are in-flight."
- same, TMA swizzle: "each set of eight threads loads a row from the shared memory buffer and stores it to a column ... This results in an eight-way bank conflict when storing." / "the TMA engine can be instructed to 'swizzle' the data before storing it in shared memory" / "each matrix element is from a different bank for both the rows and columns"
- 04-special-topics/l2-cache-control.html: "A portion of the L2 cache can be set aside to be used for persisting data accesses to global memory." / "When the GPU is configured in Multi-Instance GPU (MIG) mode, the L2 cache set-aside functionality is disabled."
- 02-basics/understanding-memory.html 2.6.3: "Page-locked host memory is required for asynchronous copies between the CPU and GPU. Page-locked host memory also improves performance of synchronous copies."
- 05-appendices/cpp-language-extensions.html: "Accesses to __global__ function const pointers marked with __restrict__ are compiled as read-only cache loads, similar to the PTX ld.global.nc or __ldg() low-level load and store functions instructions." / "The function __ldg() performs a read-only L1/Tex cache load." / launch bounds: "If both minBlocksPerMultiprocessor and maxThreadsPerBlock are specified, the compiler may increase register usage up to L in order to reduce the number of instructions and better hide the latency of single-threaded instructions."

- 10.2.5: texture cache "optimized for 2D spatial locality"
- 10.2.6: "There is a total of 64 KB constant memory on a device. ... - 10.2.7: "there is no register-related reason to pack data into vector data types such as float4 or int4 types."
