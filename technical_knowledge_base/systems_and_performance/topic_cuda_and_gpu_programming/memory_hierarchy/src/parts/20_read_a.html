The core idea. A kernel is fast when the bytes it needs are already close to the arithmetic: fetch each byte from DRAM once, in whole 32-byte sectors, and reuse it from shared memory and registers as many times as the math needs.

Every byte comes up the same ladder; your code decides how often it climbs

Three questions for every array in a kernel
Where does it live (which rung)? How many times is each byte read (once: stream it; many times: stage it on chip)? In what order do neighbouring threads touch it (neighbours on neighbouring addresses, or not)? Sections 1 to 8 answer them for one space each; section 9 turns them into a verdict on one kernel.

New terms

sector
the 32 bytes DRAM and the caches move at a time; four make a 128-byte cache line
coalesced
a warp's 32 addresses fall in as few sectors as possible, so bytes fetched equal bytes used
tile
a block of a matrix staged in shared memory so every thread of the block can reuse it
bank, bank conflict
shared memory is 32 banks of 4 bytes; two lanes needing different words of one bank take turns
spill, local memory
values or arrays the compiler cannot keep in registers, parked in per-thread DRAM
stage
one extra shared-memory buffer, so the next tile's copy runs during this tile's math
swizzle
a permuted shared-memory layout (column XOR row) that avoids bank conflicts without padding
TMA
Hopper's Tensor Memory Accelerator: one thread starts a copy of a whole tile into shared memory
