Access lab: count what one warp's access costs

Type any access pattern and see what NVIDIA's documented rules make of it. Global memory: 32-byte sectors per warp-wide load ({{Programming Guide 2.3.4.1|https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html}}). Shared memory: 32 banks of 4 bytes, one distinct word per bank per pass, same word broadcast (2.3.4.2). Both models are checked against a Python reference on 1,000 patterns (src/check/check_js.mjs). They count transactions, not time: caches, other warps and DRAM pages decide how much a wasted sector costs, as the {{Reading|#t-read}} tab's M1 measurements show.

Each box is one distinct word a bank must deliver, stacked by pass: blue boxes fit within the ideal number of passes, orange ones are extra. For 8- and 16-byte elements the pass count is the floor that the 32-bit rule implies (each bank delivers 4 bytes per pass, so 32 lanes × 16 bytes need at least 4 passes). NVIDIA's guide documents 16-byte accesses as groups of eight lanes (its TMA swizzle example) but does not spell out the split for 8-byte accesses; this lab does not model the split, only the bank load. measured on Apple M1 Pro GPU for comparison, 16-byte elements at strides 1, 2, 4, 8, 9: GB/s.
