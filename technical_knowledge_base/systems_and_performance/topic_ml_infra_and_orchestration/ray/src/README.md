# Source of the Ray child page

Build: `sh build.sh` writes `../index.html` from `parts/` (copied from the root's build; storage key `ry-tab`; prefix `ry`).

| Path | What |
|---|---|
| `parts/10_header.html` | title, subtitle, tab bar, page CSS (`ry-` classes) |
| `parts/20_read_[a-g].html`, `20_read_z.html` | Reading tab: in one screen, tasks, actors, objects, spilling, ownership, architecture, scheduling, fault tolerance, Ray Data, Ray Train, Tune, KubeRay, when Ray, mistakes, interview |
| `parts/15_js_ry_data.js` | generated by `scripts/make_data.py` from `runs/` (do not edit) |
| `parts/22_js_ry_read.js` | Reading visuals: cluster map, the eight-task before/after animation, object locations stepper, spill chart, head processes, fault table |
| `parts/31_*` | Ownership lab: life of a task (design), node-loss replay (measured) |
| `parts/32_*` | Ray Data pipeline: every block of three plans |
| `parts/33_*` | Train failure replay: three runs, reports, registrations, restart |
| `parts/39_tab_more.html` | Further reading |
| `scripts/ry_core.py` | tasks, actors, objects, spilling, faults, lineage (node loss) experiments |
| `scripts/ry_data.py` | Ray Data pipeline in three modes |
| `scripts/ry_train.py` | the running example on Ray Train with its checkpoint API, crash once, max_failures 1 |
| `scripts/ry_ps.py` | process list without ps (the image has none) |
| `scripts/ry_run.sh` | runs every section under the ray lock; starts Ray with the head at 2,000 MB (the setup's `up.sh` with 1500m replaced) and stops it at the end |
| `scripts/ry_quotes.py` | locates every quoted Ray source line by pattern -> `inputs/source_quotes.json` |
| `scripts/make_data.py` | `runs/` -> `ry_data.json` and `parts/15_js_ry_data.js` |
| `runs/core/` | scrubbed outputs of the final pass (2026-10-16 06:22 to 06:25 UTC); `train_oom.*` is the Ray Train run that the memory monitor killed (leftover spill IO workers) |
| `runs/train/run1..3/` | three repeats of the Ray Train crash on a fresh cluster |
| `runs/debug/` | from the first pass: task placements, and w1's process list after spilling |
| `check/check_data.py` | page embeds exactly `ry_data.json`; prose numbers match the data and the root's labs; source lines; privacy |
| `check/check_ui.mjs` | every control at 390 dark and 920 light; card screenshots |
| `check/wide.mjs` | finds elements wider than the viewport |
| `facts.md`, `viz_ideas.md`, `coverage.md` | verified facts, visual ideas built and rejected, old-page coverage note |

Rerun everything (about 4 minutes of Ray, under the ray lock): `sh scripts/ry_run.sh <scratch> <root src/data> <evidence dir>`; then `sh scripts/ry_run.sh ... <dir2> procs train` on a fresh cluster for the Train runs (the first pass leaves spill IO workers on w1 that make Ray Train run out of memory); scrub into `runs/` with the root's `src/data/scrub.py`; `python3 scripts/make_data.py`; `sh build.sh`; `python3 check/check_data.py`; from the repo root `node .../check/check_ui.mjs <index.html> <shots dir>` and `sh html_utils/checkpage.sh <this folder>`.

Ray source: sparse shallow clone of ray-project/ray at tag ray-2.59.0 (commit dd83c3a703a5422d0b47f142cb380c6330817608) in the scratchpad (`mi/src/ray-2.59.0`); Python files equal the wheel installed in `mi-ray:1`.

Departures from the child-page method: none of substance. The Ownership lab's first animation is drawn from the design (paper and whitepaper), labelled so, because per-message timings were not measured.
