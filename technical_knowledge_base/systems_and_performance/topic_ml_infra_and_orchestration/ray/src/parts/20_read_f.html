Ray Tune, briefly

Ray Tune runs many training trials with different hyperparameters: Tuner(trainable, param_space={...}, tune_config=TuneConfig(num_samples=N, scheduler=ASHAScheduler())). Each trial is a Ray actor (or a whole Ray Train run); a search algorithm proposes configurations (random, grid, Bayesian through Optuna and others) and a trial scheduler stops bad trials early (ASHA, successive halving) or mutates good ones (Population Based Training). It is the right tool for many small or medium trials on a shared cluster; for one large pretraining run there is nothing to tune in parallel. {{Ray Tune docs|https://docs.ray.io/en/latest/tune/index.html}}. not run here: a sweep of the running example would only repeat the task and actor mechanics above, and the evaluation of hyperparameter search belongs to the training topic.

KubeRay: Ray on Kubernetes

In production a Ray cluster usually lives on Kubernetes through the KubeRay operator (v1.7.1, released 2026-09-21). It adds three custom resources:

  • RayCluster: a head pod and worker groups (each a pod template and a replica range); the operator creates the pods and, with autoscaling on, a Ray autoscaler sidecar asks for more worker pods when tasks wait for resources and removes idle ones.
  • RayJob: a RayCluster plus an entrypoint (your driver script); the cluster is created for the job and deleted after it. This is what Kueue admits as one workload, so team quotas and gang admission come from Kueue while Ray schedules inside.
  • RayService: a RayCluster running Ray Serve, with zero-downtime upgrades.

GCS fault tolerance on KubeRay needs a Redis (the gcsFaultToleranceOptions field, KubeRay 1.3.0 and later). GPUs come from the Kubernetes device plugin as nvidia.com/gpu in the pod spec; Ray reads them as its GPU resource. The sibling page "Kubernetes for ML: scheduling, device plugins, gang scheduling and operators" covers operators, device plugins and Kueue. {{KubeRay docs|https://docs.ray.io/en/latest/cluster/kubernetes/index.html}}. not run here: KubeRay plus a Ray cluster on the topic's kind cluster would add about 3 GB of containers to a laptop already near its budget; the root's Tool map lists KubeRay's status.
