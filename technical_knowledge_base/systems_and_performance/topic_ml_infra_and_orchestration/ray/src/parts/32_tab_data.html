Ray Data pipeline

One pipeline, three execution plans, every block drawn where and when it ran. The input is the running example's text (TinyShakespeare) in 24 blocks; encode (0.3 s of work per block) and window (0.2 s) stand in for real preprocessing; the driver's loop takes 0.1 s per batch of 512 samples, like a training step.

Lanes are worker processes (node and pid from the run); the bottom lane is the training loop in the driver. The cursor moves through the run at a fixed fraction of real time. Measured on Apple M1 Pro, Docker Desktop VM, shared machine, 2026-10-16; the shapes (when the first batch arrives, which stages overlap, how many tasks) are the lesson, not the seconds.

Fused: each block is one task that runs both functions; the training lane starts as soon as the first blocks are done. Two operators: encode and window are separate tasks that interleave on the same 4 CPUs (window asks for 0.5 CPU, so more of them fit), with an object-store hop between them. Staged: every encode finishes before any window starts, so training waits for the whole first stage: the bulk-synchronous plan streaming replaced.
