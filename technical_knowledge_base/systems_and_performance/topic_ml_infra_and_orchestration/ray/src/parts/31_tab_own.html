Ownership lab

Two views of the same rule (the worker that creates an object owns it). First the life of one task, step by step, as Ray's design describes it. Then a real node loss on this cluster: the same program, six things placed on the worker that was killed, six different fates.

2. A worker node dies: who loses what

ry_core.py lineage placed, on ray-w2: A, an 8 MB task output (driver owns it, task retryable); B, the same with max_retries=0; C, an 8 MB array that a task on w2 ray.put itself (that task's worker owns it) and returned the ref; D, a 1 KB task output (inline: lives in the driver); and two actors, one with max_restarts=1, one with the default 0. Then docker kill mi-ray-w2, and the driver asked for each in turn.

The node loss, replayed from the run's logs measured

Timeline dots: GCS log lines (purple), the driver's answers (blue), the re-executed task (orange).
