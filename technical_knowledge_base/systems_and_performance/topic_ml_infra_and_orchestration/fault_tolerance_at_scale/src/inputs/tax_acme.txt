ARITHMETIC CHECKS (mine)
- Total failures (sum of Num) = 2,575. Infrastructure 281 (10.9%), Framework 404 (15.7%), Script 1,890 (73.4%).
  Text: infrastructure failures "take over 82% GPU resources (GPU Time) with only 11% failed job quantity (Num)". OK.
- Total% reproduces exactly as Num x GPUTimeAvg / sum(Num x GPUTimeAvg) for every row (sum = 104,561,289 GPU-min,
  about 1.74M GPU-hours). Max row difference 0.01 points (Dataloader Killed 4.39 calc vs 4.38 printed).
- Category Total%: Infrastructure 82.06%, Framework 14.71%, Script 3.22%; whole column sums to 99.99%. OK.
- TR/TF% is approximately TRavg / TFavg: matches to within rounding for most rows; small rows deviate because the
  printed averages are rounded (e.g. Type Error 0.2/0.9 = 22% vs 28.27% printed; Called Process Error 11.7/0.2 =
  5850% vs 5714.29% printed; NCCL Remote Error TRavg printed 0.0 with TRmed 0.7, so TRavg is below 0.05 but above
  zero). No row looks like a typo.
- Row-level check that GPUTimeAvg is not simply GPUavg x TFavg: NVLink 800 x 868.1 = 694,480 vs 585,683 printed;
  expected, since the mean of a product differs from the product of means.

KEY QUOTES (verbatim)
1. "They take over 82% GPU resources (GPU Time) with only 11% failed job quantity (Num). Most of these jobs are
   long-term pretraining tasks that can experience hardware failures multiple times ... Note that NodeFailure
   indicates uncategorized errors caused by unclear hardware issues."
2. "Script errors typically stem from programming errors or user oversights. They constitute the majority of
   failures and are often addressed by revising codes."
3. "training 7B models in Kalos tend to result in GPU overheating, which can cause NVLinkError or ECCError ... We
   observe that the overall temperature in the cluster server room increased by approximately 5 C when training
   these models ... most of these jobs occurred in July 2023".
Other:
- "A significant number of ConnectionError and NetworkError incidents stem from these auxiliary services"
  (metric reporting, logging, monitoring and alerting).
- "In Kalos, only 6.7% of evaluation tasks encounter errors, and notably, there are no recorded instances of GPU or
  NVLink failures."
- Restart triggers: "(1) when an error occurs within the job, (2) when there are anomalies in training metrics such
  as a loss spike, and (3) when the training process is stuck."
- Detection: two-round NCCL allgather test on two-node worlds, then pair suspects with normal nodes, "thus
  identifying the faulty nodes and then cordoning them off" (akin to DLRover).
- "our failure diagnosis system significantly reduces manual intervention by around 90% ... Note this is not a
  rigorous assessment since components of our system are still under improvement."
