SOURCE: Eisenman, Matam, Ingram, Mudigere, Krishnamoorthi, Nair, Smelyanskiy, Annavaram (Facebook, USC). "Check-N-Run: a Checkpointing System for Training Deep Learning Recommendation Models". NSDI 2022. arXiv:2010.08679v2 (4 May 2021) read.
URL: https://arxiv.org/abs/2010.08679 (NSDI page: https://www.usenix.org/conference/nsdi22/presentation/eisenman; usenix PDF download returned HTML via curl)
LABEL: vendor (Facebook on its own system). Read 2026-10-16.

MECHANISM (my words): For recommendation models (multi-TB embedding tables, only a small fraction updated per iteration), training stalls only briefly to copy model state from GPU HBM to pinned host memory (a distributed snapshot across hosts); background CPU processes then write an incremental checkpoint (only the embedding rows modified since the last checkpoint, tracked with a bit vector) and quantize it before writing to remote storage. Full precision is kept for training; quantization only matters if a checkpoint is restored.

VERBATIM
- Abstract: "These techniques allow Check-N-Run to reduce the required write bandwidth by 6-17x and the required capacity by 2.5-8x on real-world models at Facebook".
- Contributions: quantization approaches "reduce the checkpoint size by 4-13x, without degrading the training accuracy."
- Stall: "creating a snapshot (in CPU DRAM) of a typical model residing in the GPU memory and partitioned across 16 nodes, each with 8 GPUs (total of 128 GPUs), would stall training in our system for less than 7 seconds." "We measured this operation to take up to 7 seconds in our setting, during which training is stalled. When checkpoint intervals are 30 minutes, the default setting, that overhead translates to less than 0.4% reduction in training throughput."
- Baseline compression: Zstandard reduces size "by at most 7%".

CAVEATS
- Specific to recommendation models (sparse updates); incremental trick does not carry to dense LLMs, where every parameter changes every step. Scale 128 GPUs in the stall example.
