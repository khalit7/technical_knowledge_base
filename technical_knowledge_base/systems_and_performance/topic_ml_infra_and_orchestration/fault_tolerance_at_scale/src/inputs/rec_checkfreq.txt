SOURCE: Mohan (UT Austin), Phanishayee (Microsoft Research), Chidambaram (UT Austin, VMware). "CheckFreq: Frequent, Fine-Grained DNN Checkpointing". USENIX FAST 2021, Feb 23-25, 2021.
URL: https://www.usenix.org/conference/fast21/presentation/mohan (PDF https://www.usenix.org/system/files/fast21-mohan.pdf)
LABEL: vendor (authors of the system). Read 2026-10-16.

MECHANISM (my words): Two-phase checkpointing: snapshot() makes a consistent in-memory copy of model state (on GPU if memory allows, else CPU), pipelined with the next iteration's forward and backward pass and only blocking the next weight update if unfinished; persist() writes the snapshot to disk asynchronously in a background process (fsync, new file each time). An online profiler picks the checkpoint interval k (iterations) to keep overhead under a user bound (e.g., 5%) and adapts it at runtime; a resumable data iterator keeps exactly-once-per-epoch data order across restarts.

VERBATIM
- Abstract: "CheckFreq can reduce the recovery time from hours to seconds while bounding the runtime overhead within 3.5%."
- "CheckFreq reduces the wasted GPU time from order of hours to just under a minute, while incurring less than 3.5% runtime overhead, as compared to the existing epoch-based checkpointing schemes. CheckFreq reduces the end-to-end training time by 2x when training a ResNet50 job on a 1080Ti GPU, and by 1.6x for a ResNext101 job on a V100 GPU, when the job is interrupted every 5 hours in both cases."
- "Existing state-of-the-art data loaders like DALI [4] result in up to 13% drop in accuracy while CheckFreq is able to train the model to target accuracy" (ResNet18, interrupted every 2 epochs).
- "The checkpointing operation is split into a snapshot() and a persist() phase. In the snapshot() phase, CheckFreq performs a consistent in-memory copy of all the learnable model state ... In the persist() phase, the snapshot is asynchronously written to the storage device."
- Motivation numbers: ResNext101 on ImageNet-1K on a V100 "takes 270 hours (~3.9 hours per epoch)"; epoch-boundary checkpointing loses "about two hours of GPU computation" on average.
- Hardware: two servers, each 8 GPUs, 24 CPU cores, 500 GB DRAM: "Conf-Pascal 1080Ti" with HDD and "Conf-Volta V100" with SSD. PyTorch 1.1.0, CUDA 10.0. Models: image classification / NLP DNNs (ResNet18/50, ResNext101, DenseNet121, ...).

CAVEATS
- Single server scale (8 GPUs), pre-LLM models. Historic: the two-phase snapshot/persist split is the ancestor of the async designs in DCP, MegaScale, ByteCheckpoint.
