SCALE AND PERIOD
- Microsoft "Philly". "The cluster under study consists of hundreds of machines accounting for thousands of GPUs of
  the same model. The cluster has 2 server SKUs, one with 2 GPUs per server and another with 8 GPUs per server"
  [dash replaced]. "collect logs over a 75-day period from Oct. 2017 to Dec. 2017. Our logs contain a total of 96260
  jobs over 14 virtual clusters." Scheduler: Apache YARN; jobs mostly 1 to a few tens of GPUs (not LLM scale).
- Exact GPU count: not given in the paper (unconfirmed).

UNIT OF COUNTING
Failure events ("Trial"), grouped also by distinct job ID ("Job") and distinct user ID ("User"). A job is retried
on failure a fixed number of times; each retry failure is a Trial. Classified by a rule-based classifier: "our
classifier has in total more than 230 rules"; "If there is no signature for a failure, we tag it as no signature,
which constitutes 4.2% of the total failures."
Categories: "(i) Infrastructure (IF) which includes YARN, HDFS and all other framework components, (ii) AI Engine
(AE) which includes TensorFlow, Torch, and any other platforms, and (iii) User (U) which represents programmers."
"A failure reason may be observed in multiple categories."

- RTF Total% column sums to 100.01%. OK.

- Repetition factors "2.3 and 38.8 on average for Job and User": pooled top-8 ratio sum(Trial)/sum(Job) =
  34834/15209 = 2.29 (matches 2.3); sum(Trial)/sum(User) = 34834/927 = 37.6 (not 38.8); mean of per-reason ratios
  gives 2.18 and 44.2. So the 38.8 does not reproduce exactly; flag as minor.
- Category shares (my computation, a reason can carry several categories so these overlap): reasons tagged U cover
  32,666 trials (82.1% of 39,776); tagged IF 17,944 (45.1%); tagged AE 17,937 (45.1%). Single-category only: IF
  3,254 (8.2%), AE 2,172 (5.5%), U 2,988 (7.5%). The paper does NOT print a "share in user code vs infra" number;
  the claim is qualitative: "Failures incurred by user errors, such as configuration/syntax/semantic errors in
  program and script, are dominant."
- By GPU time (RTFxDemand), IF-only reasons (Model ckpt error 16.33, MPI runtime failure 15.34, Job preempted 4.73,
  MPI error 1.24) = 37.6% of failure GPU time from 8.2% of trials. My computation.

DEFINITIONS (verbatim)
- "(1) Incorrect inputs: Model files or input data stored in the external HDFS storage cannot be read."
- "(2) Semantic error: Errors that happen due to library version mismatch or other dependencies of the user training
  program not being setup correctly."
- "(3) Model checkpoint error: ... usually due to either transient error in HDFS or HDFS name node recovery."
- "(4) MPI runtime failure: This is usually due to either a failure of network connection to peer MPI process, or
  possibly an internal failure of the MPI daemon itself."
- "(5) Job preempted: YARN reclaims any GPU currently in use to schedule another job."
- "(6) Invalid memory access: Training job dies because of violating access on memory address space".

KEY QUOTES
1. "Around 30% of jobs are killed or finish unsuccessfully due to failures. Failures are caused by errors across the
   stack, with programming errors dominating failures and occurring early in the training process; failures due to
   cluster components like HDFS tend to occur much later in the training lifecycle."
2. "Infrastructure failures occur infrequently but have much longer runtime to failure (RTF)."
3. "Many failures of training jobs happen quickly, for example within 10 mins." Design implication: "many failures
   ought to be caught early, well before they are scheduled on a larger shared cluster."
