SOURCE: Jang, Yang, Zhang, Jin, Chowdhury (U. Michigan, AWS, Peking U.). "Oobleck: Resilient Distributed Training of Large Models Using Pipeline Templates". SOSP 2023. arXiv:2309.08125v2, 7 Nov 2023.
URL: https://arxiv.org/abs/2309.08125
LABEL: vendor (authors). Read 2026-10-16.

MECHANISM (my words): Before training, Oobleck precomputes a set of heterogeneous pipeline templates (pipelines of different node counts with layer-to-stage mappings) and instantiates at least f+1 logically equivalent data-parallel pipeline replicas, so any f simultaneous failures leave at least one complete copy of the model state. On a node failure or addition it does not restart from a checkpoint: it reinstantiates pipelines from the templates to use all remaining nodes, copies missing layers' states from surviving replicas, redistributes the global batch, and resumes. If fewer than f+1 replicas can be kept it saves progress and exits (fallback to checkpoint restart).

VERBATIM
- Abstract: "instantiates at least f + 1 logically equivalent pipeline replicas to tolerate any f simultaneous failures. During execution, it relies on already-replicated model states across the replicas to provide fast recovery. Oobleck provably guarantees that some combination of the initially created pipeline templates can be used to cover all available resources after f or fewer simultaneous failures ... it outperforms state-of-the-art fault tolerance solutions like Bamboo and Varuna by up to 29.6x."
- "When node failure(s) happen, if we have a complete model replica, Oobleck does not restart but reconfigures the pipelines ... nodes share information about the ownership of model states and copy missing model states from others."
- Results: "outperforms the state-of-the-art solutions by up to 29.6x when nodes fail more frequently and matches them as failures become less frequent"; with spot traces "It outperforms the rest by up to 9.1x on average". Planning is one-time: "the planning overhead is marginal (< 0.1%)" relative to ~100-day training.
- Failure rates tested: "one failure happens every six hours and every 10 minutes". Spot traces from Bamboo repo (EC2 p3.2xlarge/p3.8xlarge, GCP a2-highgpu-1g): "Node preemption events happen every 7.7 minutes and 10.3 minutes, on average".
- Hardware: "30 NVIDIA A40 GPUs with 40GB GPU memory each ... 200Gbps Mellanox ConnectX-6 InfiniBand". Models up to GPT-3 6.7B. Varuna baseline used a 6-node MinIO object store. "Bamboo cannot run any model larger than GPT-2" (OOM); "for GPT-3 with 6.7 billion parameters, Varuna hung over the entire time".

CAVEATS
- Demonstrated on 30 A40 GPUs and models up to 6.7B; "29.6x" is at the highest failure rate (every 10 minutes) against baselines that partly failed. No per-recovery second count extracted.
