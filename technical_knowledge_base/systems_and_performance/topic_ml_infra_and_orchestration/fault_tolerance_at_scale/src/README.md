# Source of the fault tolerance child page (prefix `ft`)

Build: `sh build.sh` writes `../index.html` from `parts/` (copied from the root's build; storage key `ft-tab`).

| Path | What |
|---|---|
| `parts/10_header.html` | title, subtitle, tab bar, page CSS (`ft-` classes) |
| `parts/20_read_[a-h].html`, `20_read_z.html` | Reading: in one screen, what fails, five shapes, detection and health checks, recovery designs, restore traps, silent data corruption (measured), stragglers, goodput accounting, mistakes, interview |
| `parts/15_js_ft_data.js` | generated by `scripts/make_data.py` (do not edit) |
| `parts/22_js_ft_sdc.js` | bit-flip animation, loss-difference chart, detector table |
| `parts/23_js_ft_det.js` | time-to-notice chart (defaults, lab, tuned) |
| `parts/24_js_ft_read.js` | predict-then-reveal; Llama 3 against the 2026 32K-job table |
| `parts/25_js_ft_gp.js` | goodput accounting of the root lab's three Slurm runs |
| `parts/31_*` | Failure taxonomies tab |
| `parts/32_*` | Recovery designs tab (goodput model of the root's Failure lab) |
| `parts/33_*` | Straggler replay tab |
| `scripts/ft_lab.py`, `ft_run.sh` | the native experiments (stragglers, bit flips, replays): 4 ranks, gloo, 1 thread each, nice 15, about 1 minute in all |
| `scripts/ft_save_runs.py` | scratch runs -> `runs/*.json` (columnar, every logged field) |
| `scripts/tax_build.py` | published failure tables -> `inputs/tax.json`, with our common-scheme mapping and arithmetic checks |
| `scripts/rec_build.py` | recovery-design inputs with sources -> `inputs/rec.json` |
| `scripts/recompute.py` | every computed number in the prose -> `recompute.json` (needs torch for the one-weight AdamW check) |
| `scripts/ft_quotes.py` | locates every quoted PyTorch v2.14.1 line by pattern -> `inputs/source_quotes.json` |
| `scripts/make_data.py` | runs + inputs + root Failure lab (read only) -> `ft_data.json`, `parts/15_js_ft_data.js` |
| `inputs/` | text extracts of every source read 2026-10-16 (`tax_*`, `rec_*`, `det_*`, `sdc_*`, `str_*`), `tax.json`, `rec.json`, `source_quotes.json` |
| `runs/` | the 14 native runs (2026-10-16) |
| `check/check_data.py` | page embeds exactly the data; prose numbers; source lines; privacy |
| `check/check_ui.mjs`, `check/wide.mjs` | every control at 390 dark and 920 light; wide elements |
| `facts.md`, `viz_ideas.md`, `coverage.md` | verified facts, visual ideas, old-page note |

Rerun: `sh scripts/ft_run.sh <scratch> <root src/data> <scratch>/mi/ft/runs` (native, no cluster lock needed; run the scratch guard first), `python3 scripts/ft_save_runs.py <scratch>/mi/ft/runs runs`, `python3 scripts/tax_build.py`, `python3 scripts/rec_build.py`, `<venv>/bin/python scripts/recompute.py`, `python3 scripts/make_data.py`, `sh build.sh`, `python3 check/check_data.py`, then from the repo root `node <this>/check/check_ui.mjs <index.html> <shots dir>` and `sh html_utils/checkpage.sh <page folder>`.

Departures from the child-page method: no cluster workload was run (the root's Failure lab already recorded twelve failures on the three clusters; this page reuses them). The two new experiments run natively on macOS because they need per-rank timing and bit-level control, not a scheduler. The recovery-design rows combine published inputs from different systems, so each row is labelled illustrative as a whole.
