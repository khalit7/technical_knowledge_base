# Source of the Observability and cost child page (prefix `oc`)

Build: `sh build.sh` writes `../index.html` from `parts/` (build copied from the sibling Fault tolerance page; storage key `oc-tab`).

| Path | What |
|---|---|
| `parts/10_header.html` | title, subtitle, tab bar, page CSS (`oc-` classes) |
| `parts/15_js_oc_data.js` | generated by `scripts/make_data.py` (do not edit) |
| `parts/20_read_[a-d].html`, `20_read_z.html` | Reading: one screen, words, GPU counters, util against work, MFU in code, goodput, Prometheus, logs, alerts, scheduling efficiency, chargeback, capacity; mistakes, interview |
| `parts/22_js_oc_read.js` | predict-then-reveal, tables from data, healthy-against-hung animation, Prometheus sizing calculator |
| `parts/31_*` | Metrics explainer (simulated 132-SM H100; every counter from its definition; 7 situations before/after) |
| `parts/32_*` | Cluster dashboard (replay of the recorded Prometheus data, alerts, scrape costs) |
| `parts/33_*` | Capacity planner (run, fleet, own vs rent); `OCP` functions mirror `scripts/recompute.py` |
| `scripts/oc_exporter.py` | the tiny exporter: training logs, Kueue ClusterQueue status, Slurm squeue/scontrol, node cgroups |
| `scripts/prom/` | `prometheus.yml` and `oc_rules.yml` that ran (Prometheus v3.13.4) |
| `scripts/oc_up.sh`, `oc_down.sh` | start/stop the stack: one container `oc-prom` (256 MB, 0.5 CPU), exporter, kubectl proxy, Kueue port-forward, a ServiceAccount bound to `kueue-metrics-reader` |
| `scripts/oc_kind.sh` | four kind scenarios (base, slow node via pod cgroup `cpu.max`, hang via SIGSTOP, queue of 3), run under the kind lock |
| `scripts/oc_slurm.sh` | Slurm fragmentation scenario and sacct accounting, under the slurm lock |
| `scripts/oc_record.py` | Prometheus query_range -> `runs/prom/*.json` |
| `scripts/oc_mfu.py` | MFU of the running example against a measured matmul ceiling, in `mi-train:1` (1 CPU) |
| `scripts/make_data.py`, `recompute.py` | data for the page; planner defaults in Python |
| `runs/` | recorded runs, scrubbed with the root's `src/data/scrub.py` (kind logs, events, Workloads; Slurm sacct, squeue; Prometheus recordings; `mfu.jsonl`) |
| `inputs/` | source extracts read 2026-10-16 (DCGM fields, cluster utilisation studies, buy vs rent, Prometheus/Kueue/Slurm metrics, published monitoring practice) and `page_inputs.json` |
| `check/check_data.mjs`, `check/check_ui.mjs` | data and prose checks; every control at 390 dark and 920 light |
| `facts.md`, `viz_ideas.md`, `coverage.md` | verified facts, visual ideas, old-page note |

Rerun (from the repo root, scratch = the session scratchpad's `mi` folder): `sh <scratch>/../inf/guard.sh`; `S=<scratch> sh src/scripts/oc_up.sh`; under the kind lock `K=<scratch>/k.sh SHARED=<scratch>/shared/k8s OUT=<scratch>/oc/kind sh src/scripts/oc_kind.sh base slow hang queue`; under the slurm lock `OUT=<scratch>/oc/slurm sh src/scripts/oc_slurm.sh`; `python3 src/scripts/oc_record.py http://127.0.0.1:19090 <t0> <t1> <out>`; `S=<scratch> sh src/scripts/oc_down.sh`; scrub into `runs/`; `python3 scripts/make_data.py && python3 scripts/recompute.py && sh build.sh`; `node <page>/src/check/check_data.mjs <page>`.

Departures from the child-page method: no GPU exists here, so GPU counters are derived from their definitions (labelled) and CPU time of the training pods stands in for the device meter; the dashboard is a replay of a recording, not a live Grafana (the page is a sandboxed iframe). Ray was not run (its 3.7 GB of caps; the Ray child's head-memory measurement is linked instead). The PodThrottled rule was corrected during the slow-node run (it first read the container cgroup); the page says so and the recorded alert times show it.
