Cluster dashboard: what Prometheus saw on the local clusters

A real recording, not a mock-up. On 2026-10-16 one Prometheus (v3.13.4, in a 256 MB container) scraped the topic's kind cluster and Slurm cluster every 5 seconds while the running example went through five situations: a healthy run, a slow node, a hang, a queue that fits one job at a time, and a Slurm job waiting with GPUs free. Pick one, replay it, and watch which panel notices first and which alert fires. Every panel shows the query that drew it.

measured on Apple M1 Pro, Docker Desktop VM, shared machine. The GPUs are fake counted resources, so there are no GPU counters here: CPU time of the training pods (cAdvisor, through the kubelet) stands in, and the {{Metrics explainer|#t-met}} shows what the GPU counters would add. Event order, alert firing and the queue are exact; rates are rough.

How it was wired

Four kinds of target, the same four a real GPU cluster has: the training job's own numbers (here an exporter reading the per-rank JSON logs; on a real cluster the training loop exports them or pushes to a gateway), the node and container counters (cAdvisor; on GPU nodes add dcgm-exporter as a DaemonSet), the scheduler (Kueue's metrics endpoint, and for Slurm an exporter parsing squeue and scontrol because Slurm 24.11 has no metrics endpoint; 25.11 added one), and Prometheus itself. The config, rules and scripts that ran are in src/scripts/.
