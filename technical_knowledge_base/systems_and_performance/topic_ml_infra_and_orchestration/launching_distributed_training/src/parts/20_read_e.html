9. Containers and networks: what the processes can see

10. Bringing up a new cluster: a checklist

Every step isolates one link of section 1, cheapest first, so a failure points at one layer (the tags name the links of the hero figure). Commands are the standard ones; this laptop could only run the CPU steps (marked), the rest are described.

  1. 4 workersOne node, one process. python -c "import torch; print(torch.__version__, torch.cuda.device_count())" in the exact image the jobs will use. Catches the wrong image, a CUDA mismatch, no GPUs visible.
  2. 5 communicatorOne node, all GPUs, NCCL only. nccl-tests: all_reduce_perf -b 8 -e 8G -f 2 -g 8. Compare the bus bandwidth (its busbw column: the algorithm bandwidth "size (S) / time (t)" times 2(n−1)/n for all-reduce, as defined in {{nccl-tests PERFORMANCE.md|https://github.com/NVIDIA/nccl-tests/blob/master/doc/PERFORMANCE.md}}) with what the vendor's node should do. Catches NVLink or PCIe problems, a small /dev/shm, a missing peer-to-peer path.
  3. 5 communicatorTwo nodes, NCCL only, with NCCL_DEBUG=INFO. Read the log before the numbers: "Bootstrap: Using <iface>" ({{bootstrap.cc:133|L:nccl_boot_using}}), "Using network IB" or "Socket" ({{init.cc:486|L:nccl_net_name}}), no NET/IB : No device found.. Then the bus bandwidth against the NIC's line rate. Catches the interface choice, the RDMA devices not mapped into the container, a socket fallback.
  4. 3 rendezvous5Two nodes, torchrun, a hello-world all-reduce. torchrun --nnodes=2 --nproc-per-node=8 --rdzv-backend=c10d --rdzv-endpoint=$HEAD:29500 hello.py, printing rank, host and the all-reduced rank sum. Catches DNS, ports, the rendezvous, PyTorch's NCCL. (Run here on CPU with gloo: the parent's Launch lab.)
  5. 346 first stepTwo nodes, the real job for 20 steps, then kill one rank on purpose and watch the restart and resume (with TORCH_DISABLE_SHARE_RDZV_TCP_STORE=1 on torch 2.14.1, section 5). Catches checkpoint paths that only one node can see, a broken resume. (Run here: section 3.)
  6. 6Scale in doublings (2, 4, 8, ... nodes) and plot step time; a jump names the level of the network where it happens (sibling page {{Cluster anatomy|n:3fc5c17b0d0d816a871df56477fc83b2}}, and {{Interconnects and scaling|n:3c65c17b0d0d81808563fd41fb163af0}}).
  7. allWrite the defaults down into the job template: NCCL_SOCKET_IFNAME, NCCL_IB_HCA, the shared-memory size and memlock limit, the timeouts of section 7, TORCH_FR_BUFFER_SIZE and TORCH_NCCL_DUMP_ON_TIMEOUT=1, a hang watchdog, and the health check each node passes before it is given a job (sibling page {{Fault tolerance at scale|n:3fc5c17b0d0d815786d1c1dddb311a9b}}).
