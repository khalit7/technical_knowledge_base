# ML platforms and workflows: verified facts (copy of what was appended to the topic's shared FACTS.md under "## mp")

Verified or measured 2026-10-16. Measured = Apple M1 Pro, macOS native, CPU, shared machine; MLflow 3.17.1, Metaflow 2.19.39, torch 2.14.1 (own venv, src/inputs/venv_freeze.txt).

## Versions and code facts (installed packages, file and line)
- MLflow 3.17.1: default tracking URI `sqlite:///mlflow.db` (mlflow/store/tracking/__init__.py line 13) unless ./mlruns already holds experiment data (mlflow/tracking/_tracking_service/utils.py `_get_default_tracking_uri`, line 55). Docs: the default moved from ./mlruns to SQLite in MLflow 3.7.0 and the file store is in maintenance mode (https://mlflow.org/docs/latest/self-hosting/architecture/backend-store/).
- MLflow 3.17.1 FileStore raises unless MLFLOW_ALLOW_FILE_STORE=true (mlflow/store/tracking/file_store.py lines 223-235): "The filesystem tracking backend (e.g., './mlruns') is in maintenance mode ...". Measured. (The docs' opt-out "set MLFLOW_TRACKING_URI=./mlruns" alone is not enough in 3.17.1.)
- MLflow 3.17.1 mlflow.pytorch.log_model defaults to serialization_format "pt2" (torch.export) outside Databricks, which requires input_example (mlflow/pytorch/__init__.py lines 236-248, 322-323). Measured error text in runs/errors.txt. An input example of batch 1 specialises the batch dimension: reloaded model fails "Guard failed: idx.size()[0] == 1"; batch 2 kept it dynamic (measured).
- MLflow registry stages deprecated since 2.9.0: @deprecated(since="2.9.0") on transition_model_version_stage (mlflow/tracking/client.py line 4941). Aliases: models:/<name>@<alias> (MLflow docs model-registry page).
- MLflow 3: LoggedModel entity, models stored under <experiment>/models/m-<id>/artifacts; registry source "models:/m-<id>" (measured). MLflow 3 release blog dated 2025-06-11 (mlflow.org/releases/3); PyPI 3.0.0 2025-06-10 (Tool map).
- mlflow server 3.17.1: uvicorn app plus a job-runner process; about 540 MB RSS for the three processes at idle (measured); "Security middleware enabled with default settings (localhost-only)".
- Metaflow 2.19.39: artifacts stored content-addressed by sha1 of the serialised blob (metaflow/datastore/content_addressed_store.py line 98); resume "reuses results of every successful step" decided by flow and step names, not code; parameters cannot change on resume (docs.metaflow.org/metaflow/debugging). @timeout: "By default, there is no timeout for steps"; @retry default three times (docs.metaflow.org/scaling/failures).
- Neptune: hosted app and API off "On March 5, 2026, at 10 am PST" (docs.neptune.ai/transition_hub, read 2026-10-16), hosted data "securely and irreversibly deleted"; migration guides offered for MLflow, W&B, ZenML, Comet and others; self-hosted Helm and image repositories deleted 2026-03-08.
- lakeFS acquired the DVC open-source project from Iterative, announced 2025-11-18 (https://lakefs.io/blog/lakefs-acquires-dvc/); DVC continues as an independent open-source tool.
- Airflow: started October 2014 at Airbnb; Apache Incubator March 2016; top-level project January 2019 (airflow.apache.org project page). Airflow 3.0.0 (2025-04-22): DAG versioning (AIP-66), Task Execution API and Task SDK (AIP-72), assets (AIP-74/75), scheduler-managed backfills (AIP-78), Edge executor (AIP-69), React UI, restricted metadata DB access.
- Metaflow open-sourced by Netflix in December 2019 (Metaflow docs roadmap; press 2019-12-03/04). Flyte open-sourced by Lyft 2020-01-07 (Lyft engineering blog; Lyft figures: over 7,000 workflows, over 100,000 executions a month). Uber Michelangelo blog 2017-09-05.
- Sculley et al., "Hidden Technical Debt in Machine Learning Systems", NIPS 2015.
- OLMo 2 (arXiv 2501.00656): header links public W&B logs (api.wandb.ai/links/ai2-llm/...), OLMES eval standard, thousands of intermediate checkpoints; Beaker section 6.2.

## Measured on the running example (lab: src/lab, records: src/runs)

The MLflow run of the hung workflow shows FINISHED with no metrics (each step opens and closes the run).

## Added 2026-10-24 (documentation read that day)
- SageMaker TrainingJob API: secondary statuses Starting, Downloading, Training, Uploading ("model artifacts are being uploaded to the S3 location"); billed from TrainingStartTime to TrainingEndTime, which for successful jobs "is the time after model artifacts are uploaded"; StoppingCondition "Use this API to cap model training costs", SIGTERM then 120 seconds to save artifacts (docs.aws.amazon.com/sagemaker/latest/APIReference/API_TrainingJob.html).
- SageMaker HyperPod: "a persistent cluster service" (how-it-works-training); Slurm or Amazon EKS orchestration (sagemaker-hyperpod.html); node recovery Automatic by default, "reboots or replaces faulty nodes"; `srun --auto-resume=1` restarts from the last saved checkpoint after nvidia-smi, Neuron sysfs and EFA checks; do not use $SLURM_JOB_NODELIST after auto-resume; GRES nodes are re-queued and restarted from the beginning; Slurm health monitoring agents since 2025-09-11 (sagemaker-hyperpod-resiliency-slurm-auto-resume.html).
- SageMaker managed MLflow: compute and backend store in the SageMaker service account, artifact store in your S3; Small/Medium/Large for up to 25/50/100 users, 25/50/100 sustained TPS; 200 MB download limit; MLflow Apps on 3.16; models auto-registered to SageMaker Model Registry; EventBridge events include "SageMaker MLFlow Tracking Server Setting Registered Model Alias" (docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html).
- Azure ML: workspaces are MLflow-compatible ("use an Azure Machine Learning workspace the same way you use an MLflow server"); SDK v2 has no logging of its own; MLproject support fully retired September 2026 (learn.microsoft.com concept-mlflow, updated 2026-10-19).
- Google: Vertex AI rebranded Gemini Enterprise Agent Platform at Cloud Next, April 2026 (HPCwire 2026-04-23); its Pipelines run Kubeflow Pipelines or TFX "in a serverless manner", ML Metadata lineage; serverless training "Deletes the VMs after the training job completes" (docs.cloud.google.com).
- Feast: offline store for training, online store for low-latency serving; point-in-time joins look back from each entity row up to the TTL; filter_by_created_timestamp=True keeps backfilled values out (docs.feast.dev). Databricks announced acquiring Tecton, reported 2025-08-26 (ChannelLife).
