1. Inside one node: the parts list

A GPU server has many more parts than "8 GPUs", and each is a place where a job can be slow or broken: a GPU on the wrong CPU socket, a network card that is not the one next to its GPU, a disk that vanishes with the node. The reference is NVIDIA's DGX H100, the most fully documented 8-GPU server; most HGX servers from other builders (Meta's Grand Teton, Dell, Supermicro) use the same 8-GPU board and a similar layout ({{DGX H100 user guide|https://docs.nvidia.com/dgx/dgxh100-user-guide/introduction-to-dgxh100.html}}) vendor.

The PCIe tree and NUMA: why "which GPU" matters inside one box

PCIe is the bus every device hangs from (taught on the {{interconnects page|n:3c65c17b0d0d81808563fd41fb163af0}}). In an 8-GPU server it is a tree: each CPU socket has PCIe lanes, under each socket sit PCIe switches, and under each switch (typically) two GPUs, their two network cards and some NVMe drives. Two consequences:

  • GPU and NIC pairs. When GPU 3 sends to another node, the fastest path is the NIC under the same PCIe switch: GPU to switch to NIC, never touching the CPU (GPUDirect RDMA). A NIC under the other socket means crossing the link between the two CPUs. NCCL reads the tree, pairs each GPU with its nearest NIC, and names the distances PIX (same PCIe switch), PXB (several PCIe switches), PHB (through the CPU, same NUMA node) and SYS ("crossing the SMP interconnect (e.g. QPI/UPI)") ({{NCCL environment variables|https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html}}) docs.
  • NUMA. Each socket's memory is near its own cores and far from the other's. A rank whose process runs on socket 1 while its GPU hangs under socket 0 copies every batch across the inter-socket link. The fix is CPU affinity: Slurm's --gpu-bind and --cpu-bind, Kubernetes' Topology Manager, or numactl in the launch script (switches on {{Slurm|n:3c65c17b0d0d81889c32cd050bbbadd3}} and {{Kubernetes for ML|n:3c65c17b0d0d81cf9417de52108cfbce}}; pinning from the operating system side on {{Scheduling and CPU time|n:3f05c17b0d0d81ed9c18cc47c6bfdf76}}).
The commonest node-level mistake
Running 8 ranks with no binding, so the operating system spreads them over both sockets as it likes. Nothing fails; input copies and the data loader get slower, by an amount that depends on the job. Read nvidia-smi topo -m before writing the launch script (section 7).
