## km (Kubernetes for ML child)
Checked or measured 2026-10-16 on kind v0.33.0, Kubernetes v1.37.0, Kueue v0.20.2, JobSet v0.13.0 (evidence in the child's src/runs/). Source clones: kubernetes v1.37.0 (f54c212e3a2f75d674b717a9b29052b20b60aefc), jobset v0.13.0 (0025c8257ba3cb8ec7169ee21f68f0c8e5eca6d9), kueue v0.20.2 (296ec3db567abbe36b65a63695710e3d3f3d0bdb), kubeflow/trainer v2.3.0 (658725bdae5c7e3a0854d93ac6ff492e109a22ab).
- Default scheduler scoring ignores GPUs: NodeResourcesFit LeastAllocated scores cpu and memory only (apis/config/v1/defaults.go:33-35); an extended resource enters a score only if listed in the strategy and requested (noderesources/resource_allocation.go:176-182). Default weights TaintToleration 3, NodeAffinity 2, NodeResourcesFit 1, PodTopologySpread 2, InterPodAffinity 2, BalancedAllocation 1, ImageLocality 1 (default_plugins.go:40-52). Non-zero defaults 100m / 200 MiB (scheduler/util/pod_resources.go:28-31).
- Measured: the same pods (2,1,1,2,2 fake GPUs then 4) under the default profile left the 4-GPU pod Pending ("3 Insufficient example.com/gpu"); under a MostAllocated profile with example.com/gpu weight 5 it fit on worker3. recompute.py reproduces 135/135 logged plugin scores (schedule_one.go:984 at V(10)).
- Pods' exit code under torchrun: a rank exiting 13 makes torchrun exit 1 (ChildFailedError lists "exitcode : 13"); podFailurePolicy onExitCodes [13] never matches (Job fails by BackoffLimitExceeded after 2 attempts, 34 s); rule on 1 fails it at 11.6 s with reason PodFailurePolicy.
- Job backoff: 10 s doubling per failure after last success, cap 10 min (job_controller.go:76-79, backoff_utils.go:255-276); 2 failed pods -> 20 s; measured 19.1 s from the second pod's end to new pods.
- Eviction (Eviction API) adds DisruptionTarget reason EvictionByEvictionAPI. With podFailurePolicy Ignore on DisruptionTarget and backoffLimit 0, the evicted pod is not counted (failed 1) but its peer exits 1 (gloo peer gone) and fails the Job (BackoffLimitExceeded). JobSet failurePolicy rule RestartJobSetAndIgnoreMaxRestarts on onJobFailureReasons [PodFailurePolicy] + Job podFailurePolicy FailJob on DisruptionTarget: restarted once (restarts 1), resumed from step 50, completed; a crash under the same JobSet (maxRestarts 0) failed at 8.8 s with ReachedMaxRestarts.
- Resume from step 50 (4 ranks) differed from the uninterrupted run at steps 70, 180 and 200 by 2.4e-7 (one float32 step), consistent with the fl DDP bucket-rebuild finding (different steps from fl's resume at 100).
- successPolicy succeededIndexes "0": SuccessCriteriaMet at 8.1 s, Complete at 39.3 s: workers (sleep as PID 1, ignores SIGTERM) killed after the 30 s grace period (exit 137). backoffLimitPerIndex 1: index 2 retried after 9.7 s, Job Failed reason FailedIndexes, completedIndexes 0,1,3.
- Jobs in 1.37 add condition SuccessCriteriaMet before Complete, FailureTarget before Failed.
- Priority: a 1000-priority pod preempted a 100-priority pod ("preemption: found a potential placement for pod on node mi-kind-worker3, preempting 1 victims"; victim event "Preempted by pod <uid> on node mi-kind-worker3"), bound 2.2 s later; preemptionPolicy Never: "preemption: not eligible due to preemptionPolicy=Never."
- topologySpread maxSkew 1 over blocks with b2's only node tainted: nodeTaintsPolicy Ignore (default) left 2 of 3 pods Pending ("2 node(s) didn't match pod topology spread constraints"); Honor placed all 3 in b1.
- Native gang scheduling: GenericWorkload beta, off by default in v1.37 (pkg/features/kube_features.go:1622-1625); API scheduling.k8s.io/v1beta1 PodGroup with schedulingPolicy.gang.minCount; pods join via spec.schedulingGroup.podGroupName (core/v1 types.go:4716; replaced workloadRef in 1.36); GangScheduling plugin Permit waits up to 5 min (gangscheduling.go:42). Measured on the root's deadlock input (3 jobs x 2 pods x 4 GPUs, released a0 b0 c0 a1 b1 c1): without, a0/b0/c0 Running and the rest Pending indefinitely; with, a ran first, then b, then c; log "minCount (2) cannot be satisfied: 1 scheduled, 0 remaining". PodGroups carry finalizer scheduling.k8s.io/podgroup-protection (needs kube-controller-manager with the gate).
- Kueue's pod webhook mpod.kb.io has failurePolicy Fail for every namespace except kube-system and kueue-system: while the Kueue controller restarted (after an API server restart) every pod creation failed ('failed calling webhook "mpod.kb.io" ... connection refused').
- Kueue flavors: ClusterQueue with flavors km-b1 (8 GPUs) then km-b2 (4): 3 workloads of 4 GPUs -> b1, b1, b2; 4th: "insufficient unused quota for example.com/gpu in flavor km-b1, 4 more needed, insufficient unused quota for example.com/gpu in flavor km-b2, 4 more needed"; Kueue injected nodeSelector mi.example.com/block.
