5. Multi-node networking: getting the RDMA NIC into the pod

A pod normally has one interface, eth0, on the cluster's pod network (made by the cluster's CNI plugin: an overlay or routed network over TCP). That is enough for DNS and torchrun's rendezvous, but NCCL's all-reduce between nodes wants the RDMA fabric (InfiniBand or RoCE, usually one 400 Gb/s card per GPU: {{Cluster anatomy|n:3fc5c17b0d0d816a871df56477fc83b2}}). With no RDMA device in the container NCCL prints NET/IB : No device found. and carries on over sockets, much slower and without an error ({{Launching distributed training|n:3fc5c17b0d0d81b3a8a5c58224bff9fa}}). Two things must be added to the pod: the RDMA device and a network interface on the fabric.

A training pod with two networks: the pod network for names, the RDMA fabric for NCCL

The GPUs come from the GPU device plugin (section 4); the RDMA device from a second device plugin (the RDMA shared device plugin, or the SR-IOV network device plugin, which hands each pod its own virtual function of the NIC); the second interface, net1, from Multus, a CNI "meta-plugin" that calls further CNI plugins for each network the pod's annotation k8s.v1.cni.cncf.io/networks names (a NetworkAttachmentDefinition object) ({{Multus CNI|https://github.com/k8snetworkplumbingwg/multus-cni}} v4.3.1 docs). Not run here: the kind cluster has no RDMA hardware.

  • The simple way: hostNetwork: true. The pod sees every host interface, RDMA NICs included; it gives up network isolation and port separation between pods, which is acceptable on nodes that run one training pod each.
  • The managed way: the NVIDIA Network Operator (v26.7.1, 2026-10-16 vendor), the networking counterpart of the GPU Operator. Its NicClusterPolicy installs the NIC driver container, the RDMA shared device plugin or the SR-IOV network device plugin, Multus and the secondary-network CNI plugins (macvlan, host-device, IP over InfiniBand) and an IP address manager, so that "RDMA and GPUDirect RDMA workloads" run in the cluster ({{Mellanox/network-operator README|https://github.com/Mellanox/network-operator}} vendor). A pod then requests, next to nvidia.com/gpu: 8, a resource such as rdma/hca_shared_devices_a: 1 (the plugin's example name) and names the secondary network in its annotation.
  • How to check: inside the pod, ibv_devices lists the RDMA devices and ip addr shows net1; with NCCL_DEBUG=INFO the log must say NET/IB, not NET/Socket; set NCCL_NET=IB to turn a silent fallback into an error.

The fabric itself (InfiniBand against RoCE, rails, GPUDirect RDMA) is on {{Interconnects and scaling|n:3c65c17b0d0d81808563fd41fb163af0}}; NCCL's variables on Launching distributed training.
