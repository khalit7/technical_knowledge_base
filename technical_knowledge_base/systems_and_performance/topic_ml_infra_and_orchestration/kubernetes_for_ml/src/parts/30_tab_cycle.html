Scheduling cycle: one pod at a time, every plugin, every node

The kube-scheduler of this topic's kind cluster placed the same six pods twice, once under the default profile and once under a bin-packing profile, while logging every plugin's score for every node (--vmodule=schedule_one=10, which reaches the V(10) lines at pkg/scheduler/schedule_one.go lines 980-1052 at v1.37.0). Step through the cycle of each pod: Filter removes nodes, Score ranks the rest, the highest total wins, Bind writes the result. Every score shown is the scheduler's logged value; a check mark means src/recompute.py computed the same number from the node's state with the ported formulas. Reading section {{3|#t-read}} explains the plugins.

Workers have 5 CPUs, 9.7 GiB and 4 fake GPUs each (as the nodes report them; the containers are capped lower, which the scheduler does not see). Every pod requests 100m CPU and 64Mi. The control plane is filtered by its taint node-role.kubernetes.io/control-plane:NoSchedule. TaintToleration gives every untainted node 100, weight 3 (300); ImageLocality logged 0 for every node in both runs; the page does not explain why (not investigated). In "your own sequence" the formulas are the same ported code, and a tie goes to the first node in name order; the real scheduler draws at random (framework/sorted_nodes.go lines 61-64).

The profile that ran

apiVersion: kubescheduler.config.k8s.io/v1
kind: KubeSchedulerConfiguration
clientConnection:
  kubeconfig: /etc/kubernetes/scheduler.conf
leaderElection:
  leaderElect: true
profiles:
- schedulerName: default-scheduler
- schedulerName: km-binpack
  pluginConfig:
  - name: NodeResourcesFit
    args:
      scoringStrategy:
        type: MostAllocated
        resources:
        - {name: cpu, weight: 1}
        - {name: memory, weight: 1}
        - {name: example.com/gpu, weight: 5}

src/k8s/km-sched-config.yaml, mounted into kind's kube-scheduler static pod with --config by src/scripts/km_sched_reconf.sh for the runs and removed after (the original manifest restored and checked identical). A pod chooses the profile with spec.schedulerName: km-binpack.

The formulas

LeastAllocated
per resource ⌊(capacity − requested) × 100 / capacity⌋, then the weighted mean, rounded down; requested counts a container with no request as 100m CPU and 200 MiB (least_allocated.go lines 52-60, scheduler/util/pod_resources.go lines 28-31)
MostAllocated
per resource ⌊requested × 100 / capacity⌋, weighted mean (most_allocated.go lines 54-65)
BalancedAllocation
50 + ⌊(50 + swith pod − swithout) / 2⌋, s = ⌊(1 − σ) × 100⌋, σ the spread of the CPU and memory fractions (balanced_allocation.go lines 204-262)
total
3 × TaintToleration + 1 × NodeResourcesFit + 1 × BalancedAllocation + 1 × ImageLocality (+ 2 × the affinity and spread plugins, 0 here)
