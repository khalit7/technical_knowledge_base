3. Checkpoint-time calculator: from this laptop to 16,384 GPUs

At scale the measurement turns into arithmetic. Three numbers decide how long a checkpoint stops training: its size, the slowest pipe it must squeeze through (one node's link for a consolidated write; all the nodes' links or the storage system's aggregate bandwidth, whichever is smaller, for a sharded one), and, for asynchronous checkpointing, the copy of each GPU's shard to host memory. Everything below is derived from the inputs; each tier's number says where it comes from.

Checkpoint size
Each GPU's shard
Sharded write pipe
Bandwidth for the target

tconsolidated = S / min(link, B)   tsharded = S / min(B, nodes × link)   tasync stop = (S / GPUs) / copy
S
checkpoint size = parameters x bytes per parameter
B
the storage system's aggregate write bandwidth
link
one node's network bandwidth to storage (default 50 GB/s, one 400 Gb/s port; a DGX B200 has two)
copy
GPU to host memory per GPU (default 63 GB/s, PCIe Gen5 x16 nominal; real copies reach less)

Defaults check: 405B at 14 bytes on 16,384 GPUs gives 5.67 TB, 346 MB per GPU (inside Llama 3's stated 1 MB to 4 GB per GPU) and 2.8 s at Tectonic's 2 TB/s sustained. Simplifications, said plainly: no metadata or file-creation cost, no gather time for the consolidated write, perfect parallelism, and a store that sustains its rated bandwidth under a burst (Meta built Tectonic's 7 TB/s peak for exactly this). The formulas are recomputed in src/io/recompute.py.
