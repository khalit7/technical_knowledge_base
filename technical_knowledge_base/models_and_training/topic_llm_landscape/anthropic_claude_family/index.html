The idea in one screen

Claude is one closed-weight recipe, aligned with Constitutional AI and trained hard with agentic RL, sold at four price rungs; its API is built around a model that decides for itself how long to think and must see an append-only history, so an agent's bill is set by the cache-read price and by how many tokens the caller's effort level lets it write.

What Anthropic chose, what it publishes, and what the caller still controls

Solid boxes are published (papers, docs, price list); dashed boxes are undisclosed; RLVR and agentic RL are named in release posts but never specified. Prices are dollars per million input and output tokens, read 19 October 2026 (pricing). Anthropic publishes no parameter count and no architecture for any Claude model.

You need: what thinking tokens are and why they cost money (Test-time compute and reasoning, sections 1 and 7), and prompt caching as an idea (Context engineering; its economics across providers on Caching, section 11). The RL methods are taught in RL for LLMs; this page names what Anthropic chose.

Tier, or rung
Haiku (fast, cheap), Sonnet (the balanced default), Opus (complex, long-running agentic work), Fable (the most capable generally available model). Named sizes and prices, not architectures.
Mythos class
The tier above Opus that appeared in 2026. Fable is its generally available model; Mythos is the same model under looser safeguards, restricted to vetted organisations.
Adaptive thinking
The model decides, per request and per step, whether to think and for how long.
Effort
The caller's coarse level, low to max, that steers how many tokens the model writes. Guidance, not a budget.
Thinking block, signature
Reasoning tokens returned in thinking blocks and billed as output; each carries a signature, an encrypted copy of the full reasoning that must be passed back unmodified.
Cache read, cache write
Storing a prompt prefix (write, 1.25 times the input price) so later requests re-read it (read, a few per cent of the input price).

2023: Constitutional AI and long context. Anthropic was founded in 2021 by former OpenAI safety leadership (Wikipedia) on the bet that the expensive human-preference step in RLHF could largely be replaced by the model judging itself against written principles (Training). Claude 1 was announced on 14 March 2023 (Anthropic); in May its context grew from 9K to 100K tokens (Anthropic), well ahead of rivals, and Claude 2.1 (21 November 2023) doubled it to 200K (Anthropic). Document-heavy work was the early niche.

2024: the three-tier ladder, and post-training over size. Claude 3 (March 2024) named Haiku, Sonnet and Opus as a size, price and latency ladder from one training programme, now the industry default (Anthropic). Claude 3.5 Sonnet then beat the larger 3 Opus on Anthropic's internal agentic coding evaluation, 64% against 38%, at twice the speed and $3 and $15 per million tokens (Anthropic): the first clear public sign that post-training and data had overtaken parameter count for coding. The upgraded 3.5 Sonnet (22 October 2024) shipped computer use, screenshots in and mouse and keyboard actions out, the first production API for GUI agents (Anthropic).

2025: hybrid reasoning with a caller's budget, then agentic coding. Claude 3.7 Sonnet (February) put both modes in one checkpoint: the same weights answer at once or think first, and the caller set a budget_tokens cap per request, up to the 128K output limit (Anthropic). It was the deliberate counter-design to OpenAI's router: the caller owned the cost decision instead of a classifier it could not inspect, and with one model there was no capability jump between the fast and slow paths, at the price of having to know which tasks needed thinking. Claude 4 to 4.5 then aimed at long-horizon tool use: interleaved thinking between tool calls (beta with Claude 4, Anthropic), file-backed memory that survives beyond the context (the memory tool and context editing with Sonnet 4.5, Anthropic), and a 1M-token context beta (Sonnet 4, August 2025, Anthropic). Opus 4.5 (24 November) cut the Opus price from $15 and $75 to $5 and $25 and introduced effort: at medium effort it matched Sonnet 4.5's best SWE-bench Verified score with 76% fewer output tokens, and closed 2025 on top of the coding benchmarks (Anthropic).

Early 2026: the model takes over the thinking decision. Opus 4.6 (5 February) brought adaptive thinking steered by effort and deprecated the manual budget (Anthropic); from Opus 4.7 (16 April) a request carrying budget_tokens is rejected (thinking docs), as are non-default temperature, top_p and top_k (model deprecations). Opus 4.7 also added xhigh and a new tokenizer that counts the same text as more tokens (Anthropic: 1.0 to 1.35 times, Anthropic; the pricing page: "approximately 30%"). Every 4.6-and-later model now bills its full 1M window at the standard rate (pricing).

2026: the Mythos class and safeguards as configuration. Claude Mythos Preview (7 April) was withheld from general release for its ability to find and exploit software vulnerabilities and offered only to Project Glasswing's infrastructure and security partners (Anthropic). Fable 5 and Mythos 5 (9 June) made it a tier above Opus, the first break in the three-name ladder since Claude 3: one underlying model, Fable with classifiers that route sensitive cybersecurity, biology and distillation requests to Opus 4.8, Mythos without them for approved partners (Anthropic). Fable 5.1 and Mythos 5.1 (1 September) repeated the pattern and brought preserved thinking and a 75% cut to cached input (Anthropic).

The pattern. Twice in 2026 the tier below caught the top within weeks: Opus 5 came "close to the frontier intelligence of Claude Fable 5 at half the price" (Anthropic), and Opus 5.5 beat Fable 5.1 on every row of Anthropic's table three weeks after it, at 40% of its list price (Anthropic). Evaluation moved with the models, from single answers to SWE-bench and Terminal-Bench, which reward recovering from failure (what they measure: Agentic benchmarks).

How Claude is trained: what is published

Only the alignment stage is described in a paper; the stages that make the agentic lead are named, not detailed

Stage contents from Bai et al., 2022 (the two Constitutional AI phases) and Anthropic's release posts (RLVR and agentic RL are named there, never specified). The step-by-step mechanism, with the paper's numbers and its released critique chains replayed, is on the Constitutional AI paper page.

Constitutional AI is Anthropic's structured RLAIF (reinforcement learning from AI feedback) in two phases (Bai et al., 2022). Supervised: the model critiques and revises its own answers against principles from a short written constitution (16 about harmlessness in the paper, one drawn at random each step), and is fine-tuned on the revisions. RL: a feedback model picks the better of two answers under a principle, and those AI labels replace human harmlessness rankings. Only the harmlessness labels were AI-written; helpfulness labels stayed human, mixed into one hybrid preference model. Anthropic published a new, much longer constitution for Claude in January 2026 (Anthropic).

What it buys is scale and auditability: harmlessness labels stop being the human bottleneck, and the values are a document you can read, diff and argue with. What it costs is that the judge shares the model's blind spots, so the constitution has to carry the work that disagreement between humans used to.

On top sit RLVR, where a program checks the answer (a test suite, a maths grader) and cannot be flattered, and heavy agentic RL, where an episode is a whole task in a sandbox with real tools and the reward is whether the task ended up done (the algorithms: RL for LLMs). That is the expensive part and the likeliest source of the family's agentic lead: the environments, not the objective, are the moat. The lead shows from outside on METR's measurements, where six of the record-setting time horizons between June 2024 and April 2026 belong to Claude models (Task length).

What Anthropic publishes is unusually detailed system cards, alignment evaluations and interpretability research, and almost nothing about architecture. Circuit tracing replaces the MLP layers with a cross-layer transcoder of sparse, readable features and traces which features drove one output (an attribution graph for one behaviour), applied to Claude 3.5 Haiku (Anthropic, March 2025). The introspection work injects a concept's activation pattern and asks whether the model notices: Claude Opus 4.1 did in about 20% of trials at the best layer and strength, and "failures of introspection remain the norm" (Anthropic, October 2025). The asymmetry: you can learn a great deal about what these models do and essentially nothing about how they are built.

Thinking: from the caller's budget to the model's choice

The same request, before and after: who decides how long the model thinks

Adaptive thinking. On Opus 5.5, Fable 5.1 and Mythos 5.1 it is always on and cannot be disabled; on Sonnet 5.5 and Haiku 5.5 it is the thinking mode, at default effort high and medium respectively; on Opus 4.6 to 4.8 and Sonnet 4.6 it is off until you ask. Of the callable models only Haiku 4.5 (and the older Opus 4.5 and Sonnet 4.5) still use thinking: {type: "enabled", budget_tokens: N} (thinking docs).

Effort (output_config.effort: low, medium, high, xhigh, max) is a behavioural signal, not a token budget: it scales every output token (thinking, text and tool calls, so lower effort also means fewer and terser tool calls), and at low effort the model still thinks on a hard enough problem, just less. The hard ceiling is max_tokens, which bounds thinking plus response together. The default is high on most models and medium on Opus 5.5, so a request that omits effort runs one level lower on Opus 5.5 than it did on Opus 5 (effort docs).

Interleaved thinking, reasoning about each tool result before acting on it, is automatic under adaptive thinking; Haiku 4.5 does not support it. What you see is not what you pay for: you never receive the raw chain of thought. With display: "summarized" a thinking block holds a summary written by a different model; with "omitted", the default on the 5.x models, it is empty. Either way every thinking token is billed as output.

Sampling knobs went the same way. API version 2026-10-21, the first new anthropic-version since 2023-06-01, returns a 400 for temperature, top_p or top_k "even at the parameter's default value"; every request samples at the defaults (temperature 1.0), as Claude 4.7 and later models already required, while on an older model such as Sonnet 4.6 a lowered temperature simply stops having an effect. 2023-06-01 is not deprecated, so a request that depends on non-default sampling can stay on it. The new SDK majors (Python 2.0.0, TypeScript 1.0.0, Go 2.0.0, Java 3.0.0 and the rest) send the new version by default, send the key as Authorization: Bearer instead of X-Api-Key (the API accepts either, but a proxy that reads X-Api-Key must change), and are licensed Apache 2.0 instead of MIT (migration guide). Who controls sampling is now the provider's call, the same move the thinking budget made earlier in 2026.

Preserved thinking: why the history must be append-only

Within a tool-use turn, every thinking block must be passed back complete and unmodified with its tool_use block, or the model loses the reasoning that led to the call; a modified block is rejected with a 400 error. On current Opus and Sonnet models and the Mythos class, earlier turns' thinking blocks stay in context (and in the cache) and are billed as input; on Haiku 4.5 and older they are stripped once a new user message arrives (thinking docs). Preserved thinking, introduced with Fable 5.1 and extended to Opus 5.5 and Sonnet 5.5, adds two checks to the signature (preserved thinking docs):

  • Which model produced the block. Fable 5.1 and Mythos 5.1 read every earlier model's blocks and no earlier model reads theirs; Opus 5.5 reads Opus 5 and earlier Opus, Sonnet and Haiku blocks; Sonnet 5.5 reads Sonnet 5, Opus 4.8, Haiku 4.5 and earlier. A block the current model cannot read is dropped silently and not billed.
  • Whether everything before it is unchanged: system prompt, tools and every earlier message. If the prefix changed, that block and every later one are invalid, and the API rejects the request with a 400 error or drops the invalid blocks (unbilled, though the model may think more to rebuild the reasoning), as the caller chooses.

Append-only, or what an edit costs: the same instruction kills or keeps the reasoning depending on where it goes

An agent conversation as the API sees it. Apply one change before the next request and watch which thinking blocks survive and where the prompt cache stops matching. Block sizes are illustrative; the rules are from the preserved thinking and prompt caching docs.

Predict, then try: "Edit the system prompt in place", then "Add a mid-conversation system message instead". The same instruction reaches the model either way; only the second keeps the reasoning and the cache.

Anthropic states the purpose as anti-distillation: without the checks, someone could take a thinking block from an expensive model, edit the conversation before it, and reuse the reasoning to train or steer a cheaper one (the technique: Distillation and small language models). Its September threat report (10 September 2026) lists illicit distillation among the seven kinds of misuse it disrupted (Anthropic). The prefix check is enforced by default for API accounts created on or after 31 August 2026 and is opt-in on older ones; Sonnet 5.5 also ties its blocks to the account that produced them.

The consequence for a harness builder: the conversation has to be append-only. Instructions, tool changes and effort changes go in as new messages at the end (mid-conversation system messages, tool_addition and tool_removal blocks, per-message effort, server-side compaction and context editing). Cost per task is steered rather than set: effort is the dial and max_tokens the fuse. This is also why Claude-based harnesses such as Claude Code do well on long-horizon coding evaluations: the model is built to think again after every observation.

What one agent session costs

An agent re-reads the same long context every turn. Take a 100,000-token prefix (system prompt, tools, files already read), 50 turns, 5,000 new input tokens and 2,000 output tokens (thinking included) per turn. The bill splits into four parts: writing the prefix to the cache once, re-reading it each turn, the new input, and the output:

The formula holds the prefix fixed and the cache warm (each read refreshes it), which understates a real session whose context grows, but isolates the price list. The Session cost tab frees every input and runs the growing version on every model.

Turn by turn, the context grows and caching turns most of it from full price into cheap reads

What it shows. On Fable 5 the cached prefix was 40% of each turn's cost ($0.10 of $0.25); after the 5.1 cut it is 14% ($0.025 of $0.175), and output, thinking included, is 57%. The cache cut alone makes the same session 27% cheaper, in line with Anthropic's "around 25% for typical workloads"; without caching at all, Fable 5.1 costs almost six times as much. Once caching is cheap, the lever left is how many tokens the model writes, which is what effort controls. And a cheaper model that needs more tokens can cost more per task: on Artificial Analysis's runs Sonnet 5.5 at max effort costs $7.62 per index task against Opus 5.5's $5.98 at half the per-token price, because it used 1.6 times the output tokens and 1.7 times the input (Effort and cost per task).

Thinking and effort: per-model details

Changing effort mid-conversation. On Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5 and Sonnet 5.5, a per-message setting (beta: an empty system message carrying the new output_config.effort) changes it from the next user turn and keeps the prompt cache. Changing the top-level value between requests restarts the cache, because effort is rendered into the prompt itself (effort docs).

Progress updates. The newest models (Fable 5.1, Mythos 5.1, Opus 5.5, Sonnet 5.5, Fable 5) write short progress updates between tool calls, notes for the person watching the agent rather than reasoning, and fewer of them at higher effort; a beta display: "updates" shows only those. On Fable 5.1, Opus 5.5, Sonnet 5.5 and Fable 5 a prompt that tries to pull the reasoning into the visible answer can be refused as reasoning_extraction (thinking docs).

Sonnet 5.5's effort. Its docs suggest starting agentic coding at medium effort; its thinking can be reduced to between_tools (accepted at high effort or below) when up-front deliberation is not worth paying for, and its levels are recalibrated against Sonnet 5.

Preserved thinking and other labs. Preserved thinking narrows what a neutral harness can replay or reconstruct from a transcript: the same direction as GPT-6 Astra's recurrent depth, for a different reason (detail on OpenAI: GPT family). Preserved thinking extends Anthropic's publishing asymmetry to the reasoning itself, which is summarised or hidden and now also protected against extraction.

Model IDs, lifecycle, tokenizer and older models

Snapshots. Every ID (claude-opus-5-5) is a pinned snapshot whose behaviour does not change under you. From the 4.6 generation IDs carry no date; earlier ones do (claude-haiku-4-5-20251001) (models overview). Lifecycle: active, legacy (served, no longer updated), deprecated (a retirement date is set) or retired (requests fail). Anthropic gives at least 60 days' notice before retiring a public model, and every current model's retirement is set for not sooner than one year after its release (model deprecations). Sonnet 4.5 was deprecated on 30 September 2026 and retires on 30 November: 61 days.

Tokenizer. Claude Opus 4.7 and later use the newer tokenizer, about 30% more tokens for the same text; Sonnet 4.6, Haiku 4.5 and earlier use the old one (pricing). 1M tokens is about 555K English words on the new tokenizer and about 750K on the old (models overview). Haiku 4.5, now legacy, keeps its 200K window, 64K output limit, February 2025 cutoff and the older tokenizer.

Business shape volatile

Revenue skews to API, enterprise and coding against OpenAI's consumer skew, which explains the product priorities: agentic tooling, long context and reliability over voice, image generation and consumer surface area. The restricted Mythos releases add a second shape: capability sold first to vetted security and life-sciences organisations, with a safeguarded twin for everyone else.

The scale, as reported rather than filed: the IPO prospectus shows 2025 revenue of nearly $4.6 billion against operating losses above $8 billion, with about a quarter of revenue from two customers, and an investor presentation reported by the Financial Times put third-quarter 2026 revenue at $16.8 billion, up from about $11.6 billion in the second quarter (TechStartups on the FT report). The Wall Street Journal, reading a confidential draft S-1 (reported 20 October 2026; no public filing on EDGAR as of 26 October), gives first-half 2026 revenue of $16.3 billion against $1.1 billion a year earlier, and a net loss of $80.7 billion of which about $72 billion is a non-cash fair-value charge on convertible notes and other financing instruments (Investing.com on the WSJ report); draft figures can change before filing. Anthropic's tally counts sales made through its cloud partners and OpenAI's does not, so the two labs' revenue figures are not directly comparable (Axios). On 18 October 2026 Anthropic committed 5% of its shares, subject to stockholder approval, to a new Anthropic Public Benefit Fund, with 2% more for each 50% rise in value above a baseline (Anthropic).

Common mistakes
  • Sending budget_tokens to a current model: a 400 error on Opus 4.7 and everything after; steer with effort and cap with max_tokens.
  • Assuming hidden thinking is free: with the default display: "omitted" the thinking text is empty but every thinking token is billed as output.
  • Comparing per-token prices across tokenizers: Opus 4.7 and later count the same text as about 30% more tokens than Sonnet 4.6, Haiku 4.5 and earlier, so per-token prices understate how much cheaper Haiku 4.5 is per word. Compare cost per task.
  • Carrying effort settings across models: Opus 5.5 defaults to medium where Opus 5 defaulted to high; rerun an effort sweep on your own evaluations.
  • Quoting a benchmark number without its harness: Anthropic's Opus 5.5 figures are at max effort except Terminal-Bench 4.0 (xhigh), OSWorld comes in 2.0 and 2.1 versions and in partial and strict scoring, and GDPval-AA v2 and v2.1 sit on different Elo anchors.
  • Carrying an old index score forward: the roughly 63 and 62 Artificial Analysis figures belong to Opus 5 and Fable 5 on the pre-v4.2 scale.

Effort and cost per task

Artificial Analysis runs each model through its Intelligence Index (v4.3, methodology 4.3.2, read 1 October 2026) and reports the score, the cost per index task and the tokens it used (leaderboard). Effort settings of the same model are joined by a line. Cost is on a log scale.

One run taken apart

The cost of a whole index run splits into output (published output tokens times the output price), cached input and uncached input. Artificial Analysis does not publish the cache-hit share it assumes ("live measurements of the model's typical cache hit rate", methodology), so the share below is fitted: the value that makes the three parts add up to its published run cost. The split therefore reproduces Artificial Analysis by construction.

Try: Run "Sonnet 5.5 (max)", price it at Opus 5.5: half the per-token price did not make it cheaper per task, because it used more tokens. Then run "Fable 5.1 (max)" priced at Fable 5: the old cache price makes the same run about 31% dearer.

Task length: how long a task each model can finish

METR measures a model's 50% time horizon: the length of task, timed by how long it takes skilled humans, that the model completes half the time. The data are METR's own (METR-Horizon-v1.1, updated 8 May 2026, raw data, METR); no Claude 5.x model has been measured yet. The fitted line is an ordinary least-squares fit of log2(horizon) on release date over the points you select, and its slope gives the doubling time.
