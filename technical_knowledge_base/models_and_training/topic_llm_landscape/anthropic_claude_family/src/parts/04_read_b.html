How Claude is trained: what is published

Only the alignment stage is described in a paper; the stages that make the agentic lead are named, not detailed

Stage contents from {{Bai et al., 2022|@cai}} (the two Constitutional AI phases) and Anthropic's release posts (RLVR and agentic RL are named there, never specified). The step-by-step mechanism, with the paper's numbers and its released critique chains replayed, is on the {{Constitutional AI paper page|n:3c65c17b0d0d815a9b31e9443961c700}}.

Constitutional AI is Anthropic's structured RLAIF (reinforcement learning from AI feedback) in two phases ({{Bai et al., 2022|@cai}}). Supervised: the model critiques and revises its own answers against principles from a short written constitution (16 about harmlessness in the paper, one drawn at random each step), and is fine-tuned on the revisions. RL: a feedback model picks the better of two answers under a principle, and those AI labels replace human harmlessness rankings. Only the harmlessness labels were AI-written; helpfulness labels stayed human, mixed into one hybrid preference model. Anthropic published a new, much longer constitution for Claude in January 2026 ({{Anthropic|@const26}}).

What it buys is scale and auditability: harmlessness labels stop being the human bottleneck, and the values are a document you can read, diff and argue with. What it costs is that the judge shares the model's blind spots, so the constitution has to carry the work that disagreement between humans used to.

On top sit RLVR, where a program checks the answer (a test suite, a maths grader) and cannot be flattered, and heavy agentic RL, where an episode is a whole task in a sandbox with real tools and the reward is whether the task ended up done (the algorithms: {{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}). That is the expensive part and the likeliest source of the family's agentic lead: the environments, not the objective, are the moat. The lead shows from outside on METR's measurements, where six of the record-setting time horizons between June 2024 and April 2026 belong to Claude models (Task length).

What Anthropic publishes is unusually detailed system cards, alignment evaluations and interpretability research, and almost nothing about architecture. Circuit tracing replaces the MLP layers with a cross-layer transcoder of sparse, readable features and traces which features drove one output (an attribution graph for one behaviour), applied to Claude 3.5 Haiku ({{Anthropic, March 2025|@circ}}). The introspection work injects a concept's activation pattern and asks whether the model notices: Claude Opus 4.1 did in about 20% of trials at the best layer and strength, and "failures of introspection remain the norm" ({{Anthropic, October 2025|@intro}}). The asymmetry: you can learn a great deal about what these models do and essentially nothing about how they are built.

Thinking: from the caller's budget to the model's choice

The same request, before and after: who decides how long the model thinks

Adaptive thinking. On Opus 5.5, Fable 5.1 and Mythos 5.1 it is always on and cannot be disabled; on Sonnet 5.5 and Haiku 5.5 it is the thinking mode, at default effort high and medium respectively; on Opus 4.6 to 4.8 and Sonnet 4.6 it is off until you ask. Of the callable models only Haiku 4.5 (and the older Opus 4.5 and Sonnet 4.5) still use thinking: {type: "enabled", budget_tokens: N} ({{thinking docs|@think}}).

Effort (output_config.effort: low, medium, high, xhigh, max) is a behavioural signal, not a token budget: it scales every output token (thinking, text and tool calls, so lower effort also means fewer and terser tool calls), and at low effort the model still thinks on a hard enough problem, just less. The hard ceiling is max_tokens, which bounds thinking plus response together. The default is high on most models and medium on Opus 5.5, so a request that omits effort runs one level lower on Opus 5.5 than it did on Opus 5 ({{effort docs|@effort}}).

Interleaved thinking, reasoning about each tool result before acting on it, is automatic under adaptive thinking; Haiku 4.5 does not support it. What you see is not what you pay for: you never receive the raw chain of thought. With display: "summarized" a thinking block holds a summary written by a different model; with "omitted", the default on the 5.x models, it is empty. Either way every thinking token is billed as output.

Sampling knobs went the same way. API version 2026-10-21, the first new anthropic-version since 2023-06-01, returns a 400 for temperature, top_p or top_k "even at the parameter's default value"; every request samples at the defaults (temperature 1.0), as Claude 4.7 and later models already required, while on an older model such as Sonnet 4.6 a lowered temperature simply stops having an effect. 2023-06-01 is not deprecated, so a request that depends on non-default sampling can stay on it. The new SDK majors (Python 2.0.0, TypeScript 1.0.0, Go 2.0.0, Java 3.0.0 and the rest) send the new version by default, send the key as Authorization: Bearer instead of X-Api-Key (the API accepts either, but a proxy that reads X-Api-Key must change), and are licensed Apache 2.0 instead of MIT ({{migration guide|https://platform.claude.com/docs/en/api/migration-2026-10-21}}). Who controls sampling is now the provider's call, the same move the thinking budget made earlier in 2026.

Preserved thinking: why the history must be append-only

Within a tool-use turn, every thinking block must be passed back complete and unmodified with its tool_use block, or the model loses the reasoning that led to the call; a modified block is rejected with a 400 error. On current Opus and Sonnet models and the Mythos class, earlier turns' thinking blocks stay in context (and in the cache) and are billed as input; on Haiku 4.5 and older they are stripped once a new user message arrives ({{thinking docs|@think}}). Preserved thinking, introduced with Fable 5.1 and extended to Opus 5.5 and Sonnet 5.5, adds two checks to the signature ({{preserved thinking docs|@pres}}):

  • Which model produced the block. Fable 5.1 and Mythos 5.1 read every earlier model's blocks and no earlier model reads theirs; Opus 5.5 reads Opus 5 and earlier Opus, Sonnet and Haiku blocks; Sonnet 5.5 reads Sonnet 5, Opus 4.8, Haiku 4.5 and earlier. A block the current model cannot read is dropped silently and not billed.
  • Whether everything before it is unchanged: system prompt, tools and every earlier message. If the prefix changed, that block and every later one are invalid, and the API rejects the request with a 400 error or drops the invalid blocks (unbilled, though the model may think more to rebuild the reasoning), as the caller chooses.

Append-only, or what an edit costs: the same instruction kills or keeps the reasoning depending on where it goes

An agent conversation as the API sees it. Apply one change before the next request and watch which thinking blocks survive and where the prompt cache stops matching. Block sizes are illustrative; the rules are from the {{preserved thinking|@pres}} and {{prompt caching|@cache}} docs.

Predict, then try: "Edit the system prompt in place", then "Add a mid-conversation system message instead". The same instruction reaches the model either way; only the second keeps the reasoning and the cache.

Anthropic states the purpose as anti-distillation: without the checks, someone could take a thinking block from an expensive model, edit the conversation before it, and reuse the reasoning to train or steer a cheaper one (the technique: {{Distillation and small language models|n:3c65c17b0d0d81efa2a8c3b3b623eb09}}). Its September threat report (10 September 2026) lists illicit distillation among the seven kinds of misuse it disrupted ({{Anthropic|@threat}}). The prefix check is enforced by default for API accounts created on or after 31 August 2026 and is opt-in on older ones; Sonnet 5.5 also ties its blocks to the account that produced them.

The consequence for a harness builder: the conversation has to be append-only. Instructions, tool changes and effort changes go in as new messages at the end (mid-conversation system messages, tool_addition and tool_removal blocks, per-message effort, server-side compaction and context editing). Cost per task is steered rather than set: effort is the dial and max_tokens the fuse. This is also why Claude-based harnesses such as {{Claude Code|n:3c65c17b0d0d81db9c7fc54987c1ab65}} do well on long-horizon coding evaluations: the model is built to think again after every observation.
