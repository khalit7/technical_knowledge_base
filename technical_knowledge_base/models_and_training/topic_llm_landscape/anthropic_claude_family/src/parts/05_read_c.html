What one agent session costs

An agent re-reads the same long context every turn. Take a 100,000-token prefix (system prompt, tools, files already read), 50 turns, 5,000 new input tokens and 2,000 output tokens (thinking included) per turn. The bill splits into four parts: writing the prefix to the cache once, re-reading it each turn, the new input, and the output:

C=Pw+T(Pc+Ni+Oo)106
C
session cost in dollars
P, T
cached prefix in tokens (100,000); number of turns (50)
N, O
new, uncached input per turn (5,000); output per turn, thinking included (2,000)
w, c, i, o
5-minute cache-write price (1.25 times input), cache-read price, input price and output price, all in dollars per million tokens

The formula holds the prefix fixed and the cache warm (each read refreshes it), which understates a real session whose context grows, but isolates the price list. The Session cost tab frees every input and runs the growing version on every model.

The worked example on each model: one 50-turn session, the fixed prefix cached

Per turn is one turn's cache read, new input and output; the bars split one such turn on Fable 5 and on Fable 5.1, before and after the 75% cut to its cache-read price.

In a real session the context does not stay fixed. Turn by turn, the context grows: each turn's input and output (thinking included, since current models keep it in context) join what the next request sends, and with automatic caching each request reads everything the previous one cached and writes only what is new. Fig. 6 runs that session for 16 turns with the same P, N and O, priced on the model you pick. Prices from the {{pricing page|@pricing}}; the growing-context accounting is this page's model of {{automatic caching|@cache}}, not a figure Anthropic publishes.

Fig. 6, step by step: one column per turn, height in tokens (steps 1 to 4), then in dollars (steps 5 and 6, rescaled at step 6 to fit the session without the cache)

  1. Turn 1: write the prefix. The 100,000-token prefix and the first 5,000 tokens of input are written to the cache at 1.25 times the input price (gold), and the model writes 2,000 tokens of output, thinking included (purple). Writing costs more than sending once; it pays back on the first read.
  2. Turn 2: read it back. Everything already cached, 105,000 tokens, is read at the cache-read price (green dots: the history carried forward). Only what is new since the last request, last turn's output and this turn's input (7,000 tokens), is written.
  3. Turns 3 to 16: the context grows. Each turn adds 7,000 tokens, so the green read grows while the gold write and the purple output stay the same. By turn 16 the request holds 210,000 tokens, 203,000 of them read from the cache.
  4. A 200K window fills. The glass plane is Haiku 4.5's 200,000-token window: turn 15's request would hold 203,000 tokens, so on Haiku 4.5 the session cannot continue past turn 14 without compaction. The 1M-token models' window is five times higher, far above the frame.
  5. The same columns in dollars. On Opus 5.5 turn 1 costs $0.565, almost all of it the write; turn 16 costs $0.116, and its 203,000 cached tokens are only 35% of that. Cached, the 16 turns cost $2.15.
  6. Without the cache. The back row bills every turn's whole context at the full input price, and the bill per turn grows with the context: the same 16 turns cost $10.72, 5.0 times the cached session. Output is now the largest line that effort, not the price list, controls.

What it shows. On Fable 5 the cached prefix was 40% of each turn's cost ($0.10 of $0.25); after the 5.1 cut it is 14% ($0.025 of $0.175), and output, thinking included, is 57%. The cache cut alone makes the same session 27% cheaper, in line with Anthropic's "around 25% for typical workloads"; without caching at all, Fable 5.1 costs almost six times as much. Once caching is cheap, the lever left is how many tokens the model writes, which is what effort controls. And a cheaper model that needs more tokens can cost more per task: on Artificial Analysis's runs Sonnet 5.5 at max effort costs $7.62 per index task against Opus 5.5's $5.98 at half the per-token price, because it used 1.6 times the output tokens and 1.7 times the input (Effort and cost per task).

Cache reads cost 10% of the base input price on most models (Haiku 5.5 included), 5% on Opus 5.5 and Sonnet 5.5 and 2.5% on Fable 5.1 and Mythos 5.1; a 5-minute cache write costs 1.25 times the input price (the 1-hour cache, 2 times), and the Batch API halves input and output prices, stacking with the cache multipliers.
