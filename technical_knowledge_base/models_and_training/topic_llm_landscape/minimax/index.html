The idea in one sentence
MiniMax, a Shanghai lab founded in December 2021 (Wikipedia), has run one experiment three times at production scale: replace most softmax attention with linear attention (MiniMax-01, M1), go back to full attention when exact recall broke at scale (M2), then keep full attention's cache but let each query read only 16 selected blocks (M3), in every layer from M3.1 Flash on.

You need: GQA and trained sparse attention (DSA, NSA) from Attention variants; linear attention and hybrids from Beyond attention; KV-cache sizing from Long context; the PPO clip and GRPO from RL for LLMs. This page says what MiniMax chose, with its numbers, and explains its own variants in full.

Lightning attention (MiniMax-01, M1): linear attention computed in blocks

The bill being attacked. Softmax attention forms an n × n score matrix, so prefill costs on the order of n2d per head, and every decoded token reads the whole KV cache: 2 · Hkv · dh · b bytes per token per layer (key and value, KV heads, head dimension, 2 bytes in BF16; Long context owns the sizing). Linear attention drops the softmax, so (QK⊤)V = Q(K⊤V): a fixed d × d state St = St−1 + kt⊤vt replaces the cache, and ot = qtSt (Beyond attention owns the recurrence and its gated successors).

Lightning attention is MiniMax's IO-aware way of computing it: a kernel contribution, not a new mathematical form (MiniMax-01 report, arXiv 2501.08313). Computed token by token, causal linear attention is a cumulative sum along the sequence, which serialises the very dimension a GPU wants to parallelise. Lightning cuts the sequence into blocks and splits each block's output in two: inside the block, the ordinary masked quadratic product (the report's "left product", small and parallel); from all earlier blocks, one multiplication by the carried state (the "right product").

Predict, then watch: four tokens with scalar q = (1, 2, 1, 3), k = (1, 1, 2, 1), v = (2, 1, 1, 3). Token by token the running sums are 2, 3, 5, 8, so o = (2, 6, 5, 24). How many dependent steps does each way take? Fig. 3 plays both.

  1. Four tokens. Each purple bar is a token's k · v = 2, 1, 2, 3: what linear attention adds to its state. The output of token t is qt times the sum of every k · v up to t.
  2. Token by token: four dependent steps. The running sum is 2, then 2 + 1 = 3, then 5, then 8 (teal), each waiting for the one before, and o = q × sum = 2, 6, 5, 24 (orange). On a GPU that serial chain along the sequence is the bottleneck.
  3. Cut into blocks of B = 2. Lightning splits the sequence into blocks and each block's output into two parts: one computed inside the block, one from everything before it.
  4. Block 1: the masked product. Inside the block, the ordinary masked quadratic product (the report's "left product", rows queries, columns keys, the upper cell masked) gives both outputs at once: o1 = 1 × 2 = 2, o2 = 2 × (2 + 1) = 6. There is no earlier state yet.
  5. Only the state crosses: S₁ = 3. S1 = k1v1 + k2v2 = 3 is all block 1 hands on (in a real model a d × d matrix per head; here d = 1). Nothing else from block 1 is kept.
  6. Block 2: intra-block plus inter-block. The masked product inside block 2 gives 2 and 15 (purple); the carried state, q × S1 (the "right product"), gives 3 and 9 (teal). So o3 = 5 and o4 = 3 × (2 + 3) + 3 × 3 = 24, the same as token by token, in two block steps instead of four token steps.

For block i of B tokens, the same split as a formula:

Oi=[(QiKi⊤)⊙M]Vi+QiSi−1,Si=Si−1+Ki⊤Vi
Qi, Ki, Vi
the B × d queries, keys and values of block i
M
the B × B causal mask; ⊙ is elementwise, so the first term is the intra-block part
Si−1

Cost per head O(nd2 + nBd): state updates and reads, plus the intra-block products; linear in n for a fixed block size.

At real scale. MiniMax uses blocks of 256 tokens, keeps each block's working set in on-chip SRAM in the spirit of FlashAttention, and reports a constant training speed as sequence length grows, the only linear model in its comparison to beat FlashAttention-2 (report, section 2.2 and appendix). One head with d = 128, B = 256, n = 1,048,576: softmax's n2d ≈ 1.41 × 1014 against lightning's nd(d + B) ≈ 5.15 × 1010 multiply-adds, a ratio of n / (d + B) ≈ 2,731 (constant factors ignored); and 4,096 dependent block steps instead of 1,048,576 token steps.

The 7:1 hybrid, and what the state costs

A fixed state is a lossy summary of everything seen so far, so exact recall of one earlier token (a needle, a definition looked up in context, an identifier copied verbatim) degrades in a way perplexity does not show. The MiniMax-01 report says it plainly: pure linear attention matches the transformer at language modelling but "falls short in retrieval tasks". So MiniMax-01 shipped a 7:1 hybrid (the hero's top row): seven lightning layers do the cheap bulk mixing, then one softmax GQA layer restores exact addressing, repeating.

The numbers. MiniMax-Text-01 has 80 layers, 64 query heads of dimension 128, and softmax layers with 8 KV heads (config; its attn_type_list marks every eighth layer as softmax). So 10 layers keep a KV cache and 70 keep a state:

  • KV cache per token: 10 × 2 × 8 × 128 × 2 = 40,960 bytes = 40 KiB, against 320 KiB if all 80 layers were softmax GQA; at 1,048,576 tokens, 40 GiB per sequence instead of 320 GiB.
  • State per sequence: 70 × 64 × 128 × 128 = 73,400,320 elements, fixed: 140 MiB at 2 bytes per element whatever the context (the report does not state the state's precision; in FP32 it doubles).

At 456B total and 45.9B active parameters, MiniMax describe Text-01 as the first successful large-scale implementation of linear attention. It was trained on contexts up to 1M tokens and extrapolated to 4M at inference, which is where the 4M-token claim comes from (Text-01 model card).

M2's reversal: back to full attention

M2 (27 October 2025) dropped lightning attention and returned to softmax GQA in every layer: 62 layers, 48 query heads and 8 KV heads of dimension 128 (config), trained to a 192K-token native context (M2 series report, arXiv 2605.26494). That is 62 × 2 × 8 × 128 × 2 bytes = 248 KiB per token, about 46.5 GiB for one full 196,608-token sequence: 6.2 times the hybrid's per-token cache, paid deliberately.

MiniMax-01 report, January 2025
The hybrid "not only matches but surpasses the retrieval and extrapolation capabilities of softmax attention" on its small-scale comparisons (arXiv 2501.08313, section 2.2.2).
M2 post and report, late 2025 and 2026
At larger scale "the model had clear deficits in complex, multi-hop reasoning tasks", which the saturated benchmarks of the time did not show (MiniMax). The later source is the lab revising the earlier.

MiniMax's reasons (Why did M2 end up as a full attention model?; M2 series report, section 2.2.2):

  • The benchmarks hid the gap. Hybrids matched full attention on MMLU, BBH, MATH and LongBench during Text-01's development; the real bottleneck, in their words, was "the limitations of evaluation": proxy metrics built to catch the weakness may stop correlating with real performance at the next scale.
  • Some circuits are set early. Retrieval and induction heads (patterns that find and copy an earlier token) form early in pretraining in global attention. Converting a trained model into a sliding-window hybrid by continued pretraining "can hardly adjust those patterns afterwards", and finding every such head to keep as full attention "from human priors" was nearly impossible.
  • Sliding windows failed the same way. In ablations continued for hundreds of billions to trillions of tokens, hybrid sliding-window attention (SWA) degraded retrieval, multi-hop reasoning and in-context learning. The chart has every row of the two tables: the gap opens past 32K tokens and is mixed below it.
  • The infrastructure was not there. Linear attention is far more sensitive to numerical precision, many linear designs are memory-bound even in training, and it did not yet work cleanly with prefix caching and speculative decoding. In theory its compute crossover with full attention lies at "a few thousand tokens"; reaching it in production needs those three problems solved.

The workloads that had become the product, long reasoning chains that refer back to their own steps and agent loops full of tool outputs to be quoted exactly, are exact-recall workloads, where a compressed state is weakest; paying the quadratic cost was the cheaper trade. MiniMax framed the reversal as conditional: "as GPU compute growth slows while data length keeps increasing, the benefits of linear and sparse attention will gradually emerge."

MSA (MiniMax Sparse Attention, M3): keep exact lookup, read a few blocks

M3 takes the third route. Trained sparse attention keeps the softmax and the full KV cache but lets each query attend only to a selected subset of keys; if the right keys are selected the lookup is exact, because nothing was compressed. The difficulty moves into selection (cheap, trainable end to end) and into kernels (a selected set is irregular, and irregular memory access is what GPUs do worst). Sparse attention in general, and DeepSeek's DSA, are taught on Attention variants; MSA is MiniMax's version, from the MSA paper, arXiv 2606.13392 and M3's config:

  1. A token arrives. At position 131,072 it enters one of M3's 57 MSA layers and forms 64 query heads of 128 (4 GQA groups of 16), its key and value for each of the 4 KV heads, and for the index branch 4 index queries (one per group) and one shared index key, all of dimension 128. Each grey plate is one KV head's cache over the whole context, in blocks of 128 earlier tokens (to scale: a lit block is one block); the gold plate holds the index keys.
  2. Write to the cache: nothing is dropped. Its keys and values (2 × 4 × 128 × 2 = 2,048 bytes) go to every KV head and its index key (256 bytes, BF16 assumed) to the gold plate. All 1,024 blocks stay resident: MSA never shrinks what is stored, it only chooses what to read.
  3. Index branch: score every earlier token. One small index query head per KV group and one index key head shared by all groups score every earlier token, Si,j = qidxi,r · kidxj / √didx: 4 × 128 × 131,072 multiply-adds, reading all the index keys (32.0 MiB). The one part of MSA that still grows with the context, which is why it is kept light.
  4. Block scores: max-pool. Keys are cut into blocks of Bk = 128 tokens; a block scores the maximum of its tokens' scores, so one strongly relevant token lifts its whole block (the gold shade: group 1's block scores).
  5. Selection per GQA group: 16 blocks each. Each group ranks the blocks by raw score (an "exp-free" top-k, since softmax preserves order) and keeps its own top k = 16, the query's own block always included. The four colours are the four groups: they share the local block and the sink at the start but retrieve different long-range blocks; 64 of 1,024 blocks are lit.
  6. Exact attention on the selection. Each group's 16 query heads run ordinary softmax over the kBk = 2,048 selected keys of their own KV head, reading 4 × 2,048 × 2 × 128 × 2 bytes = 4 MiB. Nothing was compressed, so if the right blocks were chosen the lookup is exact. This layer read 36.0 MiB for the token, against 512 MiB in one of M2's layers.
  1. A token arrives. At position 131,072 it enters one of M2's 62 layers and forms 48 query heads of 128 (8 GQA groups of 6) and its key and value for each of the 8 KV heads, one orange plate each.
  2. Write to the cache. Its keys and values, 2 × 8 × 128 × 2 = 4,096 bytes, are appended to the 8 heads; the cache already holds every earlier token, 1,024 blocks of 128.
  3. Every query head scores every key. No selection: each head's query is dotted with all 131,072 keys of its group's KV head, so the token reads every key (256 MiB) and does 48 × 128 × 131,072 multiply-adds for the scores.
  4. Softmax over everything, then the values. The weighted sum reads every value (256 MiB more, purple), another 48 × 128 × 131,072 multiply-adds: 512 MiB read in this one layer for one token. Exact, the reference the other two routes are measured against, and its cost grows with every token in every layer: why M2 stopped at a 196,608-token window and M3 needed MSA to reach 1M.
  1. A token arrives. It enters one of MiniMax-01's 70 lightning layers and forms 64 heads of query, key and value, each of dimension 128.
  2. No cache: update the state. Nothing is appended per token: this layer keeps no cache at all. Each head adds k⊤v to its fixed 128 × 128 state (green glass): 64 × 128 × 128 multiply-adds.
  3. Read the state, not the history. The output is q times the state: another 64 × 128 × 128 multiply-adds, reading 64 × 128 × 128 × 2 bytes = 2 MiB at any context. The cheapest route by far, and the one that lost exact recall: a fixed state cannot hand back one earlier token verbatim.
  4. The 8th layer is still softmax. One layer in every eight is softmax GQA with 8 KV heads: it caches 4,096 bytes per token and reads all of them, as M2 does (512 MiB here). That is MiniMax-01's 40 KiB per token: only 10 of its 80 layers grow with context. MiniMax gave this up in M2 for quality on multi-hop reasoning and retrieval, not for speed.

Block scores and selections are illustrative (a fixed seed with a sink block and a few hot regions, the pattern of the MSA paper's Figure 5); every count and byte figure is computed from the configs. One GQA group is 16 query heads in M3 and 6 in M2. Training: a KL loss pulls the index scores towards the main branch's attention; its inputs are detached, so it updates only the index projections (details in a closed block below).

The cost per query at position n, counting multiply-adds for scores and the weighted sum in the main branch and for scores alone in the index branch:

Cfull=2Hdhn,CMSA=2HdhkBk+Hidxdidxn

With M3's H = 64, dh = 128, kBk = 2,048, Hidx = 4, didx = 128 at n = 1,048,576: Cfull ≈ 1.72 × 1010, CMSA = 33,554,432 + 536,870,912 ≈ 5.70 × 108, a ratio of about 30. Each query reads 2,048 of 1,048,576 keys, 1 in 512, and the index branch is 94% of what remains, which is why it has to be light.

Selection does not shrink storage. Every key must stay resident for the indexer to choose from. M3's main cache is 60 × 2 × 4 × 128 × 2 bytes = 120 KiB per token, about 120 GiB for one 1M-token sequence, plus one 128-dimension index key per token in each of the 57 MSA layers: 14.25 KiB more per token if stored in BF16 (the precision is not stated; assumption). The saving over M2 comes from halving the KV heads (8 to 4), not from MSA; the model card's "reduces the attention compute and memory footprint" (M3 card) is true of what each query reads, not of what is stored.

The kernel: "KV outer, gather Q". A natural sparse kernel loops over queries and fetches the blocks each one selected; every fetched tile then serves only the G query heads of one group, about G FLOPs per byte (16 in M3: 64 query heads over 4 groups). MSA's kernel inverts the loops: for each KV block it gathers every query that selected it into one 128 × 128 matrix multiply, so the tile is loaded once and reused. The paper puts the intensity at about ⅔ Bk, roughly 85 for Bk = 128; hot blocks (an early "sink" block nearly every query selects) are split across thread blocks by a scheduler. MiniMax report it as more than 4 times faster than the open-source Flash-Sparse-Attention and flash-moba kernels (M3 announcement, repeated by launch partner Fireworks; code on GitHub).

Same (query, block) pairs, fewer tile loads when the loop runs over blocks

Where MSA sits, and what it scored. Block-level selection with a separate top-k per GQA group keeps reads contiguous while letting groups retrieve different blocks (the paper's attention maps show each group tracing its own long-range stripes beside a shared local diagonal and sink column). In granularity MSA is finer than Kimi's MoBA but coarser than DSA, which selects individual tokens; the M3 announcement's wording that MSA partitions the KV "more precisely" than DSA and MoBA (MiniMax) is about effective coverage, not selection unit. On the paper's 109B test model (41 layers, 6B active, 3T training tokens), MSA converted from a full-attention checkpoint and extended to long context scored 72.12 on RULER at 128K against 72.00 for full attention, and 45.93 on HELMET at 128K against 46.53; trained sparse from scratch, it matched or beat full attention on most of the paper's pretraining suite.

Post-training: CISPO and what M1's RL run cost

CISPO (Clipped Importance-Sampling Policy Optimization) came with M1 (M1 report, arXiv 2506.13585). RL for LLMs owns it, with its formula and a toy of one rare token through sixteen updates; what MiniMax saw is the part that belongs here. Reflective tokens such as "However", "Recheck", "Wait" and "Aha" fork a reasoning path but get low probability from the base model, so one update can double their probability; with PPO or GRPO's clip their ratio then sits past 1 + ε and their gradient is exactly zero for the rest of the batch (M1 ran 16 off-policy updates per generation batch). DAPO's answer, a higher upper clip bound, was "less effective" in this setup. CISPO clips the importance weight instead, under a stop-gradient: each token's update is sg(min(r, 1 + εIShigh)) · Â · ∇ log π, so no token is silenced. A "Wait" token at r = 2.5, Â = +1, ε = 0.2 (illustrative): PPO weight 0, CISPO weight 1.2. There is no KL penalty.

  • What it bought. On a controlled zero-RL comparison from Qwen2.5-32B-base on AIME 2024, CISPO matched DAPO in 50% of the training steps and beat both GRPO and DAPO at equal steps.
  • The bill. M1's full RL run took three weeks on 512 H800 GPUs, a rental cost of $534,700, a figure few labs publish. The hybrid made the long rollouts cheap: M1 uses less than 50% of DeepSeek-R1's FLOPs at a 64K-token generation length and about 25% at 100K.
  • A precision fix that travels. Training and inference kernels disagreed on token probabilities; computing the language-model head in FP32 raised the correlation between the two from about 0.9 to 0.99 (M1 report).
  • Kept after the reversal. M2's agentic RL kept CISPO with the weight's lower bound set to 0, clip(r, 0, 1 + εIShigh), so tokens that became improbable can be down-weighted aggressively (M2 report, section 6.1.4); the M2.5 line still used it (M2.5 card).

The MoE side: from few large experts to many small ones

Licences and who pays

The weights are open but the licences are not uniform: Apache 2.0 for M1, a modified MIT licence for the M2 line, and the custom MiniMax Community License for M3 and M3.1 Flash (M1 card, M2 card, M3 card). M3.1 Flash's copy is non-commercial by default: non-commercial use is free; any commercial use, which includes serving a fine-tuned derivative, must display "Built with MiniMax M3.1-Flash" and send MiniMax a one-time notice, needs prior written authorisation above 20 million US dollars of yearly revenue, and military use is prohibited outright (M3.1 Flash licence). Revenue does not fund the model line: in 2025 it was $79.0 million (up 158.9%), 67.2% from "AI-native products" (the Talkie and Xingye character apps, Hailuo AI video and MiniMax Agent) and 32.8% from the Open Platform API and enterprise services, more than 70% from outside China, while research and development cost $252.8 million and the adjusted net loss was $250.9 million (2025 annual report). The models run on investor capital, now including public markets: MiniMax listed in Hong Kong on 9 January 2026, the day after Zhipu (Wikipedia; Zhipu on Wikipedia). Open weights at low prices are how a lab without frontier brand recognition buys attention (the page's reading, not a MiniMax statement).

Depth

MSA's training and FLOP model, in full (the KL loss, the warmup, eq. 12, ablations)

The index branch learns with a KL-divergence loss that pulls its distribution towards the main branch's group-averaged attention on the selected tokens; its inputs are detached, so this loss updates only the two index projections and cannot simplify the main model's attention to lower itself. The indexer warms up under full attention (40B tokens in the paper's runs) before sparsity is switched on. MSA works both from scratch and by converting a full-attention checkpoint.

ℒKL=1NHkv∑i=1N∑r=1HkvDKL(sg(Pi(r))∥Piidx,(r))
Pi(r)
the main branch's attention over the selected tokens, averaged over the G query heads of group r
Piidx,(r)
the softmax of the index scores over the same tokens
sg
stop-gradient; N is the sequence length, Hkv the number of groups

The paper's own count averages over a whole prefill of N tokens, so the causal triangle halves the full-attention and index terms (FLOPs, two per multiply-add; eq. 12 of the MSA paper):

FGQA=2HqdhN2,FMSA=HkvdidxN2+4HqdhNkBk

In ablations, block size (32, 64 or 128 at the same token budget) made little difference to quality, and a FLOP-matched sliding window had higher perplexity than MSA on agent tasks throughout training.

M3.1 Flash: a model shipped inside a harness first (volatile, dated)

M3.1 Flash reached users in two stages. As M3.1-Flash-Preview (27 September 2026) it ran only inside MiniMax's own coding agent and subscription plan, with no published price, speed, benchmark or parameter count (MiniMax docs; DataNorth); an earlier version had already served traffic anonymously on OpenRouter as "Space Bunny". On 19 October it reached the API at $0.15 / $0.60 per million ($0.015 cached), with MiniMax claiming about three times the inference speed and 70% lower agentic-task cost than its predecessor, and its own scores of 73.7% on DeepSWE v1.1 and 61.7 on OSWorld V2 (MiniMax). MiniMax published no technical report; the weights followed on 23 October with a model card that gives about 428B total and 23B active (MarkTechPost had read the same from the product page, MarkTechPost). The Hugging Face widget shows 220.5B because 206.6B of the stored values are bytes that each pack two 4-bit weights: a storage count, not the model's size. The point worth carrying: a model can now ship inside a harness weeks before it is sold per token, and it can be measured independently only from the day it is.

On the same index reading of 1 October 2026, at M3's $0.30 / $1.20 list price DeepSeek V4.1 Flash scored 39.5 (45 for its 1017 checkpoint by 19 October), and Zhipu's GLM 5.3 Flash scored 41.8 at $0.15 / $0.50 (leaderboard; Zhipu: GLM); M3 was among the cheapest capable open frontier options at release and is now one of several. StepFun's Step 5 Preview does not undercut M3: it lists at $1.00 / $2.70, and its weights arrived only in mid-October 2026 (Other notable providers).

Misreadings worth catching (each seen in coverage or in this page's sources)
  • "MiniMax-01 has no KV cache." Its 10 softmax layers do: 40 KiB per token.
  • "M2 went back to full attention because linear attention is slow." The stated reasons are quality on multi-hop reasoning and retrieval-style circuits, an evaluation gap that hid it, and immature infrastructure; speed was the attraction, not the problem.
  • "MSA shrinks the KV cache." It shrinks what each query reads; M3's smaller cache comes from 4 KV heads instead of 8.
  • "The 4M-token context was trained." Training reached 1M; 4M is inference extrapolation.
  • "Full attention scales exponentially with context." Quadratically: prefill grows with n2 and each decoded token's reads with n. The phrase appears in launch coverage (Fireworks).
  • "MiniMax's apps pay for its models." The apps provide two-thirds of revenue, but 2025 revenue of $79.0 million was under a third of R&D spending.
