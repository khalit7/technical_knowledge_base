Lightning attention (MiniMax-01, M1): linear attention computed in blocks

The bill being attacked. Softmax attention forms an n × n score matrix, so prefill costs on the order of n2d per head, and every decoded token reads the whole KV cache: 2 · Hkv · dh · b bytes per token per layer (key and value, KV heads, head dimension, 2 bytes in BF16; {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}} owns the sizing). Linear attention drops the softmax, so (QK⊤)V = Q(K⊤V): a fixed d × d state St = St−1 + kt⊤vt replaces the cache, and ot = qtSt ({{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}} owns the recurrence and its gated successors).

Lightning attention is MiniMax's IO-aware way of computing it: a kernel contribution, not a new mathematical form ({{MiniMax-01 report, arXiv 2501.08313|@p01}}). Computed token by token, causal linear attention is a cumulative sum along the sequence, which serialises the very dimension a GPU wants to parallelise. Lightning cuts the sequence into blocks and splits each block's output in two: inside the block, the ordinary masked quadratic product (the report's "left product", small and parallel); from all earlier blocks, one multiplication by the carried state (the "right product").

Predict, then step: four tokens with scalar q = (1, 2, 1, 3), k = (1, 1, 2, 1), v = (2, 1, 1, 3). Token by token the running sums are 2, 3, 5, 8, so o = (2, 6, 5, 24). How many dependent steps does each way take? Step through both.

In blocks: block 1 gives o1 = 2, o2 = 6 and hands on only S1 = 3; block 2 gives o4 = 3 × (2 + 3) + 3 × 3 = 24 (intra plus inter). Same outputs, two block steps instead of four token steps.

For block i of B tokens, the same split as a formula:

Oi=[(QiKi⊤)⊙M]Vi+QiSi−1,Si=Si−1+Ki⊤Vi
Qi, Ki, Vi
the B × d queries, keys and values of block i
M
the B × B causal mask; ⊙ is elementwise, so the first term is the intra-block part
Si−1
the d × d state summing kj⊤vj over all earlier blocks: the inter-block part

Cost per head O(nd2 + nBd): state updates and reads, plus the intra-block products; linear in n for a fixed block size.

At real scale. MiniMax uses blocks of 256 tokens, keeps each block's working set in on-chip SRAM in the spirit of {{FlashAttention|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}, and reports a constant training speed as sequence length grows, the only linear model in its comparison to beat FlashAttention-2 ({{report|@p01}}, section 2.2 and appendix). One head with d = 128, B = 256, n = 1,048,576: softmax's n2d ≈ 1.41 × 1014 against lightning's nd(d + B) ≈ 5.15 × 1010 multiply-adds, a ratio of n / (d + B) ≈ 2,731 (constant factors ignored); and 4,096 dependent block steps instead of 1,048,576 token steps.

The 7:1 hybrid, and what the state costs

A fixed state is a lossy summary of everything seen so far, so exact recall of one earlier token (a needle, a definition looked up in context, an identifier copied verbatim) degrades in a way perplexity does not show. The MiniMax-01 report says it plainly: pure linear attention matches the transformer at language modelling but "falls short in retrieval tasks". So MiniMax-01 shipped a 7:1 hybrid (the hero's top row): seven lightning layers do the cheap bulk mixing, then one softmax GQA layer restores exact addressing, repeating.

The numbers. MiniMax-Text-01 has 80 layers, 64 query heads of dimension 128, and softmax layers with 8 KV heads ({{config|@c01}}; its attn_type_list marks every eighth layer as softmax). So 10 layers keep a KV cache and 70 keep a state:

  • KV cache per token: 10 × 2 × 8 × 128 × 2 = 40,960 bytes = 40 KiB, against 320 KiB if all 80 layers were softmax GQA; at 1,048,576 tokens, 40 GiB per sequence instead of 320 GiB.
  • State per sequence: 70 × 64 × 128 × 128 = 73,400,320 elements, fixed: 140 MiB at 2 bytes per element whatever the context (the report does not state the state's precision; in FP32 it doubles).

At 456B total and 45.9B active parameters, MiniMax describe Text-01 as the first successful large-scale implementation of linear attention. It was trained on contexts up to 1M tokens and extrapolated to 4M at inference, which is where the 4M-token claim comes from ({{Text-01 model card|@k01}}).

M2's reversal: back to full attention

M2 (27 October 2025) dropped lightning attention and returned to softmax GQA in every layer: 62 layers, 48 query heads and 8 KV heads of dimension 128 ({{config|@cm2}}), trained to a 192K-token native context ({{M2 series report, arXiv 2605.26494|@pm2}}). That is 62 × 2 × 8 × 128 × 2 bytes = 248 KiB per token, about 46.5 GiB for one full 196,608-token sequence: 6.2 times the hybrid's per-token cache, paid deliberately.

The hybrid "not only matches but surpasses the retrieval and extrapolation capabilities of softmax attention" on its small-scale comparisons ({{arXiv 2501.08313|@p01}}, section 2.2.2).
M2 post and report, late 2025 and 2026
At larger scale "the model had clear deficits in complex, multi-hop reasoning tasks", which the saturated benchmarks of the time did not show ({{MiniMax|@full}}). The later source is the lab revising the earlier.

MiniMax's reasons ({{Why did M2 end up as a full attention model?|@full}}; {{M2 series report|@pm2}}, section 2.2.2):

  • The benchmarks hid the gap. Hybrids matched full attention on MMLU, BBH, MATH and LongBench during Text-01's development; the real bottleneck, in their words, was "the limitations of evaluation": proxy metrics built to catch the weakness may stop correlating with real performance at the next scale.
  • Some circuits are set early. Retrieval and induction heads (patterns that find and copy an earlier token) form early in pretraining in global attention. Converting a trained model into a sliding-window hybrid by continued pretraining "can hardly adjust those patterns afterwards", and finding every such head to keep as full attention "from human priors" was nearly impossible.
  • Sliding windows failed the same way. In ablations continued for hundreds of billions to trillions of tokens, hybrid sliding-window attention (SWA) degraded retrieval, multi-hop reasoning and in-context learning. The chart has every row of the two tables: the gap opens past 32K tokens and is mixed below it.
  • The infrastructure was not there. Linear attention is far more sensitive to numerical precision, many linear designs are memory-bound even in training, and it did not yet work cleanly with prefix caching and speculative decoding. In theory its compute crossover with full attention lies at "a few thousand tokens"; reaching it in production needs those three problems solved.

The hybrid loses most where context is long and recall is exact

Sliding-window hybrid's score minus full attention's, on MiniMax's ablation models at the M2 architecture scale, not the released M2. Source: {{M2 series report|@pm2}}, Tables 2 and 3 (columns "Baseline" = full attention and "w/ SWA"). Orange: the hybrid loses; green: it wins.

The workloads that had become the product, long reasoning chains that refer back to their own steps and agent loops full of tool outputs to be quoted exactly, are exact-recall workloads, where a compressed state is weakest; paying the quadratic cost was the cheaper trade. MiniMax framed the reversal as conditional: "as GPU compute growth slows while data length keeps increasing, the benefits of linear and sparse attention will gradually emerge."
