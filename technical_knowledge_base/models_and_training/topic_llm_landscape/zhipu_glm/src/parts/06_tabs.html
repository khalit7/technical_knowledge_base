Attention work: every GLM attention design, from its config

Each GLM generation rebuilt attention to change one of two numbers: how much cache a request holds, and how much attention work each decoded token does.

The cache, in one line. GLM-4.5's grouped-query attention keeps 368 KiB per token, 46 GiB at 128K; GLM-5.2 and 5.3 keep 93 KiB of latents and shared indexer keys; GLM-5.3-Flash keeps about 11.7 KiB plus a fixed KDA state, 8.0 times less than GLM-5.3 per token and 4.59x per layer against Z.ai's published 4.44x (16-bit). Every GLM design here is a preset in the {{KV-cache calculator|n:3fd5c17b0d0d81059ee1ce20c0326dc5#t-kv}}, with the context slider and the published-figure check.

This tab computes the other number, attention work per decoded token, from the config.json files ({{GLM-4.5|@cfg45}}, {{GLM-5|@cfg5}}, {{GLM-5.3|@cfg53}}, {{GLM-5.3-Flash|@cfgfl}}) at any context length. Try: drag the context to 1M and watch the indexer term take over GLM-5's compute; add the active weights to see IndexShare's 2.9x appear.

Attention work per decoded token

work per token = Σlayers [HIdI · L / pool + H · min(k, L) · (dscore + dvalue)]
indexer layers
layers that run an indexer: all 78 in GLM-5 and 5.1, 21 in GLM-5.2 and 5.3, 11 in Flash, where IndexPool scores one pooled key per 4 tokens
HIdI
32 indexer heads × 128 dimensions
H
attention heads (64; 96 in GLM-4.5)
k
2,048 entries read by sparse attention; full attention reads all L
dscore + dvalue
576 + 512 in MLA's decode form, 512 + 512 for Flash, 128 + 128 per head for GQA

Flash's 34 KDA layers hold a fixed state of 64 × 128 × 128 numbers each and do about 3 × 128 × 128 multiply-adds per head per token (an estimate of the delta-rule update and read, labelled). Projections and experts are outside the attention terms unless "add active weights" is on.
