Parameters and memory, rebuilt from config.json

Every number on this tab is computed in the page from the released configuration files ({{K3 config|@k3cfg}}, {{K2 config|@k2cfg}}) and the module shapes in K3's {{modeling code|@k3mod}}, then checked against what Hugging Face counts in the published safetensors ({{K3|@hfk3}}, {{K2|@hfk2}}) and what the reports state.

What the defaults reproduce
  • K3's routed experts, 92 MoE layers × 896 × 3 × 3,584 × 3,072 = 2,722,740,830,208, equal to Hugging Face's count of MXFP4 parameters exactly (independent).
  • K3 active per token, counting the output head but not the input-embedding lookup, 104.19B, reproducing the report's 104.2B (independent). Including the lookup gives 105.4B.
  • K3's checkpoint at MXFP4 experts plus BF16 for the rest, 1,560,860,324,864 bytes, equal to the safetensors index total exactly (independent arithmetic on Hugging Face's per-dtype counts).
  • K2's config sums to 1.0264T, equal to Hugging Face's 1,026,408,235,864. The report's 1.04T is not what the released config holds; adding the one multi-token-prediction module that K3's report lists for K2 gives 1.044T, a reconstruction (unconfirmed). K2's 32.6B active is not reproduced exactly: 31.7B without that module, 32.3B with it.

Where the parameters live

Weights in memory

Bytes are each part's parameters times its bits per weight over 8. MXFP4 is 4.25 bits (4-bit elements plus one 8-bit scale per 32); FP8 with K2's 128 × 128 block scales is about 8 bits.

Cache against context

Per sequence, a Gated MLA layer caches 576 numbers per token (the 512-number latent plus the 64-number shared key part; NoPE means it is not rotated) and a KDA layer holds a fixed 96 × 128 × 128 state plus 3 tokens of short-convolution state for its queries, keys and values. The cache is assumed BF16; the precision of the KDA state is not stated by Moonshot, so it is a switch.

Defaults: the cut at 1,048,576 tokens is 73.8% with an FP32 state (limit 1 − 24/93 = 74.2%), matching the page's "about a 74% cut" by construction from the config. Kimi Linear's "up to 75%" is the same arithmetic at exactly 3:1. Counts per sequence, all heads, all layers.
