Kimi Delta Attention and the linear/full hybrid

Full softmax attention keeps every past key and value, so its cache grows with context and every decoded token reads all of it. A linear-attention layer instead keeps a fixed-size state matrix per head, at the price of capacity: writes superimpose and precise recall far back degrades. The recurrence, the delta rule and Gated DeltaNet (GDN), the design KDA extends, are owned by {{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}}, whose "one state, five write rules" animation shows each write rule on the same words.

KDA, from the Kimi Linear paper ({{arXiv 2510.26692|@kl}}), is a gated delta-rule linear attention: each write first subtracts what the state retrieves for that key (so a new association overwrites the old one instead of piling on top), and learned decay makes old content fade. Kimi's contribution is the gate's granularity. GDN, like Mamba-2, has one forget rate per head per token, a scalar; KDA gives every key channel its own forget rate, a diagonal matrix, so a layer can keep one feature for thousands of tokens while flushing another at once.

Predict, then try: a fact sits under key channel 1 and scratch under channel 2; ten tokens then write elsewhere. With one scalar gate, can you keep the fact and lose the scratch? Per-channel gates of 0.99 and 0.5 keep 0.904 of the fact and 0.001 of the scratch; switch to GDN's scalar gate and it must pick one rate for both. The other preset, Overwrite, writes v1 = (1, 2) then v2 = (3, −1) under k = (1, 0): plain linear attention reads back the blend (4, 1), the delta rule the new value (3, −1).

The kernel, and what Kimi Linear's ablations kept (depth)

The transition is a diagonal-plus-low-rank (DPLR) matrix of a constrained form, and that constraint is what lets Moonshot's chunkwise-parallel kernel run on tensor cores with substantially less computation than a general DPLR kernel. Kimi Linear also adds a low-rank sigmoid output gate and a short convolution (kernel 4) on the queries, keys and values, both of which its ablations keep: without the gate validation perplexity rose from 5.65 to 5.67, with a swish gate instead to 5.81, without the convolution to 5.70.

The hybrid: three KDA layers, then one full MLA layer. Kimi Linear ablated the ratio on the same 1.4T-token recipe: 3:1 had the lowest validation perplexity (5.65); 7:1 matched its training loss but generalised worse (5.70); 1:1 was about as good (5.66) at a higher inference cost; pure full attention was worst (5.77), and 15:1 worse still (5.82). The full layers keep an exact, lossless recall path for retrieval and copying; the KDA layers carry most of the depth at constant memory.

No positions in the full layers. The MLA layers use no positional encoding at all (NoPE): KDA's decay is itself position-aware, so position and recency are handed entirely to the KDA layers. With nothing rotated, MLA needs no decoupled RoPE key, so these layers run as plain multi-query attention at inference (why: {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}), and the RoPE adjustments that long-context training otherwise needs (frequency-base tuning, YaRN: {{Positional encodings|n:3c65c17b0d0d81a5b7c9e578fcdfac00}}) disappear; K3 extrapolates to 1M tokens "without any positional-encoding modification" ({{K3 report|@k3rep}}, §3.4).

The payoff, against a full-MLA baseline trained the same way on 1.4T tokens: up to 75% less KV cache, up to 6 times the decoding throughput at 1M-token context (time per output token 1.84 ms against 11.48 ms, 6.3×), and equal or better quality on short-context, long-context and RL-style evaluations. It costs custom chunked-parallel kernels (needed to use tensor cores at all), and any capability that depends on exact long-range recall now leans on the one-in-four full layers.

Where "up to 75%" comes from. Only full-attention layers grow a cache, so with r KDA layers per full layer the cache is 1/(r + 1) of an all-full stack of the same shape: 1/4 at 3:1, a 75% cut. In K3, 24/93 = 25.8% of the layers cache, about a 74% cut against an all-MLA 93-layer stack, plus a fixed KDA state per request that does not grow with context: 96 heads × 128 × 128 = 1,572,864 numbers per KDA layer, 108.5 million over 69 layers. That state is why the cut is "up to": at 1M tokens it is 74.0% counted in numbers, 73.8% in bytes if the state is kept in FP32, but below a few thousand tokens the hybrid holds more than an all-MLA stack would. (How to size any model's cache: {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5#t-kv}}.)

What K3 changed in the hybrid ({{K3 report|@k3rep}}, §2.1):

  • A bounded decay (config gate_lower_bound −5), so every chunk of the kernel runs as a dense tensor-core matrix multiply instead of a slow position-pair path.
  • Full-rank gates: KDA's output gate becomes a full-rank projection, and the MLA layers get the same kind of channel-wise sigmoid gate on their output, hence "Gated MLA" (output gates across models: {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}, sinks and gates).
  • One extra global layer: the 3:1 pattern repeats 23 times (92 layers) and one more Gated MLA layer closes the stack so the final layer always attends globally: 69 KDA plus 24 MLA, 93 layers (config full_attn_layers ends 92, 93).
Why the decay had to be bounded, and the full-rank gate's formula (depth)

Kimi Linear maps the gate logit to a log-decay with g = −eA Softplus(z), which is unbounded below; the chunkwise kernel rescales keys by the reciprocal of the cumulative decay, which can overflow, so the diagonal 16-token tiles needed a slow position-pair path. K3 uses g = gmin Sigmoid(eAz) with gmin = −5: every retention factor exceeds e−5 ≈ 0.0067, a 16-token tile's cumulative log-decay stays in (−80, 0), the reciprocal stays below e80 inside BF16's range, and every tile runs as a dense tensor-core matrix multiply. The full-rank output gate: y = Wo[Sigmoid(Wgx) ⊙ RMSNorm(õ)].
