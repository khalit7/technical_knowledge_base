Test-time compute: computation spent at inference, deliberating before answering; a reasoning model is trained to use it well.
Chain of thought (CoT): the tokens a model generates before its final answer, holding intermediate steps. In reasoning models it usually sits in a separate thinking block that the product may hide, summarise or show.
Verifier: a program that checks an answer: exact or numeric match against a reference, a unit-test suite, a proof checker. Correct by construction on the property it checks.
Reward model: a learned network that scores an answer. It generalises to tasks with no checker, and it has errors that optimisation can find. An outcome reward model scores the finished answer, a process reward model (PRM) every step.
pass@k: the probability that at least one of k independent samples is correct: what best-of-k with a perfect verifier achieves.
Self-consistency (majority voting): sample several answers and return the most common final answer. Written cons@k or maj@k for k samples. Best-of-n: sample n answers and return the one a scorer (verifier or reward model) rates highest.
In-context learning: picking up a task from demonstrations in the prompt, weights frozen; zero-, one-, few-shot name how many demonstrations (section 10).
RLVR: reinforcement learning with verifiable rewards: the model's own attempts are scored by a program, not a learned model.

One question, three places to spend the budget

Serial: one chain written longer, which can re-read and revise its own working (section 1, 2). Parallel: several independent chains and a selector, a checker, a vote or a reward model, that picks one answer (sections 3 to 5). Latent: the same layers looped inside the network, depth that never becomes text (section 9). 1. Why a chain of thought adds computation

The intuition is scratch paper. A model that must answer in its first token gets one forward pass of computation, however hard the question. A model allowed to write its working first gets one forward pass per token written, can look back at what it wrote, and can cross it out. A transformer forward pass has fixed depth, so the serial computation available to produce one next-token distribution is bounded by the layer count; a chain of thought removes that bound, and the context window acts as an external working memory persisting across the steps.

Three capabilities follow. Decomposition: a problem needing more serial steps than the model has layers becomes reachable. Externalised state: intermediate results are written down instead of held in activations discarded at every token. Revision: the model can read what it wrote, notice a contradiction and start again, which no single forward pass can do. A reasoning model is trained, typically by large-scale reinforcement learning on tasks whose answers can be checked mechanically (mathematics with a reference answer, code with unit tests), to plan, verify, backtrack and self-correct in that working rather than to emit a plausible-looking derivation (section 8).

The working memory is not free: every generated token leaves keys and values in the KV cache for every later token to attend to. The formula (2 × layers × key-value heads × head dimension × bytes per number, per token) and a calculator for 45 real models are on {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}} (its KV-cache calculator), with T counting the prompt as well as the thinking; the serving techniques that make long traces affordable (paged attention, cache quantisation, multi-query and latent attention) are on {{Batching, KV cache and scheduling in depth|n:3c65c17b0d0d819db53bd2c48909e5b2}}.

What test-time compute does not buy. It adds no knowledge that is not in the weights or retrievable by a tool. It does not make a problem solvable if the model cannot make any correct partial progress on it, since there is nothing for later steps to build on. And the returns are shaped badly for economics (sections 3 and 7).

The theory: a change in kind, not only in amount

Transformer decoders allowed a number of decoding steps logarithmic in the input length gain "only slightly" over a single pass, while a linear number of steps lets them recognise all regular languages and a polynomial number lets them recognise exactly the problems solvable in polynomial time, under standard complexity conjectures and a mild generalisation of pre-norm in the normalisation layers (Merrill and Sabharwal, 2023). That is the whole mechanism: each emitted token is another full forward pass conditioned on everything written so far, so serial steps become unbounded.

2. One long chain or many: the same budget, to scale

Sequential and parallel share one budget in different shapes. Sequential costs irreducible latency (10,000 thinking tokens at an illustrative 50 a second is 200 seconds before the answer starts), a KV cache growing linearly with the trajectory, and attention over an ever-longer scratchpad getting more expensive per token. Parallel need not add wall-clock time given the hardware, but total tokens scale with the sample count and it lives or dies on the selector. Predict before it plays: which shape spends less wall-clock time, and which one can fix its own mistake?

  1. The budget. 10,000 thinking tokens drawn as 40 blocks of 250. Every block is 250 forward passes through all 60 layers, and every token in it leaves 240 KiB of keys and values in the cache.
  2. One long chain: attempt 1. Laid end to end along wall-clock time, one block every 5 seconds at 50 tokens a second. The first 3,500 tokens work the problem and reach a candidate answer, 412. Each new token attends to everything before it (the dots run back along the chain).
  3. Re-check ("Wait"), then attempt 2. The model rereads its own working, finds a step that contradicts an earlier one, backs up (1,000 tokens), and attacks again from the corrected step (3,500 more). Only a sequential chain can do this: the later tokens see the earlier ones. Nothing here runs in parallel: token 6,000 cannot start before token 5,999 exists.
  4. Verify, then answer at 200 s. The model substitutes its result back into the problem (1,500 tokens), then commits to 384 (500). 10,000 tokens at 50 a second is 200 seconds before the answer starts. How likely the answer is to be right has no formula: it depends on how well the model revises.
  5. The same 40 blocks as five chains. The same prompt sampled five times, independently and at a temperature above zero, 5 × 2,000 tokens. All five generate at once, so wall-clock time follows the longest chain, not the total: the same 10,000 tokens take 200 seconds as one chain and 40 as five, and hold the same total KV memory.
  6. Five answers at 40 s. Each chain commits: 384, 412, 384, 97, 384. No chain saw another, so chain 2's mistake was never corrected; it can only be outvoted or rejected.
  7. Majority vote. The most common final answer wins: 384, three votes of five. If each chain is right with p = 0.6 and the wrong ones all agree on one answer, a five-vote is right 68.3% of the time; if wrong answers scatter over four values, 83.5%. Voting needs answers in a comparable form (a number, a choice), which is why it works for mathematics and not for essays.
  8. A verifier instead. Where a checker exists (unit tests, a proof checker, a reference answer), only accepted answers survive (chains 1, 3 and 5) and the selector needs just one: pass@5 = 1 − (1 − 0.6)5 = 0.990. A learned reward model in the checker's place is weaker: a larger sample is also a larger search for its errors (section 3).

Illustrative throughout: the problem, the traces and the answers are invented to show the mechanism, on section 1's illustrative model (240 KiB of KV cache a token, 50 tokens a second). The vote and verifier probabilities are computed from section 3's formulas at p = 0.6 per chain (0.683, 0.835 and 0.990).

What it shows. The same 10,000 tokens and the same total KV memory, five times faster in parallel. The single chain can notice its own error and repair it; the five chains can only be outvoted or rejected, so the result is only as good as the selector.
