What one request costs

Bets 3 to 5 turn into one bill. Four rules make it ({{pricing|@pricing}}, {{prompt caching|@cache}}): input and output are billed separately; reasoning tokens count as output; a prompt above 272K input tokens is charged at the higher rate for the whole request; and since GPT-5.6, input tokens fall into three buckets, uncached, read from the prompt cache, or written to it. Fig. 3 takes one request through them, then one real task.

  1. One request, in tokens. 50,000 tokens in and 5,000 out. The 5,000 out include the hidden reasoning tokens: the caller never sees them, and they are billed as output.
  2. Priced on GPT-6 Astra: $0.75. (50,000 × 10 + 5,000 × 50) / 106 dollars at $10 and $50 per million: $0.50 of input and $0.25 of output. Output is 9% of the tokens and a third of the bill.
  3. The same request on each tier. $0.75 on GPT-6 Astra, $0.15 on GPT-6.1 Sol (one fifth) and $0.0075 on GPT-6 Luna (one hundredth): the tiers are price bands on one rule.
  4. Past 272K, the whole request reprices. A 300,000-token prompt with 10,000 out costs $6.75 on Astra, every input token at 2× and every output token at 1.5×, against $3.50 at the base rates (the outline). Trimming the prompt by 28,000 tokens to 272,000, 9% shorter, cuts Astra's bill by more than half, to $3.22.
  5. An agent turn, mostly cached. 200,000 tokens in, 75% of them read from the prompt cache at $1 per million, a tenth of the input price: $0.50 uncached, $0.15 cached and $0.25 of output, $0.90, against $2.25 with nothing cached.
  6. One index task, in tokens. On Artificial Analysis' index runs one task takes Astra about 717,000 input and 36,700 output tokens, GPT-6.1 Sol 926,000 and 45,000, GPT-6 Luna 1.74 million and 80,300. The cheaper tiers spend more tokens; nearly all of them are input, and most of that is read from the cache (89%, 90% and 93%).
  7. The same task, in dollars. Astra $3.26: $0.78 uncached input, $0.64 cached, $1.36 of hidden reasoning and $0.48 of visible answer. GPT-6.1 Sol $0.72, a fifth of Astra's price per token but 22% of its cost per task; GPT-6 Luna $0.068, a hundredth per token but 2.1% per task. 74% of Astra's output tokens and 89% of Luna's were hidden reasoning.

Steps 1 to 5 are OpenAI's pricing rule on the {{pricing page|@pricing}}'s standard prices (read 1 October 2026), by construction. Steps 6 and 7 are Artificial Analysis' Intelligence Index runs (v4.3, methodology v4.3.2, read 1 October 2026, {{Artificial Analysis|@aalb}}): tokens per task are the run totals scaled to one task and the cached share is back-solved from the run's cost, so the totals reproduce AA's cost per task by construction (the closed block below shows how).

Price per token is not cost per task

A cheaper model that needs more turns, more effort or more reasoning tokens to finish can cost more per solved task than its price suggests, which is why OpenAI's own comparisons quote cost per task (the general point and the cross-lab chart are the {{landscape root's|n:3c65c17b0d0d812d9e00f6ec89965286}}). Steps 6 and 7 are the evidence: the cheaper tiers spend more tokens.

Prompt caching: when a reused prefix pays

The prompt cache stores the key and value tensors of a prefix, not the text, so a later request with the same prefix skips recomputing it. On GPT-5.6 and later the first request writes the prefix at 1.25× the input rate and each reuse reads it at 0.1× (0.05× on GPT-6.1 Sol). A prefix must be at least 1,024 tokens, an entry stays eligible for 30 minutes after its last write or reuse, the whole rendered prefix must match (tools, effort and formatting settings included), and each request can create up to four cache writes ({{prompt caching guide|@cache}}). With N requests sharing the prefix (one write, N − 1 full reads) and r the read rate as a fraction of the input price:

CcachedCuncached=1.25+(N−1)rN,Nbreak-even=1.25−r1−r

Inside the network and behind the API: GPT-6 Astra

Every earlier OpenAI reasoning model spends its test-time budget as hidden chain-of-thought tokens: text the caller cannot see, but which exists, is billed and can be monitored. Recurrent depth (also called opaque recurrence, or a looped transformer) loops activations back through the model's own layers, so part of the deliberation happens in activations and never becomes text. That is a third place to spend the budget:

Where the budget goesExampleBilled asReadable by a monitor

Loops in activationsGPT-6 Astra (reported, in part)no tokens at allno

A loop buys serial depth without adding parameters or emitting tokens, and costs the readability of the reasoning; the mechanism, the first published architecture of the family (the Recurrent Looped Transformer, by Yifan Zhang, Jichen Feng and Shihan Qin, tested on synthetic algorithmic tasks only) and the sceptical reading are on the {{landscape root's recurrent depth section|n:3c65c17b0d0d812d9e00f6ec89965286}}, with its animation.

Provenance. The architecture is known from reporting, not from OpenAI's documents: The Information reported it on 2 September ({{TechCrunch|@tcrunch}}), and OpenAI researchers, among them chief scientist Jakub Pachocki, answered that OpenAI had limited how much of the model uses the looped transformer so that its reasoning stays legible, and would share more about the architecture later ({{Fortune|@fortune}}). The system card does not describe the architecture ({{system card|@card}}). What it does measure about Astra's own reasoning:

  • Astra is "more capable of controlling its own CoT than GPT-5.6 Sol, and less likely to include incriminating information in its CoT".
  • Under adversarial conditions (pushed to evade monitors) it can remain undetected when strategically underperforming in evaluations (sandbagging), and can sometimes evade OpenAI's internal monitors on certain sabotage tasks.
  • No evidence of steganographic reasoning, hidden load-bearing reasoning inside ordinary text, was found.

Serving changed with it. If part of the working state lives in activations or in reasoning the caller never sees, a request that arrives without that state has to rebuild it. OpenAI's API keeps it on OpenAI's side: reasoning items are returned to the caller only as encrypted_content (in stateless mode) or kept server-side and referenced with previous_response_id, and reasoning.context: all_turns, the default on GPT-5.6 and supported on GPT-6.1 Sol, renders reasoning from earlier turns into the next one. The items "remain opaque" and carry only within one model family ({{reasoning guide|@reason}}).

The headline number is a harness number

ARC Prize ran Astra on the ARC-AGI-3 Semi-Private set through two harnesses at six efforts ({{ARC Prize|@arc}}). Its standard, provider-neutral harness lets the model carry forward only the notes it chooses to keep. The new Provider Adapter preserves the opaque reasoning state between requests (the encrypted items above) and compacts longer conversations so the model can reuse prior work. Same weights: 62.7% against 99.9%.

Fig. 4 plays the same game, two turns, through each harness; switch the harness above it and it replays. The difference is what crosses the gap between requests, and what turn 2 has to redo.

  1. A frame arrives. The harness sends GPT-6 Astra the current frame of an unfamiliar ARC-AGI-3 game. It has to explore, infer the goal and plan, with no instructions.
  2. Astra reasons, out of sight. Hidden reasoning works out what the objects do. The caller sees none of it; the tokens are billed as output, and on Astra part of the work may stay in activations.
  3. It acts and keeps notes. It returns an action and the notes it chooses to carry forward. ARC Prize saw Astra invent a compact algebraic shorthand for them, such as "extend8 to3".
  4. Between requests. The standard harness is provider-neutral: the next request carries the transcript and the notes, and Astra's opaque reasoning state is dropped, so whatever it had worked out but not written down is gone. The Provider Adapter passes the state back with the notes: in OpenAI's API, encrypted reasoning items or a previous_response_id, which only OpenAI can read.
  5. Turn 2. Standard: before it can make new progress, part of turn 1's understanding has to be rebuilt from the notes and the transcript, more reasoning tokens and more time for the same next move. Adapter: nothing to rebuild; the next move starts from the state turn 1 left, and the same progress costs fewer reasoning tokens.
  6. A whole game, a whole run. The rebuilding repeats every turn: the best standard run scored 62.7%, at max effort, for $26,098. When a game runs long the adapter compacts earlier turns so the model keeps reusing its work: best run 99.9% at high effort for $18,817.

Every adapter run beats the best standard run

Predict: on the standard harness, does a higher effort cost more dollars for the whole run? Guess, then hover or tap the points.

On the standard harness higher effort is cheaper, because Astra solves games in fewer actions and so makes fewer calls; and every adapter run, even at effort none, scores above the best standard run. Same weights, 37.2 points apart (99.9 − 62.7), and the higher-scoring run cost 1 − 18,817 / 26,098 = 27.9% less in dollars. Across the 167 game-and-effort pairs both harnesses solved, the adapter runs were about 3.66 times faster by aggregate elapsed time and used 49% fewer total tokens. Through the adapter at max effort Astra used fewer actions than the median human tester on 96.0% of levels, 51.7% fewer per level on average. ARC Prize will now report both harnesses, labelled. Keeping state on OpenAI's side can be worth more than a model upgrade, and it costs portability: the harness that scores best is the one only that vendor runs.
