More experts, same active count. Moonshot fitted a sparsity scaling law with Muon: holding active experts at 8 (plus 1 shared) and FLOPs constant, raising the total expert count kept lowering loss. To reach a validation loss of 1.5, sparsity 48 needed 1.69×, 1.39× and 1.15× fewer FLOPs than sparsity 8, 16 and 32 ({{K2 report|@k2}}, §2.3). K2 stopped at 48 (8 of 384) as the point where the gain stopped paying for the infrastructure complexity. K3 goes to 896 experts with 16 active, sparsity 56, under the name Stable LatentMoE, which the card credits (together with KDA, AttnRes and refined training and data recipes) for an approximate 2.5× improvement in overall scaling efficiency over K2. With hundreds of small experts the costs on the MoE page sharpen: load imbalance, all-to-all traffic per token, every expert resident in memory, and each expert seeing proportionally fewer tokens.

Half the heads. DeepSeek-V3 used 128 heads, about twice its layer count. Moonshot measured that doubling heads from 64 to 128 lowered validation loss by only 0.5% to 1.2%, while at 128k context it raised inference FLOPs by 83% (with 384 experts fixed), and agentic workloads live at long context. K2 took 64. K3's card lists 96.

Worked example: two sparsity numbers. K2's expert sparsity is 384 / 8 = 48, but its parameter ratio is 1.04T / 32.6B = 31.9, because attention, embeddings and the shared expert are always active. K3: 896 / 16 = 56 for experts, 2.8T / 104B = 26.9 for parameters (26.7 with the report's 2.78T / 104.2B). K3 is sparser than K2 by the first measure and less sparse by the second; quote which one you mean.

Stable LatentMoE: what the report describes

The card names Stable LatentMoE without describing it; K3's technical report does ({{K3 report|@k3rep}}, §2.3). In a conventional MoE each selected expert receives the full d-wide token, so communication and expert-weight traffic grow with the number of experts each token visits. LatentMoE separates the two widths: shared experts keep a full-width path, while routed experts work in a compact latent of width ℓ (3,584, half of 7,168):

𝐮=∑i∈Tk(𝐱)piEirouted(W↓𝐱),𝐲=∑j=1NsEjshared(𝐱)+W↑RMSNorm(𝐮)
W↓, W↑
the shared down-projection to the latent and up-projection back (7,168 × 3,584 each)
Tk(x), pi
the 16 selected experts and their renormalised router weights
Ns
the 2 full-width shared experts

At 896 experts two failure modes of the plain design get worse, and "Stable" names the three fixes. The routed path chains W↓, a gated expert network and W↑ into nearly four consecutive matrix multiplies, which at 2.8T scale produced exploding internal activations; an RMSNorm before the up-projection (which also improved validation loss and benchmarks) and SiTU-GLU, a SwiGLU whose gate and up branches are each soft-capped with β tanh(x/β) (β1 = 4, β2 = 25, so the output is bounded by β1β2 = 100 while it tracks SwiGLU near the origin), suppress it. Balancing nearly 103 experts exceeds the regime where DeepSeek's fixed-step bias update behaves, so K3 uses Quantile Balancing: each expert's routing bias is set directly from the quantile of router-score margins that would give it exactly its target load, q = mk/n tokens.

b^j(t+1)←−quantile1−k/n(s:,j−𝛂(t)),b(t+1)←b^(t+1)−mean(b^(t+1))
si,j
token i's sigmoid router score for expert j; the bias steers which experts are chosen but is left out of the mixture weights p

The new bias takes effect only in the next step, so a batch is never routed with a bias derived from itself; at scale the quantile is read from per-expert histograms summed with one all-reduce, and the final bias is frozen at inference. DeepSeek-V3's rule instead nudges each bias by a fixed γ towards the mean load, trading slow adaptation against oscillation.

Try: 16 tokens choose among 4 experts with skewed router scores (illustrative). Press the Quantile Balancing step a few times: it jumps most of the way to the target from one pass and settles within a token of it after two or three, with no step size to tune. Reset and press the fixed-step update instead: it creeps, then keeps oscillating, faster or slower with γ.

Attention Residuals: attention across depth

Attention Residuals ({{arXiv 2603.15031|@ar}}, March 2026) change the residual stream itself. In a standard PreNorm transformer each layer adds its output to a running sum, hl = hl−1 + fl−1(hl−1), so layer l sees the embedding plus every earlier output with weight exactly 1. Two problems follow: the sum's magnitude grows roughly linearly with depth, diluting each new layer's contribution (later layers learn ever larger outputs to be heard, which can destabilise training), and no layer can pick out one earlier layer's output once it has been summed in. Moonshot's observation is that this is the depth-wise analogue of an RNN compressing a sequence into one state, and the fix is the one attention brought to sequences:

𝐡l=∑i=0l−1αi→l𝐯i,αi→l=exp(𝐰l⊤RMSNorm(𝐯i))∑j=0l−1exp(𝐰l⊤RMSNorm(𝐯j))
hl
the input to layer l
v0, vi
the token embedding, and the output fi(hi) of layer i (attention and MLP sublayers count as separate layers; K3's checkpoint has one pseudo-query for each)
αi→l
the weight layer l puts on source i
wl
a single learned pseudo-query per layer, a d-dimensional vector

The RMSNorm on the keys stops a large-magnitude layer from dominating the weights by size alone. The weights depend on the token, because the vi do, so different tokens can retrieve different depths. The cost per layer is one d-dimensional vector of parameters. The pseudo-queries start at zero, so training begins with uniform weights: at layer 4, the four sources each get 0.25, which is the standard residual sum divided by 4, a scale the next RMSNorm removes, so the model starts out behaving like a standard transformer.

At scale every layer's output would have to be kept and, under pipeline parallelism, shipped between stages, so production uses Block AttnRes: layers are grouped into about 8 blocks, outputs inside a block are summed as usual, and the softmax runs only over the block summaries and the embedding, cutting memory and communication from one vector per layer to one per block. Moonshot reports Block AttnRes matching a baseline trained with 1.25× more compute, under 4% end-to-end training overhead with pipeline parallelism, under 2% inference latency overhead, and bounded hidden-state magnitudes with gradients spread more evenly across depth. It was validated on the Kimi Linear 48B architecture over 1.4T tokens before K3 adopted it. K3 partitions its 93 layers into 8 blocks of 12 (the last block partial, 9 layers), "9 total blocks when counting the embedding" ({{K3 report|@k3rep}}, §2.2), and its EAGLE-3 draft model reads features from the 1st, 4th and final blocks.

Try: pick a layer of K3. Under the plain residual every earlier output arrives with weight 1 and the count grows with depth; Full AttnRes at initialisation spreads 1 over the same sources; Block AttnRes keeps at most 9. The "trained" weights are illustrative: only their shape (a softmax over sources) is real.

Low precision as a release format, not a post-processing step

Moonshot ships its models natively quantised, a strategic choice rather than a convenience: the published checkpoint is the deployable one, trained to tolerate its own precision. The formats themselves (integer and block-scaled floating-point grids, post-training quantisation against QAT, and the hardware that runs them) are on {{Quantization and Precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}}. Weight memory is parameters times bits per weight divided by 8:

bytes=∑partsNpart×bpart8
Npart
the parameter count of each part of the model
bpart
the bits stored per weight in that part, including any share of a per-block scale

Worked example: K3's weights. At BF16, 2.78 × 1012 × 2 = 5.56 TB. MXFP4 stores 4-bit elements plus one 8-bit scale per block of 32, so b = 4 + 8/32 = 4.25. But only the routed experts are MXFP4: 2,722,740,830,208 of them, 98% of the parameters; attention, the latent projections, shared experts, routers, embeddings and the vision encoder stay in higher precision ({{K3 report|@k3rep}}, §4.1.4; config ignore list). So the weights take 2.7227 × 1012 × 4.25/8 + 57.18 × 109 × 2 = 1.561 TB, which is the checkpoint's published size to the byte ({{safetensors index|@k3idx}}): about 28% of BF16, the difference between a model a few labs can run and one a well-equipped team can serve. An earlier version of this page put every weight at 4.25 bits and got 1.49 TB. Every scheme, and K2's, is on Parameters and memory.

INT4 QAT, K2 Thinking. Moonshot applied quantisation-aware training in the post-training stage, with weight-only INT4 on the MoE components, which hold nearly all the parameters ({{model card|@k2t}}). The forward pass sees the 4-bit weights while training continues, so the model adapts to the coarse grid instead of being rounded onto it afterwards. It matters most for reasoning models: post-training quantisation introduces small per-step errors, and long chains of dependent reasoning steps compound them, so the loss shows up far more in long chains than in short answers. Moonshot reports a lossless 2× speed-up in low-latency mode, since decode is memory-bandwidth-bound and the expert weights are a quarter of their BF16 size; all its benchmark results are reported at INT4.

MXFP4, K3. K3 ships MXFP4 expert weights with MXFP8 activations, trained in with QAT from the SFT stage onward and through RL, with rollout and training sharing the same quantisation so there is no train-inference mismatch ({{model card|@k3card}}; report §4.1.4). Block-wise scaling is what makes 4 bits survivable: an outlier distorts only its own 32-value block instead of crushing the whole tensor's resolution, and the format has native tensor-core support on Blackwell-class hardware, so it is fast rather than merely small. Shipping the flagship as an MXFP4 checkpoint is how a 2.8T model gets to be practically open-weight.

Post-training: manufacturing agentic data, and rewards where no checker exists

There is very little naturally occurring data for multi-step tool use, so Moonshot manufactures it ({{K2 report, §3.1.1|@k2}}). The pipeline has three stages:

1. ToolsMore than 3,000 real MCP (Model Context Protocol) tool specs taken from GitHub, plus over 20,000 synthetic tools evolved from a hierarchy of categories and domains (financial trading, robot control, software applications and so on).
2. Agents and tasksThousands of agents, each a generated system prompt with a sampled tool set, and for each agent tasks from simple to complex, every task paired with an explicit rubric: success criteria, expected tool-use pattern and checkpoints.
3. TrajectoriesLLM-simulated users with distinct personas hold multi-turn conversations with the agent; a tool simulator, in effect a world model, executes calls, keeps state across them and injects controlled randomness (partial failures, edge cases). An LLM judge scores each trajectory against its rubric and only successes are kept. Coding and software-engineering tasks run in real sandboxes instead, scored by test pass rates.

The kept trajectories feed supervised fine-tuning; the paper describes the whole thing as large-scale rejection sampling. Reinforcement learning then runs in a Gym-like framework over many tasks with verifiable rewards (tests, checkers), the RLVR recipe explained on {{RL for LLMs: RLHF, GRPO, RLVR|n:3c65c17b0d0d818c9bcff7177325fe56}}. K2's policy objective comes from K1.5:

LRL(θ)=𝔼x∼D[1K∑i=1K(r(x,yi)−r‾(x)−τlogπθ(yi∣x)πold(yi∣x))2]
x, D
a prompt, and the task distribution it is drawn from
y1 … yK
K responses sampled from the previous policy πold
r(x, yi), r̄(x)
response i's reward, and the mean reward of the K samples (a group baseline, as in GRPO)
πθ, τ
the policy being trained, and a regulariser τ > 0 that keeps it near πold

Minimising the squared term pushes each response's log-probability ratio towards its advantage divided by τ. It is optimised with Muon, like everything else in K2.

Three additions keep it stable across domains: a per-task token budget, with responses that exceed it truncated and penalised (RL otherwise inflates lengths everywhere, including where thinking does not pay); an auxiliary loss on hand-picked high-quality data (PTX) so RL does not erase it; and a sampling temperature that starts high for exploration and decays.

Where no automatic checker exists (writing quality, judgement, following a complex instruction), K2 adds the self-critique rubric reward: the model, bootstrapped as a judge during supervised fine-tuning, ranks its own candidate responses by pairwise comparison against rubrics (core values, prescriptive rubrics written to block known reward hacks, and human-written rubrics for specific instructions), and the ranking becomes the reward. It buys reward coverage over the large fraction of real work that is not verifiable, and costs the honesty of the grader, since a policy trained against a judge derived from itself has an obvious incentive to learn what the judge likes. Moonshot's mitigation is to keep retraining the critic on on-policy rollouts from verifiable tasks, so its judgement stays tied to outcomes that can be checked. What defeats that mitigation is any quality the verifiable tasks never exercise, such as style in creative writing, where nothing anchors the critic. The general failure mode is on {{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}}.

The thinking variants are additionally trained for interleaved reasoning, alternating reasoning and tool calls rather than thinking once and then acting, which is what agentic browsing benchmarks actually reward. K2 Thinking's card claims coherent behaviour across 200 to 300 consecutive tool calls, where prior models degraded after 30 to 50 ({{model card|@k2t}}). Thinking budgets, test-time compute and how reasoning models are trained in general are on {{Reasoning models and test-time compute|n:3c65c17b0d0d8190b9b4cd0acbcb66df}}.

What K3 added ({{K3 report|@k3rep}}, §4). Three stages: SFT on trajectories synthesised by earlier domain-specialised Kimi models; RL that trains one expert per domain (general tasks, general agents, coding agents) at each of three reasoning efforts (low, high, max), nine experts in all; then multi-teacher on-policy distillation, where the student is rewarded per token by the clipped log-ratio of the matching teacher's probability to its own. Effort is trained with a per-problem budget: a trajectory longer than τ · b0(x), with b0 estimated from the cold-start model, gets reward −1, and annealing τ down yields the high and low experts. For non-verifiable tasks an agentic generative reward model reads the output, writes a rubric, scores each candidate and records the scores, with a verbosity budget under which an over-long candidate automatically loses its comparison. Rollouts pause when a fraction of trajectories finish and resume next iteration from resumable microVM sandboxes. K3 always thinks; its API takes reasoning_effort low, high or max (default max), and the full assistant message, reasoning included, must be passed back each turn ({{model card|@k3card}}).

Common mistakes and misconceptions

"Muon replaces AdamW everywhere."
It handles 2D hidden-layer matrices only; embeddings, the output head and norm gains stay on AdamW.
"Muon makes the update exactly orthogonal."
Five tuned Newton-Schulz steps leave singular values spread around 1 (roughly 0.7 to 1.2 in practice, inside Jordan's 0.7 to 1.3 target), by design.
"QK-Clip clips logits."
It rescales weights after the step; that step's forward and backward passes are unchanged, and a logit soft-cap is the method that clips logits.
"QK-Clip permanently constrains K2."
It fired only in the first 70,000 steps, on 12.7% of heads, and never afterwards.
"KDA is pure linear attention."
Kimi Linear and K3 are hybrids; one layer in four (24 of 93 in K3) is full MLA, and that is where exact recall lives.
"Per-channel gating is the same as GDN."
GDN forgets with one rate per head; KDA has one rate per key channel.
"A linear-attention layer always uses less memory than a cache."
Its state is fixed, not small: a K3 KDA layer holds 1,572,864 numbers per request, as much as an MLA layer's cache at about 2,700 tokens. The saving appears only at long context.
"Expert sparsity and the total over active ratio are the same number."
K2 is 48 by experts and 31.9 by parameters; K3 is 56 and 26.9, so they rank the two models in opposite orders.
"Attention Residuals are cross-attention to earlier layers' tokens."
They mix whole earlier layer outputs for the same token, with weights set by one learned vector per layer; no token attends to another through them.
"The 4-bit checkpoint is a community quantisation."
The 4-bit weights are the trained release format.
"K3's checkpoint is all 4-bit."
Only the routed experts are MXFP4; the other 57 billion parameters stay in higher precision, which is why the checkpoint is 1.56 TB rather than 1.49 TB.
"K3 is modified MIT like K2."
K3 has its own Kimi K3 License with an extra commercial threshold for Model-as-a-Service businesses.
