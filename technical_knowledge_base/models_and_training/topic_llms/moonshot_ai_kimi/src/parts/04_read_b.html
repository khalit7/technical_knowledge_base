Kimi Delta Attention and the linear/full hybrid

The problem. Full softmax attention keeps every past key and value, so its cache grows with context and every decoded token reads all of it. Linear attention removes the softmax so the layer becomes a recurrence over a fixed-size state matrix: each token writes its key-value outer product in, the query reads out, and memory per token is constant. The catch is capacity: a fixed state holds finitely many associations, writes superimpose, and precise recall of something far back degrades. {{LLM Architecture Gallery|n:3c65c17b0d0d81be8a07f2562fa2030a}} owns the general mechanism, with the plain linear-attention recurrence and Gated DeltaNet (GDN), the design KDA extends.

KDA, from the Kimi Linear paper ({{arXiv 2510.26692|@kl}}), is a gated delta-rule linear attention. Delta rule: each write first subtracts what the state currently retrieves for that key, so a new association overwrites the old one instead of accumulating on top of it. Gated: learned decay, so old content fades rather than occupying capacity forever. KDA's contribution over GDN is the gate's granularity. GDN, like Mamba-2, has one forget rate per head per token, a scalar; KDA gives every key channel its own forget rate, a diagonal matrix, so the layer can keep one feature for thousands of tokens while flushing another at once. In the gallery's Gated DeltaNet layout (the paper stores the transpose):

St=St−1Diag(𝛂t)(I−βt𝐤t𝐤t⊤)+βt𝐯t𝐤t⊤,𝐨t=St𝐪t
St
the head's state after token t, of size dv × dk (128 × 128 in K3)
kt, qt, vt
the token's key and query (dimension dk, L2-normalised) and value (dimension dv)
αt
the per-channel forget gate in (0, 1)dk (GDN has a single scalar αt here), held in the diagonal matrix Diag(αt)
βt
the write strength in (0, 1)
I, ot
the identity, and the output

Read right to left inside the first term: decay each key channel by its own rate, then erase what is stored under kt; the second term writes vt there. The transition is a diagonal-plus-low-rank (DPLR) matrix of a constrained form, and that constraint is what lets Moonshot's chunkwise-parallel kernel run on tensor cores with substantially less computation than a general DPLR kernel. Kimi Linear also adds a low-rank sigmoid output gate and a short convolution (kernel 4) on the queries, keys and values, both of which its ablations keep: without the gate validation perplexity rose from 5.65 to 5.67, with a swish gate instead to 5.81, without the convolution to 5.70.

Try: the two presets are the page's worked examples. Overwrite: write v1 = (1, 2) under k = (1, 0), then v2 = (3, −1), and read with q = k; plain linear attention returns the blend (4, 1), the delta rule the new value (3, −1). Keep the fact, flush the scratch: per-channel gates of 0.99 and 0.5 keep 0.904 of the fact and 0.001 of the scratch after ten tokens; a scalar gate must pick one rate for both.

The hybrid. Kimi Linear interleaves KDA with full attention layerwise, three KDA layers then one full MLA layer. The ratio was ablated against the same 1.4T-token recipe: 3:1 had the lowest validation perplexity (5.65); 7:1 matched its training loss but generalised worse (5.70); 1:1 was about as good (5.66) at a higher inference cost; pure full attention was worst (5.77), and 15:1 worse still (5.82). The full layers keep an exact, lossless recall path for retrieval and copying; the KDA layers carry most of the depth at constant memory.

Kimi Linear Table 1 ({{arXiv 2510.26692|@kl}}). Horizontal axis: share of layers that keep a growing cache, 1/(r + 1) for an r:1 ratio. K3's 24 of 93 is marked for reference; it was not part of the ablation.

The full MLA layers use no positional encoding at all (NoPE): KDA's decay is itself position-aware, so position and recency are handed entirely to the KDA layers. NoPE also lets the MLA layers be run as plain multi-query attention at inference, and removes the RoPE adjustments (frequency-base tuning, YaRN) that long-context training otherwise needs; K3 extrapolates to 1M tokens "without any positional-encoding modification" ({{K3 report|@k3rep}}, §3.4). The reported payoff, against a full-MLA baseline trained the same way on 1.4T tokens: up to 75% less KV cache, up to 6 times the decoding throughput at 1M-token context (time per output token 1.84 ms against 11.48 ms, 6.3×), and equal or better quality on short-context, long-context and RL-style evaluations. It costs custom chunked-parallel kernels (needed to use tensor cores at all), and any capability that depends on exact long-range recall now leans on the one-in-four full layers.

What K3 changed in the hybrid ({{K3 report|@k3rep}}, §2.1):

  • A bounded decay. Kimi Linear maps the gate logit to a log-decay with g = −eA Softplus(z), which is unbounded below; the chunkwise kernel rescales keys by the reciprocal of the cumulative decay, which can overflow, so the diagonal 16-token tiles needed a slow position-pair path. K3 uses g = gmin Sigmoid(eAz) with gmin = −5 (config gate_lower_bound): every retention factor exceeds e−5 ≈ 0.0067, a 16-token tile's cumulative log-decay stays in (−80, 0), the reciprocal stays below e80 inside BF16's range, and every tile runs as a dense tensor-core matrix multiply.
  • Full-rank gates. KDA's output gate becomes a full-rank projection, y = Wo[Sigmoid(Wgx) ⊙ RMSNorm(õ)], and the MLA layers get the same kind of channel-wise sigmoid gate on their output, hence "Gated MLA".
  • One extra global layer. The 3:1 pattern repeats 23 times (92 layers) and one more Gated MLA layer closes the stack so the final layer always attends globally: 69 KDA plus 24 MLA, 93 layers (config full_attn_layers ends 92, 93).

Worked example: where the 75% comes from. Only full-attention layers grow a cache, so with r KDA layers per full layer the cache is 1/(r + 1) of an all-full stack of the same shape: 1/4 at 3:1, a 75% cut. In K3, 24/93 = 25.8% of the layers cache, about a 74% cut against an all-MLA 93-layer stack, plus a fixed-size KDA state per request that does not grow with context: 96 heads × 128 × 128 = 1,572,864 numbers per KDA layer, 108.5 million over 69 layers. That state is why the cut is "up to": at 1M tokens it is 74.0% counted in numbers, 73.8% in bytes if the state is kept in FP32, but below a few thousand tokens the hybrid holds more than an all-MLA stack would. The arithmetic, with the state's precision as an exposed assumption, is on Parameters and memory.
