What Mistral is

Mistral AI is a Paris lab founded in April 2023 by Arthur Mensch (from Google DeepMind) and Guillaume Lample and Timothée Lacroix (both from Meta) ({{Wikipedia|@wiki}}). It is the European counterweight to the Chinese labs that lead open weights, alongside Ai2 and the Institute of Foundation Models (the page's own positioning, not a sourced ranking).

Its strategy is a bet that a cheaper model with open weights and EU jurisdiction wins the deals that raw benchmark position does not: sovereign and defence deployments, regulated on-premises installs, and anyone who cannot legally send tokens to a US API. Mensch put the capability position plainly in July 2026: "we do not yet own the best language models, but we've constantly reduced that gap" ({{Tech Times|@tt}}).

Technically it is a fast follower rather than an originator. It takes an efficiency idea that already works (sliding-window attention, grouped-query attention, sparse mixture of experts, and in 2025 DeepSeek's latent attention) and has repeatedly been early to ship it at a size people can run on their own hardware: Mistral 7B in September 2023, then Mixtral 8x7B a few months later, which made open sparse mixture-of-experts models mainstream. Two things are distinctively Mistral, and the rest of this page is about them:

  • The shapes it chose: a 4,096-token window over 32 layers, 32 query heads sharing 8 key-value heads, eight big experts, and now 128 small ones (Mistral 7B, Mixtral, Current line).
  • A licence ladder from Apache 2.0 to API only, which decides what you may do with each model more than any benchmark does (Licences).

The generic mechanisms are owned elsewhere and summarised here only as far as this page needs them: mixture-of-experts routing, load balancing and expert parallelism on {{Mixture-of-Experts (MoE) models|n:3c65c17b0d0d810080cce6648ac8f2f2}}; grouped-query and sliding-window attention across the field, and how to read a KV-cache figure, on {{LLM Architecture Gallery|n:3c65c17b0d0d81be8a07f2562fa2030a}}; reasoning modes on {{Reasoning models and test-time compute|n:3c65c17b0d0d8190b9b4cd0acbcb66df}}.

Mistral 7B: a sliding window and shared key-value heads

The intuition. A decoder's KV cache holds the keys and values every past token leaves behind for attention to read. It grows with every token, and at decode time reading it is the bottleneck: decoding is limited by memory bandwidth rather than arithmetic, so a smaller cache turns directly into larger batches and more tokens per second on the same GPU. Mistral 7B attacked the cache twice at once: it limits how many past tokens each layer may attend to, and it lets several query heads share one set of keys and values.

Sliding-window attention (SWA). Each layer attends only to the last W tokens, with W = 4,096, so the cache never needs more than W positions. Mistral implemented it as a rolling buffer: position i is written to slot i mod W, overwriting the token that just fell out of the window, so the cache is a fixed-size ring rather than a growing list. Information still travels further than W because windows stack: layer 2 at position i reads layer-1 states that already summarise the W tokens before them, so after k layers a token can be influenced by roughly k · W earlier tokens, the way a stack of small convolutions builds a large receptive field. The price: anything beyond the window arrives only through what the intermediate states carried forward, so exact long-range recall is weaker than with full attention. Mistral itself dropped the window in Mixtral, which supports "a fully dense context length of 32k tokens" ({{Mixtral paper|@mixp}}); the field later settled on mixing windowed and full layers, covered on the {{LLM Architecture Gallery|n:3c65c17b0d0d81be8a07f2562fa2030a}} page.

Grouped-query attention (GQA). 32 query heads but only 8 key-value heads, so each group of 4 query heads reads the same keys and values. The cache stores 8 heads per layer instead of 32, a quarter of what full multi-head attention (MHA) would store. GQA in general, with the group factor as a dial between multi-head and multi-query attention, is on the {{LLM Architecture Gallery|n:3c65c17b0d0d81be8a07f2562fa2030a}} page.

The shape ({{Mistral 7B paper|@m7p}}, Table 1; {{config.json|@cfg7}}): model width 4,096, 32 layers, head dimension 128, feed-forward width 14,336, 32 query heads, 8 key-value heads, window 4,096, context length 8,192, vocabulary 32,000, Apache 2.0. It outperformed "the best open 13B model (Llama 2) across all evaluated benchmarks, and the best released 34B model (Llama 1) in reasoning, mathematics, and code generation" ({{paper|@m7p}}), which is what established the lab, and it became a common small base for fine-tuning (unconfirmed as "the default"). Mistral's announcement calls it a 7.3B-parameter model ({{Mistral|@m7}}); summing the table gives 7.24B (32 layers of 218.1M plus 0.26B of input and output embeddings), about 14.5 GB at 16 bits.

The maths

btok=2·L·nkv·dh·s M(n)=btok·min(n,W)R(k)≈k·W
btok
bytes of cache one token leaves behind across all layers; the 2 counts one key and one value vector
L
number of layers
nkv
key-value heads per layer
dh
head dimension
s
bytes per stored number (2 for 16-bit)
M(n)
cache in bytes for a sequence of n tokens; min(n, W) says the rolling buffer stops growing at the window. Without a window, M(n) = btok · n
R(k)
how many tokens back information can have travelled by layer k: an upper bound on influence, not a guarantee that the information survived

Worked example: Mistral 7B's cache at 32,768 tokens

  1. Bytes per token: 2 × 32 × 8 × 128 × 2 = 131,072 bytes, 128 KiB.
  2. Without the window, 32,768 tokens cost 32,768 × 128 KiB = 4 GiB.
  3. With the rolling buffer only min(32,768, 4,096) = 4,096 positions are held: 4,096 × 128 KiB = 512 MiB, eight times less: "On a sequence length of 32k tokens, this reduces the cache memory usage by 8x, without impacting the model quality" ({{paper|@m7p}}).
  4. With full multi-head attention (nkv = 32) and no window, four times step 2: 16 GiB, more than the model's own weights (about 14.5 GB at 16 bits).
  5. Reach at the last layer: 32 × 4,096 = 131,072 tokens, the paper's "theoretical attention span of approximately 131K tokens", sixteen times the 8,192-token context the model was trained on.

The two savings multiply: GQA divides the per-token cost by 4, the window caps the number of tokens, and at 32k together they hold the cache to 512 MiB against 16 GiB, a factor of 32.
