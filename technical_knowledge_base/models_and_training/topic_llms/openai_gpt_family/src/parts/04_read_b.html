The per-request price is still not the per-task price: a cheaper model that needs more turns, more effort or more reasoning tokens to finish can cost more per solved task than its price suggests, which is why OpenAI's own comparisons quote cost per task. Prompt caching: when a reused prefix pays

The prompt cache stores the key and value tensors of a prefix, not the text, so a later request with the same prefix skips recomputing it. On GPT-5.6 and later the first request writes the prefix at 1.25× the input rate and each reuse reads it at 0.1× (0.05× on GPT-6.1 Sol). A prefix must be at least 1,024 tokens, an entry stays eligible for 30 minutes after its last write or reuse, the whole rendered prefix must match (tools, effort and formatting settings included), and each request can create up to four cache writes ({{prompt caching guide|@cache}}).

CcachedCuncached=1.25+(N−1)rN,Nbreak-even=1.25−r1−r

N is the number of requests that use the prefix (one write, N − 1 full reads) and r the read rate as a fraction of the input price.

Recurrent depth: Astra's reasoning outside the transcript

Every earlier OpenAI reasoning model spends its test-time budget as hidden chain-of-thought tokens: text the caller cannot see, but which exists, is billed and can be monitored. Recurrent depth, also called opaque recurrence or a looped transformer, loops activations back through the model's own layers, so part of the deliberation happens in activations and never becomes text. Provenance. The architecture is known from reporting, not from OpenAI's documents: The Information reported it on 2 September ({{TechCrunch|@tcrunch}}), and OpenAI researchers, among them chief scientist Jakub Pachocki, answered that OpenAI had limited how much of the model uses the looped transformer so that its reasoning stays legible, and would share more about the architecture later ({{Fortune|@fortune}}). The system card does not describe the architecture ({{system card|@card}}). The generic mechanism, the first published architecture of the family (the Recurrent Looped Transformer, by Yifan Zhang, Jichen Feng and Shihan Qin, tested on synthetic algorithmic tasks only) and the sceptical reading are on {{Reasoning models and test-time compute|n:3c65c17b0d0d8190b9b4cd0acbcb66df}}; in one line, a loop buys serial depth without adding parameters or emitting tokens, and costs the readability of the reasoning.

What OpenAI has measured about Astra's own reasoning, in its system card ({{system card|@card}}):

  • Astra is "more capable of controlling its own CoT than GPT-5.6 Sol, and less likely to include incriminating information in its CoT".
  • Under adversarial conditions (pushed to evade monitors) it can remain undetected when strategically underperforming in evaluations (sandbagging), and can sometimes evade OpenAI's internal monitors on certain sabotage tasks.
  • No evidence of steganographic reasoning, hidden load-bearing reasoning inside ordinary text, was found.

Serving changed with it. If part of the working state lives in activations or in reasoning the caller never sees, a request that arrives without that state has to rebuild it. OpenAI's API keeps it on OpenAI's side: reasoning items are returned to the caller only as encrypted_content (in stateless mode) or kept server-side and referenced with previous_response_id, and reasoning.context: all_turns, the default on GPT-5.6 and supported on GPT-6.1 Sol, renders reasoning from earlier turns into the next one. The items "remain opaque" and carry only within one model family ({{reasoning guide|@reason}}). That is what the ARC Prize Provider Adapter uses, and why the products in the next section all move parts of the harness behind the API.
