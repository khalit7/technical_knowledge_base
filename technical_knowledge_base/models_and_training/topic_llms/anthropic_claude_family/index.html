Why understand Claude as a family

Claude is Anthropic's family of closed-weight large language models, sold through the Claude API, the major clouds and Anthropic's own apps. The weights are never released and the architecture is undisclosed.

Three things make it worth understanding as a family rather than as a list of releases, and one question runs through all three: what does a Claude task cost, and which dials does the caller still hold?

  • A price and capability ladder. Haiku, Sonnet, Opus, and above them the Mythos class: choosing a model is choosing a rung (Current lineup).
  • Constitutional AI. Anthropic's method of aligning a model against a written set of principles, still the base of its training (Training).
  • Thinking the caller steers. How much the model thinks decides what a task costs and how an agent harness has to be written (Thinking, Session cost).

The tabs: Lineage puts every release and every change to the API on one time axis; Session cost prices an agent session on every model at once; Effort and cost per task takes Artificial Analysis's measured runs apart; Task length shows how long a task each model can finish, from METR's data.

The terms you need

Tier

A rung of the ladder. Haiku is the fast, cheap tier; Sonnet the balanced default; Opus the tier for complex, long-running agentic work; Fable the most capable generally available model. Tiers are named sizes and prices, not architectures: Anthropic publishes no parameter counts and no architecture for any of them.

Mythos class

The tier above Opus that appeared in 2026. Fable is its generally available model; Mythos is the same model under looser safeguards, restricted to vetted organisations.

Snapshot and model ID

Every ID (claude-opus-5-5) is a pinned snapshot whose behaviour does not change under you. From the 4.6 generation IDs carry no date; earlier ones do (claude-haiku-4-5-20251001) (models overview).

Lifecycle

Active, legacy (served, no longer updated), deprecated (a retirement date is set) or retired (requests fail). Anthropic gives at least 60 days' notice before retiring a public model, and every current model's retirement is set for not sooner than one year after its release (model deprecations). Sonnet 4.5 was deprecated on 30 September 2026 and retires on 30 November: 61 days.

Thinking

Reasoning tokens the model writes before or between its answers, returned in thinking blocks and billed as output (Thinking).

Prompt caching

Storing a prompt prefix so later requests re-read it at a fraction of the input price. For an agent that re-reads a long context every turn, the cache-read price is usually the line item that decides the bill (Session cost).

Tokenizer

Claude Opus 4.7 and later models use a newer tokenizer that produces about 30% more tokens for the same text; Sonnet 4.6, Haiku 4.5 and earlier use the old one (pricing). 1M tokens is about 555K English words on the new tokenizer and about 750K on the old (models overview).

Lineage

Every release with its date, price and source is on the Lineage tab; this is what changed and why it matters.

2023: Claude 1 and 2, and Constitutional AI

Anthropic was founded in 2021 by former OpenAI safety leadership (Wikipedia) on the bet that the expensive human-preference step in RLHF (reinforcement learning from human feedback) could largely be replaced by the model judging itself against written principles: Constitutional AI, described under Training. Claude 1 was announced on 14 March 2023 (Anthropic). In May 2023 its context window grew from 9K to 100K tokens (Anthropic), well ahead of rivals; Claude 2 (11 July 2023) kept 100K (Anthropic) and Claude 2.1 (21 November 2023) doubled it to 200K (Anthropic). That made document-heavy work the family's early niche.

Claude 3 (March 2024): the three-tier shape

Haiku, Sonnet and Opus named a size, price and latency ladder produced from one training programme, now the industry default (Anthropic). Claude 3.5 Sonnet (June 2024) became the developer favourite by beating the larger Opus on code: 64% against Claude 3 Opus's 38% on Anthropic's internal agentic coding evaluation, at twice the speed and the Sonnet price of $3 and $15 per million tokens (Anthropic), the first clear public sign that post-training and data had overtaken parameter count for coding. The upgraded 3.5 Sonnet (22 October 2024) shipped computer use: a tool loop in which the model receives screenshots and returns mouse and keyboard actions, the first production API for GUI agents (Anthropic).

Claude 3.7 Sonnet (February 2025): hybrid reasoning

Rather than a separate reasoning model, both modes live in one checkpoint: the same weights either answer at once or think first (Anthropic). The caller set a token budget for thinking on each request (budget_tokens, up to the 128K output limit), the deliberate counter-design to OpenAI's router: the caller owned the cost and latency decision instead of delegating it to a classifier it could not inspect, and with one model there was no capability jump between the fast and slow paths. The cost was that the caller had to know when a task needed thinking, which is what the 2026 redesign handed back to the model. Claude Code, Anthropic's terminal coding agent, appeared alongside as a research preview.

Claude 4 to 4.5 (2025): agentic coding

Opus 4 and Sonnet 4 (22 May 2025), Opus 4.1 (August), Sonnet 4.5 (29 September), Haiku 4.5 (15 October) and Opus 4.5 (24 November) all pointed at long-horizon tool use rather than single-turn answers. Three concrete pieces:

  • Interleaved thinking: the model reasons between tool calls, not only before the first, so it can respond to what a command returned instead of following a plan made blind ("extended thinking with tool use", beta with Claude 4: Anthropic).
  • Memory: file-backed notes the model writes and re-reads across a long session, so state survives beyond what fits in context (Opus 4's memory files; the memory tool and context editing with Sonnet 4.5, Anthropic).
  • A 1M-token context beta for the cases where it does fit (Sonnet 4, August 2025, Anthropic).

Evaluation moved with the models, from single-answer benchmarks to SWE-bench (real GitHub issues, scored by whether the repository's own tests pass after the model's patch; Opus 4 scored 72.5% on the Verified set, Anthropic) and Terminal-Bench (multi-step tasks judged by the end state of a real shell). Both reward recovering from failure rather than first-try correctness. Opus 4.5 cut the Opus price from $15 and $75 to $5 and $25 and introduced the effort parameter: at medium effort it matched Sonnet 4.5's best SWE-bench Verified score with 76% fewer output tokens (Anthropic). It closed 2025 on top of the coding benchmarks.

Early 2026, Opus 4.6 to 4.8: the control surface changes

Opus 4.6 (5 February), Sonnet 4.6 (17 February), Opus 4.7 (16 April) and Opus 4.8 (28 May) were incremental in capability and consequential for anyone writing against the API.

  • Adaptive thinking, in which the model decides when and how deeply to think, arrived with Opus 4.6, with effort levels low to max steering it; the manual budget was deprecated (Anthropic). From Opus 4.7 a request carrying budget_tokens is rejected (thinking docs).
  • 1M tokens of context at the standard rate. Opus 4.6 launched its 1M window as a beta priced at $10 and $37.50 above 200K input tokens (Anthropic); today every 4.6-and-later model bills the full window at the standard per-token rate (pricing).
  • Opus 4.7 added the xhigh effort level and the new tokenizer (Anthropic's launch post gives 1.0 to 1.35 times as many tokens, Anthropic; the pricing page "approximately 30%"), and began rejecting non-default temperature, top_p and top_k, so sampling is steered by prompting rather than by parameters (model deprecations).

2026: the Mythos class

The class began as Claude Mythos Preview, announced on 7 April 2026 through Project Glasswing: a model whose ability to find and exploit software vulnerabilities Anthropic judged too dangerous for general release, offered only to a coalition of infrastructure and security organisations (among them AWS, Apple, Google, Microsoft and NVIDIA) at $25 and $125 per million input and output tokens, with $100 million in usage credits (Anthropic). Fable 5 and Mythos 5 (9 June 2026) turned it into a tier above Opus, breaking the three-name ladder for the first time since Claude 3: one underlying model, with Fable 5 carrying classifiers that route sensitive cybersecurity, biology and distillation requests to Opus 4.8, and Mythos 5 without them for approved partners, both at $10 and $50 (Anthropic). Access to Fable 5 was suspended from 12 June to 1 July. Sonnet 5 landed on 30 June (Anthropic), and Opus 5 on 24 July, "close to the frontier intelligence of Claude Fable 5 at half the price" ($5 and $25 against $10 and $50, Anthropic).

Fable 5.1 and Mythos 5.1 (1 September 2026): one model, two safeguard configurations

One underlying model shipped twice: Fable 5.1 generally available with production safeguards, Mythos 5.1 the same model under more permissive ones, for organisations in Anthropic's Cyber Verification and Life Sciences Verification programmes, US-only for now (Anthropic). The capability jump over Fable 5 is concentrated in long-horizon agentic work: Terminal-Bench-Science 0.1 from 24.7% to 52.6%, Terminal-Bench 4.0 from 42.0% to 55.8% (Mythos 5.1: 60.9%), AutomationBench from 17.1% to 31.4%, CursorBench 3.2.0 from 70.5% to 73.4%. The commercially significant change is a 75% cut to cached input, from $1.00 to $0.25 per million against $10 standard input; Anthropic puts the saving at "around 25%" for typical workloads and "up to around 45%" for highly agentic ones (the Session cost tab shows which token mixes give which). Enterprise Frontier Safeguards let customers keep their data on their own cloud infrastructure while Anthropic can still detect misuse, rolling out from autumn 2026 (Anthropic). It also introduced preserved thinking (Passing thinking back). Coverage: VentureBeat.

Opus 5.5 and Sonnet 5.5 (22 and 28 September 2026): the Claude 5.5 family

Opus 5.5 costs $4 and $20 per million, 20% below Opus 5, with cache reads at $0.20, 60% below Opus 5's $0.50; Anthropic puts the overall saving at 40% on typical workloads and output generation at more than 30% faster, with output "40% less verbose" than Opus 5 (Anthropic). On the same tokens the price list alone makes it 35% cheaper (the worked session below: $4.50 against $6.875), so the rest of the claimed 40% is fewer tokens. On Anthropic's own table it beats Fable 5.1 on every row. Against GPT-6 Astra the sweep is not clean: Astra leads on Terminal-Bench-Science 0.1 and narrowly on AutomationBench. Anthropic also claims that Opus 5.5 at its default medium effort beats Astra at max effort on GDPval-AA v2.1, and beats Astra's top FrontierCode v1.1 score, each for about a fifth of the cost per task; the independent aggregate is less one-sided (Rankings).

Sonnet 5.5 followed six days later at unchanged Sonnet pricing ($2 and $10, cache reads $0.20), "30% faster" than Sonnet 5 and costing "up to 30% less per task" (Anthropic). It lands next to Opus 5.5: ahead on Terminal-Bench 4.0, eight points behind on FrontierCode 1.1, two Elo points behind on GDPval-AA v2.1 (measured in pre-release testing that a structured-output bug could degrade, an effect Anthropic expects to be minimal). Both made thinking harder to switch off: Opus 5.5's adaptive thinking cannot be disabled, and Sonnet 5.5's lowest setting, between_tools, removes only the up-front thinking.

Where Claude ranks

The Artificial Analysis Intelligence Index is a composite of ten evaluations (agents 30%, coding 20%, general knowledge 30%, scientific reasoning 20%) on one 0 to 100 scale, a coarse cross-lab ranking since the mixture is theirs rather than yours (methodology). Its version matters more than its rank. Version 4.2 (4 September 2026) dropped GPQA Diamond as saturated; version 4.3 (7 September) moved Terminal-Bench to 4.0, replaced tau3-Banking with AutomationBench-AA and raised the weight of private held-out tests from 40% to 45%; methodology 4.3.2 (19 September) re-anchored the GDPval-AA Elo scale. The result is still a 0 to 100 score.

On v4.3, Opus 5.5 at max effort leads every model at 57.6; Fable 5.1 (max) scores 53.4, Opus 5 (max) 50.8 (Artificial Analysis, read 1 October 2026). Opus 5.5 at its default medium effort scores 51.2 at $1.34 per index task against GPT-6 Astra at max effort on 52.7 at $3.26: a point and a half lower for 41% of the cost (1.336 / 3.2575; Artificial Analysis). Before v4.2 the composite was on a different 0 to 100 scale, on which Opus 5 led through August 2026 at roughly 63 and Fable 5 at roughly 62; those figures cannot be set beside v4.3 scores, and no v4.3 model inherits them. The Effort and cost per task tab plots every Claude run.

What is measured directly is narrower and firmer. Real-SWE, published in September 2026 by Specific Labs on tasks licensed from private production codebases, put Fable 5.1 in Claude Code first at 38.8% (GPT-6 Astra in Codex 33.8%, Gemini 3.8 Flash 31.2%, with overlapping confidence intervals); it did not include Opus 5.5 or Sonnet 5.5 (DEV Community). The documentation now recommends starting with Opus 5.5 for most workloads and moving to Fable 5.1 for demanding reasoning and long-horizon agentic work, "or when your evals on Claude Opus 5.5 at higher effort still fall short" (models overview). The release's other case for Fable 5.1 is its writing: Glean's judges preferred its answers "roughly 2-to-1" over Fable 5 on everyday knowledge questions, and Canva called the writing "the standout" (Anthropic).

How thinking is controlled

The family's signature API surface is how the caller steers deliberation, and it changed shape in 2026. The first design (Claude 3.7 Sonnet to Opus 4.5) was a caller-set cap; the current one is a model-decided amount steered by a coarse caller-set level.

Adaptive thinking. The model decides, per request and per step, whether to think and for how long. On Opus 5.5, Fable 5.1 and Mythos 5.1 it is always on and cannot be disabled; on Sonnet 5.5 it is on by default. On Opus 4.6 to 4.8 and Sonnet 4.6 it is off until you ask for it. Only Haiku 4.5 among current models still uses the older manual mode, thinking: {type: "enabled", budget_tokens: N} (thinking docs).

Effort. The caller steers adaptive thinking with output_config.effort: low, medium, high, xhigh or max. Effort is a behavioural signal, not a token budget: it scales every output token (thinking, text and tool calls, so lower effort also means fewer and terser tool calls), and at low effort the model still thinks on a hard enough problem, just less. The hard ceiling is max_tokens, which bounds thinking plus response together. The default is high on most models and medium on Opus 5.5, so a request that omits effort runs one level lower on Opus 5.5 than it did on Opus 5 (effort docs).

Changing effort mid-conversation. On Fable 5.1, Mythos 5.1, Opus 5.5, Opus 5 and Sonnet 5.5, a per-message setting (beta: an empty system message carrying the new output_config.effort) changes it from the next user turn and keeps the prompt cache. Changing the top-level value between requests restarts the cache, because effort is rendered into the prompt itself (effort docs).

Interleaved thinking. Thinking between tool calls, so the model reasons about each tool result before acting on it. Under adaptive thinking it is automatic; Haiku 4.5 does not support it. The newest models (Fable 5.1, Mythos 5.1, Opus 5.5, Sonnet 5.5, Fable 5) also write short progress updates between tool calls, notes for the person watching the agent rather than reasoning, and they write fewer of them at higher effort (thinking docs).

What you see, and what you pay for. You never receive the raw chain of thought. With display: "summarized" a thinking block holds a summary written by a different model; with "omitted", the default on the 5.x models, the block's text is empty (a beta "updates" shows only the progress updates). Either way you are billed for the full thinking tokens as output tokens, so the billed output count does not match the text you can see. On Fable 5.1, Opus 5.5, Sonnet 5.5 and Fable 5 a prompt that tries to pull the reasoning into the visible answer can be refused as reasoning_extraction.

Passing thinking back, and preserved thinking

Each thinking block carries a signature, an encrypted copy of the full reasoning. Within a tool-use turn, every thinking block must be passed back complete and unmodified alongside its tool_use block, or the model loses the reasoning that led to the call; a modified block is rejected with a 400 error. On current Opus and Sonnet models and the Mythos class, earlier turns' thinking blocks stay in context (and in the cache) and are billed as input like the rest of the history; on Haiku 4.5 and older models they are stripped once a new user message arrives (thinking docs).

Preserved thinking, introduced with Fable 5.1 and extended to Opus 5.5 and Sonnet 5.5, adds two checks to the signature (preserved thinking docs):

  • Which model produced the block. Fable 5.1 and Mythos 5.1 read every earlier model's blocks and no earlier model reads theirs; Opus 5.5 reads Opus 5 and earlier Opus, Sonnet and Haiku blocks; Sonnet 5.5 reads Sonnet 5, Opus 4.8, Haiku 4.5 and earlier. A block the current model cannot read is dropped silently and not billed.
  • Whether everything before it is unchanged: the system prompt, the tools and every earlier message. If the prefix changed, that block and every later one are invalid, and the API either rejects the request with a 400 error or drops the invalid blocks (unbilled, though the model may then think more to rebuild the reasoning), whichever the caller chooses.

The prefix check is enforced by default for API accounts created on or after 31 August 2026 and is opt-in on older ones; Sonnet 5.5 also ties its blocks to the account that produced them. Anthropic states the purpose as anti-distillation: without it, someone could take a thinking block from an expensive model, edit the conversation before it, and reuse the reasoning to train or steer a cheaper model. It sits beside Anthropic's September threat report (10 September, twelve days before Opus 5.5), which lists illicit distillation among the seven kinds of misuse it disrupted (Anthropic), and it narrows what a neutral harness can replay or reconstruct from a transcript: the same direction as GPT-6 Astra's recurrent depth, for a different reason (detail on OpenAI: GPT family).

Append-only, or what an edit costs

Try: "Edit the system prompt in place", then "Add a mid-conversation system message instead". The same instruction reaches the model either way; only the second keeps the reasoning and the cache.

Two consequences for a harness builder. Cost per task is now steered rather than set: effort is the dial and max_tokens the fuse, and neither fixes the number of thinking tokens in advance. And the conversation has to be append-only: a harness that rewrites earlier turns, edits the system prompt mid-session or swaps tools in place invalidates the model's reasoning, so instructions, tool changes and effort changes go in as new messages at the end (mid-conversation system messages, tool_addition and tool_removal blocks, per-message effort, server-side compaction and context editing). This is also why Claude-based harnesses such as Claude Code do well on long-horizon coding evaluations like SWE-bench and Terminal-Bench: the model is built to think again after every observation.

How Claude is trained

Constitutional AI and RLAIF

Constitutional AI runs in two phases (Bai et al., 2022). A constitution is a short, public list of explicit principles; the paper's has 16 about harmlessness, one drawn at random at every step. In the supervised phase the model answers, critiques its own answer against a principle and rewrites it, and the rewrites become fine-tuning data. In the RL phase a feedback model judges pairs of responses by which better satisfies a principle, giving RLAIF (reinforcement learning from AI feedback) where RLHF would have used human rankings. Step through it:

What it buys is scale and auditability: harmlessness labels stop being the human bottleneck, and the values are a document you can read, diff and argue with rather than an aggregate of contractor judgements. What it costs is that the judge shares the model's blind spots, so the constitution has to carry the work that disagreement between humans used to. Note what the paper did not replace: helpfulness labels were still human, and only the harmlessness labels came from the AI, mixed into one hybrid preference model.

Verifiable rewards and agentic RL

Constitutional AI and RLAIF remain the base, now combined with RLVR (reinforcement learning from verifiable rewards) for reasoning, where a program checks the answer (a test suite, a maths grader) rather than a learned preference model, so it cannot be gamed by producing text a judge likes; and with heavy agentic RL, where an episode is a whole task inside a sandboxed environment with real tools and the reward depends on whether the task ended up done. That is the expensive part and the likeliest source of the family's agentic lead: the environments, not the objective, are the moat. The Task length tab shows the lead from outside: on METR's measurements six of the record-setting time horizons between June 2024 and April 2026 belong to Claude models.

What Anthropic publishes

Unusually detailed system cards, alignment evaluations and interpretability research, and almost nothing about architecture. Two interpretability lines worth knowing by name. Circuit tracing replaces the model's MLP layers with a cross-layer transcoder of sparse, human-readable features and traces which features actually drove a given output, producing an attribution graph for one behaviour; it was applied to Claude 3.5 Haiku (Anthropic, March 2025). The introspection work injects a concept's activation pattern into the model and asks whether it notices: Claude Opus 4.1 did in about 20% of trials at the best layer and strength, and "failures of introspection remain the norm" (Anthropic, October 2025). The practical asymmetry: you can learn a great deal about what these models do and essentially nothing about how they are built. Preserved thinking extends the same asymmetry to the reasoning itself, which is summarised or hidden and now also protected against extraction.

Business shape

Revenue skews to API, enterprise and coding against OpenAI's consumer skew, which explains the product priorities: agentic tooling, long context and reliability over voice, image generation and consumer surface area. The restricted Mythos releases add a second shape: capability sold first to vetted security and life-sciences organisations, with a safeguarded twin for everyone else.

Worked example: what one agent session costs

An agent session re-reads the same long context every turn, so its cost splits into four parts: writing the context to the cache once, re-reading it from the cache each turn, the new input each turn, and the output each turn (thinking included).

What it shows. On Fable 5 the cached prefix was 40% of each turn's cost ($0.10 of $0.25); after the cut it is 14% ($0.025 of $0.175), and output, thinking included, is 57%. The cache cut alone makes the same session 27% cheaper, in line with Anthropic's "around 25% for typical workloads"; without caching at all, Fable 5.1 costs almost six times as much. Once caching is on and priced this low, the lever left is how many tokens the model writes, which is what effort controls. Two caveats keep the comparison honest: the example gives every model the same token counts, but Opus 4.7 and later count the same text as about 30% more tokens than Haiku 4.5 does, so per-token prices understate how much cheaper Haiku is per word; and a cheaper model that needs more turns or more output tokens to finish can cost more per task, which is the quantity that matters. Artificial Analysis's runs show it happening: Sonnet 5.5 at max effort costs $7.62 per index task against Opus 5.5's $5.98 at half the per-token price, because it used 1.6 times the output tokens and 1.7 times the input (Effort and cost per task).

Which model when

  • Start with Opus 5.5 for most work, at its default medium effort, which is Anthropic's own recommendation. Raise effort before changing model.
  • Move up to Fable 5.1 for demanding reasoning and long-horizon agentic work where Opus 5.5 at xhigh or max still falls short on your evaluations, or where writing quality is the product. It costs 2.5 times Opus 5.5 per token, and on Anthropic's published table it does not beat Opus 5.5 on any listed evaluation.
  • Move down to Sonnet 5.5 for high-volume agentic coding, well-scoped tasks and anything latency-sensitive: close to Opus 5.5 on most rows (ahead on Terminal-Bench 4.0, eight points behind on FrontierCode 1.1) at half the price, and faster. Its docs suggest starting agentic coding at medium effort; its thinking can be reduced to between_tools (accepted at high effort or below) when up-front deliberation is not worth paying for.
  • Use Haiku 4.5 for the cheapest, fastest classification, extraction and sub-agent work that needs neither 1M tokens of context nor adaptive thinking, and plan for its successor: its retirement date is not sooner than 15 October 2026.
  • Mythos 5.1 is not a choice for most teams: it is restricted to vetted cybersecurity and life-sciences organisations.
  • Batch anything that can wait (half price), and cache any prefix that is read more than once.

Common mistakes

Sending budget_tokens to a current model
It returns a 400 error on Opus 4.7 and everything after; steer with effort and cap with max_tokens instead.
Treating effort as a budget
Effort is guidance the model interprets; only max_tokens is a hard limit, and it bounds thinking plus response together.
Assuming hidden thinking is free
With the default display: "omitted" the thinking text is empty but every thinking token is billed as output.
Editing the conversation history
Rewriting an earlier turn, the system prompt or the tool list in place invalidates every later thinking block under preserved thinking, and restarts the cache from the edit. Append instead.
Comparing per-token prices across tokenizers
Opus 4.7 and later count the same text as about 30% more tokens than Sonnet 4.6, Haiku 4.5 and earlier. Compare cost per task.
Carrying effort settings across models
Opus 5.5 defaults to medium where Opus 5 defaulted to high, and Sonnet 5.5's levels are recalibrated against Sonnet 5; rerun an effort sweep on your own evaluations.
Quoting a benchmark number without its harness
Anthropic's Opus 5.5 figures are at max effort except Terminal-Bench 4.0 (xhigh), OSWorld comes in 2.0 and 2.1 versions and in partial and strict scoring, and GDPval-AA v2 and v2.1 sit on different Elo anchors; a number moved without those is a future false comparison (see the grid under Lineage).
Carrying an old index score forward
The roughly 63 and 62 Artificial Analysis figures belong to Opus 5 and Fable 5 on the pre-v4.2 scale. On v4.3 Opus 5 (max) is 50.8 and Fable 5.1 (max) 53.4.

Effort and cost per task

Artificial Analysis runs each model through its Intelligence Index (v4.3, methodology 4.3.2, read 1 October 2026) and reports the score, the cost per index task and the tokens it used (leaderboard). Effort settings of the same model are joined by a line. Cost is on a log scale.

One run taken apart

The cost of a whole index run splits into output (published output tokens times the output price), cached input and uncached input. Artificial Analysis does not publish the cache-hit share it assumes ("live measurements of the model's typical cache hit rate", methodology), so the share below is fitted: the value that makes the three parts add up to its published run cost. The split therefore reproduces Artificial Analysis by construction.

Try: Run "Sonnet 5.5 (max)", price it at Opus 5.5: half the per-token price did not make it cheaper per task, because it used more tokens. Then run "Fable 5.1 (max)" priced at Fable 5: the old cache price makes the same run about 31% dearer.

Task length: how long a task each model can finish

METR measures a model's 50% time horizon: the length of task, timed by how long it takes skilled humans, that the model completes half the time. The data are METR's own (METR-Horizon-v1.1, updated 8 May 2026, raw data, METR); no Claude 5.x model has been measured yet. The fitted line is an ordinary least-squares fit of log2(horizon) on release date over the points you select, and its slope gives the doubling time.
