What it is and why it matters

Almost every open model released since 2023 is the same machine as GPT-2: a stack of identical decoder blocks, each doing attention (every token looks back at earlier tokens) and then a feed-forward network (FFN, a per-token multilayer perceptron), with normalisation and a residual connection around each, and a positional scheme telling attention where each token sits. What differs between models is a small number of choices inside that block, and nearly all of them are about memory and compute efficiency rather than modelling power.

This page owns those generic mechanisms for the llms topic: the attention variants (MHA, MQA, GQA, MLA, sliding window, trained sparse, linear and hybrid), the MoE feed-forward in brief, normalisation placement, positional encoding and stack shape, each with what it buys and what it costs. The lab pages keep only what their own variant does differently, and carry their own animations of it: {{DeepSeek|n:3c65c17b0d0d81a2ae7ec6796947a235}} (MLA, DSA, V4.1-Flash), {{Qwen|n:3c65c17b0d0d81fd8c36ce06672bb235}} and {{Zhipu|n:3c65c17b0d0d81a88a84c2ca84b4daf4}} (hybrids), {{Moonshot AI: Kimi|n:3c65c17b0d0d81f5abf5dbdbac821a12}} (KDA) and {{Mistral AI|n:3c65c17b0d0d814a9882e6ebc326fa56}} (sliding window).

The single number that ties the choices together is the KV cache per token: the bytes a model must keep in accelerator memory for every token of context it holds. It is set by the attention design, not by the parameter count, so two models of the same size can differ on it by an order of magnitude, and it decides whether long context and high concurrency are affordable. Learn to compute it and read it off a card, and most of what changed in a new model follows.

Terms

Decoder block
Attention, then an FFN, each wrapped as x ← x + F(Norm(x)) in the pre-norm layout most models use. A model is L of these stacked.
Residual stream
The vector x each token carries through the stack; every sublayer reads it and adds its output back.
Query, key, value
Per-token vectors made by learned projections of the residual stream. A token's query is compared with earlier tokens' keys to decide how much of each of their values to take.
Head
One independent attention computation of dimension dh (the head dimension, typically 64 to 256). A layer runs H query heads in parallel.
KV heads
The number of distinct key and value projections a layer computes, Hkv: equal to H in classic multi-head attention, smaller in the variants below.
KV cache
During generation, the keys and values of every earlier token, stored so they are not recomputed at each step. It grows by one entry per layer for every token of context.
Prefill and decode
Prefill processes the whole prompt in parallel and is compute-bound; decode produces one token at a time and must read all the weights and the whole KV cache for each token, so it is memory-bandwidth-bound. A smaller cache means faster decode, not only more room.
Dense and MoE
A dense model runs every FFN parameter for every token; a mixture-of-experts (MoE) model has many expert FFNs and a router that activates a few per token, so total parameters (memory) and active parameters (compute per token) differ.

Attention and the KV cache

One attention head computes, for a sequence of T tokens:

Attention(Q, K, V) = softmax( Q K⊤ / √dh + M ) V
Q, K, V
∈ ℝT × dh: the query, key and value vector of every token, one per row, for this head
Q K⊤
the T × T matrix of dot products between every query and every key (the attention logits)
√dh
keeps the logits' spread roughly constant as the head dimension grows
M
the mask: 0 where a query may look, −∞ where it may not (for a causal decoder, every later position)
softmax
runs along each row, turning that query's logits into weights that sum to 1, which then average the rows of V

A layer runs H such heads and concatenates their outputs. At decode time only the newest token's query is new, but it needs the keys and values of all earlier tokens, which is why they are cached. The cache for one token, and the memory a deployment must hold, are:

KV bytes per token = 2 × L × Hkv × dh × b
KV memory = KV bytes per token × Tctx × Nconcurrent
2
counts keys and values
L
the number of layers that keep a cache (all of them in a plain transformer)
Hkv
KV heads per layer, which is where the attention variant enters
dh
the head dimension
b
bytes per stored element: 2 for BF16, 1 for FP8, 0.5 for FP4
Tctx, Nconcurrent
the context held per request, and the number of requests resident at once

Worked example: Llama 3.1 70B. Its {{configuration|@l70}} has L = 80 layers, 64 query heads, Hkv = 8 KV heads and a hidden size of 8,192, so dh = 8,192 / 64 = 128. In BF16: per token 2 × 80 × 8 × 128 × 2 = 327,680 bytes = 320 KiB; one request holding a 131,072-token (128K) context 327,680 × 131,072 = 42,949,672,960 bytes = 40 GiB; eight such requests, 320 GiB of KV cache, more than twice the roughly 140 GB the 70 billion BF16 weights occupy (70 × 109 × 2 bytes). Had the same model used full multi-head attention (Hkv = 64), every figure would be 8 times larger: 2,560 KiB per token and 320 GiB for a single 128K request. That factor is why the attention variant, not the parameter count, decides whether long context is affordable.

Try: the defaults are Llama 3.1 70B and reproduce 320 KiB, 40 GiB and 320 GiB. Set KV heads to 64 to see the MHA counterfactual, or FP8 to halve everything.

The gallery's headline does not credit sliding windows

The gallery quotes this per-token figure in BF16 for every model, using the same formula (with the MLA and linear-layer variants below), per its {{KV-cache calculation notes|@kvc}}: "the logical cache added by one token for one sequence", batch 1, 2 bytes per element, a logical estimate separate from measured serving memory (allocator padding, buffers and kernel layouts usually add more). A windowed layer is counted at full per-token cost: the window only limits how long entries are kept. So for a model with many windowed layers the long-context memory is much lower than the headline suggests (worked through under sliding windows). The same notes count only layers that append to a growing cache: DeltaNet, Lightning Attention, Mamba-2 and xLSTM layers add 0 B per token and keep a fixed-size state instead.
