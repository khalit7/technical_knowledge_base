What MiniMax is: one running experiment on attention

MiniMax is a Shanghai lab (founded December 2021, Wikipedia) whose model line is defined by one running experiment: how far the quadratic softmax attention of a standard transformer can be replaced by something cheaper without losing frontier quality.

It has shipped all three answers at production scale, one after another, and written up why it moved: linear attention in a hybrid (MiniMax-01 and M1), a public reversal to full attention (M2), and trained block-sparse attention (M3). That sequence, with the reasons attached, is unusually direct evidence on where efficient attention breaks, and for anyone deciding what to serve it is worth more than any one of the models.

The softmax sits between the two matrix products, so the n × n score matrix must be formed: prefill costs on the order of n2d per head, and every decoded token must read the keys and values of every earlier token, which are kept in the KV cache. Per layer and per token that cache holds

GQA (grouped-query attention) shrinks Hkv by letting several query heads share one key/value head; the Architecture Gallery works through it and the other variants across the field. MiniMax has attacked the quadratic term, then given the attack up, then attacked the reads instead.

Lightning attention (MiniMax-01, M1): linear attention computed in blocks

Linear attention drops the softmax, so the product becomes associative and can be regrouped:

(QK⊤)V=Q(K⊤V)

The n × n matrix disappears and a d × d state takes its place. In recurrent form, with row vectors qt, kt, vt,

St=St−1+𝐤t⊤𝐯t,𝐨t=𝐪tSt

so decoding needs no KV cache at all, only the fixed-size state, whatever the context length. The gallery page owns this recurrence and its gated successors such as Gated DeltaNet.

Lightning attention is MiniMax's IO-aware way of computing it: a kernel contribution, not a new mathematical form (MiniMax-01 report, arXiv 2501.08313). Causal linear attention looks cheap, but computed token by token it is a cumulative sum along the sequence, which serialises the very dimension a GPU wants to parallelise. Lightning attention cuts the sequence into blocks of B tokens and splits each block's output in two: inside the block, the ordinary masked quadratic product (small and fully parallel, the report's "left product"); from all earlier blocks, one multiplication by the carried state (the "right product"). For block i:

Oi=[(QiKi⊤)⊙M]Vi+QiSi−1,Si=Si−1+Ki⊤Vi
Qi, Ki, Vi
the queries, keys and values of the B tokens in block i, each B × d
M
the B × B causal mask (1 where the key is at or before the query, 0 elsewhere); ⊙ is elementwise multiplication, so the first term is the intra-block part
Si−1
the d × d state summing kj⊤vj over every token in blocks 1 to i − 1, so the second term is the inter-block part; the second equation carries the state on

The cost per head is

O(nd2+nBd)

where nd2 is the state updates and reads and nBd the intra-block products: linear in n for a fixed block size.

MiniMax partitions sequences into blocks of 256 tokens, keeps each block's working set in on-chip SRAM in the spirit of FlashAttention, and reports that lightning attention keeps a constant training speed as sequence length grows, the only linear model in its comparison to beat FlashAttention-2 (MiniMax-01 report, section 2.2 and appendix).

Worked example (toy, one-dimensional head). Four tokens with scalar q = (1, 2, 1, 3), k = (1, 1, 2, 1), v = (2, 1, 1, 3), so kjvj = (2, 1, 2, 3). Token by token, ot = qt ∑j ≤ t kjvj: the running sums are 2, 3, 5, 8, so o = (2, 6, 5, 24). In blocks of B = 2: block 1 is intra-block only, o1 = 1 × 2 = 2 and o2 = 2 × (2 + 1) = 6, leaving state S1 = 3. Block 2: o3 = 1 × 2 + 1 × 3 = 5 (intra plus inter) and o4 = 3 × (2 + 3) + 3 × 3 = 24. Same outputs, but each block's work is parallel and only one small state crosses the block boundary.

Try: step through the same four tokens both ways. Token by token, every output waits for the one before it; in blocks, the two outputs of a block are computed together and only the state (green) is handed on.

Worked example (real scale). One head with d = 128, B = 256 and n = 1,048,576 tokens: softmax attention's n2d ≈ 1.41 × 1014 against lightning's nd(d + B) = 1,048,576 × 128 × 384 ≈ 5.15 × 1010, a ratio of n / (d + B) ≈ 2,731 in multiply-adds (constant factors ignored). In serial terms, a token-by-token scan over that sequence is 1,048,576 dependent steps; in blocks of 256 it is 4,096.

The 7:1 hybrid, and what the state costs

A fixed d × d state is a lossy summary of everything seen so far, so exact recall of one earlier token (a needle in a long document, a definition looked up in context, an identifier copied verbatim) degrades in a way perplexity does not show. The MiniMax-01 report says it plainly: pure linear attention matches the transformer at language modelling but "falls short in retrieval tasks". MiniMax-01 therefore shipped a 7:1 hybrid: seven lightning-attention layers, then one softmax-attention layer, repeating. The linear layers do the cheap bulk mixing; the periodic softmax layers restore exact addressing.

MiniMax-Text-01 has 80 layers, 64 query heads of dimension 128, and softmax layers using GQA with 8 key/value heads (config; its attn_type_list marks every eighth layer as softmax). So 10 layers keep a KV cache and 70 keep a state:

  • KV cache per token: 10 × 2 × 8 × 128 × 2 = 40,960 bytes = 40 KiB, against 320 KiB if all 80 layers were softmax GQA. At a 1,048,576-token context that is 40 GiB per sequence instead of 320 GiB.
  • State per sequence: 70 × 64 × 128 × 128 = 73,400,320 elements, fixed: 140 MiB at 2 bytes per element whatever the context (the report does not state the state's precision; in FP32 it doubles).

M2's reversal: back to full attention

M2 (27 October 2025, release notes) dropped lightning attention entirely and returned to softmax GQA in every layer: 62 layers, 48 query heads and 8 key/value heads of dimension 128 (config), trained to a 192K-token native context (M2 series report, arXiv 2605.26494). That is 62 × 2 × 8 × 128 × 2 bytes = 248 KiB per token, about 46.5 GiB for one full 196,608-token sequence: 6.2 times the hybrid's per-token cache, paid deliberately.

MiniMax's account (Why did M2 end up as a full attention model?; M2 series report, section 2.2.2):

  • The benchmarks hid the gap. During Text-01's development, hybrid models matched full attention on MMLU, BBH, MATH and LongBench, but at larger scale showed "clear deficits in complex, multi-hop reasoning". The real bottleneck, in their words, was "the limitations of evaluation": proxy metrics built to catch the weakness may stop correlating with real performance at the next scale.
  • Some circuits are set early. Retrieval heads and induction heads (attention patterns that find and copy an earlier token) are established early in pretraining in global attention. When MiniMax converted a trained model into a sliding-window hybrid by continued pretraining, it "can hardly adjust those patterns afterwards", and finding every such head to keep as full attention "from human priors" was nearly impossible.
  • Sliding windows failed the same way. In ablations continued for hundreds of billions to trillions of tokens, hybrid sliding-window attention (SWA) degraded retrieval, multi-hop reasoning and in-context learning. The chart below has every row of the two tables; the gap opens past 32K tokens and is mixed below it.
  • The infrastructure was not there. Linear attention is far more sensitive to numerical precision, many linear designs are memory-bound even in training, and it did not yet work cleanly with prefix caching and speculative decoding. In theory linear attention's compute crossover with full attention lies at "a few thousand tokens"; reaching it in production needs those three problems solved.

Both regimes that had become the product, long reasoning chains that refer back to their own earlier steps and agentic loops whose context is full of tool outputs to be quoted exactly, are exact-recall workloads, where a compressed state is weakest; paying the quadratic cost was the cheaper trade. MiniMax framed the reversal as conditional: "as GPU compute growth slows while data length keeps increasing, the benefits of linear and sparse attention will gradually emerge."

MSA (MiniMax Sparse Attention, M3): keep exact lookup, read a few blocks

M3 takes the third route. Trained sparse attention keeps the softmax and the full KV cache but lets each query attend to only a selected subset of keys; if the right keys are selected the lookup is exact, because nothing was compressed. The difficulty moves into selection (cheap, and trainable end to end) and into kernels (a selected set is irregular, and irregular memory access is what GPUs do worst). The mechanism is from the MSA paper, arXiv 2606.13392 and M3's config:

  1. Index branch. Two small projections are added to a GQA layer: one index query head per key/value group and a single index key head shared by all groups (in M3, 4 index query heads and the shared key, all of dimension 128). For query position i and group r it scores every earlier token: Si,j = qidxi,r · kidxj / √didx.
  2. Block scoring. The keys are cut into blocks of Bk = 128 tokens, and a block's score is the maximum of its tokens' scores (max-pooling), so one strongly relevant token is enough to select its block.
  3. Selection per GQA group. Each query keeps the top k = 16 blocks, chosen separately for each key/value group, and the block holding the query itself is always included. Selection ranks raw scores, since softmax preserves order ("exp-free" top-k).
  4. Exact attention on the selection. Ordinary softmax attention runs over the kBk = 2,048 selected keys only, with each group's own key/value head.
  5. Training. The index branch learns with a KL-divergence loss that pulls its distribution towards the main branch's group-averaged attention on the selected tokens; its inputs are detached, so this loss updates only the two index projections and cannot simplify the main model's attention to lower itself. The indexer warms up under full attention (40B tokens in the paper's runs) before sparsity is switched on. MSA works both from scratch and by converting a full-attention checkpoint.

Worked example: M3's shape at a 1M context. With H = 64, dh = 128, kBk = 2,048, Hidx = 4, didx = 128, n = 1,048,576: Cfull = 2 × 64 × 128 × 1,048,576 ≈ 1.72 × 1010; CMSA = 33,554,432 + 536,870,912 ≈ 5.70 × 108; a ratio of about 30. Selection does not shrink storage. Every key must stay resident for the indexer to choose from. M3's main cache is 60 × 2 × 4 × 128 × 2 bytes = 120 KiB per token, about 120 GiB for one 1M-token sequence, plus the index keys: one 128-dimension key per token in each of the 57 MSA layers, 14.25 KiB more per token if stored in BF16 (the precision is not stated; assumption). The saving over M2 there comes from halving the key/value heads (8 to 4), not from MSA. The model card's "reduces the attention compute and memory footprint" (M3 card) is true of what each query reads, not of what is stored.

The kernel: "KV outer, gather Q". A natural sparse kernel loops over queries and fetches the blocks each one selected; every fetched tile then serves only the G query heads of one group, so the arithmetic per byte loaded is about G (16 in M3, 64 query heads over 4 groups). MSA's kernel inverts the loops: the outer loop runs over KV blocks, and for each block it gathers every query that selected it, packing several query positions into one 128 × 128 matrix multiply, so the tile is loaded once and reused by all of them. The paper puts the arithmetic intensity at about ⅔ Bk, roughly 85 for Bk = 128, against G for the query-outer order; hot blocks (an early "sink" block nearly every query selects) are split across many thread blocks by a scheduler. MiniMax report it as more than 4 times faster than the open-source Flash-Sparse-Attention and flash-moba kernels (M3 announcement, repeated by launch partner Fireworks; kernel code on GitHub).

Try: move the block size and the GQA ratio. The two loop orders do the same arithmetic; only the bytes moved differ. Larger blocks favour KV-outer; selection gets coarser.

MSA's distinguishing combination is block-level selection with a separate top-k per GQA group, which keeps reads contiguous while letting different groups retrieve different blocks (the paper's attention maps show each group tracing its own long-range stripes beside a shared local diagonal and sink column). In granularity it is finer than MoBA but coarser than DSA, whose selection is per token. The M3 announcement's wording that MSA partitions the KV "more precisely" than DSA and MoBA (MiniMax) is about effective coverage, not selection unit, and should not be read as finer than DSA.

Quality. On the paper's 109B test model (41 layers, 6B active, 3T training tokens), MSA converted from a full-attention checkpoint and extended to long context scored 72.12 on RULER at 128K against 72.00 for full attention, and 45.93 on HELMET at 128K against 46.53. Trained sparse from scratch, it matched or beat full attention on most of the paper's pretraining suite. In ablations, block size (32, 64 or 128 at the same token budget) made little difference to quality, and a FLOP-matched sliding window had higher perplexity than MSA on agent tasks throughout training.

The arc

Compressing history into a fixed state (linear) buys the most and costs recall; selecting which history to read (sparse) buys less and preserves exactness, at the price of a trained selector that can miss; full attention remains the reference both are measured against. MiniMax's three generations are that sentence run as an experiment, and the reversal in the middle is more informative than either claim around it.

CISPO: the RL objective from M1

CISPO (Clipped Importance-Sampling Policy Optimization) was introduced with M1 (M1 report, arXiv 2506.13585) to fix one failure of PPO-style clipping on long reasoning traces. RL for LLMs owns PPO and GRPO; the one fact needed here is that both maximise, per token,

min(rA^,clip(r,1−ε,1+ε)A^)
r

When Â > 0 and r > 1 + ε, the clipped branch is the minimum and it does not depend on the parameters, so the token's gradient is exactly zero (and symmetrically for Â < 0 and r < 1 − ε).

The problem. MiniMax found that reflective tokens such as "However", "Recheck", "Wait" and "Aha", which act as forks in a reasoning path, are rare and get low probabilities from the base model. A token with low probability can double its probability in one update, so after the first on-policy step its ratio is far above 1 + ε and it is clipped out of every later off-policy step in the batch (M1 ran 16 off-policy updates per generation batch): the tokens that steer the reasoning stop contributing exactly when they are being learned. DAPO's answer, a higher upper clip bound, was "less effective" in this setup.

The gradient of a token's term is r̂ Â ∇θ log πθ: a REINFORCE update with a truncated importance weight. Every token keeps a non-zero gradient; clipping only caps how much one token's weight can grow. There is no KL penalty. M2's agentic RL kept CISPO with the weight's lower bound set to 0, clip(r, 0, 1 + εIShigh), which lets tokens that became improbable be down-weighted aggressively (M2 report, section 6.1.4).

Worked example (illustrative numbers). A "Wait" token had probability 0.02 under the sampling policy and 0.05 after the first update, so r = 2.5, with Â = +1 and ε = εIShigh = 0.2. PPO-clip: r > 1.2, the clipped branch is active, gradient weight 0. CISPO: r̂ = min(2.5, 1.2) = 1.2, gradient weight 1.2 × 1 = 1.2 on ∇ log π. For an ordinary token with r = 1.1, both give weight 1.1: the two differ only on the tokens PPO would have silenced.

What it bought. On a controlled zero-RL comparison from Qwen2.5-32B-base on AIME 2024, CISPO matched DAPO's performance in 50% of the training steps and beat both GRPO and DAPO at equal steps. M1's full RL run took three weeks on 512 H800 GPUs, a rental cost of $534,700, a figure few labs publish. Two other M1 lessons travel: the hybrid's linear layers made the long rollouts of RL cheap (M1 uses less than 50% of DeepSeek-R1's FLOPs at a 64K-token generation length and about 25% at 100K), and a precision mismatch between training and inference kernels was fixed by computing the language-model head in FP32, which raised the correlation between training-side and inference-side token probabilities from about 0.9 to 0.99 (M1 report). MiniMax still used CISPO for the M2.5 line (M2.5 card).

Where M3 stands now. M3 was among the cheapest capable open frontier options at release and is now one of several on list price. On the Artificial Analysis Intelligence Index v4.3 (methodology v4.3.2, read 1 October 2026) it scores 29.2 at $0.51 per index task (Artificial Analysis); at the same $0.30 / $1.20 list price DeepSeek V4.1 Flash scores 39.5, and Zhipu's GLM 5.3 Flash scores 41.8 at $0.15 / $0.50 (leaderboard; Zhipu: GLM). StepFun's Step 5 Preview does not undercut M3: it lists at $1.00 / $2.70, and its weights are promised rather than published (Other notable providers).

A model shipped inside a harness. M3.1-Flash-Preview (27 September 2026) is the first M3.1-branded model, and it runs only inside MiniMax's own coding agent and subscription plan, with no published price, speed, benchmark or parameter count (MiniMax docs; DataNorth). That a model shipped inside a harness is becoming as normal as one shipped behind an API is the point worth carrying; that it cannot be benchmarked independently is the cost.

The business behind the models

MiniMax's revenue comes mostly from consumer products. In 2025 it was $79.0 million (up 158.9%), of which 67.2% came from "AI-native products" (the Talkie and Xingye character apps, Hailuo AI video and MiniMax Agent) and 32.8% from the Open Platform API and enterprise services; more than 70% came from outside China (2025 annual report). Revenue does not fund the model line on its own: research and development cost $252.8 million that year and the adjusted net loss was $250.9 million, so the models run on investor capital, now including public markets. MiniMax listed on the Hong Kong Stock Exchange on 9 January 2026, the day after Zhipu (Wikipedia; Zhipu on Wikipedia).

Open weights at low prices are how a lab without frontier brand recognition buys attention (the page's reading, not a MiniMax statement). The licences are open but not uniform: Apache 2.0 for M1, a modified MIT licence for the M2 line, and the custom MiniMax Community License for M3 (M1 card, M2 card, M3 card).

Trade-offs: which route buys what

  • Linear hybrid (01, M1) buys a KV cache cut by the ratio of all layers to softmax layers (8 times for 7:1) and near-linear prefill, so million-token contexts and long RL rollouts are cheap; it costs exact recall and multi-hop reasoning in ways the standard benchmarks did not show, plus immature tooling (precision, prefix caching, speculative decoding).
  • Full GQA (M2) buys the quality reference and the mature serving stack; it costs a cache that grows with every token in every layer, which is why M2 stopped at 192K.
  • Block-sparse (M3) buys roughly a 30 times cut in attention compute per query at 1M while keeping lookups exact; it costs a trained indexer that runs over every token and can miss a block, and it leaves the stored cache as large as full attention's at the same head count.
  • Choosing a MiniMax model. For agentic coding at short to medium context, M2.7 has the smaller active count (9.8B) at the same list price as M3's standard tier, though M3 is listed as faster. For contexts beyond 204,800 tokens, or image and video input, M3 is the only current MiniMax API option, and above 512K input its price doubles.

Common mistakes and misconceptions

"Lightning attention is a new kind of attention."
It is linear attention computed in blocks: an IO-aware kernel. The maths, and the recall limit, are linear attention's.
"MiniMax-01 has no KV cache."
Its 10 softmax layers do: 40 KiB per token. Only the 70 lightning layers replace the cache with a fixed state.
"M2 went back to full attention because linear attention is slow."
The stated reasons are quality on multi-hop reasoning and retrieval-style circuits, an evaluation gap that hid it, and immature infrastructure; speed was the attraction, not the problem.
"MSA shrinks the KV cache."
It shrinks what each query reads. The whole cache stays resident so the indexer can choose from it, plus its own index keys; M3's smaller cache comes from 4 key/value heads instead of 8.
"MSA's selection is finer than DSA's."
DSA selects individual tokens; MSA selects 128-token blocks, separately per GQA group. MSA is finer than MoBA, not than DSA.
"CISPO just widens the clip."
It moves the clip from the update to the weight and stops the weight's gradient, so no token's gradient is ever zeroed; a wider PPO clip still silences tokens past it.
"The 4M-token context was trained."
Training reached 1M; 4M is inference extrapolation.
"M3 has 22B active parameters."
The model card says about 23B, and the config rebuilds to 23.5B.
"Full attention scales exponentially with context."
Quadratically: prefill grows with n2 and each decoded token's reads with n. The phrase appears in launch coverage (Fireworks).
"MiniMax's apps pay for its models."
The apps provide two-thirds of revenue, but 2025 revenue of $79.0 million was under a third of R&D spending; the models are funded by investors and the listing.

Defaults that reproduce published figures

  • 40 KiB per token, 40 GiB against 320 GiB at 1,048,576 tokens, the 140 MiB state, M2's 248 KiB and 46.5 GiB, and M3's 120 KiB and 120 GiB: the page's own arithmetic, so these match by construction.
  • The MSA paper's 28.4 times compute cut at 1M: reproduced independently from its eq. 12 at its test model's shape (Reading tab, MSA).
  • MiniMax's "1/20 of the previous generation's per-token compute" for M3 against M2 at 1M: not reproduced. The computed view gives about 9.5 times with M3's three full-attention layers and about 23 times without them; MiniMax's accounting is not published.
  • The paper's 7.6 times faster decoding: the read view at the paper's shape gives 7.9 times fewer bytes per decoded token (2 GiB against 260 MiB per layer at 1M: 256 MiB of index keys plus 4 MiB of selected keys and values); decode is memory-bound, so a measured speed-up just under the bytes ratio is what one expects (our reconstruction).

Read per decoded token: the keys and values (and, for MSA, all index keys plus the 16 selected blocks per group) one new token reads, summed over layers, in BF16; lightning layers read and rewrite their state. Compute: multiply-adds for scores and value sums, summed over layers; lightning layers count one state read and one update per head (2 × 128 × 128). Weights, MLPs and MoE experts are excluded: this is attention only.
