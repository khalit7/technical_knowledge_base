What MiniMax is: one running experiment on attention

MiniMax is a Shanghai lab (founded December 2021, {{Wikipedia|@wiki}}) whose model line is defined by one running experiment: how far the quadratic softmax attention of a standard transformer can be replaced by something cheaper without losing frontier quality.

It has shipped all three answers at production scale, one after another, and written up why it moved: linear attention in a hybrid (MiniMax-01 and M1), a public reversal to full attention (M2), and trained block-sparse attention (M3). That sequence, with the reasons attached, is unusually direct evidence on where efficient attention breaks, and for anyone deciding what to serve it is worth more than any one of the models.

The bill being attacked

Softmax attention for one head computes, over a sequence of n tokens,

softmax(QK⊤d)V
Q, K, V
the n × d matrices of queries, keys and values for one head
d
the head dimension

The softmax sits between the two matrix products, so the n × n score matrix must be formed: prefill costs on the order of n2d per head, and every decoded token must read the keys and values of every earlier token, which are kept in the KV cache. Per layer and per token that cache holds

KVlayer=2Hkvdhb bytes
Hkv
the number of key/value heads
dh
the head dimension
b
bytes per element (2 in BF16)
2
one key and one value

GQA (grouped-query attention) shrinks Hkv by letting several query heads share one key/value head; the {{Architecture Gallery|n:3c65c17b0d0d81be8a07f2562fa2030a}} works through it and the other variants across the field. MiniMax has attacked the quadratic term, then given the attack up, then attacked the reads instead.

Lightning attention (MiniMax-01, M1): linear attention computed in blocks

Linear attention drops the softmax, so the product becomes associative and can be regrouped:

(QK⊤)V=Q(K⊤V)

The n × n matrix disappears and a d × d state takes its place. In recurrent form, with row vectors qt, kt, vt,

St=St−1+𝐤t⊤𝐯t,𝐨t=𝐪tSt

so decoding needs no KV cache at all, only the fixed-size state, whatever the context length. The gallery page owns this recurrence and its gated successors such as Gated DeltaNet.

Lightning attention is MiniMax's IO-aware way of computing it: a kernel contribution, not a new mathematical form ({{MiniMax-01 report, arXiv 2501.08313|@p01}}). Causal linear attention looks cheap, but computed token by token it is a cumulative sum along the sequence, which serialises the very dimension a GPU wants to parallelise. Lightning attention cuts the sequence into blocks of B tokens and splits each block's output in two: inside the block, the ordinary masked quadratic product (small and fully parallel, the report's "left product"); from all earlier blocks, one multiplication by the carried state (the "right product"). For block i:

Oi=[(QiKi⊤)⊙M]Vi+QiSi−1,Si=Si−1+Ki⊤Vi
Qi, Ki, Vi
the queries, keys and values of the B tokens in block i, each B × d
M
the B × B causal mask (1 where the key is at or before the query, 0 elsewhere); ⊙ is elementwise multiplication, so the first term is the intra-block part
Si−1
the d × d state summing kj⊤vj over every token in blocks 1 to i − 1, so the second term is the inter-block part; the second equation carries the state on

The cost per head is

O(nd2+nBd)

where nd2 is the state updates and reads and nBd the intra-block products: linear in n for a fixed block size.

MiniMax partitions sequences into blocks of 256 tokens, keeps each block's working set in on-chip SRAM in the spirit of {{FlashAttention|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}, and reports that lightning attention keeps a constant training speed as sequence length grows, the only linear model in its comparison to beat FlashAttention-2 ({{MiniMax-01 report|@p01}}, section 2.2 and appendix).

Worked example (toy, one-dimensional head). Four tokens with scalar q = (1, 2, 1, 3), k = (1, 1, 2, 1), v = (2, 1, 1, 3), so kjvj = (2, 1, 2, 3). Token by token, ot = qt ∑j ≤ t kjvj: the running sums are 2, 3, 5, 8, so o = (2, 6, 5, 24). In blocks of B = 2: block 1 is intra-block only, o1 = 1 × 2 = 2 and o2 = 2 × (2 + 1) = 6, leaving state S1 = 3. Block 2: o3 = 1 × 2 + 1 × 3 = 5 (intra plus inter) and o4 = 3 × (2 + 3) + 3 × 3 = 24. Same outputs, but each block's work is parallel and only one small state crosses the block boundary.

Try: step through the same four tokens both ways. Token by token, every output waits for the one before it; in blocks, the two outputs of a block are computed together and only the state (green) is handed on.

Worked example (real scale). One head with d = 128, B = 256 and n = 1,048,576 tokens: softmax attention's n2d ≈ 1.41 × 1014 against lightning's nd(d + B) = 1,048,576 × 128 × 384 ≈ 5.15 × 1010, a ratio of n / (d + B) ≈ 2,731 in multiply-adds (constant factors ignored). In serial terms, a token-by-token scan over that sequence is 1,048,576 dependent steps; in blocks of 256 it is 4,096.

The 7:1 hybrid, and what the state costs

A fixed d × d state is a lossy summary of everything seen so far, so exact recall of one earlier token (a needle in a long document, a definition looked up in context, an identifier copied verbatim) degrades in a way perplexity does not show. The MiniMax-01 report says it plainly: pure linear attention matches the transformer at language modelling but "falls short in retrieval tasks". MiniMax-01 therefore shipped a 7:1 hybrid: seven lightning-attention layers, then one softmax-attention layer, repeating. The linear layers do the cheap bulk mixing; the periodic softmax layers restore exact addressing.

MiniMax-Text-01 has 80 layers, 64 query heads of dimension 128, and softmax layers using GQA with 8 key/value heads ({{config|@c01}}; its attn_type_list marks every eighth layer as softmax). So 10 layers keep a KV cache and 70 keep a state:

  • KV cache per token: 10 × 2 × 8 × 128 × 2 = 40,960 bytes = 40 KiB, against 320 KiB if all 80 layers were softmax GQA. At a 1,048,576-token context that is 40 GiB per sequence instead of 320 GiB.
  • State per sequence: 70 × 64 × 128 × 128 = 73,400,320 elements, fixed: 140 MiB at 2 bytes per element whatever the context (the report does not state the state's precision; in FP32 it doubles).
