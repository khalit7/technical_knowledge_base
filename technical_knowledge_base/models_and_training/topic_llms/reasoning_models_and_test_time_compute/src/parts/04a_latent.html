Recurrent depth: spending the budget inside the network

The third way spends the budget in activations rather than in tokens. A looped transformer reuses the same layers several times per token, so serial depth grows without adding parameters and without writing anything down. The idea goes back to the {{Universal Transformer (Dehghani et al., 2018)|@ut}}, which applied one block repeatedly with a learned halting rule. The clearest modern form is Huginn ({{Geiping et al., 2025|@geiping}}): a prelude that embeds the token, a recurrent core iterated r times with the input re-injected each time, and a coda that decodes. Its 3.5-billion-parameter proof of concept, trained on 800 billion tokens with layers (2, 4, 2) and a mean of 32 iterations, improved on reasoning benchmarks "up to a computation load equivalent to 50 billion parameters".

Dtoken=Lprelude+Lcore×r+Lcoda
Dtoken
serial layer applications spent on one token
Lprelude, Lcore, Lcoda
layers in each part (2, 4 and 2 in Huginn)
r
how many times the core runs, chosen at inference

Huginn at its training mean: 2 + 4 × 32 + 2 = 132 layer applications per token from 8 distinct layers. Other members of the family: {{Ouro (Zhu et al., 2025)|@ouro}} pre-trains looped models on 7.7 trillion tokens with a learned depth allocation and reports 1.4B and 2.6B models matching up to 12B ones; Nanbeige4.2-3B runs its 22-layer stack twice, which its report found kept about 75% of a standard model's token efficiency, and Mixture-of-Recursions adds a router deciding per token how many passes it gets (both as summarised by {{Raschka|@rasb}}).

RLT. The {{Recurrent Looped Transformer|@rlt}} (Yifan Zhang, Jichen Feng and Shihan Qin, September 2026) closes a different loop. In a standard decoder-only model nothing computed at the last layer of token t reaches the first layer of token t + 1; RLT pairs a causal encoder, which supplies token representations and a global key-value memory, with a decoder that feeds the previous token's final decoder state into the current token's input through a gated merge and keeps local sliding-window attention caches, in chunks that continue across prompt, response and message boundaries with no reset. That gives unbounded temporal depth at fixed per-token compute. The report illustrates a tied 48+48 layout, weights shared between encoder and decoder, so 96 logical blocks per token, and after t tokens the state path has traversed 48t decoder blocks. Its experiments use untied eight- and sixteen-layer models on six algorithmic tasks against a decoder-only transformer, three seeds each: the 5+3 and 7+1 splits keep 100% accuracy on 256-bit parity, and on permutation tracking at length 512 the 4+4 split reaches 55.70% ± 25.78 final-state accuracy against the transformer's 0.85% ± 0.30. The gains depend on the task and the split (addition accuracy falls beyond the trained operand widths), and the report "explicitly reports no measured efficiency, reasoning quality, or scaling results" and trains no language model ({{MarkTechPost|@mtp}}), so for frontier models it is vocabulary rather than evidence.

GPT-6 Astra. OpenAI released GPT-6 Astra in September 2026, and reports that it uses this technique ("opaque recurrence", looping activations back through its layers so part of the deliberation never becomes text) came from press coverage rather than from OpenAI's announcement, which does not describe the architecture ({{OpenAI|@astra}}; {{TechCrunch|@tc}}). TechCrunch called Astra's use of it "reportedly limited", and OpenAI's chief scientist Jakub Pachocki wrote that "OpenAI has worked to preserve and utilize chain-of-thought monitoring since our very first reasoning models". The system card finds Astra's chain-of-thought controllability "substantially higher than that of GPT-5.6 Sol and GPT-5.5 Thinking", and that told a monitor is present it can shorten its chain of thought enough to "occasionally evade CoT-only monitors", while saying OpenAI is "quite confident that changes in CoT controllability are not differentially due to any architectural changes" ({{system card|@card}}).

What it buys

Compute without the token bill and without the latency of emitting the reasoning; serial depth without parameters.

What it costs

Everything downstream of the transcript: a monitor cannot read deliberation that was never written, an evaluation harness cannot reconstruct the working state, and a serving stack has to persist the recurrent state between requests or recompute it.

What it does not save

A looped block halves the block parameters to hold in memory, but costs about the same compute and the same KV cache as the unlooped depth it replaces: 22 blocks run twice need the cache of 44 distinct blocks ({{Raschka|@rass}}).

The disagreement. Buck Shlegeris (Redwood Research) warned that if OpenAI pushes it further, "they'll have the option to massively increase the recurrence and totally destroys CoT monitorability" ({{TechCrunch|@tc}}). Ryan Greenblatt wrote that Astra "appears to be a massive jump in opaque reasoning ability", able to solve hard competition problems "entirely in its head", guessed the jump is downstream of architectural changes with more serial depth (with a normal pretraining scale-up a plausible alternative), and said that if later generations move to "full-on opaque reasoning architectures with extreme depth", chain of thought "would no longer be a meaningful oversight tool" ({{Greenblatt|@gbs}}); a later post he co-authored argues the same at length ({{Finnveden et al.|@gbl}}). Sebastian Raschka is the sceptical counterweight: the gains are "likely primarily due to other reasons, namely improved training recipes and training data" ({{Raschka's survey|@rass}}), reusing layers "does not by itself suppress visible chain of thought", and fewer reasoning tokens from more passes is the same effect as scaling up the model ({{Raschka on Astra|@rasb}}).
