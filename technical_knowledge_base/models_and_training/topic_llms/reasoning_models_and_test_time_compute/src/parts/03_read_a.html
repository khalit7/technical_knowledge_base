What it is and why it matters

A reasoning model produces a long chain of thought (CoT) before its answer, and is trained to use that chain well: typically large-scale reinforcement learning on tasks whose answers can be checked mechanically (mathematics with a reference answer, code with unit tests), so the model learns to plan, verify, backtrack and self-correct rather than to emit a plausible-looking derivation. This converts inference tokens into accuracy, which is why test-time compute is a second scaling axis alongside pretraining compute.

The intuition is scratch paper. A model that must answer in its first token gets one forward pass of computation, however hard the question. A model allowed to write its working first gets one forward pass per token written, can look back at what it wrote, and can cross it out. How much a query costs, how long it takes and how good the answer is are all now functions of how much the model is allowed to think, and the question every product and every lab answers differently is how much thinking to buy and where to spend it: longer, wider, or deeper inside the network. This page is the general mechanism; how each lab exposes it is on the lab pages (linked under Further reading).

Terms

Chain of thought (CoT)

The tokens a model generates before its final answer, holding intermediate steps. In reasoning models it usually sits in a separate thinking block that the product may hide, summarise or show.

Reasoning model

A model trained, not merely prompted, to produce and use long chains of thought. Since 2025 most flagships are reasoning models with a switch or a dial for how much they think.

Test-time compute

Computation spent per query at inference, as opposed to the one-off training compute. For a token-emitting model it is measured in generated tokens (thinking plus answer), and it can be spent three ways: sequentially, in parallel, or inside the network.

Verifier

A program that checks an answer: exact or numeric match against a reference, a unit-test suite, a proof checker. Correct by construction on the property it checks.

Reward model

A learned network that scores an answer. It generalises to tasks with no checker, and it has errors that optimisation can find.

pass@k

The probability that at least one of k independent samples is correct: what best-of-k with a perfect verifier achieves.

Self-consistency (majority voting)

Sample several answers and return the most common final answer. Written cons@k or maj@k for k samples.

Best-of-n

Sample n answers and return the one a scorer (verifier or reward model) rates highest.

Thinking budget or effort level

The control a caller or router uses to set how much the model thinks: a token count, a level such as low, medium or high, or an on/off switch.

Recurrent depth (looped transformer)

Reusing the same layers several times per token, so serial computation grows inside the network without emitting tokens.

How test-time compute works

A transformer forward pass has fixed depth, so the serial computation available to produce one next-token distribution is bounded by the layer count and cannot be raised at inference. A chain of thought removes that bound: each emitted token is another full forward pass conditioned on everything written so far, so serial steps become unbounded and the context window acts as an external working memory persisting across them. That is the whole mechanism.

Dserial=L×T
Dserial
the number of layer applications that can happen one after another before the answer is committed
L
the number of layers in the model
T
the number of tokens generated before the answer (at least 1)

Worked example. Take an illustrative 60-layer model. Answering directly in one token allows 60 × 1 = 60 serial layer applications. Thinking for 10,000 tokens first allows 60 × 10,000 = 600,000, four orders of magnitude more serial depth from the same weights. Theory agrees that this is a change in kind and not only in amount: transformer decoders allowed a number of decoding steps logarithmic in the input length gain "only slightly" over a single pass, while a linear number of steps lets them recognise all regular languages and a polynomial number lets them recognise exactly the problems solvable in polynomial time, under standard complexity conjectures and a mild generalisation of pre-norm in the normalisation layers ({{Merrill and Sabharwal, 2023|@merrill}}).

Three capabilities follow. Decomposition: a problem needing more serial steps than the model has layers becomes reachable. Externalised state: intermediate results are written down instead of held in activations discarded at every token. Revision: the model can read what it wrote, notice a contradiction and start again, which no single forward pass can do.

The working memory is not free. Every generated token leaves keys and values in the KV cache for every later token to attend to:

MKV=2×L×hkv×dh×b×T
MKV
KV-cache memory for one sequence, in bytes
2
one key and one value vector
hkv
key and value heads per layer (fewer than query heads under grouped-query attention)
dh
dimension of each head
b
bytes per stored number (2 for BF16)
L, T
as above, with T here counting the prompt as well as the generated tokens

With the illustrative 60 layers, 8 KV heads of dimension 128 in BF16, one token costs 2 × 60 × 8 × 128 × 2 = 245,760 bytes (240 KiB), and a 32,768-token trace costs 7.5 GiB for a single request. {{Inference techniques: what actually makes serving fast|n:3c65c17b0d0d819db53bd2c48909e5b2}} covers the serving techniques (paged attention, cache quantisation, multi-query and latent attention) that make this affordable.

Defaults reproduce the page's worked numbers by construction (60 layers, 8 KV heads of 128, BF16, 32,768 tokens: 240 KiB a token, 7.5 GiB). Drag T to 1 to see what answering directly buys.

What test-time compute does not buy matters equally. It adds no knowledge that is not in the weights or retrievable by a tool. It does not make a problem solvable if the model cannot make any correct partial progress on it, since there is nothing for later steps to build on. And the returns are shaped badly for economics, which is the subject of Where the scaling stops paying.

Three ways to spend it

Sequential

One longer chain

Self-correction and revision inside one trajectory (the o1 and R1 pattern). Later steps see earlier ones, which is what makes backtracking possible, and this is the axis RL training scales.

Costs irreducible latency (10,000 thinking tokens at an illustrative 50 a second is 200 seconds before the answer starts), a KV cache growing linearly with the trajectory, and attention over an ever-longer scratchpad getting more expensive per token.

Parallel

Many chains, then a selector

Sample many independent solutions and select one. Wall-clock time need not grow given the hardware, but total tokens scale with the sample count, and the approach lives or dies on the selector.

Majority voting needs answers in a canonical comparable form. Best-of-n against a learned reward model gains less than it appears to as n grows. Best-of-n against a real verifier (unit tests, a proof checker) is the strongest form.

Latent

Depth inside the network

Loop activations back through the same layers, so part of the deliberation happens in activations and never becomes text: compute without the token bill and without the latency of emitting the reasoning.

Costs everything downstream of the transcript: monitoring, evaluation, and serving state. Described under Recurrent depth.

What it shows. The same 10,000 tokens and the same total KV memory take 200 seconds as one chain and 40 seconds as five. The single chain can notice its own error and repair it; the five chains cannot see each other, so an error in one is never corrected, only outvoted or rejected, and the result is only as good as the selector. Multi-agent tiers such as Grok 4 Heavy and Gemini Deep Think are the parallel pattern with aggregation between the parallel trajectories rather than a single final vote; their branches are still token traces a monitor can read. The three ways compose, and frontier "heavy" tiers are usually parallel sampling of already-long sequential traces, which is why they cost an order of magnitude more than the standard tier for a few points of benchmark score.
