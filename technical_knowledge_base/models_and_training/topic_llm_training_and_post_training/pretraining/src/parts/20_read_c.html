1 · The objective

Every generative LLM is pretrained with causal language modelling: predict every token from the tokens before it, with cross-entropy over the vocabulary, on text nobody labelled. Every position of every sequence carries a training signal, and the trained model generates by the same rule it was trained on. It is the most expensive stage by far, and it sets the ceiling every later stage works under (the root page, {{Topic: llm-training-and-post-training|n:3c65c17b0d0d81b6876ee72b7056793b}}, Axis 1, shows reinforcement learning sharpening what pretraining put there rather than adding to it). The alternatives use the same loss and differ only in what the model sees and which positions it must predict; the stepper runs one sentence through each.

Per 512 tokens derived: masked LM hides round(0.15 × 512) = 77; span corruption at mean span 3 makes round(77 / 3) = 26 spans, so the input is 512 − 77 + 26 + 1 = 462 tokens and the target 77 + 26 + 1 = 104 (T5's own code, run on the {{T5 paper page|n:3d45c17b0d0d81ec8ebfec02e953a7fd}}, does the same arithmetic).

  • Masked LM (BERT) hides about 15% of tokens and predicts them from both sides: better for encoders (classification, retrieval), not for generation; the {{Seq vs Seq paper page|n:3c65c17b0d0d81139cffea35080afe2b}} trains matched encoders and decoders and measures this split.
  • Span corruption (T5) replaces each corrupted run with one sentinel and trains the decoder to emit only the dropped spans, so decoder sequences stay short and a step is cheap. UL2 ({{Tay et al. 2022|https://arxiv.org/abs/2205.05131}}) mixes denoisers of different corruption rates and span lengths, each example prefixed by a mode token, so one model learns short-span, long-span and prefix-LM denoising at once. Mostly historical for LLMs; still the default for an encoder-decoder ({{Encoder-Decoder Gemma and T5Gemma 2|n:3d45c17b0d0d81a9a22ffaada508db5c}} for the 2025 revival).
  • Fill-in-the-middle (FIM) cuts a document into prefix, middle and suffix and moves the middle to the end, so a causal model learns to infill; standard for code. A high FIM rate leaves left-to-right ability intact, "FIM for free" ({{Bavarian et al. 2022|https://arxiv.org/abs/2207.14255}}); DeepSeek-V3 applies FIM to 10% of documents in prefix-suffix-middle order and reports no loss of next-token ability ({{DeepSeek-V3, section 4.1|https://arxiv.org/html/2412.19437v2#S4.SS1}}).

How much the choice is worth, measured. T5 moved only the objective, holding architecture, data, compute and evaluation fixed ({{Raffel et al., section 3.3|https://arxiv.org/html/1910.10683v4#S3.SS3}}): the gap between objective families is large, the gap within denoising is noise.

Families differ by 9.79 GLUE points; rates and span lengths inside denoising by less than half a point

GLUE average on T5's validation sets, Tables 4 to 7 of the {{T5 paper|https://arxiv.org/html/1910.10683v4#S3.SS3}}, transcribed (they match by construction), each panel on the same 72 to 86 scale. The grey band is ±1 standard deviation of the baseline over 10 reruns (0.235, Table 1). derived ranges: families 82.96 − 73.17 = 9.79 points (about 42 standard deviations); corruption rates 10 to 25%: 83.28 − 82.82 = 0.46 (about 2); span lengths 2 to 5: 0.14; only a 50% rate and spans of 10 are worse.

So pick a denoising variant on cost, not quality. The same paper is also a measured result against the field's habit: at matched compute an encoder-decoder (83.28 GLUE) beat a decoder-only prefix LM (81.82), both trained with denoising, and the field went decoder-only anyway, for in-context learning and serving reasons the comparison did not test ({{Table 2|https://arxiv.org/html/1910.10683v4#S3.T2}}).

Correction
The old page quoted "a plain causal LM trails badly on understanding tasks, GLUE 74.70 against 83.28". In Table 2, 74.70 is a decoder-only language model trained with the denoising objective; the same decoder with the plain causal objective scored 73.78. Both trail the encoder-decoder's 83.28, so the point stands, but the 9-point gap is about the architecture (no bidirectional encoder), not the objective. The objective comparison is Table 4: prefix LM 80.69 against BERT-style 82.96.

2 · Reading the loss

L = −(1/T) Σt log pθ(xt | x<t)    perplexity = eL
L
mean cross-entropy per token, in nats (divide by ln 2 for bits)
T
tokens in the evaluated text
perplexity
the effective number of equally likely choices per token

Downstream ability tracks loss smoothly enough for scaling laws to work: a run's loss at a given size and token count can be forecast from small runs, and the {{Llama 3 paper|n:3c65c17b0d0d81aca58ccb9d720b474e}} forecast benchmark accuracy from it in two steps. Three cautions keep the number honest:

  • Per-token loss depends on the tokenizer. Longer tokens make fewer, harder tokens; compare models with different tokenizers in bits per byte (total bits over total bytes). The NanoGPT speedrun can use per-token loss (3.28) only because its rules fix the tokenizer and the validation stream ({{modded-nanogpt rules|https://github.com/KellerJordan/modded-nanogpt#rules}}).
  • The average hides the floor. Some tokens are predictable (the rest of a word, the answer to a sum), others are real choices whose entropy no model removes. The passage below shows it on a model this page trained (section 5 describes it): the loss on the answer digits of a sum can fall to almost zero, while the random operands cannot go below about 3.25 bits per digit (the average of log2 9 for a leading digit and log2 10 for the second).
  • Held-out loss on high-quality text predicts downstream better than training loss, which moves with the data mix: when the mix changes at an anneal, training loss jumps or falls for reasons that have nothing to do with the model improving.
