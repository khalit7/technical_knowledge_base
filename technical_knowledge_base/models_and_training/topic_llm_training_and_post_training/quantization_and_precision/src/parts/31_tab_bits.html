Bit explorer

Type or slide a number and see what every format does with it: the bits it stores, the value you get back, the error, the gap to the next representable number at that magnitude, and what happens at the edges (subnormals, underflow to zero, overflow to infinity or saturation). It extends Reading: Number formats.

Try: 1e-8, a tiny gradient: fp16 stores 0 and bf16 keeps it (why fp16 training needs loss scaling). 70000: fp16 overflows to infinity. 500: E4M3 saturates at 448 while E5M2 stores 512. 1 + 2^-8: bf16 cannot tell it from 1, fp16 can.

Rounding is round-to-nearest-even with subnormals, as in hardware conversion. Formats with infinities (fp32, tf32, bf16, fp16, E5M2) overflow to infinity once past the largest value by half a step; E4M3 and E2M1 have none, and conversion kernels saturate. "Step here" is the gap between neighbouring values at this magnitude (one unit in the last place).

Inside a block: one shared scale

Block formats store each number as a small element times a scale shared with its neighbours, set by the block's largest magnitude. Set that largest magnitude and see where your value lands. A value much smaller than the block's largest loses most of its precision in every block format: that is the outlier problem from Reading: Outliers.

MX scale per the OCP spec: 2 to the floor(log2(largest)) minus the element format's largest exponent (2 for E2M1, 8 for E4M3), so the largest element can exceed the element maximum and clip. NVFP4's second-level FP32 tensor scale is set as if this block held the tensor's largest value (amax / (448 × 6)), so the block scale is 448. NF4 codes from QLoRA Appendix E.
