2. Sharing a scale: per tensor, per channel, per block

Integer and 4-bit formats store a code and a scale: q = round(x / scale) + zero_point, and the value read back is (q − zero_point) × scale. The scale is set by the largest magnitude in the group it covers (absmax; asymmetric schemes also fit a zero point to the minimum), so one large value sets the step for everything that shares its scale. That is why the choice of scope matters more than the bit count. The animation runs one block of 32 real weights through five scopes; the weights are the exact bf16 values of the layer in the hero, chosen because its largest weight, −1.664 in input column 5, is 64 times the layer's standard deviation (0.026) measured here.

The quantisers are ported exactly from src/qformats.py and follow the specs: INT4 symmetric absmax; MXFP4 with the OCP shared exponent floor(log2(amax)) − 2 (Rouhani et al. 2023, Algorithm 1); NVFP4 with an E4M3 block scale and a per-tensor FP32 scale of amax / (448 × 6).

The scale costs bits. Bits per weight = element bits + scale bits / block size derived: INT4 with an fp16 scale and zero per 128 is 4 + 32/128 = 4.25; MXFP4 4 + 8/32 = 4.25 (MXFP8 8.25); NVFP4 4 + 8/16 = 4.5, plus one FP32 per tensor; NF4 with double quantisation 4 + 8/64 + 32/(64 × 256) = 4.127; llama.cpp's Q4_K block 4.5 and a whole Q4_K_M file about 4.9. Budget memory on these effective bits, never on the nominal 4.

MXFP4 against NVFP4. An E8M0 scale is a power of two, so a block's largest value lands anywhere between 4 and 8 times the scale, and above 6 it clips; NVFP4's E4M3 scale puts the largest on 6 almost exactly, over blocks half as long. Pick MXFP4 and row 223, block 0, in the animation to see the clipping. MXFP4's advantage is portability: it is an open standard that also runs on AMD (the MI355X, per Spheron's guide, a vendor blog that calls its own accuracy table directional).

3. Post-training quantisation: GPTQ and AWQ

PTQ quantises a trained model with no retraining. fp32 to fp16 or bf16 is essentially free; integer and 4-bit formats need the scales of section 2, and activations need a choice of when to set them: dynamic PTQ computes them on the fly per batch or token (a little latency, no calibration data), static PTQ freezes them from a calibration set (lower latency; inputs beyond the frozen range clip). Weight-only methods are the LLM mainstream because generating one token at a time is memory-bound: the time goes into streaming weights, so shrinking them speeds decoding up even if the multiply still runs in 16-bit. When the matmul itself is the bottleneck, FP8 W8A8 is the default (section 7).

Round-to-nearest treats each weight alone. GPTQ (Frantar et al. 2022) quantises a layer one column at a time and, after each column, adjusts the columns not yet quantised to cancel the error in the layer's output, using approximate second-order (Hessian) information from calibration activations (H = 2XTX, with one row of X per calibration token). When two input channels carry similar signals, an error rounded into one can be paid back by the other:

GPTQ pushes each column's rounding error into the columns still to come, so a later weight rounds the other way

illustrative One row w = (0.60, −0.88, −0.76, 0.20), a grid with step 0.25 and six calibration inputs, so every number fits on screen; the update is the paper's Algorithm 1: H = 2XTX plus 1% of its mean diagonal (dampening), U the upper Cholesky factor of H−1, and after quantising column j, wk ← wk − (wj − qj) / Ujj × Ujk for every later k. Round-to-nearest stores 0.50, −1.00, −0.75, 0.25 (output error 32.9%); GPTQ stores 0.50, −0.75, −0.75, 0.25 (8.5%), with a slightly higher weight error (13.0% against 12.4%) derived by src/visuals_ref.py.

GPTQ is built on Optimal Brain Quantization with lazy batch updates and a Cholesky reformulation; it quantised 175B models "in approximately four GPU hours" to 3 or 4 bits. Act-order (quantising columns in decreasing order of activation size) is not in the paper; it came from the GPTQ repository, where it lowered LLaMA-7B's WikiText-2 perplexity from 7.15 to 6.09 (IST-DASLab/gptq).

AWQ (Lin et al. 2023, MLSys 2024 best paper) starts from "protecting only 1% salient weights can greatly reduce quantization error", and picks the salient channels from the activation distribution, not the weights. Rather than keep them in high precision, it multiplies those input channels by a scale s = sXα before 4-bit quantisation (α by grid search over [0, 1]) and folds 1/s into the previous operation; group size 128. It is the weight-side half of section 4's migration, animated there.

Lower weight error is not the goal: GPTQ and AWQ raise it and lower the output error

The 4.25-bit schemes on the whole layer measured here: round-to-nearest with groups of 128 gives 7.80% output error, AWQ 6.20% and GPTQ with act-order 6.12%, while both methods raise the plain weight error (from 10.8% to 12.8% and 18.1%): they spend error where the activations are small. Weight error is not output error, which is why both need calibration data.

Below 4 bits the data matters as much as the method. At 2 bits scalar PTQ (one value per weight, as above) collapses to chance on QA tasks; vector codebooks, which quantise groups of weights to entries of a learned codebook, plus jointly chosen calibration and recovery-training data reached about 2.3 effective bits at 89 to 97% of full-precision QA accuracy on 3.8B to 32B dense and MoE models, with 1.4 to 30 times less compute than the best quantisation-aware baseline ({{Beyond 4 bits (arXiv 2610.28537)|https://arxiv.org/abs/2610.28537}}).
