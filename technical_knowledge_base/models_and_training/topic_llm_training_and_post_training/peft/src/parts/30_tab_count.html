Trainable parameters, every method, from real configs

How many numbers each method trains, for a model's real shapes (from its config.json), a rank and a set of target matrices. The formulas are below; for the open models they give exactly the counts the {{PEFT library|https://huggingface.co/docs/peft}} reports (). This tab extends {{The methods|#t-read}} in the Reading tab; what the bytes mean for training memory is the parent page's {{bytes-per-parameter calculator|n:3c65c17b0d0d81b6876ee72b7056793b}}.

Where a LoRA adapter's parameters sit

The current LoRA configuration, matrix by matrix: each targeted matrix costs r(din + dout) per layer (per expert in a mixture-of-experts layer).

Formulas

Full
every parameter: embeddings (once if tied) + L × (all matrices + norms) + final norm
LoRA
L × Σtargets r(din + dout) × (experts per layer, 1 if dense)
DoRA
LoRA + L × Σtargets dout (one magnitude per output unit)
LoRA-FA
L × Σtargets r dout (only B; A stays frozen)
VeRA
L × Σtargets (dout + r) (vectors b and d); the shared frozen pair adds 2 dmax r if counted
(IA)³
L × (key width + value width + MLP hidden width); PEFT scales queries instead of keys for Qwen
Prompt tuning
n × d
Prefix tuning
n × L × 2 × (KV heads × head dim): one key and one value per virtual token per layer (PEFT, no reparametrisation MLP)
Adapters (Houlsby)
2L(2dm + m + d): two bottleneck adapters per block with biases, the LoRA paper's formula
