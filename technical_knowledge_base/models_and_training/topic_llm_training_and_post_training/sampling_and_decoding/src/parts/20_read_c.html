Structured, or constrained, decoding

A constraint guarantees that the output matches a format (a JSON schema, a regular expression, a context-free grammar) by masking invalid tokens at every step: compile the constraint to an automaton over the tokenizer's vocabulary, intersect it with the current state, and set the disallowed logits to −∞ before the sampler runs. The animation runs Qwen2.5-0.5B-Instruct on one request, with greedy decoding, without and with a grammar for {"name": string, "age": integer}.

The request is illustrative (a made-up person); everything else is the model's real output measured here. The grammar is a regular expression with whitespace capped at two characters between tokens of JSON, checked against all 151,665 tokenizer entries at every step; a token is allowed when the text so far plus the token can still complete a match. A tick marks tokens the grammar allows.

Try: step 0 in both modes. The model puts 57% on a Markdown fence ```, which no JSON parser accepts; the constrained run allows 4 tokens holding 36% of the mass and starts with {. Then step 2 of the constrained run: the model wants two spaces of indentation, the toy grammar's whitespace cap forbids the second, and it is forced onto a token it gave 0.0004%. The output is still valid JSON, with one-space indentation.

Three engines do this in production:

  • Outlines compiles a regular expression or JSON schema to a finite-state machine over tokens and indexes, for every state, which tokens are allowed: "transitions between the states of a finite-state machine" ({{Willard and Louf, 2023|https://arxiv.org/abs/2307.09702}}). It is the approach that popularised near-zero-overhead structured output.
  • XGrammar handles full context-free grammars with a pushdown automaton. It splits tokens into context-independent ones, whose validity depends only on the automaton's position and is precomputed, and context-dependent ones, checked at runtime against a persistent stack: for Llama-3.1 and a JSON grammar the context-dependent tokens are "less than 1% (1134 out of 128k)", cut to 120 by context expansion. It overlaps mask computation with the GPU's forward pass; masks take under 40 µs per token for JSON schema ({{Dong et al.|https://arxiv.org/abs/2411.15100}}). It is the default structured-output backend in vLLM (the "auto" backend tries XGrammar first and falls back to llguidance: {{sampling_params.py|https://github.com/vllm-project/vllm/blob/main/vllm/sampling_params.py}}), in SGLang ({{serving_hook.py|https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/arg_groups/serving_hook.py}}), TensorRT-LLM and MLC-LLM ({{README|https://github.com/mlc-ai/xgrammar}}).
  • llguidance (behind Guidance) runs an Earley parser on top of a lexer built from regular-expression derivatives and computes masks lazily by walking a trie of the vocabulary, about 50 µs per token for a 128k tokenizer. "LLGuidance shipped in OpenAI for JSON Schema", and it is integrated in llama.cpp, vLLM (from 0.8.2), SGLang (from 0.4.4) and Chromium ({{README|https://github.com/guidance-ai/llguidance}}).

Provider-side "structured outputs" and strict function calling are this mechanism plus training. OpenAI's launch post: Structured Outputs works "by constraining OpenAI models to match developer-supplied schemas and by training our models to better understand complicated schemas"; the schema is converted to a context-free grammar; gpt-4o-2024-08-06 scored 100% on its complex-schema eval against under 40% for gpt-4-0613 ({{OpenAI, 6 August 2024, archived|https://web.archive.org/web/20240806180746/https://openai.com/index/introducing-structured-outputs-in-the-api/}}). JSON mode guarantees valid JSON; only Structured Outputs guarantees schema adherence ({{docs|https://developers.openai.com/api/docs/guides/structured-outputs}}). Grammar-constrained tool-call parsing is standard in serving stacks.

Caveats
  • Constraining distorts the distribution. When the model wanted a token you masked, the rest of the answer is conditioned on text it would not have written. Schema design (field order, letting the model think before the JSON) mitigates it. The size of the effect is disputed: {{Tam et al., 2024|https://arxiv.org/abs/2408.02442}} report "a significant decline in LLMs reasoning abilities under format restrictions"; the Outlines team re-ran their tasks with matched prompts and found structured generation slightly better (GSM8K 0.78 against 0.77, Last Letter 0.77 against 0.73, Shuffled Objects 0.44 against 0.41: {{.txt, "Say what you mean"|https://blog.dottxt.ai/say-what-you-mean.html}}).
  • Whitespace and token boundaries are the classic bugs. A token can straddle a grammar boundary (": closes a key and starts the colon), whitespace rules decide which tokenisations are reachable (step 2 above), and an unbounded whitespace rule lets a model emit spaces forever.

Techniques built on sampling

  • Self-consistency and best-of-n sample n answers and return the majority answer ({{Wang et al., 2022|https://arxiv.org/abs/2203.11171}}) or the one a reward model or verifier rates highest. Best-of-n is also a baseline alignment method and a reward-hacking amplifier ({{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}}). The maths of pass@k, voting and best-of-n, with a sampling lab, is on {{Topic: llms, Deeper: test-time compute|n:3c65c17b0d0d812d9e00f6ec89965286}}.
  • Speculative decoding: a cheap draft model (or n-gram lookup, or extra heads as in {{Medusa|https://arxiv.org/abs/2401.10774}} and {{EAGLE|https://arxiv.org/abs/2401.15077}}) proposes γ tokens, and the target model scores all of them in one forward pass. Each drafted token x is accepted with probability min(1, p(x)/q(x)), p the target's and q the draft's probability; at the first rejection a replacement is drawn from the normalised max(0, p − q). The output distribution is exactly the target's, so the speed-up is lossless ({{Leviathan et al., 2023|https://arxiv.org/abs/2211.17192}}; {{Chen et al., 2023|https://arxiv.org/abs/2302.01318}}). With acceptance rate α, each target pass yields on average (1 − αγ+1) / (1 − α) tokens: 3.4 tokens at α = 0.8 and γ = 4 derived. Serving details are on {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}; a calculator that reproduces Leviathan's Table 4 is on {{Google DeepMind: Gemini and Gemma|n:3c65c17b0d0d8173a0aafcb27cf7a5f3}}; an animation of one token at a time against speculative and block-diffusion decoding is in {{2026-08-24: tech news|n:3c65c17b0d0d81ca8c8af3c2fc0c3ced}}.
  • Test-time compute scaling: longer chains of thought, and parallel sampling with a verifier reranking the samples. It is the decoding-side half of the reasoning-model story; the training-side half (RL with verifiable rewards) is on {{Alignment: SFT, RLHF, DPO Family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}, and the comparison across labs on {{Topic: llms|n:3c65c17b0d0d812d9e00f6ec89965286}}.

Common mistakes

"Temperature 0 makes the output reproducible"
It makes the rule deterministic, not the computation: batching on a shared server changes the numerics (80 distinct completions out of 1,000 in Thinking Machines' test, above).
"Top-p 0.9 keeps a handful of tokens"
Only at moderate temperature. At T 1.5 on a step where the model is 96% sure, top-p 0.9 keeps 5,166 of 151,936 tokens measured here; whatever temperature spreads out, top-p collects back.
"Min-p is proven better than top-p"
The mechanism is real; the evidence that it improves quality is disputed (Schaeffer et al., 2025). Tune both on your own task.
"The sampler order is fixed"
Hugging Face and vLLM apply temperature before truncation; llama.cpp applies it after by default. The same settings keep different token sets.
"Beam search finds better text"
It finds more probable text, which for open-ended generation is more repetitive text (the loops above). Use it for short closed-ended outputs.
"A repetition penalty is free"
It penalises every repeated token, including the correct ones (a name, a pattern, code identifiers).
"Constrained decoding cannot hurt quality"
It guarantees the format, not the content: when the grammar overrules the model (0.0004% in the example above) everything after is conditioned on text it would not have written.
