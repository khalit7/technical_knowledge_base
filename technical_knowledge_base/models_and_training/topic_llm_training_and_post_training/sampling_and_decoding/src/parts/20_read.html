A language model does not write text. At each step it outputs one number per vocabulary entry, and a separate rule, the decoder, turns those numbers into the next token. The same model gives repetitive, bland, creative or broken text depending on that rule alone. This page is about the rule: searching for the most probable text, sampling from a reshaped distribution, forcing a format, and the inference techniques built on sampling.

From logits to a token

One forward pass ends in a vector of logits z, one per vocabulary entry: 151,936 for {{Qwen2.5-0.5B-Instruct|https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct}}, the small open model whose real distributions fill the animations below, and 50,257 for {{GPT-2|https://huggingface.co/openai-community/gpt2}}. The softmax turns them into probabilities, with a temperature T that rescales the logits first:

pi = exp(zi / T) / Σj exp(zj / T)
zi
logit of token i (only differences between logits matter)
T
temperature: T = 1 is the model's own distribution, T < 1 sharpens it, T > 1 flattens it towards uniform, T → 0 puts all the mass on the top token

A decoder then picks a token, appends it, and runs the model again. Decoders fall into two families. Search is deterministic and tries to find a high-probability sequence (greedy, beam search). Sampling draws at random from a reshaped distribution (temperature, then truncation by top-k, top-p, min-p and others). A third layer, constraints, removes tokens that would break a required format before either family chooses.

Deterministic search: greedy and beam

  • Greedy decoding takes the argmax token at every step. It is locally optimal and globally poor for open-ended text: repetitive and dull. It is still fine for short factual answers, and it is effectively what temperature 0 means.
  • Beam search keeps the B highest-probability partial sequences at every step: each is extended by its best next tokens, all candidates are scored by their total log-probability, and only the top B survive. It is the standard for machine translation and summarisation, where outputs are short and closed-ended. For open-ended generation it produces degenerate, repetitive, low-diversity text, because high probability is not the same as human-like ({{Holtzman et al., 2019|https://arxiv.org/abs/1904.09751}}), and chat LLMs essentially do not use it.

The animation runs both on the same real input: GPT-2 small continuing a sentence from Jerome K. Jerome's {{Three Men in a Boat|https://www.gutenberg.org/ebooks/308}} (1889). Every score is the model's own log-probability.

Try: step to 4 in beam mode. Greedy's choice "was very" is still among the candidates but scores below three other branches, so beam search drops it; greedy can never revisit a choice. After six tokens the best beam is 6.7 times more probable than greedy's text measured here (exp(−7.54 + 9.44); script recompute.py).

Finding the more probable text does not make it better. Run both for 80 tokens on the same prompt measured here:

Both searches fall into a loop the model rates as highly probable; the sample wanders but does not repeat. This is the paradox Holtzman et al. named: "using likelihood as a decoding objective leads to text that is bland and strangely repetitive", and the per-token probability of natural text is "on average, much lower than text generated by beam search" (§4.3). On 5,000 WebText continuations with GPT-2 Large (762M) they measured perplexity 12.38 for human text against 1.50 for greedy and 1.48 for beam search with 16 beams, and 73.66% of greedy texts repeating (Table 1, {{paper|https://arxiv.org/abs/1904.09751}}). The {{Twelve decoders|#t-deg}} tab reruns that comparison on GPT-2 small.

Correction: temperature 0 is greedy, but greedy is not reproducible on a server
Greedy is deterministic for a fixed computation. A served model is not a fixed computation: the batch it shares with other requests changes the kernels' reduction order. Thinking Machines sent the same prompt 1,000 times to Qwen3-235B at temperature 0 and got 80 different completions, diverging at token 103; batch-invariant kernels made all 1,000 identical ({{He, September 2025|https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/}}). Anthropic's migration guide says the same of its API: "temperature = 0 ... never guaranteed identical outputs" ({{Opus 5.5 migration guide|https://platform.claude.com/docs/en/models/opus-5-5/migration-guide}}).
