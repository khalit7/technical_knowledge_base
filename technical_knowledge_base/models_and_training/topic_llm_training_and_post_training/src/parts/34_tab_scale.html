The calculator

Training a dense Transformer costs about six floating-point operations per parameter per token: two for the forward pass (one multiply, one add), four for the backward pass. That gives the rule every lab uses, C ≈ 6ND. The rest of this tab hangs off that one number: how long it takes on real hardware, what it costs to rent, and what the Chinchilla fit says the compute should have bought.

C ≈ 6 N D  (+ 6 L nctx dattn D)
N
parameters touched per token: all of them for a dense model, the active ones for a Mixture-of-Experts
D
training tokens
6 L nctx dattn
attention scores and weighted sums per token (Kaplan et al. 2020, §2.1, times three for the backward pass), with L layers, context nctx and attention width dattn. It is nctx / 12d of 6N for a standard block, so it matters only for long contexts or narrow models
GPU-hours
C / (peak FLOP/s × MFU) / 3,600, with MFU (model FLOPs utilisation) the share of the datasheet's dense peak the run sustains
Try: pick Llama 3.1 405B: 6ND lands on Meta's published 3.8 × 10²⁵ FLOPs, while the GPU-hours at Meta's own 41% MFU come out 16% short of the model card. Then switch on the attention term, or move MFU until the hours match.

Mistakes to avoid

Using an MoE's total parameters in 6ND
Each token only passes through the active experts, so compute follows active parameters: DeepSeek-V3 is 6 × 37B × 14.8T = 3.3 × 10²⁴, not 6 × 671B × 14.8T = 6.0 × 10²⁵. Total parameters set memory and the number of GPUs needed to hold the weights, not FLOPs.
Reading a model card's GPU-hours as the pretraining run
Cards count whatever the lab chose to count. Llama 3.1's are "total GPU time required for training each model", which is why the 8B implies 14% MFU; DeepSeek-V3 separates pretraining (2.664M) from context extension and post-training (124K more). None include ablations, failed runs or the research that preceded the final run.
Quoting MFU against the wrong peak
Datasheets print sparse figures, twice the dense peak no training run uses; this calculator uses dense throughout. An FP8 run measured against the BF16 peak looks twice as efficient as against the FP8 peak: DeepSeek-V3's same GPU-hours are 35% or 17%. Compare MFU only at matched precision. MFU also differs from hardware FLOPs utilisation (HFU), which counts recomputed activations.
Comparing losses across fits or datasets
Chinchilla's fit predicts loss on MassiveText with its tokenizer; Kaplan's on WebText2 with GPT-2's, counting non-embedding parameters only. The absolute numbers are not comparable with each other or with any other model's loss; only the changes within one fit mean something.
Reading the dollar figure as what the model cost
GPU-hours times a rental rate prices the final run only. DeepSeek's own "$5.576M" is exactly that (2.788M H800 hours at an assumed $2), and the report says it excludes prior research and ablations. The disclosed costs of real runs, with what each includes, are on the {{Price list|#t-price}} tab.
