Rollout mismatch: how far the engine's probabilities drift from the trainer's

For every sampled token, the probability the "engine" sampled it with against the probability the "trainer" computes for the same token with the same weights. Three set-ups, all real, on this page's rollouts: float16 with a KV cache (generation, on Apple MPS) against float32 in one pass (CPU); bfloat16 in one pass against float32; and an engine left with the model's shipped repetition penalty 1.1, a sampling processor the trainer does not know about. Section 8 of the Reading tab explains the corrections.

The trainer here is the same weights in float32 on CPU; a real trainer (FSDP, Megatron) and engine (vLLM, SGLang) differ in more ways (kernels, batch-dependent reductions, FP8 rollouts), so production gaps can be larger.
