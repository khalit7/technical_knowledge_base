Reinforcement learning in one screen

Reinforcement learning (RL) is learning to act by trial and error. An agent takes actions in an environment, receives a scalar reward after each one, and adjusts its behaviour to maximise the total reward it collects over time. Nobody tells it the correct action: it only learns how good the outcome was, often many steps later. That makes RL the tool for problems where behaviour can be scored but not demonstrated: games, control and, since InstructGPT in 2022, the post-training of language models, where a reward model or a programmatic verifier scores whole responses.

The field arrived in three layers. The classical core defines the problem (Markov decision processes and the Bellman equations) and solves it with tables, either by planning with a known model or by learning from samples. Deep RL replaces the tables with neural networks and adds the tricks that keep that stable (DQN, PPO, SAC, AlphaZero, MuZero). RL for language models applies the same machinery to token generation (RLHF, GRPO, RLVR), where the environment is trivial and the reward is the expensive part.

The one idea that runs through the page: one target, many estimators
Every method estimates the same quantity, the expected return that the Bellman equation describes, and improves behaviour against that estimate. The methods differ mainly in what they use in place of that expectation: the exact model, a whole sampled episode, one sampled step plus the current estimate, a learned critic, a tree search, or the mean reward of a group of sampled answers. The section The one idea runs all of them on one episode.

What RL is, and why it is its own subject

Three things set RL apart from supervised learning ({{Sutton and Barto, §1.1|http://incompleteideas.net/book/RLbook2020.pdf#page=23}}; {{Silver, Lecture 1|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/intro_rl.pdf}}). The feedback is a score, not a label: it says how good an action was, not which action was right. The feedback can be delayed: a chess move is rewarded only when the game ends, so the agent must work out which earlier action earned a later reward (the credit assignment problem). And the agent's own actions decide what data it sees next, so it must trade exploiting what it knows works against exploring to find something better.

Silver's classic examples are a helicopter flying stunts (rewarded for following the trajectory, punished for crashing), backgammon (won or lost) and Atari games (the score). The agent maximises cumulative reward, so it can pay now to gain later: refuelling a helicopter costs time but may prevent a crash. All of this rests on the reward hypothesis, that every goal can be written as maximising expected cumulative scalar reward. It is an assumption, and it breaks in instructive ways for language models: "helpful" has no formula, so training maximises a proxy (a learned reward model, a test suite, a judge), and a policy that optimises a proxy hard enough finds shortcuts such as longer answers, flattery or special-cased tests. That failure, reward hacking, is the subject of {{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}}.

Two problems share the vocabulary: in learning, the environment is unknown and the agent improves by interacting with it; in planning, a model of the environment is known and the agent improves by computing with it, for example by searching a game whose rules are known.

The loop, the state and the return

At each step t the agent sees an observation and a reward, chooses an action At, and the environment answers with the next observation and the reward Rt+1: in Silver's and Sutton and Barto's indexing, the reward for At arrives at t + 1. The agent summarises everything it has seen into a state. A state is Markov if the future depends only on it, not on how the agent got there; a single Atari frame is not (it shows where the ball is, not where it is going), which is why DQN stacks the last four frames ({{Mnih et al. 2015|https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf}}). When the agent cannot see everything that matters (a poker hand, a robot that does not know where it is), the problem is partially observable and the agent must build its own state from history. A language model generating text sees its whole prefix, so generation is fully observable.

The quantity the agent maximises is the return, the discounted sum of future rewards:

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ... = Rt+1 + γGt+1
γ ∈ [0, 1]
the discount: a reward k steps further away counts γk as much. The weights sum to 1/(1 − γ), so γ = 0.9 looks about 10 steps ahead and γ = 0.99 about 100 derived. Discounting keeps returns finite in never-ending tasks and makes the solvers converge; language-model RL uses γ = 1, because every response ends and the reward comes at the end.

The formal object is the Markov decision process (MDP): states, actions, transition probabilities, rewards and γ. A policy π(a | s) says how the agent acts. Its state value Vπ(s) is the expected return from a state, and its action value Qπ(s, a) the expected return after taking action a there. The difference matters in practice: picking the best action from Q is a lookup, while picking it from V needs a model of where each action leads, which is why model-free control learns Q. Reward is not value: in Silver's student example, a lecture costs −2 now yet the state is worth +1.5, because it leads toward passing ({{Silver, Lecture 2|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-2-mdp.pdf}}).

The one idea: one target, many estimators

The return obeys a one-step recursion, Gt = Rt+1 + γGt+1. Take expectations and you get the Bellman equation: the value of a state is the immediate reward plus the discounted value of where you land, on average.

Vπ(s) = 𝔼π[ Rt+1 + γVπ(St+1) | St = s ]
𝔼π
an average over the actions π chooses and the next states the environment produces. Replace the average by a max over actions and you get the optimality equation, whose solution is the best policy's value.

No agent can compute that expectation directly unless it knows the environment. So every method substitutes something for it, and nudges its estimate toward that substitute, the target: V(St) ← V(St) + α (target − V(St)). Policy-gradient methods use the same substitutes as the weight on "make that action more likely". That is the whole map of the field:

MethodWhat stands in for the expectationBias and variance
Dynamic programmingThe exact expectation over a known modelExact; needs the model
Monte CarloThe whole sampled return to the end of the episodeUnbiased; high variance
TD(0), SARSA, Q-learningOne real reward plus the current estimate of the next state (SARSA: the action actually taken next; Q-learning: the best next action)Biased by the estimate; low variance
n-step, TD(λ), GAEA blend: n real rewards, then the estimateA dial between the two above
DQNThe Q-learning target, computed by a frozen copy of the networkAs Q-learning, plus approximation error
REINFORCEThe sampled return, optionally minus a baselineUnbiased; high variance
Actor-critic, PPOAn advantage from a learned critic: the TD error, or GAE's blend of themLower variance; biased by the critic
AlphaZero, MuZeroA tree search: its improved move distribution and the game's outcomeBetter than the raw networks, at a large compute cost per move
GRPOThe response's reward minus the mean of a group of responses to the same prompt, divided by their standard deviationMonte Carlo with a sampled baseline; no critic
RLVRAny of the above, with the reward from a program that checks the answerNo reward-model error; checkable tasks only

Why there is a dial. A target built from real rewards is unbiased but carries every step's randomness; a target that stops after one step and trusts the estimate carries little randomness but inherits whatever error the estimate has.
