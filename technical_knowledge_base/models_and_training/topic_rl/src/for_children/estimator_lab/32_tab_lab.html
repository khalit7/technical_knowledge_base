Estimator lab. Four classic experiments from Sutton and Barto's {{Reinforcement Learning: An Introduction (2nd ed., 2018, free online)|https://incompleteideas.net/book/the-book-2nd.html}}, run live in your browser and seeded, so every run replays exactly. Each one puts two estimators of the same target side by side: the expected return, estimated from a model or from samples, from whole episodes or from one step and a guess, toward the policy being followed or the greedy one. The defaults are the book's settings; each section says whether its figure reproduces, independently or only in shape, and where it does not. The {{Reading|#t-read}} tab explains the ideas; the child pages hold the depth: {{Dynamic programming|n:3c65c17b0d0d81baada7e1c05ce69d01}} for sections 1 and the model side, {{Model-free methods|n:3c65c17b0d0d81898a0cd4c05c744969}} for sections 2 to 4.

1. Same target, from a model or from samples

Example 4.1 and Figure 4.1 ({{book p. 77|https://incompleteideas.net/book/RLbook2020.pdf#page=99}})

A 4 × 4 grid; the two shaded corners end the episode; every move costs −1; a move off the grid leaves you in place. The target is vπ of the random policy (each of the four moves with probability 1/4): minus the expected number of steps to a corner. Expected updates (dynamic programming) know the model and set each state to the average over its four moves of −1 plus the neighbour's current value, all states at once, one sweep at a time. Sampled updates know nothing but the episodes they see: TD(0) nudges a state toward −1 plus its successor's estimate, Monte Carlo averages the returns that actually followed. Each frame gives both sides the same work: one sweep is 14 states × 4 moves = 56 look-ups, so a sampled method gets 56 steps per frame.

Numbers in cells: the current estimate, to two significant digits like the book. Arrows: the greedy moves with respect to it (all ties shown, as in the book's right column).
Error against the target (root mean square over the 14 states, log scale)

    2. TD or Monte Carlo: one step and a guess, or the whole episode

    Example 6.2 ({{p. 125|https://incompleteideas.net/book/RLbook2020.pdf#page=147}}) and Figure 6.2 ({{p. 127|https://incompleteideas.net/book/RLbook2020.pdf#page=149}})

    Five states A to E; every episode starts in C and steps left or right with equal probability until it falls off an end. Falling off the right pays 1, everything else 0, so the true value of a state is its chance of ending on the right: 1/6, 2/6, ..., 5/6. All estimates start at 0.5. TD(0) moves V(S) a step α toward R + V(S′) after every step. Constant-α Monte Carlo waits until the episode ends, then moves every visited state toward the return that actually followed (here 0 or 1). Same walks for both.

    Batch updating: after each new episode, all episodes so far are replayed with a tiny α until the values stop moving. This page jumps straight to where that converges: batch Monte Carlo gives each state the mean return seen after it; batch TD gives the values that would be exactly right for the Markov chain estimated from the transitions seen (the certainty-equivalence estimate, {{p. 128|https://incompleteideas.net/book/RLbook2020.pdf#page=150}}). check.py replays batches with α = 0.001 and lands on the same values to 5 × 10−10.

      3. The dial between them: n steps, or a decaying mix of all n

      Example 7.1 and Figure 7.2 ({{p. 145|https://incompleteideas.net/book/RLbook2020.pdf#page=167}}), Figure 12.3 ({{p. 291|https://incompleteideas.net/book/RLbook2020.pdf#page=313}}), Figure 12.6 ({{p. 295|https://incompleteideas.net/book/RLbook2020.pdf#page=317}})

      The same kind of walk with 19 states, −1 for falling off the left and +1 off the right, values starting at 0 (true values −0.9 to 0.9). n-step TD waits n steps and uses the n rewards plus the estimate where it landed; n = 1 is TD(0), n longer than the episode is Monte Carlo. The λ-return averages all the n-step returns with weights (1 − λ)λn−1; the off-line version applies it at the end of each episode. TD(λ) gets nearly the same effect on-line: every visited state keeps an eligibility trace that decays by λ per step, and each step's TD error is shared out in proportion to the traces.

      Both learn from the same walks with α = 0.4; the episodes before the one shown are run first.

        4. Whose next action the target assumes: Sarsa against Q-learning

        Example 6.6 ({{p. 132|https://incompleteideas.net/book/RLbook2020.pdf#page=154}})

        A 4 × 12 grid; start bottom left, goal bottom right, and between them a cliff: stepping in costs −100 and sends you back to the start; every other move costs −1. Both agents act ε-greedily (a random move 10% of the time) and update the value of the move they just made. Sarsa (on-policy) targets the value of the next move it will actually make, random moves included, so the cliff edge looks costly and it learns a path further up. Q-learning (off-policy) targets the best next move, as if it would never slip, so it learns the shortest path along the edge, and then keeps falling off it while exploring. Optionally, Expected Sarsa targets the average over the ε-greedy policy.

        Shading: the best Q-value in the cell (darker is worse); arrows: the greedy move; the trail: this episode so far, with falls marked.

        Sum of rewards during the episode, averaged over runs

          How the lab works

          • Seeded and deterministic. Every random draw comes from a seeded generator (mulberry32), one stream per purpose and run, so a run replays identically, the two sides of each comparison see the same walks where that makes sense, and a Python port can match the page exactly. Long averages run in small slices between frames, so the page stays responsive on a phone.
          • Checked against Python. src/lab/check.py ports the engine line by line and reproduces the page's numbers bit for bit on every experiment (random walks, every parameter and step size of the three 19-state families, the three cliff agents, all five gridworld methods, the step-by-step traces). It also checks independently: Figure 4.1 against its printed values, true values by linear solve, the batch closed forms against replayed batches, the λ-return recursion against equation 12.3, the cases where methods coincide (n = 1 and λ = 0 are TD(0); n ≥ episode length and λ = 1 are Monte Carlo), and the cliff's exact ε-greedy returns by linear solve.
          • Exact definitions. Undiscounted everywhere (γ = 1). Monte Carlo on the walks is every-visit constant-α (equation 6.1); on the gridworld it is first-visit sample averages (the book's box in Section 5.1). Dynamic programming sweeps are synchronous (two arrays), which is what Figure 4.1's numbers require; an in-place sweep gives different intermediate values. Value iteration and policy iteration stop when no value moves by more than 0.0001; policy iteration starts from the random policy and breaks ties toward the first move in the order up, down, right, left. n-step TD follows the box in Section 7.1. The off-line λ-return takes its targets from the values held at the start of the episode and applies them in time order at its end (equation 12.4). TD(λ) uses accumulating traces (Section 12.2). On the cliff, ties between equal Q-values are broken at random; the greedy path reported afterwards takes the first best move and counts as "none" if it loops or falls.
          • What is assumed, and what is not compared. The book does not state α for the cliff (0.5 here, labelled) or how many runs its cliff graph averages; it states 100 runs for the random walks and 10 episodes for the 19-state sweeps, used here. Apart from Figure 4.1, whose values are printed, the book's results exist only as plotted curves, and this page never reads numbers off a plot: it tests the shapes and orderings the text and captions state.
          • Not built. The 10-armed testbed (Figures 2.2 and 2.4) and Expected Sarsa's step-size sweep (Figure 6.3): see src/lab/viz_ideas.md for why.
