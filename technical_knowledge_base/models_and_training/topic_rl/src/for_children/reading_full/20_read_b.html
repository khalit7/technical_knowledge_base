6What an agent contains, and three axes that place any method

An agent may include any subset of three components ({{Silver, Lecture 1|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/intro_rl.pdf}}):

  • Policy π: the behaviour function, a map from state to action. Deterministic, a = π(s), or stochastic, π(a | s). An LLM is a stochastic policy over tokens.
  • Value function: a prediction of expected future reward, Vπ or Qπ, used to judge states or state-action pairs and so to choose between actions.
  • Model: the agent's own representation of the environment. A transition model predicts the next state, P̂ass′ ≈ ℙ[St+1 = s′ | St = s, At = a]; a reward model predicts the next immediate reward, R̂as ≈ 𝔼[Rt+1 | St = s, At = a]. The hats mark estimates, which may be wrong. In LLM work "reward model" usually means something else: a network trained on human preferences that scores whole responses. It plays the environment's reward role; the agent does not plan with it.

Which components an agent keeps, and how it gets its data, place it on three independent axes; every agent sits somewhere on each:

  • What the agent stores. A value-based agent keeps V or Q and acts greedily on it; the policy is implicit. A policy-based agent keeps the policy π(a | s) itself and moves it along the gradient of expected return. An actor-critic keeps both: the value function (the critic) judges the policy's actions (the actor) and lowers the variance of its updates.
  • Whether it models the environment. Model-based methods plan with a model, either given (dynamic programming, the rules of the game in AlphaZero) or learned (MuZero); model-free methods go from experience straight to values or a policy. The reward model in RLHF does not make it model-based: it stands in for the reward, and nothing plans with it.
  • Whose experience it learns from. On-policy methods learn about the policy that generated the data. Off-policy methods learn about a target policy, usually the greedy one, from data generated by a different behaviour policy, which is what lets them reuse old experience from a replay buffer (section 9). Dynamic programming sits outside this axis: it computes from the model and uses no experience at all.

Prediction and control. Prediction evaluates the future: given a fixed policy π, how much reward will it collect? Compute Vπ or Qπ. Control optimises the future: find an optimal policy π*, equivalently V* or Q*. You usually solve prediction to solve control: evaluate the current policy, improve it by acting greedily on its values, repeat. With a model that loop is policy iteration (section 8); without one, the same loop runs on samples: Monte Carlo and TD for prediction, SARSA and Q-learning for control (section 9).

7Exploration against exploitation: bandits

Exploitation uses current knowledge to take the action believed best, maximising reward now. Exploration deliberately tries actions that look worse, to gather information that may pay off later. Silver's everyday examples: go to your favourite restaurant or try a new one; drill for oil at the best known site or at a new location; play the move you believe is best or an experimental one. Every RL agent must balance the two. Pure exploitation gets stuck on the first decent behaviour it finds, because it never collects the evidence that something else is better; pure exploration never cashes in what it has learned.

The cleanest setting for the trade-off is the multi-armed bandit: an MDP with a single state. Choose one of k levers; each pays a reward from its own unknown distribution; maximise the total ({{Sutton and Barto, chapter 2|http://incompleteideas.net/book/RLbook2020.pdf#page=47}}). There is no credit-assignment problem and no state to track, so only exploration is left. Performance is measured by regret: the reward lost, summed over time, against always pulling the best arm. Lai and Robbins showed that any good strategy must suffer regret growing at least logarithmically with time ({{Lai and Robbins 1985|https://doi.org/10.1016/0196-8858(85)90002-8}}), so the question is how close to log T a strategy gets. The standard strategies:

  • Greedy: always pull the arm with the highest estimated mean. It locks onto whichever arm looked good first.
  • ε-greedy: with probability 1 − ε take the greedy action, otherwise an action chosen uniformly at random. With m actions, π(a | s) = 1 − ε + ε/m for the greedy action and ε/m for each other; the greedy action also gets its share of the random picks, hence the ε/m added to it. With ε = 0.1 and m = 4 the greedy action is taken with probability 0.9 + 0.025 = 0.925 and each other with 0.025 ({{Silver, Lecture 5|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}). Decaying ε so that the policy becomes greedy in the limit while every action is still tried infinitely often is called GLIE (greedy in the limit with infinite exploration).
  • Optimistic initialisation: start every estimate high, so a greedy agent is disappointed by whatever it tries and moves on to the untried actions. It needs a constant step size; with sample averages the optimism is erased by the first pull.
  • Upper confidence bound (UCB): pull argmaxa [ Q(a) + c √(ln t / N(a)) ], where N(a) is how often arm a has been pulled: the bonus is large for arms pulled rarely, so the agent explores where it is uncertain rather than at random. Its regret grows logarithmically ({{Auer et al. 2002|https://doi.org/10.1023/A:1013689704352}}; {{Sutton and Barto §2.7|http://incompleteideas.net/book/RLbook2020.pdf#page=57}}).
  • Thompson sampling: keep a posterior over each arm's mean, draw one sample from each, pull the best sample. It explores in proportion to the probability that an arm is the best ({{Russo et al., tutorial|https://arxiv.org/abs/1707.02038}}).
Four strategies, the same five arms, the same reward for the same arm at the same step

Arms pay their true mean (0.2, 1.0, −0.4, 1.5, 0.6, the tick on each bar; illustrative) plus standard normal noise. All four strategies read the same pre-drawn table of rewards, so the difference between them is only the choices they make; regret is Σ (1.5 − μ of the arm pulled). Estimates are sample averages except for the optimistic agent (constant step 0.1, as in {{Sutton and Barto Figure 2.3|http://incompleteideas.net/book/RLbook2020.pdf#page=56}}). Try other seeds: greedy is sometimes lucky, never reliable.

Beyond bandits. In a full MDP, exploration has to be deep: the payoff of an exploratory action may only show up many steps later, and dithering strategies like ε-greedy explore exponentially slowly in sparse-reward problems. Atari's Montezuma's Revenge, where a random agent essentially never scores, became the test case; count-based bonuses and curiosity, such as Random Network Distillation's bonus for states whose features a network cannot yet predict ({{Burda et al. 2018|https://arxiv.org/abs/1810.12894}}), and Go-Explore's "remember promising states, return to them, then explore" ({{Ecoffet et al. 2019|https://arxiv.org/abs/1901.10995}}) were the responses; {{Lilian Weng's survey|https://lilianweng.github.io/posts/2020-06-07-exploration-drl/}} maps them. Two mechanisms recur in the rest of this page: entropy bonuses in deep RL (add the policy's entropy to the objective so it does not collapse onto one action too early; SAC builds its whole objective on this, section 15) and sampling temperature in LLM rollouts (sampling several different responses per prompt at a temperature around 1 gives GRPO a spread of rewards to learn from, section 18). For language models, exploration is largely inherited: RL can only reinforce answers the pretrained model already sometimes produces.

8Planning with a known model: dynamic programming

When the transition probabilities and rewards are known, the Bellman equations can be solved by turning them into update rules and sweeping them over every state ({{Sutton and Barto, chapter 4|http://incompleteideas.net/book/RLbook2020.pdf#page=95}}; {{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}). This is dynamic programming (DP), and it is the exact answer every other method on this page approximates. Its target is the full expectation over the model: no sample, no noise.

  • Policy evaluation (prediction): apply the expectation equation as an update to every state, Vk+1(s) = Σa π(a | s) [Ras + γ Σs′ Pass′ Vk(s′)], until the values stop changing.
  • Policy improvement: make the policy greedy on those values. The policy improvement theorem guarantees the greedy policy is at least as good everywhere; if nothing changes, the Bellman optimality equation already holds.
  • Policy iteration (control): alternate evaluation and improvement until the policy stops changing. It terminates, because a finite MDP has finitely many deterministic policies.
  • Value iteration (control): skip the explicit policy and apply the optimality equation directly, Vk+1(s) = maxa [Ras + γ Σs′ Pass′ Vk(s′)]; read the policy off at the end. Its intermediate values need not be the value of any policy.
  • Generalised policy iteration (GPI): any interleaving of some evaluation with some improvement converges, as long as both keep happening. Policy iteration and value iteration are its two extremes, and most of RL, up to PPO for language models, has this shape: a critic doing approximate evaluation, a policy step doing approximate improvement.

Why it converges, and how fast. With γ < 1 the Bellman operators are contractions in the max norm: one sweep shrinks the distance between any two value functions by at least γ, so the error after k sweeps is at most γk times the initial error. Cutting the error a thousandfold needs about 66 sweeps at γ = 0.9 and 688 at γ = 0.99 derived: k ≥ ln 1000 / ln(1/γ). One sweep costs O(mn²) for n states and m actions, which is why DP stops at small state spaces: ten variables with ten values each are already ten billion states (the curse of dimensionality). Asynchronous variants (in-place updates, prioritised sweeping, real-time DP) update only the states that matter, and everything from section 9 on replaces the full sweep by samples.

One world, two ways to get its values: sweep the model, or learn from samples

Russell and Norvig's 4×3 world ({{AIMA, Figure 17.1|https://aima.cs.berkeley.edu/}}; {{the book's code|https://github.com/aimacode/aima-python/blob/master/aima/mdp.py}}): each move goes where intended with probability 0.8 and sideways with 0.1 each; bumping a wall stays put; every step costs 0.04; the two exits pay +1 and −1; γ = 1. Value iteration converges on exactly the utilities printed in AIMA's Figure 17.3 (0.812, 0.868, 0.918 on the top row; 0.705, 0.655, 0.611, 0.388 on the bottom), reproduced independently. The Q-learning agent never sees the 0.8 and 0.1: it starts each episode in a random cell, behaves ε-greedily (ε = 0.3), updates Q(s, a) toward −0.04 + maxa′ Q(s′, a′) with step 1/N(s, a)0.8, and shows maxa Q. Its run is one seeded draw; the step-size and start settings are illustrative.

What the comparison shows. Value iteration reaches AIMA's values in about 20 sweeps, each touching all 9 states with 4 actions and 3 outcomes, and it never moves the agent. Q-learning gets within a few hundredths of the same numbers only after thousands of episodes and tens of thousands of transitions, and its rarely visited cells (bottom right, next to the −1) lag longest. That is the trade: the model buys exactness and speed; samples buy independence from the model. Note too that the learner behaves ε-greedily yet converges on the values of the greedy policy: that is what off-policy means (section 9).

9Learning from samples: Monte Carlo, TD, SARSA and Q-learning

Without a model the agent cannot compute the expectation in the Bellman equation, so it substitutes samples. All the methods in this section use one incremental update, moving the estimate a fraction of the way toward a target:

V(St) ← V(St) + α ( target − V(St) )
V(St)
the current estimate
α ∈ (0, 1]
the step size
target
a stand-in for the expectation in the Bellman equation; the methods differ only here
  • Monte Carlo (MC) waits for the end of the episode and uses the actual return Gt. It is unbiased, but a whole episode's randomness lands in every estimate, so variance is high, and it must wait for termination. It does not rely on the Markov property. First-visit MC averages the return after the first visit to a state in each episode; every-visit MC averages after every visit; both converge.
  • Temporal-difference learning, TD(0) ({{Sutton 1988|https://doi.org/10.1007/BF00115009}}), uses one real reward plus its own estimate of the next state: target Rt+1 + γV(St+1). The gap δt = Rt+1 + γV(St+1) − V(St) is the TD error. It learns online, after every step, works on tasks that never end, and has low variance; it is biased by whatever error the estimate has, and in practice usually learns faster than MC.

Two independent properties describe how a value update is built (Silver's "unified view", {{Lecture 4|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}). Bootstrapping: the target involves an existing estimate; solve one step, then trust your current answer for the rest. Sampling: the target uses one sampled successor instead of the full expectation over all of them.

Bootstrapping buys lower variance and updates before the episode ends, and costs bias, because the target leans on an estimate that may be wrong. Sampling buys independence from the model and costs variance. In the student MRP with γ = ½, the Monte Carlo target for Class 1 is a whole sampled return such as −2.25 or −3.125, while the TD target after the step from Class 1 to Class 2 is −2 + ½ V(Class 2): one real reward plus the current estimate. A classic illustration of the difference: on Sutton and Barto's batch "A, B" example, batch MC fits the returns it saw while batch TD fits the most likely Markov model behind them (certainty equivalence), and the two disagree on V(A) (0 against 0.75; {{Sutton and Barto, Example 6.4|http://incompleteideas.net/book/RLbook2020.pdf#page=149}}).

Control from samples: SARSA and Q-learning

For control, learn Q rather than V (greedy on Q needs no model) and keep exploring with an ε-greedy policy:

SARSA:   Q(S, A) ← Q(S, A) + α [ R + γQ(S′, A′) − Q(S, A) ]
Q-learning:   Q(S, A) ← Q(S, A) + α [ R + γ maxa′ Q(S′, a′) − Q(S, A) ]
A′
the action the agent actually takes next (SARSA is named for the quintuple S, A, R, S′, A′)
maxa′
the best next action under the current estimates, whatever the agent then does

SARSA bootstraps off the action actually taken next, so it learns the value of the exploratory policy it is running: it is on-policy. Q-learning ({{Watkins and Dayan 1992|https://doi.org/10.1007/BF00992698}}) bootstraps off the best next action, so it learns the greedy policy's values while behaving exploratorily: it is off-policy, which is exactly what makes replaying old experience legitimate (section 12). Q-learning is sampled value iteration; SARSA is sampled policy iteration. Expected SARSA replaces Q(S′, A′) with its expectation under the policy, removing the variance of the next action ({{Sutton and Barto §6.6|http://incompleteideas.net/book/RLbook2020.pdf#page=155}}).

Cliff walking shows the difference in one picture ({{Sutton and Barto, Example 6.6|http://incompleteideas.net/book/RLbook2020.pdf#page=154}}): on a grid whose shortest path runs along a cliff edge, Q-learning learns the edge path (optimal for a greedy agent) but, exploring with ε = 0.1, keeps falling off while it learns; SARSA learns a safer path one row up and collects more reward online. If ε decays, both converge on the edge path. It runs live, against the book's figure, in the {{Estimator lab|#t-lab}}.

When they converge. Tabular TD(0) converges to Vπ with step sizes satisfying Σα = ∞ and Σα² < ∞ (the Robbins-Monro conditions). SARSA converges to Q* under GLIE exploration with such step sizes; Q-learning converges to Q* as long as every state-action pair keeps being updated, whatever the behaviour policy ({{Sutton and Barto §6.4 and §6.5|http://incompleteideas.net/book/RLbook2020.pdf#page=151}}). These guarantees are for tables; section 11 is what happens without them.

Off-policy learning and importance sampling

On-policy learning ("learn on the job") learns about π from experience sampled from π. Off-policy learning ("look over someone's shoulder") learns about a target policy π from experience sampled from a different behaviour policy μ. It is useful for learning from human demonstrations or other agents, reusing data from old policies (replay buffers), learning a greedy target while behaving exploratorily, and learning about several policies from one stream of behaviour ({{Silver, Lecture 5|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}). The general correction is importance sampling: weight each sample by how much more or less likely the target policy was to take the action:

ρt = π(At | St) / μ(At | St),    because   𝔼X~μ[ (π(X)/μ(X)) f(X) ] = 𝔼X~π[ f(X) ]
ρt
the importance ratio; f is any function

Example: the behaviour policy took an action with probability 0.25 that the target policy would take with probability 0.5, so the sample counts double (ρ = 2); an action the target policy never takes gets weight 0. Ratios multiply along a trajectory, so off-policy Monte Carlo can have very high variance. One-step Q-learning needs no ratio at all, because its target takes the max over next actions instead of using the action μ chose. The same ratio, clipped, is the heart of PPO (section 14) and GRPO (section 18), whose rollouts come from a slightly stale copy of the policy, computed by an inference engine whose probabilities differ slightly from the trainer's: LLM RL is mildly off-policy.

10The bias-variance dial: n-step returns, TD(λ) and GAE

MC and TD are the two ends of a dial. Between them are targets that use n real rewards before trusting the estimate:

Gt(n) = Rt+1 + γRt+2 + ... + γn−1Rt+n + γnV(St+n),    Gtλ = (1 − λ) Σn=1∞ λn−1 Gt(n)
Gt(n)
the n-step return: n real rewards, then the estimate of the state reached. An n-step return that reaches past the end of the episode is just the full return Gt.
λ ∈ [0, 1]
how fast the weights decay with n. At λ = 0 only the one-step TD target is left; at λ = 1 only the Monte Carlo return. In an episode that ends at time T, the weights are (1 − λ)λn−1 for n = 1, ..., T − t − 1, and the remaining λT−t−1 falls on Gt.

The λ-return is the forward view; eligibility traces compute the same thing online, as a backward view: each state keeps a trace Et(s) = γλEt−1(s) + 1(St = s) of how recently and how often it was visited, and every TD error is credited to all states in proportion to their traces. This is TD(λ) ({{Sutton and Barto, chapter 12|http://incompleteideas.net/book/RLbook2020.pdf#page=309}}). In deep RL the same dial reappears as generalised advantage estimation (GAE; {{Schulman et al. 2015|https://arxiv.org/abs/1506.02438}}), a λ-weighted sum of TD errors used as the advantage in actor-critic methods (section 13): Ât = Σl≥0 (γλ)l δt+l. PPO's reference settings use λ = 0.95 and γ = 0.99 ({{Schulman et al. 2017, Tables 3 to 5|https://arxiv.org/abs/1707.06347}}).

Why there is a dial
A target built from real rewards is unbiased but carries every step's randomness; a target that stops after one step and trusts the estimate carries only one step's randomness but inherits whatever error the estimate has. Short targets win when the estimate is good, long ones when it is poor. The same trade appears on every layer: TD(λ) with tables, GAE's λ in PPO, and GRPO, which takes the pure Monte Carlo end with a sampled baseline because a per-token critic for a language model is as large as the policy and hard to fit from a single end-of-sequence reward.

One episode, every target

The worked example that ties the page together. A three-step episode S0 → S1 → S2 → end, with γ = 0.9, rewards R1 = 0, R2 = 0, R3 = 1, current estimates V(S0) = 0.2, V(S1) = 0.4, V(S2) = 0.7 and step size α = 0.1 illustrative. The targets for S0:

  • Monte Carlo: G0 = 0 + 0.9 × 0 + 0.9² × 1 = 0.81, so the update gives 0.2 + 0.1 × (0.81 − 0.2) = 0.261.
  • TD(0): R1 + γV(S1) = 0 + 0.9 × 0.4 = 0.36, so the update gives 0.2 + 0.1 × (0.36 − 0.2) = 0.216.
  • Two-step: R1 + γR2 + γ²V(S2) = 0 + 0 + 0.81 × 0.7 = 0.567.
  • λ-return at λ = 0.5: weights 0.5 on the one-step target, 0.25 on the two-step target and the remaining 0.25 on the full return, 0.5 × 0.36 + 0.25 × 0.567 + 0.25 × 0.81 = 0.52425 (0.18 + 0.14175 + 0.2025), between the TD and Monte Carlo targets.
  • Dynamic programming, if the model were known: say the action from S0 reaches S1 with probability 0.8 and ends the episode with reward 0 with probability 0.2. The target is the expectation, 0.8 × (0 + 0.9 × 0.4) + 0.2 × 0 = 0.288, with no sample involved.
  • Policy-gradient weights (section 13): REINFORCE with V(S0) as the baseline weights the first action by G0 − V(S0) = 0.81 − 0.2 = 0.61; an actor-critic uses the TD error δ0 = 0.36 − 0.2 = 0.16.
  • GRPO (section 18), on a separate illustrative case: four responses to one prompt score 1, 0, 0 and 0. The group mean is 0.25 and the standard deviation √((0.75² + 3 × 0.25²)/4) = 0.433, so the correct response gets the advantage (1 − 0.25)/0.433 = +1.732 and each wrong one (0 − 0.25)/0.433 = −0.577, applied to every token of that response.
