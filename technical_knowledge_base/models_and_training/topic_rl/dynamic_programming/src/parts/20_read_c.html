11Why it converges, and how fast

Measure the distance between two value functions u and v by the largest difference in any state, ‖u − v‖∞ = maxs |u(s) − v(s)|. Write T for one full synchronous sweep of backups, either the expectation backup for a fixed π or the optimality backup. Both are γ-contractions ({{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}):

‖Tu − Tv‖∞ ≤ γ ‖u − v‖∞
Tu
the value function after applying one sweep to u
why
for the expectation backup, the rewards cancel and what is left is γ times an average of differences, which is at most γ times the largest difference; for the optimality backup, |maxa f(a) − maxa g(a)| ≤ maxa |f(a) − g(a)| finishes the argument

One sweep brings any two value functions at least a factor γ closer. By the contraction mapping theorem (Banach's fixed-point theorem), repeated sweeps converge to a unique fixed point (Vπ or V*) from any start, at a linear rate. Since the true values are a fixed point, TV* = V*, the error after k sweeps obeys

‖Vk − V*‖∞ ≤ γk ‖V0 − V*‖∞   ⇒   k ≥ ln(1/ε) / ln(1/γ) sweeps cut the error by 1/ε
V0
the starting guess; Vk the estimate after k sweeps
ε
the factor by which you want the initial error shrunk

With γ = 0.9, cutting the error by a factor of 1,000 takes 66 sweeps (0.966 ≈ 0.00096); with γ = 0.99 it takes 688 derived. Since ln(1/γ) ≈ 1 − γ, the sweep count grows like the effective horizon 1/(1 − γ): rewards that far away still matter, and each sweep reaches one step further. Szepesvári's lecture notes give the standard form: k ≥ ln(1/(ε(1 − γ)))/(1 − γ) iterations bring value iteration within ε of V* ({{RL Theory, lecture 3|https://rltheory.github.io/lecture-notes/planning-in-mdps/lec3/}}).

A small change is not a small error. If one sweep changes no value by more than θ, the contraction gives ‖Vk+1 − V*‖∞ ≤ γθ/(1 − γ). With γ = 0.99 and θ = 0.001 the values can still be off by up to 0.099, about a hundred times the last change. A small error is a small loss, though: acting greedily on any V with ‖V − V*‖∞ ≤ ε loses at most 2γε/(1 − γ) of return in any state ({{Singh and Yee 1994|https://doi.org/10.1007/BF00993308}}, in the form given by {{RL Theory, lecture 3|https://rltheory.github.io/lecture-notes/planning-in-mdps/lec3/}}).

Without discounting. At γ = 1 there is no contraction, yet Figure 4.1, Silver's shortest path and Russell and Norvig's 4 × 3 world all use γ = 1 and converge. What saves them is termination: if every policy evaluated eventually reaches a terminal state (a "proper" policy), the sweeps still converge, a stochastic-shortest-path result outside this page's scope (Bertsekas and Tsitsiklis 1996). Drop that and an undiscounted evaluation of a policy that loops forever on a −1 reward runs off to −∞.

Both converge to the same V* and π*. "Both policy iteration and value iteration are widely used, and it is not clear which, if either, is better in general" ({{Sutton and Barto §4.7|http://incompleteideas.net/book/RLbook2020.pdf#page=109}}). Policy iteration wins when evaluation is cheap (few actions, or an affordable linear solve) and value iteration when each state has many actions or the policy would change many times; modified policy iteration, with a handful of evaluation sweeps per improvement, sits between them and is often the practical choice. Counting model look-ups in the {{Sweep lab|#t-lab}} makes the trade concrete: to reach an error of 10−4 on the 4 × 4 grids, policy iteration needs about 60 to 80 times as many look-ups as value iteration, most of them spent evaluating the starting random policy at γ = 1, while modified policy iteration with three sweeps comes within a factor of 1.6 of value iteration; on the 4 × 3 world it beats value iteration (1,581 look-ups against 2,112).

13Cost, scale and the linear-programming view

One sweep backs up every state, and each backup looks at every action and every possible successor. With n states and m actions a sweep over state values costs O(mn²); a sweep over action values Q(s, a) costs O(m²n²), because there are mn entries and each backup looks at mn successor pairs ({{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}). Those are dense worst cases: in a gridworld each action has at most three successors, so a sweep costs about 3mn look-ups, which is what the Sweep lab counts derived. These are full-width backups: every successor and every action considered, using the known model.

DP is exponentially faster than searching policies. "In the worst case, the time that DP methods take to find an optimal policy is polynomial in the number of states and actions", although there are mn deterministic policies; direct search would have to examine each one to give the same guarantee ({{Sutton and Barto §4.7|http://incompleteideas.net/book/RLbook2020.pdf#page=109}}). In practice DP handles millions of states (Silver; Sutton and Barto) and "usually converge[s] much faster than [its] theoretical worst-case run times, particularly if [started] with good initial value functions or policies".

The curse of dimensionality is the catch: the number of states grows exponentially with the number of state variables. Ten variables with ten values each already make ten billion states, and at that size even one backup can be too expensive. Backgammon has over 1020 states; Sutton and Barto note that at a million backups a second one sweep would take "over a thousand years" (§4.5), which is an understatement: 1020/106 seconds is about 3.2 million years derived. Sutton and Barto add that large state sets are "inherent difficulties of the problem, not of DP as a solution method": DP copes with them better than direct search or linear programming.

How fast the state space grows

The linear-programming view, in brief. V* is the smallest function that satisfies every one-step inequality, so it solves a linear program: minimise Σs c(s) V(s) subject to V(s) ≥ R(s, a) + γ Σs′ P(s′ | s, a) V(s′) for every state and action, with any positive weights c; n variables and nm constraints. Its dual has one variable per state-action pair, the discounted occupancy measure (how often the policy visits each pair), and the optimal policy read from it does not depend on the weights ({{Mahajan, Stochastic control notes, linear programming|https://adityam.github.io/stochastic-control/mdps/linear-programming.html}}, written for costs, so the inequalities flip). Solving the LP with an off-the-shelf solver returns exactly the V* that value iteration converges to on the 4 × 3 world (9 variables, 36 constraints), Figure 4.1's grid and the Dyna maze derived, checked in src/recompute.py. Linear programming can have better worst-case guarantees than DP, but "become[s] impractical at a much smaller number of states than do DP methods (by a factor of about 100)" (§4.7); the dual view returns in constrained MDPs and offline RL, where occupancy measures are the natural variable, and de Farias and Van Roy built approximate DP on it ({{de Farias and Van Roy 2003|https://doi.org/10.1287/opre.51.6.850.24925}}).

14Asynchronous DP: in place, prioritised, real time

Asynchronous DP backs up states in any order rather than in systematic sweeps, "using whatever values of other states happen to be available"; some states may be updated several times before others once. It converges "given only that all states occur in the sequence {sk} an infinite number of times" for 0 ≤ γ < 1; the order can even be random ({{Sutton and Barto §4.5|http://incompleteideas.net/book/RLbook2020.pdf#page=107}}). It does not necessarily mean less computation: it means never getting "locked into any hopelessly long sweep before it can make progress", and freedom to choose which states to back up ({{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}; Bertsekas 1982, 1983):

  • In-place DP: one array, each backup immediately visible to the next. The corridor converges in one sweep with the right order (section 10). In the Sweep lab's Dyna maze, in-place value iteration in reverse reading order reaches an error of 10−4 with a third of the look-ups synchronous sweeps need (920 against 2,760).
  • Prioritised sweeping: back up the state with the largest Bellman error, |maxa(R + γΣPV) − V(s)|, kept in a priority queue; after each backup update the priorities of the affected states, which needs the reverse dynamics (predecessor states). Developed independently by Moore and Atkeson and by Peng and Williams in 1993 ({{Sutton and Barto §8.4 and notes|http://incompleteideas.net/book/RLbook2020.pdf#page=190}}), it solved a rod-manoeuvring task with 14,400 potential states that is "probably too large to be solved with unprioritized methods". The Sweep lab runs a model-known version that pushes γ × P(s | p, a) × |change| onto each predecessor p: on the Dyna maze it needs 965 look-ups against 2,760 for synchronous sweeps.
  • Real-time DP (RTDP): back up only the states an agent actually visits, with the agent acting greedily on the current values, so computation goes where experience goes. On Sutton and Barto's racetrack (9,115 reachable states, only 599 relevant), Gauss–Seidel value iteration converged in 28 sweeps and 252,784 updates; RTDP needed 127,600 updates over 4,000 episodes, about half, and left about 290 states never updated, with both policies averaging 14 to 15 steps ({{Sutton and Barto §8.7, Example 8.6|http://incompleteideas.net/book/RLbook2020.pdf#page=201}}; Barto, Bradtke and Singh 1995).

The {{Sweep lab|#t-lab}} races all of these on the same world with the same budget of model look-ups.

15Beyond DP: drop the model, drop the table

Past millions of states, either the model has to go or the table has to go. Sample backups replace the full sum over successors with one sampled transition ⟨S, A, R, S′⟩: they need no model, and the cost of a backup becomes "constant, independent of n", which "breaks the curse of dimensionality through sampling" (Silver, Lecture 3). That is {{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}: Q-learning is the sampled form of value iteration, and the TD target is the sampled form of the evaluation backup. Approximate DP replaces the table with a function approximator and backs up only sampled states, as in fitted value iteration, which leads to DQN on {{Value-based deep RL|n:3ee5c17b0d0d818689b2c0dbce434ece}}.

One world, two ways to get its values: sweep the model, or learn from samples

Russell and Norvig's 4 × 3 world ({{AIMA, Figure 17.1|https://aima.cs.berkeley.edu/}}; {{the book's code|https://github.com/aimacode/aima-python/blob/master/aima/mdp.py}}): each move goes where intended with probability 0.8 and sideways with 0.1 each; bumping a wall stays put; every step costs 0.04; the two exits pay +1 and −1; γ = 1. Value iteration converges on exactly the utilities printed in AIMA's Figure 17.3 (0.812, 0.868, 0.918 on the top row; 0.762 and 0.660 in the middle; 0.705, 0.655, 0.611, 0.388 on the bottom), reproduced independently. The Q-learning agent never sees the 0.8 and 0.1: it starts each episode in a random cell, behaves ε-greedily (ε = 0.3), updates Q(s, a) toward −0.04 + maxa′ Q(s′, a′) with step 1/N(s, a)0.8, and shows maxa Q. Its run is one seeded draw; the step-size and start settings are illustrative.

What the comparison shows. Value iteration reaches AIMA's values in about 20 sweeps, each touching all 9 states with 4 actions and 3 outcomes, and it never moves the agent. Q-learning gets within a few hundredths of the same numbers only after thousands of episodes and tens of thousands of transitions, and its rarely visited cells (bottom right, next to the −1) lag longest. That is the trade: the model buys exactness and speed; samples buy independence from the model. The bottom row also shows what optimal means under risk: the cell second from the right goes left, the long way round, rather than up beside the −1 exit, where every move risks a 10% sideways slip into it.

16How it connects, and why it still matters for LLM work

  • Up the tree: {{Topic: rl|n:3c65c17b0d0d8195a6c6c11ad093c16e}} places DP as planning with a known model, the exact form of the expectation every other family estimates; its {{Method atlas|n:3c65c17b0d0d8195a6c6c11ad093c16e}} and {{Taxonomy|n:3c65c17b0d0d8195a6c6c11ad093c16e}} tabs place value and policy iteration on every axis.
  • Generalised policy iteration is the shape of nearly every RL algorithm, including PPO for RLHF: the critic update is approximate policy evaluation and the policy-gradient step is approximate policy improvement ({{Policy gradients and actor-critic|n:3ee5c17b0d0d8101a262d3620e75747c}}). AlphaZero is GPI with Monte Carlo tree search as the improvement operator ({{Model-based RL and planning|n:3ee5c17b0d0d8116be5fd39e10bd94c5}}).
  • The one-step backup is the template for every target: V(s) ← r + γV(s′) is a DP backup with the expectation over successors replaced by one sample. It is the TD target ({{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}), and Q-learning is the sampled form of value iteration. DQN regresses a network onto the same target ({{Value-based deep RL|n:3ee5c17b0d0d818689b2c0dbce434ece}}), and GAE (generalised advantage estimation) is built from the TD errors r + γV(s′) − V(s) that the critic in PPO produces ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}).
  • Token generation is an MDP with a trivial, known transition (append the token), so the model DP needs is available; what makes DP impossible there is the size of the state space, every possible prefix, which is why LLM RL samples instead ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}). The RL stage of post-training is on {{Alignment: SFT, RLHF, DPO family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}.
  • Offline RL reuses the occupancy-measure view of section 13 and the danger of acting greedily on values the data never checked ({{Offline RL and imitation|n:3ee5c17b0d0d81d4995ec47e428de9b3}}); bandits are the one-state MDP where planning is trivial and only exploration is left ({{Bandits and exploration|n:3ee5c17b0d0d81acba54d70ac51c601c}}).

Common mistakes and misconceptions

Calling DP learning.
It never interacts with an environment; it computes from a model it is given. Without the model you need the sampling methods on {{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}.
Acting greedily on V without a model.
The greedy step needs the one-step lookahead, which needs P and R. A model-free agent that stores only V cannot pick actions from it; model-free control uses Q(s, a) precisely so that the greedy step becomes a plain argmax.
Treating the optimality equation as linear.
Matrix inversion solves the expectation equation for a fixed policy, not the optimality equation, whose max needs iteration (or a linear program with one inequality per action).
Putting the action being chosen into the history.
Ht ends at Ot, Rt; the agent chooses At from it, and the reward for At is Rt+1.
Reading value iteration's intermediate values as a policy's value.
Before convergence they may belong to no policy (section 9).
Trusting a small last change.
A last change of θ can hide an error of up to γθ/(1 − γ), a hundred times θ at γ = 0.99 (section 11).
Letting policy iteration flip between equally good actions.
If ties in the argmax are broken arbitrarily, "the policy did not change" may never be true even though the values have stopped improving. Break ties consistently (keep the current action unless another is strictly better) or stop when the values stop changing ({{Sutton and Barto, Exercise 4.4|http://incompleteideas.net/book/RLbook2020.pdf#page=104}}).
Assuming full evaluation is required before improving.
A few sweeps are usually enough; one sweep is value iteration (section 8).
Stopping modified policy iteration on an unchanged policy alone.
After a truncated evaluation the values are not yet the policy's own, so an unchanged greedy policy can still be suboptimal; also require the values to have converged.
Using γ = 1 carelessly.
Without discounting the contraction argument is gone, and evaluation converges only if every policy you evaluate eventually reaches a terminal state (section 11). It is not always wrong: it is standard when every episode terminates, as in LLM RL.
Blaming the curse of dimensionality on DP.
Large state sets are "inherent difficulties of the problem, not of DP as a solution method"; DP still beats direct policy search and linear programming at scale (section 13).
Treating DP as obsolete.
Its structure, evaluate then improve, and its backup, reward plus discounted next value, are inside every modern RL algorithm (section 16).
