Both need the model and converge to the same V* and π*. "Both policy iteration and value iteration are widely used, and it is not clear which, if either, is better in general" ({{Sutton and Barto §4.7|http://incompleteideas.net/book/RLbook2020.pdf#page=109}}). Policy iteration wins when evaluation is cheap (few actions, or an affordable linear solve), value iteration when each state has many actions or the policy would change many times; modified policy iteration, with a handful of evaluation sweeps per improvement, sits between them and is often the practical choice. Counting model look-ups in the {{Sweep lab|#t-lab}} makes the trade concrete: to reach an error of 10−4 on the 4 × 4 grids, policy iteration needs about 60 to 80 times as many look-ups as value iteration, most of them spent evaluating the starting random policy at γ = 1, while modified policy iteration with three sweeps comes within a factor of 1.6 of value iteration; on the 4 × 3 world it beats value iteration (1,581 look-ups against 2,112).

Worst-case complexity, known results (depth)
  • Policy iteration: at most Õ(nm/(1 − γ)) improvements for fixed γ, independent of the reward's precision: strongly polynomial ({{Ye 2011|https://doi.org/10.1287/moor.1110.0516}}; bound as in {{RL Theory, lecture 4|https://rltheory.github.io/lecture-notes/planning-in-mdps/lec4/}}).
  • Value iteration: O(mn² ln(1/δ)/(1 − γ)) operations for a δ-optimal answer; its dependence on δ is not needed in principle, since Ω(n²m) operations are a lower bound for any method ({{RL Theory, lecture 3|https://rltheory.github.io/lecture-notes/planning-in-mdps/lec3/}}).

11Cost, scale and the curse of dimensionality

One sweep backs up every state, and each backup reads every action and every possible successor. With n states and m actions a sweep over state values costs O(mn²); a sweep over action values Q(s, a) costs O(m²n²), because there are mn entries and each backup reads mn successor pairs ({{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}). Those are dense worst cases: in a gridworld each action has at most three successors, so a sweep costs about 3mn look-ups, which is what the Sweep lab counts derived.

DP is exponentially faster than searching policies. "In the worst case, the time that DP methods take to find an optimal policy is polynomial in the number of states and actions", although there are mn deterministic policies, each of which direct search would have to examine for the same guarantee ({{Sutton and Barto §4.7|http://incompleteideas.net/book/RLbook2020.pdf#page=109}}). In practice DP handles millions of states (Silver; Sutton and Barto) and "usually converge[s] much faster than [its] theoretical worst-case run times, particularly if [started] with good initial value functions or policies".

The curse of dimensionality (Bellman's phrase) is the catch: states multiply with every state variable. Predict before moving the sliders: ten variables with ten values each make how many states? Then try twenty.

States grow exponentially with the number of variables; one sweep soon takes years

States n = (values)variables; look-ups per value-iteration sweep: mn² if every state can lead to every state, mnb with b = 3 successors per action as in the grids here; deterministic policies mn. The time assumes 109 look-ups a second, an illustrative rate.

Ten variables with ten values each already make ten billion states, and at that size even one backup can be too expensive. Backgammon has over 1020 states; Sutton and Barto note that at a million backups a second one sweep would take "over a thousand years" (§4.5), an understatement: 1020/106 seconds is about 3.2 million years derived. Large state sets are "inherent difficulties of the problem, not of DP as a solution method": DP copes with them better than direct search or linear programming.

The linear-programming view (depth, 1 min)

V* is the smallest function that satisfies every one-step inequality, so it solves a linear program: minimise Σs c(s) V(s) subject to V(s) ≥ R(s, a) + γ Σs′ P(s′ | s, a) V(s′) for every state and action, with any positive weights c; n variables and nm constraints (one inequality per action is how the max of the optimality equation becomes linear). Its dual has one variable per state-action pair, the discounted occupancy measure (how often the policy visits each pair), and the optimal policy read from it does not depend on the weights ({{Mahajan, Stochastic control notes, linear programming|https://adityam.github.io/stochastic-control/mdps/linear-programming.html}}, written for costs, so the inequalities flip). An off-the-shelf solver returns exactly the V* that value iteration converges to on the 4 × 3 world (9 variables, 36 constraints), Figure 4.1's grid and the Dyna maze derived, checked in src/recompute.py. Linear programming can have better worst-case guarantees than DP, but "become[s] impractical at a much smaller number of states than do DP methods (by a factor of about 100)" (§4.7). The dual view returns in constrained MDPs and offline RL, where occupancy measures are the natural variable, and de Farias and Van Roy built approximate DP on it ({{de Farias and Van Roy 2003|https://doi.org/10.1287/opre.51.6.850.24925}}).

12Asynchronous DP: in place, prioritised, real time

Asynchronous DP backs up states in any order rather than in systematic sweeps, "using whatever values of other states happen to be available"; some states may be updated several times before others once. It converges "given only that all states occur in the sequence {sk} an infinite number of times" for 0 ≤ γ < 1; the order can even be random ({{Sutton and Barto §4.5|http://incompleteideas.net/book/RLbook2020.pdf#page=107}}). It does not necessarily mean less computation: it means never getting "locked into any hopelessly long sweep before it can make progress", and freedom to choose which states to back up ({{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}; Bertsekas 1982, 1983). The {{Sweep lab|#t-lab}} races these on the same world with the same budget of model look-ups.

  • In-place DP: one array, each backup immediately visible to the next (the corridor of section 8 converges in one sweep with the right order). In the Sweep lab's Dyna maze, in-place value iteration in reverse reading order reaches an error of 10−4 with a third of the look-ups synchronous sweeps need (920 against 2,760; in reading order it needs 2,208): which order helps depends on where the reward sits.
  • Prioritised sweeping: back up the state with the largest Bellman error, |maxa(R + γΣPV) − V(s)|, kept in a priority queue; after each backup update the priorities of the affected states, which needs the reverse dynamics (predecessor states). The Sweep lab's model-known version pushes γ × P(s | p, a) × |change| onto each predecessor p: on the Dyna maze it needs 965 look-ups against 2,760 for synchronous sweeps.
  • Real-time DP (RTDP): back up only the states an agent actually visits while acting greedily on the current values, so computation goes where experience goes. On Sutton and Barto's racetrack it needed about half the updates of Gauss–Seidel value iteration for an equally good policy (numbers below). Trajectory sampling at scale is {{Model-based RL and planning|n:3ee5c17b0d0d8116be5fd39e10bd94c5}}'s.
The published numbers: prioritised sweeping and the racetrack (depth, 1 min)

Prioritised sweeping was developed independently by Moore and Atkeson and by Peng and Williams in 1993 ({{Sutton and Barto §8.4 and notes|http://incompleteideas.net/book/RLbook2020.pdf#page=190}}); it solved a rod-manoeuvring task with 14,400 potential states that is "probably too large to be solved with unprioritized methods".

On Sutton and Barto's racetrack (9,115 reachable states, only 599 relevant), Gauss–Seidel value iteration converged in 28 sweeps and 252,784 updates, about twice as fast as the Jacobi version; RTDP needed 127,600 updates over 4,000 episodes, about half, and left about 290 states never updated, with both policies averaging 14 to 15 steps ({{Sutton and Barto §8.7, Example 8.6|http://incompleteideas.net/book/RLbook2020.pdf#page=201}}; Barto, Bradtke and Singh 1995).

13Beyond DP: drop the model, drop the table

Past millions of states, either the model has to go or the table has to go. Sample backups replace the full sum over successors with one sampled transition ⟨S, A, R, S′⟩: they need no model, and the cost of a backup becomes "constant, independent of n", which "breaks the curse of dimensionality through sampling" (Silver, Lecture 3). Predict: on the same 9-cell world, how many sampled transitions does Q-learning need to get within a few hundredths of what value iteration reaches in about 20 sweeps?

One world, two ways to get its values: sweep the model, or learn from samples

Russell and Norvig's 4 × 3 world ({{AIMA, Figure 17.1|https://aima.cs.berkeley.edu/}}; {{the book's code|https://github.com/aimacode/aima-python/blob/master/aima/mdp.py}}): each move goes where intended with probability 0.8 and sideways with 0.1 each; bumping a wall stays put; every step costs 0.04; the two exits pay +1 and −1; γ = 1. Value iteration converges on exactly the utilities printed in AIMA's Figure 17.3 (0.812, 0.868, 0.918 on the top row; 0.762 and 0.660 in the middle; 0.705, 0.655, 0.611, 0.388 on the bottom), reproduced independently. The Q-learning agent never sees the 0.8 and 0.1: it starts each episode in a random cell, behaves ε-greedily (ε = 0.3), updates Q(s, a) toward −0.04 + maxa′ Q(s′, a′) with step 1/N(s, a)0.8, and shows maxa Q. Its run is one seeded draw; the step-size and start settings are illustrative.

The answer. Value iteration reaches AIMA's values in about 20 sweeps, each touching all 9 states with 4 actions and 3 outcomes, and it never moves the agent. Q-learning gets within a few hundredths of the same numbers only after thousands of episodes and tens of thousands of transitions, and its rarely visited cells (bottom right, next to the −1) lag longest. The model buys exactness and speed; samples buy independence from the model. The bottom row also shows what optimal means under risk: the cell second from the right goes left, the long way round, rather than up beside the −1 exit, where every move risks a 10% sideways slip into it.

Where DP lives on. Replace the expectation by one sample and the backup is the TD target (Q-learning is sampled value iteration); replace the table by a network and it is approximate DP, DQN; keep evaluate-then-improve with both approximated and it is GPI, the shape of PPO. Token generation even has the known model DP needs, but every possible prefix is a state, so LLM RL samples instead.

Each connection, with the page that owns it (links, 1 min)
  • The one-step backup is the template for every target: V(s) ← r + γV(s′) is a DP backup with the expectation replaced by one sample. It is the TD target, and Q-learning is the sampled form of value iteration ({{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}). Approximate DP replaces the table with a function approximator and backs up only sampled states, as in fitted value iteration; DQN regresses a network onto the same target ({{Value-based deep RL|n:3ee5c17b0d0d818689b2c0dbce434ece}}), and GAE (generalised advantage estimation) is built from the TD errors r + γV(s′) − V(s) that the critic in PPO produces ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}).
  • GPI is the shape of nearly every RL algorithm, including PPO for RLHF: the critic update is approximate policy evaluation and the policy-gradient step approximate improvement ({{Policy gradients and actor-critic|n:3ee5c17b0d0d8101a262d3620e75747c}}). AlphaZero is GPI with Monte Carlo tree search as the improvement operator ({{Model-based RL and planning|n:3ee5c17b0d0d8116be5fd39e10bd94c5}}).
  • Token generation is an MDP with a trivial, known transition (append the token), so the model DP needs is available; what makes DP impossible is the size of the state space, every possible prefix, which is why LLM RL samples instead ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}; the RL stage of post-training is on {{Alignment: SFT, RLHF, DPO family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}).
  • Offline RL reuses the occupancy-measure view (section 11) and the danger of acting greedily on values the data never checked ({{Offline RL and imitation|n:3ee5c17b0d0d81d4995ec47e428de9b3}}); bandits are the one-state MDP where planning is trivial and only exploration is left ({{Bandits and exploration|n:3ee5c17b0d0d81acba54d70ac51c601c}}). {{Topic: rl|n:3c65c17b0d0d8195a6c6c11ad093c16e}}'s Method atlas and Taxonomy tabs place value and policy iteration on every axis.
