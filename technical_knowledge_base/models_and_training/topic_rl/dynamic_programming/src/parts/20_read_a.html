Dynamic programming in one screen

Dynamic programming (DP) computes value functions and optimal policies when the full model of the environment is known: for every state and action you have the transition probabilities P(s′ | s, a) and the expected reward R(s, a). Nothing is learned from interaction. The algorithms compute, which makes DP model-based planning, not learning ({{Sutton and Barto, chapter 4|http://incompleteideas.net/book/RLbook2020.pdf#page=95}}; {{Silver, Lecture 3|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-3-planning-by-dynamic-programming-.pdf}}).

The idea is the one in Richard Bellman's name for it: a long-horizon problem breaks into one-step pieces. The value of a state is the reward you get now plus the discounted value of the state you land in, so if you had good values for the successors you could compute this state's value in one line. DP starts from a guess for every state and applies that one-line computation, a backup, to every state, again and again. Each sweep pushes reward information one more step back from where it is earned, and the guesses converge to the true values.

It matters for two reasons. DP is the ideal every model-free method approximates: Monte Carlo, TD learning, SARSA and Q-learning replace its exact expectation over all successor states with one sampled successor. And the DP backup is the template for every learning target in RL: a TD target, a DQN target and the value target inside PPO are all "reward plus discounted value of the next state". DP solves two problems: prediction (given a policy, how good is it? policy evaluation) and control (find the best policy: policy iteration and value iteration). Their model-free counterparts, SARSA and Q-learning, are on {{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}.

Three facts to carry
It converges: with γ < 1 one sweep shrinks the worst-case error by at least γ (a contraction), so 66 sweeps cut it a thousandfold at γ = 0.9 and 688 at γ = 0.99 (section 11). It is fast for what it does: polynomial in states and actions, although there are mn deterministic policies (section 13). It does not scale: one sweep touches every state, and states multiply with every state variable, Bellman's curse of dimensionality; sampling, function approximation or both are the way out (section 15).

1The setting: loop, history, state and observability

At each time step t ({{Silver, Lecture 1|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/intro_rl.pdf}}): the agent receives an observation Ot and a scalar reward Rt; it chooses and executes an action At; the environment receives At and emits the next observation Ot+1 and reward Rt+1, and t increments. So the reward that follows action At is Rt+1. This indexing, used by Silver and by Sutton and Barto, is why every return below starts at Rt+1; some texts write rt for the reward of the action taken at t, and only the subscript shifts.

Ht = O1, R1, A1, O2, R2, A2, ..., At−1, Ot, Rt
Ht
the history: everything observed up to time t. It ends with the latest observation and reward and does not yet contain At, because the agent chooses At from it. What happens next depends on the history: the agent selects actions, the environment selects observations and rewards. It grows without bound, which is why agents summarise it.

A state is the information used to decide what happens next: formally, any function of the history, St = f(Ht). Two kinds matter. The environment state Set is the environment's private representation, whatever it uses to pick the next observation and reward; it is usually invisible to the agent, and even when visible may hold irrelevant detail, so it is useful for reasoning about the environment, not as an input the agent can use. The agent state Sat = f(Ht) is the agent's own summary of the history, the information it uses to pick its next action; this is the state RL algorithms work with.

ℙ[St+1 | St] = ℙ[St+1 | S1, ..., St]
Markov
a state is Markov if the next state depends only on the current one, not on the rest of the history: "the future is independent of the past given the present". Once a Markov state is known the history can be thrown away, because the state is a sufficient statistic of the future. S1, ..., St are all the states so far; ℙ[· | ·] is a conditional probability.

The environment state is Markov, and so, trivially, is the full history Ht. The design problem is a compact agent state that is still Markov, or close to it. A single Atari frame is not Markov: it shows where the ball is but not where it is going. Stacking the last four frames, as DQN (deep Q-network) does, recovers the velocity ({{Mnih et al. 2015, Methods|https://storage.googleapis.com/deepmind-media/dqn/DQNNaturePaper.pdf}}). The Markov property is what makes DP's one-step recursion valid: the backup reads only the successor's value, never the path that led there.

Observability. When the agent directly observes the environment state, Ot = Sat = Set, the problem is fully observable: agent state, environment state and Markov state coincide, and the problem is formally a Markov decision process (MDP, section 2). Most of RL theory, and all of DP on this page, lives here. When the agent observes the environment only indirectly (a robot with camera vision that is not told its absolute location, a trading agent that sees only current prices, a poker agent that sees only the public cards), the problem is a partially observable MDP (POMDP), and the agent must build its own state. Three standard choices:

  • the complete history, Sat = Ht;
  • a belief: the vector of probabilities Sat = (ℙ[Set = s1], ..., ℙ[Set = sn]) over the n possible environment states;
  • a learned recurrent summary, an RNN (recurrent neural network) state Sat = σ(Ws Sat−1 + Wo Ot), where σ is an elementwise nonlinearity such as the logistic sigmoid or tanh, Ws a learned matrix applied to the previous agent state and Wo a learned matrix applied to the new observation.

DP extends to POMDPs by planning over beliefs, which turns a finite problem into one over a continuous belief space ({{Sutton and Barto, chapter 1 history|http://incompleteideas.net/book/RLbook2020.pdf#page=36}} cites Lovejoy's 1991 survey); this page stays fully observable. The language-model case: a decoder conditioning on its full token prefix is the Sat = Ht choice, and in plain text generation nothing is hidden: the state is the prompt plus the tokens so far, and appending a token is deterministic, so generation is a fully observable MDP with a trivial, known transition (section 16 returns to why DP still cannot solve it).

2Markov process to MRP to MDP, and the return

The formal object DP solves is built in three steps, each adding one ingredient. The running example is David Silver's student chain ({{Silver, Lecture 2|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-2-mdp.pdf}}): the states Class 1, Class 2, Class 3, Pass, Pub, Facebook and Sleep, where Sleep is terminal. The diagram in section 3 draws all three.

1. Markov process (Markov chain) ⟨𝒮, P⟩: a memoryless random sequence of states S1, S2, ... with the Markov property, where 𝒮 is a finite set of states and P the state transition matrix, Pss′ = ℙ[St+1 = s′ | St = s], one row per current state and one column per successor, each row summing to 1. In the student chain, Class 1 goes to Class 2 or Facebook with probability 0.5 each; Class 2 goes to Class 3 with 0.8 or Sleep with 0.2; Class 3 goes to Pass with 0.6 or Pub with 0.4; Pass goes to Sleep with 1.0; Pub goes to Class 1, Class 2 or Class 3 with 0.2, 0.4 and 0.4; Facebook stays on Facebook with 0.9 and returns to Class 1 with 0.1.

2. Markov reward process (MRP) ⟨𝒮, P, R, γ⟩: a Markov chain with rewards. Rs = 𝔼[Rt+1 | St = s] is the expected reward for leaving state s, and γ ∈ [0, 1] the discount factor. In the student MRP each class gives −2, Facebook −1, Pub +1, Pass +10 and Sleep 0. An MRP defines a return and a value, but nobody decides anything.

3. Markov decision process (MDP) ⟨𝒮, 𝒜, P, R, γ⟩: an MRP with decisions. 𝒜 is a finite set of actions, and transitions and rewards now depend on the action:

Pass′ = ℙ[St+1 = s′ | St = s, At = a],    Ras = 𝔼[Rt+1 | St = s, At = a]
Pass′
the probability of landing in s′ after taking a in s; written P(s′ | s, a) elsewhere on this page
Ras
the expected immediate reward for taking a in s; written R(s, a)

You no longer drift between states at random: your action moves you, possibly stochastically. The only new ingredient is agency. In the student MDP, from Class 1 you choose Study (−2, to Class 2) or Facebook (−1, to Facebook); from Facebook, Facebook again (−1) or Quit (0, back to Class 1); from Class 2, Study (−2, to Class 3) or Sleep (0, the end); from Class 3, Study (+10, pass, the end) or Pub (+1, after which chance sends you to Class 1, Class 2 or Class 3 with 0.2, 0.4 and 0.4). Sutton and Barto write the dynamics as one joint distribution p(s′, r | s, a) rather than P and an expected R; they note the MDP literature usually uses the pair, and for DP the two are equivalent because only the expected reward enters the backups ({{Sutton and Barto, chapter 3 notes|http://incompleteideas.net/book/RLbook2020.pdf#page=92}}).

A policy is a distribution over actions given states, π(a | s) = ℙ[At = a | St = s]; a deterministic policy picks one action, written π(s). Fixing a policy turns an MDP back into an MRP:

Pπss′ = Σa π(a | s) Pass′,    Rπs = Σa π(a | s) Ras

Averaging over the policy's choices removes the agency, which is why evaluating a fixed policy is an MRP problem, and why policy evaluation (section 6) is linear.

The return and why to discount

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ... = Σk=0∞ γk Rt+k+1    and recursively    Gt = Rt+1 + γGt+1
Gt
the return: the total discounted reward from step t on; in an episodic task the sum stops at the terminal step
γ ∈ [0, 1]
a reward k + 1 steps ahead counts γk times as much as the same reward now; near 0 is myopic, near 1 far-sighted. The weights sum to 1/(1 − γ), so γ = 0.9 behaves like a horizon of about 10 steps and γ = 0.99 like 100 derived

The agent maximises cumulative reward, not immediate reward, so it can pay to sacrifice reward now: refuelling a helicopter costs time now but may prevent a crash hours later, and a financial investment may take months to mature (Silver, Lecture 1). Four reasons to discount, from Silver's second lecture:

  1. Cycles. It keeps returns finite in cyclic or never-ending processes (the student chain can loop on Facebook indefinitely).
  2. Uncertainty. The future is less certain than the present, and the model of it may be imperfect, so weight it less.
  3. Convenience. With γ < 1 the Bellman operators are contractions, so iterating them converges to a unique answer from any start: the reason DP converges (section 11).
  4. Preference. Human and animal behaviour prefers reward sooner, and immediate money can earn interest.

Undiscounted returns (γ = 1) are fine when every sequence is guaranteed to terminate; LLM RL typically uses γ = 1, because every response ends and the reward arrives at the end.

The return is a random variable. Start in Class 1 with γ = ½ and sample the episode Class 1, Class 2, Class 3, Pass, Sleep: the rewards for leaving each state are −2, −2, −2 and +10, so G1 = −2 + ½(−2) + ¼(−2) + ⅛(10) = −2 − 1 − 0.5 + 1.25 = −2.25. Another episode from the same start, Class 1, Facebook, Facebook, Class 1, Class 2, Sleep, gives −2 − ½ − ¼ − 2/8 − 2/16 = −3.125. The value function is the average over all such episodes. Averaging samples is what model-free methods do; DP computes the same average exactly from the model. The widget shows both.

The value is the average return: sample episodes of the student MRP from Class 1, against the exact value

Episodes are drawn with the chain's own probabilities from a seeded random stream (seed 42), so each reset replays the same draws; the line is the running mean of the sampled returns and the dashed line the exact value from the Bellman equation (next section), the number DP computes. The mean creeps toward it slowly, because one episode can loop on Facebook for dozens of steps: that slowness is what the model buys you out of. Sampling methods are on {{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}.

3Value functions and the Bellman equations

The value function is the expected return, which removes the randomness of individual episodes. In an MRP, V(s) = 𝔼[Gt | St = s]. In an MDP the return depends on how you act, so values are defined for a policy π:

Vπ(s) = 𝔼π[Gt | St = s],    Qπ(s, a) = 𝔼π[Gt | St = s, At = a]
Vπ(s)
the state value: expected return from state s when following π
Qπ(s, a)
the action value: expected return from taking action a in s, then following π
𝔼π
an expectation over the randomness of both the policy and the environment

The two are one step apart:

Vπ(s) = Σa π(a | s) Qπ(s, a),    Qπ(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) Vπ(s′)
first
averages the action values under the policy
second
the one-step lookahead: the step that needs the model, P and R

That asymmetry is why Q is what you want for model-free control: acting greedily on Q is argmaxa Q(s, a), a lookup over actions, while acting greedily on V needs the lookahead and so the transition dynamics. DP has the model, so it works with V and computes Q when it needs it.

Optimal values. V*(s) = maxπ Vπ(s) is the best achievable expected return from s, and Q*(s, a) = maxπ Qπ(s, a). An MDP is solved once Q* is known, because the policy that picks argmaxa Q*(s, a) in every state is optimal. For any finite MDP there is an optimal policy π* at least as good as every other policy in every state, all optimal policies share V* and Q*, and there is always a deterministic one ({{Silver, Lecture 2|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-2-mdp.pdf}}).

Deriving the Bellman equation

The Bellman equation cuts a long-horizon problem into one-step pieces: the value of a state is the immediate reward plus the discounted value of the successor. It follows from the return's own recursion:

V(s) = 𝔼[Gt | St = s] = 𝔼[Rt+1 + γGt+1 | St = s] = 𝔼[Rt+1 + γV(St+1) | St = s]
last step
replaces the random tail Gt+1 by its expectation V(St+1), which the Markov property allows. For an MRP with known P and R it reads V(s) = Rs + γ Σs′ Pss′ V(s′), where Rs is the expected reward for leaving s, Pss′ the probability of moving to s′ and V(s′) each successor's value

The four equations

Bellman expectation equations, for a fixed policy π:

Vπ(s) = Σa π(a | s) [ R(s, a) + γ Σs′ P(s′ | s, a) Vπ(s′) ]
Qπ(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) Σa′ π(a′ | s′) Qπ(s′, a′)
s, a, s′
the current state, an action, a possible next state
a′
the action taken in the successor s′
bracket
the one-step lookahead value of action a

These are linear in the values: one equation per state, as many unknowns as states. In matrix form Vπ = Rπ + γPπVπ, with the direct solution

Vπ = (I − γPπ)−1 Rπ
Vπ, Rπ
column vectors with one entry per state
Pπ
the state-to-state transition matrix under π (the MRP of section 2)
I
the identity. Inversion costs O(n³) for n states, so the direct solution is only for small problems; large ones use iterative methods: DP, Monte Carlo, temporal-difference learning

Bellman optimality equations, for the optimal values:

V*(s) = maxa [ R(s, a) + γ Σs′ P(s′ | s, a) V*(s′) ]
Q*(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) maxa′ Q*(s′, a′)

The max replaces the average under a policy. It makes the equations nonlinear, so in general there is no closed form: they are solved iteratively, by value iteration and policy iteration when the model is known (this page), and by Q-learning, and SARSA with exploration decaying to greedy, from samples when it is not ({{Model-free prediction and control|n:3c65c17b0d0d81898a0cd4c05c744969}}). Everything downstream, from value iteration to DQN's TD target to the value model in PPO-based RLHF, is a way of approximately solving one of these equations. Four value functions, four Bellman equations, four DP updates: "little more than these equations turned into assignment statements" ({{Sutton and Barto §4.8|http://incompleteideas.net/book/RLbook2020.pdf#page=110}}).

Prediction and control, the two problems these equations pose. Prediction evaluates the future: given a fixed policy π, how much reward will it collect? Compute Vπ or Qπ. Control optimises the future: find an optimal policy π*, equivalently V* or Q*. You usually solve prediction to solve control: evaluate the current policy, improve it by acting greedily on its values, repeat. With a model, prediction is policy evaluation (section 6) and control is policy iteration (section 8) or value iteration (section 9).

4Where the equations and the algorithms come from

  • Hamilton and Jacobi to Bellman. "Optimal control" came into use in the late 1950s. One approach, developed in the mid-1950s by Richard Bellman and others, extended a nineteenth-century theory of Hamilton and Jacobi: it uses a dynamical system's state and a value function, or "optimal return function", to define a functional equation, now called the Bellman equation; the class of methods that solve it came to be known as dynamic programming ({{Sutton and Barto §1.7|http://incompleteideas.net/book/RLbook2020.pdf#page=36}}). Bellman called the optimality equation the "basic functional equation"; its continuous-time, continuous-state counterpart is the Hamilton–Jacobi–Bellman equation ({{Sutton and Barto, chapter 3 notes|http://incompleteideas.net/book/RLbook2020.pdf#page=93}}).
  • The name. "The term dynamic programming is due to Bellman (1957a)", the book Dynamic Programming ({{Sutton and Barto, chapter 4 notes|http://incompleteideas.net/book/RLbook2020.pdf#page=111}}). Bellman later wrote that he picked it in 1950 at RAND so that the work would not sound like mathematical research to the Secretary of Defense, Charles Wilson, who disliked the word: "dynamic" because it was "impossible to use ... in a pejorative sense", and "programming" in the military sense of planning schedules and logistics, as in linear programming, not writing code ({{Dreyfus 2002, Operations Research 50(1)|https://doi.org/10.1287/opre.50.1.48.17791}}, reprinting the autobiography). Russell and Norvig point out that the story "cannot be strictly true": Bellman's first paper using the term (1952) predates Wilson's appointment in 1953 (quoted in {{Wikipedia, Dynamic programming: History|https://en.wikipedia.org/wiki/Dynamic_programming#History_of_the_name}}). The phrase curse of dimensionality is Bellman's too.
  • MDPs and value iteration. Bellman also introduced the discrete stochastic version of the optimal control problem, Markov decision processes ({{Bellman 1957, "A Markovian Decision Process", J. Math. Mech. 6|https://doi.org/10.1512/iumj.1957.6.56038}}). Value iteration, the successive-approximation solution of his equation, is his; it predates policy iteration, though textbooks now present it as truncated policy iteration (the {{Method atlas|n:3c65c17b0d0d8195a6c6c11ad093c16e}} tab of Topic: rl places it first among 47 methods).
  • Policy iteration. "The policy improvement theorem and the policy iteration algorithm are due to Bellman (1957a) and Howard (1960)", Ronald Howard's Dynamic Programming and Markov Processes. Modified policy iteration, which contains both policy and value iteration as special cases, is due to Puterman and Shin (1978); asynchronous DP to Bertsekas (1982, 1983), who called it distributed DP; and the contraction-mapping treatment of DP to Denardo (1967) ({{Sutton and Barto, chapter 3 and 4 notes|http://incompleteideas.net/book/RLbook2020.pdf#page=111}}).
  • DP meets RL. The first connection was a footnote by Minsky (1961) on Samuel's checkers player, which may have led AI researchers to think DP applied only to analytically tractable problems; Werbos (1977) proposed "heuristic dynamic programming"; Watkins (1989) called a class of RL methods "incremental dynamic programming" and made the most influential link between RL and MDPs, with Q-learning (same source).
