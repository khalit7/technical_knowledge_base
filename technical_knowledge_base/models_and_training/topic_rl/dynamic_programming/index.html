Dynamic programming in one screen

Dynamic programming (DP) computes value functions and optimal policies when the full model of the environment is known: for every state and action you have the transition probabilities P(s′ | s, a) and the expected reward R(s, a). Nothing is learned from interaction. The algorithms compute, which makes DP model-based planning, not learning (Sutton and Barto, chapter 4; Silver, Lecture 3).

The idea is the one in Richard Bellman's name for it: a long-horizon problem breaks into one-step pieces. The value of a state is the reward you get now plus the discounted value of the state you land in, so if you had good values for the successors you could compute this state's value in one line. DP starts from a guess for every state and applies that one-line computation, a backup, to every state, again and again. Each sweep pushes reward information one more step back from where it is earned, and the guesses converge to the true values.

It matters for two reasons. DP is the ideal every model-free method approximates: Monte Carlo, TD learning, SARSA and Q-learning replace its exact expectation over all successor states with one sampled successor. And the DP backup is the template for every learning target in RL: a TD target, a DQN target and the value target inside PPO are all "reward plus discounted value of the next state". DP solves two problems: prediction (given a policy, how good is it? policy evaluation) and control (find the best policy: policy iteration and value iteration). Their model-free counterparts, SARSA and Q-learning, are on Model-free prediction and control.

Three facts to carry
It converges: with γ < 1 one sweep shrinks the worst-case error by at least γ (a contraction), so 66 sweeps cut it a thousandfold at γ = 0.9 and 688 at γ = 0.99 (section 11). It is fast for what it does: polynomial in states and actions, although there are mn deterministic policies (section 13). It does not scale: one sweep touches every state, and states multiply with every state variable, Bellman's curse of dimensionality; sampling, function approximation or both are the way out (section 15).

1The setting: loop, history, state and observability

At each time step t (Silver, Lecture 1): the agent receives an observation Ot and a scalar reward Rt; it chooses and executes an action At; the environment receives At and emits the next observation Ot+1 and reward Rt+1, and t increments. So the reward that follows action At is Rt+1. This indexing, used by Silver and by Sutton and Barto, is why every return below starts at Rt+1; some texts write rt for the reward of the action taken at t, and only the subscript shifts.

Ht = O1, R1, A1, O2, R2, A2, ..., At−1, Ot, Rt
Ht
the history: everything observed up to time t. It ends with the latest observation and reward and does not yet contain At, because the agent chooses At from it. What happens next depends on the history: the agent selects actions, the environment selects observations and rewards. It grows without bound, which is why agents summarise it.

A state is the information used to decide what happens next: formally, any function of the history, St = f(Ht). Two kinds matter. The environment state Set is the environment's private representation, whatever it uses to pick the next observation and reward; it is usually invisible to the agent, and even when visible may hold irrelevant detail, so it is useful for reasoning about the environment, not as an input the agent can use. The agent state Sat = f(Ht) is the agent's own summary of the history, the information it uses to pick its next action; this is the state RL algorithms work with.

ℙ[St+1 | St] = ℙ[St+1 | S1, ..., St]
Markov
a state is Markov if the next state depends only on the current one, not on the rest of the history: "the future is independent of the past given the present". Once a Markov state is known the history can be thrown away, because the state is a sufficient statistic of the future. S1, ..., St are all the states so far; ℙ[· | ·] is a conditional probability.

The environment state is Markov, and so, trivially, is the full history Ht. The design problem is a compact agent state that is still Markov, or close to it. A single Atari frame is not Markov: it shows where the ball is but not where it is going. Stacking the last four frames, as DQN (deep Q-network) does, recovers the velocity (Mnih et al. 2015, Methods). The Markov property is what makes DP's one-step recursion valid: the backup reads only the successor's value, never the path that led there.

Observability. When the agent directly observes the environment state, Ot = Sat = Set, the problem is fully observable: agent state, environment state and Markov state coincide, and the problem is formally a Markov decision process (MDP, section 2). Most of RL theory, and all of DP on this page, lives here. When the agent observes the environment only indirectly (a robot with camera vision that is not told its absolute location, a trading agent that sees only current prices, a poker agent that sees only the public cards), the problem is a partially observable MDP (POMDP), and the agent must build its own state. Three standard choices:

  • the complete history, Sat = Ht;
  • a belief: the vector of probabilities Sat = (ℙ[Set = s1], ..., ℙ[Set = sn]) over the n possible environment states;
  • a learned recurrent summary, an RNN (recurrent neural network) state Sat = σ(Ws Sat−1 + Wo Ot), where σ is an elementwise nonlinearity such as the logistic sigmoid or tanh, Ws a learned matrix applied to the previous agent state and Wo a learned matrix applied to the new observation.

DP extends to POMDPs by planning over beliefs, which turns a finite problem into one over a continuous belief space (Sutton and Barto, chapter 1 history cites Lovejoy's 1991 survey); this page stays fully observable. The language-model case: a decoder conditioning on its full token prefix is the Sat = Ht choice, and in plain text generation nothing is hidden: the state is the prompt plus the tokens so far, and appending a token is deterministic, so generation is a fully observable MDP with a trivial, known transition (section 16 returns to why DP still cannot solve it).

2Markov process to MRP to MDP, and the return

The formal object DP solves is built in three steps, each adding one ingredient. The running example is David Silver's student chain (Silver, Lecture 2): the states Class 1, Class 2, Class 3, Pass, Pub, Facebook and Sleep, where Sleep is terminal. The diagram in section 3 draws all three.

1. Markov process (Markov chain) ⟨𝒮, P⟩: a memoryless random sequence of states S1, S2, ... with the Markov property, where 𝒮 is a finite set of states and P the state transition matrix, Pss′ = ℙ[St+1 = s′ | St = s], one row per current state and one column per successor, each row summing to 1. In the student chain, Class 1 goes to Class 2 or Facebook with probability 0.5 each; Class 2 goes to Class 3 with 0.8 or Sleep with 0.2; Class 3 goes to Pass with 0.6 or Pub with 0.4; Pass goes to Sleep with 1.0; Pub goes to Class 1, Class 2 or Class 3 with 0.2, 0.4 and 0.4; Facebook stays on Facebook with 0.9 and returns to Class 1 with 0.1.

2. Markov reward process (MRP) ⟨𝒮, P, R, γ⟩: a Markov chain with rewards. Rs = 𝔼[Rt+1 | St = s] is the expected reward for leaving state s, and γ ∈ [0, 1] the discount factor. In the student MRP each class gives −2, Facebook −1, Pub +1, Pass +10 and Sleep 0. An MRP defines a return and a value, but nobody decides anything.

3. Markov decision process (MDP) ⟨𝒮, 𝒜, P, R, γ⟩: an MRP with decisions. 𝒜 is a finite set of actions, and transitions and rewards now depend on the action:

Pass′ = ℙ[St+1 = s′ | St = s, At = a],    Ras = 𝔼[Rt+1 | St = s, At = a]
Pass′
the probability of landing in s′ after taking a in s; written P(s′ | s, a) elsewhere on this page
Ras
the expected immediate reward for taking a in s; written R(s, a)

You no longer drift between states at random: your action moves you, possibly stochastically. The only new ingredient is agency. In the student MDP, from Class 1 you choose Study (−2, to Class 2) or Facebook (−1, to Facebook); from Facebook, Facebook again (−1) or Quit (0, back to Class 1); from Class 2, Study (−2, to Class 3) or Sleep (0, the end); from Class 3, Study (+10, pass, the end) or Pub (+1, after which chance sends you to Class 1, Class 2 or Class 3 with 0.2, 0.4 and 0.4). Sutton and Barto write the dynamics as one joint distribution p(s′, r | s, a) rather than P and an expected R; they note the MDP literature usually uses the pair, and for DP the two are equivalent because only the expected reward enters the backups (Sutton and Barto, chapter 3 notes).

A policy is a distribution over actions given states, π(a | s) = ℙ[At = a | St = s]; a deterministic policy picks one action, written π(s). Fixing a policy turns an MDP back into an MRP:

Pπss′ = Σa π(a | s) Pass′,    Rπs = Σa π(a | s) Ras

Averaging over the policy's choices removes the agency, which is why evaluating a fixed policy is an MRP problem, and why policy evaluation (section 6) is linear.

The return and why to discount

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ... = Σk=0∞ γk Rt+k+1    and recursively    Gt = Rt+1 + γGt+1
Gt
the return: the total discounted reward from step t on; in an episodic task the sum stops at the terminal step
γ ∈ [0, 1]
a reward k + 1 steps ahead counts γk times as much as the same reward now; near 0 is myopic, near 1 far-sighted. The weights sum to 1/(1 − γ), so γ = 0.9 behaves like a horizon of about 10 steps and γ = 0.99 like 100 derived

The agent maximises cumulative reward, not immediate reward, so it can pay to sacrifice reward now: refuelling a helicopter costs time now but may prevent a crash hours later, and a financial investment may take months to mature (Silver, Lecture 1). Four reasons to discount, from Silver's second lecture:

  1. Cycles. It keeps returns finite in cyclic or never-ending processes (the student chain can loop on Facebook indefinitely).
  2. Uncertainty. The future is less certain than the present, and the model of it may be imperfect, so weight it less.
  3. Convenience. With γ < 1 the Bellman operators are contractions, so iterating them converges to a unique answer from any start: the reason DP converges (section 11).
  4. Preference. Human and animal behaviour prefers reward sooner, and immediate money can earn interest.

Undiscounted returns (γ = 1) are fine when every sequence is guaranteed to terminate; LLM RL typically uses γ = 1, because every response ends and the reward arrives at the end.

The return is a random variable. Start in Class 1 with γ = ½ and sample the episode Class 1, Class 2, Class 3, Pass, Sleep: the rewards for leaving each state are −2, −2, −2 and +10, so G1 = −2 + ½(−2) + ¼(−2) + ⅛(10) = −2 − 1 − 0.5 + 1.25 = −2.25. Another episode from the same start, Class 1, Facebook, Facebook, Class 1, Class 2, Sleep, gives −2 − ½ − ¼ − 2/8 − 2/16 = −3.125. The value function is the average over all such episodes. Averaging samples is what model-free methods do; DP computes the same average exactly from the model. The widget shows both.

3Value functions and the Bellman equations

The value function is the expected return, which removes the randomness of individual episodes. In an MRP, V(s) = 𝔼[Gt | St = s]. In an MDP the return depends on how you act, so values are defined for a policy π:

Vπ(s) = 𝔼π[Gt | St = s],    Qπ(s, a) = 𝔼π[Gt | St = s, At = a]
Vπ(s)
the state value: expected return from state s when following π
Qπ(s, a)
the action value: expected return from taking action a in s, then following π
𝔼π
an expectation over the randomness of both the policy and the environment

The two are one step apart:

Vπ(s) = Σa π(a | s) Qπ(s, a),    Qπ(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) Vπ(s′)
first
averages the action values under the policy
second
the one-step lookahead: the step that needs the model, P and R

That asymmetry is why Q is what you want for model-free control: acting greedily on Q is argmaxa Q(s, a), a lookup over actions, while acting greedily on V needs the lookahead and so the transition dynamics. DP has the model, so it works with V and computes Q when it needs it.

Optimal values. V*(s) = maxπ Vπ(s) is the best achievable expected return from s, and Q*(s, a) = maxπ Qπ(s, a). An MDP is solved once Q* is known, because the policy that picks argmaxa Q*(s, a) in every state is optimal. For any finite MDP there is an optimal policy π* at least as good as every other policy in every state, all optimal policies share V* and Q*, and there is always a deterministic one (Silver, Lecture 2).

Deriving the Bellman equation

The Bellman equation cuts a long-horizon problem into one-step pieces: the value of a state is the immediate reward plus the discounted value of the successor. It follows from the return's own recursion:

V(s) = 𝔼[Gt | St = s] = 𝔼[Rt+1 + γGt+1 | St = s] = 𝔼[Rt+1 + γV(St+1) | St = s]
last step
replaces the random tail Gt+1 by its expectation V(St+1), which the Markov property allows. For an MRP with known P and R it reads V(s) = Rs + γ Σs′ Pss′ V(s′), where Rs is the expected reward for leaving s, Pss′ the probability of moving to s′ and V(s′) each successor's value

The four equations

Bellman expectation equations, for a fixed policy π:

Vπ(s) = Σa π(a | s) [ R(s, a) + γ Σs′ P(s′ | s, a) Vπ(s′) ]
Qπ(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) Σa′ π(a′ | s′) Qπ(s′, a′)
s, a, s′
the current state, an action, a possible next state
a′
the action taken in the successor s′
bracket
the one-step lookahead value of action a

These are linear in the values: one equation per state, as many unknowns as states. In matrix form Vπ = Rπ + γPπVπ, with the direct solution

Vπ = (I − γPπ)−1 Rπ
Vπ, Rπ
column vectors with one entry per state
Pπ
the state-to-state transition matrix under π (the MRP of section 2)
I
the identity. Inversion costs O(n³) for n states, so the direct solution is only for small problems; large ones use iterative methods: DP, Monte Carlo, temporal-difference learning

Bellman optimality equations, for the optimal values:

V*(s) = maxa [ R(s, a) + γ Σs′ P(s′ | s, a) V*(s′) ]
Q*(s, a) = R(s, a) + γ Σs′ P(s′ | s, a) maxa′ Q*(s′, a′)

The max replaces the average under a policy. It makes the equations nonlinear, so in general there is no closed form: they are solved iteratively, by value iteration and policy iteration when the model is known (this page), and by Q-learning, and SARSA with exploration decaying to greedy, from samples when it is not (Model-free prediction and control). Everything downstream, from value iteration to DQN's TD target to the value model in PPO-based RLHF, is a way of approximately solving one of these equations. Four value functions, four Bellman equations, four DP updates: "little more than these equations turned into assignment statements" (Sutton and Barto §4.8).

Prediction and control, the two problems these equations pose. Prediction evaluates the future: given a fixed policy π, how much reward will it collect? Compute Vπ or Qπ. Control optimises the future: find an optimal policy π*, equivalently V* or Q*. You usually solve prediction to solve control: evaluate the current policy, improve it by acting greedily on its values, repeat. With a model, prediction is policy evaluation (section 6) and control is policy iteration (section 8) or value iteration (section 9).

4Where the equations and the algorithms come from

  • Hamilton and Jacobi to Bellman. "Optimal control" came into use in the late 1950s. One approach, developed in the mid-1950s by Richard Bellman and others, extended a nineteenth-century theory of Hamilton and Jacobi: it uses a dynamical system's state and a value function, or "optimal return function", to define a functional equation, now called the Bellman equation; the class of methods that solve it came to be known as dynamic programming (Sutton and Barto §1.7). Bellman called the optimality equation the "basic functional equation"; its continuous-time, continuous-state counterpart is the Hamilton–Jacobi–Bellman equation (Sutton and Barto, chapter 3 notes).
  • The name. "The term dynamic programming is due to Bellman (1957a)", the book Dynamic Programming (Sutton and Barto, chapter 4 notes). Bellman later wrote that he picked it in 1950 at RAND so that the work would not sound like mathematical research to the Secretary of Defense, Charles Wilson, who disliked the word: "dynamic" because it was "impossible to use ... in a pejorative sense", and "programming" in the military sense of planning schedules and logistics, as in linear programming, not writing code (Dreyfus 2002, Operations Research 50(1), reprinting the autobiography). Russell and Norvig point out that the story "cannot be strictly true": Bellman's first paper using the term (1952) predates Wilson's appointment in 1953 (quoted in Wikipedia, Dynamic programming: History). The phrase curse of dimensionality is Bellman's too.
  • MDPs and value iteration. Bellman also introduced the discrete stochastic version of the optimal control problem, Markov decision processes (Bellman 1957, "A Markovian Decision Process", J. Math. Mech. 6). Value iteration, the successive-approximation solution of his equation, is his; it predates policy iteration, though textbooks now present it as truncated policy iteration (the Method atlas tab of Topic: rl places it first among 47 methods).
  • Policy iteration. "The policy improvement theorem and the policy iteration algorithm are due to Bellman (1957a) and Howard (1960)", Ronald Howard's Dynamic Programming and Markov Processes. Modified policy iteration, which contains both policy and value iteration as special cases, is due to Puterman and Shin (1978); asynchronous DP to Bertsekas (1982, 1983), who called it distributed DP; and the contraction-mapping treatment of DP to Denardo (1967) (Sutton and Barto, chapter 3 and 4 notes).
  • DP meets RL. The first connection was a footnote by Minsky (1961) on Samuel's checkers player, which may have led AI researchers to think DP applied only to analytically tractable problems; Werbos (1977) proposed "heuristic dynamic programming"; Watkins (1989) called a class of RL methods "incremental dynamic programming" and made the most influential link between RL and MDPs, with Q-learning (same source).

5Backups, sweeps, synchronous and in place

Four words recur below (Sutton and Barto §4.1):

  • A backup (Sutton and Barto: an expected update) is one application of the right-hand side of a Bellman equation to one state, as an assignment. "Expected" because it averages over every possible successor with its probability, rather than one sampled successor: that is what a full-width backup means, and why it needs the model.
  • A sweep backs up every state once.
  • A synchronous sweep computes every new value from the previous sweep's values, so it keeps two arrays (old and new). It is also called Jacobi-style, after Jacobi's classical method for linear systems.
  • An in-place sweep overwrites values as it goes, so states later in the sweep already see this sweep's new values (Gauss–Seidel-style). It needs one array, usually converges faster, and then the order in which states are swept matters; Sutton and Barto "usually have the in-place version in mind" (chapter 4 notes). On the racetrack below (section 14), Gauss–Seidel value iteration was about twice as fast as the Jacobi version.

6Policy evaluation: the prediction problem

Estimate Vπ, the value function of a given, fixed policy, by turning the Bellman expectation equation into an update rule:

Vk+1(s) = Σa π(a | s) [ R(s, a) + γ Σs′ P(s′ | s, a) Vk(s′) ]
Vk
the estimate after k sweeps; Vk+1 the estimate after one more; every other symbol as in section 3
  1. Start with an arbitrary value function, usually all zeros. Terminal states have value 0 and stay there.
  2. For every state, look one step ahead: for each action the policy might take, the immediate reward plus the discounted value of each possible successor, weighted by its probability.
  3. Set the state's new value to the policy-weighted average of those lookahead values.
  4. Repeat the sweep until the largest change in any state, maxs |Vk+1(s) − Vk(s)|, falls below a small threshold θ.

Why it converges. Vπ is a fixed point of the update, and the backup is a γ-contraction (section 11), so the iteration converges to the unique Vπ from any start. Sutton and Barto's condition is wider: Vπ exists, is unique and is the limit "as long as either γ < 1 or eventual termination is guaranteed from all states under the policy π" (§4.1). With γ = 1 the contraction argument does not apply, and convergence needs every state to reach a terminal state eventually under π.

Or solve it directly. Because the equations are linear (section 3), Vπ = (I − γPπ)−1Rπ is one linear solve, of the order of n³ operations. Iterative policy evaluation is "a classical successive approximation algorithm for solving a system of linear equations" (Sutton and Barto, chapter 4 notes); it wins when n is large, when transitions are sparse (each sweep then costs about n times the number of successors), and when a good starting guess exists, as it does inside policy iteration.

The standard example is Sutton and Barto's 4 × 4 gridworld (Example 4.1): two shaded corners end the episode, every move costs −1, a move off the grid leaves you in place, γ = 1, and the policy picks each of the four moves with probability ¼. Its Vπ is minus the expected number of steps to a corner. The Sweep lab runs it sweep by sweep: the computed values reproduce Figure 4.1 independently, 92 of the 96 printed values at two significant digits. The other four are the exact value −1.75 at k = 2, printed −1.7 while the same figure prints −2.875 as −2.9: a rounding slip in the figure, not a different computation. Figure 4.1's numbers also require synchronous sweeps; an in-place sweep gives different intermediate values. The greedy policy on those values is optimal from k = 3 on, as the figure's caption says (book p. 77).

7Policy improvement and its theorem

Once you know Vπ, you can do better than π by acting greedily with respect to it. Compute the lookahead value Qπ(s, a) of every action (section 3) and pick the best:

π′(s) = argmaxa [ R(s, a) + γ Σs′ P(s′ | s, a) Vπ(s′) ] = argmaxa Qπ(s, a)
π′
the new, deterministic policy
argmaxa
returns the action with the largest bracket

The policy improvement theorem (Sutton and Barto §4.2): if deterministic policies π and π′ satisfy Qπ(s, π′(s)) ≥ Vπ(s) in every state, then Vπ′(s) ≥ Vπ(s) in every state, strictly wherever the premise is strict. The proof keeps expanding the Q side and reapplying the premise:

Vπ(s) ≤ Qπ(s, π′(s)) = 𝔼π′[Rt+1 + γVπ(St+1) | St = s] ≤ 𝔼π′[Rt+1 + γRt+2 + γ²Vπ(St+2) | St = s] ≤ ... ≤ 𝔼π′[Rt+1 + γRt+2 + γ²Rt+3 + ... | St = s] = Vπ′(s)

In words: taking the better action once and then following π is at least as good as following π, and doing the same at every later step only adds improvement. The greedy policy satisfies the premise automatically, because the best action's value is at least the policy-weighted average of all actions' values, which is Vπ(s). And if greedy improvement changes nothing, then Vπ(s) = maxa Qπ(s, a) in every state, which is exactly the Bellman optimality equation: π is already optimal. So policy improvement "must give us a strictly better policy except when the original policy is already optimal".

Stochastic policies and ties. The theorem carries over to stochastic policies. When several actions tie for the max, the new policy may split its probability among them in any way, as long as every non-maximising action gets zero. Figure 4.1's right column draws an arrow for every tied action for this reason. The student MDP in section 3 shows a full improvement in one step: greedy on the uniform policy's Qπ is already optimal.

8Policy iteration: control with an explicit policy

Alternate the two steps until the policy stops changing: evaluate the current policy, then improve it greedily. This yields a chain π0 → Vπ0 → π1 → Vπ1 → ... → π* → V*, each policy strictly better than the last unless already optimal (Sutton and Barto §4.3).

  1. Start with an arbitrary policy, for example uniformly random, and arbitrary values.
  2. Evaluate: run policy evaluation sweeps for the current policy until the values settle, or solve the linear system directly. Start each evaluation from the previous policy's values: this "typically results in a great increase in the speed of convergence of policy evaluation (presumably because the value function changes little from one policy to the next)".
  3. Improve: replace the policy with the greedy policy on those values.
  4. If the policy did not change, stop: it is optimal. Otherwise go back to step 2.

Why it terminates. A finite MDP has finitely many deterministic policies, mn for m actions and n states. Each improvement gives a policy at least as good everywhere and strictly better somewhere unless already optimal, so no policy repeats, and the loop must end at a policy satisfying the Bellman optimality equation. In practice it needs very few outer iterations, because the policy changes in whole jumps and often becomes optimal long before its values have converged: on Figure 4.1's gridworld it "would find the optimal policy after just one iteration", and on Jack's car rental (Example 4.2, two locations with up to 20 cars each, Poisson rentals and returns, γ = 0.9) the sequence π0, ..., π4 reaches the optimum in four improvements (Figure 4.2). On the Sweep lab's worlds it stops after 2 improvements on both 4 × 4 grids, 3 on the Dyna maze and 5 on Russell and Norvig's 4 × 3 world.

The tie bug
As written, the stopping test "the policy did not change" may never fire if ties in the argmax are broken arbitrarily: the policy can flip forever between equally good actions while the values stay put. Sutton and Barto leave this as Exercise 4.4 ("a subtle bug ... okay for pedagogy, but not for actual use"). Fix: keep the current action unless another is strictly better, or stop when the values stop changing. The Sweep lab keeps the current action among ties.

Evaluation does not have to converge. Stopping evaluation after k sweeps and improving anyway still converges to the optimal policy. This is modified policy iteration (Puterman and Shin 1978), which contains policy iteration (k → ∞) and value iteration (k = 1) as special cases. In Silver's 4 × 4 gridworld (Figure 4.1's) k = 3 evaluation sweeps were already enough for the greedy policy to be optimal (Silver, Lecture 3). One catch, found while building the old version of this page: with truncated evaluation, "the policy did not change" no longer proves optimality, because the values the policy was greedy on were not yet its own. Stop only when the policy is unchanged and the values have stopped changing.

Generalised policy iteration (GPI) is the general pattern: any interleaving of some evaluation with some improvement, at any granularity, down to a single state. "As long as both processes continue to update all states, the ultimate result is typically the same, convergence to the optimal value function and an optimal policy" (Sutton and Barto §4.6). The two processes compete (making the policy greedy makes the values wrong for it; making the values right makes the policy no longer greedy) and cooperate: both stabilise only when the policy is greedy with respect to its own value function, which is the Bellman optimality equation. "Almost all reinforcement learning methods are well described as GPI" (section 16).

9Value iteration: control with no explicit policy

Turn the Bellman optimality equation itself into the update, with no policy stored anywhere:

Vk+1(s) = maxa [ R(s, a) + γ Σs′ P(s′ | s, a) Vk(s′) ]
maxa
over every action available in s; Vk is the estimate after k sweeps
  1. Start with an arbitrary value function, usually all zeros.
  2. For every state, compute the lookahead value of every action and keep the best.
  3. Repeat until the largest change in a sweep falls below θ.
  4. Read off the policy once at the end, greedily: π(s) = argmaxa of the same bracket.

It looks like policy evaluation with one crucial difference: no policy is being followed; each sweep takes a max over all actions rather than an average under some π. Equivalently, each sweep is one evaluation sweep of the policy that is greedy on the current values, so value iteration is policy iteration with evaluation cut to a single sweep (Sutton and Barto §4.4). Silver's intuition: "start with final rewards and work backwards"; it "still works with loopy, stochastic MDPs". A consequence: the intermediate value functions need not be the value of any policy; only the limit is, and it is the optimal policy's (Silver, Lecture 3). Silver's shortest-path slide shows it: a 4 × 4 grid with one goal in the corner, −1 per step; synchronous value iteration from zeros gives V2 = −1 everywhere but the goal, V3 = −2 in most cells, and only V7 holds the true distances, 0 to −6 (reproduced exactly in the Sweep lab).

Formally value iteration converges only in the limit, but the greedy policy becomes optimal after finitely many sweeps (Bertsekas 1987, cited in Sutton and Barto's notes). Between the two extremes, "faster convergence is often achieved by interposing multiple policy evaluation sweeps between each policy improvement sweep" (§4.4): modified policy iteration again.

A worked showcase: the gambler's problem (Sutton and Barto Example 4.3). A gambler with capital 1 to 99 stakes any whole number of dollars up to what he has (and what he needs to reach 100) on a coin that comes up heads with probability ph; reaching 100 pays +1, everything else 0, γ = 1, so the value is the probability of winning. With ph = 0.4, value iteration's optimal policy is famously curious: at capital 50 bet everything, at 51 bet a little. It is optimal but not unique; a whole family of optimal policies corresponds to ties in the argmax. The Sweep lab runs it live for any ph.

10Worked example: a three-state corridor

Three states in a row, A, B and C, with a terminal goal G to the right of C. Two actions, left and right, both deterministic. Moving right from C enters G, earns a reward of 10 and ends the episode; every other move earns 0; moving left from A bumps into the wall and stays in A. The discount is γ = 0.9 and V(G) = 0 always.

Value iteration, synchronous, from all zeros. The backups are V(A) ← max(0.9 V(A), 0.9 V(B)), V(B) ← max(0.9 V(A), 0.9 V(C)) and V(C) ← max(0.9 V(B), 10 + 0.9 × 0).

Policy iteration, from the uniformly random policy (left and right with probability 0.5 each). Evaluation backups: V(A) ← 0.45 V(A) + 0.45 V(B), V(B) ← 0.45 V(A) + 0.45 V(C) and V(C) ← 0.45 V(B) + 5, where 0.45 is 0.5 × 0.9 and 5 is 0.5 × 10. Right wins everywhere, so one improvement already gives the optimal policy. Evaluating it gives (8.1, 9, 10), the next improvement changes nothing, and policy iteration stops after two outer iterations.

Evaluation did not need to converge: after only three sweeps, with values (1.0125, 2.25, 6.0125), the greedy comparison is already right everywhere (in A, right is 0.9 × 2.25 = 2.025 against left 0.9 × 1.0125 = 0.91; in B, 5.41 against 0.91; in C, 10 against 2.025). That is modified policy iteration paying off.

11Why it converges, and how fast

Measure the distance between two value functions u and v by the largest difference in any state, ‖u − v‖∞ = maxs |u(s) − v(s)|. Write T for one full synchronous sweep of backups, either the expectation backup for a fixed π or the optimality backup. Both are γ-contractions (Silver, Lecture 3):

‖Tu − Tv‖∞ ≤ γ ‖u − v‖∞
Tu
the value function after applying one sweep to u
why
for the expectation backup, the rewards cancel and what is left is γ times an average of differences, which is at most γ times the largest difference; for the optimality backup, |maxa f(a) − maxa g(a)| ≤ maxa |f(a) − g(a)| finishes the argument

One sweep brings any two value functions at least a factor γ closer. By the contraction mapping theorem (Banach's fixed-point theorem), repeated sweeps converge to a unique fixed point (Vπ or V*) from any start, at a linear rate. Since the true values are a fixed point, TV* = V*, the error after k sweeps obeys

‖Vk − V*‖∞ ≤ γk ‖V0 − V*‖∞   ⇒   k ≥ ln(1/ε) / ln(1/γ) sweeps cut the error by 1/ε
V0
the starting guess; Vk the estimate after k sweeps
ε
the factor by which you want the initial error shrunk

With γ = 0.9, cutting the error by a factor of 1,000 takes 66 sweeps (0.966 ≈ 0.00096); with γ = 0.99 it takes 688 derived. Since ln(1/γ) ≈ 1 − γ, the sweep count grows like the effective horizon 1/(1 − γ): rewards that far away still matter, and each sweep reaches one step further. Szepesvári's lecture notes give the standard form: k ≥ ln(1/(ε(1 − γ)))/(1 − γ) iterations bring value iteration within ε of V* (RL Theory, lecture 3).

A small change is not a small error. If one sweep changes no value by more than θ, the contraction gives ‖Vk+1 − V*‖∞ ≤ γθ/(1 − γ). With γ = 0.99 and θ = 0.001 the values can still be off by up to 0.099, about a hundred times the last change. A small error is a small loss, though: acting greedily on any V with ‖V − V*‖∞ ≤ ε loses at most 2γε/(1 − γ) of return in any state (Singh and Yee 1994, in the form given by RL Theory, lecture 3).

Without discounting. At γ = 1 there is no contraction, yet Figure 4.1, Silver's shortest path and Russell and Norvig's 4 × 3 world all use γ = 1 and converge. What saves them is termination: if every policy evaluated eventually reaches a terminal state (a "proper" policy), the sweeps still converge, a stochastic-shortest-path result outside this page's scope (Bertsekas and Tsitsiklis 1996). Drop that and an undiscounted evaluation of a policy that loops forever on a −1 reward runs off to −∞.

Both converge to the same V* and π*. "Both policy iteration and value iteration are widely used, and it is not clear which, if either, is better in general" (Sutton and Barto §4.7). Policy iteration wins when evaluation is cheap (few actions, or an affordable linear solve) and value iteration when each state has many actions or the policy would change many times; modified policy iteration, with a handful of evaluation sweeps per improvement, sits between them and is often the practical choice. Counting model look-ups in the Sweep lab makes the trade concrete: to reach an error of 10−4 on the 4 × 4 grids, policy iteration needs about 60 to 80 times as many look-ups as value iteration, most of them spent evaluating the starting random policy at γ = 1, while modified policy iteration with three sweeps comes within a factor of 1.6 of value iteration; on the 4 × 3 world it beats value iteration (1,581 look-ups against 2,112).

13Cost, scale and the linear-programming view

One sweep backs up every state, and each backup looks at every action and every possible successor. With n states and m actions a sweep over state values costs O(mn²); a sweep over action values Q(s, a) costs O(m²n²), because there are mn entries and each backup looks at mn successor pairs (Silver, Lecture 3). Those are dense worst cases: in a gridworld each action has at most three successors, so a sweep costs about 3mn look-ups, which is what the Sweep lab counts derived. These are full-width backups: every successor and every action considered, using the known model.

DP is exponentially faster than searching policies. "In the worst case, the time that DP methods take to find an optimal policy is polynomial in the number of states and actions", although there are mn deterministic policies; direct search would have to examine each one to give the same guarantee (Sutton and Barto §4.7). In practice DP handles millions of states (Silver; Sutton and Barto) and "usually converge[s] much faster than [its] theoretical worst-case run times, particularly if [started] with good initial value functions or policies".

The curse of dimensionality is the catch: the number of states grows exponentially with the number of state variables. Ten variables with ten values each already make ten billion states, and at that size even one backup can be too expensive. Backgammon has over 1020 states; Sutton and Barto note that at a million backups a second one sweep would take "over a thousand years" (§4.5), which is an understatement: 1020/106 seconds is about 3.2 million years derived. Sutton and Barto add that large state sets are "inherent difficulties of the problem, not of DP as a solution method": DP copes with them better than direct search or linear programming.

The linear-programming view, in brief. V* is the smallest function that satisfies every one-step inequality, so it solves a linear program: minimise Σs c(s) V(s) subject to V(s) ≥ R(s, a) + γ Σs′ P(s′ | s, a) V(s′) for every state and action, with any positive weights c; n variables and nm constraints. Its dual has one variable per state-action pair, the discounted occupancy measure (how often the policy visits each pair), and the optimal policy read from it does not depend on the weights (Mahajan, Stochastic control notes, linear programming, written for costs, so the inequalities flip). Solving the LP with an off-the-shelf solver returns exactly the V* that value iteration converges to on the 4 × 3 world (9 variables, 36 constraints), Figure 4.1's grid and the Dyna maze derived, checked in src/recompute.py. Linear programming can have better worst-case guarantees than DP, but "become[s] impractical at a much smaller number of states than do DP methods (by a factor of about 100)" (§4.7); the dual view returns in constrained MDPs and offline RL, where occupancy measures are the natural variable, and de Farias and Van Roy built approximate DP on it (de Farias and Van Roy 2003).

14Asynchronous DP: in place, prioritised, real time

Asynchronous DP backs up states in any order rather than in systematic sweeps, "using whatever values of other states happen to be available"; some states may be updated several times before others once. It converges "given only that all states occur in the sequence {sk} an infinite number of times" for 0 ≤ γ < 1; the order can even be random (Sutton and Barto §4.5). It does not necessarily mean less computation: it means never getting "locked into any hopelessly long sweep before it can make progress", and freedom to choose which states to back up (Silver, Lecture 3; Bertsekas 1982, 1983):

  • In-place DP: one array, each backup immediately visible to the next. The corridor converges in one sweep with the right order (section 10). In the Sweep lab's Dyna maze, in-place value iteration in reverse reading order reaches an error of 10−4 with a third of the look-ups synchronous sweeps need (920 against 2,760).
  • Prioritised sweeping: back up the state with the largest Bellman error, |maxa(R + γΣPV) − V(s)|, kept in a priority queue; after each backup update the priorities of the affected states, which needs the reverse dynamics (predecessor states). Developed independently by Moore and Atkeson and by Peng and Williams in 1993 (Sutton and Barto §8.4 and notes), it solved a rod-manoeuvring task with 14,400 potential states that is "probably too large to be solved with unprioritized methods". The Sweep lab runs a model-known version that pushes γ × P(s | p, a) × |change| onto each predecessor p: on the Dyna maze it needs 965 look-ups against 2,760 for synchronous sweeps.
  • Real-time DP (RTDP): back up only the states an agent actually visits, with the agent acting greedily on the current values, so computation goes where experience goes. On Sutton and Barto's racetrack (9,115 reachable states, only 599 relevant), Gauss–Seidel value iteration converged in 28 sweeps and 252,784 updates; RTDP needed 127,600 updates over 4,000 episodes, about half, and left about 290 states never updated, with both policies averaging 14 to 15 steps (Sutton and Barto §8.7, Example 8.6; Barto, Bradtke and Singh 1995).

The Sweep lab races all of these on the same world with the same budget of model look-ups.

15Beyond DP: drop the model, drop the table

Past millions of states, either the model has to go or the table has to go. Sample backups replace the full sum over successors with one sampled transition ⟨S, A, R, S′⟩: they need no model, and the cost of a backup becomes "constant, independent of n", which "breaks the curse of dimensionality through sampling" (Silver, Lecture 3). That is Model-free prediction and control: Q-learning is the sampled form of value iteration, and the TD target is the sampled form of the evaluation backup. Approximate DP replaces the table with a function approximator and backs up only sampled states, as in fitted value iteration, which leads to DQN on Value-based deep RL.

One world, two ways to get its values: sweep the model, or learn from samples

Russell and Norvig's 4 × 3 world (AIMA, Figure 17.1; the book's code): each move goes where intended with probability 0.8 and sideways with 0.1 each; bumping a wall stays put; every step costs 0.04; the two exits pay +1 and −1; γ = 1. Value iteration converges on exactly the utilities printed in AIMA's Figure 17.3 (0.812, 0.868, 0.918 on the top row; 0.762 and 0.660 in the middle; 0.705, 0.655, 0.611, 0.388 on the bottom), reproduced independently. The Q-learning agent never sees the 0.8 and 0.1: it starts each episode in a random cell, behaves ε-greedily (ε = 0.3), updates Q(s, a) toward −0.04 + maxa′ Q(s′, a′) with step 1/N(s, a)0.8, and shows maxa Q. What the comparison shows. Value iteration reaches AIMA's values in about 20 sweeps, each touching all 9 states with 4 actions and 3 outcomes, and it never moves the agent. Q-learning gets within a few hundredths of the same numbers only after thousands of episodes and tens of thousands of transitions, and its rarely visited cells (bottom right, next to the −1) lag longest. That is the trade: the model buys exactness and speed; samples buy independence from the model. 16How it connects, and why it still matters for LLM work

  • Up the tree: Topic: rl places DP as planning with a known model, the exact form of the expectation every other family estimates; its Method atlas and Taxonomy tabs place value and policy iteration on every axis.
  • Generalised policy iteration is the shape of nearly every RL algorithm, including PPO for RLHF: the critic update is approximate policy evaluation and the policy-gradient step is approximate policy improvement (Policy gradients and actor-critic). AlphaZero is GPI with Monte Carlo tree search as the improvement operator (Model-based RL and planning).
  • The one-step backup is the template for every target: V(s) ← r + γV(s′) is a DP backup with the expectation over successors replaced by one sample. It is the TD target (Model-free prediction and control), and Q-learning is the sampled form of value iteration. DQN regresses a network onto the same target (Value-based deep RL), and GAE (generalised advantage estimation) is built from the TD errors r + γV(s′) − V(s) that the critic in PPO produces (RL for LLMs).
  • Token generation is an MDP with a trivial, known transition (append the token), so the model DP needs is available; what makes DP impossible there is the size of the state space, every possible prefix, which is why LLM RL samples instead (RL for LLMs). The RL stage of post-training is on Alignment: SFT, RLHF, DPO family, RLVR.
  • Offline RL reuses the occupancy-measure view of section 13 and the danger of acting greedily on values the data never checked (Offline RL and imitation); bandits are the one-state MDP where planning is trivial and only exploration is left (Bandits and exploration).

Common mistakes and misconceptions

Calling DP learning.
It never interacts with an environment; it computes from a model it is given. Without the model you need the sampling methods on Model-free prediction and control.
Acting greedily on V without a model.
The greedy step needs the one-step lookahead, which needs P and R. A model-free agent that stores only V cannot pick actions from it; model-free control uses Q(s, a) precisely so that the greedy step becomes a plain argmax.
Treating the optimality equation as linear.
Matrix inversion solves the expectation equation for a fixed policy, not the optimality equation, whose max needs iteration (or a linear program with one inequality per action).
Putting the action being chosen into the history.
Ht ends at Ot, Rt; the agent chooses At from it, and the reward for At is Rt+1.
Reading value iteration's intermediate values as a policy's value.
Before convergence they may belong to no policy (section 9).
Trusting a small last change.
A last change of θ can hide an error of up to γθ/(1 − γ), a hundred times θ at γ = 0.99 (section 11).
Letting policy iteration flip between equally good actions.
If ties in the argmax are broken arbitrarily, "the policy did not change" may never be true even though the values have stopped improving. Break ties consistently (keep the current action unless another is strictly better) or stop when the values stop changing (Sutton and Barto, Exercise 4.4).
Assuming full evaluation is required before improving.
A few sweeps are usually enough; one sweep is value iteration (section 8).
Stopping modified policy iteration on an unchanged policy alone.
After a truncated evaluation the values are not yet the policy's own, so an unchanged greedy policy can still be suboptimal; also require the values to have converged.
Using γ = 1 carelessly.
Without discounting the contraction argument is gone, and evaluation converges only if every policy you evaluate eventually reaches a terminal state (section 11). It is not always wrong: it is standard when every episode terminates, as in LLM RL.
Blaming the curse of dimensionality on DP.
Large state sets are "inherent difficulties of the problem, not of DP as a solution method"; DP still beats direct policy search and linear programming at scale (section 13).
Treating DP as obsolete.
Its structure, evaluate then improve, and its backup, reward plus discounted next value, are inside every modern RL algorithm (section 16).

    How the lab works

    Methods. Policy evaluation runs on the uniform random policy (Figure 4.1's). Policy iteration starts from the uniform random policy, evaluates it until no value moves by more than θ, then improves greedily, keeping the current action when it is among the tied best (so it cannot flip between equally good policies), and stops when no action changes. Modified policy iteration does exactly 3 evaluation sweeps per improvement and stops when the policy is unchanged and the last sweep moved nothing by more than θ. Value iteration and policy evaluation run synchronously (two arrays, as Figure 4.1 requires) or in place, in reading order or reversed. Prioritised sweeping is the model-known form: every state's Bellman error is computed once, then the state with the largest priority is backed up, and γ × P(s | p, a) × |change| (the largest over p's actions) is added to each predecessor p's priority, an upper bound on how much its Bellman error can have grown; it stops when no priority exceeds 10−12.

Each backup costs one look-up per (action, successor) pair it reads; an improvement step reads every action of every state; prioritised sweeping pays one more look-up per predecessor update.
