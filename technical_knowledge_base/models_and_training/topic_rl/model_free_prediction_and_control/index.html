Model-free prediction and control in one screen

Model-free reinforcement learning learns values and policies from experience alone: the agent never sees the transition probabilities or the reward function, it only acts and observes what happens. Every method on this page answers one question: when the expectation over next states that dynamic programming computes from a model is unavailable, what do you replace it with?

Rows are clickable. Two ideas carry the page. First, Monte Carlo and TD are the two ends of one bias-variance dial, and n-step returns and TD(λ) are the settings in between. It matters beyond tabular RL because the modern targets are these ones: DQN regresses a network onto the Q-learning target, PPO's critic learns a TD target and its advantage estimator is a TD(λ) average, and GRPO's single end-of-sequence reward is a Monte Carlo return (section Where this goes next). Model-free against model-based, and the words this page uses

The power of model-free RL: you do not need a model of the environment or any understanding of its dynamics. You sample from it (interact with it) and work out the optimal policy from experience. This also covers the case where a model exists but is too big to use except by sampling, such as the game of Go (Silver, Lecture 5 slides), and the case where the model is known but its probabilities are hard to write down: Sutton and Barto's blackjack has fully known rules, yet "it is not easy to determine" the probability of each outcome for DP, while generating sample games is easy (§5.1). The price: you only learn about states you actually visit, which creates the exploration problem of section Control.

Dynamic programming computes values from a known model with full-width backups: every state, every action, every successor weighted by its probability. Model-free methods use sample backups: one sampled transition (TD) or one sampled episode (MC) stands in for the expectation, so the cost of an update no longer depends on the number of states, and no model is needed.

The vocabulary is owned by Topic: rl (its Reading tab, sections "The loop, the state and the return" and "The one idea"); the parts this page uses:

  • An episode is one run from a start state to a terminal state: S0, A0, R1, S1, A1, R2, ..., ST, where St is the state at time t, At the action taken there, Rt+1 the reward that follows it, and T the time step at which the episode terminates.
  • The return from time t is Gt = Rt+1 + γRt+2 + ... + γT−t−1RT, the discounted sum of the rewards still to come, with discount factor γ ∈ [0, 1].
  • The state value Vπ(s) = Eπ[Gt | St = s] is the expected return from s following policy π; the action value Qπ(s, a) is the expected return after taking a in s and following π afterwards. V(s) and Q(s, a) without a subscript are the agent's current estimates, stored in a table with one entry per state or state-action pair.
  • Prediction estimates Vπ or Qπ for a fixed policy; control finds a good policy.
  • An update moves an estimate towards a target by a step size α ∈ (0, 1]: new estimate = old estimate + α (target − old estimate). The methods on this page differ only in the target.
  • Bootstrapping: the target contains an existing estimate. Sampling: the target uses sampled transitions instead of an expectation computed from a model. DP bootstraps without sampling, MC samples without bootstrapping, TD does both (Silver, Lecture 4 slides).
  • On-policy methods learn about the policy that generates the data; off-policy methods learn about a target policy π from data generated by a different behaviour policy (μ in Silver's slides, b in Sutton and Barto's book; this page uses b for importance sampling and μ elsewhere, as its sources do).

Monte Carlo prediction

Core idea: follow the policy for complete episodes and average the returns that actually followed each state. The value is literally the mean return, so by the law of large numbers the estimate converges to Vπ(s) as the number of visits grows (Silver, Lecture 4 slides).

  1. Run an episode with policy π until it terminates.
  2. Walk backwards through it computing each return, Gt = Rt+1 + γGt+1 with GT = 0.
  3. For each visited state, move its estimate towards the return that followed it.

First-visit MC uses only the first visit to a state in each episode; every-visit MC uses every visit. Both converge. First-visit returns are independent, identically distributed samples of Vπ(s), so each average is unbiased and its error's standard deviation falls as 1/√n in the number of returns n; every-visit MC is harder to analyse (several returns from one episode are correlated, and its estimate is biased for a finite number of episodes), but it also converges, and it "extends more naturally to function approximation and eligibility traces" (Sutton and Barto, §5.1; the comparison is Singh and Sutton 1996, who also tie first-visit MC to replacing traces and every-visit MC to accumulating ones).

The running average can be kept incrementally, because a mean satisfies μk = μk−1 + (1/k)(xk − μk−1), where μk is the mean of the first k samples x1, ..., xk. Replacing 1/k by a constant step size gives constant-α MC, which forgets old episodes and so tracks a changing (non-stationary) problem:

V(St) ← V(St) + α ( Gt − V(St) )
V(St)
the current estimate for the state visited at time t
Gt

α

Gt − V(St)

Properties:

  • Unbiased: Gt is a sample of exactly the quantity Vπ(St) is the expectation of.
  • High variance: Gt depends on every random action, transition and reward until the end of the episode.
  • Needs episodes that terminate: the target is unknown until the episode ends, so MC only applies to episodic tasks and learns nothing mid-episode.
  • No bootstrapping: the estimate of one state does not build on the estimate of any other, so the cost of estimating one state does not depend on the number of states; you can generate episodes from the states you care about and ignore the rest (Sutton and Barto, §5.1).
  • It does not rely on the Markov property, so it copes better when the state does not capture everything that matters (Silver, Lecture 4 slides).

History: the term "Monte Carlo" dates from the 1940s at Los Alamos; an early use to estimate action values in RL was Michie and Chambers (1968), who averaged episode durations in pole balancing, "similar in spirit to Monte Carlo ES with every-visit MC estimates"; Monte Carlo ES itself first appeared in the 1998 edition of Sutton and Barto (chapter 5 notes). The parent page's Method atlas dates the family the same way.

Temporal-difference (TD) learning

Core idea: do not wait for the real return. After one step, you know one real reward and where you landed, and you already have an estimate of how good that place is. Use reward plus discounted estimate as the target. TD "updates a guess towards a guess" (Silver, Lecture 4 slides). The method and the name are from Sutton (1988).

V(St) ← V(St) + α ( Rt+1 + γV(St+1) − V(St) )
Rt+1
the reward received on the step from St to St+1
γV(St+1)
the discounted current estimate of the next state (0 if St+1 is terminal)
Rt+1 + γV(St+1)
the TD target
δt
= Rt+1 + γV(St+1) − V(St), the TD error, the surprise on this step
α
the step size

This is TD(0), the one-step case. Compare it with the DP backup for policy evaluation, V(s) ← Eπ[Rt+1 + γV(St+1) | St = s]: TD is the same backup with the expectation replaced by one sample and a step of size α towards it.

Properties (Silver, Lecture 4 slides):

  • Online and incomplete episodes: it learns after every step, so it works on continuing (non-terminating) tasks.
  • Biased: the target leans on V(St+1), which may be wrong. The ideal target Rt+1 + γVπ(St+1) would be unbiased; the one actually used is not, and TD is more sensitive to the initial values than MC.
  • Low variance: the target depends on one random action, transition and reward, not on a whole episode.
  • Usually more sample-efficient than MC, because it exploits the Markov property.
  • Convergence. For a fixed policy, tabular TD(0) converges to Vπ: in the mean for a constant step size that is small enough (Sutton 1988), and with probability 1 when the step sizes decrease so that Σn αn = ∞ and Σn αn2 < ∞ (Dayan 1992; Sutton and Barto, §6.2 and equation 2.7). With a linear function approximator, on-policy TD(0) still converges, to the "TD fixed point" (§9.4); with non-linear approximators or off-policy data it can diverge, which is where Value-based deep RL picks up the story (the deadly triad).

Worked example: MC and TD on one random-walk episode

The standard test problem is the five-state random walk (Sutton and Barto, Example 6.2). States A, B, C, D, E sit in a row. Every episode starts in C and moves left or right with probability 0.5 each; it ends when it steps off either end. Stepping off the right end earns a reward of 1; every other reward is 0, and there is no discounting (γ = 1). So the true value of a state is the probability of finishing on the right: Vπ = (1/6, 2/6, 3/6, 4/6, 5/6) for A to E. All estimates start at 0.5, and α = 0.1.

Episode: C → D → E → off the right end, rewards 0, 0, 1.

TD(0) updates after every step

  • C → D: δ = 0 + 0.5 − 0.5 = 0, so V(C) stays 0.5.
  • D → E: δ = 0 + 0.5 − 0.5 = 0, so V(D) stays 0.5.
  • E → end: δ = 1 + 0 − 0.5 = 0.5, so V(E) becomes 0.5 + 0.1 × 0.5 = 0.55.

MC waits for the end

Every visited state had return G = 1 (the final reward, undiscounted), so V(C), V(D) and V(E) each become 0.5 + 0.1 × (1 − 0.5) = 0.55.

MC moved three states, all by the full surprise; TD moved only the last one. TD's information travels backwards one state per episode: next time the walk passes D → E, D's target will be 0 + 0.55 and D will rise to 0.505. MC credits the whole path at once, but each credit carries the full randomness of where that particular walk happened to end. Measured as the root-mean-square error against the true values, averaged over the five states and over 100 runs, TD was consistently better than MC on this task across the step sizes Sutton and Barto compared (Example 6.2). The TD or Monte Carlo tab replays these walks step by step through both methods, starting with this kind of episode, and reruns the book's 100-run comparison live: every TD curve stays below every MC curve.

Batch MC against batch TD: what each converges to

Given a fixed batch of experience replayed until convergence, the two methods converge to different answers (Sutton and Barto, Example 6.4; Silver, Lecture 4 slides). Eight episodes, no discounting: one episode A, 0, B, 0 (start in A, reward 0 on the move to B, then reward 0 on terminating); six episodes B, 1; one episode B, 0.

  • Both agree V(B) = 6/8 = 0.75.
  • Batch MC gives V(A) = 0: A was seen once and its return was 0. This is the minimum squared error fit to the observed returns.
  • Batch TD gives V(A) = 0.75: A always led to B, and B is worth 0.75. This is the value under the maximum-likelihood Markov model of the data (certainty equivalence), and if the process really is Markov it predicts future data better. The optimality of batch TD(0) is from Sutton (1988).

On the random walk the same thing shows as Figure 6.2: under batch training TD beats MC at every episode count, although batch MC is optimal on the data it has seen. The TD or Monte Carlo tab computes both batch answers exactly (sample means for MC, the certainty-equivalence model solved by Gaussian elimination for TD).

MC against TD, intuitively

Silver's driving analogy (Lecture 4): you are driving, a car swerves at you, you nearly crash but do not, and the episode ends fine. Monte Carlo only sees the final return, so the near-death moment leaves no trace: the episode ended well, so every state gets credited with a good outcome. TD updates online from the next state's value: the moment the crash looks imminent, the value estimate plunges, and the preceding states are immediately updated toward that plunge. TD propagates the "that was almost a disaster" signal; MC misses it.

The dial between them: n-step returns and TD(λ)

Between one step and the whole episode lie the n-step returns: take n real rewards, then bootstrap (Sutton and Barto, §7.1).

Gt(n) = Rt+1 + γRt+2 + ... + γn−1Rt+n + γnV(St+n)
Gt(n)
the n-step return from time t (the book writes Gt:t+n)
V(St+n)
the estimate of the state reached after n steps. If the episode ends before step t + n, the return is just the rewards up to the end.

n = 1 is the TD(0) target; n = ∞ (in practice, the end of the episode) is the Monte Carlo return. n-step TD updates V(St) towards Gt(n), which it can only do n steps later. Its guarantee is the error-reduction property: the worst error of the expected n-step return is at most γn times the worst error of V (§7.1, equation 7.3), so each extra real reward shrinks the bias the estimate can pass on.

TD(λ) averages all n-step returns with geometrically decaying weights, the λ-return (the forward view is due to Watkins 1989; TD(λ) itself to Sutton 1988):

Gtλ = (1 − λ) Σn=1∞ λn−1 Gt(n)
λ ∈ [0, 1]
sets how fast the weights decay; (1 − λ) makes them sum to 1. In an episode ending at time T, every n-step return with n ≥ T − t equals the full return Gt, so their weights collect into one lump: (1 − λ)λn−1 for each n < T − t and λT−t−1 on Gt itself.

The endpoints recover the two pure methods (Silver, Lecture 4 slides): λ = 0 puts all the weight on Gt(1), one-step TD; λ = 1 puts all of it on Gt, Monte Carlo. So MC and TD are two ends of a single bias-variance dial: more real rewards in the target means less bias and more variance.

Each TD error is broadcast back to recently visited states in proportion to their traces. With λ = 0 only the current state is updated (TD(0)); with λ = 1 and updates applied at the end of the episode, the total update equals the MC update exactly, because the discounted sum of TD errors telescopes into Gt − V(St) (Silver, Lecture 4 slides). Online, TD(1) is "a way of implementing Monte Carlo algorithms that is more general": it also applies to discounted continuing tasks and learns during the episode (§12.2).

  • Three kinds of trace. The accumulating trace above adds 1 on every visit. The replacing trace resets it to 1 instead, so a state revisited in a loop never builds a trace above 1 (Singh and Sutton 1996). The dutch trace is the one that makes the online backward view exactly equal to the online λ-return with linear approximation: true online TD(λ) (van Seijen and Sutton 2014; §12.5). Sutton and Barto now see replacing traces as "crude approximations to dutch traces, which largely supersede them" (§12.6).
  • Ordinary TD(λ) is only approximately the λ-return when it updates during the episode. The n-step and TD(λ) tab shows the gap: on the 19-state walk the two agree closely below the best step size and part ways above it, where TD(λ) with λ ≥ 0.9 diverges (Figure 12.6).
  • Which setting wins. On the 19-state walk an intermediate value is best: n = 4 or λ = 0.8 in the live rerun, with error rising toward both ends (Figures 7.2 and 12.3). The more an update relies on actual returns, the smaller the step size it tolerates.

In deep RL the same dial reappears as generalised advantage estimation (GAE; Schulman et al. 2015), a λ-weighted sum of TD errors used as the advantage in actor-critic methods, Ât = Σl≥0 (γλ)l δt+l, worked through on Policy gradients and actor-critic.

Model-free control: making evaluation and improvement work from samples

Control follows the same two-phase loop as DP policy iteration, evaluate then improve, known as generalised policy iteration (GPI; Sutton and Barto, §5.3). Done with Monte Carlo evaluation, both phases break when you only sample:

  • Evaluation is no longer guaranteed to cover every state: DP sweeps all states; sampling only touches the states your trajectories visit.
  • Greedy improvement is no longer guaranteed to help, because the values it is greedy over may be wrong for unvisited actions: this is the exploration against exploitation problem showing up in the algorithm itself.

Two standard fixes:

  1. Use Q(s, a), not V(s), for evaluation. Acting greedily on V needs a model to know where each action leads, π′(s) = argmaxa [R(s, a) + γ Σs′ P(s′ | s, a) V(s′)]; acting greedily on Q is just π′(s) = argmaxa Q(s, a) over actions you have estimates for.
  2. Keep exploring, either by starting episodes from every state-action pair (exploring starts) or by keeping the policy soft (ε-greedy).

Exploring starts: Monte Carlo ES

If every episode starts from a randomly chosen state-action pair, with every pair possible, then every pair is visited infinitely often however greedy the policy is. Monte Carlo ES alternates evaluation and improvement episode by episode: after each episode, average the returns that followed each first visit of a pair into Q, then make the policy greedy at the states visited (§5.3, box). On blackjack it finds a policy that matches Thorp's (1966) basic strategy except for one notch in the usable-ace policy, which the authors are "confident" is optimal for their version of the game (Example 5.3, Figure 5.2). It cannot settle on a suboptimal policy, since that policy's values would make it change; but "convergence to this optimal fixed point ... has not yet been formally proved", which Sutton and Barto call "one of the most fundamental open theoretical questions in reinforcement learning" (partial solution: Tsitsiklis 2002). Exploring starts are easy in a simulator and rarely possible when learning from real interaction.

Soft policies: ε-greedy

ε-greedy exploration: with probability 1 − ε take the greedy action, otherwise an action chosen uniformly at random from all m actions, so the greedy action has probability 1 − ε + ε/m and every other action ε/m. It is the simplest ε-soft policy (every action has probability at least ε/m); bandit-style alternatives such as UCB and optimistic starts are on Bandits and exploration. Every action keeps a non-zero probability, and the ε-greedy policy with respect to Qπ is guaranteed to be at least as good as the ε-soft policy π it came from, so improvement still works (Silver, Lecture 5 slides; the proof is equation 5.2 of §5.4: the ε-greedy policy's value is a weighted average that puts the 1 − ε mass on the largest Q). The catch: policy iteration over ε-soft policies finds only the best ε-soft policy, not the best policy.

Exploration therefore has to fade for the policy to become optimal. A schedule is GLIE (greedy in the limit with infinite exploration) when every state-action pair is visited infinitely often and the policy converges to the greedy policy; ε-greedy with εk = 1/k on the k-th episode is GLIE.

GLIE Monte Carlo control: sample the k-th episode with the current ε-greedy policy; for each visited pair increment the count N(St, At) and update Q(St, At) ← Q(St, At) + (1/N(St, At))(Gt − Q(St, At)); then set ε ← 1/k and make the policy ε-greedy on the new Q. It converges to the optimal action values, Q(s, a) → Q*(s, a) (Silver, Lecture 5 slides).

SARSA (on-policy TD control)

Replace MC by TD in the control loop: lower variance, online, works on incomplete episodes. Evaluate Q with a TD update after every step, and improve by acting ε-greedily on the latest Q. The update uses the quintuple (S, A, R, S′, A′), hence the name:

Q(S, A) ← Q(S, A) + α ( R + γQ(S′, A′) − Q(S, A) )
S, A
the current state and the action taken in it
R, S′
the reward received and the next state
A′
the action the agent actually takes next, chosen ε-greedily from Q(S′, ·)
Q(S′, A′)
0 if S′ is terminal
α, γ
the step size and the discount

The loop, per episode:

  1. Start in S and choose A ε-greedily from Q.
  2. Take A; observe R and S′.
  3. Choose A′ ε-greedily from Q in S′.
  4. Update Q(S, A) with the rule above.
  5. Set S ← S′, A ← A′ and repeat from step 2 until S is terminal.

Because A′ comes from the same ε-greedy policy that is acting, SARSA learns the value of the policy it is executing, exploration included: on-policy, model-free, TD control. It converges to Q* with probability 1 if the policies are GLIE and the step sizes αt satisfy the Robbins-Monro conditions Σt αt = ∞ and Σt αt2 < ∞: big enough in total to overcome any initial values, shrinking fast enough for the noise to average out (Silver, Lecture 5 slides; Sutton and Barto, §6.4; the proof is Singh, Jaakkola, Littman and Szepesvári 2000). Those step-size conditions are for theory: Sutton and Barto note they "are seldom used in applications and empirical research", where a constant α is the norm (§2.5). With ε held fixed SARSA instead settles on a policy that is good given that it keeps exploring, which is exactly what the cliff example below shows.

History: SARSA came after Q-learning, not before. Rummery and Niranjan introduced it in 1994 as "Modified Connectionist Q-learning"; the name "Sarsa" is from Sutton (1996) (chapter 6 notes; the parent page's Method atlas records the same correction).

Three variants use the same machinery:

  • n-step SARSA targets Rt+1 + ... + γn−1Rt+n + γnQ(St+n, At+n) (§7.2); SARSA(λ) averages those with λ-weights and keeps one eligibility trace per state-action pair (§12.7). Both move along the MC-TD dial exactly as TD(λ) does. On a gridworld with a single reward at the goal, one episode of one-step SARSA strengthens only the last action before the goal, while n-step SARSA strengthens the last n (Figure 7.4 of the book).
  • Expected SARSA replaces the sampled Q(S′, A′) with its expectation under the policy, Σa′ π(a′ | S′) Q(S′, a′), which removes the variance due to the random choice of A′ (§6.6). On the deterministic cliff it "can safely set α = 1 without suffering any degradation of asymptotic performance, whereas Sarsa can only perform well in the long run at a small value of α" (Figure 6.3, adapted from van Seijen, van Hasselt, Whiteson and Wiering 2009; the algorithm goes back to George John, 1994). With a greedy target policy and an exploratory behaviour it is exactly Q-learning, so it "subsumes and generalizes Q-learning while reliably improving over Sarsa", at a small extra cost per step. In the Cliff walking tab's live rerun, Expected SARSA averages −20.8 per episode over episodes 401 to 500, against SARSA's −27.4 and Q-learning's −50.3 (100 runs, α = 0.5 assumed).

Q-learning (off-policy TD control)

Same shape, but the bootstrap uses the best next action rather than the one actually taken (Watkins 1989, whose convergence outline was made rigorous by Watkins and Dayan 1992):

Q(S, A) ← Q(S, A) + α ( R + γ maxa′ Q(S′, a′) − Q(S, A) )
maxa′ Q(S′, a′)
the largest current estimate over all actions in S′ (0 if S′ is terminal); every other symbol is as for SARSA

The agent still behaves ε-greedily (the behaviour policy μ), but the target evaluates the greedy policy π(S′) = argmaxa′ Q(S′, a′) (the target policy). Learning about π from experience generated by μ is what makes it off-policy. No importance-sampling correction is needed, because the target does not use the action μ chose next; the policy only decides which pairs get updated (Silver, Lecture 5 slides). The same property is what lets DQN learn from a replay buffer of old experience.

Classification: off-policy, model-free, TD control. It is the sampled, model-free counterpart of value iteration (the max in the target is the Bellman optimality backup), and it is the direct ancestor of DQN (Value-based deep RL). All it needs to converge to Q* with probability 1 is that every state-action pair keeps being updated, plus "a variant of the usual stochastic approximation conditions" on the step sizes (Sutton and Barto, §6.5; more general proofs: Jaakkola, Jordan and Singh 1994, Tsitsiklis 1994); ε does not have to decay for the values to converge, although it does for the behaviour to become optimal.

Worked example: one transition, two targets

illustrative The agent is in S next to a cliff, took A = right, and got R = −1, with γ = 1, α = 0.5 and Q(S, right) = −5. In the next state S′, Q(S′, right) = −4 is the best action and Q(S′, down) = −100 steps into the cliff. The ε-greedy policy happened to pick the exploratory A′ = down.

  • SARSA uses the action taken: target = −1 + (−100) = −101; new Q(S, right) = −5 + 0.5 × (−101 − (−5)) = −53.
  • Q-learning uses the best action: target = −1 + (−4) = −5; new Q(S, right) = −5 + 0.5 × (−5 − (−5)) = −5, unchanged.

Cliff walking: SARSA against Q-learning

The standard demonstration is Sutton and Barto's cliff-walking gridworld (Example 6.6): a 4 by 12 grid, with the start in the bottom-left corner and the goal in the bottom-right corner (Gymnasium, Cliff Walking). The ten cells between them along the bottom row are the cliff. Actions are up, down, left and right; every step costs −1, stepping into the cliff costs −100 and sends the agent back to the start, and the task is undiscounted. Both methods act ε-greedily with ε = 0.1.

  • The optimal path runs along the edge of the cliff: one step up, eleven right, one down, 13 steps and a return of −13. Q-learning learns the values of this path, because its target assumes greedy behaviour.
  • But the agent is not greedy. On each of the ten cells along the edge, the random 10% of actions picks "down" a quarter of the time, a probability of 0.1/4 = 0.025 per step of falling in. The chance of one pass along the edge without a fall is 0.97510 ≈ 0.776, so about 22% of passes fall at least once, and Q-learning's online return is poor derived. Exactly, acting ε-greedily around the edge path is worth −50.80 per episode (policy evaluation on the known grid, in the Cliff walking tab), which is what Q-learning's simulated average converges to.
  • SARSA learns a longer path through the upper part of the grid, because its values include its own exploratory stumbles, and it collects more reward per episode than Q-learning while ε stays at 0.1: −27.4 against −50.3 per episode over episodes 401 to 500 in the live rerun (100 runs; the book does not state α, 0.5 is assumed).
  • If ε were gradually reduced, both would converge to the optimal edge path.

Which path SARSA learns
The parent page's overview says SARSA learns "a safer path one row up". The live rerun finds something more specific: after 500 episodes SARSA's greedy path is a 17-step route that climbs to the top row (the shortest such route: up 3, right 11, down 3) in 73 of 100 runs, 19 or 21 steps in 11, and in 16 its greedy moves loop through rarely visited cells; the route one row above the edge (15 steps) never appears. Q-learning's greedy path is the 13-step edge path in all 100 runs. The book's own wording is "the longer but safer path through the upper part of the grid".

Which is "right" depends on the question. Q-learning answers "what is optimal if I stop exploring?"; SARSA answers "what is best given that I will keep exploring like this?". For a robot that must explore on real hardware, SARSA's answer is the safer one.

Maximisation bias and Double Q-learning

Taking a max over noisy estimates is biased upwards: if several actions all have true value 0 but their estimates scatter above and below 0, the max of the estimates is positive. With 10 such actions and unit noise the expected max is 1.539 derived (the expected maximum of 10 standard normals). Q-learning uses that max as its target, and an ε-greedy SARSA uses it implicitly through the greedy part of its policy (Sutton and Barto, §6.7). The bias propagates: every state that leads to the noisy one inherits the optimism.

The cause is using the same samples both to pick the maximising action and to estimate its value. Double learning splits them: learn two independent estimates Q1 and Q2, choose with one and value with the other, Q2(argmaxa Q1(a)), which is unbiased in the sense that its expectation is the true value of the chosen action. Double Q-learning (van Hasselt 2010) flips a coin on each step and updates one table:

Q1(S, A) ← Q1(S, A) + α ( R + γQ2(S′, argmaxa Q1(S′, a)) − Q1(S, A) )
Q1, Q2
two tables, treated symmetrically: on tails the same update runs with their roles swapped
behaviour
ε-greedy on Q1 + Q2

It doubles the memory but not the computation per step. Sutton and Barto's Example 6.7 makes the bias cost reward: from state A, "left" leads to a state B whose many actions each pay a reward with mean −0.1, so left is always a mistake, yet Q-learning "initially learns to take the left action much more often than the right action", while Double Q-learning "is essentially unaffected" (Figure 6.5). The Maximisation bias tab reruns it with 10,000 runs and animates one run, showing B's noisy estimates and the max that Q-learning bootstraps from. Double DQN is the same idea with the two networks DQN already has (van Hasselt, Guez and Silver 2015; on Value-based deep RL).

Off-policy learning and importance sampling

On-policy learning ("learn on the job") learns about π from experience sampled from π. Off-policy learning ("look over someone's shoulder") learns about a target policy π from experience sampled from a different behaviour policy b. It is useful for learning from human demonstrations or other agents, reusing data from old policies, learning a greedy target while behaving exploratorily, and learning about several policies from one stream of behaviour (Silver, Lecture 5). It needs coverage: every action π might take must have a non-zero probability under b (Sutton and Barto, §5.5).

The general correction is importance sampling: weight each return by how much more or less likely the target policy was to produce that trajectory. The environment's transition probabilities appear in both and cancel, so the ratio needs only the two policies:

ρt:T−1 = ∏k=tT−1 π(Ak | Sk) / b(Ak | Sk),    Eb[ρt:T−1 Gt | St = s] = vπ(s)
ρ
the importance-sampling ratio of the rest of the episode (equations 5.3 and 5.4)
  • Ordinary importance sampling averages the scaled returns, V(s) = Σ ρG / (number of returns). Its first-visit version is unbiased, but its variance is in general unbounded.
  • Weighted importance sampling divides by the sum of the ratios instead, V(s) = Σ ρG / Σ ρ. It is biased (after one return it simply equals that return), with the bias falling to zero as returns accumulate, and its variance is bounded: with bounded returns it goes to zero "even if the variance of the ratios themselves is infinite" (Precup, Sutton and Dasgupta 2001). "In practice, the weighted estimator usually has dramatically lower variance and is strongly preferred" (§5.5). Every-visit versions of both are biased, with the bias vanishing asymptotically.
  • Example: the behaviour policy took an action with probability 0.25 that the target policy would take with probability 0.5, so the sample counts double (ρ = 2); an action the target policy never takes gets weight 0, and so does the whole rest of the trajectory before it.

Two of the book's examples make this concrete, and the Importance sampling tab reruns both. On one blackjack state evaluated from random play (Example 5.4), the weighted estimator's error is far lower over the first episodes and both errors approach zero by 10,000 episodes; the state's value, −0.27726 in the book from 100 million simulated games, is −0.27720 computed exactly derived. On a one-state MDP whose target policy loops (Example 5.5), the scaled returns have expectation 1 and infinite variance, E[(ρG)2] = 0.2 Σj≥0 1.8j = ∞, and ten runs of ordinary importance sampling are still scattered after millions of episodes, while the weighted estimate is exactly 1 from the first episode consistent with π.

Incremental and control versions

  • Weighted importance sampling, incrementally: keep a cumulative weight C per pair; for each new return with weight W, C ← C + W and Q ← Q + (W/C)(G − Q) (equations 5.7 and 5.8, §5.6). With π = b every W is 1 and this is the ordinary running mean.
  • Off-policy Monte Carlo control makes the target greedy and the behaviour soft, walks each episode backwards, and stops at the first action that is not greedy, since from there on π would have weight 0 (§5.7). The catch, in the book's words: "this method learns only from the tails of episodes"; if non-greedy actions are common, learning is slow. TD methods are the usual remedy.
  • Off-policy n-step methods multiply the ratios of the actions inside the n-step window (n-step SARSA uses ρt+1:t+n, which starts and ends one step later than n-step TD's ρt:t+n−1, because the first action is already given; §7.3). The tree-backup algorithm avoids ratios altogether by taking expectations over the actions not taken at each step; its one-step case is Expected SARSA (§7.5); Watkins's Q(λ) instead cuts its traces at the first exploratory action (§12.10). Deep RL's safe multi-step corrections, such as Retrace, which truncates the ratios at 1, descend from these (Munos et al. 2016).
  • One-step Q-learning and Expected SARSA need no ratio, because their targets average or maximise over the next action instead of using the one b chose.

The same ratio, clipped, is the heart of PPO and GRPO: their rollouts come from a slightly stale copy of the policy, and an inference engine whose probabilities differ slightly from the trainer's, so language-model RL is mildly off-policy and corrects for it per token (RL for LLMs; Policy gradients and actor-critic).

DP and TD: the same backups, sampled

Each TD control method is a sampled version of a DP method on Q, with x ←α y meaning x ← x + α(y − x) (Silver, Lecture 5 slides):

Bellman equationFull backup (DP, needs the model)Sample backup (TD, model-free)
Expectation equation for VIterative policy evaluation: V(s) ← E[R + γV(S′) | s]TD learning: V(S) ←α R + γV(S′)
Expectation equation for QQ-policy iteration: Q(s, a) ← E[R + γQ(S′, A′) | s, a]SARSA: Q(S, A) ←α R + γQ(S′, A′)
Optimality equation for QQ-value iteration: Q(s, a) ← E[R + γ maxa′ Q(S′, a′) | s, a]Q-learning: Q(S, A) ←α R + γ maxa′ Q(S′, a′)

Silver's "unified view" adds the two other corners: a backup that is full-width and goes to the end of the episode is exhaustive search; one that is sampled and goes to the end is Monte Carlo. Expected SARSA sits between the two columns, sampling the next state but not the next action.

Trade-offs and when to use which

  • MC or TD for prediction. TD when the task is continuing, episodes are long, or the state is close to Markov: lower variance and learning mid-episode usually win. MC when episodes are short, the state is only partially observed (MC does not rely on the Markov property), or when you will use a function approximator and need the more robust convergence. An intermediate n or λ is often better than either end.
  • SARSA or Q-learning for control. Q-learning when you want the optimal greedy policy and mistakes during learning are cheap (a simulator), or when learning from old or someone else's data. SARSA when the exploring agent's own performance during learning matters, because it optimises the policy it actually runs. Expected SARSA is a low-variance compromise and becomes Q-learning when its target policy is greedy; it tolerates larger step sizes.
  • Maximisation bias. When the rewards or transitions are noisy and many actions compete, consider Double Q-learning (or Double DQN with networks).
  • Off-policy Monte Carlo. Prefer weighted importance sampling; expect slow learning when the target and behaviour policies differ often.
  • The step size α. Larger α learns faster and fluctuates more around the answer; a constant α never settles exactly but tracks a changing problem. TD with a large constant α can even get worse after a while (the TD or Monte Carlo tab: α = 0.15 bottoms out and rises, Exercise 6.5).
  • ε. More exploration finds better actions and costs reward while learning; decay it (GLIE) when the final policy should be greedy.
  • Tables. Every method here stores one number per state or state-action pair and learns nothing about a state it has not visited; that stops working as soon as the state space is large or continuous.

Common mistakes and misconceptions

"TD is always better than MC."
It usually is on Markov tasks with a table, but it is biased, depends more on the initial values, and can diverge with non-linear function approximation or off-policy data where MC does not.
Thinking MC and TD converge to the same thing on finite data.
On a fixed batch MC fits the observed returns and TD solves the maximum-likelihood Markov model: V(A) = 0 against 0.75 in the AB example.
Acting greedily on V without a model.
The greedy step over V needs the transition model; model-free control learns Q so that the greedy step is a plain argmax.
Choosing SARSA's A′ twice.
SARSA's A′ must be the action actually executed next. If you compute A′ for the update and then pick a different action to execute, you have built something that is neither SARSA nor Q-learning.
"Q-learning is off-policy, so it needs importance sampling."
One-step Q-learning does not: its target never uses the behaviour policy's next action. Off-policy MC and off-policy n-step methods do need importance ratios, and those multiply along the trajectory and can blow up the variance (infinitely, in Example 5.5).
"On-policy means online, off-policy means offline."
Q-learning is off-policy while learning online; the distinction is which policy the values describe. Learning from a fixed dataset with no interaction is offline RL, a different problem (Offline RL and imitation).
Reading Q-learning's values as the return you will get.
They are the returns of the greedy policy; while ε-greedy exploration continues, the actual return is lower, as on the cliff (−50.8 expected, against −13 for the greedy path).
Forgetting maximisation bias.
The max over noisy estimates overestimates; Double Q-learning fixes it.
Bootstrapping from a terminal state.
V(S′) and Q(S′, ·) are 0 at a terminal state; bootstrapping from a stale estimate there leaks value past the end of the episode.
"SARSA is the older method and Q-learning improved on it."
The other way round: Q-learning is from 1989, SARSA from 1994, introduced as a modification of Q-learning.
"Weighted importance sampling is unbiased because it is normalised."
It is the ordinary (first-visit) estimator that is unbiased; the weighted one is biased, with the bias vanishing as returns accumulate. Its advantage is variance.
"The Robbins-Monro conditions are how you set α in practice."
They are what the convergence proofs need; practice mostly uses a constant α, which never fully converges but tracks change.

Where this goes next

Everything above stores Q as a table, which dies with large or continuous state spaces. Replacing the table with a neural network, plus the tricks needed to make that stable (a replay buffer, which Q-learning's off-policy target makes legitimate, and a frozen target network), is Value-based deep RL. There, DQN regresses a network onto the Q-learning target, Double DQN applies the double-learning fix above, and n-step targets return as one of Rainbow's components. Actor-critic methods learn a critic with TD targets (Policy gradients and actor-critic). Dyna mixes Q-learning on real experience with Q-learning on simulated experience from a learned model (Model-based RL and planning).

The MC-against-TD dial also reappears in language-model RL (RL for LLMs: RLHF, GRPO, RLVR). GRPO's single end-of-sequence reward, compared against the mean of a sampled group, is a Monte Carlo return: unbiased, no value model, high variance. PPO with a value model uses generalised advantage estimation (GAE), a λ-weighted average of the TD errors r + γV(s′) − V(s) from its critic, so it sits partway along the TD(λ) dial, with its own λ choosing the bias-variance trade-off.

Up the tree, Topic: rl places these methods on its axes: all four are model-free and value-based; SARSA is on-policy and Q-learning off-policy; Monte Carlo does not bootstrap and TD does.

        The bias in one picture

        Take a state where every action is worth exactly 0, and estimates that are each unbiased but noisy. The largest estimate is, on average, above 0: whichever action happened to get lucky wins the max. The fix splits the job: one set of estimates chooses the action, an independent second set values it, and the second set's value of the first set's choice is unbiased.

            When ordinary importance sampling never settles

            Example 5.5 and Figure 5.4 (book p. 106 to 108)

            One non-terminal state s and two actions. Right ends the episode with reward 0. Left returns to s with probability 0.9 (reward 0) or ends with reward +1 with probability 0.1. The target policy always goes left, so vπ(s) = 1. The behaviour policy goes left or right with probability ½. An episode that ever goes right has ρ = 0; one that goes left k times and then ends has ρ = 2k and G = 1. Every scaled return has expectation 1, yet its variance is infinite:

            E[(ρG)2] = Σk≥1 (½)k 0.9k−1 0.1 · (2k)2 = 0.2 Σj≥0 1.8j = ∞
            k
            the number of left actions in the episode (the last one ends it)
            (½)k 0.9k−1 0.1
            the probability of that episode under the behaviour policy
            Ten independent runs of first-visit Monte Carlo with ordinary importance sampling (episodes on a log scale)

            The book runs to 100 million episodes; 10 million is the most this page offers on a phone. Weighted importance sampling is drawn dashed: it is exactly 1 from the first episode that follows the target policy, because only returns consistent with π get any weight, and all of them are 1.
