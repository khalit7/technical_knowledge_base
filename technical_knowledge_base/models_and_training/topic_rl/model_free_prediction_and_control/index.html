The idea in one screen

Without a model you cannot compute dynamic programming's expectation over next states, so you replace it with a sample: the whole return (Monte Carlo), or one real reward plus your own estimate of where you landed (TD). Every method on this page is one choice of that target: how many real rewards before it trusts an estimate (a bias-variance dial), and which next action it assumes (the one taken: on-policy; the best one: off-policy).

Two choices define every target: how far it looks, and which next action it trusts

Left: one trajectory; each bracket is a target for V(St). Real rewards (solid) are unbiased and noisy; the bootstrapped estimate at the bracket's end is low-noise and possibly wrong. Right: at the next state S′, SARSA trusts the action the agent actually takes, Expected SARSA the policy's average, Q-learning the best action, whatever the agent does.

1Monte Carlo and TD prediction: wait for the return, or trust the next estimate

The test problem is the five-state random walk (Sutton and Barto, Example 6.2): states A to E in a row, every episode starts in C and steps left or right with probability 0.5 until it falls off an end; falling off the right pays 1, every other reward is 0, γ = 1. So the true value of a state is its chance of ending on the right, Vπ = (1/6, 2/6, 3/6, 4/6, 5/6). Estimates start at 0.5; α = 0.1. One episode: C → D → E → off the right end, rewards 0, 0, 1.

TD(0) updates after every step

  • C → D: δ = 0 + 0.5 − 0.5 = 0, so V(C) stays 0.5.
  • D → E: δ = 0 + 0.5 − 0.5 = 0, so V(D) stays 0.5.
  • E → end: δ = 1 + 0 − 0.5 = 0.5, so V(E) becomes 0.5 + 0.1 × 0.5 = 0.55.

Monte Carlo waits for the end

Every visited state had return G = 1, so V(C), V(D) and V(E) each become 0.5 + 0.1 × (1 − 0.5) = 0.55.

MC moved three states by the full surprise; TD moved one. TD's information travels back one state per episode (next time the walk passes D → E, D's target is 0 + 0.55 and D rises to 0.505), but each TD target carries one step of randomness, while each MC credit carries the whole walk's luck. As updates:

TD is DP's policy-evaluation backup, V(s) ← Eπ[R + γV(S′) | s], with the expectation replaced by one sample and a step of size α towards it: it "updates a guess towards a guess" (Silver, Lecture 4).

    Batch MC and batch TD converge to different answers on the same data (Example 6.4). Eight episodes: A, 0, B, 0 once; B, 1 six times; B, 0 once. Both give V(B) = 6/8 = 0.75. Batch MC gives V(A) = 0, the only return seen from A; batch TD gives V(A) = 0.75, because A always led to B. TD's answer is the value under the maximum-likelihood Markov model of the data (certainty equivalence), which predicts future data better if the process is Markov (the optimality of batch TD(0) is from Sutton 1988); that is why batch TD beats batch MC on the walk (switch the chart to Batch). Silver's version: you nearly crash and the episode ends fine; MC credits every state with the good ending, TD marks down the states before the moment the crash looked certain.

    Monte Carlo details: first against every visit, why model-free, history (depth)

    First-visit MC uses only the first visit to a state in each episode; every-visit MC uses all of them. First-visit returns are independent, identically distributed samples of Vπ(s), so each average is unbiased and its standard error falls as 1/√n; every-visit returns from one episode are correlated and its estimate is biased for a finite number of episodes, but it also converges and "extends more naturally to function approximation and eligibility traces" (Sutton and Barto, §5.1; Singh and Sutton 1996 compare the two and tie first-visit MC to replacing traces, every-visit to accumulating ones). The incremental form follows from μk = μk−1 + (1/k)(xk − μk−1).

    Because MC does not bootstrap, the cost of estimating one state does not depend on the number of states: generate episodes from the states you care about and ignore the rest (§5.1). Model-free methods also apply when a model exists but is only usable by sampling (Go, Silver, Lecture 5), or when its probabilities are hard to write down: blackjack's rules are fully known, yet "it is not easy to determine" each outcome's probability for DP, while sample games are easy (§5.1). The price is the exploration problem of section 3: you learn only about states you visit. DP's full-width backups touch every successor; model-free sample backups cost the same whatever the number of states.

    History: "Monte Carlo" dates from the 1940s at Los Alamos; an early RL use was Michie and Chambers (1968), who averaged episode durations in pole balancing, "similar in spirit to Monte Carlo ES with every-visit MC estimates"; Monte Carlo ES first appeared in the 1998 edition of the book (chapter 5 notes).

      Error reduction, and the three kinds of trace (depth)

      Error-reduction property: the worst error of the expected n-step return is at most γn times the worst error of V (§7.1, equation 7.3), so each extra real reward shrinks the bias the estimate can pass on. n-step TD updates V(St) only n steps later.

      Traces. The accumulating trace adds 1 on every visit. The replacing trace resets it to 1, so a state revisited in a loop never builds a trace above 1 (Singh and Sutton 1996). The dutch trace makes the online backward view exactly equal to the online λ-return with linear approximation: true online TD(λ) (van Seijen and Sutton 2014; §12.5). Sutton and Barto now see replacing traces as "crude approximations to dutch traces, which largely supersede them" (§12.6).

      3Control from samples: learn Q, and keep exploring

      Control runs DP's loop, evaluate then improve (generalised policy iteration, §5.3; taught on Dynamic programming), and sampling breaks both halves. Improvement greedy on V needs the model, π′(s) = argmaxa [R(s, a) + γ Σs′ P(s′ | s, a) V(s′)], so model-free control learns Q(s, a), where greedy is a plain argmax. And evaluation only covers what the agent visits, so a greedy policy can lock onto a wrong action it never retries: the policy must keep exploring.

      ε-greedy: with probability 1 − ε the greedy action, otherwise one of the m actions uniformly, so the greedy action has probability 1 − ε + ε/m and every other ε/m. The ε-greedy policy with respect to Qπ is at least as good as any ε-soft π (every action at least ε/m), because its value puts the 1 − ε mass on the largest Q (§5.4, equation 5.2). The catch: improvement then finds only the best ε-soft policy. For the optimum, exploration must fade: a schedule is GLIE (greedy in the limit with infinite exploration) when every pair is visited infinitely often and the policy converges to greedy; εk = 1/k on the k-th episode is GLIE (Silver, Lecture 5).

      Monte Carlo control: exploring starts, GLIE MC control, blackjack (depth)

      Monte Carlo ES starts every episode from a random state-action pair, every pair possible, so all pairs are visited however greedy the policy is; after each episode it averages the returns that followed each first visit into Q and makes the policy greedy at the visited states (§5.3, box). On blackjack it finds a policy matching Thorp's (1966) basic strategy except one notch in the usable-ace policy, which the authors are "confident" is optimal for their version (Example 5.3, Figure 5.2). It cannot settle on a suboptimal policy, but "convergence to this optimal fixed point ... has not yet been formally proved", "one of the most fundamental open theoretical questions in reinforcement learning" (partial solution: Tsitsiklis 2002). Exploring starts are easy in a simulator and rarely possible with real interaction.

      GLIE Monte Carlo control: sample the k-th episode with the ε-greedy policy; for each visited pair increment N(St, At) and move Q(St, At) by (1/N)(Gt − Q); set ε ← 1/k. It converges to Q* (Silver, Lecture 5).

      4SARSA, Expected SARSA and Q-learning: which next action the target assumes

      Put TD in the control loop: update Q after every step, act ε-greedily on the latest Q. One transition shows the whole difference. illustrative The agent is in S beside a cliff, took A = right, got R = −1; γ = 1, α = 0.5, Q(S, right) = −5. In S′, Q(S′, right) = −4 is best and Q(S′, down) = −100 steps into the cliff; exploration happened to pick A′ = down.

      • SARSA uses the action taken: target −1 + (−100) = −101, new Q(S, right) = −5 + 0.5 × (−101 + 5) = −53.
      • Q-learning uses the best action: target −1 + (−4) = −5, so Q(S, right) stays −5.

      SARSA's value of "right, beside the cliff" absorbs the risk that its own exploration stumbles in; Q-learning's assumes greedy behaviour from S′ on. Change the numbers (the two other actions in S′ are −5 and −6, for Expected SARSA's average):

      SARSA learns the value of the policy it runs, exploration included: on-policy TD control. Q-learning (Watkins 1989; proof Watkins and Dayan 1992) behaves ε-greedily (the behaviour policy) but its target evaluates the greedy policy (the target policy): off-policy, and needing no importance ratio, because the target never uses the action the behaviour chose next; behaviour only decides which pairs get updated. That is what lets DQN learn from a replay buffer. Its max is the Bellman optimality backup, so it is sampled value iteration. Expected SARSA removes the variance of the random A′ and, with a greedy target policy, is exactly Q-learning (§6.6).

      What the rerun checks, and which path SARSA learns (live numbers, a correction)
        Which path SARSA learns
        The parent page's overview said SARSA learns "a safer path one row up". After 500 episodes SARSA's greedy path is a 17-step route that climbs to the top row (up 3, right 11, down 3) in 73 of 100 runs, 19 or 21 steps in 11, and in 16 its greedy moves loop through rarely visited cells; the 15-step route one row above the edge never appears. Q-learning's greedy path is the 13-step edge path in all 100 runs. The book's wording is "the longer but safer path through the upper part of the grid".

        Which is "right" depends on the question. Q-learning answers "what is optimal if I stop exploring?"; SARSA "what is best given that I keep exploring like this?". For a robot exploring on real hardware, SARSA's answer is the safer one; Q-learning's values are not the return you will get while exploration continues (−50.8 expected, against −13 for the greedy path).

        Convergence conditions, Expected SARSA at α = 1, n-step SARSA and SARSA(λ), history (depth)

        SARSA converges to Q* with probability 1 under GLIE policies and Robbins-Monro step sizes, Σt αt = ∞ and Σt αt2 < ∞: big enough in total to overcome any initial values, shrinking fast enough for the noise to average out (§6.4; proof Singh, Jaakkola, Littman and Szepesvári 2000). Those conditions are for proofs: they "are seldom used in applications and empirical research", where a constant α is the norm and never fully settles but tracks change (§2.5). With ε fixed, SARSA settles on the best policy given that it keeps exploring.

        Q-learning needs only that every pair keeps being updated, plus "a variant of the usual stochastic approximation conditions" on the step sizes (§6.5; general proofs Jaakkola, Jordan and Singh 1994, Tsitsiklis 1994); ε need not decay for the values to converge, only for the behaviour to become optimal.

        Expected SARSA on the deterministic cliff "can safely set α = 1 without suffering any degradation of asymptotic performance, whereas Sarsa can only perform well in the long run at a small value of α" (Figure 6.3, from van Seijen, van Hasselt, Whiteson and Wiering 2009); it "subsumes and generalizes Q-learning while reliably improving over Sarsa", at a small extra cost per step.

        n-step SARSA targets Rt+1 + ... + γn−1Rt+n + γnQ(St+n, At+n) (§7.2); SARSA(λ) keeps one trace per state-action pair (§12.7). On a gridworld with one reward at the goal, an episode of one-step SARSA strengthens only the last action before the goal, n-step SARSA the last n (Figure 7.4). Expected SARSA goes back to George John (1994).

        History: SARSA came after Q-learning. Rummery and Niranjan introduced it in 1994 as "Modified Connectionist Q-learning"; the name "Sarsa" is from Sutton (1996) (chapter 6 notes).

        5Maximisation bias and Double Q-learning

        A max over noisy estimates is biased upwards. If 10 actions are all truly worth 0 and each estimate carries unit noise, the expected largest estimate is 1.539 derived: whichever got lucky wins. Q-learning's target is that max, and an ε-greedy SARSA uses it through the greedy part of its policy; the optimism flows back into every state that leads there (§6.7). The cause is using the same samples to pick the action and to value it. Double learning keeps two independent estimates and values one's choice with the other, Q2(argmaxa Q1(a)), whose expectation is the true value of the chosen action.

          6Off-policy Monte Carlo: importance sampling

          Off-policy learning learns about a target policy π from data of a behaviour policy b: from demonstrations or other agents, from old policies' data, a greedy target while behaving exploratorily, several policies from one stream (Silver, Lecture 5). It needs coverage: every action π might take has non-zero probability under b (§5.5). Q-learning gets away without a correction; a Monte Carlo return does not, because the whole rest of the episode followed b's choices. The correction weights each return by how much more likely π was to produce it; the transition probabilities appear in both policies' trajectory probabilities and cancel. Concretely: if b took an action with probability 0.25 that π takes with probability 0.5, the sample counts double (ρ = 2); an action π never takes gives weight 0 to the whole return from before it.

          ρt:T−1 = ∏k=tT−1 π(Ak | Sk) / b(Ak | Sk),   Eb[ρt:T−1 Gt | St = s] = vπ(s);   ordinary V = Σ ρG / n,   weighted V = Σ ρG / Σ ρ
          ordinary
          first-visit version unbiased, variance in general unbounded
          weighted
          biased (after one return it equals that return), the bias falling to zero; with bounded returns its variance goes to zero "even if the variance of the ratios themselves is infinite" (Precup, Sutton and Dasgupta 2001). "In practice, the weighted estimator usually has dramatically lower variance and is strongly preferred" (§5.5). Every-visit versions of both are biased, the bias vanishing asymptotically. Normalising is what makes it biased, not unbiased.

              Incremental weighted IS, off-policy MC control, n-step ratios, tree backup, Retrace (depth)
              • Incrementally: keep a cumulative weight C per pair; for each new return with weight W, C ← C + W and Q ← Q + (W/C)(G − Q) (equations 5.7 and 5.8, §5.6). With π = b every W is 1 and this is the running mean.
              • Off-policy MC control makes the target greedy and the behaviour soft, walks each episode backwards and stops at the first non-greedy action, where π's weight becomes 0 (§5.7). "This method learns only from the tails of episodes": slow if non-greedy actions are common. TD is the usual remedy.
              • Off-policy n-step methods multiply the ratios inside the window: n-step SARSA uses ρt+1:t+n, one step later than n-step TD's ρt:t+n−1, because the first action is given (§7.3). Tree backup avoids ratios by taking expectations over the actions not taken; its one-step case is Expected SARSA (§7.5). Watkins's Q(λ) cuts its traces at the first exploratory action (§12.10). Deep RL's Retrace truncates the ratios at 1 (Munos et al. 2016).

              The same ratio, clipped, is the heart of PPO and GRPO: their rollouts come from a slightly stale copy of the policy and from an inference engine whose probabilities differ slightly from the trainer's, so language-model RL is mildly off-policy and corrects per token (RL for LLMs; Policy gradients and actor-critic).

              7Beyond tables: function approximation and the deadly triad

              Every method so far stores one number per state or state-action pair and learns nothing about a state it has not visited, which fails as soon as the state space is large or continuous. Replace the table with v̂(s, w) and move the weights along the gradient of the estimate, treating the target as fixed: semi-gradient TD(0), w ← w + α [R + γv̂(S′, w) − v̂(S, w)] ∇v̂(S, w) (§9.3). Monte Carlo with the same update is true gradient descent on squared error; TD is not, because its target moves with w. With linear features and on-policy data it still converges, to the TD fixed point, whose error is at most 1/(1 − γ) times the best the features allow (§9.4, equation 9.14): a factor of 100 at γ = 0.99 derived.

              Correction to the old page
              The old page's table said TD with function approximation "not always" converges, without the condition. Linear on-policy semi-gradient TD(0) provably converges, to the TD fixed point above; the failures need non-linear approximation or off-policy updates.

              The failure has a name. The deadly triad is function approximation (generalising across states), bootstrapping (targets built from current estimates, as in TD and DP) and off-policy training (updates on a distribution other than the target policy's): "If any two elements of the deadly triad are present, but not all three, then instability can be avoided" (§11.3). It needs neither control nor sampling: it appears in prediction, even with DP's expected updates. The smallest case is two states whose estimates share one weight, w and 2w, with a transition from the first to the second paying 0 (§11.2): the TD error is γ · 2w − w = (2γ − 1)w, so each update multiplies w by 1 + α(2γ − 1), above 1 whenever γ > 0.5. With α = 0.1 and γ = 1, w goes 10, 11, 12.1 derived: raising the first state raises the second twice as much. On-policy, the 2w state's own update would pull w back; off-policy, nothing does.

              Baird's counterexample is the complete version (Baird 1995; Figure 11.1). Seven states, eight weights: the six upper states have value 2wi + w8, the seventh w7 + 2w8; every reward is 0, so every true value is 0, which w = 0 represents exactly. The target policy always takes the "solid" action to state 7; the behaviour policy takes "dashed" (to a random upper state) with probability 6/7, so all seven states are updated equally often. With γ = 0.99 the weights diverge "for any positive step size, no matter how small", even with expected updates of every state at once.

              8The map: DP and TD backups, what to use, where it goes next

              Where it goes next. Replace the table with a network, plus a replay buffer (legitimate because Q-learning is off-policy) and a frozen target network: Value-based deep RL, where Double DQN is the double-learning fix and n-step targets return in Rainbow. Actor-critic methods learn a critic with TD targets and use GAE as the dial (Policy gradients and actor-critic). Dyna mixes Q-learning on real experience with Q-learning on experience simulated from a learned model (Model-based RL and planning). Learning from a fixed dataset with no interaction is offline RL, a different problem from off-policy learning (Offline RL and imitation). In language-model RL (RL for LLMs: RLHF, GRPO, RLVR), GRPO's single end-of-sequence reward against a group mean is a Monte Carlo return (unbiased, no value model, high variance), and PPO with a value model sits partway along the TD(λ) dial through GAE, its λ choosing the trade-off. On Topic: rl's axes all four methods are model-free and value-based; SARSA is on-policy and Q-learning off-policy; Monte Carlo does not bootstrap and TD does.

              Depth: misconceptions, and how the experiments are run

              Misconceptions worth a second look (seven)
              • "TD is always better than MC." Usually, on Markov tasks with a table; but it is biased, leans more on initial values, and can diverge with non-linear approximation or off-policy data where MC does not.
              • "MC and TD converge to the same thing on finite data." On a fixed batch MC fits the observed returns and TD solves the maximum-likelihood Markov model: V(A) = 0 against 0.75 in the AB example.
              • "Q-learning is off-policy, so it needs importance sampling." One-step Q-learning does not; off-policy MC and n-step methods do, and their ratios multiply along the trajectory (infinitely, in Example 5.5).
              • "On-policy means online, off-policy means offline." Q-learning is off-policy and online; the distinction is which policy the values describe.
              • "SARSA is older and Q-learning improved on it." The other way round: Q-learning is from 1989, SARSA from 1994, introduced as a modification of Q-learning.
              • "Weighted importance sampling is unbiased because it is normalised." The ordinary (first-visit) estimator is the unbiased one; the weighted one wins on variance.
              • "The Robbins-Monro conditions are how you set α." They are what the proofs need; practice uses a constant α.
              How the experiments are run, checked and defined (provenance)
              • Seeded and deterministic. Every random draw comes from a seeded generator (mulberry32), one stream per purpose and run, so a run replays identically, both sides of a comparison see the same walks where that makes sense, and a Python port matches the page exactly. Long averages run in small slices between frames, so the page stays responsive on a phone; each starts when its chart scrolls into view.
              • Checked against Python. src/lab/check.py ports the engine of the random-walk, 19-state and cliff experiments line by line and reproduces their numbers bit for bit; it also checks independently: true values by linear solve, the batch closed forms against replayed batches, the λ-return recursion against equation 12.3, the cases where methods coincide (n = 1 and λ = 0 are TD(0); n ≥ episode length and λ = 1 are Monte Carlo), and the cliff's exact ε-greedy returns by linear solve. src/checks/recompute.py does the same for the maximisation-bias, importance-sampling and Baird experiments and the four-learner animation.
              • Exact definitions. Undiscounted everywhere except Baird's (γ = 0.99). Monte Carlo on the walks is every-visit constant-α (equation 6.1). n-step TD follows the box in Section 7.1. The off-line λ-return takes its targets from the values held at the start of the episode and applies them in time order at its end (equation 12.4). TD(λ) uses accumulating traces. On the cliff, ties between equal Q-values break at random; the greedy path reported takes the first best move and counts as "none" if it loops or falls.
              • Assumed, and not compared. The book does not state α for the cliff (0.5 here) or how many runs its cliff graph averages, nor how many actions B has in Example 6.7 (10 here); it states 100 runs for the random walks and 10 episodes for the 19-state sweeps, used here. Its results exist only as plotted curves, and this page never reads numbers off a plot: it tests the shapes and orderings the text and captions state.
