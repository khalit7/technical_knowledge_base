The idea in one screen

Without a model you cannot compute dynamic programming's expectation over next states, so you replace it with a sample: the whole return (Monte Carlo), or one real reward plus your own estimate of where you landed (TD). Every method on this page is one choice of that target: how many real rewards before it trusts an estimate (a bias-variance dial), and which next action it assumes (the one taken: on-policy; the best one: off-policy).

Two choices define every target: how far it looks, and which next action it trusts

Left: one trajectory; each bracket is a target for V(St). Real rewards (solid) are unbiased and noisy; the bootstrapped estimate at the bracket's end is low-noise and possibly wrong. Right: at the next state S′, SARSA trusts the action the agent actually takes, Expected SARSA the policy's average, Q-learning the best action, whatever the agent does.

You need: the Bellman expectation backup and policy evaluation from {{Dynamic programming|n:3c65c17b0d0d81baada7e1c05ce69d01}} (this page samples its backups), and the loop, return and value vocabulary of {{Topic: rl|n:3c65c17b0d0d8195a6c6c11ad093c16e}} (its Method atlas tab dates every method here). ε-greedy and other exploration rules are on {{Bandits and exploration|n:3ee5c17b0d0d81acba54d70ac51c601c}}.

1Monte Carlo and TD prediction: wait for the return, or trust the next estimate

The test problem is the five-state random walk ({{Sutton and Barto, Example 6.2|https://incompleteideas.net/book/RLbook2020.pdf#page=147}}): states A to E in a row, every episode starts in C and steps left or right with probability 0.5 until it falls off an end; falling off the right pays 1, every other reward is 0, γ = 1. So the true value of a state is its chance of ending on the right, Vπ = (1/6, 2/6, 3/6, 4/6, 5/6). Estimates start at 0.5; α = 0.1. One episode: C → D → E → off the right end, rewards 0, 0, 1.

TD(0) updates after every step

  • C → D: δ = 0 + 0.5 − 0.5 = 0, so V(C) stays 0.5.
  • D → E: δ = 0 + 0.5 − 0.5 = 0, so V(D) stays 0.5.
  • E → end: δ = 1 + 0 − 0.5 = 0.5, so V(E) becomes 0.5 + 0.1 × 0.5 = 0.55.

Monte Carlo waits for the end

Every visited state had return G = 1, so V(C), V(D) and V(E) each become 0.5 + 0.1 × (1 − 0.5) = 0.55.

MC moved three states by the full surprise; TD moved one. TD's information travels back one state per episode (next time the walk passes D → E, D's target is 0 + 0.55 and D rises to 0.505), but each TD target carries one step of randomness, while each MC credit carries the whole walk's luck. As updates:

MC: V(St) ← V(St) + α ( Gt − V(St) )     TD(0): V(St) ← V(St) + α ( Rt+1 + γV(St+1) − V(St) )
Gt
the return actually observed to the end of the episode, computed backwards as Gt = Rt+1 + γGt+1
Rt+1 + γV(St+1)
the TD target (V = 0 at a terminal state); its gap to V(St) is the TD error δt ({{Sutton 1988|https://doi.org/10.1007/BF00115009}} named and introduced the method)
α
1/N(St), the visit count, gives MC the exact running mean; a constant α ("constant-α MC") forgets old episodes and tracks a changing problem

TD is DP's policy-evaluation backup, V(s) ← Eπ[R + γV(S′) | s], with the expectation replaced by one sample and a step of size α towards it: it "updates a guess towards a guess" ({{Silver, Lecture 4|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}).

    Batch MC and batch TD converge to different answers on the same data ({{Example 6.4|https://incompleteideas.net/book/RLbook2020.pdf#page=149}}). Eight episodes: A, 0, B, 0 once; B, 1 six times; B, 0 once. Both give V(B) = 6/8 = 0.75. Batch MC gives V(A) = 0, the only return seen from A; batch TD gives V(A) = 0.75, because A always led to B. TD's answer is the value under the maximum-likelihood Markov model of the data (certainty equivalence), which predicts future data better if the process is Markov (the optimality of batch TD(0) is from Sutton 1988); that is why batch TD beats batch MC on the walk (switch the chart to Batch). Silver's version: you nearly crash and the episode ends fine; MC credits every state with the good ending, TD marks down the states before the moment the crash looked certain.

    Monte Carlo details: first against every visit, why model-free, history (depth)

    First-visit MC uses only the first visit to a state in each episode; every-visit MC uses all of them. First-visit returns are independent, identically distributed samples of Vπ(s), so each average is unbiased and its standard error falls as 1/√n; every-visit returns from one episode are correlated and its estimate is biased for a finite number of episodes, but it also converges and "extends more naturally to function approximation and eligibility traces" ({{Sutton and Barto, §5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=114}}; {{Singh and Sutton 1996|https://doi.org/10.1007/BF00114726}} compare the two and tie first-visit MC to replacing traces, every-visit to accumulating ones). The incremental form follows from μk = μk−1 + (1/k)(xk − μk−1).

    Because MC does not bootstrap, the cost of estimating one state does not depend on the number of states: generate episodes from the states you care about and ignore the rest ({{§5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=117}}). Model-free methods also apply when a model exists but is only usable by sampling (Go, {{Silver, Lecture 5|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}), or when its probabilities are hard to write down: blackjack's rules are fully known, yet "it is not easy to determine" each outcome's probability for DP, while sample games are easy ({{§5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=116}}). The price is the exploration problem of section 3: you learn only about states you visit. DP's full-width backups touch every successor; model-free sample backups cost the same whatever the number of states.

    History: "Monte Carlo" dates from the 1940s at Los Alamos; an early RL use was Michie and Chambers (1968), who averaged episode durations in pole balancing, "similar in spirit to Monte Carlo ES with every-visit MC estimates"; Monte Carlo ES first appeared in the 1998 edition of the book ({{chapter 5 notes|https://incompleteideas.net/book/RLbook2020.pdf#page=138}}).
