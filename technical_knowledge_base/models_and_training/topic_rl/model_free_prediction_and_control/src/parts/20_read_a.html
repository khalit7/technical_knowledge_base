Model-free prediction and control in one screen

Model-free reinforcement learning learns values and policies from experience alone: the agent never sees the transition probabilities or the reward function, it only acts and observes what happens. Every method on this page answers one question: when the expectation over next states that dynamic programming computes from a model is unavailable, what do you replace it with?

Rows are clickable. Two ideas carry the page. First, Monte Carlo and TD are the two ends of one bias-variance dial, and n-step returns and TD(λ) are the settings in between. Second, on-policy against off-policy decides what the learned values mean, which shows up on the cliff-walking gridworld: SARSA learns a safe detour, Q-learning learns the risky optimal edge.

It matters beyond tabular RL because the modern targets are these ones: DQN regresses a network onto the Q-learning target, PPO's critic learns a TD target and its advantage estimator is a TD(λ) average, and GRPO's single end-of-sequence reward is a Monte Carlo return (section {{Where this goes next|#t-read/rd-next}}). Model-free against model-based, and the words this page uses

The power of model-free RL: you do not need a model of the environment or any understanding of its dynamics. You sample from it (interact with it) and work out the optimal policy from experience. This also covers the case where a model exists but is too big to use except by sampling, such as the game of Go ({{Silver, Lecture 5 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}), and the case where the model is known but its probabilities are hard to write down: Sutton and Barto's blackjack has fully known rules, yet "it is not easy to determine" the probability of each outcome for DP, while generating sample games is easy ({{§5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=116}}). The price: you only learn about states you actually visit, which creates the exploration problem of section {{Control|#t-read/rd-ctl}}.

{{Dynamic programming|n:3c65c17b0d0d81baada7e1c05ce69d01}} computes values from a known model with full-width backups: every state, every action, every successor weighted by its probability. Model-free methods use sample backups: one sampled transition (TD) or one sampled episode (MC) stands in for the expectation, so the cost of an update no longer depends on the number of states, and no model is needed.

The vocabulary is owned by {{Topic: rl|n:3c65c17b0d0d8195a6c6c11ad093c16e}} (its Reading tab, sections "The loop, the state and the return" and "The one idea"); the parts this page uses:

  • An episode is one run from a start state to a terminal state: S0, A0, R1, S1, A1, R2, ..., ST, where St is the state at time t, At the action taken there, Rt+1 the reward that follows it, and T the time step at which the episode terminates.
  • The return from time t is Gt = Rt+1 + γRt+2 + ... + γT−t−1RT, the discounted sum of the rewards still to come, with discount factor γ ∈ [0, 1].
  • The state value Vπ(s) = Eπ[Gt | St = s] is the expected return from s following policy π; the action value Qπ(s, a) is the expected return after taking a in s and following π afterwards. V(s) and Q(s, a) without a subscript are the agent's current estimates, stored in a table with one entry per state or state-action pair.
  • Prediction estimates Vπ or Qπ for a fixed policy; control finds a good policy.
  • An update moves an estimate towards a target by a step size α ∈ (0, 1]: new estimate = old estimate + α (target − old estimate). The methods on this page differ only in the target.
  • Bootstrapping: the target contains an existing estimate. Sampling: the target uses sampled transitions instead of an expectation computed from a model. DP bootstraps without sampling, MC samples without bootstrapping, TD does both ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}).
  • On-policy methods learn about the policy that generates the data; off-policy methods learn about a target policy π from data generated by a different behaviour policy (μ in Silver's slides, b in Sutton and Barto's book; this page uses b for importance sampling and μ elsewhere, as its sources do).

Monte Carlo prediction

Core idea: follow the policy for complete episodes and average the returns that actually followed each state. The value is literally the mean return, so by the law of large numbers the estimate converges to Vπ(s) as the number of visits grows ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}).

  1. Run an episode with policy π until it terminates.
  2. Walk backwards through it computing each return, Gt = Rt+1 + γGt+1 with GT = 0.
  3. For each visited state, move its estimate towards the return that followed it.

First-visit MC uses only the first visit to a state in each episode; every-visit MC uses every visit. Both converge. First-visit returns are independent, identically distributed samples of Vπ(s), so each average is unbiased and its error's standard deviation falls as 1/√n in the number of returns n; every-visit MC is harder to analyse (several returns from one episode are correlated, and its estimate is biased for a finite number of episodes), but it also converges, and it "extends more naturally to function approximation and eligibility traces" ({{Sutton and Barto, §5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=114}}; the comparison is {{Singh and Sutton 1996|https://doi.org/10.1007/BF00114726}}, who also tie first-visit MC to replacing traces and every-visit MC to accumulating ones).

The running average can be kept incrementally, because a mean satisfies μk = μk−1 + (1/k)(xk − μk−1), where μk is the mean of the first k samples x1, ..., xk. Replacing 1/k by a constant step size gives constant-α MC, which forgets old episodes and so tracks a changing (non-stationary) problem:

V(St) ← V(St) + α ( Gt − V(St) )
V(St)
the current estimate for the state visited at time t
Gt

α
the step size (1/N(St), with N(St) the visit count, gives the exact running mean)
Gt − V(St)
the error the update shrinks

Properties:

  • Unbiased: Gt is a sample of exactly the quantity Vπ(St) is the expectation of.
  • High variance: Gt depends on every random action, transition and reward until the end of the episode.
  • Needs episodes that terminate: the target is unknown until the episode ends, so MC only applies to episodic tasks and learns nothing mid-episode.
  • No bootstrapping: the estimate of one state does not build on the estimate of any other, so the cost of estimating one state does not depend on the number of states; you can generate episodes from the states you care about and ignore the rest ({{Sutton and Barto, §5.1|https://incompleteideas.net/book/RLbook2020.pdf#page=117}}).
  • It does not rely on the Markov property, so it copes better when the state does not capture everything that matters ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}).

History: the term "Monte Carlo" dates from the 1940s at Los Alamos; an early use to estimate action values in RL was Michie and Chambers (1968), who averaged episode durations in pole balancing, "similar in spirit to Monte Carlo ES with every-visit MC estimates"; Monte Carlo ES itself first appeared in the 1998 edition of Sutton and Barto ({{chapter 5 notes|https://incompleteideas.net/book/RLbook2020.pdf#page=138}}). The parent page's Method atlas dates the family the same way.

Temporal-difference (TD) learning

Core idea: do not wait for the real return. After one step, you know one real reward and where you landed, and you already have an estimate of how good that place is. Use reward plus discounted estimate as the target. TD "updates a guess towards a guess" ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}). The method and the name are from {{Sutton (1988)|https://doi.org/10.1007/BF00115009}}.

V(St) ← V(St) + α ( Rt+1 + γV(St+1) − V(St) )
Rt+1

γV(St+1)
the discounted current estimate of the next state (0 if St+1 is terminal)
Rt+1 + γV(St+1)

δt
= Rt+1 + γV(St+1) − V(St), the TD error, the surprise on this step
α
the step size

This is TD(0), the one-step case. Compare it with the DP backup for policy evaluation, V(s) ← Eπ[Rt+1 + γV(St+1) | St = s]: TD is the same backup with the expectation replaced by one sample and a step of size α towards it.

Properties ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}):

  • Online and incomplete episodes: it learns after every step, so it works on continuing (non-terminating) tasks.
  • Biased: the target leans on V(St+1), which may be wrong. The ideal target Rt+1 + γVπ(St+1) would be unbiased; the one actually used is not, and TD is more sensitive to the initial values than MC.
  • Low variance: the target depends on one random action, transition and reward, not on a whole episode.
  • Usually more sample-efficient than MC, because it exploits the Markov property.
  • Convergence. For a fixed policy, tabular TD(0) converges to Vπ: in the mean for a constant step size that is small enough ({{Sutton 1988|https://doi.org/10.1007/BF00115009}}), and with probability 1 when the step sizes decrease so that Σn αn = ∞ and Σn αn2 < ∞ ({{Dayan 1992|https://doi.org/10.1007/BF00992701}}; {{Sutton and Barto, §6.2 and equation 2.7|https://incompleteideas.net/book/RLbook2020.pdf#page=146}}). With a linear function approximator, on-policy TD(0) still converges, to the "TD fixed point" ({{§9.4|https://incompleteideas.net/book/RLbook2020.pdf#page=228}}); with non-linear approximators or off-policy data it can diverge, which is where {{Value-based deep RL|n:3ee5c17b0d0d818689b2c0dbce434ece}} picks up the story (the deadly triad).

Worked example: MC and TD on one random-walk episode

The standard test problem is the five-state random walk ({{Sutton and Barto, Example 6.2|https://incompleteideas.net/book/RLbook2020.pdf#page=147}}). States A, B, C, D, E sit in a row. Every episode starts in C and moves left or right with probability 0.5 each; it ends when it steps off either end. Stepping off the right end earns a reward of 1; every other reward is 0, and there is no discounting (γ = 1). So the true value of a state is the probability of finishing on the right: Vπ = (1/6, 2/6, 3/6, 4/6, 5/6) for A to E. All estimates start at 0.5, and α = 0.1.

Episode: C → D → E → off the right end, rewards 0, 0, 1.

TD(0) updates after every step

  • C → D: δ = 0 + 0.5 − 0.5 = 0, so V(C) stays 0.5.
  • D → E: δ = 0 + 0.5 − 0.5 = 0, so V(D) stays 0.5.
  • E → end: δ = 1 + 0 − 0.5 = 0.5, so V(E) becomes 0.5 + 0.1 × 0.5 = 0.55.

MC waits for the end

Every visited state had return G = 1 (the final reward, undiscounted), so V(C), V(D) and V(E) each become 0.5 + 0.1 × (1 − 0.5) = 0.55.

MC moved three states, all by the full surprise; TD moved only the last one. TD's information travels backwards one state per episode: next time the walk passes D → E, D's target will be 0 + 0.55 and D will rise to 0.505. MC credits the whole path at once, but each credit carries the full randomness of where that particular walk happened to end. Measured as the root-mean-square error against the true values, averaged over the five states and over 100 runs, TD was consistently better than MC on this task across the step sizes Sutton and Barto compared ({{Example 6.2|https://incompleteideas.net/book/RLbook2020.pdf#page=147}}). The {{TD or Monte Carlo|#t-rw}} tab replays these walks step by step through both methods, starting with this kind of episode, and reruns the book's 100-run comparison live: every TD curve stays below every MC curve.

Batch MC against batch TD: what each converges to

Given a fixed batch of experience replayed until convergence, the two methods converge to different answers ({{Sutton and Barto, Example 6.4|https://incompleteideas.net/book/RLbook2020.pdf#page=149}}; {{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}). Eight episodes, no discounting: one episode A, 0, B, 0 (start in A, reward 0 on the move to B, then reward 0 on terminating); six episodes B, 1; one episode B, 0.

  • Both agree V(B) = 6/8 = 0.75.
  • Batch MC gives V(A) = 0: A was seen once and its return was 0. This is the minimum squared error fit to the observed returns.
  • Batch TD gives V(A) = 0.75: A always led to B, and B is worth 0.75. This is the value under the maximum-likelihood Markov model of the data (certainty equivalence), and if the process really is Markov it predicts future data better. The optimality of batch TD(0) is from {{Sutton (1988)|https://doi.org/10.1007/BF00115009}}.

On the random walk the same thing shows as Figure 6.2: under batch training TD beats MC at every episode count, although batch MC is optimal on the data it has seen. The {{TD or Monte Carlo|#t-rw}} tab computes both batch answers exactly (sample means for MC, the certainty-equivalence model solved by Gaussian elimination for TD).

MC against TD, intuitively

Silver's driving analogy ({{Lecture 4|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}): you are driving, a car swerves at you, you nearly crash but do not, and the episode ends fine. Monte Carlo only sees the final return, so the near-death moment leaves no trace: the episode ended well, so every state gets credited with a good outcome. TD updates online from the next state's value: the moment the crash looks imminent, the value estimate plunges, and the preceding states are immediately updated toward that plunge. TD propagates the "that was almost a disaster" signal; MC misses it.

The old page's table said TD with function approximation "not always" converges, without the condition.
