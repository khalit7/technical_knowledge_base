The dial between them: n-step returns and TD(λ)

Between one step and the whole episode lie the n-step returns: take n real rewards, then bootstrap ({{Sutton and Barto, §7.1|https://incompleteideas.net/book/RLbook2020.pdf#page=164}}).

Gt(n) = Rt+1 + γRt+2 + ... + γn−1Rt+n + γnV(St+n)
Gt(n)
the n-step return from time t (the book writes Gt:t+n)
V(St+n)
the estimate of the state reached after n steps. If the episode ends before step t + n, the return is just the rewards up to the end.

n = 1 is the TD(0) target; n = ∞ (in practice, the end of the episode) is the Monte Carlo return. n-step TD updates V(St) towards Gt(n), which it can only do n steps later. Its guarantee is the error-reduction property: the worst error of the expected n-step return is at most γn times the worst error of V ({{§7.1, equation 7.3|https://incompleteideas.net/book/RLbook2020.pdf#page=166}}), so each extra real reward shrinks the bias the estimate can pass on.

TD(λ) averages all n-step returns with geometrically decaying weights, the λ-return (the forward view is due to {{Watkins 1989|https://www.cs.rhul.ac.uk/~chrisw/new_thesis.pdf}}; TD(λ) itself to {{Sutton 1988|https://doi.org/10.1007/BF00115009}}):

Gtλ = (1 − λ) Σn=1∞ λn−1 Gt(n)
λ ∈ [0, 1]
sets how fast the weights decay; (1 − λ) makes them sum to 1. In an episode ending at time T, every n-step return with n ≥ T − t equals the full return Gt, so their weights collect into one lump: (1 − λ)λn−1 for each n < T − t and λT−t−1 on Gt itself.

The endpoints recover the two pure methods ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}): λ = 0 puts all the weight on Gt(1), one-step TD; λ = 1 puts all of it on Gt, Monte Carlo. So MC and TD are two ends of a single bias-variance dial: more real rewards in the target means less bias and more variance.

The λ-return is the forward view: like MC, it needs the rest of the episode. The backward view computes the same thing online with an eligibility trace per state, which records how recently and how often each state was visited ({{§12.2|https://incompleteideas.net/book/RLbook2020.pdf#page=314}}):

Et(s) = γλEt−1(s) + 1(St = s),    V(s) ← V(s) + α δt Et(s) for every s
Et(s)
the trace of state s at time t (starting at 0)
1(St = s)
1 if s is the current state and 0 otherwise
δt
the ordinary one-step TD error

Each TD error is broadcast back to recently visited states in proportion to their traces. With λ = 0 only the current state is updated (TD(0)); with λ = 1 and updates applied at the end of the episode, the total update equals the MC update exactly, because the discounted sum of TD errors telescopes into Gt − V(St) ({{Silver, Lecture 4 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-4-model-free-prediction-.pdf}}). Online, TD(1) is "a way of implementing Monte Carlo algorithms that is more general": it also applies to discounted continuing tasks and learns during the episode ({{§12.2|https://incompleteideas.net/book/RLbook2020.pdf#page=316}}).

  • Three kinds of trace. The accumulating trace above adds 1 on every visit. The replacing trace resets it to 1 instead, so a state revisited in a loop never builds a trace above 1 ({{Singh and Sutton 1996|https://doi.org/10.1007/BF00114726}}). The dutch trace is the one that makes the online backward view exactly equal to the online λ-return with linear approximation: true online TD(λ) ({{van Seijen and Sutton 2014|https://proceedings.mlr.press/v32/seijen14.html}}; {{§12.5|https://incompleteideas.net/book/RLbook2020.pdf#page=321}}). Sutton and Barto now see replacing traces as "crude approximations to dutch traces, which largely supersede them" ({{§12.6|https://incompleteideas.net/book/RLbook2020.pdf#page=323}}).
  • Ordinary TD(λ) is only approximately the λ-return when it updates during the episode. The {{n-step and TD(λ)|#t-nl}} tab shows the gap: on the 19-state walk the two agree closely below the best step size and part ways above it, where TD(λ) with λ ≥ 0.9 diverges (Figure 12.6).
  • Which setting wins. On the 19-state walk an intermediate value is best: n = 4 or λ = 0.8 in the live rerun, with error rising toward both ends (Figures 7.2 and 12.3). The more an update relies on actual returns, the smaller the step size it tolerates.

In deep RL the same dial reappears as generalised advantage estimation (GAE; {{Schulman et al. 2015|https://arxiv.org/abs/1506.02438}}), a λ-weighted sum of TD errors used as the advantage in actor-critic methods, Ât = Σl≥0 (γλ)l δt+l, worked through on {{Policy gradients and actor-critic|n:3ee5c17b0d0d8101a262d3620e75747c}}.

Model-free control: making evaluation and improvement work from samples

Control follows the same two-phase loop as DP policy iteration, evaluate then improve, known as generalised policy iteration (GPI; {{Sutton and Barto, §5.3|https://incompleteideas.net/book/RLbook2020.pdf#page=119}}). Done with Monte Carlo evaluation, both phases break when you only sample:

  • Evaluation is no longer guaranteed to cover every state: DP sweeps all states; sampling only touches the states your trajectories visit.
  • Greedy improvement is no longer guaranteed to help, because the values it is greedy over may be wrong for unvisited actions: this is the exploration against exploitation problem showing up in the algorithm itself.

Two standard fixes:

  1. Use Q(s, a), not V(s), for evaluation. Acting greedily on V needs a model to know where each action leads, π′(s) = argmaxa [R(s, a) + γ Σs′ P(s′ | s, a) V(s′)]; acting greedily on Q is just π′(s) = argmaxa Q(s, a) over actions you have estimates for.
  2. Keep exploring, either by starting episodes from every state-action pair (exploring starts) or by keeping the policy soft (ε-greedy).

Exploring starts: Monte Carlo ES

If every episode starts from a randomly chosen state-action pair, with every pair possible, then every pair is visited infinitely often however greedy the policy is. Monte Carlo ES alternates evaluation and improvement episode by episode: after each episode, average the returns that followed each first visit of a pair into Q, then make the policy greedy at the states visited ({{§5.3, box|https://incompleteideas.net/book/RLbook2020.pdf#page=121}}). On blackjack it finds a policy that matches Thorp's (1966) basic strategy except for one notch in the usable-ace policy, which the authors are "confident" is optimal for their version of the game (Example 5.3, Figure 5.2). It cannot settle on a suboptimal policy, since that policy's values would make it change; but "convergence to this optimal fixed point ... has not yet been formally proved", which Sutton and Barto call "one of the most fundamental open theoretical questions in reinforcement learning" (partial solution: {{Tsitsiklis 2002|https://www.jmlr.org/papers/v3/tsitsiklis02a.html}}). Exploring starts are easy in a simulator and rarely possible when learning from real interaction.

Soft policies: ε-greedy

ε-greedy exploration: with probability 1 − ε take the greedy action, otherwise an action chosen uniformly at random from all m actions, so the greedy action has probability 1 − ε + ε/m and every other action ε/m. It is the simplest ε-soft policy (every action has probability at least ε/m); bandit-style alternatives such as UCB and optimistic starts are on {{Bandits and exploration|n:3ee5c17b0d0d81acba54d70ac51c601c}}. Every action keeps a non-zero probability, and the ε-greedy policy with respect to Qπ is guaranteed to be at least as good as the ε-soft policy π it came from, so improvement still works ({{Silver, Lecture 5 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}; the proof is equation 5.2 of {{§5.4|https://incompleteideas.net/book/RLbook2020.pdf#page=123}}: the ε-greedy policy's value is a weighted average that puts the 1 − ε mass on the largest Q). The catch: policy iteration over ε-soft policies finds only the best ε-soft policy, not the best policy.

Exploration therefore has to fade for the policy to become optimal. A schedule is GLIE (greedy in the limit with infinite exploration) when every state-action pair is visited infinitely often and the policy converges to the greedy policy; ε-greedy with εk = 1/k on the k-th episode is GLIE.

GLIE Monte Carlo control: sample the k-th episode with the current ε-greedy policy; for each visited pair increment the count N(St, At) and update Q(St, At) ← Q(St, At) + (1/N(St, At))(Gt − Q(St, At)); then set ε ← 1/k and make the policy ε-greedy on the new Q. It converges to the optimal action values, Q(s, a) → Q*(s, a) ({{Silver, Lecture 5 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}).

SARSA (on-policy TD control)

Replace MC by TD in the control loop: lower variance, online, works on incomplete episodes. Evaluate Q with a TD update after every step, and improve by acting ε-greedily on the latest Q. The update uses the quintuple (S, A, R, S′, A′), hence the name:

Q(S, A) ← Q(S, A) + α ( R + γQ(S′, A′) − Q(S, A) )
S, A
the current state and the action taken in it
R, S′
the reward received and the next state
A′
the action the agent actually takes next, chosen ε-greedily from Q(S′, ·)
Q(S′, A′)
0 if S′ is terminal
α, γ
the step size and the discount

The loop, per episode:

  1. Start in S and choose A ε-greedily from Q.
  2. Take A; observe R and S′.
  3. Choose A′ ε-greedily from Q in S′.
  4. Update Q(S, A) with the rule above.
  5. Set S ← S′, A ← A′ and repeat from step 2 until S is terminal.

Because A′ comes from the same ε-greedy policy that is acting, SARSA learns the value of the policy it is executing, exploration included: on-policy, model-free, TD control. It converges to Q* with probability 1 if the policies are GLIE and the step sizes αt satisfy the Robbins-Monro conditions Σt αt = ∞ and Σt αt2 < ∞: big enough in total to overcome any initial values, shrinking fast enough for the noise to average out ({{Silver, Lecture 5 slides|https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/lecture-5-model-free-control-.pdf}}; {{Sutton and Barto, §6.4|https://incompleteideas.net/book/RLbook2020.pdf#page=151}}; the proof is {{Singh, Jaakkola, Littman and Szepesvári 2000|https://doi.org/10.1023/A:1007678930559}}). Those step-size conditions are for theory: Sutton and Barto note they "are seldom used in applications and empirical research", where a constant α is the norm ({{§2.5|https://incompleteideas.net/book/RLbook2020.pdf#page=55}}). With ε held fixed SARSA instead settles on a policy that is good given that it keeps exploring, which is exactly what the cliff example below shows.

History: SARSA came after Q-learning, not before. Rummery and Niranjan introduced it in 1994 as "Modified Connectionist Q-learning"; the name "Sarsa" is from Sutton (1996) ({{chapter 6 notes|https://incompleteideas.net/book/RLbook2020.pdf#page=161}}; the parent page's Method atlas records the same correction).

Three variants use the same machinery:

  • n-step SARSA targets Rt+1 + ... + γn−1Rt+n + γnQ(St+n, At+n) ({{§7.2|https://incompleteideas.net/book/RLbook2020.pdf#page=167}}); SARSA(λ) averages those with λ-weights and keeps one eligibility trace per state-action pair ({{§12.7|https://incompleteideas.net/book/RLbook2020.pdf#page=325}}). Both move along the MC-TD dial exactly as TD(λ) does. On a gridworld with a single reward at the goal, one episode of one-step SARSA strengthens only the last action before the goal, while n-step SARSA strengthens the last n (Figure 7.4 of the book).
  • Expected SARSA replaces the sampled Q(S′, A′) with its expectation under the policy, Σa′ π(a′ | S′) Q(S′, a′), which removes the variance due to the random choice of A′ ({{§6.6|https://incompleteideas.net/book/RLbook2020.pdf#page=155}}). On the deterministic cliff it "can safely set α = 1 without suffering any degradation of asymptotic performance, whereas Sarsa can only perform well in the long run at a small value of α" (Figure 6.3, adapted from {{van Seijen, van Hasselt, Whiteson and Wiering 2009|https://doi.org/10.1109/ADPRL.2009.4927542}}; the algorithm goes back to George John, 1994). With a greedy target policy and an exploratory behaviour it is exactly Q-learning, so it "subsumes and generalizes Q-learning while reliably improving over Sarsa", at a small extra cost per step. In the {{Cliff walking|#t-cl}} tab's live rerun, Expected SARSA averages −20.8 per episode over episodes 401 to 500, against SARSA's −27.4 and Q-learning's −50.3 (100 runs, α = 0.5 assumed).
