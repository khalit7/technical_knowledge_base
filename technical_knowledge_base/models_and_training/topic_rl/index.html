Reinforcement learning in one screen

Reinforcement learning (RL) is learning to act by trial and error. An agent takes actions in an environment, receives a scalar reward after each one, and adjusts its behaviour to maximise the total reward it collects over time. Nobody tells it the correct action: it only learns how good the outcome was, often many steps later. That makes RL the tool for problems where behaviour can be scored but not demonstrated: games, control and, since InstructGPT in 2022, the post-training of language models, where a reward model or a programmatic verifier scores whole responses.

The field arrived in three layers. The classical core defines the problem (Markov decision processes and the Bellman equations) and solves it with tables, either by planning with a known model or by learning from samples. Deep RL replaces the tables with neural networks and adds the tricks that keep that stable (DQN, PPO, SAC, AlphaZero, MuZero). RL for language models applies the same machinery to token generation (RLHF, GRPO, RLVR), where the environment is trivial and the reward is the expensive part.

The one idea that runs through the page: one target, many estimators
Every method estimates the same quantity, the expected return that the Bellman equation describes, and improves behaviour against that estimate. The methods differ mainly in what they use in place of that expectation: the exact model, a whole sampled episode, one sampled step plus the current estimate, a learned critic, a tree search, or the mean reward of a group of sampled answers. The section The one idea runs all of them on one episode.

What RL is, and why it is its own subject

Three things set RL apart from supervised learning (Sutton and Barto, §1.1; Silver, Lecture 1). The feedback is a score, not a label: it says how good an action was, not which action was right. The feedback can be delayed: a chess move is rewarded only when the game ends, so the agent must work out which earlier action earned a later reward (the credit assignment problem). And the agent's own actions decide what data it sees next, so it must trade exploiting what it knows works against exploring to find something better.

Silver's classic examples are a helicopter flying stunts (rewarded for following the trajectory, punished for crashing), backgammon (won or lost) and Atari games (the score). The agent maximises cumulative reward, so it can pay now to gain later: refuelling a helicopter costs time but may prevent a crash. All of this rests on the reward hypothesis, that every goal can be written as maximising expected cumulative scalar reward. It is an assumption, and it breaks in instructive ways for language models: "helpful" has no formula, so training maximises a proxy (a learned reward model, a test suite, a judge), and a policy that optimises a proxy hard enough finds shortcuts such as longer answers, flattery or special-cased tests. That failure, reward hacking, is the subject of Reward Hacking.

Two problems share the vocabulary: in learning, the environment is unknown and the agent improves by interacting with it; in planning, a model of the environment is known and the agent improves by computing with it, for example by searching a game whose rules are known.

The loop, the state and the return

At each step t the agent sees an observation and a reward, chooses an action At, and the environment answers with the next observation and the reward Rt+1: in Silver's and Sutton and Barto's indexing, the reward for At arrives at t + 1. The agent summarises everything it has seen into a state. A state is Markov if the future depends only on it, not on how the agent got there; a single Atari frame is not (it shows where the ball is, not where it is going), which is why DQN stacks the last four frames (Mnih et al. 2015). When the agent cannot see everything that matters (a poker hand, a robot that does not know where it is), the problem is partially observable and the agent must build its own state from history. A language model generating text sees its whole prefix, so generation is fully observable.

The quantity the agent maximises is the return, the discounted sum of future rewards:

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ... = Rt+1 + γGt+1
γ ∈ [0, 1]
the discount: a reward k steps further away counts γk as much. The weights sum to 1/(1 − γ), so γ = 0.9 looks about 10 steps ahead and γ = 0.99 about 100 derived. Discounting keeps returns finite in never-ending tasks and makes the solvers converge; language-model RL uses γ = 1, because every response ends and the reward comes at the end.

The formal object is the Markov decision process (MDP): states, actions, transition probabilities, rewards and γ. A policy π(a | s) says how the agent acts. Its state value Vπ(s) is the expected return from a state, and its action value Qπ(s, a) the expected return after taking action a there. The difference matters in practice: picking the best action from Q is a lookup, while picking it from V needs a model of where each action leads, which is why model-free control learns Q. Reward is not value: in Silver's student example, a lecture costs −2 now yet the state is worth +1.5, because it leads toward passing (Silver, Lecture 2).

The one idea: one target, many estimators

The return obeys a one-step recursion, Gt = Rt+1 + γGt+1. Take expectations and you get the Bellman equation: the value of a state is the immediate reward plus the discounted value of where you land, on average.

Vπ(s) = 𝔼π[ Rt+1 + γVπ(St+1) | St = s ]
𝔼π
an average over the actions π chooses and the next states the environment produces. Replace the average by a max over actions and you get the optimality equation, whose solution is the best policy's value.

No agent can compute that expectation directly unless it knows the environment. So every method substitutes something for it, and nudges its estimate toward that substitute, the target: V(St) ← V(St) + α (target − V(St)). Policy-gradient methods use the same substitutes as the weight on "make that action more likely". That is the whole map of the field:

Why there is a dial. A target built from real rewards is unbiased but carries every step's randomness; a target that stops after one step and trusts the estimate carries little randomness but inherits whatever error the estimate has. Short targets win when the estimate is good, long ones when it is poor. Step through one episode and watch the targets for the same state spread out:

The families, in a paragraph or two each

Each family is one answer to "what stands in for the expectation, and what does it cost?" The Method atlas places every method on one grid and the Taxonomy on every classification axis; the three axes that matter most are what the agent stores (values, a policy, or both: value-based, policy-based, actor-critic), whether it uses a model of the environment (model-based or model-free), and whose experience it learns from (on-policy: its own current behaviour; off-policy: anyone's, including old data).

Exploration: bandits

Strip away states and delay and one problem is left: a row of slot machines with unknown payouts, the multi-armed bandit. Always pulling the arm that looks best (greedy) locks onto the first decent one; pulling at random never cashes in. The standard answers explore on purpose: ε-greedy takes a random action a small fraction of the time; optimistic initialisation starts every estimate high so the agent is disappointed into trying everything; UCB adds a bonus to rarely tried arms, exploring where it is uncertain (Auer et al. 2002); Thompson sampling tries each arm in proportion to the chance it is best. In full RL problems exploration has to be deep, since a good action may pay off only many steps later; deep RL adds entropy bonuses and curiosity, and language-model RL samples several answers per prompt at a temperature around 1.

Planning with a known model: dynamic programming

If you know every transition probability and reward, you can compute the expectation exactly. Dynamic programming turns the Bellman equation into an update and sweeps it over every state until the values stop changing. Policy iteration alternates evaluating the current policy with making it greedy on those values; value iteration applies the optimality equation directly. Each sweep shrinks the error by at least γ, so it always converges, but each sweep touches every state, and real problems have far too many (ten variables with ten values each are already ten billion states). DP is therefore the ideal every other method approximates by sampling, and its rhythm, evaluate a little, improve a little, is the shape of almost every RL algorithm up to PPO for language models.

Go deeper: Dynamic programming: planning with a known model works policy and value iteration by hand, the convergence proof and asynchronous DP.

Learning from samples: Monte Carlo, TD, SARSA, Q-learning

Without a model, the agent replaces the expectation with experience. Monte Carlo waits for the episode to end and uses the actual return: honest but noisy. Temporal-difference (TD) learning (Sutton 1988) updates after every step toward one real reward plus its own guess about the next state, "bootstrapping": less noisy, online, but only as good as its guesses. For control the agent learns Q. SARSA bootstraps from the action it actually takes next, so it learns the value of its own exploring behaviour (on-policy); Q-learning (Watkins and Dayan 1992) bootstraps from the best next action, so it learns the greedy policy while exploring (off-policy), which is what later lets DQN learn from a replay buffer of old experience. On Sutton and Barto's cliff-walking grid, Q-learning learns the shortest path along the edge and keeps falling off while exploring, while SARSA learns a safer path one row up. Learning from another policy's data in general needs importance sampling: reweight each sample by how much likelier the target policy was to take that action; PPO's and GRPO's ratios are this correction.

Go deeper: Model-free prediction and control (currently titled "Model-free methods") works Monte Carlo against TD, n-step returns and TD(λ), SARSA against Q-learning and cliff walking.

Deep value methods: DQN and its fixes

Tables need an entry per state; an Atari screen or a Go board has astronomically many. Replace the table with a neural network and the agent generalises across similar states, but the classical guarantees break: Sutton and Barto's deadly triad (function approximation, bootstrapping and off-policy learning together) can make value estimates diverge (§11.3). DQN is Q-learning with a convolutional network plus two stabilisers: an experience replay buffer that breaks the correlation between consecutive frames, and a frozen target network so the target does not move while the network chases it (the 2013 version had replay only; the target network arrived in the 2015 Nature paper). One architecture and one set of settings learned 49 Atari games from pixels, beyond 75% of a professional tester's score on 29 of them (Mnih et al. 2015). Later fixes target known flaws: the max in the target overestimates noisy values, which Double DQN corrects by choosing with one network and valuing with the other (van Hasselt et al.); Rainbow combined six such improvements (Hessel et al.).

Policy gradients and actor-critic, up to PPO

Instead of learning values and acting greedily, learn the policy itself and push it uphill: make the actions that turned out well more likely, in proportion to how well they turned out. That sentence is the policy gradient theorem (Sutton et al. 1999). It handles continuous and huge action spaces and stochastic policies naturally. REINFORCE (Williams 1992) weights each action by the whole return, which is unbiased and very noisy; subtracting a baseline (what the agent expected) keeps it unbiased and cuts the noise, turning the return into an advantage, "better or worse than expected". Learning that baseline with a value network that also bootstraps makes an actor-critic; A2C and A3C are the standard forms (Mnih et al. 2016).

A policy step is only trustworthy near the policy that collected the data. TRPO made "the largest safe step" precise with a KL constraint (Schulman et al. 2015); PPO gets the same effect simply by clipping the probability ratio between new and old policies at 1 ± ε (0.2 in the paper), so the objective goes flat once the policy has moved far enough, and each batch can be reused for several epochs (Schulman et al. 2017). For continuous control with expensive samples (robots), off-policy actor-critics that reuse a replay buffer win on data: TD3 and SAC, which adds an entropy bonus so the policy keeps exploring (Haarnoja et al. 2018).

Model-based RL and search

A model of the environment lets the agent rehearse: every imagined step is free experience. The catch is that errors in a learned model compound over a plan, and a planner happily exploits them. When the model is exact, as in a board game, search wins: Monte Carlo tree search guided by a policy and a value network returns a better move distribution than the network alone, so the search acts as the improvement step and the network learns to imitate it. AlphaZero reached superhuman chess, shogi and Go within 24 hours from the rules alone (Silver et al. 2017); MuZero dropped the rules, learning a model that predicts only what planning needs (reward, policy and value, never the screen), and matched AlphaZero while setting a new state of the art on 57 Atari games (Schrittwieser et al. 2019). World models such as DreamerV3 learn by imagining whole trajectories; it was the first algorithm to collect diamonds in Minecraft from scratch (Hafner et al.).

Offline RL and imitation

Sometimes the agent may not explore: a hospital cannot try random treatments. Behaviour cloning copies expert actions by supervised learning (supervised fine-tuning of a language model is exactly this), but small mistakes lead to unfamiliar states where it makes bigger ones; DAgger fixes that by asking the expert to label the states the learner actually reaches (Ross et al. 2011). Offline RL tries to beat the policy that collected a fixed dataset; its central danger is that the max in a Q-learning target picks actions the data never tried, whose values are pure guesswork, so offline methods stay close to the data (Levine et al. 2020). Note that offline is not the same as off-policy: Q-learning is off-policy yet learns online.

RL for language models

Generating text is an MDP with odd proportions: the state is the prompt plus the tokens so far, the action is the next token from a vocabulary of about 105, the transition is trivial (append the token), and there is usually one reward at the end. The hard parts are credit assignment across thousands of tokens and the reward itself.

  • RLHF learns a reward model from people's comparisons, then optimises the policy against it with PPO and a KL penalty that keeps it near the starting model. InstructGPT made it the standard recipe: its 1.3B model's outputs were preferred to 175B GPT-3's (Ouyang et al. 2022; InstructGPT page). PPO here keeps four models in memory: policy, reference, reward model and a critic as large as the policy.
  • GRPO deletes the critic: sample a group of answers to the same prompt and use the group's mean (and spread) as the baseline (DeepSeekMath, 2024; DeepSeekMath page). It is the Monte Carlo end of the dial with a sampled baseline. A group in which every answer scores the same teaches nothing.
  • RLVR deletes the learned reward model where a program can check the answer (maths, code). The name comes from Tülu 3 (Lambert et al. 2024). DeepSeek-R1-Zero ran GRPO with rule-based rewards straight on a base model and its AIME 2024 accuracy rose from 15.6% to 71.0% in the January 2025 preprint (77.9% in the later Nature version), with answers growing much longer (Guo et al. 2025; DeepSeek-R1 page; Milestones).

Read as a lineage, the three are two deletions: GRPO deletes RLHF's critic, RLVR its learned reward model. A learned reward is a proxy, and pushing it too far makes the true quality rise, peak and fall (Gao et al. 2022); verifiers help but can be gamed too. Whether RLVR teaches new reasoning or mostly turns the model's best answers into its usual ones is debated (Yue et al. 2025). DPO skips both the reward model and the RL loop by training directly on preference pairs, offline (DPO page); the pipeline around RL is on Alignment.

Go deeper: RL for LLMs: RLHF, GRPO, RLVR covers PPO for RLHF, GRPO in detail, R1, and the 2025 corrections (Dr. GRPO, DAPO, GSPO); Reward Hacking catalogues what goes wrong.

Common mistakes

  • "Reward and value are the same." Reward is one step's signal; value is the expected sum of what follows.
  • "The observation is the state." One frame, or the last chat message, can leave out what the future depends on.
  • "γ = 1 is always wrong." It is standard when every episode ends, as in language-model RL.
  • "Model-based means a learned model." Dynamic programming and AlphaZero use a given one.
  • "The reward model makes RLHF model-based." Nothing plans with it; it stands in for the reward.
  • "On-policy means online, off-policy means offline." Q-learning is off-policy while interacting; PPO reuses each batch for several epochs and is still approximately on-policy.
  • "Any learned baseline makes an actor-critic." REINFORCE with a baseline, RLOO and GRPO never bootstrap from it, so they are policy-based (Sutton and Barto §13.5).
  • "Deep RL is a different theory." Its targets are the classical ones; what is new is function approximation and the tricks that keep it stable.
  • "Token generation is a hard environment." The transition is trivial; credit assignment and a trustworthy reward are the hard parts.
  • "A higher reward means a better model." With a proxy reward, the policy can climb it while true quality falls (reward hacking).

Taxonomy: every axis RL methods are classified on

Calling a method "model-free, off-policy, value-based" places it on three axes; there are at least fifteen more, and most confusions in RL come from treating two of them as one: off-policy as offline, online as on-policy, a reward model as a model. The Arcade Learning Environment's 57 games are scored as human-normalised scores, 100 × (agent − random) / (human − random), so 100% is the human tester.
