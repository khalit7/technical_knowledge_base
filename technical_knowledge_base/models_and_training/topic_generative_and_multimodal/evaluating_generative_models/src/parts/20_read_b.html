In one screen

A generative model has no right answer to compare against, so it is judged by comparing distributions: does the set of images it makes look like a set of real images, in the eyes of some feature extractor? Every image metric on this page is a choice of three things: which features (Inception, DINOv2, CLIP, a domain classifier), which distance between the two clouds of feature vectors (Fréchet distance between fitted Gaussians, a kernel distance, nearest-neighbour coverage), and how many samples. Text-to-image adds a fourth question, did it draw what was asked, which needs the prompt; and in the end people decide, by votes in arenas or through reward models trained on their votes.

Everything measured here uses one running example (the topic's {{data setup|n:3c65c17b0d0d817ab6ade318917bff55}}): the 10,000 Fashion-MNIST test images are the reference, and eight sets of 10,000 images each are scored against them, from a perfect one to a bad one. They come from checkpoints the topic's labs and sibling pages already trained; nothing was trained for this page.

Each strip: the first image of each class, left to right T-shirt, trouser, pullover, dress, coat, sandal, shirt, sneaker, bag, ankle boot (the VAE ignores labels, so its strip is ten random draws; the "half" set only has the first five classes). measured on Apple M1 Pro (MPS); sampling times in the {{Metric comparator|#t-evcmp}} tab.

1. The problem: scoring a model that has no right answer

A classifier is scored image by image: each prediction is right or wrong. A generator draws a new image from noise; there is no "correct" image for that noise. What we can ask is whether its output distribution (all the images it would make, with their frequencies) matches the data distribution. That splits into questions that one number cannot answer at once:

  • Fidelity: does each image look real? (a blurry VAE sample fails)
  • Diversity or coverage: does the model make everything the data has, in the right proportions? (a model that only draws trousers fails, however good its trousers)
  • Alignment: for a conditional model, does the image match its condition (the class label here, the prompt for text-to-image)?
  • Preference: would a person choose it? This mixes all of the above with taste.

Images are compared in a feature space: a pretrained network maps each image to a vector, and similar-looking images land near each other. Raw pixels are a bad space for this (shift a shirt by two pixels and almost every pixel changes). Then each set of images becomes a cloud of points, and a metric is a distance between two clouds. The choice of network decides what "similar" means: Inception-v3 was trained to name 1,000 ImageNet classes, so it sees the world as ImageNet objects; DINOv2 learned without labels; CLIP learned from captions. That choice is why the same eight sets can be ranked differently by different metrics (section 4).

The test every metric must pass first
Score real images against other real images from the same distribution. Whatever comes out is the metric's floor: the value that means "nothing is wrong" at that sample count. For FID on this data the floor is at 10,000 images and about at 1,000 (the topic setup's measurement, reproduced below). A model's score means something only next to its floor.
