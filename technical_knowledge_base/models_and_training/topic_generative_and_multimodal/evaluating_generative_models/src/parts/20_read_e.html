5. Pitfalls: the same images, a different FID

FID is a function of the pixels that reach Inception, so anything that touches pixels between the generator and the metric changes it: file format, resizing, the reference set, the code. The {{Pitfall lab|#t-evpit}} tab runs each one; the rule they share is process both sets identically, with the same code, and say how.

Resizing

Inception wants 299 x 299. Downsampling with a fixed-width bilinear filter (what TensorFlow 1 and PyTorch's F.interpolate did) aliases: fine detail folds into false patterns. clean-fid measured that the same 1024-px FFHQ images resized by different libraries already differ by FID 4.34 (TensorFlow bilinear) and 7.43 (nearest) from the PIL-bicubic version, and that StyleGAN2's FID of 2.98 becomes 7.45 if only the generated images go through TensorFlow's or PyTorch's bilinear resize (Table 1). Their library offers mode="clean" (PIL bicubic) plus two legacy modes that reproduce the old numbers. Here the images are 28 px, so the resize is an upsampling and aliasing cannot occur; but resizing one set differently still moves FID: pre-resizing only the real set to 299 with PIL bicubic gives , with nearest-neighbour ; resizing both sets the same way gives .

The reference set, the features and the code

  • Reference set. Training images or held-out images, how many, and which split: each gives a different number. ADM and EDM2 use statistics of the whole training set against 50,000 samples; this topic uses the 10,000 test images. Say which.
  • ImageNet leakage. {{Kynkäänniemi et al. 2022|https://arxiv.org/abs/2203.06026}} resampled generated images so that Inception's top-1 class histogram matched the real data's: FID fell by about 10% with no visible change (FFHQ 5.30 to 4.70, Table 1), while FID computed in CLIP space barely moved (2.76 to 2.74). Matching all of Inception's "fringe" features cut FFHQ FID from 5.30 to 1.78. A generator (or a discriminator built on ImageNet features) can game FID without looking better.
  • Implementation. Inception weights ported from TensorFlow, the resize, float precision and the square-root method all differ between libraries. The topic's setup checked that MPS features differ from CPU features by at most 1.8e-5 over 200 images; differences between libraries are larger. Compute every number you compare with one tool.
What to write next to an FID
Features and weights (for example torch-fidelity 0.4.0, inception-v3-compat), resize (library and filter), file format of both sets, reference set and its size, number of generated samples, and the spread over seeds. Without these, two FIDs are not comparable.

6. Prompt alignment: did it draw what was asked?

Distribution metrics ignore the prompt: a model that draws beautiful random scenes scores well. For text-to-image we also check each image against its prompt.

CLIPScore

CLIPScore ({{Hessel et al. 2021|https://arxiv.org/abs/2104.08718}}) is CLIP's cosine similarity between the image and the text, CLIP-S = 2.5 · max(cos, 0), with CLIP ViT-B/32 (the factor 2.5 stretches the usual 0 to 0.4 range of cosines; the paper scored captions, prefixed "A photo depicts"). Many text-to-image papers instead report 100 · cos with a larger CLIP and call it "CLIP score": the same idea on a different scale. It needs no reference image, and it inherits CLIP's blind spots: CLIP's text side behaves much like a "bag of words" (the VQAScore authors' phrase), so counts, relations and text are weak, as the {{Vision lab|n:3c65c17b0d0d817ab6ade318917bff55}} showed with its typographic attack.

Question-answering checks

Instead of one similarity, ask questions. TIFA ({{Hu et al. 2023|https://arxiv.org/abs/2303.11897}}) turns the prompt into question-answer pairs with a language model and asks a VQA model about the image; with mPLUG it correlated with human faithfulness ratings at Spearman 0.60 against 0.33 for CLIPScore (Table 2). DSG ({{Cho et al. 2024|https://arxiv.org/abs/2310.18235}}) orders the questions in a dependency graph so that "is the motorcycle blue?" is skipped when there is no motorcycle. VQAScore ({{Lin et al. 2024|https://arxiv.org/abs/2404.01291}}) asks one question, "Does this figure show '{text}'? Please answer yes or no.", and uses the probability of "Yes"; on Winoground its group score was 46.0 against 7.8 for CLIPScore. GenEval ({{Ghosh et al. 2023|https://arxiv.org/abs/2310.11513}}) uses an object detector instead of a VLM for six tasks (single object, two objects, counting, colours, position, attribute binding): SD v1.5 scores 0.43 overall, SDXL 0.55, IF-XL 0.61, with position at most 0.15 (Table 2), and it agrees with human annotators on 83% of images against 88% between annotators.
