5. Pitfalls: the same images, a different FID

FID is a function of the pixels that reach Inception, so anything between the generator and the metric changes it: file format, resizing, the reference set, the code. The rule: process both sets identically, with the same code, and say how.

  1. The floor. Each case uses real training images as the "model", so the right answer is "nothing is wrong" and any change from the floor is pure artefact. Stored losslessly (PNG) on both sides, they score 2.54 against the 10,000 test images.
  2. Saved as JPEG on one side. PIL, grey, read back: to the eye, the same garments. FID 5.10 at quality 90, 10.04 at 75 (PIL's default), 22.20 at 50. Real images saved as JPEG look the same and score four times worse.
  3. What changed. The absolute difference, amplified 8x: JPEG works on 8 x 8 blocks, and on a 28-pixel image one block is almost a third of the width. At quality 75 the mean change is 3.69 of 255 per pixel over all 10,000 images (PSNR 32.5 dB).
  4. Compress both sides. Compress the reference the same way and it comes back to 2.60.
  5. Resize one side. Only the real set pre-resized to 299, so the extractor's own resize does nothing for it: PIL bicubic 74.19 (bicubic overshoots at edges and blurs differently from the bilinear resize the reference gets), nearest-neighbour 331.25 (blocky: hard pixel edges the reference never has; cut at the top of the scale). The same function on both sides: 3.22, back near the floor; only the reference resized: 75.03.
  6. Model samples too. DDPM scores 11.46 as PNG, 15.40 with its samples saved as JPEG 75, 22.37 if only the reference is compressed, and 10.13 with both compressed, lower than its PNG score.

The clean-fid paper ({{Parmar, Zhang and Zhu 2022|https://arxiv.org/abs/2104.11222}}) found the same on FFHQ: JPEG-75 copies of real images score "a high score (21)", while StyleGAN2 scores "around 3"; and on LSUN Church, whose training images were stored as JPEG, compressing StyleGAN2's samples at quality 87 improved its FID from 4.00 to 3.48.

Compression is not neutral: it erases fine detail the model got wrong as well as detail it got right. The flow model: 15.96, 22.11, 21.40 and 13.75 in the same four cases. Other features notice JPEG too: the JPEG-75 real set's FD-DINOv2 is 81.3 (floor 17.1) and its CMMD 0.103 (floor 0.0002), worse than the flow model's 0.072.

Resizing

Inception wants 299 x 299. Downsampling with a fixed-width bilinear filter (TensorFlow 1, PyTorch's F.interpolate) aliases: fine detail folds into false patterns. Here the images are 28 px, so the resize is an upsampling and cannot alias; resizing one set differently still moves FID (Fig. 3, step 5). The reference set, the features and the code

  • Reference set. Training or held-out images, how many, which split: each gives a different number. ADM and EDM2 use statistics of the whole training set against 50,000 samples; this topic uses the 10,000 test images.
  • ImageNet leakage. {{Kynkäänniemi et al. 2022|https://arxiv.org/abs/2203.06026}} resampled generated images so that Inception's top-1 class histogram matched the real data's: FID fell by about 10% with no visible change (FFHQ 5.30 to 4.70, Table 1), while FID in CLIP space barely moved (2.76 to 2.74). Matching all of Inception's "fringe" features cut FFHQ FID from 5.30 to 1.78. A generator (or a discriminator built on ImageNet features) can game FID without looking better.
  • Implementation. Inception weights ported from TensorFlow, the resize, float precision and the square-root method differ between libraries. The topic's setup found MPS features differ from CPU features by at most 1.8e-5 over 200 images; differences between libraries are larger. Compute every number you compare with one tool.
What to write next to an FID
Features and weights (for example torch-fidelity 0.4.0, inception-v3-compat), resize (library and filter), file format of both sets, reference set and its size, number of generated samples, and the spread over seeds. Without these, two FIDs are not comparable.
