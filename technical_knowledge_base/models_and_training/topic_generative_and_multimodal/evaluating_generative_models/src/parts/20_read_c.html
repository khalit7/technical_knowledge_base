2. FID from zero

FID, the Fréchet Inception Distance ({{Heusel et al. 2017|https://arxiv.org/abs/1706.08500}}), is the standard score for image generators. Step through it on real data first: a good model, a blurry one and a model with half the variety go through the same four steps.

FID in four steps: only two summaries per set survive

Drawn: 300 test images and 300 samples of the chosen set, projected onto the two directions along which the real features vary most (principal components). The counters and FID use all 2,048 dimensions over all 10,000 images. measured on Apple M1 Pro (MPS features, CPU float64 statistics).

  1. Features. Resize every image to 299 x 299 and pass it through Inception-v3, an ImageNet classifier from 2015; keep the 2,048 numbers of its last pooling layer.
  2. Fit a Gaussian to each set: mean μr (2,048 numbers) and covariance Σr (2,048 x 2,048) for the real images; μg, Σg for the generated ones.
  3. Distance between the two Gaussians, the Fréchet (2-Wasserstein) distance, which has a closed form:
FID = ‖μr − μg‖² + Tr(Σr + Σg − 2 (ΣrΣg)1/2)

the covariance term: how differently the clouds are spread (too little variety, or variety in the wrong directions); zero when Σr = Σg

Read the counters for the two failures. The VAE's samples are blurry, so their features sit away from the real ones and the mean term is large. The "half" set holds perfect real images of 5 classes: each image is flawless, yet its FID is far from the floor, mostly through the covariance term. FID cannot tell you which failure you have; precision and recall can (section 4).

The code that computes it, and where the 299 pixels come from

The topic's own implementation (shared by every lab), the formula line for line:

def frechet(mu1, s1, mu2, s2):
    """||mu1 - mu2||^2 + Tr(S1 + S2 - 2 (S1 S2)^(1/2)) (Dowson and Landau 1982; Heusel et al. 2017)."""
    diff = mu1 - mu2
    covmean = linalg.sqrtm(s1 @ s2)          # scipy >= 1.16: no disp argument
    if not np.isfinite(covmean).all():
        off = np.eye(s1.shape[0]) * 1e-6
        covmean = linalg.sqrtm((s1 + off) @ (s2 + off))
    covmean = covmean.real
    return float(diff @ diff + np.trace(s1) + np.trace(s2) - 2 * np.trace(covmean))

3. Sample count: the bias that never goes away by itself

The real set alone scores at 250 samples and at 10,000. The covariance is estimated from N samples and enters through a matrix square root; estimation noise makes the cloud look more spread out, and the formula turns that into extra distance. So FID at N samples is too large, by roughly K/N: {{Chong and Forsyth 2020|https://arxiv.org/abs/1911.07023}} showed FIDN ≈ FID∞ + K/N, with a slope K that depends on the generator. Fixing N therefore does not make two models comparable: the model with more spread pays more bias (their Figure 3: two identical DCGANs whose order swaps with N).

Every set's FID falls with N, and the real data is far from 0 at small N

The real set's extrapolated FID∞ is , not 0: extrapolating removes the bias from the generated side only, and the fixed 10,000-image reference has a noisy covariance too (and train and test images need not be identically distributed).

Hence the convention: 50,000 generated images against statistics of the whole training set (since Heusel et al.; stated for ADM by {{Dhariwal and Nichol 2021|https://arxiv.org/abs/2105.05233}} and for EDM2 by {{Karras et al. 2024|https://arxiv.org/abs/2312.02696}}). The official FID code warns: "We recommend using a minimum sample size of 10,000 to calculate the FID otherwise the true FID of the generative model is underestimated" ({{TTUR README|https://github.com/bioinf-jku/TTUR}}; read "misestimated": the finite-N error is an overestimate, as the curves show). Below 2,048 samples the covariance is not even full rank.
