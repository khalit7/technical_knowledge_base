6. Choosing the path: straight, cosine, or diffusion's (one family)

The problem. "Flow matching" usually means the straight path at = t, bt = 1 − t, but the loss works for any Gaussian path xt = at x1 + bt x0 (Lipman et al. 2023; Albergo and Vanden-Eijnden's stochastic interpolants). Diffusion's paths are variance preserving (VP: a² + b² = 1). Which path is best, and how different are flow and diffusion really?

One family. Both train on a scaled data point plus scaled noise, so any such model can be read as predicting the noise, the clean data or the velocity: given xt, each determines the others. On the straight path, x̂1 = xt + (1 − t) vθ and x̂0 = xt − t vθ derived. Every diffusion model also has a deterministic ODE with the same marginals, the probability-flow ODE (Song et al. 2021), which DDIM solves ({{Diffusion from zero, sections 4 and 5|n:3c65c17b0d0d81cf9bf0d94e57ce9164}}). So "flow against diffusion" is three separable choices: the path, what the network outputs (which sets how the loss weighs each noise level), and how t is drawn in training (section 11).

Three paths, all exact. Because the toy's field is exact for any path, this comparison has no learning error: straight; cosine VP (a = sin(πt/2), b = cos(πt/2), SiT's GVP); and the continuous DDPM schedule (Song et al.'s VP SDE, β from 0.1 to 20).

7. Couplings: which noise is paired with which image

The problem. A coupling is the rule that pairs noises with images in training. Plain flow matching draws both at random; random pairs cross everywhere, and crossing lines are what the average bends around. Can a better pairing straighten the flow without a second training?

How it works. Minibatch optimal transport (OT; Tong et al., arXiv 2302.00482; Pooladian et al., "Multisample Flow Matching", arXiv 2304.14772; both 2023): inside each batch of B noises and B images, re-pair them to minimise the total squared distance (the Hungarian algorithm), then train as usual. The marginals are unchanged; only which line each point is on changes.
