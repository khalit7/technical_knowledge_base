2. Two kinds of image token: one to read, one to write

The problem. A transformer works on a sequence of vectors. Text gets there by looking each token id up in an embedding table. An image has no ids, so something must turn pixels into sequence positions, and the choice decides whether the model can ever write images.

Soft tokens (continuous). A vision encoder (ViT, SigLIP) cuts the image into patches and outputs one vector per patch; a projector maps them to the model's width. Rich, semantic, good for answering questions about the image. But the model cannot output them: its output layer is a softmax over the vocabulary, and soft tokens are not in it. Every VLM and the encoder-free models read images this way. Cost: 1,088 positions for one image in SmolVLM-500M, 280 by default in Gemma 4 12B Unified.

Discrete tokens (codes). An image tokenizer (a VQ-VAE, VQGAN or FSQ autoencoder) maps each patch of a small latent grid to the index of its nearest codebook entry: an integer, exactly like a text token id. A decoder maps a grid of codes back to pixels. Now an image is a sequence of ids the model can predict with the same softmax and cross-entropy loss it uses for words. Cost: the tokenizer's reconstruction is lossy, and the model must write every code.

How the tokenizer is trained (straight-through gradients, dead codes, FSQ, VQGAN's losses) is the sibling page Autoencoders and VAEs; here it is a fixed part. The running example uses that page's best tiny tokenizer, an FSQ autoencoder with levels [8, 5, 5, 5] (8 × 5 × 5 × 5 = 1,000 codes): each 28 × 28 Fashion-MNIST image, padded to 32 × 32, becomes an 8 × 8 grid, so 64 tokens from 1,000 codes. The Latent lab's 128-code VQ-VAE gives a second tokenizer of the same shape.

How many bits is an image? With 1,000 codes, writing one code blindly costs log2 1,000 = 9.97 bits, so 64 codes cost bits. Codes are not equally common: their frequencies over the training set give bits per code, bits per image. An autoregressive model that predicts each code from the class and the codes before it needs, on held-out validation images, bits per image: its exact negative log-likelihood, a number diffusion models cannot give cheaply. Why not one kind for both jobs? Janus tried it: with one VQ tokenizer for both reading and writing, its understanding score (POPE) was 60.1; with SigLIP features to read and VQ codes to write, 87.0 (Janus Table 5, {{arXiv 2410.13848v1|https://arxiv.org/html/2410.13848v1}}) vendor. Codes trained to reconstruct pixels keep what the pixels need (exact edges, colours), not what a question needs (what the object is). That is why Janus, BAGEL and most unified models keep two encodings (section 6).
