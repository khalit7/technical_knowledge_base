2. Two kinds of image token: one to read, one to write

A transformer works on a sequence of vectors; text gets there by looking each token id up in an embedding table. An image has no ids, and what it becomes decides whether the model can ever write images.

Soft tokens (continuous). A vision encoder (ViT, SigLIP) outputs one vector per patch; a projector maps them to the model's width. Rich and semantic, but the model cannot output them: its output layer is a softmax over the vocabulary, and soft tokens are not in it. Every VLM and the encoder-free models read images this way: 1,088 positions for one image in SmolVLM-500M, 280 by default in Gemma 4 12B Unified.

Discrete tokens (codes). An image tokenizer (VQ-VAE, VQGAN or FSQ) maps each cell of a small latent grid to the index of its nearest codebook entry: an integer, exactly like a text token id, and a decoder maps codes back to pixels. Now the model can predict an image with the same softmax and cross-entropy it uses for words. The price: the tokenizer's reconstruction is lossy, and the model must write every code.

How the tokenizer is trained is the sibling page {{Autoencoders and VAEs|n:3c65c17b0d0d814da93bdb159b7c1e11}}'s; here it is a fixed part. The running example uses that page's best tiny tokenizer, an FSQ autoencoder with levels [8, 5, 5, 5] (8 × 5 × 5 × 5 = 1,000 codes): each 28 × 28 Fashion-MNIST image, padded to 32 × 32, becomes an 8 × 8 grid, so 64 tokens from 1,000 codes. The topic's 128-code VQ-VAE (root Latent lab recordings; VQ training is taught on {{Autoencoders and VAEs|n:3c65c17b0d0d814da93bdb159b7c1e11}}) gives a second tokenizer of the same shape.

How many bits is an image? Writing one of 1,000 codes blindly costs log2 1,000 = 9.97 bits, so 64 codes cost bits; the codes' frequencies over the training set give bits per code, per image. An autoregressive model that predicts each code from the class and the codes before it needs, on held-out validation images, bits per image: its exact negative log-likelihood, a number diffusion models cannot give cheaply.

Why not one kind for both jobs? Janus tried it: with one VQ tokenizer for reading and writing, its understanding score (POPE) was 60.1; with SigLIP features to read and VQ codes to write, 87.0 (Janus Table 5, {{arXiv 2410.13848v1|https://arxiv.org/html/2410.13848v1}}) vendor. Codes trained to reconstruct pixels keep what pixels need (exact edges, colours), not what a question needs (what the object is). That is why Janus, BAGEL and most unified models keep two encodings (section 6).

3. Writing an image one token at a time

Put the image's codes in raster order (left to right, top to bottom) and model them like words. The chain rule turns the probability of a whole image into a product of next-token probabilities:

p(x1, …, x64 | c) = ∏i p(xi | c, x1, …, xi−1)
xi
the code at position i (one of 1,000 here)
c
the condition: a class here, a text prompt in a real model, both as tokens before the image

Training is next-token cross-entropy with teacher forcing, all 64 positions in one pass under a causal mask; generating is a loop of one call, one sampled code, append. The running example's model is a 6-layer transformer of width 192 ( parameters, 3.07M), the class embedding as the first position (LlamaGen's layout), trained with the topic's exact DDPM recipe (the one {{Diffusion from zero|n:3c65c17b0d0d81cf9bf0d94e57ce9164}} uses) (batch 128, AdamW 5 × 10-4, EMA 0.999, 10% of labels dropped for guidance) for steps, s on the M1 Pro's GPU.

Three knobs, the same as for text. Temperature T divides the logits before the softmax (0 means always take the top code, greedy); top-k keeps the k likeliest codes; classifier-free guidance on logits runs the conditional and the null-class input together and uses lu + s(lc − lu), s = 1 being the plain conditional model. LlamaGen states this form; its best ImageNet result uses s = 1.65 ({{arXiv 2406.06525v1|https://arxiv.org/html/2406.06525v1}}). Guidance doubles the batch, not the number of sequential steps. The same knobs for text, with real logits, are on {{Sampling and Decoding|n:3c65c17b0d0d8115bafcda29a2c7086e}}; for images the verdicts differ.

Temperature and top-k trade diversity for typicality and FD punishes it; guidance is the knob that buys fidelity

One knob per view, 1,000 samples per point (100 per class), the same random draws at every setting; FD in the shared classifier's feature space against the 10,000 test images (lower is better; 1,000 real validation images score ). measured on Apple M1 Pro (MPS)

What the measurements say. Without guidance the best FD is at temperature 1, the temperature the model was trained for: cooling to 0.7 makes every class look tidier (classifier accuracy rises) but samples cluster around the most typical shapes, diversity drops and FD gets worse; heating to 1.3 adds noise faster than variety. Top-k behaves like cooling: keeping the 10 likeliest codes gives FD against with all 1,000. Guidance helps most: the best scale, s = , brings FD to with of samples recognised as the asked-for class; s = 0 (the unconditional model) gives FD and the right class only of the time, chance level. measured Guidance on logits behaves as guidance on noise predictions does for diffusion (the topic's DDPM runs scored best at s = 2, root Diffusion lab recordings).

for i in range(m.n_tok):
    inp_tokens = out if (not use_cache or i == 0) else out[:, -1:]
    if cfg not in (0, 1):
        inp_tokens = torch.cat([inp_tokens, inp_tokens])
    if use_cache:
        lg = m(inp_tokens if i > 0 else inp_tokens[:, :0], yy, caches=caches, start=0 if i == 0 else i)[:, -1]
    else:
        lg = m(inp_tokens, yy)[:, -1]
    if cfg not in (0, 1):
        lc, lu = lg.chunk(2); lg = lu + cfg * (lc - lu)
    f = _filter(lg.float(), temperature, top_k)
    if f is None:
        nxt = lg.argmax(-1)
        p = lg.float().softmax(-1)
    else:
        p = f.softmax(-1)
        if u is not None:
            nxt = _draw(p, u[:, i].to(dev))
        else:
            nxt = torch.multinomial(p.cpu(), 1, generator=gen).squeeze(1).to(dev)
    out = torch.cat([out, nxt[:, None]], 1)

Guidance in library code: transformers implements the same line for Janus as scores_processed = uncond_logits + (cond_logits - uncond_logits) * self.guidance_scale ({{logits_process.py line 2205, v5.20.1|https://github.com/huggingface/transformers/blob/v5.20.1/src/transformers/generation/logits_process.py#L2205}}), and Janus's generate falls back to 5 when no scale is given (modeling_janus.py line 1194).

Checks that ran: the cached and uncached loops give logits within 1.4 × 10-6 and identical samples (CPU); one image at batch 1 takes s with the cache and s without (MPS, median of 3): at 64 tokens recomputing the short prefix is cheaper than the cache's bookkeeping on this GPU; the cache pays off for the thousands of tokens of a real image or conversation, where recomputation grows with the square of the length. measured
