Token economics: what a multimodal request costs in tokens, cache and sequential calls

Everything a native multimodal model reads or writes becomes positions in one sequence, so the bill is counted in tokens. This tab does the arithmetic for a whole request (images, audio, video and text in) and for one output (an image or a stretch of speech out). The reading-side rules for single VLMs, with tiles and cache, are on the sibling page Vision-language models (its Token and cache budget tab); this tab adds audio and video, the native and closed models, and the writing side, which a VLM does not have.

Derived: autoregressive tokens = (resolution / f)2, one call each; a masked model fills the same tokens in the chosen number of rounds, each round a full pass over all of them; the diffusion transformer works on (resolution / 16)2 latent tokens (an 8 times VAE and 2 × 2 patches, the SD3 and FLUX layout). Compute = 2 FLOPs per parameter per token processed (attention and the tokenizer or VAE ignored), times 2 with guidance. Defaults: 7B, f = 16 at 512 px is Chameleon-7B's 1,024 tokens per image; the diffusion row defaults to SD3 Medium's 2.03B transformer (2,028,328,000 parameters counted on the sibling page Latent diffusion and diffusion transformers) and its pipeline default of 28 steps with guidance. The time per call is yours to set (20 ms is an illustrative value, not a measurement); a call of the diffusion model processes far more tokens than an autoregressive decode step, so equal milliseconds per call is optimistic for it. derived
