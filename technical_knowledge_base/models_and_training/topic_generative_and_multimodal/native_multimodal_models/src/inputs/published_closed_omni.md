## 1. GPT-4o (OpenAI)

Source A: "GPT-4o System Card", OpenAI, dated August 8, 2024 in the document; arXiv:2410.21276v1, posted 25 Oct 2024. https://arxiv.org/html/2410.21276v1
Source B: "Hello GPT-4o" blog, OpenAI, May 13, 2024. Fetched via Wayback Machine snapshot https://web.archive.org/web/20240515000000id_/https://openai.com/index/hello-gpt-4o/ (openai.com returns 403 to bots).

- Omni model, one network (vendor): "GPT-4o [ 1 ] is an autoregressive omni model, which accepts as input any combination of text, audio, image, and video and generates any combination of text, audio, and image outputs. It's trained end-to-end across text, vision, and audio, meaning that all inputs and outputs are processed by the same neural network." (Source A, 2024-08-08, Section 1 Introduction; https://arxiv.org/html/2410.21276v1)
- Audio latency (vendor): "GPT-4o can respond to audio inputs in as little as 232 milliseconds, with an average of 320 milliseconds, which is similar to human response time [ 2 ] in a conversation." (Source A, Section 1 Introduction). Same numbers in Source B: "It can respond to audio inputs in as little as 232 milliseconds, with an average of 320 milliseconds, which is similar to human response time (opens in a new window) in a conversation." (Source B, 2024-05-13, opening section)
- Text parity and price (vendor): "It matches GPT-4 Turbo performance on text in English and code, with significant improvement on text in non-English languages, while also being much faster and 50% cheaper in the API." (Source A, Section 1; identical sentence in Source B)
- Previous Voice Mode pipeline and latencies (vendor): "Prior to GPT-4o, you could use Voice Mode to talk to ChatGPT with latencies of 2.8 seconds (GPT-3.5) and 5.4 seconds (GPT-4) on average. To achieve this, Voice Mode is a pipeline of three separate models: one simple model transcribes audio to text, GPT-3.5 or GPT-4 takes in text and outputs text, and a third simple model converts that text back to audio." (Source B, 2024-05-13, Model capabilities section)
- What the pipeline loses (vendor): "This process means that the main source of intelligence, GPT-4, loses a lot of information [em dash] it can't directly observe tone, multiple speakers, or background noises, and it can't output laughter, singing, or express emotion." (Source B, same paragraph). Note: the original has no spaces around the em dash.
- End-to-end training, blog wording (vendor): "With GPT-4o, we trained a single new model end-to-end across text, vision, and audio, meaning that all inputs and outputs are processed by the same neural network. Because GPT-4o is our first model combining all of these modalities, we are still just scratching the surface of exploring what the model can do and its limitations." (Source B, same section)
- Training data cutoff (vendor): "GPT-4o's text and voice capabilities were pre-trained using data up to October 2023, sourced from a wide variety of materials including:" (Source A, Section 2 Model data and training)
- Data includes audio and video (vendor): "Our dataset includes images, audio, and video to teach the LLMs how to interpret and generate non-textual input and output." (Source A, Section 2)
- Voice output restrictions, summary table (vendor): "In all of our post-training audio data, we supervise ideal completions using the voice sample in the system message as the base voice." and "We only allow the model to use certain pre-selected voices and use an output classifier to detect if the model deviates from that." (Source A, Section 3.3 risk/mitigation table, row "Unauthorized voice generation")
- Preset voices and streaming output classifier (vendor): "Risk Mitigation: We addressed voice generation related-risks by allowing only the preset voices we created in collaboration with voice actors [ 11 ] to be used. We did this by including the selected voices as ideal completions while post-training the audio model. Additionally, we built a standalone output classifier to detect if the GPT-4o output is using a voice that's different from our approved list. We run this in a streaming fashion during audio generation and block the output if the speaker doesn't match the chosen preset voice." (Source A, Section 3.3.1 Unauthorized voice generation)
- Why: unintended voice imitation was observed (vendor): "During testing, we also observed rare instances where the model would unintentionally generate an output emulating the user's voice." (Source A, Section 3.3.1)
- Voice classifier numbers (vendor): "Table 2 : Our voice output classifier performance over a conversation by language: Precision Recall English 0.96 1.0 Non-English 5 0.95 1.0" (Source A, Section 3.3.1, Table 2)
- Speaker identification refusal (vendor): "We post-trained GPT-4o to refuse to comply with requests to identify someone based on a voice in an audio input, while still complying with requests to identify famous quotes." (Source A, Section 3.3 table)
- NOT disclosed (checked by searching the full system card text): parameter count; how audio is tokenized or represented (no codec, frame rate, or token rate given); whether there are separate encoders or decoders per modality; how images are generated; context length; training compute. The only architecture-related words in the card are contributor role titles ("Architecture leads", "Tokenizer lead") in the authorship list. The card makes no explicit statement that architecture is withheld; it simply does not describe it. UNCONFIRMED: any audio token rate or codec for GPT-4o.

## 2. GPT-4o native image generation (system card addendum)

Source: "Addendum to GPT-4o System Card: Native image generation", OpenAI, March 25, 2025 (date printed on page 1). https://cdn.openai.com/11998be9-5319-4302-bfbf-1167e093f1fb/Native_Image_Generation_System_Card.pdf (read pages 1--3 of the PDF).

- Autoregressive, native, confirmed (vendor): "Unlike DALL·E, which operates as a diffusion model, 4o image generation is an autoregressive model natively embedded within ChatGPT. This fundamental difference introduces several new capabilities that are distinct from previous generative models, and that pose new risks:" (Section 2.1 Safety Challenges: New risks from native image generation)
- Embedded in the omni model (vendor): "And because it is embedded natively, deep in the architecture of our omnimodal GPT-4o model, 4o image generation can use everything it knows to apply these capabilities in subtle and expressive ways, creating images that are not only beautiful, but also useful." (Section 1 Introduction)
- Capabilities listed (vendor): "Image-to-Image Transformation: This capability allows 4o image generation to take one or multiple images as input, and to produce a related or modified image." (Section 2.1, bullet list; other bullets: Photorealism, Instruction Following including rendering "text and instructional diagrams")
- Tool framing in the product (vendor): "Prompt blocking: This strategy, which happens after a call to the 4o image generation tool has been made, involves blocking the tool from generating an image if text or image classifiers flag the prompt as violating our policies." (Section 2.2 Safety stack). Note the tension: the model is described as "natively embedded", but in ChatGPT it is invoked as a "tool" that the chat model can refuse to trigger ("the chat model can refuse to trigger the image generation process based on the user's prompt", Section 2.2).
- NOT disclosed (pages 1--3 read): image tokenizer, whether pixels are produced by a separate decoder (diffusion or otherwise) after autoregressive tokens, resolution, token counts, parameter count. UNCONFIRMED: anything beyond "autoregressive" about how pixels are produced.

## 3. Gemini (Google DeepMind)

### Gemini 1.0
Source: "Gemini: A Family of Highly Capable Multimodal Models", Gemini Team, Google; arXiv:2312.11805v4, 17 Jun 2024 (v1 Dec 2023). https://arxiv.org/html/2312.11805v4

- Multimodal from the beginning; discrete image tokens (vendor): "The visual encoding of Gemini models is inspired by our own foundational work on Flamingo ( Alayrac et al., 2022 ) , CoCa ( Yu et al., 2022a ) , and PaLI ( Chen et al., 2022 ) , with the important distinction that the models are multimodal from the beginning and can natively output images using discrete image tokens ( Ramesh et al., 2021 ; Yu et al., 2022b ) ." (Section 2 Model Architecture)
- Interleaved inputs, video as frames (vendor): "Figure 2 : Gemini models support interleaved sequences of text, image, audio, and video as inputs (illustrated by tokens of different colors in the input sequence). They can output responses with interleaved image and text. Video understanding is accomplished by encoding the video as a sequence of frames in the large context window. Video frames or images can be interleaved naturally with text or audio as part of the model input." (Section 2, Figure 2 caption and following text)
- Audio input via USM features at 16 kHz (vendor): "In addition, Gemini models can directly ingest audio signals at 16kHz from Universal Speech Model (USM) ( Zhang et al., 2023 ) features. This enables the model to capture nuances that are typically lost when the audio is naively mapped to a text input (for example, see audio understanding demo on the website )." (Section 2)
- Natively multimodal, joint training (vendor): "The Gemini models are natively multimodal, as they are trained jointly across text, image, audio, and video." (Section 5 Evaluation)
- Backbone and context (vendor): "Gemini models build on top of Transformer decoders ( Vaswani et al., 2017b ) that are enhanced with improvements in architecture and model optimization to enable stable training at scale and optimized inference on Google's Tensor Processing Units. They are trained to support 32k context length, employing efficient attention mechanisms (for e.g. multi-query attention ( Shazeer, 2019a ) )." (Section 2)
- Video evaluation sampling (vendor): "For each video task, we sample 16 equally-spaced frames from each video clip and feed them to the Gemini models." (Section 5.2.2 Video Understanding)
- NOT disclosed: the image tokenizer used for output, how many tokens per image or per second of audio, parameter counts (Nano sizes are given elsewhere in the report; not re-checked here). UNCONFIRMED: Gemini 1.0 audio output.

### Gemini 1.5
Source: "Gemini 1.5: Unlocking multimodal understanding across millions of tokens of context", Gemini Team, Google; arXiv:2403.05530v5, 16 Dec 2024. https://arxiv.org/html/2403.05530v5

- Up to at least 10M tokens (vendor): "Gemini 1.5 models are built to handle extremely long contexts; they have the ability to recall and reason over fine-grained information from up to at least 10M tokens. This scale is unprecedented among contemporary large language models (LLMs), and enables the processing of long-form mixed-modality inputs including entire collections of documents, multiple hours of video, and almost five days long of audio." (Section 1 Introduction)
- Per-modality needle recall numbers (vendor): "Figure 1 : Gemini 1.5 Pro achieves near-perfect "needle" recall ( > 99.7%) up to 1M tokens of "haystack" in all modalities, i.e., text, video and audio. It even maintains this recall performance when extending to 10M tokens in the text modality (approximately 7M words); 9.7M tokens in the audio modality (up to 107 hours); 9.9M tokens in the video modality (up to 10.5 hours)." (Figure 1 caption)
- Concrete examples (vendor): "this context length enables Gemini 1.5 Pro models to comfortably process almost five days of audio recordings (i.e., 107 hours), more than ten times the entirety of the 1440 page book (or 587,287 words) "War and Peace", the entire Flax ( Heek et al., 2023 ) codebase (41,070 lines of code), or 10.5 hours of video at 1 frame-per-second. Further, since the model is natively multimodal and supports interleaving of data from different modalities, it can support a mix of audio, visual, text, and code inputs in the same input sequence." (Section 3 Model Architecture)
- Architecture (vendor): "Gemini 1.5 Pro is a sparse mixture-of-expert (MoE) Transformer-based model that builds on Gemini 1.0's ( Gemini-Team et al., 2023 ) research advances and multimodal capabilities." (Section 3.1)
- Derived (not stated as such): 9.7M audio tokens over 107 hours is about 25 tokens per second of audio; 9.9M video tokens over 10.5 hours at 1 fps is about 260 tokens per frame. These are arithmetic on the vendor figures, not quoted rates. UNCONFIRMED as official per-second rates.

### Gemini 2.5
Source: "Gemini 2.5: Pushing the Frontier with Advanced Reasoning, Multimodality, Long Context, and Next Generation Agentic Capabilities", Gemini Team, Google; arXiv:2507.06261v4, 22 Jul 2025. https://arxiv.org/html/2507.06261v4

- Natively multimodal family (vendor): "The Gemini 2.X series are all built to be natively multimodal, supporting long context inputs of >1 million tokens and have native tool use support." (Section 1 Introduction)
- Architecture, inputs only (vendor): "The Gemini 2.5 models are sparse mixture-of-experts (MoE) ( ... ) transformers ( Vaswani et al., 2017 ) with native multimodal support for text, vision, and audio inputs." (Section 2.1 Model Architecture; citation list shortened with "( ... )")
- Audio generation and causal audio representations (vendor): "While Gemini 1.5 was focused on native audio understanding tasks such as transcription, translation, summarization and question-answering, in addition to understanding, Gemini 2.5 was trained to perform audio generation tasks such as text-to-speech or native audio-visual to audio out dialog. To enable low-latency streaming dialog, we incorporated causal audio representations that also allow streaming audio into and out of Gemini 2.5." (Audio paragraph, capabilities section)
- Native audio dialog model (vendor): "Our Gemini 2.5 Flash Preview Native Audio Dialog model uses native audio generation, which enables the same level of style, pacing and accent control as available in our controllable TTS offering. Our dialog model supports tool use and function calling, and is available in more than 24 languages. With native audio understanding and generation capabilities, it can understand and respond appropriately to the user's tone. This model is also capable of understanding when to respond to the user, and when not to respond, ignoring background and non-device directed audio." (Section "Gemini 2.5 Audio Generation")
- TTS and native dialog are separate products (vendor): "With Gemini 2.5, the Controllable TTS and Native Audio Dialog capabilities are available as separate options on AI Studio (Generate Media and Stream sections respectively)." (same section)
- Visual token count (vendor): "We have also trained our models so that they perform competitively with 66 instead of 258 visual tokens per frame, enabling using about 3 hours of video instead of 1h within a 1M tokens context window" (Video paragraph; footnote: "This is referred to as low media resolution in the API")
- Native image generation, Gemini 2.0 Flash (vendor): "In March 2025, we released an experimental version of Gemini 2.0 Flash Native Image Generation. It has brought to the users new capabilities as a result of a strong integration between the Gemini model and image-generation capabilities, enabling new experiences related to image generation & image editing via natural-language prompting." (Section "Gemini 2.0 Flash Native Image Generation Model")
- Disagreement / tension to flag: Section 2.1 lists native support only for text, vision and audio *inputs*, while the capabilities section describes native audio *output* (dialog) and a separate native image generation model. The report does not say whether audio or image output comes from the same 2.5 Pro/Flash weights or separate variants. NOT disclosed: audio codec, token rate, image tokenizer.

## 4. Qwen2.5-Omni and Qwen3-Omni (Alibaba Qwen team, open weights)

### Qwen2.5-Omni
Source: "Qwen2.5-Omni Technical Report", Qwen Team; arXiv:2503.20215v1, 26 Mar 2025. https://arxiv.org/html/2503.20215v1 . Model cards: https://huggingface.co/Qwen/Qwen2.5-Omni-7B , https://huggingface.co/Qwen/Qwen2.5-Omni-3B

- Thinker-Talker (vendor): "To concurrently generate text and speech while avoiding interference between the two modalities, we propose Thinker-Talker architecture. In this framework, Thinker functions as a large language model tasked with text generation, while Talker is a dual-track autoregressive model that directly utilizes the hidden representations from the Thinker to produce audio tokens as output. Both the Thinker and Talker models are designed to be trained and inferred in an end-to-end manner." (Abstract)
- End-to-end jointly trained (vendor): "As a result, Thinker-Talker architecture is end-to-end jointly trained, with each component dedicated to generating distinct signals." (Section 1 Introduction)
- What Talker consumes (vendor): "Talker receives both high-level representations and embeddings of the text tokens sampled by Thinker. The integration of high-dimensional representations and discrete sampling tokens is essential in this context." (Section 2.3 Generation, Speech)
- Speech codec (vendor): "We designed an efficient speech codec named qwen-tts-tokenizer . qwen-tts-tokenizer efficiently represents key information of speech and can be decoded to speech streamingly through a causal audio decoder. After receiving the information, Talker starts to autoregressively generate audio tokens and text tokens. The generation of speech does not require word-level and timestamp-level alignment with the text." (Section 2.3, Speech)
- Codes to waveform: sliding-window DiT plus BigVGAN (vendor): "Specifically, we utilize a Flow-Matching ( Lipman et al., ) DiT model. The input code is transformed into a mel-spectrogram using Flow-Matching, followed by a modified BigVGAN ( Lee et al., ) to reconstruct the generated mel-spectrogram back into the waveform." and "We limit the DiT's receptive field to 4 blocks, including a lookback of 2 blocks and a lookahead of 1 block." (Section 2.4, Streaming Codec Generation)
- Audio input rate (vendor): "we resample it to a frequency of 16kHz and transform the raw waveform into a 128-channel mel-spectrogram with a window size of 25ms and a hop size of 10ms. We adopt the audio encoder from Qwen2-Audio ( Chu et al., 2024b ) , to make each frame of audio representation roughly corresponds to a 40ms segment of the original audio signal." (Section 2.2). That is about 25 audio tokens per second (arithmetic, not quoted).
- TMRoPE (vendor): "To synchronize the timestamps of video inputs with audio, we organize the audio and video sequentially in an interleaved manner and propose a novel position embedding approach, named TMRoPE ( T ime-aligned M ultimodal RoPE )." (Abstract) and "we dynamically adjust the temporal IDs between frames based on the actual time corresponding to each frame to ensure that one temporal ID corresponds to 40ms." (Section 2.2, Video and TMRoPE)
- Streaming encoders (vendor): "the audio encoder is changed from full attention over the entire audio to performing attention in blocks of 2 seconds each." (Section 2.4, Support Prefilling)
- Vision encoder size (vendor): "we employ the vision encoder from Qwen2.5-VL ( Bai et al., 2025 ) , which is based on the Vision Transformer (ViT) model with approximately 675 million parameters" (Section 2.2)
- Size: the report compares against models "of similar size (7B)" (Section 5.1.1). Model cards exist for Qwen2.5-Omni-7B and Qwen2.5-Omni-3B.
- First-packet latency: the report defines four latency components (Section 2.4: "the initial packet latency is a critical indicator of the system's streaming performance") but gives NO millisecond figure. UNCONFIRMED: any Qwen2.5-Omni first-packet latency number.
- Licence: Qwen2.5-Omni-7B model card front matter: "license_name: apache-2.0". Qwen2.5-Omni-3B model card: "license_name: qwen-research" (different licence for the 3B). (Hugging Face model cards, fetched 2026-10-17)

### Qwen3-Omni
Source: "Qwen3-Omni Technical Report", Qwen Team; arXiv:2509.17765v1, 22 Sep 2025. https://arxiv.org/html/2509.17765v1

- Thinker-Talker MoE (vendor): "Qwen3-Omni adopts a Thinker–Talker Mixture-of-Experts (MoE) architecture that unifies perception and generation across text, images, audio, and video, yielding fluent text and natural real-time speech. It supports text interaction in 119 languages, speech understanding in 19 languages and speech generation in 10 languages." (Abstract)
- Multi-codebook speech, ConvNet decoder, 234 ms (vendor): "To reduce first-packet latency in streaming synthesis, the Talker autoregressively predicts discrete speech codecs using a multi-codebook scheme. Leveraging the representational capacity of these codebooks, we replace computationally intensive block-wise diffusion with a lightweight causal ConvNet, enabling streaming from the first codec frame. In cold-start settings (no prior context), Qwen3-Omni achieves a theoretical end-to-end first-packet latency of 234 ms." (Abstract)
- RVQ, codebook 0 plus MTP for residuals (vendor): "Architecturally, our approach departs from Xu et al. (2025) by operating directly on RVQ tokens. The Talker employs a hierarchical prediction scheme: the backbone ingests the aggregated codebook features of the current frame and uses a linear head to predict the zeroth codebook, after which a multi-token prediction (MTP) module generates all residual codebooks." (Section 2.4 Speech Generation)
- 12.5 Hz in and out (vendor): "(5) the input and output audio code rates are reduced to 12.5 Hz, with the output codec enabling single-frame, immediate speech synthesis." (Section 1 Introduction) and "the 12.5Hz token rate Talker requires only one token to synthesize 80ms audio." (Section 2.5)
- AuT audio encoder (vendor): "Qwen3-Omni employs the AuT encoder as the audio encoder to obtain general purpose audio representations at a token rate of 12.5Hz." and "trained from scratch on 20 million hours of supervised audio data" (Section 2.2 Audio Transformer (AuT))
- Module sizes and latency, Table 1 (vendor): "Audio Encoder AuT 650M ... Vision Encoder SigLIP2-So400M 540M ... Thinker MoE Transformer 30B-A3B ... Talker MoE Transformer 3B-A0.3B ... MTP Dense Transformer 80M ... Code2wav ConvNet 200M ... End-to-End First-Packet Latency: 234/547ms" (Section 2.5, Table 1; "/" separates audio/video; ellipses mark removed table cells such as streaming checkmarks)
- Latency under load, Table 2 (vendor, theoretical): "Overral Latency (Audio/Video) 234/547ms 728/1517ms 1172/2284ms" for 1, 4 and 6 concurrency; "Generation RTF(Real Time Factor) 0.47 0.56 0.66". Measured "on the vLLM framework ( Kwon et al., 2023 )" with "torch.compile and CUDA Graph acceleration" (Section 2.5, Table 2 and text). Note the paper calls these "theoretical first-packet latency".
- Change from Qwen2.5-Omni (vendor): "Talker no longer consumes the Thinker's high-level text representations and conditions only on audio and visual multimodal features." (Section 2.1 Overview). Possible tension: Section 2.4 says the Talker is "conditioned on a rich context inherited from a "Thinker" component, comprising historical textual tokens, multimodal representations, and the current turn's streamed text." Read together: Talker takes text tokens but not Thinker's hidden text representations. Flag for careful wording.
- TM-RoPE (vendor): "we employs a Time-aligned Multimodal Rotary Position Embedding (TM-RoPE), which extends the Multimodal Rotary Position Embedding (M-RoPE) ( Bai et al., 2023b ) by incorporating absolute temporal information. TM-RoPE factorizes the conventional rotary position embedding into three distinct dimensions: temporal, height, and width." (Section 2.3)
- Long audio (vendor): "The system can process audio recordings up to 40 minutes per instance for ASR and spoken-language understanding" (Abstract)
- Licence (vendor): "Qwen3-Omni-30B-A3B, Qwen3-Omni-30B-A3B-Thinking and Qwen3-Omni-30B-A3B-Captioner are publicly released under the Apache 2.0 license." (Abstract)
- Cascade comparison (vendor, qualitative): "Crucially, it exhibits advantages over cascaded pipelines, including stronger cross-modal reasoning, lower end-to-end latency, and lower system complexity and cost." (Section 7 Conclusion)
- Minor discrepancy: Qwen3-Omni says "we replace Whisper audio encoder with our AuT", while Qwen2.5-Omni describes its encoder as "the audio encoder from Qwen2-Audio". Not contradictory if Qwen2-Audio's encoder is Whisper-based, but the Qwen2.5-Omni report itself does not say "Whisper" in the passages checked. UNCONFIRMED from the Qwen2.5-Omni report alone.
- Number of codebooks in the Qwen3-Omni codec: UNCONFIRMED (not found in passages read).

## 5. AnyGPT (Fudan University)

Source: "AnyGPT: Unified Multimodal LLM with Discrete Sequence Modeling", Zhan et al.; arXiv:2402.12226v3, 07 Mar 2024. https://arxiv.org/html/2402.12226v3 (authors are academics; still "vendor" in the sense of authors about their own model)

- Discrete representations, no architecture change (authors): "We introduce AnyGPT, an any-to-any multimodal language model that utilizes discrete representations for the unified processing of various modalities, including speech, text, images, and music. AnyGPT can be trained stably without any alterations to the current large language model (LLM) architecture or training paradigms. Instead, it relies exclusively on data-level preprocessing" (Abstract)
- Backbone (authors): "We employ the LLaMA-2 ( Touvron et al., 2023 ) 7B as the backbone, which is pre-trained on 2 TB of text tokens. Apart from reshaping the embedding matrix and prediction layer, the rest of the language model remains unaltered." (Section 3.2). Note "2 TB of text tokens" is as written (likely meant 2T tokens).
- Tokenizer table (authors): "Modality Image Speech Music Vocab Size 8192 1024 4096 Tokens per Sample 32 / per image 50 / s 200 / s RVQ ✘ ✔ ✔ Input Size 224*224 variable duration 5s Table 1: Details of tokenization of different modalities." (Section 3.1)
- Image: SEED (authors): "We utilize the SEED tokenizer ( Ge et al., 2023a ) for image tokenization." ... "the Causal Q-Former converts the patch features into 32 causal embeddings. A codebook with 8192 entries discretizes the embeddings into a sequence of quantized codes." Decoding goes to "the pre-trained unCLIP Stable Diffusion(unCLIP-SD)". (Section 3.1, Image Tokenizer)
- Speech: SpeechTokenizer (authors): "The SpeechTokenizer compresses single-channel audio sequences into a discretized matrix using eight hierarchical quantizers, each with 1,024 entries, and achieves a frame rate of 50 Hz. The first quantizer layer captures semantic content, while layers 2 to 8 encode paralinguistic details. A 10-second audio is thus transformed into a 500 × 8 matrix" ... "In AnyGPT, the Large Language Model (LLM) is employed to model the semantic tokens, while a voice cloning model supplements the remaining paralinguistic information." (Section 3.1, Speech Tokenizer)
- Speech decoding (authors): "For speech, we utilize SoundStorm ( Borsos et al., 2023b ) , a non-autoregressive Masked Language Model, trained to generate SpeechTokenizer's acoustic tokens from semantic tokens." ... "This approach enables AnyGPT replicate the voice of any speaker using a 3-second speech prompt" (Section 3.3)
- Music: Encodec (authors): "This variant processes 32 kHz monophonic audio, and achieves a frame rate of 50 Hz. The embeddings generated are quantized using an RVQ with four quantizers, each with a codebook size of 2048, resulting in a combined music vocabulary size of 8192. We encode 5 seconds music into 250 latent frames, ultimately generating a 250 × 4 codes matrix." (Section 3.1, Music Tokenizer)
- Internal inconsistency to flag: Table 1 lists the music "Vocab Size" as 4096, while the text says four codebooks of 2048 give "a combined music vocabulary size of 8192". Token rate: 50 Hz × 4 quantizers = 200 tokens/s (matches Table 1's "200 / s").

## 6. NExT-GPT (NUS)

Source: "NExT-GPT: Any-to-Any Multimodal LLM", Wu et al.; arXiv:2309.05519v3, 25 Jun 2024 (ICML 2024). https://arxiv.org/html/2309.05519v3

- Pipeline design (authors): "NExT-GPT comprises three tiers. First , we leverage established encoders to encode inputs in various modalities, where these representations are projected into language-like representations comprehensible to LLM through a projection layer. Second , we harness an existing open-sourced LLM as the core to process input information for semantic understanding and reasoning. The LLM not only directly generates text tokens but also produces unique 'modality signal' tokens that serve as instructions to dictate the decoding layers on whether and what modal content to output correspondingly." (Section 1 Introduction)
- Only 1% trained (authors): "By leveraging the existing well-trained high-performing encoders and decoders, NExT-GPT is tuned with only a small amount of parameter (1%) of certain projection layers, which not only benefits low-cost training but also facilitates convenient expansion to more potential modalities." (Abstract)
- The arithmetic (authors): "This amounts to, 155M(=28+33+31+31+32) / [155M + 12.275B(=1.2+7+1.3+1.8+0.975)], or only 1% of parameters need to be updated." (Section 3). Note: 155M / 12.43B = 1.25%, so "1%" is rounded down.
- Components, Table 1 (authors): encoder "ImageBind 1.2B"; input projection "Grouping 28M"; LLM "Vicuna 7B" with "(LoRA 33M )"; output projections "Transformer 31M" (image), "Transformer 31M" (audio), "Transformer 32M" (video); decoders "SD 1.3B", "AudioLDM 975M", "Zeroscope 1.8B". (Table 1: "Summary of NExT-GPT system configuration. Only 1% of parameters need updating during fine-tuning.")
- Decoders named (authors): "we employ the current off-the-shelf latent conditioned diffusion models of different modal generations, i.e., Stable Diffusion ( SD-v1.5 ) for image synthesis ( Rombach et al., 2022 ) , Zeroscope ( v2-576w ) for video synthesis ( Cerspense, 2023 ) , and AudioLDM ( l-full ) for audio synthesis ( Liu et al., 2023a ) ." (Section 3, Multimodal Generation Stage)
- LLM (authors): "Technically, we employ the Vicuna (7B-v0) ( Chiang et al., 2023 )" (Section 3)

## 7. Moshi and Mimi (Kyutai)

Source: "Moshi: a speech-text foundation model for real-time dialogue", Défossez et al., Kyutai; arXiv:2410.00037v2, 02 Oct 2024. https://arxiv.org/html/2410.00037v2

- Mimi: 12.5 Hz, 8 codebooks of 2048, 1.1 kbps, CONFIRMED (lab): "Quantization rate. We use Q = 8 quantizers, each with a codebook size of N A = 2048 . (Abstract)

## 8. Cascade (ASR + LLM + TTS) latency in primary sources

- Moshi abstract (lab, qualitative): "Current systems for spoken dialogue rely on pipelines of independent components, namely voice activity detection, speech recognition, textual dialogue and text-to-speech. Such frameworks cannot emulate the experience of real conversations. First, their complexity induces a latency of several seconds between interactions." (arXiv:2410.00037v2, Abstract)
- Moshi introduction (lab, qualitative): "First, latency compounds along the many components of these pipelines, resulting in a typical global latency of several seconds. This is unlike natural conversations which demonstrate response times of a few hundred milliseconds." (arXiv:2410.00037v2, Section 1; the preceding sentence cites ChatGPT voice via https://openai.com/index/chatgpt-can-now-see-hear-and-speak/ as an example)
- OpenAI, a concrete cascade number (vendor, about its own old product): "latencies of 2.8 seconds (GPT-3.5) and 5.4 seconds (GPT-4) on average" for the three-model Voice Mode pipeline (Hello GPT-4o, 2024-05-13; see Section 1 above).
- Qwen3-Omni (vendor, qualitative only): claims "lower end-to-end latency" than "cascaded pipelines" without a cascade number (Section 7).
- Qwen2.5-Omni: no cascade latency figure found.
- UNCONFIRMED: any independent, per-component breakdown (ASR ms + LLM TTFT ms + TTS first-audio ms) of a typical cascade in these primary sources. None of the sources above gives one; the only numeric cascade figures are OpenAI's own 2.8 s / 5.4 s.

## Disagreements and cautions (summary)

1. GPT-4o latency 232 / 320 ms is a vendor claim with no stated measurement setup; Moshi's 160 / 200 ms and Qwen3-Omni's 234 ms are also self-reported, and Qwen3-Omni calls its figure "theoretical" (cold start, 1 concurrency, audio; 547 ms for video; 1172 ms at 6 concurrency). These numbers are not measured the same way and should not be ranked against each other as if they were.
2. GPT-4o image generation: "autoregressive model natively embedded" (addendum) vs invoked as a "tool" that the chat model can decline to trigger (same document, Section 2.2). Both are true at different levels (model vs product); write carefully.
3. Gemini 2.5: architecture section says native multimodal *inputs*; audio output and image generation are described as separate model offerings (Native Audio Dialog, TTS, 2.0 Flash Native Image Generation).
4. AnyGPT Table 1 music vocab 4096 vs text 8192.
5. NExT-GPT "1%" is 1.25% by its own arithmetic.
6. Qwen3-Omni: "Talker no longer consumes the Thinker's high-level text representations" (Section 2.1) vs Talker conditioned on "historical textual tokens ... and the current turn's streamed text" (Section 2.4): tokens yes, hidden text representations no.
7. Qwen2.5-Omni licence differs by size: 7B Apache 2.0, 3B "qwen-research".
