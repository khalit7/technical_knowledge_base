3. Why a plain autoencoder does not generate

The problem. To generate, you pick a code and decode it. But which codes are valid? A plain autoencoder never says. Training only ever decodes the codes of real images, so the code space is a scattered cloud, with gaps between the clusters and at a scale nobody chose. A random code lands in a gap, or in the wrong place entirely.

Ghosh et al. made this point with deterministic "regularised autoencoders" plus a density fitted afterwards ({{From Variational to Deterministic Autoencoders, 2019|https://arxiv.org/abs/1903.12436}}) published. All of these tiny generators are far from the floor: a one-shot decoder from a simple Gaussian cannot model the data's many modes; this is why modern systems put a diffusion or autoregressive model on top of the latent instead of sampling it directly.

4. The VAE: an encoder that outputs a distribution

How it works. The VAE's encoder outputs, for each latent dimension, a mean μ and a log-variance log σ2: a little Gaussian per image instead of a point. Training decodes a random draw from it, and adds a penalty that pulls every image's Gaussian towards N(0, I):

z = μ(x) + σ(x) · ε,   ε ~ N(0, I)     loss = reconstruction(x, decoder(z)) + β · ½ Σj (μj2 + σj2 − 1 − log σj2)
ε
the randomness, drawn outside the network: the reparameterisation trick. Sampling z directly would block gradients; writing it as μ + σε makes z a differentiable function of μ and σ
KL
the second term is KL(N(μ, σ2) ‖ N(0, I)) in closed form, in nats: zero only when μ = 0 and σ = 1 (the code carries nothing)
β
1 gives the negative ELBO, the standard VAE loss; the derivation is on {{Variational inference and generative-model maths|n:3f05c17b0d0d81aa9857eb5fa1bac530}} (sections 7 to 10). Section 6 below varies it

The code that trained every VAE on this page (the topic's shared code; src/data/nets.py lines 249 to 252 and objectives.py lines 130 to 136):

def forward(self, x): # ConvVAE mu, logvar = self.encode(x) z = mu + torch.exp(0.5 * logvar) * torch.randn_like(mu) # the reparameterisation trick return self.decode(z), mu, logvar def vae_loss(model, x, y=None, beta=1.0): """Negative ELBO (beta = 1) per image: reconstruction + beta * KL(q(z|x) || N(0, I)).""" logits, mu, logvar = model(x) rec = recon_bce(logits, x) kl = 0.5 * (mu.pow(2) + logvar.exp() - 1 - logvar).flatten(1).sum(1).mean() loss = rec + beta * kl return loss, {"loss": loss.item(), "rec": rec.item(), "kl": kl.item()}

The cost, measured. On the 10,000 test images the 16-number VAE pays nats of KL per image, and its reconstruction is worse than the plain autoencoder's: against nats, against dB PSNR. In return its codes sit where N(0, I) expects them. In the 2-number VAE the encoder's σ averages : each image claims a tiny ellipse of a space whose overall spread is 1 (click a point in the right-hand explorer above to see its ellipse).

When it matters, how to check. Watch the KL per dimension: a dimension whose KL is near 0 is unused (its μ is always about 0 and σ about 1); "active units" counts dimensions whose μ varies across images by more than 0.01 ({{Burda et al. 2015|https://arxiv.org/abs/1509.00519}}). The 16-number VAE at beta 1 uses of 16. When nearly all go inactive the decoder is ignoring the code: posterior collapse, common with strong decoders such as autoregressive ones (the Math page derives it).

Pixel mixing gives a ghost of both garments at every step. Both latent paths give single garments that change shape. The VAE's middle frames tend to be the cleaner (its decoder was trained on noisy codes, so the space between two images is familiar ground), while the autoencoder's can turn blotchy; at this scale the difference is small, and the VAE's clear advantage is off the data, in the random-code test of section 3. In large latent diffusion models the same idea is used through the noise: interpolate the starting noise (spherically, since Gaussian noise lives near a sphere) rather than the clean latent ({{DDIM, section 5.3 and Appendix D.5|https://arxiv.org/abs/2010.02502}}).
