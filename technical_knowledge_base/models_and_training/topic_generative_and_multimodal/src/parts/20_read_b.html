1. What a generative model is, and the five families

The problem. A 28 × 28 greyscale image is a list of 784 numbers, a point in a 784-dimensional space. Almost every point in that space is static; the images that look like clothing occupy a tiny, oddly shaped region of it. We never get a formula for that region, only examples from it (the training set). We call the unknown rule that produced the examples the data distribution, written p(x). A generative model is a recipe for drawing new points from (an approximation of) that region. Some families can also score a given image, reporting how probable the model finds it (its likelihood); others can only sample. A conditional model draws from p(x | c), where the condition c is a class label or a text prompt.

Every pixel depends on many others (a sleeve on the left implies one on the right); the five families are five ways to capture that, and differ mostly in network calls per sample and training signal.

Autoregressive. Write the image as a sequence and predict each element from the ones before it: p(x) = ∏ p(xi | x<i), the same chain rule a language model uses, trained with the same cross-entropy loss. Likelihood is exact. Early models predicted raw pixels and gave poor samples (Gated PixelCNN: FID 65.93 on CIFAR-10, {{DDPM Table 1|https://arxiv.org/html/2006.11239v2#S4.T1}}); later ones predict image tokens from a learned codebook (section 2): Parti treated text-to-image "as a sequence-to-sequence modeling problem" and scaled to 20B parameters ({{Yu et al. 2022|https://arxiv.org/abs/2206.10789}}). The cost is one network call per token, in order.

VAE (variational autoencoder, {{Kingma and Welling, Dec 2013|https://arxiv.org/abs/1312.6114}}). Encode an image to a short code kept close to a standard Gaussian, decode it back; a random Gaussian code then decodes to something sensible. One call per sample, but blurry (section 2).

GAN (generative adversarial network, {{Goodfellow et al., June 2014|https://arxiv.org/abs/1406.2661}}). A generator turns noise into an image; a discriminator tries to tell its images from real ones; "the training procedure for G is to maximize the probability of D making a mistake". Sharp images in one call, but no likelihood, notoriously unstable training, and mode collapse: the generator finds a few outputs that fool the judge and stops covering the rest of the data.

Diffusion ({{Ho et al., June 2020|https://arxiv.org/abs/2006.11239}}). Destroy training images by adding Gaussian noise in many small steps, and train a network to undo one step. To generate, start from pure noise and apply the network again and again. DDPM reached FID 3.17 on CIFAR-10, the best unconditional score in its table ({{DDPM page|n:3c65c17b0d0d811481e4e36333454f7a}}).

Flow matching ({{Lipman et al. 2022|https://arxiv.org/abs/2210.02747}}; rectified flow, {{Liu et al. 2022|https://arxiv.org/abs/2209.03003}}). Learn a velocity field that carries noise to data along nearly straight paths; generate by following it. Straighter paths need fewer steps.

derived Autoregressive: 1,024 calls, one per token, each waiting for the last (Chameleon encodes "a 512×512 image into 1024 discrete tokens from a codebook of size 8192", {{Chameleon Team 2024|https://arxiv.org/html/2405.09818v1}}). Diffusion: 30 steps × 2 (conditional and unconditional pass) = 60 calls, and diffusers runs the two passes of a step as one batch of 2 (torch.cat([latents] * 2), {{pipeline_stable_diffusion.py line 1037, v0.41.0|https://github.com/huggingface/diffusers/blob/v0.41.0/src/diffusers/pipelines/stable_diffusion/pipeline_stable_diffusion.py#L1037}}), so 30 sequential rounds; 1,024 / 60 ≈ 17. But each autoregressive call reuses a cache and processes one new token, while each diffusion call processes the whole image: counting calls alone is not counting compute (section 10).
