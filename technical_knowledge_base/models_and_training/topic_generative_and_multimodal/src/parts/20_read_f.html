Common mistakes

Decoding latents without the VAE's scaling factor, or with another model's

Stable Diffusion v1 latents are multiplied by 0.18215 before diffusion and divided by it before decoding; each later autoencoder has its own factor (FLUX's 16-channel one uses 0.3611). Skip it and the denoiser sees latents about 5.5 times too large, so its noise schedule is wrong for them; use another model's and the decoder gets the wrong scale. Read it from the loaded model (vae.config.scaling_factor), never from memory, and check where it came from: the pinned Stable Diffusion v1.5 vae/config.json has no scaling_factor entry at all, so diffusers silently falls back to its class default of 0.18215 ({{autoencoder_kl.py line 90, v0.41.0|https://github.com/huggingface/diffusers/blob/v0.41.0/src/diffusers/models/autoencoders/autoencoder_kl.py#L90}}), which is right for this checkpoint and wrong for any other autoencoder saved the same way (section 2). Comparing FIDs computed at different sample counts or with different code

FID is biased upwards at small sample counts, and resizing, compression and the reference set move it (section 9). Two samples drawn from the same distribution still get a positive FID, and it shrinks as the count grows: 

import numpy as np
from scipy import linalg

def fid(a, b):  # the Frechet distance FID uses, on any features
    m1, m2 = a.mean(0), b.mean(0)
    s1, s2 = np.cov(a, rowvar=False), np.cov(b, rowvar=False)
    covmean = linalg.sqrtm(s1 @ s2).real
    return float(((m1 - m2) ** 2).sum() + np.trace(s1 + s2 - 2 * covmean))

d = 64                                   # Inception features have 2,048 dimensions; 64 keeps this fast
rng = np.random.default_rng(0)
A = rng.normal(size=(d, d)) / np.sqrt(d)
cov = A @ A.T + 0.1 * np.eye(d)          # one fixed "true" feature distribution
L = np.linalg.cholesky(cov)
draw = lambda n: rng.normal(size=(n, d)) @ L.T

for n in [500, 2000, 10000, 50000]:
    scores = [fid(draw(n), draw(n)) for _ in range(3)]
    print(f"n = {n:>6}: FID between two samples of the SAME distribution = {np.mean(scores):.4f} (3 draws: {', '.join(f'{s:.4f}' for s in scores)})")
n =    500: FID between two samples of the SAME distribution = 3.3324 (3 draws: 3.3952, 3.3297, 3.2723)
n =   2000: FID between two samples of the SAME distribution = 0.8557 (3 draws: 0.8410, 0.8715, 0.8546)
n =  10000: FID between two samples of the SAME distribution = 0.1669 (3 draws: 0.1666, 0.1617, 0.1726)
n =  50000: FID between two samples of the SAME distribution = 0.0331 (3 draws: 0.0338, 0.0334, 0.0322)

measured on Apple M1 Pro CPU (numpy 2.5.4, scipy 1.18.1; src/read/fid_bias.py). The true distance is 0; the estimate falls roughly as 1 / n, and with 2,048 Inception dimensions instead of 64 the bias is far larger. So "FID 3.3" at 500 samples and "FID 0.03" at 50,000 can be the same model: compare only at equal n, and prefer 50,000.

Mixing up the two guidance-scale conventions

The paper writes ε = (1 + w) εcond − w εuncond; libraries write εuncond + s(εcond − εuncond), so s = 1 + w, and "guidance 7.5" in diffusers is w = 6.5 ({{math page, section 17|n:3f05c17b0d0d81aa9857eb5fa1bac530}}). Scale 1 in the library convention means no guidance at all.

A scheduler that does not match how the model was trained

The sampler must know what the network predicts (noise, clean image or v), which way time runs (diffusion papers put data at t = 0; Lipman et al.'s flow matching puts noise there) and the training schedule. A mismatch still produces images, just bad ones: washed out, noisy or over-contrasted. In diffusers the scheduler's prediction_type and schedule come from the checkpoint's scheduler/scheduler_config.json; swap samplers with from_config so they inherit it.

Training on images in [0, 1] (or [0, 255])

The forward process assumes data on the scale of unit-variance noise: DDPM scales pixel values "linearly to [−1, 1]" ({{Ho et al. 2020, section 3.3|https://arxiv.org/html/2006.11239v2#S3.SS3}}). Unscaled data changes the effective signal-to-noise ratio at every timestep; samples look grey or blown out. Clip predicted clean images to the data range while sampling.

Counting steps instead of network passes

Guidance doubles the passes per step; some solvers make two passes per step (Heun's method, as in {{EDM|https://arxiv.org/abs/2206.00364}}). Compare samplers and models by passes (and by time on the same hardware), not by the step count printed in a config (section 10).

Reading CLIPScore as image quality

It measures agreement with the prompt as CLIP sees it: a sharp image and a mushy one with the right objects score alike, and CLIP cannot count or check relations (section 5). Pair it with a fidelity metric, GenEval-style checks and human preference.

Judging a VLM by its captions

Fluent captions hide hallucination. Ask yes/no questions about objects that are absent as well as present (POPE), report the yes rate on absent objects, and run a text-only baseline with the image removed: questions it still answers are not testing vision (section 9).

Shrinking the image until the text is unreadable

A VLM's processor resizes or tiles the image to fit a token budget. Small text that falls below a patch or two is gone before the language model sees it; raise the resolution or the tile count, and watch the token count and the context it uses (section 6).

Interview questions

Short answers; answer first, then open. The design questions have no single right answer: name the constraint that decides it.

Why are VAE samples blurry, and why is Stable Diffusion's autoencoder sharp?
A Gaussian (squared-error) reconstruction loss is minimised by the mean of the images consistent with the code, and the mean of several sharp images is blurry; the KL term forces codes to overlap, which leaves more of them ambiguous. Stable Diffusion's autoencoder barely regularises the latent (KL weight about 10−6) and adds a perceptual loss and a patch adversarial loss, which reward realistic texture over the average. It is a compressor, not a generator: the diffusion model does the generating.
Explain diffusion training and sampling in one minute.
Training: take an image, pick a random noise level, mix in that much Gaussian noise with the closed form xt = √āt x0 + √(1 − āt) ε, and train a network to predict the noise with a squared error. Sampling: start from pure noise and repeatedly use the predicted noise to step to a slightly less noisy image, 20 to 50 times with a deterministic sampler. The network never generates in one go; it only ever denoises a little.
Diffusion against flow matching: what is actually different?
The path from noise to data (a variance-preserving curve against a straight line), what the network predicts (noise against velocity) and how training weights the noise levels. Both define an ODE that is integrated at sampling, and Gaussian diffusion paths are a special case of flow matching. Straight paths are easier to integrate with large steps, so flow models need fewer steps and distil well to 1 to 4.
What is classifier-free guidance, what does it cost, and what goes wrong at high scale?
Train one network with and without the condition (drop it some of the time); at sampling extrapolate from the unconditional prediction through the conditional one. It costs a second pass per step (2× compute, though batched). Too high a scale over-saturates colours, reduces variety and pushes samples off the data; a little guidance also rescues too-short samplers. Distilled models often fold guidance in and run one pass.
How does an image become tokens in a VLM, and how many?
A ViT encoder cuts the image into patches (14 or 16 pixels) and outputs one vector per patch; a projector (linear or MLP) maps them into the language model's embedding space, often after merging neighbours; they replace an image placeholder in the prompt. Count = (side / patch)2 per tile, divided by any merge factor, times the number of tiles: LLaVA-1.5 at 336 pixels and patch 14 is 576. More resolution reads smaller text and costs quadratically more tokens.
Design: why does your VLM hallucinate, and how do you measure and reduce it?
Causes: the language prior is strong (objects that usually co-occur get mentioned), the encoder lost the detail (resolution, too few tokens), and instruction data rewarded long confident descriptions. Measure with a POPE-style probe (balanced yes/no questions about present and absent objects, with random, popular and co-occurring absent objects; report the false-yes rate), a caption metric such as CHAIR ({{Rohrbach et al. 2018|https://arxiv.org/abs/1809.02156}}), and a text-only baseline. Reduce with higher resolution or tiling, better or unfrozen encoders, grounded and negative examples in instruction data (questions whose answer is "no"), preference tuning against hallucinated answers, and decoding that refuses to guess. Re-measure on held-out images, with error bars.
Design: a text-to-image system that returns an image in under 1 second.
Budget the passes: time one denoiser pass at the target resolution on the target GPU and multiply. 50 steps with guidance is 100 passes, so unless a pass takes under 10 ms it cannot meet 1 s, before the text encoder and decoder. Use a model distilled to 1 to 4 steps with guidance folded in (adversarial or consistency distillation), bf16 or fp8 weights, a compiled graph, the text encoder output cached for repeated prompts, and a fast decoder (or a tiny distilled decoder for previews). Generate at 512 to 768 and upscale if needed; batch requests per GPU; keep a few-step preview then refine path for quality. Measure the latency distribution, and check quality against the slow model with preference tests, because distillation loses variety.
Why can FID disagree with people?
It measures distance between Gaussian fits of Inception-v3 features, an ImageNet classifier's view: it is sensitive to ImageNet class statistics, resizing and compression, biased by sample count, and blind to prompt following and text rendering. For text-to-image work, report it next to prompt-alignment checks, CLIP-feature distances such as CMMD, and human preference.
CLIP's loss against SigLIP's: what changes?
CLIP applies a softmax over all captions in the batch for each image (and vice versa), so every pair's loss depends on the whole N × N similarity matrix. SigLIP scores each pair independently with a sigmoid (match or not, with a learned bias), so no global normalisation is needed: cheaper to shard across devices, better at small batches, and able to grow the batch further.
A multimodal LLM should also generate images: autoregressive tokens or diffusion?
Discrete tokens reuse the language-model stack, loss and serving (Chameleon, and, per its system card, GPT-4o image generation), but cost one pass per token and lose detail in the tokenizer. Diffusion or flow on continuous latents gives better images per FLOP and runs in tens of passes, but needs a second objective and sampler (Transfusion puts both in one transformer; others attach a separate diffusion decoder). Choose by what you must share (one context, editing in conversation), the latency budget and the quality bar.
