How a model turns pixels into something it can compare with words, from zero, on real weights: CLIP ViT-B/32 and SigLIP 2 base (patch 16), run here on the topic’s running example (the 16 colour test images and the 10,000 Fashion-MNIST test images). Every number marked measured was computed for this page on an Apple M1 Pro, on the CPU (float32, 4 threads), on 2026-10-17; published numbers are quoted from the paper that states them; derived numbers show their formula.

In one screen
  • A vision transformer cuts an image into square patches, turns each into a vector with one shared matrix, adds a learned position vector, and from then on treats the image as a sequence of tokens, like words.
  • CLIP and SigLIP train an image tower and a text tower together so that a picture and its caption land close together. CLIP uses a softmax over the whole batch; SigLIP judges every image-caption pair on its own with a sigmoid, which needs no batch-wide sum and so shards more cheaply.
  • That shared space gives zero-shot classification: write one sentence per class, pick the nearest. On Fashion-MNIST it works far above chance but well below a probe trained on a few hundred labels: the information is in the embedding, the prompts only get part of it out.
  • The embedding keeps what helps match captions and loses much else: a written word can override the object, and counting, left and right, and which colour belongs to which shape are close to guesses.

1. An image as a sequence of patches

The problem. A transformer reads a sequence of vectors. An image is a grid of pixels: 224 × 224 × 3 = 150,528 numbers. Treating every pixel as a token would give 50,176 tokens and about 2.5 billion attention scores per head per layer derived: 224² = 50,176; 50,176², far too many. The Vision Transformer (ViT, {{Dosovitskiy et al., October 2020|https://arxiv.org/abs/2010.11929}}) groups pixels into square patches instead: its title, “An Image is Worth 16x16 Words”, is the patch size.

How it works. Cut the image into a grid of P × P patches; unroll each into a vector of 3P² numbers; multiply every one by the same learned matrix (the patch embedding) to get a token of width D (768 for both models here); add a learned position embedding, one vector per slot, so the model can tell where each patch was; optionally prepend a learned summary token, [CLS]; run the transformer; and pool the output into one image vector, either by taking the [CLS] output (CLIP) or with a small attention layer whose learned query looks at every patch (SigLIP’s MAP head, multihead attention pooling). On SigLIP 2’s fixed pooling slots compare {{Vision Transformers Need Registers (Darcet et al., September 2023)|https://arxiv.org/abs/2309.16588}}: “high-norm tokens appearing during inference primarily in low-informative background areas of images, that are repurposed for internal computations”. Switch the model to see the same image as 49 coarse tokens or 196 fine ones.

“A convolution” is just this matrix. Both models implement the patch embedding as a 2-D convolution with kernel size and stride equal to the patch size, which is the same arithmetic as cutting, flattening and multiplying. The check below cuts the five images above into patches with unfold, multiplies by the convolution’s own weights reshaped into a matrix, and compares with the model’s convolution (from src/vision/analyse.py; output from the run):

conv = emb.patch_embedding(pv).flatten(2).transpose(1, 2)                         # the model's own way
cols = torch.nn.functional.unfold(pv, kernel_size=ps, stride=ps).transpose(1, 2)  # cut and flatten
W = emb.patch_embedding.weight.reshape(emb.patch_embedding.weight.shape[0], -1)   # one matrix
mm = cols @ W.T + (emb.patch_embedding.bias if emb.patch_embedding.bias is not None else 0)
print((mm - conv).abs().max())

Output: 0.0 for CLIP (a 768 × 3,072 matrix, no bias, 2,359,296 parameters) and 6.9e-06 for SigLIP 2 (768 × 768 plus a bias, 590,592 parameters), float32 rounding measured. The convolution is the efficient way to write “cut, flatten, multiply”; nothing convolutional happens across patches.

The cost. Tokens grow with the square of resolution over patch size: N = (224 / P)², and attention per layer grows with N². Halving the patch from 32 to 16 quadruples the tokens (49 to 196) and multiplies attention scores by about 15 (2,500 to 38,416 with CLIP’s [CLS]) derived. That is the same trade a vision-language model makes when it decides how many image tokens to put in a prompt ({{VLM lab|#t-vlm}}). On the CPU here CLIP B/32 embedded 119 Fashion-MNIST images per second (15,000 in 126 s) and SigLIP 2 B/16 23 per second (15,000 in 654 s) measured; a 5.2× gap; part of it is the 4× token count, part the different software paths, so the ratio is not a clean measure of either.

When it matters, how to check. Fine detail (small text, thin lines, counting small things) needs small patches or higher resolution; a 32-pixel patch sees a whole word as one blob. Check a model’s patch_size and image_size in its config.json, and what its processor does to your image (CLIP resizes the short side to 224 and centre-crops, so a wide image loses its edges; SigLIP 2’s processor squashes to 224 × 224 without cropping).

2. Convolutions against attention, and learning without captions

Inductive bias. A convolutional network (CNN) slides small filters (3 × 3 pixels, say) over the image, so each layer only mixes neighbours and the same filter is used everywhere. Those two built-in assumptions (nearby pixels belong together; a pattern means the same thing anywhere) are its inductive bias: they make it learn from little data, and they limit what one layer can see. A stack of L such layers (stride 1) sees a window of only 2L + 1 pixels derived; real CNNs downsample to see further. A ViT has neither assumption: from the first layer every patch can attend to every other, and it must learn locality from data. The ViT paper found that this costs it on small datasets and pays off at scale: it beat the best CNNs of 2020 only after pre-training on hundreds of millions of images (the {{ViT page|n:3c65c17b0d0d811fa231cfcde6c1954d}} animates one image through a ViT and a ResNet and retrains both at toy scale). The position-similarity step above shows the learned version of locality in released weights: nobody told either model that the grid is 2-D.

Learning without captions. Labels are scarce, so most vision encoders are pre-trained on a proxy task. Self-supervised methods use the images alone. MAE masks “a high proportion of the input image, e.g., 75%” of the patches and learns to reconstruct the missing pixels, running the encoder on the visible patches only ({{He et al., November 2021|https://arxiv.org/abs/2111.06377}}). DINO trains a student network to match a slowly updated teacher copy of itself across different crops of the same image, “a form of self-distillation with no labels”, and its ViT features turn out to contain “explicit information about the semantic segmentation of an image” ({{Caron et al., April 2021|https://arxiv.org/abs/2104.14294}}). These give strong features for dense tasks (segmentation, depth, matching) but no link to words; image-text training (next section) gives that link. SigLIP 2 combines both: it adds “captioning-based pretraining, self-supervised losses (self-distillation, masked prediction) and online data curation” to the sigmoid loss ({{Tschannen et al., February 2025|https://arxiv.org/abs/2502.14786}}). Collapse, MAE against I-JEPA and InfoNCE on a real text batch are taught on {{Contrastive and self-supervised learning|n:3c65c17b0d0d811db6a7d02d0ee7215c}}.
