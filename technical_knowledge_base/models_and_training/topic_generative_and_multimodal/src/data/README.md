# The running example of Topic: generative-and-multimodal

Every lab on the root page works on the same images, the same tiny models and the same pretrained checkpoints, so that a reconstruction in the Latent lab, a noised image in the Diffusion lab, a flow path in the Flow lab, a patch grid in the Vision lab and an image-token count in the VLM lab are all about the same objects. This folder holds the definition (this file), the shared code every lab imports, the scripts that built and smoke-tested everything, their small results (`smoke/`), the fixed test images as small thumbnails, and a manifest of every artefact with size and sha256 (`manifest.json`). Large files (the dataset arrays, checkpoints, FID statistics, full-size test images, the venv, pinned source clones) stay outside the repo in the shared setup folder named by the environment variable `GM_SCRATCH`; the Hugging Face weights stay in the standard cache (`~/.cache/huggingface`, `HF_HOME` unset).

Built on 2026-10-17. Machine: Apple M1 Pro (10 CPU cores, 16 GB unified memory), macOS 27.0.1. GPU work runs on MPS (PyTorch's Metal backend) at low priority (`nice -n 15`, 4 CPU threads) on a machine shared with other agents. Timings are rough and labelled "measured on Apple M1 Pro (MPS)"; shapes, parameter counts and losses at a fixed seed are deterministic up to MPS kernel non-determinism.

## The dataset: Fashion-MNIST

Chosen over CIFAR-10 and flower or face sets for four reasons: (1) a clear licence: MIT, Copyright (c) 2017 Zalando SE ([LICENSE](https://github.com/zalandoresearch/fashion-mnist/blob/master/LICENSE)), where CIFAR-10 has no stated licence and the face and flower sets have mixed or unclear terms; (2) size: a 1M-parameter U-Net learns recognisable 28x28 samples in minutes on this laptop's GPU, which a colour 32x32 or 64x64 set does not; (3) labels: 10 balanced classes give class-conditional generation and classifier-free guidance without text; (4) it is not MNIST: digits are too easy to judge by eye, while clothing has texture, shape and class confusions (shirt vs T-shirt vs pullover vs coat) that show blur, mode dropping and guidance effects. The cost: grey, low resolution, and far from the photographs Inception was trained on, so FID values here are only comparable within this topic (see FID below).

Paper: Xiao, Rasul, Vollgraf, "Fashion-MNIST: a Novel Image Dataset for Benchmarking Machine Learning Algorithms", arXiv:1708.07747 (2017).

Fixed splits (`prepare_data.py`, recorded in `splits.json` with hashes of the index arrays and of the image arrays):
- **train**: 55,000 of the official 60,000 training images; **val**: the other 5,000, chosen by `np.random.default_rng(0).permutation(60000)[:5000]`; **test**: the official 10,000 (1,000 per class).
- Classes: 0 T-shirt/top, 1 Trouser, 2 Pullover, 3 Dress, 4 Coat, 5 Sandal, 6 Shirt, 7 Sneaker, 8 Bag, 9 Ankle boot.
- Model format (`common.to_model`): uint8 28x28 to float in [-1, 1], padded with 2 pixels of background (-1) to **1x32x32**, so a U-Net can halve it to 16 and 8. `common.from_model` crops back to 28x28 uint8. Training-set pixel mean 72.98 and std 90.03 (uint8 scale): most pixels are background.
- Minibatches (`common.batches`) are an endless shuffle with a fixed seed, identical across labs.

**The 16 fixed test images** (`test16/`, committed, 28x28 PNG, 300 to 600 bytes each, plus `grid_8x2.png`): the first test image of each class 0 to 9, then the second test image of classes 0 to 5. Test-set indices `[19, 2, 1, 13, 6, 8, 4, 9, 18, 0, 27, 3, 16, 29, 10, 11]`, labels `[0..9, 0..5]`. `common.test16()` returns them. Use these for every before/after on the trained models (the same image through the autoencoder, the VAE, the forward noising process, and so on).

## Shared prompts

In `pretrained.PROMPTS` (g01..g06 made the generated test images; all eight are for step, guidance and scheduler comparisons):
g01 "a photograph of a red bicycle leaning against a brick wall"; g02 "a photograph of a bowl of oranges on a wooden table"; g03 "a photograph of a lighthouse on a cliff at sunset"; g04 "a photograph of a golden retriever puppy sitting on grass"; g05 "a photograph of a stop sign on a snowy street"; g06 "an astronaut riding a horse on the moon, digital art"; x07 "a white mug on a desk with the word HELLO printed on it" (text rendering); x08 "two cats and three dogs sitting on a sofa" (counting, attribute binding).
Generation defaults (`pretrained.GEN`): 512x512, 25 steps, guidance scale 7.5, DPMSolverMultistepScheduler built from the repo's scheduler config, no negative prompt, initial noise from `torch.Generator("cpu").manual_seed(seed)` so it is the same on any device.

## Pretrained models (inference only)

All in `~/.cache/huggingface` (downloaded 2026-10-17), loaded only through `pretrained.py`, which pins the exact Hub revision. Licences as stated on the Hub card on 2026-10-17.

| role | repo @ revision | licence | parameters | downloaded | dtype here |
|---|---|---|---|---|---|
| latent diffusion | `stable-diffusion-v1-5/stable-diffusion-v1-5` @ 451f4fe16113 | CreativeML OpenRAIL-M (open weights with use-based restrictions; not OSI open source) | U-Net 859,520,964; VAE 83,653,863; CLIP ViT-L/14 text encoder 123,060,480 | 2.47 GB (fp16 U-Net and text encoder, VAE in fp16 and fp32, configs) | float16 |
| contrastive (softmax) | `openai/clip-vit-base-patch32` @ 3d74acf9a28c | no licence field on the Hub card; the OpenAI CLIP code is MIT; the card restricts deployed use | 151,277,313 | 0.61 GB (float32 .bin only) | float16 |
| contrastive (sigmoid) | `google/siglip2-base-patch16-224` @ 75de2d55ec2d | Apache 2.0 | 375,187,970 (the 256k-token multilingual vocabulary makes the text side large) | 1.54 GB | float16 |
| VLM | `HuggingFaceTB/SmolVLM-500M-Instruct` @ a7da5b986cb5 | Apache 2.0 | 507,482,304 (SigLIP vision encoder, pixel-shuffle connector, SmolLM2 language model) | 1.02 GB | bfloat16 |

Why these: SD 1.5 is the model the classic latent-diffusion explanations describe (8x VAE, 4-channel latent, the 0.18215 scaling factor, a U-Net with cross-attention to CLIP text, real classifier-free guidance at 7.5), fits in fp16 with room to spare, and is not gated. SD-Turbo (distilled, 1 to 4 steps) was considered and left out to keep one generator; its distillation is described from the paper instead. CLIP B/32 is the reference contrastive model; SigLIP 2 is added (small, Apache 2.0) so the Vision lab can set the softmax and sigmoid losses side by side on the same images. SmolVLM-500M is small enough to run many questions per minute and its image splitting makes the token-count lesson concrete; a 2B-class model (Qwen3-VL-2B-Instruct, Apache 2.0) was considered and not downloaded (4 GB; one VLM is enough for the labs).

Facts from the configs: the SD 1.5 VAE config has `latent_channels` 4 and three downsamplings (512x512x3 to 64x64x4) and **no `scaling_factor` key**, so diffusers uses AutoencoderKL's default 0.18215 (`diffusers/models/autoencoders/autoencoder_kl.py:90` at v0.41.0). The repo's scheduler is PNDM with `scaled_linear` betas 0.00085 to 0.012 over 1000 training steps; `pretrained.load_sd` swaps in DPM-Solver multistep (or DDIM or Euler by argument) from that config.

Safety checker: not downloaded and not loaded (`safety_checker=None`); the prompts here are benign.

## FID here

Implementation: torch-fidelity 0.4.0's `FeatureExtractorInceptionV3("inception-v3-compat")`, the 2015 TensorFlow Inception weights (`weights-inception-2015-12-05-6726825d.pth`, sha256 6726825d0af5...) that torchmetrics' `FrechetInceptionDistance` also wraps; 2048-d pool features, images resized to 299 inside the extractor with its TensorFlow-1-compatible bilinear resize; grey images repeated to 3 channels. Features on MPS in float32 (max difference from CPU features 1.8e-5 on 200 images); statistics and the matrix square root on CPU in float64 with scipy (MPS has no float64). Reference statistics in `GM_SCRATCH/fid/` (`inc_test.npz`: the 10,000 test images; `inc_train10k.npz`; `clf_test.npz` for `fd_fmnist`).

**Real-vs-real floors** (`smoke/fid_floor.json`): FID of N real training images against the 10,000 real test images, which is what FID says when nothing is wrong. N = 10,000: 2.54; 5,000: 3.84; 1,000: 15.4 to 15.8; 500: 27.9 to 28.1; 250: 44.9 to 47.4 (three random draws). FID is strongly biased upward at small N: a model scored on 500 samples must be compared with about 28, not with 0 and not with papers' 50,000-sample numbers. Inception never saw grey 28x28 clothing, so absolute FIDs here are not comparable with any paper's.

## The bench lock and memory (every lab)

GPU (MPS) work only while holding the shared bench lock, gated on a successful acquire, released the moment GPU work ends, touched at least every 10 minutes (`train.fit` does it if `GM_LOCK` points at `lock.sh`):
```sh
sh <scratchpad>/inf/guard.sh            # OK or HIGH; if HIGH do light work and check again later
sh <scratchpad>/inf/lock.sh acquire bench <prefix> 3600 && { GM_SCRATCH=... GM_LOCK=.../lock.sh nice -n 15 $GM_SCRATCH/venv/bin/python -I run.py; sh <scratchpad>/inf/lock.sh release bench <prefix>; }
```
One model per process, one process at a time; `common.empty_cache()` between stages. Measured peaks below say what fits: everything here stays under about 4.5 GB except two cases fixed in the shared code (SD without attention slicing peaked at 8.0 GB, so `load_sd` turns slicing on; Inception at batch 100 peaked at 7.1 GB, so `fid.inception_features` uses batch 50).

What the smoke tests already show (the labs will build on these):
- **CLIP and SigLIP 2** each match 15 of 16 images to their own caption; the miss for both is the typographic image s04, matched to the plain cat caption (the two captions are nearly the same). Embedding widths 512 and 768; CLIP's learned logit scale is 100.0 (the clamp), SigLIP 2's scale is 112.4 with bias -16.77.
- **Typographic attack**: CLIP B/32 prefers "a photo of a cat" for the plain cat photo (cosine 0.2845 vs 0.2318) but flips to "a photo of a dog" once the `DOG` sticker is added (0.2775 vs 0.2855). SigLIP 2 does not flip (0.1281 vs 0.1112), and SmolVLM answers "There is a cat in this image."
- **SmolVLM image tokens**: one 512x512 image becomes **1,088 image tokens**: the processor upscales the longest edge to 2,048 (`size.longest_edge`), splits it into 4x4 = 16 tiles of 512 plus one downscaled global view (`pixel_values` shape [1, 17, 3, 512, 512]), and each tile gives 64 tokens (`image_seq_len` 64, after a pixel shuffle with `scale_factor` 4). The whole prompt for a one-sentence question is 1,142 tokens. The chat template begins `<|im_start|>User:<image>Describe this image in one sentence.<end_of_utterance>\nAssistant:` before the processor expands `<image>`.
- **SmolVLM answers**: "In this image we can see a cat." (p01); "3" for the red circles (correct).
- **SD 1.5 generations** (seeds 0 to 5): five follow their prompts; g05 renders a legible `STOP`; g06 ("an astronaut riding a horse on the moon") shows an astronaut on the moon with no horse, a prompt-following failure worth keeping.
