6. Posterior collapse: when the decoder does not need the code

The KL is exactly 0 when the encoder ignores the image and outputs N(0, I) for everyone. If the decoder can reconstruct well without the code, nothing pays for leaving that optimum: posterior collapse. Section 4 caused it with loss units; here a strong decoder does.

A decoder that does not need z. A PixelCNN decoder predicts each pixel from the true pixels above and to its left (masked convolutions) plus the code, so it can predict most of an image from its own context. Here: the topic's VAE encoder (16 numbers), a PixelCNN decoder of one 7 × 7 and five 3 × 3 masked layers, 64 channels, the code added as a learned bias to every layer (src/collapse/pixelvae.py), parameters, the usual recipe.

KL nats per test image, of 16 active units. The direct check: give every test image another image's code (a shuffle) and the reconstruction term gets worse by only nats. The decoder does the job itself. measured

Three fixes, same model, same data. KL annealing ({{Bowman et al. 2016|https://arxiv.org/abs/1511.06349}}): raise the KL weight from 0 to 1 (here over the first half of training) so the encoder learns to carry information before the KL charges for it. Free bits (Kingma et al. 2016, {{IAF|https://arxiv.org/abs/1606.04934}}): do not charge for the first λ nats of each dimension, Σj max(λ, KLj), KLj averaged over the minibatch (here λ = 0.5). Or weaken the decoder: information the decoder can model locally is not worth sending through z, so limit its receptive field to what the code should leave out (Chen et al., {{Variational Lossy Autoencoder|https://arxiv.org/abs/1611.02731}}).

What the runs show. The plain ELBO collapsed completely. Annealing did not save it: the code was used while the weight was small (about 13 nats and all 16 dimensions at step 400), then drained away as the weight reached 1. Free bits kept the code alive, each dimension near the 0.5-nat floor, worth nats of reconstruction, at a price: its true negative ELBO () is worse than the collapsed run's (). By the ELBO's own measure ignoring the code is the better model: with a decoder this strong collapse is the optimum, not an accident (Chen et al.'s point), so if you want a code for downstream use, likelihood alone is the wrong target. measured, one seed each

Costs, and how to check. Annealing and free bits change the objective, so compare models on the true negative ELBO; free bits can leave dimensions carrying exactly λ nats of noise; annealing only delays the KL; a weaker decoder costs likelihood. Collapse threatens any VAE with a powerful decoder (text VAEs, PixelCNN and transformer decoders, some audio and video models). Check KL per dimension and active units over training, and run the shuffle test: if the code does not change the output, it is not used.

Where the fixes come from (provenance)

Bowman et al. anneal "from a vanilla autoencoder to a vae" ({{arXiv 1511.06349|https://arxiv.org/abs/1511.06349}}); DALL-E's dVAE raised its KL weight from 0 to 6.6 over the first 5,000 updates ({{Ramesh et al. 2021, appendix A.2|https://arxiv.org/abs/2102.12092v2}}). Free bits is from the IAF paper's appendix ({{arXiv 1606.04934|https://arxiv.org/abs/1606.04934}}); its appendix C.8 found λ from 0.125 to 2 helpful on CIFAR-10; here λ = 0.5 frees up to 8 nats in total. All four PixelCNN models beat the ordinary-decoder VAE's nats by a wide margin.
