7. Why reconstructions blur, and what fixes it

Pixel-loss autoencoders give soft reconstructions, VAEs more so. Four causes, each with its own fix:

  1. The pixel loss rewards the average. Where the code does not pin down a detail, squared error is minimised by the mean of all images consistent with it, and the mean of slightly different sharp edges is a soft edge (L1's median is the same in kind). Fix: a perceptual or adversarial loss.
  2. Too little rate. A small latent, a high β or a large Gaussian σ leaves more to average over. Fix: more channels or tokens, a smaller KL weight.
  3. The VAE's sampling noise. Training decodes μ + σε, so the decoder hedges against a jittered code; decoding μ at test time helps only a little.
  4. The downsampling factor. At 8 × downsampling a 1-pixel stroke shares a latent cell with 63 other pixels; the decoder redraws it from nothing.

The trade-off you cannot escape. At a given rate, the lowest pixel error and the most realistic output are different targets (Blau and Michaeli, {{The perception-distortion trade-off, 2018|https://arxiv.org/abs/1711.06077}}): a decoder that draws plausible fur where the code was unsure scores a worse PSNR than one that draws the average blur. Judge a tokenizer for generation on realism, not PSNR alone.

8. VQ-VAE: an image as tokens, and keeping the codebook alive

Keep the latent as a grid (here 8 × 8 positions of 8 numbers) and replace each position's vector ze by the nearest of K learned vectors e, the codebook (here K = 128): the image becomes 64 integers ({{van den Oord et al. 2017|https://arxiv.org/abs/1711.00937}}). The lookup has no gradient, so the decoder's gradient is copied to ze unchanged (the straight-through estimator, z_st = ze + (zq - ze).detach()), and two terms train the codebook and keep the encoder near it:

loss = reconstruction + ‖sg[ze] − e‖2 + β ‖ze − sg[e]‖2
sg
stop-gradient: the first extra term (the codebook loss) moves only the codes, the second (the commitment loss, β = 0.25 in the paper, eq. 3, and here) only the encoder

Dead codes. A code that is never the nearest to any encoder output gets no gradient, never moves and is never chosen: codebook collapse. With the usual initialisation (uniform in ±1/K, far smaller than the encoder's outputs) most codes die in the first few hundred steps (the real runs below). Fig. 5 shows the mechanism on a 2-D toy.

  2. Each output snaps to its nearest code. Each colour is one code's share of the points. With the codes bunched in the middle only those on the outside of the bunch win: 8 of 16 win any point; the others (red) get no gradient.
  3. Plain VQ: live codes move to the mean of their points (what the codebook loss does in the limit), dead codes stay put. In this toy they recover as the live codes leave the centre (16 of 16 by training step 5), but usage stays uneven: perplexity 11.3, the effective number of equally used codes. In real training the healing is slow ( of 128 codes used at step 200, below).
  4. Restarts re-seed dead codes on the data. Every 3 steps a code that won nothing jumps to a random encoder output (Jukebox’s restart), so it comes back where the data is: perplexity 12.2.
  5. FSQ [4, 4]: a fixed grid, nothing to learn. Each coordinate is squashed by tanh and rounded to one of 4 levels, so the 16 codes are a fixed grid (drawn where each level sits in the encoder’s units); a code is unused only if the encoder never sends a point there: 15 of 16 here.
  6. LFQ, 2 bits: the sign of each coordinate. In 2-D that is 4 codes, the quadrants (a real LFQ uses log2 K channels: 18 for 218 codes); MAGVIT-v2 adds an entropy penalty so every sign pattern gets used.

The quantizer that trained the tokens here (code)
    def quantize(self, ze):                    # the topic's src/latent/vq.py
        B, D, H, W = ze.shape
        flat = ze.permute(0, 2, 3, 1).reshape(-1, D)
        E = self.codebook.weight
        d = flat.pow(2).sum(1, keepdim=True) - 2 * flat @ E.t() + E.pow(2).sum(1)[None]
        idx = d.argmin(1)
        zq = E[idx].view(B, H, W, D).permute(0, 3, 1, 2)
        return zq, idx.view(B, H, W)
    def forward(self, x):
        ze = self.ae.encode(x)
        zq, idx = self.quantize(ze)
        z_st = ze + (zq - ze).detach()                              # straight-through estimator
        return self.ae.decode(z_st), ze, zq, idx

The fixes in use, each run here on the same tokenizer:

  • Dead-code restarts: re-seed unused codes from random encoder outputs of the current batch (Jukebox, {{Dhariwal et al. 2020, section 3.1|https://arxiv.org/abs/2005.00341}}).
  • EMA codebook: each code becomes a moving average of the outputs assigned to it (decay 0.99, Laplace-smoothed counts; VQ-VAE appendix A.1). Stabler, but a code that wins nothing still does not move.
  • Normalised codes: L2-normalise ze and the codebook, so every code lives on the data's sphere, usually with 8 to 32-number codes (ViT-VQGAN's "factorized codes", {{Yu et al. 2021, section 3.2|https://arxiv.org/abs/2110.04627}}).
  • Not run here: k-means initialisation on the first batch's encoder outputs (SoundStream, which also uses EMA and restarts: {{Zeghidour et al. 2021, section III-C|https://arxiv.org/abs/2107.03312}}) and the rotation trick, a better-than-copied gradient ({{Fifty et al. 2024|https://arxiv.org/abs/2410.06424}}).
