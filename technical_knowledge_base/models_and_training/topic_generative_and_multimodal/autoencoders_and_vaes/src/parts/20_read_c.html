2. The ELBO in working form: two numbers, and their units

The problem. The VAE's loss is the negative ELBO (evidence lower bound): a reconstruction term plus a KL term. The derivation is on {{the Math page|n:3f05c17b0d0d81aa9857eb5fa1bac530}} (section 4). In practice the trouble is not the derivation but the units: the two terms are only balanced as the derivation intends when both are log-probabilities of a whole image, in the same unit. Change how either is summed or averaged and you have silently changed β.

loss per image =
−log p(x | z)  [summed over all pixels]
+ β · KL(q(z | x) ‖ N(0, I))  [summed over all latent dimensions]
−log p(x | z)
the reconstruction term, in nats (natural-log units) for the whole image: Bernoulli cross-entropy for the topic's tiny models, a Gaussian (squared error) or Laplace (absolute error) likelihood elsewhere
KL
the rate: how many nats of information the code carries about this image, on average; 0 means the code says nothing
β
1 for the true ELBO; the Latent lab sweeps it from 0.1 to 10

Reading the two numbers. The parent lab's 16-number VAE at β = 1 ends at nats of reconstruction plus nats of KL per test image: nats, or bits per pixel (divide by 1,024 pixels and by ln 2) derived. The KL is the code's budget: bits per image, about the size of a short sentence, and the reconstruction term says how much of the image those bits fail to pin down.

The Gaussian decoder and σ. With a squared-error loss the decoder is implicitly a Gaussian with a fixed standard deviation σ per pixel: −log p(x | z) = Σ (x − x̂)2 / (2σ2) + a constant. Writing plain "MSE summed + KL" fixes σ2 = 1/2. So σ is a β: relative to the summed squared error, the KL's weight is 2σ2 derived. Measured on pixels scaled to [−1, 1]: with σ = 1 the code carries nats and reconstructs at dB; with σ = 0.1, which makes squared error 100 times more expensive, it carries nats and reconstructs at dB, but its random-code samples get worse (prior FD against ): the β trade-off of the Latent lab, reached by changing a "noise level" nobody thinks of as a weight. All 16 dimensions stay active in both. measured Learning σ instead of fixing it is one fix; the LDM autoencoder learns a single log-variance for its whole reconstruction term (nll_loss = rec_loss / torch.exp(self.logvar) + self.logvar, {{contperceptual.py line 53|https://github.com/CompVis/latent-diffusion/blob/a506df575647/ldm/modules/losses/contperceptual.py#L53}}), so its effective weight between reconstruction and KL moves during training.

A detail of that loss worth knowing. In the same function the LPIPS distance, one number per image, is added to the L1 error of every pixel before the sum (lines 48 to 51 and 57: rec_loss = rec_loss + self.perceptual_weight * p_loss, then torch.sum(...) / shape[0]), so the perceptual term counts once per pixel and channel, 786,432 times at 512 × 512. The KL, summed over the latent and weighted by 10−6 (line 83), is tiny against it by design. source read at CompVis/latent-diffusion a506df575647

When it matters, how to check. Whenever you write a VAE loss by hand or port one: log the reconstruction and the KL separately and in nats per image, check that the reconstruction's reduction is a sum over pixels (or that β has been rescaled to match), print the KL per latent dimension, and count active units. A KL near zero with a fine-looking loss curve is the signature of every case above.

3. Posterior collapse: when the decoder does not need the code

The problem. The KL term is smallest, exactly 0, when the encoder ignores the image and outputs N(0, I) for everyone. If the decoder can reconstruct well without the code, nothing pays for leaving that optimum, and the code goes unused: posterior collapse. The {{Math page|n:3f05c17b0d0d81aa9857eb5fa1bac530}} explains the mechanism with Bowman et al.'s LSTM text decoder (section 10); here it is on images, with the three standard fixes compared on the same model.

A decoder that does not need z. A PixelCNN decoder predicts each pixel from the pixels above and to its left (masked convolutions), plus the code. During training it sees the true previous pixels, so it can predict most of an image from its own left-and-above context: a garment's edge continues, the background stays black. The model here: the topic's VAE encoder (16 numbers), a PixelCNN decoder of one 7 × 7 and five 3 × 3 masked layers, 64 channels, the code added as a learned bias to every layer (src/collapse/pixelvae.py), parameters, trained with the same recipe as every other model here.

KL nats per test image, of 16 active units. The direct check: give every test image another image's code (a shuffle) and the reconstruction term gets worse by only nats. The decoder learned to do the job itself. measured

Three fixes, same model, same data.

  • KL annealing (Bowman et al. 2016, {{arXiv 1511.06349|https://arxiv.org/abs/1511.06349}}): start with the KL weight at 0 and raise it linearly to 1 (here over the first half of training), so the encoder learns to carry information before the KL starts charging for it ("annealing from a vanilla autoencoder to a vae", in the paper's words). DALL-E's dVAE used the same idea, raising its KL weight from 0 to 6.6 over the first 5,000 updates ({{Ramesh et al. 2021, appendix A.2|https://arxiv.org/abs/2102.12092v2}}).
  • Free bits (Kingma et al. 2016, IAF, {{arXiv 1606.04934|https://arxiv.org/abs/1606.04934}}): do not charge for the first λ nats of each latent dimension: the KL term becomes Σj max(λ, KLj), with KLj averaged over the minibatch (here λ = 0.5 nats per dimension, so up to 8 nats in total are free). The paper's appendix C.8 found λ from 0.125 to 2 helpful on CIFAR-10.
  • Weaken the decoder, or drop the PixelCNN entirely (the ordinary decoder of the Latent lab, which cannot reconstruct anything without the code). Chen et al.'s {{Variational Lossy Autoencoder|https://arxiv.org/abs/1611.02731}} explains collapse in exactly these terms: information the decoder can model locally is not worth sending through z, so limit the decoder's receptive field to what you want the code to leave out.

All four PixelCNN models beat the ordinary-decoder VAE's nats by a wide margin; if you want a code for downstream use, the likelihood is the wrong thing to maximise alone. measured, one seed each

The cost of each fix. Annealing and free bits change the objective, so the number the run reports is no longer the ELBO: compare models on the true negative ELBO (reconstruction + full KL), which the table shows. Free bits can leave dimensions that carry exactly λ nats of noise to dodge the penalty; annealing only delays the KL and can collapse later. Removing the strong decoder costs likelihood: an ordinary decoder's negative ELBO is far worse than a PixelCNN's.

When it matters, how to check. Any VAE with an autoregressive or otherwise powerful decoder (text VAEs, PixelCNN and transformer decoders, some video and audio models), and any VAE whose loss units are off (section 2). Check: KL per dimension and active units over training; the shuffle test (reconstruction with another image's code); decode the same code twice with different random draws and different codes once: if the code does not change the output, it is not being used.
