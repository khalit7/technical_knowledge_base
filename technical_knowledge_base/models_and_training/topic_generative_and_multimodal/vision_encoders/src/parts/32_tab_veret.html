Retrieval on the running example

Retrieval is ranking a collection (the gallery) by similarity to a query: embed everything once, then sort by cosine. Here the gallery is 1,000 Fashion-MNIST test images (the first 100 of each class) and the vectors are the ones saved for the {{Encoder comparison|#t-vecmp}} tab. A green outline means the result has the class the query asks for (or the query image's class); red means it does not. Everything is precomputed from the released models measured; the page only looks results up.

Text to image (CLIP and SigLIP 2 only)

Only an encoder trained with captions has a text tower, so DINOv2 and MAE cannot take a sentence. Try the descriptive queries: some name things the 28-pixel grey images cannot show ("a red dress", "a striped t-shirt"), and "a cat" names nothing in the gallery, yet search always returns eight images. The last three options keep SigLIP 2's capitals (the case trap, Reading section 7).

Image to image (all four encoders)

Pick a query image, or click any result to search with it. Each row is one encoder's 8 nearest gallery images; the number under each is its cosine to the query.

How retrieval is scored

With class labels as relevance (any image of the query's class counts), the scores are precision@K (share of the top K that are relevant) and mean average precision (mAP, which rewards putting all relevant items early). Image-text benchmarks such as COCO and Flickr30k instead pair each image with its own captions, and report recall@K: the share of queries whose one correct partner is among the top K. On the 16 colour test images and their captions (the Vision lab's matrix), CLIP B/32 has image-to-text recall@1 of 15 of 16 and text-to-image 16 of 16 measured.
