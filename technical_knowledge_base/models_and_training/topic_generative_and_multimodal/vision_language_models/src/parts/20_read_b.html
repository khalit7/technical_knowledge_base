1. Connectors: five ways to hand patches to a language model

The problem. The encoder gives a grid of vectors, for example 576 vectors of 1,024 numbers for LLaVA-1.5’s CLIP ViT-L at 336 pixels, or 1,024 vectors of 768 numbers per 512-pixel tile for SmolVLM. The language model expects tokens of its own width (4,096 numbers for a 7B Llama, 960 for SmolVLM’s, 1,024 for Qwen3.5-0.8B’s) and pays for every token it reads: context length, attention, cache memory and time. A connector must make the vectors readable (in the language model’s space), few (cheap), and faithful (small text and positions survive). The five designs below trade those three against each other.

1a. Projector (LLaVA)

How it works. Each patch vector goes through the same small network, independently: first a single linear layer (“a simple linear layer to connect image features into the word embedding space”, LLaVA, {{Liu et al., April 2023, section 4.1|https://arxiv.org/html/2304.08485v2}}), then in LLaVA-1.5 “a two-layer MLP” which “can improve LLaVA’s multimodal capabilities” ({{Liu et al., October 2023, section 3.3|https://arxiv.org/html/2310.03744}}) paper. Nothing is merged: 576 patches become 576 tokens. Which encoder layer feeds it matters: LLaVA-1.5 reads the second-to-last block and drops the [CLS] token (the sibling page Vision encoders quotes the code and measures why a late, not last, layer is better).

Cost and when it matters. The cheapest connector to train (stage 1 of LLaVA trains only it) and the most faithful (every patch keeps its own token), but the most expensive to read: the token count is the patch count, so resolution is paid for quadratically. It is the right default when images are few and small.

1b. Query transformer (BLIP-2’s Q-Former)

How it works. A fixed set of learned queries (vectors that are parameters of the model, the same for every image) attend to the frozen encoder’s features through cross-attention and to each other through self-attention. BLIP-2 “use[s] 32 queries where each query has a dimension of 768”; the output “(32×768) is much smaller than the size of frozen image features (e.g. 257×1024 for ViT-L/14)”; the Q-Former is initialised from BERT-base, has cross-attention “inserted every other transformer block”, and “contains 188M parameters”. A fully connected layer then projects the 32 outputs to the language model’s width and they are “prepended to the input text embeddings” as “soft visual prompts” ({{Li et al., January 2023, section 3|https://arxiv.org/html/2301.12597}}) paper.

Cost and when it matters. Thirty-two tokens whatever the image: cheap to read, but a bottleneck the paper names as such (“an information bottleneck between the frozen image encoder and the frozen LLM”). Fine text, counts and positions have to squeeze through 32 vectors chosen during pretraining, and the Q-Former needs its own pretraining stage (section 6). It suits a frozen language model and a tight budget, not documents.

1c. Resampler and gated cross-attention (Flamingo)

How it works. As the root lab quotes from the paper and checks word for word ({{Alayrac et al., April 2022, sections 2.1 to 2.3|https://ar5iv.labs.arxiv.org/html/2204.14198}}) paper: a frozen vision encoder; a Perceiver Resampler that “produces a fixed number of visual outputs (64)” from however many features the image or video gave; new gated cross-attention blocks between the frozen language model’s layers, each output multiplied by tanh(α) with α “a layer-specific learnable scalar initialized to 0”, so training starts exactly at the frozen language model; and each text token “attends to the visual tokens of the image that appeared just before it”. The image never enters the token sequence.

Cost and when it matters. Context stays free (many images or long video cost no sequence length) and the language model is untouched at the start. The price is new layers (a quarter of all parameters trained in Idefics2’s comparison below) and a less standard architecture that serving stacks support less well.

Read the ablation, not the headline: cross-attention against tokens in the sequence

Idefics2 is the one controlled comparison ({{Laurençon et al., May 2024, section 3.2 and Table 3|https://arxiv.org/html/2405.02246}}) paper. Same backbones, same data, same updates; average score over its benchmarks:

ArchitectureBackbonesAvg. score
Tokens in the sequence, no resamplerfrozen51.8

With frozen backbones cross-attention wins; once the backbones can adapt (through LoRA, since full unfreezing “would yield loss divergences”), tokens in the sequence win, “even though the latter has more parameters”. That is why almost every open VLM since 2024 puts image tokens in the sequence. Two of the prose numbers do not match the table: the text says cross-attention “performs 7 points better” (table: 66.7 − 60.3 = 6.4) and LoRA gives “a 12.9 points increase under the fully autoregressive architecture” (table: 69.5 − 60.3 = 9.2; 0.6 for cross-attention matches) derived. The ranking holds either way; quote the table. The same paper finds its learned resampler both “increases the performance by 8.5 points” (60.3 − 51.8, matches) and cuts tokens “from 729 to 64”, and sees “no gains when using more than 64 visual tokens” (Table 4: 71.2 at 128, 71.7 at 64).

1d. Merging neighbours (pixel shuffle, patch merger)

How it works. Instead of learned queries, take each block of neighbouring patch vectors and lay them side by side into one longer vector (pixel shuffle or space-to-depth), then project. Nothing is averaged away; the projector must learn to read several positions out of one vector. InternVL 1.5 uses “a simple pixel shuffle to reduce the number of visual tokens to one-quarter”, so “a 448×448 image is represented by 256 visual tokens” ({{Chen et al., April 2024, section 3.1|https://arxiv.org/html/2404.16821}}) paper. SmolVLM merges 4 × 4 = 16 patches (1,024 to 64 per tile; the root lab shows the code). Qwen2-VL merges 2 × 2 with an MLP: “a simple MLP layer is employed after the ViT to compress adjacent 2×2 tokens into a single token”, so a 224 × 224 image with 14-pixel patches becomes “66 tokens” ({{Wang et al., September 2024, section 2.1|https://arxiv.org/html/2409.12191}}) paper: (224 / 14)² / 4 = 64, plus the start and end markers derived.

Cost and when it matters. A fixed compression factor (4 or 16) with no extra pretraining stage and every number kept. Combined with tiling or native resolution (section 2) it is today’s default. The more aggressive the merge, the more each token has to carry: the SmolVLM paper reports that “smaller VLMs benefit from more aggressive compression (r=4)”; section 8 measures what happens when tokens are merged further without retraining.

1e. Inside the encoder: are there outlier tokens?

The sibling page Vision encoders found that SigLIP 2 B/16 at 224 pixels has a few patch tokens with 15 to 22 times the median norm at fixed grid positions in every image, the “high-norm tokens” that registers were invented to absorb. A VLM passes every patch token to its connector, so such tokens would be a fixed tax on every image.
