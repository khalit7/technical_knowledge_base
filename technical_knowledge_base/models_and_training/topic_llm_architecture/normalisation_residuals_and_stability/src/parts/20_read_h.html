5. Output logits and z-loss

The problem. The last layer's softmax has the same weakness at the other end of the model. Cross-entropy depends only on differences between the output logits yj, so the whole vector can drift up or down for free; Z = Σj eyj is the softmax's normaliser and log Z is that drift. {{Wortsman et al. 2023 (section 3.1.2)|https://arxiv.org/abs/2309.14322}} describe an instability where the logits "diverge and become very negative", far from the log-probabilities, which in low precision loses the small differences that matter.

loss = cross-entropy + c · (log Z)2,   log Z = log Σj exp(yj),   c = 10−4
log Z
0 when the logits are already log-probabilities; the penalty pulls them there without changing which token wins
c
PaLM's coefficient: "z loss = 10−4 · log2 Z to encourage the softmax normalizer log(Z) to be close to 0, which we found increases the stability of training" ({{PaLM, section 5|https://arxiv.org/abs/2204.02311}}); OLMo 2 and Wortsman et al. use the same value

A real-world trap. OLMo 2's team found that the fused cross-entropy in Flash Attention (which includes a z-loss) and their own PyTorch z-loss gave the same forward value but behaved differently in the backward pass; a fork that switched implementations saw its z-loss jump about thirty-fold within a few hundred steps, and they retrained from the switch point (the {{OLMo 2 paper page|n:3c65c17b0d0d81fb9857fb956165ae1c}} replays it). The lesson is general: do not change a loss implementation in the middle of a run.

How to check. Log mean log Z on a fixed batch; a value drifting steadily away from 0 is the symptom z-loss treats. Computing it costs one logsumexp you already pay for in the cross-entropy.
