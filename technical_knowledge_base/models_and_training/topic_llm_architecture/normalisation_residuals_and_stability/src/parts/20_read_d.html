1. The residual stream, and why depth is a stability problem

The problem. A transformer is a stack of L blocks, each with two sub-layers (attention, then the feed-forward network). Each sub-layer computes a branch F(x) and adds it to a running vector per token, the residual stream: x ← x + F(x). After L blocks the stream is the embedding plus 2L branch outputs. Two things can go wrong with depth. Forward: the stream's size can drift, either growing (every add makes it bigger) or being forced flat (normalising it after every add). Backward: the gradient that reaches block 1 has to travel through every block above it; if each step scales it by a little less than one, it vanishes, and by a little more, it explodes. Normalisation (rescaling a vector to a fixed size, defined from zero on the {{ML-fundamentals Normalisation and initialisation page|n:3c65c17b0d0d81369e1cc38ed4e11d48}}) and the placement of the norm relative to the add decide which of these happens.

x2L = x0 + F1(·) + F2(·) + … + F2L(·)     ∂x2L/∂x0 = I + (terms through the branches)
x0
the token embedding (plus a position vector in the tiny GPT); shape (B, T, D) with D = d_model = 256
Fi
sub-layer i's output, written into the stream; under pre-norm it reads Norm(x), under post-norm the add is normalised
I
the identity: with a clean residual path the gradient reaches every block undiminished, whatever the branches do

What each piece buys, measured. The {{transformer from zero|n:3fd5c17b0d0d8174980ddde4a20c7b3c}} child trained the tiny GPT with one piece removed at a time, at an equal budget: without the residual connection it learns nothing (held-out 6.011, the unigram floor is {%unigram%}); without the norms it trains but worse (2.546 against 2.276; at lr 1e-3, 3.061 against 2.464). The residual path is what makes depth trainable; the norm is what lets it train at a useful learning rate. This page is about the second part: how the norm is placed, which norm, what else is added for stability, and how the weights start.

So the four placements disagree before the first step: pre-norm starts almost as an identity map, post-norm pins the stream at RMS 1, and the two "norm the output" placements make it grow like the square root of the number of sub-layers. After training the picture changes again (pre-norm grows to {%rs_pre_trained_last%}); the {{Residual stream|#t-resid}} tab animates every placement through all 12 sub-layers, before and after training, for the median token, one traced token, token 0 and the largest single entry.

How to check it on a real run. Log the stream's RMS after each block for a fixed batch every few hundred steps (forward hooks on each decoder layer's output; in transformers, output_hidden_states=True returns the stream after every block, with the last entry already after the final norm, as the root's Inside lab found). A pre-norm stream that grows steadily is normal; a single dimension that is hundreds of times larger than the rest is a massive activation (section 7); a stream that is identical in every layer under post-norm is also normal, because the norm forces it.
