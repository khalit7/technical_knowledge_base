What a tokenizer does

A modern tokenizer is four stages, each a separate object in the Hugging Face tokenizers library: a normalizer (optional cleanup such as Unicode NFC; the running example has none), a pre-tokenizer (cuts text into word-like chunks, and for byte-level BPE turns each chunk into bytes), the model (BPE: applies the learned merges inside each chunk) and a post-processor (adds special tokens such as a beginning-of-sequence marker). The decoder runs it backwards and gives back exactly the same text.

  1. The text. "Roxy loved to climb the icy hill.": 33 characters. The model cannot read characters; everything that follows turns them into a short list of integers and back.
  2. UTF-8 bytes. Byte-level BPE starts from bytes, so no input is ever unknown: 33 bytes, each one of the 256 base tokens (ids 1 to 256). A non-Latin character would be 2 to 4 bytes.
  3. Pre-tokenize. GPT-2's regex (quoted under Encoding) cuts the bytes into 8 chunks; a space travels with the word after it, and no merge may cross a chunk boundary.
  4. Merge inside each chunk. The learned merges apply lowest rank first: " loved" takes five merges, " the" three (merges 1, 2 and 7). Predict what happens to "Roxy" before it plays: the trainer never learned a merge for it, so it stays four byte tokens (orange); the full stop is a single byte too. 11 tokens.
  5. Ids. 11 integers, [50, 79, 88, 89, 505, 266, 1014, 263, 3183, 1443, 14]: 33 bytes compressed 3.0 times. These integers are all the model receives.
  6. Embedding rows. Each id selects one row of the 4,096 × 256 embedding matrix, so the model's input is an 11 × 256 array. "Roxy"'s four rows sit in the byte region at the front; " icy" (3183) was learned late.
  7. Output layer, tied. After the six blocks, the same matrix scores all 4,096 entries for the next token: 2Vd = 2.10M FLOPs per token. Decoding runs the other way, ids to bytes to text, exactly: decode(encode(text)) == text, which the library guarantees for byte-level BPE.

Three things to read off Fig. 1. A leading space is part of the next token (Ġloved is " loved"; byte-level BPE writes the space byte as Ġ so that every byte has a printable character). "Roxy" costs four tokens while " climb" costs one, because merges are learned from frequency and the name is rare in TinyStories. And id 0 is <|endoftext|>, a special token that the setup reserved before training to separate stories.

Where the ids go (steps 6 and 7): id i selects row i of the embedding matrix E (V × d = 4,096 × 256 in the tiny GPT), and the output layer multiplies the final hidden state by a V × d matrix to give one score (logit) per entry. The tiny GPT ties the two: the output matrix is the embedding matrix ({{Press and Wolf 2016|https://arxiv.org/abs/1608.05859}}).

measured 5: r|hin|o|cer|os. The running text's 874 characters become 255 tokens (3.43 characters per token), but rare words shatter: " rhinoceros" 5, " Roxy" and "Roxy" 4 each, " slippery" 3; every other word of the passage is 1 or 2 tokens. GPT-2's 50,257-entry vocabulary needs 228 tokens for the same text, Llama 3's 128,256 entries 222. A rarely seen word costs the model more positions, and the model must learn to assemble its meaning across them.
