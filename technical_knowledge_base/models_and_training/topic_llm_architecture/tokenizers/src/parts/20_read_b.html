What a tokenizer does

A modern tokenizer is four stages, each a separate object in the Hugging Face tokenizers library: a normalizer (optional cleanup such as Unicode NFC; the running example has none), a pre-tokenizer (cuts text into word-like chunks, and for byte-level BPE turns each chunk into bytes), the model (BPE: applies the learned merges inside each chunk) and a post-processor (adds special tokens such as a beginning-of-sequence marker). The decoder runs it backwards and gives back exactly the same text.

Real bytes, the real pre-tokenizer, the real merges in the order the trainer learned them, the real ids and the embedding rows they select. Predict what the merge stage does to "Roxy", then step to it: the trainer never learned a merge for it, so it stays four tokens.

Three things to read off it. A leading space is part of the next token (Ġloved is " loved"; byte-level BPE writes the space byte as Ġ so that every byte has a printable character). "Roxy" costs four tokens while " climb" costs one, because merges are learned from frequency and the name is rare in TinyStories. And id 0 is <|endoftext|>, a special token that the setup reserved before training to separate stories.

Where the ids go (the hero above): id i selects row i of the embedding matrix E (V × d = 4,096 × 256 in the tiny GPT), and the output layer multiplies the final hidden state by a V × d matrix to give one score (logit) per entry. The tiny GPT ties the two: the output matrix is the embedding matrix ({{Press and Wolf 2016|https://arxiv.org/abs/1608.05859}}).

The running text's 874 characters become 255 tokens (3.43 characters per token), but rare words shatter: " rhinoceros" 5, " Roxy" and "Roxy" 4 each, " slippery" 3; every other word of the passage is 1 or 2 tokens. GPT-2's 50,257-entry vocabulary needs 228 tokens for the same text, Llama 3's 128,256 entries 222. A rarely seen word costs the model more positions, and the model must learn to assemble its meaning across them.
