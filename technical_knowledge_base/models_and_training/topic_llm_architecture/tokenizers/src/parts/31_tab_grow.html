Grow a vocabulary

The running example's tokenizer is 256 bytes plus 3,839 merges, learned in order on TinyStories. Because BPE's merge lists are nested (a smaller vocabulary is the first part of a larger one, checked for nine sizes on the {{Reading|#t-read}} tab), every vocabulary size from 257 to 4,096 is one position of the slider below. This tab replays the merges on the running sequence, shows what each size costs, and lets you inspect any string.

Embedding = (257 + merges) × 256 parameters; share against the tiny GPT's 4,721,920 other parameters.

What each vocabulary size costs

Nine tokenizers trained from scratch at 257 to 65,536 entries, measured on the 19.2M-character validation split. Top: characters per token. Bottom: the tiny GPT's FLOPs for one pass over the validation split, split into the blocks and the output layer. Try moving the merge slider above: the marker follows.

measured on Apple M1 Pro (CPU) token counts from src/bpe/bpe_sweep.py (tokenizers 0.23.3, 30 seconds per training run). derived FLOPs = tokens × 2 × 4,721,920 for the blocks and tokens × 2 × 256V for the tied output layer; attention scores omitted (the same per token at every V). The 65,536 run stopped at 43,702 entries (no pair left with count 2 or more). Not run here: the tiny GPT's loss at each vocabulary, which needs a GPU training run per size.

Training counts and norms belong to the full 4,096-entry tokenizer and the ref_baseline_s1500 checkpoint (src/bpe/freq_glitch.py); with fewer merges a piece may not exist in that model. Red: never seen in training.
