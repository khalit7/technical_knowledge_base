3. The variants trained on one budget

Pictures of caches say nothing about quality. So each variant of the tiny GPT was trained from scratch with the same seed, the same 1,500 batches (12.3M tokens of TinyStories), the same learning-rate schedule and RoPE positions everywhere (the setup's baseline uses learned positions and its MLA preset uses RoPE, so the comparison would otherwise mix two changes). Held-out loss is the mean cross-entropy on 3,200 fixed validation windows of 256 tokens (eval.py); lower is better, and ln 4,096 = 8.32 is a model that knows nothing.

4. What the published ablations say

A 6M-parameter model trained for five minutes cannot show the quality differences that appear at billions of parameters and trillions of tokens. Two papers trained variants that differ only in attention at real scale; both are the authors' own runs, and both compare on benchmarks rather than loss.

5. Decode speed: the cache is what the step reads

The claim to test. At decode, every new token's attention reads the whole cache once. If that read is memory-bound, the time of the attention step should scale with the bytes cached, not with the number of query heads or the FLOPs. One attention layer at Llama 3.1 8B's shape (32 query heads of 128, batch 4, fp16) was timed on the M1 Pro's GPU for each variant, with the cache sized to each context.
