# Attention lab: verified facts (copied from the topic's shared FACTS.md, 2026-10-18)
- GQA paper Table 1 (https://arxiv.org/html/2305.13245, read 2026-10-18): T_infer s per sample / Average: MHA-Large 0.37 / 46.0; MHA-XXL 1.51 / 47.2; MQA-XXL 0.24 / 46.6; GQA-8-XXL 0.28 / 47.1. T5.1.1; GQA only in decoder self- and cross-attention, not encoder; MQA/GQA uptrained from MHA-XXL with 5% of pre-training compute; time per sample per TPUv4 chip.
- DeepSeek-V2 Table 8 (Appendix D.1, https://arxiv.org/html/2405.04434): 7B dense, 1.33T tokens, params aligned by layer count: MQA 7.1B / GQA-8 6.9B / MHA 6.9B; MMLU 37.9 / 41.2 / 45.2; BBH 33.2 / 35.6 / 37.0; C-Eval 30.0 / 37.7 / 42.9; CMMLU 34.6 / 38.4 / 43.5.
- DeepSeek-V2 Table 9 (D.2): small MoE (about 16B, 1.33T tokens) MHA vs MLA KV elements per token 110.6K vs 15.6K, MMLU 48.7 vs 50.0; large MoE (about 250B, 420B tokens) 860.2K vs 34.6K, MMLU 57.5 vs 59.0. Table 1 text: MLA's cache "is equal to GQA with only 2.25 groups, but its performance is stronger than MHA".
- NSA Table 4 (https://arxiv.org/html/2502.11089): decode memory access in equivalent tokens, full vs NSA: 8192 vs 2048 (4x), 16384 vs 2560 (6.4x), 32768 vs 3584 (9.1x), 65536 vs 5632 (11.6x): authors' expected speedups, a calculation.
- StreamingLLM Table 10 (https://arxiv.org/html/2309.17453): 160M models, PG19 first sample perplexity, cache 0+1024 / 1+1023 / 4+1020: vanilla 27.87 / 18.49 / 18.05; +1 learned sink token 1235 / 18.01 / 18.02. Table 5: Llama-2-7B-Chat ARC-E window 3.58 vs StreamingLLM 71.34 (cache 1024).
- Mistral 7B paper section 2: SWA "theoretical attention span of approximately 131K tokens" (W 4096, 32 layers); rolling buffer cache "reduces the cache memory usage by 8x" at 32k.
- Gemma 3 report: "5 local layers for every global layer", local span "only 1024 tokens". gpt-oss model card (arXiv 2508.10925): alternating "banded window and fully dense patterns, where the bandwidth is 128 tokens"; 64 query heads of 64, 8 KV heads; "learned bias in the denominator of the softmax".
- DeepSeek-V3.2 technical report (https://huggingface.co/deepseek-ai/DeepSeek-V3.2/blob/main/assets/paper.pdf) section 2: lightning indexer, ReLU scores, "can be implemented in FP8"; DSA reduces core attention "from O(L^2) to O(Lk)"; indexer "still has a complexity of O(L^2)". V3.2 config: index_topk 2048, index_n_heads 64, index_head_dim 128. V3.2-Exp card 2025-11-17 note: indexer RoPE needs non-interleaved layout, MLA RoPE interleaved (demo code bug).
- transformers v5.20.1 (0ea8779): repeat_kv at models/llama/modeling_llama.py lines 168-177; num_key_value_groups line 214; integrations/sdpa_attention.py lines 109-114 pass enable_gqa=True when use_gqa_in_sdpa (lines 30-37; MPS needs torch >= 2.13, CUDA needs no mask).
- torch 2.14.1 error, SDPA with 8 query heads and 2 KV heads without enable_gqa: "RuntimeError: The size of tensor a (8) must match the size of tensor b (2) at non-singleton dimension 1".
- KV at 131,072 tokens, bf16, windows credited, CC code (src/attn/real_numbers.mjs): Llama 3.1 70B 320 KiB/token, 40 GiB; gpt-oss-120b 72 KiB/token, 4.50 GiB (9.00 GiB uncredited); Mistral 7B v0.1 0.50 GiB (16.00 uncredited); Nemotron-H 8B 2.00 GiB + 98.8 MiB state; DeepSeek-V3.2 83.88 KiB/token incl. 128-number indexer key.
