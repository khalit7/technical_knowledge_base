The other tabs build a transformer from its parts. This one opens trained models and measures what they do with those parts: which earlier tokens each attention head reads, where attention goes when nothing is worth reading, how large the residual stream grows, and what the model would predict if it stopped after layer k. Each measurement explains a design decision met elsewhere on this page.

The models. SmolLM2-135M (Hugging Face, Apache-2.0, revision 93efa2f): a Llama-architecture model with 30 layers, 9 query heads sharing 3 key-value heads, width 576, RoPE, RMSNorm before each sub-layer, tied input and output embeddings. Qwen3-0.6B (Alibaba, Apache-2.0, revision c1899de, run in float16): 28 layers, 16 query heads on 8 key-value heads, width 1,024, plus RMSNorm on every query and key (QK-norm). Pythia-70M-deduped (EleutherAI, Apache-2.0): 6 layers of 8 heads, with checkpoints published from the start of training, which we read but did not train. And the tiny GPT of this topic (6 layers, 8 heads, width 256, trained here on TinyStories; see {{the running example|#t-block}}). The text is the running sequence, the story of Roxy the rhinoceros, re-tokenised by each model's own tokenizer.

Terms. An attention weight aij is how much query position i reads from key position j: one row of the softmax over the scores qi·kj/√d, so each row sums to 1. A head is one such pattern; a layer has several. The residual stream is the vector each token carries from layer to layer; every attention and feed-forward sub-layer reads it and adds its output back.

All values measured on an Apple M1 Pro (MPS for SmolLM2 and Qwen3, CPU for Pythia and the tiny GPT), 2026-10-18, torch 2.14.1, transformers 5.20.1. These are deterministic forward passes on fixed inputs: what transfers to a datacenter GPU is everything here except the timings (none are quoted).

Where the attention weights come from

The problem. Fast attention kernels never build the T × T matrix of weights: FlashAttention and PyTorch's scaled_dot_product_attention (SDPA) stream over keys and keep only running sums ({{FlashAttention|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}). So the weights you want to look at do not exist in a normal forward pass.

How to get them. Load the model with attn_implementation="eager". Eager attention is the textbook arithmetic, and it returns the weights. In transformers v5.20.1 (commit 0ea8779), src/transformers/models/llama/modeling_llama.py, which SmolLM2 runs:

180 def eager_attention_forward(module, query, key, value, attention_mask, scaling, dropout=0.0, **kwargs): 190 key_states = repeat_kv(key, module.num_key_value_groups) # GQA: copy each KV head to its query heads 191 value_states = repeat_kv(value, module.num_key_value_groups) 193 attn_weights = torch.matmul(query, key_states.transpose(2, 3)) * scaling # (B, H, T, T) scores 195 attn_weights = attn_weights + attention_mask # causal mask: -inf above the diagonal 197 attn_weights = nn.functional.softmax(attn_weights, dim=-1, dtype=torch.float32).to(query.dtype) 199 attn_output = torch.matmul(attn_weights, value_states) 202 return attn_output, attn_weights

Lines 180 to 202, abridged (signature joined, comments ours). Lines 253 to 255 pick the function: ALL_ATTENTION_FUNCTIONS.get_interface(self.config._attn_implementation, eager_attention_forward); line 331 records each LlamaAttention's second output as outputs.attentions. The softmax runs in float32 even for a float16 model (line 197). Qwen3 differs only by RMSNorm on queries and keys first (modeling_qwen3.py lines 229 and 244). Lines located by pattern: src/inside/locate_source.py.

How we measure the rest without editing the library: transformers lets you register your own attention function (AttentionInterface.register).
