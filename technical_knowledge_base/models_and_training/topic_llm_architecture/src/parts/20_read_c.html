4. The sequence mixer: attention, its cache, and the fixed-state alternative

Attention. Each position makes a query (what it looks for), a key (what it offers) and a value (what it passes on) from its normalised residual stream, and its output is a weighted average of earlier positions' values, weighted by query-key match. For one head:

Attention(Q, K, V) = softmax( Q K⊤ / √dh + M ) V
Q, K, V
T × dh matrices, one row per position; dh is the head dimension (64 to 256 in current models)
√dh
a dot product of dh unit-variance terms has spread about √dh; dividing keeps the softmax from saturating into a one-hot ({{Vaswani et al. 2017, section 3.2.1|https://arxiv.org/abs/1706.03762}}); H heads run in parallel, each with its own projections, and are concatenated back to d ({{Inside a real model|#t-inside}} finds what SmolLM2's heads track)
M
the causal mask: 0 where a query may look (itself and earlier), minus infinity for later positions

Why a cache. A past token's keys and values never change, so generation computes them once and keeps them: the KV cache. Prefill runs the whole prompt as one large matrix multiply, limited by arithmetic; decode makes one token per step and must read every weight and the whole cache to do little arithmetic, so it is limited by memory bandwidth; batching more sequences raises the FLOPs per weight byte but not per cache byte, since each sequence reads its own cache. What each token leaves behind is:

KV bytes per token = 2 × L × Hkv × dh × b
2
keys and values
L
layers that keep a cache
Hkv
key-value heads per layer, set by the attention variant (not the query heads)
b
bytes per number: 2 in BF16, 1 in FP8

At long context this, not the parameter count, decides what a GPU can serve: Llama 3.1 70B (80 layers, 8 KV heads of 128, BF16) keeps 320 KiB per token, 40 GiB for one 128K request against about 141 GB of weights (derived; sized for 45 models on {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}}'s {{KV-cache calculator|n:3fd5c17b0d0d81059ee1ce20c0326dc5#t-kv}}). FlashAttention changes how attention is computed (tiled, never storing the T × T matrix), not how much is cached ({{FlashAttention|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}).

Two misreadings this table prevents: a window or a sparse indexer does not shrink the per-token entry (only fewer KV heads, compression, lower precision or layers without a cache do), and a hybrid is not cache-free (Qwen3-Next's attention layers keep 24 KiB per token, and each request also carries a fixed state for the recurrent layers). Trained models also park attention on the first tokens (attention sinks), so any cache that evicts tokens must keep them ({{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}, measured in {{Inside a real model|#t-inside}}).

The fourth lever: how a recurrent layer keeps a fixed state

A recurrent layer replaces the growing cache with a fixed-size state updated once per token, so memory and work per token stay constant however long the context. Linear attention writes each value into a matrix state indexed by its key (St = St−1 + vtkt⊤, read out as Stqt); a state-space model (SSM) runs ht = Atht−1 + Btxt, yt = Ctht. They became competitive once the update depended on the input, so the layer chooses what to keep: Mamba's selective SSM ({{Mamba|n:3c65c17b0d0d8179984fc3a1fee4c36a}}) and gated delta rules that erase what a key stored before writing (Gated DeltaNet, {{Yang et al. 2024|https://arxiv.org/abs/2412.06464}}). Training still runs in parallel with a scan or chunked algorithm. One layer of each in Qwen3-Next holds the same number of numbers at 512 tokens: 1,024 per token for attention, 524,288 in all for the Gated DeltaNet state (derived from its {{config|https://huggingface.co/Qwen/Qwen3-Next-80B-A3B-Instruct/blob/main/config.json}}; drawn on {{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}}).

Qwen3-Next keeps full attention in every fourth layer (full_attention_interval: 4) and Gated DeltaNet in the rest, 24 KiB of cache per token against 96 KiB had all 48 layers been attention; Qwen3.5-397B-A17B keeps that 3 : 1 pattern. NVIDIA's Nemotron 3 Super (120B, 12B active) interleaves 40 Mamba-2 layers with 8 attention layers of 2 KV heads, 8 KiB per token. Moonshot's Kimi K3 (2.8T total, 104B active) puts 3 Kimi Delta Attention layers before each MLA layer, MLA in 24 of its 93 layers, 27 KiB per token. Published and measured evidence on what each lever costs
  • GQA. The GQA paper converts multi-head checkpoints by continued training on "5% of original pre-training compute" and reports that "uptrained GQA achieves quality close to multi-head attention with comparable speed to MQA" ({{Ainslie et al. 2023|https://arxiv.org/abs/2305.13245}}, authors' own runs).
  • Tensor parallelism. MQA's single KV head must be replicated on every GPU, while GQA with 8 groups keeps most of MHA's quality at an eighth (for 64 heads) of its cache and its 8 KV heads split cleanly over 8 GPUs.
  • MLA. DeepSeek reports that MLA in DeepSeek-V2 "reduces the KV cache by 93.3% and boosts the maximum generation throughput to 5.76 times", against its earlier dense DeepSeek 67B ({{DeepSeek-V2 abstract|https://arxiv.org/abs/2405.04434}}, vendor; that comparison also changes the model, so it is not MLA alone). At DeepSeek-V3's shape (61 layers, 128 heads of 128) full MHA would keep 3,904 KiB per token; MLA keeps 68.6 KiB, 57 times less (derived).
  • The variants on the tiny GPT (same seed and token budget, held-out loss after 1,500 steps of 8,192 tokens, RoPE in every preset): MHA 2.160 (6,144 bytes of cache per token in BF16), GQA-4 2.185 (3,072), GQA-2 2.182 (1,536), MQA 2.177 (768), MLA 2.255 (960), sliding window 64 2.173, and 2 local : 1 global layers at window 64 2.154 measured. A second seed moved MHA by 0.016, so the grouped variants cost nothing measurable at this size; MLA is about 0.1 worse (seed 1: 2.248), which does not reproduce DeepSeek's result ({{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}} discusses why).
  • Decode is a memory-traffic story. One attention layer of Llama 3.1 8B's shape with 32K cached tokens (batch 4, on the laptop's GPU) takes 0.34 of MHA's time with GQA-8, 0.09 with MQA and 0.20 with absorbed MLA, against cache bytes of 0.25, 0.031 and 0.070 measured: the ratios follow the bytes; the milliseconds do not transfer to a datacenter GPU.
  • Fixed state against attention. {{Jelassi et al. 2024|https://arxiv.org/abs/2402.01032}} prove that "a two layer transformer can copy strings of exponential length while" fixed-state models "are fundamentally limited by their fixed-size latent state", and find pretrained transformers "dramatically outperform state space models at copying and retrieving information from context". The same limit measured here, a pretrained SSM against a transformer on copying and the tiny GPT as SSM, hybrid and attention, is sections 8 and 9 of {{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}}.
  • Sinks in SmolLM2-135M. Under 0.09 of the attention lands on the first token in layers 0 to 11, and 0.31 to 0.74 from layer 12 on. Masking the first token as a key in every layer raises the loss on the running text from 1.563 to 1.648 and derails generation ("Once upon a time, and the people were so much in love with him, that they would not let him go out of the house."). On 1,024-token stories a 64-token sliding window without the first token doubles the loss after the window (3.36 against 1.62); keeping just the first token brings it back to 1.81 measured. The tiny GPT, trained on 12.3M tokens, has no sink: at most 0.05 on the first token in any head.

5. Position: telling attention where each token sits

Attention by itself is blind to order: shuffle the earlier tokens and each query gets the same weighted average. The near-universal answer is RoPE (rotary position embedding, {{RoFormer|n:3c65c17b0d0d81cfa5e9f54459720098}}): split each query and key into pairs and rotate pair i by position × θi, with θi = base−2i/dh; rotations compose, so the query-key product depends only on the distance between the tokens, with no parameters. The base sets the slowest rotation: 10,000 in the original, 500,000 in Llama 3.1 (rope_theta). The alternatives: absolute positions added to the embedding (fixed sinusoids, {{Vaswani et al. 2017|https://arxiv.org/abs/1706.03762}}, or a learned table, GPT-2's 1,024 positions, with nothing for position 1,025); ALiBi, a score penalty proportional to distance ({{Press et al. 2021|https://arxiv.org/abs/2108.12409}}); and NoPE, no position signal at all, since a causal decoder can infer order from the mask (one layer in four in SmolLM3, {{config|https://huggingface.co/HuggingFaceTB/SmolLM3-3B/blob/main/config.json}}).

The distinction that crosses pages: position sets the third long-context wall (section 9). A model trained on 8K tokens has never seen the rotation angles of position 100,000 in its slow pairs, and quality collapses there. The fixes stretch the angles back into the trained range, position interpolation ({{Chen et al. 2023|https://arxiv.org/abs/2306.15595}}), base scaling, or YaRN, which stretches only the slow pairs ({{Peng et al. 2023|https://arxiv.org/abs/2309.00071}}), each followed by a short training phase at the longer length. The rule ships in the config: Llama 3.1 has "rope_scaling": {"rope_type": "llama3", "factor": 8.0, "original_max_position_embeddings": 8192}; gpt-oss uses YaRN with factor 32 from 4,096 to 131,072 ({{config|https://huggingface.co/openai/gpt-oss-120b/blob/main/config.json}}). Drop that field when converting or copying a config and the model still loads, still answers short prompts well, and degrades past the original length; diff the config against the original after any conversion.

Measured: past the trained length on the tiny GPT

The tiny GPT (RoPE, trained on 256-token windows) with the running story moved to start at position 1,024: loss 3.87 against 1.74 at position 0, and the greedy continuation turns into "friends like to play with the park was a little boy was very happy. As the sunrise, the sun came to the park." The config mistake does the same with no error: YaRN ×8 with original_max_position_embeddings set to 2,048 instead of 256 gives 3.78 at that position measured (section 8 of {{Positional Encodings|n:3c65c17b0d0d81a5b7c9e578fcdfac00}}, which measures every fix).
