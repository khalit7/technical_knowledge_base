A large language model (LLM) is a function that reads a sequence of tokens and returns, for the next position, a probability for every token in its vocabulary. Almost every LLM in use in 2026 computes that function with the same machine: a stack of identical decoder blocks, each mixing information across positions (attention, or a recurrent substitute) and then transforming each position on its own (a feed-forward network), with a normalisation and a residual connection around each. This page follows one token through one block, then asks at each component what the alternatives are and what each one costs, in parameters, in FLOPs and in the memory a running model must hold. 1. What an LLM computes: tokens in, a distribution out

Text is first cut into tokens, integer ids from a fixed vocabulary of size V, by a tokenizer (Llama 3.1 uses V = 128,256, {{config|https://huggingface.co/unsloth/Meta-Llama-3.1-8B/raw/main/config.json}}). The model then runs a fixed pipeline on each position:

Embedrow id of a V × d table: one vector of d numbers per token
→
L blockseach adds attention, then a feed-forward, to that vector
→
Final normrescale the vector
→
Unembedd × V matrix: one score (logit) per vocabulary entry
→
Softmaxlogits become probabilities that sum to 1

The vector of d numbers a position carries through the stack is the residual stream: every block reads it and adds its output back, so it is the model's working memory for that position. The scores before the softmax are the logits. In training, every position predicts its own next token at once and the loss is the average cross-entropy (minus the log probability given to the true next token); a causal mask stops a position from looking at later ones, so one forward pass over a 4,096-token sequence gives 4,096 training examples. In generation, the model predicts one token, appends it, and runs again (how the next token is picked from the distribution is {{Sampling and decoding|n:3c65c17b0d0d8115bafcda29a2c7086e}}).

Two small choices live here. The embedding and unembedding matrices both have V × d entries; tied embeddings use one matrix for both ({{Press and Wolf 2016|https://arxiv.org/abs/1608.05859}}), which small models do because the table is a large share of their parameters (Llama 3.1 8B does not tie, "tie_word_embeddings": false; its two tables are 1.05 billion of its 8.03 billion parameters, derived as 2 × 128,256 × 4,096). And the vocabulary size trades sequence length against table size: a bigger vocabulary needs fewer tokens per sentence, so attention is cheaper, but each token is rarer in training. How tokenizers are trained and fail is {{Tokenizers|n:3c65c17b0d0d817187bcd94a1b0f15ea}}.
