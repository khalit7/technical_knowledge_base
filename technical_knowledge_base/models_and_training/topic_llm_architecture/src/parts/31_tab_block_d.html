Real mistakes in a hand-written block

Four one-line bugs that a from-scratch attention commonly has, each run on the trained tiny GPT with the running sequence (src/block/mistakes.py, CPU). None of them raises an error: the model still produces fluent-looking text, and only the loss shows the damage. That is the case for always checking a rewritten block against a reference forward (here: the rewritten correct forward reproduces the model’s loss exactly, 1.96).

The missing mask does not change the last position (it has no future to see) but corrupts every earlier position’s keys and values from block 2 on, so even generation changes. The missing scale is the mildest here because d_head is only 32 (scores 5.7x too large in spread); at d_head 128 the softmax saturates harder. Splitting heads with .view(B, H, T, hd) cuts the sequence into head-sized slices: shapes are legal and nothing complains.

Interview questions

Count the parameters of one Llama 3.1 8B block from its config, in your head.

d = 4,096, 32 query heads and 8 KV heads of 128, FFN 14,336. Attention: Q and O are d x d each (2 x 16.8M), K and V are d x 1,024 each (2 x 4.2M): 41.9M. SwiGLU FFN: 3 x 4,096 x 14,336 = 176.2M. Two RMSNorm gains: 8,192. Block: 218.1M; x 32 = 6.98B; plus untied embedding and LM head, 2 x 128,256 x 4,096 = 1.05B: 8,030,261,248, the Hub’s exact count (the {{Config calculator|#t-calc}} reproduces it).

Forward and training FLOPs per token, and the training compute for D tokens?

Forward 2N + 4 x n_layer x d_attn x t; training about 3x that, 6N when context is short. Training compute about 6 x N x D. For Llama 3.1 8B (N = 7.50B matrix weights including the LM head) over an illustrative 15 trillion tokens: 6 x 7.50e9 x 1.5e13 = 6.8e23 FLOPs (calculated). Measured here: a training step counts exactly 3.0x the forward.

Llama 3.1 8B decodes token 131,072. Where does its compute go?

2N = 15.0 GFLOPs for the weights; attention over the context 4 x 32 x 4,096 x 131,072 = 68.7 GFLOPs, 4.6x the weights (calculated with the Config calculator’s formulas). GQA does not reduce this (32 query heads still do the dot products); it reduces the KV bytes read, which is what limits decode speed. Only windows, sparse or latent attention, or fewer attention layers (hybrids) cut the FLOPs.

Why divide the scores by √d_head? What breaks without it?

q · k sums d_head products; with unit-variance entries its variance is d_head. The softmax of large scores is nearly one-hot, its gradient nearly zero, so learning stalls, more so for wider heads. Measured here on the trained tiny GPT: removing the scale raises the loss on the running sequence from 1.96 to 2.88.

Pre-norm or post-norm? What does each cost?

Post-norm (2017 Transformer, BERT) normalises the stream after each add: activations stay bounded, but gradients to early layers pass through every norm and shrink, and deep models need a warmup and a lower learning rate. Pre-norm (GPT-2 onward) normalises only the sub-layer’s input: an identity path from embedding to output, stable at higher learning rates, but the stream’s norm grows with depth and a final norm is required before the LM head. Measured here: see the section above.

Why is the FFN 4x wide, and why is SwiGLU’s 8/3?

4x is the 2017 Transformer’s d_ff = 2,048 for d_model = 512, kept since. A two-matrix FFN of width 4d has 8 d² weights; SwiGLU has three matrices, so width 8/3 d gives the same 8 d² (Shazeer 2020, {{arXiv 2002.05202|https://arxiv.org/abs/2002.05202}}). Models then round for hardware: the tiny GPT’s SwiGLU preset uses 704 (8/3 x 256 rounded up to 32), Llama 3.1 8B uses 14,336 = 3.5 x 4,096.

Design: a model must answer 32k-token prompts cheaply. Which parts of the block would you change, and what does each cost?

Measure first: at 32k context a Llama-8B-shaped model spends about as much on attention as on all its weights in prefill (crossover 57,255 averaged over a prompt, 28,628 for decode), and decode time is set by bytes read (weights plus KV cache), not FLOPs. Levers: GQA or MLA cut KV bytes (decode speed, batch size) but not FLOPs; sliding-window layers interleaved with a few global ones (Gemma 3, 5:1) cut both, at a cost in long-range recall; replacing most attention layers with SSM layers (hybrids) makes most of the model’s cost independent of context, at a cost in exact copying; a smaller vocabulary or a tied head trims the fixed 2 x d x V. Check each with {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}, the {{KV-cache calculator|n:3fd5c17b0d0d81059ee1ce20c0326dc5#t-kv}} and the {{Config calculator|#t-calc}}, then on a long-context benchmark.
