A model's config.json is enough to know how many parameters it has, how many it uses per token, how many floating-point operations (FLOPs) each token costs, and how much memory its weights and its cache take. This tab does that arithmetic with one set of formulas, shows the formulas with the chosen model's numbers in them, and checks them against the exact stored tensor counts of real checkpoints.

Words used on this tab
Parameter: one trainable number (a weight, a bias or a norm gain). Total parameters: all of them, which is what must sit in memory. Active parameters: the ones one token actually multiplies through; smaller than the total only in a mixture of experts (MoE), where a router sends each token to k of E expert feed-forward blocks. FLOP: one floating-point add or multiply; a multiply-add is 2 FLOPs, so a token through a weight matrix with P entries costs 2P FLOPs. KV cache: the keys and values of every earlier token, kept so each new token does not recompute them; its size grows with the context. Prefill: processing the prompt (all its tokens at once); decode: generating one new token at a time against the cache. Shapes: d = hidden size (hidden_size), V = vocabulary, nh query heads, nkv key/value heads, dh head dimension, f feed-forward width (intermediate_size), L layers.

Where the parameters live

Both bars are drawn to the same scale: the top one is everything that must be in memory, the bottom one is what a single token multiplies through. For a dense model they are the same length. For an MoE model the routed experts shrink to k/E of their size in the bottom bar, which is the whole point of MoE: memory scales with the total, compute with the active part.

Try: Llama 3.1 8B (the embedding and the separate output head are 13% of it), then SmolLM2 135M (tied embeddings: the one vocabulary matrix is 21% of a small model), then DeepSeek-V3 (the routed experts are almost everything in memory and a small sliver per token).
