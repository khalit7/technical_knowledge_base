Induction heads: how a transformer copies from its context

The problem. Much of what a language model does with its context is copying: a name introduced in sentence one, a variable defined at the top of a file, a phrase the user typed. The model cannot store those in its weights; it must find them in the context at run time. Olsson et al. (Anthropic, 2022, {{In-context learning and induction heads|https://transformer-circuits.pub/2022/in-context-learning-and-induction-heads/index.html}}) traced much of this to one circuit, the induction head, and reported "a phase change that occurs early in training for language models of every size" when it appears.

How it works. Two heads in two layers. A previous-token head (section 2) writes into each position j the identity of token j−1. Later, at the current position whose token is A, an induction head builds a query that means "find positions whose previous token was A". It matches the position right after the earlier A, reads its token B, and raises B's logit. The rule it implements: [A][B] ... [A] → predict [B]. It needs two layers because the "previous token" information must already sit in the key before the second head can match on it.

The clean test. Feed a block of random tokens twice: <|endoftext|> R R, with R = 100 token ids drawn uniformly (8 random draws, seed 0). On the first copy nothing can be predicted, so the loss is near or above log(vocabulary). On the second copy every token is predictable by copying. The induction score of a head is its mean attention weight, over queries in the second copy, on the token just after the earlier occurrence of the current token: the exact place an induction head should look.

The cost and when it matters. An induction head needs the earlier tokens kept in full: that is the case for attention with a KV cache and against a fixed-size state. Jelassi et al. (2024, {{Repeat After Me|https://arxiv.org/abs/2402.01032}}) show that transformers "dramatically outperform state space models at copying and retrieving information from context"; hybrids keep a few attention layers largely for this ({{Reading: beyond attention|#t-read}}). Sliding-window layers can only copy within their window. How to check a model or a change: the repeated-random-tokens loss (first copy against second copy) is a 10-line test that needs no labels; run it after any change to attention, position encoding or caching.

Attention sinks: where attention goes when nothing is worth reading

The problem. Softmax weights must sum to 1. A head that has nothing useful to read at some position still has to put its weight somewhere. Trained models settle on one place: the first token. Xiao et al. (2023, {{StreamingLLM|https://arxiv.org/abs/2309.17453}}) named this the attention sink. The first token is a natural dump: every later query can see it, and its residual vector can be made distinctive (section 5) so that a head can match it without moving the output much.

Designs that build the sink in. Instead of letting a model hijack a real token, give every head somewhere to put weight on purpose. In gpt-oss, "each attention head has a learned bias in the denominator of the softmax", which lets a head "pay no attention to any tokens" (OpenAI, {{gpt-oss model card|https://arxiv.org/html/2508.10925}}, section 2.2, 2025-08-08; the tiny GPT's sink preset implements it, {{Attention lab|#t-attn}}). StreamingLLM also trained models with a dedicated learnable sink token. When it matters: any cache that evicts tokens (sliding windows, streaming chat, KV compression) must keep the sink, and any quantisation or pruning scheme must leave the first token's enormous vector alone (next section). How to check: the mean weight on token 0 by layer, as in the chart, takes one eager forward pass.
