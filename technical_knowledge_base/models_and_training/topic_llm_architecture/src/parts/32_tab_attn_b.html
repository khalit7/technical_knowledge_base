2. Four caches, one sequence

The same 16 tokens, the opening of the running sequence ("Once upon a time, in a big forest, there lived a rhinoceros"), decoded one at a time by the tiny GPT. The top panel is plain multi-head attention, the method every variant replaced; the bottom panel is the variant you pick. Both are drawn to one scale: one square is 16 numbers cached for one token in one layer, so area is memory. Under each panel, the 8 query heads of the current token are coloured by the KV head they read.

Shapes are the tiny GPT's presets (src/data/configs.py): 6 layers, 8 query heads of 32. GQA-4 and GQA-2 keep 4 and 2 KV heads, MQA one; MLA caches a 64-number latent plus a 16-number position key; the sliding window is drawn as 8 tokens illustrative so eviction is visible in 16 steps (the trained preset uses 64, and at its 256-token context keeps a quarter of the full cache on average). Byte counters are bf16 and agree with kv_cache_bytes_per_token in tiny_gpt.py.

What the picture says.

  • MHA (multi-head attention, {{Vaswani et al. 2017|n:3c65c17b0d0d81999af7f16f8ed8ee9e}}): each query head has its own key and value head, so each token stores 2 x 8 x 32 = 512 numbers per layer.
  • GQA (grouped-query attention, {{Ainslie et al. 2023|https://arxiv.org/abs/2305.13245}}): query heads share K and V in groups. GQA-2 keeps 2 KV heads, each read by 4 query heads: a quarter of the cache. Queries keep full resolution, so heads can still look at different things, but heads in one group must look through the same keys.
  • MQA (multi-query attention, {{Shazeer 2019|https://arxiv.org/abs/1911.02150}}): the limit, one KV head shared by all 8 query heads, an eighth of the cache.
  • MLA (multi-head latent attention, {{DeepSeek-V2|https://arxiv.org/abs/2405.04434}}): the token stores one compressed latent and one small position key shared by all heads; per-head keys and values are rebuilt from the latent by up-projections (or absorbed into the query and output at decode, so they are never materialised). Here 64 + 16 = 80 numbers instead of 512, between MQA and GQA-2 in size, but every head gets its own keys. How the compression, the decoupled RoPE key and the absorption work is animated step by step on {{DeepSeek|n:3c65c17b0d0d81a2ae7ec6796947a235}}; this lab does not repeat it.
  • Sliding window ({{Mistral 7B|https://arxiv.org/abs/2310.06825}}, {{Gemma 3|https://arxiv.org/abs/2503.19786}}, gpt-oss): what each token stores is unchanged; the layer simply forgets tokens older than the window. It caps the cache instead of shrinking each entry, and it changes what the model can see (section 6).
