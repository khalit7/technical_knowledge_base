The formulas, with this model's numbers

Every count below is a product of config fields, written once in src/calc/calc.py and ported line for line to this page. Each block lists the formula, then the same formula with the chosen model's values, then the count for all layers of that kind. Weight matrices dominate; biases and norm gains are listed so the total is exact, not because they matter for cost.

FLOPs: the 2N rule and the attention term
Forward FLOPs per token = 2 × (every weight a token multiplies through, the LM head included, the input embedding lookup excluded) + the attention term. The attention term is, per attention layer, 2 × nh × (query-key dimension + value dimension) FLOPs for every cached position the token reads: one multiply-add per dimension for the score q·k, one per dimension for the weighted sum of values. It does not depend on nkv: grouped-query attention (GQA) shrinks the cache, not the attention FLOPs. Training costs about 3× the forward pass (backward is about twice forward), which gives the familiar 6N per token. This is the same counting as Kaplan et al. 2020 (Table 1: Cforward ≈ 2N + 2nlayernctxdattn, {{arXiv 2001.08361|https://arxiv.org/abs/2001.08361}}), whose context term is ours averaged over a causal prefill.

Context length: where attention and the cache overtake the weights

At short context a token's cost is its weights: 2 FLOPs per active parameter, and the whole weight set read once per decode step. Both attention costs grow linearly with the context: the FLOPs to score every cached position, and the bytes of the cache itself, multiplied by the batch. Somewhere they pass the weights. Where depends on the attention design, and that is what the variants on the {{Attention lab|#t-attn}} are for. Press play to sweep the same model from a short prompt to its longest context; switch the attention to see the same model as if it had been built with full multi-head attention (MHA, one key/value head per query head) or multi-query attention (MQA, one key/value head for all).

What these curves leave out
Decode FLOPs assume attention over the whole cache in the plain (non-tiled) form; FlashAttention changes the memory traffic, not the FLOPs. MLA is counted in the absorbed form for decode (each head scores the 576-wide cache directly: DeepSeek-V3's {{inference/model.py|https://github.com/deepseek-ai/DeepSeek-V3/blob/9b4e9788e4a3a731f7567338ed15d3ec549ce03b/inference/model.py}} sets attn_impl = "absorb" by default at line 17 and computes the scores against kv_cache and pe_cache at lines 486 to 487, read 2026-10-18), which is why DeepSeek-V3's attention FLOPs per position are large while its cache is small. Sliding-window and chunked layers read at most their window. Recurrent layers (Mamba, Gated DeltaNet) are counted in their step-by-step form, with their fixed state taken as FP32. Weight bytes per step at batch 1 count only the experts one token uses; at larger batches, see the next section.

Dense vs MoE at equal active parameters

Take the chosen model and build its dense twin: every MoE layer replaced by one dense feed-forward block whose width is what a token actually uses (k routed experts plus the shared ones). The twin has the same active parameters and the same FLOPs per token. Step through what changes when the twin's feed-forward is cut into experts and more experts are added.
