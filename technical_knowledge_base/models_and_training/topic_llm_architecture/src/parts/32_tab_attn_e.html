8. Size the cache of a real model for a serving budget

The question a serving design starts from: how many sequences of this length fit on this GPU? Pick a model (configs read from the Hugging Face Hub on 2026-10-18, the same files and formulas as the {{Config calculator|#t-calc}}), a context, a batch and the number formats. The "what if" table re-runs the same model with its attention swapped, keeping everything else, so you can see what GQA, MQA or an MLA-sized latent would have bought it.

derived KV bytes = sum over attention layers of 2 x KV heads x head_dim x min(context, window) x bytes (MLA: (latent + RoPE key + indexer key) x context x bytes); state-space layers add a fixed state per sequence (fp32, as the calculator assumes). Windows are credited: a sliding layer holds at most its window. Weights = total parameters x the chosen bytes. GPU memory in GB (109 bytes), cache in GiB (230). Ten per cent of the GPU is held back for activations, the CUDA context and fragmentation illustrative; real engines reserve a configurable share (vLLM's gpu_memory_utilization defaults to 0.9). "What if" rows: MHA = one KV head per query head; GQA-8 = 8 KV heads; MQA = one; MLA = DeepSeek-V3's 512-number latent plus 64-number RoPE key in every attention layer; head_dim kept (for MLA models converted to MHA, head_dim = v_head_dim, DeepSeek's own convention).
