In one screen

Attention compares a query with every key by a dot product, and a dot product does not care where the two tokens sit: shuffle the tokens and each one gets the same scores. Something has to tell the model where each token is. There are three answers. Add a position vector to the input once (absolute: a learned table or fixed sinusoids). Change each attention score by the distance between the two tokens (relative: Shaw, T5, ALiBi, DeBERTa, and RoPE, which does it by rotating queries and keys). Or add nothing and let the causal mask carry the order (NoPE). Almost every open model since 2023 uses RoPE, so the practical questions are about RoPE: which base, how many dimensions to rotate, which layers get it, and how to stretch it past the length it was trained on.

Why attention needs positions at all

The problem. One attention head computes, for the token at position i, a score with every key j, sij = qi · kj / √d, turns the scores into weights with a softmax, and returns the weighted sum of the values, Σj aij vj. The query, key and value are linear maps of the token's vector, and nothing in that vector says where the token is. So if you shuffle the inputs, the outputs are shuffled the same way and nothing else changes: attention is permutation-equivariant. "Roxy climbed the hill" and "the hill climbed Roxy" contain the same set of vectors, and a model built only from attention and per-token layers would treat them as the same bag of words.

The causal mask leaks some order. A decoder masks the future: token i attends only to tokens 0 to i. Inside one layer that is still a set (shuffle tokens 0 to i − 1 and token i's output is the same), but every earlier token saw a different prefix, so from the second layer on the stack can count. A decoder with no positional encoding at all (NoPE) can therefore learn order; an encoder with bidirectional attention cannot.

Measured: shuffle the first 255 tokens of the running sequence, keep token 255 last

How to check where a model keeps position. Train a linear probe (ridge regression) to read the absolute position, 0 to 255, back from the residual stream after each block, on windows the probe never saw. An R2 of 1 means position is written in plainly; 0 means a linear readout cannot find it.

Cost, when it matters, how to check. Positions cost nothing measurable in parameters for every scheme except the learned table (65,536 parameters in the tiny GPT, 786,432 in GPT-2's 1,024 × 768). They matter whenever word order carries meaning, which in language is always; they matter most when a model must locate one token far back (a name 600 tokens earlier) and when it runs past the length it was trained on. The checks are the two above: a permutation test on one block, and a position probe per block.

Absolute positions: a learned table, or fixed sinusoids

The idea. Give every position its own vector pm and add it to the token's embedding before the first block: xm = e(tokenm) + pm. Everything after that is ordinary attention; position has to survive inside the residual stream. Two distinctions organise the whole field.

  • Learned or fixed. A positional embedding in the strict sense is a learned table: row m is a trained vector (GPT-2 has 1,024 rows, BERT 512). Simple, but there is nothing to look up past the last row. A positional encoding is a fixed function of position. The 2017 Transformer's sinusoids were chosen because they "may allow the model to extrapolate to sequence lengths longer than the ones encountered during training" (Vaswani et al. §3.5); learned embeddings gave "nearly identical results" there (Table 3, row E). The naming is loose in the literature: RoPE is "rotary position embedding" although nothing in it is learned.
  • Absolute or relative. Absolute methods answer "where is this token?" and are added once. Relative methods answer "how far apart are these two tokens?" and act inside attention, at every layer, on the score between a query and a key, which is what attention uses. A relative method gives the same score to the same pair of tokens wherever the pair sits.
PE(m, 2i) = sin(m / 100002i/d),   PE(m, 2i+1) = cos(m / 100002i/d)
m, i, d
position, frequency index (0 to d/2 − 1) and model width; each pair of dimensions is a clock running at its own speed, from one radian per token down to 1/10,000
why sin and cos together
for any offset k, PE(m + k) is a fixed rotation of PE(m), so PE(m) · PE(n) depends only on m − n; the cross terms with the token's own content do not, which is why the scheme stays absolute

What it costs. The learned table costs Lmax × d parameters (65,536 in the tiny GPT, 786,432 in GPT-2) and a hard cap. The sinusoids cost nothing. Both cost something less visible: position and content share the same vector from the first layer, which DeBERTa (below) argued against. The relative family


    

  • Shaw, Uszkoreit and Vaswani (2018). Add a learnable vector for each relative distance, clipped at a maximum k, directly into the attention computation: to the keys when scores are formed, and optionally to the values when they are summed. On WMT 2014 translation it beat absolute positions by 1.3 BLEU (English to German) and 0.3 BLEU (English to French), and "combining relative and absolute position representations yields no further improvement" (Shaw et al.).
    • 

  • T5's relative bias (2019). Simplify Shaw to one learned scalar per distance bucket, added to the logit. There are 32 buckets per head, shared across layers: the first half are exact offsets, the rest grow logarithmically up to an offset of 128, and everything further shares the last bucket. In the decoder, which looks back only, offsets 0 to 15 get a bucket each, then 16 to 18, 19 to 20, and so on, with 113 onwards in bucket 31 (recomputed with T5's bucket function). Cheap, per head, learned; one layer is blind beyond 128, though stacked layers can pass information further. Its extrapolation was the best of the pre-ALiBi baselines (600 to 800 extra tokens), at the price of training at least twice as slowly (ALiBi §2). Details on the T5 page.
    • 

  • ALiBi (2021). No embeddings at all: add a fixed, non-learned penalty −m · distance to each attention score, with a different slope m per head. For 8 heads the slopes are 1/2, 1/4, ..., 1/256; for 16, the geometric sequence from 1/√2 with ratio 1/√2 (Press et al. §3). MPT-7B's config generalises this as 2−8h/n over its 32 heads (alibi_bias_max 8: slopes from 0.84 to 1/256). Closer tokens score higher, steeply in some heads and gently in others. Its strength is extrapolation: a 1.3B model trained on 1,024 tokens "extrapolates to input sequences of length 2048, achieving the same perplexity as a sinusoidal position embedding model trained on inputs of length 2048 but training 11% faster and using 11% less memory". Used by BLOOM and MPT; every open model family since 2023 in the configs read here uses RoPE (or, in hybrids, no positions) instead, with scaling for long contexts. Its cost is that every head is forced to prefer nearby tokens; a head that should retrieve something far back has to overcome a penalty that grows with distance, and FlashAttention needed an explicit bias path for it. The tiny GPT's version is alibi_slopes and attn_bias (lines  and ). Measured here: 
    • 

  • DeBERTa's disentangled attention (2020). Summing content and position into one vector mixes the two from the first layer. DeBERTa keeps them apart: "each word is represented using two vectors that encode its content and position, respectively, and the attention weights among words are computed using disentangled matrices on their contents and relative positions" (He et al.): content-to-content, content-to-position and position-to-content terms. Absolute positions enter only in an "enhanced mask decoder" near the output, for masked-token prediction. Not run here: it is an encoder design, and none of the decoder configs read on this page uses it.

RoPE from zero: position as a rotation


The problem RoPE solves. We want a score that depends on how far apart two tokens are and not on where the pair sits, with no extra parameters, without touching the values, and in a form that still lets a key be computed once and cached. Rotary position embedding (RoFormer, Su et al. 2021) gets all four from one fact about rotations: it rotates each query and key instead of adding a position vector, which would change the vector's length and direction.


Step 1, two dimensions. Take a query q = (q0, q1) at position m and a key k at position n. Rotate the query by the angle mθ and the key by nθ, with R(α) the 2 × 2 rotation matrix. Then


(R(mθ) q) · (R(nθ) k) = qT R(mθ)T R(nθ) k = qT R((n − m)θ) k


why
a rotation's transpose is its inverse, and two rotations compose by adding their angles: R(α)T R(β) = R(β − α)
in complex numbers
read the pair as q0 + iq1; rotating is multiplying by eimθ, and Re[(q eimθ)(k einθ)*] = Re[q k* ei(m−n)θ]


The score now depends on n − m only. Each vector is rotated by its own absolute position, so a key can be rotated once, when it is computed, and stored rotated in the KV cache; the relative offset appears only inside the dot product. Rotations keep lengths, so the token's content (the vector's norm) is untouched. Values are not rotated: position shapes where a head looks, not what it reads. So RoPE is absolute in form and relative in effect.

The pairs form a geometric spectrum of clocks. In the tiny GPT (head dimension 32, base 10,000) there are 16 pairs: pair 0 turns once every 6.3 tokens, pair 6 once every 199, pair 7 once every 353 and pair 15 once every 35,333. Within its 256-token training window pairs 0 to 6 go round at least once, so the model has seen every angle they can take; pairs 7 to 15 only ever covered a wedge, pair 15 just 2.6 degrees of it. Fast pairs resolve neighbouring tokens; slow pairs measure long distances. That split, 7 fast and 9 slow, is the whole story of what breaks past 256, below. At Llama 3's shape (d = 128, base 500,000) the same spectrum spans pair 0 at 1 radian per token (a full turn every 6.3 tokens) to pair 63 at 2.46 × 10−6 radians per token (a full turn every 2.56 million tokens).

When it matters, and how to check. Every layer that uses RoPE must use the same convention as the weights were trained with: the frequency spectrum (base, rotated dimensions) and the pairing layout. Check by loading the checkpoint and comparing the loss on a few hundred tokens with the model card's or your own reference; the two silent failures below (wrong layout, wrong base) are measured on the tiny GPT in Common mistakes.

The two are equivalent only after permuting the rows of the query and key projections, which Hugging Face's Llama conversion script does with its permute function (convert_llama_weights_to_hf.py). The base, read from the configs


A larger base slows every pair except pair 0, so more pairs stay informative across a long window and fewer of them have a wavelength shorter than the context. Xiong et al. found Llama 2's base of 10,000 decayed attention too strongly beyond 4,000 to 6,000 tokens and proposed "increasing the 'base frequency b' of RoPE from 10,000 to 500,000", called adjusted base frequency, ABF (Xiong et al. §4.1); Llama 3 pretrains with 500,000 (Llama 3 page), and Qwen3 raises 10,000 to 1,000,000 for its long-context stage (Qwen3 page). This is a pretraining choice, not the NTK-aware scaling below, although both change the base. The chart reads rope_theta (or its equivalent) from every config this topic holds.














How to read a config's position line in 30 seconds. (1) Is there RoPE at all: rope_theta or rope_parameters, but check the modeling code for hybrids, where the field can be present and unused. (2) How many dimensions rotate: head_dim × partial_rotary_factor, or qk_rope_head_dim for MLA, or rotary_dim. (3) Which layers: layer_types, no_rope_layers, no_rope_layer_interval, per-layer-type rope_parameters. (4) Scaling: rope_scaling or rope_parameters.rope_type with its factor and original_max_position_embeddings, the length the model was actually pretrained at; max_position_embeddings is a ceiling, not the trained length (Qwen3's configs say 40,960 for a 32,768-token native window; MiniMax-M1's says 10,240,000).


transformers 5 renamed the field
From transformers 5, configs are standardised to rope_parameters, a dict holding rope_type, rope_theta, factor and the rest (nested per layer type for Gemma 4); old rope_theta and rope_scaling fields are still read and moved into it (RotaryEmbeddingConfigMixin.standardize_rope_params in transformers  modeling_rope_utils.py). Code that reads config.rope_scaling directly gets the old field or nothing.







Variants: partial, decoupled, multimodal, mixed layers


Five variants matter in practice. Partial RoPE rotates only a fraction of each head's dimensions and leaves the rest position-free, so those dimensions match on content alone. Decoupled RoPE (DeepSeek's multi-head latent attention, MLA) keeps position out of the compressed keys entirely and carries it in a small separate key: RoPE "is position-sensitive for both keys and queries", so a rotated key would block absorbing the key up-projection into the query, and every prefix key would have to be recomputed; the fix uses "additional multi-head queries and a shared key to carry RoPE" of 64 dimensions (DeepSeek-V2 §2.1.3; the mechanism is on Attention variants and the DeepSeek MLA explainer). Multimodal RoPE gives images and video several position indices: Qwen2-VL splits the rotation into "temporal, height, and width" components, and for text "these components utilize identical position IDs, making M-RoPE functionally equivalent to 1D-RoPE" (Qwen2-VL §2.1). Mixed layers interleave RoPE layers with layers that have no positions (NoPE) or a different base. No RoPE anywhere in hybrids, where recurrent layers carry order.

Partial RoPE comes in two kinds. The default kind spreads the whole spectrum over the rotated dimensions (exponents 2i/drot), so its slowest pair is as slow as a full head's. Gemma 4's "proportional" kind keeps the full head's exponents (2i/dhead) for the first pairs and sets the rest to zero frequency, so it keeps only the fast clocks.  Barbero et al. found Gemma uses RoPE's highest frequencies for positional attention patterns and "greatly prefers to use the lowest frequencies", which they suspect carry semantic information (Round and Round We Go); keeping only fast pairs is one way to act on that.

What transfers. The ordering of schemes inside the trained length at this scale is weak evidence about large models: at 12.3M tokens and 5.8M parameters the gaps are a few hundredths of a nat, close to seed noise. What does transfer is the mechanism the next sections measure: what each scheme does once the input is longer than anything it saw, which depends on the scheme's arithmetic and not on scale.







What breaks past the trained length


A model trained on sequences of length L has only seen relative distances below L. For pair i of RoPE that means angles from 0 to Lθi. A fast pair (wavelength shorter than L) has turned through the full circle, often many times, so every angle it meets later is familiar. A slow pair (wavelength longer than L) has only covered a wedge of its circle; the first distance beyond L pushes it into angles that no training example produced, and the attention scores it feeds are untested. Position Interpolation's authors describe the result as "catastrophically high attention scores that completely ruin the self-attention mechanism" (Chen et al. 2023); ALiBi's authors measured rotary models gaining for only 100 to 200 tokens past their training length (Press et al. §2).


Correction to the old page
It said RoPE fails past L "because high-frequency dims see unseen rotation angles". It is the other way round: the low-frequency pairs, whose wavelength exceeds L, are the ones pushed into unseen angles, which is why YaRN leaves high frequencies alone and interpolates the low ones fully (YaRN §3.2). High frequencies matter for the opposite reason: squeezing them (as Position Interpolation does) blurs neighbouring tokens. On the tiny GPT the slow pairs are pairs 7 to 15.

Stretching RoPE: the context-extension methods


Every method rewrites the frequencies θi (or, equivalently, the positions they multiply) of a model that already uses RoPE, then usually fine-tunes briefly at the new length. With s = Lnew / Ltrain, in historical order:


    

  • Position Interpolation (PI), Meta, June 2023: divide every position by s, f′(x, m) = f(x, mL/L′), so all angles stay inside the trained range. Its interpolation bound is "at least ∼600× smaller" than extrapolation's (Theorem 2.1); LLaMA 7B to 65B reached 32,768 tokens "within 1000 steps" of fine-tuning, with "minor degradation" on the original 2,048-token window, regressions of up to 2% on standard benchmarks (Chen et al.). The cost is that every pair is slowed by s, including the fast ones that resolve neighbouring tokens. Gemma 3 uses it: pretraining at 32K, then "a scaling factor of 8" on the global layers for 128K (Gemma 3 §5.3). Hugging Face's linear type divides the frequencies by the factor ().
    • 

  • NTK-aware scaling, bloc97 on Reddit, June 2023: instead of the positions, raise the base, b′ = b · s|D|/(|D|−2) (YaRN Eq. 16), "scaling high frequencies less and low frequencies more". Pair 0 is untouched and the slowest pair is slowed by exactly s: for base 10,000, d = 128 and s = 4, b′ = 40,890; for the tiny GPT (d = 32) at s = 8, b′ = 91,896 (recompute.py). It works surprisingly well with no fine-tuning, but some pairs end up slightly past their trained angles (try it in the animation). Dynamic NTK (emozilla, also on Reddit) sets s = max(1, l′/L) from the current length l′ at every step, so short inputs run unchanged (YaRN §3.3); Hugging Face's dynamic type uses a slightly different base, b · ((s l′/L) − (s − 1))d/(d−2) (). The original posts: NTK-aware, dynamic.
    • 

  • YaRN, Peng et al., August 2023: "NTK-by-parts" plus a temperature. With r(i) = L/λi, the number of turns pair i makes within the trained length, pairs with r > β (32 for Llama) are not interpolated, pairs with r < α (1) are divided by s, and a linear ramp blends between; then the logits are scaled by 1/t with √(1/t) = 0.1 ln s + 1 (Eqs. 17, 18, 22). It needed "10x less tokens and 2.5x less training steps than previous methods": Llama 2 7B and 13B were fine-tuned 400 steps at s = 16 (64K) and 200 more at s = 32, which then extrapolated to 128K (Peng et al.). DeepSeek-V2, V3 and V4, Qwen3, gpt-oss, Olmo 3, Kimi K2 and Mistral Large 3 ship it in their configs, and SmolLM3 at inference.
    • 

  • Llama 3 scaling (the llama3 rope type, July 2024): the same idea with the boundaries set by wavelength. Pairs with a wavelength under L/4 = 2,048 tokens are kept, those over L = 8,192 are divided by 8, and a smooth blend covers the six in between: 29 kept, 6 blended, 29 divided in Llama 3.1 8B (recompute.py, from its config and ). The Llama 3 paper itself does not describe this scaling; it describes the long-context stage (below).
    • 

  • LongRoPE, Microsoft, February 2024: one rescaling factor per pair, found by evolutionary search, which "extends the context window of pre-trained LLMs to an impressive 2048k tokens, with up to only 1k fine-tuning steps at within 256k training lengths", progressively, then readjusted at 8K to recover short-context quality; shown on LLaMA2 and Mistral (Ding et al.). Phi-3-mini's 128K version uses it ("a long context version via LongRope", Phi-3 report §2): its config carries 48 "long" factors from 1.07 to 64.76 and 48 "short" ones (1.10 to 3.05); Hugging Face picks the long set only when the sequence is longer than the original 4,096 (). LongRoPE2 (February 2025) blames the remaining failures on "insufficient training in higher RoPE dimensions", searches the factors with a "needle-driven" perplexity, and adds "mixed context window training" that keeps the original RoPE for short sequences; it extends LLaMA3-8B to a 128K effective length "while retaining over 98.5% of short-context performance, using only 10B tokens", 80 times fewer than Meta's own extension (Shang et al.).
    •

Beyond RoPE


    

  • NoPE. A decoder-only model with no positional encoding still learns order from the causal mask (measured above: a linear probe finds position in the NoPE model's middle blocks). Kazemnejad et al. found NoPE "outperforms other explicit positional encoding methods" on their length-generalisation tasks, and showed it "can represent both absolute and relative PEs, but when trained with SGD, it mostly resembles T5's relative PE attention patterns" (NeurIPS 2023). At scale, NoPE alone "lags behind" RoPE on standard benchmarks, although in needle tests it put the most attention on the needle (Yang et al. 2025). Hence the hybrids in the variants table: Cohere's RNoPE-SWA (RoPE in sliding-window layers, NoPE in one full-attention layer of four) reached 256K with "almost no loss" on needle tests and trains "nearly 2x faster at 128k", shipped in Command A; Llama 4 adds a position-dependent temperature on its NoPE layers ("inference time temperature scaling", from Scalable-Softmax); SmolLM3 found that removing RoPE from every 4th layer "improves long context performance without affecting short context capabilities". In 2026 hybrids (Kimi K3, Nemotron 3 Super, Granite 4.0-H) the attention layers carry no positions at all, because the recurrent layers between them already see the tokens in order.
    • 

  • CoPE (Contextual Position Encoding, Meta, 2024). Positions are counted, not indexed: each key gets a gate gij = σ(qi·kj), the position of key j from query i is the sum of the gates between them, and fractional positions interpolate between learned integer embeddings (§4). A head can therefore measure "the i-th sentence" or "the i-th verb" instead of tokens. It solves the selective copy, counting and Flip-Flop tasks where standard encodings fail and improves perplexity on language modelling and code (Golovneva et al.); not used at scale yet. Not run here: it needs a trained model and a counting task to mean anything.
    • 

  • Fixing the spectrum. FoPE (Fourier Position Embedding, ICML 2025) treats each dimension as a Fourier series and "zero-outs the destructive frequency components", those insufficiently trained because of truncation. HoPE (2024) argues "long-term decay is outdated" and keeps "only high-frequency signals", replacing the others with position-independent components, which is close to what Gemma 4's proportional RoPE ships. Wavelet-based positions (ICLR 2025) capture several window sizes at once "without limiting the model's attention field". And Barbero et al. found that Gemma uses RoPE's highest frequencies for positional attention patterns and "greatly prefers to use the lowest frequencies", which they suspect carry semantic information; this is one argument for partial RoPE.
    • 

  • Long context is not only positions. Sliding windows with a few global layers, chunked attention, KV compression and sparse attention (DeepSeek's NSA and DSA) decide what a long context costs to serve and whether the model uses it; that side lives on Long context and Attention variants, with the benchmarks on Long-context and multimodal benchmarks.

"RoPE breaks past L because the high-frequency dimensions see new angles"
The low-frequency pairs do: fast pairs have seen every angle. On the tiny GPT the culprits are pairs 7 to 15, whose wavelengths (353 to 35,333 tokens) exceed the 256 it was trained on. This was the old version of this page.


"The config has rope_theta, so the model uses RoPE"
Nemotron 3 Super's config says rope_theta 10000; transformers 's modeling_nemotron_h.py defines apply_rotary_pos_emb and calls it nowhere (counted by src/code/code_refs.py: ). Read the modeling code of hybrids before quoting their position scheme.


"NTK scaling means a base like 500,000"
NTK-aware scaling for s = 4 at d = 128 takes 10,000 to 40,890. 500,000 is Llama 3's pretraining base, chosen before training (ABF, Xiong et al.), not a scaling applied to a trained model.


"factor × original length = the context window"
Llama 3.1's 8 × 8,192 = 65,536 is half its configured 131,072; the model was trained at 128K in its long-context stage, so the rescaled spectrum does not have to cover the window on its own. Gemma 3's 8 × 32,768 = 262,144 is twice its 131,072. DeepSeek-V3's 40 × 4,096 = 163,840, Phi-3's 32 × 4,096 = 131,072, DeepSeek-V4-Pro's 16 × 65,536 = 1,048,576 and Mistral Large 3's 36 × 8,192 = 294,912 do match their configs' max_position_embeddings.


"RoPE extrapolates because it is relative"
Relative does not mean unbounded: the score at distance 10,000 uses angles a model trained at 4,096 never saw. Rotary models gained only 100 to 200 tokens past their training length in ALiBi's measurement, and the tiny GPT's RoPE loss rises from the first band past 256 (above); ALiBi, whose penalty is linear and has nothing to go out of range, is the relative method that extrapolates.


"LongRoPE is behind Phi-3's 2M-token context"
The 2,048K result is the LongRoPE paper's, on LLaMA2 and Mistral. Phi-3-mini uses LongRoPE for 128K.


"NoPE layers are worse at retrieval"
The old version of this page said so. In Yang et al.'s needle tests the NoPE variant put the most attention on the needle; its weakness was on standard benchmarks, which is why it is used in one layer of four rather than everywhere.







Interview questions


Why does a transformer need positional information, and does a decoder without any still know order?
Attention is permutation-equivariant: scores are dot products of per-token vectors. A causal decoder still leaks order through the mask (each token sees a different prefix), so from the second layer on it can count; measured above, NoPE's first block is exactly order-blind and later blocks are not. An encoder with full attention and no positions is a bag of words.


Derive why RoPE gives relative scores.
Rotate q by mθ and k by nθ: (R(mθ)q)·(R(nθ)k) = qTR(mθ)TR(nθ)k = qTR((n−m)θ)k, because rotations are orthogonal and compose by adding angles. Per pair of dimensions, with θi = base−2i/d.


Why are keys cached after rotation, and what does that break for MLA?
The rotation depends only on the key's own position, so it can be applied once. MLA wants to absorb the key up-projection into the query and cache only a latent; a position-dependent rotation between them blocks the absorption, so DeepSeek carries position in a separate 64-dimension RoPE key shared by all heads.


A model trained at 4K is run at 32K. Which RoPE dimensions misbehave and why?
The slow pairs, whose wavelength exceeds 4K: they only saw a wedge of their circle and now meet new angles. Fast pairs have seen every angle. Fixes interpolate the slow pairs (PI, NTK, YaRN, Llama 3), ideally leaving the fast ones alone.


PI against NTK-aware against YaRN in one sentence each.
PI divides every frequency by s (safe angles, blurred local detail); NTK raises the base so the slowest pair is divided by s and the fastest by 1 (good zero-shot, a few pairs slightly out of range); YaRN keeps pairs that turn more than β times, divides those that turn less than α times, ramps between, and adds a logit temperature (best per fine-tuning token).


What does YaRN's temperature do, and how big is it at s = 32?
It sharpens the softmax, which flattens when attention spreads over more tokens: √(1/t) = 0.1 ln s + 1, so logits × (0.1 ln 32 + 1)2 = 1.813. Hugging Face folds it into cos and sin, so the factor applies once to q and once to k.


Read this config: base 10,000, qk_rope_head_dim 64, YaRN factor 40, original 4,096, beta_fast 32, beta_slow 1. What is it and what happens?
DeepSeek-V3's decoupled RoPE key: 32 pairs, of which 11 are kept, 12 on the ramp and 9 fully interpolated, for a 163,840-token ceiling (recompute.py). Only the 64 rotated dimensions are stretched; the 128 latent-derived dimensions per head carry no position.


Design: you must ship a 128K model, have budget to pretrain at 8K, and must not lose short-context quality. What position recipe?
RoPE with a base chosen for the long target at pretraining (ABF: 500,000 or more at 8K), optionally NoPE or a fast-pair-only RoPE in a few global layers; then a continued-pretraining stage on long documents at increasing lengths with YaRN or Llama 3 scaling (a few billion to hundreds of billions of tokens), mixed with short data; ship the scaling in the config, prefer dynamic scaling at inference so short prompts run unscaled, and verify with needle and multi-hop long-context evaluations plus the short-context suite at every stage.


Design: an agent must handle 1M-token contexts on a hybrid. Where do positions go?
Let the linear or SSM layers carry order (they are recurrent), keep the few full-attention layers position-free or fast-pairs-only so nothing goes out of range at 1M (Kimi K3, Nemotron 3 Super, Gemma 4's global layers), and spend the remaining effort on what long context really costs: KV memory and effective use, owned by the Long context page.


How would you check that RoPE scaling is configured correctly on a checkpoint you were handed?
Print the resolved rope parameters (transformers 5 standardises them into config.rope_parameters), compare original_max_position_embeddings with the paper's pretraining length, compute the inverse frequencies with the library's function and with your own, and measure loss per position band on long held-out documents with and without the scaling: a correct setup costs a little below the original length and saves a lot beyond it (the tiny GPT's table above).

What transfers, and what does not


    

  • Transfers: which pairs go out of range and when (arithmetic, scale-free); that ALiBi, whose penalty has nothing to go out of range, stays flat while plain RoPE climbs; that NoPE and sinusoids are no safer (their attention and inputs past 256 are just as new); that interpolating every pair (PI) costs the most short-range quality, NTK-aware the least, and that by-parts scaling (YaRN) reaches furthest at a cost in between; that static scaling costs inputs inside the trained length.
    • 

  • Does not transfer: the size of each gap. A 5.8M-parameter model trained on 12.3M tokens of simple stories, with stories of about 230 tokens on average (122,021,463 tokens over 529,875 stories, root src/data), needs little long-range information, so a model that ignores distant tokens loses little here; on real long documents the far tokens matter and the gaps between schemes are different. The published long-context results (YaRN, PI, LongRoPE perplexity curves, needle tests) are the evidence for large models; they exist only as figures in their papers and are not reproduced here.
    • 

  • Not run here: fine-tuning each method at the new length (the recipes do this; two fine-tunes are the long_context sibling's, above), dynamic NTK (in one forward pass over 2,048 tokens it equals NTK-aware at s = 8 under the YaRN paper's definition, a calculation), LongRoPE (needs a factor search), and any pretrained model past its window (hours of CPU for little the toy does not already show).
