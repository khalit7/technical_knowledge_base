23 MoE models, December 2023 to July 2026

E: routed experts per MoE layer; k: routed experts per token; shared: always-on experts; width: one routed expert's hidden size (d: model width); MoE layers: of all layers; balancing: the config's topk_method (noaux_tc = DeepSeek's bias) or use_routing_bias; groups: n_group/topk_group; scale: routed_scaling_factor; C(E, k) = number of possible expert sets per token. Config fields can disagree with what training used: router_aux_loss_coef (0.001 in Qwen3, 0.02 in Mixtral, 0.9 in gpt-oss-120b) is the value transformers would use to fine-tune, not a stated pretraining value.

Design questions

You have 64 H100s (8 nodes of 8, NVLink inside, 400 Gb/s InfiniBand between) and a compute budget for a 7B-active model. Design the FFN and its parallelism.

Fine-grained MoE: for example 128 routed experts of width about d/4 with top 8 plus 1 shared, first 1 to 3 layers dense, sigmoid scores with bias balancing and a tiny sequence-wise loss, dropless kernels, router in float32 (and a z-loss if logits grow). Expert parallel 8-way inside each node (NVLink), data parallel (FSDP/ZeRO) across nodes for attention and dense parts, so the all-to-all stays on NVLink; if experts must span nodes, group-limit each token to 2 to 4 nodes. Measure per-expert load and dropped fraction from step 1, and check memory: total parameters, not active, set the shard sizes.

Serve a 1T-total, 32B-active MoE at low latency for batch 1 and cheaply at batch 512. What changes between the two?

Batch 1: few experts touched, decode reads about the active weights, latency is set by memory bandwidth and the all-to-all latency; use fewer, larger nodes and quantised experts (4 to 8 bits) so the model fits in as few GPUs as possible. Batch 512: nearly all experts touched every step; spread experts wide (EP over many GPUs) so each GPU's few experts get a useful slice of tokens, replicate hot experts (EPLB), disaggregate prefill from decode, and use grouped GEMM ({{Distributed and disaggregated serving|n:3c65c17b0d0d8170bd7cdf47af0ec07b}}, sections 5 to 7). The KV cache, not the experts, then limits the batch: that is an attention-design question.

"Sigmoid routing picks different experts from softmax": true or false?

From the same logits both pick the same top k (both are increasing); they differ in gate weights. Once a selection bias or a group limit is added, softmax-plus-bias and sigmoid-plus-bias can pick differently, because the bias is added on different scales.
