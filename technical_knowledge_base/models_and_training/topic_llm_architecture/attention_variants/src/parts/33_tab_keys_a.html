Pick a query token and a layer: the shading is SmolLM2's real attention from that query, and the underline marks what each variant lets the query read. The counters say how much of the real attention the variant keeps.

measured on Apple M1 Pro (CPU): SmolLM2-135M revision 93efa2f0, fp32, eager attention, 226 tokens, no BOS (its tokenizer adds none). Weights are stored at 64 levels of each row's maximum. The sparse rows use the real weights to choose what to keep, an oracle: a real indexer (DSA) or compressed-branch score (NSA) only approximates that choice, so the "kept" numbers are an upper bound for those methods. SmolLM2 was trained with full attention; nothing here is SmolLM2 running a variant, only which of its own weights a variant would let through.

Stacked windows: how far back the last token can see, layer by layer

A sliding window limits one layer, not the model: layer 2 reads layer 1's outputs, which already mixed in their own windows, so the reach grows by W minus 1 per layer. The same query, the same window, two stacks: every layer local (Mistral 7B v0.1's design), and two local layers then one global (the tiny GPT's swa64_g3 pattern; Gemma 3 uses five then one). calculation of reachability (which positions can influence the query through some path), not of attention weights.
