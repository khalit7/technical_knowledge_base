4. Sliding windows and local : global interleaves

The idea. A sliding window of W lets each query attend only to the last W tokens (itself included). The cache becomes a ring buffer of W entries per layer: token t overwrites slot t mod W (Mistral 7B's "rolling buffer cache", which its paper says "reduces the cache memory usage by 8x" at 32K with W = 4,096, {{arXiv 2310.06825|https://arxiv.org/abs/2310.06825}}). Memory per sequence stops growing at W, and so does the decode read. This page treats the window as a cache design; what it does to long-context quality, and how local and global layers trade memory against recall at 128K, is on {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}}.

Reach grows with depth. Layer 2 reads layer 1's outputs, which each mixed W tokens, so after L local layers the last token can be influenced by the previous L · (W − 1) tokens: Mistral's 32 layers and W 4,096 give the "theoretical attention span of approximately 131K tokens" its paper states. Theoretical, because the information has to survive many hops of mixing; the {{Which keys are read|#t-keys}} tab animates the reach layer by layer for an all-local stack and a 2 : 1 interleave.

Interleaves. Most models that use windows now keep some full-attention (global) layers so that any token can reach any other in one hop: Gemma 2 alternates 1 : 1 with W 4,096 (context 8,192), Gemma 3 uses "5 local layers for every global layer" with W 1,024, Gemma 4 keeps 5 : 1 with W 1,024 (50 and 10 layers in the 31B config), gpt-oss alternates 1 : 1 with a "bandwidth" of only 128 tokens. Gemma 3's report measured the trade (Google, section 5.2): ratio and window changes have "minimal impact on perplexity", and the cache overhead at 32K falls from 60% of model memory with global-only attention to under 15% with 1 : 3 and W 1,024 (figures and the ratio wording as the Long context child quotes them).

Measured: how small can the window be?

measured on Apple M1 Pro (MPS training, CPU evaluation): the tiny GPT with RoPE, trained with every layer local at W = 16, 32, 64 (the lab's run) and 128, against full attention (W = 256, the training length), plus two interleaves (layers 3 and 6 global); and the full-attention model served with a window it was never trained with. Held-out loss on the lab's 192 fixed validation windows, CPU, by position.

Predict: the tiny GPT trained with every layer limited to a 16-token window, then the same with layers 3 and 6 made global (2 local : 1 global). How much of the gap to full attention does the interleave close?

The cost. A local layer forgets everything older than W unless another layer carried it forward; with all layers local, recall of a fact from far back depends on many hops. Interleaving brings back one full cache per global layer, so the memory saving is set by the share of global layers (5 : 1 keeps about a sixth of the full cache at long context). Kernels must handle the window (FlashAttention has a window_size argument) and the cache must be a ring buffer or a paged cache that frees old blocks. When it matters: at contexts several times W, where the full layers' cache dominates. How to check: sliding_window and layer_types (or Gemma 3's sliding_window_pattern, where every 6th layer is global) in the config; in transformers 5.20.1 a window keeps the keys with kv_idx > q_idx - sliding_window, W keys including the query itself (section 9).
