2. Sharing keys and values: why MQA and GQA cost so little

The idea. MQA (Shazeer 2019, {{arXiv 1911.02150|https://arxiv.org/abs/1911.02150}}) keeps H query heads but only one key head and one value head; GQA (Ainslie et al. 2023, {{arXiv 2305.13245|https://arxiv.org/abs/2305.13245}}) keeps Hkv of each, every one shared by a group of H / Hkv query heads. The cache shrinks by H / Hkv. The question is why the model barely notices.

The derivation. Write head h's score as a bilinear form of the two tokens: qht · khj = xtT (WQh)T WKh xj. In MHA each head owns both factors. In MQA every head uses the same WK, so head h's form is (WQh)T WK: the heads still ask different questions (their query maps differ, so their attention patterns differ), but they must find the answers in the same dh numbers per token. Values work the same way: head h contributes WOh WV Σj ahtj xj, so every head mixes the same value vectors with its own weights and its own output map. Sharing therefore costs little exactly when the keys and values the heads need live in a subspace much smaller than H · dh. That is measurable.

Projection is not pooling. The GQA paper converts a trained MHA checkpoint by averaging the key and value projections of the heads in each group, then trains for 5% of the original steps ("uptraining"). Trained from scratch, sharing is free here. Trained with the same budget, the lab's GQA-4, GQA-2 and MQA land at 2.185, 2.182 and 2.177 (seed 1: 2.185) against MHA's 2.160 (seed 1: 2.175) on 100 windows: inside the seed spread (root {{Attention lab|n:3fd5c17b0d0d8172b490dc9f9ac281df}}). A model that is trained with shared heads from the start learns query maps that ask their questions of one shared key space; the rank measurement above says 64 to 128 directions are enough for this model, and MQA gives it 32 for keys and 32 for values in every layer.

At scale the gap appears: published, not run here

DeepSeek-V2's Appendix D.1 (Table 8, {{arXiv 2405.04434|https://arxiv.org/html/2405.04434}}; DeepSeek's own runs) trained 7B dense models on 1.33T tokens with parameters aligned by layer count: MMLU MHA 45.2, GQA-8 41.2, MQA 37.9; BBH 37.0 / 35.6 / 33.2. The GQA paper (Table 1, T5-XXL uptrained, Google): MHA 47.2 average at 1.51 s per sample, GQA-8 47.1 at 0.28 s, MQA 46.6 at 0.24 s. Both are consistent with the derivation: a model with enough data to use more key directions than the shared heads provide pays for sharing; the tiny GPT, which saw 12.3M tokens, is limited by data, not by key directions, so it does not. Not run here: a 7B model on 1.33T tokens.

The cost. GQA-8 on Llama 3.1 8B's shape stores 4x less than MHA and decodes about 2.9x faster in the lab's one-layer MPS benchmark (17.49 to 5.97 ms at 32K tokens, batch 4): close to the 4x in bytes, because decode is memory-bound. It also has fewer parameters (WK and WV shrink by 4x), which papers usually give back to the FFN or the depth when they compare at equal size. When it matters: always at serving; GQA with 4 to 16 KV heads is the default of almost every 2024 to 2026 open model without MLA (the root's Architecture map). How to check: num_key_value_heads in the config; cache per token = 2 · layers · num_key_value_heads · head_dim · bytes.
