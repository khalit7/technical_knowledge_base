4. The per-layer strips

A card's "layer mix" line ("52 sliding-window + 10 global") hides where those layers sit, and position matters: Gemma 3 puts a global layer after every five windowed ones so that information never travels more than five layers before it can reach the whole context, while a model that put all its global layers at the end would not. The strips draw each layer in order, left (layer 0, next to the embedding) to right (the last layer, next to the output head), each model stretched to the same width.

Three bars per model: mixer, FFN, position. The number on the right is the KV cache per token in bf16 (every layer at full cost). Click a name to open that model in {{Decode a config|#t-dec}}. The tiny GPT is this topic's running example (6 layers of multi-head attention with learned positions, 6,144 bytes per token), drawn on the same scale of colours.

How to read one. Count the blue, green and purple cells in the top bar: full attention, MLA and trained sparse layers, the ones whose cache grows with every token. Yellow cells (linear) and teal cells (windowed) stop growing. Orange cells in the middle bar are expert layers, so a grey first cell is the dense prefix DeepSeek-style models keep. A black cell (white in dark mode) in the bottom bar is a layer with no positional encoding: Llama 4 Maverick's every fourth layer, SmolLM3's every fourth, Kimi K3's attention layers. The {{Compare architectures|#t-cmp}} tab has the strips for every model, sortable and filterable.

5. The attention ladder: one token, seven designs, the same shape

The mixer bar has seven colours because there are, in practice, seven answers to one question: what must this token leave behind in this layer so that later tokens can attend to it? The animation runs one token through one layer of the same shape for every design: 32 query heads of 128 (Llama 3.1 8B's shape), 16 earlier tokens already cached, and five steps (arrive, project, store, read at decode, scale to 128K tokens). MHA's footprint stays drawn dashed behind every other design, so each is seen against what it replaced.

One cell is 256 numbers: one KV head's key and value (128 + 128). Cells are drawn to scale in every design.

Shapes: 32 query heads of 128 as Llama 3.1 8B ({{config|https://huggingface.co/unsloth/Meta-Llama-3.1-8B/raw/main/config.json}}); MLA at DeepSeek-V3's latent of 512 plus a 64-number RoPE key ({{config|https://huggingface.co/deepseek-ai/DeepSeek-V3/blob/main/config.json}}); the recurrent state 32 heads of 128 × 128, the shape of Qwen3-Next's Gated DeltaNet layers and Kimi Linear's KDA layers (their configs). The 16-token context and the 8-token window are illustrative; the 128K figures use the formulas of this page. The animation runs only on screen, and starts paused, one step at a time, under reduced motion.

Step 5 is the argument in numbers, per layer at 128K tokens in bf16: MHA 2 GiB, GQA 512 MiB, MLA 144 MiB, MQA 64 MiB; a 4,096-token window caps at 16 MiB and a recurrent state stays at 1 MiB. Why each design costs little quality, MLA's absorbed form and its decoupled RoPE key, are derived on {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}} and animated on {{DeepSeek (the MLA explainer)|n:3c65c17b0d0d81a2ae7ec6796947a235}}; the {{Attention lab (on Topic: llm-architecture)|n:3fd5c17b0d0d8172b490dc9f9ac281df}} trains the tiny GPT with each. This page's question is narrower: which rung each released model chose, and in what mixture. The next sections take the deltas one at a time.
