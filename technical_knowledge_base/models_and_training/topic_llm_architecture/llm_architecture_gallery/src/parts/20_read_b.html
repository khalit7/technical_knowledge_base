1. The gallery, and how this page rebuilt it

What it is. The {{LLM Architecture Gallery|https://sebastianraschka.com/llm-architecture-gallery/}} is Sebastian Raschka's side-by-side reference of open-weight model architectures: a drawn diagram per model and a fact sheet with total and active parameters, decoder type, attention and layer mix, context length, licence, links to the config and the technical report, and one headline number, the KV cache per token in bf16. Its metadata is a single {{models.yml|https://github.com/rasbt/llm-architecture-gallery}} under Apache 2.0; this page uses it at commit 589d213 (4 October 2026, read 18 October 2026): 109 entries from GPT-2 XL to models released in October 2026. It is a third-party summary: useful because it is consistent, not because it is a primary source.

Its convention for the headline number, from its {{KV-cache notes|https://sebastianraschka.com/llm-architecture-gallery/kv-cache-calculations/}}: "the logical cache added by one token for one sequence", batch 1, 2 bytes per element, summed over every layer that appends to a growing cache. A sliding-window layer is counted at full cost ("It changes how long a token remains in the cache"), linear and state-space layers count 0 B and their fixed state is kept outside the number, and MLA counts its compressed latent, not expanded keys and values. The root page's {{Architecture map (on Topic: llm-architecture)|n:3fd5c17b0d0d8172b490dc9f9ac281df}} and this page use the same convention, so the three agree, and both add a second number with the windows credited.

How this page rebuilt it. For each entry the script downloads nothing at build time: it reads the saved config.json (public mirrors for gated Meta and Google repos), decodes one code per layer for the mixer, the FFN and the position scheme, and sums the cache layer by layer. Then it compares its own number with the gallery's.

Not rebuilt: four entries whose config is not public (three gated repos, one LoRA adapter with no config of its own), and the three DeepSeek V4 entries, whose compressed caches the per-layer formula does not express; for those the gallery's figure is shown, with the reconstruction in section 12.

2. Reading a model card in thirty seconds

A model card answers five questions, and each answer predicts something different. Ask them in this order:

  1. Total and active parameters. The total is the memory you must provision for the weights; the active count is what runs per token, so it sets latency and price. They are routinely conflated. Their ratio is the MoE sparsity.
  2. Attention type and layer mix. Full attention, windows, linear layers or trained sparse attention, and in what proportion: how cost grows with context, which matters more than the advertised context length.
  3. KV cache per token, times context, times concurrent requests, with the windows credited: whether long context fits, in GiB.
  4. Experts: routed, active, shared. How much expert parallelism serving needs, and how much skewed traffic will hurt (the {{Mixture of experts|n:3fd5c17b0d0d81fda06bf955af7c2b58}} page owns why).
  5. Licence, and whether base weights shipped. Base weights decide whether you can post-train at all.

gpt-oss-120b (August 2025)

  1. 117B total, 5.1B active (OpenAI's {{model card|https://huggingface.co/openai/gpt-oss-120b}}, vendor): 4.4% runs per token, so it decodes like a 5B model and needs memory for 117B.
  2. 36 layers alternating a 128-token sliding window and full attention, one to one: cost grows with context through 18 of 36 layers.
  3. 8 KV heads of 64: 72 KiB per token on the card, 36 KiB per token effective at 131,072 tokens; one full-context request holds 4.5 GiB, so 16 such requests need 72 GiB of cache.
  4. 128 routed experts, 4 active, no shared expert in the config.
  5. Apache 2.0; the card does not say whether a base checkpoint shipped.

Kimi K3 (July 2026)

  1. 2.8T total, 104B active (gallery line from Moonshot's card, vendor): 3.7% runs per token.
  2. 93 layers: 69 Kimi Delta Attention layers (linear, fixed state) and 24 MLA layers that carry no positional encoding (mla_use_nope).
  3. Only the 24 MLA layers grow a cache: 24 × (512 + 64) × 2 = 27 KiB per token, 3.4 GiB at 131,072 tokens; the 69 linear layers add a fixed state of 1,572,864 numbers each, 414 MiB per sequence in FP32 (matrix state only).
  4. 896 routed experts, 16 active, 2 shared; the first layer dense.
  5. "Kimi K3 License" (gallery); read it before planning to serve or post-train.

3. Reading the config: the fields behind each strip

The card is a summary; the config.json is what the loading code reads, so when the two disagree the config wins for that checkpoint. Thirty fields describe the architecture, but each strip comes from a handful, and every lab spells them differently. The {{Decode a config|#t-dec}} tab shows, for any of the 105 models, exactly which fields this page read and what each one set.

Traps met building this page, each real:

  • The config is not where you think. Multimodal checkpoints nest the language model under text_config (Gemma 4, Qwen3.5, Kimi K3); DeepSeek V4.1-Flash stores its text_config as a Python-repr string, not JSON; DeepSeek V4-Pro stores compress_ratios as a string holding a list; Mistral Large 3 ships params.json with its own key names.
  • A saved file that is not a config. Gated repos answer a download without a token with an error body, and a script that does not check saves it as config.json. This page's own earlier build had nine such files (eight error bodies from gated repos and one "Entry not found"), among them unsloth__Meta-Llama-3-8B.json containing only Invalid username or password. and google__gemma-3-27b-it.json beginning Access to model google/gemma-3-27b-it is restricted. Those models were silently skipped; Llama 3 8B now comes from the public mirror unsloth/llama-3-8b.
  • The list includes layers that are not in the stack. Step 3.5 Flash's layer_types has 48 entries for 45 decoder layers: the last three are its multi-token-prediction layers.
  • The config alone is not enough. Gemma 4 E2B's config says head_dim 256, but transformers gives its global layers global_head_dim 512 and lets its last 20 layers reuse earlier caches; Motif 3 has kv_lora_rank like MLA, but its released code caches the expanded keys and values. Both are settled only by reading the modeling code (section 1's corrections).
