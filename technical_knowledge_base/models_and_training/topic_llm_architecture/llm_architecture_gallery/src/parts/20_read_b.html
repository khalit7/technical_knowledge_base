2. Reading a model card in thirty seconds

Five questions, in this order; each answer predicts something different.

  1. Total and active parameters. Total is the weight memory; active is what runs per token, so latency and price. Their ratio is the MoE sparsity. They are routinely conflated, and an encoder-decoder can have two active counts (DeepSeek V4.1-Flash: 8B during prefill, 16B during decode, gallery).
  2. Attention type and layer mix. Full attention, windows, linear layers or trained sparse attention, and in what proportion: how cost grows with context, which matters more than the advertised context length.
  3. KV cache per token, times context, times concurrent requests, with the windows credited: whether long context fits, in GiB.
  4. Experts: routed, active, shared. How much expert parallelism serving needs, and how much skewed traffic will hurt.
  5. Licence, and whether base weights shipped. Base weights decide whether you can post-train at all.

gpt-oss-120b (August 2025)

  1. 117B total, 5.1B active (OpenAI's {{model card|https://huggingface.co/openai/gpt-oss-120b}}, vendor): 4.4% runs per token, so it decodes like a 5B model and needs memory for 117B.
  2. 36 layers alternating a 128-token sliding window and full attention, one to one: cost grows with context through 18 of 36 layers.
  3. 8 KV heads of 64: 72 KiB per token on the card, 36 KiB per token effective at 131,072 tokens; one full-context request holds 4.5 GiB, so 16 such requests need 72 GiB of cache.
  4. 128 routed experts, 4 active, no shared expert in the config.
  5. Apache 2.0; the card does not say whether a base checkpoint shipped.

Kimi K3 (July 2026)

  1. 2.8T total, 104B active (gallery line from Moonshot's card, vendor): 3.7% runs per token.
  2. 93 layers: 69 Kimi Delta Attention layers (linear, fixed state) and 24 MLA layers that carry no positional encoding (mla_use_nope).
  3. Only the 24 MLA layers grow a cache: 24 × (512 + 64) × 2 = 27 KiB per token, 3.4 GiB at 131,072 tokens; the 69 linear layers add a fixed state of 1,572,864 numbers each, 414 MiB per sequence in FP32 (matrix state only).
  4. 896 routed experts, 16 active, 2 shared; the first layer dense.
  5. "Kimi K3 License" (gallery); read it before planning to serve or post-train.

  • The config is not where you think. Multimodal checkpoints nest the language model under text_config (Gemma 4, Qwen3.5, Kimi K3); DeepSeek V4.1-Flash stores its text_config as a Python-repr string, V4-Pro its compress_ratios as a string holding a list; Mistral Large 3 ships params.json with its own key names.

4. The per-layer strips

A card's "52 sliding-window + 10 global" hides where those layers sit, and placement matters: Gemma 3 puts a global layer after every five windowed ones, so information never travels more than five layers before it can reach the whole context. The strips draw each layer in order, left (next to the embedding) to right (next to the output head), every model stretched to the same width.

Twelve stacks side by side: the cache grows only in the blue, green and purple cells

Three bars per model: mixer, FFN, position; on the right the KV cache per token in bf16, card convention. Click a name to open it in {{Decode a config|#t-dec}}. The tiny GPT is this topic's running example (6 layers of multi-head attention with learned positions, 6,144 bytes per token).

How to read one. Blue (full attention), green (MLA) and purple (trained sparse) cells grow a cache with every token; teal (windowed) cells stop at W and yellow (linear) cells keep a fixed state. Orange cells in the middle bar are expert layers, so a grey first cell is the dense prefix DeepSeek-style models keep. A black cell (white in dark mode) in the bottom bar is a layer with no positional encoding: Llama 4 Maverick's every fourth layer, SmolLM3's every fourth, Kimi K3's attention layers. {{Compare architectures|#t-cmp}} has the strips of every model, sortable and filterable.

Seven colours, seven answers to one question: what must this token leave behind in this layer so later tokens can use it? A key and value for every query head (MHA), one per group (GQA) or one for all (MQA), a latent every head rebuilds from (MLA), the same entries for the last W tokens only (window), all entries kept but only the top k read (trained sparse), or a fixed-size state (Gated DeltaNet, KDA, Mamba-2). How each works is on {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}} and {{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}}; this page's question is which answer each released model chose, and in what mixture.
