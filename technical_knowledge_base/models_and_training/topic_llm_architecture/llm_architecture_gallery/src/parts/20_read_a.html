The idea in one screen

An open model of 2026 is still the decoder block of {{Topic: llm-architecture|n:3fd5c17b0d0d8172b490dc9f9ac281df}} with a handful of choices changed, and two of them decide what it costs to serve: how many weights run per token (experts) and what each token leaves behind in each layer (shared heads, latents, windows, linear layers). Both can be read off a config.json in thirty seconds; in 2026 almost every model is sparse on both, in different proportions.

Fourteen models, one row each: which choices they made

Tinted cells are choices, read from each model's own config by src/gen_data.py; layer counts are out of the model's layers (W the window, 1K = 1,024 tokens). Click a row to open it in {{Decode a config|#t-dec}}; on a phone, scroll sideways. Bottom row, the gallery's 66 models of 2026: MLA in 16; no plain MHA at all; windows in 25; linear or SSM hybrids in 20; trained sparse attention in 11; MoE in 52 (39 add a shared expert and 31 keep their first layers dense); partial RoPE in 25; layers with no position in 5; median cache 68.6 KiB per token against 144 KiB for the 2025 models.

You need: the decoder block and what a KV cache is ({{The transformer from zero|n:3fd5c17b0d0d8174980ddde4a20c7b3c}}). This page does not teach the mechanisms; it counts who uses them and links each to its owner: {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}} (MHA, GQA, MQA, MLA, windows, sparse attention), {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}} (sizing a whole cache at a context length), {{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}} (linear and state-space layers), {{Mixture of experts|n:3fd5c17b0d0d81fda06bf955af7c2b58}}, {{Positional Encodings|n:3c65c17b0d0d81a5b7c9e578fcdfac00}} and {{Normalisation, residuals and stability|n:3fd5c17b0d0d8163b50dc5e9d9240e89}}.

1. The gallery, and the six figures the configs do not reproduce

The {{LLM Architecture Gallery|https://sebastianraschka.com/llm-architecture-gallery/}} is Sebastian Raschka's side-by-side reference of open-weight architectures: a diagram and a fact sheet per model (total and active parameters, attention and layer mix, context, licence, links to config and report) and one headline number, the KV cache per token in bf16. Its metadata is one {{models.yml|https://github.com/rasbt/llm-architecture-gallery}} (Apache 2.0), used here at commit 589d213 (4 October 2026, read 18 October 2026): 109 entries from GPT-2 XL to October 2026. It is a third-party summary, useful because it is consistent, not because it is primary.

Its convention ({{KV-cache notes|https://sebastianraschka.com/llm-architecture-gallery/kv-cache-calculations/}}): "the logical cache added by one token for one sequence", batch 1, 2 bytes per element, summed over every layer that appends to a growing cache. A sliding-window layer counts at full cost ("It changes how long a token remains in the cache"), linear and state-space layers count 0 B with their fixed state kept outside the number, and MLA counts its latent, not expanded keys and values. The root's {{Architecture map (on Topic: llm-architecture)|n:3fd5c17b0d0d8172b490dc9f9ac281df}} and this page use the same convention and add a second number with the windows credited.

How this page rebuilt it. For the 105 of the 109 models whose config this page could read, the script reads the saved config.json (public mirrors for gated Meta and Google repos; nothing is downloaded at build time), decodes one code per layer for mixer, FFN and position, sums the cache layer by layer and compares with the gallery.

Defaults reproduce the gallery, independently
Recomputed from each model's own config with the gallery's convention, the KV cache per token matches the gallery's figure for 95 of the 101 figures both sides compute, within rounding (two only once the trained-sparse indexer keys are added, as the gallery does). Not rebuilt: four entries whose config is not public (three gated repos, one LoRA adapter with no config of its own), and the three DeepSeek V4 entries, whose compressed caches the per-layer formula does not express (their reconstruction is in section 10). Rows this page adds: Llama 3.1 8B and 70B, Granite 4.0-H Small, Step-5 Preview (gallery figure "N/A") and the tiny GPT.

Correction
Gemma 4 E2B and E4B: 18 KiB and 56 KiB per token, not the gallery's 35 and 84: the last 20 and 18 layers reuse an earlier layer's cache and the global layers use global_head_dim 512 (transformers 5.20.1). MiMo-V2-Flash and MiMo-V2.5: 217.5 KiB, not 144: the config gives sliding layers their own 8 KV heads and 128-dimension values. LongCat-Flash-Lite: 31.5 KiB, not 63: 14 config layers of two MLA sublayers are 28 caches, not 56.
