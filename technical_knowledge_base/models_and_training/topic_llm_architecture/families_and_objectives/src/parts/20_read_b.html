2. The objectives: what the model is asked to predict

An objective is a recipe that turns raw text into (input, target) pairs and a loss. The mask decides what each position can read; the objective decides what goes in, what comes out and which positions are scored. The {{Objective drill|#t-obj}} runs every recipe below on the same 24 tokens of the running sequence.

Causal language modelling (CLM)

Input: the text. Target: the same text shifted left by one. Loss: the mean cross-entropy over every position, so a 256-token window gives 255 loss terms (the last position has no next token inside the window; the topic's trainer reads 257 tokens and scores all 256). Mask: causal, otherwise the target is visible (section 3). This is the objective of every decoder on the root page, and the one {{Pretraining|n:3c65c17b0d0d814f82cffd0d5c0dd5ba}} runs at scale.

Why it won. Every token of every document is a training example; any task can be written as a prompt; the trained model generates by running the same forward it was trained with. The costs are a strict left-to-right loop at inference and a model that never sees the right-hand context of the token it is predicting.

Masked language modelling (MLM)

Input: the text with some tokens hidden. Target: the hidden tokens only. Mask: bidirectional, so a hidden word is predicted from both sides. BERT ({{BERT paper page|n:3c65c17b0d0d81e5ad9bd09cbf18ad7c}}) picks 15% of positions; of those, 80% become [MASK], 10% a random token and 10% stay unchanged, because [MASK] never appears when the model is later fine-tuned, and a model that only ever sees [MASK] at scored positions learns nothing useful about real tokens there. transformers 5.20.1 keeps exactly these defaults in DataCollatorForLanguageModeling: mlm_probability = 0.15, mask_replace_prob = 0.8, random_replace_prob = 0.1 (data/data_collator.py lines ).

The cost is signal per token: only 15% of positions produce a loss term, about 38 per 256-token window against CLM's 255. ELECTRA ({{Clark et al. 2020|https://arxiv.org/abs/2003.10555}}, ICLR 2020) answered with replaced-token detection, a discriminator that labels every position as original or replaced, so "the task is defined over all input tokens rather than just the small subset that was masked out". ModernBERT later raised the masking rate to 30% (section 4).

Span corruption (T5)

Input: the text with random contiguous spans replaced by one sentinel token each (<extra_id_0>, <extra_id_1>, ...). Target: each sentinel followed by the tokens it replaced. T5's default corrupts 15% of tokens in spans of mean length 3 ({{T5 paper page|n:3d45c17b0d0d81ec8ebfec02e953a7fd}}, whose Corrupt a sentence tab runs T5's own preprocessing). Because a span of 3 becomes one sentinel, the input shrinks and the target is short: per 512 input tokens the target is about tokens ( corrupted tokens, sentinels, one end token), so the decoder, the expensive autoregressive half, works on about a fifth of the text. Mask: bidirectional encoder over the corrupted input, causal decoder over the target.

Three more, each with its own section

  • Prefix LM (section 6): CLM where the first part of the window is read bidirectionally and only the rest is scored.
  • Multi-token prediction (section 7): CLM plus extra loss terms for tokens two or more places ahead.
  • Masked diffusion (section 8): MLM with the masking rate drawn at random between 0 and 1 for each sequence and each loss term weighted by one over that rate; at rate 0.15 it is exactly BERT's objective, and the random rate is what makes it a generator.

3. Why the causal mask is not optional: the leak, measured

Pair the next-token objective with a bidirectional mask and the target sits in the input, one position to the right. The model does not have to understand anything: one attention head that reads position i+1 solves the task. How this happens in real code
Writing your own attention with F.scaled_dot_product_attention(q, k, v) and forgetting is_causal=True (the default is False); passing a padding mask and assuming it also makes attention causal; or loading a decoder checkpoint into an encoder class. The symptom is always the same: a training loss far below anything plausible for the data (here  nats per token on stories whose honest loss is about 2.3), then nonsense at generation. A loss that is too good is a bug until proven otherwise.
