8. Diffusion language models

The problem. A decoder writes 48 tokens in 48 forwards, each waiting for the last. Image models do not work that way: a diffusion model starts from noise and refines the whole picture at once over a fixed number of steps (the {{Diffusion from zero|n:3c65c17b0d0d81cf9bf0d94e57ce9164}} page teaches it for pixels). A diffusion language model does the same for text, with masking as the noise: start from a sequence of [MASK] tokens and fill in several per forward, in any order.

How it works: masked diffusion from zero

  1. Forward process (the noise). Pick a time t between 0 and 1 and hide each token independently with probability t. At t = 0 the text is clean; at t = 1 it is all [MASK].
  2. The model is a bidirectional transformer (an encoder) that reads the partly masked sequence and predicts the original token at every masked position.
  3. The loss (LLaDA, {{Nie et al., arXiv 2502.09992|https://arxiv.org/abs/2502.09992}}): cross-entropy on the masked positions only, each weighted by 1/t, averaged over the sequence length. The weight makes the sum an upper bound on the negative log-likelihood, so the loss is comparable to (but never below) a true per-token loss; MDLM ({{Sahoo et al., NeurIPS 2024|https://arxiv.org/abs/2406.07524}}) calls it "a mixture of classical masked language modeling losses". Fix t = 0.15 and you have BERT; draw t at random and the model learns every stage from nearly clean to fully masked.
  4. Sampling (the reverse process). Start with the prompt followed by L masks. Each step, predict every masked position, commit some of the predictions and leave the rest masked. LLaDA commits the most confident ones (low-confidence remasking). With L tokens and K steps it commits L/K tokens per forward.

Real bad output: parallel commits do not coordinate

The causal model continues prompt 7 with "". The diffusion model at 12 steps writes "". Our tokenizer splits the name Roxy into pieces (R, o, x, y: the Objective drill shows them), and each step predicts every masked slot independently given the current context. Slots filled in the same step cannot agree with each other, so the name comes out as fragments ("R", "Ro", "Roy") and confident common pieces land in neighbouring slots ("named named"); the causal model, which writes each piece knowing the previous one, spells Roxy correctly. This is the conditional-independence cost of committing several tokens per step: it grows with tokens per step, which is why fewer steps lose quality and why production systems commit in small blocks with confidence thresholds.

What it costs

Every diffusion step is a full bidirectional forward over prompt plus answer, and nothing can be cached between steps because every position's keys change as tokens are committed ("LLaDA is incompatible with KV caching"). An AR decoder with a cache processes each token once. So diffusion trades more FLOPs for fewer sequential forwards: worth it when decoding is memory-bound (one user, small batch), not when a server is already compute-bound at large batch. For the 48-token continuation of an -token prompt, 12 diffusion steps process token positions against the AR decoder's (derived). Block diffusion ({{Arriola et al., ICLR 2025|https://arxiv.org/abs/2503.09573}}) fixes the caching problem by generating blocks left to right, diffusing inside each block and caching the finished ones; DiffusionGemma uses the same block-AR idea.
