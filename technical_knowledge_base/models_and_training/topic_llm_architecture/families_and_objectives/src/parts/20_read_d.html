7. Multi-token prediction (MTP)

The problem. Next-token prediction has two costs. In training, each position is asked about one token only, so a model can do well by matching local patterns without planning what comes after. At inference, the decoder makes one forward per token, and each decode forward at small batch is limited by reading the weights from memory, not by arithmetic ({{Performance math|n:3c65c17b0d0d81faad1ef390b0e54d08}}). Multi-token prediction adds loss terms for tokens two or more places ahead: a denser training signal, and a ready-made guess for the next forward to check.

Two designs

One position, two ways to predict the token after next

  • Parallel heads ({{Gloeckle et al., arXiv 2404.19737|https://arxiv.org/abs/2404.19737}}, April 2024): n independent output heads, each one transformer layer, on a shared trunk and a shared unembedding; head k predicts token t+k from the trunk's state at t alone. Heads run forward and backward one at a time, so peak memory stays O(V + d) instead of O(nV + d). Results (vendor, Meta): at 13B, 12% more HumanEval and 17% more MBPP problems solved than next-token models; "worse than the baseline for small model sizes, but outperform the baseline at scale"; n = 4 best for token-level code; with the extra heads as drafts, 3.0x faster decoding on code and 2.7x on text.
  • Sequential module (DeepSeek-V3, {{arXiv 2412.19437 section 2.2|https://arxiv.org/abs/2412.19437}}): the k-th module takes the previous depth's state hi and the embedding of the known token ti+k, normalises both with RMSNorm, concatenates them and projects 2d to d with a matrix Mk, runs one transformer block, then the main model's shared output head. Because each depth sees the actual next token, the chain of predictions stays causal (the paper compares it to EAGLE). DeepSeek-V3 uses D = 1 (one extra token) and weights the loss by λ = 0.3 for the first 10T tokens and 0.1 for the remaining 4.8T.
