0. In one screen

A sequence mixer is the part of a block that lets a token use earlier tokens (attention in a transformer; the feed-forward then works on each token alone). Attention keeps every past key and value (the KV cache) and reads all of it for each new token. The designs on this page keep a fixed-size state per layer instead, updated once per token. The one-sentence answer. A fixed state makes memory and decode cost independent of context length and is as good as attention at predicting the next word on average, but it cannot hold an arbitrary amount of text exactly; hybrids keep one attention layer in every 4 to 8 so the model can still look things up, and that is what shipped in 2025 and 2026.

1. Recurrence against attention, from zero

The problem. To produce token t, causal attention compares the new query qt with every earlier key and takes a weighted average of every earlier value: ot = ∑j≤t softmaxj(qt·kj/√d) vj. During generation those keys and values are kept (the KV cache), so memory grows linearly with the context and each new token reads all of it: T reads at position T, and T2/2 for a whole sequence. The topic's tiny GPT keeps 6,144 bytes per token in bf16 (6 layers × 8 heads × 32 × 2 for K and V × 2 bytes); Llama 3.1 8B keeps 128 KiB per token, 16 GiB at 131,072 tokens (the root's Config calculator tab).

A recurrent layer instead keeps a state ht of fixed size and updates it once per token, ht = f(ht−1, xt), reading out yt = g(ht, xt). Memory and work per generated token no longer depend on t. That was the RNN and LSTM era (Sequence models: the pre-transformer lineage), and it lost to attention for one reason: with a nonlinear f, ht needs ht−1, so training walks the sequence one step at a time and cannot use a GPU's parallelism across positions.

How the new designs get both. Make the update linear in the state: ht = At ht−1 + bt, where At and bt may depend on the input xt but not on h. Unrolled, every ht is a sum of earlier inputs weighted by products of A's, which can be computed for all t at once: by a parallel scan (an associative combine done in log T rounds; the Mamba paper page animates Blelloch's version), by a convolution when A does not depend on the input (S4), or as one masked matrix product that looks exactly like attention (linear attention and Mamba-2, sections 2 and 4). Training is parallel over positions; decoding is the cheap recurrence. Every design on this page is a choice of what h is, how At forgets, and how bt writes.

What it costs. Whatever the state does not hold is gone. A state of b bits cannot reproduce a string carrying more than b bits, which is the copying bound of Jelassi et al. 2024 ("GSSMs cannot accurately copy strings with more bits than the size of the latent state"). Attention pays memory to avoid that limit. When it matters: long contexts and many concurrent sequences (memory), and long generations (decode work), against tasks that look up exact earlier text (copying, retrieval, few-shot formats). How to check: for any config, compare the per-sequence state with KV bytes per token × context (State vs KV cache); for any model, probe recall directly (Recall probes).

2. Linear attention is a recurrence

The derivation. Softmax attention's weight for key j is exp(q·kj) divided by the sum over all keys. Katharopoulos et al. 2020 replace exp(q·k) by a dot product of feature maps φ(q)·φ(k), with φ(x) = elu(x) + 1 to keep weights positive ("We prefer elu(.) over relu(.) to avoid setting the gradients to 0 when x is negative", eq. 7). Then the sum can be reassociated:

ot = ∑j≤t (φ(qt)⊤φ(kj)) vj / ∑j≤t φ(qt)⊤φ(kj) = St⊤φ(qt) / zt⊤φ(qt)
St = St−1 + φ(kt) vt⊤    zt = zt−1 + φ(kt)
St
the state: a dk × dv matrix, the sum of every key's outer product with its value
zt
the normaliser: the sum of the keys
φ
a feature map applied to queries and keys (elu + 1 here; later work uses identity with L2-normalised keys)

The paper puts it as "any transformer layer with causal masking can be written as a model that, given an input, modifies an internal state and then predicts an output, namely a Recurrent Neural Network" with "two hidden states, namely the attention memory s and the normalizer memory z". For one head of the tiny GPT (dk = dv = 32) the state is 1,024 + 32 numbers whatever the context, against 64 numbers per past token for its KV cache: the state is cheaper past 16 tokens.

Two ways to compute the same thing. In training, stack all positions: O = ((φ(Q)φ(K)⊤) ⊙ M) V with M the causal mask, a T × T matrix like an attention map (row-normalised by the same sums). In decoding, run the recurrence. The script below checks the two forms agree to 4.4e-16 in float64 (output pasted from src/code/out/demos.txt):

linear attention, T=64, d=16: max |parallel - recurrent| = 4.44e-16
state size: 272 numbers, whatever T is; a KV cache here holds 2048 numbers

The cost. The parallel form is quadratic like attention; the recurrence is linear but sequential; production kernels split the sequence into chunks, use the quadratic form inside each chunk (matrix multiplies, which tensor cores are built for) and pass the state between chunks (section 4). Published speed: "up to 4000x faster on autoregressive prediction of very long sequences" (abstract), which Figure 4 shows is pixel-by-pixel CIFAR-10 image generation (sequence length 3,072; "more than 300 times" on MNIST), not text. authors' measurement

The catch. S is a sum. Every write adds to it and nothing is ever removed, so once more keys than dk have been written they cannot all be orthogonal and reads return blends. Schlag, Irie and Schmidhuber 2021 name it: "linear Transformers can end up in an overcapacity regime, if the sequence length L exceeds the dimension d_dot of the keys". The next section fixes that two ways, and the animation shows both on one input.

3. Forget or overwrite: decay, gates and the delta rule

Decay (forgetting everything a little). Multiply the state by a number a < 1 before each write: St = at St−1 + vtkt⊤. A write made n steps ago then counts an, so old memories fade and stop interfering. RetNet used a fixed a per head; Gated Linear Attention and RWKV-6 make it depend on the input and on the channel; Mamba-2 makes it one input-dependent scalar per head (section 4). A half-life h = ln 0.5 / ln a says how many tokens a memory survives at half strength (a = 0.9 gives 6.6 tokens). Decay is, in RWKV-7's words, "a blunt tool that cannot remove only the values stored at specific keys".

The delta rule (overwrite what this key held). Before writing value v under key k, read what the state currently returns for k, S k, and write only the difference: St = St−1 + βt(vt − St−1kt)kt⊤, with a write strength β between 0 and 1. With unit keys and β = 1 the read S k returns exactly v afterwards, so a key written twice keeps only its latest value. Yang et al. 2024 read it as learning: "This process can also be regarded as optimizing an online regression loss using a single step of SGD", L(S) = ½‖S kt − vt‖2, whereas plain linear attention follows the "negative inner-product" loss −⟨S kt, vt⟩. The rule is the Widrow-Hoff rule of 1960, brought to transformers by DeltaNet (Schlag et al. 2021).

Both together. Gated DeltaNet (Yang, Kautz and Hatamizadeh 2024, eq. 10): St = St−1(αt(I − βtktkt⊤)) + βtvtkt⊤. Their motivation: "gating enables rapid memory erasure while the delta rule facilitates targeted updates". (The papers write S as dv × dk and multiply S k; RWKV-7 and Kimi write the transpose. This page follows the DeltaNet papers.)

Predict: a Gated DeltaNet head in Qwen3-Next has dk = dv = 128. Roughly how many unrelated (key, value) facts can its state hold before writes start to damage each other?
About dk. Exact retrieval needs keys that do not overlap, and at most dk unit vectors can be mutually orthogonal (the toy above: ten keys fit at dk = 16, not at 8). The 128 × 128 = 16,384 entries are the price of storing dv = 128 numbers under each of those directions. Learned keys are not random, so a trained model can do better on structured text and worse on adversarial lists; this is why Qwen3-Next keeps one attention layer in four.

4. State-space models: S4, then Mamba, then Mamba-2

S4: a continuous system, discretised

The idea. A state-space model (SSM) comes from control theory: a 1-D input signal u(t) drives an N-dimensional state x(t), x′(t) = A x(t) + B u(t), read out as y(t) = C x(t) (+ D u(t), a skip). S4 (Gu, Goel and Ré 2021) applies one such system to each channel of the model. To run it on tokens it is discretised with a step size Δ: S4 uses the bilinear method, Ā = (I − Δ/2·A)−1(I + Δ/2·A), B̄ = (I − Δ/2·A)−1ΔB, giving the recurrence xk = Āxk−1 + B̄uk, yk = Cxk. Mamba later switched to zero-order hold, Ā = exp(ΔA).

Why it trains fast. Ā, B̄ and C are the same at every position (the model is linear time-invariant, LTI), so the output is one convolution of the input with the kernel K̄ = (CB̄, CĀB̄, CĀ2B̄, ...), computed with FFTs. Why it remembers. A random A forgets fast or explodes; the HiPPO matrix makes "the state x(t) to memorize the history of the input u(t)", and in an earlier model "simply modifying an SSM from a random matrix A to equation (2) improved its performance on the sequential MNIST benchmark from 60% to 98%". S4 was "the first model to solve the difficult LRA Path-X task (length-16384)". authors The arXiv version read on 2026-10-19 has two sets of numbers: its prose keeps "88% accuracy" on Path-X and an "80.48%" LRA average, its Table 4 prints 96.35 and 86.09 (updated runs); quote the table.

What it cannot do. Because Ā, B̄, C ignore the input, the layer weighs a token by its distance only, never by what it is. It cannot decide to keep a name and skip filler. The Mamba paper's Selective Copying task makes that failure measurable; its paper page trains an S4-style and a selective layer side by side (99.8% against 67.4% on its toy).

Mamba: make the system depend on the input

Mamba (Gu and Dao 2023): "simply letting the SSM parameters be functions of the input addresses their weakness with discrete modalities, allowing the model to selectively propagate or forget information along the sequence length dimension depending on the current token". Δt, Bt and Ct become projections of xt: a large Δt resets the state toward the current token, a small one keeps the past. The convolution is gone (the kernel changes every step), so Mamba computes the recurrence with "a hardware-aware parallel algorithm in recurrent mode": the expanded state (batch × length × channels × N) never touches GPU main memory; parameters are loaded into on-chip SRAM, discretised and scanned there. Per layer the state is dinner × N with N = 16 (the code's default and the paper's setting), dinner = 2 × dmodel: 5,120 × 16 per layer for Mamba 2.8B. Throughput: "4-5x higher inference throughput than a Transformer of similar size, since without the KV cache it can use much higher batch sizes" (section 4.5; the abstract rounds to 5x). authors

Mamba-2: restrict A to a scalar, and the layer becomes masked attention

Mamba-2 (Dao and Gu 2024) simplifies A "from diagonal to scalar times identity structure": one decay at = exp(ΔtA) per head per step, shared by all its channels and state entries, with head dimension P = 64 or 128 like a transformer. Then unrolling gives

yi = ∑j≤i (Ci·Bj) · (aj+1aj+2…ai) · xj   ⇒   Y = (L ⊙ C B⊤) X
C B⊤
a T × T matrix of query-key scores: C plays the query, B the key, x the value
L
the decay mask, Lij = product of a's between j and i (1 on the diagonal, 0 above it): "1-semiseparable"

That is linear attention (section 2) with a decaying mask instead of the plain causal mask: "When L is the causal mask, it is standard linear attention", and the two are "duals of each other with the exact same linear and quadratic forms". The name is state space duality (SSD). It matters for speed: split the sequence into chunks, use the quadratic form inside each chunk (matrix multiplies) and the recurrence between chunks; the SSD kernel is "2-8x faster than Mamba's fused associative scan, which does not leverage matmul units" (a kernel speedup, not a whole-model one) and crosses FlashAttention-2 "at sequence length 2K", "6x faster at sequence length 16K". The same speed buys state: Mamba-2 uses N "around 64 or 128" (code default 64; Nemotron-H 8B uses 128) against Mamba's 16. authors

The topic's tiny GPT uses exactly this layer. Its SSM mixer (16 heads of 32 channels, N = 16, a short causal convolution, a gate) trains in the quadratic dual form and decodes with the recurrence (code in section 11). On the trained SSM-only model, the two forms give logits that differ by at most on the running sequence (src/inside/ssm_inside.py, CPU, fp32). Because Y = (L ⊙ CB⊤)X, every SSM head has an implicit attention map ("Mamba models give rise to three orders of magnitude more attention matrices than transformers", Ali et al. 2024); the Inside the trained SSM tab draws them beside real attention maps for the same tokens, with each head's decay.

Mamba-3 (2026, published only)
Mamba-3 adds "a more expressive recurrence derived from SSM discretization", "a complex-valued state update rule that enables richer state tracking" and a multi-input multi-output form; the authors report "comparable perplexity to Mamba-2 despite using half of its predecessor's state size" at 1.5B. authors Not run here (no released small checkpoint in the topic's environment).

5. RWKV: an RNN built from attention's pieces

RWKV-4 (Peng et al. 2023) computes, per channel, a weighted average of past values whose weights decay with distance: wkvt = (∑i<t e−(t−1−i)w + ki vi + eu + kt vt) / (same sum without v). The vector w is "a channel-wise time decay", u a "bonus" for the current token. It is softmax-like attention whose scores are a key-only term plus a fixed linear distance penalty, which is what lets numerator and denominator be carried as running sums: a normalised linear attention with exponential decay. The RWKV authors trained up to 14B parameters, "by far the largest dense RNN ever trained", and state the cost plainly: the architecture "inherently limits its ability to 'look back' at previous tokens", and "carefully designed prompts may be even more crucial". transformers 5.20.1 ships only RWKV-4; its CPU fallback carries the two running sums plus a running maximum for numerical safety (quoted in section 11).

RWKV-5 and 6 (Eagle and Finch, 2024): "multi-headed matrix-valued states" (a dk × dv state per head, as in linear attention) and, in RWKV-6, decay that changes with the input, per channel: "each channel of w_t can now vary independently over time, in a data-dependent manner". RWKV-7 (Goose, 2025) moves to "a newly generalized formulation of the delta rule with vector-valued gating and in-context learning rates", and proves it "can perform state tracking and recognize all regular languages" (solving an S5 permutation tracking problem with one layer), which the authors set against transformers' TC0 limit under standard complexity conjectures. Models from 0.19B to 2.9B, Apache-2.0. authors RWKV has stayed a community line: none of the 2026 frontier hybrids below uses it, but its trajectory (decay, then matrix state, then input-dependent decay, then the delta rule) is the same path the others took.

6. Gated DeltaNet and Kimi Delta Attention in production

Gated DeltaNet is section 3's gated delta rule with learned, input-dependent αt (per head) and βt, L2-normalised queries and keys, a short convolution on q, k and v, and an output gate. The authors report at 1.3B parameters and 100B tokens: Wikitext perplexity 16.42 against 16.56 for Mamba-2, 17.71 for DeltaNet and 18.53 for their Transformer++ (Table 3); on recall-heavy tasks with 2K inputs, average 30.6 against 37.0 for the Transformer++ and 39.0 to 40.1 for their hybrids with sliding-window attention (Table 4); on single-needle retrieval at 8K, 91.8 (pass key) where Mamba-2 falls to 30.4 because it "decays historical information too quickly" (Table 2). authors

What ships. Qwen3-Next-80B-A3B (September 2025): "Hybrid Layout: 12 * (3 * (Gated DeltaNet -> MoE) -> 1 * (Gated Attention -> MoE))", Gated DeltaNet heads "32 for V and 16 for QK; Head Dimension: 128". The Qwen blog: "When we mix Gated DeltaNet with standard attention at a 3:1 ratio ... the model consistently outperforms any monolithic architecture". Qwen3.5 keeps the layout from 0.8B ("6 x (3 x (Gated DeltaNet -> FFN) -> 1 x (Gated Attention -> FFN))") to 397B-A17B ("15 * (3 * ...)"), context "262,144 natively". Qwen model cards, read 2026-10-19

Kimi Delta Attention (KDA), Kimi Linear 2025: "While GDN, similar to Mamba2, employs a coarse head-wise forget gate, KDA introduces a channel-wise variant in which each feature dimension maintains an independent forgetting rate". In code the difference is one broadcast: Qwen3-Next's loop multiplies the state by decay[:, :, i].exp()[..., None, None] (one number per head), Kimi Linear's by g[:, i][..., None].exp() (one number per key channel); the delta step is line for line the same (section 11). Kimi Linear 48B-A3B interleaves KDA and MLA "in a uniform 3:1 ratio", reports "reducing KV cache usage by up to 75% and achieving up to 6x decoding throughput for a 1M context", and uses no positions in its MLA layers: "we apply NoPE to all full attention (MLA) layers. This design delegates the entire responsibility for encoding positional information and recency bias to the KDA layers." Kimi K3's config keeps the pattern at 93 layers (69 KDA, 24 MLA). authors

How to check a delta-rule layer. In transformers, torch_recurrent_gated_delta_rule (Qwen3-Next) and recurrent_kimi_delta_attention are the readable references; with the flash-linear-attention kernels missing, transformers falls back to them, slowly. The state per layer is value heads × dk × dv (Qwen3-Next: 32 × 128 × 128 = 524,288 numbers) plus the convolution's last 3 inputs, kept in fp32 (Qwen3.5's config: "mamba_ssm_dtype": "float32").

7. Hybrids and their ratios

The problem a hybrid solves. A recurrent layer is cheap but cannot look things up exactly; an attention layer can but costs a growing cache. Most of a model's layers do work that a recurrence handles (local syntax, running summaries); a few must retrieve. So keep a few attention layers and make the rest recurrent. The cache then grows only in the attention layers, and the recurrent layers add a fixed state. Read from each model's config (layer counts by type, cache in bf16, state in fp32, one sequence):

"KV = state at" is the context at which the attention layers' cache has grown to the size of the recurrent state: below it the state is the larger memory cost. How the ratios were chosen (published).

  • Jamba (AI21, 2024): 1 attention per 7 Mamba layers, chosen because at 1.3B and 250B tokens "There is no substantial difference between 1:3 and 1:7 ratios" (HellaSwag 65.1 both; NQ 16.5 against 16.0) and 1:7 is cheaper. The same study shows why attention is kept at all: on IMDB, QuAC and NarrativeQA pure Mamba scores 48.8, 20.2, 27.7 against attention's 84.1, 27.9, 45.8 and the hybrid's 90.9, 26.6, 43.7, because "the pure Mamba model often does not follow the correct format" (answering "Very Good" or "3/10" where "Positive" or "Negative" was asked). They conjecture that "the lack of an attention mechanism in the pure Mamba model makes it difficult for it to learn in-context" and found 12 induction heads in the hybrid's attention layers. authors
  • NVIDIA: Waleffe et al. 2024 trained 8B Mamba, Mamba-2, Transformer and a hybrid of "43% Mamba-2, 7% attention, and 50% MLP layers" on the same data; the pure SSMs "lag behind Transformers on tasks which require strong copying or in-context learning abilities (e.g., 5-shot MMLU, Phonebook)", the hybrid "exceeds the 8B Transformer on all 12 standard tasks we evaluated (+2.65 points on average)". Nemotron-H follows it: "roughly 8% of the total layers", 4 attention layers of 52 in the 8B (4 attention to 24 Mamba-2 among mixers), "up to 3x faster at inference". Nemotron 3 Super (March 2026, 120B total, 12B active, up to 1M context) keeps 8 attention layers of 88 (counted from its config), as "global 'anchors'". authors
  • IBM Granite 4.0-H: "Mamba-2 layers and conventional transformer blocks sequentially in a 9:1 ratio" (36 to 4), "over 70% reduction in RAM needed to handle long inputs and multiple concurrent batches". vendor
  • Kimi Linear swept the ratio of KDA to MLA layers at equal FLOPs (Table 1, validation perplexity, lower is better): 3:1 5.65, 1:1 5.66, 7:1 5.70, 15:1 5.82, and pure attention (0:1) 5.77. "A higher ratio (e.g., 7:1) produced a comparable training loss but led to significantly worse validation performance, while a lower ratio (e.g., 1:1) maintained a similar validation loss but at the cost of increased inference overhead." Qwen made the same 3:1 choice. authors
  • Parallel instead of interleaved. Falcon-H1 (TII, 2025) runs attention and Mamba-2 side by side in every layer and concatenates their channels, SSM : attention : MLP channels "roughly following 2:1:5"; "Having more attention channels significantly degrades the performance". Hymba (NVIDIA) also fuses "attention and SSMs in parallel" heads. Every Falcon-H1 layer therefore has both a cache and a state (the table's 72 + 72). authors
  • The counter-example. MiniMax-01 used lightning (linear) attention with "one transformer block with softmax attention ... every seven transnormer blocks" (80 layers). MiniMax-M2 went back to full attention: at small scale the hybrid "looked just as good", but "the price paid became obvious at a larger scale: the model had clear deficits in complex, multi-hop reasoning tasks" (MiniMax, 30 October 2025). vendor

Positions. Jamba: "positional embeddings or mechanisms like RoPE are not necessary, and so we do not use any explicit positional information" (adding RoPE changed nothing measurable, their Table 8); Nemotron-H: "We do not use any position embeddings"; Granite 4.0-H: NoPE; Kimi Linear: NoPE in MLA. 8. What a fixed state is bad at, and good at

Recall, defined. Associative recall is producing a token because it followed the same cue earlier in the context ("Hakuna Matata means no worries Hakuna Matata it means no" → "worries"). Zoology (Arora et al. 2023) found that such tokens are "6.4% of all tokens in the Pile" yet "account for 82% of the perplexity gap to attention" of attention-free models, and that "a 70M parameter attention model outperforms a 1.4 billion parameter gated-convolution model on associative recall". Their multi-query associative recall (MQAR) task lists key-value pairs and then asks for several keys; a recurrent model's "required ... hidden state dimensionality grows with the number of key-value pairs that the model needs to recall", attention's does not. BASED (Arora et al. 2024) turns it into a trade-off curve: "a key tradeoff between a model's state size and recall ability". Mamba-2's own MQAR experiment: going "from N=16 to N=64 and N=256 consistently improves performance". authors

Copying. Jelassi et al. 2024 prove a two-layer transformer can copy strings of exponential length while a fixed-state model "fails to solve the copy task, unless its latent state grows linearly with the sequence length", and in a phone-book test "even the smallest transformer (410M parameters) outperforms the largest GSSMs (2.8B parameters) when the phone-book size is long enough (L >= 70)", although "the Mamba models achieve lower perplexity than the Pythia models" (the paper prints the curves, not the numbers).

Measured here, three ways (all in Recall probes):

  • Pythia-160M against Mamba-130M, same Pile data and tokenizer: copying a list of random common words, and finding a number in a synthetic phone book.
  • The topic's tiny GPTs (same budget, section 9): a made-up name ("Zubo", split into " Z" "u" "bo") introduced, then repeated after d filler tokens; scored on the name's later pieces against a control where the first mention was a different name.
  • MQAR trained from scratch on 2-layer, 128-wide models (attention, SSM with state 16 or 64 per channel, one of each).
Predict: Pythia-160M and Mamba-130M are asked to repeat a list of random words. Mamba's state is 24 layers × 1,536 channels × 16 = 589,824 numbers; Pythia's KV cache holds 18,432 numbers per token. At about what list length should Mamba start to fall behind?

What a fixed state is good at. Constant memory and constant work per generated token, so long generations and many concurrent sequences are cheap (section 10); no position limit inside the recurrence (the tiny SSM GPT has no positions at all); and some state-tracking problems (parity, permutations) that delta-rule and Mamba-3-style layers solve and plain attention does not at fixed depth (RWKV-7, Mamba-3 papers, published). The trade is exact, unbounded lookup, which is why hybrids keep attention.

10. Serving a recurrent or hybrid model

Memory. Per sequence, an attention model needs KV bytes per token × context; a recurrent layer needs its state once. At batch B both multiply by B, so the saving is what lets a server run more sequences at once, which is where the published throughput gains come from (Mamba: "since without the KV cache it can use much higher batch sizes"; Nemotron-H: "lower memory footprint from Mamba-2 layers facilitates using higher batch sizes"). The state is not free: at short contexts it is the bigger cost. Nemotron-H 8B's 98.8 MiB of fp32 state per sequence equals its attention layers' cache at tokens; Kimi K3 carries MiB of KDA state per sequence before its first token's cache. A server must reserve state memory for every live sequence even if it is 10 tokens long.

Compute. Decoding one token reads the weights (the same for both), plus the whole KV cache for attention or the fixed state for a recurrent layer. Prefill (processing the prompt) is matrix multiplies either way: attention's cost grows with T2, a chunked recurrent layer's with T. Vendor speedups compare whole systems: Qwen3-Next's "over 10x" beyond 32K is against dense Qwen3-32B, so its 3B active parameters (mixture of experts) carry part of it; Nemotron 3 Super's "up to 2.2x and 7.5x" against gpt-oss-120b and Qwen3.5-122B is at 8K input and 64K output on B200. vendor

What a state makes harder (follows from the mechanism, no measurement needed). A KV cache can be cut at any token: share a prompt prefix between requests, roll back rejected tokens in speculative decoding, branch for beam search. A recurrent state exists only at positions where it was saved. Prefix caching needs state snapshots at block boundaries, speculative decoding needs the state from before the draft (or a recomputation), and every branch needs its own copy of the state. Serving engines handle this with per-sequence state slots beside the paged KV cache (Batching, KV cache and scheduling, vLLM); in the hybrid, only the attention layers use the paged cache.

Precision. States accumulate over thousands of steps, so they are kept in fp32 even when weights and the KV cache are bf16 (transformers' delta-rule loops cast to fp32: "calculations happen in float as states are more susceptible to rounding errors", modeling_kimi_linear.py). Section 12 measures what low precision does to a decay mask.

11. The code, at pinned versions

Located by pattern with src/code/quotes.py in transformers 5.20.1 and the topic's src/data/tiny_gpt.py, so the line numbers are checked, not typed.

The tiny GPT's SSM, in one sentence of maths. (src/data/tiny_gpt.py, lines 293 to 297) at = exp(dtt Ah) is one decay per head per step (Mamba-2's scalar A).

Per head h (P channels, state size N), with a scalar decay a_t = exp(dt_t * A_h) that depends on the input:
    state_t = a_t * state_{t-1} + dt_t * x_t B_t^T      (P x N)
    y_t     = state_t C_t + D_h * x_t
Training uses the equivalent "dual" quadratic form y = (L o C B^T) (dt x), L[i,j] = prod_{j<k<=i} a_k, which is
exact and fast at T <= 1-2k; decoding uses the recurrence with a constant-size state (no KV cache).

Training: the dual (quadratic) form. (src/data/tiny_gpt.py, lines 351 to 356) seg is the log of L, the decay mask; G is L ⊙ C B⊤, an attention-like (heads, T, T) matrix.

cs = torch.cumsum(la, 1).transpose(1, 2)                        # (B,nh,T)
seg = cs[..., :, None] - cs[..., None, :]                       # (B,nh,Ti,Tj) = sum_{j<k<=i} log a_k
causal = torch.ones(T, T, dtype=torch.bool, device=x.device).tril()
L = torch.exp(seg.masked_fill(~causal, float("-inf")))           # decay from j to i, 0 above the diagonal
G = (Cm @ Bm.transpose(1, 2))[:, None] * L                      # (B,nh,Ti,Tj): like an attention matrix
y = (G @ (xh * dt[..., None]).transpose(1, 2)).transpose(1, 2)  # (B,T,nh,P)

Decoding: the same layer as a recurrence. (src/data/tiny_gpt.py, lines 346 to 347) One state of (heads, P, N) = (16, 32, 16) per layer, whatever the context.

st = torch.exp(la[:, t])[..., None, None] * st + (dt[:, t, :, None, None] * xh[:, t, :, :, None]) * Bm[:, t, None, None, :]
ys.append((st @ Cm[:, t, None, :, None]).squeeze(-1))       # (B,nh,P)

... with a segment sum instead of a difference of cumulative sums (transformers/models/mamba2/modeling_mamba2.py, lines 73 to 90) (why: section 12, second mistake).

def segment_sum(input_tensor):
    """
    More stable segment sum calculation. Uses cumulative sums and masking instead of direct subtractions.
    """
    chunk_size = input_tensor.size(-1)
    # 1. expand input tensor to have an additional dimension and repeat along that dimension
    # [..., chunk_size] -> [..., chunk_size, chunk_size]
    input_tensor = input_tensor[..., None].expand(*input_tensor.size(), chunk_size)
    # 2. create a lower triangular mask with the diagonal set to 0 to 0 out elements above diag
    mask = torch.tril(torch.ones(chunk_size, chunk_size, device=input_tensor.device, dtype=torch.bool), diagonal=-1)
    input_tensor = input_tensor.masked_fill(~mask, 0)
    # 3. compute actual cumsum
    tensor_segsum = torch.cumsum(input_tensor, dim=-2)

    # 4. apply mask to keep only the lower triangular part of the cumulative sum result (incl diagonal this time)
    mask = torch.tril(torch.ones(chunk_size, chunk_size, device=input_tensor.device, dtype=torch.bool), diagonal=0)
    tensor_segsum = tensor_segsum.masked_fill(~mask, -torch.inf)
    return tensor_segsum

12. Common mistakes, with real outputs

Running an SSM model without its kernels and blaming the architecture for the speed
transformers 5.20.1 on a machine without CUDA kernels prints, for Mamba-130M (seen here):
[transformers] `causal_conv1d_fn` is falling back to its reference PyTorch implementation because `causal_conv1d` is not installed. This is correct but much slower; install `causal_conv1d` for the optimized kernel.
[transformers] `selective_scan_fn` is falling back to its reference PyTorch implementation because `mamba_ssm` is not installed. This is correct but much slower; install `mamba_ssm` for the optimized kernel.
The fallback is the Python loop over positions quoted in section 11: correct, but one step per token per layer. A 1,000-token forward of Mamba-130M took s on 4 CPU threads here, against s for Pythia-160M on its ordinary attention path (rough, shared machine). Results are right; timings from this path say nothing about the architecture. The same holds for Gated DeltaNet and KDA without flash-linear-attention.
Building the decay mask by subtracting cumulative sums, in low precision
Lij = exp(csi − csj) with cs the cumulative sum of log a is exact in algebra, but cs grows with position and the difference of two large numbers loses the small one. Measured (src/code/demos.py, 2,048 positions): max error 0.22 in bf16 against 0.0017 with a segment sum; 3.7e-6 against 5.8e-8 in fp32. transformers' Mamba-2 path uses the segment sum ("More stable ... instead of direct subtractions"); the tiny GPT subtracts, which is fine in fp32 at 256 tokens and would not be in bf16 at long context. Keep states and their decays in fp32.
Judging an attention-free model by its average loss
The tiny SSM GPT ties attention on held-out loss ( against ) and loses on the one story that repeats a name ( against nats per token). Zoology found the same at scale: recall tokens are 6.4% of the Pile and 82% of the gap. Always add a recall or copy probe.
Assuming the recurrent state is small
The tiny SSM GPT's state (6 layers × (512 × 16 + 544 × 3) numbers in fp32 = 235,776 bytes) equals the baseline's KV cache at 38 tokens. A server reserves it for every live sequence from the first token. Below the crossover context the hybrid uses more memory than attention would, and the crossover is thousands of tokens for real hybrids (State vs KV cache).
Tuning RoPE on a hybrid whose attention has no positions
Nemotron-H's and Jamba's configs carry rope_theta; their transformers modeling files define apply_rotary_pos_emb and never call it (section 7). Changing the base or adding a RoPE scaling for long context changes nothing. Read the modeling code, not the config, before a long-context fix.
Reading a vendor speedup as a mixer speedup
Mamba-2's "2-8x" is its SSD kernel against Mamba-1's scan, not a model against a transformer. Qwen3-Next's "over 10x" is an 80B-total, 3B-active MoE hybrid against dense Qwen3-32B. Mamba's "5x" comes from larger batches without a KV cache. Each compares whole systems at a stated setting.
Mixing equation conventions between papers
DeltaNet and Gated DeltaNet write the state as dv × dk and update St−1(I − βkk⊤) + βvk⊤; RWKV-7 and Kimi write the transpose with row vectors; transformers' loops keep (dk, dv) and multiply on the left. A port that mixes them silently reads the state with the wrong side.

13. Interview questions

Show that causal linear attention is an RNN. What is its state?
Replace exp(q·k) by φ(q)·φ(k); the sum over j factors as φ(qt)⊤∑φ(kj)vj⊤. The state is St = St−1 + φ(kt)vt⊤ (dk × dv) plus the normaliser zt = ∑φ(kj). Constant memory per head; the parallel form is (φ(Q)φ(K)⊤ ⊙ M)V.
Why did S4 train as a convolution and why can Mamba not?
S4's Ā, B̄, C are the same at every step, so the output is the input convolved with a fixed kernel (FFT). Mamba makes Δ, B, C depend on the token (selection), so the kernel changes every step; it uses a parallel scan in on-chip memory instead.
What does Mamba-2 give up relative to Mamba, and what does it get?
A becomes a scalar per head per step instead of a diagonal per channel (less expressive decay). In exchange the layer equals masked linear attention, Y = (L ⊙ CB⊤)X, which trains with chunked matrix multiplies on tensor cores (2 to 8 times faster kernels) and affords a state 4 to 16 times larger (N 64 to 256).
What is the delta rule and why does it help recall?
Before writing v under k, subtract what the state already returns for k: S ← S + β(v − Sk)k⊤, one SGD step on ½‖Sk − v‖2. A re-written key replaces its value instead of blending, and old content is removed per key rather than by blanket decay. Capacity is still about dk independent keys.
Compute Nemotron-H 8B's recurrent state per sequence from its config.
24 Mamba-2 layers, dinner 8,192 (128 heads of 64), state 128, 8 groups, conv 4: per layer 8,192 × 128 + (8,192 + 2 × 8 × 128) × 3 = 1,079,296 numbers; × 24 × 4 bytes = 98.8 MiB. Its 4 attention layers add 16 KiB per token, so the cache matches the state at about 6,300 tokens.
Why do Jamba, Nemotron-H and Kimi Linear use no positional encoding?
The recurrent layers process tokens in order and carry recency through their decay, so the attention layers receive order already. Jamba measured no difference with RoPE; Kimi argue RoPE in the global layers "yields an overemphasis on short-range order" and NoPE eases long-context extension.
Why is prefix caching harder for a hybrid?
A KV cache can be truncated at any token; a recurrent state only exists where it was saved. Sharing a prefix, rolling back speculative tokens or branching beams needs state snapshots (or recomputation), held per sequence beside the paged KV blocks of the attention layers.
Design: a model for 1M-token contexts serving 32 concurrent users on 8 × 80 GB GPUs.
Budget: 640 GB minus weights. A pure-attention 70B-class model with GQA keeps about 320 KiB per token: 32 × 1M tokens ≈ 10 TiB: impossible. MLA (68.6 KiB per token) still needs about 2.1 TiB. So most layers must be recurrent: a 3:1 delta-rule hybrid with MLA or GQA in the attention layers (Kimi Linear style: 7 MLA layers of 27, 7.9 KiB per token, about 252 GiB for 32 × 1M plus 43 MiB of state per user) fits beside the weights. Keep fp32 states, NoPE or partial RoPE in attention, test retrieval at full length (RULER-style, Long context), and keep enough attention layers that multi-hop retrieval holds (MiniMax's warning).
Design: you must cut serving memory of an existing 8B transformer by 4× at 32K context without retraining from scratch. Options?
GQA or MLA conversion with uptraining (Attention variants child), sliding windows on most layers with a few global ones (Long context child), or distilling into a hybrid (replace most attention layers with Mamba-2 or Gated DeltaNet layers initialised from the attention weights and train briefly, as several 2024 and 2025 distillation papers do; not run here). Check recall probes and long-context retrieval after each, not only perplexity.
