The idea in one screen

These layers replace attention's growing KV cache with a fixed-size state, updated once per token by a rule that is linear in the state, so they train in parallel like attention and decode at constant memory and cost. The designs differ only in how the state forgets and how it writes; and because a fixed state cannot hold arbitrary text exactly, every 2026 model that uses one keeps a few attention layers (a hybrid).

1. Recurrence against attention

Attention keeps everything: memory grows with every token and each new token reads all of it. To produce token t, causal attention compares qt with every earlier key and averages every earlier value, ot = ∑j≤t softmaxj(qt·kj/√d) vj, so generation keeps all of them (the KV cache): T reads at position T, and T2/2 for a whole sequence. The topic's tiny GPT keeps 6,144 bytes per token in bf16 (6 layers × 8 heads × 32 × 2 for K and V × 2 bytes); Llama 3.1 8B keeps 128 KiB per token, 16 GiB at 131,072 tokens (sizing for any model: Long context).

A recurrent layer keeps a state ht of fixed size, updated once per token, ht = f(ht−1, xt), and reads out yt = g(ht, xt): memory and work per generated token no longer depend on t. Step through the same 8 tokens under both:

Why recurrence lost, and how it came back. RNNs and LSTMs (Sequence models: the pre-transformer lineage) lost to attention for one reason: with a nonlinear f, ht needs ht−1, so training walks the sequence one step at a time and cannot use a GPU's parallelism across positions. The new designs make the update linear in the state, ht = At ht−1 + bt, with At and bt allowed to depend on xt but not on h. Unrolled, every ht is a sum of earlier inputs weighted by products of A's, computable for all t at once: by a parallel scan (an associative combine in log T rounds; the Mamba paper page animates Blelloch's version), by a convolution when A does not depend on the input (S4), or as one masked matrix product that looks exactly like attention (sections 2 and 4). Training is parallel; decoding is the cheap recurrence. What At is and how bt writes are the hero grid's two axes.

What it costs. Whatever the state does not hold is gone: a state of b bits cannot reproduce a string carrying more than b bits, the copying bound of Jelassi et al. 2024 ("GSSMs cannot accurately copy strings with more bits than the size of the latent state"). Attention pays memory to avoid that limit. So the state wins on long contexts, many concurrent sequences and long generations, and loses on tasks that look up exact earlier text (copying, retrieval, few-shot formats). To check a config, compare its state with KV bytes per token × context (State vs KV cache); to check a model, probe recall (section 8).

2. Linear attention is a recurrence

The derivation. Softmax attention's weight for key j is exp(q·kj) divided by the sum over all keys. Katharopoulos et al. 2020 replace exp(q·k) by a dot product of feature maps φ(q)·φ(k), with φ(x) = elu(x) + 1 to keep weights positive ("We prefer elu(.) over relu(.) to avoid setting the gradients to 0 when x is negative", eq. 7). Then the sum can be reassociated:

ot = ∑j≤t (φ(qt)⊤φ(kj)) vj / ∑j≤t φ(qt)⊤φ(kj) = St⊤φ(qt) / zt⊤φ(qt)
St = St−1 + φ(kt) vt⊤    zt = zt−1 + φ(kt)
St
the state: a dk × dv matrix, the sum of every key's outer product with its value
zt
the normaliser: the sum of the keys
φ
a feature map applied to queries and keys (elu + 1 here; later work uses identity with L2-normalised keys)

In the paper's words, "any transformer layer with causal masking can be written as a model that, given an input, modifies an internal state and then predicts an output, namely a Recurrent Neural Network" with "two hidden states, namely the attention memory s and the normalizer memory z". For one head of the tiny GPT (dk = dv = 32) the state is 1,024 + 32 numbers whatever the context, against 64 numbers per past token for its KV cache: the state is cheaper past 16 tokens.

Two ways to compute the same output: a masked T × T product for training, a d × d state for decoding

Left: stack all positions, O = ((φ(Q)φ(K)⊤) ⊙ M) V with M the causal mask, a T × T matrix like an attention map (row-normalised by the same sums): quadratic, parallel. Right: the recurrence, one outer product added per token, then one read with the query: linear, sequential. src/code/demos.py (CPU, float64, T = 64, d = 16): the two forms agree to 4.4e-16, with a state of 272 numbers whatever T is, where a KV cache here holds 2,048. measured

The cost. The parallel form is quadratic like attention; the recurrence is linear but sequential; production kernels split the sequence into chunks, use the quadratic form inside each chunk (matrix multiplies, which tensor cores are built for) and pass the state between chunks (section 4).

The "4000x faster" claim, read (provenance)
Published speed: "up to 4000x faster on autoregressive prediction of very long sequences" (abstract), which Figure 4 shows is pixel-by-pixel CIFAR-10 image generation (sequence length 3,072; "more than 300 times" on MNIST), not text. authors' measurement

The catch. S is a sum. Every write adds to it and nothing is ever removed, so once more keys than dk have been written they cannot all be orthogonal and reads return blends. Schlag, Irie and Schmidhuber 2021: "linear Transformers can end up in an overcapacity regime, if the sequence length L exceeds the dimension d_dot of the keys". The next section fixes that two ways, on one input.

3. Forget or overwrite: decay, gates and the delta rule

Decay (forget everything a little). Multiply the state by a < 1 before each write: St = at St−1 + vtkt⊤. A write made n steps ago counts an, so old memories fade and stop interfering (a = 0.9 gives a half-life of 6.6 tokens). RetNet used a fixed a per head; Gated Linear Attention and RWKV-6 make it depend on the input and on the channel; Mamba-2 makes it one input-dependent scalar per head (section 4). In RWKV-7's words decay is "a blunt tool that cannot remove only the values stored at specific keys".

The delta rule (overwrite what this key held). Before writing v under k, read what the state returns for k, S k, and write only the difference: St = St−1 + βt(vt − St−1kt)kt⊤, with write strength β between 0 and 1. With unit keys and β = 1, S k returns exactly v afterwards, so a key written twice keeps only its latest value. Yang et al. 2024: "This process can also be regarded as optimizing an online regression loss using a single step of SGD", L(S) = ½‖S kt − vt‖2, where plain linear attention follows the "negative inner-product" loss −⟨S kt, vt⟩. It is the Widrow-Hoff rule of 1960, brought to transformers by DeltaNet (Schlag et al. 2021).

Both together, Gated DeltaNet (Yang, Kautz and Hatamizadeh 2024, eq. 10): St = St−1(αt(I − βtktkt⊤)) + βtvtkt⊤: "gating enables rapid memory erasure while the delta rule facilitates targeted updates". (DeltaNet papers' convention, S is dv × dk; see the conventions mistake in section 11.)

One state, five write rules: linear attention blends, decay forgets the old, the delta rule overwrites

What it shows. At dk = 8, ten distinct keys overfill the state. Linear attention blends (mean cosine after all 12 writes 0.58; the re-written "Roxy" returns a mix of its old and new values). Decay keeps the recent and loses the old (0.61). The delta rule returns the re-written words almost exactly (1.00 for "hill") but its overwrites damage overlapping keys (mean 0.44; "climb" turns negative). At dk = 16, room for ten keys, the delta rule is the best recurrent rule (0.86 against 0.81 for linear). Softmax over a full cache recalls every single-write word at every size, but averages a re-written key's two values ("Roxy" 0.56): a bare key does not say which write is newer; real attention gets recency from positions.

Predict: a Gated DeltaNet head in Qwen3-Next has dk = dv = 128. Roughly how many unrelated (key, value) facts can its state hold before writes start to damage each other?
About dk. Exact retrieval needs keys that do not overlap, and at most dk unit vectors can be mutually orthogonal (the toy above: ten keys fit at dk = 16, not at 8). The 128 × 128 = 16,384 entries are the price of storing dv = 128 numbers under each of those directions. Learned keys are not random, so a trained model can do better on structured text and worse on adversarial lists; this is why Qwen3-Next keeps one attention layer in four.

4. State-space models: S4, then Mamba, then Mamba-2

S4: a continuous system, discretised

A state-space model (SSM) comes from control theory: a 1-D input signal u(t) drives an N-dimensional state x(t), x′(t) = A x(t) + B u(t), read out as y(t) = C x(t) (+ D u(t), a skip). S4 (Gu, Goel and Ré 2021) applies one such system to each channel of the model and runs it on tokens by discretising it with a step size Δ, giving the recurrence xk = Āxk−1 + B̄uk, yk = Cxk. Ā, B̄ and C are the same at every position (the model is linear time-invariant, LTI), so the output is one convolution of the input with the kernel K̄ = (CB̄, CĀB̄, CĀ2B̄, ...), computed with FFTs: that is why it trains fast. It remembers because A is not random but the HiPPO matrix, which makes "the state x(t) to memorize the history of the input u(t)".

What it cannot do. Because Ā, B̄, C ignore the input, the layer weighs a token by its distance only, never by what it is. It cannot decide to keep a name and skip filler. The Mamba paper's Selective Copying task makes that failure measurable; its paper page trains an S4-style and a selective layer side by side (99.8% against 67.4% on its toy).

S4's discretisation, HiPPO's evidence and the Path-X numbers (depth; a correction)

S4 uses the bilinear method, Ā = (I − Δ/2·A)−1(I + Δ/2·A), B̄ = (I − Δ/2·A)−1ΔB; Mamba later switched to zero-order hold, Ā = exp(ΔA). A random A forgets fast or explodes; in an earlier model "simply modifying an SSM from a random matrix A to equation (2) improved its performance on the sequential MNIST benchmark from 60% to 98%". S4 was "the first model to solve the difficult LRA Path-X task (length-16384)". authors

Mamba: make the system depend on the input

Mamba (Gu and Dao 2023): "simply letting the SSM parameters be functions of the input addresses their weakness with discrete modalities, allowing the model to selectively propagate or forget information along the sequence length dimension depending on the current token". Δt, Bt and Ct become projections of xt: a large Δt resets the state toward the current token, a small one keeps the past. In the trained tiny SSM below, one head's decay at moves with the text; an S4-style layer would draw a flat line.

How it stays fast. The convolution is gone (the kernel changes every step), so Mamba runs the recurrence as "a hardware-aware parallel algorithm in recurrent mode": the expanded state never leaves on-chip SRAM. Its state per layer is dinner × N with N = 16: 5,120 × 16 for Mamba 2.8B. Without a KV cache it serves "4-5x higher inference throughput than a Transformer of similar size" because it "can use much higher batch sizes". authors

Mamba's kernel and state, in detail (depth)
The expanded state (batch × length × channels × N) never touches GPU main memory; parameters are loaded into on-chip SRAM, discretised and scanned there. N = 16 is the code's default and the paper's setting, dinner = 2 × dmodel. The throughput quote is section 4.5 ("since without the KV cache it can use much higher batch sizes"); the abstract rounds it to 5x.

Mamba-2: restrict A to a scalar, and the layer becomes masked attention

Mamba-2 (Dao and Gu 2024) simplifies A "from diagonal to scalar times identity structure": one decay at = exp(ΔtA) per head per step, shared by all its channels and state entries, with head dimension P = 64 or 128 like a transformer. Then unrolling gives

yi = ∑j≤i (Ci·Bj) · (aj+1aj+2…ai) · xj   ⇒   Y = (L ⊙ C B⊤) X
C B⊤
a T × T matrix of query-key scores: C plays the query, B the key, x the value
L
the decay mask, Lij = product of a's between j and i (1 on the diagonal, 0 above it): "1-semiseparable"

That is linear attention (section 2) with a decaying mask instead of the plain causal mask: "When L is the causal mask, it is standard linear attention", and the two are "duals of each other with the exact same linear and quadratic forms". The name is state space duality (SSD). 5. RWKV: an RNN built from attention's pieces

RWKV-4 (Peng et al. 2023) keeps, per channel, a weighted average of past values whose weights decay with distance: wkvt = (∑i<t e−(t−1−i)w + ki vi + eu + kt vt) / (same sum without v), with w "a channel-wise time decay" and u a "bonus" for the current token. The scores are a key-only term plus a fixed linear distance penalty, so numerator and denominator can be carried as running sums: a normalised linear attention with exponential decay (the hero grid's fixed-decay row). The authors state the cost: it "inherently limits its ability to 'look back' at previous tokens", and "carefully designed prompts may be even more crucial".

Then RWKV walked the grid: "multi-headed matrix-valued states" in RWKV-5, decay that changes with the input per channel in RWKV-6 (Eagle and Finch, 2024: "each channel of w_t can now vary independently over time, in a data-dependent manner"), and "a newly generalized formulation of the delta rule with vector-valued gating and in-context learning rates" in RWKV-7 (Goose, 2025). It stayed a community line (Apache-2.0) that no 2026 frontier hybrid uses, but its path is the one the others took.

RWKV's scale, state tracking and code (depth)

The RWKV-4 authors trained up to 14B parameters, "by far the largest dense RNN ever trained". RWKV-7 is proved to "perform state tracking and recognize all regular languages" (solving an S5 permutation tracking problem with one layer), which the authors set against transformers' TC0 limit under standard complexity conjectures; models from 0.19B to 2.9B. authors transformers 5.20.1 ships only RWKV-4; its CPU fallback carries the two running sums plus a running maximum for numerical safety (quoted in section 11).

6. Gated DeltaNet and Kimi Delta Attention in production

Gated DeltaNet is section 3's gated delta rule with learned, input-dependent αt (per head) and βt, L2-normalised queries and keys, a short convolution on q, k and v, and an output gate. Qwen3-Next-80B-A3B (September 2025) ships it: "Hybrid Layout: 12 * (3 * (Gated DeltaNet -> MoE) -> 1 * (Gated Attention -> MoE))", Gated DeltaNet heads "32 for V and 16 for QK; Head Dimension: 128". Qwen3.5 keeps the layout from 0.8B ("6 x (3 x (Gated DeltaNet -> FFN) -> 1 x (Gated Attention -> FFN))") to 397B-A17B ("15 * (3 * ...)"), context "262,144 natively". Qwen model cards, read 2026-10-19

Kimi Delta Attention (KDA), Kimi Linear 2025, changes one thing: "While GDN, similar to Mamba2, employs a coarse head-wise forget gate, KDA introduces a channel-wise variant in which each feature dimension maintains an independent forgetting rate".

7. Hybrids and their ratios

The problem a hybrid solves. A recurrent layer is cheap but cannot look things up exactly; an attention layer can but costs a growing cache. Most of a model's layers do work that a recurrence handles (local syntax, running summaries); a few must retrieve. So keep a few attention layers and make the rest recurrent. The cache then grows only in the attention layers, and the recurrent layers add a fixed state that is reserved from the first token. Step a real request through both:

How the ratios were chosen. Three findings set the one-in-four-to-eight rule:

  • Attention is kept for in-context learning. In Jamba's ablations (AI21, 2024) pure Mamba scores 48.8 on IMDB against attention's 84.1 and the hybrid's 90.9, because "the pure Mamba model often does not follow the correct format" (answering "Very Good" or "3/10" where "Positive" or "Negative" was asked); the hybrid's attention layers hold 12 induction heads. authors
  • Few attention layers suffice. Kimi Linear swept KDA : MLA at equal FLOPs (Table 1, validation perplexity): 3:1 5.65, 1:1 5.66, 7:1 5.70, 15:1 5.82, pure attention (0:1) 5.77. Jamba found "no substantial difference between 1:3 and 1:7 ratios" and took the cheaper 1:7; Qwen chose 3:1. authors
  • Too few fails at scale. MiniMax-01 used one softmax block per seven linear (lightning attention) blocks; MiniMax-M2 went back to full attention because at scale "the model had clear deficits in complex, multi-hop reasoning tasks" (MiniMax, 30 October 2025). vendor
The three findings in full: Jamba's ablations, Kimi's sweep, MiniMax's account (depth)

Jamba (1.3B, 250B tokens): HellaSwag 65.1 for both 1:3 and 1:7, NQ 16.5 against 16.0, "There is no substantial difference between 1:3 and 1:7 ratios". On IMDB, QuAC and NarrativeQA pure Mamba scores 48.8, 20.2, 27.7 against attention's 84.1, 27.9, 45.8 and the hybrid's 90.9, 26.6, 43.7. NVIDIA's, IBM's and TII's ratios, and the RoPE that is never applied (depth)
  • NVIDIA: Waleffe et al. 2024 trained 8B Mamba, Mamba-2, Transformer and a hybrid of "43% Mamba-2, 7% attention, and 50% MLP layers" on the same data; the pure SSMs "lag behind Transformers on tasks which require strong copying or in-context learning abilities (e.g., 5-shot MMLU, Phonebook)", the hybrid "exceeds the 8B Transformer on all 12 standard tasks we evaluated (+2.65 points on average)". 8. What a fixed state is bad at, and good at

Associative recall is producing a token because it followed the same cue earlier in the context ("Hakuna Matata means no worries Hakuna Matata it means no" → "worries"). Zoology (Arora et al. 2023) found that such tokens are "6.4% of all tokens in the Pile" yet "account for 82% of the perplexity gap to attention" of attention-free models, and that "a 70M parameter attention model outperforms a 1.4 billion parameter gated-convolution model on associative recall". A recurrent model's "required ... hidden state dimensionality grows with the number of key-value pairs that the model needs to recall", attention's does not. For copying, Jelassi et al. 2024 find that "even the smallest transformer (410M parameters) outperforms the largest GSSMs (2.8B parameters) when the phone-book size is long enough (L >= 70)", although "the Mamba models achieve lower perplexity than the Pythia models".

MQAR, BASED and the copying proof (depth)
Zoology's multi-query associative recall (MQAR) task lists key-value pairs and then asks for several keys; the state-dimension quote above is from it. BASED (Arora et al. 2024) turns it into a trade-off curve: "a key tradeoff between a model's state size and recall ability". Mamba-2's own MQAR experiment: going "from N=16 to N=64 and N=256 consistently improves performance". Jelassi et al. prove a two-layer transformer can copy strings of exponential length while a fixed-state model "fails to solve the copy task, unless its latent state grows linearly with the sequence length"; the paper prints the phone-book curves, not the numbers. authors
Predict: Pythia-160M and Mamba-130M are asked to repeat a list of random words. Mamba's state is 24 layers × 1,536 channels × 16 = 589,824 numbers; Pythia's KV cache holds 18,432 numbers per token. At about what list length should Mamba start to fall behind?
Mamba keeps up for short lists and falls behind as the list outgrows what its state can hold (the chart below). The break is gradual, not at the 32-token point where the two memories are equal in size: a state is not a list of slots, and a trained model compresses.

What a fixed state is good at. Constant memory and constant work per generated token, so long generations and many concurrent sequences are cheap (section 10); no position limit inside the recurrence (the tiny SSM GPT has no positions at all); and some state-tracking problems (parity, permutations) that delta-rule and Mamba-3-style layers solve and plain attention does not at fixed depth (RWKV-7, Mamba-3 papers, published). The trade is exact, unbounded lookup, which is why hybrids keep attention.

10. Serving a recurrent or hybrid model

Memory. Per sequence, attention needs KV bytes per token × context, a recurrent layer its state once; both multiply by the batch, so the saving lets a server run more sequences at once, which is where the published throughput gains come from (Nemotron-H: "lower memory footprint from Mamba-2 layers facilitates using higher batch sizes"). The state is not free: at short contexts it is the bigger cost. Nemotron-H 8B's 98.8 MiB of fp32 state per sequence equals its attention layers' cache at 6,324 tokens; Kimi K3 carries 443.1 MiB of KDA state per sequence before its first token's cache; the tiny SSM GPT's state (6 layers × (512 × 16 + 544 × 3) numbers in fp32 = 235,776 bytes) equals the baseline's KV cache at 38 tokens. A server must reserve state memory for every live sequence even if it is 10 tokens long.

Compute. Decoding one token reads the weights (the same for both), plus the whole KV cache for attention or the fixed state for a recurrent layer. Prefill is matrix multiplies either way: attention's cost grows with T2, a chunked recurrent layer's with T. Vendor speedups compare whole systems, not mixers (closed block).

Two vendor speedups, read (depth)
Qwen3-Next's "over 10x" beyond 32K is against dense Qwen3-32B, so its 3B active parameters (mixture of experts) carry part of it; Nemotron 3 Super's "up to 2.2x and 7.5x" against gpt-oss-120b and Qwen3.5-122B is at 8K input and 64K output on B200. Mamba-2's "2-8x" is its kernel against Mamba-1's scan; Mamba's "5x" comes from larger batches without a KV cache. vendor

What a state makes harder. A KV cache can be cut at any token: share a prompt prefix between requests, roll back rejected tokens in speculative decoding, branch for beam search. A recurrent state exists only at positions where it was saved:

Rolling back to token 10: attention drops entries, a recurrent layer must restore and recompute

16 tokens of one request; the server must return to token 10 (a rejected speculative draft, or a second request sharing the first 10 tokens). The KV cache keeps one entry per token, so it simply drops 11 to 16. The recurrent layer's state is one object overwritten every token; the server kept snapshots only at block boundaries (every 4 tokens here, illustrative), so it restores token 8's snapshot and recomputes 9 and 10. Follows from the mechanism; no measurement needed.

So prefix caching needs state snapshots at block boundaries, speculative decoding needs the state from before the draft (or a recomputation), and every branch needs its own copy of the state. Serving engines handle this with per-sequence state slots beside the paged KV cache (Batching, KV cache and scheduling, vLLM); in the hybrid, only the attention layers use the paged cache.

Precision. States accumulate over thousands of steps, so they are kept in fp32 even when weights and the KV cache are bf16 (transformers' delta-rule loops cast to fp32: "calculations happen in float as states are more susceptible to rounding errors", modeling_kimi_linear.py). A decay mask built by subtracting cumulative sums loses precision in bf16 (section 11).

Building the decay mask by subtracting cumulative sums, in low precision
Lij = exp(csi − csj) with cs the cumulative sum of log a is exact in algebra, but cs grows with position and the difference of two large numbers loses the small one. Measured (src/code/demos.py, 2,048 positions): max error 0.22 in bf16 against 0.0017 with a segment sum; 3.7e-6 against 5.8e-8 in fp32. transformers' Mamba-2 path uses the segment sum ("More stable ... instead of direct subtractions"); the tiny GPT subtracts, which is fine in fp32 at 256 tokens and would not be in bf16 at long context. Keep states and their decays in fp32.
Tuning RoPE on a hybrid whose attention has no positions
Nemotron-H's and Jamba's configs carry rope_theta; their transformers modeling files define apply_rotary_pos_emb and never call it (section 7, closed block). Changing the base or adding a RoPE scaling for long context changes nothing. Read the modeling code, not the config, before a long-context fix.
Mixing equation conventions between papers
DeltaNet and Gated DeltaNet write the state as dv × dk and update St−1(I − βkk⊤) + βvk⊤; RWKV-7 and Kimi write the transpose with row vectors; transformers' loops keep (dk, dv) and multiply on the left. A port that mixes them silently reads the state with the wrong side.
Design questions (interview rehearsal, 5)
What does Mamba-2 give up relative to Mamba, and what does it get?
A becomes a scalar per head per step instead of a diagonal per channel (less expressive decay). In exchange the layer equals masked linear attention, Y = (L ⊙ CB⊤)X, which trains with chunked matrix multiplies on tensor cores (2 to 8 times faster kernels) and affords a state 4 to 16 times larger (N 64 to 256).
Compute Nemotron-H 8B's recurrent state per sequence from its config.
24 Mamba-2 layers, dinner 8,192 (128 heads of 64), state 128, 8 groups, conv 4: per layer 8,192 × 128 + (8,192 + 2 × 8 × 128) × 3 = 1,079,296 numbers; × 24 × 4 bytes = 98.8 MiB. Its 4 attention layers add 16 KiB per token, so the cache matches the state at about 6,300 tokens.
Why do Jamba, Nemotron-H and Kimi Linear use no positional encoding?
The recurrent layers process tokens in order and carry recency through their decay, so the attention layers receive order already. Jamba measured no difference with RoPE; Kimi argue RoPE in the global layers "yields an overemphasis on short-range order" and NoPE eases long-context extension.
Design: a model for 1M-token contexts serving 32 concurrent users on 8 × 80 GB GPUs.
Budget: 640 GB minus weights. A pure-attention 70B-class model with GQA keeps about 320 KiB per token: 32 × 1M tokens ≈ 10 TiB: impossible. MLA (68.6 KiB per token) still needs about 2.1 TiB. So most layers must be recurrent: a 3:1 delta-rule hybrid with MLA or GQA in the attention layers (Kimi Linear style: 7 MLA layers of 27, 7.9 KiB per token, about 252 GiB for 32 × 1M plus 43 MiB of state per user) fits beside the weights. Keep fp32 states, NoPE or partial RoPE in attention, test retrieval at full length (RULER-style, Long context), and keep enough attention layers that multi-hop retrieval holds (MiniMax's warning).
Design: you must cut serving memory of an existing 8B transformer by 4× at 32K context without retraining from scratch. Options?
GQA or MLA conversion with uptraining (Attention variants child), sliding windows on most layers with a few global ones (Long context child), or distilling into a hybrid (replace most attention layers with Mamba-2 or Gated DeltaNet layers initialised from the attention weights and train briefly, as several 2024 and 2025 distillation papers do; not run here). Check recall probes and long-context retrieval after each, not only perplexity.

Per head h (P channels, state size N), with a scalar decay a_t = exp(dt_t * A_h) that depends on the input:
    state_t = a_t * state_{t-1} + dt_t * x_t B_t^T      (P x N)
    y_t     = state_t C_t + D_h * x_t
Training uses the equivalent "dual" quadratic form y = (L o C B^T) (dt x), L[i,j] = prod_{j<k<=i} a_k, which is
exact and fast at T <= 1-2k; decoding uses the recurrence with a constant-size state (no KV cache).

def segment_sum(input_tensor):
    """
    More stable segment sum calculation. Uses cumulative sums and masking instead of direct subtractions.
    """
    chunk_size = input_tensor.size(-1)
    # 1. expand input tensor to have an additional dimension and repeat along that dimension
    # [..., chunk_size] -> [..., chunk_size, chunk_size]
    input_tensor = input_tensor[..., None].expand(*input_tensor.size(), chunk_size)
    # 2. create a lower triangular mask with the diagonal set to 0 to 0 out elements above diag
    mask = torch.tril(torch.ones(chunk_size, chunk_size, device=input_tensor.device, dtype=torch.bool), diagonal=-1)
    input_tensor = input_tensor.masked_fill(~mask, 0)
    # 3. compute actual cumsum
    tensor_segsum = torch.cumsum(input_tensor, dim=-2)

    # 4. apply mask to keep only the lower triangular part of the cumulative sum result (incl diagonal this time)
    mask = torch.tril(torch.ones(chunk_size, chunk_size, device=input_tensor.device, dtype=torch.bool), diagonal=0)
    tensor_segsum = tensor_segsum.masked_fill(~mask, -torch.inf)
    return tensor_segsum

b_i = beta[:, i][..., None]

kv_mem = (last_recurrent_state * k_i[..., None]).sum(dim=-2)
delta = (v_i - kv_mem) * b_i

last_recurrent_state = last_recurrent_state + k_i.unsqueeze(-1) * delta.unsqueeze(-2)
core_attn_out[:, i] = (last_recurrent_state * q_i.unsqueeze(-1)).sum(dim=-2)

RWKV-4's WKV, one token (CPU fallback). (transformers/models/rwkv/modeling_rwkv.py, lines 185 to 197) A numerator and a denominator carried as decayed running sums, with a running maximum for safe exponentials.

max_for_output = torch.maximum(max_state, current_key + time_first)
e1 = torch.exp(max_state - max_for_output)
e2 = torch.exp(current_key + time_first - max_for_output)
numerator = e1 * num_state + e2 * current_value
denominator = e1 * den_state + e2
output[:, current_index] = (numerator / denominator).to(output.dtype)

# Update state for next iteration
max_for_state = torch.maximum(max_state + time_decay, current_key)
e1 = torch.exp(max_state + time_decay - max_for_state)
e2 = torch.exp(current_key - max_for_state)
num_state = e1 * num_state + e2 * current_value
den_state = e1 * den_state + e2
