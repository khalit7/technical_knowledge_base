1. Recurrence against attention, from zero

The problem. To produce token t, causal attention compares the new query qt with every earlier key and takes a weighted average of every earlier value: ot = ∑j≤t softmaxj(qt·kj/√d) vj. During generation those keys and values are kept (the KV cache), so memory grows linearly with the context and each new token reads all of it: T reads at position T, and T2/2 for a whole sequence. The topic's tiny GPT keeps 6,144 bytes per token in bf16 (6 layers × 8 heads × 32 × 2 for K and V × 2 bytes); Llama 3.1 8B keeps 128 KiB per token, 16 GiB at 131,072 tokens (the root's {{Config calculator|n:3fd5c17b0d0d8172b490dc9f9ac281df}} tab).

A recurrent layer instead keeps a state ht of fixed size and updates it once per token, ht = f(ht−1, xt), reading out yt = g(ht, xt). Memory and work per generated token no longer depend on t. That was the RNN and LSTM era ({{Sequence models: the pre-transformer lineage|n:3c65c17b0d0d818da4ded61ace6847ce}}), and it lost to attention for one reason: with a nonlinear f, ht needs ht−1, so training walks the sequence one step at a time and cannot use a GPU's parallelism across positions.

How the new designs get both. Make the update linear in the state: ht = At ht−1 + bt, where At and bt may depend on the input xt but not on h. Unrolled, every ht is a sum of earlier inputs weighted by products of A's, which can be computed for all t at once: by a parallel scan (an associative combine done in log T rounds; the Mamba paper page animates Blelloch's version), by a convolution when A does not depend on the input (S4), or as one masked matrix product that looks exactly like attention (linear attention and Mamba-2, sections 2 and 4). Training is parallel over positions; decoding is the cheap recurrence. Every design on this page is a choice of what h is, how At forgets, and how bt writes.

What it costs. Whatever the state does not hold is gone. A state of b bits cannot reproduce a string carrying more than b bits, which is the copying bound of {{Jelassi et al. 2024|https://arxiv.org/abs/2402.01032}} ("GSSMs cannot accurately copy strings with more bits than the size of the latent state"). Attention pays memory to avoid that limit. When it matters: long contexts and many concurrent sequences (memory), and long generations (decode work), against tasks that look up exact earlier text (copying, retrieval, few-shot formats). How to check: for any config, compare the per-sequence state with KV bytes per token × context ({{State vs KV cache|#t-mem}}); for any model, probe recall directly ({{Recall probes|#t-recall}}).

2. Linear attention is a recurrence

The derivation. Softmax attention's weight for key j is exp(q·kj) divided by the sum over all keys. {{Katharopoulos et al. 2020|https://arxiv.org/abs/2006.16236}} replace exp(q·k) by a dot product of feature maps φ(q)·φ(k), with φ(x) = elu(x) + 1 to keep weights positive ("We prefer elu(.) over relu(.) to avoid setting the gradients to 0 when x is negative", eq. 7). Then the sum can be reassociated:

ot = ∑j≤t (φ(qt)⊤φ(kj)) vj / ∑j≤t φ(qt)⊤φ(kj) = St⊤φ(qt) / zt⊤φ(qt)
St = St−1 + φ(kt) vt⊤    zt = zt−1 + φ(kt)
St
the state: a dk × dv matrix, the sum of every key's outer product with its value
zt
the normaliser: the sum of the keys
φ
a feature map applied to queries and keys (elu + 1 here; later work uses identity with L2-normalised keys)

The paper puts it as "any transformer layer with causal masking can be written as a model that, given an input, modifies an internal state and then predicts an output, namely a Recurrent Neural Network" with "two hidden states, namely the attention memory s and the normalizer memory z". For one head of the tiny GPT (dk = dv = 32) the state is 1,024 + 32 numbers whatever the context, against 64 numbers per past token for its KV cache: the state is cheaper past 16 tokens.

Two ways to compute the same thing. In training, stack all positions: O = ((φ(Q)φ(K)⊤) ⊙ M) V with M the causal mask, a T × T matrix like an attention map (row-normalised by the same sums). In decoding, run the recurrence. The script below checks the two forms agree to 4.4e-16 in float64 (output pasted from src/code/out/demos.txt):

linear attention, T=64, d=16: max |parallel - recurrent| = 4.44e-16
state size: 272 numbers, whatever T is; a KV cache here holds 2048 numbers

The cost. The parallel form is quadratic like attention; the recurrence is linear but sequential; production kernels split the sequence into chunks, use the quadratic form inside each chunk (matrix multiplies, which tensor cores are built for) and pass the state between chunks (section 4). Published speed: "up to 4000x faster on autoregressive prediction of very long sequences" (abstract), which Figure 4 shows is pixel-by-pixel CIFAR-10 image generation (sequence length 3,072; "more than 300 times" on MNIST), not text. authors' measurement

The catch. S is a sum. Every write adds to it and nothing is ever removed, so once more keys than dk have been written they cannot all be orthogonal and reads return blends. {{Schlag, Irie and Schmidhuber 2021|https://arxiv.org/abs/2102.11174}} name it: "linear Transformers can end up in an overcapacity regime, if the sequence length L exceeds the dimension d_dot of the keys".
