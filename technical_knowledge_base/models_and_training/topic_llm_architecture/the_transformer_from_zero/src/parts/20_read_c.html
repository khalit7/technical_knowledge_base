2. Tokens to vectors: the embedding and the position table

The problem. A network computes with numbers, and a token id is a name, not a quantity: id 1,407 is not "more" than id 12. The fix is a lookup table with one learned row of D numbers per vocabulary entry. Row lookup is the same as multiplying a one-hot vector (all zeros, a 1 at the id) by the table, so the table is an ordinary weight matrix that the optimiser trains like any other, but no multiplication is performed: an nn.Embedding just indexes.

Why a second table. Attention, built in the next section, compares every position with every other through dot products, and a dot product does not know where its two vectors came from. Shuffle the tokens of a sentence and an attention layer without a mask returns exactly the same outputs, shuffled the same way: the layer is permutation-equivariant. Word order would be invisible. GPT-2 style models add a second learned table with one row per position (learned absolute positions), so the vector for " R" at position 20 differs from " R" at position 25. Every later block reads the sum.

3. One attention head, by hand

The problem. After the embedding, position t knows only its own token. To predict what follows "Roxy found an", the model must read earlier positions, and which ones matter depends on the content ("an" points at the next word's first sound; "Roxy" points back at whoever Roxy is). A fixed averaging window cannot do that; a content-dependent weighting can.

How it works. Each position emits three vectors of hd numbers, all linear maps of its residual vector x: a query q (what it is looking for), a key k (what it offers to be found by) and a value v (what it hands over if found). The score of position j for position i is the dot product qi·kj, divided by √hd. The causal mask sets the scores of later positions (j > i) to minus infinity, so the softmax (exponentiate each score, divide by the row's sum) gives them weight exactly 0 and turns the rest into weights that sum to 1. The output for position i is the weighted sum of the values.

yi = Σj≤i softmaxj( qi·kj / √hd ) vj,   q = xWq, k = xWk, v = xWv

Why divide by √hd. If the entries of q and k are independent with mean 0 and variance 1, their dot product sums hd such products and has variance hd (Vaswani et al. 2017, section 3.2.1 and its footnote, {{arXiv 1706.03762|https://arxiv.org/abs/1706.03762}}; the paper page {{Attention Is All You Need|n:3c65c17b0d0d81999af7f16f8ed8ee9e}} reproduces it). The measured standard deviation above is [[f:dot_std|f2]] for hd = 32, against √32 = 5.66. Scores that wide push the softmax onto one key: with 256 random keys the largest weight averages [[f:maxw32_raw|f2]] unscaled and [[f:maxw32_sc|f2]] scaled at hd = 32, and [[f:maxw128_raw|f2]] unscaled at hd = 128, so the row is close to one-hot and its gradient close to zero. The scale keeps the softmax soft at any head size. Llama's code stores it as self.scaling = self.head_dim**-0.5 ([[ref:hf_scaling]]); nanoGPT multiplies by 1.0 / math.sqrt(k.size(-1)) ([[ref:nano_scores]]). Dropping it on the trained tiny GPT raises the running sequence's loss from 1.96 to 2.88, measured by the root's Block lab, which also shows the mask and transpose bugs.

Cost. T × T scores per head: memory and FLOPs that grow with the square of the context (section 10). When it matters. Every token of every LLM; the alternatives (sharing K and V across heads, compressing them, windows) are {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}. How to check. Rows of the weights sum to 1, the upper triangle is 0, and editing a later token never moves an earlier output.

Predict: with the causal mask, what is the attention weight of token 0 on itself, in every head and every layer?
Exactly 1. Token 0 may only look at keys 0..0, so its softmax has one entry, and one entry always gets weight 1, whatever the score. Its attention output is its own value vector. The {{Inside a real model|n:3fd5c17b0d0d8172b490dc9f9ac281df}} tab on the root shows how real models then use the first token as a place to park attention (the sink), which the tiny GPT does not (first-token share 0.005 to 0.015 per layer, root Attention lab).

4. Many heads in one matrix multiply

The problem. One head produces one weighting per position, so it can follow one relation at a time (the previous word, or the subject, or the matching quote). Several heads let the layer follow several relations in parallel, each in its own smaller space of hd = D / H numbers, at the same parameter count as one wide head.

How it works. Instead of H small (D, hd) matrices, one (D, D) matrix computes all H queries at once; the result is reshaped from (B, T, D) to (B, T, H, hd) and transposed to (B, H, T, hd), so that the head axis sits next to the batch axis and every head becomes an independent batched matrix multiply. After attention the heads are transposed back and laid side by side, and an output projection Wo (D, D) mixes them. The four matrices are the layer's 4D2 = [[f:p_attn_layer|i]] parameters.

Two details trip everyone once. nn.Linear(D_in, D_out) stores its weight as (out, in) and computes x WT, so head h's query matrix is the slice q.weight[h*hd:(h+1)*hd].T. And .view needs memory laid out in the order of the new shape, which a transpose breaks: the merge must use .reshape or .contiguous().view, as the error above says. The split must be a view to (B, T, H, hd) followed by a transpose; viewing straight to (B, H, T, hd) silently scrambles tokens across heads (loss 1.96 to 3.64 on the trained model, root Block lab).

Cost. The same 4D2 parameters and the same FLOPs whatever H is; each head's scores are T × T, so H heads hold H score matrices. When it matters.
