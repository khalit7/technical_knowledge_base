8. Training it, and reading the loss curve

The loop. Draw 32 random windows of 257 tokens from the training split, run the model, take the loss, backpropagate (the gradient of the loss with respect to every parameter; derived in {{Matrix calculus and backprop|n:3f05c17b0d0d817e9892e01088179c93}}), clip the gradient's norm to 1, and let AdamW update the weights. The schedule is the running example's for every run on this topic: learning rate 3e-3 reached after 100 warm-up steps, then a cosine decay to 3e-4 at step 1,500; AdamW with betas (0.9, 0.95) and weight decay 0.1 on matrices only; fp32 (faster than bf16 autocast on this GPU: 40k against 30k tokens/s, root setup). How these choices are made at scale is {{Pretraining|n:3c65c17b0d0d814f82cffd0d5c0dd5ba}}.

Reading the curve. A loss curve is easier to read against the losses of models you can write down. A model that ignores context and always predicts each token's overall frequency scores the unigram cross-entropy, [[f:unigram|f3]] nats on the held-out split (root Block lab). A model that sees only the previous token scores at best about the bigram cross-entropy, [[f:bigram|f3]] nats here (counts of token pairs in the 122M training tokens, smoothed toward the unigram, calculated by src/train/curve.py). The uniform guess is 8.318. The run passes the unigram line by step [[f:cross_uni|i]] (train loss) and the bigram line between steps 200 and 250 (held-out); everything below [[f:bigram|f2]] is the model using more than one token of context.

Predict first: which tokens of the story stay expensive longest? Three phases show up; the steps walk seven of the run's twelve snapshots (all twelve are the dots on the curve).

  1. Step 0: uniform. Held-out 8.381 against the uniform 8.318; every token costs about the same, and the greedy continuation is a repeated fragment ("ryryry", "volcano volcano").
  2. Steps 0 to about 50: the model learns which tokens are common. Held-out 4.609 at step 50, far below the unigram line; the continuation strings common words together ("She was a time").
  3. Steps 50 to about 300: grammar arrives, local and repetitive ("The little girl named Lily. The little girl named Lily."). Held-out 4.082 at step 100.
  4. Step 300: below the bigram line. Held-out 3.312: the model now uses more than one token of context, but the name is still expensive: the three tokens after " R" cost about 25 nats at every occurrence at step 0, and still 9 to 11 at step 300.
  5. Step 500: memory of the story. Held-out 2.942. After that the gains are in the tokens that need memory of the story; the drop for repeats of the name starts here.
  6. Step 1,000. Held-out 2.469; the greedy continuation is a story ("he saw a big, shiny rock on the ground").
  7. Step 1,500: the name is reused. Held-out 2.274. The three tokens after " R" cost [[f:roxy_first|f1]] nats together at the name's first appearance, [[f:roxy_second|f1]] at the second and [[f:roxy_later|f1]] on average from the third on (nine occurrences). So the model reuses the name from earlier in its context; greedy writes "Roxy saw a big, scary cat".

It does so without an induction head in the usual sense (the root Inside lab's repeated-random-token probe scores 0.012 on this model), so the mechanism at this scale is unconfirmed.

How to check a run is healthy: the first logged loss is near ln V; the loss falls below the unigram line within tens of steps; the held-out loss keeps falling with the training loss (12.3M tokens is a tenth of one pass over the training shard, so no window is seen twice on average and there is nothing to overfit yet); no spike survives clipping.

Recompute the prefix, or keep its keys and values: the same ten new tokens both ways

A 30-token prompt, then 10 generated tokens, as in steps.py's cache test. FLOPs are derived for the tiny GPT: weights 2 × [[f:matmul_params|i]] per token through the model (every block matrix and the output layer), attention 4 × L × D per key read (a query against a key and a weight times a value); with a cache only the new token goes through.

9. Sampling: from logits to text

Generation runs the prompt through the model, turns the last position's logits into a distribution, picks one token, appends it, and repeats. Recomputing the whole prefix every step repeats work: the keys and values of earlier positions never change (the mask stops them from seeing new tokens), so a KV cache keeps them per layer, and each new step runs the model on one token only and attends over the cache.

  1. Prefill. The 30 prompt tokens go through in one forward pass, the same either way. Without a cache nothing is kept but the logits.
  2. Token 31. The whole prefix, now 31 tokens, goes through the model again to produce one new token.
  3. Token 32. 32 tokens through: every step repeats all the earlier work and a little more.
  4. Token 35. 35 tokens through for one new token; the FLOPs of the step grow with the length.
  5. Token 40. 40 tokens through; summed over the steps, the total grows with the square of the length.
  1. Prefill. The same pass over the 30 prompt tokens, and their keys and values are kept: per layer K is (1, 8, 30, 32) = (B, H, t, hd), and V the same.
  2. Token 31. Only the new token goes through; its query reads the 30 cached keys and values in each layer, and its own key and value are appended.
  3. Token 32. One token through again; the cache grows by one token, 2 × L × D numbers.
  4. Token 35. The step costs the weights once plus a read of the cache; it no longer reruns the prefix.
  5. Token 40. 40 tokens cached; the FLOPs so far are a fraction of the recompute total on the other tab, for 245,760 bytes of cache in bf16.

Measured: decoding tokens 30 to 39 one at a time with the cache matches one full forward to [[f:cache_diff|e]]. The cache costs 2 × L × D numbers per token: 6,144 bytes in bf16 here, 128 KiB for Llama 3.1 8B with its 8 key-value heads (root findings). How big it gets at long context is the {{Long context|n:3fd5c17b0d0d81059ee1ce20c0326dc5}} page's KV-cache calculator; serving at scale is {{Batching, KV cache and scheduling|n:3c65c17b0d0d819db53bd2c48909e5b2}}.

Picking the token. Greedy decoding takes the largest logit; it is deterministic and, in small models, repetitive. Temperature T divides the logits before the softmax: T < 1 sharpens the distribution toward greedy, T > 1 flattens it toward uniform. Top-k keeps only the k largest logits. The explorer uses the trained model's real logits at two points of the running sequence; the bars are the probabilities after the transform.
