The idea in one screen

A decoder-only transformer keeps one vector of D numbers per token, the residual stream, and every block adds two updates to it: attention, which mixes in what earlier positions hold, and a feed-forward network, which transforms each position on its own; the token table, reused as the output layer, turns the last vector into next-token scores, and cross-entropy against the sequence shifted by one is the whole training signal.

  1. Ids to vectors. The running sequence's 256 token ids, (1, 256) = (B, T), pick rows of the token table (4,096 × 256 = 1,048,576 parameters) and of the position table (256 × 256 = 65,536); their sum, (1, 256, 256) = (B, T, D), is the residual stream ({{section 2|#tz-s2}}).
  2. One block. Each block reads a normalised copy of the stream twice: attention (8 heads of hd = 32; q, k, v, o: 4 × 256 × 256 = 262,144 parameters) adds what earlier positions hold, then the FFN (256 to 1,024 to 256, 524,288 parameters) transforms each position on its own and adds again ({{sections 3 to 6|#tz-s3}}).
  3. Six blocks, one stream. The same block six times, 786,944 parameters each; the stream keeps its shape (1, 256, 256) all the way up. The columns are the trained model's median stream norm after the embedding and after each block: 1.3 to 65.5 (root Block lab).
  4. Final norm, then the token table again. A last LayerNorm (256 gains), then the unembedding, which is the token table itself (tied: 0 new parameters), scores the final vector against all 4,096 rows: logits (1, 256, 4,096) = (B, T, V) ({{section 7|#tz-s7}}).
  5. Next-token loss. Softmax over the logits, then minus the log probability of the token that came next. For "o" at position 157 the next token is "x", given [[f:p_next|pct1]], so the loss there is [[f:loss_here|f3]] nats. Averaged over the running sequence: untrained [[f:loss0|f3]] (ln 4,096 = 8.318), trained [[f:loss_trained|f3]].
  6. What each piece is worth. Each piece removed and the model retrained at the same budget ({{section 11|#tz-s11}}), held-out loss against [[f:abl_base_val|f3]] for the full model: no positions [[f:abl_nopos_val|f3]], one head [[f:abl_1head_val|f3]] ([[f:abl_1head_s1_val|f3]] at seed 1), no FFN [[f:abl_noffn_val|f3]] (also 54% fewer parameters), no attention [[f:abl_noattn_val|f3]] (the bigram floor), no norms [[f:abl_nonorm_val|f3]], no residual sum [[f:abl_noresid_val|f3]] (the unigram level).

The tiny GPT, [[f:p_total|i]] parameters, on the running sequence (B = 1, T = 256). Not to scale: the token table has 16 times the position table's rows. Stream norms and probabilities are the trained checkpoint's, traced on CPU by the root's src/block/trace.py (this page's file loads that checkpoint with identical logits); removal losses measured on Apple M1 Pro.

1. The task, the running example and the notation

A language model gives the next token a probability from the tokens before it; a decoder-only transformer gives T of them in one pass over T tokens, position t predicting token t + 1 from positions 0 to t. Training lowers the average cross-entropy (minus the log probability of the token that came next) in nats; a loss L means the model is as unsure as a uniform choice among eL tokens, the perplexity.

The running example, defined once for the whole topic by the root page: TinyStories (Eldan and Li 2023, {{arXiv 2305.07759|https://arxiv.org/abs/2305.07759}}; licence CDLA-Sharing-1.0), short stories written by GPT-3.5 and GPT-4 for training small models; a byte-level BPE tokenizer of V = 4,096 tokens trained on it; and the running sequence, the first 256 tokens of validation story 1, never seen in training:

Once upon a time, in a big forest, there lived a rhinoceros named Roxy. Roxy loved to climb. She climbed trees, rocks, and hills. One day, Roxy found an icy hill. She had never seen anything like it before. It was shiny and cold, and she wanted to climb it. ...

The model is the root's tiny GPT, with tied embeddings and a context of 256 tokens. Every shape on this page uses these letters:

Ffeed-forward hidden width (1,024 = 4D; 14,336 in Llama 3.1 8B)

2. Tokens to vectors: the embedding and the position table

Each token id selects one learned row of D numbers from a (V, D) table: an id is a name, not a quantity (id 1,407 is not "more" than id 12). A row lookup equals a one-hot vector times the table, so the table trains like any weight matrix, but nn.Embedding only indexes. A second table adds one learned row per position (learned absolute positions, as in GPT-2), because attention compares positions only through dot products, which do not know where their vectors came from: shuffle the tokens and an attention layer without a mask returns the same outputs, shuffled the same way (it is permutation-equivariant), so word order would be invisible. Every later block reads the sum.

  1. An id picks a row. Token 157 of the running sequence, "o" in "Why are you sad, Ro|xy", is id 79; the lookup takes row 79 of the (4,096, 256) token table. The same as a one-hot vector times the table (difference 0), but nn.Embedding only indexes.
  2. The row is the token's vector. 256 learned numbers (norm [[f:emb_tok_norm|f2]] in the trained model), drawn as signed bars: up for positive, down for negative.
  3. The position picks a row of a second table. Row 157 of the (256, 256) position table (norm [[f:emb_pos_norm|f2]]): one learned row per position, as in GPT-2.
  4. The sum is what block 1 reads. x = token row + position row (norm [[f:emb_x_norm|f2]]): the residual stream starts here, (1, 256, 256) = (B, T, D) for the whole sequence.
  5. One row, many sums. "o" is [[f:o_count|i]] of the 256 tokens of the running sequence; all of them read row 79, and only their position rows tell them apart. Measured on "Roxy"'s first token " R" at positions 20 and 25: the token rows are identical (difference 0.0); after adding the position rows their cosine is 0.433.

3. One attention head, by hand

After the embedding, position t knows only its own token. Predicting what follows "Roxy found an" needs earlier positions, and which ones depends on content ("an" points at the next word's first sound; "Roxy" back at whoever Roxy is), which no fixed averaging window can do. Each position emits three linear maps of its residual vector x, hd numbers each: a query q (what it looks for), a key k (what it offers to be found by) and a value v (what it hands over if found). Position j's score for position i is qi·kj / √hd; the causal mask sets the scores of later positions (j > i) to minus infinity, so the softmax (exponentiate, divide by the row's sum) gives them weight exactly 0 and the rest weights that sum to 1. The output for position i is the weighted sum of the values.

  1. Three projections. Layer 1's LayerNorm hands the head a normalised copy of "o"'s vector (256 numbers); three (256, 32) matrices, Wq, Wk and Wv, turn it into a query, a key and a value of hd = 32 numbers each. Every position does the same.
  2. Scores against every key. The query is dotted with the key of each of the 158 positions so far and divided by √32: one row of the (T, T) score matrix on the floor (keys across, queries in depth). The highest, [[f:h4_top_score|f2]], is the "x" at position 143.
  3. The causal mask. Keys after the query (j > i, the dark triangle) get minus infinity, so position 157 cannot read the 98 tokens after it. Every row has the same rule, so the triangle is the mask of all 256 queries at once.
  4. Softmax. Each row becomes weights that sum to 1 (measured: max |sum − 1| = 2.4e-07; above the diagonal exactly 0.0). This head puts [[f:h4_x_share|pct0]] of its weight on the [[f:h4_x_count|i]] earlier "x" tokens, the token that followed "Ro" each time "Roxy" appeared, [[f:h4_top|f2]] on the latest at 143; the model ends up giving "x" [[f:p_next|pct0]] (section 7).
  5. Mix the values. The output for position 157 is the weighted sum of the values, y = Σj≤157 wj vj, 32 numbers for this head; the dots show each value's weight.
  6. Edit a later token. Key 200 lies in the masked triangle for rows 0 to 199, so changing token 200 cannot move their outputs. Measured on the running sequence (a head with random weights, steps.py): changing token 200 moves outputs 0 to 199 by exactly 0.0 and outputs 200 to 255 by up to 4.1e-04. One forward pass is therefore T valid next-token examples.

Why divide by √hd. If the entries of q and k are independent with mean 0 and variance 1, their dot product sums hd such products and has variance hd (Vaswani et al. 2017, section 3.2.1 and its footnote, {{arXiv 1706.03762|https://arxiv.org/abs/1706.03762}}; the {{Attention Is All You Need|n:3c65c17b0d0d81999af7f16f8ed8ee9e}} paper page reproduces it). Measured: standard deviation [[f:dot_std|f2]] for hd = 32, against √32 = 5.66. Scores that wide push the softmax onto one key, so the row is close to one-hot and its gradient close to zero; the scale keeps the softmax soft at any head size:

Dropping the scale on the trained tiny GPT raises the running sequence's loss from 1.96 to 2.88, measured by the root's Block lab, which also shows the mask and transpose bugs. Llama's code stores it as self.scaling = self.head_dim**-0.5 ([[ref:hf_scaling]]); nanoGPT multiplies by 1.0 / math.sqrt(k.size(-1)) ([[ref:nano_scores]]).

Cost. T × T scores per head: memory and FLOPs that grow with the square of the context (section 10). The alternatives (sharing K and V across heads, compressing them, windows) are {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}. Check: rows of the weights sum to 1, the upper triangle is 0, and editing a later token never moves an earlier output.

Predict: with the causal mask, what is the attention weight of token 0 on itself, in every head and every layer?
Exactly 1. Token 0 may only look at keys 0..0, so its softmax has one entry, and one entry always gets weight 1, whatever the score. Its attention output is its own value vector. The {{Inside a real model|n:3fd5c17b0d0d8172b490dc9f9ac281df}} tab on the root shows how real models then use the first token as a place to park attention (the sink), which the tiny GPT does not (first-token share 0.005 to 0.015 per layer, root Attention lab).

4. Many heads in one matrix multiply

One head produces one weighting per position, so it follows one relation at a time (the previous word, or the subject, or the matching quote). Several heads follow several relations in parallel, each in its own space of hd = D / H numbers, at the same parameter count as one wide head. Instead of H small (D, hd) matrices, one (D, D) matrix computes all H queries at once; the result is viewed as (B, T, H, hd) and transposed to (B, H, T, hd), so the head axis sits next to the batch axis and every head becomes an independent batched matrix multiply. After attention the heads are transposed back, laid side by side, and an output projection Wo (D, D) mixes them. The four matrices are the layer's 4D2 = [[f:p_attn_layer|i]] parameters.

  1. One matmul for all heads. att.q is one (256, 256) matrix: it computes all 8 heads' queries at once, (1, 256, 256) = (B, T, D); drawn is row 157, "o", in layer 1 of the trained model. Wk and Wv do the same for keys and values.
  2. view: 256 = 8 × 32. .view(B, T, H, hd) cuts each 256-vector into 8 heads of 32, (1, 256, 8, 32). Nothing moves in memory.
  3. transpose: heads become a batch. .transpose(1, 2) gives (1, 8, 256, 32): 8 independent (T, hd) problems, each with its own (T, T) weights. Row 157 of each, measured: heads 0 and 5 put [[f:h0_prev|pct0]] and [[f:h5_prev|pct0]] on the previous token " R"; head 4 [[f:h4_x_share|pct0]] on the earlier "x" tokens (Fig. 3); heads 1, 2 and 7 spread almost evenly ([[f:ent_lo|f1]] to [[f:ent_hi|f1]] bits of entropy; uniform over 158 keys is [[f:ent_uniform|f1]]).
  4. Each head's output. Each head mixes its own values into 32 numbers: (1, 8, 256, 32).
  5. Merge and mix. .transpose(1, 2).reshape(B, T, D) lays the 8 outputs side by side again, 256 numbers, and Wo (256, 256) mixes them into attention's output for "o" (norm [[f:l1_attn_out|f2]]), which is added to the stream (section 6).

Measured: the batched layer equals 8 separate one-head calls concatenated (max difference 0) and F.scaled_dot_product_attention(q, k, v, is_causal=True) to [[f:sdpa_diff|e]]; the file uses the fused call for speed. Vectors and weights: the trained checkpoint, layer 1, traced by the root's src/block/trace.py; weights under 0.3% are not drawn.
