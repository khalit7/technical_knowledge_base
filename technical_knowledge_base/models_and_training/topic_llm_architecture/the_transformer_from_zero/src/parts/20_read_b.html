The idea in one screen

A decoder-only transformer keeps one vector of D numbers per token, the residual stream, and every block adds two updates to it: attention, which mixes in what earlier positions hold, and a feed-forward network, which transforms each position on its own; the token table, reused as the output layer, turns the last vector into next-token scores, and cross-entropy against the sequence shifted by one is the whole training signal.

1. The task, the running example and the notation

A language model gives the next token a probability from the tokens before it; a decoder-only transformer gives T of them in one pass over T tokens, position t predicting token t + 1 from positions 0 to t. Training lowers the average cross-entropy (minus the log probability of the token that came next) in nats; a loss L means the model is as unsure as a uniform choice among eL tokens, the perplexity.

The running example, defined once for the whole topic by the root page: TinyStories (Eldan and Li 2023, {{arXiv 2305.07759|https://arxiv.org/abs/2305.07759}}; licence CDLA-Sharing-1.0), short stories written by GPT-3.5 and GPT-4 for training small models; a byte-level BPE tokenizer of V = 4,096 tokens trained on it; and the running sequence, the first 256 tokens of validation story 1, never seen in training:

Once upon a time, in a big forest, there lived a rhinoceros named Roxy. Roxy loved to climb. She climbed trees, rocks, and hills. One day, Roxy found an icy hill. She had never seen anything like it before. It was shiny and cold, and she wanted to climb it. ...

The model is the root's tiny GPT, with tied embeddings and a context of 256 tokens. Every shape on this page uses these letters:

Ffeed-forward hidden width (1,024 = 4D; 14,336 in Llama 3.1 8B)

2. Tokens to vectors: the embedding and the position table

Each token id selects one learned row of D numbers from a (V, D) table: an id is a name, not a quantity (id 1,407 is not "more" than id 12). A row lookup equals a one-hot vector times the table, so the table trains like any weight matrix, but nn.Embedding only indexes. A second table adds one learned row per position (learned absolute positions, as in GPT-2), because attention compares positions only through dot products, which do not know where their vectors came from: shuffle the tokens and an attention layer without a mask returns the same outputs, shuffled the same way (it is permutation-equivariant), so word order would be invisible. Every later block reads the sum.

Two lookups and a sum: the same token at two positions becomes two vectors

"Roxy" is four tokens (" R", "o", "x", "y"). At positions 20 and 25 the token rows are identical (difference 0.0); after adding the position rows their cosine is 0.433. The shuffle test on the trained model's embeddings and head 0 of its first attention layer, without the causal mask: without positions the outputs are the same rows shuffled (largest change 5.6e-07 of the largest output); with positions added, 1.13. 3. One attention head, by hand

After the embedding, position t knows only its own token. Predicting what follows "Roxy found an" needs earlier positions, and which ones depends on content ("an" points at the next word's first sound; "Roxy" back at whoever Roxy is), which no fixed averaging window can do. Each position emits three linear maps of its residual vector x, hd numbers each: a query q (what it looks for), a key k (what it offers to be found by) and a value v (what it hands over if found). Position j's score for position i is qi·kj / √hd; the causal mask sets the scores of later positions (j > i) to minus infinity, so the softmax (exponentiate, divide by the row's sum) gives them weight exactly 0 and the rest weights that sum to 1. The output for position i is the weighted sum of the values.

Why divide by √hd. If the entries of q and k are independent with mean 0 and variance 1, their dot product sums hd such products and has variance hd (Vaswani et al. 2017, section 3.2.1 and its footnote, {{arXiv 1706.03762|https://arxiv.org/abs/1706.03762}}; the {{Attention Is All You Need|n:3c65c17b0d0d81999af7f16f8ed8ee9e}} paper page reproduces it). Measured: standard deviation [[f:dot_std|f2]] for hd = 32, against √32 = 5.66. Scores that wide push the softmax onto one key, so the row is close to one-hot and its gradient close to zero; the scale keeps the softmax soft at any head size:

Without the scale, one key takes most of the weight

The largest of 256 softmax weights, averaged over random unit-variance queries and keys (steps.py, CPU). A uniform row would give each key 1/256 = 0.004.

Dropping the scale on the trained tiny GPT raises the running sequence's loss from 1.96 to 2.88, measured by the root's Block lab, which also shows the mask and transpose bugs. Llama's code stores it as self.scaling = self.head_dim**-0.5 ([[ref:hf_scaling]]); nanoGPT multiplies by 1.0 / math.sqrt(k.size(-1)) ([[ref:nano_scores]]).

Cost. T × T scores per head: memory and FLOPs that grow with the square of the context (section 10). The alternatives (sharing K and V across heads, compressing them, windows) are {{Attention variants|n:3fd5c17b0d0d8120859ecc2d0236e846}}. Check: rows of the weights sum to 1, the upper triangle is 0, and editing a later token never moves an earlier output.

Predict: with the causal mask, what is the attention weight of token 0 on itself, in every head and every layer?
Exactly 1. Token 0 may only look at keys 0..0, so its softmax has one entry, and one entry always gets weight 1, whatever the score. Its attention output is its own value vector. The {{Inside a real model|n:3fd5c17b0d0d8172b490dc9f9ac281df}} tab on the root shows how real models then use the first token as a place to park attention (the sink), which the tiny GPT does not (first-token share 0.005 to 0.015 per layer, root Attention lab).

4. Many heads in one matrix multiply

One head produces one weighting per position, so it follows one relation at a time (the previous word, or the subject, or the matching quote). Several heads follow several relations in parallel, each in its own space of hd = D / H numbers, at the same parameter count as one wide head. Instead of H small (D, hd) matrices, one (D, D) matrix computes all H queries at once; the result is viewed as (B, T, H, hd) and transposed to (B, H, T, hd), so the head axis sits next to the batch axis and every head becomes an independent batched matrix multiply. After attention the heads are transposed back, laid side by side, and an output projection Wo (D, D) mixes them. The four matrices are the layer's 4D2 = [[f:p_attn_layer|i]] parameters.

nanoGPT does the same split at [[ref:nano_split]] and the merge at [[ref:nano_merge]]. nn.Linear(D_in, D_out) stores its weight as (out, in) and computes x WT, so head h's query matrix is the slice q.weight[h*hd:(h+1)*hd].T. The split must be a view to (B, T, H, hd) followed by a transpose; viewing straight to (B, H, T, hd) silently scrambles tokens across heads (loss 1.96 to 3.64 on the trained model, root Block lab).
