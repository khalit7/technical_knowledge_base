The idea in one screen

A decoder-only transformer keeps one vector of D numbers per token, the residual stream, and every block adds two updates to it: attention, which mixes in what earlier positions hold, and a feed-forward network, which transforms each position on its own; the token table, reused as the output layer, turns the last vector into next-token scores, and cross-entropy against the sequence shifted by one is the whole training signal.

1. The task, the running example and the notation

A language model gives the next token a probability from the tokens before it; a decoder-only transformer gives T of them in one pass over T tokens, position t predicting token t + 1 from positions 0 to t. Training lowers the average cross-entropy (minus the log probability of the token that came next) in nats; a loss L means the model is as unsure as a uniform choice among eL tokens, the perplexity.

The running example, defined once for the whole topic by the root page: TinyStories (Eldan and Li 2023, arXiv 2305.07759; licence CDLA-Sharing-1.0), short stories written by GPT-3.5 and GPT-4 for training small models; a byte-level BPE tokenizer of V = 4,096 tokens trained on it; and the running sequence, the first 256 tokens of validation story 1, never seen in training:

2. Tokens to vectors: the embedding and the position table

Each token id selects one learned row of D numbers from a (V, D) table: an id is a name, not a quantity (id 1,407 is not "more" than id 12). A row lookup equals a one-hot vector times the table, so the table trains like any weight matrix, but nn.Embedding only indexes. A second table adds one learned row per position (learned absolute positions, as in GPT-2), because attention compares positions only through dot products, which do not know where their vectors came from: shuffle the tokens and an attention layer without a mask returns the same outputs, shuffled the same way (it is permutation-equivariant), so word order would be invisible. Every later block reads the sum.

3. One attention head, by hand

After the embedding, position t knows only its own token. Predicting what follows "Roxy found an" needs earlier positions, and which ones depends on content ("an" points at the next word's first sound; "Roxy" back at whoever Roxy is), which no fixed averaging window can do. Each position emits three linear maps of its residual vector x, hd numbers each: a query q (what it looks for), a key k (what it offers to be found by) and a value v (what it hands over if found). Position j's score for position i is qi·kj / √hd; the causal mask sets the scores of later positions (j > i) to minus infinity, so the softmax (exponentiate, divide by the row's sum) gives them weight exactly 0 and the rest weights that sum to 1. The output for position i is the weighted sum of the values.

Why divide by √hd. If the entries of q and k are independent with mean 0 and variance 1, their dot product sums hd such products and has variance hd (Vaswani et al. 2017, section 3.2.1 and its footnote, arXiv 1706.03762; the Attention Is All You Need paper page reproduces it). Measured: standard deviation 5.65 for hd = 32, against √32 = 5.66. Scores that wide push the softmax onto one key, so the row is close to one-hot and its gradient close to zero; the scale keeps the softmax soft at any head size:

4. Many heads in one matrix multiply

One head produces one weighting per position, so it follows one relation at a time (the previous word, or the subject, or the matching quote). Several heads follow several relations in parallel, each in its own space of hd = D / H numbers, at the same parameter count as one wide head. Instead of H small (D, hd) matrices, one (D, D) matrix computes all H queries at once; the result is viewed as (B, T, H, hd) and transposed to (B, H, T, hd), so the head axis sits next to the batch axis and every head becomes an independent batched matrix multiply. After attention the heads are transposed back, laid side by side, and an output projection Wo (D, D) mixes them. The four matrices are the layer's 4D2 = 262,144 parameters.

Shapes on the running sequence (steps.py): att.q(x) (1, 256, 256) = (B, T, D), (B, T, D): all 8 heads in one matmul; .view(B, T, H, hd) (1, 256, 8, 32) = (B, T, H, hd), split D = 8 x 32; .transpose(1, 2) (1, 8, 256, 32) = (B, H, T, hd), heads before T: 8 independent (T, hd) problems; q @ k.transpose(-2, -1) (1, 8, 256, 256) = (B, H, T, T), 8 score matrices; merge: .transpose(1, 2).reshape(B, T, D) (1, 256, 256) = (B, T, D), heads side by side again; att.o(y) (1, 256, 256) = (B, T, D), output projection mixes the heads.

Cost. The same 4D2 parameters and the same FLOPs whatever H is; each head's scores are T × T, so H heads hold H score matrices. The single-head ablation in section 11 measures what eight heads buy here. Check: the concatenation test, or the comparison with the fused kernel.

5. The feed-forward network: the same MLP at every position

Attention moves information between positions, but its output is a weighted average of value vectors followed by one linear map: little nonlinear computation happens inside it. The model also needs a place to transform what a position now holds (combine features, look up facts associated with them). That is the feed-forward network (FFN), also called the MLP: up from D to F = 4D, GELU (a smooth ReLU: x times the probability that a standard normal is below x; the file uses its tanh approximation, as GPT-2 did), and down from F to D, applied to each position independently. Because no position looks at another, one token alone gives the same answer as inside the sequence (8.9 × 10-8). The 4x width is the 2017 choice (dff = 2,048 for dmodel = 512 in Vaswani et al.) and nanoGPT's (nanoGPT model.py:82).

Two matrices or three: the weights of one FFN drawn to scale

SwiGLU. Most 2024 to 2026 models replace the two matrices with three: a gate Wg and an up matrix Wu both map D to F, the gate goes through SiLU (x · sigmoid(x)) and multiplies the up branch element by element, and Wd maps back down. Shazeer (2020, arXiv 2002.05202) kept parameters and compute equal by shrinking the hidden size: "To keep the number of parameters and the amount of computation constant, we reduce the number of hidden units dff ... by a factor of 2/3" (section 2; his base model goes from 3,072 to 2,048). Hence F = 8/3 D; Llama 3.1 8B uses 14,336 for D = 4,096, which is 3.5 D, wider than the equal-parameter rule. transformers writes the whole layer in one line, self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x)) (transformers modeling_llama.py:164). The file has it as a switch (Config(swiglu=True), F = 704, 3.1% more parameters than the GELU FFN); what activation functions do is Activation functions.

Shapes on the running sequence (steps.py): ffn.up(x) (1, 256, 1,024) = (B, T, F), 4 x wider; gelu(.) (1, 256, 1,024) = (B, T, F), elementwise: shape unchanged; ffn.down(.) (1, 256, 256) = (B, T, D), back to D.

Cost. 2 D F = 8D2 parameters, twice attention's 4D2: two thirds of every block's weights and of its FLOPs at short context. It is the part a mixture of experts multiplies (Mixture of experts); section 11 removes it. Check: the position-wise test; the parameter count 2 × 256 × 1,024 = 524,288.

6. The block: residual stream and pre-norm

Stacking attention and FFN layers twelve deep in plain sequence makes a deep network whose gradient must pass through every layer on the way back, and whose input signal is rewritten by every layer on the way up. He et al. (2016, arXiv 1512.03385) found deeper plain networks trained worse than shallower ones; the fix was the residual connection: each layer adds its output to its input instead of replacing it.

The vector each position carries from the embedding to the output is the residual stream. A block reads a normalised copy of it, runs attention on the copy and adds the result to the stream; then reads a normalised copy again, runs the FFN and adds that. The stream itself is never normalised in place: this is pre-norm, GPT-2's change to the 2017 layout ("Layer normalization ... was moved to the input of each sub-block ... and an additional layer normalization was added after the final self-attention block", Radford et al. 2019, section 2.3, GPT-2 paper). LayerNorm subtracts each vector's mean, divides by its standard deviation and multiplies by a learned gain (D numbers; this model has no bias, like most modern ones); RMSNorm skips the mean subtraction.

7. The whole model, the unembedding and the loss

Embed, run L blocks, apply a final LayerNorm, and multiply by the unembedding (the lm_head), a (V, D) matrix that gives each position one score per vocabulary entry: the logits, shape (B, T, V). With tied embeddings (Press and Wolf 2016, arXiv 1608.05859) the unembedding is the token table itself: the logit of token w is the dot product of the final vector with w's own embedding row, which saves V × D parameters (18% of this model). nanoGPT ties at nanoGPT model.py:138, transformers declares it with _tied_weights_keys (transformers modeling_llama.py:411). The file builds and initialises its modules in the same order as the root's tiny_gpt.py, so seed 0 gives the same 5,836,032 starting weights, and the root's trained checkpoint, with its parameter names mapped, gives the same logits to the last bit.

The targets are the inputs shifted by one

The first tokens of the running sequence. Position t's logits are scored against token t + 1, so a 257-token window gives 256 inputs and 256 targets; the last input has no target inside a 256-token sequence, hence (B, T − 1, V) below.

Shapes on the running sequence (steps.py): logits (1, 255, 4,096) = (B, T-1, V), predictions made at positions 0..254; targets = idx[:, 1:] (1, 255) = (B, T-1), the next token at each position.

The loss. Cross-entropy takes logits of shape (N, V) and targets of shape (N), so both are flattened over B and T first (nanoGPT nanoGPT model.py:187). Hugging Face models do the shift for you: labels = input_ids is correct there, because the loss pads and shifts at transformers loss/loss_utils.py:64; shifting yourself as well trains each position to predict the token after next.

What the first number says. An untrained model should be maximally unsure, so its loss should be close to ln V = 8.318; 8.360 is slightly above because random logits are not exactly flat (standard deviation 0.320). A starting loss far from ln V means a bug in the init or the loss (a missing scale on the logits, the wrong targets). It ends at 3.695, 0.08 above the bigram cross-entropy counted from all 122M training tokens (3.616); the network saw a tenth of them. Its greedy text shows it: one plausible phrase, then the same token repeated ("the park." and then only line breaks). A known answer the run lands on is a check on the whole pipeline. Everything the baseline gains below 3.62 comes from attention reading more than one token back.

No FFN: +0.43, but it is also a smaller model. Attention-only blocks have 2,688,768 parameters against 5,836,032; the run cannot separate "no MLP" from "54% fewer parameters" (a parameter-matched version with 18 attention-only layers was not run; it would cost about three times the attention compute per step). At 2.70 it is still far below the bigram floor, so attention alone does most of the context work; the FFN adds per-token computation on top.

No norm: trains, but worse and more sensitive. 2.546 at lr 3e-3 (+0.27); at lr 1e-3 it falls further behind (3.061 against 2.464 for the normalised baseline at the same rate, root Block lab): the unnormalised stream grows with depth and the update size that suits it is different. At 6 layers it does not diverge; the stability story at depth is Normalisation, residuals and stability.

No position: +0.10, much less than "word order is invisible" suggests. The causal mask leaks order: position t averages over exactly t + 1 tokens, so the model can count (Haviv et al. 2022, arXiv 2203.16634: "causal attention enables the model to infer the number of predecessors that each token can attend to"). It agrees with the Positional Encodings child's NoPE run of the root model (2.3666 on the same 20 windows; on 100 windows this run gives 2.3987 against its 2.389), which also shows what a learned table costs past 256 tokens.

One head: a small cost that depends on the seed. Eight heads of 32 against one head of 256, same parameters and FLOPs: +0.006 at seed 0, +0.063 at seed 1 (mean +0.035; the baseline's own spread is about 0.02). At this size and budget, eight heads buy a few hundredths of a nat; Michel et al. (2019, arXiv 1905.10650) found that "a large percentage of attention heads can be removed at test time without significantly impacting performance". One head did run about a third faster on MPS (55,029 against 40,711 tokens/s, rough), plausibly because fewer, larger kernels suit this GPU (not profiled). What does not transfer: at 4,096 wide a single head would have hd = 4,096 and one attention pattern per layer for everything; real models keep hd at 64 to 256.

What transfers from these toy ablations: the order (residual and attention are essential, the FFN and norm matter, positions and head count matter least at this size) and the known answers (unigram for a broken network, bigram for no attention). What does not: the size of the gaps for a model a thousand times larger trained a thousand times longer.

Loud: the error tells you

Cross-entropy on (B, T, V) logits. F.cross_entropy(logits, targets) with logits (1, 255, 4,096) and targets (1, 255) reads dimension 1 as the classes:

RuntimeError: Expected target size [1, 4096], got [1, 255]

Flatten first: F.cross_entropy(logits.view(-1, V), targets.view(-1)). If the shapes happen to line up (T = V), it runs and trains the wrong thing.

Merging heads with .view after .transpose.

RuntimeError: view size is not compatible with input tensor's size and stride (at least one dimension spans across two contiguous subspaces). Use .reshape(...) instead.

Use .reshape(B, T, D) or .contiguous().view(B, T, D) (nanoGPT nanoGPT model.py:72).

Using an nn.Linear weight as if it were (in, out).

RuntimeError: mat1 and mat2 shapes cannot be multiplied (4x256 and 1024x256)

nn.Linear(256, 1024).weight has shape (1,024, 256); the layer computes x WT. GPT-2's original checkpoints use a Conv1D that stores (in, out), which is why nanoGPT transposes four weight names when loading them.

Reading past the learned position table.

IndexError: index out of range in self

A 300-token input to a model with a 256-row position table. The message names neither positions nor lengths; nanoGPT crops the context to block_size before every generation step (nanoGPT model.py:314).

Temperature 0 by division.

RuntimeError: probability tensor contains either `inf`, `nan` or element < 0

Logits divided by 0 are plus and minus infinity; the softmax of that is NaN. Temperature 0 means greedy: take the argmax instead.

Leak: how far the output logits at position 150 move when only token 200 changes (0 for a causal model). Zeroing future weights after the softmax looks like masking, but the softmax's denominator already summed every future score, so earlier positions still depend on later tokens, and the rows no longer sum to 1.

Training on unshifted targets: the loss goes to zero and the model learns nothing useful. model(x, targets=x) asks every position for its own token, which it can read straight from its embedding. From scratch (batch 8 × 256, lr 1e-3, CPU), the training loss falls from 7.25 to 0.067 in 150 steps, faster than any real run; the held-out loss with correctly shifted targets is 13.36 nats, worse than a uniform guess (8.32), and the greedy continuation of prompt 7 is ".........................". Even the first loss is low (7.25 against 8.36 for real targets): with tied embeddings the output layer scores each position's own token with its own embedding, so the identity is favoured from the start. A loss that drops this fast is a bug, not a success.

The mirror image is shifting twice. Hugging Face's causal-LM loss shifts the labels itself (transformers loss/loss_utils.py:64); if you also shift them, each position is trained to predict the token after next. Scoring the trained tiny GPT that way gives 8.84 nats on the running sequence against 1.96: a different task, not a small error.

Counting tied parameters twice. sum(v.numel() for v in model.state_dict().values()) gives 6,884,608 for a 5,836,032-parameter model (section 7). Count model.parameters(), or, for a checkpoint, check whether lm_head.weight and the embedding hold the same data.

Interview rehearsal: nine questions with short answers

Write the shapes through one attention layer for a batch of B sequences of T tokens. x (B, T, D) → q, k, v (B, T, D) → view (B, T, H, hd) → transpose (B, H, T, hd) → scores q kT (B, H, T, T) → mask and softmax over the last axis → weights × v (B, H, T, hd) → transpose (B, T, H, hd) → reshape (B, T, D) → Wo (B, T, D). With GQA, k and v are (B, Hkv, T, hd) and each serves H / Hkv query heads.

Why divide the scores by √dhead, and what breaks without it? A dot product of hd unit-variance terms has variance hd; unscaled, the softmax saturates onto one key and its gradient vanishes. Measured: standard deviation 5.65 at hd = 32, the largest of 256 weights 0.62 on average unscaled against 0.04 scaled; removing it from the trained tiny GPT raises the running sequence's loss 1.96 to 2.88 (root Block lab).

Count the parameters of a GPT-2 style model in your head. 12 L D2 for the blocks plus V D for the tied embedding (plus positions). GPT-2 small: 12 × 12 × 7682 = 84.9M, plus 50,257 × 768 = 38.6M, plus 1,024 × 768 = 0.8M, about 124.3M; the exact count with biases and LayerNorm terms is 124,439,808.

How many FLOPs to train a 7B dense model on 2T tokens? About 6 N Dtokens = 6 × 7e9 × 2e12 = 8.4e22 FLOPs, plus the attention term (12 L D T per token: for 32 layers, D 4,096, T 4,096 that is 6.4 GFLOPs per token, 15% on top of 6N = 42 GFLOPs). With the attention term, about 9.7e22; at 40% of an H100 SXM's 989 TFLOP/s dense bf16 (NVIDIA's datasheet figure, vendor) that is about 2.4e8 GPU-seconds, roughly 68,000 GPU-hours (calculated); the hardware side is Performance math.

What does the residual connection buy, measured? Without it, this 6-block model at the same budget ends at 6.01, the unigram level (6.01): it learned token frequencies and nothing else. Each sublayer has to rebuild the whole representation instead of adding a correction, and gradients reach the embedding only through twelve stacked layers (Dong et al. 2021: without skip connections and MLPs, attention's output "converges doubly exponentially to a rank-1 matrix").

Why does a causal decoder still work without any position encoding? The mask itself tells a position how many predecessors it has, so order can be inferred (Haviv et al. 2022). Measured here: no positions 2.375 against 2.276 at an equal budget. Without the mask (an encoder), no positions means a bag of words.

Why tie the input and output embeddings, and why do large models stop? Tying saves V D parameters, a large share of a small model (18% here, 21% of SmolLM2-135M) and gives the rare tokens' output rows the gradient of their input use. In an 8B model the table is 6.5% of the weights and untying lets input and output spaces differ: Llama 3.1 8B, Qwen3-8B and Mistral 7B are untied, SmolLM2 and Qwen3-0.6B tied (configs).

Your training loss reaches 0.07 in 150 steps on a language model. What do you check first? The targets: they are probably the inputs, not the inputs shifted by one (measured above: 0.067 train, 13.4 held-out). Then the mask (a missing causal mask lets each position read its own next token; the Families and objectives page measured a leaky model at 0.21 held-out under the leak and 7.02 under the causal mask).

Design: a 125M-parameter decoder for a 4,096-token context on one 24 GB GPU. What do you choose and why? Start from the 2026 default rather than GPT-2: about 12 layers of D 768 (12 × 12 × 7682 = 85M in blocks) with a 32k to 50k tied vocabulary (25 to 38M); RoPE instead of a learned table (no hard length wall, extendable later); pre-norm RMSNorm with QK-norm for stability; SwiGLU at about 8/3 D; GQA with 4 KV heads to cut the cache 3x for serving. At 4,096 tokens the attention term is 12 L D T = 0.45 GFLOPs per token against 6N = 0.75: use FlashAttention or SDPA (never materialise (B, H, T, T)); bf16 weights and activations with fp32 master weights and AdamW states, 16 bytes a parameter, 2 GB, leave the rest to activations with checkpointing if needed. Then verify like this page: initial loss ln V, a falling curve past the unigram and bigram lines, and one ablation to make sure every component pulls its weight.

Shapes and counts: every weight and activation of ten real configs

The tool for every section of the Reading tab: pick a model and a context length, and read each stored weight of one layer with the shape the checkpoint stores, every activation through the layer, the parameter total against the Hugging Face count, the KV cache per token and the forward FLOPs of one token. The formulas are section 10's; the configs are the root's saved config.json files (read 2026-10-18), and every total matches the safetensors count after the stored non-parameters named in section 10, checked by src/zero/accounting.py. Predict first: in one layer of Llama 3.1 8B, is k_proj the same shape as q_proj, and which matrix is largest?

Shapes follow each checkpoint's convention: nn.Linear stores (out, in) and computes x WT; GPT-2 stores its linear layers as Conv1D with weights (in, out). With grouped-query attention, k_proj and v_proj have Hkv × hd outputs, not H × hd: using H here is the classic GQA mistake. Qwen3 adds per-head q and k RMSNorm gains (hd each); OLMo 2 normalises q and k over the full width and puts its norms after the sublayers. Forward FLOPs: 2 per weight touched (every block matrix and the output layer; the embedding lookup is free) plus 4 × L × T × H × hd for the query against T keys and the weights against T values. The scores row is why fused attention kernels never store the (T, T) matrices, and the logits row (B, T, V) is often the largest single activation in training, which is why some trainers compute the loss in chunks. KV cache per token here is one line of arithmetic; sizing at a context length, with every attention design, is the Long context page's KV-cache calculator.
