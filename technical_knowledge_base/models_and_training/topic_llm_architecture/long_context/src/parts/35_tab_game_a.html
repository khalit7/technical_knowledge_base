Six client briefs. Each one asks you to fit a model and its users' KV caches into GPU memory without giving up more quality than the client allows. The moves are this page's levers; each card prices itself live: the memory it saves (the {{calculator's|#t-kv}} arithmetic, so the numbers match it exactly) and the quality it costs, taken only from a published or measured number the knowledge base already cites, or marked "no published number". Score: quality points given up plus GPUs used; lower is better.

How the game counts, and where every quality number comes from
  • Memory. One user's cache is the calculator's KC.seq at the brief's context; weights are parameters × bytes per weight; usable memory is 92% of each GPU (vLLM's default), with weights and caches split evenly across GPUs as tensor parallelism would. Like the calculator, the game ignores activations, paged-block rounding and the copies a tensor-parallel engine makes of a cache with fewer KV heads than GPUs (MQA's single head, an MLA latent).
  • Two quality currencies, never mixed in a limit. MMLU points from DeepSeek-V2's ablations for the attention design; pass-key points (share of 30 prompts answered, in percentage points) from this page's SmolLM2-135M runs at 4,096 tokens for cache precision and eviction. The score adds them, as a game score only. Costs of two moves are added; no run measured them together.
  • No published number means none on these pages: the move is allowed, flagged in amber and counted as an unpriced risk beside the score, never as zero evidence.
  • Switching attention in a released model means retraining (the GQA paper uptrains with 5% of the original compute). In the levels that allow it you are choosing the design of the model you will train.
