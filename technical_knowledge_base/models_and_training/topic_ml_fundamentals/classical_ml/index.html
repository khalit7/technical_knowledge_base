Classical ML

In one screen

Classical ML is every method that learns from a table of features without a deep network: it fits a line, asks yes/no questions, finds a widest gap, looks at neighbours, or groups and compresses the data. On tables of numbers and categories these methods, and above all boosted trees, were the default for twenty years; since 2025 tabular foundation models have overtaken them on small and medium tables (section 4).

The comparison-level summary is on the parent page, Topic: ml-fundamentals (Reading tab, "Beyond one network", "Classical ML: still the default on tables"). This page owns the details: how each method decides, what it assumes, the evidence on when it wins, and the common mistakes. Every model below runs live in the page; the Boundary lab puts seven of them side by side.

1 · Linear models and naive Bayes

Linear regression predicts a numeric target as ŷ = wTx + b and is fitted by least squares, minimising the mean squared error; the closed form is w = (XTX)−1XTy, the maximum-likelihood fit under Gaussian noise (the losses and their noise models are on Loss functions). Polynomial regression is the same model on powers and products of the features: still linear in the weights. The regularised variants add a penalty: ridge (L2, λΣw2, shrinks every weight), lasso (L1, λΣ|w|, sets some weights exactly to zero) and elastic net (both); how and why they work, with the geometry, is on Regularisation.

Logistic regression is a linear model, a sigmoid and binary cross entropy: p(y = 1 | x) = σ(wTx + b), so the weights act additively on the log-odds and the decision boundary is a straight line (a hyperplane). Softmax regression (multinomial logistic regression) is the multiclass version: one weight vector per class and a softmax. scikit-learn's LogisticRegression is L2-penalised by default with C = 1, minimising ½||w||2 + CΣ log-loss (user guide), a default worth knowing when a "plain" logistic regression shrinks its weights. Try it on circles in the lab: no straight line separates a ring from its centre unless the features are transformed first.

Naive Bayes applies Bayes' rule with the assumption that features are independent given the class: p(y | x) ∝ p(y) ∏j p(xj | y). Each factor is estimated separately (word frequencies per class for text, a Gaussian per feature for numbers), so training is one counting pass. The assumption is almost never true, yet the classifier is a strong, cheap baseline for text: on short snippets it beat SVMs in Wang and Manning's comparison, and their NBSVM (an SVM on naive Bayes log-count ratios) was a strong text baseline for years (Wang and Manning 2012). The generative model reaches its best error with fewer examples, though a discriminative model such as logistic regression ends lower with enough data (Ng and Jordan 2002). Its probabilities are overconfident when features are correlated, because the same evidence is counted several times; recalibrate before using them (the calibration animation on Evaluation metrics does exactly this to a real naive Bayes model).

2 · Decision trees

A decision tree asks one yes/no question about one feature at a time ("is mean radius ≤ 0.43?") and predicts, in each leaf, the majority class or the mean target of the training points that reach it. It is grown greedily, CART style (Breiman, Friedman, Olshen and Stone 1984): at each node, try every feature and every threshold between two neighbouring distinct values (scikit-learn uses the midpoint), and keep the split that lowers the weighted impurity of the two children most.

Gini = 1 − Σk pk2   entropy = −Σk pk log2 pk   gain = I(parent) − (nL/n) I(left) − (nR/n) I(right)
pk
share of class k among the node's training points; for regression, I is the variance of the targets (squared error)

Greedy means one step ahead only: a split that is useless by itself but makes the next one perfect (XOR, in the lab) can be missed at depth 1. Unlimited, the tree keeps splitting until every leaf is pure, so it can fit any training set exactly; its predictions then change a lot when a few training points change (high variance). Depth, a minimum leaf size, or cost-complexity pruning hold it back.

Trees need no feature scaling (only the order of values matters), handle mixed feature types, and read as rules. Their boundaries are axis-aligned staircases, which is both a weakness (a diagonal boundary needs many steps) and, on tables, a strength: Grinsztajn et al. found that rotating a table's features hurts trees and helps nothing, because real tabular features carry meaning individually (section 4).

3 · Ensembles: bagging cuts variance, boosting cuts bias

Bagging (bootstrap aggregating) trains many models, each on a bootstrap sample of the rows (n draws with replacement, so each sample leaves out about 1 − (1 − 1/n)n ≈ 1/e ≈ 36.8% of the rows) and averages them (or takes a majority vote) (Breiman 1996). Averaging B models each with variance σ2 and pairwise correlation ρ leaves variance ρσ2 + (1 − ρ)σ2/B: more trees remove the second term, and only less correlated trees reduce the first (Hastie, Tibshirani and Friedman, ESL eq. 15.1). A random forest lowers ρ by letting each split consider only a random subset of the features (Breiman 2001; √p for classification is the usual choice; scikit-learn's regressor defaults to all features since version 1.1, which is plain bagging, docs). The rows each tree never saw give an out-of-bag error for free, a built-in validation estimate (the lab shows it). Forests are close to tuning-free: in a benchmark of six algorithms on 38 OpenML datasets, random forest (ranger) gained least from tuning, 0.006 AUC against 0.042 for SVMs (Probst, Boulesteix and Bischl 2019, Table 2).

Boosting builds the models in sequence, each correcting the ensemble so far. Gradient boosting (Friedman 2001) treats the ensemble's predictions F as the parameters and takes gradient descent steps in function space: each new tree fits the negative gradient of the loss with respect to F, which for squared error is exactly the residual y − F(x), and is added with a small learning rate ν (shrinkage). The trees are shallow (high bias, low variance each), so the sum drives bias down stage by stage; it also eventually fits the noise, so the number of stages is chosen by early stopping on held-out data. AdaBoost, the first practical booster, is the same idea with the exponential loss (Friedman, Hastie and Tibshirani 2000), which is why it suffers under label noise (Loss functions, "the margin").

XGBoost, LightGBM, CatBoost: what each added

XGBoost (Chen and Guestrin 2016) makes each step a second-order (Newton) step with a penalty on the tree: with gi and hi the first and second derivatives of the loss at the current prediction, and G, H their sums over a leaf,

obj ≈ Σi [gi f(xi) + ½ hi f(xi)2] + γT + ½λ Σ w2   w* = −G / (H + λ)
gain = ½ [GL2/(HL + λ) + GR2/(HR + λ) − (GL + GR)2/(HL + HR + λ)] − γ
T
number of leaves; γ charges each new leaf, λ shrinks leaf values (XGBoost defaults: λ = 1, γ = 0, learning rate 0.3, depth 6, parameters)
w*
the best value of a leaf; for log-loss, with λ = 0, it is Σ(y − p) / Σp(1 − p), the leaf update scikit-learn's gradient boosting classifier also uses, and the one this page's lab runs

The second derivative is why a loss needs a usable curvature here. The Huber loss has second derivative 0 beyond its threshold, so leaves full of large errors get H ≈ 0 and the step is set by λ alone; log-cosh and pseudo-Huber are smooth substitutes. Correction to the old pageIt said XGBoost prefers twice-differentiable losses "like log-cosh over Huber". The direction is right, but XGBoost ships its own answer: the objective reg:pseudohubererror, "a twice differentiable alternative to absolute loss", with huber_slope as its threshold, alongside reg:absoluteerror and reg:quantileerror, which use smooth approximations (XGBoost parameters, read 3 October 2026). Log-cosh is not a built-in objective. XGBoost also added column and row subsampling, a sparsity-aware split finder for missing values, and a weighted quantile sketch for approximate splits.

LightGBM (Ke et al. 2017) bins each feature into a histogram (255 bins by default) so a split search is over bins, not rows; grows trees leaf-wise (always split the leaf with the largest gain) instead of level by level; samples rows by gradient size (GOSS: keep the large-gradient rows, subsample the rest) and bundles mutually exclusive sparse features (EFB). It reported training up to over 20 times faster than conventional gradient boosting at the same accuracy. CatBoost (Prokhorenkova et al. 2018) encodes categorical features by ordered target statistics and uses ordered boosting: each row's gradient is computed by a model that has not seen that row, removing a target leak ("prediction shift") that plain boosting has; its trees are oblivious (the same split at every node of a level). Its defaults are strong: on TabArena the default CatBoost is the best untuned tree model (section 4).

4 · Do boosted trees still win on tables?

Until 2024 the answer was yes, with a caveat about size; on the dated evidence it is now "on large tables and on CPUs, yes; on small and medium ones, no".

5 · Support vector machines

A support vector machine (Cortes and Vapnik 1995) looks for the separating hyperplane with the widest margin: the band, of width 2/||w|| between the lines where the score wTx + b equals ±1, that it keeps clear of training points. Real data are rarely separable, so the soft margin lets points into the band at a price set by C:

min ½||w||2 + C Σi max(0, 1 − yi(wTxi + b))   yi ∈ {−1, +1}
max(0, 1 − m)
the hinge loss on the margin m = y·f(x): zero once a point is beyond its side's margin line; compared with logistic and exponential losses on Loss functions ("One axis for every classification loss: the margin")
C
the inverse of the L2 penalty's strength: small C, wide margin and many violations; large C, every violation expensive

The solution depends only on dot products between points, and only on the points on or inside the margin, the support vectors: in the dual problem every other point has weight αi = 0, and the score is f(x) = Σ αiyi K(xi, x) + b with 0 ≤ αi ≤ C. The kernel trick replaces the dot product with a kernel K, a dot product in a feature space that is never built: the RBF kernel exp(−γ||x − x′||2) corresponds to an infinite-dimensional one, and the polynomial kernel (xTx′ + c)d to all monomials up to degree d. γ sets how far one point's influence reaches; scikit-learn's default, "scale", is 1/(number of features × variance of X). The page's SVM is the same solver family as libsvm: sequential minimal optimisation, which changes two αs at a time, with libsvm's second-order rule for choosing the pair (Fan, Chen and Lin 2005).

The margin as C grows, without and with a kernel. 140 training points from two interleaved moons, 60 held out. Dashed lines are the margin (score ±1), the solid line the decision (score 0); ringed points are support vectors.

Defaults reproduce scikit-learn's SVC independently (recompute.py): linear kernel, C from 0.01 to 1: support vectors 110 → 54, margin width 3.12 → 1.29, training accuracy stuck at 81.4%; RBF kernel at C = 1: 55 support vectors, 93.6% training and 93.3% test accuracy. Decision values agree with libsvm to within 0.013 everywhere (both solvers stop at tolerance 10−3). Data: scikit-learn make_moons(200, noise = 0.25, random_state = 0), standardised.

Cost and limits. The scikit-learn guide puts libsvm's training cost "between O(nfeatures × nsamples2) and O(nfeatures × nsamples3)", while the linear solver in LinearSVC "can scale almost linearly to millions of samples" (SVM user guide). Correction to the old pageIt said SVMs scale poorly "past ~10^5 samples". For kernel SVMs the practical limit is lower: scikit-learn's SVC reference says the fit time "scales at least quadratically with the number of samples and may be impractical beyond tens of thousands of samples" (SVC). Linear SVMs have no such limit. SVM scores are not probabilities: the hinge loss is minimised by the sign of the true class probability and nothing more (Bartlett et al., on Loss functions), so scikit-learn's probability=True fits Platt scaling, "logistic regression on the SVM's scores, fit by an additional cross-validation on the training data", which is expensive and can disagree with the decision function (user guide, after Platt 1999). They remain strong on small and medium data with many features (Probst et al. found them the most tuning-sensitive of six algorithms, so they need the search of section 10).

6 · Nearest neighbours

k nearest neighbours has no training step: it stores the training set and, for a query, returns the majority class (or the mean target) of the k closest points. k and the distance are its hyperparameters: k = 1 reproduces every training label (zero training error, a jagged boundary), a large k smooths towards the overall majority; try both in the lab. Because everything rests on distances, feature scaling is mandatory: a feature measured in thousands swamps one measured in fractions (the same reason PCA needs standardising, section 9). A naive query compares against all n stored points, O(nd) per query; tree indexes help in a few dimensions and approximate nearest-neighbour indexes such as HNSW (Malkov and Yashunin 2016) in many. The same machinery, on learned embeddings, is vector retrieval (Topic: rag-and-retrieval).

In high dimensions, distances stop discriminating. Under broad conditions the ratio of the nearest to the farthest distance from a query tends to 1 as dimension grows (Beyer et al. 1999), so "nearest" stops meaning "similar". That is the curse of dimensionality for kNN; it bites least where the data lie near a low-dimensional surface, which is why kNN works on good embeddings.

8 · Anomaly detection

Anomalies are rare, so this is usually unsupervised: model what normal looks like and flag what does not fit. Isolation forest (Liu, Ting and Zhou 2008) builds random trees that split on a random feature at a random value; an anomaly, being few and different, is isolated in few splits. The score is s = 2−E[h(x)]/c(n), where h is the path length to isolate x and c(n) = 2H(n − 1) − 2(n − 1)/n the average path length of an unsuccessful search in a binary search tree (H the harmonic number): s near 1 is anomalous, well below 0.5 normal. It needs no distances, so it scales to large, high-dimensional data. A one-class SVM (Schölkopf et al. 2001) separates the data from the origin in kernel space with a fraction ν of outliers allowed; density and reconstruction thresholds flag points with low likelihood under a fitted density (a Gaussian mixture, section 7) or with a large reconstruction error from PCA or an autoencoder (section 9); the local outlier factor compares a point's local density with its neighbours' (Breunig et al. 2000).

Evaluate with precision and recall, not accuracy or ROC alone: with 1 anomaly in 1,000, "nothing is anomalous" is 99.9% accurate, and a small false positive rate still swamps the true alarms. The threshold lab on Evaluation metrics shows this on real scores with rare positives.

9 · Fewer dimensions: PCA, t-SNE, UMAP

PCA finds the orthogonal directions of greatest variance: the eigenvectors of the covariance matrix, ordered by eigenvalue, equivalently the right singular vectors of the centred data matrix (scikit-learn computes it by SVD). Projecting on the first m keeps the most variance any m-dimensional linear projection can, and the eigenvalue shares are the "explained variance". It is linear, and it is not scale-invariant: on raw data the feature with the largest numbers wins.

The same 178 wines, raw and standardised. 13 chemical measurements of wines from three cultivars (colours). Left: share of variance per component, with the cumulative line; right: every wine projected on the first two components (each axis scaled to unit spread for display).

Defaults reproduce scikit-learn's PCA independently: raw, PC1 explains 99.81%, almost all of it proline (variance 98,610 against 203 for magnesium and under 12 for the other eleven); standardised, PC1 36.2% and PC2 19.2%, and the three cultivars separate. Explained-variance ratios agree to 10−15 (src/check). Data: UCI Wine via scikit-learn's load_wine.

t-SNE (van der Maaten and Hinton 2008) and UMAP (McInnes, Healy and Melville 2018) are nonlinear embeddings for pictures: they keep each point's neighbours close and give up on everything else. In their plots, cluster sizes and the distances between clusters mean little, and a perplexity or neighbour count changes the picture (Wattenberg, Viégas and Johnson 2016, with live examples). Use them to look, never as features for a model or as evidence of cluster structure on their own. Autoencoders are the nonlinear, learned version of PCA: a network squeezed through a narrow layer and trained to reconstruct its input (a linear autoencoder with squared error learns the same subspace as PCA).

Correction to the old page
It said UMAP "is faster and preserves more global structure". Faster, usually, yes. But the better global structure was traced to initialisation: UMAP starts from a spectral embedding and t-SNE implementations from a random one; with the same informative initialisation, t-SNE preserves global structure as well as UMAP, and UMAP from a random start loses it (Kobak and Linderman 2021, "Initialization is critical for preserving global data structure in both t-SNE and UMAP").

MethodIdeaWhen
Grid searchevery combination of a few values per hyperparameterone or two hyperparameters, cheap models
Random searchsample configurations at random from the rangesusually beats grid at equal budget, because the few hyperparameters that matter get many distinct values instead of few (Bergstra and Bengio 2012)
Bayesian optimisationfit a surrogate of score against configuration (a Gaussian process, Snoek, Larochelle and Adams 2012, or a tree-structured Parzen estimator, Bergstra et al. 2011) and choose the next trial by expected improvementexpensive trials; Optuna (Akiba et al. 2019) and Hyperopt default to TPE

Bergstra and Bengio's argument is geometric. With 9 trials on a 3 × 3 grid, each hyperparameter gets only 3 distinct values; 9 random trials give 9 of each. When only some hyperparameters matter, which they found to be the usual case, a grid wastes most trials on the ones that do not. Random search also has a budget rule that needs no knowledge of the surface: with n independent trials, the chance that at least one lands in the best 5% of the space is 1 − 0.95n, which passes 95% at n = 60 (1 − 0.9560 = 0.954) derived.

Real searches would not see the surface in advance; here it is precomputed so every method reads the same numbers.

What the surface shows, honestly. Here both hyperparameters matter about equally (each explains about 35% of the variance of accuracy across the box, recompute.py), so Bergstra and Bengio's low-effective-dimension case does not hold, and a 2-D grid is not reliably worse: a 4 × 4 grid happens to land on 99.00%, a 5 × 5 grid only on 98.83%, which is luck of alignment. Add hyperparameters that do nothing (a cache size, a tolerance far below the noise) and the grid collapses: 27 trials on a 3 × 3 × 3 grid test only 9 distinct (C, gamma) pairs and reach 98.39%, while random search with the same 27 trials always gets 27 distinct pairs. Bayesian optimisation reaches the ridge in fewer trials on median, but every method ends within the cross-validation noise of the best cell. Searching harder than that noise only fits the validation folds (Cawley and Talbot 2010): report a held-out score, or nest the search inside an outer cross-validation.

Common mistakes

Scaling, imputing or selecting features on the whole dataset before splitting
The test fold then leaks into training statistics. Fit every preprocessing step inside the cross-validation loop (a scikit-learn Pipeline does this). Trees need no scaling; kNN, SVMs, k-means, PCA and penalised linear models do.
Reading SVM scores, naive Bayes or boosted-tree outputs as calibrated probabilities
SVM scores carry only the decision; naive Bayes double-counts correlated evidence; boosted trees drift with the number of stages. Calibrate on held-out data (Platt or isotonic) when the probability is used.
Growing boosted trees without early stopping, or a single tree without a depth limit
Both memorise: in the motorcycle animation boosting's held-out error rises after about 20 stages, and the unlimited tree on tumours falls from 89.5% to 86.0% on test. A forest is the exception: more trees never hurt it.
Running k-means once, or on unscaled features, or on non-round clusters
Use several restarts with k-means++ (scikit-learn's n_init), standardise first, and switch to DBSCAN or a Gaussian mixture when clusters are elongated, nested or of different densities.
Reading clusters, distances or sizes off a t-SNE or UMAP plot
Neither preserves them; check any structure you see with a method that does (distances in the original space, a clustering run on the data itself).
Tuning on the test set, or reporting the best cross-validation score as the final estimate
The best of many noisy scores is biased upwards. Keep a test set out of the search, or nest the search in an outer cross-validation.
Assuming "boosted trees always win on tables" (or the opposite) from a single benchmark
The answer depends on table size, the split (random, temporal, grouped), the tuning budget and the hardware; check the matching subset of a maintained benchmark, with its date (section 4).
