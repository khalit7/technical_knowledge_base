Activation functions

The nonlinearity between two linear maps: the saturating classics (sigmoid, tanh), the ReLU family and its dead units, the smooth ReLUs (GELU, SiLU, Mish), the gated units that every current LLM uses (GLU, ReGLU, GEGLU, SwiGLU) with the 2/3 width rule, the output layer, and what these functions actually do inside three released models. In one screen

An activation function is the elementwise nonlinearity between two linear maps. It decides three things: whether the gradient survives many layers (saturation), whether units can switch off for good (dead units), and, at the output, what the numbers mean (probabilities, or a value). In 2026 the answer for hidden layers of a language model is a gated unit, almost always SwiGLU; GELU survives in vision transformers and older encoders; the ReLU family in convolutional networks and a few efficiency-minded LLMs; sigmoid and tanh only inside gates and at outputs.

This page owns the details. The parent topic places the activation in one training step and has three live pieces this page links rather than repeats: "one batch through five networks" (sigmoid with Xavier, ReLU with 1/n, ReLU with He, BatchNorm residual, pre-RMSNorm SwiGLU, with the variance and the gradient of every layer) in step 2 of the Reading tab of Topic: ml-fundamentals; the Training lab tab, which trains the same network with six activations swapped live; and the Defaults across models tab, which lists the activation and FFN width of twenty-one models from AlexNet to Kimi K2, each with its source.

Why a nonlinearity, and what it must be

  • Non-linear, or the stack collapses: W2(W1x) = (W2W1)x, one linear map however many layers there are.
  • Not a polynomial, which is the precise condition for a one-hidden-layer network to approximate any continuous function: "a standard multilayer feedforward network with a locally bounded piecewise continuous activation function can approximate any continuous function to any degree of accuracy if and only if the network's activation function is not a polynomial" (Leshno, Lin, Pinkus and Schocken 1993). x2 alone would not do; squared ReLU, max(0, x)2, is piecewise and is not a polynomial, so it qualifies.
  • Differentiable almost everywhere is enough for gradient descent: ReLU has no derivative at exactly 0 and frameworks simply pick one (PyTorch's autograd uses 0 there; this page's derivatives agree with autograd everywhere else, src/recompute.py).

Everything else is a trade between four properties: slope near 1 over a wide range (gradients survive depth), outputs centred on zero (updates do not zig-zag), cheap to compute, and smooth (the optimiser sees a smooth surface). No function has all four; the history below is the field trading one for another.

Sigmoid and tanh: saturation

ActivationFormulaRangeLargest slopeGood atTrouble
Sigmoid σ1 / (1 + e−x)(0, 1)0.25, at x = 0an output read as a probability; a gate that opens between 0 and 1saturates on both sides; outputs always positive, not zero-centred
Tanhtanh x = 2σ(2x) − 1(−1, 1)1, at x = 0zero-centred: outputs, and so the next layer's updates, can have either signstill saturates: slope below 0.01 once |x| > 3.0 derived

Saturation. Backpropagation multiplies the gradient by the activation's slope at every layer. A sigmoid's slope is at most 0.25, so even at its best a gradient shrinks by 4 per layer, and in a saturated unit (|x| large) the slope is close to 0: the slope of the sigmoid is below 0.01 once |x| > 4.6 derived from σ(1 − σ) = 0.01. On the parent's "one batch through five networks", the first layer of the 16-layer sigmoid network receives a gradient about 2 billion times smaller than the last (step 2 of the Reading tab of Topic: ml-fundamentals). Tanh is a rescaled sigmoid (the identity above), with four times the slope at 0, which is why it was preferred for hidden layers before ReLU.

Why zero-centred matters. A unit's weight gradient is its input times one shared error term. If every input is positive (a sigmoid layer's output always is), every weight of that unit moves in the same direction at each step, so reaching a target that needs some weights up and others down takes a zig-zag. LeCun et al. recommend inputs with mean close to zero for this reason, and a scaled tanh, 1.7159 tanh(2x/3), for hidden units (Efficient BackProp, 1998, sections 4.3 and 4.4).

Where they still live. Inside gates, where a value between 0 and 1 is the point: the LSTM's forget, input and output gates are sigmoids and its cell candidate a tanh (Sequence models: the pre-transformer lineage); the gated units below are this idea moved into the feed-forward block. And at the output, for a binary or multilabel probability.

The ReLU family

ReLU, max(0, x), has slope exactly 1 for every positive input, so the gradient passes through any number of active layers unshrunk, and it costs one comparison. It entered deep learning through restricted Boltzmann machines (Nair and Hinton 2010) and deep supervised networks (Glorot, Bordes and Bengio 2011, who stressed that it makes representations sparse: many units output exactly 0). AlexNet made it the default: a four-layer convolutional network with ReLUs reached 25% training error on CIFAR-10 six times faster than the same network with tanh (Krizhevsky, Sutskever and Hinton 2012, section 3.1). Its variants each patch one weakness:

Dead units, measured

A ReLU unit whose input is negative for every example outputs 0 everywhere and receives zero gradient, so nothing in backpropagation pushes it back: it is dead. A high learning rate or a large negative bias can kill many at once. The usual statement is that a dead unit "never recovers". That is exact only for a unit whose inputs cannot change (the first layer, fed fixed data); a dead unit deeper in the network can come back when the layers below it change, as the measured run below shows.

A leaky unit with negative input on every image is counted the same way, though it still passes 1% of the gradient.

Across five seeds and ten learning rates (the chart below, from the same script): up to a rate of 0.04 no ReLU unit dies; at 0.05 and 0.06 a handful die and the network still reaches 96 to 98% held-out accuracy; from 0.07 most runs lose a whole layer, after which every image produces the same output, the loss sits at ln 10 = 2.303 and accuracy at chance. With leaky ReLU nothing can go fully silent, so the same rates do not end in a dead network; they end in a loss that overflows to "not a number". The learning rate is the cause in both; the activation decides only whether the failure is silent or loud.

What to do about dead units
  • Check for them: count, over a batch or a held-out set, the units whose output is 0 on every example (the parent's When training goes wrong tab runs a network whose biases start at −3, so most ReLUs are off from the start, and shows the plateau that follows).
  • Lower the learning rate, warm it up, clip gradients: the runs above die only above a threshold rate.
  • Initialise for the activation (He for the ReLU family) and keep biases at 0, not negative.
  • Normalise before the activation, which keeps pre-activations centred, or switch to a variant with a negative side (leaky, ELU, GELU, SiLU). Neither removes the cause if the rate is too high.

In a released model. Dead units are not only a training accident. In OPT, whose feed-forward blocks use ReLU, "many neurons (more than 70% in some layers of the 66b model) are 'dead', i.e. they never activate on a large collection of diverse data", all of them in the first half of the network (Voita, Ferrando and Nalmpantis 2023). GELU's idea. Multiply the input by a random mask m ~ Bernoulli(Φ(x)): kept with a probability that grows with x. Its expected value is x Φ(x), so GELU is a deterministic version of a stochastic regulariser that blends ReLU (a mask of 0 or 1 set by the sign), dropout (a random 0) and zoneout (a random 1) (GELU paper, section 2). Unlike ReLU it is smooth, not monotone (a small dip below 0), and lets small negative inputs pass a small gradient.

Several GELUs. The paper gives two cheaper forms, and trained models use all three; a checkpoint must be run with the form it was trained with:

Correction: SiLU is not "nearly identical" to GELU, and was not found by the search

The old version of this page said SiLU has a "nearly identical curve to GELU" and was "found by architecture search". The curves differ by up to 0.193 derived, max |SiLU − GELU| on [−6, 6], and SiLU's dip is 64% deeper (−0.278 against −0.170). The near-identity is GELU against x σ(1.702x): SiLU is that curve stretched 1.702 times along x (and rescaled). As for the search: x σ(x) was already in the GELU paper (as SiLU) and in Elfwing et al.; Ramachandran et al.'s automated search found the family x σ(βx), which they named Swish, and their paper says that with β = 1 "Swish is equivalent to the Sigmoid-weighted Linear Unit (SiL) of Elfwing et al." Their result is that replacing ReLU with Swish raised ImageNet top-1 accuracy by 0.9% for Mobile NASNet-A and 0.6% for Inception-ResNet-v2. Overlay the curves in the Activation atlas.

Why the smooth ones win in transformers is not settled. The papers report empirical gains (GELU over ReLU and ELU on their benchmarks, Swish over ReLU on ImageNet and translation); the old page's "self-scaling" has no source beyond the Bernoulli motivation above. In Shazeer's controlled comparison (next section), GELU and Swish alone barely beat ReLU in pre-training perplexity (1.983 and 1.994 against 1.997 at 65,536 steps, with run-to-run spreads of 0.003 to 0.005) and were behind it at the end of training (1.679 and 1.683 against 1.677): the gain that stuck came from gating.

Gated units: GLU, ReGLU, GEGLU, SwiGLU

A gated linear unit computes two projections of the same input and multiplies them elementwise, one passed through a nonlinearity (Dauphin et al. 2016, for gated convolutional language models). What the gate does to the gradient. With g = xW and u = xV, the hidden unit is h = SiLU(g) u, so ∂h/∂u = SiLU(g): the slope of the linear path is not a fixed function of its own input but is set, token by token, by a second projection of the same input. That is the old page's "learned adaptive slope", and the only mechanism the formula itself shows. Its other claims for gated units ("very expressive, stable training, balanced mean/variance") are unconfirmed: the paper that introduced them offers none, and says so: "We offer no explanation as to why these architectures seem to work; we attribute their success, as all else, to divine benevolence."

Every gated variant beat every ungated one in pre-training perplexity, at both lengths derived from Table 1.

PaLM adopted SwiGLU on this evidence: "they have been shown to significantly increase quality compared to standard ReLU, GeLU, or Swish activations (Shazeer, 2020). Note that this does require three matrix multiplications in the MLP rather than two" (Chowdhery et al. 2022, section 2). Llama followed: "We replace the ReLU non-linearity by the SwiGLU activation function ... We use a dimension of 2/3 4d instead of 4d as in PaLM" (Touvron et al. 2023, section 2.2), and so did nearly every open model since; the parent's Defaults across models tab shows the switch year by year. A later line of work goes the other way for inference speed: replacing SiLU and GELU with ReLU in a pre-trained Llama or Falcon and fine-tuning briefly brings back exact zeros that a server can skip (Mirzadeh et al. 2023, "ReLU Strikes Back").

The 2/3 rule, and who follows it

A plain feed-forward block with hidden width 4d has two matrices: 2 · d · 4d = 8d2 parameters, and as many multiply-adds per token. A gated block has three: 3dh. Matching them gives h = 8d/3 = ⅔ · 4d. Shazeer did exactly this: "we reduce the hidden layer to dff = 2048" from 3,072 at d = 768 (2 × 768 × 3,072 = 3 × 768 × 2,048 = 4,718,592). Llama's code applies the same rule, then an optional multiplier, then rounds up to a hardware-friendly multiple:

h = m · ⌈ int(f · int(2 · 4d / 3)) / m ⌉

The output layer

The last layer's activation is chosen by what the output has to be, and it must agree with the loss (the loss for each is on Loss functions). In PyTorch the loss usually applies the output activation itself, so the network should end with the raw scores (logits):

Softmax, in four facts. (1) Adding a constant to every logit changes nothing, softmax(z + c) = softmax(z), which is why every implementation subtracts the largest logit before exponentiating (without it, e1000 overflows). (2) With two classes it is the sigmoid: softmax([x, 0])1 = σ(x) checked to 10−15, so a binary sigmoid output is a two-class softmax with one logit fixed at 0. (3) Its derivative, ∂pi/∂zj = pi(δij − pj), goes to zero as one probability approaches 1: a softmax saturates like a sigmoid, which is why it is paired with a log in the loss (cross entropy's gradient on the logits is simply p − y). (4) A temperature T, softmax(z/T), sharpens (T < 1) or flattens (T > 1) the distribution without changing the order; try it on a real model's logits in the Sampler lab of Sampling and Decoding. Softmax also normalises attention scores (Attention Is All You Need) and mixture-of-experts router scores.

Correction: with a large vocabulary, the cost is the projection, not the softmax

The old page called softmax "expensive for very large K". The exponentials are cheap; what grows with the vocabulary V is the output projection that produces the logits: d · V multiply-adds per token against V exponentials. For Qwen2.5-0.5B (d = 896, V = 151,936, config.json) that is 136 million multiply-adds against 152 thousand exponentials, 896 times more derived; and in training the logits themselves take memory: a batch of 8 sequences of 4,096 tokens holds 8 × 4,096 × 151,936 = 5.0 billion logits, 19.9 GB in 32-bit floats derived. Sampled and hierarchical softmaxes, and fused or chunked cross-entropy kernels, target these two costs.

Common mistakes

Applying softmax (or sigmoid) before a loss that applies it again
CrossEntropyLoss expects "the unnormalized logits for each class" (PyTorch docs); a softmax in front of it squashes the scores twice, so training still runs but the gradients are wrong and confidence is capped. End the network with logits and put the softmax only where probabilities are read.
Sigmoid followed by BCELoss instead of BCEWithLogitsLoss
The combined loss "is more numerically stable than using a plain Sigmoid followed by a BCELoss as, by combining the operations into one layer, we take advantage of the log-sum-exp trick for numerical stability" (PyTorch docs). A saturated sigmoid rounds to exactly 0 or 1, and the log of that is infinite.
A ReLU or sigmoid on a regression output
A ReLU output can never predict a negative value and receives no gradient when it outputs 0; a sigmoid caps it at 1. Regression outputs are linear unless the target's range is known (then softplus for positive values, tanh for a bounded range).
Running a checkpoint with a different GELU
GPT-2 runs with the tanh form, CLIP with x σ(1.702x), BERT's Hugging Face configs with the exact form. The tanh form is within 4.7 × 10−4 of exact; the sigmoid form is off by up to 0.020 per unit, which compounds over layers. Use the activation string in the model's config (gelu, gelu_new, gelu_pytorch_tanh, quick_gelu).
Treating SiLU and GELU as the same function
They differ by up to 0.19 (above). Swapping one for the other in a trained model changes its outputs; in a model trained from scratch either works.
Counting a SwiGLU block as two matrices
It has three, so its parameters are 3dh. A width quoted as "4d" means a block 1.5 times the size of a plain 4d one (PaLM, Gemma 3); "2.69d" means the matched size (the 2/3 rule).
An initialisation that does not match the activation
Xavier was derived for sigmoid and tanh, He for the ReLU family, LeCun's 1/n for SELU; the wrong one shrinks or grows the signal at every layer. The parent's thread 2 ("keep the variance constant", in the Reading tab of Topic: ml-fundamentals) shows each mismatch, and the Activation atlas table gives the variance-preserving gain of every function here; the details are on Normalisation and initialisation.
Expecting exact zeros from a SwiGLU model
SiLU is never exactly 0 for a nonzero input, so a SwiGLU block has small values, not zeros; tricks that skip zero rows (built for ReLU models such as OPT) need a threshold or a ReLU fine-tune first (Mirzadeh et al. 2023). See the Inside real models tab.
Blaming the activation for a learning rate that is too high
In the runs above, ReLU networks die and leaky ReLU networks overflow at the same learning rates. Swapping the activation changes the symptom; lowering or warming up the rate removes the cause. The parent's When training goes wrong tab goes from symptom to cause.

On a standard normal input

What one layer of each function does to an input drawn from N(0, 1), the situation initialisation tries to create. The variance-preserving gain is 1/√E[f(z)2]: the factor by which to scale weights of variance 1/n so that the next layer's pre-activations keep variance 1. E[f′(z)2] is the matching factor for the gradient on the way back. PyTorch's calculate_gain is shown beside it.

Computed in your browser by Simpson's rule on [−12, 0] and [0, 12], and checked against SciPy's adaptive quadrature to 10−9. Reproduces independently: ReLU's gain √2 (He et al.'s factor 2) and leaky ReLU's √(2/(1 + α2)), exactly PyTorch's formulas; SELU's mean 0 and second moment 1 (Klambauer et al.'s fixed point). Does not reproduce, by design: PyTorch's tanh gain is 5/3, a heuristic, against 1.59 here; its sigmoid gain is 1 against 1.85; its SELU gain is 3/4, which its documentation says "sacrifices the normalization effect for more stable gradient flow in rectangular layers" and tells SELU users to pass nonlinearity='linear' (gain 1) instead (torch.nn.init). A gain only fixes the second moment at initialisation; the parent's thread 2 shows what happens over 16 layers, and Normalisation and initialisation owns the schemes.

Inside real models

What the activation actually outputs in three released models, measured on every feed-forward hidden unit, every layer and every token of the same text: OPT-125m (ReLU), GPT-2 small (GELU, tanh form) and SmolLM2-135M (SwiGLU).

Try: pick a model and a measure. Move the threshold that counts a value as "near zero", or the activity below which a unit counts as dead, and watch which layers respond. Tap a layer's bar to see how often each of its units is on.

How it was measured

  • Text: WikiText-2 (raw), test split, the whole of it: 283,287 tokens for OPT and GPT-2 (they share a tokenizer), 301,948 for SmolLM2 (Salesforce/wikitext), in chunks of 511 tokens after the model's start token, which is left out of every count.
  • What is recorded: the input of the down projection, captured with a forward hook: ReLU(xW1 + b1) for OPT, GELU(xW1 + b1) for GPT-2, SiLU(xWgate) ⊙ xWup for SmolLM2; in float32 on CPU with PyTorch 2.14 and Transformers.
  • Near zero compares each value with the root mean square of its own token's hidden vector, so that one threshold means the same in every layer and model; exact zeros count as near zero. Values are binned in fifths of a decade from 10−5, and the page interpolates within a bin.
  • On means: OPT, output above 0; GPT-2, pre-activation above 0 (where GELU is close to the identity); SmolLM2, gate pre-activation above 0 (where SiLU passes most of u). A unit that is never on in GPT-2 or SmolLM2 still outputs small values and still receives a small gradient; in OPT it outputs exactly 0 and receives none.
  • Caveats: one text from one domain; Voita et al. used over 20 million tokens from many domains and up to 66 billion parameters, so a unit that is never on here may fire on other text. Script: src/real_models.py; results in src/inputs/real_models.json.

What it checks. Voita et al.: dead neurons concentrated in the first half of OPT, the second half "fully alive" (2023): reproduced on OPT-125m qualitatively (their per-layer values are only plotted, not printed, and are not read off the figure).
