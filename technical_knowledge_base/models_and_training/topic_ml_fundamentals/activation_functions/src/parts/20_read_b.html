Dead units, measured

A ReLU unit whose input is negative for every example outputs 0 everywhere and receives zero gradient, so nothing in backpropagation pushes it back: it is dead. A high learning rate or a large negative bias can kill many at once. The usual statement is that a dead unit "never recovers". That is exact only for a unit whose inputs cannot change (the first layer, fed fixed data); a dead unit deeper in the network can come back when the layers below it change, as the measured run below shows.

Predict, then watch: will dead units come back once they die? A real network, trained offline: a 64-128-128-128-10 network on 1,797 handwritten digits, He initialisation, SGD with momentum 0.9, 30 epochs. In Fig. 2 each column is one of the 384 hidden units, as tall as the share of the 1,797 images on which it is on; a flat red tile is dead (off on every image). Dots carry the signal from layer to layer, as dense as the share of live units in the layer they leave. Switch runs: the same network at learning rate 0.04, at 0.08, and at 0.08 with leaky ReLU.

  1. Before training. He initialisation and zero biases: every unit is on for roughly half of the images, and held-out accuracy is 9.2%, chance.
  2. Epochs 1 to 3: it learns. The training loss falls from 0.782 to 0.147 and held-out accuracy reaches 96.4%. No unit dies.
  3. Epochs 4 to 30: nothing dies at this rate. The loss keeps falling, to 0.0001; still 0 dead of 384, and 96.9% of the held-out digits right.
  1. Before training. The same start: every unit on for about half the images, accuracy 9.2%.
  2. Epochs 1 and 2: the first deaths. Twice the rate, and units start going dark in layers 2 and 3: 2, then 8 dead, while accuracy still climbs to 94.2%.
  3. Epochs 3 to 5: large steps kill dozens. The loss jumps back up to 1.121 and the dead count grows to 69: 41 in layer 2, 28 in layer 3.
  4. Epoch 6: dead units come back. Layer 3 drops from 28 dead to 5: a unit in layer 2 or 3 is dead only for the inputs it currently receives, and those change when the layers below learn. Accuracy 90.3%.
  5. Epochs 7 and 8: a whole layer goes dark. Layer 3 loses 72, then all 128 units. The output layer now sees zeros for every image, so it gives the same answer for all: accuracy 8.6%.
  6. Epochs 9 to 30: nothing can undo it. With layer 3 silent, no gradient reaches anything below it. The loss sits at about 2.308, ln 10 = 2.303, for 22 epochs; it ends with 203 dead and 8.9% accuracy.
  1. Before training. The same start, with leaky ReLU (slope 0.01 below zero) in every hidden unit.
  2. Epochs 1 to 4: units go negative, not silent. The same rhythm as the ReLU run: 25 units have a negative input on every image by epoch 4, but each still passes 1% of its gradient. Accuracy 88.1%.
  3. Epoch 5: the loss explodes. One large update sends the training loss to 52,940 and accuracy to 12.2%; 108 units are negative on every image.
  4. Epoch 6: overflow. The logits reach infinity and every number in the network becomes not-a-number (NaN): the same instability that silenced the ReLU network, loud instead of silent.

Measured with src/dead_relu_toy.py (PyTorch 2.14, CPU, seed 0 for these three runs). Data: scikit-learn's digits (UCI), pixels standardised, 1,437 images to train on and 360 held out; "dead" is judged on all 1,797. A leaky unit with negative input on every image is counted the same way (a red tile), though it still passes 1% of the gradient.

Across five seeds and ten learning rates (the chart, from the same script): up to a rate of 0.04 no ReLU unit dies; at 0.05 and 0.06 a handful die and the network still reaches 96 to 98% held-out accuracy; from 0.07 most runs lose a whole layer, after which every image produces the same output, the loss sits at ln 10 = 2.303 and accuracy at chance. With leaky ReLU nothing can go fully silent, so the same rates do not end in a dead network; they end in a loss that overflows to "not a number". The learning rate is the cause in both; the activation decides only whether the failure is silent or loud.

What to do about dead units
  • Check for them: count, over a batch or a held-out set, the units whose output is 0 on every example (the parent's {{When training goes wrong|n:3c65c17b0d0d81d796ccc0a293218c57}} tab runs a network whose biases start at −3, so most ReLUs are off from the start, and shows the plateau that follows).
  • Lower the learning rate, warm it up, clip gradients: the runs above die only above a threshold rate.
  • Initialise for the activation (He for the ReLU family) and keep biases at 0, not negative.
  • Normalise before the activation, which keeps pre-activations centred, or switch to a variant with a negative side (leaky, ELU, GELU, SiLU). Neither removes the cause if the rate is too high.

In a released model. Dead units are not only a training accident. In OPT, whose feed-forward blocks use ReLU, "many neurons (more than 70% in some layers of the 66b model) are 'dead', i.e. they never activate on a large collection of diverse data", all of them in the first half of the network (Voita, Ferrando and Nalmpantis 2023).
