The ReLU family

ReLU, max(0, x), has slope exactly 1 for every positive input, so the gradient passes through any number of active layers unshrunk, and it costs one comparison. It entered deep learning through restricted Boltzmann machines (Nair and Hinton 2010) and deep supervised networks (Glorot, Bordes and Bengio 2011, who stressed that it makes representations sparse: many units output exactly 0). AlexNet made it the default: a four-layer convolutional network with ReLUs reached 25% training error on CIFAR-10 six times faster than the same network with tanh (Krizhevsky, Sutskever and Hinton 2012, section 3.1). Its variants each patch one weakness:

Dead units, measured

A ReLU unit whose input is negative for every example outputs 0 everywhere and receives zero gradient, so nothing in backpropagation pushes it back: it is dead. A high learning rate or a large negative bias can kill many at once. The usual statement is that a dead unit "never recovers". That is exact only for a unit whose inputs cannot change (the first layer, fed fixed data); a dead unit deeper in the network can come back when the layers below it change, as the measured run below shows.

Try: a real network, trained offline: a 64-128-128-128-10 network on 1,797 handwritten digits, He initialisation, SGD with momentum 0.9, 30 epochs. Each square is one of the 384 hidden units; its shade is the share of the 1,797 images on which it is on, and a red square is dead (off on every image). Press play to run the epochs, then switch runs: the same network at learning rate 0.04, at 0.08, and at 0.08 with leaky ReLU.

Measured with src/dead_relu_toy.py (PyTorch 2.14, CPU, seed 0 for these three runs). Data: scikit-learn's digits (UCI), pixels standardised, 1,437 images to train on and 360 held out; "dead" is judged on all 1,797. A leaky unit with negative input on every image is counted the same way, though it still passes 1% of the gradient.

Across five seeds and ten learning rates (the chart below, from the same script): up to a rate of 0.04 no ReLU unit dies; at 0.05 and 0.06 a handful die and the network still reaches 96 to 98% held-out accuracy; from 0.07 most runs lose a whole layer, after which every image produces the same output, the loss sits at ln 10 = 2.303 and accuracy at chance. With leaky ReLU nothing can go fully silent, so the same rates do not end in a dead network; they end in a loss that overflows to "not a number". The learning rate is the cause in both; the activation decides only whether the failure is silent or loud.

What to do about dead units
  • Check for them: count, over a batch or a held-out set, the units whose output is 0 on every example (the parent's {{When training goes wrong|n:3c65c17b0d0d81d796ccc0a293218c57}} tab runs a network whose biases start at −3, so most ReLUs are off from the start, and shows the plateau that follows).
  • Lower the learning rate, warm it up, clip gradients: the runs above die only above a threshold rate.
  • Initialise for the activation (He for the ReLU family) and keep biases at 0, not negative.
  • Normalise before the activation, which keeps pre-activations centred, or switch to a variant with a negative side (leaky, ELU, GELU, SiLU). Neither removes the cause if the rate is too high.

In a released model. Dead units are not only a training accident. In OPT, whose feed-forward blocks use ReLU, "many neurons (more than 70% in some layers of the 66b model) are 'dead', i.e. they never activate on a large collection of diverse data", all of them in the first half of the network (Voita, Ferrando and Nalmpantis 2023).
