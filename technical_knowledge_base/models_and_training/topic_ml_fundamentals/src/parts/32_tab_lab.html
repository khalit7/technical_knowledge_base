Controls

Every component of A and B can be set separately; rows where they differ are highlighted. Changing anything restarts both runs from the same seed. A preset is just a set of these values.

Shared by both runs

Does it happen on every seed?

A single run can mislead: one seed's data, starting weights and batch order. This repeats the current comparison on seeds 1 to 10 without drawing, and checks each of the preset's claims on every seed. It takes from a few seconds to about a minute on a phone.

How the lab works

  • The task. Points in a square, two classes: two spirals, a ring around a disc, a checkerboard, or two moons. The training set is small (40 to 400 points) and a chosen share of its labels can be flipped; the validation set is 400 fresh points with correct labels, so the gap between the two is how much the net memorised.
  • The network. A multilayer perceptron: input (2) to hidden layers of the chosen width to two output logits. The plotted loss is cross-entropy on those logits for every run, whatever the run trains on, so runs with different losses can be compared on one axis.
  • Written by hand, checked against PyTorch. Forward and backward passes, the four losses, the three normalisations, dropout and the five optimisers are plain JavaScript in double precision. Offline, the same code ran 342 configurations (every activation, normalisation, placement, residual setting and loss, plus dropout) through PyTorch 2.14: gradients agree to a relative 2 × 10⁻¹², losses to 3 × 10⁻¹⁵. Forty training steps per optimiser (SGD, momentum, Adam, AdamW, Muon, with schedules, both kinds of weight decay, BatchNorm running statistics and dropout masks) end on the same weights to 2 × 10⁻¹⁵.
  • Exact definitions. Momentum is PyTorch's (buffer = 0.9 × buffer + gradient). Adam and AdamW use β = (0.9, 0.999), ε = 10⁻⁸; Adam's weight decay is L2 (added to the gradient), AdamW's is decoupled (weights multiplied by 1 − lr·λ). Weight decay applies to weight matrices only, not biases or normalisation gains. GELU is the tanh approximation. BatchNorm uses the batch's statistics in training and running averages (momentum 0.1) for validation and the boundary. Label smoothing is 0.1, the focal loss's γ is 2. Early stopping halts when validation loss has not improved for 15% of the run; it does not roll back.
  • Muon. As torch.optim.Muon: momentum 0.95 with Nesterov, five Newton-Schulz steps with coefficients (3.4445, −4.7750, 2.0315), on the hidden square matrices; its step is scaled by 0.2 √max(rows, columns) (PyTorch's "match_rms_adamw" option, from Moonshot's Muon work) so the same learning rate suits it and the AdamW that handles the other weights. PyTorch runs the Newton-Schulz steps in bfloat16 for speed; this page runs them in double precision (the check swaps in a double-precision copy of PyTorch's function; in bfloat16 the weights after 40 steps differ by about 0.5%).
  • Deterministic. One seed drives the data, the label flips, the starting weights, the batch order and the dropout masks, each from its own stream, so A and B share all of them and a run replays identically.
  • What a toy cannot show. At this scale some comparisons that matter in large models show no reliable difference: over ten seeds, Muon and AdamW reach the spiral equally well, and MSE trains slower than cross-entropy but ends in the same place. Use the presets for the effects that do show up here, and the child pages for the evidence at scale.
