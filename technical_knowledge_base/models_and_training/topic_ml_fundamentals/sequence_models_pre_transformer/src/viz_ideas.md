# Visualisation ideas: Sequence models, the pre-transformer lineage

The question the page keeps returning to: **why did each sequence model replace the one before it, and what exactly broke?** (Vanishing gradients, the fixed-vector bottleneck, one vector per word, sequential computation.) A visual earns its place when it makes one of those failures, and its fix, visible on real numbers.

Already built elsewhere, so linked, not rebuilt:
- Parent root (Topic: ml-fundamentals), Reading tab: the lineage table "Sequence models before the transformer: what the transformer kept", and thread 3's scalar BPTT slider (tanh RNN factor against the LSTM forget-gate path).
- Attention Is All You Need: recurrent layer against one self-attention layer on the same sentence (animated, Table 1 counters), Table 1 path lengths for ByteNet/ConvS2S, a trained toy transformer.
- Mamba: Theorem 1 (gated RNN as a special case of selection) as a slider; hybrids in production.
- Positional Encodings and Tokenizers pages: what the transformer had to add back (order) and what replaced word vocabularies (subwords).

Scoring (0 to 2 each): parameter to move; reproduces a stated figure (counts double); computable from public data or real weights (counts double); shows what a sentence cannot; corrects a misconception; measures the central question; absent elsewhere; step-by-step before/after animation. What the methodology lacked for this page: a rule for **toy tasks that isolate one capability** (memory only, copying only), where the toy's finding is qualitative and the page must say which published effect it mirrors (Bahdanau's length curve, Sutskever's reversal) and which it adds (attention not extrapolating past the training length). Also a rule for **"representable but not learnable"**: when a negative result could be read as "cannot", run the setting where it can (the short-trained plain RNN) and show both.
