5 · LayerNorm and RMSNorm: the same recipe on the other axis

LayerNorm normalises each example (each token, in a transformer) over its own features, with one γ, β vector per layer (Ba, Kiros and Hinton 2016). That fixes BatchNorm's three weaknesses at once: no dependence on batch size, fine for RNNs and variable-length inputs, and the same computation at training and inference, with no running averages (the LayerNorm mode of the animation above). It gives up the mild regularising noise of batch statistics and a little inference compute, because the statistics are computed per token instead of being folded into the weights. It was the 2017 transformer's norm.

RMSNorm(x) = x / RMS(x) · γ,   RMS(x) = √( (1/d) Σ xi² + ε )
vs LayerNorm
no mean subtraction, no β: half the reductions and one fewer parameter vector

RMSNorm (Zhang and Sennrich 2019) is LayerNorm without the re-centring. Its argument: LayerNorm's benefit comes from re-scaling invariance (the output does not change when the input is multiplied by a constant), not from re-centring; it "achieves comparable performance against LayerNorm but reduces the running time by 7%~64% on different models" reported, and its abstract singles out RNNs as the networks LayerNorm's overhead "significantly slows". In the axes figure, RMSNorm leaves each token's mean in place and only fixes its scale. It is the default in essentially every open LLM since Llama (Llama, Mistral, Qwen, DeepSeek, Gemma and OLMo 2; their config files name rms_norm_eps; the parent's Defaults across models tab lists 21 landmark models).

ε is not a detail. It bounds the output when the input is nearly constant. Released configs use 10−5 (Llama 3.1, Mistral 7B v0.3, GPT-2, SmolLM2) or 10−6 (Qwen3, Gemma 3, OLMo 2), and BERT's LayerNorm uses 10−12 (src/inputs/configs_norm_init.json, read from each model's config.json). An ε below what the number format can resolve against the variance does nothing, so low-precision kernels usually compute the statistics in float32.

Where the norm sits in a transformer block (post, pre, sandwich, output norm), QK-norm and the other logit controls are taught on {{Normalisation, residuals and stability|n:3fd5c17b0d0d8163b50dc5e9d9240e89}} (Topic: llm-architecture). Measured: does QK-norm cap attention logits in Qwen3-0.6B?

QK-norm is an RMSNorm on each head's query and key vectors (ViT-22B, Qwen3, OLMo 2, Gemma 3). An attention logit is q · k / √dh. With unit gain, an RMS-normalised head vector has length √dh, so a logit is at most √dh. But the gain γ is learned: ‖q‖ ≤ √dh · max|γq| (RoPE only rotates), so the ceiling is √dh · max|γq| · max|γk| derived. The bars compare that ceiling, from the released weights, with the largest logit reached on a 145-token English passage.

Trained gains put the ceiling hundreds of times above the real logits

Qwen3-0.6B, 28 layers, dh = 128; gains read from q_norm.weight and k_norm.weight; logits from the model's own eager attention in float32, causal mask, first token excluded as a query (src/recompute.py, src/real/real_streams.py) measured. Log scale.

The trained gains are far from 1 (the key gains reach 96 in layer 1), so the ceilings run from 184 to 12,897 while the real largest logits per layer stay between 12.5 and 48: QK-norm does not cap logits at a small number in a trained model, so do not assume a √dh bound. What it changes is where growth can come from: not the projection weights or the residual stream, only a dh-sized gain vector, which an optimiser with a bounded step changes slowly. That is our reading of the numbers, not a claim from the papers.

2025: normalisation without statistics (Dynamic Tanh)

Zhu, Chen, He, LeCun and Liu 2025 observe that LayerNorm in trained transformers "often produces tanh-like, S-shaped input-output mappings" and replace every norm layer with Dynamic Tanh, DyT(x) = γ · tanh(αx) + β with a learned scalar α, reporting matched or better results across vision and language tasks reported. It computes no statistics at all: an element-wise squashing that bounds activations. Whether it holds at frontier scale is not yet shown.
