The idea in one sentence

Training works when the scale of the signal stays about 1 at every layer: feature scaling fixes the inputs once, initialisation picks weights that neither shrink nor grow the signal at step zero, and normalisation layers reset the scale at every layer on every step, which is why a normalised network barely cares about its initialisation.

Twenty layers multiply a small error twenty times; a norm resets it each layer

The same 1,024 inputs through the same 20-layer ReLU network of width 512, built in PyTorch, with no bias; only the initialisation changes, or a LayerNorm is added before every ReLU. Each layer multiplies the mean square (the second moment, E[x²]) by a fixed factor: 0.163 with nn.Linear's own default (1.7 × 10−16 after 20 layers), 0.495 with Xavier (7.8 × 10−7), 0.990 with He (0.82), 0.101 with a fixed N(0, 0.02) (1.3 × 10−20), 1.015 with orthogonal weights (1.32), and the LayerNorm line stays at 0.51 whatever came before measured (src/recompute.py, src/signal_prop.py, torch 2.14.1). Section 2 derives the factors; section 3 onwards is the norm line.

second moment
E[x²], the mean square of a layer's numbers; equal to the variance when the mean is 0. The quantity every scheme on this page keeps near 1.
fan-in, fan-out
nin, nout: how many inputs a unit sums, and how many units read its output.
γ, β
the learned gain and shift a norm applies after normalising, one per feature.
running statistics
BatchNorm's moving averages of the mean and variance, used at inference instead of batch statistics.
residual stream
the vector x in x → x + F(x) that every block of a residual network adds into.

1 · Feature scaling: the inputs, once

A model that measures distance (k-nearest neighbours, SVMs with an RBF kernel, k-means), projects variance (PCA) or penalises all weights alike (ridge, lasso) treats one unit of every feature the same, so a feature measured in thousands outvotes one measured in fractions. Gradient descent suffers too: unequal scales stretch the loss surface into a narrow ravine, so the step that is safe along the steep feature is tiny along the flat one. Tree models split one feature at a time and do not care.

The statistics (μ, σ, minimum, maximum) are fitted on the training set only and applied unchanged to validation and test data; fitting them on all the data leaks the test set into training (scikit-learn, common pitfalls). A pipeline object does this for you.

On all 13 features measured (src/scaling.py): kNN with k = 20 scores 77.78% raw, 96.30% standardised and 98.15% min-max scaled. For least squares on the same data (alcohol from the other 12 features), the condition number of the Hessian XTX/n, the ratio of the steepest to the flattest direction of the loss and so roughly how many more steps gradient descent needs, is 1.6 × 108 raw, 690 min-max scaled and 45 standardised.

Correction: scikit-learn's own example overstates the gap
It reports that PCA to two components then logistic regression scores 35.19% unscaled against 96.30% standardised. Rerunning its code reproduces both numbers, but the example passes one PCA object to both pipelines, so fitting the standardised pipeline refits the PCA that the unscaled pipeline then uses on raw data. With a PCA of its own, the unscaled pipeline scores 74.07% (log-loss 0.497, against 1.18) measured. Scaling still wins (96.30%, log-loss 0.0739); the gap is 22 points, not 61 (src/scaling.py).
