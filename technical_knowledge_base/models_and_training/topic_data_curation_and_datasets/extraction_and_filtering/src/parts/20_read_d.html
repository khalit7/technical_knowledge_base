5. Tables, code and maths

The problem. Main-content extractors are tuned on news and blog posts. Three structures carry meaning in their layout: a table (rows and columns), a code block (line breaks and indentation, which in Python are syntax) and maths (TeX for MathJax to render in the browser, or MathML with TeX attached as an annotation and an image as fallback). Our WARC file has only 3 pages with MathML among 20,280, so this page fetched 131 pages from the same crawl chosen for each structure and measured what survives each extractor:

Code indentation and TeX survive only where an extractor keeps text verbatim

  • Code. trafilatura 1.11 turns a syntax-highlighted <pre> block into one line, because its clean-up function trim is ' '.join(string.split()): every run of whitespace, newlines included, becomes one space. trafilatura 2.3.1 keeps indentation on about two thirds of such lines; resiliparse keeps <pre> text verbatim; jusText rejects code blocks (almost no English stop words).
  • Maths. On Wikipedia every extractor but jusText removes all 804 formulas: trafilatura deletes <math> elements outright, and resiliparse with Dolma's settings drops the fallback image's alt text, where Wikipedia also puts the TeX. What is left reads "Suppose that for every where is the indicator function". On Stack Exchange the TeX is plain text between dollar signs, so it survives whenever the post does.
  • Tables. trafilatura writes Markdown-like rows ("Acquisition date | Company | Business |" then "---|---|"), resiliparse cells separated by tabs with one row per line, readability-lxml a whole table as one paragraph.
The fingerprint in FineWeb itself
The filters after extraction remove what the extractor left. In 50,000 random FineWeb documents from CC-MAIN-2024-30, not one contains the character "{", the string "javascript" or "lorem ipsum" (C4's rules drop such documents or lines), not one has a line starting with four spaces or a tab (datatrove's C4 step strips every line, c4_filters.py:95, so indentation cannot survive even if an extractor kept it), and none contains "\frac" measured. A general web corpus built this way has no code with braces and no LaTeX at all; code and maths need their own pipelines (The Stack, OpenWebMath, FineMath, MegaMath; see {{Pretraining corpora|n:3c65c17b0d0d81f382b6e75707d00663}}).
Predict: FineWeb's ablation of C4's rules says the curly-bracket rule removes 2.8% of tokens. What does a rule that drops any document containing "{" do to a dataset meant to teach code?
How the pages were fetched, and the traces in the source (method; file:line)

The 131 distinct pages were found by looking their URLs up in Common Crawl's index and range-requesting the single WARC record of each: Stack Exchange questions (MathJax TeX in the text), arXiv abstracts, Wikipedia maths articles (MathML), Python and JavaScript documentation and Stack Overflow (code in <pre>), Wikipedia "List of" articles and statistics sites (tables). For each page the reference structures are read from the HTML; survival is then measured in each extractor's output.

Code, traced. On the Python documentation's example class ("class Foo: def __getitem__(self, index): ... def __len__(self): ..." as one line), trafilatura's own XPath path produced the text, no fallback was involved, and trim is at utils.py:333-339; only a few code paths ask to preserve spaces (main_extractor.py:246, 277, 390). resiliparse's serialiser keeps <pre> text verbatim (preserve_formatting=True).

Maths, traced. trafilatura's MANUALLY_CLEANED (settings.py:211-219) includes math; resiliparse drops alt text with alt_texts=False. OpenWebMath had to write its own extractor on top of resiliparse for exactly this reason: most LaTeX on Common Crawl is MathJax source that only the browser's JavaScript turns into maths, so the delimiters must be found in the raw HTML (OpenWebMath, arXiv 2310.06786, sections 3 and B, published).
