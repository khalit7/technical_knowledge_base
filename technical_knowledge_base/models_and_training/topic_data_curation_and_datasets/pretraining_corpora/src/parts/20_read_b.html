1. Common Crawl: the raw material

Common Crawl is a non-profit (a California 501(c)(3) founded in 2007) that has crawled the public web since 2008 and gives every crawl away: "more than 10 petabytes", each crawl "typically containing more than two billion web pages" ({{Common Crawl, About|https://blog.commoncrawl.org/about}}, checked 2026-10-14), free on AWS Open Data at s3://commoncrawl/ and over plain HTTPS at https://data.commoncrawl.org/ with no account ({{Get started|https://commoncrawl.org/get-started}}). Each crawl is a time slice of a few weeks named CC-MAIN-YYYY-WW (year and ISO week), about one a month in 2026. Its crawler, CCBot, reads each site's /robots.txt before fetching. A crawl is a sample of the web, not a mirror, and two crawls overlap heavily, which is why corpora built from many crawls must deduplicate across them ({{Deduplication|n:3f95c17b0d0d8171ac17e43ab5ea276f}} owns how).

Most of a crawl's bytes are not text: WET is about 7% of WARC

Compressed TiB per file type of CC-MAIN-2026-39, as printed on its {{file listing|https://data.commoncrawl.org/crawl-data/CC-MAIN-2026-39/index.html}} (checked 2026-10-14). WARC (Web ARChive, an ISO standard): each URL's request, response (HTTP headers and raw HTML, byte for byte) and metadata records, about 0.9 GB per gzip file, 100,000 files per crawl. WAT: JSON metadata per record (headers, <head> fields, every link). WET: the visible text Common Crawl's own converter pulled out. C4 was built from WET; FineWeb, RefinedWeb and DCLM re-extracted text from the WARC HTML themselves, because extraction quality turned out to matter ({{Extraction and filtering|n:3c65c17b0d0d81579b32c07c92b7472b}}). The URL and columnar indexes let you fetch one page without the rest (closed block below).

These are shares of sites (a one-page blog counts as much as a news site), so they sit below token-weighted figures; sample error about @@rb_se@@ points.

robots.txt is a request, not an access control. Common Crawl obeys it, so a site that blocks CCBot drops out of future crawls; old crawls stay downloadable (an inference: nothing published says they are altered). Since September 2025 Common Crawl also publishes an Opt-Out Ledger of legal removal requests ({{announcement|https://commoncrawl.org/blog/common-crawl-foundation-opt-out-registry}}). The independent, token-weighted measurement is {{Longpre et al. 2024, Consent in Crisis|https://arxiv.org/abs/2407.14933}}: among the most-used domains of C4, RefinedWeb and Dolma, 20 to 33% of tokens were fully restricted by April 2024, against under 3% a year earlier.

Fetch one page from a crawl without downloading a terabyte (the index, the code, its output)

Each WARC record is its own gzip member, so any record can be cut out of a 0.9 GB file with an HTTP range request if you know its byte offset. The URL index (a CDX index, one line per capture, sorted by a reversed-host key such as org,python)/) gives file name, offset and length. The columnar index is the same table as Parquet files that Spark, Athena or DuckDB can query with SQL ("all captures from *.gov.uk with MIME text/html") ({{cc-index-table|https://github.com/commoncrawl/cc-index-table}}). The script runs with curl, gunzip and Python 3; its two requests were run here on 2026-10-14 (the retry loop was added after the index server started failing later that day):

src/scripts/cc_one_record.sh
#!/bin/sh
# Find one page in a Common Crawl crawl and fetch only its record (no account, no key), as shown on the page.
# 1. ask the URL index where the capture lives (file, byte offset, length)
CRAWL=CC-MAIN-2026-39
# the index server is busy at times (502/504, or an empty reply): retry a few times
for i in 1 2 3 4 5; do
  curl -s "https://index.commoncrawl.org/$CRAWL-index?url=www.python.org/&output=json&limit=1" > cdx.json
  grep -q '"offset"' cdx.json && break; sleep 5
done
cat cdx.json
# 2. fetch only those bytes from the 1 GB WARC file and decompress the one gzip member
python3 - <<'PY'
import json, subprocess
c = json.loads(open('cdx.json').readline())
off, ln = int(c['offset']), int(c['length'])
url = 'https://data.commoncrawl.org/' + c['filename']
subprocess.run(['curl', '-s', '-r', f'{off}-{off + ln - 1}', url, '-o', 'record.warc.gz'], check=True)
PY
gunzip -c record.warc.gz > record.warc
wc -c record.warc.gz record.warc
head -c 600 record.warc
Its output (recorded 2026-10-14; long lines cut)


The record is 10,644 bytes out of a file of 921,782,734 bytes: you read 0.001% of the file. The WARC header says when and from where the page was fetched and carries a SHA-1 payload digest (also in the index, so identical pages across crawls can be spotted without reading them); then the HTTP headers exactly as sent, then 52,590 bytes of HTML for a page whose visible text is a few kilobytes. The index server is often busy (502 and 504 errors and empty replies here, hence the retries), and some URLs are simply not in a given crawl ("No Captures found" for two Wikipedia pages tried in CC-MAIN-2026-39). The topic's {{Pipeline lab|n:3c65c17b0d0d811fa5ecda8d365ab00f}} tab runs the whole funnel on a real WARC file.




Crawl details: CCBot, segments, sizes per capture, and when statistics disagree (provenance)


A web crawler keeps a list of URLs to visit (the frontier), downloads each page, stores what came back, and adds the page's links to the frontier. Common Crawl's FAQ describes CCBot as "a Nutch-based web crawler that makes use of the Apache Hadoop project"; it obeys Crawl-delay, honours nofollow ({{CC FAQ|https://commoncrawl.org/faq}}) and crawls from published IP ranges so sites can tell it from impostors ({{CCBot page|https://commoncrawl.org/ccbot}}). The 2026 crawls were weeks 04, 08, 12, 17, 21, 25, 30, 34 and 39; each crawl is split into 100 segments of 1,000 files. Besides WARC, WAT and WET, a crawl publishes the robots.txt files CCBot fetched, the non-200 responses (redirects, 404s) and the two indexes.


Compressed WARC per crawl did not shrink with the page count: 99.25 TiB for 3.35 billion pages in CC-MAIN-2023-50, 82.79 TiB for 2.17 billion in CC-MAIN-2026-39, so about 33 KB per capture then and 42 KB now (division of the published figures). The statistics disagree with the crawl pages for some early crawls (CC-MAIN-2013-20: 1.80 billion in the statistics, "2.00 billion" on its page), because the page repeats the original announcement while the statistics are recomputed from the index: quote the source with the number.


Longpre et al.'s full figures: about 1% of tokens across these corpora were fully restricted in mid-2023 and 5 to 7% in April 2024; the jump in the top 2,000 domains per corpus ("Head") came "directly after the introduction of GPTBot and Google-Extended" (August and September 2023). By crawler, OpenAI's agents were blocked on 25.9% of Head C4 tokens, Anthropic's and Common Crawl's on 13.3%, Google-Extended on 9.8% (their Figure 1). Their abstract says "28%+" and their introduction "~25%+" for the most critical domains: different populations, so quote the population with the number. The site-level sample here is closer to their whole-corpus figures than to the Head ones.
