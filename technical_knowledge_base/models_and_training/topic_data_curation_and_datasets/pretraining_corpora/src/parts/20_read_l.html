10. Common mistakes

Comparing token counts across corpora as if they were one unit
FineWeb counts GPT-2 tokens, DCLM GPT-NeoX tokens, C4's famous 156B are spaCy words, FineWeb2 and peS2o count words, Nemotron-CC does not say. For English web text the tokenizers agree within a few percent (section 2); for French the gap is about 25% and for code @@tok_code_ratio@@ times (GPT-2 splits indentation into one token per space: measured here, def f(x): plus an indented return x is 16 GPT-2 tokens and 8 Qwen3 tokens, the eight spaces being 7 tokens against 1). Re-count a sample with your own tokenizer before planning epochs.
Quoting the headline size of a corpus that has since changed
"FineWeb is 15T tokens from 96 crawls" was true of v1.0; v1.4.0 covers 110 crawls and about 18.3T tokens (its card's table total counts one crawl twice), and its card's own description is stale. The Pile's "300B tokens" is Pythia's training budget. The Stack's "3 TB", "6 TB" and "900B tokens" are three different objects. Cite version and revision.
Treating per-crawl deduplicated corpora as unique text
FineWeb, FineWeb-Edu and DCLM deduplicate within each crawl or shard; about 80% of DCLM-Baseline and FineWeb-Edu-score-2 are fuzzy duplicates across crawls (Nemotron-CC Table 4; Zyphra's recount of DCLM to 750B tokens). For a short run this is harmless; for a long one it is repetition you did not plan.
Reading a vendor's ablation as a neutral ranking
Each corpus wins its own paper, the margins are often under a point at small scale, and the harness changes the winner (DCLM against FineWeb-Edu: 13.5 MMLU points under one harness, "quite similar" under another). Look for the independent rows (section 5).
Choosing the strictest filter for a long run
A filter that keeps 8 to 10% of the web is right at 100B to 1T tokens and runs out at 10T, where repeating it costs more than adding medium-quality text. That is Nemotron-CC's argument and why recipes switch pools between stages.
Reusing a library's filter and assuming it is the paper's
datatrove's C4 filter requires 5 sentences by default, the C4 paper 3; C4's own documents pass the library default at @@ms_c4_c4@@ (section 8). Check every threshold you think you are reproducing.
Running English rules on code, maths or other languages
Gopher's quality rules pass @@ms_owm_gq@@ of OpenWebMath and @@ms_fra_gq@@ of FineWeb2 French (section 8). Domain and language corpora need their own pipelines.
Assuming the licence field is the whole licence
ODC-By or CC BY covers the compilation, not the pages; gated agreements add terms (NVIDIA's forbids redistribution); some fields are simply wrong (Ultra-FineWeb's Apache tag). Read all four layers (section 7).
Keeping no provenance
Without the source, crawl, URL and licence of every document you cannot honour a takedown, answer a licence question, or remove a contaminated source later. FineWeb keeps the source WARC file path and record id for each document, Nemotron-CC the record id; keep them through your pipeline.

11. Interview questions

What is the difference between WARC, WAT and WET, and which would you build a corpus from?
WARC holds the raw HTTP responses (headers and HTML), WAT JSON metadata and links, WET Common Crawl's extracted text. Build from WARC: your own extractor (trafilatura, resiliparse) keeps more of the main text and less boilerplate, and FineWeb's ablation found WARC extraction clearly better; WET is fine for quick experiments. WET is about 7% of the WARC bytes.
FineWeb deduplicates each crawl separately. Why not deduplicate across all crawls?
In FineWeb's ablations, global MinHash over all crawls removed up to 90% of old crawls and what survived was mostly rare, lower-quality text; the 31B tokens kept by global dedup in the 2013-48 crawl trained a worse model than the 171B tokens it removed. Per-crawl dedup kept popular pages several times, which acted as useful up-weighting. The cost is repetition at very large budgets.
DCLM keeps the top 10% by a fastText classifier. What is the classifier trained on, and why might it inflate benchmark scores?
Positives: OpenHermes 2.5 instructions plus top r/ExplainLikeImFive answers; negatives: ordinary web pages. It selects text that reads like questions answered clearly, which resembles benchmark items (MMLU-style questions). That is part of why it wins MMLU-heavy evaluations; it beat every alternative filter in DCLM's Table 4 (30.2 Core against 27.5 for no learned filter).
How would you compare two candidate corpora fairly?
Same model, tokenizer, hyperparameters and token budget; several seeds or data samples to measure noise; a benchmark suite chosen before the comparison with early-signal tasks, in more than one task format; decontaminate both corpora against it; report per-task scores, not only an average; and say who ran it.
A colleague wants to train a commercial model on FineWeb-Edu, Nemotron-CC v2 and The Stack v2, and publish the cleaned data. What do you check?
FineWeb-Edu: ODC-By plus Common Crawl terms, redistributable with attribution. Nemotron-CC v2: the NVIDIA agreement allows training but forbids redistributing the data, so it cannot be in the published set. The Stack v2: content only through Software Heritage under an agreement, each file under its own licence, opt-outs to honour. Then keep provenance per document and run it past counsel.
System design: assemble the pretraining data for a 7B model trained on 4T tokens, with a commercial licence and a 3-month timeline.

Requirements. 4T training tokens; English-first with code and maths; commercially usable; reproducible; decontaminated against the evaluation suite.

Sources. Do not re-crawl: start from released, redistributable pools. Web about 80%: DCLM-Baseline (3.8T, CC BY) and FineWeb-Edu (1.3T, ODC-By), or Nemotron-CC v1 buckets; code about 10% (Stack-Edu or The Stack v2 under the Software Heritage agreement); maths about 5% (FineMath, MegaMath); papers about 5% (peS2o, FinePDFs). Check epochs: 3.2T web from 5.1T is fine, but DCLM's internal duplication means globally deduplicating it first (about 750B unique) and up-weighting deliberately.

Pipeline. Re-tokenise everything with the model's tokenizer and record counts; global MinHash dedup across sources (datatrove or NeMo Curator, sharded by hash bands); decontaminate with 13-gram matching against every evaluation set; PII scrubbing; provenance columns (source, version, URL, licence) kept per document; write tokenised shards (see {{Storage and loading at scale|n:3f95c17b0d0d81398782efcb29d950d4}}).

Validation. 1B-parameter ablations at 20 to 50B tokens for the mix and any filter you change; a held-out anneal set of the best data for the last 5 to 10%.

Cost drivers. Classifier scoring (FineWeb-Edu's classifier took 6,000 H100 hours for 15T tokens: avoid rescoring what is already scored), dedup memory, and ablation compute. Risks. Licence layers, contamination, and over-filtering for the budget.
