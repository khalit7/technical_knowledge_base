1. Common Crawl from zero

Almost every open pretraining corpus on this page starts from the same raw material, so it is worth knowing it well. Common Crawl is a non-profit (a California 501(c)(3) founded in 2007) that has crawled the public web since 2008 and gives every crawl away: "more than 10 petabytes", each crawl "typically containing more than two billion web pages" ({{Common Crawl, About|https://blog.commoncrawl.org/about}}, checked 2026-10-14). It is hosted free by AWS's Open Data programme, at s3://commoncrawl/ and over plain HTTPS at https://data.commoncrawl.org/, with no account needed for HTTPS ({{Get started|https://commoncrawl.org/get-started}}).

What a crawl is

A web crawler is a program that keeps a list of URLs to visit (the frontier), downloads each page, stores what came back, pulls the links out of it and adds the new ones to the frontier. Before fetching anything from a site it reads that site's /robots.txt, a plain-text file in which the site says which crawlers may fetch which paths. Common Crawl's crawler is called CCBot; its FAQ describes it as "a Nutch-based web crawler that makes use of the Apache Hadoop project", it obeys Crawl-delay and honours nofollow ({{CC FAQ|https://commoncrawl.org/faq}}), and it crawls from published IP ranges so a site can tell the real CCBot from impostors ({{CCBot page|https://commoncrawl.org/ccbot}}). Each crawl is a time slice of a few weeks; it is named CC-MAIN-YYYY-WW (year and ISO week), and in 2026 there was roughly one a month (weeks 04, 08, 12, 17, 21, 25, 30, 34 and 39). A crawl is not the whole web, and two crawls overlap heavily: the same popular URL is fetched again in most of them, which is why corpora that use many crawls must deduplicate across them ({{Deduplication|n:3f95c17b0d0d8171ac17e43ab5ea276f}} owns how).

The files of one crawl, to scale

Every crawl publishes the same set of files, split into 100 segments of 1,000 files each in 2026. Three formats matter:

  • WARC (Web ARChive, an ISO standard): the raw capture. For each URL, a request record, a response record (the HTTP headers and the raw HTML, byte for byte) and a metadata record. About 0.9 GB per gzip file, 100,000 files per crawl.
  • WAT (Web Archive Transformation): JSON metadata computed from each WARC record: HTTP headers, the HTML <head> fields, and every link on the page.
  • WET (WARC Encapsulated Text): the visible text Common Crawl's own converter pulled out of each HTML page, nothing else. C4 was built from WET text; FineWeb, RefinedWeb and DCLM threw it away and re-extracted text from the WARC HTML themselves, because extraction quality turned out to matter (section 3, and {{Extraction and filtering|n:3c65c17b0d0d81579b32c07c92b7472b}} for why).

Alongside them: the robots.txt files CCBot fetched, the responses that were not a 200 (redirects, 404s), and two indexes. The bars below are the compressed sizes printed on the crawl's own page for the latest crawl.

Source: {{CC-MAIN-2026-39 file listing|https://data.commoncrawl.org/crawl-data/CC-MAIN-2026-39/index.html}} (compressed TiB as printed there, checked 2026-10-14). WET is about 7% of the WARC bytes: most of a raw page is markup, scripts and boilerplate, not text.

Finding one page without downloading a terabyte

Each WARC record is stored as its own gzip member, so any record can be cut out of a 0.9 GB file with an HTTP range request if you know its byte offset. The URL index (a CDX index, one line per capture, sorted by a reversed-host key such as org,python)/) gives exactly that: file name, offset and length. There is also a columnar index, the same table as Parquet files that Spark, Athena or DuckDB can query with SQL ("all captures from *.gov.uk with MIME text/html", for example) ({{cc-index-table|https://github.com/commoncrawl/cc-index-table}}). This is the code; copy it and it runs with curl, gunzip and Python 3. Its two requests were run here on 2026-10-14 (the retry loop was added after the index server started failing later that day):

src/scripts/cc_one_record.sh
#!/bin/sh
# Find one page in a Common Crawl crawl and fetch only its record (no account, no key), as shown on the page.
# 1. ask the URL index where the capture lives (file, byte offset, length)
CRAWL=CC-MAIN-2026-39
# the index server is busy at times (502/504, or an empty reply): retry a few times
for i in 1 2 3 4 5; do
  curl -s "https://index.commoncrawl.org/$CRAWL-index?url=www.python.org/&output=json&limit=1" > cdx.json
  grep -q '"offset"' cdx.json && break; sleep 5
done
cat cdx.json
# 2. fetch only those bytes from the 1 GB WARC file and decompress the one gzip member
python3 - <<'PY'
import json, subprocess
c = json.loads(open('cdx.json').readline())
off, ln = int(c['offset']), int(c['length'])
url = 'https://data.commoncrawl.org/' + c['filename']
subprocess.run(['curl', '-s', '-r', f'{off}-{off + ln - 1}', url, '-o', 'record.warc.gz'], check=True)
PY
gunzip -c record.warc.gz > record.warc
wc -c record.warc.gz record.warc
head -c 600 record.warc
Its output (recorded 2026-10-14; long lines cut)


The record is 10,644 bytes out of a file of 921,782,734 bytes: you read 0.001% of the file. The WARC header says when and from where the page was fetched and carries a SHA-1 payload digest (the same digest appears in the index, so identical pages across crawls can be spotted without reading them); then come the HTTP headers exactly as the server sent them, then 52,590 bytes of HTML for a page whose visible text is a few kilobytes. Two lessons from running it: the index server is often busy (it returned 502 and 504 errors and empty replies to some queries here, so the full script retries), and some URLs simply are not in a given crawl ("No Captures found" for two Wikipedia pages tried in CC-MAIN-2026-39), because a crawl is a sample of the web, not a mirror.

robots.txt and opt-outs


A robots.txt file is a list of groups, each naming crawlers (User-agent: GPTBot) followed by path rules (Disallow: /). It is a request, not an access control: a crawler that ignores it can still fetch the page. Common Crawl obeys it, and a site that blocks CCBot is left out of future crawls; nothing Common Crawl has published says old crawls are altered, and they stay downloadable (an inference, not a stated policy). Since September 2025 Common Crawl also publishes an Opt-Out Ledger of the legal removal requests it has received ({{announcement|https://commoncrawl.org/blog/common-crawl-foundation-opt-out-registry}}).


The independent reference measurement is {{Longpre et al. 2024, Consent in Crisis|https://arxiv.org/abs/2407.14933}} (Data Provenance Initiative, July 2024): across the domains behind C4, RefinedWeb and Dolma, about 1% of tokens were fully restricted by robots.txt in mid-2023 and 5 to 7% in April 2024; among the most-used domains ("Head", the top 2,000 per corpus) 20 to 33% of tokens, against under 3% a year earlier, with the jump "directly after the introduction of GPTBot and Google-Extended" (August and September 2023). By crawler, OpenAI's agents were blocked on 25.9% of Head C4 tokens, Anthropic's and Common Crawl's on 13.3%, Google-Extended on 9.8% (their Figure 1). Note that their abstract says "28%+" and their introduction "~25%+" for the most critical domains: different populations, so quote the population with the number.

Terms of use: Common Crawl does not licence the content


Common Crawl's {{terms of use|https://commoncrawl.org/terms-of-use}} (last updated 2024-03-07) give a licence to access the service; the crawled pages "may be subject to separate terms" of their owners, and "by using the Crawled Content, you agree to respect the copyrights and other applicable rights of third parties". Every corpus built from it inherits this: a card that says ODC-By or CC-BY 4.0 licences the compilation (the selection, the cleaning, the metadata), not the copyright in each web page.
