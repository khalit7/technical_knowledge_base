DoReMi step by step

One run of DoReMi's weight update (Algorithm 1, section 3a of Reading) on five domains, step by step: the proxy's loss against the reference's, the clipped excess, the multiplicative update, the renormalised and smoothed weights, and their running average, which is DoReMi's answer. Then the before/after: the same "main model" trained on the reference weights and on DoReMi's weights, same token budget.

What is real here and what is not
The update rule is the paper's, ported line for line (η = 1, c = 10−3, average of αt over the run). The losses are illustrative: each domain's loss is a made-up power law Ei + Ai·(ni + 1)−ai in the tokens it has effectively seen, with an optional share of web tokens counting for every domain (web is diverse, so it transfers), plus seeded noise. The "web" curve has a high floor E (hard for everyone), "code" a low floor and a steep curve (learned fast), maths and papers sit in between. The same code runs in src/recompute.py, and the page check confirms the two agree. The measured version is a pending GPU run (section 7 of Reading).

Predict: in this toy (natural-like reference, transfer on), which domain loses the most weight relative to the reference?
Web, from 0.40 to about 0.29; code (easy, learned fast) also loses weight, from 0.15 to about 0.11; wiki, maths and papers gain. That is the paper's own hypothesis about which domains can be downweighted (the lowest- and highest-entropy ones), reproduced by construction of the toy's curves, not as evidence. In the real Pile run the diverse web domain went the other way, to 60.6%, which a five-curve toy cannot capture: transfer from web to everything is far stronger in real text.

What to take from it: DoReMi's answer is an average over a noisy trajectory (the README: "we expect the domain weights during training to be somewhat noisy and the averaged domain weights to be mostly smooth"); it depends on the reference (iterated DoReMi re-trains the reference on the last answer until weights change by less than 10−3, which took 3 rounds on the GLaM dataset); and it optimises worst-case excess loss, not average loss, so it can make a domain worse in exchange for others, as the before/after bars show for web and code.
