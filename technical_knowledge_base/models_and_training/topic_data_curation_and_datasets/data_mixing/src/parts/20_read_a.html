In one screen

A pretraining corpus is several piles of different text: web pages, code, maths, scientific papers, encyclopedias, books, other languages. Data mixing decides three things about them, and each decision moves what the model can do at a fixed compute budget:

  1. How much of each (the mixture weights, also called domain weights or proportions): the fraction of training tokens each pile supplies.
  2. How many times a pile may be read (its epochs): a small, valuable pile given a large weight is repeated, and repeated tokens are worth less than fresh ones.
  3. In what order (the curriculum or stages): most modern runs change the mix during training, ending on the best data while the learning rate decays (mid-training, also called the anneal). Continued pretraining on a new domain is the same decision taken later by someone else: how much new-domain data against how much general data replayed.

Running example. Two, used throughout. (1) The Pile's 22 domains, because the main methods (DoReMi, RegMix, and the papers that check them) were all run on it, so one set of real sizes, weights and published results connects every section. (2) A five-domain proxy experiment built from the topic's running example samples (web from DCLM-baseline, Wikipedia, code from Stack-Edu, maths from FineMath, papers from peS2o): the scripts, the CPU smoke test and the GPU runs that will fill it are in section 7.
