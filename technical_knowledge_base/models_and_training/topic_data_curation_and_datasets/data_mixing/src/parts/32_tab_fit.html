Mixing-law fitter

RegMix released all of its proxy runs: 512 tiny models (1M non-embedding parameters, 1B tokens each) trained on random mixtures of The Pile's 17 available domains, plus 256 unseen mixtures at 1M, 256 at 60M and 64 at 1B parameters on 25B tokens, each with its validation loss per domain. This tab fits a mixing law to the 1M runs in your browser and tests it on the unseen ones, including the 1B runs: the rank-invariance bet of section 3c, checked on real data published runs, fits computed here.

Test on

Try: keep Pile-CC and 1B, and drag the training runs down from 512 to 32: the linear fit loses rank quality fast, the exponential law much less. Then switch the test set to 60M: the absolute losses shift (a different model size), but the ranking is what transfers.

What each fit recommends

Each fitted model scores 20,000 random mixtures drawn as in RegMix's notebook (Dirichlet with the natural token shares as concentration) and averages the best 128. Compare with the mixtures actually trained at 1B in RegMix's Table 4.

Which domains move the target

Predict: for the GitHub validation loss as target, which training domain does the fitted law say matters most?
Under the exponential law (the default model), GitHub itself, by far (exponent −58.5 relative to the domain that helps least, against −8.6 for the next): code is learned from code. Switch the model to linear and the top coefficient becomes Enron Emails, a domain with 0.2% of the tokens: few runs gave it any weight, so its coefficient is poorly determined, and with weights that sum to 1 a linear coefficient is only meaningful relative to the others. Read fitted coefficients as a fit, not as causes. For Pile-CC (RegMix's target) the exponential law also puts Pile-CC first, which is why the recommended mixture is mostly web text.
