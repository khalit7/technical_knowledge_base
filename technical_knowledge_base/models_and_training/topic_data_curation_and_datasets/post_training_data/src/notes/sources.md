## 1. Self-Instruct (arXiv 2212.10560v2, ACL 2023) https://arxiv.org/html/2212.10560

- Seed tasks: "We initiate the task pool with 175 tasks (1 instruction and 1 instance for each task)." (Sec 2.2). Footnote: "newly written by the authors and their labmates at UW". Per step: "we sample 8 task instructions from this pool as in-context examples. Of the 8 instructions, 6 are from the human-written tasks" (and 2 from model-generated ones).
- ROUGE-L filter: "a new instruction is added to the task pool only when its ROUGE-L similarity with any existing instruction is less than 0.7." (Sec 2.2, "Filtering and Postprocessing"). It compares the new instruction against every instruction already in the pool (seeds plus accepted generated ones), not only the seeds.
- Keyword filter: "We also exclude instructions that contain some specific keywords (e.g., image, picture, graph) that usually can not be processed by LMs." Also: instances that are exact duplicates or "the same input but different outputs" are dropped; heuristics drop instructions that are too long or too short, and outputs that repeat the input.
- Model: "We use the largest GPT3 LM (''davinci'' engine) accessed through the OpenAI API." (Sec 3).
- Size, Table 1: # of instructions 52,445; classification 11,584; non-classification 40,861; # of instances 82,439; instances with empty input 35,878; avg instruction length 15.9 words; avg non-empty input 12.7; avg output 18.9. Prose: "over 52K instructions and more than 82K instances". Prose and table AGREE.
- Cost (Appendix, Table 4 area): "OpenAI charges $0.02 per 1000 tokens ... The generation of our entire dataset cost around $600." Fine-tuning GPT3 on the data via the OpenAI API "cost $338."
- Extra: regenerating outputs with InstructGPT-003 ("a distillation of InstructGPT-003 with our data") beat the original data "by 10%" (Sec 4.5 / Fig 7).

## 2. Stanford Alpaca

Blog https://crfm.stanford.edu/2023/03/13/alpaca.html ; README https://raw.githubusercontent.com/tatsu-lab/stanford_alpaca/main/README.md

- 52K and model: "52K instruction-following demonstrations generated in the style of self-instruct using text-davinci-003." (blog). Fine-tuned from LLaMA 7B.
- Seeds: "We started with the 175 human-written instruction-output pairs from the self-instruct seed set." (blog)
- Cost: data "costed less than $500 using the OpenAI API"; "fine-tuning a 7B LLaMA model took 3 hours on 8 80GB A100s, which costs less than $100 on most cloud compute providers." Summary line: "easy/cheap to reproduce (<600$)". Consistent.
- Pipeline changes (README, "Data Generation Process"), verbatim bullets:
  - "We used `text-davinci-003` to generate the instruction data instead of `davinci`."
  - "We wrote a new prompt (`prompt.txt`) that explicitly gave the requirement of instruction generation to `text-davinci-003`."
  - "We adopted much more aggressive batch decoding, i.e., generating 20 instructions at once, which significantly reduced the cost of data generation."
  - "We simplified the data generation pipeline by discarding the difference between classification and non-classification instructions."
  - "We only generated a single instance for each instruction, instead of 2 to 3 instances as in [1]."
- Input field: "Around 40% of the examples have an input." (README)
- Licence: "The dataset is CC BY NC 4.0 (allowing only non-commercial use) and models trained using the dataset should not be used outside of research purposes." (README). Reason (blog): "First, Alpaca is based on LLaMA, which has a non-commercial license ... Second, the instruction data is based on OpenAI's text-davinci-003, whose terms of use prohibit developing models that compete with OpenAI."
- Eval: "Alpaca wins 90 versus 89 comparisons against text-davinci-003." (blog)

## 12. Length bias

- Singhal et al., arXiv 2310.03716: Table 5, "Accuracy of always preferring longer response": WebGPT 55.7%, Stack 59.6%, RLCD 63.1%. Length-only reward PPO vs standard PPO (prose): "56% vs 58% win-rate ... on WebGPT and 64% vs 63% ... on RLCD". Table 2 AGREES (W-GPT ppo 58%, lppo 56%; RLCD ppo 63%, lppo 64%; Stack ppo 58%, lppo 59%). Table 2 lengths: W-GPT sft 100 vs ppo 230 tokens. Table 1, non-length share of reward gain (std PPO): wgpt 2.0%, stack 53.4%, rlcd 27.2%. Prose: "For WebGPT and RLCD, 70%-90% of the improvement ... can be explained by length shifts". Table check: implied length shares are 98% (wgpt std), 84.9% (wgpt high-lambda), 72.8% (rlcd std), 80.9% (rlcd high-lambda). The WebGPT standard case (98%) exceeds the 70 to 90% prose range, so prose and table agree only loosely.
- AlpacaEval LC, arXiv 2404.04475: "it increases the Spearman correlation with LMSYS Chatbot Arena from 0.94 to 0.98." Gameability: "The baseline model (gpt4_1106_preview) fluctuates from 22.9% to 64.3% by varying the verbosity instruction in the prompt." Method: fit a GLM and predict with "a zero difference in lengths".
- Park et al., arXiv 2403.19159: "we achieve up to 20% improvement in win rates when controlling for length, despite the GPT-4 judge's well-known verbosity bias." Fig 2 caption: "While both datasets exhibit a small bias in preference towards longer responses, the un-regularized DPO model produces answers twice as long on average" (HH and TL;DR).
- Related: OLMo 3 caps chosen/rejected length difference at 100 tokens (item 9). Tulu 3 uses length-normalized DPO to mitigate "the length bias common in human and model preferences".

- Commit 72f46040363137f0a69b58c8371b2d6f14979f41 is real but very recent: 2026-10-14, "Fix IFEvalG word-counting checkers ..." (current main; its finetune.py is byte-identical to main).
