The idea in one screen

Every post-training row is a prompt plus a signal of what good looks like: a written answer, a comparison of two answers, a checker program, or a test suite in a sandbox. The data is exactly as good as that signal, so building these sets is making the signal cheap (a stronger model writes it, a model judges it, a program checks it) and then checking the signal itself.

Four kinds of row: the same prompt slot, a different signal, and the way each went wrong when measured here

Blue: the signal the model learns from. Orange: the failure measured on this page (sections 1, 5, 6 and 7). A pretraining corpus can be noisy because noise averages out over trillions of tokens; post-training is a few hundred thousand to a few million rows, and a wrong row teaches the wrong thing directly.

This page is about the data.

Distilled data
responses written by a stronger teacher model; most open SFT and preference data is distilled.
Rejection sampling
generate several answers, keep only those a checker or judge accepts.
Preference pair
a prompt with a chosen and a rejected answer, picked by a human or a model judge; binarization is the rule that turns several rated answers into one pair.
On-policy
written by the model being trained (off-policy: by another model).
Checker
a program that turns a response into a verdict: an extractor finds the answer, a comparator matches it with the label.
Pass rate
the share of a prompt's rollouts the checker accepts.
Environment, trajectory
a task the model acts in through tools, with a programmatic success test; the trajectory is its recorded actions and observations.

Labels: measured means run on this machine (Apple M1 Pro CPU, 2026-10-15) on public samples whose revisions are recorded in src/inputs/pd_manifest.jsonl; published means a number from a paper or card, with its table; derived means arithmetic on published numbers.
