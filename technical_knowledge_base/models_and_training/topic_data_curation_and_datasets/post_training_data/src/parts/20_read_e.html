5. Chat templates and loss masking: what a row becomes

The problem. A row is a list of turns; a model reads one string of tokens. The chat template renders the turns into that string, with headers that say who speaks, and the loss mask decides which tokens the model is graded on. Get the template different between training and serving and the model sees headers it never learned; forget the mask and it learns to write the user's half too. The mechanics (how masked tokens drop out of the loss, packing several rows into one sequence) are on {{Alignment: SFT, RLHF, DPO Family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}, which animates them; here is what they do to the data.

How Tulu 3 did it. open-instruct renders the conversation with its "tulu" template (<|user|>, <|assistant|> headers, end-of-text token after each answer; dataset_transformation.py lines 260 to 279 at commit 72f46040), then, for each non-assistant message, renders the conversation up to that message and masks that span of tokens, including the <|assistant|> header that follows it (finetune.py lines 401 to 444 at the Tulu 3 release commit b0899767; today's code builds the same labels another way, lines 1598 to 1728). How much of a row is trained measured: the same template and masking on every set (at most 3,000 rows each, seed 0), share of all tokens that get loss.

The spread is the point. In a reasoning set nearly every token is the model's own trace, so nearly every token is trained. In an agent trajectory the observations (file contents, test output) are most of the tokens and are masked: only about one token in six or seven is the agent's. Two sets with the same number of rows can carry five times different amounts of training signal, so budgets are set in trained tokens, not rows.

Three ways this goes wrong
Template drift: the base model's tokenizer ships one template, the training script uses another, the serving stack a third; whitespace and the end-of-turn token are the usual differences. Render a row with each and diff the strings. No end token: if the token after the answer is masked or missing, the model never learns to stop. Masking by string search: finding "assistant" in the text to start the mask breaks on any answer that contains the word; render prefixes, as open-instruct does.
