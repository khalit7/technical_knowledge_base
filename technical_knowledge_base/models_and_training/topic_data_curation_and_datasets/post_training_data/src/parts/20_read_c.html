2. SFT data: from templated tasks to distilled mixtures

The problem. A pretrained model continues text; it does not answer. Showing it a few hundred thousand examples of "request, then a good answer" teaches the format, the tone and when to stop. The question has always been where the answers come from: people are slow and expensive, models are fast and cheap but inherit their teacher's mistakes and terms of use.

Self-Instruct's filter, step by step

How it works. Start a pool with 175 human-written tasks. Each round, show the model 8 instructions from the pool (6 human, 2 generated) and ask for new ones. A candidate joins the pool only if its ROUGE-L with every instruction already there is below 0.7. ROUGE-L is the length of the longest common subsequence of words, scaled: F = 2 × LCS / (words in a + words in b). Two instructions that share most of their words in order score near 1. The cost is one LCS against every pool member for every candidate, so it grows with the square of the pool; Alpaca's code ran it with a process pool. The animation feeds the same stream of real candidates (Dolly instructions, which no filter ever saw) into a pool, with and without the filter.

What it shows, measured on the real sets measured. Every instruction of Alpaca against every other one: @@si_alp_above@@ pairs score above 0.7 and @@si_alp_exact@@ instructions have a neighbour at exactly 0.7. That is the fingerprint of Alpaca's own rule, which rejects only when the score is strictly greater than 0.7 (generate_instruction.py line 196 at commit 761dc5bf), so the released set was filtered against itself as a whole, and the boundary cases slipped through. The same filter on Dolly, written by people and never filtered, would reject @@si_dolly_above@@ of @@si_dolly_n@@ instructions (@@si_dolly_pct@@); replaying it in file order rejects @@si_dolly_seq@@. Among the 175 human seeds themselves, @@si_seed_above@@ seeds have a neighbour above 0.7 (for example "Write a conversation based on the given facts." and "Write a cover letter based on the given facts.").

The filter measures wording, not task
ROUGE-L is a ratio of shared words, so short instructions cross 0.7 easily: @@si_dolly_short_example@@. Two different tasks in the same template are rejected; a paraphrase of the same task in new words passes. It keeps a pool lexically varied, which is what it was for; it is not a duplicate-task detector. For that, near-duplicate detection on prompt and answer together (MinHash, embeddings) does better ({{Deduplication|n:3f95c17b0d0d8171ac17e43ab5ea276f}}).

Today's mixtures, by skill

A modern SFT set is a mixture: subsets chosen per skill, each with its own source and generator. The bars are every row of the three Ai2 mixtures, counted by the dataset's own source column (Hugging Face's dataset statistics over the full train split, fetched 2026-10-15), grouped into skills by this page (the grouping is ours, the counts are not).

Three things to read off. Tulu 3 and OLMo 2 used the same mixture (one hard-coded identity subset differs). OLMo 3's instruct mixture is more than twice as large and adds whole new skills (tool use, @@mx_dolci_tool@@ rows; verifiable reasoning; logic puzzles). And the skills whose answers a program can check grow fastest: math is the largest skill in Tulu 3 (over a third of the rows), and in OLMo 3 verifiable reasoning and logic puzzles plus code with tests are the largest groups. A generated answer that can be checked can be kept only when it is right, which makes those rows cheap to trust.
