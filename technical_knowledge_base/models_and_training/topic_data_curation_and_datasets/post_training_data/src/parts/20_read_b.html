0. In one screen

Pretraining teaches a model language and facts from trillions of tokens of web text. Post-training turns that model into an assistant with a few hundred thousand to a few million carefully built rows. Each row is a label: a demonstration to copy, a judgement between two answers, a problem with a program that checks the answer, or a whole task in a sandbox. A pretraining corpus can be noisy because noise averages out over trillions of tokens; a post-training row that is wrong teaches the wrong thing directly.

Four kinds of row, one real example each (from the datasets measured on this page), with what makes such a row wrong and the cheapest check. The rest of the page takes them in order, then the quality control that applies to all four.

The idea that runs through the page
Every kind of post-training data is "a prompt plus something that says what good looks like": a written answer, a comparison, a checker, a test suite. The quality of the data is the quality of that something. Most of the work in building these sets is making the "something" right and cheap: writing it with a stronger model, judging it with a model, checking it with a program, and then checking the checker.

Labels: measured means run on this machine (Apple M1 Pro CPU, 2026-10-15) on public samples whose revisions are recorded in src/inputs/pd_manifest.jsonl; published means a number from a paper or card, with its table; derived means arithmetic on published numbers, with the formula. How these data are used in training (losses, schedules, RL algorithms) is on {{Topic: llm-training-and-post-training|n:3c65c17b0d0d81b6876ee72b7056793b}} and its child {{Alignment: SFT, RLHF, DPO Family, RLVR|n:3c65c17b0d0d81d5bed7e608d4061c7a}}; this page is about the data.

1. Words you need

Turn, conversation
A message from one role (system, user, assistant, tool). A row of chat data is a list of turns.
SFT
Supervised fine-tuning: the model is trained to predict the assistant's tokens of each row, exactly as in pretraining but on chosen text.
Chat template
The exact text format (special tokens, headers per role) a conversation is rendered into before tokenization. Training and inference must use the same one (section 5).
Loss mask
Which tokens of a rendered row count in the loss. Usually only the assistant's; the prompt is context, not a target (section 5).
Distillation (data)
Writing the responses with a stronger model (the teacher) and training a smaller one on them. Most open SFT data is distilled (section 3).
Preference pair
A prompt with two answers, one marked better (chosen) and one worse (rejected), by a human or a model judge.
On-policy, off-policy
An answer is on-policy when the model being trained wrote it, off-policy when another model did. On-policy pairs teach the model about its own mistakes.
Verifiable reward
A reward computed by a program: extract the final answer and compare it with a label, run unit tests, or check a formatting constraint. RL with such rewards is RLVR.
Checker, extractor
The program that turns a response into a verdict. The extractor finds the answer in the text; the comparator decides whether it equals the label.
Environment, trajectory
An environment is a task the model acts in through tools (a repository and a shell, a web page) with a programmatic success test. A trajectory is the recorded sequence of the model's actions and the environment's observations.
Decontamination
Removing training rows that contain evaluation items; owned by the {{Decontamination, PII and data governance|n:3f95c17b0d0d8100b7e4e0f96074c309}} page, applied here to the post-training sets (section 9).
