A simple quality filter, before and after

The problem. Distilled and crowd-sourced rows carry junk: a teacher model announcing it is ChatGPT, a "knowledge cutoff" sentence, a response stuck in a loop, the same conversation twice. How it works. Cheap rules, applied in order, each removing what it matches. The text rules here are Ai2's own clean-up scripts for the Tulu 3 SFT mixture, run unchanged from {{open-instruct|https://github.com/allenai/open-instruct/tree/72f46040363137f0a69b58c8371b2d6f14979f41/scripts/data/filtering_and_updates}} (commit 72f46040): filter_dataset_by_keywords.py (model and provider names in assistant turns, PATTERNS lines 45 to 105), filter_cutoff_date.py (CUT_OFF_PATTERN lines 17 to 37) and filter_ngram_repetitions.py (repeated blocks or sentences, lines 679 to 694). The other rules are defined here and named as such. The cost is a regex per row; the risk is what the rules take that you wanted.

How to check a filter like this: count what each rule removes per subset, then read what it removed. On this sample the identity rule fires on refusals in the WildGuardMix subset that say "As an AI developed by OpenAI" (row examples above); the cutoff rule checks every message, so one sentence in any turn of a long WildChat conversation removes the whole conversation.

Answer checkers: when is an answer right?

An RLVR row is a prompt plus a checker: a program that extracts the final answer from the model's response and compares it with the stored label. The reward is only as good as both halves. Six ways to extract and compare, run on every GSM8K and MATH row of Tulu 3's RLVR set against the reference solution of the same problem (GSM8K and MATH training splits, joined on the question text: rows): a correct checker should accept all of them.
