The same web text appears many times: syndicated articles, mirrors, templates, and, above all, boilerplate. This lab runs every deduplication method a pretraining pipeline uses on the page's running example (one Common Crawl WARC file of CC-MAIN-2024-30, taken through a FineWeb-style datatrove pipeline as run0) and shows what each one removes, why, and what it costs.

Labels used below: measured on the running example on an Apple M1 Pro (CPU) on 2026-10-14; published by the authors (their scale, not rerun here); derived from a formula; vendor claims. Timings are rough (a shared machine, 4 threads, low priority).

At a glance: five methods on the same 2,692 documents

The input is run0's filtered stage: the 2,692 English documents from our WARC that passed every heuristic filter, exactly what datatrove's MinHash step received. Each method was run on all of them; the bars count documents a method removes outright (the suffix-array row counts documents that lose at least half their bytes).

measured Exact: identical text, first copy kept. MinHash: datatrove 0.10.1 with FineWeb's settings (5-word shingles, 14 bands of 8 hashes), the same 75 documents run0 removed. C4 spans: datatrove's SentenceDedup (drop every repeated three-sentence span, then drop documents left with fewer than 3 sentences or 50 words). Suffix arrays: Google's deduplicate-text-datasets, repeated spans of 100 bytes or more, every copy removed. Semantic: SemDeDup's rule with an arctic-embed-m encoder, cosine at least 0.9.

The same documents before and after each method

Fourteen of the 2,692, picked to show where the methods disagree. Each card is one document (hostname, the start of its text after PII scrubbing). Every cluster here includes the copy a method keeps, except semantic dedup, whose kept copy of the banner sits outside this set. Fates come from the full run on all 2,692 documents.

What the animation shows
Most of what MinHash removes on a single crawl file is not "the same article twice" but boilerplate that survived extraction: 25 documents whose extracted text is only a cookie banner. Exact hashing catches byte-identical copies only; MinHash also catches the banner with an extra heading, and through chaining (A is close to B, B to C) it also removed the stove page, which had two sentences of real text. Suffix arrays remove the shared span inside every copy, keeping none, and leave the stove sentences. Semantic dedup is the only one that pairs the two casino spam articles, which share almost no 5-word phrases.
