Exact substrings with suffix arrays

The problem. MinHash judges whole documents. A 600-byte disclaimer pasted into thousands of otherwise different pages leaves each page unique by Jaccard, but the model still reads the disclaimer thousands of times. The tool. A suffix array is the list of every starting position in a text, sorted by the text that follows each position. Identical spans then sit next to each other, so one pass over neighbours finds every span of length L or more that occurs twice anywhere. Lee et al. (2021) built this for C4 and the Pile; RefinedWeb and Dolma 3 used it after MinHash.

illustrative three short documents written for this demo, joined with a unique separator per document (#0, #1, ...) so no match can cross a boundary, as the real tool's loaders do with 0xFF 0xFF plus a document index. The array is built live in your browser. Real corpora use the same idea with a linear-time construction (the Rust tool), not this sort.

On the running example

measured Google's deduplicate-text-datasets (commit 4e9888ac, built here with Rust 1.99): make, then self-similar --length-threshold L and collect per threshold, on bytes (no tokenizer). Lee et al.'s 50-token threshold is about 230 bytes of English (GPT-2 averages about 4.6 characters per token on FineWeb); Dolma 3 used 500 bytes. Remove all is what the tool's ranges mean: self-similar writes every position of a repeated span, the first included (main.rs:900-922), so deleting the ranges deletes every copy. Keep one is what Dolma 3 says it added ("we ensure we keep at least one copy of each substring"); estimated here by keeping the first range of each distinct span. Building the array took about s for the MB extracted file; the array file is bytes per text byte (pointer width grows with the text: 5 or 6 bytes at hundreds of GB).
