2. URL filtering: the cheapest stage

The problem. Adult and spam sites are a large share of any crawl, and you want to drop them before paying for extraction. How it works. datatrove's URLFilter (pipeline/filters/url_filter.py:104-132) checks, in order: the registered domain against a domain blocklist, the full host name, the exact URL, then the words of the URL against three word lists: a "hard" list (one hit drops the page), a "soft" list (two hits drop it), and "subwords" matched anywhere inside the normalised URL with an Aho-Corasick automaton. The lists ship inside the package: 4,558,939 domains and 19,586 URLs in assets/url_filterblacklistsv0_3_0.tar.gz, and 215 hard words, 88 soft words and 134 subwords (counted here; the code does not say where the lists come from). Cost: a set lookup and a string scan per URL, no page content read.

183 of 20,463 HTML pages (0.9%) removed, by the rule that fired first.

The 77 removals that were not a blocklisted domain, labelled from the URL alone (by the agent that built this tab; one reader): right drop, wrong drop, unclear. The 108 domain and host-name hits were not inspected.

What a word list gets wrong

A word in a URL is evidence, not proof. The cost of a wrong drop here is small (10 pages of 20,463), but it is not random: it falls on sports, religion and hobby pages whose vocabulary overlaps the list, which is a bias, not noise. Real pipelines accept it because the alternative, reading every page, costs more than the pages are worth.

3. Extraction: the same page, three ways

The problem. A raw WARC record is HTML: markup, scripts, navigation, the article, the footer. A training document should be the article. How it works. A main-content extractor parses the page into a tree and keeps the blocks that look like content: trafilatura scores nodes by text density, link density and tag names and falls back to other algorithms when unsure; resiliparse walks the DOM once in C++ with simpler rules (skip nav, footer, elements with boilerplate class names, link-dense blocks). Common Crawl's WET is not a main-content extraction at all: it keeps every visible string. FineWeb re-extracted WARCs with trafilatura because WET "retained too much boilerplate and menu text" (FineWeb paper, section 3); DCLM chose resiliparse as about as good downstream and about 8 times faster (published, DCLM Table 16).
