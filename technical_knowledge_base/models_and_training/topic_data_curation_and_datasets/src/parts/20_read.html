A training dataset is what survives a chain of filters ordered from cheap to expensive, and every stage trades the same two things: how good each token is against how many unique tokens are left before the run has to repeat them.

Data curation is everything done to text before a model trains on it: finding it, turning it into clean text, throwing most of it away, removing copies and test questions, and deciding how much of each kind to show the model and when. This page is the map: what each stage is, how the stages compare, and which child page owns each one. The children teach the mechanisms.

Fig. 1 follows one Common Crawl file through the pipeline, cheapest stage first. Each stage is a glass gate: the documents that pass flow on, the ones it removes fall into the tray in front, and the white column after each gate is the share of the file's HTML pages still alive, to scale. Every count is measured on the running example (below) with datatrove 0.10.1.

  1. Collect, then the URL filter. Collecting means Common Crawl's raw HTTP responses, plus code, papers, PDFs, books; licences and opt-outs are decided here ({{Pretraining corpora|n:3c65c17b0d0d81f382b6e75707d00663}}). One WARC file holds 20,991 responses; 20,463 HTML pages enter. The URL filter checks blocklists of adult and spam domains, before any page is read: −183 → 20,280 ({{Extraction and filtering|n:3c65c17b0d0d81579b32c07c92b7472b}}, section 10; section 3).
  2. Extract. HTML to the page's main text; menus and footers dropped. 1,039 pages give no text → 19,241 (Extraction and filtering, sections 1 to 5).
  3. Language ID. Keep the languages wanted (English at 0.65 or more). The largest cut of a multilingual crawl: −12,270 → 6,971 (Extraction and filtering, section 6).
  4. Heuristic rules. Gopher, C4 and FineWeb rules on length, repetition, punctuation: −4,279 → 2,692. The heuristic-rules gate is four steps (Gopher repetition 1,512, Gopher quality 1,883, C4 355, FineWeb 529; Extraction and filtering, sections 7 to 9; its Fig. 3 runs the 6,971 documents through the rule gates one by one).
  5. Deduplicate. Exact, fuzzy (MinHash), substring, semantic: −75 inside one file → 2,617 ({{Deduplication|n:3f95c17b0d0d8171ac17e43ab5ea276f}}; section 4 on why one file finds so few copies).
  6. Quality model. A classifier scores every document; a threshold keeps the top slice. On the 2,617: FineWeb-Edu's classifier keeps 159, DCLM's 573, the two thin columns ({{Quality classifiers and data selection|n:3f95c17b0d0d810baaabe41da6c9c50f}}; section 5). The stages after it were measured on all 2,617, so the main stream carries on at that width.
  7. Decontaminate, scrub PII. Remove benchmark items you will report; mask emails and IP addresses. The 2,617 documents share no 13-gram with any benchmark item, so nothing falls out; PII edits text and removes nothing (101 documents edited) ({{Decontamination, PII and data governance|n:3f95c17b0d0d8100b7e4e0f96074c309}}; section 6).
  8. Mix and stage. How many tokens of each domain, how often each repeats, and when: the planning step, with no file count. Web text is one of five domains here; the column shows the running example's natural shares (17% web, 16% Wikipedia, 31% code, 21% maths, 15% papers), then the weights a 0.8M-parameter DoReMi proxy chose (2.6%, 10.7%, 37.9%, 38.5%, 10.3%; one seed, not a recommended mix: section 7; {{Data mixing|n:3c65c17b0d0d819ea5d6c59471e66875}}).
  9. Store and load. Tokenize once, shard, pack, shuffle, stream to the trainer, resume. On 2,000 FineWeb documents, bytes per token of each stored form: 5.41 as JSONL, 1.93 as JSONL with zstd, 4.01 as a uint32 token shard (derived: file bytes over 1,422,641 Qwen3 tokens, from the {{Tool map|#t-map}}'s measurement; {{Storage and loading|n:3f95c17b0d0d81398782efcb29d950d4}} draws every form in its Fig. 1; the four shards drawn here are illustrative).
  10. The whole line, and beside it. From 20,463 HTML pages to 2,617 documents, 12.8%; FineWeb kept 2,425 documents from the same file, and 2,403 of them are in this output. Beside the main line: synthetic data, where a model writes or rephrases text when good real tokens run out; it joins the mix (200 pages rephrased by Qwen3-4B: {{Synthetic data|n:3c65c17b0d0d8171b5d9e36e05b7a5d0}}); and post-training data, a second, smaller pipeline: prompts plus a signal of what good looks like (samples of Tulu 3, UltraFeedback, RLVR prompts: {{Post-training data|n:3f95c17b0d0d81318c3ec7e4564d7b42}}).

The bars to scale, stage by stage, are {{Extraction and filtering|n:3c65c17b0d0d81579b32c07c92b7472b}}'s hero; the {{Pipeline lab|#t-pipe}} runs the same funnel with three extractors. The real order varies (FineWeb deduplicates before its last rules; DCLM runs its quality model after dedup), but the principle is fixed: cheap stages run on everything, expensive ones only on what survives.

You need nothing beyond knowing what a language model trains on; token counts depend on the tokenizer ({{Tokenizers|n:3c65c17b0d0d817187bcd94a1b0f15ea}}), which is why every corpus size here says whose count it is.

New terms on this page (19)

Token: the unit a model reads, a word piece of about four characters of English. Corpus: the documents a model trains on, sized in tokens. Crawl (snapshot, dump): one pass of Common Crawl over the web. WARC, WAT, WET: a crawl's raw HTTP responses, their metadata, and Common Crawl's own extracted text. Extraction: HTML to the page's main text. Language ID: a classifier giving each document a probability per language. Heuristic filter: a hand-written rule on a simple statistic with a threshold. Deduplication: removing exact or near copies. Quality model: a model that scores documents so a threshold can keep the best. Data ablation: train identical small proxy models on data differing in one decision and compare scores. Decontamination: removing training text that overlaps the test sets you will report. PII: personal data (emails, addresses, names). Mixture weights: the share of training tokens each domain supplies. Epoch: one pass over a domain's unique tokens. Mid-training or annealing: a short final stage on the best data while the learning rate decays. Continued pretraining (CPT): training a finished model further on one domain. Synthetic data: text written or rewritten by a model. SFT, preference, RLVR, environment data: the four shapes of post-training example (section 9).

The running example, and how numbers are labelled

Every lab tab measures on the same public data on one laptop, so numbers compare across tabs and child pages. The raw slice is one Common Crawl WARC file, the first of the July 2024 crawl (CC-MAIN-2024-30, 718.7 MB, 20,991 responses of which 20,463 HTML pages reach the pipeline), with its WET and WAT files; the Pipeline lab widens it to four files (81,738 HTML pages). It was chosen because FineWeb and FineWeb-Edu record the source WARC of every document, so the documents each kept from this exact file are known: 2,425 in FineWeb and 159 in FineWeb-Edu. DCLM-baseline only covers crawls before 2023, so a 50,000-document DCLM sample stands in for it and DCLM's own classifier is run on our pages; Nemotron-CC is represented by samples of each of its quality buckets from the same crawl. Seven benchmark test sets (MMLU, GSM8K, ARC-Challenge, ARC-Easy, HumanEval, MATH-500, HellaSwag) are the decontamination targets, and samples of Tulu 3's SFT mixture, UltraFeedback and Tulu 3's RLVR prompts stand for post-training data. The models are fastText lid.176 for language ID, the FineWeb-Edu classifier and DCLM's fastText classifier, all run on an Apple M1 Pro CPU; the full definition, with revisions and checksums, is in src/data/README.md.
