Model collapse in the case the theory is about: a "model" that is a probability for each of 1,000 word types, refit every generation by counting a finite sample of its own output. Watch the rare words vanish, and change one thing at a time: how the next generation's training data is chosen, the sample size, how heavy the tail is.

The four workflows

  • Replace (Shumailov et al., setting A): each generation is fit only on n samples from the previous model. A type that misses one sample is gone forever; in the long run one type remains.
  • Accumulate (Gerstgrasser et al.): each generation is fit on the real sample plus every synthetic sample so far. Real counts never leave the pool, so no type seen in the real sample can die; each new generation's noise counts for less and less.
  • Accumulate-subsample (Kazdan et al.): the pool accumulates, but each model trains on only n samples drawn from it (a fixed compute budget). Losses slow down and level off, above accumulate.
  • Fresh real data (Alemohammad et al.'s fresh-data loop; Shumailov's setting B keeps a random 10% of the original instead): each generation's n samples include a share of new draws from the real distribution, which brings dead types back.

What this toy leaves out, on purpose: a real language model shares parameters across words, so it can give a never-seen word some probability (functional expressivity and approximation errors in Shumailov's terms, which can either soften or worsen collapse). Not run here: a neural model trained from scratch, generation after generation. Training a small transformer on its own samples for several iterations (Gerstgrasser et al.'s TinyStories setup) costs hours of GPU time and would only restate their published result at smaller scale, so it was dropped. Their Table 2 already gives the answer for GPT-2 (9M) and Llama-2 (12M to 126M) models: test cross-entropy 1.82 at iteration 1; at iteration 4, 1.74 when accumulating against 2.39 when replacing; 2.91 after 10 replacing iterations ({{arXiv 2404.01413|https://arxiv.org/abs/2404.01413}}). The two CPU toys on this page cover the mechanism: the categorical model above and the {{Reading tab's bigram language model|#t-read}} trained on real TinyStories, which shows the same split (replace degrades, accumulate holds).
