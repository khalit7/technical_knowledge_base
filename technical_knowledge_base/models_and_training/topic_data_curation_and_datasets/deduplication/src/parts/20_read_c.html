2. Exact dedup: hashes of URLs, documents, paragraphs and lines

The cheapest duplicates are byte-identical: the same page fetched twice, a mirrored file, the same "Home | About | Contact" line on every page of a site. Hash every unit to 64 or 128 bits, keep the first unit with each hash value, drop the rest. On one machine the "seen" set is a hash table; on many, items are routed by their hash (a shuffle: all items whose hash starts with the same bits go to the same worker), so no worker needs the whole set.

measured On run0's 19,241 extracted documents: 258 exact copies, 284 after normalising (lowercase, no punctuation, digits as 0); of 743,644 non-blank lines, 256,024 (34.4%) repeat an earlier line; the most repeated are "|", "-", "Home" and "Search". After the quality filters, exact document copies fall to 50 of 2,692, all inside MinHash's clusters (root lab).

The unit decides what you catch. Common Crawl already removes repeated URLs inside one crawl, so URL dedup only matters across crawls (Llama 3 keeps the most recent version of each URL across its whole dataset, {{Section 3.1.1|https://arxiv.org/html/2407.21783}}). Document hashes catch mirrors and empty or error pages. Line and paragraph hashes catch boilerplate, and also strip structure (table separators, list markers, repeated headings).

How big must the hash be?

Two different items with the same hash are a collision: the second is wrongly dropped. With n items and a b-bit hash there are n2/2 pairs, each colliding with probability 2−b (the birthday problem). Predict before you change the selects: is 64 bits enough for 1012 lines?

derived expected colliding pairs = n(n−1)/2 · 2−b, and memory for a plain set = n × b/8 bytes (a hash table needs 1.5 to 2 times more). A 32-bit hash is unusable past a few tens of thousands of items; 64 bits is fine for documents and marginal for 1012 lines.

When it matters: always, first: it is a single pass and removes the bulk at web scale. How to check it: count items per hash and read the 50 most frequent; for a line rule, sample removed lines from pages you consider good (Llama 3's own warning, below).

The code that produced these numbers, and line dedup in practice (depth)
import hashlib, re
def h(s):                       # 8 bytes of SHA-1 is plenty below ~10^9 items (see the calculator)
    return hashlib.sha1(s.encode("utf-8")).digest()[:8]
def norm(s):                    # light normalisation: case, punctuation, digits, spaces
    s = re.sub(r"\d", "0", s.lower())
    return " ".join(re.sub(r"[^\w\s]", " ", s).split())

seen_doc, seen_norm, seen_line = set(), set(), set()
dup_doc = dup_norm = lines = dup_lines = 0
for t in docs:                  # run0's 19,241 extracted documents
    k = h(t);       dup_doc += k in seen_doc;   seen_doc.add(k)
    k = h(norm(t)); dup_norm += k in seen_norm; seen_norm.add(k)
    for line in t.split("\n"):
        if line.strip():
            lines += 1; k = h(line); dup_lines += k in seen_line; seen_line.add(k)

  • CCNet (used by Llama 1 and the first Dolma) hashes paragraphs within groups of shards of one crawl; in Dolma it "removed approximately 70% of paragraphs, primarily consisting of headers and navigation elements" ({{Dolma Section 5.1|https://arxiv.org/html/2402.00159}}).
  • Llama 3 removes "lines that appeared more than 6 times in each bucket of 30M documents", and notes this removes "frequent high-quality text" too, yet "our empirical evaluations showed strong improvements" (Section 3.1.1). A count threshold rather than "keep the first" keeps a line that recurs a few times, such as a common quote.
  • Dolma v1, all with its Bloom filter (section 7): exact URL dedup removed 53.2% of documents, exact document dedup 14.9% of the rest, exact paragraph dedup 18.7% of paragraphs ({{Section 5.4|https://arxiv.org/html/2402.00159}}). Dolma 3 (2025): exact dedup removed 67% of the pool after heuristic filtering, before MinHash.
