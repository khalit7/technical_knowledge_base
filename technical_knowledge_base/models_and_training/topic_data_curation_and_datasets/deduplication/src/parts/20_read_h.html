7. Bloom filters: exact dedup in fixed memory, and DCLM's near-dup variant

The problem. Exact dedup of paragraphs or n-grams across a corpus needs a "seen" set of 1011 to 1013 items: at 8 bytes each, terabytes.

How it works. A Bloom filter is an array of m bits and k hash functions. Adding an item sets its k bits; testing checks whether all k are set. It never misses an item it has seen, but can say "seen" for a new item whose bits were all set by others, a false positive. The figure adds two lines and tests a third:

  1. An empty filter. 16 bits, all 0, and 3 hash functions. A real filter holds billions of bits.
  2. Add "Home". Its three hashes point at bits 2, 7 and 11, which are set to 1. Nothing about the line itself is stored.
  3. Add "Search". Bits 4, 7 and 13: bit 7 was already set by "Home", so the two lines share it. 5 of the 16 bits are now set.
  4. Test "Login": a false positive. A new line whose hashes point at bits 2, 4 and 13. All three were set by the other two lines, so the filter answers "seen" and the line is wrongly dropped. A filter never misses a line it has seen; it can only raise false alarms like this one.

illustrative 16 bits and 3 hash functions with made-up hash values (two lines fill the bits a third line needs: a false positive); a real filter fills to about half its bits set at the best k.

After n items the false-positive rate is about (1−e−kn/m)k. The best k is (m/n) ln 2, which gives m/n = −ln p / (ln 2)2 bits per item for a target rate p: 9.6 bits at 1%, 14.4 at 0.1%, 57.5 at 10−12 (derived). In dedup a false positive drops one unique item, which is acceptable at 1%. The root lab checked the Dolma toolkit's filter against this formula (closed block below). How to check it: run the filter on a sample where a plain Python set gives the true answer and count the difference; log the fill ratio at the end of each shard.

DCLM's BFF: near-duplicates with a Bloom filter

DCLM-baseline was deduplicated with a modified "Big Friendly Filter": cut each paragraph into 13-grams and test every 13-gram against one filter holding all 13-grams seen so far. A paragraph is removed when more than 80% of its 13-grams were seen; a document when more than 80% of all its 13-grams were (published {{DCLM Appendix L|https://arxiv.org/html/2406.11794}}; false-positive rate 0.01). Unlike MinHash it compares a document with the whole corpus seen so far, in one streaming pass.
