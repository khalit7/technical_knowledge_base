Shuffle and resume

A corpus written the way pipelines write it: 11 shards of 200 documents, each shard one Nemotron-CC quality bucket and kind (CC-MAIN-2024-30, the first 200 documents of each head sample). The strip shows the order a training loader would read them in, one cell per document coloured by shard, 100 per row; below it, how far each batch of 32 is from the true mix. A perfectly mixed batch would hold every shard at 1/11.

Resuming mid-epoch

The same 2,200 documents, one epoch. Top: the order an uninterrupted run reads them in. Bottom: a run stopped after k samples and resumed. Green: the same document at the same position as the uninterrupted run; yellow: a document the resumed run reads a second time; the count says how many documents the epoch never reads.

This panel replays the three behaviours with this page's own JavaScript (a seeded buffer shuffle that follows the Hugging Face algorithm) illustrative mirror; the measured results of the real libraries at k = 640 are in the Reading tab's section 12 table (index-based loaders, torchdata and MosaicML Streaming resumed exactly; datasets with a buffer of 100 or 1,000 skipped 100 or 1,000 documents). The mirror reproduces those counts: with a buffer of B and the buffer not saved, exactly B documents are never read.
