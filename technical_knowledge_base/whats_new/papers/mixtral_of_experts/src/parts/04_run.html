Route text through a toy Mixtral

Section 5 of the paper is the only part about what Mixtral's router learned, and it rests on one model nobody outside Mistral could probe in the browser. This tab repeats the section on a toy built to the paper's recipe and trained here, on held-out text it never saw, so every claim can be checked against a model whose routing you can inspect token by token. It is not Mixtral: 4 layers instead of 32, about parameters instead of 46.7B, four small domains instead of The Pile. Read it as a test of whether the paper's findings are what a top-2 router tends to learn, not as a measurement of Mixtral.

What is Mixtral's in the toy, what is ours, and how it was trained
  • From the paper ({{§2.1|ax:S2.SS1}}): decoder-only; every FFN an MoE layer; 8 SwiGLU experts; top-2 with the softmax over the two kept logits; RMSNorm, rotary positions, grouped-query attention (4 query heads sharing 2 key-value heads here, 32 sharing 8 in Mixtral), untied output head.
  • Ours: width 128, 4 layers, expert inner width 256, a 2,048-token byte-level BPE vocabulary trained on the corpus, 256-token windows, AdamW (β = 0.9, 0.95, weight decay 0.1) with warmup and cosine decay, steps of 32 windows (8 per domain), seed 0, two CPU threads.
  • Load balancing: the paper says nothing; the released Hugging Face config sets a Switch-style auxiliary loss at 0.02. "With aux loss 0.02" uses it, "no auxiliary loss" trains the same model without; switch between them with the control at the top of each panel.
  • Data (about 1.2 MB of text per domain; split into train and held-out by 8 KB documents): code, the Python standard library's own source (for Pile GitHub); novels, five public-domain books from Project Gutenberg (Pride and Prejudice, Moby Dick, Sherlock Holmes, Frankenstein, A Tale of Two Cities); Wikipedia, plain-text extracts of named English articles; maths, one question and its answer per line from our own generator in the style of DeepMind Mathematics (arithmetic, linear equations, derivatives, remainders, rounding), synthetic and narrow like the original. Everything below is measured on held-out tokens per domain ( windows of 256).
  • Scripts: data.py, train.py, analyse.py in the page's source; uv run --with torch --with tokenizers python train.py main takes about 11 minutes on two laptop CPU threads. The page ships only the measured routing, not the weights.

3. Do consecutive tokens repeat their expert? (Table 5, rebuilt with controls)

Try: compare the measured repeat rate with the three baselines. The paper compares only against uniform random choice. Shuffled keeps every token's own routing but scrambles the order, so it removes position and keeps the fact that some experts are used more than others; different tokens only drops pairs where the same token appears twice in a row (two spaces, two newlines), which repeat their expert trivially.

4. Token or topic: what predicts the expert?

A direct test of "syntax, not domain" that the paper does not run: guess each held-out token's first-choice expert from its token alone (the expert that token most often got), from its domain alone, or from nothing (the most used expert). The guesses are fitted on half the held-out windows and scored on the other half.
