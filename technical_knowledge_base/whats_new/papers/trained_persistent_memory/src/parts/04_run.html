Simulate the memory bank

The paper's three write rules, run exactly as written: the attention-coupled write of M.1, M.2, M.3 and M.5 ({{Eq. 7|ax:S4.E7}}), M.4's Hebbian outer product with its norm rescaling ({{Eq. 16|ax:S4.E16}}) and M.6's top-k slot write ({{Eqs. 24 to 28|ax:S4.E24}}). The write projections are fixed random maps, which is faithful: the paper never trains them ({{§5|ax:S5.SS0.SSS0.Px2}}). What is illustrative is the input: 600 turns of random latents with d = 32 features and 8 tokens per turn, instead of Flan-T5-XL's 2,048-wide encoder states. The row counts (64 or 640), the Hebbian size (scaled to d = 32 in the paper's 256 : 2,048 and 810 : 2,048 ratios), the 8 of 64 or 640 slots and γ are the paper's ({{§6.2|ax:S6.SS2.SSS0.Px2}}). Everything runs in float64 in your browser, and check_sim.py checks this JavaScript against an independent NumPy implementation of the same equations: across 15 cases the largest relative difference is about 10−13.

The bank cannot be read without the trained read adapters, which were not released, so the simulation measures what any read could find: how much of the bank a turn still accounts for after l more turns, and how many different rows the bank actually holds.

Defaults reproduce

At γ = 0.95 the attention-coupled bank is an exponential moving average: a turn's weight after l turns is 0.95l, so 0.95256 ≈ 2.0 × 10−6, the effective window is 1/(1 − γ) = 20 turns, and the weight drops below bfloat16's 2−8 after 109 turns. These follow from {{Eq. 7|ax:S4.E7}} and the printed γ ({{§6.2|ax:S6.SS2.SSS0.Px2}}) and are recomputed in recompute.py; the chart's curve follows the same slope, independently. Keeping 1% of a turn for 256 turns would need γ ≥ 0.9822 (try it on the slider). Not reproducible here: the recall rates themselves, which need the trained adapters and Flan-T5-XL.

Does a ten times bigger bank hold more?

The 10x results are read as "capacity is doing much of the work" ({{§6.4|ax:S6.SS4}}). Capacity only helps if different rows hold different things. In the attention-coupled write every row's key is computed from the row itself, so rows that are equal get equal attention and receive equal updates. The animation shows the 64 rows of a 1x bank (one column each, 32 features down) after each turn, from a zero start and from a small random start.

Colour: each cell's value divided by the largest absolute value in the bank at that turn (blue positive, orange negative). Spread: the rows' distance from their mean, as a share of the bank's norm. Random latents, d = 32, seed 7; illustrative.

What this cannot show: real encoder states are not random, and a trained read adapter might extract something from a bank whose rows agree (a single averaged vector of the last 20 turns still carries recent context). What it does show is that, as written, ten times more rows add no independent storage to the attention-coupled bank, and at 10x the slot rule from a zero start only ever writes 64 of its 640 slots, because ties go to the same first slots (from a small random start it writes 120 of them in 600 turns). The paper does not state the initial bank, so both starts are shown.
