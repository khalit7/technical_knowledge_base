Schedule the curriculum

The paper's curriculum ({{§4.2|ax:S4.SS2}}, {{Figure 5|ax:S4.F5}}) in one picture: a pool of 120 user-turn examples, each with router scores over C0 to C3, is split into three stages of 40. Run it in routing order (hard or soft score, Eq. 2) or the way plain SFT does it, shuffled, and watch the score the model sees over training. Change the traffic, how sure the router is, and how many easy examples are held back for later stages.

The steps, for the ordering chosen in the card

  1. Score the pool. Each example gets the router's four tier scores π, re-estimated from the request and history before the first supervised response. Soft score: the score-weighted mean tier (Eq. 2).
  2. Sort by score. Line the examples up by soft score, lowest left. The soft score is continuous, so examples assigned the same tier still get a definite order.
  3. Hold some easy examples back. Pick a share of the lowest-scored third (outlined) and set it aside for stages 2 and 3, so the end of training is not made only of high-demand turns (§4.2).
  4. Stage 1. The lowest-scored remaining examples fill the first third.
  5. Stage 2. The middle of the ranking, plus half of the held-back easy examples.
  6. Stage 3. The highest-scored examples plus the other half of the held-back ones. Every example is used exactly once per pass.
  7. Train. Stages run in order with one optimizer and one learning-rate schedule (no reset); within a stage the order is shuffled here. The line is the mean soft score of the last 10 examples seen; dashed is the same pool shuffled.
  1. Score the pool. Same router scores; the hard score is just the assigned tier, 0 to 3 (Eq. 2).
  2. Sort by tier. Four flat steps: within a tier the order is arbitrary, so a stage boundary can cut through a tier at random.
  3. Hold some easy examples back. The same share of the lowest third is set aside for later stages.
  4. Stage 1. Lowest tiers first.
  5. Stage 2. Middle tiers plus half the held-back examples.
  6. Stage 3. Highest tiers plus the rest of the held-back ones.
  7. Train. The same staged order, by tier. Compare the line with the soft version: fewer distinct levels, same overall rise.
  1. Score the pool. The same pool, with the same router scores, which plain SFT ignores.
  2. Shuffle. Plain SFT orders examples at random.
  3. Split into thirds. The same three thirds of training, for comparison: each third is a random sample, so every stage looks like the whole pool.
  4. Train. The model sees the same mix of demand from the first step to the last. This is the baseline the paper does not run against.

What is the paper's and what is not. Eq. 2's two scores, three roughly equal stages, higher scores later, some lower-scored examples reserved for later stages, each example used once, no optimizer reset: the paper's. The pool, its score distributions, the router-confidence knob and the reserve rule (a random share of the lowest-scored third, split evenly between stages 2 and 3) are illustrative: the paper gives none of them. Each dot is one example, coloured by its nearest tier (C0 faint to C3 strong).

What this cannot show
Whether the ordering helps. The paper never trains the same data shuffled, so there is no number for "routing curriculum against no curriculum" (see {{How much to believe|tab:t-read:s-trust}}). The picture shows what the method does to the order of the data, which is all the paper specifies.
