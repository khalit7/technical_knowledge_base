In Evolution a creator edits its own code harness, spends one of ten "pairs" to score a version on 100 SWE-Pro tasks and 89 Terminal-Bench tasks, reads the result, and edits again; at the end it declares one version final ({{§3.2|ax:S3.SS2}}). After every run ended, the authors scored each version on 630 more SWE-Pro tasks that the creator never saw. Before Evolution: how two creators built their first harness

Creation trajectories for code, from the appendices: the same task, two styles. Neither got a settled SWE task right during development, which is normal with one to three development cases; what differs is how each used the feedback.

GPT-5.5 builds iteratively ({{Appendix F|ax:A6}})
  • Read the seed 14 times before its first edit; 20 editing operations; read 109 feedback artifacts.
  • Replaced the one-shot runner with a JSON-action tool loop in one 1,245-line agent.py (seed to final: 12 paths, +1,251 / −4 lines).
  • Each failed dev run produced a fix: artifact bookkeeping for files outside git, a parser for several JSON actions in one turn, /bin/bash instead of /bin/sh, safe de-duplication of identical reads, a parser for Codex-style patch envelopes.
  • Final record: contract smoke 1, SWE 0, Terminal 1.
Opus 4.8 designs up front ({{Appendix G|ax:A7}})
  • Read the seed 20 times; wrote 10 harness modules up front (seed to final: +1,252 / −596 lines, 1,876 lines in the end).
  • A native tool-calling ReAct loop with max_steps=120, a 6,600-second time budget and a 150,000-token soft context limit; repeated no-tool turns or an empty diff are reported as partial, not success.
  • Both settled benchmark runs scored zero (SWE 38 steps, Terminal 94 steps); Opus attributed them to the task solutions and made no harness change in response.
  • Final record: contract smoke 1, SWE 0, Terminal 0.

The 120-step limit in Opus's design is the same kind of executor-specific budget the paper blames for the Opus harness that collapsed under Gemini; the appendix does not say whether this is that harness.
