Corrections to the old version of this page

  • "37,300 runnable environments": 37,273 environments an LLM judge found task-sufficient, judged on available context, not on building or running ({{Appendix B.2|ax:A2.SS2}}). 1,464 of them are SWE repositories used only in the transfer ablation; the main corpus comes from 35,809 terminal environments.
  • "then fills in the dependencies": the completion agent also writes missing source, data and configuration; on average 87% of a completed terminal workspace's files ({{Table 13|ax:A1.T13}}).
  • "The larger gain on the multi-round evaluation is consistent with the depth axis being the more valuable of the two": the two gains are on different metrics and cannot be compared. Single-WS data alone takes MT@4 from 6.3 to 18.4; Multi-Round adds 2.6 more ({{Table 9|ax:S6.T9}}), and the Full Mixture scores below Single-WS + Multi-Round. The axis the paper's own scaling ablation favours is the number of environments ({{Table 10|ax:S6.T10}}).
  • "the supply it unlocks is proportional to deployed agent usage": true of the idea, not of this paper's data: 96% of its terminal environments come from LFM2-Terminal, whose rows (all 640 we sampled) are DeepSeek-V3.2 rollouts on generated tasks, not deployed usage.
  • "The obvious open risk, which the abstract does not address, is distributional": the abstract does not, but the paper's limitations section does ({{§7|ax:S7}}), and its Figure 5 shows the skew (84.7% Python).
  • "Terminal-Bench 2.1, which as of 2026-09-07 is one version behind current (4.0)": the leaderboard shows 4.0 as current (checked 3 October 2026); whether any version came between 2.1 and 4.0 is unconfirmed here, so "one version behind" is dropped.
  • "+11.9 on Terminal-Bench 2.1": correct, under Terminus2-XML; under Claude Code the gain is +10.4.
