The paper

DeepSeek Elastic Compute (DSec): A Sandbox Infrastructure for Effective Agentic Training at Scale (arXiv HTML v1)

arXiv technical report, the paper itself; the HTML version has the anchors this page links to. abstract page, PDF.

Firecracker: Lightweight Virtualization for Serverless Applications

Agache et al., NSDI 2020: the microVM DSec uses for its security-sensitive backend: why a VM boundary can boot in under 125 ms (the project's own figure).

(45 min)

EROFS: a compression-friendly readonly file system

Gao et al., USENIX ATC 2019: the read-only, randomly accessible compressed filesystem every DSec image layer is stored in.

(40 min)

Fire-Flyer File System (3FS)

DeepSeek-AI: the distributed filesystem that serves image data; its README explains the large-sequential-I/O profile that shapes DSec's read and write paths.

(15 min)

The Power of Two Random Choices: A Survey of Techniques and Results

Mitzenmacher, Richa and Sitaraman, 2001: the theory behind DSec's placement engine, including why stale load information makes 'pick the least loaded' herd.

(45 min)

Core scheduling

Linux kernel documentation: the kernel feature that keeps best-effort work off the sibling thread of a latency-sensitive task.

(10 min)

DAMON: Data Access MONitor

Linux kernel documentation: the access sampler DSec uses to evict cold guest pages so the balloon can return them.

(10 min)

AgentENV

kvcache-ai: an open-source Firecracker environment platform (MIT) whose README says it powers agentic RL training for Kimi K3; the closest thing to DSec you can run.

(15 min)

E2B

E2B: an open-source sandbox service for running AI-generated code, the inference-side system the paper cites.

(10 min)
