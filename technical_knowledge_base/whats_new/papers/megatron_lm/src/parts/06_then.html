Then and now: tensor parallelism from 2019 to 2026

How runs combine tensor (TP), pipeline (PP), data (DP), context (CP) and expert (EP) parallelism.

Degrees and GPU counts are as each paper states them; the captions quote or link the line.

Each step is one later training run or system, with the parallel layout its paper reports. The box is one server (its GPUs coloured by the axis that lives inside it); the bars are the degree of each axis across the whole run, on a log scale. A degree the paper does not state is drawn dashed and marked "not stated".

  1. 2019: Megatron-LM, 8.3B. This paper: 8-way tensor parallelism inside each 16-GPU DGX-2H server (two groups per server), 64-way data parallelism across all 32 servers ({{Appendix B.1|ax:A2.SS1}}). No pipeline.
  2. 2020: GPT-3, 175B. "We use a mixture of model parallelism within each matrix multiply and model parallelism across the layers of the network" ({{GPT-3 §2.3|https://arxiv.org/abs/2005.14165}}, {{KB page|n:3c65c17b0d0d8193ac92c7648cfaca12}}): tensor plus pipeline parallelism, degrees not published.
  3. 2021: PTD-P, 1T parameters. Tensor parallelism inside each 8-GPU DGX A100, pipeline parallelism across servers, data parallelism on top: "For large enough models, we use a tensor-model-parallel size of 8", and peak performance came when "the tensor-parallel size is equal to the number of GPUs in a single node" ({{Narayanan et al. 2021|https://arxiv.org/abs/2104.04473}}).
  4. 2022: MT-NLG, 530B. "Each 530 billion parameter model replica spans 280 NVIDIA A100 GPUs, with 8-way tensor-slicing within a node and 35-way pipeline parallelism across nodes", then data parallelism "to thousands of GPUs" ({{MT-NLG §2.2|https://arxiv.org/abs/2201.11990}}): DeepSpeed and Megatron together, the "3D" layout.
  5. 2022: sequence parallelism. The same TP groups, but LayerNorm and dropout now run on a slice of the sequence instead of being duplicated: g becomes an all-gather and its conjugate a reduce-scatter, which together move what one all-reduce did. With selective recomputation, activation memory falls 5× ({{Korthikanti et al. 2022|https://arxiv.org/abs/2205.05198}}).
  6. 2024: Llama 3, 405B. "4D parallelism": TP 8, CP 16, PP 16 and FSDP-style DP 8 for the 131,072-token stage (at 8,192 tokens: TP 8, PP 16, DP 128). "Within each machine, the high NVLink bandwidth enables the use of tensor parallelism (Shoeybi et al., 2019)" ({{Llama 3 §3.3.2, Table 4|https://arxiv.org/abs/2407.21783}}, {{KB page|n:3c65c17b0d0d81aca58ccb9d720b474e}}).
  7. 2024: DeepSeek-V3, 671B MoE. "16-way Pipeline Parallelism, 64-way Expert Parallelism spanning 8 nodes, and ZeRO-1 Data Parallelism", and "without using costly Tensor Parallelism" ({{DeepSeek-V3 §3.2|https://arxiv.org/abs/2412.19437}}, {{KB page|n:3c65c17b0d0d815fb8dac9ba1e35ab81}}). For MoE models the expert axis takes the room TP had; serving still uses TP 4 with sequence parallelism for attention (§3.4.1).
  8. 2026: serving. Inference has no backward pass, so a TP layer costs 2 all-reduces per token step. It is the default way to serve a model that does not fit one GPU: {{vLLM|https://docs.vllm.ai/en/latest/serving/parallelism_scaling.html}} and {{TensorRT-LLM|https://nvidia.github.io/TensorRT-LLM/features/parallel-strategy.html}} call it tensor_parallel_size, SGLang tp_size. See {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}.

What survived

  • The split itself: column-parallel then row-parallel, with conjugate f and g, is still how every TP implementation splits attention and the MLP; sequence parallelism keeps the pair and only changes what g does.
  • The placement rule: TP of 8 inside one NVLink server, in Megatron-LM (8 of 16 GPUs), PTD-P, MT-NLG and Llama 3 ("Within each machine, the high NVLink bandwidth enables the use of tensor parallelism", {{Llama 3 §3.3.2|https://arxiv.org/abs/2407.21783}}).
  • Vocabulary-parallel embeddings and the fused cross-entropy, unchanged in Megatron-Core's {{cross_entropy.py|https://github.com/NVIDIA/Megatron-LM/blob/main/megatron/core/tensor_parallel/cross_entropy.py}}.
  • Serving: TP is how a model too large for one GPU is served across a server ({{vLLM|https://docs.vllm.ai/en/latest/serving/parallelism_scaling.html}}, {{TensorRT-LLM|https://nvidia.github.io/TensorRT-LLM/features/parallel-strategy.html}}); even DeepSeek-V3, which trains without it, serves attention with TP 4.
