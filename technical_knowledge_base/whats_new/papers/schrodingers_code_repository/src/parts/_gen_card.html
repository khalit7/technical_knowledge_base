Schrödinger's Code Repository: Have LLMs Learned SWE-bench or Memorized It? (SchrodingerRepo)

Silin Chen, Yufei Yang, Xiaodong Gu, Yuling Shi, Chengcheng Wan, Haibing Guan
Shanghai Jiao Tong University (four authors), Xi'an Jiaotong University, East China Normal University and Shanghai Innovation Institute · arXiv v1 submitted 21 August 2026, the only version so far (checked 3 October 2026)

In one line: Re-instantiating SWE-bench Verified's repositories at run time under four behaviour-preserving transformations (issue reworded, identifiers renamed, definitions reordered, code near the fix rewritten) cut Pass@1 by 6.0 to 11.2 points for three models on all 500 tasks (14.4 for a fourth, on the 300 with the strongest leakage evidence) and raised actions 1.6 to 2.2 times and input tokens 2.4 to 3.5 times; renaming alone was the costliest single level, and for the two models analysed over 80% of the extra actions went to finding code rather than editing it. On SWE-QA the score fell 4.64 points for one model and 0.55 for the other. So part of a repository-level score is knowing where to look in a familiar codebase; the study does not separate memorised names from names that simply carry meaning, and its fresh-task control (110 tasks, one model) was too small to rule out added difficulty. (Scoped on 26 October 2026 from the earlier database Takeaway, which read: "Instantiating the test repository dynamically under four behaviour-preserving transformations consistently degrades agent performance and raises interaction cost on SWE-bench Verified and SWE-QA, so part of a repository-level coding score is knowing where to look rather than knowing what to do." "Consistently" holds for Pass@1 on SWE-bench Verified, but on SWE-QA DeepSeek-v4-Flash moves 0.55 points (the paper prints 0.75) and two of its single levels score higher; and the evidence shows unfamiliar names cost exploration, not that the familiar ones were memorised. The Notion property needs the same edit.)

How far to trust it: Believe the direction: renaming a repository's own identifiers reliably costs agents exploration and a few points of Pass@1. Do not read it as proof of memorisation. The renamed names also lose meaning, the one control for difficulty (one model, 110 fresh tasks, 19 solved) could not have detected the drop it was meant to rule out, Gemini's 14.4 points come from the 300 most-leaked instances, two printed changes are wrong, and the released code builds Levels 1 and 3 differently from the text.
