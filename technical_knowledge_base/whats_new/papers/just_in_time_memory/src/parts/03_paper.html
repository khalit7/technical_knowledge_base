@@CARD@@

The idea in one sentence: store past trajectories raw and let a curator write each new task its own compact briefing from them once the task is known, so nothing is thrown away before anyone knows what it is for, and the briefing is graded by that task's success at once; in the paper the untrained version already beats write-time memory in 15 of 17 like-for-like comparisons, while most of the headline +16 points comes from RL-training the curator.

You need: GRPO's group-relative advantage, which trains the curator ({{RL for LLMs|n:3c65c17b0d0d818c9bcff7177325fe56}}); agent memory designs in general ({{Context engineering|n:3f15c17b0d0d811292cee46514370431}}). New terms: write-time curation (distil a finished trajectory into a fixed artifact when it is stored); read-time curation (keep it raw, distil when a task retrieves it); curator (the model that turns retrieved trajectories plus the task into a payload); payload (the briefing prepended to the executor's prompt); executor (the frozen model that does the task); quality gate (the executor judging its own trajectory before it is stored); -base, -gpt, -gemini (the curator untrained, or a prompted frontier model).

Problem

[[S1|§1 Introduction]]

An agent solving tasks one after another should learn from its own past. Agentic memory does that, and almost every system curates it at write time: when a task ends, its trajectory is distilled into a fixed artifact (a verbal reflection as in Reflexion, an insight, a workflow, an executable skill, a reasoning strategy as in ReasoningBank) that later tasks retrieve by similarity ({{§1|ax:S1}}, {{§2|ax:S2}}; memory designs in general: {{Context engineering|n:3f15c17b0d0d811292cee46514370431}}).

Curating then, the paper argues, has two costs that come from one root: the decision is made without knowing what it will be used for ({{§1|ax:S1}}).

  1. Information loss is premature and irreversible. Whatever the distillation discarded is unavailable to every later task that needed it.
  2. One fixed artifact must serve many different future queries. The paper's example: the same household trajectory may teach one task a state change (heating or cooling an object) and another a placement strategy. A trajectory holds many possible lessons, and which one matters depends on a task nobody has seen yet.

Learning a write-time curator adds credit assignment: a storage decision is only graded when some later task retrieves the artifact, so the reward is delayed and badly attributed. SkillOS, the closest prior work, trains a skill curator with RL and has to group related tasks into streams to manufacture that signal ({{§1|ax:S1}}, {{§2|ax:S2}}).

Idea

[[S1.F1|§1, Figure 1]]

Keep the raw trajectories and curate at read time, just in time, once the task to be solved is known ({{§1|ax:S1}}).

The bank becomes a passive store of complete trajectories. When a task arrives, a retriever picks past trajectories and a memory curator reads them together with the new task and writes a compact, task-specific payload, so one stored trajectory can yield a different payload for every task that retrieves it: memory reconstructed, not replayed ({{§1|ax:S1}}).

It also changes learning: the payload is consumed by the task it was written for, so that task's success grades it at once, with zero delay and no task grouping ({{§1|ax:S1}}, {{§3|ax:S3}}). The animation runs the paper's own example ({{Figure 3|ax:S4.F3}}) through both designs; the trajectory's steps and the write-time artifact are illustrative, the artifact following the paper's ReasoningBank-style distillation prompt ({{Appendix A|ax:A1}}).

One past trajectory, two later tasks.

Note that JitMem never hands raw trajectories to the executor: it still distils, only later and with the task in view ({{Connections|tab:t-read:s-conn}}).
