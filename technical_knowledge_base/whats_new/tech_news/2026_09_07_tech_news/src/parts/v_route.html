One agent session, with and without routing

The same five requests in a Java codebase, run twice. Back row, without routing: Claude reads every file itself, so the text stays in its context and is re-read on every later call. Front row, with the post's routing: a PreToolUse hook blocks any Read of a file over 350 lines and sends the files to a bulk-reader mode on a cheap worker model, which returns a short summary; boilerplate goes to a code-writer mode that writes straight to disk. Targeted reads, edits and reasoning stay with Claude. Each column is the context Claude re-reads on one call, stacked by what it holds and drawn to one scale, so a row's total height is the input Claude processes over the session. Dots show where text goes on each turn. Drag to turn the scene.

Step by step

  1. Start: the same project, twice. Both rows begin with the same 12,000-token context (system prompt, tool definitions, project notes), the first column in each. The pile on the left is the codebase's five files for turn 1, at the same token scale.
  2. Turn 1: five files, 4,100 lines. "What does this service do?" needs files of 1,200, 950, 820, 700 and 430 lines. Without routing all five Reads are allowed and 41,000 tokens of source stream into Claude's context: the call reads 53,300 tokens. With routing the hook blocks every Read (each file is over 350 lines) and the files go to the worker, which returns a 4,100-token summary: 90% fewer, the post's figure (set by construction here). The call reads 16,400.
  3. Turn 2: a follow-up on the same files. "Which methods call the database?" Without routing nothing new is read, since the files are already in context, but all 41,000 tokens of source are re-read with the call: 53,600. With routing the same paths are re-sent to the worker (41,000 more worker tokens: "free where it matters", the post says) and a 1,200-token answer lands: 17,900.
  4. Turn 3: tests from a reference file. "Write tests for UserService like OrderTest.java": a 600-line reference and a new file of about 450 lines. Without routing Claude reads the reference (6,000 tokens) and writes 4,500 tokens of test code as its own expensive output: 64,100. With the code-writer mode the worker matches the reference and writes the file to disk; Claude sees a 150-token confirmation: 18,050. This is the part the issue had backwards: the code writing also goes to the cheap model.
  5. Turn 4: a targeted fix. "Fix the null check at line 212": a Read of 60 lines (600 tokens), then a 200-token edit. Editing cannot be delegated (the worker's summaries have no reliable line numbers), and the hook lets targeted reads through, so both rows do the same: 64,900 and 18,850.
  6. Turn 5: a thread-safety bug. "Find the thread-safety bug in Cache.java": 300 lines, under the threshold, so both rows read it (3,000 tokens) and reason for 1,500 tokens: 69,400 and 23,350. In the post's tests the worker found surface patterns but missed a subtle thread-safety bug that Claude spotted in seconds, so debugging, architecture and safety-critical code are excluded from routing.
  7. The session: add up the columns. Without routing Claude processed 305,300 input tokens over the five calls; with routing 94,550 (69% fewer), and its output fell from 6,800 to 2,300 tokens. The worker handled 92,500 tokens on the cheap model. In this illustrative session the saving is below the 90% of one bulk read, because targeted reads, edits and reasoning still go through Claude.
