One agent turn, two architectures: V4-Flash against V4.1-Flash

The same turn of an agent loop through both models at once: a tool result arrives that is not in the cache, the model reads it (prefill), keeps its cache, then writes its reply (decode). Each tower is one model's layer stack, one slab per layer, drawn to scale (43 layers for V4-Flash on the left, 40 for V4.1-Flash on the right); a slab's depth is the whole prompt, because prefill processes all its tokens together, layer by layer. A layer that keeps a global cache has a plate on its outer side whose length is the bytes it stores per prompt token, so the area of the plates is the cache. V4-Flash is decoder-only: every prompt token runs every layer and 41 layers each keep their own cache. V4.1-Flash splits the stack: the prompt runs only the 20 encoder layers, the decoder's cache is projected once from the encoder's output, and only the last 128 prompt tokens are replayed through the decoder. Colours: grey, a layer that attends only to a sliding window and keeps no global cache; orange, a layer that writes a cache (its plate in pale orange; the glass plate is V4.1-Flash's decoder cache, written without running the layer); teal, a layer that reuses an earlier layer's cache; purple, the decoder replay; blue, the generated token.

Step by step

  1. The same tool result arrives at both models. The agent called a tool and the result has to be read before the next reply: 32,768 new tokens with no cached prefix for them. Nothing has been computed yet. V4.1-Flash is the bigger model (552B against 284B total parameters), but it is cut into a 20-layer causal encoder (layers 0 to 19) and a 20-layer decoder (20 to 39).
  2. Layers 0 and 1: sliding window only, in both. All prompt tokens go through each layer together (prefill is parallel across tokens), one layer after another. The first two layers attend only to the last 128 positions and keep no global cache. In V4.1-Flash, layer 1 also injects Engram, a hashed n-gram memory.
  3. The prompt climbs the stack: 41 caches against 3. In V4-Flash each of the 41 remaining layers computes attention over the whole context and stores its own compressed cache: 21 CSA layers (one entry per 4 tokens, plus indexer keys: the long plates) and 20 HCA layers (one entry per 128 tokens: the thin ones). Nothing is shared between layers; the prompt costs N x 43 layer passes. In V4.1-Flash's encoder, layers 2, 8 and 14 each compute and store one cache copy (two adjacent tokens merged into one FP4 entry); the five layers after each one reuse it with their own queries instead of storing their own (the teal dots). Only 8B parameters are active per prompt token, against 13B.
  4. V4.1-Flash: the decoder's cache is projected from the encoder's output. The decoder never runs on most of the prompt. Its single global cache (layer 20, one entry per token: the glass plate) is a projection of the encoder's final hidden state, so it is written without running layers 20 to 39 on those tokens. The decoder's other layers reuse or re-index it.
  5. V4.1-Flash: only the last 128 tokens run through the decoder. Decoder layers still keep a sliding-window cache, which needs real decoder activations, so only the last 128 prompt tokens are replayed through layers 20 to 39 (the purple sliver at the front, drawn to scale with a minimum width so it stays visible). The report finds the effective receptive field of the window is small enough that this costs only negligible quality.
  6. Prefill done: about half the layer passes, a quarter of the cache. V4-Flash's prompt cost N x 43 layer passes and left 3,514 bytes of global cache per token in HBM for as long as the session lives. V4.1-Flash's cost N x 20 + 128 x 20 layer passes, the report's O(NL/2 + n_win L/2), and left 890 bytes per token, about a quarter.
  7. Persisted for the next turn. V4-Flash writes both the global cache and the sliding-window cache to the SSD cache; the report says the sliding-window part (grey) is nearly half of that store. V4.1-Flash no longer writes the sliding-window cache to SSD: it lives for minutes in a pool of host memory, and a miss is repaired by replaying 128 tokens. Its persistent store shrinks to about 1/8 of V4-Flash's.
  8. Decode: each new token runs every layer. Generation is unchanged in shape: every new token runs all 43 layers of V4-Flash with 13B active parameters, reading 41 separate caches, or all 40 layers of V4.1-Flash with 16B active parameters (more than V4-Flash's 13B), reading 4 cache copies instead of 41 (the dots). The saving is in the prompt and the cache, which is where long agent loops spend.

Defaults reproduce DeepSeek's published 890 bytes per token for V4.1-Flash and 3,514 for V4-Flash (the {{V4.1-Flash report|https://arxiv.org/abs/2609.19969}}, Figure 1) independently, from the {{V4.1-Flash|https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash}} and {{V4-Flash|https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731}} configs (layer counts, compress_ratios, kv_source_layer_ids, head and indexer widths) with the entry sizes worked out in {{zartbot's breakdown|https://zartbot.github.io/blog/model_arch/dsv41flash_arch/en.html}} (src/recompute.py); the same arithmetic gives the report's 437x against DeepSeek LLM 67B. The prompt's layer passes follow the report's own formula, N x L against N x L/2 + 128 x L/2. Derived: parameter compute is 2 x active parameters per token (13B for V4-Flash, 8B for V4.1-Flash's encoder and 8B more for its decoder), spread evenly over the layers; attention compute, which grows with context, is left out. Published, not recomputed: the persistent cache ratio (about 1/8: SWA cache no longer persisted, which nearly halves it, times the 1/4 global cache); the SSD blocks are drawn to that ratio. Layer-by-layer detail of the V4.1 stack is on the {{DeepSeek page|n:3c65c17b0d0d81a2ae7ec6796947a235}}.

Where the factor of four comes from

The global cache each prompt token leaves in HBM, built up one change at a time from the two models' config.json files: sharing caches across layers, then finer sequence compression (which goes the other way), then the FP4 main entry. Each bar is to scale; the arithmetic is under each bar.
