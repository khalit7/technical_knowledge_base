"The Hegel skill sortof sucks right now"

(1 min)

Without the prompts, nothing can be reproduced

gregwebs, genxy, FranciscoCarlos and luckydata, Hacker News, 8 September 2026, critique: Asked for the exact prompts, the Audit instruction and the harness so others could rerun their own workflows; one called the result "essentially devoid of any value" without them. Right on the facts: no prompts, transcripts, tests or scoring code are public. jakevoytko replied with a list of what makes such benchmarks hard to publish at all.

(3 min)

Left alone, the agent's Verus spec restates the implementation

emtel, Hacker News, 8 September 2026, practitioner report: Agrees with the Verus finding and adds the case the post did not test: once a person had worked out an accurate specification, Claude proved the code against it without trouble and found real bugs. gz09 and gr_norm made the same point: a formal tool helps when a person writes the spec.

(1 min)

Mutation testing as a build gate cannot be skipped

vetronauta, kqr and coder-pm, Hacker News, 8 September 2026, critique: The agents did mutation testing by hand; a mutation tool wired into the build, failing it when mutants survive, is something an agent cannot quietly skip. The post tested the instruction, not the gate; coder-pm reports a gate catching a test that passed on both the fixed and the mutated code.

(2 min)

Testing cannot be separated from how the code is built

siscia and sceptic123, Hacker News, 8 September 2026, critique: Most of effective testing is architecture (dependency injection, sans-IO), and one-shot greenfield runs with a bare instruction do not answer the title's question. yorwba answered with the post's own framing: it tests a user with no testing expertise who names a technique.

(3 min)

Alloy fell on its face against fuzzing in a real project

lmeyerov, Hacker News, 8 September 2026, practitioner report: Longer-running use on a GPU graph-query engine agrees in direction: Alloy did badly against fuzzing even with guidance; guided fuzzing, written specifications next to the code and fresh-context adversarial review worked; one-shot auto-written skills evaluated badly.

(3 min)

Since the article (the author's rerun and the tested skill, checked 27 November 2026)

Test/verification technique effectiveness with Astra

2 November 2026: The author's rerun with GPT-6 Astra (feed date 2 November; Hacker News 16 November, 91 points, 17 comments). Zstd is saturated (over 99% fully correct at about $1, medium). On IMAP (xhigh, 80 runs each) Default passes 76 of 80 and the four best conditions 77; all 27 are as alike as one coin (our recompute: chi-square 29.2 on 26 degrees of freedom, p = 0.30). On Pandoc (Ultra effort, 25 runs each, about $90k) many conditions sit above Default's fitted cost curve and agents finally used structured fuzzing, property-based tests and differential testing as intended; TDD again did worse, ACL2 and Proptest again did well, and the author's own skill now did worse. He calls the error bars wide and the gains plausible, not shown.
