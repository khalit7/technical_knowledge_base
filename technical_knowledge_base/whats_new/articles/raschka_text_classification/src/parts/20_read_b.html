1. Before transformers: count the words, or read them in order

[[ah:§1-language-modeling-and-classification-in-the-pre-transformer-era|Section 1]]

Bag-of-words with logistic regression scored 89.9%, and the author still starts every text problem with it. Each vocabulary word gets one position holding its count, so any text becomes a fixed vector and a linear model learns which words push towards which label; word order is lost ({{the dog bites the man|ar:the dog bites the man}} and its reverse are one vector). He calls it {{logistic regression remains my go-to baseline|ar:logistic regression remains my go-to baseline}}, the instinct a later test of Jev took up (responses). A Hacker News commenter named the step the article skips: averaged word vectors, as in fastText.

Reading in order did not help until the model was pretrained. An LSTM trained from scratch overfit: {{an LSTM RNN achieved only 85.66% accuracy|ar:an LSTM RNN achieved only 85.66% accuracy}}. ULMFiT (2018) pretrained the same kind of network as a language model, fine-tuned it, and {{achieved an impressive 95.4% test accuracy on IMDb|ar:achieved an impressive 95.4% test accuracy on IMDb}}: on the same test set, pretraining bought 9.74 points, the lesson the rest of the article builds on and one our Sequence models page does not tell. A text CNN slides filters over windows of word vectors and max-pools over positions so any length gives a fixed vector ({{global max-pooling would be a better option here|ar:global max-pooling would be a better option here}}); {{such a CNN gets about 90.07% accuracy|ar:such a CNN gets about 90.07% accuracy}}. One aside is loose: state-space models are not {{still has to be processed sequentially|ar:it still has to be processed sequentially}} in training, where a parallel scan covers the sequence ({{Mamba|n:3c65c17b0d0d8179984fc3a1fee4c36a}}).

2. Transformers: three ways to get one label

[[ah:§2-transformers|Section 2]]

An encoder reads a classification token; a decoder must read its last token. BERT-style models {{have a classification token at the first position|ar:have a classification token at the first position}} that sees the whole text, so a small head on it is fine-tuned ({{ModernBERT gets approximately 95% accuracy|ar:ModernBERT gets approximately 95% accuracy}}). A GPT-style model gets a small head too, but under the causal mask only the last position has seen everything, so the head reads {{the final non-padding token's hidden state|ar:the final non-padding token’s hidden state}} (GPT-2 124M, about 92%). An encoder-decoder can do either, or train its decoder to write the label, which the article names {{call this approach text-to-text classification|ar:call this approach text-to-text classification}}; prompting a chat model is that without training, {{unnecessarily brittle and inefficient|ar:unnecessarily brittle and inefficient}} for a fixed domain. Which family wins at equal size is on {{Families and objectives|n:3fd5c17b0d0d8105b616c17c1439f766}}; its newest encoder-decoder example, {{being DeepSeek V4.1 Flash|ar:being DeepSeek V4.1 Flash}}, is not there yet.

The hero's accuracies are not one experiment. They come from three test sets (checked in the linked notebooks). Read the ladder for its two big steps, pretraining (about +5 points) and no training at all at the top, not for one-point gaps.

3. Jev: three question types, and 96.47% on IMDb without training

[[ah:§3-jev-overview|Section 3]]

Jev takes text and typed questions and returns probabilities, not text. TypeSafe launched it on 15 September 2026 with {{three main API types|ar:there are three main API types illustrated below}}: Choice (one of N described options, a probability each and a confidence), Noul (one yes probability; several make a multi-label classifier) and Score (a level on an ordered rubric). The article's framing is the useful one, {{the ChatGPT moment for classification|ar:the ChatGPT moment for classification}}: one general model instead of a classifier per task. Prices, vendor speed claims and the decision models that followed are on {{Other notable providers|n:3c65c17b0d0d8154ba44e521a4ed8749}}. The confidence field is {{different from the probability assigned to the winning|ar:different from the probability assigned to the winning}} class: TypeSafe's docs define it as (pmax − 1/n) / (1 − 1/n), so a binary answer at 0.74 has confidence 0.48; calibration lives in the probabilities.

On the 25,000 test reviews Choice scored 96.47% in 22 minutes 24 seconds for $0.6492 (Noul 96.20%, $0.6345), above every trained model in the article, with no IMDb examples. The author names the catch: {{we don't know if the IMDb test set|ar:we don’t know if the IMDb test set}} was in Jev's training data, and IMDb has been public since 2011. A repeat run differed slightly, and the Choice to Noul gap (67 reviews, 0.27 points) is within that noise. A fine-tuned ModernBERT matched it after {{23 min to fine-tune on the training set|ar:23 min to fine-tune on the training set}}, and can do nothing else. So the old rule (a cheap LLM for one-off decisions, {{fine-tune a custom classifier if we want|ar:Fine-tune a custom classifier if we want}} to repeat them) gains a middle option, still beaten by a tuned specialist on a narrow high-volume task.

One comparison is attributed loosely. The article says Jev {{claims to be on par with GPT-5.6 Luna|ar:claims to be on par with GPT-5.6 Luna}}; TypeSafe's launch text names GPT-5.6 Terra as closest "at intelligence to Jev on average", and its workflow evaluations measure agreement with GPT-6 Astra and Fable 5.1, not correctness.
