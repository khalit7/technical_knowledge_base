The idea in one sentence: fine-tune a small coding model to write, for each keypress, the edit to a terminal's screen; with no shell behind it, whatever stays consistent between commands is what the network carries in its context.

1. One keypress in, one screen edit out

[[ah:how-it-sees-a-terminal|How it sees a terminal]] [[ah:copying-rows|Copying rows]]

A terminal is a grid, not a stream: clear sends the cursor to the top, so {{I need to predict changes to the screen|ar:I need to predict changes to the screen}}. After a snapshot of the screen, each keypress goes in as a terminal's bytes, and the answer names rows to rewrite and the cursor: l at the prompt gives ROW_0 17 'l', CURSOR 0 18 1. {{Nothing gets cleared first|ar:Nothing gets cleared first}}, so a row's edit runs from its first changed cell to its last. Idle time goes in as {{a WAIT token|ar:the model gets a WAIT token}}.

Copying a row makes a scroll cheap. Rewriting every row costs {{around 3,000 tokens for a single keypress|ar:around 3,000 tokens for a single keypress}}; with ROW_0 COPY 1, {{a scroll costs three tokens per row|ar:A scroll now costs three tokens per row}}, and a copied row can be patched (Fig. 1, Enter at the bottom: 98 tokens against 901).

A tiny vocabulary, every output valid: Qwen's {{256 byte tokens|ar:Qwen already has tokens for all 256 byte values}}, 64 row tokens and a few operations make {{333 tokens|ar:tiny vocabulary of 333 tokens}} (the demo lists 334, with a draft marker), and {{decoding is grammar-constrained|ar:Decoding is grammar-constrained}} ({{Sampling and Decoding|n:3c65c17b0d0d8115bafcda29a2c7086e}}).

2. Training data: real programs in Docker, typed like a person

[[ah:generating-the-training-data|Generating the training data]]

The recordings he found lacked {{keystroke-to-screen alignment|ar:precise keystroke-to-screen alignment}}, so he made his own: vim, python, tmux, man and snake in offline Docker containers, random personas and screen sizes, one-key typing with {{1.2% typos|ar:typo rate to 1.2%}}, and {{35% of sessions starting partway through|ar:35% of sessions start partway through}}: {{336k episodes|ar:landed on 336k episodes}}, about 2B tokens.
