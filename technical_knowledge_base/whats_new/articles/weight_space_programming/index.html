Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights

Rikiya Takehi, Jayden Teoh, Alex Zhang, Omar Khattab (MIT CSAIL) · published 2 November 2026

In one line: In one blog post with complete released logs, mostly single runs, GPT-6 Astra named what small networks (17K to 24K weights) were trained for from their raw weights with no tools, wrote MinAtar policies from all-zero weights that beat PPO at 100M steps in all three games (at 500M steps only in Breakout), and, with a Python kernel over Qwen3.5-0.8B's weights and 50 forward passes on practice problems, made a rank-one edit to 131,072 weights (0.016%) that cut thinking loops and raised MATH-500 from 7.9% to 48.1% in a looping-prone setting (thinking on, 32,768 tokens). The same procedure did not improve Gemma 3 270M, which rarely loops.

How far to trust it: Believe the small-network results as demonstrations: the logs are complete, and independent runs reproduced the game naming and the Breakout writing, with the caveat that reading leans on the input layer. Read the Qwen result as an agent doing interpretability with tools, not as reading weights: the prompt named repetition as a failure worth fixing, the direction came from activations measured in forward passes, the edit is directional steering written into one matrix at strength 6, and each budget is one run beside others that made no edit. The evidence, judged.

The idea in one sentence: a frontier LLM, used as it is with no training for the job, can treat a neural network's weights like source code, reading them to say what the network does and writing or editing them to change it; the post shows this cleanly on networks of 17,000 to 172,000 weights given as text, while its headline result on a 0.8-billion-weight language model was an agent with a Python kernel and 50 forward passes doing an interpretability edit.

You need: what PPO trains (Policy gradients and actor-critic); what a transformer block's matrices are and that each MLP neuron writes one column of the down projection into the residual stream (The transformer from zero); induction heads (Topic: llm-architecture, Inside a real model tab).

New terms: Weight-Space Programming (the authors' name for treating weights as a program to be read and written, "instead of leaving them entirely to an optimizer"); Astra (OpenAI's GPT-6 Astra, the reader and writer in every experiment); forward pass (here a budgeted call that runs the network on a batch: up to 128 games of Go, or up to 512 practice answers for Qwen); copying head (the post's word for an induction head); direction (a unit vector u in the residual stream); steering (adding or removing a direction in a model's activations to change a behaviour).

The claim: weights are a program an LLM can read and write

Weight-Space Programming

The post argues that reasoning-driven optimisation, already used on prompts, harnesses and training code, now reaches the weights themselves. We let LLMs improve text artefacts because humans can edit text by hand; weights were left to symbolic optimisers such as Adam because nobody can edit them by hand. The authors claim that has changed: a general-purpose LLM, from a natural-language goal and without gradients, can now read what a network computes and write weights that compute something else (in the article).

The evidence is eight experiments in three groups, all done by GPT-6 Astra: reading (what game, what shape, what language, which model is sycophantic), fixing (a stuck car policy, Qwen3.5-0.8B's math) and writing from scratch (three MinAtar games, 9×9 Go) (the list). Each experiment has a Setup box saying what Astra was given. That box is the most important thing on the post, because what Astra was given changes from experiment to experiment, and the hero figure above sorts them by it.

The wording moved after publication. The first archived copy (2 November, 18:22 UTC) said LLMs read and write weights "well past what we'd expect from humans or conventional algorithms"; the current TL;DR says "sometimes with tools such as a Python kernel and sometimes from the raw weights alone" and that the results "may extend beyond" what we would expect (the current TL;DR). The experiments and numbers did not change; the 12 November addendum came later (below).

Reading small networks with no tools (Experiments 1 and 2)

Experiments 1 and 2

Given only the 17,253 weights of a PPO policy as text, Astra named the game for all four networks without being told the options. The four games (grid versions of Breakout, Pong, Pac-Man and Freeway) share one 10×10 grid, the same five actions and the same MLP shape, 500 → 32 → 32 → 5, so the game is only in the weight values (Setup). The post's account of how: where each input channel's first-layer weights concentrate (for Breakout, the agent's weights lie along the bottom row, where a paddle lives) and which actions the output layer tells apart (in the article).

Given three diffusion models' weights, it named the shape each generates (circle, square, triangle; MLP 160 → 64 → 64 → 144, 23,824 weights, no forward pass allowed) by reading the output layer, where each hidden unit's weights draw one piece of the shape's edge. It drew every shape as an outline although the models generate filled shapes, which the authors read as a sign it reasoned about the geometry of the weights rather than computing a forward pass in its head (in the article).

Both readings rest on the first or the last layer, the two places where the weights are tied to something with a meaning (pixels on a grid, actions, output pixels). The authors say so themselves before Experiment 3 (in the article), and two later studies measured it: shuffling the weights or keeping only the first layer, and reading new games (Responses).

Reading the middle of a language model (Experiment 3)

Experiment 3

With the input and output layers removed, Astra still named the training language of three character-level transformers and found every copying head, with no false ones. The models (4 layers of 6 heads, width 384, 7.16 million weights) were trained on Python code, Japanese in romaji and English Wikipedia; Astra got the four middle blocks, with no labels on the 384 dimensions, and up to 100 runs of Python to analyse them, but could not run the network or any layer on any input (Setup). It was right in both attempts on each model, with stated confidence of 0.48 to 0.62.

How it found the copying heads is a textbook method it was never shown. It found a first-layer head that attends one character back, then multiplied weight matrices to find the later heads that search using what that head writes: the previous-token and induction-head circuit of Elhage et al. (2021), whose two-head mechanism the knowledge base explains on the Topic: llm-architecture page (Inside a real model tab). Code repeats names far more than prose, so many copying heads pointed to Python; romaji stood out because the last block writes in fewer directions, as if it had fewer letters to tell apart (in the article).

Ground truth: each head was scored by running the model on a random string repeated twice; copying heads scored 0.22 to 0.55, every other head at most 0.02. Astra never saw these scores.

Writing and fixing networks (Experiments 4, 5 and 6)

Experiments 4 to 6

Fixing a stuck policy: one reply, no tools, 3.5% of the weights changed, and the car succeeded in all 1,024 episodes. PPO, trained for a billion steps on a Kinetix level where a car must back up before jumping a red strip, learned to drive straight at the ramp and stall (0 of 256 episodes). Given all 171,664 weights, the scene and one recorded failed episode, Astra explained the local minimum and added a small separate path through a few units per layer that reads the car's position and speed, backs the car up, and switches off once the wheel is past the strip (in the article).

Writing from nothing: networks for three MinAtar games, written as text in one reply from all-zero weights, beat PPO trained for 100 million steps in all three. Astra had the game's rules and source code and the network's layout (600 → 32 → 32 → 6), and no data, loss, gradients, tools or play before scoring. Against PPO at 500 million steps it scored 20 times as much in Breakout, close in Asterix and 60% in Seaquest (figure). Its method was to design a program and compile it into weights: in Breakout, the first layer computes where the ball will land and the second moves the paddle there (in the article).

Writing a 1.5-million-weight Go network needed Python, and grew stronger with runs of the network. Too big to write as text, the 243 → 512 × 6 → 82 network was built in a Python sandbox where Astra could read and save tensors but not run them; each forward pass played up to 128 games against a practice opponent. With 0 passes (one Python run of 336 lines encoding liberties, groups in danger, captures and eyes) it won more than half its games against two smaller PPO networks; with 50 passes it beat the equal-sized PPO network trained on 20 million games (in the article).

Spotting a sycophant (Experiment 7): no from weights, yes from attention

Experiment 7

From the weights alone Astra could not tell which of two fine-tuned Gemma 3 270M copies was the sycophant, in four attempts. The pairs were trained the same way on the same questions, one to give the correct answer and one to give whatever answer the user suggested (it then follows 100% of wrong guesses, the honest copy 1 to 3%); the embeddings and output layer were frozen so the difference had to be inside. Astra found many weight differences but could not map them to behaviour (in the article).

Allowed to see attention patterns on up to 16 texts it wrote (never the outputs), it picked the sycophant in all three pairs, and explained it: in the sycophant, middle-layer heads look at the user's suggestion. In the post's example, head 10.2 at the answer position puts 94.3% of its attention on the question's numbers and 0.75% on the user's answer in the honest model, against 3.5% and 85.7% in the sycophant (Figure 2). This is the first experiment where running the model was the step that made it work.

Editing Qwen3.5-0.8B (Experiment 8), and the control that did not improve

Experiment 8

Asked to make Qwen3.5-0.8B better at math without gradients, Astra edited 131,072 of its weights (0.016%) and MATH-500 rose from 7.9% to 48.1%, GSM8K from 13.8% to 67.1% and IFEval from 21.0% to 62.3%. It had a Python kernel over the weights (CPU, no GPU, up to 300 code runs), 14,744 practice problems from the GSM8K and MATH training sets, and a budget of 10, 25 or 50 forward passes; a pass either generated up to 512 practice answers or read up to 1,024 texts and returned hidden states and MLP activations (Setup; the prompt is in the logs).

What it fixed was looping, not arithmetic. With thinking on and Qwen's recommended sampling, the base model ran 85 of its first 96 practice answers to the 32,768-token limit, repeating itself; on MATH-500, 93.0% of answers hit the limit. After the 50-pass edit, 33.1% did (in the article). The gain on instruction following follows from the same cause: the loops are not specific to math. The model card warns about these loops, and turning thinking off avoids them; the authors chose thinking on because that is where the weights have the fault (addendum).

The control, Gemma 3 270M, rarely loops (8.5% of answers at its token limit), and Astra could not improve it. It found ordinary reasoning errors with no single component to switch off; no edit moved MATH-500 by more than about a point (6.8% unedited). The authors' conclusion: editing removed an obstacle that hid an ability, it did not add one (in the article).

Each budget is one run, and the released results table holds more runs than the post shows. The three edited rows are prompt version 3; the table also lists a version-2 run with 0 passes, a version-3 run with 5 passes and a version-4 run with 10 passes that made no edit, and a version-4 run with 25 passes that matched the version-3 one (14.1%). The three reported edits are three different edits: a loop direction removed from 30 matrices at 10 passes, one attention head switched off at 25, and the two-matrix edit below at 50 (exp8 README, results table). The README says the unreported runs are not part of the post; they are in the table it releases, which counts in the authors' favour.

What the 50-pass edit is, measured from the released weights

Experiment 8, the edit

The edit pushes against one direction u in the residual stream, written into 64 neurons' output columns in each of two MLPs. Each neuron j of an MLP writes its activation times one column wj of the down projection (1,024 numbers) into the residual stream. Astra's final answer gives the formula, and the released diff reproduces it exactly:

W ← W − α · u (m ⊙ uTW),   α = 6
u
the loop direction (unit length), from the difference between mean activations on four looping and non-looping contexts
m
a mask: 1 on the 64 chosen columns (neurons) of 3,584, 0 elsewhere
uTW
how much each neuron writes along u per unit of activation

At α = 6 it does not remove the direction, it reverses and amplifies it. Each chosen column's component along u goes from c to −5c; α = 1 would remove it. Measured here with src/real_edit.py on the released diff against the public base weights: the change is rank one (99.999% of its energy in one direction in both layers), the share of each column's component removed is 6.00 (5.99 to 6.01), and the two matrices change by 10.6% and 8.1% of their norm. So "0.016% of the weights" is true of the count, but each of those weights moves a lot.

The direction and the neurons came from running the model, not from reading the weights. Astra's final report says the direction was built from four matched productive and repetitive contexts at the residual outputs of layers 15 and 19, and the 64 neurons per layer were chosen from activations recorded in a forward pass. By the weights alone they are not the 64 that write most along u: only 31 of layer 15's and 18 of layer 19's chosen columns are in that top 64 (figure). The prompt itself named the target: "if the model often fails because it repeats itself and never finishes, finding and fixing what drives that repetition counts" (prompt, turn 1).

Astra checked its own edit with a control: a random direction of the same norm, orthogonal to u, gained 1.56 points (standard error 3.52) where the real edit gained 49.8 points (SE 1.5) on 1,152 held-out practice problems (10.6% to 60.4%, 579 rescued and 5 lost) (final report).

Try the edit on a toy: why it acts like steering

Because the edit only rescales the u-part of a few columns, its effect on any input is proportional to how strongly those few neurons fire. The output change is −α · u · Σj chosen aj (u·wj): an activation-dependent push along u. When the looping neurons fire, the model is pushed out of the loop; when they are quiet, almost nothing changes. That is why a UC San Diego group called it "context-dependent activation steering" written into a weight matrix, and why the post itself compares it with removing a refusal direction from a model's weights (Responses).

Predict first: the toy opens with no edit. At Astra's α = 6, editing only the 4 chosen neurons, what happens to the productive context's output along u? Then drag α to 6, and switch to "Edit all 16" to compare.

Three things to see. At α = 1 the chosen neurons stop writing along u at all (the classic "remove the direction"). At α = 6 they write against it, five times as hard as they used to write along it. Editing every column instead of the chosen few is a full projection: it also moves the productive context, which is the cost the mask avoids. In Qwen, 64 of 3,584 neurons per layer is 1.8% of the columns of two matrices; here 4 of 16 is 25%, so the toy exaggerates the share.

What the authors expect next, and their addendum

What Comes Next and Response to Comments

The authors expect it to change interpretability and optimisation, and list five uses none of the experiments tests (auditing, cheap optimisation, editing capabilities in or out, self-improvement, grafting circuits between models); the papers that tried some of them within three weeks are in Since the article.

The five uses, as the authors put them

Auditing a model from its weights without running it (finding backdoors, say); much cheaper optimisation, such as initialising a model in one shot; adding or unlearning a capability from a prompt with an edit small enough to avoid catastrophic forgetting; recursive self-improvement through a model editing its own weights; and grafting a circuit between models of different architectures where today's merging averages weights of identical ones. They say they are building a benchmark and harness (in the article).

The 12 November addendum answers four objections (Response to Comments):

  • It is a concept, not a method. The experiments are evidence that an LLM is starting to be able to do it, not a recipe; gradients are not ruled out in principle, only excluded here to show what reasoning alone does.
  • "Natively" means the LLM does the reasoning about the weights: no training loop, no gradient, no model trained for the task. Python is a tool for that reasoning; each Setup box says what was allowed.
  • The baselines are not a race. PPO puts a price in experience on what Astra did with none; a better-tuned PPO answers a different question. They compare this with GPT-3 showing in-context learning while it was still weak.
  • Astra was not compared with interpretability researchers, and may succeed by composing known techniques at scale, as models now do in mathematics.

How much of this to believe

What holds up. The release is unusually complete for a blog post: every prompt, reply, code run, forward pass, network and evaluation is in the logs (CC BY 4.0), each number in the post is mapped to the file it comes from, all 1,125 turns were audited to confirm the model's own tools stayed off (Python ran only through the experimenters' sandbox), and the edited Qwen can be rebuilt bit for bit (we did, for the two edited matrices, and both hashes match). Failures are reported, not hidden: the sycophant from weights alone, and the Gemma control. Independent runs reproduced the parts that need no lab: naming the game (Willison on an open 27B model, three of four; a LessWrong ablation study) and writing Breakout networks (514, 550 and 307 against the post's 517.4, arXiv 2611.21449).

Where the evidence is weaker than the wording.

  • Three kinds of result under one claim. Raw weights with no tools appear only in Experiments 1, 2 and 4, on 17K to 172K weights; Experiment 5 writes from zeros with nothing to read; every language-model result used Python, and the headline Qwen result also ran the model 50 times (the hero figure; Honnibal's point, which the post's own Setup boxes support). The first TL;DR ("well past what we'd expect from humans or conventional algorithms") was softened after publication.
  • The Qwen fault was named in the prompt. The task said that fixing repetition "counts" and told Astra to look for answers "cut off at the token limit (often while repeating itself in its thinking)". "Astra spots and fixes" a looping failure is therefore a diagnosis it was pointed toward, carried out well, not a discovery from the weights.
  • The Qwen edit is a known technique. A direction built from activation differences and written against in one matrix is directional steering (the post cites Arditi et al. on refusal); UC San Diego's analysis reproduces it as context-dependent activation steering and shows trained steering vectors cut loops further. Simply turning thinking off gave 53.3% against the steered 57.7% on their 1,152 practice problems.
  • Single runs, with unreported siblings. Each Qwen budget is one run; the released table holds four more Qwen runs not in the post (three made no edit), and the 10, 25 and 50-pass edits are different edits, so the table is not a scaling curve. Experiments 1 to 3 are 3 or 4 items each; Experiment 4 is one try.
  • Reading leans on the input layer and on priors. With the first layer alone Astra named the game 100% of the time, with the last alone 62%; on three new games it recovered the board layout but mostly not the rules (2611.21449); Claude Opus 5.5 on image CNNs followed familiar datasets and broke when labels were permuted (2611.08070). What is read is mostly the layout of where inputs and outputs connect.
  • Baselines and settings chosen for the claim. PPO at 500M steps beats Astra's networks in two of three MinAtar games; the Qwen setting (thinking on, 32,768 tokens) is the one where the base model loops 93% of the time. The addendum states both choices openly, which counts in the authors' favour.

Verdict. The small-network demonstrations are real and replicated: a frontier LLM can compile a designed program into an MLP's weights and read what a small network's input and output layers connect to. The Qwen result is a capable agent doing a known interpretability edit with tools, a prompt hint and forward passes; it shows that the agent can run that workflow end to end, not that it reads 0.8 billion weights.

Where it moves the knowledge base

  • Topic: llm-architecture (Inside a real model, induction heads): Experiment 3 is a case of finding induction heads from weights alone, by composing the previous-token head with later heads' query and key matrices, which complements that tab's activation-based score.
  • OpenAI: GPT family: GPT-6 Astra's best-known capability demonstration of November 2026 is not on that page yet.
  • Alibaba: Qwen: Qwen3.5-0.8B loops in thinking mode (93% of MATH-500 answers at 32,768 tokens with the recommended sampling), a dated, measured fact for the small Qwen models.
  • Policy gradients and actor-critic: PPO stuck in a local minimum on a control task (the Kinetix car) and repaired by a direct edit to its weights is a concrete example of a policy-gradient local optimum.
  • Safety and honesty benchmarks: sycophancy was not detectable from weights alone in Experiment 7, but was from attention patterns.
Since the article (checked 27 November 2026): papers that build on it
  • WeightBench: Evaluating Language Models as Weight-Space Programmers (arXiv 2611.18553) (13 November 2026): 42 tasks in five tracks on networks of 2K to 7B weights: agents read small networks and write control policies, but cannot yet patch language models, compress without data, or tell an impossible edit from a hard one. Macro score: Claude Opus 5.5 0.535; GPT-6.1-sol 0.568 against Opus 0.546 on the 38 tasks both ran.
  • Language Models Can Rewrite Their Own Weights (arXiv 2611.21885) (16 November 2026): An open 27B model, with its weights, its graded answers and the ability to run itself, edits its own weights: +6.6 points on unseen problems; only the largest model of one family improves, smaller ones make no edit or break themselves.
  • TrojanMaxxing: One-shotting VLM Backdoors with Weight-Space Programming (arXiv 2611.27425) (20 November 2026): Claude Opus 5.5 and Mythos 5.2 agents implant backdoors in vision-language models by editing weights, with no training: attack success 93% to 100% on content moderation, 78% to 100% on OCR, clean accuracy kept.

Responses, in date order

The 'Astra can read and write weights to improve Qwen' post is misleading

Matthew Honnibal (spaCy, Explosion), 3 November 2026, rebuttal: Tabulates what each experiment gave Astra: raw weights with no tools only in Experiments 1, 2 and 4 (17K to 172K weights); every experiment on a real language model uses Python, and the Qwen edit also ran the model on up to 50 batches of practice problems. Argues the two kinds of result do not belong under one claim.

(5 min)

Qwen 3.8 27B on my laptop can interpret model weights, too

Simon Willison, 3 November 2026, replication: Ran Experiment 1's four released prompts once each through an open 27B model on a laptop (4-bit GGUF in LM Studio): Breakout, Pong and Pac-Man recognised, Freeway missed, 46 to 65 minutes a prompt. Thinks a patient human with a notepad could do the same.

(8 min)

Can an LLM Actually Reason and Program about Neural Network's Weights or is it just memorization on steroids? (arXiv 2611.08070)

Nazmus Sakib Ahmed, 5 November 2026, audit: Claude Opus 5.5 on 125,000-weight CNNs for five image datasets, raw weights, no tools: accurate arithmetic at the first and last layers, but semantic answers follow familiar datasets (KMNIST read as MNIST, satellite images as CIFAR-10 animals) and break when CIFAR-10's labels are permuted. Mostly single runs.

(40 min)

What do LLMs Really Learn About Model Weights? A Stratification Approach

CCaptainX (LessWrong), 8 November 2026, replication: Re-ran Experiment 1 with ablations, 15 runs per condition: shuffled weights made Astra refuse 52 of 60 times and answer right once; the first layer alone gave 100%, the last layer alone 62%. DeepSeek-V4.1-Flash leaned on the prompt's metadata.

(15 min)

Response to Comments (the authors' addendum)

Takehi, Teoh, Zhang, Khattab, 12 November 2026, author reply: Weight-Space Programming is a concept, not a method; "natively" means the LLM does the reasoning, with Python as a tool; the baselines put a price in experience on each narrow claim; Astra was not compared with interpretability researchers.

(6 min)

Replicating and Extending Weight-Space Programming (arXiv 2611.21449)

Roksana Goworek, Alexander Hickey, Federico Nanni, Martin O'Reilly, 16 November 2026, replication: Breakout writing reproduces (514, 550 and 307 against 517); the written networks decompile to Python that matches their actions; reading is mostly reading the input layer (board layout recovered on three new games, game rules mostly missed); weight-only audits flag poisoned models but never find the trigger.

(25 min)

A closer look at "Sparks of Weight-Space Programming"

Zhi Wang, Brandon Hsu, Tianhao Wang, Mikhail Belkin (UC San Diego; LessWrong linkpost), 17 November 2026, analysis: Argues, with reruns, that the Qwen edit is context-dependent activation steering written into the MLP output matrix, with a direction built from four short synthetic looping and non-looping pairs. On 1,152 practice problems: unedited 12.3% (87.0% looping), thinking off 53.3%, Astra-style steering 57.7%; trained steering vectors cut looping further.

WeightBench: Evaluating Language Models as Weight-Space Programmers (arXiv 2611.18553)

13 November 2026: 42 tasks in five tracks on networks of 2K to 7B weights: agents read small networks and write control policies, but cannot yet patch language models, compress without data, or tell an impossible edit from a hard one. Language Models Can Rewrite Their Own Weights (arXiv 2611.21885)

16 November 2026: An open 27B model, with its weights, its graded answers and the ability to run itself, edits its own weights: +6.6 points on unseen problems; only the largest model of one family improves, smaller ones make no edit or break themselves.
