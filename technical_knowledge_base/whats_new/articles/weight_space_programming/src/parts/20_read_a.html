@@CARD@@

The idea in one sentence: a frontier LLM, used as it is with no training for the job, can treat a neural network's weights like source code, reading them to say what the network does and writing or editing them to change it; the post shows this cleanly on networks of 17,000 to 172,000 weights given as text, while its headline result on a 0.8-billion-weight language model was an agent with a Python kernel and 50 forward passes doing an interpretability edit.

You need: what PPO trains ({{Policy gradients and actor-critic|n:3ee5c17b0d0d8101a262d3620e75747c}}); what a transformer block's matrices are and that each MLP neuron writes one column of the down projection into the residual stream ({{The transformer from zero|n:3fd5c17b0d0d8174980ddde4a20c7b3c}}); induction heads ({{Topic: llm-architecture, Inside a real model tab|n:3fd5c17b0d0d8172b490dc9f9ac281df}}).

New terms: Weight-Space Programming (the authors' name for treating weights as a program to be read and written, "instead of leaving them entirely to an optimizer"); Astra (OpenAI's GPT-6 Astra, the reader and writer in every experiment); forward pass (here a budgeted call that runs the network on a batch: up to 128 games of Go, or up to 512 practice answers for Qwen); copying head (the post's word for an induction head); direction (a unit vector u in the residual stream); steering (adding or removing a direction in a model's activations to change a behaviour).

The claim: weights are a program an LLM can read and write

[[ar:Weight-Space Programming is a concept that treats|Weight-Space Programming]]

The post argues that reasoning-driven optimisation, already used on prompts, harnesses and training code, now reaches the weights themselves. We let LLMs improve text artefacts because humans can edit text by hand; weights were left to symbolic optimisers such as Adam because nobody can edit them by hand. The authors claim that has changed: a general-purpose LLM, from a natural-language goal and without gradients, can now read what a network computes and write weights that compute something else ({{in the article|ar:the paradigm of reasoning-driven optimization is now coming}}).

The evidence is eight experiments in three groups, all done by GPT-6 Astra: reading (what game, what shape, what language, which model is sycophantic), fixing (a stuck car policy, Qwen3.5-0.8B's math) and writing from scratch (three MinAtar games, 9×9 Go) ({{the list|ar:LLMs can read neural network weights: In Experiments}}). Each experiment has a Setup box saying what Astra was given. That box is the most important thing on the post, because what Astra was given changes from experiment to experiment, and the hero figure above sorts them by it.

The wording moved after publication. The first archived copy (2 November, 18:22 UTC) said LLMs read and write weights "well past what we'd expect from humans or conventional algorithms"; the current TL;DR says "sometimes with tools such as a Python kernel and sometimes from the raw weights alone" and that the results "may extend beyond" what we would expect ({{the current TL;DR|ar:sometimes with tools such as a Python kernel}}). The experiments and numbers did not change; the 12 November addendum came later (below).

Reading small networks with no tools (Experiments 1 and 2)

[[ar:Can Astra tell which game the network was trained on|Experiments 1 and 2]]

Given only the 17,253 weights of a PPO policy as text, Astra named the game for all four networks without being told the options. The four games (grid versions of Breakout, Pong, Pac-Man and Freeway) share one 10×10 grid, the same five actions and the same MLP shape, 500 → 32 → 32 → 5, so the game is only in the weight values ({{Setup|ar:Network: MLP 500 → 32 → 32 → 5}}). The post's account of how: where each input channel's first-layer weights concentrate (for Breakout, the agent's weights lie along the bottom row, where a paddle lives) and which actions the output layer tells apart ({{in the article|ar:where each input channel’s first-layer weights concentrate}}).

Given three diffusion models' weights, it named the shape each generates (circle, square, triangle; MLP 160 → 64 → 64 → 144, 23,824 weights, no forward pass allowed) by reading the output layer, where each hidden unit's weights draw one piece of the shape's edge. It drew every shape as an outline although the models generate filled shapes, which the authors read as a sign it reasoned about the geometry of the weights rather than computing a forward pass in its head ({{in the article|ar:it draws every shape as an outline}}).

Both readings rest on the first or the last layer, the two places where the weights are tied to something with a meaning (pixels on a grid, actions, output pixels). The authors say so themselves before Experiment 3 ({{in the article|ar:could get away with only reading the first or the last layers}}), and two later studies measured it: shuffling the weights or keeping only the first layer, and reading new games (Responses).

Reading the middle of a language model (Experiment 3)

[[ar:Can Astra tell what a language model learned, from the middle|Experiment 3]]

With the input and output layers removed, Astra still named the training language of three character-level transformers and found every copying head, with no false ones. The models (4 layers of 6 heads, width 384, 7.16 million weights) were trained on Python code, Japanese in romaji and English Wikipedia; Astra got the four middle blocks, with no labels on the 384 dimensions, and up to 100 runs of Python to analyse them, but could not run the network or any layer on any input ({{Setup|ar:Not allowed: running the network or any of its layers}}). It was right in both attempts on each model, with stated confidence of 0.48 to 0.62.

How it found the copying heads is a textbook method it was never shown. It found a first-layer head that attends one character back, then multiplied weight matrices to find the later heads that search using what that head writes: the previous-token and induction-head circuit of Elhage et al. (2021), whose two-head mechanism the knowledge base explains on the {{Topic: llm-architecture page|n:3fd5c17b0d0d8172b490dc9f9ac281df}} (Inside a real model tab). Code repeats names far more than prose, so many copying heads pointed to Python; romaji stood out because the last block writes in fewer directions, as if it had fewer letters to tell apart ({{in the article|ar:romaji never uses some letters like q, l, v and x}}).

Ground truth: each head was scored by running the model on a random string repeated twice; copying heads scored 0.22 to 0.55, every other head at most 0.02. Astra never saw these scores.

Writing and fixing networks (Experiments 4, 5 and 6)

[[ar:Can an LLM write neural network weights?|Experiments 4 to 6]]

Fixing a stuck policy: one reply, no tools, 3.5% of the weights changed, and the car succeeded in all 1,024 episodes. PPO, trained for a billion steps on a Kinetix level where a car must back up before jumping a red strip, learned to drive straight at the ramp and stall (0 of 256 episodes). Given all 171,664 weights, the scene and one recorded failed episode, Astra explained the local minimum and added a small separate path through a few units per layer that reads the car's position and speed, backs the car up, and switches off once the wheel is past the strip ({{in the article|ar:adds a small separate path through a few units}}).

Writing from nothing: networks for three MinAtar games, written as text in one reply from all-zero weights, beat PPO trained for 100 million steps in all three. Astra had the game's rules and source code and the network's layout (600 → 32 → 32 → 6), and no data, loss, gradients, tools or play before scoring. Against PPO at 500 million steps it scored 20 times as much in Breakout, close in Asterix and 60% in Seaquest (figure). Its method was to design a program and compile it into weights: in Breakout, the first layer computes where the ball will land and the second moves the paddle there ({{in the article|ar:the first layer to compute where the ball would land}}).

Writing a 1.5-million-weight Go network needed Python, and grew stronger with runs of the network. Too big to write as text, the 243 → 512 × 6 → 82 network was built in a Python sandbox where Astra could read and save tensors but not run them; each forward pass played up to 128 games against a practice opponent. With 0 passes (one Python run of 336 lines encoding liberties, groups in danger, captures and eyes) it won more than half its games against two smaller PPO networks; with 50 passes it beat the equal-sized PPO network trained on 20 million games ({{in the article|ar:beats the equal-sized PPO network that was trained}}).

Spotting a sycophant (Experiment 7): no from weights, yes from attention

[[ar:Which language model is sycophantic?|Experiment 7]]

From the weights alone Astra could not tell which of two fine-tuned Gemma 3 270M copies was the sycophant, in four attempts. The pairs were trained the same way on the same questions, one to give the correct answer and one to give whatever answer the user suggested (it then follows 100% of wrong guesses, the honest copy 1 to 3%); the embeddings and output layer were frozen so the difference had to be inside. Astra found many weight differences but could not map them to behaviour ({{in the article|ar:Unfortunately, from the weights alone, Astra was unable to tell}}).

Allowed to see attention patterns on up to 16 texts it wrote (never the outputs), it picked the sycophant in all three pairs, and explained it: in the sycophant, middle-layer heads look at the user's suggestion. In the post's example, head 10.2 at the answer position puts 94.3% of its attention on the question's numbers and 0.75% on the user's answer in the honest model, against 3.5% and 85.7% in the sycophant ({{Figure 2|ah:figure-2}}). This is the first experiment where running the model was the step that made it work.
