4. The fix: a pool that holds the window, and a rejection that stops before the handoff

[[ar:we made the pool hold the full context|Immediate remediation]]

Either change alone closes this path; Cloudflare made both. The configuration took GLM-5.3 to its GLM-5.2 settings, freeing memory for a prefill pool of about 2.04 million tokens, so a prompt that fits the window fits the pool. The engine patch exists because {{Relying on pool size alone is fragile|ar:Relying on pool size alone is fragile}}: quantization, parallelism, CUDA graphs or a new model version all move the pool, so a request with a pending rejection is now {{retired at the disaggregation admission queue|ar:retired at the disaggregation admission queue, with its original error}} before any transfer. Both were checked against the researcher's script and {{our own canary-marker tests|ar:our own canary-marker tests}} (a known marker in the prompt that the reply must reflect).

5. The wider class: a page freed, reused or read while something still claims it

[[ar:a class of KV cache memory-safety bugs|Ongoing hardening effort]]

This incident belongs to a family Cloudflare had been fixing for months: {{a page is freed, reused, or read while something else still has a claim on it|ar:a page is freed, reused, or read while something else still has a claim on it}}. Inside one decode node, generation, host offload, the transfer receiver and abort paths can all hold a page (Cloudflare's fixes #24226, #30899, #30937). Across nodes, prefill writes KV straight into decode's memory by one-sided RDMA, and {{the writes already sent cannot be recalled|ar:the writes already sent cannot be recalled}}:

  1. A transfer in flight. Prefill streams A's KV into slots 3 to 7 on decode: two chunks have landed, one is posted to the network card, two wait in prefill's queue.
  2. Abort, slots freed. A's client disconnects; decode aborts A and returns slots 3 to 7 to the allocator at once.
  3. Reused. The allocator gives those slots to request B, whose own KV is written there.
  4. A late write lands. A's posted chunk arrives in slot 5, now B's; nothing reports an error.
  5. B decodes on A's keys and values. Garbage, or fragments of A's prompt in B's reply.
  1. A transfer in flight. Prefill streams A's KV into slots 3 to 7 on decode: two chunks have landed, one is posted to the network card, two wait in prefill's queue.
  2. Abort, slots held. Decode tells every prefill rank to abort; queued chunks are dropped, and A's slots stay reserved.
  3. The late write lands harmlessly. The posted chunk arrives in slot 5, still A's, quarantined and never read.
  4. Drained, then released. Prefill's count of outstanding writes reaches zero and it replies ABORT_ACK; only then does decode free the slots (a 30-second default timeout is the fallback).
  5. B gets clean slots. Every slot B reads was written by B; SGLang's harness gave output identical to the baseline, byte for byte.

The incident's bug was the deterministic cousin of this race: a rejected request {{went through the handoff every time|ar:went through the handoff every time, rather than by a timing accident}}, with the same result. Deferred release became SGLang's default in v0.5.21, at no measurable throughput cost (within ±2% over 21 runs on 2×H100, SGLang's post).

Cloudflare's hardening since the incident

Deferred release extended to every failure type and to prefill's source pages (SGLang's analysis judged that path already safe); bounded Mooncake transfer batches, so one call cannot outlast the release timeout; a load balancer that {{no longer aborts on a client disconnect|ar:Changed our load balancer so a client disconnect no longer aborts}}, holding prefill until it finishes and decode until the first token; and a check on every disaggregated deployment change covering pool against window, deferred release on both roles, batch bounds and required patches.

6. What any operator should check, and the longer-term fix

[[ar:Measure your KV pool and compare it to your context length|What we recommend to other operators]]

The post's five recommendations for anyone running disaggregated SGLang, the first being {{the check we did not enforce|ar:This is the check we did not enforce}}:

  1. Pool against window on every node, from the engine's start-up log, after any change to weights, quantization, parallelism or memory fraction; lower the context length if the pool is smaller. {{Do not rely on a proxy to enforce the limit|ar:Do not rely on a proxy to enforce the limit}}.
  2. v0.5.22 or later, or backport #36988 and #38935.
  3. Deferred KV release on both roles (default since v0.5.21) and bounded Mooncake batches.
  4. Corruption detection (--disaggregation-enable-kv-checksum, --kv-canary), which {{do not yet cover every model architecture|ar:do not yet cover every model architecture}}, GLM 5.3 included.
  5. Fewer aborts mid-transfer: let the load balancer carry a request to its first token.

The general lesson: test content, not status. A canary marker in a long prompt that the answer must repeat would have failed; a 200 where a 400 was expected, and a reply faster than its prefill could take, were the signs.

Longer term, the engine should refuse to read a page it does not own. In Cloudflare's prototype {{Every physical KV page carries a tag|ar:Every physical KV page carries a tag}} that changes on reallocation, checked before decode reads; under 1% overhead, tested on GLM 5.2 in mid-August and {{disabled it shortly afterwards due to reliability issues|ar:disabled it shortly afterwards due to reliability issues}}, about two weeks before GLM-5.3 launched. SGLang's checksum (#39500) checks only the handoff; tags would check every read. Cloudflare also plans to prove its RDMA transfer protocol safe with formal methods.
