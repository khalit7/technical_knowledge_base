Qwenputer: a fully functioning, deterministic RISC-V CPU inside Qwen3.5

Divyansh Agrawal (independent) · published 22 October 2026

In one line: In one blog post with released code and weights, a compiler sets the weights of 11 extra layers (about 1M nonzero weights) in front of an unchanged Qwen3.5-4B so that Gated DeltaNet heads, with gate 1, write strength 1 and one-hot keys, act as exact RAM for a RISC-V (RV32IM) CPU. Qwen calls it through its tool-call format; on four 40-problem DeepMind arithmetic sets (greedy, one run each) it lands within one problem of base Qwen given the same tool answered on the host, and above base Qwen without tools (mul_big 97.5% against 55%). It runs through a custom driver, not plain generate(), and the post's NUPA 100% figure is from the earlier CHIP-8 version.

How far to trust it: Believe the mechanism and its exactness: the RAM trick is plain linear algebra, and the released code checks the circuit against riscv-tests, qemu and a reference machine over millions of instructions. Read the benchmarks as parity with a host-side tool on small sets, with one bar from a different model, and read "no runtime" as "nothing outside the weights computes the answer": a custom driver boots the CPU, routes its trace tokens past Qwen and, in the measured runs, executes the compiled layers with a Triton re-implementation checked bit-equal to them.
