The idea in one sentence: a Gated DeltaNet head whose gate is held at 1, whose write strength is 1 and whose keys are one-hot stores and returns values exactly, like a RAM, so a compiler can write a whole RISC-V CPU into 11 extra layers in front of an unchanged Qwen3.5-4B, and Qwen can hand it arithmetic through its usual tool-call format.

What the post is. A short build report (9 minutes) by an independent developer, with the code, both checkpoints and a long design log released. Its claims are about one artefact: what the compiled layers do, how exactly, and what they add to Qwen on arithmetic. This page follows the post in its order, runs the RAM trick live in section 2, and then checks the claims against the released design log and the repository's history: most hold, one chart bar comes from a different model, and "no runtime" needs a qualifier.

You need: the delta rule and its gate ({{Beyond attention|n:3fd5c17b0d0d8142bc9ecac1fc366966}}, sections 3 and 6: the update this post pins to 1); residual stream, attention and MLP sublayers ({{The transformer from zero|n:3fd5c17b0d0d8174980ddde4a20c7b3c}}); Qwen3.5's 3:1 hybrid of Gated DeltaNet and attention ({{Alibaba: Qwen|n:3c65c17b0d0d81fd8c36ce06672bb235}}).

New terms: one-hot key (all zeros except a single 1: it picks one row of the state, like an address); compiled weights (weights computed by a program from a circuit description, not learned); RV32IM (the 32-bit RISC-V base integer instruction set plus multiply and divide); trace token (a token the CPU generates for itself, one record per instruction, which is how its writes reach memory); free-running (the CPU continues on its own generated tokens with no reference machine correcting it); RvChat (the author's decoding driver that boots the CPU and keeps its trace tokens out of Qwen's layers).
