Run Bitune: a toy decoder, finetuned nine ways

A real model, trained offline with PyTorch and running here in plain JavaScript (the same arithmetic, checked against PyTorch: ). It is built to answer one question the paper's benchmarks cannot: when does reading the prompt bidirectionally matter? Everything below is computed in your browser unless it says "from training".

The setup

  • World. 48 people and 32 clubs, with a fixed random membership table (25% of pairs are members).
  • Pretraining (causal language modelling, 12,000 steps of 128 sequences). Half the sequences state facts with the club first ("chess Ada yes choir Ben no ..."), half ask a question before the list ("<bos> ? chess Ada Ben Cy : Ben <eos>"). The pretrained model answers question-first prompts correctly of the time.
  • Instruction tuning (3,000 steps of 32 prompts, AdamW, 10% warmup then linear decay, no weight decay, as the paper's Table 9). The new template asks the question after the list: "<bos> Ada Ben Cy Dee ? chess" then ": Ben <eos>". 3 to 6 people, exactly one a member. The ":" is moved to the answer side, as in the paper. LoRA rank 4 on every linear layer (the paper: rank 8 on models 64 times wider), scale 1; the pretrained weights stay frozen.

  • Protocol, as the paper's: the learning rate is tuned for LoRA alone () and reused for every method; 3 seeds each; accuracy on 2,000 fresh held-out prompts ().

Look inside: the two passes

Rows are query tokens, columns the tokens they read; darker is more attention. The answer row is the ":" token reading the cache (mixed, for the two-pass models). The mixing chart shows the learned α = |θ| / (0.01 + |θ|) of each block for keys and values, against the paper's Llama3-8B (its Figure 3 averages, decoded).
