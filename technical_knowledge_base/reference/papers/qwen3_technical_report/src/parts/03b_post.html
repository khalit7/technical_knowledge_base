Post-training: four stages for the flagships, distillation for the rest

[[S4|§4, Figure 1]]

Post-training has two goals ({{§4|ax:S4}}): thinking control (one model with a thinking and a non-thinking mode, and a token budget for the thinking) and strong-to-weak distillation (small models built from the large ones instead of trained the long way). The two flagships, Qwen3-235B-A22B and Qwen3-32B, go through four stages; the six smaller models are distilled from them. The animation runs both routes, as {{Figure 1|ax:S4.F1}} draws them.

What each stage trains on, and where its signal comes from.

Stages and their data follow {{§4.1 to §4.5|ax:S4.SS1}}. "Signal per response" counts what one training response tells the model: a target token per position (fine-tuning), one reward per response (RL), or the teacher's whole next-token distribution per position (on-policy distillation; the vocabulary has 151,669 entries). The only measured cost in the report is Table 21's GPU hours for one 8B comparison; the 1/10 of "the four-stage training method" in {{§4|ax:S4}} is not itemised. The animation stops when off screen and starts paused if your system asks for reduced motion.

Stage 1: a deliberately small long chain-of-thought cold start

[[S4.SS1|§4.1]]

A dataset of math, code, logical reasoning and general STEM problems, each with a verified reference answer or test cases, filtered twice ({{§4.1|ax:S4.SS1}}):

  • Query filter (by Qwen2.5-72B-Instruct): drop queries that are not easily verifiable (several sub-questions, general text generation) and queries it answers correctly without chain-of-thought, "to prevent the model from relying on superficial guessing". It also labels each query's domain to keep the mix balanced.
  • Response filter: after reserving a validation set, QwQ-32B generates N candidates per query; when it keeps failing, human annotators judge the responses. For queries with a positive Pass@N, responses are dropped if they (1) reach a wrong answer, (2) repeat themselves substantially, (3) guess without adequate reasoning, (4) think one thing and summarise another, (5) mix languages or shift style inappropriately, or (6) look too similar to validation items.

Only "a carefully selected subset" is used, with as few samples and steps as possible: the aim is to instil the reasoning format "without overly emphasizing immediate reasoning performance", so as not to cap what RL can add later. No sizes are given.

Stage 2: reasoning RL on 3,995 problems

[[S4.SS2|§4.2]]

The query-verifier pairs must be unused in stage 1, learnable for the cold-start model, as hard as possible and spread over sub-domains: 3,995 in all. The algorithm is GRPO (the {{DeepSeekMath page|n:3c65c17b0d0d817f9fc5cb9a9fbcbee5}} runs it live), with large batches, many rollouts per query and off-policy reuse of samples, and the entropy kept "to increase steadily or remain stable". Training improved steadily "without any manual intervention on hyperparameters": Qwen3-235B-A22B went from 70.1 to 85.1 on AIME'24 in 170 RL steps ({{§4.2|ax:S4.SS2}}).

Stage 3: thinking mode fusion, one checkpoint for both modes

[[S4.SS3|§4.3, Table 9]]

Stage 3 continues supervised fine-tuning of the stage-2 reasoning model on a mix of thinking and non-thinking data, so that one set of weights does both ({{§4.3|ax:S4.SS3}}):

  • Thinking data is generated by the stage-2 model itself, by rejection sampling on stage-1 queries, so the extra fine-tuning does not degrade it.
  • Non-thinking data is curated across coding, math, instruction following, multilingual tasks, creative writing, question answering and role-play, graded with automatically generated checklists; translation tasks are up-weighted for low-resource languages.
  • The chat template carries the switch: /think or /no_think in the user or system message. A non-thinking response keeps an empty think block, so both modes share one format, and a deployer can force non-thinking by pre-filling the empty block (Hugging Face's template does this with enable_thinking=False).
  • Thinking is the default: some thinking samples carry no flag. In multi-turn data flags are inserted at random and the response follows the last flag seen.
Two requests, one quick and one hard, at 32B scale.

Token layout is {{Table 9|ax:S4.T9}}'s template. Weight memory is parameters × 2 bytes in BF16, to scale: Qwen2.5-32B-Instruct and QwQ-32B are both 32.5B-parameter models ({{Qwen2.5-32B-Instruct card|https://huggingface.co/Qwen/Qwen2.5-32B-Instruct}}, {{QwQ-32B card|https://huggingface.co/Qwen/QwQ-32B}}), Qwen3-32B is 32.8B (recounted above). The token counts of the two answers are illustrative.

The fusion has a measured cost, in the report's own Table 22: peak math and code scores in thinking mode drop slightly after stage 3 (AIME'24 83.8 to 81.9, LiveCodeBench 68.4 to 67.2 for Qwen3-32B), while instruction following, format following and agent scores rise. The thinking budget

[[S4.SS3.SSS0.Px3|§4.3, Thinking Budget]]

Once a model can answer both after full thinking and after empty thinking, the report says, it "naturally develops the ability to handle intermediate cases", answering from incomplete thinking. The budget uses that: when the thinking reaches a user-set number of tokens, generation is halted and this text is inserted ({{§4.3|ax:S4.SS3.SSS0.Px3}}):

"Considering the limited time by the user, I have to give the solution based on the thinking directly now.\n</think>.\n\n"

The model then writes its answer from the reasoning so far. "This ability is not explicitly trained but emerges naturally as a result of applying Thinking Mode Fusion." The report runs no ablation of that sentence: there is no model without fusion, and no model trained on cut-off thinking, to compare against. The toy on this page runs both.

A toy Qwen3 is fused exactly as stage 3 describes: half its samples think to the end, half have an empty think block, never anything in between. Cut its thinking off half way and insert the closing tag. What does it answer?

What the budget buys on the real model. {{Figure 2|ax:S4.F2}} plots Qwen3-235B-A22B on four benchmarks at budgets of 1K to 32K thinking tokens, against its non-thinking score. The figure prints no numbers; the points below are read from the arXiv HTML's vector graphic, calibrated on its own gridlines. The calibration checks itself: the four non-thinking lines land on Table 12's scores (40.1, 24.7, 35.3, 62.9) to within 0.05.

On AIME'24, how much does doubling the budget from 1K to 2K thinking tokens add?

0.6 points (42.1 to 42.7), and GPQA moves 0.1 (64.2 to 64.3). The curves are not straight in log budget: they are flat at first, steep between 2K and 16K, and flattening by 32K. A competition problem whose thinking runs to several thousand tokens gains little from 1K more; the gain arrives when the budget reaches the length the problem needs.

Points: {{Figure 2|ax:S4.F2}}, read from thinking_budget.svg by extract_fig2.py (grid residual 0.0). Diamonds at 32K: the same model's thinking-mode score in {{Table 11|ax:S4.T11}}. Pass@1 here is the report's metric (AIME: 64 samples per question, averaged; GPQA: 10 samples).

Two things the figure shows that the text does not say:

  • Even 1K tokens of thinking beats not thinking, on all four benchmarks (AIME'24 42.1 against 40.1; LiveCodeBench 45.1 against 35.3). The real model, cut off early, does at least as well as answering directly. That is the property the toy lacks, and it is what makes the dial safe to turn down.
  • The 32K points are not Table 11's numbers for the same model and mode: AIME'24 86.7 against 85.7, AIME'25 81.7 against 81.5, GPQA 72.0 against 71.1 and LiveCodeBench 67.8 against 70.7. The figure is a separate run, with settings the report does not give (Table 11's runs may allow longer outputs: the model card recommends 38,912 output tokens for competition math).

The report expects scores to keep rising "if we further extend the output length beyond 32K" and leaves that as future work ({{§4.7|ax:S4.SS7.SSS0.Px1}}). The general mechanism and how other labs expose the same dial are on {{Topic: llms|n:3c65c17b0d0d812d9e00f6ec89965286}} (Deeper: test-time compute), and the {{lab page|n:3c65c17b0d0d81fd8c36ce06672bb235}} has a strip showing where a budget cuts a chain.

Stage 4: general RL

[[S4.SS4|§4.4]]

A reward system over more than 20 tasks, each with its own scoring criteria, aimed at five capabilities ({{§4.4|ax:S4.SS4}}):

  • Instruction following: content, format, length, structured output.
  • Format following: switching modes on /think and /no_think, and keeping <think> and </think> where they belong.
  • Preference alignment on open-ended queries: helpfulness, engagement, style.
  • Agent ability: tool calls through designated interfaces, with complete multi-turn rollouts against real environments that execute them.
  • Specialised scenarios, for example retrieval-augmented generation, rewarded for accurate, grounded answers to curb hallucination.

Three kinds of reward: rule-based (as in reasoning RL, also for instruction and format following; hard to hack), model-based with a reference answer (Qwen2.5-72B-Instruct scores the response against it, avoiding the false negatives of strict rules) and model-based without one (a reward model trained on human preference data, for the widest range of queries).

Strong-to-weak distillation

[[S4.SS5|§4.5 and §4.7]]

The five small dense models (0.6B, 1.7B, 4B, 8B, 14B) and Qwen3-30B-A3B skip the four stages ({{§4.5|ax:S4.SS5}}):

  1. Off-policy distillation. Fine-tune the student on the teachers' responses in both /think and /no_think modes: basic reasoning and mode switching.
  2. On-policy distillation. The student samples its own responses to sampled prompts, in either mode, and is trained to align its logits with the teacher's (Qwen3-32B or Qwen3-235B-A22B) by minimising the KL divergence.
ℒ = Σt KL( pstudent(· | y<t) ‖ pteacher(· | y<t) ),   y ∼ pstudent

The student is graded at every position of its own response on the teacher's whole next-token distribution, where RL gets one reward per response. The report does not say which direction of KL it uses; the toy uses the student-first (reverse) one written here.

The report's evidence is one comparison ({{Table 21|ax:S4.T21}}): from the same off-policy-distilled Qwen3-8B, on math and code queries only, on-policy distillation reached AIME'24 74.4 and AIME'25 65.5 for 1,800 GPU hours; reinforcement learning reached 67.6 and 55.5 for 17,920 (1,800 ÷ 17,920 = 10.0%). Distillation also raised pass@64 (AIME'24 90.0 to 93.3, AIME'25 83.3 to 86.7) where RL left it unchanged, which the report reads as distillation expanding "the exploration space" while RL does not ({{§4.7|ax:S4.SS7.SSS0.Px2}}). The lab page draws these as {{bars|n:3c65c17b0d0d81fd8c36ce06672bb235}}.

AIME'24 has 30 questions. How many more questions does on-policy distillation solve at least once in 64 tries than RL does?

One. 93.3 − 90.0 = 3.3 points, and one question is 100 ÷ 30 = 3.33 points; AIME'25's 83.3 to 86.7 is also one question. The pass@1 gap is larger: 74.4 − 67.6 = 6.8 points, about two questions' worth of average accuracy. So "expands the exploration space" rests on one problem per year, in one run. What stages 3 and 4 each buy

[[S4.SS7.SSS0.Px3|§4.7, Table 22]]

{{Table 22|ax:S4.T22}} scores Qwen3-32B after stage 2, 3 and 4, in both modes, on public benchmarks and four in-house ones ({{§4.7|ax:S4.SS7.SSS0.Px3}}):

  • CounterFactQA: counterfactual questions the model should recognise as non-factual instead of answering.
  • LengthCtrl: creative writing to a target length, scored by the difference.
  • ThinkFollow: multi-turn dialogues with randomly inserted flags; did the model switch correctly?
  • ToolUse: single-turn, multi-turn and multi-step tool calling, scored on intent, format and parameters.

Each bar is the change in points from one stage to the next, on one shared axis, from {{Table 22|ax:S4.T22}}; the changes printed in the table recompute from its scores to within 0.1 (rounding). Non-thinking mode starts at stage 3, which creates it. ThinkFollow is one score per stage (88.7, then 98.9). Stage 4's thinking scores equal the released Qwen3-32B's in {{Table 13|ax:S4.T13}}, so the table describes the shipped model.

Stage 3 lifts the in-house and alignment scores (CounterFactQA +10.9, LengthCtrl +8.0 in thinking mode), and stage 4 lifts them again (ToolUse +15.1, ThinkFollow 88.7 to 98.9). Peak reasoning goes the other way: from stage 2 to stage 4, thinking-mode AIME'24 falls 2.4 points and LiveCodeBench 2.7, GPQA and MMLU-Redux under a point. The report says so: the degradation is probably "due to the model being trained on a broader range of general tasks", and "we choose to accept this performance trade-off to enhance the model's overall versatility". That trade is what Qwen undid three months later by splitting the modes again (see {{Why it matters|tab:t-read:s-why}}).
