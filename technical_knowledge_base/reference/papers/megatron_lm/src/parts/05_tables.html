The paper's tables, rebuilt

Every number below is transcribed from the arXiv HTML (v4) of the paper, except Figure 5's labels, which come from the PDF; every derived number is recomputed in recompute.py. Each section links the table it rebuilds.

Table 1: the scaling models, recounted [[S5.T1|Table 1]]

Parameters recounted as vh + 1,024h + l(12h² + 13h) + 2h: tied embedding with the padded vocabulary v = 51,200, learned positions, per layer the QKV, output and two MLP matrices with biases and two LayerNorms, and a final LayerNorm. Defaults reproduce: 1.2, 2.5, 4.2 and 8.3 billion independently; and the fewest GPUs under 32 GB (the {{memory calculator|tab:t-read:memx}}'s accounting) equals the model-parallel column for every row.

Table 2: the GPT-2 models, and the throughput their epoch time implies [[S5.T2|Table 2]]

An epoch is 68,507 iterations of 512 × 1,024 tokens, 35.9 billion tokens ({{§5.2|ax:S5.SS2}}). FLOPs per iteration 96Bslh²(1 + s/6h + v/16lh), which counts the recomputed forward pass of activation checkpointing ({{Narayanan et al. 2021, Eq. 3|https://arxiv.org/abs/2104.04473}}, a later paper by the same group). Training days = days per epoch × 300,000 / 68,507 iterations.

Close, not exact
Table 2's 2.10 days per epoch for the 8.3B model implies 13.8 PFLOP/s, 27.0 TFLOP/s per GPU, against the headline's "up to" 15.1 PFLOP/s, which was measured on the 32-head scaling configuration of Table 1, not this 24-head model. 74% of the 39 TFLOP/s baseline is 28.9 TFLOP/s per GPU, so the throughput the epoch time implies is 6.5% below what Figure 5's efficiency gives; the paper does not break the epoch time down, so that gap is unexplained.
