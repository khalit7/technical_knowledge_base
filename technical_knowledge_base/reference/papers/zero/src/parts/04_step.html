Step through a training step

One training step of an 8-layer model on Nd data-parallel GPUs, run twice on the same input: once with the method on the left of the comparison and once with the one on the right, drawn to the same scale. Each GPU is one row; its strip is its memory for model states, one cell per layer for the fp16 parameters and gradients and for the fp32 optimizer states, widths in proportion to bytes (2 : 2 : 12). A filled cell is resident; an outlined one is not. Coloured bands between rows are the collectives of {{§7|ax:S7}}, labelled with the volume each GPU moves.

Try: start with DDP against ZeRO-3 and watch the parameters: under ZeRO-3 each layer's weights appear just before forward uses them and vanish after, then return for backward. Then switch to ZeRO-1 against ZeRO-2 and watch the gradient cells: ZeRO-2 frees every gradient it does not own as soon as it is reduced. The counters keep score against the paper's 2Ψ and 3Ψ.

Schedule as the paper describes it ({{§5|ax:S5}}, {{§7|ax:S7}}): partitions are contiguous groups of layers, owner i holding layers 8i/Nd + 1 to 8(i + 1)/Nd; gradients are reduced in buckets of two layers. Volumes are in elements per GPU and leave out the ring's (N − 1)/N factor, as the paper does. Memory counts model states only, for GPU 0, in bytes per parameter (multiply by Ψ); a short-lived gathered bucket counts while it is resident. Real implementations add prefetching and overlap that this one-bucket-at-a-time view leaves out. The animation stops when it is off screen, and starts paused, one step at a time, if your system asks for reduced motion.
