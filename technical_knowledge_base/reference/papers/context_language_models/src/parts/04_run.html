Replay a trajectory

One deep-research episode, the same input stream every time, run under three context policies: Base appends until the budget is full, Summary replaces everything after the task with one summary when the context passes a threshold (Codex-style, {{Appendix E|ax:A5}}), and CLM edits its own context file, folding finished turns into one-line notes as in {{Figure 3|ax:S4.F3}}. Every model call is priced with the paper's own cost model for Qwen3.6-27B ({{Eq. 9|ax:A3.E9}}), under standard prefix caching or under Suffix Cache Reuse.

What is the paper's and what is illustrative

The paper's: the cost model and its constants (they reproduce Figure 16 exactly, below), message-level prefix matching ({{Appendix C|ax:A3}}), the summary trigger at 75% of the budget and the search sizes (10 snippets of 512 tokens, documents capped at 8,192; {{Appendix E|ax:A5}}), the 28,672-token budget of the released BrowseComp-Plus configuration, and SCR's K = 6 spans. Illustrative: the 24 actions, the 1,600-token summary, the 260-token edit command, the note sizes, and above all the CLM's rule, which stands in for choices a real model makes for itself (here: edit when the context passes 75% of the budget, the released harness's third nudge, and fold every finished turn). No accuracy is simulated: every policy sees the same actions, so this measures cost only. Nothing here reproduces the paper's 21.5%.

The whole episode, three policies side by side

Things to try. Move CLM edits at down to 40%: it edits more often, and each edit re-prefills the turns that follow it, so cost rises even though the context is smaller; this is the "batch, mind the tail" advice in the released system prompt. Set keeps the newest 1 turn: under a prefix cache that kept turn is re-prefilled after every edit, and switching to Suffix Cache Reuse recovers it. Under Summary, SCR changes nothing: a summary replaces everything after the task, so no span survives to be relocated.
