Method

[[S3|§3, Appendix A]]

Tasks x1, x2, ..., xT arrive one at a time. Solving xt produces a trajectory ξt of interleaved observations and actions and a reward rt in [0, 1]. JitMem has four parts: a memory bank of raw trajectories, a retriever, a curator πφ, and a frozen executor πL. Only the curator is trainable, and the goal is the expected sum of task rewards ({{§3|ax:S3}}). Each task runs four steps:

StepWhat happensDetails
1. Retrievetop-k raw trajectories for xtBM25 over task descriptions only, not trajectory content, so retrieval cost does not grow with trajectory length; chosen for consistency with the baselines, untrained, k = 3 ({{§3|ax:S3}}, {{Appendix A|ax:A1}})
2. Curatept = πφ(xt, retrieved)a prompt with the task followed by the k trajectories; the output is a concise briefing: which past experiences are relevant, which strategies worked, and specific guidance for this task (per-benchmark prompts in {{Appendix A|ax:A1}})
3. Execute(ξt, rt) = πL(xt, pt)the payload is prepended to the frozen executor's prompt; the executor never sees the raw trajectories
4. Updateappend ξt if the quality gate accepts itno labels exist at deployment, so the executor model judges its own trajectory and only judged successes are stored, keeping memories positive examples; the payload is never stored

Training the curator. GRPO: sample G = 8 payloads for a training task, let the frozen executor attempt the task with each, and score it with the benchmark's own reward (success on ALFWorld, the 0 to 100 score on WebShop). Advantages are rewards minus the group mean, without dividing by the standard deviation (as in Dr. GRPO):

L = −(1/G) Σi Âi · log πφ(p(i) | xt, retrieved),   Âi = r(i) − meanj r(j)

({{§3|ax:S3.Ex1}}). The reward depends only on the payload written for that same task, so the curator learns directly from task success and credit assignment is one step, where a write-time decision at task s is graded only when some task t > s retrieves it. Recipe: Qwen3-8B curator, thinking off; 100 steps, learning rate 1 × 10−6, 32 tasks per batch, KL loss 1 × 10−3, payloads up to 8,192 tokens (ALFWorld) or 4,096 (WebShop); Qwen3-8B executor in non-thinking mode for speed ({{§4|ax:S4}}, {{Table 7|ax:A1.T7}}).

A fixed training bank. So that the reward reflects payload quality, not which trajectories happen to be stored, training retrieves from a frozen bank of the base executor's successes on the training set (by ground-truth label). At test time the bank fills with curator-assisted trajectories instead, a mild shift that the staged-refresh ablation measures ({{§3|ax:S3}}).

Evaluation. The test bank starts empty and grows as tasks are solved. Tasks run in batches that share one bank state (10 per batch; 5 on tau2-bench), and the bank updates after each batch. The verifier scores success; the bank's gate sees only the LLM judge, so no label leaks into memory. Results: mean and standard deviation over 3 random orderings (4 on tau2-bench) ({{§3|ax:S3}}, {{Appendix A|ax:A1}}).
