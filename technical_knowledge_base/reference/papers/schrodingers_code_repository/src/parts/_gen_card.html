Schrödinger's Code Repository: Have LLMs Learned SWE-bench or Memorized It? (SchrodingerRepo)

Silin Chen, Yufei Yang, Xiaodong Gu, Yuling Shi, Chengcheng Wan, Haibing Guan
Shanghai Jiao Tong University (four authors), Xi'an Jiaotong University, East China Normal University and Shanghai Innovation Institute · arXiv v1 submitted 21 August 2026, the only version so far (checked 3 October 2026)

In one line: Instantiating the test repository dynamically under four behaviour-preserving transformations consistently degrades agent performance and raises interaction cost on SWE-bench Verified and SWE-QA, so part of a repository-level coding score is knowing where to look rather than knowing what to do. (The database Takeaway, kept as written. Two qualifications from this page: "consistently" holds for Pass@1 on SWE-bench Verified, but on SWE-QA DeepSeek-v4-Flash moves 0.55 points and two of its levels score higher; and the evidence shows unfamiliar names cost exploration, not that the familiar ones were memorised.)

How far to trust it: Believe the direction: renaming a repository's own identifiers reliably costs agents exploration and a few points of Pass@1. Do not read it as proof of memorisation. The renamed names also lose meaning, the one control for difficulty (one model, 110 fresh tasks, 19 solved) could not have detected the drop it was meant to rule out, Gemini's 14.4 points come from the 300 most-leaked instances, two printed changes are wrong, and the released code builds Levels 1 and 3 differently from the text.
