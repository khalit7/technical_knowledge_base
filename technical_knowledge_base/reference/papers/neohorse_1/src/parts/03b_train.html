Agentic post-training

[[S4|§4]]

Supervision within a user turn

Each user turn is serialised with the Qwen3.5 chat template and tool-call format, keeping the recorded system instructions and harness context so every assistant target stays paired with the conditions it was produced under ({{§4.1|ax:S4.SS1}}). The pattern being learned is interleaved thinking: reason, call a tool, read the result, reason again. A turn can hold several assistant responses between tool results, and all retained assistant spans of the current turn are supervised in one sequence. History and every non-assistant span (system instructions, tool specifications, harness context, user messages, tool results) get no loss; causal attention means each response sees earlier actions and results but not later ones.

ℒSFT(θ;ℬ)=−∑i∈ℬ∑t=2Timi,tlogpθ(xi,t∣xi,<t)∑i∈ℬ∑t=2Timi,t

mi,t = 1 on the retained assistant spans of the current turn (reasoning when present, serialised tool calls and their arguments, visible responses, end-of-response tokens), 0 everywhere else including padding ({{Eq. 1|ax:S4.E1}}). Every supervised token weighs the same, normalised by the count of supervised tokens in the batch, not by sequence length or number of turns, so a long multi-tool turn counts in proportion to how much the assistant wrote.

Routing-guided curriculum

[[S4.SS2|§4.2]]

Agent interactions range from routine replies to complex planning and tool coordination, and the routing estimate of that demand orders the SFT examples into a curriculum. For each example the router gives an assigned tier ki and a normalised score vector πi over C0 to C3; the curriculum key is either ({{Eq. 2|ax:S4.E2}}):

si=ki(hard)orsi=∑k=03kπi,k(soft)

The estimate is re-made from the request and the history available before the first supervised response, and assigned to the whole example: a turn-level ordering proxy, not a difficulty label for each action. It changes when an example is seen, never its targets, and it is not used to reweight the loss.

Training runs in three stages of roughly one third of the examples each, bringing in higher-scored examples stage by stage while reserving some lower-scored examples for later stages, so the end of training is not made only of high-demand interactions. Every example is used once per pass, the objective stays Eq. 1 throughout, and the optimizer and learning-rate schedule are not reset between stages ({{§4.2|ax:S4.SS2}}, {{Figure 5|ax:S4.F5}}). The paper does not say how many low-scored examples are held back, or how. Routing-guided on-policy distillation

[[S4.SS3|§4.3]]

SFT learns from recorded responses, but a deployed student conditions on its own generated prefixes. On-policy distillation (OPD, {{Agarwal et al. 2024|https://arxiv.org/abs/2306.13649}}) closes that gap: the student generates, and a teacher supplies a next-token distribution at every position of the student's response ({{§4.3|ax:S4.SS3}}). Here the starting contexts are recorded states just before assistant responses, scored with Eq. 2 and introduced over the same three stages (ρj is the stage-j distribution over context batches), lower-scored contexts again partly reserved for later. At stage j a rollout checkpoint generates one response per context; a fixed teacher (not named in the report) scores each position given the context and the student's preceding tokens, both models rendering the same messages with their own templates and token IDs aligned. The rollout checkpoint is refreshed as training proceeds, so later contexts are supervised on more recent student behaviour.

ℒOPD=1∑rwr∑r∈ℛwrLr∑t=1LrDKL(P~θ,r,t‖Q~r,t)

{{Eq. 3|ax:S4.E3}}. P̃ and Q̃ are the student's and teacher's distributions coarsened to K + 1 bins: the rollout student's top-K candidate tokens at that position, plus one bin holding all remaining probability (both models use the same candidates and their full-vocabulary probabilities). The KL runs from student to teacher, a reverse KL, which pushes the student off tokens the teacher thinks unlikely. Each response contributes its average per-token divergence (Lr is its retained length, wr a fixed weight, 1 unweighted); prompt and padding get no loss; gradients flow through the current student's probabilities with the generated tokens, candidate IDs and teacher scores held fixed. Stage j's objective is the expectation of this over contexts from ρj and responses from the rollout student ({{Eq. 4|ax:S4.E4}}).

Lumping every token outside the student's top K into one bin makes the loss cheap to store. Compared with the reverse KL over the full vocabulary, can the coarsened KL be larger, is it always smaller or equal, or can it go either way?

Merging outcomes can only hide differences between two distributions, never create them (the data-processing inequality), so the coarsened KL is a lower bound on the full one.
