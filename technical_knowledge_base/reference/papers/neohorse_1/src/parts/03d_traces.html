What the traces show

[[S5.SS1|§5.1]]

To explain the scores the authors read representative trajectories. Three in the main text ({{§5.1|ax:S5.SS1}}):

Training closes the loop (4B)

QwenClawBench, project scheduling. Qwen3.5-4B finds the files but never opens a manager's email with an updated dependency, plans from stale information, produces an invalid schedule and writes it to the wrong place. NeoHorse-1-4B reads the email, recognises the new dependency, recomputes and verifies the schedule and saves it to the required path.

Scale under feedback (4B vs 9B)

WorkBuddy, code repair. NeoHorse-1-4B stops after one implementation attempt with no test and repair loop, leaving an error in thread-execution semantics. NeoHorse-1-9B runs a full edit, test, inspect, repair cycle until the verifier passes, treating test outcomes as inputs to its next decision.

Changing strategy (4B vs 9B)

PinchBench, data analysis without pandas. The 4B keeps trying to install the dependency, parse the CSV by hand and patch scripts, adding errors until no report comes out. The 9B abandons pandas for Python's standard csv and math libraries and finishes; against the 4B run it uses fewer model requests, execution time and tokens.

The authors' reading: the larger model's advantage is not more actions or wider search, but recognising unproductive trajectories, revising strategy from environmental feedback and spending a limited interaction budget on actions that move the task forward.

Appendix B: three cases, base 9B against NeoHorse-1-9B

[[A2|Appendix B]]
A: daily ticket report

A Chinese Markdown report for 18 May 2026 from a 64-row ticket export, a JSON state snapshot with key aliases, guidance and an interface description: exact desk and channel matching, merged aliases, each ticket's latest in-day update, next-day updates must not override. Qwen3.5-9B rewrites the report repeatedly; its final version says 20 tickets while its status counts sum to 26 and progress counts to 31, and it gives ticket 3101 the next-day state of R-004 while saying R-004 is excluded. NeoHorse-1-9B reports 50 eligible records and 19 tickets, matching an independent recount, gives R-003 resolved/100% and keeps source-row references, but puts two priority labels where status labels belong ({{Table 4|ax:A2.T4}}).

B: time-leakage auditor

Complete app/audit_leakage.py: allow a small tolerance, record genuinely late features, keep exporting clean samples; the README sets five minutes and fixes the output schema. Qwen3.5-9B never reads the README, hard-codes a 2-second tolerance, rejects sample s1 (cutoff 10:00, feature at 10:04, inside the window), renames the output file, emits features for feature_count and drops the summary structure. NeoHorse-1-9B reads the README first, uses 5 minutes, keeps the CLI, runs it and checks both outputs: s1 and s3 kept in order, s2's 10:06 and s4's next-day features rejected ({{Table 5|ax:A2.T5}}).

C: Gomoku in HTML

"Use HTML to create a simple Gomoku game", replayed with the same 26 clicks. Qwen3.5-9B's handler reads nonexistent cell.clientX/clientY properties, so every click gives an invalid index: the board stays empty and the turn indicator stays on Black. NeoHorse-1-9B shows 13 black and 13 white stones matching the input after every move, turn back to Black, gameOver=false, no runtime exceptions ({{Table 6|ax:A2.T6}}, {{Figure 8|ax:A2.F8}}).

These are chosen examples, one run each, and the authors' own interpretation column is careful (Case A: "improved grounding does not establish complete output consistency"). They illustrate the kind of difference, not its frequency.

The data experiments

[[S5.SS2|§5.2]]

Two controlled experiments on the 4B, both starting from Qwen3.5-4B and scored on the five benchmarks every checkpoint has (LiveCodeBench, HumanEval, IFBench, BFCL v4, τ²-Bench) ({{§5.2|ax:S5.SS2}}).

Source of the trajectories. Routing-harness data against {{Toucan|https://arxiv.org/abs/2510.01179}}, a public synthetic tool-agent dataset. Both are scored by the same offline routing labeller and trained with the same curriculum, optimizer, seed, packing and evaluation, at "closely matched" budgets (the sources differ in sequence composition). The harness run wins on all five, by +6.26 on average: HumanEval +8.54, τ²-Bench +11.31, the rest +2.43 to +5.00 ({{Table 3|ax:S5.T3}}). The authors conclude that routing-mediated interactions "provide stronger and more transferable agentic supervision than public synthetic trajectories".

Amount of data. From one quality-ranked pool, strictly nested subsets (each contains the previous), with initialisation, optimisation, packing and passes fixed. The five-benchmark average rises "steadily" from 69.31 for the base to 71.45 at the largest size, measured in unique supervised tokens on a log axis ({{Figure 7|ax:S5.F7}}).

Table 3 never prints the untrained Qwen3.5-4B on those five benchmarks. Where does it sit?

Read together, the two experiments say less than the text claims. The base is 69.31 (Figure 7 prints it; it is also the mean of the base's five Table 1 scores). So the Toucan run made the model 4.99 points worse than not training at all, and the routing-harness run made it 1.26 better; the +6.26 is mostly the public data hurting. Both runs also score below the base on BFCL (57.20 and 54.77 against 61.02). Decoding Figure 7's vector markers shows Table 3's harness run is Figure 7's second point (70.57, at about 3.4 million unique supervised tokens), and that the whole scaling sweep spans 1.7 to 10.1 million tokens in six equal steps. The released NeoHorse-1-4B scores 74.39 on the same five: of its gain over the base is not reached by any controlled run, so it comes from whatever the full recipe adds (more data, on-policy distillation, other stages) and the paper does not break that down.
