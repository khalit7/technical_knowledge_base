Schedule the checkout yourself

The checkout endpoint needs three services: user (400 ms), config (600 ms) and profile (300 ms), and profile needs the user's id ({{server.ts|https://github.com/benchflow-ai/skillsbench/blob/main/tasks/react-performance-debugging/environment/api-simulator/src/server.ts}}). The verifier wants the request under 800 ms and at least 400 ms, "Checkout calls user(400ms), config(600ms), profile(300ms) - even optimized takes 600ms+" ({{test_outputs.py|https://github.com/benchflow-ai/skillsbench/blob/main/tasks/react-performance-debugging/verifier/test_outputs.py}}). Choose when config and profile start, or pick one of the arms' schedules.

The model adds the service delays along the schedule's critical path and nothing else; the measured times (the paper's 915 ms for the workflow patch and a warm average of 711.6 ms for the skill patch) add about 12 to 15 ms of request and framework overhead. The task's reference solution uses the skill's schedule ({{solve.sh|https://github.com/benchflow-ai/skillsbench/blob/main/tasks/react-performance-debugging/oracle/solve.sh}}). The shortest possible time is the longer of user then profile (700 ms) and config (600 ms).
