Method: Algorithm 1, line by line

[[S3|§3, Algorithm 1, Appendices B and G]]

Architecture ({{§3|ax:S3}}, {{Appendix G|ax:A7}}). Each block computes MLP(x) + gR(x) + gF(x), each adapter a bias-free SwiGLU branch g(x) = Wdown(SiLU(Wgatex) ⊙ Wupx), the same as widening the MLP's hidden layer. Wdown starts at zero, so training starts from the base model exactly. Each adapter has 3dnL parameters (hidden size d, width n, layers L): 28.3M per adapter for Qwen3-8B (d = 4096, n = 64, L = 36), the two together 0.7% of the model; 0.83M for SmolLM2-135M, 62.9M for Qwen3-32B (all three recomputed in {{the checks|tab:t-tables:gfChecks}}).

One training step ({{Algorithm 1|ax:alg1}}), a modified GRPO step:

  1. Roll out target-environment groups from πR+F (both adapters on) and anchor-environment groups from πR.
  2. Run the monitor: flagged target trajectories form BF, the rest BU. The reward is never changed.
  3. Advantages: the GRPO advantage with one change, the group baseline averages only the unflagged rewards (the standard deviation still uses all of them):
âτ = ( rτ − mean{ rτ′ : τ′ ∈ Gτ \ BF } ) / ( std{ rτ′ : τ′ ∈ Gτ } + ε )
gR = (1/N) ∇θR[ ℓ(πR+F, BU) + 0 · ℓ(πR+F, BF) + ℓ(πR, BA) ]
gF = (1/N) ∇θF[ ℓ(πR+F, BU) + 2 · ℓ(πR+F, BF) ]

Why each piece is there:

  • The baseline skips flagged samples ({{Appendix B|ax:A2}}). Flagged hacks usually have high reward. With the ordinary group mean, the samples that do update θR would carry negative advantages on average, which the authors found destabilised πR. Excluding them makes the retain adapter's advantages sum to zero in every group. The cost, stated in the appendix: a lone unflagged sample in a group gets zero advantage.
  • The ×2 on the forget adapter ({{Appendix B|ax:A2}}). Masking θR halves the parameters a flagged sample can move (the adapters are the same size); doubling θF's gradient keeps the total push on flagged behaviour the same as without routing. Without it, the monitor would act as a reward signal again, just more quietly.
  • Adam would undo the ×2, because it divides each parameter's step by a running estimate of its own gradient size. So the optimiser takes its second moment from the unrouted gradient (both coefficients set to 1) and its first moment from the routed one ({{Eq. 1|ax:S3.E1}}); the code calls it SplitMomentAdamW.
  • The anchor environment. Without it nothing ever trains πR as it will be deployed. For Qwen3-8B the anchor is LeetCode (medium and hard problems), a different Python task. In the toy environments the anchor is the target environment itself, sampled from πR with a penalty on flagged samples ({{§4.2|ax:S4.SS2}}), so there πR does see the monitor, on 128 of every 640 samples ({{Appendix G.2|ax:A7.SS2}}).
  • MLP adapters, not LoRA ({{Appendix G|ax:A7}}). Two LoRAs on the same matrix W add into one update W + Δ1 + Δ2; in the full-rank limit ∂L/∂Δ1 = ∂L/∂Δ2 on every sample, so unrouted samples train both identically and the adapters end up alike. Separate MLP branches have their own hidden units and do not share that update. The authors report weaker localisation with LoRA, without numbers.

Cost ({{Appendix G.6|ax:A7.SS6}}): an update costs about what adapter fine-tuning with the same number of adapter parameters costs, and runs converge in about the same number of steps. Routing needs separate losses per routing class; their packed kernel does it in one forward and backward pass. In some toy runs the deployed hack rate fell only after the reward had converged, so those runs used more compute. Hardware: 1 to 2.5 H200-hours per small run, 2 to 4 per Qwen3-8B run, 4 hours on 8 H200s per 32B SFT run plus 1 to 1.5 hours of agentic evaluation per checkpoint.

The same for supervised fine-tuning, and the variants

For SFT ({{§3, Variants|ax:S3}}, {{§5|ax:S5}}) the loss is cross-entropy and there are no advantages: BF comes from the labelled hacks DL, anchors from a random 1% of the unlabelled data DU (forward pass through πR, retain update only), and the rest of DU updates both adapters. Anchors may contain some hacks in SFT, the authors argue, because the training distribution is fixed; in RL a hack reinforced in an anchor update could grow. With minibatches, lines 6 to 8 run once per minibatch. Hyperparameters for Qwen3-8B ({{Appendix G.3|ax:A7.SS3}}): rollout batch 1,024 target plus 64 anchor samples, groups of 16, cosine learning rate 1.67e-4 over 200 steps, no KL term, DAPO's asymmetric clip (0.2, 0.28). The learning rate was tuned per method on what a practitioner can see (proxy reward and flagged rate): 1.67e-4 for GRAFT, 5e-4 for the penalty and steering.
