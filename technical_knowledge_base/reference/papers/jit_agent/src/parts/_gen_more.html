The paper

JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution (arXiv HTML v2)

Preprint (ICLR 2027 template), the paper itself; the HTML version has the anchors this page links to. abstract page, PDF.

(45 min)

Code: bingreeky/JIT, MIT. bingreeky/JIT, MIT

The inference runtime (generate three harnesses, pick one, run it, score it), the HarnessFactory seed harnesses (11 of the paper's 13), adapters and data for seven of the nine benchmarks (not BrowseComp-Plus or PinchBench). No training code for the three stages and no streaming archive. The 27B checkpoint is on Hugging Face (Apache 2.0), as are 2,852 of the training harnesses.

(20 min)

Best resources

bingreeky/JIT on GitHub

the authors, MIT licence, commit ababa06 of 27 August 2026: the runtime: jit/README.md explains generate, select (the model ranks its own three candidates by log-probability) and execute; harness_factory/ holds the seed harnesses with a design write-up for each.

(20 min)

JIT-Agent/jit-27b

Hugging Face model card, Apache 2.0: the released checkpoint: 27.36B parameters on Qwen3.6-27B, "the initial research release", built on the Stage-I model and "further trained through distillation from the final research checkpoint".

(5 min)

JIT-Agent/jit-meta-harness

Hugging Face dataset: 2,852 training harnesses for 1,427 task instructions, each as the four Python modules plus a prompt file; the browsing and counting on this page's second tab come from it.

(15 min)

Project page

the authors: the leaderboard figure from v1, the method overview and the generated-harness gallery.

(5 min)

GDPO: Group reward-Decoupled Normalization Policy Optimization

Liu et al., NVIDIA, arXiv 2601.05242: the method Evo-GDPO adapts: GRPO applied to a sum of several rewards collapses distinct reward combinations into identical advantages; normalising each reward separately keeps them apart.

(30 min)

Meta-Harness: end-to-end optimization of model harnesses

Lee et al., arXiv 2603.28052: the ahead-of-time approach JIT-Agent argues against: search for one durable harness from traces, then keep it.

(40 min)

Connected papers in this knowledge base

HarnessDev: Can LLMs Create and Evolve Their Own Agent Harness?

Asks whether untrained frontier models can build and evolve a harness; their evolution steps helped held-out scores only about half the time. JIT-Agent claims the same skill can be trained, but never measures evolution step by step.

Prime Agent: A Self-Improving RLM Harness

The mirror image: it gives an untrained model a rich harness and notes models are not trained to operate it; JIT-Agent trains a model to build the harness but keeps the harness simple. Neither has done both.

StateM

The hand-built harness whose lift JIT-Agent tries to automate; StateM's versioned YAML runbook is roughly a hand-tuned (M, P, A, F) instance.

Demystifying Agent Skills

The F module is the skills question; the 10% skill-misapplication rate found there is a plausible source of residual failures. In the released training harnesses, F mostly exposes every tool.

Learn What's Left, Not What's Mastered (SA-MRPO)

The same multi-objective RL problem as Evo-GDPO's three channels, approached by saturation-aware reweighting rather than frontier comparison.

Repo-To-Skill

Another way to make the capability layer learnable: distil repositories into skills. Like JIT-Agent, its headline gains need checking against what each result actually used.

NeoHorse-1

Uses the serving harness as a training curriculum; like JIT-Agent it ablates none of its own components.

ReAct

The baseline harness of Figure 4 and the first row of the seed bank: full history, no planner, the ReAct loop, every tool.

DeepSeekMath (GRPO)

Where group-relative advantages come from; Evo-GDPO keeps the group but normalises each reward channel separately.

Direct Preference Optimization

Stage I's preference step is DPO weighted by the size of the reward, latency and cost gap.
