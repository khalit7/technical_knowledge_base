Run a toy Mamba

Five small models trained offline on the paper's two synthetic tasks ({{§4.1|ax:S4.SS1.SSS1}}) and run here in plain JavaScript: the Mamba block exactly as the released code builds it, with the selective layer (S6) or with Δ, B, C frozen into constants (S4, time-invariant), plus a small Transformer for comparison. Everything below is computed live from their weights.

Every model: 2 layers, D = 32, E = 2 (64 inner channels), N = 16, convolution width 4, Δ rank ⌈32/16⌉ = 2, S4D-Real initialisation of A, Δ bias from Uniform[0.001, 0.1], RMSNorm, tied embeddings, discretisation as the code (A = exp(ΔA), B = ΔB). The Transformer: 2 layers, 4 heads with RoPE, SwiGLU MLP of width 64, RMSNorm, no biases (the paper's MHA-RoPE baseline in miniature). Trained with AdamW (0.9, 0.95), constant learning rate 1e-3 after 200 warmup steps (the paper uses constant rates for these tasks), batch 32, fresh random sequences every step, at most 8,000 steps, stopping early once 500 held-out sequences were all right three checks running. "Held out" is 1,000 sequences from a separate seed; none of them occurred in the training stream (checked by hashing every training sequence). Weights shipped at 6 bits per matrix entry.

Selective Copying: edit the input

[[S4.SS1.SSS1|§4.1.1, Table 1]]

Click a position to cycle its token (noise, then the 8 colours); the six markers at the end ask for the data tokens in order. The task generator always places exactly 6 data tokens; with more or fewer you are testing outside the training distribution, which is a fair experiment to try.

Try: put two data tokens next to each other, or one at position 1 and one at 48: the selective model does not care about spacing. Then look at the Δ strips (averaged over channels): in the selective model they move with position and at the markers rather than spiking on the coloured tokens (the textbook picture is not what this toy learned; see the Selection animation on The paper tab); in the time-invariant one they are flat by construction.

Induction Heads: train at 64, test at any length

[[S4.SS1.SSS2|§4.1.2, Table 2, Table 11]]

Each sequence is random tokens with one trigger token (▲) placed once and followed by the answer; the trigger appears again as the last token and the model must output the answer. All three models were trained only at length 64.

Try: start at 64 (all three are right), then 256, 1,024 and 16,384. The Mamba models run in recurrent mode, one token at a time with a fixed state, so their cost grows linearly and their memory not at all; the attention model is quadratic and is only run up to 4,096 here (the paper stopped at 16,384 for memory). Long lengths take a few seconds.

Measured offline in PyTorch on the shipped (quantised) weights, from 26 to 220 = 1,048,576 tokens (200 sequences per length up to 4,096, then 64, then 16 from 217; attention to 213, which already took 12 minutes on a shared CPU), against the paper's {{Table 11|ax:A5.T3}} (trained at 256). The x axis is the test length divided by the training length, so the two line up.
