Then and now: from all-Mamba to hybrids

What happened to the architecture after the paper, one released model at a time, each drawn from its own config.json: which layers mix tokens with attention and which with a state space layer, and what that costs in memory at inference. Attention layers pay a KV cache that grows with every token; SSM layers pay a fixed state.

One square per layer, in order. KV cache per token = 2 × attention layers × KV heads × head size × 2 bytes; state per sequence = SSM layers × (inner width × state size + convolution buffer) × 2 bytes; both bf16, from each model's config.json (sources in each step). Jamba and Granite also replace most MLPs with mixtures of experts, Nemotron 3 Nano too; that changes compute, not the cache.

Try: cache plus state per sequence for every model above at the chosen context (log scale). Over the whole range the pure SSMs are cheapest and flat; the 2.7B Transformer's cache already passes Mamba's whole state at 38 tokens. At 128K tokens the hybrids need between about a third (Mamba-2 + attention, 6 attention layers of 64) and a fiftieth (Nemotron 3 Nano, 6 attention layers with 2 KV heads) of the Transformer's 40 GiB: their cost is still almost all cache, so the number and width of the attention layers decide it. Mamba-3 (2026) is not drawn: it changes the layer (a more expressive discretisation, complex-valued state, multi-input multi-output) and reports Mamba-2's perplexity at half its state size ({{Lahoti et al.|https://arxiv.org/abs/2603.15569}}), but no config of a released language model of that family was used here.
