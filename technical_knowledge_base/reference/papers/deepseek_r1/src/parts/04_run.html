Train a tiny R1-Zero

A 1,514-parameter policy, pretrained on an illustrative "web" of worked solutions, then trained in your browser with GRPO exactly as R1-Zero was set up: a rule reward for accuracy and format (Eq. 4), 16 answers per question, 16 minibatches per rollout trained once each, clip ratio 10, KL 0.001 to a reference replaced every 16 steps, and a length cap that is raised late in training, as R1-Zero's was at step 8.2k of 10,400. Nothing is shipped but the pretrained base model; every number below is computed here, deterministically, and the engine's gradients match PyTorch autograd of the paper's objective to @@CHECK@@.

What is built in, and what is tested

By construction: a question is n digits (n from 1 to 8, each 0, 1 or 2); the answer is their sum mod 3. Each thinking token reads one digit and claims the running sum; the network never sees the whole list at once, so a model that answers before reading every digit must guess. Longer thinking helps here because the toy is built that way (one addition per token, the toy's stand-in for a fixed amount of computation per token). What the toy tests is everything else: whether an outcome reward alone, through GRPO's group baseline, finds that out; how fast; what a length cap does; what the language reward, a cold start, a small clip ratio and Dr. GRPO's unbiased loss change. It cannot test whether an LLM's reasoning is real, how R1's cold start affects a strong base, or anything at scale.

What the toy reproduces, and what it does not
    The toy in full: task, model, corpus, settings against R1's
    Task
    n digits, n uniform from 1 to 8, digits uniform in {0, 1, 2}; answer the sum mod 3. Guessing scores 1/3.
    Tokens
    thinking tokens 0, 1, 2 (language A) and 零, 一, 二 (language B), each claiming the running sum; </think>; answers →0, →1, →2. After </think> only an answer may follow. An answer without </think> fails the format rule; running out of length before answering scores 0.
    Policy
    a one-hidden-layer network (36 one-hot inputs: previous token, the digit under the reader, digits left, last claimed sum, thinking tokens so far; 32 tanh units; 10 outputs): 1,514 parameters
    Corpus
    illustrative 35% answer straight away without tags, 50% open the tags and write 0 to 3 steps, 15% write every step; writers know the answer, so short solutions still end with the right one, which the model cannot see. 55% language A, 25% B, 20% switching token by token; 5% of steps are slips, carried forward.
    Pretraining
    20,000 documents, 3 epochs, Adam 3e-3, batches of 32; weights rounded to 4 decimals and shipped. Base model: 44% accurate at cap 7 (48% at cap 10), 1.4 thinking tokens per answer, 63% of answers well formed.
    Cold start
    128 clean solutions, every step written, all in language A; 4 epochs, Adam 3e-3, batches of 16: 79% accurate before any RL.
