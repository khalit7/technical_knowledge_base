Result 1: Creation, and the distance to human references

[[S4.SS2|§4.2, Tables 3 and 4, Figure 4]]

Every creator turned the zero-scoring seed into something that works, and quality varied sharply by task family. Under Self-Eval Opus 4.8 has the best average, 67.8, against 86.2 for the human-engineered references ({{Table 3|ax:S4.T3}}). Both averages are over SWE-Pro, Terminal-Bench, EQ-Bench3 and BrowseComp only; MLE-bench is left out of the Avg. column (this page recomputes every average in Tables 3 and 4 from its row: all 13 match).

On which benchmark did the best generated harness beat its human-engineered reference by the widest margin?

Each bar is a creator's avg@3 score as a percentage of the reference for that benchmark (the paper's {{Figure 4|ax:S4.F4}}, rebuilt from {{Tables 3 and 4|ax:S4.T3}}); the raw score is at the bar's end. The line under each benchmark names the model the reference ran ({{Table 9|ax:A2.T9}}). Starred references are external reports the authors did not re-run.

The paper's summary of this chart: generated harnesses match the reference on short-form writing (EQ-Bench3), exceed it on machine-learning experimentation (MLE-bench), stay substantially behind on code, and are furthest behind on search and research (BrowseComp), which needs long-horizon information seeking ({{§1|ax:S1}}, {{§4.2|ax:S4.SS2}}). Opus 4.8 and Gemini 3.1 Pro lead MLE-bench with medal rates of 32.9 and 32.4 against the reference's 24.0.

Two things the chart shows that the summary does not:

  • "Match" and "exceed" are about the best creators. On EQ-Bench3 Opus (84.6) and GPT-5.5 (83.0) are at or above the reference's 83.7; the other four score 68.7 to 75.4. On MLE-bench two creators beat 24.0; the other four score 3.1 to 19.6.
  • The references did not run the same models. The writing reference (Kimi Writer) ran Opus 4.8, the same model as the best creator, and the MLE-bench reference (MLEvolve) ran Gemini 3.1. The code and search references ran Claude Fable 5 and GPT-5.6 Sol, newer models than any creator ({{Appendix B.2|ax:A2.SS2}}). The paper says plainly that the references "are not paired controls under a common executor" and the figure "only shows the distance to the selected mature systems" ({{Figure 4 caption|ax:S4.F4}}). So where generated harnesses "lose", part of the gap is the model. See {{How much to believe|tab:t-read:s-trust}}.

Single harnesses are not representative ({{§4.2|ax:S4.SS2}}), hence avg@3. One Opus code harness nearly collapsed under Gemini because it hard-coded a 120-step limit around its original executor; strict stopping rules did similar damage in Data. Table 4 marks three code cells containing one collapsed replica: without it, Opus on SWE-Pro is 49.1 instead of 33.0, and DeepSeek 43.8 and 57.3 instead of 29.2 and 38.2 ({{Table 4|ax:S4.T4}}). GPT-5.5's EQ-Bench3 cell (46.5) includes a first harness that scored zero; without it, 69.7.

Cost is uneven, and paying more does not buy more. MLE-bench executor tokens vary about nineteen-fold between creators' harnesses (557.1M for Seed 2.0 Pro against 29.3M for GPT-5.5; 557.1 / 29.3 = 19.0). GPT-5.5's harness reaches a medal rate of 19.1 with 29.3M tokens while DeepSeek V4's reaches 19.6 with 208.4M ({{Figure 9|ax:A2.F9}}). The paper reports the trade-off directly rather than folding it into one cost-adjusted score; the {{tables tab|tab:t-tables:costCard}} has the scatter.

Result 2: a harness is tuned to the model that runs it

[[S4.F6|§4.2, Figure 6]]

Fixing the executor to Gemini 3.1 Pro changes the ranking ({{§4.2|ax:S4.SS2}}). Qwen, Seed and DeepSeek improve in several Data and Search settings under Gemini, so their own models were the bottleneck: Qwen gains 17.6 points on BrowseComp and 12.9 on MLE-bench. Opus and GPT-5.5 are usually stronger with their own executors. Opus's SWE-Pro harness falls from 69.3 to 33.0 and its writing harness from 84.6 to 74.2. In the Opus search harness the duplicate-query rate rises from 10.1% to 88.2% once Gemini runs it: its deduplication, review and stopping rules were fitted to Opus. Pick a benchmark:

Filled dot: Self-Eval (the creator runs its own harness). Ring: the same three harnesses run by Gemini 3.1 Pro. Gemini's own harness is the control, so its two marks coincide. Dashed line: the human reference. Values from {{Tables 3 and 4|ax:S4.T3}}; the paper's {{Figure 6|ax:S4.F6}}.

The conclusion the paper draws: a runnable harness can be used by another model, but capability transfers only when its prompts, tool protocol, budgets and stopping rules stay compatible. Self-Eval therefore measures harness design, executor capability and the fit between them at once, and a harness cannot be scored in isolation from the model that runs it. Note that the fixed executor is also one of the creators: under Unified-Eval Gemini runs its own co-adapted harness and everyone else's foreign one.

Result 3: what is inside the generated harnesses

[[S4.T5|§4.2, Table 5, Figure 5]]

Strategies differ. Opus often rewrites the execution stack; GPT-5.5 adds one large monolithic agent; DeepSeek, Qwen and Seed extend the seed with agent, tool, context and state modules; Gemini mostly edits the runner in place ({{§4.2|ax:S4.SS2}}). The 18 code artifacts add 17,111 net lines between them ({{Table 5|ax:S4.T5}}), and size does not predict performance: Gemini adds the fewest (1,006 lines over three harnesses, median 324) yet has the best Terminal-Bench score (68.8), which the authors read as "focused changes and frequent verification matter more than code volume".

Which modules exist. All 18 code harnesses implement an explicit execution loop; tools, lifecycle control and verification are complete in 13, 13 and 15 of 18 ({{Figure 5|ax:S4.F5}}). State and memory are the clearest gap: 11 of 18 define a State class, but only one exposes a state-saving interface and only one checkpoints periodically, and no checkpoint event appears in 26,679 recorded task trajectories. Validation is mostly syntactic: 441 of 2,325 executed Data tasks (19.0%) produce degenerate submissions that no harness detects, and 77.8% of failed Data tasks are attributed to harness defects rather than the executor.

Dead code. Of 108 component instances in the code harnesses, 72 trigger in real runs, 18 have only partial evidence and 18 are never observed, all of the unobserved ones state and memory. Beyond code, 124 of 587 writing features are confirmed dead code and 36 Data mechanisms sit on dead paths; small implementation errors can disable a whole tool chain.

Testing helps only when it changes something. The number of self-tests a creator ran has a Spearman correlation of only 0.13 to 0.26 with the downstream score (not significant), while the number of revision calls reaches 0.57 (p ≤ .0005). "Testing helps when the creator reads the failure, makes a targeted change, and re-verifies it." The two creation trajectories in the appendices show the contrast: GPT-5.5 turned every failed development run into a targeted fix, while Opus designed ten modules up front and made no harness change after two zero scores (both are laid out side by side in the {{replay tab|tab:t-run:crH}}).
