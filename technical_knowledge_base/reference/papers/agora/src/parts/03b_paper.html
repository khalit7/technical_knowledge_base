Reading the frontier: analyze, clusters and a diversity-aware ranking

[[S3.SS4|§3.3, §3.4, Eq. 3]]

agora analyze (a CLI command and HTTP endpoint) summarises the graph in views that answer those questions: what has been tried (recent activity, tags, contributors); which claims hold (unverified results, contested verifications, open hypotheses, so a worker can pick something to reproduce or test); where the frontier is (metric leaders, the most built-on nodes, promising results with at most two descendants, and leaves with no follow-on work). Every view can be rebuilt from the published record, and analyze is the first thing each session runs and the last before publishing, which makes it the main channel through which workers coordinate ({{§3.3|ax:S3.SS3}}).

Seeing concentration. A worker that picks the best-scoring parent tends to make the same choice as every other worker. To see this, the server embeds each description with Arctic-Embed 2.0 (568M parameters, 1,024-dimensional vectors, served through an OpenAI-compatible endpoint). Once at least 50% of contributions have embeddings, analyze forms single-link clusters, joining two contributions when the cosine similarity of their embeddings is at least a threshold (0.90 by default; pairwise analysis is capped at the 5,000 most recent contributions). With k clusters holding shares p1 to pk, it reports the top-cluster share max pi, the effective cluster count keff = exp(−Σ pi log pi) ("how many ideas are really being pursued": k when all clusters are equal, falling towards 1 as one dominates), evenness keff/k, cluster sizes, a metric histogram, and a frontier of promising nodes in small clusters ({{§3.4|ax:S3.SS4}}).

Equation 3 ({{§3.4|ax:S3.E3}}), a UCB rule in the spirit of bandits and UCT (Auer et al. 2002; Kocsis and Szepesvári 2006), plus a novelty term. Candidates are then shown in three slots: exploit (reproduce or refine the leaders), explore known (extend promising work in a thin cluster), explore novel (inspect untouched nodes in singleton or very small clusters).

Two details are easy to miss. For a minimised metric such as bits per byte, the "upper tail" that inflates C holds the weakest results, as the authors note themselves ({{§3.4|ax:S3.SS4}}). And the novelty term can reach 100D, as large as the whole quality term.

The run: 13 agents, one weight-transfer problem

[[S4.SS1|§4.1 to §4.3, Figure 2]]

The task. How much of a trained model's predictive quality can be put into a model whose architecture matches none of the available donors, using only the donors' weights and forward passes: no training corpus and no gradient update on the target? The donor zoo holds 141 open-weight models (534 GB) from 32 architecture families, including GPT-2, LLaMA, Mistral, Qwen, Gemma, Pythia, RWKV and Mamba. The target is a 14-layer hybrid that alternates attention blocks with simplified Mamba-style state-space (SSM) blocks, which keep Mamba's projections, depthwise causal convolution and gating but replace the selective scan with a data-dependent scalar gate; hidden size 672, seven query heads sharing one key-value head, untied embeddings, 119,572,320 parameters, dimensions chosen so that no donor matches any of them ({{§4.1|ax:S4.SS1}}).

The evaluator. A participant submits a Python file with a transfer(model, config) function that receives the randomly initialised target and returns it with new weights. The evaluator seeds every random-number generator with 42, runs transfer() and scores 200 FineWeb-Edu texts in non-overlapping 512-token chunks under the GPT-2 tokenizer, reporting bits per byte (summed next-token cross-entropy in bits divided by the UTF-8 byte count). The FineWeb-Edu loader raises an error if called from inside transfer(); the rules forbid pretraining, fine-tuning and editing the evaluator or target configuration. Two runs of the same code on the same hardware are bit-identical; across GPU types the score can differ in the third decimal place. Random initialisation scores 3.3923 and a conventionally trained GPT-2 124M about 1.0; the project README set an aspirational target below 2.5 ({{§4.1|ax:S4.SS1}}).

The workers, the launcher and the brief

The workers. Coding-agent sessions: Claude Code with Claude Opus 4.7, and Codex with GPT-5.5 or GPT-5.4, each started by a small launcher in a container with one GPU, one Agora account credential and a short prompt (stored as one line: "read program.md for full instructions, and run agora analyze to see what others have tried"; the H100 launcher, the only one whose logs survive, added "decide without asking for guidance" and "end the session only after publishing"). When a session ended, a new one started on a free credential. program.md, the first node, is a two-page brief: task, rules, evaluator contract, "every contribution must run from a fresh checkout", and the loop. Apart from an SVD weight-projection baseline shipped as an example, nothing names a method, assigns a role or ranks the participants ({{§4.2|ax:S4.SS2}}).

Thirteen worker accounts wrote 1,699 of the 1,703 contributions: worker1 to worker5 on A100 nodes from April 27, slurm_worker_1 to 8 on H100 nodes from April 28. The other four came from the setup account and three agent sessions the authors ran by hand (17 accounts in all). Of the H100 accounts' 1,285 contributions, Claude Opus 4.7 sessions published 866 (@@R:h100_models.opus_share:0%@@%), GPT-5.5 276 and GPT-5.4 143; the A100 workers' models were not recorded. Each worker had the Agora CLI, Git, Python with PyTorch and Transformers, the donor zoo, the evaluator and one 80 GB GPU. The eight H100 workers shared one eight-GPU node: no files, but they could list one another's processes, and several descriptions, the winning module's included, report choosing an experiment after seeing what neighbours were running ({{§4.2|ax:S4.SS2}}).

The loop. Each session read analyze, picked a parent, checked out that exact commit, made one change, evaluated, committed everything needed to reproduce, pushed with a description and metric, then posted what else it had learned (an insight, hypothesis, verification, or a new tag). Descriptions state the parent and its score, the single change, a predicted outcome band, the result and named follow-ups. The run lasted 11 days and 19 hours, from the setup commit on April 26 to the cutoff on May 8: 1,124 scored contributions (any that report a metric), 284 insights, 203 hypotheses, 165 verifications and one report, with tag overlaps (they sum to @@R:tag_sum:0@@); 232 scored ones beat random initialisation and every earlier score ({{§4.3|ax:S4.SS3}}).
