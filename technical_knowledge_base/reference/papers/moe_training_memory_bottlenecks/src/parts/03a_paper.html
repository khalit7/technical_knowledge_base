The row's earlier summary was written from a newsletter abstract (TLDR AI, 23 September 2026), not from the paper, and said so: no numbers, baselines, scales or ablations, nothing to quote as measured. This page is written from the full paper, titled on arXiv "Flattening Every Memory Peak in Long-Context Mixture-of-Experts Training". Its claim holds (four bottlenecks bounded by scheduling, not approximation), with three corrections: everything is measured on H200 nodes with 2 TB of host memory, 16 to 64 GPUs end to end, not on "a fixed pair of consumer cards" ({{Table 5|ax:A1.T5}}, {{§7|ax:S7}}); two of the four operators are offload, scheduled (it excludes quantisation and approximate routing, not offload, {{§1|ax:S1}}); and it builds on ZeRO-3 and on Megatron's vocabulary sharding rather than sitting beside them ({{§3.5|ax:S3.SS5}}).

Problem

[[S1|§1 Introduction]]

A training step dies when any one component's peak memory exceeds the device, so a plan that lowers three peaks and leaves the fourth free to grow "buys nothing at the point where the workload grows" ({{§1|ax:S1}}).

Mixture-of-experts (MoE) models are now trained at long context or large batch, and when adding GPUs is not an option, memory is bought with time. Every standard trade charges it: gradient checkpointing recomputes, state sharding (ZeRO, FSDP) communicates, and optimizer offload serialises the update on the host CPU ({{§1|ax:S1}}). Peak memory is a maximum over live sets, the groups of tensors that must be resident at the same moment, and the paper picks four that the parallelism plans in common use leave unbounded:

  1. Expert dispatch, which grows with the routing matrix the router draws: how many token copies land on one GPU.
  2. The vocabulary projection, which grows with tokens times vocabulary: the logits.
  3. Gradient-checkpoint boundaries, which grow with depth times sequence length.
  4. Optimizer state (AdamW), which grows with parameter count.

They grow at different rates, so which runs out first depends on the configuration: logits at large vocabulary and long context, dispatch at high routing imbalance, boundaries at depth, optimizer state at large parameter count on few devices ({{§1|ax:S1}}). Lowering the largest only exposes the next, so the paper bounds all four, each switchable on its own.

The constraint it sets itself: change only the order and granularity of computation and data movement. No low-rank adapters, no quantised state, no approximate routing or attention, so the model, parameterisation, optimizer, precision and loss stay those of standard full-parameter BF16 training, and the memory and throughput numbers are comparable with it ({{§1|ax:S1}}).

The four live sets

The fourth row is different in kind: offload already removes optimizer state from the GPU, and what stays unbounded is the time of the serial host update.

Each operator must return the forward values and gradients of what it replaces, change only the order of computation, and keep its bound through checkpoint recomputation, since a checkpointed step peaks inside backward ({{§2|ax:S2}}); that rules out keeping anything sized by the routing matrix.
