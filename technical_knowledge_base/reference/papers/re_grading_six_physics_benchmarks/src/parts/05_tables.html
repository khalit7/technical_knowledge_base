Table 1: pre-audit and corrected accuracy

[[S3.T1|Table 1]]

For GPT-5.6-Sol, the audit already fixes the corrected score

The audit run kept every question GPT-5.6-Sol answered acceptably at least once, and the experts turned its grader errors into correct answers. If the re-run reproduced the audit run, its pass rate on the kept questions would be (accepted + grader errors) / kept. The re-run lands a few points below that on every benchmark, as fresh sampling would: the corrected GPT-5.6-Sol scores are largely by construction.

Where the gain comes from: removal or re-grading

Drop the excluded questions and change nothing else: if they had all scored zero before, the pre-audit correct attempts divided by the kept questions' attempts is the score removal alone would give. It is an upper bound for removal's effect (any excluded question that scored above zero lowers it); above 100% it shows the assumption fails. Compare it with the reported corrected score.

CritPt is left out: its pre-audit score is a different metric (mean@5) on a different question set with different references.

Tables 3 and 4: how often the reviewers agreed

[[A6.T3|Tables 3 and 4]]

Scott's pi corrects raw agreement for the agreement two reviewers would reach by chance given how often each label is used. The paper prints raw agreement only and not each reviewer's label shares, so pi is bounded here: every split of the agreed cases into labels that is consistent with Table 2's final counts and Table 4's disagreement pairs is tried, and the lowest and highest pi kept. Values up to about 0.4 are usually called fair agreement, 0.4 to 0.6 moderate.
