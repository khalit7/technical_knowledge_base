Problem

§1 Introduction

The paper calls itself a proof-of-concept pilot study: one frozen Flan-T5-XL backbone, small trainable adapters, one dataset, and it is explicit that resource constraints shaped every choice (abstract, §1, §7.3). This page reads it the same way.

A frozen encoder-decoder language model is stateless. The encoder turns the current input xt into a latent Zt, the decoder reads Zt through cross-attention and writes the answer, and Zt is discarded after every forward pass (Eq. 1, Figure 1). Nothing persists between turns or sessions: if a user says "I like reading" in session 1 and asks "What do I like?" in session 3, the model cannot answer (§1).

The industry answer is text-level memory, which is what every agent framework ships: write facts to a store as strings, retrieve the relevant ones later, and paste them back into the prompt. MemGPT and MemoryBank are the paper's examples (§2). It works, but the write and the read are discrete, non-differentiable operations bolted on from outside the model.

The question: can memory live in the model's continuous latent space instead, so that reading and writing become differentiable operations on dense vectors that can be trained end to end, while every backbone weight stays frozen?

Idea

§1, Eq. 2

Add a persistent memory bank Pt, a matrix of nP rows of width d (Flan-T5-XL's d = 2,048), that survives from turn to turn. Each turn now does three things (Eq. 2):

EncodeZt = Efrozen(xt)unchanged
Readŷt = Dfrozen(Read(Zt, Pt−1))the answer sees what earlier turns left in the bank
WritePt = Write(Pt−1, Zt)this turn's latent is folded into the bank

Why not just keep the raw encoder outputs and let the decoder attend to all of them? The decoder's cross-attention was pre-trained to read current encoder states; piling up history in the same softmax spreads attention thin instead of sharpening retrieval. So a small trainable adapter θMem learns to put memory in a form the frozen decoder can use (§1, §7.1). The animation runs the paper's own example through both systems: the stateless baseline and a model with a bank.

The paper's example from §1; illustrative turns.

The bank's shading is the share of it that each turn still holds under the paper's decay γ = 0.95 per turn (§6.2): a turn written l turns ago keeps weight γl before normalisation. The simulation tab runs the real write rules.

Six methods

§4, Tables 1 and 2

The paper builds six variants spanning three injection points (where memory enters the frozen model: before the encoder, between encoder and decoder, or inside the decoder) and four write mechanisms (how the bank updates: an attention-coupled update, a Hebbian outer product, gated cross-attention, sparse slot addressing) (§1, Table 1). The backbone stays frozen and only the small adapters train. Each method borrows a known primitive: prefix tuning (M.1), Flamingo's gated cross-attention (M.2, M.5), Memorizing Transformers' extra keys and values (M.3), fast-weight outer products (M.4) and Neural Turing Machine slots (M.6); the contribution claimed is the controlled comparison, not the primitives (§2).

Pick a method to see where its memory enters and how it writes. Parameter counts are recounted from Flan-T5-XL's configuration (d = 2,048, 24 decoder layers, 2.85B parameters in total).

Delegated or explicit read. M.1, M.3 and M.6 hand all of P to the decoder as extra keys and values and let the frozen cross-attention pick; M.2, M.4 and M.5 do their own content-based retrieval first (Table 1). Two of the three "inside the decoder" methods are not built that way: for M.2 and M.5 the per-layer read is approximated by computing it once with Zt standing in for the decoder's hidden state and passing the result to the decoder as extra encoder positions (§4.2 implementation note, §4.5). As run, then, five of the six methods enter through the same door, extra positions in the decoder's cross-attention; only M.1 differs.

The write rules, in full. Four methods share one attention-coupled write: queries from the current latent, keys from the bank, values from the current latent, then Pt = γPt−1 + At⊤V with At = softmax(QK⊤/√d). Taking values from Zt, not from P, is what lets an all-zero bank fill up at all (Eq. 7). M.4 keeps a dh × dh matrix, adds (1/n)(ZWK,H)⊤(ZWV,H) each turn and rescales it whenever its Frobenius norm passes 1 (Eq. 16). M.6 mean-pools the turn, scores the 64 slots, and moves only the top 8 towards the new vector, γP[s] + (1 − γ)ut (Eqs. 24 to 28). Zero-initialised read projections (M.2's β, M.3's WMem) and M.5's negative gate bias make each method start exactly or nearly as the frozen baseline; M.4 initialises WQ,H small but non-zero, since zeroing both of its read matrices would deadlock the gradients (§4.4, §4.5).

Training, then conversational learning

§5, §6.2 Implementation details

"Frozen" means the encoder and decoder get no weight updates, not that gradients stop at them: the loss flows back through the frozen decoder (and, for M.1, the frozen encoder) to the adapter, the same principle as prefix tuning, LoRA and adapters (§5). Training has two phases (Figure 8):

  • Type 1, supervised. Only the small adapters train, by backpropagation of a teacher-forced answer loss (Eq. 31). The write rule runs without gradients, so the write-side projections (WQ, WK, WV, M.4's WK,H, WV,H, M.6's Wa, Wu) and the decay γ stay at their random initialisation for good. The paper argues that random maps still keep distinct inputs distinct (Johnson-Lindenstrauss); the read side learns to decode whatever the fixed write rule deposits (§5).
  • Type 2, conversational learning. After training, θMem is frozen too, but the bank keeps accumulating at inference with no gradients: every turn runs the write rule, so a fact stated in session 1 could in principle be recalled in session 10 without being restated (Eq. 32, §1).

The metric: a forgetting curve

§6.1, §6.3, Eqs. 33 to 41

Every condition sees only the current turn; no method gets the history as text (the equal-input principle, §6.2). For each LoCoMo question the evidence lag is the number of turns from the oldest annotated evidence turn to the end of the conversation, ℓq = T − min Eq (Eq. 37). Each trained method answers twice, with its bank intact and with its bank forced to zero, and the memory recall rate is the share of the available headroom the bank fills (Eq. 40):

ρq = max(0, F1mem − F1zero) / max(1 − F1zero, ε)

Scores are averaged in five lag buckets (0 to 31, 32 to 63, 64 to 127, 128 to 255, 256 or more turns) and smoothed with a weighted non-increasing isotonic fit, so a curve can only stay flat or fall with lag (§6.3).

The stateless baseline scores exactly 0% at every lag. What does that zero tell you?

The baseline has no bank to ablate, so F1mem = F1zero and ρ = 0 by definition (Eq. 41); it still answers some questions (6.44 F1, Table 5). The zero is a sanity check, not a comparison. And the max(0, ...) clips each question at zero before averaging: a bank that changes answers at random, helping some questions and hurting as many, still averages above zero. Try it:

Illustrative: 200 questions with a zero-memory F1 of 0.06 (near the baseline's 6.44); a helped question gains, a hurt one loses, by a random amount up to 0.3 F1 (seeded). The other questions are unchanged. The paper's own Table 5 shows this happening: at 1x M.1 scores a positive 0.02% recall rate while its answers with memory are 6.42 F1 points worse than the baseline's.

So the headline "all six positive" is close to guaranteed for any adapter whose answers change at all when the bank is wiped. What the metric can tell apart is how much each method helps and whether the help falls with lag, which is where the results start.

Results

§6.4, §6.5, §7.2; Tables 3 to 5

Evaluated on LoCoMo with the forgetting-curve protocol at two capacity scales, 1x and 10x (§6.4). LoCoMo is a public benchmark of 10 very long two-person conversations, generated by LLM agents and edited by people (19 to 32 sessions, 369 to 689 turns each) with annotated evidence turns for every question, which is what lets each question sit at a known lag (LoCoMo; counts from the released data). The test set has 639 questions, and 62% of them sit 256 or more turns back.

  • At 1x three methods score near zero: M.1 Prefix 0.02%, M.3 KV Ext 0.00%, M.5 Gated 0.15% on average. M.2 XAttn and M.6 Slot start above 17% at short lag and fall to about 9% and 7%; M.4 Hebbian is nearly flat at about 9.3% (Table 3). The 1x picture is weaker, and the honest read is that capacity is doing much of the work.
  • At 10x all six adapters score above zero at every lag, with means from 8.34% (M.5) to 12.05% (M.3). The paper says M.4 Hebbian "leads with ... the best mean (11.6%)" and that M.3 has "the highest short-lag recall (15.6%)"; its own table has M.3's mean higher (12.05 against 11.60) and M.4's short-lag score higher (15.86 against 15.58) (§6.4). Weighted by the number of questions per bucket, M.4 does lead (10.60 against 10.17), and it has the best long-lag score (10.32).
  • Most of these gaps are noise. With 28 questions in the shortest-lag bucket, a 15% average can carry a standard error of up to about 7 points (the bound for a score between 0 and 1) before the isotonic fit; the means carry about ±1.2. Every 10x method sits between 7.8% and 10.6% on the question-weighted mean. One seed, so seed-to-seed spread is unknown.
At 1x, M.3 KV Ext's recall rate is 0.00%. With its bank switched on, how do its answers compare with plain Flan-T5-XL (no adapter, 6.44 F1)?

The paper's adapter-interference analysis, Table 5, gives two numbers per method: the adapter tax, how far the adapter alone (bank zeroed) pulls F1 below the baseline, and the net benefit, F1 with the bank minus the baseline (Eqs. 44, 45). Since the baseline is 6.44 F1 at both scales, both F1 levels follow; the chart puts them side by side.

F1 with the bank zeroed = 6.44 − tax; F1 with the bank = 6.44 + benefit (derived here from Table 5, which prints only tax and benefit). At 1x, M.1, M.3 and M.5 answer with memory at 0.02, 0.00 and 0.14 F1: memory switched on destroys almost every answer. The paper calls the tax "modest (2 to 4%)"; against a 6.44 baseline, 2.38 to 4.23 points is 37% to 66% of what the frozen model answered on its own.

Net benefit at 10x is positive for all six, +1.83 to +6.26 F1 points over the baseline; at 1x only M.2 (+6.76), M.6 (+5.75) and M.4 (+3.10) come out ahead (§7.2). The taxes take only two values per scale (2.38 or 4.23 for the delegated-read methods, 3.39 for every explicit-read one), which is unusual for six separately trained adapters and is not explained.

Knowledge accumulation (§6.5, Table 4): after writing sessions 1 to s, probe every question whose evidence is already written, and track the mean F1 Ks; ΔK = K30 − K1. At 1x M.6 has the largest gain (ΔK = 9.71) and M.4 (7.84) and M.2 (7.34) follow, while M.1, M.3 and M.5 stay under 0.2. Two things do not add up. The text says M.6 has "the highest terminal K30 = 9.7%", but M.2 (11.04) and M.4 (10.62) are higher in the same table. And the stateless baseline gains 5.57 points, explained as "more context injected into the current prompt", although the equal-input rule gives it only the current turn; with K1 = 0, what changes is which questions are answerable, not the baseline. Two of the three test conversations have 30 sessions; conv-49 has 25.

Why it matters (beyond the paper)

§7.4 Broader implications

The framing is the valuable part. Nearly all deployed agent memory is text-level and non-differentiable: retrieval is a separate system, and the model has no say in what gets written or how it is encoded. OpenClaw keeps memory as plain Markdown files such as MEMORY.md (OpenClaw docs); Hermes injects bounded MEMORY.md and USER.md files at session start and plugs in external memory providers (Hermes docs). Latent-space memory makes the write mechanism itself learnable, and the six-variant taxonomy (injection point × write mechanism) is a reasonable map of the design space, even if these experiments cannot rank the options convincingly.

What it does not show:

  • whether it beats a competent RAG or text-memory system: there is no RAG or text-memory baseline. For scale, on the same benchmark LoCoMo's authors report 41.4 F1 for GPT-3.5-turbo reading its top 5 retrieved observations, and 13.9 for Mistral-7B with no memory at all (LoCoMo Tables 2 and 3); here the best adapter with memory reaches about 12.7 F1 (6.44 + 6.26). Different models and possibly different scoring scripts, so a scale, not a comparison;
  • whether it transfers off Flan-T5-XL to a modern decoder-only model (the paper says this "must be validated separately", §7.3);
  • whether latent memory stays interpretable and auditable, which is exactly what makes text memory operationally attractive: a Markdown file can be read, corrected and deleted line by line, a 640 × 2,048 array cannot.

A positive score against a zero baseline is a floor, not evidence of a competitive system. The paper's own forward-looking claims (that unfreezing the backbone, 70B+ models, more data and banks of millions of slots will give "substantially stronger results", §7.3, §8) are expectations, not results.

Connections

  • The practical alternative it implicitly argues against: text-level memory in personal agents (OpenClaw's MEMORY.md, Hermes's memory providers and skills) and retrieval generally: RAG, Topic: rag-and-retrieval, and the text-memory agent papers Proactive Memory Agent and Just-in-Time Memory.
  • Related compression-into-latents work: context distillation (Snell et al.), KV-cache compression and Gist tokens (Mu et al.); at scale, Latent Context Language Models.
  • Adjacent in this batch: Bitune and LLM Modules, also frozen-backbone-plus-adapter designs; LoRA is the standard way to add few trainable parameters to a frozen model.
  • The backbone family: T5 (Flan-T5-XL is an instruction-tuned T5) and, for a newer encoder-decoder to retry this on, Encoder-Decoder Gemma and T5Gemma 2.
  • A bank that decays every step is a fixed-size recurrent state; Mamba learns an input-dependent decay instead of a fixed γ, which is the obvious fix for the problem below.

How much of this to believe

§6, §7, Tables 3 to 5

What holds up. The protocol is clean in two ways: every condition sees the same current-turn input, and each method is scored against itself with its bank wiped, so the score isolates what the bank contributes (§6.2, Eq. 40). The equations are complete enough to run (the simulation tab does), the hyperparameters are given, and the parameter counts check out when recounted. The author is upfront about the limits: a pilot, one backbone, one dataset, absolute recall "modest (up to ≈ 12%)" (§7.3), and that counts in the paper's favour.

The weaknesses, concretely:

  1. The headline cannot fail. The recall rate is clipped at zero per question, and the baseline is zero by construction (Eqs. 40, 41); any adapter whose answers change when its bank is wiped scores above zero (the widget under The metric). M.1 at 1x scores +0.02% while its answers are 6.42 F1 points worse than the baseline's (Table 5).
  2. No competitor. No RAG or text-memory baseline, not even "paste the last few turns into the prompt". The only F1 levels are derived: 6.44 for the frozen model, at most about 12.7 with memory.
  3. Five of the six write rules all but erase a turn within about 100 turns, but most questions are older. See the question below; only the slot rule (M.6) keeps a trace, because slots it does not pick do not decay.
  4. One seed, 639 questions, no error bars; most gaps between methods are inside one standard error (Table 3; bounds in the tables tab).
  5. The text disagrees with its own tables in eight places, listed with the evidence in the tables tab: the best 10x mean, the best 10x short-lag score, the best K30, "learned selective writes" (the write side is never trained, §5), "explicit gating (M.5, M.6)" (M.6 has no gate), M.2's "more selective" write (it is M.1's), the baseline's ΔK, and a LoCoMo "training split" that does not exist.
  6. The injection-point comparison is not what was run: M.2 and M.5 are approximated as extra encoder positions (§4.2), the same door M.3, M.4 and M.6 use.
  7. Nothing to check against: "we ... release six trained memory adapters" (§1), but no code or weights are linked from the paper or its arXiv page (checked 3 October 2026).
The bank decays by γ = 0.95 per turn. In the attention-coupled bank (M.1, M.2, M.3, M.5), how much of a turn written 256 turns ago is still there?

0.95256 ≈ 2 × 10−6. The bank is an exponential moving average with an effective window of 1/(1 − γ) = 20 turns; a turn's weight drops below bfloat16's resolution (2−8, the precision the backbone runs at) after 109 turns. Below, the paper's three write rules run on a synthetic 600-turn conversation (the bars are the share of LoCoMo's 639 test questions at each lag):

Yet the long-lag scores are where the methods score most of their points: 7% to 10% at 256+ turns, on 62% of the questions. Whatever earns that credit is unlikely to be the evidence turn itself. One candidate is recent context: in the three test conversations, 34% of answerable questions share a content word of the answer with the last 20 turns (33% of those at lag 256+), counted from the released data. And in the simulation, an attention-coupled bank that starts at zero, as §4.1's remark about zero initialisation suggests, keeps all 64 (or 640) rows identical forever, because identical keys give every row the same attention weight, and a bank started from small random values drifts to the same state (its rows' spread falls from 21% after one turn to 0.3% after 100, at 1x); ten times the rows then stores nothing more, so the "capacity" story does not follow from the write rule as written. The slot rule fares little better from a zero start: ties always pick the same first slots, so 64 of the 640 slots at 10x are ever written (simulation tab). Both are illustrative (random latents, d = 32), not a rerun of the paper.

Verdict: read it as a map of the design space and a clear statement of the problem, not as evidence that latent memory works. The metric cannot go below zero, three methods make answers worse at 1x, five of the six write rules as specified all but erase a turn within about 100 turns while most questions are older, and there is one seed, no competitor and no released code.

What it takes to use this

  • Code and licence: none. The paper promises six trained adapters; nothing is linked (checked 3 October 2026). Rebuilding means implementing the equations of §4 yourself; they are complete except for the initial bank and M.5's exact gate bias.
  • Hardware and budget: modest. A frozen 3B Flan-T5-XL in bfloat16 on one GPU, adapters of 1.0M to 21.0M parameters, 10 epochs over a few LoCoMo conversations (§6.2). The bank costs 0.5 MB per conversation at 1x and 5.2 MB at 10x in float32 (640 × 2,048 × 4 bytes; the paper's "≈ 5 MB", §7.4), one per user, stored outside the model.
  • What worked: at 1x only M.2, M.4 and M.6 beat the plain model; at 10x all six did, by 1.8 to 6.3 F1 points on a 6.44 baseline. Only Flan-T5-XL was tried; the frozen decoder must be open-weight and hookable (M.2 needs source-level access to the decoder blocks, §4.2).
  • When it pays off: as a research starting point for learned memory, mainly the taxonomy and the self-ablation metric (with the clipping removed). For an agent that has to remember users today, text memory or retrieval is far ahead on this very benchmark and can be read and audited; nothing here suggests otherwise. If you try it, start with a learned or input-dependent decay instead of γ = 0.95, so that turns can survive the hundreds of turns LoCoMo asks about.

Simulate the memory bank

The paper's three write rules, run exactly as written: the attention-coupled write of M.1, M.2, M.3 and M.5 (Eq. 7), M.4's Hebbian outer product with its norm rescaling (Eq. 16) and M.6's top-k slot write (Eqs. 24 to 28). The write projections are fixed random maps, which is faithful: the paper never trains them (§5). What is illustrative is the input: 600 turns of random latents with d = 32 features and 8 tokens per turn, instead of Flan-T5-XL's 2,048-wide encoder states. The row counts (64 or 640), the Hebbian size (scaled to d = 32 in the paper's 256 : 2,048 and 810 : 2,048 ratios), the 8 of 64 or 640 slots and γ are the paper's (§6.2). Everything runs in float64 in your browser, and check_sim.py checks this JavaScript against an independent NumPy implementation of the same equations: across 15 cases the largest relative difference is about 10−13.

The bank cannot be read without the trained read adapters, which were not released, so the simulation measures what any read could find: how much of the bank a turn still accounts for after l more turns, and how many different rows the bank actually holds.

Defaults reproduce

At γ = 0.95 the attention-coupled bank is an exponential moving average: a turn's weight after l turns is 0.95l, so 0.95256 ≈ 2.0 × 10−6, the effective window is 1/(1 − γ) = 20 turns, and the weight drops below bfloat16's 2−8 after 109 turns. These follow from Eq. 7 and the printed γ (§6.2) and are recomputed in recompute.py; the chart's curve follows the same slope, independently. Keeping 1% of a turn for 256 turns would need γ ≥ 0.9822 (try it on the slider). Not reproducible here: the recall rates themselves, which need the trained adapters and Flan-T5-XL.

Does a ten times bigger bank hold more?

The 10x results are read as "capacity is doing much of the work" (§6.4). Capacity only helps if different rows hold different things. In the attention-coupled write every row's key is computed from the row itself, so rows that are equal get equal attention and receive equal updates. The animation shows the 64 rows of a 1x bank (one column each, 32 features down) after each turn, from a zero start and from a small random start.

Colour: each cell's value divided by the largest absolute value in the bank at that turn (blue positive, orange negative). Spread: the rows' distance from their mean, as a share of the bank's norm. Random latents, d = 32, seed 7; illustrative.

What this cannot show: real encoder states are not random, and a trained read adapter might extract something from a bank whose rows agree (a single averaged vector of the last 20 turns still carries recent context). What it does show is that, as written, ten times more rows add no independent storage to the attention-coupled bank, and at 10x the slot rule from a zero start only ever writes 64 of its 640 slots, because ties go to the same first slots (from a small random start it writes 120 of them in 600 turns). The paper does not state the initial bank, so both starts are shown.
