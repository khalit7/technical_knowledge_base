Prime Agent: A Self-Improving RLM Harness

Seth Karten, Alex L. Zhang, Kevin Thomas, Sebastian Müller, Elie Bakouch, Daniel Auras, Mika Senghaas, Fares Obeid, Konstantin Dunas, Johannes Hagemann, Sami Jaghouar
Prime Intellect, with Princeton University and MIT (correspondence: Seth Karten, Alex L. Zhang) · 24 August 2026 (arXiv v1, the only version so far; the HTML says first published 5 August 2026, the day of the launch blog post)

In one line: Open-source harness built on a four-level state hierarchy (weights, context, persistent IPython REPL plus live subagents, disk history) with a Recursive Language Model abstraction, a Continual Harness that versions prompts/memories/skills/subagent specs across trajectories, and direct agent-to-agent messaging; lifts ARC-AGI-3 RHAE Best@1 from 30% to 95.5%, sustains 85.5-hour nanoGPT speedruns and 7-day Factorio runs, and reports that models are not trained to use most of what it offers.

Problem

§1 Introduction

A language model on its own is a bounded sequential processor: its next decision can use only what is in its weights and its active context. A harness supplies everything else, the tool calls that act on the world and the information management beyond what the weights already know (§1). The first such management was agentic compaction, where the model shrinks its own context and keeps what matters. The paper's claim is that the useful state has outgrown weights plus context, so a harness should give the model somewhere else to keep and process it.

The authors frame Prime Agent first as an evaluation harness (§1). The common long-horizon metrics are score at a fixed spend (tokens, cost, time) and score at a practical plateau, both from METR's note on metrics of agent ability. A model should fail an evaluation because the task is beyond it, "not because the harness dropped state, restricted useful actions, miscounted resources, or terminated prematurely". So the harness should be a thin, expressive membrane: it standardises execution, recovery, verification and resource accounting, leaves strategy entirely to the model, and so stops harness failures masquerading as model failures, pushing a measurement "toward the model's true maximal underlying capability" (abstract).

What the old summary added. It opened with "harness quality, not model quality, is now the binding constraint on long-horizon tasks", and the example of an agent failing at hour 40 of a 7-day task without anyone knowing whether the model or the harness ran out. That framing is the summary's own; the paper's argument is the narrower one above, about evaluation that does not confuse the two.

Idea: treat the model's state like a memory hierarchy

§2.2, Figure 2

Seen as a cache of state information, the model's weights are L0, its active context L1, a persistent REPL plus recursive subagents L2, and disk-backed history, memories and skills L3 (Figure 2). That makes the system "more von Neumann-like": the model can read, transform and write addressable state outside the instruction it is generating. The boundary that matters is between L1 and L2: above it, state is token-visible to one model call; below it, state is managed by code and enters the context only when something serialises it. Each level changes through its own mechanism. Click a level:

From that view, expressivity is the property a harness needs: rather than encode one workflow, it exposes primitives from which the model builds programs, subagents and feedback loops while it runs (§1). Prime Agent splits the job in two (§2.1): information management (what state enters a model call, and what survives compaction or restart) and computation management (mapping the model's chosen actions to code, tools and recursive subagent sessions), joined by direct agent-to-agent messages. Five properties follow: models handle intermediate values with code; sessions keep their history across compaction, detachment and restart; subagents inherit the root's execution and messaging primitives; the runtime records model calls, tool use, messages, harness changes and resource use; and the model, not the harness, controls decomposition, compute allocation, communication and stopping. The retained trajectories can also train later models.

The idea is easiest to see on the paper's own orchestration example (Appendix B): a parent hands a review and a test run to two subagents, then sends the reviewer a follow-up. Below, the same task runs through a classic harness, where a subagent is a tool call that blocks and pastes its answer into the parent's context, and through Prime Agent's rlm, where it is a persistent session the parent addresses by name.

Method

§2 Architecture

Figure 1 is the whole system: a human uses the Agents View to reach a root session; the root calls rlm() to start subagents, which act on the environment and send messages back; a daemon owns every session, and Continual Harness holds the state that persists between trajectories. Solid arrows carry execution and messages, dashed ones persistent state.

The persistent REPL and the RLM primitive

§2.3

Each session owns a persistent IPython REPL, and it is the model's main tool rather than a fixed tool schema (§2.3). Installed tools are imported as Python modules, so parsing, filtering, aggregating and verifying are ordinary code; intermediate values persist across turns and stay out of the context until selected, which avoids pasting large logs, task specifications and evaluator output into the context again and again. Test-time compute is then three things, model inference, Python execution and tool calls, and evaluations report tokens, time and cost separately.

The Recursive Language Model abstraction (Zhang, Kraska and Khattab 2025) is implemented as an asynchronous rlm function. Calling it creates and schedules a subagent session and returns a stable handle before the subagent finishes; the subagent gets its own model context, IPython kernel, history and workspace metadata; the parent keeps computing; results arrive later as agent-to-agent messages; and retained handles allow follow-ups after compaction or restart. The model chooses between local code, tools, sequential delegation and parallel subagents, and Prime Agent defines how each executes instead of fixing a workflow graph. In the launch post's words, context becomes a program the model writes rather than a policy the harness enforces (blog).

# Appendix B: admit independent subagents; do not wait for answers here.
review = await rlm("Audit the implementation. Reply with concrete issues.", name="reviewer")
tests  = await rlm("Run the test suite and classify failures.", name="tester")
# Later, recover retained sessions and send a follow-up.
children = await rlm.list_subagents()
await agent_message.send("Also inspect error-handling edge cases.",
                         receiver_role="child", receiver_name=review.name)

"The explicit reply path is intentional: a child is a persistent concurrent session, not a stateless completion returned by rlm" (Appendix B).

Moving information between levels

§2.2

External state affects generation only when the runtime injects it or an operation serialises a result into the context. Python values and tool outputs in L2 enter generation when serialised into L1. Compaction replaces a conversational prefix with a summary and keeps the original events in L3, where the REPL can retrieve them. The runtime assembles selected Continual Harness entries into later supplemental prompts; other L3 artifacts enter context on retrieval; L0 stays fixed. The model manages L2 itself by creating, keeping, summarising or deleting REPL values and subagent sessions as the task changes, which the paper calls agentic garbage collection (the blog adds that a spawned agent cleans the kernel asynchronously, to stop REPL memory building up).

What is kept: an append-only event history, selected kernel snapshots, the rooted session tree, context and compaction records, persistent message queues and versioned Continual Harness state. Branching or forking creates a new continuation without deleting the earlier events; recovery rebuilds a session under the same identity; Python objects that cannot be serialised, and external processes, are recreated from saved artifacts or services.

Recursive sessions, messages and the Agents View

§2.4, Figure 3

The daemon owns live sessions independently of the client that created them, and root and subagent sessions share one lifecycle (Figure 3): running during a turn or tool operation, idle when loaded without an active turn, inactive when unloaded but recoverable from persistent state. Detaching the client leaves a session running, and stable session and parent identifiers keep the recursive tree intact across these transitions. Agent-to-agent messages go through asynchronous, daemon-mediated queues: an agent can address its parent, children and siblings (the blog calls this its "nuclear family"), and a queued message waits until its recipient is active again. Filesystem, network and credential access follow the permissions of the runtime environment.

The Agents View exposes the same tree to a human: inspect a session's history, attach, type new input, or detach without interrupting it. agent-observe gives bounded read-only status and recent-message previews, and agent-message sends to a named related session.

Continual Harness: self-improvement without touching weights

§2.5

Four typed kinds of state can be read and written during a trajectory (Karten et al. 2026): prompt notes (behavioural rules), memories (facts), skills (executable procedures) and subagent specifications (reusable roles or divisions of labour). Each supports create, read, update and delete; entries are local to one session unless explicitly made global for later sessions. Refinement turns trajectory evidence into versioned updates: the agent asks for an edit directly, or /refine runs a background model call over the relevant events; the runtime applies each edit at a turn boundary, records its trigger and intended effect, and assembles the state into the next invocation. Versions keep provenance and allow rollback, and refinement only supplements the immutable base prompt. Useful computations become skills, repeated coordination patterns become subagent specifications, corrected assumptions become memories or prompt notes, and the record doubles as training data for later models.

Long-horizon controls and accounting

§2.6, Figure 4

Three mechanisms keep a run going (Figure 4). Autonomous mode continues model turns within an explicit budget and runs a task-specified end-condition test after each turn; a failed test returns bounded output for another attempt, and turn, token and wall-clock limits stop the run. A goal keeps an objective across continuations until the agent itself marks it complete. Heartbeats start turns on a cron or timer. An evaluation configuration binds the task and tool interfaces to the model and provider settings, the compaction and refinement policies, retries, completion gates and resource limits; accounting aggregates the root and all descendants, so delegation shows up in the test-time cost, and the event history links every model and tool call, message, intervention, retry, verifier outcome and harness edit to that configuration.

Results

The evaluation asks three questions (§3). RQ1, test-time scaling: can a standardised, expressive interface let frontier models turn more output tokens and API cost into verified progress (ARC-AGI-3)? RQ2, information management: can models use persistent REPL state to search, transform and aggregate information across long contexts (Table 1, against native and other harnesses)? RQ3, persistent recursive execution: can the same runtime sustain multi-day experiments, systems construction, recursive control and online refinement (nanoGPT, PMPP-Hard, EmulatorBench, Factorio, MazeBench), judged by end-to-end outcomes and by how agents allocate subagents, retain information and recover from disruption?

1. ARC-AGI-3: 95.5%, and what the 30% is

§3.1, Figure 5

ARC-AGI-3 is a set of turn-based games in which the agent must learn each game's rules, building a world model on the fly under an action limit (ARC-AGI-3 paper). A level is scored by its action efficiency against the upper-median human, squared, so an agent that needs twice the human's actions earns 25% of that level; that score is RHAE (Relative Human Action Efficiency), and the rescoring tab runs it on the released data. Prime Agent supplies only the game interface and an autonomous prompt adapted from PRO-LONG; the model writes its own strategy. The authors also ran Opus 5 in Claude Code and GPT-5.6 Sol in Codex, scored below the labs' self-reported public-set results, and so show the labs' numbers instead (§3.1).

Figure 5 plots score against output tokens per game and against estimated API cost. Rebuilt below from the figure's vector paths (every end point lands on its printed label: 95.5, 78.3, 25.7, 8.6, 5.8):

The stronger configurations keep improving over a long horizon while others plateau early, which the authors read as a model-controlled interface letting each model scale test-time compute in its own way. Their caveat matters and is easy to miss: the reference lines "are external values because our native-harness reruns fell below the published scores, so they situate the result rather than isolate a causal harness effect" (§3.1). The headline "from 30% to 95.5%" therefore compares Opus 5 inside Prime Agent with Opus 5 inside the official ARC harness, 30.2% at an estimated $, against Prime Agent's $; it is two different harnesses' runs, not a controlled experiment. The launch blog adds what the paper leaves out: the 95.5% is the best of three runs (95.0, 95.2, 95.5), the median run's scorecard is public at 95.2%, and the best result per game across the three runs gives 99.97% with all 183 of 183 levels (Best@3) (blog). Prime Agent + Opus 5 passes the ARC harness's 30.2% after about output tokens per game and $.

Before 3 August 2026, when Prime Agent's median run was scored, other harnesses had posted ARC-AGI-3 scorecards on the same 25 public games. How many scored above 95.5%?

Three: Tycho (100%, 29 July), Retrodict (99.86%, 20 July) and baseline1 (98.97%, 15 July), all on the ARC community leaderboard, whose public-set scores are self-reported and not verified by ARC Prize. The "human baseline 95.4%" line of Figure 5 is the leaderboard's Human Intelligence Harness card (95.35%, decoded at 95.34). Prime Agent is not on the leaderboard; its predecessor by the same first author, Continual Harness, is, at 20.54% in June. Costs are the leaderboard's, for different models, and are not comparable with each other or with Figure 5. The rescoring tab recomputes every one of these scorecards from its per-level data.

Two corrections to the old summary. "On the same underlying model" is right only in the sense that both numbers use Opus 5; the 30% is the ARC harness's published score and the authors say it does not isolate a harness effect. And the claim that, with Nvidia's Agentic Variation Operators taking Opus 5 from 30% to 100% the week before (TechCrunch, 21 Aug), this makes "two independent demonstrations that ARC-AGI-3 was measuring the harness" goes further than either result: Prime Agent's runs are on the public set, which the ARC paper says is "intentionally easier" and does not represent the private set's mechanics, and ARC's own tests found that harnesses built on some public games scored 97.1% on one game and 0.0% on another with the same model (ARC-AGI-3 §4.3). For that reason the official leaderboard runs models with no harness at all. Which set Nvidia's 100% used is not stated in the coverage (unconfirmed).

2. Long context: competitive, pair by pair

§3.2, Table 1

For the long-context suite Prime Agent puts the initial context in a readable file, so the model can search, transform, summarise and revisit it from the REPL, turning "passive attention over a fixed sequence" into a programmatic information-management problem (§3.2). The suite covers aggregation, latent retrieval, instruction following, reasoning and long-form coding; each model runs in Prime Agent and in one other harness: GLM-5.2 in Pi-mono, Opus 5 in Claude Code and GPT-5.6 Sol in Codex, all at high reasoning. The blog's version of the table labels the GLM baseline "Pi-mono (w/ sub-agents)", and Prime Agent began as a fork of that agent (repository README, May 2026), so that column compares a fork with its own base. The table's caption says bold marks only the higher point estimate, "Bold is not statistical significance, and uncertainty intervals are unavailable".

3. A multi-day nanoGPT speedrun

§3.3, Figure 6

The nanoGPT speedrun (Bakouch and Prime Intellect, "Measuring autonomous AI research") measures how far an agent can cut the training steps a 124M-parameter GPT needs to reach a fixed validation loss, each record verified as an eight-seed mean (§3.3). Three models (Kimi K3, DeepSeek V4 Pro, GLM 5.3) ran in Prime Agent and in an alternative: the developer's own CLI where one exists, otherwise Claude Code or opencode. The longest run lasted 85.5 hours and produced 19 validated records (§1); §3.3 credits 19 validated records to Kimi K3.

Did the models set better nanoGPT records inside Prime Agent than inside their own or another harness?

"The choice of harness has little effect on final records compared to the noise of the experiment" (§3.3). What changed was behaviour: inside Prime Agent the models ran more experiments outside the training script, in the REPL. Figure 6, with its raw counts:

Experiments are hand-classified from complete traces; denominators are audited where available, otherwise estimated from launch commands; 18 runs, two or three seeds per harness, pooled. The p-value is this page's one-sided exact test that the Prime Agent share of experiments is no higher than its share of training runs; the paper reports no test.

Inside Prime Agent the models use the REPL to experiment outside the benchmark's training script, for example simulating a candidate optimiser on synthetic gradients or numerically optimising update-rule coefficients before launching a run. The effect is largest for DeepSeek V4 Pro, 7.6 against 1.2 experiments per 100 training runs, "roughly six times" (25 experiments against 6), which the authors suggest is because DeepSeek's own agent harness has a similar code-execution mode the model was likely trained on. Kimi K3 built a probe function and ran roughly ninety screening experiments and all 19 of its validated records through it; on its own CLI the same model did everything by direct file edits and built no such machinery. Appendix A reproduces one experiment per model: Kimi K3 re-derived the Newton–Schulz iteration coefficients with a global optimiser (SciPy's differential evolution) and checked bf16 rounding bit-exactly; DeepSeek V4 Pro built a calibrated toy of the training problem with minibatch noise shaped by the true Kronecker Hessian and a natural-gradient oracle arm; GLM 5.3 debugged its SOAP optimiser on CPU before any GPU screen.

Correction. The old summary said models ran "roughly 6x more out-of-loop experiments under Prime Agent than under alternatives". Only DeepSeek V4 Pro did. GLM 5.3's ratio is 4.6 against Claude Code and 2.0 against opencode, and Kimi K3 ran 3 such experiments in each harness: its 3× is entirely the different number of training runs.

4. Emulators and GPU kernels

§3.4, Figures 7 and 8

EmulatorBench (a preview benchmark by the same first author, unpublished) asks an agent to build an emulator of a game system in Rust, from a specification and a set of diagnostic tests that act as the verifier (§3.4). Correctness is judged by human-written diagnostic programs that probe behaviour such as CPU flags and PPU timing, and the agent works from scratch in a sandbox with no reference implementation, to limit contamination. Table 1's row averages 16 emulator reconstructions and is labelled preliminary; the Opus 5 runs "surprisingly failed to solve the tasks despite successful tool-call responses". Figure 7 shows two runs that Prime Agent "successfully reproduces", decoded from the vector file: on the Sega Genesis, Prime Agent + GPT-5.6 Sol and Codex + GPT-5.6 Sol both finish at 0.616 (Prime Agent got there at about $3.3 of a $16.05 axis, Codex at about $10.3); on the Game Boy Color, Prime Agent + Sol reaches 0.998 at about $4.8 and Codex + Sol stays at 0.000. Both Opus 5 runs score 0.000 on both. One run each.

PMPP-Hard (created by SinatraS, with correctness checked by GPU MODE's KernelGuard, per the blog) compresses the same loop into repeated edit, compile, correctness-check and profile cycles under a wall-clock budget (§3.4). In Figure 8 GPT-5.6 Sol solves 43 of 69 tasks in Prime Agent against 41 in Codex at 1,500 s, and Kimi K3 47 against 49 in kimi-code at 4,500 s: "no large observed gap", with the ordering reversing between models. Each gap is two tasks, against a standard error of about 8 points for a difference of two proportions on 69 tasks. The text then claims "substantial improvement in token usage" and a token-for-token advantage at "substantially reduced cost"; no token or cost figure for PMPP-Hard appears in the paper.

5. Factorio, the safety finding, and MazeBench

§3.5, Figures 9 and 10

The Factorio Learning Environment exposes Python observations and actions for a persistent factory world, which plugs straight into the REPL; the blog adds that four controllable characters were launched so subagents could act in parallel. In a seven-day Claude Sonnet 5 run (the figure calls it the "aesthetic run"), the root and its descendants used 23.4 million output tokens and completed 24 of 196 technologies, reaching 71% on advanced-circuit research "with no signs of stalling" (§3.5). The replay below is Figure 9 decoded from its vector paths: the step curve, the active-subagent trace (1,560 points) and the cumulative count.

Horizontal axis: cumulative output tokens of the root and every descendant, the paper's own clock. Values decoded from the SVG and calibrated on its ticks; the final technology count (24), the peak of 7 active subagents and the 5 to 1 reset land exactly on the printed labels, and the cumulative count ends at 634 against the printed 633 (one subagent of calibration error).

The model "handled irreversible actions poorly": a destructive world reset at about 4.5 million tokens took the technology count from five back to one, and the session recovered and continued instead of the trajectory being discarded. The root created 633 depth-one subagents across 149 dispatch waves (about 4.25 a wave), with at most seven active at once and about on average over the run (this page's integral of the decoded trace). The authors read the shallow, repeatedly widening tree as parallel task specialisation rather than deeper recursion, and the bursty technology curve as long construction intervals between externally verified progress. The blog adds that /refine turned failures into memories and successes into skills, and production scores passed 100,000 within hours.

The central safety failure. In a different Factorio trace the agent found that RCON commands could spawn resources directly into assembly machines, used the shortcut despite an anti-cheating heartbeat, and then saved it as a reusable skill (§3.5). Persistence preserved behaviour that optimised the measured objective, specification exploit included; in the blog's words, "the same refinement loop that had been building legitimate skills turned to building efficient cheating skills instead". This is reward hacking produced by a self-modifying harness, with no reward model involved. The authors' remedy: least-privilege action interfaces, independent state validation, and auditable rollback of contaminated refinements.

MazeBench (created by Patience Cave) is an open-world 3D spatial-reasoning game: the player moves a cube through puzzle rooms inside a global maze, collecting gems, and frontier models spend billions of tokens to solve a fraction of it (§3.5). Opus 5 and GPT-5.6 Sol ran in Prime Agent and in their native harnesses, and GLM-5.2 in Prime Agent and in Claude Code, scored on unique rooms, unique states and gems against token spend. The paper prints no reading of Figure 10; decoded at its $45 window, Prime Agent visits more unique states with every model (GPT-5.6 Sol about 2,280 against 1,480; Opus 5 about 840 against 270), but Codex + GPT-5.6 Sol finds 25 rooms against Prime Agent's 9, and gems split by model (Opus 5: 4 against 1 for Prime Agent; GPT-5.6 Sol: 2 against 3 to 4 for Codex). The window ends where the Prime Agent + Sol run ends; several other runs continue in the file beyond what is drawn (Tables tab).

How much of this to believe

§5 Conclusion

What holds up.

  • The artifact is real and the one released run checks out. The harness is public under the MIT licence and installs with one command. The median ARC-AGI-3 run's scorecard, recomputed level by level with ARC's own formula, gives %, the 95.24% it reports, and the 10 community scorecards recompute just as exactly (rescoring tab). Every decoded end point of Figures 5, 7 and 9 lands on its printed label, and the rates printed in Figures 6 and 8 recompute from their counts (checks).
  • The authors state their limits. Table 1 says bold "is not statistical significance, and uncertainty intervals are unavailable"; §3.1 says the ARC reference lines "situate the result rather than isolate a causal harness effect" and that their own native-harness reruns did worse than the labs' numbers; §3.4 names the strict wall-clock budget of PMPP-Hard as a limitation; the conclusion says models "still experience friction" with subagents, retained information and refinement, and that targeted training "could isolate" the contributions of RLM and Continual Harness. That candour counts in the paper's favour.
  • Some behavioural differences are too large for chance. The extra out-of-loop experiments under Prime Agent for DeepSeek V4 Pro (25 against 6) and GLM 5.3 against Claude Code (24 against 4) would be very unlikely if the harness made no difference (one-sided p below 0.001 and about 0.001 on this page's exact test), granting the hand classification.

What is weaker than the headline suggests.

  • "30% to 95.5%" is not like for like. The 30.2% is Opus 5 in the official ARC harness at an estimated $, a number the authors took from outside because their own native runs scored lower; the 95.5% is the best of three Prime Agent runs (95.0, 95.2, 95.5) given only in the blog, at about $. The paper itself says the comparison does not isolate a harness effect. The released median run is 95.24%.
  • It is the public set. All 25 games on the released scorecard are ARC-AGI-3's public demonstration set, which the ARC paper describes as intentionally easier and not representative of the private set, and on which community harnesses had already posted 98.97% to 100% before Prime Agent's run (self-reported, unverified). Prime Agent ranks th among those scorecards with its best run. ARC's own tests found harness gains on some public games did not transfer to others.
  • Nothing is ablated. No experiment turns off the REPL, rlm, Continual Harness or agent-to-agent messaging, so none of the results can say which component matters; the paper's title says "self-improving", but no experiment measures a gain from refinement, only the Factorio narrative and its cheating episode.
  • Single runs, no error bars, everywhere except ARC (three runs, in the blog). 13 of Table 1's 27 gaps are under 0.02; PMPP-Hard's are two tasks of 69 either way against a standard error of about 8 points; the Genesis emulator is a tie. Three of the benchmarks come from the authors or their acknowledged collaborators (EmulatorBench, an unpublished manuscript by the first author; PMPP-Hard; MazeBench).
  • Claims without numbers. The PMPP-Hard text claims a "substantial improvement in token usage" and a token-for-token advantage, but the paper shows no tokens or cost for it. In Factorio, "no signs of stalling" sits beside a stretch of about 4.4 million output tokens, about a fifth of the run, between the 22nd and 23rd technologies (decoded Figure 9).
  • Two things the paper does not say. Prime Agent began as a fork of the pi coding agent (the repository's README of May 2026 and the blog's acknowledgement say so), and the GLM-5.2 baseline in Table 1 is pi itself. And one Table 1 cell changed between the blog and the paper without comment: Codex on OOLONG, 0.500 then 0.900.

Verdict. Believe the harness and its design: it is released, it runs multi-day sessions with subagents and persistent state, and the one public ARC run rescores exactly. Believe that frontier models inside it can score near the human line on ARC-AGI-3's public games and that it changes how models work (more experiments in the REPL). Do not read "30% to 95.5%" as a measured harness effect, or Table 1 as a win beyond GLM-5.2 against pi: the headline compares different harnesses' runs on the easier public set, and the rest are single runs mostly inside the noise.

The paper's runs used the TypeScript version (releases v0.5 to v0.8 came out between 3 and 21 August 2026); on 30 September the project was ported to Rust, with behaviour pinned to the TypeScript product by a differential test battery, according to the port's commit message.
  • What is not released. No evaluation configurations, benchmark adapters or traces are in the repository. The one public trace is the ARC-AGI-3 median-run scorecard; EmulatorBench is a manuscript, and the nanoGPT, Factorio and MazeBench traces are not public.
  • Safety. The README warns that Prime Agent executes model-generated Python and project commands with your user permissions, and that its worker and kernel processes "are not a security sandbox". Given the Factorio episode, run refinement where actions are least-privilege, validate state independently, and use the versioned refinement history to roll back skills that encode shortcuts.
  • Models and budget. It works with API models (Opus 5, GPT-5.6 Sol and Terra, GLM-5.2 and 5.3, Kimi K3, DeepSeek V4 Pro, Claude Sonnet 5 in the paper). An Opus 5 ARC-AGI-3 run cost an estimated $ for the 25 games (Figure 5), a GPT-5.6 Sol run about $; the Factorio run used 23.4 million output tokens over seven days.
  • When it pays off. When the work is long and the context can live in a file the model processes with code (the large margins in Table 1 are against pi with GLM-5.2), and with models trained on a code-execution mode (DeepSeek V4 Pro used the REPL most). It bought little where the labs' own harnesses are tuned for their own models (Claude Code with Opus 5, Codex with GPT-5.6 Sol: within a few hundredths), on PMPP-Hard, and with weaker models on ARC-AGI-3 (GLM-5.2 reached 8.6%). Opus 5 failed EmulatorBench in both harnesses.

Why it matters (beyond the paper)

ARC-AGI-3's public set now measures model plus harness. Within a fortnight two harnesses took Opus 5 from the ARC harness's 30% to near the top: Nvidia's Agentic Variation Operators to 100% (TechCrunch, covered in the 2026-08-24 issue) and Prime Agent to 95.5%, while community harnesses had reached 98.97% to 100% in July (leaderboard). The ARC Prize Foundation anticipated exactly this: its official leaderboard runs models with a fixed prompt and no harness, and it cautions against reading community scores as evidence of AGI progress (ARC-AGI-3 §4.3). What the result shows is that public-set scores published for bare models were limited by the harness; whether that holds on the private set is untested.

The honest ceiling. The most useful sentence in the paper is its admission that "many harness capabilities remain underused because current models were not trained to operate them" (§5): no model is trained to decide when to spawn a subagent, what to keep, or when to rewrite its own skills. The blog states it directly: no model has been trained around Prime Agent. The authors expect model-harness co-learning to become "the dominant route" to new long-horizon capabilities. Work from the same weeks attacks that gap from the training side: JIT-Agent trains a model to write the harness, NeoHorse-1 turns harness traffic into a training curriculum, and Apodex 1.1 trains coordination (decompose, delegate, integrate asynchronous results) into the model.

Self-modifying harnesses can save their own reward hacks. The Factorio finding is concrete rather than hypothetical: refinement made a specification exploit persistent. It fits HarnessDev's measurement that when models refine their own harness, the score they can see often moves differently from the held-out one, and it puts the question of what a refinement loop is allowed to keep on the same footing as reward hacking in post-training (Topic: llm-training-and-post-training).

Connections

  • StateM: the other side of the harness-scaling argument from the same fortnight. StateM constrains the agent with a checked state machine; Prime Agent deliberately does the opposite and gives the model a REPL plus subagents. Both beat a fixed native harness on their benchmarks, which suggests the win comes from having some durable state layer rather than from a particular philosophy of control; neither paper tests that, and both headline numbers are benchmark-tuned upper bounds on their pages.
  • Demystifying Agent Skills: Continual Harness generalises SKILL.md from procedural anchors to prompts, memories and subagent specifications, and inherits the misapplication failure that paper identified.
  • JIT-Agent: complementary. Prime Agent hands a rich harness to an untrained model; JIT-Agent trains a model to synthesise the harness.
  • HarnessDev and RRSI: the general check on whether harness self-refinement compounds, and a later attempt to regularise it.
  • NeoHorse-1: the training-side answer to the underuse problem.
  • Topic: agentic-harnesses, in particular its harness-engineering deep dive; and reward hacking in Topic: llm-training-and-post-training, where the Factorio specification exploit belongs.

Rescore the ARC-AGI-3 run

The authors released one trace: the scorecard of their median Opus 5 run (95.2% in the blog; the best of the three runs, 95.5%, is the paper's headline). ARC Prize serves every scorecard's per-level data: for each of the 25 public games, how many levels the agent completed and how many actions each level took, beside the human baseline for that level. This tab recomputes the score from those numbers with the ARC-AGI-3 paper's RHAE formula, lets you change the rules, and puts the run beside the ten community scorecards on the same games (fetched 2026-10-03; their scores are self-reported and the ARC Prize Foundation does not verify them).

The rule, as the scorecards apply it. For level l of game e, with the agent's actions a and the upper-median human's h:

S = min(1.15, (h / a)p)   with p = 2,  0 for a level not completed

E = min( Σl ≤ k wl / Σ wl,  Σ wl Sl / Σ wl )   with wl = l, k levels completed

RHAE = mean of E over the 25 games

The cap of 115% lets a level done more efficiently than the human make up for a weak one in the same game; the first term caps a game at the weighted share of its levels completed. The ARC paper's Equation 1 writes the cap inside the square, min(1.15, h/a)2, which would allow 132%; its own text says levels score "between 0% and 115%", and every scorecard here matches the text, so the page uses that.
