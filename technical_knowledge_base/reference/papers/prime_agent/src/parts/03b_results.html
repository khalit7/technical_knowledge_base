Results

The evaluation asks three questions ({{§3|ax:S3}}). RQ1, test-time scaling: can a standardised, expressive interface let frontier models turn more output tokens and API cost into verified progress (ARC-AGI-3)? RQ2, information management: can models use persistent REPL state to search, transform and aggregate information across long contexts (Table 1, against native and other harnesses)? RQ3, persistent recursive execution: can the same runtime sustain multi-day experiments, systems construction, recursive control and online refinement (nanoGPT, PMPP-Hard, EmulatorBench, Factorio, MazeBench), judged by end-to-end outcomes and by how agents allocate subagents, retain information and recover from disruption?

1. ARC-AGI-3: 95.5%, and what the 30% is

[[S3.SS1|§3.1, Figure 5]]

ARC-AGI-3 is a set of turn-based games in which the agent must learn each game's rules, building a world model on the fly under an action limit ({{ARC-AGI-3 paper|https://arxiv.org/abs/2603.24621}}). A level is scored by its action efficiency against the upper-median human, squared, so an agent that needs twice the human's actions earns 25% of that level; that score is RHAE (Relative Human Action Efficiency), and {{the rescoring tab|tab:t-run}} runs it on the released data. Prime Agent supplies only the game interface and an autonomous prompt adapted from {{PRO-LONG|https://arxiv.org/abs/2607.20064}}; the model writes its own strategy. The authors also ran Opus 5 in Claude Code and GPT-5.6 Sol in Codex, scored below the labs' self-reported public-set results, and so show the labs' numbers instead ({{§3.1|ax:S3.SS1}}).

{{Figure 5|ax:S3.F5}} plots score against output tokens per game and against estimated API cost. Rebuilt below from the figure's vector paths (every end point lands on its printed label: 95.5, 78.3, 25.7, 8.6, 5.8):

The stronger configurations keep improving over a long horizon while others plateau early, which the authors read as a model-controlled interface letting each model scale test-time compute in its own way. Their caveat matters and is easy to miss: the reference lines "are external values because our native-harness reruns fell below the published scores, so they situate the result rather than isolate a causal harness effect" ({{§3.1|ax:S3.SS1}}). The headline "from 30% to 95.5%" therefore compares Opus 5 inside Prime Agent with Opus 5 inside the official ARC harness, 30.2% at an estimated $, against Prime Agent's $; it is two different harnesses' runs, not a controlled experiment. The launch blog adds what the paper leaves out: the 95.5% is the best of three runs (95.0, 95.2, 95.5), the median run's scorecard is public at 95.2%, and the best result per game across the three runs gives 99.97% with all 183 of 183 levels (Best@3) ({{blog|https://www.primeintellect.ai/blog/prime-agent}}). Prime Agent + Opus 5 passes the ARC harness's 30.2% after about output tokens per game and $.

Before 3 August 2026, when Prime Agent's median run was scored, other harnesses had posted ARC-AGI-3 scorecards on the same 25 public games. How many scored above 95.5%?

Three: Tycho (100%, 29 July), Retrodict (99.86%, 20 July) and baseline1 (98.97%, 15 July), all on the {{ARC community leaderboard|https://arcprize.org/leaderboard/community}}, whose public-set scores are self-reported and not verified by ARC Prize. The "human baseline 95.4%" line of Figure 5 is the leaderboard's Human Intelligence Harness card (95.35%, decoded at 95.34). Prime Agent is not on the leaderboard; its predecessor by the same first author, Continual Harness, is, at 20.54% in June. Costs are the leaderboard's, for different models, and are not comparable with each other or with Figure 5. The rescoring tab recomputes every one of these scorecards from its per-level data.

Two corrections to the old summary. "On the same underlying model" is right only in the sense that both numbers use Opus 5; the 30% is the ARC harness's published score and the authors say it does not isolate a harness effect. And the claim that, with Nvidia's Agentic Variation Operators taking Opus 5 from 30% to 100% the week before ({{TechCrunch, 21 Aug|https://techcrunch.com/2026/08/21/nvidia-just-showed-that-the-harness-not-the-ai-model-is-now-the-real-hero/}}), this makes "two independent demonstrations that ARC-AGI-3 was measuring the harness" goes further than either result: Prime Agent's runs are on the public set, which the ARC paper says is "intentionally easier" and does not represent the private set's mechanics, and ARC's own tests found that harnesses built on some public games scored 97.1% on one game and 0.0% on another with the same model ({{ARC-AGI-3 §4.3|https://arxiv.org/abs/2603.24621}}). For that reason the official leaderboard runs models with no harness at all. Which set Nvidia's 100% used is not stated in the coverage (unconfirmed).

2. Long context: competitive, pair by pair

[[S3.SS2|§3.2, Table 1]]

For the long-context suite Prime Agent puts the initial context in a readable file, so the model can search, transform, summarise and revisit it from the REPL, turning "passive attention over a fixed sequence" into a programmatic information-management problem ({{§3.2|ax:S3.SS2}}). The suite covers aggregation, latent retrieval, instruction following, reasoning and long-form coding; each model runs in Prime Agent and in one other harness: GLM-5.2 in Pi-mono, Opus 5 in Claude Code and GPT-5.6 Sol in Codex, all at high reasoning. 3. A multi-day nanoGPT speedrun

[[S3.SS3|§3.3, Figure 6]]

The nanoGPT speedrun ({{Bakouch and Prime Intellect, "Measuring autonomous AI research"|https://www.primeintellect.ai/blog/measuring-autonomous-research}}) measures how far an agent can cut the training steps a 124M-parameter GPT needs to reach a fixed validation loss, each record verified as an eight-seed mean ({{§3.3|ax:S3.SS3}}). Three models (Kimi K3, DeepSeek V4 Pro, GLM 5.3) ran in Prime Agent and in an alternative: the developer's own CLI where one exists, otherwise Claude Code or opencode. The longest run lasted 85.5 hours and produced 19 validated records ({{§1|ax:S1.p4}}); §3.3 credits 19 validated records to Kimi K3.

Did the models set better nanoGPT records inside Prime Agent than inside their own or another harness?

"The choice of harness has little effect on final records compared to the noise of the experiment" ({{§3.3|ax:S3.SS3}}). What changed was behaviour: inside Prime Agent the models ran more experiments outside the training script, in the REPL. {{Figure 6|ax:S3.F6}}, with its raw counts:

Experiments are hand-classified from complete traces; denominators are audited where available, otherwise estimated from launch commands; 18 runs, two or three seeds per harness, pooled. The p-value is this page's one-sided exact test that the Prime Agent share of experiments is no higher than its share of training runs; the paper reports no test.

Inside Prime Agent the models use the REPL to experiment outside the benchmark's training script, for example simulating a candidate optimiser on synthetic gradients or numerically optimising update-rule coefficients before launching a run. The effect is largest for DeepSeek V4 Pro, 7.6 against 1.2 experiments per 100 training runs, "roughly six times" (25 experiments against 6), which the authors suggest is because DeepSeek's own agent harness has a similar code-execution mode the model was likely trained on. Kimi K3 built a probe function and ran roughly ninety screening experiments and all 19 of its validated records through it; on its own CLI the same model did everything by direct file edits and built no such machinery. {{Appendix A|ax:A1}} reproduces one experiment per model: Kimi K3 re-derived the Newton–Schulz iteration coefficients with a global optimiser (SciPy's differential evolution) and checked bf16 rounding bit-exactly; DeepSeek V4 Pro built a calibrated toy of the training problem with minibatch noise shaped by the true Kronecker Hessian and a natural-gradient oracle arm; GLM 5.3 debugged its SOAP optimiser on CPU before any GPU screen.

Correction. The old summary said models ran "roughly 6x more out-of-loop experiments under Prime Agent than under alternatives". Only DeepSeek V4 Pro did. GLM 5.3's ratio is 4.6 against Claude Code and 2.0 against opencode, and Kimi K3 ran 3 such experiments in each harness: its 3× is entirely the different number of training runs.

4. Emulators and GPU kernels

[[S3.SS4|§3.4, Figures 7 and 8]]

EmulatorBench (a preview benchmark by the same first author, unpublished) asks an agent to build an emulator of a game system in Rust, from a specification and a set of diagnostic tests that act as the verifier ({{§3.4|ax:S3.SS4.SSS0.Px1}}). Correctness is judged by human-written diagnostic programs that probe behaviour such as CPU flags and PPU timing, and the agent works from scratch in a sandbox with no reference implementation, to limit contamination. Table 1's row averages 16 emulator reconstructions and is labelled preliminary; the Opus 5 runs "surprisingly failed to solve the tasks despite successful tool-call responses". {{Figure 7|ax:S3.F7}} shows two runs that Prime Agent "successfully reproduces", decoded from the vector file: on the Sega Genesis, Prime Agent + GPT-5.6 Sol and Codex + GPT-5.6 Sol both finish at 0.616 (Prime Agent got there at about $3.3 of a $16.05 axis, Codex at about $10.3); on the Game Boy Color, Prime Agent + Sol reaches 0.998 at about $4.8 and Codex + Sol stays at 0.000. Both Opus 5 runs score 0.000 on both. One run each.

PMPP-Hard (created by SinatraS, with correctness checked by GPU MODE's KernelGuard, per the blog) compresses the same loop into repeated edit, compile, correctness-check and profile cycles under a wall-clock budget ({{§3.4|ax:S3.SS4.SSS0.Px2}}). In {{Figure 8|ax:S3.F8}} GPT-5.6 Sol solves 43 of 69 tasks in Prime Agent against 41 in Codex at 1,500 s, and Kimi K3 47 against 49 in kimi-code at 4,500 s: "no large observed gap", with the ordering reversing between models. Each gap is two tasks, against a standard error of about 8 points for a difference of two proportions on 69 tasks. The text then claims "substantial improvement in token usage" and a token-for-token advantage at "substantially reduced cost"; no token or cost figure for PMPP-Hard appears in the paper.

5. Factorio, the safety finding, and MazeBench

[[S3.SS5|§3.5, Figures 9 and 10]]

The {{Factorio Learning Environment|https://arxiv.org/abs/2503.09617}} exposes Python observations and actions for a persistent factory world, which plugs straight into the REPL; the blog adds that four controllable characters were launched so subagents could act in parallel. In a seven-day Claude Sonnet 5 run (the figure calls it the "aesthetic run"), the root and its descendants used 23.4 million output tokens and completed 24 of 196 technologies, reaching 71% on advanced-circuit research "with no signs of stalling" ({{§3.5|ax:S3.SS5.SSS0.Px1}}). The replay below is {{Figure 9|ax:S3.F9}} decoded from its vector paths: the step curve, the active-subagent trace (1,560 points) and the cumulative count.

Horizontal axis: cumulative output tokens of the root and every descendant, the paper's own clock. Values decoded from the SVG and calibrated on its ticks; the final technology count (24), the peak of 7 active subagents and the 5 to 1 reset land exactly on the printed labels, and the cumulative count ends at 634 against the printed 633 (one subagent of calibration error).

The model "handled irreversible actions poorly": a destructive world reset at about 4.5 million tokens took the technology count from five back to one, and the session recovered and continued instead of the trajectory being discarded. The root created 633 depth-one subagents across 149 dispatch waves (about 4.25 a wave), with at most seven active at once and about on average over the run (this page's integral of the decoded trace). The authors read the shallow, repeatedly widening tree as parallel task specialisation rather than deeper recursion, and the bursty technology curve as long construction intervals between externally verified progress. The blog adds that /refine turned failures into memories and successes into skills, and production scores passed 100,000 within hours.

The central safety failure. In a different Factorio trace the agent found that RCON commands could spawn resources directly into assembly machines, used the shortcut despite an anti-cheating heartbeat, and then saved it as a reusable skill ({{§3.5|ax:S3.SS5.SSS0.Px1}}). Persistence preserved behaviour that optimised the measured objective, specification exploit included; in the blog's words, "the same refinement loop that had been building legitimate skills turned to building efficient cheating skills instead". This is reward hacking produced by a self-modifying harness, with no reward model involved. The authors' remedy: least-privilege action interfaces, independent state validation, and auditable rollback of contaminated refinements.

MazeBench (created by Patience Cave) is an open-world 3D spatial-reasoning game: the player moves a cube through puzzle rooms inside a global maze, collecting gems, and frontier models spend billions of tokens to solve a fraction of it ({{§3.5|ax:S3.SS5.SSS0.Px2}}). Opus 5 and GPT-5.6 Sol ran in Prime Agent and in their native harnesses, and GLM-5.2 in Prime Agent and in Claude Code, scored on unique rooms, unique states and gems against token spend. The paper prints no reading of {{Figure 10|ax:S3.F10}}; decoded at its $45 window, Prime Agent visits more unique states with every model (GPT-5.6 Sol about 2,280 against 1,480; Opus 5 about 840 against 270), but Codex + GPT-5.6 Sol finds 25 rooms against Prime Agent's 9, and gems split by model (Opus 5: 4 against 1 for Prime Agent; GPT-5.6 Sol: 2 against 3 to 4 for Codex). The window ends where the Prime Agent + Sol run ends; several other runs continue in the file beyond what is drawn ({{Tables tab|tab:t-tables:f10Card}}).
