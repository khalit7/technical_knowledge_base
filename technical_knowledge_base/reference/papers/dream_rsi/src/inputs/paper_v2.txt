Abstract

Recursive self-improvement is becoming essential for autonomous AI agents, whose progress depends on discovering high-value solutions across complex domains. Effective exploration drives this process, yet managing and improving exploration strategies remains a major bottleneck. Current systems face a fundamental dilemma: fixed strategies fail to adapt as search spaces scale, while online policy optimization must navigate vast meta-search spaces under delayed, expensive feedback from long-horizon rollouts. We introduce Dream-RSI, a framework for scalable, recursively self-improving exploration. A lightweight orchestration layer makes exploration explicit and programmable while leaving the underlying base agent unchanged. Our key insight is that accumulated discovery history can act as a replay simulator over the realized search space. By dreaming within this simulator built from historical discovery trees, Dream-RSI obtains immediate, low-cost off-policy feedback to evaluate and refine exploration policies without repeated, expensive online evaluation. The improved policy is then redeployed online to drive further discovery, continuously expanding the simulator pool in a self-improving loop. Across 9 tasks in 4 domains, Dream-RSI
achieves competitive quality and improves discovery efficiency in several settings.

1 Introduction

Recursive self-improvement (RSI) has emerged as an ambitious goal for autonomous AI systems (Liu et al., 2026c). A common mechanism underlying RSI is an iterative loop wherein agents propose candidate solutions, evaluate outcomes, and fold the resulting feedback into subsequent iterations. Such loops have driven substantial progress across algorithm design (Novikov et al., 2025; Romera-Paredes et al., 2024), open-ended mathematical optimization (Georgiev et al., 2025; Anthropic, 2026), systems design (Jaber and Jaber, 2026; Cao et al., 2026), and agent self-improvement (Zhang et al., 2026b; Zhang et al., 2026c; Lee et al., 2026; Zheng et al., 2026a). As agents grow stronger and self-improvement targets grow harder, discovery demands long-horizon exploration over vast search spaces, often spanning thousands of proposal-evaluation cycles (Ye et al., 2026; OpenAI, 2026). At this scale, orchestrating exploration becomes critical (Zheng et al., 2026b): poor exploration wastes computation and time, sharply limiting the efficiency and scalability of RSI.

Existing approaches largely rely on manually designed exploration strategies that stay fixed throughout discovery (Novikov et al., 2025; Yan et al., 2026b; Du et al., 2026; Jiang et al., 2026; Ye et al., 2026). Such strategies cannot learn from accumulated experience and may repeatedly spend computation on unproductive search directions. Recent work therefore attempts to optimize exploration policies online (Liu et al., 2026a), but this faces two fundamental bottlenecks. First, meta-level feedback is delayed and expensive. Unlike evaluating a single candidate, assessing an exploration policy requires observing how it shapes discovery over many proposal–evaluation cycles. Second, the meta-policy space is vast, so many alternatives must be tried before a good one is found. Together, these make meta-level improvement costly. Each policy demands a long online rollout before yielding useful signal, making the self-improvement loop hard to close at the exploration layer.

To address these bottlenecks, we want to design a fast and cheap simulator of discovery to prune exploration policies before costly online deployment. Surprisingly, completed discovery histories already provide such a simulator. Prior work treats past history merely as static textual context (Hu et al., 2025; Ouyang et al., 2026b) or as training data for fine-tuning (Yuksekgonul et al., 2026; Wang et al., 2025). Yet a completed discovery process inherently records a structured tree of exploration decisions and their realized code-execution outcomes. By analogy to model-based reinforcement learning and World Models (Ha and Schmidhuber, 2018; Hafner et al., 2023) (§2), this discovery history can serve as a replay simulator11

Building on this insight, we introduce Dream-RSI, a framework for scalable, recursively self-improving meta-exploration in agent-driven discovery. We first make exploration programmable through a lightweight orchestration layer that controls branching, parallelism, and stopping while leaving the underlying base agent unchanged. To improve this policy, Dream-RSI follows a self-improvement loop (Figure 1): (1) Online Exploration, where the current policy drives real-world discovery and logs execution traces; (2) Replay Simulator Construction, where recorded discovery trees become a reusable replay simulator pool; and (3) Dreaming-based Policy Improvement, where candidate policies are cheaply evaluated by dreaming over the simulator. The updated policy is redeployed online, generating new experience that expands the simulator pool and closing an RSI loop at the meta-exploration layer. We evaluate Dream-RSI on 9 discovery tasks across four domains. On algorithm engineering (Lasso path solver), it outperforms sklearn and strong baselines while using up to $162\times$ fewer agent calls than SimpleTES. On mathematical optimization, it matches or exceeds the best results among the compared baselines on two of three tasks. On GPU kernel engineering (KernelBench), it reaches similar speeds with $1.79\times$ – $2.43\times$ fewer generations, or improves kernel performance by up to $2.09\times$ under a comparable budget. On harness optimization, it improves the seed harness by over 8 points on Terminal-Bench 2.1.

We introduce Dream-RSI, to our knowledge the first framework to close a meta-layer RSI loop using discovery history as a replay simulator. 3) Empirical Validation. 2 Motivation: Discovery History as a Replay Simulator

Consider an agent navigating an unfamiliar environment. On its first attempt it wanders, hits dead ends, and backtracks -- but in doing so it builds a map. That map is reusable: a new policy can plan over it, skip known dead ends, revisit earlier choices, and compare routes without physically walking them again (Gupta et al., 2017).
This is the logic of model-based reinforcement learning (Sutton, 1990; M. Moerland et al., 2023). A model of how the environment responds to actions lets policies be trained or evaluated in simulation instead of through repeated real interaction (Ha and Schmidhuber, 2018). The Dreamer family (Hafner et al., 2019; Hafner et al., 2020; Hafner et al., 2023; Hafner et al., 2025) is the clearest example: learn a compact dynamics model from collected experience, then improve the policy by imagining trajectories inside it.

Long-horizon discovery has the same structure. An exploration policy decides which directions to pursue, which candidates to refine, what to branch on in parallel, and when to stop. Running it online leaves behind a structured history -- branches explored, decisions made, costs incurred, outcomes observed. As shown in Figure 2, we treat this history as an empirical replay simulator: a grounded model of the part of the discovery space already seen.
Inside this simulator, a different exploration policy simply traces a different path through the recorded discovery tree, choosing other branches, another ordering, a different degree of parallelism, or an earlier stopping point. Scoring that path only requires revealing outcomes already stored along it; no rerun of the coding agent or evaluator is needed. One expensive online run therefore funds many cheap evaluations of alternative strategies.

3 Dream-RSI: RSI through Evolving Worlds

As shown in Figure 1, Dream-RSI alternates between online exploration and offline “dreaming” for policy evaluation to improve the exploration policy that allocates discovery computation. For online rollout, the exploration policy directs a fixed discovery agent to generate a tree-structure discovery trace, where each node in the tree is an discovery attempt and is scored by a fixed evaluator. The discovery tree then becomes a replay world: alternative policies can be re-evaluated against stored outcomes. In the offline dreaming phase, a fixed agent iteratively revises the code for the exploration policy, and every revision is evaluated in all stored replay worlds. The best version is then deployed for the next online rollout. Only the policy code changes; the models, evaluator, and execution interfaces stay fixed.

Discovery trees and the shared decision interface.

A discovery tree is rooted at $r$ , the initial workspace state. Every non-root node $v$ has exactly one primary parent (root or a previous node), which decides where its attempt begins: the discovery agent resumes the parent’s saved workspace and inherits its accumulated observations as context to generate the attempt in $v$ . Node $v$ keeps all previous generation history for it, and its own filesystem snapshot, together with an evaluation score $s_{v}$ . Scores are generated from a fixed protocol, and larger values are better. We define the root score $s_{r}=0$ . In both online rollout and offline evaluation, the exploration policy observes a tree $\mathcal{T}$ , initially
containing only the root, and selects nodes in $\mathcal{T}$ to continue exploration. The eligible nodes are $A(\mathcal{T})=\{r\}\cup\{v\in\mathcal{T}:v\text{ is a leaf}\}$ , which contains the root and all leave node in the current tree. We assume there are $W\geq 1$ parallel workers, each running one generation–evaluation request at a time (e.g. concurrent API calls). For the current tree $\mathcal{T}$ , the exploration policy’s action is a batch $C\in A(\mathcal{T};W)$ , where $A(\mathcal{T};W)=\{C\subseteq A(\mathcal{T}):|C|\leq W\}$ is the feasible batch set. The batch determines both where exploration continues and how many attempts run concurrently. Both the online and offline phase use this
decision interface, and differ only in how state transitions after an action: one executes for real, the other replays.

Here, $\lambda$ controls the strength of the parallelism penalty.
The first term measures the normalized area dominated by the
quality–cost Pareto frontier, rewarding policies that attain higher
quality with fewer discovery-agent calls. The second term measures the
average number of completed sequential rounds per call across the budget

Policy improvement and selection.

A policy version $\pi_{t}^{m}$ is evaluated by its average replay score over $\mathcal{H}_{t}$ , denoted by $V^{m}=\frac{1}{t}\sum_{i=1}^{t}V_{i}^{m}$ . The offline phase starts $\pi_{t}^{0}=\pi_{t}$ . At each step $m=0,\ldots,M-2$ , a policy-development agent inspects the replay trajectories and scores of $\pi_{t}^{m}$ , along with feedback from earlier revisions, to identify successful decisions and recurring failures. It then rewrites the executable policy code into $\pi_{t}^{m+1}$ , which is evaluated on the same $t$ replay worlds. The next online policy is the best-scoring candidate, $\pi_{t+1}=\pi_{t}^{m^{\star}}$ with $m^{\star}\in\operatorname*{arg\,max}_{m\in\{0,\cdots,M-1\}}V^{m}$ . Since the current rollout policy $\pi_{t}=\pi_{t}^{0}$ is included among the candidates,
 $V^{m^{\star}}\geq V^{0}$ , so $\pi_{t+1}$ is never worse than $\pi_{t}$ on the average
replay score over $H_{t}$ .

4 Experiments

We evaluate Dream-RSI on algorithm engineering, kernel optimization, mathematical optimization, and harness optimization. We primarily use Gemini-3.1-Pro for scientific discovery experiments, with additional Lasso experiments using Gemini-3.7-Flash to assess applicability across backbones. For harness optimization, we use Claude Opus 4.8 with Claude Code. On the scientific discovery tasks, our main controlled baseline is Recursive Fixed Exploration. Both methods use identical discovery agents, evaluators, initialization, per-round budget limits, and the same hand-designed starting policy. From the second round onward, Recursive Fixed Exploration keeps its policy fixed, while Dream-RSI updates it through replay-based dreaming over accumulated discovery history. For harness optimization, we focus on end-to-end performance and omit the fixed-policy comparison due to its substantial cost: an additional full search is estimated to cost over $100,000. We measure discovery cost as the cumulative number of discovery-agent calls.

4.1 Kernel Engineering

The goal of kernel engineering is to discover high-performance kernel implementations while preserving numerical correctness. We use four representative KernelBench tasks (Ouyang et al., 2025): VGG16, LayerNorm, ConvDiv, and ConvMax. Candidates are scored by execution performance, measured as inverse runtime ( $1/\mathrm{ms}$ ), subject to correctness checks against the reference implementation. With Gemini-3.1 Pro as the coding agent, we compare Dream-RSI against Recursive Fixed Exploration under an identical evaluation protocol and initialization, and against the strong PaceEvolve baseline (Yan et al., 2026b), whose maximum discovery time we cap at two days for fairness.

Results.

Figure 3 shows discovery trajectories as the number of generations increases. On VGG16 and LayerNorm, Dream-RSI matches final performance with $2.43\times$ and $1.79\times$ fewer generations. On ConvDiv and ConvMax, under comparable budgets, it achieves $2.09\times$ and $1.44\times$ higher performance. Adapting the exploration policy across recursive rounds thus improves both the efficiency and the effectiveness of long-horizon discovery, and Dream-RSI surpasses PACEvolve in kernel performance (Detailed PACEvolve scaling curves are provided in Appendix C.). Appendix E.2 gives the discovered ConvDiv kernel. Rather than optimizing convolution in isolation, it restructures the operator chain around downstream pooling and reduction. Adjacent convolution outputs are max-pooled immediately, while width pooling and subsequent reductions run directly on register-resident values, avoiding materialization of convolution and pooled feature maps. Linear operations, such as scaling, averaging, and bias accumulation, are deferred to a lightweight final reduction.

4.3 Algorithm Engineering

In this task, we consider Lasso Regularization Path as our algorithm-engineering task, a fundamental computational primitive in high-dimensional statistics that is widely used in model selection and cross-validation across domains such as genomics and finance. We follow the benchmark setting of SimpleTES (Ye et al., 2026), where the goal is to discover efficient implementations of the complete Lasso regularization path while preserving numerical correctness. During discovery, we use the same 17 synthetic instances as SimpleTES, which cover diverse problem regimes in terms of dimensionality, sparsity, feature correlation, and active-set structure. To evaluate whether the discovered algorithms generalize beyond the search distribution, we additionally evaluate them on six held-out downstream datasets spanning biological and non-biological domains. We compare against standard Lasso solvers
sklearn (Pedregosa et al., 2011) and
glmnet (Friedman et al., 2010),
as well as SimpleTES (Ye et al., 2026). We run both controlled baseline and Dream-RSI for 5 rounds.

Main Results.

Figure 4(a) summarizes the Lasso discovery results.
Across both discovery-agent backbones, Dream-RSI achieves a better
downstream quality–compute trade-off than Recursive Fixed Exploration.
With Gemini-3.1 Pro, it reduces the average runtime across the six held-out
datasets from 3587.1 ms to 2931.0 ms while using only 317 discovery-agent
calls, compared with 550 calls for fixed exploration.
With Gemini-3.7-Flash, Dream-RSI further reduces the average runtime
from 2516.7 ms to 2350.6 ms using 1879 calls instead of 3200. Despite using substantially less discovery compute, the resulting solvers also
outperform the standard sklearn and glmnet implementations on all six held-out
datasets. Relative to SimpleTES’s reported 51,200 generations, our Pro
and Flash runs use approximately 162 $\times$ and 27 $\times$ 
fewer discovery-agent calls, respectively, with lower average
downstream runtime, although these comparisons use different
model backbones. For 3.1 Pro, the average improvement over fixed exploration is
driven by RCV1, despite slower runtimes on the other five datasets.
For 3.7 Flash, runtime improves on five of the six datasets.

Recursive Discovery Dynamics.

Figure 4(b) shows the trajectory of downstream performance across recursive discovery rounds against cumulative discovery compute. By design, both methods behave identically in the first round. Afterward, Recursive Fixed Exploration keeps a static exploration policy, while Dream-RSI iteratively refines and redeploys its policy by dreaming over accumulated discovery history. By the final round, Dream-RSI achieves lower average downstream runtime with fewer discovery-agent calls than Recursive Fixed Exploration on both backbones. We further examine the discovered solver, whose implementation appears in Appendix E.1. Unlike SimpleTES, which switches between LARS and coordinate descent by problem dimension, the discovered solver makes the active-set optimization itself adaptive. It pairs strong-rule screening with Cauchy–Schwarz KKT pruning, computing exact gradients only when necessary and falling back to a full refresh once pruning loses effectiveness.

We further evaluate Dream-RSI on the harness optimization task, where the goal is to improve the program surrounding a fixed language model, including how information is stored, retrieved, and presented during agent execution. We follow the setting of Meta-Harness (Lee et al., 2026) and initialize the discovery from Terminus-Kira as the seed harness. Each discovered harness is evaluated on the full Terminal-Bench 2.1 (Merrill et al., 2026) suite of 89 tasks, with two independent runs per task. We use Claude Opus 4.8 with Claude Code as both the discovery agent and the policy-development agent, while harness evaluation is also performed with Claude Opus 4.8. We reproduce Meta-Harness following its original search protocol, using Opus 4.8 for both search and evaluation.

Results.

Figure 5 shows that Dream-RSI improves the harness throughout the discovery process, increasing the full-suite score from 0.7247 to 0.8090. The discovered harness also outperforms Claude Code (0.75) and Meta-Harness (0.79) under the same evaluation setting.

6 Related Work

AI-Driven Scientific and Algorithmic Discovery.

LLM-based discovery systems iteratively generate, evaluate, and refine candidate solutions using prior artifacts and feedback, as in AlphaEvolve (Novikov et al., 2025), OpenEvolve (Sharma, 2025), CodeEvolve (Assumpção et al., 2025), ShinkaEvolve (Lange et al., 2026), PACEvolve (Yan et al., 2026b), DeltaEvolve (Jiang et al., 2026) and MLEvolve Du et al. (2026). More recent work emphasizes the importance of exploration itself: SkyDiscover provides adaptive discovery infrastructure (Liu et al., 2026b), SwarmResearch dynamically orchestrates multiple search branches (Virk et al., 2026), and EvoX (Liu et al., 2026a) explicitly optimizes search strategies rather than only candidate solutions. This shift makes exploration a meta-level optimization problem, but useful supervision for exploration strategies is expensive and delayed because their quality often becomes apparent only after long discovery rollouts.

Self-Evolving Agents.

A broader line of work studies agents that improve their own components during interaction. Prior methods evolve model weights (Huang et al., 2026c; Huang et al., 2026a; Li et al., 2026a), agent harnesses (Lee et al., 2026; Zhang et al., 2026b), contexts (Zhang et al., 2026d), skills (Zhang et al., 2026a; Ouyang et al., 2026a; Wu et al., 2026b), model behavior through test-time learning (Wang et al., 2025; Yuksekgonul et al., 2026; Yan et al., 2026a; Wu et al., 2026a), rubrics (Xiong et al., 2026), environments (Huang et al., 2026b; Li et al., 2026c; Li et al., 2026b) and other applications (Dai et al., 2026). Most operate at the object level, improving components used for task execution or reasoning. Recent work has begun to optimize meta-level mechanisms, including search strategies and self-improvement procedures (Liu et al., 2026a; Yan et al., 2026a; Wang et al., 2026; Zhang et al., 2026c; Kim et al., 2026). However, such meta-level strategies are difficult to improve because their quality is often revealed only after costly long-horizon rollouts. Dream-RSI turns accumulated discovery history into replay simulators for off-policy evaluation and refinement of exploration policies, then redeploys the selected policy for new online discovery, closing a recursive self-improvement loop.

Memory, History, and Experience Reuse.

Prior work reuses agent experience as search history, context, memory, reusable skills, or training signals. DeltaEvolve structures evolutionary history through semantic deltas (Jiang et al., 2026); SwarmResearch and MLEvolve use cross-branch or retrospective information to guide subsequent search (Virk et al., 2026; Du et al., 2026); and other work improves how agents access and retain experience through evolving contexts, broader harness state, libraries, or skills (Zhang et al., 2026d; Lee et al., 2026; Xu et al., 2026; Ouyang et al., 2026a). We take a different view: rather than using exploration history only as context or memory for the next decision, we organize it as a replay simulator in which many alternative exploration controllers can be evaluated cheaply. This turns previously collected discovery experience into reusable feedback for meta-level optimization, alleviating the scarcity and high cost of training signals.

7 Conclusion

We presented Dream-RSI, a framework for the recursive self-improvement of exploration policies in long-horizon discovery. The central idea in Dream-RSI is to convert accumulated discovery history from static context into an active, replayable simulator, directly targeting the core bottleneck of meta-optimization: delayed and expensive feedback. By "dreaming" within replay simulators constructed from historical discovery trees, Dream-RSI evaluates candidate exploration policies rapidly and at negligible execution cost. Improved policies are then redeployed online, driving further discovery and expanding the simulator pool -- closing the recursive self-improvement loop. Our experiments demonstrate competitive discovery quality across diverse domains and improved discovery-agent-call efficiency in several settings.

B.3 Detailed Task Description

Problem 1 (Lasso Regularization Path)

Given a feature matrix
 $X\in\mathbb{R}^{n\times p}$ ,
response $y\in\mathbb{R}^{n}$ ,
and a decreasing sequence
 $\lambda_{1}>\cdots>\lambda_{K}$ ,
define

 $F_{k}(w):=\frac{1}{2n}\|y-Xw\|_{2}^{2}+\lambda_{k}\|w\|_{1},\qquad w_{k}^{\star}\in\arg\min_{w\in\mathbb{R}^{p}}F_{k}(w).$ 

A candidate solver returns approximate coefficients
 $\widetilde{W}=(\widetilde{w}_{1},\ldots,\widetilde{w}_{K})$ .
It passes the benchmark’s objective-value check if

 $F_{k}(\widetilde{w}_{k})\leq F_{k}(w_{k,\mathrm{sklearn}})+10^{-6},\qquad\text{for every }k,$ 

where correctness is checked on fresh instances distinct from the timing
instances. If any required check fails, the search score is zero.
Otherwise, letting $\mathcal{I}$ denote the timing instances and $t_{i}$ the
time required to compute the complete regularization path on instance $i$ ,
the search score is

 $R_{\mathrm{search}}=\left(\prod_{i\in\mathcal{I}}t_{i}\right)^{-1/|\mathcal{I}|}.$ 

Problem 2 (Sum–Difference Problem)

The Sum–Difference Problem asks for a finite set
 $A\subset\mathbb{Z}$ 
whose normalized sumset is large relative to its normalized difference set.
The objective is

 $\Gamma(A):=\frac{\log\!\left(|A+A|/|A|\right)}{\log\!\left(|A-A|/|A|\right)},$ 

where

 $A+A:=\{a+a^{\prime}:a,a^{\prime}\in A\},\hskip 18.49988ptA-A:=\{a-a^{\prime}:a,a^{\prime}\in A\}.$ 

The goal is to construct a finite set $A\subset\mathbb{Z}$ that maximizes
 $\Gamma(A)$ .

Problem 3 (Circle Packing in a Unit Square)

For $n\in\{26,32\}$ , the circle-packing task asks for centers
 $(x_{i},y_{i})\in[0,1]^{2}$ 
and radii $r_{i}\geq 0$ such that every circle lies inside the unit square
and no two circles overlap:

 $r_{i}\leq x_{i}\leq 1-r_{i},\hskip 18.49988ptr_{i}\leq y_{i}\leq 1-r_{i},$ 

 $(x_{i}-x_{j})^{2}+(y_{i}-y_{j})^{2}\geq(r_{i}+r_{j})^{2},\hskip 18.49988pt1\leq i

The objective is to maximize

 $\sum_{i}r_{i}.$ 

Problem 4 (Autocorrelation Inequalities)

For an integrable function $f:\mathbb{R}\to\mathbb{R}$ , define the
autoconvolution

 $(f*f)(t):=\int_{\mathbb{R}}f(t-x)f(x)\,dx,\hskip 18.49988ptt\in\left[-\frac{1}{2},\frac{1}{2}\right].$ 

First Autocorrelation Inequality.
Find a non-negative integrable function
 $f:\mathbb{R}\to\mathbb{R}$ 
supported on
 $\left[-\frac{1}{4},\frac{1}{4}\right]$ 
such that

 $\int_{-1/4}^{1/4}f(x)\,dx=1.$ 

The objective is to minimize

 $\Phi_{1}(f):=\max_{t\in[-1/2,\,1/2]}(f*f)(t).$ 

Second Autocorrelation Inequality.
Find a non-negative integrable function
 $f:\mathbb{R}\to\mathbb{R}$ 
supported on
 $\left[-\frac{1}{4},\frac{1}{4}\right]$ 
such that

 $\int_{-1/4}^{1/4}f(x)\,dx=1.$

Third Autocorrelation Inequality.
Find an integrable (possibly signed) function

such that

Problem 5 (VGG16)

The VGG16 task asks for an efficient implementation of the forward pass of a
VGG16 network. The input is

 $x\in\mathbb{R}^{10\times 3\times 224\times 224},$ 

and the network consists of five convolutional blocks. Each convolution uses a
 $3\times 3$ kernel with stride $1$ and padding $1$ , followed by a ReLU
activation. The channel configurations of the five blocks are

 $(64,64),\hskip 9.24994pt(128,128),\hskip 9.24994pt(256,256,256),\hskip 9.24994pt(512,512,512),\hskip 9.24994pt(512,512,512),$ 

with a $2\times 2$ max-pooling operation of stride $2$ after each block.
After the final pooling layer, the resulting
 $512\times 7\times 7$ feature map is flattened and passed through three fully
connected layers,

 $512\cdot 7\cdot 7\;\rightarrow\;4096\;\rightarrow\;4096\;\rightarrow\;1000,$ 

with ReLU activations after the first two layers. Dropout is disabled
( $p=0$ ). The final output is

 $y\in\mathbb{R}^{10\times 1000}.$ 

The goal is to produce an implementation numerically equivalent to the
reference PyTorch computation while minimizing GPU execution time.

Problem 6 (ConvDiv)

The ConvDiv task applies a sequence of 3D convolution, scaling, pooling, and
reduction operations. The input is

 $x\in\mathbb{R}^{128\times 8\times 16\times 64\times 64}.$ 

First, a 3D convolution with $8$ input channels, $16$ output channels, and a
 $3\times 3\times 3$ kernel is applied without padding:

 $z=\operatorname{Conv3D}(x)\in\mathbb{R}^{128\times 16\times 14\times 62\times 62}.$ 

The convolution output is divided by $2$ and then passed through
 $2\times 2\times 2$ max pooling:

 $u=\operatorname{MaxPool}_{2\times 2\times 2}\left(\frac{z}{2}\right)\in\mathbb{R}^{128\times 16\times 7\times 31\times 31}.$ 

Global average pooling is subsequently applied over the three spatial
dimensions,

 $v_{b,c}=\frac{1}{7\cdot 31\cdot 31}\sum_{d,h,w}u_{b,c,d,h,w},$ 

giving

 $v\in\mathbb{R}^{128\times 16\times 1\times 1\times 1}.$ 

A learnable channel-wise bias

 $\beta\in\mathbb{R}^{16\times 1\times 1\times 1}$ 

is then added, followed by summation over the channel dimension:

 $y_{b}=\sum_{c=1}^{16}\left(v_{b,c}+\beta_{c}\right).$ 

The output has shape

 $y\in\mathbb{R}^{128\times 1\times 1\times 1}.$ 

The goal is to compute this operator chain exactly up to the benchmark’s
numerical tolerance while minimizing GPU execution time.

Problem 7 (ConvMax)

The ConvMax task consists of a 3D convolution followed by max pooling,
channel-wise log-sum-exp reduction, and ReLU. The input is

 $x\in\mathbb{R}^{4\times 32\times 32\times 128\times 128}.$ 

A 3D convolution maps $32$ input channels to $64$ output channels using a
 $3\times 3\times 3$ kernel with stride $1$ and padding $1$ :

 $z=\operatorname{Conv3D}(x)\in\mathbb{R}^{4\times 64\times 32\times 128\times 128}.$ 

This is followed by $2\times 2\times 2$ max pooling with stride $2$ ,

 $u=\operatorname{MaxPool}_{2\times 2\times 2}(z)\in\mathbb{R}^{4\times 64\times 16\times 64\times 64}.$ 

The channel dimension is then reduced using log-sum-exp:

 $s_{b,1,d,h,w}=\log\left(\sum_{c=1}^{64}\exp(u_{b,c,d,h,w})\right),$ 

and the final output is

 $y=\operatorname{ReLU}(s)\in\mathbb{R}^{4\times 1\times 16\times 64\times 64}.$ 

The goal is to produce an implementation numerically equivalent to the
reference computation while minimizing GPU execution time.

Problem 8 (Layer Normalization)

The LayerNorm task applies layer normalization to an input tensor

 $x\in\mathbb{R}^{16\times 64\times 256\times 256}.$ 

Normalization is performed independently for each batch element over the
remaining three dimensions. Let

 $M=64\cdot 256\cdot 256.$ 

For each batch element $b$ , define

 $\mu_{b}=\frac{1}{M}\sum_{c,h,w}x_{b,c,h,w},$ 

and

 $\sigma_{b}^{2}=\frac{1}{M}\sum_{c,h,w}\left(x_{b,c,h,w}-\mu_{b}\right)^{2}.$ 

The normalized output is

 $y_{b,c,h,w}=\gamma_{c,h,w}\frac{x_{b,c,h,w}-\mu_{b}}{\sqrt{\sigma_{b}^{2}+\epsilon}}+\beta_{c,h,w},$ 

where

 $\gamma,\beta\in\mathbb{R}^{64\times 256\times 256}$ 

are learnable affine parameters and
 $\epsilon=10^{-5}$ .
The output has the same shape as the input,

 $y\in\mathbb{R}^{16\times 64\times 256\times 256}.$ 

The goal is to match the reference LayerNorm computation within the
benchmark’s numerical tolerance while minimizing GPU execution time.

 // High-performance branch-free soft-thresholding using std::abs and std::copysign

 37

 static inline double soft_thresh(double z, double gamma) {

 38

 double abs_z = std::abs(z);

 39

 double val = abs_z - gamma;

 40

 return std::copysign(val > 0.0 ? val : 0.0, z);

 }

 396

 }

 }

 }

 406

 double* RESTRICT r_ptr = ASSUME_ALIGNED(r_padded, 64);

 407

 408

 409

 if (delta != 0.0) {

 410

 const double* RESTRICT col_ptr = ASSUME_ALIGNED(X_padded + active[idx] * n_padded, 64);

 411

 #pragma omp simd aligned(r_ptr, col_ptr: 64)

 412

 for (int i = 0; i < n_padded; ++i) {

 413

 r_ptr[i] -= delta * col_ptr[i];

 414

 }

 415

 any_changed = true;

 416

 }

 417

 }

 418

 }

 419

 420

 // O(k^2) exact re-sync of correlation cache c (Sparse-Skipping Custom Loop)

 421

 if (any_changed && active_size > 0) {

 422

 int active_size_padded = (active_size + 7) & ~7;

 423

 #pragma omp simd aligned(c_data, grad_init_active_data: 64)

 424

 for (int i = 0; i < active_size_padded; ++i) {

 425

 c_data[i] = grad_init_active_data[i];

 426

 }

 427

 for (int j = 0; j < active_size; ++j) {

 428

 const double bj = beta_active_data[j];

 429

 if (bj != 0.0) {

 430

 const double* RESTRICT G_col = ASSUME_ALIGNED(G_data + j * current_capacity, 64);

 431

 double* RESTRICT c_ptr = ASSUME_ALIGNED(c_data, 64);

 432

 #pragma omp simd aligned(c_ptr, G_col: 64)

 433

 for (int i = 0; i < active_size_padded; ++i) {

 434

 c_ptr[i] -= bj * G_col[i];

 435

 }

 436

 }

 437

 }

 }

 // 2c. Robust Two-Stage KKT check

 441

 bool screened_kkt_ok = true;

 screened_violators.clear();

 const double KKT_bound = lam * (1.0 + 1e-9);

 445

 // SIMD 4x Register-Blocked Screened KKT Checks (reduces residual vector loads by 75%)

 #pragma omp parallel for schedule(static) if(run_parallel_screened)
