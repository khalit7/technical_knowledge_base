Why it matters (beyond the paper)

It works on models you do not control. The actor's weights, instructions and decoding are untouched; the memory agent only adds text to the next call. That makes it a harness component: something an agent framework can add around any API model, the same layer where the knowledge base's {{SoL-Pi|n:3e25c17b0d0d81a0bb77f16cbc898bb5}} page places its efficiency techniques and where {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} collects harness-scaling strategies.

It sits between two products that already exist. On one side, store-and-retrieve memory layers ({{Mem0|https://github.com/mem0ai/mem0}}, MemGPT); on the other, a stronger model advising a cheaper one. Anthropic's {{advisor tool|https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool}}, which the paper cites, lets an executor model consult a higher-intelligence advisor that reads the full transcript mid-task; there the executor decides when to ask. Here the watcher decides when to speak, and is meant to say only what the run already established. The released traces suggest that in practice the two blur: most of the memory agent's messages are an Opus model's fresh reading of the latest output.

Timing as the problem is a useful frame even where the evidence is thin. Retrieval-augmented generation fixes the timing (retrieve at every call) and makes ranking the whole problem; this paper makes timing the variable. Its own ablation shows that fixing the timing at "every step" costs nothing in accuracy on τ²-Bench; whether a well-timed reminder beats a constant one when tokens are priced is the experiment the paper motivates and does not run.

Connections

  • {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}: the constructive counterpart to its harness-scaling strategies. A second model supervising the first is the same delegating-coordinator shape, pointed at memory rather than at task decomposition.
  • {{SoL-Pi|n:3e25c17b0d0d81a0bb77f16cbc898bb5}}, from the same window, finds roughly half an agent's recorded tokens are harness overhead and cuts them 44.7% to 49.0%. Context compaction and selective reminding are the same lever pulled in opposite directions, one removing what is carried and the other restoring what was dropped, and nobody has yet measured them together. The released traces sharpen the tension: here the memory agent's own input is estimated at about 0.7 times the actor's.
  • {{Trained Persistent Memory|n:3ce5c17b0d0d81978137dd8f8cab1c74}}: memory in a frozen model's latent space, trained end to end; this paper stays entirely in text, and its "write" is a model choosing tool calls.
  • {{Just-in-Time Memory|n:3e95c17b0d0d818f89b3f066f816727b}}: learning what memory to curate for a task; this paper asks when to say it.
  • {{RAG|n:3c65c17b0d0d816c889decc342a7ad39}}: retrieval at every call with ranking as the problem, the design the paper defines itself against; {{ReAct|n:3c65c17b0d0d816b9a24c28de8f08ea8}}: the reason-act-observe loop the memory agent watches.
  • {{Terminal-Universe|n:3d45c17b0d0d814abc07fde424e09a31}} and {{HarnessDev|n:3d45c17b0d0d81cd9883f783840e013f}}: other recent work measured on Terminal-Bench, one building training environments, one evolving the harness itself.
  • Outside the knowledge base: {{Reflexion|https://arxiv.org/abs/2303.11366}} stores verbal reflections across attempts; {{Memory as Action|https://arxiv.org/abs/2510.12635}}, {{Context-Folding|https://arxiv.org/abs/2510.11967}} and {{Mem-α|https://arxiv.org/abs/2509.25911}} train the agent itself to manage its context or memory, where this paper trains only a separate memory agent and leaves the actor alone, a harder credit-assignment problem since a reminder may need to be silent, prevent a repeat or revive a diagnosis ({{§2.3|ax:S2.SS3}}).

How much of this to believe

[[S4|§4, Tables 1, 2 and 4]]

What holds up. The comparisons are paired: baseline and memory runs use the same tasks, harness and actor, and the ablations hold both models fixed. The code, both run configurations and five full example traces are public, so the mechanism can be inspected rather than taken on trust, and every printed percentage maps back to a whole number of tasks. The authors are candid in places: the training study is called preliminary, and the micro-average edge of always injecting is called "within expected run variance" ({{§4.3|ax:S4.SS3}}). The τ²-Bench gain for Sonnet is the strongest number: 19 more tasks of 278 (+6.8 points; unpaired standard error 4.2 points), significant in a paired test as long as no more than 83 tasks changed outcome between the two runs.

The weaknesses, concretely:

  1. One run per cell, no seeds or error bars, with the actor sampling at temperature 0.7. The same full configuration appears twice (Table 1 and Table 2) and solves 172 and 170 τ²-Bench tasks, a 2-task spread that is as large as several of the ablation gaps.
  2. The Terminal-Bench headline is small in tasks and its baseline is low. +8.3 points is 7 tasks of 85; it is significant in a paired test only if at most 9 tasks changed outcome. The baseline, 37.6%, is 5.2 points under the Terminal-Bench paper's own figure for the same model and harness, 42.8% ± 2.8% over at least five runs ({{Terminal-Bench, Table 2|https://arxiv.org/html/2601.11868#A1.T2}}); the memory run's 45.9% is 3.1 points above that published baseline. The released configuration caps the actor at 50 turns, which may explain part of the gap (unconfirmed). Opus's +2.4 is 2 tasks; the trained Qwen agent's +3.5 is 3.
  3. Not like for like on model strength or cost. The treatment adds Claude Opus 4.6, called twice at every step, to a Sonnet 4.5 actor. The obvious matched baseline, Opus acting alone, is in Table 1 and beats the Sonnet pair on τ²-Bench by 12 tasks (66.2% against 61.8%); the paper does not draw that comparison. No tokens, latency or cost are reported for either model, although the paper's own motivation is that surfacing too much "adds latency, consumes tokens" ({{§1|ax:S1}}). From the released traces the memory runs cost an estimated 2.2 times the baselines.
  4. The title's claim, that selectivity is what helps, is not shown. Always injecting solves 171 τ²-Bench tasks against 170 and 172; the macro edge of the selective agent comes from 3 airline tasks of 50. Ablations exist only for τ²-Bench and only for the Sonnet actor.
  5. The released agent is not as selective, or as memory-bound, as described. It speaks at 52 of 80 steps (65%) in the five traces, at 28 of 31 in one; about half of what it says is a new diagnosis of the latest output rather than a remembered fact; the reminders average about 400 tokens. The run configuration's header even calls it "single-phase". The examples are chosen (four are the paper's qualitative cases) and carry no pass or fail result.
  6. Small text and table inconsistencies: retail "+9.7" in the text against +9.6 in Table 1; the full agent's retail score 58.8% in Table 1 against 57.0% in Table 2 for the same configuration; 61.8% and 41.1% are truncated (172/278 = 61.87%, 35/85 = 41.18%) where every other figure is rounded; "at a fixed interval" and "every N steps" in the method and figure caption against "every subsequent step" in the experiments. None changes a conclusion. The details are in the {{tables tab|tab:t-tables:chk}}.
  7. The training result is thin. SFT and GRPO solve the same 58 SETA validation tasks; the set's size is not stated; the transfer is 3 tasks in one run; no weights or training code are released.

Verdict. A strong model watching a weaker one and interjecting helps the weaker one on these benchmarks: believe the direction, especially on τ²-Bench, and treat the Terminal-Bench size as provisional given its low baseline. The paper's distinctive claim, that the value lies in deciding when to remind rather than in reminding, is not supported by its own ablation, and the released traces show an agent that mostly advises. Whether the gain is worth roughly doubling the bill, against simply using the stronger model as the actor, is unmeasured, and on τ²-Bench the stronger model alone wins.

What it takes to use this

  • Code: {{yifannnwu/proactive-memory-agent|https://github.com/yifannnwu/proactive-memory-agent}}, Apache-2.0. Released: the two-phase memory agent, a Terminal-Bench runner on a vendored Harbor with Enroot sandboxes (the README explains swapping in Harbor's Docker environment), the baseline and memory configurations, five example traces. Model calls go through LiteLLM, so any action and memory model pair can be set in the YAML. Not released: the τ²-Bench runs, the ablation variants, the SETA training pipeline and the trained Qwen3.5-27B memory agent (checked 3 October 2026).
  • Running cost: two memory-model calls per action step, each carrying the bank and the last 8 steps of reasoning and terminal output. In the released traces that input averaged about 0.7 of the actor's own input tokens; at Opus 4.6 prices ($5 and $25 per million tokens against Sonnet 4.5's $3 and $15, {{pricing|https://platform.claude.com/docs/en/about-claude/pricing}}) the memory agent was about half the bill. Prompt caching, a longer interval or event triggers (after errors or repeated commands, which the paper names as future work, {{§3.4|ax:S3.SS4}}) would cut this; none is measured.
  • Which setups worked: an Opus 4.6 memory agent helped Sonnet 4.5 a lot and Opus 4.6 a little; an untrained Qwen3.5-27B memory agent made a Qwen3.5-122B-A10B actor worse on SETA, and only after SFT and GRPO did it help (+3 Terminal-Bench tasks).
  • When it pays: when the actor must stay a cheaper or fixed model and a stronger model is available to watch, on long debugging or policy-heavy dialogues. When the stronger model could simply be the actor, compare that first: on τ²-Bench it scored higher alone.

Corrections to the earlier summary

This page replaces a 3-minute summary written from The Batch's coverage of 18 September 2026

That summary carried a provenance note: no arXiv identifier or primary URL was resolvable from the newsletter, whose links are tracking redirects, so the paper had not been read directly, the figures were reported rather than verified, and the arXiv id was to be attached when it surfaced. It has now surfaced and this page is built from the paper: arXiv {{2607.08716|https://arxiv.org/abs/2607.08716}}, "Remember When It Matters", eight authors at Meta AI (Yifan Wu and Zhuokai Zhao corresponding), submitted 9 July 2026 rather than in September, with code and example traces. Corrections:

  • "Qwen3.5-27B: 37.6% to 41.1%" (also in the database's Takeaway) is not a Table 1 actor result. The actor there is a frozen Qwen3.5-122B-A10B; Qwen3.5-27B is the memory agent, trained with SFT and GRPO on SETA, and the 41.1% is its held-out transfer (Table 4).
  • The Terminal-Bench results also include Opus 4.6 as actor, 43.5% to 45.9%; the τ²-Bench 66.2% to 68.7% is that same Opus actor.
  • "Four model pairings": with Opus 4.6 as the memory agent there are two actors on two benchmarks, plus the Qwen pair on Terminal-Bench.
  • "Gains larger for the weaker actor on Terminal-Bench and smaller for the stronger one on τ²-Bench, as if substituting for context management the stronger model partly does itself": the weaker actor gains more on both benchmarks, and the paper reads the stronger actor's remaining gain as evidence that it is not merely compensating for limited capacity ({{§4.2|ax:S4.SS2}}).
  • "Reminding selectively beats reminding at every step" holds only on the macro average, by 3 airline tasks; on the task-weighted average always injecting is ahead (171 against 170 tasks), within the paper's own run-to-run spread.
  • "No cost accounting is reported" is confirmed; this page estimates it from the released traces.
