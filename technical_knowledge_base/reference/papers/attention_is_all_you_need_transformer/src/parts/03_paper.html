Problem

[[S1|§1 Introduction, §2 Background]]

In 2017 sequence transduction, translation above all, was dominated by recurrent encoder-decoders (LSTMs and GRUs), usually with an attention mechanism between encoder and decoder, and by convolutional alternatives such as ByteNet and ConvS2S ({{§1|ax:S1}}, {{§2|ax:S2}}). A recurrent network computes its hidden state ht from ht−1 and the input at position t, so training cannot be parallelised along the sequence: that caps how much of a GPU a batch can use, and memory limits batching across examples as sentences get longer. Convolutional models do compute all positions in parallel, but connecting two distant positions takes a stack of layers, O(n/k) for contiguous kernels (ConvS2S) or O(logk n) for dilated ones (ByteNet), so long-range dependency paths stay long ({{§4|ax:S4}}).

The question: can attention alone, with no recurrence and no convolution, carry an entire sequence model?

Idea

[[S4|§4 Why Self-Attention, Table 1]]

Let every position look at every other position directly, in one step. Section 4 compares layer types on three counts: total computation per layer, how much of it can run in parallel (the minimum number of sequential operations), and the longest path a signal has to travel between two positions, since shorter paths make long-range dependencies easier to learn ({{§4|ax:S4}}, {{Table 1|ax:S4.T1}}).

LayerComputation per layerSequential operationsLongest path
Self-attentionO(n²·d)O(1)O(1)
RecurrentO(n·d²)O(n)O(n)
ConvolutionalO(k·n·d²)O(1)O(logk(n))
Self-attention, restricted to r neighboursO(r·n·d)O(1)O(n/r)

n is the sequence length, d the representation size, k the kernel width, r the neighbourhood size ({{Table 1|ax:S4.T1}}).

When n < d, as with sentence-level word-piece and byte-pair tokens, self-attention is also cheaper per layer than recurrence: n²d < nd² exactly when n < d, so with the base model's d = 512 the crossover is at 512 tokens. The paper also suggests restricting attention to a neighbourhood of size r for very long sequences, at the price of an O(n/r) path ({{§4|ax:S4}}). Method: scaled dot-product attention

[[S3.SS2.SSS1|§3.2.1, Eq. 1]]

The Transformer is an encoder-decoder built only from attention, position-wise feed-forward layers, residual connections and layer normalisation ({{§3|ax:S3}}). Attention maps a query and a set of key-value pairs to a weighted sum of the values, the weights coming from how well the query matches each key. With queries and keys of size dk and values of size dv, packed as matrices:

Attention(Q, K, V) = softmax(QK⊤ / √dk) V
Equation 1 ({{§3.2.1|ax:S3.SS2.SSS1}}). Dot-product rather than additive (Bahdanau) attention, because it is a single matrix multiply: similar in theory, much faster and more memory-efficient in practice.

The 1/√dk is the load-bearing detail. If the components of q and k are independent with mean 0 and variance 1, then q·k = Σqiki has mean 0 and variance dk (the paper's footnote 1). Unscaled, the logits spread out as dk grows and push the softmax into regions with tiny gradients; the paper notes that additive attention beats unscaled dot-product attention at large dk ({{§3.2.1|ax:S3.SS2.SSS1}}).

Ten keys and one query with components drawn from a standard normal (Box-Muller, seeded). Variance of q·k is measured over 4,000 fresh pairs. "Largest gradient" is the largest entry of the softmax Jacobian, max pi(1 − pi): how much the strongest logit can still move the output. Illustrative inputs; the formula is the paper's.

Method: multi-head attention

[[S3.SS2.SSS2|§3.2.2]]

Instead of one attention over dmodel = 512 dimensions, the queries, keys and values are projected h = 8 times with learned matrices WiQ, WiK (dmodel × dk) and WiV (dmodel × dv), with dk = dv = dmodel/h = 64. Each head runs attention in parallel; the h outputs are concatenated and projected back by WO (hdv × dmodel) ({{§3.2.2|ax:S3.SS2.SSS2}}).

MultiHead(Q, K, V) = Concat(head1, …, headh) WO,   headi = Attention(QWiQ, KWiK, VWiV)

Because each head is h times narrower, the total cost is about that of one full-width head. What it buys: heads can attend to different subspaces and positions at once, where a single head has to average them. In the ablation one head costs 0.9 BLEU against the best setting (24.9 against 25.8), and too many heads hurt as well: 32 heads of 16 score 25.4 ({{Table 3 rows (A)|ax:S6.T3}}). The {{Run a Transformer|tab:t-run}} tab shows every head of a trained toy model, and a one-head version of it.

Method: the block (post-LN)

[[S3.SS1|§3.1, §3.2.3, §3.3, §3.4]]

The encoder is a stack of N = 6 identical layers with two sub-layers each: multi-head self-attention, then a position-wise feed-forward network. Every sub-layer is wrapped as LayerNorm(x + Sublayer(x)), normalisation after the residual sum ("post-LN"), with dropout on the sub-layer output before it is added. Every sub-layer and the embeddings produce outputs of size dmodel = 512 so the residuals line up ({{§3.1|ax:S3.SS1}}, {{§5.4|ax:S5.SS4}}).

The decoder is also N = 6 layers, with three sub-layers: masked self-attention, where every illegal connection is set to −∞ before the softmax so position i sees only positions up to i (combined with the outputs being shifted right by one, a prediction depends only on earlier words); cross-attention, whose queries come from the decoder and whose keys and values come from the encoder's output, so every output position can look at every input position; and the same feed-forward network ({{§3.1|ax:S3.SS1}}, {{§3.2.3|ax:S3.SS2.SSS3}}).

The base model's layout, from {{Figure 1|ax:S3.F1}}: N = 6 of each layer, dmodel = 512, h = 8, dff = 2048. Add & Norm is LayerNorm(x + Dropout(Sublayer(x))).

FFN(x) = max(0, xW1 + b1) W2 + b2
Equation 2 ({{§3.3|ax:S3.SS3}}): the same two linear maps with a ReLU between them at every position (two convolutions of kernel size 1), different from layer to layer; inner size dff = 2048, a 4× expansion.

Embeddings. One weight matrix is shared by the input embedding, the output embedding and the pre-softmax projection, and in the embedding layers it is multiplied by √dmodel ({{§3.4|ax:S3.SS4}}); with the shared English-German vocabulary of about 37,000 tokens, that one matrix is 18.9 million of the base model's parameters (37,000 × 512, {{counted in the tables tab|tab:t-tables:tbP}}).

Method: positional encoding

[[S3.SS5|§3.5]]

With no recurrence and no convolution nothing in the model knows word order, so it has to be injected. The paper adds fixed sinusoids to the embeddings at the bottom of both stacks:

PE(pos, 2i) = sin(pos / 100002i/dmodel),   PE(pos, 2i+1) = cos(pos / 100002i/dmodel)
Each dimension is a sinusoid; the wavelengths form a geometric progression from 2π to 10000 · 2π ({{§3.5|ax:S3.SS5}}).

Why sinusoids: for any fixed offset k, PEpos+k is a linear function of PEpos (each sine and cosine pair is rotated by an angle that depends only on k), which the authors hoped would make attending by relative position easy to learn. Learned absolute embeddings gave nearly identical results (25.7 BLEU against 25.8, {{Table 3 row (E)|ax:S6.T3}}); the sinusoids were kept because they might extrapolate to sequences longer than any seen in training ({{§3.5|ax:S3.SS5}}).

Left: the encoding of positions 0 (top) to 63 (bottom) across all 512 dimensions at dmodel = 512 (blue negative, orange positive): fast sinusoids on the left, wavelengths up to 10000 · 2π on the right. Right: PEp · PEp+k against the offset k for three starting positions p: the curves coincide, because the dot product depends only on the offset. Computed from the formula above.

train the same toy model without positional encoding. What does it output for "the dog chased the cat" and for "the cat chased the dog"?

Exactly the same, and not by luck. Without positions the encoder is permutation-equivariant (shuffle the input words and its outputs shuffle the same way) and cross-attention sums over the encoder's outputs, which ignores their order; so any reordering of the source gives the same translation. Method: training and decoding

[[S5|§5 Training, §6.1]]
  • Data ({{§5.1|ax:S5.SS1}}): WMT 2014 English-German, about 4.5 million sentence pairs, byte-pair encoded with a shared source-target vocabulary of about 37,000 tokens; English-French, 36 million sentences, a 32,000 word-piece vocabulary. Batches held about 25,000 source and 25,000 target tokens, sentences grouped by length.
  • Hardware and time ({{§5.2|ax:S5.SS2}}): one machine with 8 NVIDIA P100s. Base model (65M parameters): 100,000 steps at about 0.4 s each, 12 hours. Big model (213M): 300,000 steps at 1.0 s, 3.5 days.
  • Optimiser ({{§5.3|ax:S5.SS3}}): Adam with β1 = 0.9, β2 = 0.98, ε = 10−9, and a learning rate that rises linearly for 4,000 warmup steps, then falls with the inverse square root of the step (Equation 3, below).
  • Regularisation ({{§5.4|ax:S5.SS4}}): residual dropout 0.1 on every sub-layer output and on the sums of embeddings and positional encodings (0.3 for the big English-German model); label smoothing εls = 0.1, which "hurts perplexity, as the model learns to be more unsure, but improves accuracy and BLEU". The section announces three types of regularisation and lists these two.
  • Decoding ({{§6.1|ax:S6.SS1}}): beam search with beam 4 and length penalty α = 0.6, maximum output length input + 50; the final model averages the last 5 checkpoints, written every 10 minutes, for base models and the last 20 for big ones.
lrate = dmodel−0.5 · min(step−0.5, step · warmup−1.5)
Equation 3 ({{§5.3|ax:S5.SS3}}). The two branches meet at step = warmup, so the peak is (dmodel · warmup)−0.5.

Results

[[S6|§6 Results, Tables 2 to 4]]
  • English to German (WMT 2014 newstest2014): the big model scores 28.4 BLEU, more than 2.0 above the best earlier result including ensembles (ConvS2S Ensemble, 26.36; the gap is 2.04). Even the base model, 27.3, beats every earlier model and ensemble at a fraction of their training cost: 3.3 × 1018 FLOPs against 9.6 × 1018 to 1.8 × 1020 for the others ({{§6.1|ax:S6.SS1}}, {{Table 2|ax:S6.T2}}).
  • English to French: 41.8 BLEU for the big model in Table 2 and the abstract, a new single-model state of the art, at 2.3 × 1019 FLOPs, under a quarter of the earlier single models' 1.2 to 1.5 × 1020 (0.15 to 0.19 of them). The two primary figures disagree: the v7 text of §6.1 still says 41.0, the figure the {{v1|https://arxiv.org/abs/1706.03762v1}} and {{v2|https://arxiv.org/abs/1706.03762v2}} abstracts reported, while Table 2 and the abstract from {{v5|https://arxiv.org/abs/1706.03762v5}} on say 41.8; this page uses 41.8, the later and tabulated figure. This model used dropout 0.1 instead of 0.3 ({{§6.1|ax:S6.SS1}}).
  • How the FLOPs were counted (Table 2, footnote 2): training time × number of GPUs × an estimate of each GPU's sustained single-precision rate (2.8, 3.7, 6.0 and 9.5 TFLOPS for K80, K40, M40 and P100). Defaults reproduce Table 2 independently: 12 h × 3,600 s × 8 × 9.5 × 1012 = 3.28 × 1018 (3.3 × 1018), and 3.5 days gives 2.30 × 1019 (2.3 × 1019); see recompute.py.
  • English constituency parsing ({{§6.3|ax:S6.SS3}}, {{Table 4|ax:S6.T4}}): a 4-layer Transformer with dmodel = 1024, trained on the 40,000 Wall Street Journal sentences alone, scores 91.3 F1 on WSJ section 23, beating the BerkeleyParser (90.4), which RNN sequence-to-sequence models had not managed in this small-data setting; only the Recurrent Neural Network Grammar (91.7) is higher. Semi-supervised, with about 17 million sentences, it scores 92.7. Vocabulary 16K (WSJ only) or 32K; beam 21, α = 0.3, maximum output length input + 300; little task-specific tuning: evidence the architecture generalises beyond translation.
  • Ablations ({{§6.2|ax:S6.SS2}}, {{Table 3|ax:S6.T3}}, measured on newstest2013 without checkpoint averaging): too many heads hurts as well as too few; shrinking dk hurts (the authors suggest a better compatibility function than the dot product might help); bigger models are better; dropout is essential at this data scale; learned positions match sinusoids.

Why it matters

beyond the paper: later work, each claim linked

This is the architecture paper of the deep learning era. Removing recurrence made training embarrassingly parallel across sequence length, which let compute be spent on model and data size instead of waiting on wall-clock sequential steps. Every frontier LLM (GPT, Claude, Llama, Gemini, DeepSeek), BERT-style encoders, ViT, CLIP, Whisper and most of diffusion's backbone work descend from this design.

What modern stacks changed since 2017 is a checklist of the paper's choices that turned out not to be load-bearing; the {{Then and now|tab:t-then}} tab morphs the 2017 block into a 2026 one step by step, each step with its paper:

  • Pre-LN instead of post-LN (the norm before each sub-layer) for stable training without the warmup sensitivity; LayerNorm itself usually replaced by RMSNorm.
  • RoPE instead of sinusoidal absolute encodings (rotary embeddings applied inside attention), plus interpolation and YaRN tricks to extend the context.
  • SwiGLU or GeGLU instead of ReLU in the FFN, bias terms dropped.
  • Decoder-only, not encoder-decoder: GPT-style causal language models won for generation; cross-attention survives mainly in multimodal adapters and encoder-decoder holdouts (T5, Whisper).
  • Attention efficiency: MQA, GQA and MLA shrink the KV cache; FlashAttention makes exact attention IO-aware; the O(n²) cost the paper acknowledged is now the central serving bottleneck (PagedAttention, sliding windows, sparse and linear hybrids such as Mamba).
  • Regularisation and optimiser: label smoothing and heavy dropout largely dropped at pretraining scale (PaLM trained without dropout); the warmup then decay schedule survives in cosine form (GPT-3: linear warmup over 375M tokens, cosine decay to 10%), and Adam's β2 moved from 0.98 to 0.95 ({{GPT-3, Appendix B|https://arxiv.org/pdf/2005.14165}}, {{PaLM §5|https://arxiv.org/pdf/2204.02311}}).

What survived untouched: scaled dot-product attention itself, multi-head projections, and the residual-plus-norm wrapping. Two items the older version of this page listed as untouched have moved: the 4× FFN expansion survives as a parameter budget, not a shape (a SwiGLU FFN has three matrices, so it uses an inner size near 8/3 × d, or 3 to 3.5 × in Qwen3 8B and Llama 3.1 8B), and weight-tied embeddings survive in small models (Llama 3.2 1B, Qwen3 0.6B) while large ones untie them (Llama 3.1 8B, Qwen3 8B, DeepSeek-V3), as their config files show (the {{Then and now|tab:t-then}} tab links them).
