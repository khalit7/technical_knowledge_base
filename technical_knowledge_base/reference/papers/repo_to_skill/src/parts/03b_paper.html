Method: DisCo distils in four stages, from a source or from a task

[[S3.SS2|§3.2, §3.3, Eq. 8, Appendix A]]

DisCo is one agent with two modes over the same backbone and harness ({{§3.3|ax:S3.SS3}}). In creator mode it produces skill graphs and deposits them in the library; in researcher mode it solves a task with skills drawn from the library. Every creator run follows the same four stages ({{Eq. 8|ax:S3.E8}}): from an anchor z, scope capabilities 𝒬, ground them in evidence 𝒳, construct a candidate graph, verify it into 𝒢 with a record R of evidence, checks and unresolved gaps.

The two forms of distillation differ in the anchor ({{§3.2|ax:S3.SS2}}). Task-agnostic: the anchor is a source (a repository, a paper, a tutorial) and the run asks what the source makes possible, ahead of any task. Task-oriented: the anchor is a problem, and the run asks what solving it demands, searching for sources it does not yet have. (The old page called these "modes"; the paper's modes are creator and researcher.) Step through both: the released Creator run on huggingface_hub, and the paper's MLE-bench protocol ({{Appendix A.2.1|ax:A1.SS2.SSS1}}).

Stages from {{Eq. 8|ax:S3.E8}}; details from {{Appendix A.1|ax:A1.SS1}} and {{A.2.1|ax:A1.SS2.SSS1}}.

The two forms differ in more than the anchor. The repository run yields scripts and references pinned to a package version, checked against that package's own tests. The MLE-bench run yields a descriptive skill with no scripts, built from web search plus up to 24 GPU-hours of diagnostic trials on the very competition it is for ({{Table 5|ax:A1.T5}}): in effect, the lab notebook of a previous attempt at the same problem.

The cost is asymmetric by design ({{§3.3|ax:S3.SS3}}): creator mode is paid once per source and amortised; researcher mode pays only for what a task opens. The library cost "about $40 per repository" of GPT-5.5 and GPT-5.6-sol at extra-high reasoning effort ({{§4.1|ax:S4.SS1}}), about $40,000 in all (derived). MLE-bench construction is up to 24 GPU-hours per competition, at most 1,800 for the 75 (derived), counted in neither arm.

In researcher mode ({{§3.3|ax:S3.SS3}}, {{§4.2|ax:S4.SS2}}) the agent sees a router skill, narrows from area to family to repository graph, and follows links only as needed; the full library "is never placed into context". Skills add operating context, not a new control loop, so any harness that reads Agent Skills can use them. The {{Follow the router|tab:t-run}} tab replays a released session doing this.

The AREX-Skill Library

[[S4|§4, Figure 3, Appendix A.1, Appendix B]]

Task-agnostic distillation run across 1,000 ML repositories yields the library ({{§4.1|ax:S4.SS1}}): 5,353 skills in 1,000 repository graphs (about 5.4 per repository), organised into 20 areas and 178 capability families, with 2,209 exact assignments of repositories to area-and-family paths; 700 repositories sit in more than one family. All of these recount exactly from the public release, which is 31,191 files and 237 MB; the median repository graph is 156 KB, its entry SKILL.md 4.6 KB.

  • Selection: "open-source visibility and practical use, with GitHub stars among the curation signals"; a curated snapshot ({{§4.1|ax:S4.SS1}}).
  • Graph: a router-like entry skill linking to component skills for data preparation, training, inference, evaluation, serving, troubleshooting or maintenance; self-contained, with provenance (source commit, package version, dirty state, evidence paths) ({{Appendix A.1|ax:A1.SS1}}).
  • Verification: assertion-backed usability cases, safe native tests, CLI checks, tiny fixtures or smoke scripts, classed pass, skill_gap, native_fail, skip_unsafe or skip_not_selected; a skill gap triggers a local repair and rerun. Static gates check metadata, links, self-containment, provenance and path leakage.
  • Taxonomy ({{§4.2|ax:S4.SS2}}): an LLM proposes a two-level tree from frozen one-line summaries (stars, URLs and old categories hidden), tested on 100 fixed batches of 10 repositories by a separate locator and judge, then revised for at least two rounds until a convergence gate passes. Only then is each graph assigned to exact paths, with rationale, evidence and confidence; keyword-only, dependency-only, optional-integration and example-only matches are rejected.

Repository memberships per area, coloured by family; from the release's assignments.jsonl (identical to {{Appendix B|ax:A2}}). Tap a bar for its families. A repository counts once per family it is assigned to.

Two further collections sit beside the repository graphs and are not in these counts ({{§4.3|ax:S4.SS3}}). Paper-derived skills: for the 20 PaperBench targets, DisCo decomposed up to 10 prior papers per target (from its related-work section) into 3 to 5 module skills each, 636 skills from 153 papers, each checked in isolation and then by a bounded recovery experiment that may not read the original code; the target paper and its released code are excluded. Task-oriented skills: one graph per MLE-bench competition (75), one recovery graph shared by FrontierCS's 188 Agent Track tasks, and one graph for PassNet.
