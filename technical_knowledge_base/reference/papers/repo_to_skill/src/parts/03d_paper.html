How much of this to believe

[[S5|§5, Appendix A, the release]]

What holds up.

  • The artefact is real and counts out. Every library count the paper prints (5,353 skills, 1,000 graphs, 2,209 assignments, 700 multi-family repositories, 20 areas, 178 families, 636 paper-derived skills) and the FrontierCS graph's 9 nodes and 42 links match the public release exactly. Code and skills are Apache-2.0, with two full session exports. That is more than most agent papers release.
  • The arithmetic is clean. Every printed number this page could recompute reproduces (the checks are in the {{Tables tab|tab:t-tables}}) except one rounding: 75.04% printed as 75.1%. MLE-bench's means and SEMs pin down unique medal counts per run that add up across tiers.
  • The MLE-bench and FrontierCS gaps are not noise. MLE-bench reports three runs per arm with a gap of 16 standard errors; FrontierCS reports a paired bootstrap interval of [3.41, 9.83] over 188 tasks. PaperBench's 18 of 20 papers improving is unlikely by chance (sign test p = 0.0004, derived).
  • The authors state some weaknesses themselves, which counts in their favour: the two PaperBench regressions and a possible retrieval-precision failure, the PassNet outliers that do not reproduce across runs, and the over-absolute PassNet rule.

What is not like for like, or not what it seems.

  • None of the four results tests the library. The 1,000-repository library is the paper's title and headline artefact, but "we evaluate DisCo beyond the public repository snapshot" ({{§5|ax:S5}}): MLE-bench, FrontierCS and PassNet use task-oriented graphs built for each benchmark, PaperBench uses paper-derived pools. Whether the repository library helps any agent on any benchmark is untested. The old version of this page, and the database Takeaway, attribute the four gains to the library.
  • "Fixed budget" excludes construction, and for MLE-bench construction is a prior attempt at the same task. Up to 24 GPU-hours of diagnostic trials on each competition shaped its skill ({{Appendix A.2.1|ax:A1.SS2.SSS1}}), so the skill arm had up to 48 GPU-hours of work per competition against 24. No script is replayed, but the skill carries "task diagnoses, model and preprocessing choices, training strategies, expected observations": a second attempt with notes from the first. The old page's "this is not more compute buying more attempts" does not hold for MLE-bench.
  • The leaderboard comparison mixes setups, and the baseline is weak. Public rows come from leaderboards with other harnesses, models, hardware and run counts; "beats the best public entry by 8.45 points" pits per-competition prior exploration against agents without it. Codex alone (31.11%) is below every public MLE-bench entry, and a large relative gain over a weak baseline is easier than over a tuned one.
  • FrontierCS spends more, and its development set is unstated. Skill runs used 1.82 times the tokens; the paper's answer (gains uncorrelated with extra usage) is fair but indirect, and no no-skill run got the same spend. The overlap of the "selected development problems" with the 188 evaluated tasks is not stated. The whole average gain sits in the 47 low-scoring tasks (net −0.17 on the other 141, derived), a split by one run's score that regression to the mean also flatters.
  • Single runs elsewhere, and one metric unmentioned. PaperBench, FrontierCS and PassNet report no repeats; PaperBench's grader is an LLM judge; PassNet samples moved from 10.63 to 0.99 between repeats in construction. PassNet's Fast_1 falls (28.48% to 26.72%) without comment.
  • "Verified" means structural and package-level checks. The released Creator example (huggingface_hub) passes shape, frontmatter, licence, links, privacy, routing and bundled-script checks, and 720 of the package's own unit and mocked tests ("verified-with-warnings": 2 native failures, 3 unsafe selections excluded). Its 15 usability cases pass a check of their "shape"; the report does not record an agent being run on them. The vLLM graph was inspected on a CPU build, "GPU execution intentionally left to user-hardware verification". Verified skills are well-formed and pinned to a version, not shown to make an agent succeed.
  • Curation is looser than "widely used ML repositories". High-confidence routes include a game-automation bot (1bananachicken/MaaNTE, under Computer Vision and Speech and Audio) and a set of beginner Python scripts (ndleah/python-mini-project, under Image Classification). 2,123 of 2,209 assignments are "high"; the confidence labels are not a quality filter.
  • The misapplication risk is acknowledged but not measured. {{Demystifying Agent Skills|n:3c65c17b0d0d81249a3cf5fda4de5d92}} found skill guidance misapplied or ignored in 10.0% of the skill arm's failure labels (against 0.8% in its no-experience arm). This paper's two PaperBench regressions and the PassNet conv3d rule are instances, but it reports no rate of misapplied skills and no retrieval-precision measurement for its router.

Verdict. Believe the artefact and the direction: the library is real, consistent and openly licensed, and task-specific skills made the same Codex agent better on four quite different benchmarks. Treat the sizes as "what a second, informed attempt is worth", not as the value of a reusable library: none of the results uses the 1,000-repository library, MLE-bench's +134.3% includes up to 24 extra GPU-hours of exploration per competition, FrontierCS's +6.51 came with 1.8 times the tokens and sits entirely in the hardest quarter of tasks, and only MLE-bench has repeated runs.

What it takes to use this

[[S4.SS2|the release]]
  • Code and licence: {{VectorSpaceLab/AREX-Skill|https://github.com/VectorSpaceLab/AREX-Skill}}, Apache-2.0 for repository-level files unless a file says otherwise; each graph also records its upstream licence. The DisCo CLI is built on the open {{pi agent toolkit|https://github.com/earendil-works/pi}} and needs Node.js 22.19 or newer; disco repo-skills install installs the library, and researcher mode routes it natively.
  • Other agents: import-repo-skills-to-agent exports selected skills plus a scoped router into Codex's or Claude Code's skills directory; nothing in the harness changes.
  • What is released and what is not: the 1,000 repository graphs and router, the PaperBench pools (636 skills), the FrontierCS graph and the PassNet skills are in the repository. The 75 MLE-bench graphs, the source of the headline number, are not; neither are the benchmark trajectories.
  • Cost to build your own: about $40 of model time per repository at extra-high reasoning effort with GPT-5.5 and GPT-5.6-sol; for an MLE-bench-style task, up to 24 GPU-hours of exploration per task before the real run.
  • Freshness: graphs pin a commit and version and drift with every release; check the provenance file, and the documented refresh procedure, before trusting a graph for a newer version.
  • When it pays: where the agent would otherwise burn its budget on setup and package behaviour (low baselines, hard tiers, unfamiliar libraries), and where a task family repeats so construction is amortised. When it buys little: tasks the agent already does well (FrontierCS tasks above 50 gained nothing on net; high-baseline PaperBench papers gained 2 points), and narrow tasks where a general rule can mislead.

Why it matters

[[S7|beyond the paper]]

The paper's framing is the durable part: an agent is a model, a harness and a knowledge layer, and the third can be manufactured from sources that already exist rather than written by hand. It reframes what a repository is for an agent: not something to read when needed, but a source of pre-compiled procedure distilled once and reused. That is the same mechanism {{Demystifying Agent Skills|n:3c65c17b0d0d81249a3cf5fda4de5d92}} identified when it found skills work as procedural anchors (steps, checks, pitfalls) rather than as knowledge injection, and this is the first work to supply such anchors at library scale. Its released sessions show the economics working as designed: in the vLLM against SGLang run, the agent read 65 KB of a 237 MB library in under two minutes and then worked for five hours.

The old version of this page called the MLE-bench figure "the largest single-intervention gain the KB currently records on that benchmark"; that is a claim about this knowledge base, not the paper, and given the per-competition exploration behind it, it should be read as the gain from task-specific preparation, not from a library. The caution carried over from the Demystifying paper applies directly: skills add a misapplication failure mode, and retrieval precision decouples from task success, so a 5,353-skill library is also 5,353 opportunities to apply the wrong procedure confidently. This paper engages with that only anecdotally (two PaperBench regressions, one PassNet rule), which is the obvious next experiment.
