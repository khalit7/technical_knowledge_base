Depth that grows with the sequence: a decoder-only Transformer against the Recurrent Looped Transformer

Eight tokens (five of prompt, three generated) through the same 96 blocks per token, drawn to the same scale: each column is a token, each row six layers. In a decoder-only Transformer, nothing computed at the top of one token feeds the bottom of the next; tokens meet only through attention, so the deepest chain of computation behind any output stays 96 blocks, and the whole prompt runs in parallel. In the RLT reference layout (48 encoder + 48 decoder layers with shared weights), the encoder runs the prompt in parallel, but each token's decoder starts from the previous token's final decoder state, so the chain grows by 48 blocks per token, and the decoder has to walk the prompt one token at a time. From the {{RLT project page|https://yifanzhang-pro.github.io/recurrent-looped-tranformer/}} and {{MarkTechPost|https://www.marktechpost.com/2026/09/13/a-princeton-researcher-proposes-recurrent-looped-transformer-rlt/}}: the 48 + 48 tied layout, 96 logical blocks per token, a path of t x 48 decoder blocks after t tokens, the encoder batched over known tokens and the decoder updated in token order during prefill. Illustrative: eight tokens and rows of six layers; no trained 48 + 48 model exists (the experiments published on 17 to 20 September use untied 8- and 16-layer models). Derived: sequential layer steps = 96 for a Transformer prompt of any length (layers run one after another, tokens in parallel), 48 + 48 x P for RLT, counting one layer of one token as one step and ignoring how a GPU would overlap them.
