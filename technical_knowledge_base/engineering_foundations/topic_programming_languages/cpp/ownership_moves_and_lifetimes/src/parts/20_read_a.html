The idea in one sentenceEvery C++ object has exactly one lifetime, and it ends at a moment you can point to in the source: the closing brace of its scope, or the destruction of its owner; RAII ties resources to that moment, and moves hand an object's contents to a new owner instead of copying them, so ownership, not a garbage collector, decides when memory is freed.

Python counts references; C++ gives each object one owner and frees it at a known line

Left: in Python, a, b and a dict entry are three names for one heap object; it dies when its reference count reaches 0, at a time no line of your code names, and a cycle waits for the cycle collector. Right: in C++, v is the object: 24 bytes on the stack holding a pointer to its heap buffer, which it owns. A reference r only observes. At the closing brace v's destructor frees the buffer. Every section below is a variation on this picture: who the owner is, when it dies, and how ownership moves.

You need: how a C++ program is compiled and what undefined behaviour means ({{C++: the essentials|n:3cd5c17b0d0d81ceadcee44fe9c023a0}}). Python is the bridge throughout; nothing else is assumed.

Lifetime: from the end of an object's constructor to the start of its destructor.
Owner: the object whose destructor ends another object's lifetime (a vector owns its buffer).
RAII: "resource acquisition is initialisation": a resource is held by an object whose destructor releases it.
Stack unwinding: destroying the locals of every scope an exception leaves.
unique_ptr, shared_ptr, weak_ptr: one owner; counted owners; an observer of counted owners.
lvalue, rvalue: an expression with a name that will be used again; a temporary about to disappear.
Move: building an object by taking another's contents (its heap buffer) instead of copying them.
Copy elision: the compiler builds a returned object directly in the caller's variable: no copy, no move.
Special members: destructor, copy and move constructors, copy and move assignment.
