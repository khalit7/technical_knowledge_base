SIMD lanes

One block of 16 elements of the dot product from {{Reading, section 6|#t-cb-read}}, run the three ways the compiler and intrinsics produced (the inputs are the benchmark's first 16 values: a[i] = (i % 17) / 4, b[i] = (i % 13) / 2). Each step is one instruction or a group of instructions that run at the same time; the clock counts the cycles on the critical path, using the latencies measured by {{Dougall Johnson|https://dougallj.github.io/applecpu/firestorm-simd.html}} (4 cycles for fmadd, fmul and fmla; 3 for fadd and faddp).

Try: play "scalar", then "NEON" on the same 16 numbers, and compare the cycle counters. The answer is the same; the shape of the work is not.

Measured, all four ways

The cycle model counts only the dependency chain inside one block; in a long loop the loads and the next block's multiplies overlap with it, so the steady-state cost per element is the chain's step (4, 3 and 0.25 cycles). At 3.2 GHz that predicts 1.25, 0.94 and 0.078 ns per element, against the measured values in the table. Real values; illustrative only in that one block is shown.
