Python hides the machine. C++ hands it to you: the same loop can be 50 times faster or slower depending on where its data sits, how the compiler translated it and what other cores are doing. This part teaches what the processor and memory actually do, with every number measured on this laptop (an Apple M1 Pro, 8 performance cores and 2 efficiency cores, macOS 27) by small C++ programs you can read in full.

About 40 minutes. Every output block is the real output, recorded on 2026-10-05 with Apple clang 17 (and LLVM clang 23 for ThreadSanitizer); timings are the first of three runs, with the spread of all three given beside them. The laptop was in normal use (load average about 5 to 12 on 10 cores during the runs), so treat the second digit of any timing as noise. Sources and the scripts that reproduce everything: src/cb/ in the repository.

The bridge from Python
In Python, total += x inside a loop costs tens of nanoseconds whatever the data looks like, because the interpreter's own work dwarfs the memory access (the root page's {{Reading, section 2|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}} counts 29 bytecode instructions per character). Once a loop compiles to a handful of machine instructions, as in C++, Rust or inside NumPy, the memory system is what is left, and everything below starts to matter. That is also why numpy.sum on a contiguous array is fast and on a strided view can be much slower.
