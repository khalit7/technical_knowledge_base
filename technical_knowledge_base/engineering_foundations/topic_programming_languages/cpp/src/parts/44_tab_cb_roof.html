Roofline

The roofline of this M1 Pro's CPU, drawn from the peak arithmetic rate and memory bandwidth measured in {{Reading, section 9|#t-cb-read}}, with the measured kernels placed on it. Left of the ridge a kernel is limited by bytes (memory-bound), right of it by arithmetic (compute-bound).

Try: play the batch sweep: the same LLM decode step, with more and more sequences sharing each weight read, moves from the memory roof to the compute roof. Change the weight format to see quantisation shift the point left or right, and the model size to see the token-rate ceilings.

I = 2B / w    tokens/s ≤ B / max( P·w / bandwidth , 2·P·B / peak )
B
sequences decoded together (batch)
w
bytes per weight
P
parameters; each is read once per step and used for one multiply-add (2 FLOPs) per sequence

Measured: roofs, and the matvec, matmul and dot product points (run 1; three runs in the Reading's table). Illustrative: the LLM decode point, which counts only weight traffic and the matrix multiplies, ignoring the KV cache, activations and attention (they add bytes, so real ceilings are lower), and assumes the measured bandwidth and peak are reachable together; for q8_0 and q4_0 the arithmetic is still counted as float multiply-adds, although real quantised kernels also spend work unpacking the blocks. It is a bound, not a prediction; {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}} owns the full accounting, and real speeds belong to llama.cpp's own benchmark in {{Part 3|#t-cl-read}}.
