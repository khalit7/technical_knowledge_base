The surprise of this tour
Guides (and this page's own root) say: to see the hot loop, read ggml_vec_dot_q4_0_q8_0 or ggml_vec_dot_q8_0_q8_0. On this M1 with the default build, call counters show those functions run zero times: the weights are rearranged at load time and a different kernel, ggml_gemv_q8_0_4x4_q8_0, does all matrix products of each new token, in calls (section 10). Reading code is not enough; check what runs.

1. The map: what is where

A new codebase of a million lines is read like a city: first the districts, then one street. llama.cpp has two libraries and a ring of programs around them.

  • ggml/, the tensor library. Tensors, the compute graph, the file format, and one backend per kind of hardware (a backend is the code that runs operations on one device: CPU, Metal for Apple GPUs, CUDA for NVIDIA, Vulkan and others). Its core is C; most backends are C++ (Metal adds Objective-C and Metal shading language, CUDA adds .cu files).
  • src/, libllama. Everything that knows what an LLM is: loading a model file, one graph builder per architecture in src/models/, the KV cache, batches, the tokenizer, samplers. All C++.
  • include/llama.h, the public C API (1,774 lines). Every program, and every binding from Python, Go or Swift, goes through it.
  • common/ (argument parsing, chat templates, helpers shared by the tools), tools/ (llama-cli, llama-server, llama-bench, llama-quantize), examples/ (small programs; simple/simple.cpp is the one to read first), gguf-py/ (the Python package that writes model files), tests/ and vendor/ (third-party code such as the HTTP library).
Lines per area, counted with git ls-files at the pinned commit (src/cl/code/repo_map.py). Hover or tap a bar.

Of lines, are C++ and C, plus headers shared by both. The CPU backend alone is lines, mostly hand-vectorised kernels for each processor family; you will read about 200 of them.

From Python
It is the same shape as PyTorch: a Python API (torch/) over a C++ tensor library (ATen) with one backend per device. Here the "Python API" is the C header llama.h, and the tensor library is ggml. The Python package llama-cpp-python wraps exactly that header with ctypes.

How to read it. Start from the smallest program that works (examples/simple/simple.cpp), follow each call one level down with grep -rn "name(" src ggml, and skip every backend you are not running. Read declarations in headers before definitions. When a log line puzzles you, grep for its text: the code that printed it is the explanation (we do this in section 5).

2. Building it

llama.cpp builds with CMake, the build system Part 1 introduced ({{Build pipeline|#t-ca-build}} tab). CMake reads CMakeLists.txt files, asks questions about the machine (which compiler, is the Accelerate framework there, is Metal there), and writes a build plan for Ninja, which runs the compiler in parallel. The choices are option() lines; each backend is one:



What the configure step found, and what the build produced (real output, filtered to the interesting lines):




Read the output like this. OpenMP not found: Apple's clang ships without OpenMP, so ggml falls back to its own thread pool (the one we read in section 9). Accelerate, Apple's BLAS library, became a backend of its own; it only takes matrix products where every side is at least 32 long (a long prompt, not one token), converting the weights to float first. Metal is on by default on Apple machines. Each backend became its own shared library (libggml-cpu.dylib, libggml-metal.dylib, libggml-blas.dylib), linked together by libggml.dylib, which keeps the list of available backends; libllama.dylib sits on top.
