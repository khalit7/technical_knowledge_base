Cache simulator

The same loop, stepped one memory access at a time, over two layouts of the same data. Each row of the grid is one 128-byte cache line, cut into 32 slots of 4 bytes. A line turns solid when it is fetched from memory; a slot is outlined when the loop actually uses it. The counters compare bytes moved with bytes used. Sections 2 and 3 of the {{Reading|#t-cb-read}} measured the real programs; this view shows why.

Try: run "Sum one field" with AoS, then switch to SoA (same loop, same 64 records): watch how many lines each needs. Then compare a matrix walked by rows and by columns with a cache that holds only 8 lines.

Illustrative model: an exact count of the lines one loop touches, with a cache of 8 lines that evicts the least recently used one (the real L1 holds 1,024 lines of 128 bytes, L2 about 98,000; the matrix here is shrunk to 16 rows of 32 integers so that its rows overflow 8 lines just as a 4096 x 4096 matrix overflows L1 and L2). No prefetching is modelled. The measured ratios under the counters are the real programs' results.
