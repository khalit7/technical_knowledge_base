14. Modern C++: where C++20, C++23 and C++26 stand (October 2026)

C++ is standardised by an ISO committee (WG21) on a three-year train: C++11, 14, 17, 20, 23, 26. Nothing old is removed, so "modern C++" is a subset you choose to write, the one this part teaches. Each compiler and standard library implements each standard gradually, and the two can differ: a feature needs both.

Ask for a standard, always

The default language version differs between compilers and even versions of one compiler. Measured here:

[[out:l_std_default]]

(199711L is C++98, 201402L C++14, 201703L C++17.) Elsewhere: GCC 16 (released 2026-04-30) is the first major compiler to default to C++20 ({{GCC 16 changes|https://gcc.gnu.org/gcc-16/changes.html}}); upstream Clang has defaulted to C++17 since Clang 16 ({{Clang status|https://clang.llvm.org/cxx_status.html}}); MSVC still defaults to C++14 ({{/std|https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version}}). So pass -std=c++20 or newer, or in CMake target_compile_features(t PUBLIC cxx_std_20).

Modules replace textual #include with compiled interfaces (import std;), attacking the 55,000-line problem of section 1. The language feature is in C++20 and import std in C++23, but tooling still lags: GCC 16's notes say modules support "is still experimental and must be enabled by -fmodules", and CMake supports named modules since 3.28 but import std only behind an experimental gate ({{cmake-cxxmodules|https://cmake.org/cmake/help/latest/manual/cmake-cxxmodules.7.html}}). Headers remain the pragmatic default in 2026; llama.cpp uses them.

Corrections to the old "C++: modern practice and standards status" page
  • "C++26 was finalized in March 2026": the technical work finished on 2026-03-28 in London (Croydon); then comes the international ballot (DIS) and ISO publication, which was not confirmed as of 2026-10-05.
  • "C++20 is the production baseline nearly everywhere": as a target, yes; as a default, no. Only GCC 16 defaults to C++20; Clang defaults to C++17, MSVC to C++14, and Apple clang 17 here to C++14 (measured above).
  • "MSVC completes /std:c++23 with Build Tools 14.52": not yet true. The current release is 14.51 in Visual Studio 2026 18.10.3 (2026-09-29) and Microsoft's documentation still lists /std:c++23preview (root page, Toolchain atlas corrections).
  • "Pattern matching did NOT make it": confirmed in the sense that cppreference's C++26 feature list has no pattern matching.
  • The old list of C++26 features is otherwise right; this page adds hardening and erroneous behaviour, the two that change day-to-day safety.

15. Mistakes that catch experienced people, and a hygiene checklist

Each of these compiles. Most were shown above; the ones marked "gallery" crash or misbehave in the {{UB gallery|#t-ca-ub}}.

A string_view, span or range view that outlives its owner
Views do not own. Initialising one from a temporary dangles at the semicolon (gallery). Range-for over a member of a temporary, for (auto& x : make().items()), dangled until C++23 extended the lifetime of every temporary in the range-for initializer ({{P2718|https://wg21.link/P2718}}); the same expression outside a range-for still dangles, so the old page's "fixed for some cases in C++23, not all" stands.
A reference, pointer or iterator into a vector, kept across push_back
Growth reallocates and frees the old buffer (section 9; gallery). Use indices, or reserve first.
Slicing a derived object into a base by value
Section 7. Pass polymorphic objects by reference or pointer.
A public non-virtual destructor in a base class used through pointers
Only the base part is destroyed (section 7).
Static initialisation order across files
Globals in different .cpp files are initialised in an unspecified order; one global's constructor that uses another may see it unconstructed. Use a function returning a reference to a function-local static, which is initialised on first use.
Unsigned arithmetic going below zero: for (size_t i = v.size() - 1; i >= 0; --i)
size_t is unsigned: i >= 0 is always true and 0 - 1 wraps to 18,446,744,073,709,551,615. An empty vector makes even the first value huge. Mixing signed and unsigned in a comparison converts the signed side to unsigned (clang warns with -Wextra).
Treating a data race as "sometimes a wrong value"
It is UB. The gallery's race printed [[g:ub_race_O0|counter = (\d+)]] instead of 2000000 at -O0 and the right answer at -O2 (the optimiser turned the loop into one addition), so a test at -O2 passes. Use std::atomic or a mutex; {{Part 2|#t-cb-read}} covers the memory model.
shared_ptr by reflex
Cycles leak; atomic counting slows single-threaded paths; ownership becomes unclear. unique_ptr first.
Using an object after std::move
Valid but unspecified (section 6). Assign to it or let it die.

Hygiene checklist

  • RAII everywhere; no naked new/delete; unique_ptr by default.
  • Rule of zero; if you must write one special member, write all five, with noexcept moves.
  • Parameters: string_view and span<const T> to read; never store them past the call without thought.
  • const by default; constexpr where a value can be computed at compile time.
  • auto for iterators, lambdas and long type names; concrete types at API boundaries.
  • Build with -std=c++20 or newer and -Wall -Wextra (-Werror in CI); ASan, UBSan and TSan in CI test runs; clang-format and clang-tidy; CMake targets with PUBLIC/PRIVATE properties, presets, and vcpkg or Conan.
