4. Pages and mmap, as a C++ program meets them

Addresses are virtual, mapped one page at a time; on Apple silicon a page is 16 KB (hw.pagesize printed 16384; 4 KB on most Linux machines). The mechanism (page tables, the TLB, page faults, the page cache) belongs to {{Virtual memory|n:3f05c17b0d0d81a48892cea154ce950b}}. Two consequences for C++ code, measured here: new of a big block only reserves addresses, and the first touch of each page is a page fault costing about microseconds (three runs: ); and mmap of a 512 MB file took ms whatever its size, with pages read only when touched. That is why llama.cpp maps model files: loading is nearly instant, processes running the same model share the physical pages, and a restart finds the weights still cached ({{Local and on-device inference|n:3c65c17b0d0d81f7a144fe25d799e811}} measures it for safetensors and GGUF).

5. The compiler's view: reading assembly


Clang (via LLVM) translates C++ into machine code; assembly is its readable text. Reading a little of it is the only reliable way to know what your C++ became: clang++ -O2 -S file.cpp -o -, or {{Compiler Explorer (godbolt.org)|https://godbolt.org/}}, which colours each source line and its instructions alike.




Predict. At -O2, how many times does sum_squares(1000) call square? How many times does its loop run?











Three transformations decide whether an abstraction is free:


    

  • Inlining: copying a small function's body into its caller, removing the call and letting the optimiser see through it. It is why small functions, lambdas and templates cost nothing, and it needs the body to be visible: same file, a header, or link-time optimisation (-flto).
    • 

  • Devirtualisation: a virtual call loads the object's vtable pointer, loads the function's address from it and jumps there, which also blocks inlining. When the compiler can prove the exact type (here the class is final), it calls or inlines directly. ({{C++: classes, templates and the standard library|n:4055c17b0d0d818a9509f6035089a7e1}} measures what dispatch costs.)
    • 

  • Vectorisation: processing several elements per instruction (next section). Clang reports its decisions with -Rpass=loop-vectorize (done), -Rpass-missed=loop-vectorize (refused) and -Rpass-analysis=loop-vectorize (why) ({{LLVM vectoriser docs|https://llvm.org/docs/Vectorizers.html}}).
    •

ARM64 assembly in two minutes: registers, the calling convention, the instructions you will meet


This laptop runs ARM64 (AArch64). Each line is one instruction, written operation destination, source, source:


You seeIt means


x0 .. x30, w0 .. w30The 64-bit general registers; w is the low 32 bits of the same register. sp is the stack pointer.


s0, d0, q0, v0.4sThe SIMD and float registers: one 32-bit float, one 64-bit double, the whole 128 bits, or the 128 bits seen as 4 floats ("4s" means 4 single-precision lanes; Apple's assembler prints fmla.4s).


arguments and resultBy the calling convention ({{AAPCS64|https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst}}), the first 8 integer or pointer arguments arrive in x0..x7, float ones in v0..v7, and the result goes back in x0 or s0/d0.


ldr, str, ldpLoad a register from memory, store it, load a pair. [x0, #8] is "the address in x0 plus 8"; [x0], #4 loads then adds 4 to x0.


add, mul, madd, fadd, fmadd, fmlaInteger and float arithmetic; fmadd/fmla are fused multiply-add (a + b x c in one instruction, one rounding).


cmp, subs, b.ne, b.lt, cbz, tbzCompare (set flags), then branch if not equal, less than, if zero, if a bit is zero. A loop ends with one of these jumping back to its label.


bl, br, retCall a function, jump to an address held in a register, return.
