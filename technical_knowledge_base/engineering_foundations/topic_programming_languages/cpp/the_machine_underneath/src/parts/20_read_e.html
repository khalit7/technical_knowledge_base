6. SIMD: one instruction, several numbers

SIMD (single instruction, multiple data) applies one operation to a short vector held in one wide register. On ARM it is NEON: 32 registers of 128 bits, each 4 floats, 8 16-bit values or 16 bytes; fmla v0.4s, v1.4s, v2.4s does four multiply-adds at once. On x86 the same ideas are SSE (128 bits), AVX2 (256 bits: 8 floats) and AVX-512 (16 floats), with intrinsics such as _mm256_fmadd_ps ({{Intel intrinsics guide|https://www.intel.com/content/www/us/en/docs/intrinsics-guide/index.html}}). This M1 Pro also reports the 8-bit dot-product extension (FEAT_DotProd: 1) but not BF16, I8MM or SME (all 0 in sysctl); llama.cpp's quantised kernels check for exactly these features.

Three ways to get SIMD code: let the compiler vectorise a plain loop, write intrinsics (C functions that map one to one onto SIMD instructions, from <arm_neon.h>; {{Arm intrinsics reference|https://developer.arm.com/architectures/instruction-sets/intrinsics/}}), or call a library that did (BLAS, Accelerate, ggml). 7. Branch prediction


A core works on hundreds of instructions at once in a pipeline. At an if it cannot wait to learn which way to go, so a branch predictor guesses from the branch's history and the core runs ahead on the guess. A right guess is free; a misprediction throws away the work on the wrong path. The test counts and sums the bytes that are at least 128 in 32 million random bytes, then the same bytes sorted:
