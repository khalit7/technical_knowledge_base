C++: classes, templates and the standard library

Classes and virtual functions, templates and concepts, the containers and ranges you will use, lambdas, and errors with exceptions against std::expected; what run-time dispatch and exceptions cost, measured on an Apple M1 Pro. Reading: 22 min, plus 17 in closed details. Data as of October 2026.
The idea in one sentenceC++ resolves an abstraction at compile time whenever the compiler can see the type (templates, overloads, lambdas, final classes), so it costs nothing; only when you ask for run-time dispatch (virtual functions, std::function, std::variant) does a call wait to learn the type, and the measured cost of that is about 1 ns when the type is predictable and about 6 ns when it is not, while an exception costs nothing until it is thrown and then about 5 µs.

1. Classes: Python's conventions, checked by the compiler

A class and a struct are the same thing except for the default: struct members are public, class members private. What Python leaves to convention, C++ checks: private really is private, a const method really cannot modify the object, and members are declared with their types. One class shows most of it:

classes.cpp (lines 5 to 23)
class Usage {
public:
    // explicit: no silent conversion from a string to a Usage
    explicit Usage(std::string user, long tokens = 0)
        : user_(std::move(user)), tokens_(tokens) {}   // member initialiser list

    const std::string& user() const { return user_; } // const: does not modify *this
    long tokens() const { return tokens_; }

    Usage& operator+=(long n) { tokens_ += n; return *this; }
    // one line gives ==, !=, <, <=, >, >= comparing members in declaration order
    auto operator<=>(const Usage&) const = default;

private:
    std::string user_;
    long tokens_;
};

Usage operator+(Usage u, long n) { u += n; return u; }
  • Member initialiser list (: user_(...), tokens_(...)): members are constructed there, before the body runs, in the order they are declared in the class, not the order you list them (clang warns when they differ).
  • explicit forbids using a one-argument constructor as a silent conversion. Without it, any function taking a Usage would accept a std::string and build a Usage behind your back. With it, that call is an error.
  • Operators are ordinary functions with special names, like Python's __iadd__ and __add__. operator<=> = default (C++20, the "spaceship") generates all six comparisons member by member, like @dataclass(order=True).

2. Virtual functions, and what dispatch really costs

A virtual function is chosen at run time by the object's actual class, like every method call in Python. A non-virtual one is chosen at compile time by the declared type, and can be inlined. = 0 makes a function pure virtual: the class is abstract, like a Python ABC, and override makes the compiler check that you really override something. The price is visible in the object itself:

A virtual function adds one hidden pointer to every object

Plain { double; f() }: 8 bytes

p.f() is a direct call to Plain::f, known when compiling
Virtual { double; virtual f() }: 16 bytes

double8 B
↓ vptr points at the class's vtable (one per class, shared)

p->f(): load the vptr from the object, load the address of f from the table, jump there

Sizes printed by sizeof on this Mac. The vtable layout is simplified (it also holds type information for dynamic_cast); the real loads are read in the assembly on C++: the machine underneath, section 5.

A base class with a virtual function, two implementations, one loop
virtual.cpp
#include <cstdio>
#include <memory>
#include <string>
#include <vector>

struct Tokenizer {                       // a base class with a virtual function
    virtual int count(const std::string& s) const = 0;   // = 0: must be overridden
    virtual ~Tokenizer() = default;      // virtual destructor: required for delete via base
};
struct Whitespace : Tokenizer {
    int count(const std::string& s) const override {
        int n = 0; bool in = false;
        for (char c : s) { bool t = c != ' '; n += t && !in; in = t; }
        return n;
    }
};
struct Bytes : Tokenizer {
    int count(const std::string& s) const override { return static_cast<int>(s.size()); }
};

int main() {
    std::vector<std::unique_ptr<Tokenizer>> ts;
    ts.push_back(std::make_unique<Whitespace>());
    ts.push_back(std::make_unique<Bytes>());
    for (const auto& t : ts)             // which count() runs is decided at run time
        std::printf("%d\n", t->count("hello token world"));
}

Measured: one sum, eight ways of calling

Two loads and an indirect jump sound slow. Whether they are depends on something else: a modern CPU does not wait to learn where a jump goes; its branch predictor guesses and runs ahead, and only a wrong guess costs (the mechanism, and about 6 ns per mispredicted if on this M1, are on the machine page, section 7). So the benchmark sums the areas of 10 million shapes eight ways, with the same arithmetic in each, and varies two things: whether the class changes unpredictably from one object to the next, and whether the objects sit next to each other in memory.

Predict, then switch: which is slower, a virtual call when every object has the same class, or a std::variant visit (no pointers, no vtable) over three classes in random order? Then switch to scattered objects: does the virtual call still matter?

ns per object, log scale; the median of three runs, with the range of the three under each label. Rows marked "flat" store the objects inside the vector, so they have no scattered version. 10 million objects, each pass visits every object once, best of 7 passes; Apple M1 Pro, Apple clang 17, -O2.

Three things show, and they are the practical rules:

  1. A predictable virtual call is cheap. One class: 0.98 ns per object, against 0.61 for a plain inlinable call through the same kind of pointer and 0.32 for plain structs stored flat. Much of the gap is probably not the jump itself but what it forbids: the compiler cannot inline a function it cannot name, so it cannot vectorise the loop or keep values in registers across the call.
  2. An unpredictable type is what costs, whatever the mechanism. Three classes in random order: virtual 6.31 ns, std::function 6.01, std::variant 5.56. The variant has no pointer and no vtable, but visit still branches on the stored type, and with three types in random order no predictor can guess that branch right more than about one time in three. The same objects visited sorted by class: 1.01 ns. Sorting by type, or keeping one vector per type, removes most of the cost.
  3. When the data is scattered, memory dominates. With the objects allocated in shuffled order every row through a pointer costs 5 to 17 ns: a cache miss per object. The plain call pays 4.97 ns, the predictable virtual call 9.35 (the jump's target depends on the loaded vptr, so fewer misses overlap), the mixed one 16.79. Flat storage, at 0.32, beats every pointer layout by more than any dispatch choice.

A few nanoseconds per call is nothing for a call per request and a lot for a call per element of a tensor. That is why performance code uses templates (section 3) instead of virtual functions in hot loops, keeps data in flat arrays, and keeps virtual interfaces for coarse-grained choices. llama.cpp does exactly this: its KV cache is a class hierarchy with virtual functions, called a few times per token, while its kernels are templates and plain functions (C++: reading llama.cpp).

final tells the compiler no class derives from this one, so a call through a SqFinal* needs no vtable: it measured 0.44 ns, an inlined call. The compiler devirtualises on its own whenever it can prove the exact class (a local object, a final class, link-time optimisation that sees every derived class).

The benchmark (dispatch.cpp), all three runs, and the C++ page's original measurement reproduced

Each row builds its own vector of 10 million objects, sums their areas seven times and keeps the fastest pass. "Scattered" allocates the same objects in a shuffled order, so the visiting order (and so the sequence of classes) is identical and only the addresses differ. The in-order rows through pointers (0.4 to 1.0 ns) vary from run to run by as much as they differ from each other: read them as "about a nanosecond", not as a ranking.

dispatch.cpp
// What a call costs, by how it is dispatched: the same "sum of areas" over 10 million shapes,
// written eight ways. Each pass visits every object once (no repeated pattern for the branch
// predictor to learn). Objects behind pointers are measured twice: in allocation order (the
// heap hands out neighbouring addresses) and allocated in a shuffled order (scattered in memory).
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <functional>
#include <memory>
#include <random>
#include <variant>
#include <vector>

// Run-time polymorphism: a base class with a virtual function
struct Shape { virtual long area() const = 0; virtual ~Shape() = default; };
struct Sq   : Shape { long a;    explicit Sq(long x) : a(x) {}             long area() const override { return a * a; } };
struct Rect : Shape { long a, b; Rect(long x, long y) : a(x), b(y) {}      long area() const override { return a * b; } };
struct Tri  : Shape { long a, b; Tri(long x, long y) : a(x), b(y) {}       long area() const override { return a * b / 2; } };
struct SqFinal final : Shape { long a; explicit SqFinal(long x) : a(x) {}  long area() const override { return a * a; } };

// Compile-time alternatives: plain structs, and a closed set of types in a std::variant
struct PSq   { long a;    long area() const { return a * a; } };
struct PRect { long a, b; long area() const { return a * b; } };
struct PTri  { long a, b; long area() const { return a * b / 2; } };
using AnyShape = std::variant<PSq, PRect, PTri>;

const int N = 10'000'000;
volatile long sink;

template <class F> double best_ns(F pass) {
    double best = 1e18;
    for (int r = 0; r < 7; ++r) {
        auto t0 = std::chrono::steady_clock::now();
        pass();
        double ns = std::chrono::duration<double, std::nano>(std::chrono::steady_clock::now() - t0).count() / N;
        if (ns < best) best = ns;
    }
    return best;
}
template <class V> double sum_ptrs(const V& v) { return best_ns([&] { long s = 0; for (auto& p : v) s += p->area(); sink = s; }); }

std::vector<int> kind(N), xs(N), ys(N);

// A row for objects behind pointers. Position k of the vector is always visited k-th, so the order of
// classes is the same in both columns; only the allocation order differs. Allocated in visiting order,
// neighbours get neighbouring addresses; allocated in a shuffled order, they are scattered.
template <class Create> double ptr_pass(Create create, bool scatter) {
    std::vector<int> order(N);
    for (int i = 0; i < N; ++i) order[i] = i;
    if (scatter) std::shuffle(order.begin(), order.end(), std::mt19937(1));
    std::vector<decltype(create(0))> v(N);
    for (int k : order) v[k] = create(k);
    return sum_ptrs(v);
}
template <class Create> void ptr_row(const char* label, Create create) {
    double in_order = ptr_pass(create, false);
    double scattered = ptr_pass(create, true);
    std::printf("  %-28s %6.2f %10.2f\n", label, in_order, scattered);
}
void flat_row(const char* label, double t) { std::printf("  %-28s %6.2f %10s\n", label, t, "(flat)"); }

int main() {
    std::mt19937 rng(42);
    for (int i = 0; i < N; ++i) { kind[i] = rng() % 3; xs[i] = 1 + rng() % 7; ys[i] = 1 + rng() % 7; }
    auto mixed = [](int i) -> std::unique_ptr<Shape> {
        if (kind[i] == 0) return std::make_unique<Sq>(xs[i]);
        if (kind[i] == 1) return std::make_unique<Rect>(xs[i], ys[i]);
        return std::make_unique<Tri>(xs[i], ys[i]);
    };
    std::printf("10 million objects, one pass each, best of 7: ns per object\n");
    std::printf("  %-28s %6s %10s\n", "dispatch", "order", "scattered");
    std::vector<int> by_class(N);   // visiting order for row 3: positions sorted by class
    for (int i = 0; i < N; ++i) by_class[i] = i;
    std::stable_sort(by_class.begin(), by_class.end(), [](int a, int b) { return kind[a] < kind[b]; });
    // 1. virtual call, one class only: the target never changes, so the predictor gets it right
    ptr_row("virtual, one class", [](int k) -> std::unique_ptr<Shape> { return std::make_unique<Sq>(xs[k]); });
    // 2. virtual call, three classes in random order: the target is unpredictable
    ptr_row("virtual, 3 classes mixed", [&](int k) { return mixed(k); });
    // 3. the same objects, visited sorted by class: predictable again
    ptr_row("virtual, 3 classes sorted", [&](int k) { return mixed(by_class[k]); });
    // 4. final class, called through its own type: the compiler devirtualises and inlines
    ptr_row("final class, devirtualised", [](int k) { return std::make_unique<SqFinal>(xs[k]); });
    // 5. plain struct behind a pointer: an ordinary, inlinable call, no vtable
    ptr_row("plain struct, pointers", [](int k) { return std::make_unique<PSq>(PSq{xs[k]}); });
    {   // 6. std::function per element: type-erased (small lambdas stored inside it), an indirect call
        std::vector<std::function<long()>> v;
        for (int i = 0; i < N; ++i) {
            long a = xs[i], b = ys[i];
            if (kind[i] == 0) v.push_back([a] { return a * a; });
            else if (kind[i] == 1) v.push_back([a, b] { return a * b; });
            else v.push_back([a, b] { return a * b / 2; });
        }
        flat_row("std::function, 3 mixed", best_ns([&] { long s = 0; for (auto& f : v) s += f(); sink = s; }));
    }
    {   // 7. std::variant in a flat vector, std::visit: a closed set of types, no heap, no vtable
        std::vector<AnyShape> v;
        for (int i = 0; i < N; ++i) {
            if (kind[i] == 0) v.push_back(PSq{xs[i]});
            else if (kind[i] == 1) v.push_back(PRect{xs[i], ys[i]});
            else v.push_back(PTri{xs[i], ys[i]});
        }
        flat_row("variant + visit, 3 mixed", best_ns([&] { long s = 0;
            for (auto& x : v) s += std::visit([](const auto& sh) { return sh.area(); }, x); sink = s; }));
    }
    {   // 8. plain structs in a flat vector: what a template over a known type compiles to
        std::vector<PSq> v;
        for (int i = 0; i < N; ++i) v.push_back(PSq{xs[i]});
        flat_row("plain struct, flat vector", best_ns([&] { long s = 0; for (auto& q : v) s += q.area(); sink = s; }));
    }
}

Two inheritance traps, both silent

Slicing: passing a Derived by value as a Base copies only the base part; the copy forgets it was a Derived. Pass polymorphic objects by reference or pointer. Non-virtual destructor: deleting a Derived through a Base* ran only ~Base, so the 400-byte buffer leaked; formally it is undefined behaviour. A base class meant for polymorphic use needs virtual ~Base() = default;.

3. Templates and concepts: generic code resolved at compile time

A Python function accepts anything with the right methods (duck typing), checked when the line runs. A C++ template is a pattern from which the compiler writes a separate function or class for each type you use it with (instantiation, or monomorphisation), checked at compile time. Each generated function is as fast as if you had written it by hand: no boxing, no dispatch, and the compiler can inline and vectorise it. That is the "decided at compile time" lane of the hero.

templates.cpp (lines 5 to 14)
// One template, many functions: the compiler writes a copy per type used.
template <typename T>
T total(const std::vector<T>& xs) {
    T sum{};
    for (const T& x : xs) sum += x;
    return sum;
}

template <typename K, typename V>
struct Pair { K key; V value; };       // a class template

4. The standard library you will actually use

The standard library ("the STL") is C++'s built-ins plus collections and itertools. On macOS it is LLVM's libc++; on Linux usually GCC's libstdc++; on Windows Microsoft's STL. The interfaces are standard; the sizes, growth factors and string buffers below are libc++'s, measured. The defaults: vector, string, unordered_map; string_view and span as parameters; algorithms over hand-written loops.

std::vector: one buffer that moves when it grows

A growable array, like a Python list, except that it holds the elements themselves, contiguously, not pointers to objects; that is why section 2's flat vector beat every pointer layout. Use it unless you have measured a reason not to. Growth is geometric, so push_back is cheap on average:

Capacity doubles; each step is a new buffer, and every old pointer into the vector dangles

The real output of vector_growth.cpp (libc++): the size at which each new buffer was allocated, and its capacity. At every step all elements move to the new buffer and the old one is freed, so every pointer, reference and iterator into the old buffer now dangles (the essentials page's UB gallery runs that bug). If you know the final size, call reserve(n) first: one allocation, no moves. Whether the elements are moved or copied at each step depends on noexcept, replayed on the ownership page.

6. Errors: exceptions against std::expected, measured


C++ has three ways to say "this did not work", and real code uses all three:


    

  • Exceptions work like Python's: throw, try/catch, unwinding that runs destructors on the way (the ownership page replays it). Use them for errors the immediate caller cannot handle: a missing config file, out of memory.
    • 

  • std::optional<T> (C++17) is "a T or nothing", like returning None, with no reason attached.
    • 

  • std::expected<T, E> (C++23) is "a T or an error E", like Rust's Result. The caller must look; transform and and_then chain steps that run only on success. Use it for failures that are part of normal operation: parsing user input, a malformed JSONL line.
    •

// 3. expected (C++23): "a value or an error", like Rust's Result
enum class ParseError { empty, not_a_number };
std::expected<long, ParseError> parse_exp(std::string_view s) {
    if (s.empty()) return std::unexpected(ParseError::empty);
    long v = 0;
    auto [p, ec] = std::from_chars(s.data(), s.data() + s.size(), v);
    if (ec != std::errc{} || p != s.data() + s.size()) return std::unexpected(ParseError::not_a_number);
    return v;
}

__attribute__((noinline)) int f_throw(int i) { if (i < 0) throw std::runtime_error("neg"); return i; }
__attribute__((noinline)) std::expected<int, int> f_exp(int i) { if (i < 0) return std::unexpected(1); return i; }

// The error crosses `d` frames: each level calls the next; only the top handles it.
// The empty asm after each call keeps every frame real (clang would otherwise turn the recursion into a loop).
__attribute__((noinline)) int deep_throw(int d, int i) {
    if (d == 0) return f_throw(i);
    int r = deep_throw(d - 1, i);
    asm volatile("");
    return r + 1;
}
__attribute__((noinline)) std::expected<int, int> deep_exp(int d, int i) {
    if (d == 0) return f_exp(i);
    auto r = deep_exp(d - 1, i);
    asm volatile("");
    if (!r) return r;            // every level checks and passes the error up
    return *r + 1;
}

Not measured here: throwing from several threads at once (some unwinders take a global lock; macOS's libunwind was not tested), and the binary-size cost of the unwind tables.




Some codebases (game engines, parts of Google's, many embedded ones) compile with exceptions turned off, and ggml, the C core under llama.cpp, reports errors with return values and assertions, since C has no exceptions. Mark functions that never throw noexcept, above all move constructors and destructors (the ownership page shows why a vector needs it), and add [[nodiscard]] to a function returning expected, so ignoring the result is a warning.


Rule of thumbExceptional and far away: throw. Expected and handled by the caller: std::expected. "Not found": std::optional.
What it costsExceptions: about 5.8 µs per throw plus 712 ns per frame, nothing otherwise. expected: a returned value, about 1 ns.
Common mistakesExceptions as control flow in a hot loop; throwing from a destructor; ignoring an expected.
