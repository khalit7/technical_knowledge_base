The four languages on one map

A programming language is a set of decisions about what the machine should do for you and what you must do yourself, and each of these four moved one kind of mistake to a different moment: Python finds it while the program runs and tells you clearly; C++ trusts you and may give no signal at all (undefined behaviour); Rust refuses to compile until it can prove a whole class of mistakes absent; TypeScript checks while you edit, then removes every check before the code runs.

The rows across the lanes are the moments a mistake can meet: while you edit, when it compiles, when it runs, and no signal at all.   2. Where each language catches a mistake. The same bug (red) runs down each lane until something stops it. TypeScript, while you edit: tsc refuses wrong types, missing fields, values that may be absent; then the types are erased. Rust, when it compiles: no program is produced until types, ownership, borrowing, data races and unhandled cases pass. Python, when it runs: every operation checked, an exception at the line that did it. C++ compiles types, missing functions and template constraints, not memory or races: out of bounds, use after free, signed overflow and data races are undefined behaviour, and the program carries on, possibly wrong. Dashed: each lane's weaker moment (Python only if you annotate and run mypy, pyright or ty; Rust a panic for bounds, failed unwrap, overflow in debug builds; wrong types from JSON.parse pass in TypeScript, and undefined + 1 is NaN). Sections 3, 6 and 10.
  3. How code runs. CPython compiles to bytecode that a loop in C interprets, 29 bytecode instructions per character of the token loop; clang and rustc hand the code to LLVM, which emits 16 and 17 machine instructions per byte, then a SIMD loop over 8 and 32 bytes at a time; tsc erases the types and V8 interprets the JavaScript, then JIT-compiles the hot function after watching its types. Section 2 steps through the real output.
  4. Who frees memory. CPython counts references on every object and frees each at its last reference; C++ runs destructors at the closing brace (RAII), and you must get it right; Rust frees at the owner's closing brace, with every borrow checked by the compiler; V8's tracing garbage collector frees later. Python's records are scattered objects, C++'s and Rust's sit side by side: summing 10 million records took ns per record from a Python list and ns from a C++ vector (measured, section 5).
  5. Threads. Four threads each add 1 to one counter a million times. Python with the GIL got 4,000,000; C++ at -O0 got 1,014,609, a data race and so undefined behaviour; Rust refused the program (E0499), and its Arc<Mutex> version got 4,000,000; JavaScript's four async tasks share one thread and its event loop, and got 4,000,000 (measured, section 9).
  6. One task, measured. The running program on a 200,000-line log, median wall time: Python 3.14 , C++ , Rust , TypeScript on Node (measured, Apple M1 Pro). Section 12 and the {{Benchmark|#t-bench}} tab say where each gap comes from.

Each section below is one axis of this map, shown on the same small program in all four languages. Most of what feels strange in a new language is that language catching, at its moment, a mistake Python would have caught at a different one.

You need: everyday Python; every other term is defined where it first appears. Python is the reference column everywhere: each axis shows what Python does, then what the others make you do instead, and why.

New terms

Founding value: the goal a language's designers kept when two goals conflicted (section 1)
Ahead-of-time, bytecode, JIT: the three routes from source to machine code (section 2)
Static, dynamic, gradual typing: types checked before running, while running, or where annotated (section 3)
Ownership, borrow: Rust's one owner per value and its checked loans (sections 4 and 5)
RAII: a destructor frees what an object owns when it goes out of scope (section 5)
Undefined behaviour: an operation C++ gives no meaning to; the compiler may assume it never happens (section 10)
GIL, event loop: CPython's one-thread-at-a-time lock, and JavaScript's one-thread scheduler (section 9)
Extension module: a compiled library CPython imports like a module (section 12)

How this page was made, and why it ends each section with false friends (optional)

Every code snippet on this page was run for it, and every output and compiler message is the real text (toolchains: ). C++ examples were compiled with Apple clang 17 from the Command Line Tools (the macOS 26 SDK, which has C++23's <expected>); sanitizer runs used LLVM clang 23.1.2, because Apple's sanitizer runtimes do not start on macOS 27. The Benchmark and Rosetta tabs used this Mac's older Apple clang 14. Numbers marked measured were measured for this page on one laptop; illustrative marks a picture that shows a shape rather than data.

Research on experienced programmers learning a second language found that they learn by mapping onto what they already know, and that most of their trouble comes from the places where the mapping silently breaks: in 450 Stack Overflow questions across 18 languages the authors found 276 instances of interference from a faulty assumption carried over from another language, and interviews showed programmers "make failed attempts to relate a new programming language with what they already know" ({{Shrestha, Botta, Barik and Parnin, ICSE 2020|https://doi.org/10.1145/3377811.3380352}}). So each section keeps a closed false friends box: things that look like Python and are not.
