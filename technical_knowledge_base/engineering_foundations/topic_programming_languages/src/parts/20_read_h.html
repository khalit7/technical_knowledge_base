10. Safety and undefined behaviour

A language is memory-safe if no program written in it can read or write memory it does not own. Python, JavaScript and safe Rust are; C++ is not. C++'s alternative is undefined behaviour: a list of operations (reading past the end of an array, reading freed memory, overflowing a signed integer, a data race) that the standard declares meaningless. The compiler is allowed to assume they never happen and optimise accordingly, so a program that does one of them may do anything, including appearing to work. The zero-overhead principle is the reason: checking every index costs time, so C++ does not check unless you ask.

clear errorIndexError, at the exact line. Every access is checked.

undefined behaviourtop[5] is unchecked: it printed 0, whatever happened to be in memory after the vector. top.at(5) is the checked version and throws. AddressSanitizer turns the unchecked read into a "heap-buffer-overflow" report, 8 bytes after the 12-byte buffer. Compilers and standard libraries now offer "hardened" modes that check [] too; they are opt-in.

checked: panicget(5) returns None; top[5] panics with the length and the index. Indexing is always bounds-checked in safe Rust; the optimiser removes checks it can prove unnecessary (iterators, as in section 2, have none).

silent undefinedJavaScript returns undefined and the arithmetic becomes NaN, no error. tsc lets const x: number = top[5] through unless noUncheckedIndexedAccess is on (the Rosetta program turns it on), in which case it is refused.

Rust is not free of the problem; it fences it. Code marked unsafe may dereference raw pointers and call C, and inside it undefined behaviour is possible again. The point is that it is rare and searchable: the standard library is built on small unsafe cores wrapped in safe interfaces, and tools such as {{Miri|https://github.com/rust-lang/miri}} check unsafe code for undefined behaviour. The Rustonomicon is the manual for that part of the language (Further reading).

False friends for a Python programmer
  • "If it ran and printed the right thing, it is correct." In C++ a program with undefined behaviour can print the right thing today and the wrong thing after a compiler upgrade. Run tests under AddressSanitizer and UndefinedBehaviorSanitizer.
  • "Rust programs cannot crash." They can panic (out of bounds, unwrap() on None, overflow in debug builds); what they cannot do in safe code is corrupt memory.

Two consequences matter for you. C++ never removes anything, so modern C++ is a subset you choose to write (the {{C++ Core Guidelines|https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines}} describe it), and old code with old habits stays legal. Rust's editions let it fix mistakes without breaking old crates, because each crate declares its edition in Cargo.toml. TypeScript 7.0 shipped without a programmatic API (expected in 7.1), so tools that embed the compiler, such as typescript-eslint, still run on TypeScript 6 alongside it, as the announcement says.

12. Tooling

Rust and modern Python have one tool that does almost everything; C++ has many that you assemble; JavaScript has several competing ones.

  • Python: uv (Astral, written in Rust) installs Python itself, creates environments, resolves and locks dependencies and runs scripts; ruff lints and formats; mypy, pyright or Astral's ty (in beta) check types; pytest tests.
  • C++: a compiler (clang, GCC, MSVC), a build system (CMake is the common one), a package manager if any (vcpkg, Conan, or none), sanitizers, clang-format and clang-tidy. There is no standard package manager, because compiled C++ libraries must match the compiler and flags they are linked with. Even the default language version differs: Apple clang 14 on this laptop defaults to C++98, recent Clang to C++17, GCC 16 to C++20, MSVC to C++14, so always pass -std=.
  • Rust: cargo builds, tests, benchmarks, documents, fetches and publishes; clippy lints, rustfmt formats; every published crate's documentation is built on docs.rs. One Cargo.lock pins every version.
  • TypeScript: a runtime (Node, Bun or Deno), a package manager (npm, pnpm, or Bun's), tsc for checking, and a test runner (vitest, or Node's built-in). Node runs .ts files directly by stripping types since 22.18; that does not type-check, so keep tsc --noEmit in CI.
Go deeper (optional): the {{Toolchain atlas|#t-tools}} tab lists every tool of the four ecosystems with versions, what each replaces and the commands for the running program; the {{Testing and quality|n:3c65c17b0d0d81548848e2ebdd2f63ee}} page covers testing practice.

The {{Benchmark|#t-bench}} tab times the running program on a 200,000-line log (measured, medians, ): Python 3.14 , Python with a regular expression , TypeScript on Node and on Bun , C++ , Rust . Three lessons carry beyond this program:

  • C++ against Rust is not one number. Here the C++ version carries its own small JSON parser (the standard library has none) and the compilers vectorised the token loop differently (section 2); either language can match the other with effort. Choose between them for safety and ecosystem, not speed.
  • Start-up and memory matter as much as throughput for command-line tools: Python and Node pay roughly 20 to 30 milliseconds and tens of megabytes before your first line runs (Bun about 6 ms); compiled binaries pay almost nothing. The Benchmark tab measures both.

How the languages call each other

You rarely rewrite a Python program; you move its hot loop into a compiled extension and keep the rest. A Python extension module is a compiled library that CPython imports like any module.

  • Rust from Python: {{PyO3|https://pyo3.rs/}} maps Rust functions and types to Python ones, and {{maturin|https://www.maturin.rs/}} builds them into wheels. This is how pydantic-core, tokenizers and polars ship. In the Benchmark tab, the token loop moved into Rust with one call per message took the program from to , and the whole file read in Rust to : crossing the boundary costs tens of nanoseconds per call, so batch the work.
  • C++ from Python: {{pybind11|https://pybind11.readthedocs.io/}} and its lighter successor {{nanobind|https://nanobind.readthedocs.io/}}; PyTorch's own C++ extensions use pybind11 through torch/extension.h. Same pattern, same lesson ( per call with nanobind, for the whole file).
  • Rust or C++ from JavaScript: compile to WebAssembly (runs in browsers and Node, sandboxed) or build a native Node addon (napi-rs for Rust, node-addon-api for C++).
  • Anything to anything: the C calling convention. A function declared extern "C" in C++ or Rust can be called from almost every language, which is why ggml's core is C (section 1).
When a rewrite is worth it
Profile first. If the time is in a loop over Python objects, try a vectorised library (NumPy, polars) or a regex; if it is still too slow and the loop is small and stable, move that loop into a Rust (PyO3) or C++ (nanobind) extension with a batch interface. Rewrite a whole program only when start-up, memory, deployment as a single binary, or concurrency is the problem, not raw loop speed.
