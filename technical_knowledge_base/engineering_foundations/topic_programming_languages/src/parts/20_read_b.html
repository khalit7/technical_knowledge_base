1. Four philosophies

A founding value is the goal a language's designers would not give up when two goals conflicted. Each of the four wrote theirs down. Read these four quotes slowly: every later section of this page is one of them playing out.

Python (early 1990s)

"Readability counts." "Explicit is better than implicit." "Errors should never pass silently." "There should be one-- and preferably only one --obvious way to do it."

From {{PEP 20, The Zen of Python|https://peps.python.org/pep-0020/}}. The programmer's time matters more than the machine's: no declarations, no compile step, everything an object you can inspect, and a mistake produces a clear exception at the line that made it.

Costs: every value carries type information and a reference count, and every operation is looked up while the program runs, so a plain Python loop is tens of times slower than compiled code (section 13).

C++ (1985)

"You don't pay for what you don't use. What you do use is just as efficient as what you could reasonably write by hand."

The {{zero-overhead principle|https://en.cppreference.com/w/cpp/language/Zero-overhead_principle}} (cppreference, after Stroustrup), plus compatibility with C: C++ began in 1979 as "C with Classes" and shipped as Cfront 1.0 in 1985 ({{cppreference history|https://en.cppreference.com/w/cpp/language/history}}). Nothing is checked unless you ask, so abstractions can compile to the same machine code as hand-written C.

Costs: the language trusts you. Reading freed memory, overflowing a signed integer or racing two threads is undefined behaviour: no error, and no guarantee about what happens (section 10).

Rust (1.0 in 2015)

"with no runtime or garbage collector" ... "Rust's rich type system and ownership model guarantee memory-safety and thread-safety, enabling you to eliminate many classes of bugs at compile-time."

From {{rust-lang.org|https://www.rust-lang.org/}} ("Performance" and "Reliability"; Rust 1.0 was {{announced 15 May 2015|https://blog.rust-lang.org/2015/05/15/Rust-1.0/}}). C++'s speed without C++'s undefined behaviour, by making the compiler prove who owns each value and who may change it.

Costs: the compiler rejects programs that are correct but that it cannot prove correct, so the first weeks are spent learning its rules; compile times are long.

JavaScript (1997 standard) and TypeScript (2012)

"Use a consistent, fully erasable, structural type system." Non-goal: "Apply a sound or 'provably correct' type system. Instead, strike a balance between correctness and productivity."

From {{TypeScript's Design Goals|https://github.com/microsoft/TypeScript/wiki/TypeScript-Design-Goals}}. TypeScript (first released as 0.8 in {{October 2012|https://devblogs.microsoft.com/typescript/announcing-typescript-1-0/}}) is JavaScript plus types that are checked and then deleted. JavaScript itself appeared in Netscape's browser and was standardised as ECMAScript in June 1997 ({{ECMA-262, Introduction|https://tc39.es/ecma262/}}). JavaScript's own rule is older: "'don't break the Web' is the number one design principle" for anything shipped in browsers ({{Mathias Bynens, V8 team, 2018|https://developer.chrome.com/blog/smooshgate}}), so JavaScript's old mistakes can never be removed, only avoided.

Costs: types can be wrong at run time (nothing checks data arriving from the network), and JavaScript's quirks (one number type, two kinds of "nothing") stay forever.

Two of these are about the programmer (Python's readability, TypeScript's productivity) and two about the machine (C++'s zero overhead, Rust's zero overhead plus proof). That split predicts most of this page: Python and TypeScript share objects freely and clean up with a garbage collector; C++ and Rust lay values out exactly as written and free them at a known moment.

What each one is for in ML work today

The four languages are not competitors in your work; they occupy different layers of the same stack. Share of bytes of source per language (tests and examples included, generated files mostly excluded by linguist). Bytes are not importance: PyTorch's C++ is a quarter of its bytes but carries most of its speed. The astral-sh/ty repository holds only packaging and Python tests: its {{README|https://github.com/astral-sh/ty}} says development "takes place in the Ruff repository", so ty's Rust lives inside astral-sh/ruff.

  • Python is the glue and the research language. Model code, training loops, notebooks, evaluation and orchestration are Python; Hugging Face Transformers is 99.9% Python by bytes. GitHub's Octoverse 2025 counts 2.6 million monthly contributors to Python and calls it "dominant for AI and data science workloads" ({{GitHub, 28 Oct 2025|https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/}}).
  • C++ is the substrate under the Python. PyTorch is two thirds Python by bytes, but the tensors, the autograd engine and the CPU kernels underneath are C++ (26%) and CUDA. ONNX Runtime is 83% C++. In llama.cpp the split is instructive: the tensor library ggml has a C core (ggml.c, the CPU kernels in ggml-cpu.c and quants.c, about 81,000 lines of C) surrounded by C++ (about 221,000 lines: the backend interface ggml-backend.cpp, the GGUF file reader gguf.cpp, the CPU operators in ggml-cpu/ops.cpp and the GPU backends), and the model loading, tokenizer, sampling and server are C++ (src/ 91,000 lines, tools/ 57,000), with 47,000 lines of CUDA for NVIDIA GPUs (commit , counted by read/code/llama/excerpts.sh). C is used where the code must be callable from any language and compile anywhere; C++ where the code needs containers, RAII and templates. Sections 5 and 14 read parts of it.
  • Rust is the new substrate of Python's own tools. uv (98% Rust), ruff (97%), Hugging Face tokenizers (95%) and safetensors, polars (63%) and pydantic-core are Rust compiled into Python packages, so you already run Rust every day. OpenAI's Codex CLI is 97% Rust. The Stack Overflow 2025 survey found Rust "yet again the most admired programming language (72%)" and uv the most admired technology among its tags (74%) ({{Stack Overflow, 2025|https://survey.stackoverflow.co/2025/technology}}). Since September 2026 Rust can also write NVIDIA GPU kernels, which belongs to {{Topic: cuda-and-gpu-programming|n:3c65c17b0d0d81c39f34d5e070d783c1}}.
  • TypeScript is the language of LLM applications and agents. The official MCP TypeScript SDK, Vercel's AI SDK, Google's Gemini CLI, OpenAI's Agents SDK for JavaScript and Anthropic's TypeScript SDK are all 85 to 99% TypeScript. In August 2025 TypeScript overtook Python and JavaScript as the most used language on GitHub by monthly contributors (2,636,006), which GitHub links partly to AI-assisted coding preferring typed code ({{Octoverse 2025|https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/}}).
False friends for a Python programmer
  • "JavaScript and TypeScript are two languages." TypeScript is JavaScript plus a type checker; whatever runs is JavaScript. Learning TypeScript means learning JavaScript's runtime first.
  • "C++ is C with extras." Modern C++ code that follows the C++ Core Guidelines uses almost none of C's habits (raw arrays, manual malloc). llama.cpp is unusual in mixing both, which is why reading it needs both (section 14).
