Rosetta: one program, four languages

The same small tool written in Python, C++, Rust and TypeScript, read line by line with Python as the reference. Every snippet on this tab compiles and runs; every output, compiler error and type-checker message below is the real text, captured by running the code (versions at the bottom).

The tool: read a chat log in JSONL (one JSON object per line), count the word-ish tokens in each message, add them up per user, print the five heaviest users. It is the kind of throwaway script an ML engineer writes weekly, and it touches files, parsing, text, a hash map, sorting, and bad input. Token rule: a run of ASCII letters or digits ([A-Za-z0-9]+), so x86_64 is 2 tokens and 日本語 is 0. Sort by count, ties by user id. The full spec, the generator and the expected output are in the page's source folder (src/rosetta/PROGRAM.md); the {{Benchmark|#t-bench}} tab times this same program.

The same numbers in memory

Eight timestamps from the log, summed one by one. A Python list does not hold numbers: it holds 8-byte pointers to separate 32-byte int objects, wherever the allocator put them. A NumPy array, a C++ std::vector<int64_t> and a Rust Vec<i64> hold the eight numbers themselves, side by side. The addresses drawn are the real ones printed by the programs in Where the numbers live above; a CPU fetches memory in 64-byte cache lines, so the counter of lines touched is the cost that matters.

What this does not show: the CPU's prefetcher hides much of the cost of a predictable walk, and the interpreter's own work per element (type checks, reference counts) is usually larger than the memory cost for eight numbers. At millions of elements both matter; the {{Benchmark|#t-bench}} tab measures the whole program.

Toolchains used

Every output on this tab was produced by src/rosetta/run_all.sh, which rebuilds each snippet, runs it, checks that the four programs print exactly the expected output, stores each capture in src/rosetta/outputs/ and regenerates this tab's data. Machine-specific paths are shortened (<python>, <llvm>); memory addresses and thread ids change on every run.
