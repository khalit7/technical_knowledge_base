# Benchmark tab: sources, scripts and raw results

The Benchmark tab (`t-bench`, parts `32_tab_bench.html`, `32_js_bm_view.js`, `32_js_bm_zanim.js`, and the generated `32_js_bm_data.js`) measures the Rosetta tab's `count_tokens` program (spec: `../rosetta/PROGRAM.md`) on the 200,000-line input from `../rosetta/data/gen_chat.py --lines 200000 --seed 7` (38,792,775 bytes; not committed, regenerated by the script).

## Reproduce
```
PL=<toolchain dir> WORK=<scratch dir> bash run_bench.sh     # about 6 minutes on an M1 Pro
```
It builds everything, checks every variant prints `results/expected_200k.txt` (the 200k output in PROGRAM.md), times them, and ends with `summarize.py` (writes `results/summary.json` and `../parts/32_js_bm_data.js`) and `check_numbers.py` (recomputes medians from the raw hyperfine JSON, checks the data part and the built `index.html`, and that every `data-bm` placeholder in the tab resolves). Run `sh ../build.sh` before `check_numbers.py` passes its index check.

Toolchains expected under `PL` (installed for this page inside the session scratchpad, never system-wide):
- `PL/rust`: rustup with `RUSTUP_HOME=PL/rust/rustup CARGO_HOME=PL/rust/cargo`, `--no-modify-path`, stable (rustc 1.99.0).
- `PL/py`: CPython 3.13.16, 3.14.8 and 3.14.8 free-threaded via `uv python install` with `UV_PYTHON_INSTALL_DIR=PL/py UV_PYTHON_INSTALL_BIN=0` (the last one stops uv from linking `python3.x` into `~/.local/bin`).
- `PL/bin`: hyperfine 1.20.0, bun 1.4.2, uv 0.12.23 (release binaries).
- `PL/ts/node_modules`: typescript (tsc 7.0.2), installed by the Rosetta agent. Node 22.22.2 from the system.
- `PL/llvm`: LLVM clang 23.1.2, compiling against the macOS SDK's libc++ so only the compiler differs from Apple clang (LLVM's own libc++ 23 made any program that destroys a `std::ifstream` abort at exit on this macOS, so it was not used).
- Apple clang 14.0.0 from Xcode (`clang++`).
- simdjson 3.13.0 single-header files (a release that builds with Apple clang 14 and its libc++; 5.0.2 does not, it needs `std::ranges::input_range`; 4.x was not tried) are downloaded into `WORK/simdjson` by the script.

## Files
- `py/`: Python variants. `common.py` (parse and print, shared), `count_re.py` (regex tokens), `count_threads.py` (N threads, for 3.14 and 3.14t), `count_ext.py` (Python calling a native module: per call, batched, whole file), `crossing.py` (per-call cost, timeit), `breakdown.py` (time per stage, executed-bytecode trace).
- `ext_rust/`: the PyO3 extension `ct_rs` (maturin). Whole-file path parses with serde into a typed struct like the Rosetta Rust program; `threads` splits the file over OS threads with the GIL released (`py.detach`).
- `ext_cpp/`: `ct_pb` (pybind11) and `ct_nb` (nanobind) built with plain clang++ by `build.sh`; `file_count.h` reuses the Rosetta `json_lite.hpp` parser. `loop_probe.cpp` times the token loop alone.
- `cpp_simdjson/`: benchmark-only C++ variant with simdjson in place of the hand-written parser, built with Apple clang 14.
- `loop_probe.sh`: the token loop under Apple clang 14, LLVM clang 23 and rustc, with the inner-loop assembly.
- `loc.py`: lines of code. `results/`: every raw file (hyperfine JSON, memory.tsv, crossing.json, breakdown_*.json, loop_probe.txt, env.txt, sizes.txt, loc.json, commands.tsv) and `summary.json`.

## Notes
- The machine was in normal use during the runs (load average recorded in `results/env.txt`); hyperfine flagged outliers on some commands. Single-thread medians were stable within a few per cent between the three full runs made while building the tab; thread scaling is the noisiest.
- Cold disk (page cache purged) was not measured: `purge` needs root. "Cold" on the tab means an empty Python bytecode cache or Node compile cache.
- External published numbers on the tab are quoted from their sources with dates and never mixed into the measured charts.
- `check_ui.mjs`: puppeteer check of every control at 390 px dark and 920 px light (`OUT=<dir> node check_ui.mjs`).
