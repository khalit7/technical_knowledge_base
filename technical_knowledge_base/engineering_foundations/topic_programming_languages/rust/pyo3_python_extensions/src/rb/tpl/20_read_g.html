11. Type stubs and tests

A compiled module has no Python source, so mypy, ty and your editor cannot see its signatures. You give them a stub file (.pyi): Python syntax with ... for bodies, read only by type checkers. For a Rust-only project like this one, maturin picks up <module>.pyi next to Cargo.toml and adds it to the wheel with a py.typed marker (maturin: adding Python type information). The hand-written one, abridged:

A script with four mistakes (code/c11_typed.py: a bytes argument, a float32 array, an int assigned to a str, a misspelt keyword) checked three ways: without the stub, mypy cannot check any call into tokrs (missing library stubs or py.typed marker); with it, mypy catches three mistakes and ty catches all four, including the float32 array that mypy let through. A stub can drift out of date, since nothing checks it against the Rust code: test it with mypy.stubtest.

12. Wheels: abi3, abi3t, CI and publishing

Users should never need Rust to install your package: they need a wheel built for their Python and their machine, which pip or uv picks from PyPI by the tags in its file name ({{Python: typing, uv, packaging and the toolchain|n:4055c17b0d0d8192878fce7505cc612f}} owns wheel tags, platform tags such as manylinux, and the four packaging layers). maturin build --release wrote tokrs-0.1.0-cp314-cp314-macosx_11_0_arm64.whl: CPython 3.14's full C ABI (it loads on 3.14 only; a free-threaded build would say cp314t), macOS 11 or later on Apple silicon. Inside: the compiled library, the stub and py.typed, metadata, and a software bill of materials (sboms/, the Rust crates compiled in, written by maturin). otool -L (macOS's ldd) shows the library does not link to libpython: it finds Python's C API symbols in the process that loads it, which is what lets one wheel work with any CPython 3.14 binary.

abi3: one wheel for many Python versions

A wheel per Python version per platform multiplies fast. CPython's stable ABI (the "limited API", PEP 384) is a subset of the C API promised not to change; an extension that uses only that subset gets the abi3 tag and loads on that version and every later one. In PyO3 it is a feature flag, pyo3/abi3-py310 (minimum Python 3.10). Built once, installed into fresh virtual environments:

[[out:b5_abi3.txt|$ maturin build --release --features pyo3/abi3-py310]] [[out:b6_abi3_install.txt|one abi3 wheel on CPython 3.12, 3.13, 3.14 and 3.14t]]

The same file loaded on three versions and was refused by the free-threaded build: abi3 assumes the GIL build's object layout. At run time abi3 can cost a little: under the limited API, PyO3 must call real C functions where the full API uses inline macros (list item access, string data).

PyO3's changelog lists such cases, for example "Optimize PyBytes::as_bytes() when not using abi3 or abi3t" (0.29.3).

abi3t is the stable ABI for free-threaded builds, PEP 803 (status Final, Python 3.15), supported by PyO3 0.29 through the abi3t-py315 feature. Built against the 3.15 release candidate:

[[out:b7_abi3t.txt|$ maturin build --release --features pyo3/abi3t-py315 -i python3.15t]] [[out:b8_abi3t_install.txt|the abi3t wheel on CPython 3.15.0rc3, free-threaded and with the GIL]]

The tag abi3.abi3t means one file for both 3.15 builds. Until you can require 3.15, ship an abi3 wheel plus a cp314t wheel per platform (tokenizers, safetensors and polars build abi3-py310 today); shipping only an abi3 wheel leaves free-threaded users unable to install.

Building for every platform in CI

You cannot build Windows or Linux wheels on a Mac without cross-compilers, so CI builds them on each platform. maturin generate-ci github writes a complete GitHub Actions workflow (186 lines; PyO3/maturin-action does the builds): every build job runs maturin build --release --out dist --find-interpreter, one wheel per Python found (one in total with abi3), and a release job uploads everything to PyPI on a git tag.

Change one thing before you use it
The generated job uploads with a long-lived PYPI_API_TOKEN secret. With trusted publishing you register the repository and workflow on PyPI once, the job (which already has id-token: write) receives a short-lived token from GitHub, and uv publish needs no credentials (uv packaging guide, PyPI trusted publishers). Delete the env: lines after setting it up.

cibuildwheel is the other route: one tool that builds wheels for every CPython on every platform for any build backend, including maturin; for Rust it must install a Rust toolchain inside its Linux containers (cibuildwheel FAQ, "Building Rust wheels"). maturin-action is simpler for a Rust-only package; cibuildwheel suits projects that run test suites per wheel or mix C, C++ and Rust.
