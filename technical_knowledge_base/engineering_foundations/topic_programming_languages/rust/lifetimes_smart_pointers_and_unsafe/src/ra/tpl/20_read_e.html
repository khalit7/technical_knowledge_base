4. unsafe, and checking it with Miri

Some correct code cannot be proved safe by the compiler: the inside of Vec, calls into C libraries, hardware access. Inside an unsafe block you may do five extra things, the "unsafe superpowers" ({{Rust Book 20.1|https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html}}): dereference a raw pointer; call an unsafe function; access or modify a mutable static; implement an unsafe trait (such as Send, section 3); access fields of a union. Nothing else changes: "unsafe doesn't turn off the borrow checker or disable any of Rust's other safety checks".

The stage follows the two programs: an unsafe gate between the pointers on the stack and the memory they point at, crossed by every dereference.

  1. Making a raw pointer is safe. v owns a [[x:ub.size]]-byte heap allocation, three u32s ([[x:uok.vals.0]], [[x:uok.vals.1]], [[x:uok.vals.2]]) at byte offsets +0, +4 and +8. p = v.as_ptr() is only an address; nothing has been read.
  2. Dereferencing it needs unsafe. unsafe { *p.add([[x:uok.idx]]) } crosses the gate: the read is in bounds because we promise it is. Printed: second = [[x:uok.second]].
  3. A safe API with an unsafe core: split_at_mut([[x:uok.mid]]). Two &mut halves of one array, [0, [[x:uok.mid]]) and [[[x:uok.mid]], len), which the borrow checker cannot prove disjoint and the invariant guarantees never overlap. Each half changes once through its own &mut: printed [[x:uok.after]].
  4. One element past the end. *p.add([[x:ub.past]]) is byte +[[x:ub.off]] of a [[x:ub.size]]-byte allocation: past the end. The native release build reads whatever is there and carries on: read past the end: [[x:ub.run_past]], exit code 0.
  5. Miri stops at the first bad read. Under Miri the same read fails: an access of [[x:ub.acc]] bytes at offset 0x[[g:l_ub_miri|\+0x([0-9a-f]+)]] of an allocation of size [[x:ub.size]], at [[x:ub.miri_at]].
  6. Use after free. w is freed at the end of its block, but q still holds its address; the release build prints read after free: [[x:ub.run_free]]. Miri never reached this line: it stopped at the first violation.
Without the block, the compiler refuses and says why each operation needs it (E0133)

That is the pattern to aim for: a small unsafe core with a stated invariant ("the two halves never overlap"), wrapped in a safe API that cannot be used to break it ({{split_at_mut docs|https://doc.rust-lang.org/std/primitive.slice.html#method.split_at_mut}}: it panics if mid > len). Because unsafe is a keyword, every such place can be found with a text search and reviewed.

Miri stops at the first violation, names it (at or beyond the end of the allocation of size 12 bytes: three u32s) and points at where the memory was allocated. It runs on the nightly toolchain (here rustc 1.101.0-nightly of 2026-10-04) and is much slower than native code, so you run your tests under it, not production. If you write unsafe, run cargo +nightly miri test in CI.
