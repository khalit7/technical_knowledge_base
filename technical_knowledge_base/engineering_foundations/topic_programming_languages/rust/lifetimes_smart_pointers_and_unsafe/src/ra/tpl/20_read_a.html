The idea in one sentence. Rust has one rule, many readers or one writer, and no reference outlives what it points to; lifetimes let the compiler check it for references, Send and Sync carry it across threads, RefCell and Mutex move the check to run time, and inside unsafe it becomes your job, with Miri checking it in your tests.

One rule, four places it is checked, and what breaking it costs in each

Read left to right as "how late the mistake is found". Most code lives in the first column; each step right buys flexibility and pays for it in when, and how loudly, a mistake shows up.

lifetime
the stretch of the program in which a reference is valid; written 'a
elision
the three rules by which the compiler fills in lifetimes you did not write
T: 'static
a bound: T holds no borrow that could expire (not "lives forever")
interior mutability
changing a value through a shared reference, with the exclusivity check done at run time
Send, Sync
marker traits: a value may move to another thread; a &T may be shared between threads
data race
two threads touch the same memory at once, one writing, nothing ordering them
undefined behaviour
a broken invariant inside unsafe; the program may do anything, including appear to work
Miri
an interpreter that runs Rust and checks every memory access against the rules
