1. Lifetimes: a contract the compiler checks at every call

A lifetime is the stretch of the program during which a reference is valid. The checker computes them itself almost everywhere. You write one, as 'a, only when a function returns a reference (or a struct holds one) and the compiler cannot tell which input it came from:

Read 'a as a name for "some region of the program". The fixed signature fn longest<'a>(a: &'a str, b: &'a str) -> &'a str says: the result is valid as long as both inputs are, so at each call 'a shrinks to the overlap of the two. Lifetimes generate no code; they are a contract the checker verifies at every call.

The stage draws one call of longest along the lines of main: each value is a slab from its declaration to the end of its scope, a value of an inner block stacked on the outer one, and the borrow w on top of what it borrows. A borrow has to rest on its owners along its whole length. (The stacking pictures "must fit inside", not where anything sits in memory.)

  1. The outer value. let a = String::from("tokens"); at line 6, alive to the end of main (line 13).
  2. The inner block's value. b is declared at line 9 inside a block that closes at line 11: its slab sits on a's and ends at that brace.
  3. The call borrows from both. w = longest(&a, &b); (line 10) gives w the lifetime 'a, and 'a must fit inside both inputs: the dots run from a and b into w.
  4. How far 'a may reach. The overlap of a and b is b's span, so 'a may reach no further than line 11, where b is dropped (the glass plate).
  5. Used after the block: E0597. println!("{w}") at line 12 stretches w past b's end; that part has nothing under it. The error names exactly the three points on the timeline: where b was borrowed, where it was dropped, where the borrow was used later.
  6. The fix: use it inside the block. In life.rs the println! moves inside the block (line 23, before b's end at 24), so w rests on b along its whole length: it compiles and prints longest: logits!. Moving one use is the whole difference.

The working program and the failing one, in full (life.rs, life_err2.rs)
life.rs
// 'a names "some region of the program". The signature promises: the result
// lives no longer than the shorter-lived of a and b.
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

// One input reference: the compiler fills in the lifetimes itself (elision).
fn first_word(s: &str) -> &str {
    s.split(' ').next().unwrap_or("")
}

// A struct that holds a reference must say how long it may live.
struct Token<'a> {
    text: &'a str,
}

fn main() {
    let a = String::from("tokens");
    let w;
    {
        let b = String::from("logits!");
        w = longest(&a, &b);
        println!("longest: {w}");
    }
    let t = Token { text: first_word("hello world") };
    let s: &'static str = "string literals live for the whole program";
    println!("{} | {}", t.text, s);
}
$ rustc --edition 2024 life.rs && ./life

When you write them: the three elision rules

The {{elision rules|https://doc.rust-lang.org/reference/lifetime-elision.html}} fill in the common cases, so most signatures carry no 'a:

RuleExampleFilled in as
1. Each input reference gets its own lifetime.fn f(a: &str, b: &str)fn f<'1, '2>(a: &'1 str, b: &'2 str)
2. Exactly one input lifetime: outputs get it.fn first_word(s: &str) -> &strthe result borrows from s
3. A method with &self: outputs get self's.fn name(&self) -> &strthe result borrows from self

So you write lifetimes when a function has two or more reference inputs and returns a reference, or a struct stores a reference (struct Token<'a> { text: &'a str } in life.rs). Rule 3 is the one that surprises: in a method it guesses self, even when the result can come from another argument.

A method that returns its argument, refused under rule 3, and the fix (elide_self_err.rs, elide_self_fix.rs)
elide_self_err.rs (lines 5 to 10)
impl Vocab {
    // Elision rule 3: with &self, the returned reference is assumed to borrow from self.
    fn pick(&self, other: &str) -> &str {
        if other.is_empty() { &self.name } else { other }
    }
}

The compiler's suggestion ties only other to the result, which would then refuse &self.name. The fix that matches what the code does names one lifetime for both inputs:

elide_self_fix.rs (lines 5 to 10)
impl Vocab {
    // Say it explicitly: the result may come from self or from other.
    fn pick<'a>(&'a self, other: &'a str) -> &'a str {
        if other.is_empty() { &self.name } else { other }
    }
}

What no lifetime can do

Annotations describe lifetimes and never extend them, so no 'a makes a reference to a value that is about to die:

Returning a reference to a local (dangle_err.rs, E0515)
dangle_err.rs (lines 1 to 4)
fn make_greeting(name: &str) -> &str {
    let s = format!("hello {name}");
    &s
}

The fix is to return the owned String. That is the general rule of thumb: if "just add a lifetime" spreads 'a through many types, store an owned value instead; borrowing in structs is an optimisation for later.

'static: two meanings, one of which is a bound

&'static str is a reference valid for the whole program: string literals are &'static str because they live in the program's binary. T: 'static as a bound is weaker and far more common: T holds no borrow that could expire. Every owned type (String, Vec, Arc<Mutex<..>>) satisfies it, and is still freed whenever its owner drops it. This is the bound on std::thread::spawn and tokio::spawn, and the reason section 3's first error says "requires argument type to outlive 'static".

use std::fmt::Debug;

// T: 'static means "T holds no borrow that could expire", not "T lives forever".
fn keep<T: Debug + 'static>(t: T) -> Box<dyn Debug> {

fn main() {

    let b = keep(owned); // fine: a String borrows nothing

    drop(b); // ... and it is freed right here, long before the program ends
    println!("dropped; a 'static bound never kept it alive");
}

Further, for when you meet them (not demonstrated here)
  • '_, the anonymous lifetime: "the elided one", written where a type needs a lifetime parameter but you want elision, as in impl fmt::Display for Token<'_>.
  • T: 'a bounds say every reference inside T outlives 'a; they appear on structs holding generic references, and the compiler infers most of them.
  • Variance decides when a &'long T may be used where a &'short T is expected (always, for shared references) and why &mut T is stricter; the {{Rustonomicon's chapter on subtyping|https://doc.rust-lang.org/nomicon/subtyping.html}} is the reference.
  • Borrows end at their last use, not at the end of the block (non-lexical lifetimes); {{Rust: the essentials|n:3c65c17b0d0d8156bed9ead8a22f33b0}} animates this on its borrow timeline, and its Borrow-checker lab has the lifetime scenarios (returning a local reference, a missing lifetime, a borrow outliving its owner, a struct holding a reference).
