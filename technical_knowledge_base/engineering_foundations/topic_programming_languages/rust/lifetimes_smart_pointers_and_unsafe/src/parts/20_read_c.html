2. Smart pointers and interior mutability

Single ownership and compile-time borrowing cover most code. For the rest, the standard library has types that own their contents in other ways, each with a cost:

TypeWhat it gives youCostPython analogue
Box<T>one owner, value on the heap; needed for recursive types and trait objectsone allocationevery object
Rc<T>shared ownership in one thread; freed when the last Rc goesa counter update per clone and dropreference counting
Arc<T>the same across threadsatomic counter updates (slower)reference counting in free-threaded CPython
Cell<T>, RefCell<T>interior mutability: change through a shared reference; RefCell checks the borrow rules at run timea flag check per borrow; a panic if the rules are broken(all objects are mutable)
Mutex<T>, RwLock<T>the same across threads, by lockinga lock per access; contentionthreading.Lock
Weak<T>a non-owning pointer to an Rc/Arc value; breaks cyclesupgrade() may find it goneweakref

A recursive type needs Box, because a value that contains itself directly would have infinite size; with the Box each child is one 8-byte pointer, as the run below prints (size_of Box<Expr> = 8).

The panic is the price of RefCell: the same rule as compile-time borrowing, but discovered while the program runs. Rc<RefCell<T>> compiles in situations where plain references would not, and it is the most common way learners make a borrow error go away and turn it into a crash. So: Rc<RefCell<T>> compiles but can still panic because the exclusivity check moved from compile time to run time. try_borrow_mut returns an error instead of panicking ({{RefCell docs|https://doc.rust-lang.org/std/cell/struct.RefCell.html}}), for code that can recover.

use std::cell::{Cell, RefCell};
use std::rc::{Rc, Weak};

// Box: put a value on the heap. Needed for recursive types, whose size would otherwise be infinite.
#[derive(Debug)]
enum Expr {
    Num(f64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

fn eval(e: &Expr) -> f64 {
    match e {
        Expr::Num(x) => *x,
        Expr::Add(a, b) => eval(a) + eval(b),
        Expr::Mul(a, b) => eval(a) * eval(b),
    }
}

#[derive(Debug)]
struct Doc {
    name: String,
    cache_hits: Cell<u32>, // interior mutability for a Copy value
}

fn main() {
    let e = Expr::Add(Box::new(Expr::Num(2.0)), Box::new(Expr::Mul(Box::new(Expr::Num(3.0)), Box::new(Expr::Num(4.0)))));
    println!("2 + 3 * 4 = {}", eval(&e));

    // Rc: shared ownership in one thread; the last owner to go frees the value
    let shared = Rc::new(Doc { name: "system prompt".into(), cache_hits: Cell::new(0) });
    let a = Rc::clone(&shared); // copies a pointer, bumps a counter
    {
        let b = Rc::clone(&shared);
        b.cache_hits.set(b.cache_hits.get() + 1); // mutate through a shared reference
        println!("strong_count inside = {}", Rc::strong_count(&shared));
    }
    println!("strong_count after = {}, hits = {}, name = {}", Rc::strong_count(&a), a.cache_hits.get(), a.name);

Reference cycles leak

Reference counting cannot free a cycle, in Rust as in Python (where the cycle collector cleans up afterwards; Rust has none). Leaking memory is safe in Rust's sense, so the compiler allows it.

Before and after: two nodes that own each other never reach 0; make the back edge Weak and both drop

Counts are leak.rs's printed values (cycle: x strong_count = 2; weak: x strong_count = 1, weak_count = 1); the code and the full output are below.

Predict, then reveal: Which of the four nodes print "drop"?

Rule of thumb: ownership should form a tree. Back pointers (child to parent, node to previous) are Weak, or better, indexes into a Vec that owns all the nodes (an "arena"), which is how most Rust graph code is written. Miri (section 4) reports memory still allocated when a program ends, so it would flag this leak in a test.

leak.rs in full
leak.rs
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: &'static str,
    next: RefCell<Option<Rc<Node>>>, // owning edge
    back: RefCell<Weak<Node>>,       // non-owning edge
}

impl Drop for Node {
    fn drop(&mut self) {
        println!("drop {}", self.name);
    }
}

fn node(name: &'static str) -> Rc<Node> {
    Rc::new(Node { name, next: RefCell::new(None), back: RefCell::new(Weak::new()) })
}

fn main() {
    {
        let x = node("x (cycle of Rc)");
        let y = node("y (cycle of Rc)");
        *x.next.borrow_mut() = Some(Rc::clone(&y)); // x -> y
        *y.next.borrow_mut() = Some(Rc::clone(&x)); // y -> x: a cycle
        println!("cycle: x strong_count = {}", Rc::strong_count(&x));
    } // our two handles go, but each node still owns the other: neither count reaches 0
    {
        let x = node("x (Weak back edge)");
        let y = node("y (Weak back edge)");
        *x.next.borrow_mut() = Some(Rc::clone(&y)); // x owns y
        *y.back.borrow_mut() = Rc::downgrade(&x); // y only points back at x
        println!("weak: x strong_count = {}, weak_count = {}", Rc::strong_count(&x), Rc::weak_count(&x));
        println!("y.back.upgrade() is {}", y.back.borrow().upgrade().map(|n| n.name).unwrap_or("gone"));
    }
    println!("end of main: the Rc cycle was never dropped (a leak, which safe Rust allows)");
}
