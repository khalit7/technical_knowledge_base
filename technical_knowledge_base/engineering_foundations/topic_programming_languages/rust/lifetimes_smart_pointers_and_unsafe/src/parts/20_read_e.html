4. unsafe, and checking it with Miri

Some correct code cannot be proved safe by the compiler: the inside of Vec, calls into C libraries, hardware access. Inside an unsafe block you may do five extra things, the "unsafe superpowers" ({{Rust Book 20.1|https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html}}): dereference a raw pointer; call an unsafe function; access or modify a mutable static; implement an unsafe trait (such as Send, section 3); access fields of a union. Nothing else changes: "unsafe doesn't turn off the borrow checker or disable any of Rust's other safety checks".

unsafe_ok.rs
fn main() {
    let v = vec![10u32, 20, 30];
    let p: *const u32 = v.as_ptr(); // making a raw pointer is safe
    let second = unsafe { *p.add(1) }; // dereferencing it is not: we promise it is in bounds
    println!("second = {second}");
    // A safe API built on unsafe: split_at_mut hands out two &mut halves of one slice,
    // which the borrow checker cannot prove disjoint by itself.
    let mut a = [1, 2, 3, 4];
    let (l, r) = a.split_at_mut(2);
    l[0] += 100;
    r[0] += 100;
    println!("{a:?}");
}
$ rustc --edition 2024 unsafe_ok.rs && ./unsafe_ok
second = 20
[101, 2, 103, 4]

A small unsafe core behind a safe API: split_at_mut's halves can never overlap

That is the pattern to aim for: a small unsafe core with a stated invariant ("the two halves never overlap"), wrapped in a safe API that cannot be used to break it ({{split_at_mut docs|https://doc.rust-lang.org/std/primitive.slice.html#method.split_at_mut}}: it panics if mid > len). Because unsafe is a keyword, every such place can be found with a text search and reviewed.

When you get it wrong: Miri

Breaking an invariant is undefined behaviour, exactly as in C++: the program may do anything, including appear to work. This program reads one element past the end of a vector, and then reads a freed vector:

main.rs
// Undefined behaviour that compiles and "works": reading one element past the end
// through a raw pointer, and using a pointer after its Vec was freed.
fn main() {
    let v = vec![10u32, 20, 30];
    let p = v.as_ptr();
    let past_end = unsafe { *p.add(3) }; // out of bounds: UB
    println!("read past the end: {past_end}");
    let q = {
        let w = vec![1u32, 2, 3];
        w.as_ptr()
    }; // w freed here; q dangles
    let after_free = unsafe { *q }; // use after free: UB
    println!("read after free: {after_free}");
}

{{Miri|https://github.com/rust-lang/miri}} is an interpreter for Rust's intermediate representation that checks every memory access against the rules. Same program, two ways of running it:

Before and after: the release build prints plausible numbers; Miri stops at the first bad read

Miri stops at the first violation, names it (at or beyond the end of the allocation of size 12 bytes: three u32s) and points at where the memory was allocated. It runs on the nightly toolchain (here rustc 1.101.0-nightly of 2026-10-04) and is much slower than native code, so you run your tests under it, not production. If you write unsafe, run cargo +nightly miri test in CI.

CostsYou take on C's obligations for that block; reviewers must check the invariant by hand.
Do notUse unsafe to silence a borrow error. If safe code cannot express it, the design usually needs an index, a RefCell or a different owner.
