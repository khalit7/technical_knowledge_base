Read it as a story. Steps 1 to 3 move only the token loop: a 3x gain, and batching (step 3) barely beats one call per message, because once the loop is in Rust the program is waiting on json.loads. Copying the strings (step 2) is visibly slower than borrowing them (step 3). Step 4 moves the parsing too: Python reads the file as bytes and makes one call; serde parses each line straight into a typed struct, and the program runs times faster than the Python version. Step 5 releases the GIL and splits the file over 8 rayon threads. The root's own whole-file PyO3 variant measured s (one thread) and s (4 threads), in line with steps 4 and 5.

11. Type stubs and tests

A compiled module has no Python source, so mypy, ty and your editor cannot see its signatures. You give them a stub file (.pyi): Python syntax with ... for bodies, read only by type checkers. For a project like this one (Rust only, no Python package directory), maturin picks up <module>.pyi next to Cargo.toml and adds it to the wheel with a py.typed marker (maturin: adding Python type information). The hand-written one, abridged:

[[file:ext/tokrs.pyi@1-14]]

A script with four mistakes (code/c11_typed.py) checked three ways:

[[file:code/c11_typed.py]] [[out:c11_mypy_nostub.txt|$ mypy --strict c11_typed.py (wheel without the stub)]] [[out:c11_mypy.txt|$ mypy --strict c11_typed.py (with the stub)]] [[out:c11_ty.txt|$ ty check c11_typed.py (with the stub)]]

Without the stub, mypy cannot check any call into tokrs. With it, mypy catches three mistakes; ty catches all four, including the float32 array that mypy let through. A stub can also drift out of date: nothing checks it against the Rust code. PyO3 is building automatic stubs (experimental-inspect feature, maturin generate-stubs, labelled "still in active development"); on this crate it produced:

[[file:outputs/b9_stubs_auto.pyi@41-65]]

Close, from the Rust types alone, but with gaps: count_many(texts: list) lost the element type (PyO3 cannot see inside a Bound<PyList>), NumPy arrays became Incomplete, MalformedLine was missing, and the file ends with a catch-all def __getattr__(name: str) -> Incomplete. It also shows count_bytes_owned(data: Sequence[int]): a Vec<u8> parameter accepts any sequence of ints, not only bytes. For now, write the stub by hand and test it with mypy.stubtest.
