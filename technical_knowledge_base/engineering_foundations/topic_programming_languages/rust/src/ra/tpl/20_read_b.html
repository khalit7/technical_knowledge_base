2. Cargo: the one tool

Rust is compiled: rustc, the compiler, turns source files into a machine-code program before anything runs. You rarely call it yourself. Cargo is the build tool and package manager: it creates projects, downloads dependencies, calls rustc, runs tests and lints. A package of Rust code is a crate; the public registry is {{crates.io|https://crates.io}}. Toolchains are installed and updated by rustup (here the stable 1.99.0 of 2026-10-01; a new stable ships every six weeks, {{RELEASES.md|https://github.com/rust-lang/rust/blob/master/RELEASES.md}}).

Clippy is the fastest way to learn idioms. On a correct program written the way a Python programmer first writes it, it warned five times, and each warning is a lesson: borrow a slice &[u64] rather than &Vec<u64>, iterate instead of indexing, write +=, test is_empty() rather than a length against zero, and the last expression of a block is its value so return is unneeded (section 3). cargo clippy --fix applies the mechanical ones (3 of the 5 here).

Cargo.lock pins the exact versions resolved, like uv.lock, and the version rules differ from pip's in one way that bites: for a 0.x crate the minor number is the breaking one.

Dependencies, versions, the lock file, features and build-time code
  • Cargo.toml lists dependencies with version requirements; Cargo.lock pins the exact versions resolved, like uv.lock. Commit it.
  • serde = "1.0" means "compatible with 1.0": any 1.x. For 0.x versions the minor number is the breaking one: "0.14" accepts 0.14.9 but not 0.15.0 ({{Cargo book, SemVer compatibility|https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html}}). Much of the ecosystem is at 0.x, so this matters.
  • Two incompatible versions of one crate can both end up in your program (say rand 0.8 and 0.9). That avoids dependency deadlock, at the cost of a confusing error: two types with the same name that are not the same type.
  • Features are optional parts of a crate switched on at compile time: serde = { version = "1", features = ["derive"] }. They are unified: if any crate in the build turns one on, everyone gets it.
  • Build scripts (build.rs) and procedural macros run code at build time, the same trust question as a Python package's setup code. cargo audit checks the lock file against the RustSec advisory database.

3. Variables and numbers: what differs from Python

[[code:lang/vars.rs]] [[out:l_vars]]
  • let introduces a variable. Its type is inferred from use, like Python, but fixed at compile time: y is an i32 (the default integer type) forever.
  • Immutable by default. Change it and the compiler refuses with E0384, "cannot assign twice to immutable variable", and suggests let mut.
The full E0384[[out:l_vars_err]]

That error has the shape of every Rust error: a code (E0384; rustc --explain E0384 prints a page about it), the file and line, the source with labels under the relevant spans, and usually a help with the fix (+++ marks inserted text).

  • Shadowing: a second let spaces makes a new variable that hides the old one, even with a new type. Useful for "parse this string into a number and keep the name"; it is not mutation.
  • Rust is expression-based: if, match and blocks { ... } produce values. A block's value is its last expression without a semicolon, which is why functions end in sum rather than return sum;.
  • println! ends in ! because it is a macro: code that writes code at compile time. {x} in the format string is like an f-string; {:?} prints the debug form (like repr), {:#?} pretty-prints it.

Numbers: fixed widths, checked overflow

Python's int grows as needed. Rust's integers are the machine's: i8 i16 i32 i64 i128 (signed) and u8 ... u128 (unsigned), plus usize/isize, the pointer-sized types used for lengths and indexes (64 bits here). Floats are f32 and f64. Nothing converts implicitly, not even u32 to f64:

[[code:lang/overflow.rs]] [[pr:l_overflow_debug|In a debug build, what does ./overflow 255 print on its last line?]] [[pr:l_overflow_release|And in a release build (-O)?]]

This is the documented rule ({{Rust Book 3.2, Integer Overflow|https://doc.rust-lang.org/book/ch03-02-data-types.html}}): debug builds check and panic; release builds wrap with two's complement and "relying on integer overflow's wrapping behavior is considered an error". When overflow is possible, say what you want: checked_* (an Option), wrapping_*, saturating_* or overflowing_*. A panic is Rust's crash for bugs: it prints the message and location, unwinds the thread and exits with code 101. If the compiler can see the overflow (255 + 1 as a u8), it refuses outright: "this arithmetic operation will overflow".

The arithmetic differences that bite Python programmers:

  • Integer / truncates toward zero (-7 / 2 is -3, Python's // gives -4); div_euclid and rem_euclid give Python's answers for positive divisors.
  • as never fails: it truncates integers (300 as u8 is 44), reinterprets signs (-1 as u32 is 4294967295), and saturates float to integer (not-a-number becomes 0). Use TryFrom when a value might not fit.
  • Floats are the same IEEE 754 doubles as Python's: 0.1 + 0.2 prints the same.
