The idea in one screen

Every Rust value has exactly one owner, and the compiler checks every borrow of it before the program runs: nothing may use a value after its owner has freed it, or while someone else is changing it. So use after free, dangling references, iterator invalidation and data races become compile errors, with no garbage collector and no reference counts; the price is that you decide who owns what.

Fig. 1 follows one program, the root page's token counter, from cargo build to Python calling it, and pins each idea of the Rust pages where it acts. This page teaches the first four steps; each later step names the child page that owns it and links to that child's own figure.

  1. cargo builds one crate. The token counter as a library with a thin program on top: lib.rs ([[lines:tokstat/src/lib.rs]] lines) declares the modules tokenize.rs ([[lines:tokstat/src/tokenize.rs]] lines) and tally.rs ([[lines:tokstat/src/tally.rs]]), main.rs ([[lines:tokstat/src/main.rs]]) is the binary, and Cargo.toml names two dependencies, serde and serde_json. cargo run --release compiles them into one program (section 2; the module layout is section 6).
  2. The borrow checker decides before anything runs. Every function is checked for one owner per value and for borrows that never overlap a change or outlive their value. gate_err.rs stops here with E0502 (it keeps a reference into a vector across a push); gate_fix.rs, which copies the number out instead, passes. None of this is checked again at run time (section 5 and its lab of fifteen real errors).
  3. One owner on the stack, its buffer on the heap. The program runs. A Vec<u32> is a [[g:l_own_anim|= (\d+)]]-byte header on the stack (pointer, capacity, length; the run printed size_of) and its elements in one heap block, here capacity [[g:l_own_anim|^1 v .* cap=(\d+)]]. The header's owner is v; when v goes, the block goes.
  4. Growth, a move, a drop. push on the full vector copied the elements into a new block of capacity [[g:l_own_anim|^3 v .* cap=(\d+)]] and freed the old one; let w = v copied only the 24-byte header to a new stack slot, the heap block stayed where it was, and v became unusable; drop(w) freed the block at that line. Fig. 2 in section 4 replays the run line by line, at every address it printed.
  5. Enums and traits cost no hidden space. An Option<&u64> is 8 bytes, the same as the reference, because a reference is never null and the all-zero pattern is free to mean None; a trait object &dyn Tokenizer is a 16-byte fat pointer, one word to the value and one to its type's vtable. Owner: {{Rust: enums, traits, errors and iterators|n:4055c17b0d0d8129b199c18b4bd56935}}, whose {{enum figure|n:4055c17b0d0d8129b199c18b4bd56935#stg-lay}} and {{generic against trait object figure|n:4055c17b0d0d8129b199c18b4bd56935#stg-dyn}} draw both.
  6. Shared ownership, and threads. When one owner is not enough, Rc keeps a count beside the value on the heap: three 8-byte handles, strong_count 3, and the value is freed when the count reaches 0. An Rc may not cross into another thread (E0277, "cannot be sent between threads safely"); Arc, whose count is updated atomically, may. Owner: {{Rust: lifetimes, smart pointers, threads and unsafe|n:4055c17b0d0d8160aa32df9cda0aef03}}, with its {{Rc figure|n:4055c17b0d0d8160aa32df9cda0aef03#stg-rc}} and {{threads figure|n:4055c17b0d0d8160aa32df9cda0aef03#stg-thr}}.
  7. tokio runs tasks on a few worker threads. Each request or job is a task; a worker polls it up to its next .await, parks it there and takes another, so a few threads serve many tasks. In that child's 4-worker run, task A started on thread 3 and resumed on thread 5 at 103.8 ms, which is why a spawned task must be Send. Owner: {{Rust: async with tokio, services with axum, and CLIs|n:4055c17b0d0d8148b863faa050cf5456}}, whose {{Fig. 1|n:4055c17b0d0d8148b863faa050cf5456#stg-hero}} draws the runtime.
  8. PyO3 hands it to Python. The same functions, compiled as an extension module, take Python's objects across a boundary: a list of strings is either copied into a Vec<String> (72.7 ns per string) or borrowed as &str views into the Python objects (9.4 ns), as measured there. Owner: {{Rust: speeding up Python with PyO3 and maturin|n:4055c17b0d0d81048311c87e9b76a78a}}, whose {{Fig. 2|n:4055c17b0d0d81048311c87e9b76a78a#stg-cross}} sends one call across.
  9. The whole map. Build, the borrow checker, ownership, moves and modules: this page. Types that carry their cases: the enums child. Sharing, threads and unsafe: the lifetimes child. Tasks and services: the async child. Python: the PyO3 child. Section 9 has the cards.

You need: everyday Python. Nothing else: this page starts from zero for a Python programmer, and the four child pages assume it. If you know C++, section 8 maps its ownership onto Rust's.

Owner, drop
the variable (or field, or vector slot) responsible for a value; when it goes out of scope the value is dropped and its memory freed.
Move
assignment or passing hands ownership over; the old name may not be used again.
Copy, clone()
small plain values (numbers, bool) are copied bit for bit; clone() is the explicit deep copy of anything else.
Borrow: &T, &mut T
a reference that uses a value without owning it: any number of shared (read-only) borrows, or one exclusive (mutable) borrow.
Borrow checker
the part of the compiler that proves every borrow ends before its value is freed or changed by someone else.
Crate, cargo
a crate is a unit of compiled Rust (a library or a program); cargo builds, tests, lints and fetches them.

1. Rust in one screen, for a Python programmer

Rust is the language under much of the Python tooling you already use (uv, ruff, ty, pydantic-core, Hugging Face tokenizers, polars). Python gets memory safety from reference counting and a garbage collector at run time; C++ trusts you. Rust checks a set of rules at compile time and then runs with no collector at all.
