6. Blocking the runtime: the mistake async makes easy

A worker thread can poll only one task at a time, and it gets the thread back only at an .await. A task that calls a blocking function (std::thread::sleep, a synchronous file read, a CPU-heavy loop) holds its worker the whole time, and every other task queued on that worker waits. Alice Ryhl (a tokio maintainer) gives the rule of thumb: "no more than 10 to 100 microseconds between each .await" ({{Async: What is blocking?|https://ryhl.io/blog/async-what-is-blocking/}}). The same three jobs as the Python page (A, B and C wait 100, 200 and 300 ms), five ways:

7. Send + 'static: why tokio::spawn rejects your code

A spawned task can outlive the function that spawned it ('static: it may not borrow its locals) and can move to another worker thread at any .await (Send: everything it holds across an await must be safe to move between threads). Part 1 explains Send and Sync ({{Reading|#t-ra-read}}); here are the three errors they produce in async code, each with the compiler's real message and the fix.

[[pr:errs_e2_borrow_in_spawn|A task that reads a local Vec without move: compiles?]]

The fix is the one the compiler suggests: async move gives the task ownership (clone first if the caller still needs the data; for large shared data, clone an Arc).

[[pr:errs_e3_rc_across_await|An Rc (single-threaded reference counting) kept across an .await inside a spawned task: compiles?]]

Read the note lines: the error names the value (cache, an Rc), the await where it is still alive, and the bound it violates (F: Future + Send + 'static on tokio::spawn). Fix: Arc (atomic counting), or drop the value before the await.

[[pr:errs_e4_mutex_across_await|A std::sync::Mutex guard held across an .await: compiles?]]

This one would be a real bug even on one thread: the lock stays held while the task sleeps, so every other task that wants it blocks its worker. Fix: lock, update, unlock before awaiting (the fixed file prints [[g:errs_e4_mutex_across_await_fix|^(\d+)]]), or use tokio::sync::Mutex, whose guard can be held across awaits, when you truly must.
