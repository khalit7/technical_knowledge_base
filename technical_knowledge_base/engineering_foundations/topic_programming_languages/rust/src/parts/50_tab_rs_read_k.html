Common mistakes

Blocking inside async code
std::thread::sleep, std::fs, a synchronous HTTP client or a long CPU loop inside an async fn stalls its worker and every task queued on it. It hides on a multi-threaded runtime until load arrives (the 300 ms line in the trace above). Use the async API, spawn_blocking, or rayon.
Forgetting that futures are lazy
Calling an async fn without .await (or spawning it) does nothing. The compiler warns ("futures do nothing unless you .await or poll them"); do not silence the warning.
Holding a lock or a non-Send value across .await
A std::sync::MutexGuard or an Rc alive at an await makes the future non-Send, and tokio::spawn refuses it. Scope the guard so it drops before the await; use Arc; reach for tokio::sync::Mutex only when the lock must be held across an await.
Assuming a dropped JoinHandle cancels the task
It detaches it; the task keeps running. Use abort(), or a JoinSet, which aborts its tasks when dropped.
Code that is not cancel safe inside select!
The losing branch is dropped mid-way. If it had read half a message or popped an item, that work is lost. Keep buffers outside the future or use methods documented as cancel safe.
println! in a CLI that may be piped
A closed pipe makes println! panic (exit 101). Write through a locked stdout and treat BrokenPipe as success.
Progress and logs on stdout
They corrupt the output for the next program in the pipe. stdout is for results; stderr for everything else; progress only when is_terminal().
Measuring a debug build
cargo run builds without optimisation. Benchmark and ship --release.
Two body limits
axum's extractors reject bodies over 2 MB regardless of your tower limit. Decide on one limit (DefaultBodyLimit) and test the 413 path.
Dying on SIGTERM
Without graceful shutdown every deploy drops in-flight requests. Wire with_graceful_shutdown to SIGTERM and Ctrl-C.
Comparing frameworks on a hello-world endpoint
Requests per second on /health say little about a service whose time goes to a database or a model. Measure your real handler, open-loop, with the latency percentiles you care about.
