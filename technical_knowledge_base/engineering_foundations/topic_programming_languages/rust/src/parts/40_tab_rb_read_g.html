abi3: one wheel for many Python versions

A wheel per Python version per platform multiplies fast. CPython's stable ABI (the "limited API", PEP 384) is a subset of the C API that is promised not to change; an extension that uses only that subset gets the abi3 tag and loads on that version and every later one. In PyO3 it is a feature flag: pyo3/abi3-py310 (minimum Python 3.10). Built once, installed into fresh virtual environments:

Building for every platform in CI

You cannot build Windows or Linux wheels on a Mac without cross-compilers, so a CI service builds them on each platform. maturin generate-ci github writes a complete GitHub Actions workflow (PyO3/maturin-action does the builds; the generated file is outputs/b10_ci.yml, 186 lines). What it builds, as generated by maturin 1.15.0:

JobTargets
linux (manylinux)x86_64, x86, aarch64, armv7, s390x, ppc64le
musllinuxx86_64, x86, aarch64, armv7
windowsx64, x86, aarch64
macosx86_64 (Intel runner), aarch64
sdistThe source distribution, for anyone with no matching wheel (they need Rust)
releaseOn a git tag: attest the artifacts and upload everything to PyPI

Each build job runs maturin build --release --out dist --find-interpreter, which builds one wheel per Python found (one in total with abi3). The release job, verbatim:

b10_ci.yml
  release:
    name: Release
    runs-on: ubuntu-latest
    if: ${{ startsWith(github.ref, 'refs/tags/') || github.event_name == 'workflow_dispatch' }}
    needs: [linux, musllinux, windows, macos, sdist]
    permissions:
      # Use to sign the release artifacts
      id-token: write
      # Used to upload release artifacts
      contents: write
      # Used to generate artifact attestation
      attestations: write
    steps:
      - uses: actions/download-artifact@v7
      - name: Generate artifact attestation
        uses: actions/attest@v4
        with:
          subject-path: 'wheels-*/*'
      - name: Install uv
        if: ${{ startsWith(github.ref, 'refs/tags/') }}
        uses: astral-sh/setup-uv@v7
      - name: Publish to PyPI
        if: ${{ startsWith(github.ref, 'refs/tags/') }}
        run: uv publish 'wheels-*/*'
        env:
          UV_PUBLISH_TOKEN: ${{ secrets.PYPI_API_TOKEN }}
Change one thing before you use it
The generated job uploads with a long-lived PYPI_API_TOKEN secret. PyPI's trusted publishing removes the secret: you register the repository and workflow on PyPI once, the job (which already has id-token: write) receives a short-lived token from GitHub, and uv publish needs no credentials (uv packaging guide, PyPI trusted publishers). Delete the env: lines after setting it up.

cibuildwheel is the other common route: one tool that builds wheels for every CPython on every platform for any build backend, including maturin; for Rust it must install a Rust toolchain inside its Linux containers (cibuildwheel FAQ, "Building Rust wheels"). maturin-action is the simpler choice for a Rust-only package; cibuildwheel suits projects that also run test suites per wheel or mix C, C++ and Rust. tokrs was not uploaded to PyPI for this page; the steps above are what would publish it.
