18. If you know some C++

Optional. Rust's ownership is C++'s RAII plus move semantics, with the compiler enforcing what the C++ Core Guidelines only recommend ({{C++ page|n:3cd5c17b0d0d81ceadcee44fe9c023a0}}, Part 1, teaches the C++ side).

19. Common mistakes, and the habit that replaces each

Cloning until it compiles.
Each clone() of a String or Vec allocates and copies. Ask first whether the callee could borrow (&str, &[T]), whether the value could move, or whether its last use could come earlier. Clone small things freely; never in a hot loop without a reason.
Rc<RefCell<T>> everywhere to recreate Python's object graph.
It compiles and then panics at run time (section 15). Give the data one owner (often a struct holding Vecs) and refer to items by index.
&String or &Vec<T> parameters.
Take &str and &[T]: they accept more callers and are what clippy suggests (section 1).
Byte indexes on text.
s.len() is bytes and &s[0..n] panics inside a character (section 7). Use chars(), char_indices(), or a byte-level algorithm on purpose (the token counter works on bytes because tokens are ASCII).
unwrap() in library code.
Return Result and use ?; reserve expect("reason") for states you can prove impossible.
Expecting dict order from HashMap.
Its order changes between runs (section 12). Sort, or use BTreeMap, or a Vec of pairs.
Timing a debug build.
cargo run is unoptimised; measure with --release. And a release build silently wraps on overflow: use checked_* where it matters (section 3).
Lifetimes in every struct.
Store owned data first; borrow in structs only when a profile says the copies matter (section 6).
Blocking inside async code.
A long computation or a blocking file read inside an async fn stalls every task on that thread; Part 3 shows spawn_blocking.
