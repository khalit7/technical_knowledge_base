Every Rust value has exactly one owner, and the compiler checks every borrow of it before the program runs: nothing may use a value after its owner has freed it, or while someone else is changing it. So use after free, dangling references, iterator invalidation and data races become compile errors, with no garbage collector and no reference counts; the price is that you decide who owns what.

One Vec, at its real addresses: a borrow copies nothing, growth moves the buffer, a move copies 24 bytes, drop frees at a known line

One small program, stepped line by line. A Rust Vec is a 24-byte header on the stack (pointer, capacity, length) and a buffer on the heap. Every address and number below was printed by the program itself when it ran (rustc 1.99.0). Predict first: after let w = v;, which address changes, the stack slot or the heap block? Then step. Switch to Python for the same steps in Python's model: names pointing at one object, and a reference count.

The captions name what changes at each step, and the counters under the figure keep the score: allocations, live blocks, bytes copied by moves, elements copied.

What the run shows, in six lines
  • Borrowing never copies. r and m are 8-byte pointers to v's stack slot (the same address the program printed for v).
  • Growth moves the buffer. push on a full vector allocated a new block (capacity 3 to 6) and freed the old one. That is exactly why the borrow checker refuses a reference into the buffer across a push (section 5).
  • A move copies 24 bytes, not the data. w has a new stack address but the same heap address as v had; v is unusable afterwards.
  • Clone allocates. c got its own buffer; on this run the allocator handed it the block freed at step 3 (heap 0x102d3d4a0, the same as step 1). Reusing freed memory is normal, and is why a dangling pointer can read someone else's data in C++.
  • Drop frees at a known line. drop(w) released the second buffer immediately; c is freed at the closing brace of main.
  • In Python every step after the first only adds a name to one object (the count rises to 4); copy() is the only new allocation; del w removes a name, not the object.

own_anim.rs
// Prints the real addresses behind the ownership animation: a Vec is three
// machine words on the stack (pointer, capacity, length) and a buffer on the heap.
fn show(step: &str, name: &str, v: &Vec<u32>) {
    println!(
        "{step} {name} stack={:p} heap={:p} len={} cap={} data={:?}",
        v as *const Vec<u32>, v.as_ptr(), v.len(), v.capacity(), v
    );
}

fn main() {
    println!("size_of::<Vec<u32>>() = {}", std::mem::size_of::<Vec<u32>>());
    let mut v: Vec<u32> = Vec::with_capacity(3);
    v.extend([10, 20, 30]);
    show("1", "v", &v);
    let r = &v; // a shared borrow: a pointer to v's stack slot
    println!("2 r points to {:p} (v's stack slot), r.len()={}", r as *const Vec<u32>, r.len());
    v.push(40); // r is no longer used, so v may be mutated: the buffer is full, so it grows
    show("3", "v", &v);
    let m = &mut v; // one exclusive borrow
    m[0] = 11;
    println!("4 m points to {:p}, wrote m[0]=11", m as *const Vec<u32>);
    let w = v; // move: the three words are copied to w's slot, the heap buffer is not touched
    show("5", "w", &w);
    let c = w.clone(); // clone: a new heap buffer with a copy of the elements
    show("6", "c", &c);
    drop(w); // w's buffer is freed now
    println!("7 dropped w");
    show("8", "c", &c);
}

Owner, drop
the variable (or field, or vector slot) responsible for a value; when it goes out of scope the value is dropped and its memory freed.
Move
assignment or passing hands ownership over; the old name may not be used again.
Copy, clone()
small plain values (numbers, bool) are copied bit for bit; clone() is the explicit deep copy of anything else.
Borrow: &T, &mut T
a reference that uses a value without owning it: any number of shared (read-only) borrows, or one exclusive (mutable) borrow.
Borrow checker
the part of the compiler that proves every borrow ends before its value is freed or changed by someone else.
Crate, cargo
a crate is a unit of compiled Rust (a library or a program); cargo builds, tests, lints and fetches them.

Rust is the language under much of the Python tooling you already use (uv, ruff, ty, pydantic-core, Hugging Face tokenizers, polars). Python gets memory safety from reference counting and a garbage collector at run time; C++ trusts you. Rust checks a set of rules at compile time and then runs with no collector at all.
