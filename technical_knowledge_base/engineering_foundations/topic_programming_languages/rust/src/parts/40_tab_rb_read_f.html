Read it as a story. Steps 1 to 3 move only the token loop: a 3x gain, and batching (step 3) barely beats one call per message, because once the loop is in Rust the program is waiting on json.loads. Copying the strings (step 2) is visibly slower than borrowing them (step 3). Step 4 moves the parsing too: Python reads the file as bytes and makes one call; serde parses each line straight into a typed struct, and the program runs times faster than the Python version. Step 5 releases the GIL and splits the file over 8 rayon threads. The root's own whole-file PyO3 variant measured s (one thread) and s (4 threads), in line with steps 4 and 5.

The phases (from ladder.py --phases): the Rust part fell from ms to ms (x on a busy laptop with 2 of its 10 cores slower efficiency cores). 11. Type stubs and tests

A compiled module has no Python source, so mypy, ty and your editor cannot see its signatures. You give them a stub file (.pyi): Python syntax with ... for bodies, read only by type checkers. For a project like this one (Rust only, no Python package directory), maturin picks up <module>.pyi next to Cargo.toml and adds it to the wheel with a py.typed marker (maturin: adding Python type information). test_tokrs.py
def test_matches_python_on_every_message():
    texts = []
    for line in CHAT.read_text(encoding="utf-8").splitlines():
        try:
            rec = json.loads(line)
        except ValueError:
            continue
        if isinstance(rec, dict) and isinstance(rec.get("text"), str):
            texts.append(rec["text"])
    assert tokrs.count_many(texts) == [py_tokens(t) for t in texts]


def test_whole_file_matches_program_md():
    lines, ok, bad, first_bad, per_user = tokrs.tally_file(CHAT)
    assert (lines, ok, bad, first_bad) == (2000, 1992, 8, 53)
    assert sum(per_user.values()) == 44698 and per_user["u0029"] == 9491
