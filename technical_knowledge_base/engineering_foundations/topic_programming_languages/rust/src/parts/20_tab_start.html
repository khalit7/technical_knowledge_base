Start here

This page teaches Rust from zero to someone who knows Python, for two jobs: making slow Python fast with a Rust extension, and writing services and command-line tools. It has three parts; pick one with the buttons above. Every output, compiler error and number comes from a real run on an Apple M1 Pro on 2026-10-05 (rustc 1.99.0, PyO3 0.29.3, tokio 1.53.2, axum 0.8.9, clap 4.6.7), and each part's sources and run scripts are in the repository. Parts 2 and 3 assume Part 1: they link back to the sections on ownership, Result and ?, and Arc, Send and Sync where they use them.

Part 1: For Python programmers

About 45 minutes. Tabs: Reading, Ownership animated, Borrow-checker lab, Python to Rust drill.
cargo, variables and numbers, ownership and moves, borrowing, lifetimes, strings, structs and enums, Option and Result, traits and generics, iterators, collections, modules, testing, smart pointers, threads without data races, unsafe, and the common mistakes.
  • Start: {{Reading|#t-ra-read}}.
  • Learn to read the compiler: {{Borrow-checker lab|#t-ra-bc}} (15 real errors and their fixes).

Part 2: Speeding up Python

About 35 to 40 minutes. Tabs: Reading, Optimisation ladder, Crossing the boundary.
PyO3 and maturin from one function to a published wheel: whether to port at all, conversions and their cost, NumPy without copies, errors, classes, releasing the GIL with rayon, free-threaded 3.14t, type stubs and tests, wheels and abi3, who ships Rust to Python users, and the alternatives measured.
  • Start: {{Reading|#t-rb-read}}.
  • The root's token counter from 1.36 s to 0.059 s in six steps: {{Optimisation ladder|#t-rb-ladder}}.

Part 3: Services and CLIs

About 45 minutes. Tabs: Reading, Async replay, Service benchmark, CLI replay.
A CLI with clap, shipping a binary (sizes, static Linux builds), async Rust from zero with tokio, an HTTP service with axum, testing, deployment, the same service measured against FastAPI, and Rust in ML serving.
  • Start: {{Reading|#t-rs-read}}.
  • The same three jobs on tokio, asyncio and Node: {{Async replay|#t-rs-async}}.

Three ways through

"I have slow Python and want it fast." Part 1 sections 1 to 9 and 15 to 16 (enough Rust for an extension), then Part 2 in order. Profile first: Part 2 section 1 shows when porting does not help.
"I want to write a service or a CLI." Part 1 in order, then Part 3; the {{Async replay|#t-rs-async}} compares tokio with the asyncio you know.
"I just want to understand Rust." Part 1 with its three labs; the {{Python to Rust drill|#t-ra-drill}} checks you.

Five things the runs showed

FindingWhere
A while loop, a for loop, an iterator chain and a generic closure all compiled to the same speed, about 0.29 ns per element; CPython took 71.4 ns for the same loop.Part 1, iterators
Moving only the counting into Rust took the program from 1.358 s to 0.466 s; moving the JSON parsing too took it to 0.112 s, and releasing the GIL with 8 threads to 0.059 s (23 times faster). Port the whole pipeline, not one function.Part 2, Optimisation ladder
On free-threaded 3.14t, a Rust class with a &mut self method shared by 8 threads raised "Already borrowed" on 13% of calls; a frozen class with a Mutex fixes it.Part 2, section 9
The same service in axum and FastAPI (4 workers each): 4,804 against 206 requests/s counting a 391 KB log, and 27 against 281 MB of memory.Part 3, Service benchmark
CPU work inside an async handler slowed every other request (/health median 10.7 ms); moving it to spawn_blocking brought it back to 0.44 ms.Part 3, async
