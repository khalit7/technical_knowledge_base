One call, three items, step by step: what happens to the arguments when Python calls Rust. Toggle between the copying signature and the borrowing one to see the same input cross both ways.

The objects and steps follow what PyO3 0.29 and CPython 3.14 do (the str layouts are PEP 393; the UTF-8 cache is filled by PyUnicode_AsUTF8AndSize). The nanosecond figures come from the measurements in {{Reading, section 4|#t-rb-read}} on 20,000 messages and a million floats, not from these three items.

What to take from it
Copies cost an allocation and a byte copy per item, and the copy must be freed again; views cost a type check and a pointer. The only extra work a view can trigger is the one-time UTF-8 encoding of a non-ASCII str, which CPython then keeps inside the string object.
When to copy anyway
When Rust must keep the data after the call (store it in a #[pyclass], or hand it to a thread that outlives the call). Views of immutable str and bytes may even be used with the GIL released, as tally_bytes_detached does).
