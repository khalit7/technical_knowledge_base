Rust turns what a Python program discovers while it runs into types the compiler checks before it runs: an enum says exactly which data each case carries and match must handle every case, Result puts every failure in the signature, a trait says what a type can do, and the iterator chains built on all of this compile to the same machine code as the loop you would have written by hand.

The Rust side of each row is a recorded run on this page: a missing match arm is error E0004 (section 2); a maybe-missing value is an Option and a failed parse of "8k" a Result, and you get the value inside only by deciding what happens in the other case (section 3); a type without the trait is E0277 at the call (section 4). The Python side is what the same mistake does in plain Python with no type checker. One exception stays a run-time failure in Rust too: a string slice that cuts a character panics (section 1). And the price of all this checking in a hot loop is none: an iterator chain ran at 0.293 ns per element, the hand-written loop at 0.290 (section 5) measured.

1. Strings and slices: String against &str, and UTF-8

A slice is a borrowed view into a run of elements owned by someone else: a pointer and a length. &[u64] is a slice of numbers (borrowed from a Vec, an array or part of either); &str is a slice of text. Rust has two main string types:

String&str
Whatowned, growable text on the heapa borrowed view of text (in a String, a literal, a file buffer)

Make oneString::from("x"), "x".to_string(), format!(...)&s, &s[a..b], "literal"

Both are always valid UTF-8, and lengths and indexes are in bytes; Python's str counts code points. The text below is the one the recorded program uses: 10 characters, 20 bytes.
