3. ruff: lint and format

A linter reads your code without running it and reports likely bugs and style problems; a formatter rewrites layout (spacing, line breaks, quotes) so nobody argues about it. ruff does both, in Rust, and replaced flake8 and its plugins, isort, pyupgrade and black. Here is a file with eight problems you have probably written yourself:

New in ruff 0.16 (2026-07-23): the default set grew from 59 to 413 rules
That is why the first run already reports isort (I), pyupgrade (UP), bugbear (B), simplify (SIM) and bandit (S) findings with no configuration at all. The release also removed 18 pycodestyle and pyflakes rules from the default set, among them E711 (== None) and E401 (two imports on one line), which is why those two appear only once they are selected explicitly below ({{ruff changelog|https://github.com/astral-sh/ruff/blob/main/CHANGELOG.md}}). Pin ruff in your dev group, or one upgrade can fail every CI run.

--fix applied nine safe fixes (sorted and pruned imports, list for List, str | None for Optional[str], the empty f-string). The five that remain need a human: a mutable default argument (seen=[] is created once and shared by every call), a file opened without with and never closed, a try/except/pass that ruff suggests writing as contextlib.suppress, a bare except that also swallows KeyboardInterrupt, and == None (use is None). "Unsafe" fixes (--unsafe-fixes) are the ones that can change behaviour, so ruff never applies them silently.

A small starting configuration in pyproject.toml (written for this page, not run as shown):

[tool.ruff] target-version = "py314" # lets UP rules rewrite to the newest syntax you support line-length = 100 [tool.ruff.lint] extend-select = ["E711", "E401"] # add back what 0.16 removed, if you want it ignore = ["S101"] # assert is fine in tests
What it costs
Nothing at run time. The cost is noise: a large default rule set on an old codebase reports hundreds of findings. Adopt it with ruff check --add-noqa once (it writes suppression comments for existing findings) and fix new code only, or start from an explicit select list.

4. Type checking in practice: ty, mypy and pyright on the same code

Python ignores annotations at run time; a type checker reads them and reports code that would fail. Three are worth knowing: mypy (the original, 2012, now 2.4.0 and actively developed), pyright (Microsoft, written in TypeScript, the engine behind VS Code's Pylance) and ty (Astral, Rust, beta since 2025-12-16, still version 0.0.84). The root page shows all three agreeing on the easy case, passing an int where a str is expected. Here are eight harder ones. Pick a case, guess which checkers flag it, then reveal their real output.

Run with --python-version 3.14 on each file separately: ty 0.0.84, mypy 2.4.0 (--no-incremental), pyright 1.1.414, all through uvx. Source: src/pb/types/run_checkers.sh.

What the grid teaches:

  • Unannotated means unchecked. A parameter without an annotation is Any, and no checker reports add_one("a") by default. mypy's --strict reports that the function has no annotations at all, which is the useful complaint.
  • Defaults differ. pyright reports a possibly unbound variable by default; ty and mypy have the rule but leave it off (--error possibly-unresolved-reference, --enable-error-code possibly-undefined).
  • Messages differ more than verdicts. On the shared cases they agree; ty and mypy add hints (list is invariant, use Sequence; "Maybe you forgot to use await?").
  • Invariance surprises everyone once: a list[int] is not a list[float], because the function could append a float to your list of ints. Accept Sequence[float] when you only read.

Speed on a real codebase

Which one to choose
Speed is not the question on most projects: all three are fast enough on a hundred files. Choose by where you read the errors. If your editor is VS Code, pyright is already running (as Pylance), so using pyright in CI means CI says what the editor said. mypy has the largest plugin ecosystem (Django, SQLAlchemy, pydantic) and the most documentation. ty is the fastest and its messages are the clearest here, but it is a 0.0.x beta whose rules still change. Whichever you pick, pin its version and run it in CI; a type checker that only runs on your laptop checks nothing.
