7. Exceptions done well

An exception is an object; raise unwinds the stack until an except clause whose class matches (by isinstance, in the order written). Since 3.11 a try that raises nothing costs nothing ("zero-cost" exceptions, {{What's new in 3.11|https://docs.python.org/3/whatsnew/3.11.html}}), so "ask forgiveness, not permission" (try it and catch the failure) is not a performance sin.

The hierarchy, and what except Exception does not catch

Everything derives from BaseException. Ordinary errors derive from its subclass Exception; four do not, on purpose, so that a broad except Exception: lets them through: KeyboardInterrupt (Ctrl-C), SystemExit (sys.exit()), GeneratorExit (section 3) and, since 3.8, asyncio.CancelledError (section 10). Give your own library one root exception so callers can catch "anything from this client" with one clause, and specific subclasses carrying data (here retry_after) for the cases callers handle differently.

e3_hierarchy.py
class LLMError(Exception):
    """Root of everything this client raises: callers can catch one type."""

class RateLimited(LLMError):
    def __init__(self, retry_after: float):
        super().__init__(f"rate limited, retry after {retry_after}s")
        self.retry_after = retry_after

class ContextTooLong(LLMError):
    pass

def complete(prompt_tokens):
    if prompt_tokens > 8192:
        raise ContextTooLong(f"{prompt_tokens} tokens > 8192")
    raise RateLimited(retry_after=1.5)

for n in (100, 10_000):
    try:
        complete(n)
    except RateLimited as e:              # most specific first
        print("wait", e.retry_after)
    except LLMError as e:                 # then the family
        print(type(e).__name__, e)

print([c.__name__ for c in RateLimited.__mro__])
print(issubclass(KeyboardInterrupt, Exception), issubclass(KeyboardInterrupt, BaseException))
print(issubclass(TimeoutError, OSError))
import asyncio
print(issubclass(asyncio.CancelledError, Exception))

Correction to the old page
The old page listed as a trap "Catching Exception around a block that includes a KeyboardInterrupt-sensitive call". except Exception does not catch KeyboardInterrupt (output above: False True); the real trap is a bare except: or except BaseException:, which does, and so makes a program impossible to stop with Ctrl-C or to cancel in asyncio.

Chaining: raise ... from

Raising inside an except block records the original exception as __context__, and the traceback says "During handling of the above exception, another exception occurred", which reads like a second bug. raise NewError(...) from e sets __cause__ and says "The above exception was the direct cause", which is what you meant: translate a low-level error into your own while keeping the evidence. from None hides the original.

e1_chain.py
import json, sys, traceback

class ConfigError(Exception):
    pass

def load(text):
    try:
        return json.loads(text)
    except json.JSONDecodeError as e:
        raise ConfigError("config is not valid JSON") from e    # explicit cause

def load_sloppy(text):
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        raise ConfigError("config is not valid JSON")           # implicit context

for fn in (load, load_sloppy):
    try:
        fn("{bad")
    except ConfigError as e:
        print(f"--- {fn.__name__}: __cause__={type(e.__cause__).__name__}, "
              f"__context__={type(e.__context__).__name__}, __suppress_context__={e.__suppress_context__}")
        traceback.print_exc(limit=0, file=sys.stdout)   # limit=0: messages only

Exception groups, except* and notes

Concurrent code can fail in several places at once. Since 3.11 an ExceptionGroup carries several exceptions, except* handles each matching subset ({{PEP 654|https://peps.python.org/pep-0654/}}), and asyncio.TaskGroup raises one when tasks fail. e.add_note(...) ({{PEP 678|https://peps.python.org/pep-0678/}}) attaches context without changing the exception's type.

e2_group.py
import asyncio

async def call(name, fail):
    await asyncio.sleep(0.01)
    if fail:
        raise fail(f"{name} failed")
    return name

async def main():
    try:
        async with asyncio.TaskGroup() as tg:            # 3.11+: structured concurrency
            tg.create_task(call("search", None))
            tg.create_task(call("rerank", TimeoutError))
            tg.create_task(call("embed", ValueError))
    except* TimeoutError as eg:                          # handles the TimeoutError part
        print("timeouts:", [str(e) for e in eg.exceptions])
    except* ValueError as eg:                            # and, separately, the ValueError part
        print("bad values:", [str(e) for e in eg.exceptions])

asyncio.run(main())

eg = ExceptionGroup("batch failed", [KeyError("a"), ValueError("b"), KeyError("c")])
match, rest = eg.split(KeyError)
print(repr(match), repr(rest), sep="\n")

try:
    try:
        {}["model"]
    except KeyError as e:
        e.add_note("while reading config.yaml, section 'llm'")   # 3.11+
        raise
except KeyError as e:
    print(repr(e), e.__notes__)

Habits
Catch the narrowest exception you can handle; let the rest propagate; translate at boundaries with raise ... from; log with the traceback (logger.exception) once, at the top.
Mistakes
Bare except:; except Exception: pass; catching around more code than the call that can fail; raising Exception("...") instead of a specific class.

8. Context managers: with

with m as r: calls m.__enter__(), binds its return value to r, runs the body, and then always calls m.__exit__(exc_type, exc, tb), with the exception if one was raised and Nones if not. If __exit__ returns a true value the exception is swallowed. It is try/finally packaged as an object, for anything that must be released: files, locks, connections, GPU memory pools, timers, temporary settings such as torch.no_grad().

contextlib.contextmanager writes the class for you from a generator: the code before yield is __enter__, the code after it (in a finally) is __exit__. Several managers in one with are entered left to right and exited right to left. ExitStack handles a number of resources known only at run time ({{contextlib|https://docs.python.org/3/library/contextlib.html}}).

x1_with.py
import contextlib, time

class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                                   # bound to the name after `as`
    def __exit__(self, exc_type, exc, tb):
        self.ms = (time.perf_counter() - self.t0) * 1000
        print(f"Timer exit: exc_type={exc_type.__name__ if exc_type else None}")
        return False                                  # do not swallow exceptions

with Timer() as t:
    sum(range(100_000))
print(f"{t.ms:.1f} ms")

@contextlib.contextmanager                            # the same protocol, written as a generator
def opened(name):
    print(f"open {name}")
    try:
        yield name.upper()                            # the value bound by `as`
    finally:
        print(f"close {name}")                        # runs even if the body raises

try:
    with opened("a") as a, opened("b") as b:          # entered left to right...
        print("body", a, b)
        raise KeyError("oops")
except KeyError:
    print("KeyError reached the caller")              # ...exited right to left

with contextlib.ExitStack() as stack:                 # a number of resources known only at run time
    names = [stack.enter_context(opened(n)) for n in ("x", "y", "z")]
    print("using", names)

with contextlib.suppress(FileNotFoundError):
    open("/no/such/file")
print("suppressed")

The async form, async with, calls __aenter__ and __aexit__, which may await (opening a connection, releasing a semaphore); section 10 uses it for asyncio.timeout, TaskGroup and Semaphore.

The mistake
Writing @contextmanager without try/finally around the yield. If the body raises, the exception is thrown in at the yield, and any cleanup written after it without finally never runs.
