7. What changed from 3.12 to 3.15, and what it means for your code

A new CPython ships every October (PEP 602) and gets two years of bug fixes, then security fixes until five years. On 2026-10-05: 3.14 is the bugfix line (3.14.8), 3.12 and 3.13 get security fixes only, and 3.15 is at its third release candidate with the final expected on 2026-10-09 ({{PEP 790|https://peps.python.org/pep-0790/}}; {{devguide|https://devguide.python.org/versions/}}). Corrections to the old page "Python: staying current"
  • "Python 3.15 is due 2026-10-01": a third release candidate was added (2026-10-02); final now expected 2026-10-09 (PEP 790).
  • "Python 3.15 ... lazy imports and abi3t are its headline items": true but incomplete; What's New also lists frozendict, sentinel, UTF-8 as the default encoding, unpacking in comprehensions, the Tachyon profiler and the JIT upgrade as highlights.
  • "abi3t lets NumPy-class extensions ship one wheel per platform": imprecise. One cp315-abi3.abi3t wheel covers 3.15 and later on both builds, but free-threaded 3.14 still needs its own wheel, and of 25 popular compiled packages only one (cryptography) ships an abi3t wheel today (section 6).
  • "from __future__ import annotations is finally obsolete": imprecise. It still works and is deprecated; What's New 3.14 says removal will not happen before 3.13's end of life in 2029.
  • "t-strings ... showing up in LLM prompt-templating libraries": no source given; not confirmed here, so left out.

8. Lazy imports (3.15), measured

A Python program's start-up time is mostly imports: each import finds a file, loads or compiles its bytecode and runs all its top-level code, including its own imports. A command-line tool that imports httpx, pydantic and rich at the top pays for all three even when the user only asked for --help. Until now the fix was to move imports inside functions. 3.15 adds lazy import: the name is bound to a lightweight proxy and the module loads the first time the name is used.

import argparse lazy import httpx # was: import httpx lazy import pydantic # was: import pydantic lazy from rich.console import Console # was: from rich.console import Console

What it costs, and when not to use it
  • Errors move: a misspelled module raises at first use, not at start-up; the traceback shows both places.
  • Import side effects (a plugin registering itself, logging configured at import) happen later or never. Do not make such imports lazy; the global all mode can be filtered with sys.set_lazy_imports_filter.
  • Only at module level: lazy inside a function, a class body or a try block is a SyntaxError, and so is lazy from x import *.
  • Code that must also run on 3.14 or older cannot use the keyword (it is a SyntaxError there; see the {{Version explorer|#t-pb-ver}}); list the modules in __lazy_modules__ instead, which older versions ignore.
