2. Names, objects and references

A Python object is a block of memory that knows its type, its value and how many references point at it. A name (a variable) is an entry in a namespace, a dict-like table from strings to objects. Assignment, b = a, writes a second entry pointing at the same object. Nothing is copied. Two names for one object are aliases.

Whether aliasing matters depends on mutability: whether the object can change after it is made. Lists, dicts, sets and most of your own classes are mutable. Ints, floats, strings, tuples, frozensets and bytes are immutable: every "change" builds a new object and rebinds the name. Predict what b holds before you open the answer:

Two questions about two names: equal, or the same object?

a == b asks "equal values?" and calls __eq__; a is b asks "the same object?" and compares identities (the address, in CPython). Use is only for singletons such as None; for everything else it answers a question you did not mean to ask.

n2_identity.py
a = [1, 2]
b = [1, 2]
print(a == b, a is b)          # equal values, two objects

x, y = 256, int("256")
print(x is y)                  # CPython keeps one shared object for -5..256
x, y = 257, int("257")
print(x is y)                  # outside that range: two objects
print(x == y)                  # == is the question you meant to ask

The 256 against 257 split is an implementation detail: "The current implementation keeps an array of integer objects for all integers between -5 and 256" ({{C API: integer objects|https://docs.python.org/3/c-api/long.html}}). Strings are the same story: some are interned (one shared object), and sys.intern forces it. Code that relies on it works in tests with small numbers and breaks in production with large ones. Why the cache exists, and what each object costs, is {{CPython internals and performance|n:4055c17b0d0d8111872ad7101b7e3c22}}, section 2.

The default argument that remembers

A function's default values are evaluated once, when def runs, and stored on the function object; a mutable default is therefore one object shared by every call that does not pass its own. The fix is None as the default and a new list inside.

Default argument
def f(x, seen=[]):
    seen.append(x)
    return len(seen)
print(f('a'), f('b'), f('c', []), f('d'))

A call that passes its own list leaves the shared one alone; the next call that relies on the default picks up where the shared list left off. h1_hero.py
"""The hero of "Python: the essentials": three lines, and what each one does to names, objects and methods."""
import dis, sys

x = [1, 2]
print("refs to the list after x = [1, 2]:", sys.getrefcount(x) - 1)   # getrefcount counts its own argument; subtract it
y = x
print("after y = x:      y is x ->", y is x, "| refs:", sys.getrefcount(x) - 1)
y.append(3)
print("after y.append(3): x ->", x)
z = x + [4]
rz = sys.getrefcount(z) - 1   # measured before print, whose argument tuple would hold one more
print("after z = x + [4]: x ->", x, "| z ->", z, "| z is x ->", z is x, "| refs to z:", rz)
print("x + [4] calls      ->", type(x).__add__)
print("y.append is found on ->", type(y).append)

print("\nbytecode of the three lines (dis, CPython", sys.version.split()[0] + "):")
dis.dis(compile("y = x\ny.append(3)\nz = x + [4]", "<hero>", "exec"))
