The idea in one screen

In Python a name is only a reference to an object, and every piece of syntax is a method call on the object's type, run as bytecode by one interpreter that counts references to each object and, in the default build, lets one thread run at a time. Almost every surprise a working Python programmer meets follows from that sentence.

Fig. 1 follows one small program, the three lines of section 2's figure saved as app.py, from install to run. Steps 3 to 7 are the five facts behind almost every surprise; each names the child page that owns it and links that page's own figure. The instruction names and reference counts drawn are this page's real run on CPython 3.14.8 (Fig. 2).

  1. One program, start to finish. Before it runs, uv installs what it imports into an environment and a type checker reads its hints. Then CPython compiles it to bytecode, one loop runs that bytecode, every value lives as an object on the heap, and in the default build one thread at a time holds the loop.
  2. Installed: the environment comes from a lock. pyproject.toml says what you asked for, uv.lock what one resolution picked, and uv sync makes .venv match the lock exactly, so a package added by hand with pip install is gone after the next sync. Owner: {{Python: typing, uv, packaging and the toolchain|n:4055c17b0d0d8192878fce7505cc612f}}, whose {{Fig. 2|n:4055c17b0d0d8192878fce7505cc612f#stg-uv}} replays a real uv session.
  3. Checked: hints are for tools. Annotations are not checked when the program runs; a type checker (ty, mypy, pyright or pyrefly) reads them before, in the editor or in CI, and Python itself never does. Owner: the toolchain page, whose {{Fig. 1|n:4055c17b0d0d8192878fce7505cc612f#stg-hero}} runs five deliberate mistakes past two checkers and past Python.
  4. Compiled and run: one loop runs bytecode. CPython compiles the file to bytecode, and a loop written in C runs it one instruction at a time: y = x is LOAD_NAME then STORE_NAME, y.append(3) finds the method with LOAD_ATTR, and + is BINARY_OP. Because every operation goes through this loop, on arrays of a thousand elements and up a Python loop was 10 to 16 times slower than one NumPy call: profile first, then move the loop out of Python. Owner: {{Python: CPython internals and performance|n:4055c17b0d0d8111872ad7101b7e3c22}}, whose {{Fig. 3|n:4055c17b0d0d8111872ad7101b7e3c22#stg-eval}} steps one function through the loop.
  5. Names point at objects. Every value is an object on the heap that knows its type and how many references point at it; a name is only an entry in a namespace. Assignment never copies: y = x gives one object a second name and its reference count goes from 1 to 2, so mutation through either name is visible through both. Copies happen only when you ask (.copy(), copy.deepcopy, a slice). Section 2 below; what each object costs and how counting frees it are the internals page's {{Fig. 4|n:4055c17b0d0d8111872ad7101b7e3c22#stg-obj}} and {{Fig. 5|n:4055c17b0d0d8111872ad7101b7e3c22#stg-rc}}.
  6. Syntax calls methods on the type. y.append(3) runs type(y).append(y, 3), found on list, so x sees the change; x + [4] runs list.__add__, which builds a new list with 1 reference. len(x), for, ==, with and x.attr are each a fixed lookup of a double-underscore ("dunder") method on the type, with documented fallbacks. Laziness is a protocol too (an iterator is any object with __next__; a generator is a function that pauses at yield), and def and class are statements that create objects at run time, which is why decorators, closures and descriptors work the way they do. Owner: {{Python: the data model and protocols|n:4055c17b0d0d816a8705e4d3f20b3da7}}, whose {{Fig. 1|n:4055c17b0d0d816a8705e4d3f20b3da7#stg-hero}} climbs each lookup and {{Fig. 7|n:4055c17b0d0d816a8705e4d3f20b3da7#stg-look}} the attribute lookup.
  7. One thread runs bytecode at a time. In the default build the GIL lets one thread at a time run the loop. The GIL makes threads useful for waiting, not for computing; processes or native code compute in parallel; asyncio runs thousands of waits on one thread, provided nothing blocks it. Owner: {{Python: concurrency, asyncio and the GIL|n:4055c17b0d0d81bdbee8c37d80b55a0e}}, whose {{Fig. 1|n:4055c17b0d0d81bdbee8c37d80b55a0e#stg-hero}} shows who runs bytecode six ways and {{Fig. 3|n:4055c17b0d0d81bdbee8c37d80b55a0e#stg-loop}} replays a real event loop.

You need: to write everyday Python. Nothing else on this page is assumed. How Python compares with C++, Rust and TypeScript (types, memory, errors, concurrency, speed), with the same program written in all four, is the parent page {{Topic: programming-languages|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}}.

Name
an entry in a namespace (a dict-like table from strings to objects); it holds a reference, never a value.
Object
a block of memory that knows its type, its value and how many references point at it.
Alias
a second name for the same object.
Mutable
can change after it is made (list, dict, set, most classes); immutable types (int, float, str, tuple, frozenset, bytes) never do.
Special ("dunder") method
a double-underscore method such as __add__ that syntax calls on the type.
Bytecode
the instructions CPython compiles your code to and runs one at a time in a loop written in C.
GIL
the global interpreter lock: in the default build only the thread holding it runs bytecode.
