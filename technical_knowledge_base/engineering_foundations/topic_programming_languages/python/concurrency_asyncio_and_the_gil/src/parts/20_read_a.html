The idea in one screen

In the default CPython build one lock, the GIL, lets only one thread run Python bytecode at a time, so threads overlap waiting but never computing. asyncio replaces many waiting threads with one event loop that switches tasks only at an await, so a single blocking call stalls every task. To compute in parallel you need several GILs (processes, subinterpreters), no GIL (the free-threaded build), or native code that releases it.

GIL
the global interpreter lock: only the thread holding it runs Python bytecode.
Free-threaded build
CPython compiled without the GIL (python3.14t), installed separately.
Coroutine
what calling an async def function returns: a paused computation that runs only when awaited or wrapped in a task.
Task
a coroutine scheduled on the event loop, so it runs concurrently with other tasks.
Event loop
one thread that runs ready tasks until each reaches an await, and wakes them when what they wait for happens.
Cooperative
a task gives up the thread only at an await; nothing interrupts it.
Subinterpreter
a second, isolated interpreter in the same process, with its own GIL.
CPU-bound, I/O-bound
limited by computing, or by waiting (network, disk, a model API).
