1. Bytecode, and how it rewrites itself while running

CPython, the standard Python, is a C program. It compiles your source to bytecode, instructions for a virtual stack machine (cached in __pycache__/*.pyc), and an evaluation loop in C executes them one by one. The root page's {{How code runs|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}} section follows one line through Python, C++, Rust and JavaScript; this section is CPython's half, seen with the dis module.

Since 3.11 the interpreter is specialising and adaptive ({{PEP 659|https://peps.python.org/pep-0659/}}): after an instruction has run a few times it is rewritten in place into a version specialised for the types it saw, guarded by a cheap check; if the check starts failing, it falls back and re-specialises. "Python 3.11 is between 10-60% faster than Python 3.10", 1.25x on average ({{What's new in 3.11|https://docs.python.org/3/whatsnew/3.11.html}}, vendor figure), largely from this. dis.dis(f, adaptive=True) shows the live, rewritten instructions. BINARY_OP (+), which must handle every type with an __add__, became BINARY_OP_ADD_INT, then BINARY_OP_ADD_FLOAT when the types changed; FOR_ITER became FOR_ITER_LIST. JUMP_BACKWARD_NO_JIT is the loop's back-edge on a build where the experimental JIT is off, which is the default in 3.14 ({{What's new in 3.14|https://docs.python.org/3.14/whatsnew/3.14.html}}); section 5 turns it on and measures it. The lesson for speed: hot loops whose types never change are the ones CPython can specialise, and even specialised, each element still costs several instructions.

2. What objects cost

Every value is a heap object with a header: a reference count and a pointer to its type, 16 bytes on a 64-bit build. A float adds its 8-byte double; an int adds a size field and 30-bit digits, because ints are arbitrary precision.

A Python int is 28 bytes where a C int64 is 8, and grows 4 bytes per 30 bits

Sizes from sys.getsizeof on Python 3.14.8 (the full output is in the closed block below). A list of a million floats is a million 8-byte pointers to a million separate 24-byte objects; NumPy stores 8 bytes each, contiguously.

A str stores 1, 2 or 4 bytes per character for the whole string, chosen by its widest character ({{PEP 393|https://peps.python.org/pep-0393/}}); a non-ASCII string also carries a larger header, which is why 'é' (1 byte per character) costs 61 bytes against 42 for 'a', and '🙂' (4 bytes per character) 64. A list over-allocates: appends reserve spare room in steps (56, 88, 120, 184 bytes as it grows), which is why append is O(1) on average.

Reference counting and the cycle collector

When an object's count reaches zero it is freed at once, deterministically; that is why a file closed by going out of scope closes immediately in CPython. Counting cannot free a cycle (A points at B, B at A: both counts stay at 1 after your last name is gone), so a separate cycle collector (gc) periodically looks for groups of objects reachable only from each other. sys.getrefcount reports one more than you expect because its own argument is a reference. a died the instant its last name went; the cycle survived del until gc.collect(). The thresholds (2000, 10, 10) are those of the generational collector: Python 3.14.0 to 3.14.4 shipped an incremental collector, and 3.14.5 reverted to "the generational GC from 3.13" after "reports of significant memory pressure in production environments" ({{What's new in 3.14, Garbage collection|https://docs.python.org/3.14/whatsnew/3.14.html}}).

Practical consequences: break cycles in long-lived structures (parent pointers, callbacks that capture self) or use weakref; do not rely on __del__ for clean-up (use with); and for PyTorch, a tensor held by a cycle keeps its GPU memory until the collector runs. What both mechanisms do to a process's memory (pymalloc's arenas and pools, freed memory that does not go back to the operating system, the copy-on-write cost in DataLoader workers) is {{Memory allocators|n:3f05c17b0d0d81209ae9d856695dc958}}, section 7.

Two implementation details that leak into results

[[drill:Integer caching]]

CPython keeps one shared object for every integer from -5 to 256 ("The current implementation keeps an array of integer objects for all integers between -5 and 256", {{C API, integer objects|https://docs.python.org/3/c-api/long.html}}), so 10 is 5 + 5 is True while two separately made 1000s are different objects; the compiler warns about is with a literal. Compare values with ==; is is for None and sentinels.

[[drill:Float arithmetic]]

A float is an IEEE 754 double, so 0.1 and 0.2 are not exact; round rounds halves to even; // and % round towards minus infinity. Why, and what it does to training numerics, is {{Numerical computing|n:3f05c17b0d0d81d6af0be4a9a2edba8d}}.
