5. ruff: one linter and formatter, and a default that grew sevenfold

A linter reads code without running it and reports likely bugs and style problems; a formatter rewrites layout so nobody argues about it. ruff does both, in Rust, and replaced flake8 and its plugins, isort, pyupgrade and black. Here is a file with eight problems you have probably written yourself:

New in ruff 0.16 (2026-07-23): the default set grew from 59 to 413 rules
That is why the first run already reports isort (I), pyupgrade (UP), bugbear (B), simplify (SIM) and bandit (S) findings with no configuration at all. The release also removed 18 pycodestyle and pyflakes rules from the default set, among them E711 (== None) and E401 (two imports on one line), which appear only once selected explicitly ({{ruff changelog|https://github.com/astral-sh/ruff/blob/main/CHANGELOG.md}}). Pin ruff in your dev group, or one upgrade can fail every CI run.
What it costs
Nothing at run time. The cost is noise: a large default rule set on an old codebase reports hundreds of findings. Adopt it with ruff check --add-noqa once (it writes suppression comments for existing findings) and fix new code only, or start from an explicit select list.
Fixing, formatting and a starting configuration (real runs, ruff 0.16.10)

--fix applied nine safe fixes (sorted and pruned imports, list for List, str | None for Optional[str], the empty f-string). The five that remain need a human: a mutable default argument (seen=[] is created once and shared by every call), a file opened without with and never closed, a try/except/pass that ruff suggests writing as contextlib.suppress, a bare except that also swallows KeyboardInterrupt, and == None (use is None). "Unsafe" fixes (--unsafe-fixes) are the ones that can change behaviour, so ruff never applies them silently.

6. pytest as a tool: discovery, fixtures and assertion rewriting

pytest finds files named test_*.py, runs every function named test_*, and treats a plain assert as the check. What to test, and how to run tests in CI, is {{Testing and quality|n:3c65c17b0d0d81548848e2ebdd2f63ee}}'s subject; this section is the tool. Predict first:

That message is pytest's assertion rewriting: at import time it rewrites each assert in test files so that a failure shows the value of every sub-expression (where 2 = tokens('max_tokens')). This is why pytest needs no assertEqual family. Five more features cover most suites; all are in the one test file in the closed block below, testing the root page's token-counting rule:

  • Fixtures (chat_file, defined in conftest.py so every test file can use it) are set-up functions pytest calls when a test names them as a parameter. Built-in ones: tmp_path (a fresh folder per test) and monkeypatch (set an environment variable or attribute, undone after the test).
  • @pytest.mark.parametrize runs one test per row of inputs, each reported separately; pytest.raises asserts that a block raises a given exception.
  • Subtests (new in pytest 9.0, 2025-11-05) check several values inside one test and report each failure separately, for values known only at run time.
  • Configuration lives natively in pyproject.toml under [tool.pytest] (pytest 9.0; the older [tool.pytest.ini_options] table still works), and strict = true turns on every strictness option (unknown markers and config keys become errors).
  • Selecting and spreading: -k selects tests by name, --co lists what would run, and -n 4 from the pytest-xdist plugin spreads tests over four worker processes. On nine tests the workers' start-up made it slower (0.37 s against 0.01 s); it pays off on suites that take minutes.

Common mistakes with pytest
  • Testing implementation details (private functions, exact call counts) instead of behaviour, so every refactor breaks tests that found no bug.
  • A fixture with scope="session" that returns a mutable object: one test's change leaks into the next.
  • Forgetting that test files are imported: module-level code in a test file runs at collection time, even for tests you deselected.
  • Running pytest instead of uv run pytest, so a global pytest without your dependencies runs the suite.
