1. Hints are read by tools, not by Python

Annotations (x: int, -> str) are stored on the function and otherwise ignored when the program runs. A type checker reads them and reports contradictions before anything runs. What the type system can say, in the forms worth using in 2026:

To sayWriteNote
Containers and "or None"list[str], dict[str, int], str | NoneBuilt-in generics and unions; no imports since 3.9 and 3.10
Same type in, same type outdef first[T](xs: Sequence[T]) -> TThe 3.12 syntax ({{PEP 695|https://peps.python.org/pep-0695/}}); T is a type variable
"Anything with a close() method"class SupportsClose(Protocol)Structural typing ({{PEP 544|https://peps.python.org/pep-0544/}}): duck typing made checkable, usually better than an abstract base class
The shape of a plain dict (a chat message)class Message(TypedDict), NotRequired[str]{{PEP 589|https://peps.python.org/pep-0589/}}; still a plain dict at run time
An exact set of valuesLiteral["system", "user", "assistant"]
A return type that depends on the argument type@overload, one signature per case

One file (t1_types.py, in the closed block below) uses every row, then makes five deliberate mistakes. It was run with Python 3.14.8 and checked with mypy 2.4.0 and ty 0.0.84.

What the table shows
  • Python ran past mistakes 1 to 3 because annotations are not checked at run time; mistake 3 is a crash waiting for the day the user is missing. Both checkers caught 1, 2, 3 and 5 on the exact lines.
  • Neither caught mistake 4, the only one that crashed. legacy has no annotations, so its parameter is "any type" and anything goes; mypy by default does not even check the bodies of unannotated functions ({{mypy: no errors reported for obviously wrong code|https://mypy.readthedocs.io/en/stable/common_issues.html#no-errors-reported-for-obviously-wrong-code}}). Type checking protects only the code you annotate.
  • Conn never mentions SupportsClose and passes; int fails because it has no close. That is a Protocol at work.
What it buys, what it costs, the habit
Whole classes of bugs found before running (None handling, wrong keys, wrong argument order), editor completion and documentation that cannot go stale, for the time spent writing annotations, occasional fights with the checker over correct code that is hard to express, and nothing at run time. Annotate every public function and every boundary, run the checker in CI, and validate external data at run time with Pydantic, because a TypedDict on json.loads(...) is a promise, not a check (the root's {{Types section|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}} makes the same point for TypeScript).

t1_types.py
from collections.abc import Iterable, Sequence
from typing import Literal, NotRequired, Protocol, TypedDict, overload, reveal_type

class Message(TypedDict):                 # the shape of a dict, checked statically only
    role: Literal["system", "user", "assistant"]
    content: str
    name: NotRequired[str]

def first[T](xs: Sequence[T]) -> T:       # PEP 695 generic function (3.12+)
    return xs[0]

class SupportsClose(Protocol):            # structural: anything with close() fits
    def close(self) -> None: ...

def shutdown(things: Iterable[SupportsClose]) -> int:
    n = 0
    for t in things:
        t.close()
        n += 1
    return n

class Conn:                               # never mentions SupportsClose
    def close(self) -> None:
        print("closed")

@overload
def parse(x: str) -> int: ...
@overload
def parse(x: bytes) -> list[int]: ...
def parse(x: str | bytes) -> int | list[int]:
    return int(x) if isinstance(x, str) else list(x)

def find_user(msgs: list[Message], name: str) -> Message | None:
    return next((m for m in msgs if m.get("name") == name), None)

def legacy(x):                            # no annotations at all
    return x + 1

msgs: list[Message] = [{"role": "user", "content": "hello there", "name": "kh"}]
print(first([3, 4]), shutdown([Conn()]), parse("42"), parse(b"ab"))
reveal_type(first(["a", "b"]))
