The idea in one screen

Every operator, loop, with block and attribute access is a call to a special method looked up on the object's type, with a fixed order of fallbacks when the method is missing or declines; implement the methods and your class behaves like a built-in, and almost every Python surprise is one of these lookups doing exactly what the rules say.

Five pieces of syntax, five lookups on the type: Fig. 1 draws each as a stack of the places Python tries, lowest first; a lookup climbs until one of them answers. Each climb is a real run of d2_dispatch.py (CPython 3.14.8), which logged every method Python called; the rules are the language reference's {{Data model|https://docs.python.org/3/reference/datamodel.html}} chapter. The Data model explorer in section 1 replays 19 such lookups step by step from that run.

  1. Five stacks. v + 1, a == b, for x in xs, obj.attr and with m as r, each a stack of places to try. The bottom plate (blue) is the special method on the type, and runs first; a higher plate is tried only if every plate below is missing or declines. with is the exception: it always climbs all three.
  2. v + 1: the left side declines, the right side answers. In 5 + A(2), int.__add__ does not know A and returns NotImplemented (inside C, so nothing is logged); Python then tries the right operand's reflected method, and the run logged call A.__radd__(A(2), 5) and the result A(7). Had both declined, the top plate: TypeError (section 1).
  3. a == b: both decline, identity answers. In E(1) == '1' the run logged call E.__eq__(E(1), '1') returning NotImplemented; str.__eq__ declines too, in C; so Python compares identities, a is b: False, never an error.
  4. for: no __iter__, so the old sequence protocol. Old defines only __getitem__, so list(Old()) called it with 0, 1, 2 and 3; the IndexError at 3 ends the loop, and the list is [0, 10, 20]. A class with __iter__ is answered by the bottom plate: __next__ until StopIteration (section 3).
  5. obj.attr: every place misses, so __getattr__. For o.missing there is no data descriptor on the type, no entry in o.__dict__ and nothing on the class, so the run logged call K.__getattr__('missing'), which returned 'made up for missing'. Without __getattr__, the top plate: AttributeError. Fig. 7 in section 5 climbs this stack for every outcome.
  6. with: enter, body, exit, always. __enter__ returned 'resource', bound to r; the body raised ValueError('boom'); __exit__ received it and returned True, which swallows the exception, so the function went on and returned 'after the with' (section 7).

Type hints that describe these protocols (Protocol, Iterator[T]) are on {{Python: typing, uv, packaging and the toolchain|n:4055c17b0d0d8192878fce7505cc612f}}; this page is what happens when the code runs.

Special method
a double-underscore ("dunder") method such as __add__ that syntax calls for you.
Protocol
a set of special methods that makes an object usable somewhere (iteration, with, +); no base class needed.
NotImplemented
the value an operator method returns to say "not my type; ask the other operand".
Closure, cell
a function that keeps variables of the function that made it, stored in cells.
MRO
method resolution order: the list of classes that attribute lookup and super() walk.
Descriptor
a class attribute with __get__ (data descriptor: also __set__) that runs on attribute access; property, methods and slots are descriptors.
Exception group
one exception carrying several, handled with except*.
