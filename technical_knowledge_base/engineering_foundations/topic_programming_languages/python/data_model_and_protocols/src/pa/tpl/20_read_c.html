2. Copies and calls: what a function receives

Assignment never copies (the essentials page's first fact). So two questions decide most "who changed my list?" bugs: what a copy copies, and what a function call hands over.

Shallow and deep copies

Fig. 3 · The shallow copy shares the inner list; the deep copy shares nothing with the original

Recorded by code/n7_graph.py: it runs each line with exec and labels every list by id() in order of first appearance. Ints are drawn as values.

A shallow copy (x.copy(), list(x), x[:], copy.copy) makes a new outer container whose slots point at the same inner objects. A deep copy (copy.deepcopy) copies recursively, keeping a memo so that an object shared twice in the original is shared twice in the copy too. Predict what copy1 prints after line 4 in each mode, then let Fig. 3 run the five lines: the boxes are CPython's real objects, labelled by id() as the program ran.

  1. One list, one name. row = [1, 2]: one list object, L1, and the name row pointing at it.
  2. Two slots, one list. grid = [row, row]: a new list L2 whose two slots both point at L1. Nothing was copied; L1 now has three references (row and two slots).
  3. The shallow copy. copy1 = grid.copy(): a new outer list L3, but its slots point at the same L1. A shallow copy copies one level.
  4. Mutating the inner list. grid[0].append(3) mutates L1, and every path to L1 sees it: row, both slots of grid and both slots of copy1.
  5. Changing the outer list. grid.append([9]) changes only the outer list L2. L3 is a different outer list, so copy1 still has two slots.
  1. One list. row = [1, 2]: one list object, L1.
  2. Two slots, one list. grid = [row, row]: L2 with two slots pointing at L1.
  3. The deep copy. copy1 = copy.deepcopy(grid): new lists all the way down, L3 and a new inner list L4. Both slots of L3 point at the one L4: deepcopy keeps a memo, so sharing inside the original is reproduced, not multiplied.
  4. Mutating the original. grid[0].append(3) mutates L1; copy1 is untouched, because L4 is a separate object.
  5. Changing the outer list. grid.append([9]) changes L2 only.

The [[0] * n] * m trap
* on a list repeats references, not objects: three rows that are one row. Build nested lists with a comprehension. The same mistake inside a model config (one dict shared by every layer) is harder to see.

Passing arguments: the function gets the object, not a copy

Python passes a reference to the object (sometimes called "call by sharing"). A function can mutate the caller's object, but rebinding its own parameter name changes nothing outside. Default values are evaluated once, when def runs, so a mutable default is shared by every call.

+= is a method call too

Costs and habits (what it solves, what it costs, when not to)
What it solves
No copying on assignment or call: passing a 10 GB list costs the same as passing an int.
What it costs
Spooky action at a distance: any alias can change what you hold.
Habits
Do not mutate arguments unless that is the function's job (and say so); return new objects; prefer tuples and frozen dataclasses for values that should not change.
