4. Unions and narrowing: where TypeScript earns its keep

A union A | B is a value that is one of several types. You can only use what all members share: on string | number | null you cannot call toFixed, because a string has no such method and null has nothing at all.

Narrowing is how you get to a single member: tsc follows your ifs, switches and early returns and, at each line, knows which members are still possible. Every check JavaScript can do at run time narrows:

Discriminated unions: the pattern for LLM events, tool calls and states

A discriminated union is a union of object types that share one literal field (the tag, here type). Checking the tag narrows to exactly one member, with its own fields. This is how every LLM SDK types its streaming events, and how you should model anything with states. 5. Generics, and types computed from values

A generic function has type parameters in angle brackets: first<T>(xs: T[]): T | undefined works for any element type and keeps it, instead of losing it to any; tsc infers T from the arguments, so callers almost never write it. A constraint (T extends { length: number }) says what T must at least have, and K extends keyof T says "K is one of T's keys", which is how pluck(rows, "tokens") knows it returns number[]. The constraints are what make the errors precise. Two rules of thumb: a type parameter that appears only once in a signature does nothing (f<T>(x: T): void is just f(x: unknown): void), and a generic that needs a comment to be understood is probably worse than two plain functions.

TypeScript also has a small language for computing types from values, which is how one constant becomes the single source of truth for both:

  • typeof DEFAULTS in a type position reads the type of a value.
  • keyof T is the union of T's keys; T["temperature"] (an indexed access type) is the type of one property.
  • (typeof MODELS)[number] turns an as const array into the union of its elements: write the list once, get the type for free.

To make tsc print a type, the snippets assign it to never with satisfies and read the error message; the trick is used throughout this page. Note the order in the printed unions: "large" | "medium" | "small" is not the order the array was written in. TypeScript 7 orders union members deterministically (stableTypeOrdering is "true by default, and cannot be turned off", says the {{7.0 post|https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/}}), so do not read meaning into the order in an error message.

satisfies: check without forgetting. An annotation (const a: Record<string, Route>) checks the value and then replaces its type with the annotation, so the specific keys are forgotten. satisfies (TypeScript 4.9) checks the value against the type and keeps the inferred type: the wrong auth on line 4 is caught, and so is the typo b.hom.

Prefer satisfies for configuration objects and lookup tables, and never as to get the same effect (as checks nothing, section 6).

Mapped, conditional and template literal types, at a practical level

The utility types are not built-in magic: they are written in TypeScript's type language, which has loops over keys, if-then-else and string building. You will read these in library code more often than you write them.

Mapped types loop over keys: { [K in keyof T]: ... }. as renames keys, and -readonly or -? removes a modifier.
