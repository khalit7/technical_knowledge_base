In one screen

JavaScript looks like Python with braces, and most of it behaves the same: names point at objects, functions are values, classes have methods, exceptions propagate. Six differences cause almost every surprise; each section below opens one up.

1. One number type, and loose conversionsEvery number is a 64-bit float (a Python float), so integers are exact only up to 253; == converts types before comparing and + concatenates as soon as one side is a string. Use ===, and BigInt for big integers. Section 2.
2. Missing is undefined, not an errorA missing key, array index or argument gives undefined instead of KeyError, IndexError or TypeError; the crash comes later, where the value is used. ?. and ?? handle it. Sections 2 and 3.
3. this depends on the callA method taken off its object forgets its object (Python's bound methods remember self). Arrow functions keep the outer this. Section 4.
4. Objects are bags with a prototype chainclass is syntax over prototypes; plain objects double as records and as dictionaries with string keys (use Map for a real hash map). Sections 3 and 5.
5. One thread, an event loop, and nothing blocksYour code never runs in parallel with itself. I/O is started, and its result arrives later as a callback, a promise or an await; the order is fixed by two queues (microtasks before the next macrotask). A long loop freezes everything. Sections 9 to 11 and the Event-loop stepper.
6. The runtime is a choiceThe language (ECMAScript) has no files, network or processes: a runtime adds them. Node is the default for servers and tools; Bun and Deno run most of the same code and start faster. Sections 1, 12 and 14.
Why JavaScript first, if you want TypeScript

1. Running JavaScript

JavaScript was made for web pages in 1995; Node.js (2009) took Google's V8 engine out of the browser and added what a server needs: files, sockets, processes, and an event loop built on the C library libuv. In Python terms, Node is both the interpreter (python) and a large standard library. You write a file and run it; there is no compile step.

a1_hello.mjs
// hello.mjs: run with  node hello.mjs  (.mjs means "an ES module"; section 6)
const name = "Khalid";                  // const: this name is never rebound
let count = 3;                          // let: a variable you may reassign
count = count + 1;
console.log(`hello ${name}, count is ${count}`);   // backticks: a template string, like an f-string
console.log("typeof count:", typeof count, " typeof name:", typeof name);
console.log("runtime:", process.version, "on", process.platform, process.arch);

2. Values and types

JavaScript has seven primitive types (number, bigint, string, boolean, undefined, null, symbol) and objects (everything else: arrays, functions, dates, maps). Primitives are immutable and compared by value; objects are compared by identity. typeof x tells you which, with one historical lie (below).

Numbers: everything is a double

In Python, 7 is an int of any size and 7.0 a float. JavaScript has only the float: an IEEE 754 64-bit double, so integer arithmetic is exact only up to 253 − 1 (Number.MAX_SAFE_INTEGER), and / never truncates.

b1_numbers.mjs
// One number type: a 64-bit IEEE 754 double, exactly like a Python float.
console.log(0.1 + 0.2);                       // same as Python
console.log(7 / 2, -7 / 2);                   // no integer division: / always gives a double
console.log(Math.trunc(-7 / 2), Math.floor(-7 / 2), -7 % 2);   // Python's -7 // 2 is -4, -7 % 2 is 1
console.log(Number.MAX_SAFE_INTEGER);         // 2**53 - 1: the last integer every double can hold
console.log(2 ** 53 + 1);                     // rounded: the + 1 is lost
console.log(JSON.parse('{"id": 1234567890123456789}').id);   // a 64-bit id from an API, silently changed
console.log(1 / 0, -1 / 0, 0 / 0);            // no ZeroDivisionError: Infinity and NaN
console.log(NaN === NaN, Number.isNaN(0 / 0));
console.log(parseInt("42px"), Number("42px"), parseInt("08"), (255).toString(16));

Problem it solves
One numeric type is simple and fast; V8 still stores small integers ("Smis") as real integers internally (section 15).
What it costs
64-bit ids from APIs and databases silently lose digits when parsed from JSON; there is no integer division operator.
Do instead
Keep ids as strings; use Math.trunc or Math.floor explicitly; parse with Number(s) (strict) rather than parseInt (stops at the first bad character), and give parseInt a radix.

Strings: UTF-16 code units

A Python str is a sequence of Unicode code points, so len("🚀") is 1. A JavaScript string is a sequence of UTF-16 code units: characters outside the Basic Multilingual Plane (emoji, many CJK extensions) take two units, a "surrogate pair". .length, indexing and slice count units; iteration (for...of, [...s]) goes by code point. Strings are immutable, as in Python.

b3_strings.mjs
// Strings are immutable sequences of UTF-16 code units (Python: sequences of code points).
const s = "héllo 🚀";
console.log(s.length);                        // 8: the rocket is TWO UTF-16 units (a surrogate pair)
console.log([...s].length);                   // 7: spreading iterates by code point
console.log(s.slice(0, 7), "|", s.slice(0, 8)); // slicing in the middle of the pair leaves half a character
console.log(s.codePointAt(6).toString(16), s.charCodeAt(6).toString(16));
console.log(new TextEncoder().encode(s).length, "bytes in UTF-8");
console.log("a,b,,c".split(","), "  pad ".trim(), "ab".repeat(3), "abc".at(-1));
console.log("10" + 1, "10" - 1, "3" * "4");   // + concatenates if either side is a string; - * / convert to numbers

Template strings (backticks) are f-strings: `${a} + ${b} = ${a + b}`. For token counting on LLM text, remember that neither units nor code points are tokens, and that byte lengths (what APIs bill and limit) come from TextEncoder.

Two kinds of nothing: undefined and null

Python has None. JavaScript has undefined ("never set": a missing property, a missing argument, a function with no return) and null ("set to nothing on purpose"). Reading a missing property is not an error; the error comes when you read a property of undefined or null. Optional chaining a?.b stops at either, and x ?? fallback replaces only those two (unlike ||, which also replaces 0 and "").

b4_nullish.mjs
// Two "nothing" values. undefined: "never set". null: "set to nothing on purpose". Python has only None.
let a;                                        // declared, never assigned
const obj = { x: 1 };
console.log(a, obj.y, [1, 2][5]);             // missing things are undefined, not errors
console.log(typeof undefined, typeof null);   // typeof null is "object": a bug kept since 1995 for compatibility
console.log(null == undefined, null === undefined);
function f(x) { return x; }
console.log(f(), f(null));                    // a missing argument is undefined, not a TypeError
console.log(obj.y ?? "default", 0 ?? "default", 0 || "default");  // ?? replaces only null/undefined; || replaces any falsy
const user = { profile: null };
console.log(user.profile?.name, user.settings?.theme?.dark);       // ?. stops at null/undefined
try { console.log(user.profile.name); } catch (e) { console.log(e.constructor.name + ": " + e.message); }

== ("loose equality") converts both sides by a table of rules before comparing; === ("strict equality") never converts. Always write === and !==; the one common exception is x == null, which is true for exactly null and undefined. Objects and arrays compare by identity under both, like Python's is; there is no built-in deep equality.

Variables: const, let, never var

Python has function scope: a name assigned inside an if is visible after it. JavaScript's let and const are scoped to the enclosing block { ... }; the old var is function scoped and "hoisted" (created at the top of the function), which is why old code is full of bugs. A let used before its line throws (the "temporal dead zone"). const stops rebinding, not mutation: a const object can still change. Default to const, use let when you reassign.

b7_scope.mjs
// let and const are block scoped; var is function scoped and hoisted. Never use var.
if (true) { var v = "var leaks"; let l = "let stays"; }
console.log(v);
try { console.log(l); } catch (e) { console.log(e.name + ": " + e.message); }
try { console.log(early); let early = 1; } catch (e) { console.log(e.name + ": " + e.message); }  // the "temporal dead zone"
const cfg = { debug: false };
cfg.debug = true;                               // const stops rebinding, not mutation
console.log(cfg);
try { cfg = {}; } catch (e) { console.log(e.name + ": " + e.message); }
console.log(Object.isFrozen(Object.freeze({ a: 1 })));

3. Objects, arrays, destructuring, spread

An object literal { role: "user", text: "hi" } is what you reach for where Python uses a dict, a dataclass or a SimpleNamespace: a bag of properties you read as msg.role or msg["role"]. Two differences matter. Keys are always strings (or symbols): 1 and "1" are the same key. And iteration order is insertion order except that integer-like keys come first, in numeric order. For a real hash map with keys of any type, use Map; for a set, Set. Both compare keys by identity for objects (there is no __hash__).

c1_objects.mjs
// An object literal looks like a dict, but its keys are strings (or symbols), and it has a prototype.
const msg = { role: "user", text: "hi", 1: "one" };
msg.tokens = 2;                                 // add a property: just assign
console.log(msg, Object.keys(msg));            // integer-like keys come first, as strings
console.log(msg[1] === msg["1"], "role" in msg, msg.missing);
delete msg.tokens;
const counts = new Map();                       // Map: a real hash map with keys of any type, in insertion order
counts.set(1, "number one").set("1", "string one").set(msg, "an object as key");
console.log(counts.size, counts.get(1), counts.get("1"), counts.has(msg));
const seen = new Set([3, 1, 3, 2]);
console.log(seen, seen.has(2), [...seen]);
console.log(new Set([[1], [1]]).size);          // two different arrays: a Set compares by identity

Copying. Assignment never copies, as in Python. Spread ({ ...o }, [...xs]) copies one level, like copy.copy; structuredClone copies deeply, like copy.deepcopy, and keeps dates, maps and cycles. (Memory is managed by a garbage collector, as in Python but with no reference counting: objects are freed some time after nothing reaches them, cycles included. A WeakMap attaches data to an object without keeping it alive, a cache that cannot leak.) The old JSON.parse(JSON.stringify(x)) trick silently turns dates into strings and drops undefined and functions.

// Assignment never copies (as in Python). Spread copies one level; structuredClone copies everything.
const conv = { id: 1, msgs: [{ role: "user", text: "hi" }], when: new Date(0) };
const alias = conv, shallow = { ...conv }, deep = structuredClone(conv);
conv.msgs.push({ role: "assistant", text: "hello" });
console.log(alias.msgs.length, shallow.msgs.length, deep.msgs.length);
const viaJson = JSON.parse(JSON.stringify({ when: new Date(0), n: undefined, f() {}, big: NaN }));
console.log(viaJson);                           // the JSON round trip loses types: date becomes a string, the rest vanish or change

4. Functions, closures and this

Functions are values, as in Python. There are three spellings; the arrow function x => x * 2 is the everyday one (a lambda that may also have a block body). Arguments are not checked: extra ones are ignored, missing ones are undefined. Default values are evaluated on every call, so Python's mutable-default trap does not exist here (it runs in reverse).

d1_functions.mjs
// Three ways to write a function. All are objects you can pass around, as in Python.
function add(a, b = 10) { return a + b; }        // declaration: hoisted, usable above this line
const mul = function (a, b) { return a * b; };   // expression
const sq = x => x * x;                           // arrow: short, and no own `this` (below)
const sum = (...nums) => nums.reduce((s, n) => s + n, 0);   // rest parameter: Python's *args
console.log(add(1), add(1, 2), mul(3, 4), sq(5), sum(1, 2, 3));
console.log(add(1, 2, 99), add());               // extra arguments are ignored; missing ones are undefined
function push(x, xs = []) { xs.push(x); return xs; }
console.log(push(1), push(2));                   // defaults are evaluated on EVERY call (Python: once, at def)

A closure is a function that keeps the variables of the scope it was created in, exactly as in Python (without needing nonlocal to assign). Closures are how JavaScript does private state, callbacks and factories. The classic loop trap: var gives every iteration the same variable; let gives each iteration a fresh one.

d2_closures.mjs
// A closure: a function that keeps the variables of the scope it was created in.
function makeCounter() {
  let n = 0;                                    // private: nothing outside can reach n
  return { inc: () => ++n, get: () => n };
}
const c1 = makeCounter(), c2 = makeCounter();
c1.inc(); c1.inc(); c2.inc();
console.log(c1.get(), c2.get());
const withVar = [], withLet = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);   // one i shared by all three closures
for (let j = 0; j < 3; j++) withLet.push(() => j);   // a fresh j per iteration
console.log(withVar.map(f => f()), withLet.map(f => f()));

Inside a function, this is not fixed when the function is written; it is set by the call. obj.method() sets this to obj; calling the same function bare (const f = obj.method; f()) sets it to undefined (in modules and classes, which are always "strict mode"). 6. Modules: ES modules and CommonJS

JavaScript has two module systems, and Node runs both. ES modules (ESM, the standard since 2015): import and export, loaded and linked before any code runs, asynchronous, with top-level await. Python has one system; its import is closest to require (synchronous, runs the module once, caches it).

9. Asynchronous JavaScript and the event loop

A Node process runs your JavaScript on one thread. It never waits: reading a file, a socket or a timer is started, the call returns at once, and the result is delivered later by the event loop, the loop inside Node that runs one piece of your code at a time, to completion, and then picks the next. Python's asyncio is the same design, opt-in; in JavaScript it is the only model, and every I/O API is built for it. Three generations of API sit on top.

Callbacks

The original style: pass a function to call when the result is ready. Node's convention puts the error first. Each dependent step nests one level deeper ("callback hell"), and errors must be checked by hand at every level.

Promises, then async/await

A promise is an object standing for a result that is not there yet: pending, then once and for all fulfilled with a value or rejected with an error. .then(f) registers what to do next and returns a new promise, so steps chain instead of nesting. async function and await are syntax over promises: an async function always returns a promise, and await p pauses the function until p settles, returning its value or throwing its error, so plain try/catch works. One difference from Python matters: a promise is eager. The work starts when the promise is created; a Python coroutine does nothing until awaited or wrapped in a task.

10. The async toolbox

Timers. setTimeout(f, ms) runs f once, no earlier than ms later (later if the thread is busy); setInterval repeats; both return a handle for clearTimeout. import { setTimeout as sleep } from "node:timers/promises" gives Python's asyncio.sleep.

Waiting for several. Python's asyncio.gather is Promise.all: results in input order, rejects as soon as one rejects (the others keep running; nobody cancels them). Promise.allSettled never rejects and reports each outcome (gather(..., return_exceptions=True)). Promise.race settles with the first to settle; Promise.any with the first success, or an AggregateError of all failures.

i5_combinators.mjs
// Waiting for several promises: all (fail fast), allSettled (never rejects), race (first to settle), any (first success).

Cancellation and timeouts. A promise cannot be cancelled. Instead, the work accepts an AbortSignal (from an AbortController, or AbortSignal.timeout(ms)) and stops when it fires; fetch, timers, streams and most SDKs accept { signal }. A concurrency limit. "All at once" is wrong for 10,000 requests to a rate-limited API. The usual fix is a small pool: N workers pulling from a shared index (libraries such as p-limit do the same). Python's equivalent is an asyncio.Semaphore.

// 20 requests of 50 ms each, at most 4 in flight: a worker-pool limiter in eight lines (no library).
const sleep = ms => new Promise(r => setTimeout(r, ms));
async function mapLimit(items, limit, fn) {
  const results = new Array(items.length); let next = 0, inFlight = 0, peak = 0;
  async function worker() {
    while (next < items.length) { const i = next++; inFlight++; peak = Math.max(peak, inFlight); results[i] = await fn(items[i]); inFlight--; }
  }
  await Promise.all(Array.from({ length: limit }, worker));
  return { results, peak };
}
const items = Array.from({ length: 20 }, (_, i) => i);

A streaming LLM API sends server-sent events (SSE): an HTTP response that stays open, carrying text lines data: {...}, each event ended by a blank line. With fetch, response.body is a stream of Uint8Array byte chunks that you can for await over. The trap: the network decides where chunks end, not the server. A chunk can end in the middle of an event, and in the middle of a multi-byte UTF-8 character. Code that parses each chunk on its own works on a fast local test and fails in production behind a proxy. The fix is one streaming TextDecoder ({ stream: true } keeps half a character for the next chunk), a text buffer, and parsing only complete events. Official SDKs do this for you; the bug appears when you hand-roll a client, or a proxy, or a test.

The nine chunks are the ones the client really received in the recorded run of j1_sse.mjs (byte lengths saved by the script); the two parsers run live in your browser on those bytes, and their final results are checked against the recorded run.

Worker threads: CPU work off the event loop

One thread means CPU-heavy work (parsing a huge JSON, hashing, tokenising a corpus) stops everything else: timers, requests, streams. A worker thread is a second V8 instance on another OS thread with its own event loop; it shares nothing by default and talks by messages (postMessage, copied with the structured clone algorithm), or shares memory explicitly through a SharedArrayBuffer with Atomics. It is closer to Python's multiprocessing than to threading, but cheaper to start. Below, a 10 ms heartbeat timer measures how long the event loop was stuck.

k6_workers.mjs
// CPU work blocks the event loop; a worker thread runs it on another core. A 10 ms heartbeat timer shows the difference.
import { Worker } from "node:worker_threads";
function primes(n) { let c = 0; for (let i = 2; i < n; i++) { let p = true; for (let j = 2; j * j <= i; j++) if (i % j === 0) { p = false; break; } if (p) c++; } return c; }
async function heartbeat(label, work) {
  let last = performance.now(), worst = 0, beats = 0;
  const t = setInterval(() => { const now = performance.now(); worst = Math.max(worst, now - last); last = now; beats++; }, 10);
  const t0 = performance.now(); const result = await work();
  await new Promise(r => setTimeout(r, 30)); clearInterval(t);
  console.log(`${label.padEnd(24)} result ${result}  took ${Math.round(performance.now() - t0 - 30)} ms  heartbeats ${beats}  worst gap ${Math.round(worst)} ms`);
}
const N = 3_000_000;
await heartbeat("on the main thread:", async () => primes(N));
await heartbeat("in a worker thread:", () => new Promise((ok, fail) => {
  const w = new Worker(`const { parentPort, workerData } = require("node:worker_threads");
    ${primes.toString()}
    parentPort.postMessage(primes(workerData));`, { eval: true, workerData: N });
  w.once("message", ok); w.once("error", fail);
}));

Versions are semver ranges: ^5.2.1 means "5.x.y, at least 5.2.1". The exact resolved tree is pinned in a lockfile (package-lock.json, like uv.lock); commit it, and install from it in CI with npm ci. Packages go into a local node_modules/ folder per project: there is no global site-packages and no virtual environment to activate, because every project is already isolated.

14. Bun and Deno

Node is not the only runtime. Bun runs on JavaScriptCore (Safari's engine) and bundles a runtime, package manager, test runner and bundler in one binary; it runs TypeScript directly. Bun announced it was joining Anthropic on 2025-12-02, noting that "Claude Code ships as a Bun executable" (Bun is joining Anthropic); Bun 1.4 (2026-08-20) rewrote Bun itself from Zig to Rust (Bun 1.4). Deno (by Node's original author) runs on V8, is written in Rust, runs TypeScript directly, and is secure by default: no file, network or environment access without a flag. 15. V8 performance notes

V8 does not interpret your code forever. It parses it to bytecode run by the Ignition interpreter, then compiles functions that get hot: Sparkplug (a fast baseline compiler), Maglev (a mid-tier optimising compiler, shipped in Chrome 117 in 2023) and TurboFan (the top tier) (V8 blog, Maglev). The optimising tiers speculate from what they have seen: "this argument has always been a small integer", "this object always has this shape". When a guess breaks, the code deoptimises back to the interpreter and may be recompiled later. You can watch it:

n3_deopt.mjs
// Run with: node --trace-opt --trace-deopt n3_deopt.mjs | grep add   (V8 tells you when it optimises and when it gives up)
function add(a, b) { return a + b; }
let s = 0;
for (let i = 0; i < 200_000; i++) s = add(i, 1);       // only small integers: V8 compiles add for that
console.log("now call it with strings");
add("a", "b");                                         // assumption broken: deoptimise, back to the interpreter
for (let i = 0; i < 200_000; i++) s = add(i, 2);
console.log(s);

"Not a Smi": a Smi is V8's small-integer representation (31 or 32 bits, stored without allocating). The second lever is the hidden class (V8 calls it a "map"): objects with the same property names added in the same order share one, and each property access site caches the shapes it has seen ("inline caches"). A site that sees one shape is monomorphic and fast; past four it is megamorphic and does a slow lookup.

What to do with this
Create objects of one kind in one place (a constructor, a class, or one literal shape), with all fields set, in the same order; do not add properties later; do not delete (set to undefined instead); keep arrays of one element type.
What not to do

16. Traps that catch experienced people

Each one was shown running above; open one for the fix.

this lost when a method is passed as a callback
Pass () => obj.method() or obj.method.bind(obj). Section 4.
Closures over a var loop variable all see the last value
Use let (a fresh binding per iteration); never write var. Section 4.
await inside forEach does not wait
for...of with await, or await Promise.all(xs.map(...)). Section 10.
sort() sorts numbers as strings
Always pass a comparator: xs.sort((a, b) => a - b), or the non-mutating toSorted. Section 3.
Money and ids in doubles
Floats cannot hold 0.1 exactly and lose integers above 253, including 64-bit ids parsed from JSON. Use integer cents (or a decimal library), keep ids as strings, use BigInt for exact big integers. Section 2.
parseInt quirks
parseInt("42px") is 42 (it stops at the first bad character) and ["1","2","3"].map(parseInt) is [1, NaN, NaN] (map passes the index as the radix). Use Number(s), which rejects junk, or parseInt(s, 10). Sections 2 and the drills.
Mutating something another part of the program holds
Spread copies one level only; structuredClone for deep copies at boundaries; toSorted, toReversed, with instead of in-place methods on shared arrays. Section 3.
Fire-and-forget promises
A rejection nobody handles crashes Node (since Node 15). await it, or add .catch(log) deliberately. Section 10.
JSON.parse(JSON.stringify(x)) as a deep clone
It turns dates into strings and drops undefined, functions and NaN (to null), and throws on cycles and BigInt. Use structuredClone. Section 3.
Blocking the event loop
Synchronous file reads (readFileSync), big JSON.parse calls, CPU loops or synchronous crypto in a server stall every request. Use the async APIs, stream, or move CPU work to a worker thread. Sections 9 and 12.
Treating a parsed SSE chunk as a whole event
Buffer, decode with one streaming TextDecoder, and split on the blank line. Section 11.
Merging untrusted JSON into objects (prototype pollution), eval, and regexes on user input
A naive recursive merge copies a "__proto__" key from JSON onto Object.prototype, and then every object in the process has the attacker's property. Skip __proto__, constructor and prototype keys, merge into Object.create(null) or a Map, or validate the shape first (Part 2's zod). Never pass input to eval or new Function. A regex with nested quantifiers such as /(a+)+$/ can take exponential time on a crafted string and block the event loop (ReDoS); keep patterns simple or bound the input length.

// Prototype pollution: a naive deep merge of untrusted JSON can write to Object.prototype, changing EVERY object.
function merge(dst, src) {
  for (const k in src) {
    if (typeof src[k] === "object" && src[k] !== null) { dst[k] ??= {}; merge(dst[k], src[k]); }
    else dst[k] = src[k];
  }
  return dst;
}

The rules the six programs show
    

  • Synchronous code always runs to the end first. An async function runs synchronously until its first await.
    • 

  • Then all microtasks run (promise callbacks, code after await, queueMicrotask), including ones queued while draining, before the loop takes the next macrotask (a timer, an I/O callback, setImmediate). After every macrotask, microtasks are drained again (program 3).
    • 

  • Node adds process.nextTick, a queue it drains before the microtasks, and loop phases: timers, then I/O polling, then "check" (setImmediate). Inside an I/O callback, setImmediate always beats setTimeout(f, 0) (program 4); at the top level of a script that order is not guaranteed (Node: the event loop).
    • 

  • In an ES module, the module itself is evaluated as part of a microtask job, so promise callbacks run before nextTick callbacks; in CommonJS it is the reverse (programs 5a and 5b; Node docs: queueMicrotask() vs process.nextTick()). Prefer queueMicrotask and promises; avoid depending on nextTick ordering.

Objects: interface or type alias

Structural typing: shape, not name


TypeScript compares types by their structure: a value fits a type if it has the right members, whatever class or name it came from. This is the deepest difference from Java, C# or Rust, and it is what Python's typing.Protocol does.

A robust reader has three steps: find the JSON, JSON.parse it inside try, and validate with the schema, returning a typed result or an error message you can send back to the model for a retry.




The LLM JSON lab runs ten such replies through a cast and three zod variants (default, strict, coercing) and shows every real outcome, including the two cases where the cast neither crashes nor complains and the program prints a wrong value.

Common mistakes


Thinking that running a .ts file checks it
node, tsx, Bun and vitest strip types without checking. Run npx tsc (it uses noEmit or an outDir) in CI and in your editor.


JSON.parse(x) as T on data you did not create
A cast checks nothing. Parse to unknown and validate with a zod schema; derive T from it with z.infer.


Letting any in
From JSON.parse, untyped libraries, catch in old code, or an explicit annotation. It spreads silently. Lint against it (noExplicitAny, no-unsafe-*) and use unknown.


Silencing an error with as or !
Read the error first: it is usually right. If you must assert, assert as late and as narrowly as possible, with a comment saying why it is true.


A bag of optional fields instead of a discriminated union
Every use then needs a check and nothing tells you when a new kind appears. One member per kind, with a literal tag, and a never check in default.


Truthiness checks on numbers and strings
if (count) is false for 0 and if (name) for "". Use !== undefined or != null when 0 or empty are valid.


Floating promises
tsc does not catch a call to an async function whose promise is dropped. await it, return it, or mark it void; let a linter enforce it.


Enums and parameter properties in code that Node runs directly
Node's strip-only mode rejects them. Use as const objects and explicit fields; turn on erasableSyntaxOnly.


A global TypeScript install, or a caret range
Install typescript per project as a dev dependency and run npx tsc, so every machine and CI use the same compiler. Minor releases can add errors to code that compiled before (better inference finds real bugs), so many teams pin with ~ and upgrade in a dedicated change.


Type-level cleverness
Recursive conditional types that nobody else can read and that slow the editor. Derive types from one source; stop there.

3. When the call fails: retries, timeouts, typed errors


A model API fails in ordinary ways: rate limits (HTTP 429), overload (529 and other 5xx), a slow or dead connection, or a request you got wrong (400). The SDK already handles the first three. Read from the SDK's source (client.js, 0.131.0): it retries 2 times by default (maxRetries), on 408, 409, 429, every 5xx, and connection errors; it waits with exponential backoff or for the server's retry-after / retry-after-ms header; and its timeout is 10 minutes per attempt (in milliseconds in TypeScript: timeout: 600_000). A 400 is never retried: retrying a wrong request cannot fix it. A local server that fails on purpose shows each case:


a3_errors.ts
// What the SDK does when the API fails: retries (429, 5xx, timeouts) and typed errors you can catch.
import Anthropic from "@anthropic-ai/sdk";
import { createServer } from "node:http";

let attempts = 0, mode = "";
const t0 = Date.now(); const log = (s: string) => console.log(`${String(Date.now() - t0).padStart(5)} ms  ${s}`);
const server = createServer((req, res) => {
  attempts++; req.resume();
  log(`server: attempt ${attempts} (${mode}), retry-count header ${req.headers["x-stainless-retry-count"]}`);
  if (mode === "429" && attempts <= 2) return res.writeHead(429, { "content-type": "application/json", "retry-after-ms": "100" })
    .end(JSON.stringify({ type: "error", error: { type: "rate_limit_error", message: "slow down" } }));
  if (mode === "400") return res.writeHead(400, { "content-type": "application/json" })
    .end(JSON.stringify({ type: "error", error: { type: "invalid_request_error", message: "max_tokens: must be at least 1" } }));
  if (mode === "hang") return;   // never answers
  res.writeHead(200, { "content-type": "application/json" }).end(JSON.stringify({ id: "msg_1", type: "message", role: "assistant",
    model: "m", content: [{ type: "text", text: "ok" }], stop_reason: "end_turn", stop_sequence: null, usage: { input_tokens: 1, output_tokens: 1 } }));
}).listen(0);
const client = new Anthropic({ baseURL: `http://127.0.0.1:${(server.address() as any).port}`, apiKey: "mock-key" });
const ask = (opts?: Anthropic.RequestOptions) =>
  client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 64, messages: [{ role: "user", content: "hi" }] }, opts);

  mode = m; attempts = 0; console.log(`\n--- server answers ${m}${opts ? " (timeout 300 ms, maxRetries 1)" : ""}`);

4. Streaming


A long answer takes seconds to generate. Streaming sends each piece as it is produced, so the user sees text at once. On the wire it is server-sent events: one HTTP response that stays open and carries event: and data: lines, each event ended by a blank line. How to parse SSE bytes correctly yourself (chunks split events and even UTF-8 characters) is taught with an animation in Part 1's Reading, section 11; the SDK does that parsing for you. What remains is knowing the events.














Every frame is one the mock really sent in the recorded runs of b1_stream.ts and b2_stream_openai.ts (same answer text in both formats); the "assembled so far" column is computed in your browser from those frames, the way the SDK assembles them.




Event references: Anthropic streaming, OpenAI Responses streaming events.


The SDK gives three levels. create({ ..., stream: true }) returns an async iterable of the raw events, already parsed (note that it drops the ping keep-alive: 23 events arrive, the wire carried 24). messages.stream() is the helper: .on("text", f) for each text piece and await finalMessage() for the assembled Message, identical to what a non-streaming call returns. And for tool calls, the arguments stream as partial JSON (input_json_delta): fragments like "t.jsonl\",\"to" that are not JSON on their own; the helper re-parses the snapshot after each one.

5. Tool use and the agent loop


Tool use (OpenAI calls it function calling) works like this. You send, with the messages, a list of tools: a name, a description, and a JSON Schema for the arguments. The model never runs anything. When it wants a tool it stops with stop_reason: "tool_use" and a tool_use block (a name, arguments, an id). Your code runs the function, then sends a new request containing the whole conversation plus a tool_result block with the same id. The model reads the result and either asks for more tools or answers. That repetition is the agent loop, and an "agent" is nothing more than this loop plus tools.


The loop is small. Everything that makes it safe is in the guards:




Step limit
A model can ask for tools forever. Stop after maxSteps model calls and report it.


Timeout per tool
AbortSignal.timeout(500) gives every tool a deadline; a stuck tool becomes an error result, not a hung agent.


Validate the input
The arguments are the model's JSON: untrusted. safeParse them with the same zod schema that produced the JSON Schema.


Errors go to the model
A failed tool returns is_error: true with a message the model can act on. Throwing would kill the run.


Run calls concurrently
One turn may ask for several tools. Promise.all runs them together, and all results go back in one user message.


Meter the cost
Add up usage after every call; a loop multiplies the bill (every step resends everything).

const PRICE = { in: 2, out: 10 };   // US$ per million tokens, claude-sonnet-5-5 (Anthropic pricing page, 2026-10-05)
const TASK = "Who are the 3 heaviest users in chat.jsonl, and what share of all tokens do they have? Add the team of the top two.";

const schema = (s: z.ZodType) => { const { $schema, ...rest } = z.toJSONSchema(s) as any; return rest as Anthropic.Tool.InputSchema; };
const tools: Anthropic.Tool[] = [
  { name: "count_tokens", description: "Count word tokens per user in a JSONL chat log; returns totals and the top users.", input_schema: schema(CountArgs) },
  { name: "user_profile", description: "Look up a user's team.", input_schema: schema(ProfileArgs) },
];

export async function runAgent(client: Anthropic, scenario: string, opts: { maxSteps?: number; toolTimeoutMs?: number; profileUrl: string }) {
  const { maxSteps = 5, toolTimeoutMs = 500 } = opts;
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: TASK }];
  const steps: any[] = []; const tot = { in: 0, out: 0, usd: 0 };

  type Result = Anthropic.ToolResultBlockParam & { ms: number };
  async function runTool(call: Anthropic.ToolUseBlock): Promise<Result> {
    const t0 = performance.now();
    const done = (content: string, is_error = false): Result =>
      ({ type: "tool_result" as const, tool_use_id: call.id, content, ...(is_error ? { is_error } : {}), ms: Math.round(performance.now() - t0) });
    try {
      const signal = AbortSignal.timeout(toolTimeoutMs);             // every tool gets a deadline
      if (call.name === "count_tokens") {
        const args = CountArgs.safeParse(call.input);                 // the model's JSON is untrusted input
        if (!args.success) return done(`invalid input: ${z.prettifyError(args.error)}`, true);
        return done(JSON.stringify(await countTokens(args.data)));
      }
      if (call.name === "user_profile") {
        const args = ProfileArgs.safeParse(call.input);
        if (!args.success) return done(`invalid input: ${z.prettifyError(args.error)}`, true);
        return done(await userProfile(opts.profileUrl, args.data, signal));
      }
      return done(`unknown tool ${call.name}`, true);
    } catch (e: any) {                                                  // errors go back to the model, not up the stack
      const why = e.name === "TimeoutError" ? `timed out after ${toolTimeoutMs} ms` : e.code === "ENOENT" ? `cannot open ${(call.input as any).path}: ENOENT` : String(e);
      return done(why, true);
    }
  }

  for (let step = 1; step <= maxSteps; step++) {
    const msg = await client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 2048, tools, messages },
      { headers: { "x-mock-scenario": scenario } });
    tot.in += msg.usage.input_tokens; tot.out += msg.usage.output_tokens;
    tot.usd = (tot.in * PRICE.in + tot.out * PRICE.out) / 1e6;
    messages.push({ role: "assistant", content: msg.content });
    const calls = msg.content.filter((b): b is Anthropic.ToolUseBlock => b.type === "tool_use");
    const t0 = performance.now();
    const results = await Promise.all(calls.map(runTool));            // several calls in one turn run concurrently
    const wall = Math.round(performance.now() - t0);
    steps.push({ step, sent: messages.length - 1, content: msg.content, stop: msg.stop_reason, usage: msg.usage, results, wall, tot: { ...tot } });
    if (msg.stop_reason !== "tool_use") {
      const answer = msg.content.filter(b => b.type === "text").map(b => b.text).join(" ");
      return { scenario, outcome: "answered", answer, steps, tot, messages: messages.length };
    }
    messages.push({ role: "user", content: results.map(({ ms, ...r }) => r) });   // all results in ONE user message
  }
  return { scenario, outcome: `stopped: hit maxSteps=${maxSteps}`, answer: null, steps, tot, messages: messages.length };
}

8. Conversation state

  • Prompt caching. Mark the stable prefix (cache_control); later requests that start with the same bytes read it from cache at 0.1x the input price on most models (0.05x on Opus 5.5; pricing). Any change early in the prefix (a timestamp in the system prompt) silently defeats it.
    • 

  • Compaction or trimming. Summarise or drop old turns when the context grows (Anthropic offers server-side compaction as a beta).
    • 

  • Server-side state. OpenAI's Responses API can keep the conversation on its servers: pass previous_response_id (conversation state guide) instead of resending (you are still billed for those input tokens; you just do not send them).
    •

10. MCP: a server, a client, and an agent that uses them


So far the tools lived inside the agent's program. The Model Context Protocol (MCP) moves them into a separate process with a standard interface, so one tool server works with Claude Code, Claude Desktop, an IDE, or your own agent. It is JSON-RPC 2.0: every message is a JSON object with a method and an id (a request), the same id with a result or error (the response), or a method without an id (a notification). A server offers three kinds of thing: tools (functions the model calls), resources (data the client reads, addressed by URI), and prompts (templates the user picks). The protocol itself (capabilities, lifecycle, authorisation) is covered in Topic: protocols; here we build one with the official TypeScript SDK, which negotiated protocol version 2025-11-25 in our runs.


g1_mcp_server.ts, lines 12-41
export function buildServer() {
  const server = new McpServer({ name: "chat-stats", version: "1.0.0" });

  server.registerTool("count_tokens", {
    title: "Count tokens per user",
    description: "Count word tokens per user in a JSONL chat log; returns totals and the top users.",
    inputSchema: CountArgs.shape,                       // validated by the SDK before the handler runs
    annotations: { readOnlyHint: true },
  }, async (args) => {
    try {
      const stats = await countTokens(args);
      return { content: [{ type: "text", text: JSON.stringify(stats) }] };
    } catch (e: any) {                                  // a tool failure is a result the model can read, not a protocol error
      return { isError: true, content: [{ type: "text", text: `cannot open ${args.path}: ${e.code}` }] };
    }
  });

  server.registerResource("chat-log", "file:///chat.jsonl", { title: "The chat log", mimeType: "application/json" },
    async (uri) => {
      const s = await stat("chat.jsonl");
      return { contents: [{ uri: uri.href, text: JSON.stringify({ bytes: s.size, format: "JSONL, one message per line" }) }] };
    });

  server.registerPrompt("heaviest-users", {
    description: "Ask for the heaviest users of a chat log",
    argsSchema: { n: z.string().describe("how many users") },
  }, ({ n }) => ({ messages: [{ role: "user", content: { type: "text", text: `Who are the ${n} heaviest users in chat.jsonl? Use count_tokens.` } }] }));

  return server;
}


registerTool takes the zod shape; the SDK turns it into the JSON Schema clients see, and validates arguments before your handler runs. A failure inside the tool is returned as a result with isError: true, which the model can read and react to; a protocol-level error is for broken requests. 11. Serving an LLM app: stream to the browser, cancel when it leaves


A web app puts your server between the browser and the model: the browser calls /ask, your server calls the model with the API key (which must never reach the browser), and forwards each text piece as an SSE event. Two things go wrong in production that never show in a demo.


Cancellation. Users close tabs. If your server does not notice, the model keeps generating, and you pay for every token nobody will read. In Node the response's close event fires when the client goes away; hand an AbortController's signal to the SDK call and abort it there. The SDK then closes the upstream HTTP request and throws APIUserAbortError, which you catch. (AbortController and AbortSignal themselves are taught in Part 1's Reading, section 10.) The same browser closes after three pieces in both runs below; only the server's handling differs:














Times and counts are the recorded run of h1_serve.ts (the mock model sends one event every 20 ms; its answer has 114 events in all). Times are measured from the moment the browser closed.




h1_serve.ts
// Serving an LLM app: a Node HTTP endpoint that streams the model's tokens to a browser as SSE,
// and stops the upstream model call when the browser goes away (AbortController).
import Anthropic from "@anthropic-ai/sdk";
import { createServer } from "node:http";
import { startMock } from "./mock_model.ts";

const mock = await startMock({ delayMs: 20 });                  // the "model" sends one event every 20 ms
const client = new Anthropic({ baseURL: mock.url, apiKey: "mock-key", defaultHeaders: { "x-mock-scenario": "long" } });
const t0 = performance.now(); const log = (s: string) => console.log(`${String(Math.round(performance.now() - t0)).padStart(5)} ms  ${s}`);
let propagate = true;

const app = createServer(async (req, res) => {
  const ac = new AbortController();
  res.on("close", () => { if (!res.writableFinished) { log("server: browser went away"); if (propagate) ac.abort(); } });
  res.writeHead(200, { "content-type": "text/event-stream", "cache-control": "no-cache" });
  const q = new URL(req.url ?? "", "http://x").searchParams.get("q") ?? "";
  const stream = client.messages.stream({ model: "claude-sonnet-5-5", max_tokens: 1024, messages: [{ role: "user", content: q }] },
    { signal: ac.signal });                                      // aborting the signal closes the upstream HTTP request
  let sent = 0;
  try {
    for await (const ev of stream) {
      if (ev.type === "content_block_delta" && ev.delta.type === "text_delta") { res.write(`data: ${JSON.stringify(ev.delta.text)}\n\n`); sent++; }
    }
    res.end("event: done\ndata: {}\n\n");
    log(`server: upstream finished; ${sent} deltas forwarded${res.destroyed ? " (most of them to a closed socket)" : ""}`);
  } catch (e) {
    if (e instanceof Anthropic.APIUserAbortError) log(`server: upstream call aborted after ${sent} deltas`);
    else throw e;
  }
});
await new Promise<void>(r => app.listen(0, "127.0.0.1", r));
const url = `http://127.0.0.1:${(app.address() as any).port}/ask?q=tell+me+about+TypeScript`;

    }
  } catch (e) { if ((e as Error).name !== "AbortError") throw e; }
}

Backpressure. res.write() returns false when the bytes cannot leave as fast as you write them (a slow phone, a congested link); Node then keeps the rest in memory. A server that ignores the false can hold the whole response in RAM for every slow client at once. The fix is one line: when write returns false, await once(res, "drain") before writing more. A client that reads nothing for 300 ms:


h2_backpressure.ts
// Backpressure: res.write() returns false when the socket cannot keep up. Ignore it and Node queues the bytes in memory.
import { createServer, request } from "node:http";
import { once } from "node:events";

const EVENTS = 20000, EVENT = `data: ${JSON.stringify("x".repeat(90))}\n\n`;   // about 2 MB in total
async function run(respect: boolean) {
  let peak = 0, falses = 0;
  const server = createServer(async (_req, res) => {
    res.writeHead(200, { "content-type": "text/event-stream" });
    for (let i = 0; i < EVENTS; i++) {
      const ok = res.write(EVENT);
      peak = Math.max(peak, res.writableLength);              // bytes queued inside this process
      if (!ok) { falses++; if (respect) await once(res, "drain"); }
    }
    res.end();
  });
  await new Promise<void>(r => server.listen(0, "127.0.0.1", r));
  const t0 = performance.now();
  await new Promise<void>(done => request({ port: (server.address() as any).port, path: "/" }, async (res) => {
    res.pause(); await new Promise(r => setTimeout(r, 300));    // a slow reader: reads nothing for 300 ms
    res.resume(); res.on("end", done);
  }).end());
  server.close();
  console.log(`${respect ? "awaits drain " : "ignores false"}: write() returned false ${String(falses).padStart(5)} times, peak queued in the server ${(peak / 1024).toFixed(0).padStart(5)} KiB, ${Math.round(performance.now() - t0)} ms`);
}
console.log(`${EVENTS} events of ${EVENT.length} bytes = ${(EVENTS * EVENT.length / 1024).toFixed(0)} KiB to a client that waits 300 ms before reading`);
await run(false);
await run(true);

12. Evaluation hooks and logging


You cannot improve an LLM app you do not measure, and the measuring starts with two habits. Log every model call as one JSON line: which case, status, latency, how many messages were sent, why it stopped, tokens in and out. Keep a fixed set of cases with checks written in code, and run them on every change of prompt, model or tool. The cheapest hook is the SDK's fetch option: a wrapper that sees every HTTP call, retries included, without touching the agent.

13. Common mistakes


    

  • Reading content[0].text without checking the block type or stop_reason. The first block may be thinking or tool_use; a max_tokens stop means the text is cut off. TypeScript's narrowing forces the check if you let it.
    • 

  • An agent loop without a step limit or tool timeouts: the runaway run above, in production, with a real bill.
    • 

  • Trusting tool arguments. They are model output. Validate with zod, and for paths, URLs or shell commands also check what they point at (a valid string can still be ../../etc/passwd).
    • 

  • Throwing from a tool instead of returning is_error: the run dies on a problem the model could have fixed (the typo run fixed its own mistake).
    • 

  • await in a for loop over tool calls, running them one after another when Promise.all would run them together; and splitting their results over several messages instead of one.
    • 

  • Forgetting that the API is stateless, or never trimming: the bill grows with the square of the conversation's length.
    • 

  • Dropping the zod check because the API constrained the output: patterns and ranges are not enforced by the API (section 7).
    • 

  • Ignoring disconnects and write()'s return value in the server: paying for unread tokens and holding responses in memory.
    • 

  • Logging to stdout in a stdio MCP server: it corrupts the protocol stream.
    • 

  • Putting the API key in browser code, or in a logged request. Keys belong in server-side environment variables; this page's scripts unset them before running.
    • 

  • Catching errors by message text instead of instanceof Anthropic.RateLimitError and friends; and adding your own retry loop around an SDK that already retries (the SDK's 3 attempts inside your 3 attempts is 9 requests).
    • 

  • Relying on a framework default you have not read: generateText's single step, allowedTools meaning "no approval needed" rather than "only these".
