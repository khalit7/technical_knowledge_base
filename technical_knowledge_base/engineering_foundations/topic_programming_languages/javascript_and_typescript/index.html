JavaScript runs your code on one thread around an event loop: nothing runs in parallel with your code, every slow operation is started and finishes later as a callback, a promise or an await, and a long loop freezes everything. TypeScript is a type layer erased before anything runs: it is checked in your editor and CI, then deleted, so what runs is always plain JavaScript.

The event loop: run one task to the end, run every microtask, take the next task. A for loop that computes for 0.44 s holds the stack for 0.44 s: no timer, request or stream moves meanwhile (section 2 measures it).
libuv, under Nodewatches sockets with the operating system's readiness API; files, dns.lookup, some crypto and zlib calls run on its thread pool, 4 threads by default. Results come back as tasks.

1. Running JavaScript

JavaScript was made for web pages in 1995; Node.js (2009) took Google's V8 engine out of the browser and added what a server needs: files, sockets, processes, and an event loop built on the C library libuv. The language itself (ECMAScript) has no files, network or processes: a runtime adds them. In Python terms, Node is both the interpreter (python) and a large standard library. You write a file and run it; there is no compile step.

a1_hello.mjs
// hello.mjs: run with  node hello.mjs  (.mjs means "an ES module"; section 6)
const name = "Khalid";                  // const: this name is never rebound
let count = 3;                          // let: a variable you may reassign
count = count + 1;
console.log(`hello ${name}, count is ${count}`);   // backticks: a template string, like an f-string
console.log("typeof count:", typeof count, " typeof name:", typeof name);
console.log("runtime:", process.version, "on", process.platform, process.arch);

  • File extensions. .mjs is always an ES module, .cjs always CommonJS; plain .js follows the nearest package.json's "type" field. Use ES modules for anything new (how the two systems differ and interoperate: JavaScript: values, objects, functions and modules for Python programmers, section 5).
  • Interactive. node alone opens a REPL, like python; node -e "console.log(1 + 1)" runs one line; node --watch app.mjs reruns on every save.
  • Debugging. node --inspect-brk app.mjs pauses on the first line and lets Chrome's DevTools (or VS Code) attach: breakpoints, stepping, the call stack (Python's pdb, with a GUI).
  • TypeScript. node app.ts strips the types and runs the file; npx tsc --noEmit is what checks them. The TypeScript page covers both.
  • Which Node. Even-numbered releases become long-term support (LTS). On 2026-10-05, Node 24 is the Active LTS and Node 26 is "Current", due to become LTS on 2026-10-28 (Node.js releases); from Node 27 every major release will be LTS, once a year. Install it with a version manager (nvm, fnm, mise) rather than a system package. The root's Toolchain atlas tab has the dated release grid.

2. Node essentials: files, the process, streams, fetch, workers

Node's standard library is imported with a node: prefix. Five modules cover most scripts and services: node:fs/promises (files), node:path and node:os, node:process (also a global), node:http plus the global fetch, and node:worker_threads. A Buffer (or Uint8Array) is Python's bytes. Every call that waits returns a promise, so each section of a script is an await, and the thread is free meanwhile.

Files and the process

node:fs/promises has the async file API (open, read, write, stat, readdir, mkdir, rm); a missing file rejects with an error whose code is "ENOENT", as Python's FileNotFoundError carries errno. process.argv is sys.argv with two leading entries (the node binary and the script), so sys.argv[1:] is slice(2); process.env is os.environ (a missing variable is undefined); node:util's parseArgs is a small argparse. Prefer setting process.exitCode to calling process.exit(), which kills pending output and timers.

// The root page's running program (count tokens per user in a JSONL chat log, print the top 5), in plain JavaScript.
// It streams the file line by line, so memory stays flat whatever the file size. Part 2 adds the types.
import { createReadStream } from "node:fs";
import { createInterface } from "node:readline";

const isMessage = v => typeof v === "object" && v !== null && !Array.isArray(v)
  && typeof v.user === "string" && typeof v.text === "string";
const countTokens = text => (text.match(/[A-Za-z0-9]+/g) ?? []).length;

const path = process.argv[2] ?? "chat.jsonl";
const perUser = new Map();
let lines = 0, ok = 0, bad = 0, firstBad = 0;
try {
  const input = createReadStream(path, { encoding: "utf8" });
  for await (const line of createInterface({ input, crlfDelay: Infinity })) {
    lines++;
    let rec;
    try { rec = JSON.parse(line); } catch { rec = undefined; }
    if (!isMessage(rec)) { bad++; firstBad ||= lines; continue; }
    ok++;
    perUser.set(rec.user, (perUser.get(rec.user) ?? 0) + countTokens(rec.text));
  }
} catch (e) {
  console.error(`error: cannot open ${path}: ${e.code}`);
  process.exit(1);
}
let total = 0;
for (const n of perUser.values()) total += n;
const top = [...perUser].sort((a, b) => b[1] - a[1] || (a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0));
console.log(`lines ${lines}  ok ${ok}  malformed ${bad} (first at line ${firstBad})`);
console.log(`users ${perUser.size}  tokens ${total}`);
console.log("top 5 users by tokens:");
top.slice(0, 5).forEach(([user, n], i) => console.log(`${String(i + 1).padStart(2)}. ${user}  ${n}`));

HTTP and fetch

fetch is built in (stable since Node 21) and is the same API as in browsers: await fetch(url, { method, headers, body, signal }), then await res.json() or res.text() or res.body (a stream). An HTTP error status does not throw; only a network failure does. Check res.ok (Python's requests does not raise either, unless you call raise_for_status()). A local server stands in for a JSON API:

// fetch is built in (Node 18+): the same API as in browsers. A local server stands in for a JSON API.
import { createServer } from "node:http";
const server = createServer((req, res) => {
  let body = "";
  req.on("data", c => body += c).on("end", () => {
    if (req.url === "/fail") { res.writeHead(503).end("overloaded"); return; }
    res.writeHead(200, { "content-type": "application/json" }).end(JSON.stringify({ echo: JSON.parse(body || "{}"), method: req.method }));
  });
}).listen(0);
const base = `http://127.0.0.1:${server.address().port}`;
const res = await fetch(`${base}/v1/chat`, {
  method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ model: "small", messages: [{ role: "user", content: "hi" }] }),
});
console.log(res.status, res.ok, res.headers.get("content-type"));
console.log(JSON.stringify(await res.json()));
const bad = await fetch(`${base}/fail`);           // an HTTP error status does NOT throw: check res.ok yourself
console.log(bad.status, bad.ok, await bad.text());
server.close();
const gone = createServer().listen(0), port = gone.address().port; gone.close();   // a port nobody listens on
try { await fetch(`http://127.0.0.1:${port}/v1/chat`); }   // only network failures throw
catch (e) { console.log(e.name, e.message, "| cause:", e.cause?.code); }

Worker threads: CPU work off the event loop

One thread means CPU-heavy work (parsing a huge JSON, hashing, tokenising a corpus) stops everything else: timers, requests, streams. A worker thread is a second V8 instance on another OS thread with its own event loop; it shares nothing by default and talks by messages (postMessage, copied with the structured clone algorithm), or shares memory explicitly through a SharedArrayBuffer with Atomics. It is closer to Python's multiprocessing than to threading, but cheaper to start. Below, a 10 ms heartbeat timer measures how long the event loop was stuck while the same prime count ran on the main thread, then in a worker.

k6_workers.mjs
// CPU work blocks the event loop; a worker thread runs it on another core. A 10 ms heartbeat timer shows the difference.
import { Worker } from "node:worker_threads";
function primes(n) { let c = 0; for (let i = 2; i < n; i++) { let p = true; for (let j = 2; j * j <= i; j++) if (i % j === 0) { p = false; break; } if (p) c++; } return c; }
async function heartbeat(label, work) {
  let last = performance.now(), worst = 0, beats = 0;
  const t = setInterval(() => { const now = performance.now(); worst = Math.max(worst, now - last); last = now; beats++; }, 10);
  const t0 = performance.now(); const result = await work();
  await new Promise(r => setTimeout(r, 30)); clearInterval(t);
  console.log(`${label.padEnd(24)} result ${result}  took ${Math.round(performance.now() - t0 - 30)} ms  heartbeats ${beats}  worst gap ${Math.round(worst)} ms`);
}
const N = 3_000_000;
await heartbeat("on the main thread:", async () => primes(N));
await heartbeat("in a worker thread:", () => new Promise((ok, fail) => {
  const w = new Worker(`const { parentPort, workerData } = require("node:worker_threads");
    ${primes.toString()}
    parentPort.postMessage(primes(workerData));`, { eval: true, workerData: N });
  w.once("message", ok); w.once("error", fail);
}));

Why the loop freezes, step by step, and the same work as four schedules (sequential, Promise.all, a busy loop, a worker) is on JavaScript: the event loop, promises and streams, section 3. The root page's Reading, Concurrency section shows workers losing updates on a shared counter without Atomics and getting it exact with them.

3. Runtimes and packages: Node, npm and pnpm, Bun and Deno

package.json is pyproject.toml: name, version, "type", "scripts" (named commands run by npm run name), "dependencies" and "devDependencies" (tools only needed to develop, such as test runners). Versions are semver ranges: ^5.2.1 means "5.x.y, at least 5.2.1". The exact resolved tree is pinned in a lockfile (package-lock.json, like uv.lock); commit it, and install from it in CI with npm ci. Packages go into a local node_modules/ folder per project: there is no global site-packages and no virtual environment to activate, because every project is already isolated. npx tool (or pnpm dlx, bunx) runs a package's command without installing it, like uvx. A library's "exports" map, which decides which file each importer gets, is on the TypeScript page with publishing.

Node is not the only runtime, and npm is not the only installer. The four tools side by side, with this laptop's measurements (Apple M1 Pro, 2026-10-05; the runs are below the table):

Untrusted JSON merged into objects (prototype pollution), eval, and regexes on user input

A naive recursive merge copies a "__proto__" key from JSON onto Object.prototype, and then every object in the process has the attacker's property:

after safeMerge, isAdmin = undefined
The script: x2_pollution.mjs
x2_pollution.mjs
// Prototype pollution: a naive deep merge of untrusted JSON can write to Object.prototype, changing EVERY object.
function merge(dst, src) {
  for (const k in src) {
    if (typeof src[k] === "object" && src[k] !== null) { dst[k] ??= {}; merge(dst[k], src[k]); }
    else dst[k] = src[k];
  }
  return dst;
}
const body = JSON.parse('{"theme": "dark", "__proto__": {"isAdmin": true}}');   // JSON.parse makes "__proto__" an ordinary key
merge({}, body);
const user = {};
console.log("a brand-new object says isAdmin =", user.isAdmin);
delete Object.prototype.isAdmin;
function safeMerge(dst, src) {                                      // fix: skip the dangerous keys (or merge into Object.create(null) / a Map)
  for (const k of Object.keys(src)) {
    if (k === "__proto__" || k === "constructor" || k === "prototype") continue;
    if (typeof src[k] === "object" && src[k] !== null) { dst[k] ??= {}; safeMerge(dst[k], src[k]); } else dst[k] = src[k];
  }
  return dst;
}
safeMerge({}, body);
console.log("after safeMerge, isAdmin =", ({}).isAdmin);

Skip __proto__, constructor and prototype keys, merge into Object.create(null) or a Map, or validate the shape first (zod, on the TypeScript page). Never pass input to eval or new Function. A regex with nested quantifiers such as /(a+)+$/ can take exponential time on a crafted string and block the event loop (ReDoS); keep patterns simple or bound the input length.

Corrections to the old page "JavaScript: zero to expert" (checked 2026-10-05)
  • "a rejected promise inside a non-awaited call disappears": wrong for Node since version 15 (2020); the default --unhandled-rejections=throw crashes the process with exit code 1 (real run on the event-loop page). Browsers log an "Uncaught (in promise)" error and carry on.
  • "parseInt without a radix": the classic trap (a leading zero meaning octal) was removed in ES5 (2009): parseInt("08") is 8 (real run on the language page). Passing 10 is still clearer, and "0x10" still parses as hexadecimal.
  • Bun "reported to be acquired by Anthropic in early 2026": Bun's own announcement is dated 2025-12-02 (section 3).
  • "Use ES modules, not CommonJS require": still right; new since: require() of an ES module works without a flag since Node 22.12 and 20.19 (stable in 25.4), except with top-level await (the language page, section 5).
  • Confirmed: Node 24 Active LTS and Node 26 becoming LTS in October 2026 (scheduled 2026-10-28); Temporal on by default in Node 26 (real run above); a promise is eager; typeof null === "object"; V8's tiers and hidden classes (the language page, section 8, with a real trace).
