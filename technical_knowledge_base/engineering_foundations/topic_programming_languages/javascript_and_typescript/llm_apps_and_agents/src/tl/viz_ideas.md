# TypeScript: LLM apps and agents (tl): visualisation ideas

2026-10-26 child split: 1 and 2 dropped (owned by Topic: agentic-harnesses, Loop lab, and the MCP page); 3 and 4 kept inline. Added: the hero (parts of an LLM app, zod at each boundary; static SVG, two layouts), the retry timeline (a3, static), the four-run table (c1, static, replaces the stepper), the input-per-turn bars (e1; 6 was rejected before, kept now as a one-glance visual beside the quadratic claim), the backpressure bars (h2; two bars, not an animation).

Ranked by how much they teach that a static view cannot (1 to 5), all built from recorded runs.

1. **Agent loop stepper (tab, built, 5).** The same task under four scenarios (happy, tool error, slow tool, runaway); frames: request (whole messages array resent), reply (stop_reason, blocks), tools run (ms bars, Promise.all wall time), end. Counters: model calls, messages, tokens, cost. Before/after: the guards acting (is_error recovery, timeout, maxSteps). Data: `outputs/c1_agent_loop.json`.
2. **MCP message flow (tab, built, 5).** Client/server sequence with every JSON-RPC message pretty-printed; toggle stdio vs Streamable HTTP (same conversation, different envelope: POST/GET/DELETE, session and protocol headers). Data: `g2_mcp_client.json`, `g3_mcp_http.json`.
3. **Stream inspector (Reading, built, 4).** The same answer as Anthropic SSE frames vs OpenAI Responses frames, plus a tool call's partial JSON; each frame raw, with the assembled text or arguments computed live. Before/after: two wire formats of one answer. Data: `b1_stream.json`, `b2_stream_openai.json`.
4. **Cancellation before/after (Reading, built, 4).** Browser, server, model lanes plus 114 cells (read, wasted, never generated); toggle abort propagation on/off. Data: `h1_serve.txt` (one step in the "without" run is an estimated midpoint, said on the page).
5. Backpressure (rejected as an animation, 2): two numbers (2,070 KiB vs 64 KiB) say it; kept as a predict-then-reveal.
6. Token growth per turn chart (rejected, 2): six numbers in the e1 output and one sentence (quadratic) are enough.
7. Live in-page agent against a JS mock (rejected): would duplicate the stepper with invented answers; the page's rule is recorded outputs.

Methodology gap: the methodology assumes real data; here the model is a scripted mock by necessity (no API key, no paid calls). Each visual says which parts are real (SDK frames, tool outputs, timings) and which are synthetic (model text, token estimates).

## 2026-11-07: the split layout and 3D stages (renderer v2)
- **Built, 3D: Fig. 2, one streamed request** (`parts/31_js_sc_stream.js`). The request goes out once; the recorded frames come back on one open response, pass the SDK's parser (a glass plate; the ping is dropped there) and land in order as typed events whose height is the frame's size on the wire; the Message (or Response) at the front is assembled from them. Depth earns its place here because three things happen at once on different planes (the wire, the event log, the object being assembled) and the flat inspector could show only one frame at a time. Three modes, 7, 6 and 7 steps, each step one stretch of frames grouped by event kind (the long-replay rule: 24 frames are never 24 steps).
- **Built, 3D: Fig. 3, the four recorded runs of the hand-written loop** (`parts/32_js_sc_loop.js`, `TL.agent`). Your loop with `messages[]` as a stack of plates (the real count), a cost meter, the model API, and the two tools behind a zod gate; one step per model call, calls crossing the gate together, results and errors coming back. It replaces nothing (the run table stays as the summary); it shows the guards acting, which the table only states. It does not redraw one turn of the loop, which Topic: agentic-harnesses and Building a harness own (their Fig. 1 stages).
- **Kept as a widget, 2D: the stream inspector** (no autoplay, no step list; opens on the first text frame). The raw bytes of each frame are text and read best as text.
- **Kept 2D, now with a step list: cancellation before/after.** Its message is a count (114 events, 3 read, 6 or 114 generated) on a grid of cells, which reads flat; a 3D version would add nothing but motion.
- **Kept 2D: the hero** (structure: the parties and where zod sits; a static diagram is the right kind), **the retry timeline** (a timeline), **the input-per-turn bars and the backpressure bars** (two to six numbers).
- **Rejected: 3D for the MCP section** (the protocol and a stepped session are owned by the MCP page) and for structured output (a schema doing three jobs is a sentence and a recorded output).
