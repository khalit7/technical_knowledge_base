8. MCP in TypeScript: a server, a client, an agent that uses them

The Model Context Protocol moves tools out of the agent's program into a separate process, so one tool server works with Claude Code, an IDE or your own agent. The protocol (JSON-RPC 2.0 messages, the three server primitives, the lifecycle, the transports, authorisation, security) and a step-through of a real session are on {{MCP|n:3c65c17b0d0d813f9695dc4175c44cbb}}. Here is the TypeScript: the official SDK, which negotiated protocol version 2025-11-25 in these runs.

export function buildServer() {
  const server = new McpServer({ name: "chat-stats", version: "1.0.0" });

  server.registerTool("count_tokens", {
    title: "Count tokens per user",
    description: "Count word tokens per user in a JSONL chat log; returns totals and the top users.",
    inputSchema: CountArgs.shape,                       // validated by the SDK before the handler runs
    annotations: { readOnlyHint: true },
  }, async (args) => {
    try {
      const stats = await countTokens(args);
      return { content: [{ type: "text", text: JSON.stringify(stats) }] };
    } catch (e: any) {                                  // a tool failure is a result the model can read, not a protocol error
      return { isError: true, content: [{ type: "text", text: `cannot open ${args.path}: ${e.code}` }] };
    }
  });

  server.registerResource("chat-log", "file:///chat.jsonl", { title: "The chat log", mimeType: "application/json" },
    async (uri) => {
      const s = await stat("chat.jsonl");
      return { contents: [{ uri: uri.href, text: JSON.stringify({ bytes: s.size, format: "JSONL, one message per line" }) }] };
    });

  server.registerPrompt("heaviest-users", {
    description: "Ask for the heaviest users of a chat log",
    argsSchema: { n: z.string().describe("how many users") },
  }, ({ n }) => ({ messages: [{ role: "user", content: { type: "text", text: `Who are the ${n} heaviest users in chat.jsonl? Use count_tokens.` } }] }));

  return server;
}

registerTool takes the zod shape; the SDK turns it into the JSON Schema clients see, and validates arguments before your handler runs. A failure inside the tool goes back as a result with isError: true, which the model can read and react to. A client starts the server as a child process (the stdio transport) and asks what it offers; it owns the server's lifetime, and the server must log to stderr, because stdout belongs to the protocol.

// Glue: an agent whose tools come from an MCP server. tools/list becomes the API's tools; a tool_use becomes tools/call.
import Anthropic from "@anthropic-ai/sdk";
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
import { startMock } from "./mock_model.ts";

const mcp = new Client({ name: "agent", version: "1.0.0" });
await mcp.connect(new StdioClientTransport({ command: process.execPath, args: ["g1_mcp_server.ts"], cwd: new URL(".", import.meta.url).pathname }));
const tools: Anthropic.Tool[] = (await mcp.listTools()).tools.map(t =>
  ({ name: t.name, description: t.description ?? "", input_schema: t.inputSchema as Anthropic.Tool.InputSchema }));

const mock = await startMock();
const client = new Anthropic({ baseURL: mock.url, apiKey: "mock-key", defaultHeaders: { "x-mock-scenario": "typo" } });
const messages: Anthropic.MessageParam[] = [{ role: "user", content: "Who are the 3 heaviest users in chat.jsonl, and what share of all tokens do they have?" }];
for (let step = 1; step <= 5; step++) {
  const msg = await client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 2048, tools, messages });
  messages.push({ role: "assistant", content: msg.content });
  if (msg.stop_reason !== "tool_use") { console.log("answer:", msg.content.map(b => b.type === "text" ? b.text : "").join("")); break; }
  const results: Anthropic.ToolResultBlockParam[] = [];
  for (const b of msg.content) if (b.type === "tool_use") {
    const r = await mcp.callTool({ name: b.name, arguments: b.input as Record<string, unknown> });
    const text = (r.content as { type: string; text: string }[]).map(c => c.text).join("");
    console.log(`step ${step}: tools/call ${b.name}(${JSON.stringify(b.input)}) -> ${r.isError ? "isError " : ""}${text.slice(0, 70)}`);
    results.push({ type: "tool_result", tool_use_id: b.id, content: text, is_error: !!r.isError });
  }
  messages.push({ role: "user", content: results });
}
await mcp.close(); await mock.close();
Found while recording: a wrapper must forward everything
To record the messages, mcp_tap.ts wraps the client's transport. The first version forwarded start, send and close but not the optional setProtocolVersion; over HTTP the client then sent no mcp-protocol-version header after initialisation, with no error anywhere. Forwarding it fixed the run above. In TypeScript, an optional method on an interface (setProtocolVersion?:) type-checks whether or not you implement it, so a wrapper can silently change behaviour.

9. Serving: stream to the browser, cancel when it leaves

A web app puts your server between the browser and the model: the browser calls /ask, your server calls the model with the API key (which must never reach the browser, nor a logged request), and forwards each text piece as an SSE event. Two things go wrong in production that never show in a demo.

Cancellation. Users close tabs. If your server does not notice, the model keeps generating, and you pay for every token nobody will read. In Node the response's close event fires when the client goes away; hand an AbortController's signal to the SDK call and abort it there. The SDK then closes the upstream HTTP request and throws APIUserAbortError, which you catch. Predict before stepping: with nobody aborting, how many of the 114 events does the model still generate?

Cancelling a stream on the wire (what each side sees, where the provider stops billing) is on {{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}; AbortController itself on the event-loop page.

Backpressure. res.write() returns false when the bytes cannot leave as fast as you write them (a slow phone, a congested link); Node then keeps the rest in memory, so a server that ignores the false can hold the whole response in RAM for every slow client at once. The fix is one line: when write returns false, await once(res, "drain") before writing more.

h2_backpressure.ts
// Backpressure: res.write() returns false when the socket cannot keep up. Ignore it and Node queues the bytes in memory.
import { createServer, request } from "node:http";
import { once } from "node:events";

const EVENTS = 20000, EVENT = `data: ${JSON.stringify("x".repeat(90))}\n\n`;   // about 2 MB in total
async function run(respect: boolean) {
  let peak = 0, falses = 0;
  const server = createServer(async (_req, res) => {
    res.writeHead(200, { "content-type": "text/event-stream" });
    for (let i = 0; i < EVENTS; i++) {
      const ok = res.write(EVENT);
      peak = Math.max(peak, res.writableLength);              // bytes queued inside this process
      if (!ok) { falses++; if (respect) await once(res, "drain"); }
    }
    res.end();
  });
  await new Promise<void>(r => server.listen(0, "127.0.0.1", r));
  const t0 = performance.now();
  await new Promise<void>(done => request({ port: (server.address() as any).port, path: "/" }, async (res) => {
    res.pause(); await new Promise(r => setTimeout(r, 300));    // a slow reader: reads nothing for 300 ms
    res.resume(); res.on("end", done);
  }).end());
  server.close();
  console.log(`${respect ? "awaits drain " : "ignores false"}: write() returned false ${String(falses).padStart(5)} times, peak queued in the server ${(peak / 1024).toFixed(0).padStart(5)} KiB, ${Math.round(performance.now() - t0)} ms`);
}
console.log(`${EVENTS} events of ${EVENT.length} bytes = ${(EVENTS * EVENT.length / 1024).toFixed(0)} KiB to a client that waits 300 ms before reading`);
await run(false);
await run(true);

The 64 KiB plateau is Node's default stream buffer size (highWaterMark, 65,536 bytes; printed by stream.getDefaultHighWaterMark(false) on Node 24.21.0). With LLM tokens arriving at tens per second the risk is small for one stream, but a proxy that relays many streams, or a server that forwards a fast upstream to slow clients, needs it. stream.pipeline() and .pipe() handle backpressure for you when both ends are Node streams.

The browser side is the same fetch and stream-reading code as the Node "browser" in h1_serve.ts (it runs unchanged in a browser); EventSource cannot send a POST body or custom headers, so fetch is the usual choice for a chat (its limits: {{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}). Bun runs the same server code (it implements node:http: Bun's Node.js compatibility list), or its own Bun.serve with web-standard Request and Response. Before you ship: the twelve mistakes this page's runs show
  • Reading content[0].text without checking the block type or stop_reason: the first block may be thinking or tool_use, and a max_tokens stop means the text is cut off. TypeScript's narrowing forces the check if you let it.
  • An agent loop without a step limit or tool timeouts: the runaway run, in production, with a real bill.
  • Trusting tool arguments. They are model output: validate with zod, and check what paths and URLs point at.
  • Throwing from a tool instead of returning is_error: the run dies on a problem the model could have fixed (the typo run fixed its own mistake).
  • await in a for loop over tool calls, running them one after another when Promise.all would run them together; and splitting their results over several messages instead of one.
  • Forgetting that the API is stateless, or never trimming: the bill grows with the square of the conversation's length.
  • Dropping the zod check because the API constrained the output: patterns and ranges are not enforced by the API (section 5).
  • Ignoring disconnects and write()'s return value in the server: paying for unread tokens and holding responses in memory.
  • Logging to stdout in a stdio MCP server: it corrupts the protocol stream.
  • Putting the API key in browser code, or in a logged request. Keys belong in server-side environment variables; this page's scripts unset them before running (API keys in general: {{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}).
  • Catching errors by message text instead of instanceof Anthropic.RateLimitError and friends; and adding your own retry loop around an SDK that already retries.
  • Relying on a framework default you have not read: generateText's single step, allowedTools meaning "no approval needed" rather than "only these".
