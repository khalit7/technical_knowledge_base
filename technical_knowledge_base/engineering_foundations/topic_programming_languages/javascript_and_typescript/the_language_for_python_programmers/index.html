1. Values and types

JavaScript has seven primitive types (number, bigint, string, boolean, undefined, null, symbol) and objects (everything else: arrays, functions, dates, maps). Primitives are immutable and compared by value; objects are compared by identity. typeof x tells you which, with one historical lie (typeof null is "object").

Numbers: everything is a double

In Python, 7 is an int of any size and 7.0 a float. JavaScript has only the float: an IEEE 754 64-bit double, so integer arithmetic is exact only up to 253 − 1 (Number.MAX_SAFE_INTEGER), and / never truncates. How a double stores its bits, rounding and ulp are taught on Numerical computing for ML; here is what it does to integers.

b1_numbers.mjs
// One number type: a 64-bit IEEE 754 double, exactly like a Python float.
console.log(0.1 + 0.2);                       // same as Python
console.log(7 / 2, -7 / 2);                   // no integer division: / always gives a double
console.log(Math.trunc(-7 / 2), Math.floor(-7 / 2), -7 % 2);   // Python's -7 // 2 is -4, -7 % 2 is 1
console.log(Number.MAX_SAFE_INTEGER);         // 2**53 - 1: the last integer every double can hold
console.log(2 ** 53 + 1);                     // rounded: the + 1 is lost
console.log(JSON.parse('{"id": 1234567890123456789}').id);   // a 64-bit id from an API, silently changed
console.log(1 / 0, -1 / 0, 0 / 0);            // no ZeroDivisionError: Infinity and NaN
console.log(NaN === NaN, Number.isNaN(0 / 0));
console.log(parseInt("42px"), Number("42px"), parseInt("08"), (255).toString(16));

Strings: UTF-16 code units

A Python str is a sequence of Unicode code points, so len("🚀") is 1. A JavaScript string is a sequence of UTF-16 code units: characters outside the Basic Multilingual Plane (emoji, many CJK extensions) take two units, a "surrogate pair". .length, indexing and slice count units; iteration (for...of, [...s]) goes by code point. Strings are immutable, as in Python.

b3_strings.mjs
// Strings are immutable sequences of UTF-16 code units (Python: sequences of code points).
const s = "héllo 🚀";
console.log(s.length);                        // 8: the rocket is TWO UTF-16 units (a surrogate pair)
console.log([...s].length);                   // 7: spreading iterates by code point
console.log(s.slice(0, 7), "|", s.slice(0, 8)); // slicing in the middle of the pair leaves half a character
console.log(s.codePointAt(6).toString(16), s.charCodeAt(6).toString(16));

console.log("a,b,,c".split(","), "  pad ".trim(), "ab".repeat(3), "abc".at(-1));
console.log("10" + 1, "10" - 1, "3" * "4");   // + concatenates if either side is a string; - * / convert to numbers

Two kinds of nothing: undefined and null

Python has None. JavaScript has undefined ("never set": a missing property, a missing argument, a function with no return) and null ("set to nothing on purpose"). Reading a missing property is not an error; the error comes when you read a property of undefined or null. Optional chaining a?.b stops at either, and x ?? fallback replaces only those two (unlike ||, which also replaces 0 and "").

b4_nullish.mjs
// Two "nothing" values. undefined: "never set". null: "set to nothing on purpose". Python has only None.

const obj = { x: 1 };
console.log(a, obj.y, [1, 2][5]);             // missing things are undefined, not errors
console.log(typeof undefined, typeof null);   // typeof null is "object": a bug kept since 1995 for compatibility
console.log(null == undefined, null === undefined);
function f(x) { return x; }
console.log(f(), f(null));                    // a missing argument is undefined, not a TypeError
console.log(obj.y ?? "default", 0 ?? "default", 0 || "default");  // ?? replaces only null/undefined; || replaces any falsy
const user = { profile: null };
console.log(user.profile?.name, user.settings?.theme?.dark);       // ?. stops at null/undefined
try { console.log(user.profile.name); } catch (e) { console.log(e.constructor.name + ": " + e.message); }

== ("loose equality") converts both sides by a table of rules before comparing; === ("strict equality") never converts. Always write === and !==; the one common exception is x == null, which is true for exactly null and undefined. Objects and arrays compare by identity under both, like Python's is; there is no built-in deep equality.

Variables: const, let, never var

Python has function scope: a name assigned inside an if is visible after it. JavaScript's let and const are scoped to the enclosing block { ... }; the old var is function scoped and "hoisted" (created at the top of the function), which is why old code is full of bugs. A let used before its line throws (the "temporal dead zone"). const stops rebinding, not mutation: a const object can still change (Object.freeze stops that). Default to const, use let when you reassign.

2. Objects, arrays, destructuring, copies

An object literal { role: "user", text: "hi" } is what you reach for where Python uses a dict, a dataclass or a SimpleNamespace: a bag of properties you read as msg.role or msg["role"]. Two differences matter. Keys are always strings (or symbols): 1 and "1" are the same key. And iteration order is insertion order except that integer-like keys come first, in numeric order. For a real hash map with keys of any type, use Map; for a set, Set. Both compare keys by identity for objects (there is no __hash__).

3. Functions, closures and this

Functions are values, as in Python. There are three spellings; the arrow function x => x * 2 is the everyday one (a lambda that may also have a block body). Arguments are not checked: extra ones are ignored, missing ones are undefined. Default values are evaluated on every call, so Python's mutable-default trap does not exist here (it runs in reverse).

d1_functions.mjs
// Three ways to write a function. All are objects you can pass around, as in Python.
function add(a, b = 10) { return a + b; }        // declaration: hoisted, usable above this line
const mul = function (a, b) { return a * b; };   // expression
const sq = x => x * x;                           // arrow: short, and no own `this` (below)
const sum = (...nums) => nums.reduce((s, n) => s + n, 0);   // rest parameter: Python's *args
console.log(add(1), add(1, 2), mul(3, 4), sq(5), sum(1, 2, 3));
console.log(add(1, 2, 99), add());               // extra arguments are ignored; missing ones are undefined
function push(x, xs = []) { xs.push(x); return xs; }
console.log(push(1), push(2));                   // defaults are evaluated on EVERY call (Python: once, at def)

A closure is a function that keeps the variables of the scope it was created in, exactly as in Python (without needing nonlocal to assign). Closures are how JavaScript does private state, callbacks and factories. The classic loop trap: var gives every iteration the same variable; let gives each iteration a fresh one.

d2_closures.mjs
// A closure: a function that keeps the variables of the scope it was created in.
function makeCounter() {
  let n = 0;                                    // private: nothing outside can reach n
  return { inc: () => ++n, get: () => n };
}
const c1 = makeCounter(), c2 = makeCounter();
c1.inc(); c1.inc(); c2.inc();
console.log(c1.get(), c2.get());
const withVar = [], withLet = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);   // one i shared by all three closures
for (let j = 0; j < 3; j++) withLet.push(() => j);   // a fresh j per iteration
console.log(withVar.map(f => f()), withLet.map(f => f()));

this

Inside a function, this is not fixed when the function is written; it is set by the call. obj.method() sets this to obj; calling the same function bare (const f = obj.method; f()) sets it to undefined (in modules and classes, which are always "strict mode"). That is the commonest bug in the language: passing obj.method as a callback loses obj. Arrow functions have no this of their own and use the surrounding one, which is why callbacks inside methods are written as arrows. fn.bind(obj) makes a copy with this fixed (Python makes bound methods for you; JavaScript does not).

d3_this.mjs
// `this` is decided by HOW a function is called, not where it is written.
const bot = {
  name: "bot",
  hello() { return `hi from ${this?.name}`; },
  later() { return [1].map(function () { return this?.name; }); },   // a plain callback: this is lost
  laterArrow() { return [1].map(() => this.name); },                 // an arrow keeps the outer this
};
console.log(bot.hello());                       // called as bot.hello(): this = bot
const loose = bot.hello;
console.log(loose());                           // called bare: this = undefined (modules are strict)
console.log(bot.later(), bot.laterArrow());
const bound = bot.hello.bind(bot);              // Python's bound method, made by hand
console.log(bound(), bot.hello.call({ name: "other" }));

4. Classes and prototypes

class looks like Python's: a constructor is __init__, this is self (implicit, never a parameter), extends and super work as expected, get defines a property. Differences: fields can be declared in the body; #name fields are truly private, enforced by the parser (Python's _name is a convention); there is single inheritance only; and there is no operator overloading (no __eq__, __add__, __len__).

// class: syntax over prototypes. Fields, #private fields, static members, getters, extends and super.
class Counter {
  #counts = new Map();                          // # = truly private (Python's _ is only a convention)
  static created = 0;
  constructor(name) { this.name = name; Counter.created++; }   // Python's __init__; `this` is self
  add(user, n = 1) { this.#counts.set(user, (this.#counts.get(user) ?? 0) + n); return this; }
  get total() { let t = 0; for (const v of this.#counts.values()) t += v; return t; }   // like @property
  toString() { return `${this.name}: ${this.total}`; }   // like __str__ (used by template strings)
}
class TopCounter extends Counter {
  constructor(name, k) { super(name); this.k = k; }
  add(user, n) { return super.add(user, Math.min(n, this.k)); }
}

Depth: the few hooks instead of dunder methods, and Proxy

The few hooks JavaScript offers instead of dunder methods are keyed by well-known symbols: Symbol.iterator (__iter__), Symbol.asyncIterator (__aiter__), Symbol.toPrimitive (roughly __int__ and __str__), plus toString and toJSON. With no __eq__ or __add__, == on two objects is identity and + goes through toPrimitive.

e3_dunders.mjs
// Python's dunder methods have a few JavaScript counterparts, keyed by well-known Symbols.
class Range {
  constructor(n) { this.n = n; }
  *[Symbol.iterator]() { for (let i = 0; i < this.n; i++) yield i; }   // __iter__
  [Symbol.toPrimitive](hint) { return hint === "number" ? this.n : `Range(${this.n})`; }
}
const r = new Range(3);
console.log([...r], `${r}`, +r, r * 2);
const a = new Range(1), b = new Range(1);
console.log(a == b, a + b);                     // no __eq__ or __add__ overloading: == is identity, + uses toPrimitive

5. Modules: ES modules and CommonJS

JavaScript has two module systems, and Node runs both. ES modules (ESM, the standard since 2015): import and export, loaded and linked before any code runs, asynchronous, with top-level await. CommonJS (CJS, Node's original): require() and module.exports, synchronous, still in many packages. Python has one system; its import is closest to require (synchronous, runs the module once, caches it).

Node picks the system per file, and the two meet in one place that can fail

.mjsalways an ES module
.cjsalways CommonJS
.jsthe "type" field of the nearest package.json: "module" gives ESM, missing or "commonjs" gives CJS
ESM import of CJSworks: module.exports arrives as the default export
CJS require() of ESMworks since Node 22.12 and 20.19, without a flag; stable in 25.4
unless the ESM graph uses top-level awaitERR_REQUIRE_ASYNC_MODULE, because require must finish synchronously

All three cases ran in the real output below (Node docs, Loading ECMAScript modules using require()).

In ESM, relative imports need the file extension, and require, __filename and __dirname do not exist (use import.meta.url, import.meta.filename, import.meta.dirname). A module's body runs once, however many times it is imported.

6. Errors

throw, try/catch/finally work like Python's raise, try/except/finally, with three differences. There is one catch per try, with no type filter: test e instanceof X or e.code inside it and rethrow what you do not handle. Anything can be thrown, but only Error objects carry a stack, so always throw Error or a subclass. And chaining is explicit: new Error(msg, { cause: e }) is Python's raise ... from e.

7. Iteration: iterators and generators

for (const x of xs) is Python's for x in xs: it works on anything iterable (arrays, strings, maps, sets, generators). for...in is a different, older loop over an object's keys as strings, including inherited ones; it is almost never what you want on an array. The iterator protocol is Python's in disguise: xs[Symbol.iterator]() is iter(xs), and it.next() returns { value, done } instead of raising StopIteration.

h1_iter.mjs
// for...of walks VALUES (Python's for x in xs). for...in walks KEYS, as strings, and is rarely what you want.
const xs = ["a", "b"];
for (const x of xs) console.log("of:", x);
for (const k in xs) console.log("in:", k, typeof k);
for (const [k, v] of Object.entries({ u1: 3, u2: 9 })) console.log(k, v);   // dict.items()
for (const ch of "h🚀") console.log(ch, ch.length);                         // strings iterate by code point
const it = xs[Symbol.iterator]();               // the iterator protocol, by hand: iter(xs) and next()
console.log(it.next(), it.next(), it.next());

8. How V8 runs it: tiers, speculation and shapes

V8 does not interpret your code forever. It parses it to bytecode run by the Ignition interpreter, then compiles functions that get hot: Sparkplug (a fast baseline compiler), Maglev (a mid-tier optimising compiler, shipped in Chrome 117 in 2023) and TurboFan (the top tier) (V8 blog, Maglev). The optimising tiers speculate from what they have seen: "this argument has always been a small integer", "this object always has this shape". When a guess breaks, the code deoptimises back to the interpreter and may be recompiled later. You can watch it with node --trace-opt --trace-deopt; step through a real trace:

A function compiled for small integers is thrown away the first time it sees strings

The second lever is the hidden class (V8 calls it a "map"): objects with the same property names added in the same order share one, and each property access site caches the shapes it has seen ("inline caches"). A site that sees one shape is monomorphic and fast; past four it is megamorphic and does a slow lookup.

// The cost of shapes: the same loop over objects of 1 shape and of 8 shapes (V8 inline caches, measured).
function sumX(objs) { let s = 0; for (let r = 0; r < 200; r++) for (let i = 0; i < objs.length; i++) s += objs[i].x; return s; }
function make(nShapes, n) {
  const out = [];
  for (let i = 0; i < n; i++) {
    const o = {}; const k = i % nShapes;
    for (let j = 0; j < k; j++) o["p" + j] = j;    // k extra properties BEFORE x: a different hidden class per k
    o.x = 1; out.push(o);
  }
  return out;
}
function time(label, objs) {
  sumX(objs); sumX(objs);                          // warm up: let the JIT compile sumX for what it has seen
  const t = []; for (let k = 0; k < 7; k++) { const t0 = performance.now(); sumX(objs); t.push(performance.now() - t0); }
  t.sort((p, q) => p - q);
  console.log(`${label.padEnd(36)} median ${t[3].toFixed(1)} ms per 2,000,000 property reads`);
}
time("1 shape (monomorphic call site)", make(1, 10_000));
time("4 shapes (polymorphic)", make(4, 10_000));
time("8 shapes (megamorphic)", make(8, 10_000));


What to do with this
Create objects of one kind in one place (a constructor, a class, or one literal shape), with all fields set, in the same order; do not add properties later; do not delete (set to undefined instead); keep arrays of one element type.
What not to do
Do not micro-tune before profiling: node --cpu-prof app.mjs writes a profile that Chrome DevTools opens, and node --prof is the lower-level option. Most slow Node services are slow because something blocks the event loop or waits serially, not because of shapes.
