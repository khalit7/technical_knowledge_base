8. How V8 runs it: tiers, speculation and shapes

V8 does not interpret your code forever. It parses it to bytecode run by the Ignition interpreter, then compiles functions that get hot: Sparkplug (a fast baseline compiler), Maglev (a mid-tier optimising compiler, shipped in Chrome 117 in 2023) and TurboFan (the top tier) ({{V8 blog, Maglev|https://v8.dev/blog/maglev}}). The optimising tiers speculate from what they have seen: "this argument has always been a small integer", "this object always has this shape". When a guess breaks, the code deoptimises back to the interpreter and may be recompiled later. You can watch it with node --trace-opt --trace-deopt; step through a real trace:

The second lever is the hidden class (V8 calls it a "map"): objects with the same property names added in the same order share one, and each property access site caches the shapes it has seen ("inline caches"). A site that sees one shape is monomorphic and fast; past four it is megamorphic and does a slow lookup.

What to do with this
Create objects of one kind in one place (a constructor, a class, or one literal shape), with all fields set, in the same order; do not add properties later; do not delete (set to undefined instead); keep arrays of one element type.
What not to do
Do not micro-tune before profiling: node --cpu-prof app.mjs writes a profile that Chrome DevTools opens, and node --prof is the lower-level option. Most slow Node services are slow because something blocks the event loop or waits serially, not because of shapes.
