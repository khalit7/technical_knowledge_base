2. Objects, arrays, destructuring, copies

An object literal { role: "user", text: "hi" } is what you reach for where Python uses a dict, a dataclass or a SimpleNamespace: a bag of properties you read as msg.role or msg["role"]. Two differences matter. Keys are always strings (or symbols): 1 and "1" are the same key. And iteration order is insertion order except that integer-like keys come first, in numeric order. For a real hash map with keys of any type, use Map; for a set, Set. Both compare keys by identity for objects (there is no __hash__).

[[outc:c1_objects]]

Arrays are Python lists. The functional methods (map, filter, reduce, find, some, every, flatMap) return new arrays; push, pop, splice, sort and reverse change the array in place. The newer toSorted, toReversed and with (ES2023) are the non-mutating versions. sort() without a comparator converts every element to a string and compares those, so [1, 10, 2, 3] is "sorted": always pass (a, b) => a - b.

[[predict:c2_arrays]]

Destructuring is Python's unpacking, extended to objects and with defaults; spread ... is * and **. A function taking one destructured object parameter is the JavaScript way to write keyword arguments, and it is how most SDKs (including LLM clients) take options.

[[outc:c3_destructure]]

Copying. Assignment never copies, as in Python. Spread ({ ...o }, [...xs]) copies one level, like copy.copy; structuredClone copies deeply, like copy.deepcopy, and keeps dates, maps and cycles.

Fig. 2: after one push, the alias and the shallow copy both see 2 messages; the deep copy still has 1

  1. conv: one object, one array, one date. The literal makes a top object whose msgs and when are references to an array (one message) and a Date.
  2. alias = conv copies nothing. A second name for the same object, as alias = conv is in Python.
  3. shallow = { ...conv } copies one level. A new top object; spread copied only the top object, so its msgs is the same array and its when the same date.
  4. deep = structuredClone(conv) copies every level. A new object with its own array and its own date, still a Date (the last line of the run prints true).
  5. One push, seen through each. conv.msgs.push(...) adds to the one shared array. The run prints 2 2 1: alias.msgs.length, shallow.msgs.length, deep.msgs.length.
[[outc:c4_copy]]

The old JSON.parse(JSON.stringify(x)) trick, the second line above, silently turns dates into strings and drops undefined and functions (and turns NaN into null; it throws on cycles and BigInt). At boundaries, copy deeply with structuredClone; on shared arrays, prefer toSorted, toReversed and with over the in-place methods.

Memory is managed by a garbage collector, as in Python but with no reference counting: objects are freed some time after nothing reaches them, cycles included. A WeakMap attaches data to an object without keeping it alive, a cache that cannot leak.

3. Functions, closures and this

Functions are values, as in Python. There are three spellings; the arrow function x => x * 2 is the everyday one (a lambda that may also have a block body). Arguments are not checked: extra ones are ignored, missing ones are undefined. Default values are evaluated on every call, so Python's mutable-default trap does not exist here (it runs in reverse).

[[predict:d1_functions]]

A closure is a function that keeps the variables of the scope it was created in, exactly as in Python (without needing nonlocal to assign). Closures are how JavaScript does private state, callbacks and factories. The classic loop trap: var gives every iteration the same variable; let gives each iteration a fresh one.

[[predict:d2_closures]]

Fig. 3: a closure keeps the scope it was made in, after the call that made it has returned

  1. makeCounter() runs. The call gets a frame on the call stack and a scope holding its local n = 0.
  2. It returns, and its scope stays. The two arrow functions inc and get were made inside the call, so each keeps a reference to that scope. The frame is gone; the scope lives on because something still reaches it, and nothing outside can reach n except through them: private state without a class.
  3. A second call, a second scope. c2 = makeCounter() makes a new n and a new pair of functions that keep it.
  4. Each counter counts on its own. c1.inc() twice and c2.inc() once; the first line of the run prints 2 1.
  5. var: three closures, one i. A var belongs to the whole function, so all three functions keep the same binding, which is 3 when they run: [ 3, 3, 3 ]. Python's closures behave like the var side (late binding of the loop variable).
  6. let: a fresh j per iteration. Each iteration of a let loop gets its own binding, so each function keeps its own: [ 0, 1, 2 ], the second line of the run. let is the fix Python does not have.

this

Inside a function, this is not fixed when the function is written; it is set by the call. obj.method() sets this to obj; calling the same function bare (const f = obj.method; f()) sets it to undefined (in modules and classes, which are always "strict mode"). That is the commonest bug in the language: passing obj.method as a callback loses obj. Arrow functions have no this of their own and use the surrounding one, which is why callbacks inside methods are written as arrows. fn.bind(obj) makes a copy with this fixed (Python makes bound methods for you; JavaScript does not).
