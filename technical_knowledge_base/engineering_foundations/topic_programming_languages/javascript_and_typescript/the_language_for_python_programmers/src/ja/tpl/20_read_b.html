1. Values and types

JavaScript has seven primitive types (number, bigint, string, boolean, undefined, null, symbol) and objects (everything else: arrays, functions, dates, maps). Primitives are immutable and compared by value; objects are compared by identity. typeof x tells you which, with one historical lie (typeof null is "object").

Numbers: everything is a double

In Python, 7 is an int of any size and 7.0 a float. JavaScript has only the float: an IEEE 754 64-bit double, so integer arithmetic is exact only up to 253 − 1 (Number.MAX_SAFE_INTEGER), and / never truncates. How a double stores its bits, rounding and ulp are taught on {{Numerical computing for ML|n:3f05c17b0d0d81d6af0be4a9a2edba8d}}; here is what it does to integers.

What it costs
64-bit ids from APIs and databases silently lose digits when parsed from JSON; there is no integer division operator; 1 / 0 is Infinity, not a ZeroDivisionError.
Do instead
Keep ids as strings; use Math.trunc or Math.floor explicitly; parse with Number(s) (strict) rather than parseInt (stops at the first bad character), and give parseInt a radix. Money in integer cents or a decimal library.

BigInt is the exact, arbitrary-size integer (Python's int), written with a trailing n. It refuses to mix with numbers, and JSON.stringify refuses it, because JSON numbers are doubles.

Depth: number details that rarely matter

One numeric type is simple and fast; V8 still stores small integers ("Smis") as real integers internally (section 8). NaN === NaN is false; test with Number.isNaN. parseInt("08") is 8: the old trap where a leading zero meant octal was removed in ES5 (2009). ["1","2","3"].map(parseInt) is [1, NaN, NaN], because map passes the index as the radix (drill 9 in the playground).

Strings: UTF-16 code units

A Python str is a sequence of Unicode code points, so len("🚀") is 1. A JavaScript string is a sequence of UTF-16 code units: characters outside the Basic Multilingual Plane (emoji, many CJK extensions) take two units, a "surrogate pair". .length, indexing and slice count units; iteration (for...of, [...s]) goes by code point. Strings are immutable, as in Python.

Template strings (backticks) are f-strings: `${a} + ${b} = ${a + b}`. For token counting on LLM text, remember that neither units nor code points are tokens, and that byte lengths (what APIs bill and limit) come from TextEncoder.

Two kinds of nothing: undefined and null

Python has None. JavaScript has undefined ("never set": a missing property, a missing argument, a function with no return) and null ("set to nothing on purpose"). Reading a missing property is not an error; the error comes when you read a property of undefined or null. Optional chaining a?.b stops at either, and x ?? fallback replaces only those two (unlike ||, which also replaces 0 and "").

Truthiness and equality

The falsy values are false, 0, -0, 0n, "", null, undefined and NaN. Unlike Python, an empty array or object is truthy: test xs.length, not xs.

[[outc:b5_truthy]]

== ("loose equality") converts both sides by a table of rules before comparing; === ("strict equality") never converts. Always write === and !==; the one common exception is x == null, which is true for exactly null and undefined. Objects and arrays compare by identity under both, like Python's is; there is no built-in deep equality.

Variables: const, let, never var

Python has function scope: a name assigned inside an if is visible after it. JavaScript's let and const are scoped to the enclosing block { ... }; the old var is function scoped and "hoisted" (created at the top of the function), which is why old code is full of bugs. A let used before its line throws (the "temporal dead zone"). const stops rebinding, not mutation: a const object can still change (Object.freeze stops that). Default to const, use let when you reassign.
