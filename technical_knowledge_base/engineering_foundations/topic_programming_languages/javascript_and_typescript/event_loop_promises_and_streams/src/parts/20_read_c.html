2. The two queues, stepped through

When does a callback run? The event loop keeps two kinds of queue. Macrotasks: timer callbacks, I/O completions, setImmediate. Microtasks: promise reactions (.then callbacks and the continuation after an await) and queueMicrotask. The rule: run the current piece of synchronous code to the end; then run every microtask, including ones queued meanwhile; only then take the next macrotask. So a resolved promise's callback always beats a setTimeout(f, 0). Predict the order of the seven lines:

i3_order.mjs
// The classic ordering question. Predict the order of the seven lines before you look.
console.log("sync start");
setTimeout(() => console.log("setTimeout 0"), 0);
Promise.resolve().then(() => console.log("promise.then"));
queueMicrotask(() => console.log("queueMicrotask"));
(async () => {
  console.log("async body, before await");
  await null;
  console.log("async body, after await");
})();
console.log("sync end");
Predict the output, then reveal
real output, Node 24.21.0
sync start
async body, before await
sync end
promise.then
queueMicrotask
async body, after await
setTimeout 0

Why "async body, after await" comes after "queueMicrotask": the continuation of an async function is queued when it reaches await, which here is after the .then and queueMicrotask callbacks were queued, and microtasks run in the order they were queued.

The rules the six programs show
    

  • Synchronous code always runs to the end first. An async function runs synchronously until its first await.
    • 

  • Then all microtasks run (promise callbacks, code after await, queueMicrotask), including ones queued while draining, before the loop takes the next macrotask (a timer, an I/O callback, setImmediate). After every macrotask, microtasks are drained again (program 3).
    • 

  • Node adds process.nextTick, a queue it drains before the microtasks, and loop phases: timers, then I/O polling, then "check" (setImmediate). Inside an I/O callback, setImmediate always beats setTimeout(f, 0) (program 4); at the top level of a script that order is not guaranteed ({{Node: the event loop|https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick}}).
    • 

  • In an ES module, the module itself is evaluated as part of a microtask job, so promise callbacks run before nextTick callbacks; in CommonJS it is the reverse (programs 5a and 5b; {{Node docs: queueMicrotask() vs process.nextTick()|https://nodejs.org/api/process.html#when-to-use-queuemicrotask-vs-processnexttick}}). Prefer queueMicrotask and promises; avoid depending on nextTick ordering.
    • 

  • Browsers have the same two queues (no nextTick, no setImmediate), so programs 1 to 3 print the same there. The JS playground on {{JavaScript: values, objects, functions and modules for Python programmers|n:4055c17b0d0d810c982ac6ab36f88539}} runs 22 drills live in your browser; five are this page's subject (timer or promise first, two async functions interleaving at await, microtasks between timers, await inside forEach, an executor that runs at once). Python's asyncio has one ready queue and no microtask priority: compare the asyncio event-loop stepper on {{Python: concurrency, asyncio and the GIL|n:4055c17b0d0d81bdbee8c37d80b55a0e}}.
