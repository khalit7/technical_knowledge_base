The idea in one screen

Node runs your JavaScript on one thread that never waits: an I/O call starts the work and returns at once, and the event loop later runs each callback to completion, draining every microtask (promise callbacks, the code after an await) before it takes the next macrotask (a timer, an I/O completion).

Where a callback waits, and the order the loop takes them

Notice that the microtask queue sits between every two macrotasks, so a resolved promise's callback always runs before a setTimeout(f, 0) queued earlier. Node adds the nextTick queue in front of it; browsers have the same two main queues without it. A static diagram; section 2 steps through six real programs that exercise every arrow.

Event loop
the loop inside Node that runs one piece of your code at a time, to completion, then picks the next.
Promise
an object for a result not there yet: pending, then once and for all fulfilled with a value or rejected with an error.
Microtask
a promise reaction (.then callback, code after await) or a queueMicrotask callback; all of them run before the next macrotask.
Macrotask
(or just "task") a timer callback, an I/O completion, a setImmediate callback.
process.nextTick
Node's own queue, drained even before the microtasks; not part of the language.
AbortSignal
the standard way to ask async work to stop; the work must look at it.
Async iterator
a source of values that arrive over time, read with for await...of.
Backpressure
pausing a fast producer while a slow consumer catches up, so memory stays bounded.
