4. The async toolbox

Timers. setTimeout(f, ms) runs f once, no earlier than ms later (later if the thread is busy, as mode 3 above showed); setInterval repeats; both return a handle for clearTimeout. import { setTimeout as sleep } from "node:timers/promises" gives Python's asyncio.sleep.

Waiting for several. Python's asyncio.gather is Promise.all: results in input order, rejects as soon as one rejects (the others keep running; nobody cancels them). Promise.allSettled never rejects and reports each outcome (gather(..., return_exceptions=True)). Promise.race settles with the first to settle; Promise.any with the first success, or an AggregateError of all failures. In the output, the 10 ms job finished first but its result is second, and the failing all rejects after 11 ms without waiting for the 50 ms job.

i5_combinators.mjs
// Waiting for several promises: all (fail fast), allSettled (never rejects), race (first to settle), any (first success).
const ok = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));
const bad = (ms, m) => new Promise((_, j) => setTimeout(() => j(new Error(m)), ms));
let t0 = 0; const start = () => { t0 = performance.now(); }, took = () => `after ${Math.round(performance.now() - t0)} ms`;
start(); console.log("all:", await Promise.all([ok(30, "a"), ok(10, "b")]), took());   // results in INPUT order
start(); try { await Promise.all([ok(50, "a"), bad(10, "b failed")]); } catch (e) { console.log("all:", e.message, took()); }
const settled = await Promise.allSettled([ok(10, "a"), bad(10, "b failed")]);
console.log("allSettled:", settled.map(s => s.status === "fulfilled" ? `ok ${s.value}` : `error ${s.reason.message}`));
console.log("race:", await Promise.race([ok(30, "slow"), ok(10, "fast")]));
try { await Promise.any([bad(5, "x"), bad(5, "y")]); } catch (e) { console.log("any:", e.constructor.name, e.errors.map(x => x.message)); }

Cancellation and timeouts. A promise cannot be cancelled. Instead, the work accepts an AbortSignal (from an AbortController, or AbortSignal.timeout(ms)) and stops when it fires; fetch, timers, streams and most SDKs accept { signal }. Aborting is a request, not preemption: code that never looks at the signal runs to the end (the third line below). Python's task.cancel() is stronger: it throws CancelledError into the coroutine at its next await. How an LLM server passes the browser's disconnect through to the model call, measured, is on {{TypeScript: LLM apps and agents|n:4055c17b0d0d8109aad6e69a87b3bd6f}}; cancelling a stream on the wire is {{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}.

// Timeouts are the same mechanism: AbortSignal.timeout(ms). (Python: asyncio.timeout / task.cancel().)
import { setTimeout as sleep } from "node:timers/promises";
const ac = new AbortController();
setTimeout(() => ac.abort(), 50);
try { await sleep(1000, "done", { signal: ac.signal }); }
catch (e) { console.log(e.name, "|", ac.signal.aborted, ac.signal.reason.name); }
try { await sleep(1000, "done", { signal: AbortSignal.timeout(30) }); }
catch (e) { console.log(e.name, "|", e.cause?.name ?? "", e.message); }
// Work that ignores the signal is NOT stopped: aborting is a request, not preemption.
async function stubborn(signal) { await sleep(80); return signal.aborted ? "finished anyway, after the abort" : "finished"; }
const ac2 = new AbortController(); const p = stubborn(ac2.signal); ac2.abort();
console.log(await p);

Forgotten promises. Calling an async function without await or .catch ("fire and forget") means its error has nowhere to go. Since Node 15 the default (--unhandled-rejections=throw) is to treat it as an uncaught exception: the process dies, here before a pending timer gets to run ({{Node CLI docs|https://nodejs.org/api/cli.html#--unhandled-rejectionsmode}}). Browsers log an "Uncaught (in promise)" error and carry on. Await it, or add .catch(log) deliberately.

A concurrency limit. "All at once" is wrong for 10,000 requests to a rate-limited API. The usual fix is a small pool: N workers pulling from a shared index, eight lines with no library (libraries such as p-limit do the same); Python's equivalent is an asyncio.Semaphore. Twenty 50 ms requests at three limits:

Time falls with the limit until every request is in flight

i9_limit.mjs
// 20 requests of 50 ms each, at most 4 in flight: a worker-pool limiter in eight lines (no library).
const sleep = ms => new Promise(r => setTimeout(r, ms));
async function mapLimit(items, limit, fn) {
  const results = new Array(items.length); let next = 0, inFlight = 0, peak = 0;
  async function worker() {
    while (next < items.length) { const i = next++; inFlight++; peak = Math.max(peak, inFlight); results[i] = await fn(items[i]); inFlight--; }
  }
  await Promise.all(Array.from({ length: limit }, worker));
  return { results, peak };
}
const items = Array.from({ length: 20 }, (_, i) => i);
for (const limit of [1, 4, 20]) {
  const t0 = performance.now();
  const { results, peak } = await mapLimit(items, limit, async i => { await sleep(50); return i * i; });
  console.log(`limit ${String(limit).padStart(2)}: ${Math.round(performance.now() - t0)} ms, peak in flight ${peak}, last result ${results.at(-1)}`);
}
