1. Callbacks, promises, then async/await

A Node process runs your JavaScript on one thread. It never waits: reading a file, a socket or a timer is started, the call returns at once, and the result is delivered later by the event loop. Python's asyncio is the same design, opt-in; in JavaScript it is the only model, and every I/O API is built for it. Three generations of API sit on top.

Callbacks. The original style: pass a function to call when the result is ready. Node's convention puts the error first. Each dependent step nests one level deeper ("callback hell"), and errors must be checked by hand at every level. Line 2 below prints before line 3 because readFile returned before reading anything.

real output of i1_callbacks.mjs, Node 24.21.0
1. ask for the file
2. readFile has already returned; nothing has been read yet
3. got 650 characters
4. second read failed with ENOENT
The code: i1_callbacks.mjs
i1_callbacks.mjs
// Before promises: callbacks. The function returns at once; your callback runs later, from the event loop.
import { readFile } from "node:fs";
console.log("1. ask for the file");
readFile("i1_callbacks.mjs", "utf8", (err, text) => {        // Node's convention: error first, then the result
  if (err) return console.log("failed:", err.code);
  console.log("3. got", text.length, "characters");
  readFile("no_such_file.txt", "utf8", (err2) => {             // the next step nests inside: "callback hell"
    console.log("4. second read failed with", err2.code);
  });
});
console.log("2. readFile has already returned; nothing has been read yet");

Promises. A promise is pending, then once and for all fulfilled or rejected. .then(f) registers what to do next and returns a new promise, so steps chain instead of nesting; .catch and .finally work like except and finally on the chain. async function and await are syntax over promises: an async function always returns a promise, and await p pauses the function until p settles, returning its value or throwing its error, so plain try/catch works.

One difference from Python matters: a promise is eager. The work starts when the promise is created; a Python coroutine does nothing until awaited or wrapped in a task. The first line of the output below is printed by the promise's executor before anything awaits it.

real output of i2_promises.mjs, Node 24.21.0
the executor runs immediately: a promise is eager (a Python coroutine is lazy)
pending now: Promise { <pending> }
then got 43
catch got boom
finally
awaited value | p is now Promise { 42 }
try/catch works with await: rejected
The code: i2_promises.mjs
i2_promises.mjs
// A promise is an object for a value that is not there yet: pending, then fulfilled or rejected (once).
const p = new Promise((resolve) => {
  console.log("the executor runs immediately: a promise is eager (a Python coroutine is lazy)");
  setTimeout(() => resolve(42), 10);
});
console.log("pending now:", p);
p.then(v => v + 1)                               // .then returns a NEW promise: chains read top to bottom
 .then(v => { console.log("then got", v); throw new Error("boom"); })
 .catch(e => console.log("catch got", e.message))
 .finally(() => console.log("finally"));
const sleep = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));   // wrap a callback API once
async function main() {                          // async/await: the same chain, written like synchronous code
  const v = await sleep(20, "awaited value");
  console.log(v, "| p is now", p);
  try { await Promise.reject(new Error("rejected")); } catch (e) { console.log("try/catch works with await:", e.message); }
}
main();
