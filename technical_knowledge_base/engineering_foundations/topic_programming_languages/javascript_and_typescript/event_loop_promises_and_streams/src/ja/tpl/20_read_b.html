1. Callbacks, promises, then async/await

A Node process runs your JavaScript on one thread. It never waits: reading a file, a socket or a timer is started, the call returns at once, and the result is delivered later by the event loop. Python's asyncio is the same design, opt-in; in JavaScript it is the only model, and every I/O API is built for it. Three generations of API sit on top.

Callbacks. The original style: pass a function to call when the result is ready. Node's convention puts the error first. Each dependent step nests one level deeper ("callback hell"), and errors must be checked by hand at every level. Line 2 below prints before line 3 because readFile returned before reading anything.

Promises. A promise is pending, then once and for all fulfilled or rejected. .then(f) registers what to do next and returns a new promise, so steps chain instead of nesting; .catch and .finally work like except and finally on the chain. async function and await are syntax over promises: an async function always returns a promise, and await p pauses the function until p settles, returning its value or throwing its error, so plain try/catch works.

One difference from Python matters: a promise is eager. The work starts when the promise is created; a Python coroutine does nothing until awaited or wrapped in a task. The first line of the output below is printed by the promise's executor before anything awaits it.
