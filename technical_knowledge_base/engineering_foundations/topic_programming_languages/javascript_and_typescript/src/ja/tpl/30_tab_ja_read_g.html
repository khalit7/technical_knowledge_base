12. Node essentials

Node's standard library is imported with a node: prefix. Five modules cover most scripts and services: node:fs/promises (files), node:path and node:os, node:process (also a global), node:http plus the global fetch, and node:worker_threads. A Buffer (or Uint8Array) is Python's bytes.

The process

process.argv is sys.argv with two leading entries (the node binary and the script); process.env is os.environ (a missing variable is undefined); node:util's parseArgs is a small argparse. Prefer setting process.exitCode to calling process.exit(), which kills pending output and timers.

HTTP and fetch

fetch is built in (stable since Node 21) and is the same API as in browsers: await fetch(url, { method, headers, body, signal }), then await res.json() or res.text() or res.body (a stream). An HTTP error status does not throw; only a network failure does. Check res.ok (Python's requests does not raise either, unless you call raise_for_status()).

[[run:k5_fetch]]

Worker threads: CPU work off the event loop

One thread means CPU-heavy work (parsing a huge JSON, hashing, tokenising a corpus) stops everything else: timers, requests, streams. A worker thread is a second V8 instance on another OS thread with its own event loop; it shares nothing by default and talks by messages (postMessage, copied with the structured clone algorithm), or shares memory explicitly through a SharedArrayBuffer with Atomics. It is closer to Python's multiprocessing than to threading, but cheaper to start. Below, a 10 ms heartbeat timer measures how long the event loop was stuck.

13. Packages: npm, pnpm and node_modules

package.json is pyproject.toml: name, version, "type", "scripts" (named commands run by npm run name), "dependencies" and "devDependencies" (tools only needed to develop, such as test runners). Versions are semver ranges: ^5.2.1 means "5.x.y, at least 5.2.1". The exact resolved tree is pinned in a lockfile (package-lock.json, like uv.lock); commit it, and install from it in CI with npm ci. Packages go into a local node_modules/ folder per project: there is no global site-packages and no virtual environment to activate, because every project is already isolated.

[[run:l1_npm]]

Three direct dependencies: npm reported adding 1 + 68 + 35 = 104 packages, in 95 top-level folders taking 46 MB, and the lockfile pins 129 entries (27 of them optional platform-specific binaries, for example @rolldown/binding-android-arm64, installed only on matching machines). npm ls answers "who brought this in?". npm hoists everything into one flat folder, so your code can import packages you never declared (debug above), and breaks when they move. pnpm keeps one global content-addressed store on disk, hard-links files from it, and exposes only declared dependencies at the top of node_modules. Bun includes its own npm-compatible installer. npx tool (or pnpm dlx, bunx) runs a package's command without installing it, like uvx.

[[run:l2_pnpm]]
Supply chain
A dependency can run code at install time ("postinstall" scripts), and a tree of a hundred packages has a hundred maintainers. Pin with a lockfile, review what a new dependency pulls in (npm ls, the package's dependency count), and prefer packages with few dependencies. pnpm (since version 10, {{release notes|https://github.com/pnpm/pnpm/releases/tag/v10.0.0}}) and Bun ({{lifecycle scripts|https://bun.com/docs/install/lifecycle}}) do not run dependencies' install scripts unless you allow them; npm runs them by default.
