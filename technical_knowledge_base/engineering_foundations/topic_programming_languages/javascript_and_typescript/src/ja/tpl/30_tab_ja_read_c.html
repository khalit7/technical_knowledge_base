3. Objects, arrays, destructuring, spread

An object literal { role: "user", text: "hi" } is what you reach for where Python uses a dict, a dataclass or a SimpleNamespace: a bag of properties you read as msg.role or msg["role"]. Two differences matter. Keys are always strings (or symbols): 1 and "1" are the same key. And iteration order is insertion order except that integer-like keys come first, in numeric order. For a real hash map with keys of any type, use Map; for a set, Set. Both compare keys by identity for objects (there is no __hash__).

[[run:c1_objects]]

Arrays are Python lists. The functional methods (map, filter, reduce, find, some, every, flatMap) return new arrays; push, pop, splice, sort and reverse change the array in place. The newer toSorted, toReversed and with (ES2023) are the non-mutating versions. sort() without a comparator converts every element to a string and compares those, so [1, 10, 2, 3] is "sorted".

[[predict:c2_arrays]]

Destructuring is Python's unpacking, extended to objects and with defaults; spread ... is * and **. A function taking one destructured object parameter is the JavaScript way to write keyword arguments, and it is how most SDKs (including LLM clients) take options.

[[run:c3_destructure]]

Copying. Assignment never copies, as in Python. Spread ({ ...o }, [...xs]) copies one level, like copy.copy; structuredClone copies deeply, like copy.deepcopy, and keeps dates, maps and cycles. (Memory is managed by a garbage collector, as in Python but with no reference counting: objects are freed some time after nothing reaches them, cycles included. A WeakMap attaches data to an object without keeping it alive, a cache that cannot leak.) The old JSON.parse(JSON.stringify(x)) trick silently turns dates into strings and drops undefined and functions.

[[run:c4_copy]]

4. Functions, closures and this

Functions are values, as in Python. There are three spellings; the arrow function x => x * 2 is the everyday one (a lambda that may also have a block body). Arguments are not checked: extra ones are ignored, missing ones are undefined. Default values are evaluated on every call, so Python's mutable-default trap does not exist here (it runs in reverse).

[[predict:d1_functions]]

A closure is a function that keeps the variables of the scope it was created in, exactly as in Python (without needing nonlocal to assign). Closures are how JavaScript does private state, callbacks and factories. The classic loop trap: var gives every iteration the same variable; let gives each iteration a fresh one.

[[predict:d2_closures]]

this

Inside a function, this is not fixed when the function is written; it is set by the call. obj.method() sets this to obj; calling the same function bare (const f = obj.method; f()) sets it to undefined (in modules and classes, which are always "strict mode"). That is the commonest bug in the language: passing obj.method as a callback loses obj. Arrow functions have no this of their own and use the surrounding one, which is why callbacks inside methods are written as arrows. fn.bind(obj) makes a copy with this fixed (Python makes bound methods for you; JavaScript does not).

[[predict:d3_this]]
Rule of thumb
Methods as method syntax inside classes and objects; every callback as an arrow function; never pass obj.method bare, pass () => obj.method().
Also
new Fn() sets this to a fresh object; fn.call(o, ...) and fn.apply(o, [...]) set it explicitly. Those four rules are all there is.

5. Classes and prototypes

class looks like Python's: a constructor is __init__, this is self (implicit, never a parameter), extends and super work as expected, get defines a property. Differences: fields can be declared in the body; #name fields are truly private, enforced by the parser (Python's _name is a convention); there is single inheritance only; and there is no operator overloading (no __eq__, __add__, __len__).

[[run:e1_classes]] [[run:e1b_private]]

Under the syntax, there are no classes at all: every object has a prototype, another object where missing properties are looked up, and so on up a chain ending at Object.prototype. A class is a function whose prototype object holds the methods; new makes an object whose prototype is that object. Python's attribute lookup through the MRO is the same idea with more rules. Knowing the chain explains instanceof, method sharing, and why changing a prototype changes every instance.

[[run:e2_prototype]]

The few hooks JavaScript offers instead of dunder methods are keyed by well-known symbols: Symbol.iterator (__iter__), Symbol.asyncIterator (__aiter__), Symbol.toPrimitive (roughly __int__ and __str__), plus toString and toJSON.

[[predict:e3_dunders]]

For the rest of Python's attribute hooks (__getattr__, __setattr__), JavaScript has Proxy: a wrapper that intercepts reads, writes and more on any object. Reach for it rarely: it is slower than plain objects and surprising to readers.
