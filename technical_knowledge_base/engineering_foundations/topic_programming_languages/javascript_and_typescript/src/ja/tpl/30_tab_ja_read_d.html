6. Modules: ES modules and CommonJS

JavaScript has two module systems, and Node runs both. ES modules (ESM, the standard since 2015): import and export, loaded and linked before any code runs, asynchronous, with top-level await. CommonJS (CJS, Node's original): require() and module.exports, synchronous, still in many packages. Python has one system; its import is closest to require (synchronous, runs the module once, caches it).

Node decides per file: .mjs is ESM, .cjs is CommonJS, and .js follows the "type" field of the nearest package.json ("module" or the default "commonjs"). In ESM, relative imports need the file extension, and require, __filename and __dirname do not exist (use import.meta.url, import.meta.filename, import.meta.dirname).

ESM can import CommonJS (you get module.exports as the default export). CommonJS can require() an ES module since Node 22.12 and 20.19, without a flag; the feature became stable in 25.4. It fails with ERR_REQUIRE_ASYNC_MODULE if the module graph uses top-level await, because require must finish synchronously ({{Node docs, Loading ECMAScript modules using require()|https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require}}).
What to do
New code: "type": "module" in package.json and import everywhere. Dynamic await import("x") for lazy loading (Python's import inside a function). A library's package.json "exports" map says which file each runtime gets; Part 2 covers publishing with types.

7. Errors

throw, try/catch/finally work like Python's raise, try/except/finally, with three differences. There is one catch per try, with no type filter: test e instanceof X or e.code inside it and rethrow what you do not handle. Anything can be thrown, but only Error objects carry a stack, so always throw Error or a subclass. And chaining is explicit: new Error(msg, { cause: e }) is Python's raise ... from e.

[[run:g1_errors]]

An uncaught error prints the stack (innermost call first, the reverse of a Python traceback) and ends the process with exit code 1. Node errors from the system carry a stable code (ENOENT, ECONNREFUSED, ERR_REQUIRE_ASYNC_MODULE): match on the code, not on the message text.

[[run:g2_uncaught]]

Errors in asynchronous code are the hard part: a rejected promise that nobody awaits or catches does not reach any try. Section 10 shows what Node does with it.

8. Iteration: iterators and generators

for (const x of xs) is Python's for x in xs: it works on anything iterable (arrays, strings, maps, sets, generators). for...in is a different, older loop over an object's keys as strings, including inherited ones; it is almost never what you want on an array. The iterator protocol is Python's in disguise: xs[Symbol.iterator]() is iter(xs), and it.next() returns { value, done } instead of raising StopIteration.

[[predict:h1_iter]]

function* defines a generator, exactly Python's function-with-yield: lazy, paused between values, able to describe infinite sequences. Since Node 22 (ES2025 "iterator helpers"), iterators also have lazy map, filter, take, drop, flatMap and toArray methods, which make generator pipelines read like method chains.
