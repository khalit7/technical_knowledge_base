We call a model with the official SDKs, stream its answer, let it call tools in an agent loop, check its JSON with zod, write an MCP server and client, serve the whole thing to a browser with cancellation, and add the logging an evaluation needs. Every program on this page is real TypeScript that type-checks and runs, and every output is what it printed.

About 40 minutes. No paid API call was made for this page (no API key was set in the environment). In one screen

An LLM app is ordinary server code around one HTTP call. The layers, from the bottom up:

WireOne HTTPS POST with JSON (/v1/messages for Anthropic, /v1/responses for OpenAI). Streaming answers come back as server-sent events (SSE).
SDKThe official client (@anthropic-ai/sdk, openai): types for every request and response, retries, timeouts, SSE parsing, helpers for streams, structured output and tool loops.
Agent loopCall the model; if it asks for tools, run them and send the results back; repeat until it answers. About 40 lines you can write yourself, with guards: step limit, timeouts, validation, cost.
Tools via MCPThe Model Context Protocol: tools (and resources, prompts) served by a separate process over JSON-RPC, so any agent can use them.
ServingA Node or Bun HTTP server streams tokens to the browser and cancels the model call when the user leaves.
MeasuringOne log line per model call; a fixed set of cases checked in code.

Why TypeScript for this at all
Agent harnesses and MCP servers are mostly TypeScript today. Measured on 2026-10-05 with GitHub's language statistics: the official MCP reference servers repository is 490,686 bytes of TypeScript against 100,153 of Python (modelcontextprotocol/servers); OpenCode is TypeScript (sst/opencode); and Claude Code "ships as a Bun executable", a compiled JavaScript project (Bun blog, 2025-12-02). The two things TypeScript gives an LLM app are the ones Part 2 taught: the SDK's types tell you the shape of every response before you run anything, and a zod schema checks the model's JSON at run time.
Checking the old page
The old "JavaScript: zero to expert" page said: "Claude Code, OpenCode, and most MCP reference implementations are TypeScript." OpenCode and the MCP reference servers: confirmed (above). Claude Code: its source is not public, so "TypeScript" specifically is unconfirmed; what is confirmed is that it is a JavaScript-family program compiled into a single executable with Bun (Bun's post, above), and the Claude Agent SDK used in section 9 installs it as a native binary.

1. The setup: a mock model that speaks the real wire format

Every SDK takes a base URL: the address it sends requests to. In production you leave it alone (it defaults to https://api.anthropic.com, or reads ANTHROPIC_BASE_URL). Here every script starts mock_model.ts on a free local port and passes its address as baseURL. The mock answers POST /v1/messages and POST /v1/responses with the exact JSON and SSE shapes of the real APIs (checked against the SDKs' own type definitions, and confirmed by the SDKs parsing them without complaint). Its "model" is a short function, decide(), that reads the conversation and returns the next turn. That is exactly what a real model does from the SDK's point of view, so every line of client code on this page is the code you would run against the real API; only the answers are scripted.

The same trick is how you should test your own LLM code: a mock server makes tests fast, free, deterministic, and able to produce failures (a 429, a timeout, a malformed tool call) on demand.
