JavaScript runs your code on one thread around an event loop: nothing runs in parallel with your code, every slow operation is started and finishes later as a callback, a promise or an await, and a long loop freezes everything. TypeScript is a type layer erased before anything runs: it is checked in your editor and CI, then deleted, so what runs is always plain JavaScript.

Fig. 1 follows one TypeScript program from your editor to the edge of the process. Each step pins one piece where it acts and names the page that owns it; the pieces this page owns (the runtime, Node's standard library, libuv and worker threads, packages) are its sections 1 to 3. The heights in step 3 are the recorded start-up medians and in step 7 the recorded timer waits; everything else is a map, not to scale.

  1. Your program, in TypeScript. count.ts is JavaScript plus a layer of types (function countTokens(text: string): number, drawn as the glass plate). tsc, in your editor and CI, checks that layer against the code it can see; it runs nothing. How the checker works and what it cannot see: {{the TypeScript page's Fig. 1|n:4055c17b0d0d81519278df19753ab5ec#stg-hero}}.
  2. The types are erased. Before anything runs, the layer is deleted: node, Bun and Deno strip it, or tsc compiles it away. What is left, count.js, is plain JavaScript; from here on nothing checks a type. Types stop at this line.
  3. A runtime loads it. Node, Bun or Deno: an engine plus files, sockets, processes and the event loop. The bars are each one's median start-up on this laptop: Node 24 31.4 ms, Bun 8.7 ms, Deno 11.3 ms (section 3 compares them).
  4. Your code runs on one call stack. One thread, one function at a time; while it runs, nothing else does. What that code handles (values, objects and their prototype chain, closures) is the language page's subject, drawn in {{its Fig. 1|n:4055c17b0d0d810c982ac6ab36f88539#stg-hero}}.
  5. The event loop feeds the thread. Run one task (a timer or finished I/O) to the end, then run every microtask (the code after an await, a .then), then take the next task. The two queues are stepped through on six real programs in {{the event-loop page's Fig. 2|n:4055c17b0d0d81fe857de8b34db109ea#stg-loop}}; its Fig. 1 adds the loop's phases.
  6. Slow I/O leaves the thread. Under Node, libuv watches sockets with the operating system's readiness API, and runs file reads, dns.lookup and some crypto and zlib calls on its thread pool, 4 threads by default ({{libuv: thread pool|https://docs.libuv.org/en/v1.x/threadpool.html}}). The call returns at once; the result comes back later as a task (section 2).
  7. CPU work blocks the thread; a worker does not. A prime count that took 439 ms on the main thread made a 10 ms heartbeat timer wait 438 ms: nothing else moved. In a worker thread (a second engine with its own loop, talking by messages) the timer never waited more than 14 ms (section 2's run).
  8. Data from outside meets a validator. A fetch body, a model's reply, a file: JSON.parse returns whatever arrived, and the erased types cannot check it. A schema that exists at run time (zod) stands at the boundary, passes what fits and rejects the rest with a reason: of the TypeScript page's 10 recorded model replies, 4 passed and 6 were rejected ({{its section 7|n:4055c17b0d0d81519278df19753ab5ec}}). The agent loop that sends the reason back to the model is {{the LLM apps page's Fig. 3|n:4055c17b0d0d8109aad6e69a87b3bd6f#stg-loop}}.
  9. Who owns which piece. This page: the runtime, Node's standard library, libuv and worker threads, packages, and the traps that cut across. The language page: values and objects. The event-loop page: the queues. The TypeScript page: the types and the boundary. The LLM apps page: an agent built on all of it (section 5 has the cards).

1. Running JavaScript

JavaScript was made for web pages in 1995; Node.js (2009) took Google's V8 engine out of the browser and added what a server needs: files, sockets, processes, and an event loop built on the C library libuv. The language itself (ECMAScript) has no files, network or processes: a runtime adds them. In Python terms, Node is both the interpreter (python) and a large standard library. You write a file and run it; there is no compile step.

a1_hello.mjs
// hello.mjs: run with  node hello.mjs  (.mjs means "an ES module"; section 6)
const name = "Khalid";                  // const: this name is never rebound
let count = 3;                          // let: a variable you may reassign
count = count + 1;
console.log(`hello ${name}, count is ${count}`);   // backticks: a template string, like an f-string
console.log("typeof count:", typeof count, " typeof name:", typeof name);
console.log("runtime:", process.version, "on", process.platform, process.arch);
real output, Node 24.21.0
hello Khalid, count is 4
typeof count: number  typeof name: string
runtime: v24.21.0 on darwin arm64
  • File extensions. .mjs is always an ES module, .cjs always CommonJS; plain .js follows the nearest package.json's "type" field. Use ES modules for anything new (how the two systems differ and interoperate: {{JavaScript: values, objects, functions and modules for Python programmers|n:4055c17b0d0d810c982ac6ab36f88539}}, section 5).
  • Interactive. node alone opens a REPL, like python; node -e "console.log(1 + 1)" runs one line; node --watch app.mjs reruns on every save.
  • Debugging. node --inspect-brk app.mjs pauses on the first line and lets Chrome's DevTools (or VS Code) attach: breakpoints, stepping, the call stack (Python's pdb, with a GUI).
  • TypeScript. node app.ts strips the types and runs the file; npx tsc --noEmit is what checks them. The TypeScript page covers both.
  • Which Node. Even-numbered releases become long-term support (LTS). On 2026-10-05, Node 24 is the Active LTS and Node 26 is "Current", due to become LTS on 2026-10-28 ({{Node.js releases|https://nodejs.org/en/about/previous-releases}}); from Node 27 every major release will be LTS, once a year. Install it with a version manager (nvm, fnm, mise) rather than a system package. The root's {{Toolchain atlas|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}} tab has the dated release grid.
