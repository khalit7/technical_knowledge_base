JavaScript runs your code on one thread around an event loop: nothing runs in parallel with your code, every slow operation is started and finishes later as a callback, a promise or an await, and a long loop freezes everything. TypeScript is a type layer erased before anything runs: it is checked in your editor and CI, then deleted, so what runs is always plain JavaScript.

The event loop: run one task to the end, run every microtask, take the next task. A for loop that computes for 0.44 s holds the stack for 0.44 s: no timer, request or stream moves meanwhile (section 2 measures it).
libuv, under Nodewatches sockets with the operating system's readiness API; files, dns.lookup, some crypto and zlib calls run on its thread pool, 4 threads by default. Results come back as tasks.
Worker threadsa second engine with its own loop on another core; shares nothing unless asked, talks by messages. The way to run CPU work without freezing the loop.

1. Running JavaScript

JavaScript was made for web pages in 1995; Node.js (2009) took Google's V8 engine out of the browser and added what a server needs: files, sockets, processes, and an event loop built on the C library libuv. The language itself (ECMAScript) has no files, network or processes: a runtime adds them. In Python terms, Node is both the interpreter (python) and a large standard library. You write a file and run it; there is no compile step.

a1_hello.mjs
// hello.mjs: run with  node hello.mjs  (.mjs means "an ES module"; section 6)
const name = "Khalid";                  // const: this name is never rebound
let count = 3;                          // let: a variable you may reassign
count = count + 1;
console.log(`hello ${name}, count is ${count}`);   // backticks: a template string, like an f-string
console.log("typeof count:", typeof count, " typeof name:", typeof name);
console.log("runtime:", process.version, "on", process.platform, process.arch);
real output, Node 24.21.0
hello Khalid, count is 4
typeof count: number  typeof name: string
runtime: v24.21.0 on darwin arm64
  • File extensions. .mjs is always an ES module, .cjs always CommonJS; plain .js follows the nearest package.json's "type" field. Use ES modules for anything new (how the two systems differ and interoperate: {{JavaScript: values, objects, functions and modules for Python programmers|n:4055c17b0d0d810c982ac6ab36f88539}}, section 5).
  • Interactive. node alone opens a REPL, like python; node -e "console.log(1 + 1)" runs one line; node --watch app.mjs reruns on every save.
  • Debugging. node --inspect-brk app.mjs pauses on the first line and lets Chrome's DevTools (or VS Code) attach: breakpoints, stepping, the call stack (Python's pdb, with a GUI).
  • TypeScript. node app.ts strips the types and runs the file; npx tsc --noEmit is what checks them. The TypeScript page covers both.
  • Which Node. Even-numbered releases become long-term support (LTS). On 2026-10-05, Node 24 is the Active LTS and Node 26 is "Current", due to become LTS on 2026-10-28 ({{Node.js releases|https://nodejs.org/en/about/previous-releases}}); from Node 27 every major release will be LTS, once a year. Install it with a version manager (nvm, fnm, mise) rather than a system package. The root's {{Toolchain atlas|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}} tab has the dated release grid.
