6. Modules: ES modules and CommonJS

JavaScript has two module systems, and Node runs both. ES modules (ESM, the standard since 2015): import and export, loaded and linked before any code runs, asynchronous, with top-level await. CommonJS (CJS, Node's original): require() and module.exports, synchronous, still in many packages. Python has one system; its import is closest to require (synchronous, runs the module once, caches it).

Node decides per file: .mjs is ESM, .cjs is CommonJS, and .js follows the "type" field of the nearest package.json ("module" or the default "commonjs"). In ESM, relative imports need the file extension, and require, __filename and __dirname do not exist (use import.meta.url, import.meta.filename, import.meta.dirname).

f_mod/tokens.js
// tokens.js: an ES module (this folder's package.json says "type": "module")
export const TOKEN = /[A-Za-z0-9]+/g;
export function countTokens(text) { return (text.match(TOKEN) ?? []).length; }
export default function top(map, k) { return [...map].sort((a, b) => b[1] - a[1]).slice(0, k); }
console.log("tokens.js evaluated (once, however many times it is imported)");
f_mod/main.js
// main.js: named imports, a default import, a CommonJS import, a dynamic import and top-level await
import top, { countTokens } from "./tokens.js";     // the extension is required in Node ESM
import { countTokens as again } from "./tokens.js"; // a second import does not re-run the module
import legacy from "./legacy.cjs";                   // CommonJS: module.exports arrives as the default
const { readFile } = await import("node:fs/promises"); // dynamic import returns a promise; top-level await is fine in ESM
console.log(countTokens("x86_64 is 2 tokens"), again === countTokens, legacy.shout("ok"));
console.log(top(new Map([["u1", 3], ["u2", 9]]), 1));
console.log(JSON.parse(await readFile(new URL("./package.json", import.meta.url), "utf8")).type);
console.log(typeof require, typeof import.meta.url, import.meta.filename.split("/").pop());
f_mod/old.cjs
// old.cjs: CommonJS uses require() and module.exports; require is synchronous

console.log(typeof module, __filename.split("/").pop());

ESM can import CommonJS (you get module.exports as the default export). CommonJS can require() an ES module since Node 22.12 and 20.19, without a flag; the feature became stable in 25.4. It fails with ERR_REQUIRE_ASYNC_MODULE if the module graph uses top-level await, because require must finish synchronously ({{Node docs, Loading ECMAScript modules using require()|https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require}}).
What to do
New code: "type": "module" in package.json and import everywhere. Dynamic await import("x") for lazy loading (Python's import inside a function). A library's package.json "exports" map says which file each runtime gets; Part 2 covers publishing with types.

7. Errors

throw, try/catch/finally work like Python's raise, try/except/finally, with three differences. There is one catch per try, with no type filter: test e instanceof X or e.code inside it and rethrow what you do not handle. Anything can be thrown, but only Error objects carry a stack, so always throw Error or a subclass. And chaining is explicit: new Error(msg, { cause: e }) is Python's raise ... from e.

g1_errors.mjs
// throw, try/catch/finally, Error subclasses and error chaining with { cause } (Python's raise ... from ...).
class ParseError extends Error {
  constructor(line, options) { super(`bad JSON on line ${line}`, options); this.name = "ParseError"; this.line = line; }
}
function parseLine(s, n) {
  try { return JSON.parse(s); }
  catch (e) { throw new ParseError(n, { cause: e }); }      // keep the original error as the cause
}
try { parseLine("{oops", 53); }
catch (e) {
  console.log(e instanceof ParseError, e instanceof Error, e.name, e.line);
  console.log(e.message, "| cause:", e.cause.name, "-", e.cause.message);
} finally { console.log("finally always runs"); }
try { throw "a bare string"; } catch (e) { console.log(typeof e, e?.stack); }   // anything can be thrown; only Errors carry a stack
try { null.x; } catch (e) { console.log(e.name); }            // no except TypeError: one catch, then test the type

An uncaught error prints the stack (innermost call first, the reverse of a Python traceback) and ends the process with exit code 1. Node errors from the system carry a stable code (ENOENT, ECONNREFUSED, ERR_REQUIRE_ASYNC_MODULE): match on the code, not on the message text.

8. Iteration: iterators and generators

for (const x of xs) is Python's for x in xs: it works on anything iterable (arrays, strings, maps, sets, generators). for...in is a different, older loop over an object's keys as strings, including inherited ones; it is almost never what you want on an array. The iterator protocol is Python's in disguise: xs[Symbol.iterator]() is iter(xs), and it.next() returns { value, done } instead of raising StopIteration.

h1_iter.mjs
// for...of walks VALUES (Python's for x in xs). for...in walks KEYS, as strings, and is rarely what you want.
const xs = ["a", "b"];
for (const x of xs) console.log("of:", x);
for (const k in xs) console.log("in:", k, typeof k);
for (const [k, v] of Object.entries({ u1: 3, u2: 9 })) console.log(k, v);   // dict.items()
for (const ch of "h🚀") console.log(ch, ch.length);                         // strings iterate by code point
const it = xs[Symbol.iterator]();               // the iterator protocol, by hand: iter(xs) and next()
console.log(it.next(), it.next(), it.next());

function* defines a generator, exactly Python's function-with-yield: lazy, paused between values, able to describe infinite sequences. Since Node 22 (ES2025 "iterator helpers"), iterators also have lazy map, filter, take, drop, flatMap and toArray methods, which make generator pipelines read like method chains.

h2_generators.mjs
// function* makes a generator, exactly like a Python function with yield: lazy, paused between values.
function* naturals() { let n = 0; while (true) yield n++; }
function* take(it, k) { for (const x of it) { if (k-- <= 0) return; yield x; } }
function* map(it, f) { for (const x of it) yield f(x); }
console.log([...take(map(naturals(), n => n * n), 5)]);
const g = naturals();
console.log(g.next(), g.next(), typeof g[Symbol.iterator]);
// Iterator helpers (ES2025, Node 22+): the same lazy pipeline as methods
console.log(naturals().map(n => n * n).filter(n => n % 2).take(4).toArray());
