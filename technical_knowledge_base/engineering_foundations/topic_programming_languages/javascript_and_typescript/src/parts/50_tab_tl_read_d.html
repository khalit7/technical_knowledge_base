9. Higher-level options: the Vercel AI SDK and the Claude Agent SDK

Two libraries sit above the provider SDKs, and they do very different jobs.

The Vercel AI SDK (package ai, version 7) is one TypeScript API over many providers: generateText, streamText, tools with zod schemas, and a loop controlled by stopWhen. You swap anthropic("claude-sonnet-5-5") for openai("gpt-5.5") and the rest stays. It also has React hooks and stream helpers for web UIs, which is why front-end teams use it. A default that bites
In AI SDK 7, generateText and streamText default to stopWhen: isStepCount(1) (the type definitions in ai 7.0.127 say @default isStepCount(1)): one model call. With tools, the first step is usually a tool call, so the result is the model's preamble and finishReason: "tool-calls", not an answer. Pass stopWhen: isStepCount(n) (also exported as stepCountIs). Its ToolLoopAgent class defaults to 20 steps.

10. MCP: a server, a client, and an agent that uses them

So far the tools lived inside the agent's program. The Model Context Protocol (MCP) moves them into a separate process with a standard interface, so one tool server works with Claude Code, Claude Desktop, an IDE, or your own agent. It is JSON-RPC 2.0: every message is a JSON object with a method and an id (a request), the same id with a result or error (the response), or a method without an id (a notification). A server offers three kinds of thing: tools (functions the model calls), resources (data the client reads, addressed by URI), and prompts (templates the user picks). The protocol itself (capabilities, lifecycle, authorisation) is covered in {{Topic: protocols|n:3c65c17b0d0d81ec9355f4eecd6eed02}}; here we build one with the official TypeScript SDK, which negotiated protocol version 2025-11-25 in our runs.

g1_mcp_server.ts, lines 12-41
export function buildServer() {
  const server = new McpServer({ name: "chat-stats", version: "1.0.0" });

  server.registerTool("count_tokens", {
    title: "Count tokens per user",
    description: "Count word tokens per user in a JSONL chat log; returns totals and the top users.",
    inputSchema: CountArgs.shape,                       // validated by the SDK before the handler runs
    annotations: { readOnlyHint: true },
  }, async (args) => {
    try {
      const stats = await countTokens(args);
      return { content: [{ type: "text", text: JSON.stringify(stats) }] };
    } catch (e: any) {                                  // a tool failure is a result the model can read, not a protocol error
      return { isError: true, content: [{ type: "text", text: `cannot open ${args.path}: ${e.code}` }] };
    }
  });

  server.registerResource("chat-log", "file:///chat.jsonl", { title: "The chat log", mimeType: "application/json" },
    async (uri) => {
      const s = await stat("chat.jsonl");
      return { contents: [{ uri: uri.href, text: JSON.stringify({ bytes: s.size, format: "JSONL, one message per line" }) }] };
    });

  server.registerPrompt("heaviest-users", {
    description: "Ask for the heaviest users of a chat log",
    argsSchema: { n: z.string().describe("how many users") },
  }, ({ n }) => ({ messages: [{ role: "user", content: { type: "text", text: `Who are the ${n} heaviest users in chat.jsonl? Use count_tokens.` } }] }));

  return server;
}

registerTool takes the zod shape; the SDK turns it into the JSON Schema clients see, and validates arguments before your handler runs. A failure inside the tool is returned as a result with isError: true, which the model can read and react to; a protocol-level error is for broken requests. A client starts the server as a child process (the stdio transport: JSON-RPC lines over the child's stdin and stdout) and asks what it offers:

For a server many clients share over a network, the Streamable HTTP transport carries the same JSON-RPC messages as HTTP POSTs to one endpoint. The server answers with JSON or an SSE stream, gives the session an id in the mcp-session-id header, and the client echoes it, with mcp-protocol-version, on every later request:

const loggingFetch: typeof fetch = async (url, init) => {
  const h = new Headers(init?.headers);

};

Finally the glue: an agent whose tools come from MCP. tools/list gives names, descriptions and JSON Schemas, which map one to one onto the API's tools; each tool_use becomes a tools/call, and isError becomes is_error:

g5_agent_mcp.ts
// Glue: an agent whose tools come from an MCP server. tools/list becomes the API's tools; a tool_use becomes tools/call.
import Anthropic from "@anthropic-ai/sdk";
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";
import { startMock } from "./mock_model.ts";

const mcp = new Client({ name: "agent", version: "1.0.0" });
await mcp.connect(new StdioClientTransport({ command: process.execPath, args: ["g1_mcp_server.ts"], cwd: new URL(".", import.meta.url).pathname }));
const tools: Anthropic.Tool[] = (await mcp.listTools()).tools.map(t =>
  ({ name: t.name, description: t.description ?? "", input_schema: t.inputSchema as Anthropic.Tool.InputSchema }));

const mock = await startMock();
const client = new Anthropic({ baseURL: mock.url, apiKey: "mock-key", defaultHeaders: { "x-mock-scenario": "typo" } });
const messages: Anthropic.MessageParam[] = [{ role: "user", content: "Who are the 3 heaviest users in chat.jsonl, and what share of all tokens do they have?" }];
for (let step = 1; step <= 5; step++) {
  const msg = await client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 2048, tools, messages });
  messages.push({ role: "assistant", content: msg.content });
  if (msg.stop_reason !== "tool_use") { console.log("answer:", msg.content.map(b => b.type === "text" ? b.text : "").join("")); break; }
  const results: Anthropic.ToolResultBlockParam[] = [];
  for (const b of msg.content) if (b.type === "tool_use") {
    const r = await mcp.callTool({ name: b.name, arguments: b.input as Record<string, unknown> });
    const text = (r.content as { type: string; text: string }[]).map(c => c.text).join("");
    console.log(`step ${step}: tools/call ${b.name}(${JSON.stringify(b.input)}) -> ${r.isError ? "isError " : ""}${text.slice(0, 70)}`);
    results.push({ type: "tool_result", tool_use_id: b.id, content: text, is_error: !!r.isError });
  }
  messages.push({ role: "user", content: results });
}
await mcp.close(); await mock.close();

To record the messages, mcp_tap.ts wraps the client's transport. The first version forwarded start, send and close but not the optional setProtocolVersion; over HTTP the client then sent no mcp-protocol-version header after initialisation, with no error anywhere. Forwarding it fixed the run above. In TypeScript, an optional method on an interface (setProtocolVersion?:) type-checks whether or not you implement it, so a wrapper can silently change behaviour.
