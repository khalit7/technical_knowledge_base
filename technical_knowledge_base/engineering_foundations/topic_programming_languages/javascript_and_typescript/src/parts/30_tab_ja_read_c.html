3. Objects, arrays, destructuring, spread

An object literal { role: "user", text: "hi" } is what you reach for where Python uses a dict, a dataclass or a SimpleNamespace: a bag of properties you read as msg.role or msg["role"]. Two differences matter. Keys are always strings (or symbols): 1 and "1" are the same key. And iteration order is insertion order except that integer-like keys come first, in numeric order. For a real hash map with keys of any type, use Map; for a set, Set. Both compare keys by identity for objects (there is no __hash__).

c1_objects.mjs
// An object literal looks like a dict, but its keys are strings (or symbols), and it has a prototype.
const msg = { role: "user", text: "hi", 1: "one" };
msg.tokens = 2;                                 // add a property: just assign
console.log(msg, Object.keys(msg));            // integer-like keys come first, as strings
console.log(msg[1] === msg["1"], "role" in msg, msg.missing);
delete msg.tokens;
const counts = new Map();                       // Map: a real hash map with keys of any type, in insertion order
counts.set(1, "number one").set("1", "string one").set(msg, "an object as key");
console.log(counts.size, counts.get(1), counts.get("1"), counts.has(msg));
const seen = new Set([3, 1, 3, 2]);
console.log(seen, seen.has(2), [...seen]);
console.log(new Set([[1], [1]]).size);          // two different arrays: a Set compares by identity

Arrays are Python lists. The functional methods (map, filter, reduce, find, some, every, flatMap) return new arrays; push, pop, splice, sort and reverse change the array in place. The newer toSorted, toReversed and with (ES2023) are the non-mutating versions. sort() without a comparator converts every element to a string and compares those, so [1, 10, 2, 3] is "sorted".

Destructuring is Python's unpacking, extended to objects and with defaults; spread ... is * and **. A function taking one destructured object parameter is the JavaScript way to write keyword arguments, and it is how most SDKs (including LLM clients) take options.

Copying. Assignment never copies, as in Python. Spread ({ ...o }, [...xs]) copies one level, like copy.copy; structuredClone copies deeply, like copy.deepcopy, and keeps dates, maps and cycles. (Memory is managed by a garbage collector, as in Python but with no reference counting: objects are freed some time after nothing reaches them, cycles included. A WeakMap attaches data to an object without keeping it alive, a cache that cannot leak.) The old JSON.parse(JSON.stringify(x)) trick silently turns dates into strings and drops undefined and functions.

// Assignment never copies (as in Python). Spread copies one level; structuredClone copies everything.

const alias = conv, shallow = { ...conv }, deep = structuredClone(conv);
conv.msgs.push({ role: "assistant", text: "hello" });
console.log(alias.msgs.length, shallow.msgs.length, deep.msgs.length);

4. Functions, closures and this

Functions are values, as in Python. There are three spellings; the arrow function x => x * 2 is the everyday one (a lambda that may also have a block body). Arguments are not checked: extra ones are ignored, missing ones are undefined. Default values are evaluated on every call, so Python's mutable-default trap does not exist here (it runs in reverse).

d1_functions.mjs
// Three ways to write a function. All are objects you can pass around, as in Python.
function add(a, b = 10) { return a + b; }        // declaration: hoisted, usable above this line
const mul = function (a, b) { return a * b; };   // expression
const sq = x => x * x;                           // arrow: short, and no own `this` (below)
const sum = (...nums) => nums.reduce((s, n) => s + n, 0);   // rest parameter: Python's *args
console.log(add(1), add(1, 2), mul(3, 4), sq(5), sum(1, 2, 3));
console.log(add(1, 2, 99), add());               // extra arguments are ignored; missing ones are undefined
function push(x, xs = []) { xs.push(x); return xs; }
console.log(push(1), push(2));                   // defaults are evaluated on EVERY call (Python: once, at def)

A closure is a function that keeps the variables of the scope it was created in, exactly as in Python (without needing nonlocal to assign). Closures are how JavaScript does private state, callbacks and factories. The classic loop trap: var gives every iteration the same variable; let gives each iteration a fresh one.

d2_closures.mjs
// A closure: a function that keeps the variables of the scope it was created in.
function makeCounter() {
  let n = 0;                                    // private: nothing outside can reach n
  return { inc: () => ++n, get: () => n };
}
const c1 = makeCounter(), c2 = makeCounter();
c1.inc(); c1.inc(); c2.inc();
console.log(c1.get(), c2.get());
const withVar = [], withLet = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);   // one i shared by all three closures
for (let j = 0; j < 3; j++) withLet.push(() => j);   // a fresh j per iteration
console.log(withVar.map(f => f()), withLet.map(f => f()));

this

Inside a function, this is not fixed when the function is written; it is set by the call. obj.method() sets this to obj; calling the same function bare (const f = obj.method; f()) sets it to undefined (in modules and classes, which are always "strict mode"). That is the commonest bug in the language: passing obj.method as a callback loses obj. Arrow functions have no this of their own and use the surrounding one, which is why callbacks inside methods are written as arrows. fn.bind(obj) makes a copy with this fixed (Python makes bound methods for you; JavaScript does not).

d3_this.mjs
// `this` is decided by HOW a function is called, not where it is written.
const bot = {
  name: "bot",
  hello() { return `hi from ${this?.name}`; },
  later() { return [1].map(function () { return this?.name; }); },   // a plain callback: this is lost
  laterArrow() { return [1].map(() => this.name); },                 // an arrow keeps the outer this
};
console.log(bot.hello());                       // called as bot.hello(): this = bot
const loose = bot.hello;
console.log(loose());                           // called bare: this = undefined (modules are strict)
console.log(bot.later(), bot.laterArrow());
const bound = bot.hello.bind(bot);              // Python's bound method, made by hand
console.log(bound(), bot.hello.call({ name: "other" }));

Rule of thumb
Methods as method syntax inside classes and objects; every callback as an arrow function; never pass obj.method bare, pass () => obj.method().
Also
new Fn() sets this to a fresh object; fn.call(o, ...) and fn.apply(o, [...]) set it explicitly. Those four rules are all there is.

5. Classes and prototypes

class looks like Python's: a constructor is __init__, this is self (implicit, never a parameter), extends and super work as expected, get defines a property. Differences: fields can be declared in the body; #name fields are truly private, enforced by the parser (Python's _name is a convention); there is single inheritance only; and there is no operator overloading (no __eq__, __add__, __len__).

e1_classes.mjs
// class: syntax over prototypes. Fields, #private fields, static members, getters, extends and super.
class Counter {
  #counts = new Map();                          // # = truly private (Python's _ is only a convention)
  static created = 0;
  constructor(name) { this.name = name; Counter.created++; }   // Python's __init__; `this` is self
  add(user, n = 1) { this.#counts.set(user, (this.#counts.get(user) ?? 0) + n); return this; }
  get total() { let t = 0; for (const v of this.#counts.values()) t += v; return t; }   // like @property
  toString() { return `${this.name}: ${this.total}`; }   // like __str__ (used by template strings)
}
class TopCounter extends Counter {
  constructor(name, k) { super(name); this.k = k; }
  add(user, n) { return super.add(user, Math.min(n, this.k)); }
}
const c = new TopCounter("demo", 5).add("u1", 3).add("u2", 9);
console.log(`${c}`, c.total, Counter.created, c instanceof Counter);
console.log(Object.keys(c), c.counts, typeof Counter);   // private fields are invisible; a class is a function

Under the syntax, there are no classes at all: every object has a prototype, another object where missing properties are looked up, and so on up a chain ending at Object.prototype. A class is a function whose prototype object holds the methods; new makes an object whose prototype is that object. Python's attribute lookup through the MRO is the same idea with more rules. Knowing the chain explains instanceof, method sharing, and why changing a prototype changes every instance.

e2_prototype.mjs
// Under the class syntax: every object has a prototype; a missing property is looked up along the chain.
class Animal { speak() { return `${this.name} makes a sound`; } }
class Dog extends Animal { speak() { return `${this.name} barks`; } }
const d = new Dog(); d.name = "Rex";
console.log(Object.getPrototypeOf(d) === Dog.prototype, Object.getPrototypeOf(Dog.prototype) === Animal.prototype);
console.log(Object.hasOwn(d, "name"), Object.hasOwn(d, "speak"), "speak" in d);
const base = { greet() { return "hello from the prototype"; } };
const child = Object.create(base);              // an object whose prototype is base: no class needed
console.log(child.greet(), Object.keys(child));
Dog.prototype.speak = function () { return "patched at run time"; };   // monkey-patching works on every Dog
console.log(d.speak());

The few hooks JavaScript offers instead of dunder methods are keyed by well-known symbols: Symbol.iterator (__iter__), Symbol.asyncIterator (__aiter__), Symbol.toPrimitive (roughly __int__ and __str__), plus toString and toJSON.

e3_dunders.mjs
// Python's dunder methods have a few JavaScript counterparts, keyed by well-known Symbols.
class Range {
  constructor(n) { this.n = n; }
  *[Symbol.iterator]() { for (let i = 0; i < this.n; i++) yield i; }   // __iter__
  [Symbol.toPrimitive](hint) { return hint === "number" ? this.n : `Range(${this.n})`; }
}
const r = new Range(3);
console.log([...r], `${r}`, +r, r * 2);
const a = new Range(1), b = new Range(1);
console.log(a == b, a + b);                     // no __eq__ or __add__ overloading: == is identity, + uses toPrimitive

For the rest of Python's attribute hooks (__getattr__, __setattr__), JavaScript has Proxy: a wrapper that intercepts reads, writes and more on any object. Reach for it rarely: it is slower than plain objects and surprising to readers.

e4_proxy.mjs
// Proxy: intercept property reads and writes on an object (Python's __getattr__ and __setattr__, for any object).
// Libraries use it for reactivity, mocks and lazy clients; it is slower than plain objects.
const config = new Proxy({ model: "small" }, {
  get(target, key) { if (!(key in target)) throw new Error(`unknown setting: ${String(key)}`); return target[key]; },
  set(target, key, value) { if (key === "temperature" && (value < 0 || value > 2)) throw new RangeError("temperature must be in [0, 2]"); target[key] = value; return true; },
});
config.temperature = 0.7;
console.log(config.model, config.temperature);
try { config.temprature; } catch (e) { console.log(e.message); }      // a typo is now an error, not undefined
try { config.temperature = 5; } catch (e) { console.log(e.name, e.message); }
