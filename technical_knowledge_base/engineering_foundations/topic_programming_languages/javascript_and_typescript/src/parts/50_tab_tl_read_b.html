2. A first call

In Python you would write client = anthropic.Anthropic() and client.messages.create(...). The TypeScript SDK is the same API with one difference you feel at once: create returns a promise, so you await it (promises and await are taught in {{Part 1's Reading|#t-ja-read}}, section 9). Top-level await works because the file is an ES module.

a1_first_call.ts
// The first call: the official Anthropic SDK, pointed at the local mock (baseURL) instead of api.anthropic.com.
import Anthropic from "@anthropic-ai/sdk";
import { startMock } from "./mock_model.ts";

const mock = await startMock();
const client = new Anthropic({ baseURL: mock.url, apiKey: "mock-key" });   // real code: new Anthropic() reads ANTHROPIC_API_KEY

const msg = await client.messages.create({
  model: "claude-sonnet-5-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "In one sentence, what is TypeScript?" }],
});

// msg is typed Anthropic.Message: content is an array of blocks, so narrow on .type before reading .text
for (const block of msg.content) if (block.type === "text") console.log("text:", block.text);
console.log("stop_reason:", msg.stop_reason, "| usage:", JSON.stringify({ in: msg.usage.input_tokens, out: msg.usage.output_tokens }));
console.log("request id:", msg._request_id);

const sent = mock.log[0]!;
console.log("\nwhat went over the wire:");
console.log("POST", sent.path, JSON.stringify(sent.headers, null, 1).replace(/\n\s*/g, " "));
console.log("body:", JSON.stringify(sent.request));
console.log("response:", JSON.stringify(sent.response));
await mock.close();

Read the response as data, not as text:

  • content is an array of blocks, each with a type: text, tool_use, thinking and others. TypeScript makes you narrow on block.type === "text" before you may read block.text: the response type is a discriminated union, the feature Part 2 teaches with its narrowing stepper ({{Narrowing stepper|#t-tb-narrow}}). msg.content[0].text is a type error, and it should be: the first block is not always text.
  • stop_reason says why the model stopped: end_turn (finished), max_tokens (cut off), tool_use (wants a tool), stop_sequence, pause_turn, refusal and model_context_window_exceeded (the full list from the SDK's StopReason type in 0.131.0). Check it on every response.
  • usage counts input and output tokens: the bill. Real responses also carry cache counts (cache_read_input_tokens, cache_creation_input_tokens).
  • The wire shows what the SDK added for you: the anthropic-version: 2023-06-01 header (the API's version, not the model's), its retry counter, and its timeout (600 s).

3. When the call fails: retries, timeouts, typed errors

A model API fails in ordinary ways: rate limits (HTTP 429), overload (529 and other 5xx), a slow or dead connection, or a request you got wrong (400). The SDK already handles the first three. Read from the SDK's source (client.js, 0.131.0): it retries 2 times by default (maxRetries), on 408, 409, 429, every 5xx, and connection errors; it waits with exponential backoff or for the server's retry-after / retry-after-ms header; and its timeout is 10 minutes per attempt (in milliseconds in TypeScript: timeout: 600_000). A 400 is never retried: retrying a wrong request cannot fix it. A local server that fails on purpose shows each case:

a3_errors.ts
// What the SDK does when the API fails: retries (429, 5xx, timeouts) and typed errors you can catch.
import Anthropic from "@anthropic-ai/sdk";
import { createServer } from "node:http";

let attempts = 0, mode = "";
const t0 = Date.now(); const log = (s: string) => console.log(`${String(Date.now() - t0).padStart(5)} ms  ${s}`);
const server = createServer((req, res) => {
  attempts++; req.resume();
  log(`server: attempt ${attempts} (${mode}), retry-count header ${req.headers["x-stainless-retry-count"]}`);
  if (mode === "429" && attempts <= 2) return res.writeHead(429, { "content-type": "application/json", "retry-after-ms": "100" })
    .end(JSON.stringify({ type: "error", error: { type: "rate_limit_error", message: "slow down" } }));
  if (mode === "400") return res.writeHead(400, { "content-type": "application/json" })
    .end(JSON.stringify({ type: "error", error: { type: "invalid_request_error", message: "max_tokens: must be at least 1" } }));
  if (mode === "hang") return;   // never answers
  res.writeHead(200, { "content-type": "application/json" }).end(JSON.stringify({ id: "msg_1", type: "message", role: "assistant",
    model: "m", content: [{ type: "text", text: "ok" }], stop_reason: "end_turn", stop_sequence: null, usage: { input_tokens: 1, output_tokens: 1 } }));
}).listen(0);
const client = new Anthropic({ baseURL: `http://127.0.0.1:${(server.address() as any).port}`, apiKey: "mock-key" });
const ask = (opts?: Anthropic.RequestOptions) =>
  client.messages.create({ model: "claude-sonnet-5-5", max_tokens: 64, messages: [{ role: "user", content: "hi" }] }, opts);

for (const [m, opts] of [["429", undefined], ["400", undefined], ["hang", { timeout: 300, maxRetries: 1 }]] as const) {
  mode = m; attempts = 0; console.log(`\n--- server answers ${m}${opts ? " (timeout 300 ms, maxRetries 1)" : ""}`);
  try {
    const r = await ask(opts);
    log(`client: success after ${attempts} attempts: ${r.content[0]?.type === "text" ? r.content[0].text : ""}`);
  } catch (e) {
    if (e instanceof Anthropic.RateLimitError) log(`client: RateLimitError ${e.status}`);
    else if (e instanceof Anthropic.BadRequestError) log(`client: BadRequestError ${e.status}, not retried: ${e.message}`);
    else if (e instanceof Anthropic.APIConnectionTimeoutError) log(`client: APIConnectionTimeoutError after ${attempts} attempts`);
    else throw e;
  }
}
server.closeAllConnections(); server.close();
Predict: the server answers 429 twice, then succeeds. How many requests does it see, and does your code see an error? And when it never answers, with a 300 ms timeout and maxRetries 1, how long until the error?

Two lessons sit in the last block. First, timeouts are retried, so the worst case is about timeout × (maxRetries + 1) plus backoff (here two 300 ms attempts plus about 450 ms of backoff: about one second from the first attempt to the error). Second, catch the specific error classes (RateLimitError, BadRequestError, APIConnectionTimeoutError, all subclasses of Anthropic.APIError) with instanceof, never by matching message strings. In Python the same classes exist with the same names (anthropic.RateLimitError); TypeScript's catch (e) gives e the type unknown, so instanceof is also how you get a typed error back.

4. Streaming

A long answer takes seconds to generate. Streaming sends each piece as it is produced, so the user sees text at once. On the wire it is server-sent events: one HTTP response that stays open and carries event: and data: lines, each event ended by a blank line. How to parse SSE bytes correctly yourself (chunks split events and even UTF-8 characters) is taught with an animation in {{Part 1's Reading|#t-ja-read}}, section 11; the SDK does that parsing for you. What remains is knowing the events.

Every frame is one the mock really sent in the recorded runs of b1_stream.ts and b2_stream_openai.ts (same answer text in both formats); the "assembled so far" column is computed in your browser from those frames, the way the SDK assembles them.

Event references: Anthropic streaming, OpenAI Responses streaming events.

The SDK gives three levels. create({ ..., stream: true }) returns an async iterable of the raw events, already parsed (note that it drops the ping keep-alive: 23 events arrive, the wire carried 24). messages.stream() is the helper: .on("text", f) for each text piece and await finalMessage() for the assembled Message, identical to what a non-streaming call returns. And for tool calls, the arguments stream as partial JSON (input_json_delta): fragments like "t.jsonl\",\"to" that are not JSON on their own; the helper re-parses the snapshot after each one.

b1_stream.ts
// Streaming three ways with the Anthropic SDK: raw events (stream: true), the stream helper's events, and partial JSON
// for a tool call. The mock sends one SSE event per write.
import Anthropic from "@anthropic-ai/sdk";
import { writeFileSync } from "node:fs";
import { startMock } from "./mock_model.ts";

const mock = await startMock();
const client = new Anthropic({ baseURL: mock.url, apiKey: "mock-key" });
const ask = { model: "claude-sonnet-5-5", max_tokens: 1024, messages: [{ role: "user" as const, content: "In one sentence, what is TypeScript?" }] };

// 1. stream: true returns an async iterable of the raw events, already parsed from SSE
const raw = await client.messages.create({ ...ask, stream: true });
const kinds: string[] = []; let text = "";
for await (const ev of raw) {
  kinds.push(ev.type === "content_block_delta" ? `delta(${JSON.stringify(ev.delta.type === "text_delta" ? ev.delta.text : "")})` : ev.type);
  if (ev.type === "content_block_delta" && ev.delta.type === "text_delta") text += ev.delta.text;
}
console.log(`1. raw events (${kinds.length}):`, kinds.join(" "));
console.log("   first 3 SSE frames on the wire:\n" + mock.log[0]!.sse!.split("\n\n").slice(0, 3).map(f => "   | " + f.replace(/\n/g, "\n   | ")).join("\n"));

// 2. the helper: .on("text") per delta, finalMessage() for the assembled Message
const s = client.messages.stream(ask);
let deltas = 0; s.on("text", () => deltas++);
const final = await s.finalMessage();
console.log(`2. helper: ${deltas} text events; finalMessage: stop_reason ${final.stop_reason}, ${final.content.length} block, text equal to step 1: ${final.content[0]?.type === "text" && final.content[0].text === text}`);

// 3. a tool call streams its input as partial JSON; the helper parses the snapshot so far at every step
const t = client.messages.stream({ ...ask, tools: [{ name: "count_tokens", description: "count tokens per user", input_schema: { type: "object", properties: { path: { type: "string" }, top: { type: "integer" } } } }] },
  { headers: { "x-mock-scenario": "happy" } });
t.on("inputJson", (partial, snapshot) => console.log(`   + ${JSON.stringify(partial).padEnd(16)} snapshot ${JSON.stringify(snapshot)}`));
console.log("3. tool input as it arrives:");
const tm = await t.finalMessage();
console.log("   final tool_use input:", JSON.stringify(tm.content.find(b => b.type === "tool_use")));
if (process.argv[2]) writeFileSync(process.argv[2], JSON.stringify({ anthropic: mock.log[0]!.sse, tool: mock.log[2]!.sse }));
await mock.close();

// The same answer streamed by the OpenAI Responses API: different event names, same idea.

When not to stream: a batch job, or anything that needs the whole answer before acting (a classifier, a JSON extraction you validate as a whole). Then a plain create is simpler. Note that the SDK's documentation recommends streaming for large max_tokens so that long responses do not hit HTTP timeouts, and finalMessage() gives you a complete message anyway.

with client.messages.stream(...) as s: for text in s.text_stream: ... becomes const s = client.messages.stream(...); for await (const ev of s) ... or s.on("text", ...). async for is for await; the context manager's cleanup is the stream's own abort() (or breaking out of the loop).
