9. Asynchronous JavaScript and the event loop

A Node process runs your JavaScript on one thread. It never waits: reading a file, a socket or a timer is started, the call returns at once, and the result is delivered later by the event loop, the loop inside Node that runs one piece of your code at a time, to completion, and then picks the next. Python's asyncio is the same design, opt-in; in JavaScript it is the only model, and every I/O API is built for it. Three generations of API sit on top.

Callbacks

The original style: pass a function to call when the result is ready. Node's convention puts the error first. Each dependent step nests one level deeper ("callback hell"), and errors must be checked by hand at every level.

i1_callbacks.mjs
// Before promises: callbacks. The function returns at once; your callback runs later, from the event loop.
import { readFile } from "node:fs";
console.log("1. ask for the file");
readFile("i1_callbacks.mjs", "utf8", (err, text) => {        // Node's convention: error first, then the result
  if (err) return console.log("failed:", err.code);
  console.log("3. got", text.length, "characters");
  readFile("no_such_file.txt", "utf8", (err2) => {             // the next step nests inside: "callback hell"
    console.log("4. second read failed with", err2.code);
  });
});
console.log("2. readFile has already returned; nothing has been read yet");

Promises, then async/await

A promise is an object standing for a result that is not there yet: pending, then once and for all fulfilled with a value or rejected with an error. .then(f) registers what to do next and returns a new promise, so steps chain instead of nesting. async function and await are syntax over promises: an async function always returns a promise, and await p pauses the function until p settles, returning its value or throwing its error, so plain try/catch works. One difference from Python matters: a promise is eager. The work starts when the promise is created; a Python coroutine does nothing until awaited or wrapped in a task.

i2_promises.mjs
// A promise is an object for a value that is not there yet: pending, then fulfilled or rejected (once).
const p = new Promise((resolve) => {
  console.log("the executor runs immediately: a promise is eager (a Python coroutine is lazy)");
  setTimeout(() => resolve(42), 10);
});
console.log("pending now:", p);
p.then(v => v + 1)                               // .then returns a NEW promise: chains read top to bottom
 .then(v => { console.log("then got", v); throw new Error("boom"); })
 .catch(e => console.log("catch got", e.message))
 .finally(() => console.log("finally"));
const sleep = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));   // wrap a callback API once
async function main() {                          // async/await: the same chain, written like synchronous code
  const v = await sleep(20, "awaited value");
  console.log(v, "| p is now", p);
  try { await Promise.reject(new Error("rejected")); } catch (e) { console.log("try/catch works with await:", e.message); }
}
main();

The two queues

When does a callback run? The event loop keeps two kinds of queue. Macrotasks (or just "tasks"): timer callbacks, I/O completions, setImmediate. Microtasks: promise reactions (.then callbacks and the continuation after an await) and queueMicrotask. The rule: run the current piece of synchronous code to the end; then run every microtask, including ones queued meanwhile; only then take the next macrotask. So a resolved promise's callback always beats a setTimeout(f, 0).

i3_order.mjs
// The classic ordering question. Predict the order of the seven lines before you look.
console.log("sync start");
setTimeout(() => console.log("setTimeout 0"), 0);
Promise.resolve().then(() => console.log("promise.then"));
queueMicrotask(() => console.log("queueMicrotask"));
(async () => {
  console.log("async body, before await");
  await null;
  console.log("async body, after await");
})();
console.log("sync end");

Why "async body, after await" comes after "queueMicrotask": the continuation of an async function is queued when it reaches await, which here is after the .then and queueMicrotask callbacks were queued. Microtasks run in the order they were queued. Concurrency on one thread, to scale

The same three jobs as the {{Python page's asyncio replay|n:3cd5c17b0d0d81b28acdea39e7a4d998}}: A, B and C wait 100, 200 and 300 ms. Run four ways. Every bar below is a real event from i4_trace.mjs (code under the animation), stamped with milliseconds since the start and drawn on the same 0 to 620 ms axis.

Thin bar: suspended at an await (the thread is free); dark bar: running on the thread; orange bar: holding the thread in a synchronous loop; ring: the moment a timer is due. Top lane: what the one JavaScript thread is doing.
What to notice
  • 1 against 2: await in sequence takes the sum (about 600 ms); Promise.all starts all three, so the waits overlap and the total is the longest (about 300 ms). Unlike Python, no "task" wrapper is needed: calling an async function already starts it.
  • 2 against 3: a 200 ms synchronous loop in B holds the only thread. A's timer is due at 100 ms but runs at 200 ms; C cannot even start before 200 ms. Total about 500 ms, and nothing warns you.
  • 3 against 4: the same busy loop in a worker thread (section 12) runs on another core; B just awaits a message, and the total is back to about 300 ms.

The code: i4_trace.mjs
i4_trace.mjs
// Three jobs, A, B and C, wait 100, 200 and 300 ms (the same three as the Python page's asyncio replay).
// Four ways to run them; every event is stamped with ms since the start. The Reading animation replays this file's output.
import { Worker } from "node:worker_threads";
import { setTimeout as sleep } from "node:timers/promises";      // a promise-returning setTimeout
let T0 = 0, EV = [];
const ev = (who, what, note = "") => EV.push([who, what, +(performance.now() - T0).toFixed(1), note]);
const busyWait = ms => { const end = performance.now() + ms; while (performance.now() < end); };  // holds the thread

async function job(name, ms) { ev(name, "start"); ev(name, "await", `sleep(${ms})`); await sleep(ms); ev(name, "resume"); ev(name, "done"); }
async function jobBlocking(name, ms) { ev(name, "start"); ev(name, "block", `busyWait(${ms})`); busyWait(ms); ev(name, "done"); }
async function jobWorker(name, ms) {
  ev(name, "start"); ev(name, "await", `a worker thread busy-waits ${ms} ms`);
  await new Promise((ok, fail) => {
    const w = new Worker(`const e = performance.now() + ${ms}; while (performance.now() < e); require("node:worker_threads").parentPort.postMessage(1)`, { eval: true });
    w.once("message", ok); w.once("error", fail);
  });
  ev(name, "resume"); ev(name, "done");
}
const MODES = {
  sequential: async () => { await job("A", 100); await job("B", 200); await job("C", 300); },
  all: () => Promise.all([job("A", 100), job("B", 200), job("C", 300)]),
  all_blocking: () => Promise.all([job("A", 100), jobBlocking("B", 200), job("C", 300)]),
  all_worker: () => Promise.all([job("A", 100), jobWorker("B", 200), job("C", 300)]),
};
const out = {};
for (const [mode, run] of Object.entries(MODES)) {
  EV = []; T0 = performance.now();
  await run();
  const total = +(performance.now() - T0).toFixed(1);
  out[mode] = { events: EV, total_ms: total };
  console.log(`${mode.padEnd(13)} ${total.toFixed(1).padStart(6)} ms  ` + EV.map(e => `${e[0]}:${e[1]}`).join(" "));
}
if (process.argv[2]) (await import("node:fs")).writeFileSync(process.argv[2], JSON.stringify(out));
