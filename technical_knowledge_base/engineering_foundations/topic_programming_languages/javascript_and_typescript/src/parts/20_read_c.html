3. Runtimes and packages: Node, npm and pnpm, Bun and Deno

package.json is pyproject.toml: name, version, "type", "scripts" (named commands run by npm run name), "dependencies" and "devDependencies" (tools only needed to develop, such as test runners). Versions are semver ranges: ^5.2.1 means "5.x.y, at least 5.2.1". The exact resolved tree is pinned in a lockfile (package-lock.json, like uv.lock); commit it, and install from it in CI with npm ci. Packages go into a local node_modules/ folder per project: there is no global site-packages and no virtual environment to activate, because every project is already isolated. npx tool (or pnpm dlx, bunx) runs a package's command without installing it, like uvx. A library's "exports" map, which decides which file each importer gets, is on the TypeScript page with publishing.

Node is not the only runtime, and npm is not the only installer. The four tools side by side, with this laptop's measurements (Apple M1 Pro, 2026-10-05; the runs are below the table):

Three direct dependencies through npm: npm reported adding 1 + 68 + 35 = 104 packages, in 95 top-level folders taking 46 MB, and the lockfile pins 129 entries (27 of them optional platform-specific binaries, for example @rolldown/binding-android-arm64, installed only on matching machines). npm ls answers "who brought this in?". npm hoists everything into one flat folder, so your code can import packages you never declared (debug, below), and breaks when they move. pnpm keeps one global content-addressed store on disk, hard-links files from it, and exposes only declared dependencies at the top of node_modules. Bun includes its own npm-compatible installer.

The script: l2_pnpm.sh
l2_pnpm.sh
# The same three dependencies with npm, pnpm and bun, then a timed reinstall from each lockfile
# into an empty node_modules (what CI does), caches warm: hyperfine, 5 runs each.
set -e
for tool in npm pnpm bun; do
  rm -rf "$WORK/$tool-demo" && mkdir -p "$WORK/$tool-demo" && cd "$WORK/$tool-demo"
  printf '{ "name": "%s-demo", "version": "1.0.0", "type": "module" }\n' $tool > package.json
  case $tool in
    npm)  npm install zod@4.6.5 express@5.2.1 vitest@5.0.3 --no-audit --no-fund >/dev/null 2>&1; CI="npm ci --no-audit --no-fund" ;;
    pnpm) pnpm add zod@4.6.5 express@5.2.1 vitest@5.0.3 >/dev/null 2>&1; CI="pnpm install --frozen-lockfile" ;;
    bun)  bun add zod@4.6.5 express@5.2.1 vitest@5.0.3 >/dev/null 2>&1; CI="bun install --frozen-lockfile" ;;
  esac
  hyperfine --runs 5 --warmup 1 --prepare 'rm -rf node_modules' "$CI" --export-json "$WORK/$tool-ci.json" >/dev/null 2>&1
  echo "$tool: lockfile $(ls *lock* | tr -d '\n'), top-level entries in node_modules $(ls -A node_modules | wc -l | tr -d ' '), '$CI' median $(python3 -c "import json;print(round(json.load(open('$WORK/$tool-ci.json'))['results'][0]['median'],2))") s"
done
cd "$WORK/pnpm-demo"
echo '$ readlink node_modules/express   # pnpm: a link into .pnpm, which hard-links files from one global store'; readlink node_modules/express

Supply chain
A dependency can run code at install time ("postinstall" scripts), and a tree of a hundred packages has a hundred maintainers. Pin with a lockfile, review what a new dependency pulls in (npm ls, the package's dependency count), and prefer packages with few dependencies. pnpm (since version 10, {{release notes|https://github.com/pnpm/pnpm/releases/tag/v10.0.0}}) and Bun ({{lifecycle scripts|https://bun.com/docs/install/lifecycle}}) do not run dependencies' install scripts unless you allow them; npm runs them by default.

Throughput on a real task (the root's token counter on 38.8 MB, Node and Bun against Python, C++ and Rust) is on the root's {{Benchmark tab|n:3c65c17b0d0d81a2bb1ac0bc8aeb6aa9}}; this page does not repeat it.
