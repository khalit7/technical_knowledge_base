# Scaling a database: source

`sh build.sh` assembles `../index.html` from `parts/` (same build as the sibling pages; `{{text|n:id}}` and `{{text|#t-tab}}` links).
Tabs: Reading (`20_read_a` to `20_read_h`), Shard-key lab (`31_*`), Further reading (`39_tab_more.html`).
JS: `21_js_rd_common.js` (RD helpers and the step-animation controller, copied from the root), `22_js_data.js` (generated by `build_data.py` from `inputs/`), `23_js_ladder.js`, `24_js_part.js`, `25_js_fan.js` (the before/after fan-out animation), `26_js_fill.js` (measured numbers into the text, tables and timeline), `31_js_lab.js`.

## Measurements (all on one Apple M1 Pro laptop, 5 Oct 2026; run from a scratch directory, never inside the repo)
Environment for every script: `SCL_DATA=<scratch dir> uv run --no-project --python 3.12 --with pgserver --with 'psycopg[binary]' python src/measure/<script>`. Ports are fixed per server and refused if another program listens (`pgc.in_use`).
1. `gen_chat.py` (port 56401): the root's `src/plan/gen.py` with the same seeds and SQL (only the server helper and log path changed): 100k users, 1M chats, 10M messages, about 1.5 minutes. `inputs/gen_log.json`.
2. `part.py`: monthly range and hash partitioned copies, EXPLAIN measurements, retention, planning time vs partition count; about 6 minutes. `inputs/part.json`. (It leaves an index `messages_created` on the big server, which later scripts' dashboard comparisons rely on.)
3. `labdata.py`: per-shard loads for the lab and the resharding counts (router in `ring.py`); about 1 minute. `inputs/lab_data.json`.
4. Citus 14.2.0 built from source against a copy of the pgserver wheel's PostgreSQL 16.2 (`./configure PG_CONFIG=... --without-libcurl --without-lz4 --without-zstd`, `make PG_SYSROOT=$(xcrun --show-sdk-path)`, libpq path fixed with `install_name_tool`). One local patch: the columnar extension calls `systable_inplace_update_*`, added in PostgreSQL 16.5, so it was replaced with `systable_beginscan` plus `heap_inplace_update`; this page never uses columnar tables. Build about 5 minutes.
   `CITUS_PG=<copy>/pginstall citus_run.py` (coordinator 56411, workers 56412 to 56414: load, EXPLAINs, point and heavy queries, repartition join, 2PC), then `citus_rebal.py` (adds worker 56415; drains it back and rebalances again with a writer running, then the indexed dashboard comparison). `inputs/citus.json`. The first rebalance stalled on Citus's disk-space check (laptop disk 96% full); `citus.desired_percent_disk_available_after_move` was lowered to 1 and `citus.local_hostname` set to 127.0.0.1 (the background mover connects to "localhost", which resolved to IPv6 here).
5. `CRDB=<cockroach binary> crdb.py`: CockroachDB v26.3.0 (darwin arm64 tarball), 3 insecure nodes on ports 56257 to 56259 (HTTP 56280 to 56282), about 2 minutes; then `pg_flush.py` adds the Postgres real-flush baseline. `inputs/crdb.json`. Unlicensed multi-node clusters are throttled after 7 days; the run lasts minutes.
6. Research extracts with verbatim quotes and URLs: `inputs/research_stories.json`, `inputs/research_products.json` (read 5 Oct 2026).

## Checks
`python3 build_data.py && sh build.sh`; from the repo root `sh html_utils/checkpage.sh <folder>`; `node <folder>/src/check_ui.mjs` (clicks every control at 390 dark and 920 light, writes `page_numbers.json`); `python3 src/recompute.py` (every derived number against the page, plus the ring and mod-N move counts re-derived from the router alone).
