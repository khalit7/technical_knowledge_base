The idea in one screen

Measure which resource of the one server runs out, then climb only to the first rung that fixes it: copies multiply reads but never writes, splitting the data multiplies writes and size, and every split makes a query that does not name the key ask every piece.

Three ways to grow, and where one request goes in each (highlighted)

Still one machine

Rungs: fix the queries, a bigger box, a connection pooler, a cache, partitions.

Multiplies: nothing; the one box is used better. Wall: the largest machine.

More copies

Rungs: read replicas, in one region or many.

Multiplies: reads. Every write still goes to the one primary and is replayed by every replica, which is a little behind.

Split the data

Rungs: tables to other databases, sharding one table's rows, distributed SQL.

Multiplies: writes and size. A query with the shard key reaches one shard; one without it asks them all (dashed).

Drawings are schematic. The colours (one machine, copies, split) are the same in the ladder below and in every figure on the page; the highlight marks where a request goes.

Vertical scaling
a bigger machine for the same database (scaling up).
Read replica
a copy that replays the primary's log and answers reads, a little behind.
Read-your-writes
a user always sees their own last write.
Partition
a physical piece of one table, on the same server.
Shard, shard key
a slice of a table's rows on its own server; the column that decides which slice.
Scatter-gather
sending a query to every shard and merging the answers (fan-out).
Logical shard
a small fixed bucket of keys; many live on one server and move as a unit.
Range, leaseholder
in distributed SQL, a contiguous piece of a table replicated by consensus; the replica that serves its reads and proposes its writes.
