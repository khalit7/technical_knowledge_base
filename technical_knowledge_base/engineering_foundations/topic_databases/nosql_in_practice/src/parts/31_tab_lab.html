Single-table lab: design DynamoDB keys for the chat product

DynamoDB answers only questions that name a key. You list the questions first (the access patterns), then choose how each kind of item is keyed so that every question becomes one request. Pick the keys on the right; the left side shows, for each access pattern, which request it becomes and how many items DynamoDB must read. The rules are DynamoDB's own (sections 4.2 to 4.4 of the Reading tab) and were checked on DynamoDB Local with the chat data; the item counts use that data: .

Hot partitions and what it costs

Every partition serves at most 3,000 read units and 1,000 write units a second ({{DynamoDB docs, partition key design|https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/bp-partition-key-design.html}}). A key that concentrates traffic, such as one very busy group chat or "all messages of model X today", hits that ceiling however large the table is. Adaptive capacity moves busy items onto their own partitions, but a single key still cannot pass the per-partition maximum ({{burst and adaptive capacity|https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/burst-adaptive-capacity.html}}).
