# NoSQL in practice: key-value, document, wide-column, time-series, graph

Notion: https://app.notion.com/p/3ef5c17b0d0d81ec8456c41e4e8f5f6b (child of Topic: databases)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). The non-relational families taught from zero on the chat product, each as "what problem forces you here, how it models data, how you design for it, what it costs, when Postgres would still do": queries first; "the latest 50 messages of a chat" animated across four storage layouts (Postgres without and with an index, after CLUSTER, and a Cassandra partition, all measured); Redis (data structures, a sorted-set leaderboard against a Postgres rank, a Lua token bucket against the read-decide-write race, streams with a crashed consumer, RDB and AOF with kill -9, acknowledged writes lost on failover); DynamoDB (single-table design step by step on DynamoDB Local, GSIs, transactions, capacity and dated prices, hot partitions); MongoDB (embedding against referencing, the 16 MB limit hit, aggregation, a write conflict, validation) beside Postgres jsonb; Cassandra and ScyllaDB (query-first tables, a quorum calculator, tombstones up to a failed read, compaction); time series (partitions, rollups, BRIN, retention by DROP, DuckDB, the dedicated systems compared, cardinality); graph (friends of friends on Postgres, Neo4j and Kuzu, shortest path); RocksDB and LMDB. Tabs: Reading, Single-table lab (DynamoDB key design with scoring, item view, hot-partition and cost calculator), Further reading. New page (2026-10-04); no child pages, databases or video.
