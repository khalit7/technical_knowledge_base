Iceberg, step by step: every file a real table writes

A real Apache Iceberg table built on the local disk with pyiceberg 0.12.0 and a SQLite catalog, from the chat messages, one day at a time (src/measure/iceberg_walk.py, 2026-10-04). Step through the eight commits: each box is a file the table really wrote, new ones are outlined, and files the current snapshot no longer uses fade (they stay on disk for time travel). Click any box to open its decoded contents. The toggle replays the same story with Delta Lake (deltalake 1.6.6), whose metadata is a log of JSON commits instead of a tree.

What to notice

  • Nothing is modified in place. Every commit writes new files and a new metadata.json (Iceberg) or the next numbered log file (Delta). That is what makes commits atomic and old versions readable.
  • Schema and partition changes are metadata-only: steps 4 and 7 wrote one metadata.json and no data.
  • The delete rewrote a whole file (copy-on-write, in both formats): 28,798 rows copied to remove 2. Engines that support merge-on-read write a small delete file instead and pay at read time.
  • Snapshots share manifests: the manifest list of each snapshot points at the older manifests unchanged, so a commit costs one new manifest, not a copy of the table's file list.
