In one screen

The chat product's Postgres is built for the app: fetch one chat, save one message, in milliseconds. Analytics asks the opposite kind of question ("tokens per model this month") that touches a few columns of every row. This page is about the systems built for that second kind of question, all measured on the same 10 million messages as the parent page.

The one-paragraph version. Keep the app on Postgres. Copy the data out (nightly, or as a stream of changes) into Parquet files, sorted by time, and query them with DuckDB until one machine is not enough; then ClickHouse for fresh, fast dashboards, or a cloud warehouse or lakehouse when many teams and engines share terabytes. Whatever the engine, the same few mechanisms decide speed and cost: read only the needed columns, encode them small, skip blocks using statistics (which only works if the data was written sorted), and execute in batches.
