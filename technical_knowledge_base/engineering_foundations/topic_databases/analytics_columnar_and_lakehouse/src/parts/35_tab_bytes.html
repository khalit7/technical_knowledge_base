Inside a Parquet file, byte by byte

A real file: the first 1,000 chat messages (six columns, content left out so the pages stay small), written by pyarrow 25.0.1 as two row groups of 500 rows, with no compression so the bytes stay readable, dictionary encoding for role and model, delta encoding for id and plain for the rest. Every region below is drawn to scale and every value was decoded from the file by a 49-line Thrift compact-protocol reader (src/measure/thrift_compact.py); each column chunk's offsets and sizes were checked equal to pyarrow's own reading of the footer.

Try: click the orange region at the very end (the footer length), then the footer, then a role dictionary page and its data page.

How a reader uses this

  1. Read the last 8 bytes: the footer length and PAR1.
  2. Read the footer; decode it (Thrift compact protocol: each field is a one-byte header holding the gap to the previous field id and a type, then the value; integers are variable-length and zigzag-encoded).
  3. For each row group, compare the query's filter with the statistics; skip what cannot match.
  4. For each surviving column chunk the query needs, read its byte range, then page by page: the page header, then the page body (decompress, then decode).

Field numbers and enum values from parquet.thrift; the hybrid RLE/bit-packing format from the encodings page.
