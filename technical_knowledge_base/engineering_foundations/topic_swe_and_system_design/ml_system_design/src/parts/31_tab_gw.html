Gateway lab

Put a gateway in front of the chat assistant's traffic and decide what it does: route between a small and a large model, answer from caches, fall back when a provider fails. The lab shows what each request costs, how long it takes, how many fail, and how many get a worse or wrong answer, against a naive, healthy baseline: the same traffic sent to the large model, no caching, no outage. Every number is an expectation per request (no randomness).

Try: start from Naive, then Router + prefix cache: cost halves and a few percent of answers get worse (hard questions misrouted to the small model). Then Provider outage, no fallback against with fallback: the fallback turns 40% errors into slower, pricier answers. Then push the semantic cache's hit rate up and watch wrong answers climb.

How it is computed. Requests first meet the exact cache, then (if on) the semantic cache, then the router; the router sends easy requests to the small model with the stated accuracy, and its mistakes send hard requests to the small model (counted as worse answers) and easy ones to the large model (wasted money). Calls to the failing provider either error or go to the fallback, which starts with no cached prefix. Cost per request = (uncached input × input price + cached input × cache-read price + output × output price) ÷ 1,000,000. Monthly cost uses the average rate, half the peak (the parent topic's peak factor 2), over 730 hours. Mean TTFT and full time are request-weighted means.

Self-hosted Llama 3.3 70B: $1.00 per million output tokens with input included, derived from 2,209 tokens/s per H100 at half load and $3.99 per GPU-hour (the parent topic's shared figures); prefix caching saves it time, not money. Cache writes are ignored (they add 25% on the first use of each prefix). Illustrative: every latency (time to first token 0.8 s large API, 0.4 s small API, 0.2 s self-hosted; 60, 120 and 69 tokens/s per user; 10 ms gateway, 20 ms router, 20 ms semantic lookup; a cached prefix removes up to 60% of TTFT), the traffic mix and every hit rate. Defaults: the chat assistant's 231.5 peak requests a second (1 million daily users × 10 messages ÷ 86,400 × 2).
