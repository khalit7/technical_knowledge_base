Consistency lab: which models allow this history?

Each history is what clients observed on one register x (initially 0): a bar per operation, from when the client sent it to when the answer came back. w(1) writes 1; r→0 is a read that returned 0. For each consistency model the lab says whether the history is allowed and why. Models are explained in the Reading tab, {{Consistency models|#t-read}}.

Try: start with "A stale read after the write finished", then "A new value, then an old one" (the subtle one). Then tap any read bar to change what it returned and watch the verdicts flip.

How the verdicts are computed
Linearizable and sequentially consistent are checked by brute force in your browser: try every ordering of the operations, keep those that respect each client's own order (and, for linearizability, real time: if one operation ended before another began, it must come first), and accept if in one of them every read returns the latest preceding write. With at most six operations that is at most 720 orderings. src/recompute.py runs the same check in Python for every preset. Causal, read-your-writes and eventual verdicts are written by hand for the presets, with the reasoning shown; once you edit a read they show "?" rather than guess.
