4. Quorums: N, R and W

In a leaderless system each piece of data is stored on N replicas. A write is sent to all N and counts as successful once W of them confirm. A read asks replicas and waits for R answers, then takes the newest version among them (every value carries a version). The rule that makes this work is one line:

R + W > N
N
replicas that hold each item
W
replicas that must confirm a write
R
replicas a read must hear from

If R + W > N, every read set and every write set share at least R + W − N replicas, so at least one replica the read hears from has the latest successful write. This overlapping set is a quorum. Amazon's Dynamo paper: "The common (N,R,W) configuration used by several instances of Dynamo is (3,2,2)" ({{DeCandia et al., SOSP 2007|https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf}}). Predict: with N = 3, can W = 1 and R = 2 ever miss the latest write? Set it and see; the read is drawn picking the worst replicas it could.

Overlap is guaranteed only when R + W > N

The knobs trade against each other: lower W makes writes faster and keeps them working with more replicas down (N − W may be down), lower R does the same for reads (N − R).

Cassandra's consistency levels, read repair and anti-entropy (optional)

Cassandra exposes this per query as consistency levels: "QUORUM: A majority (n/2 + 1) of the replicas must respond", ONE, ALL, LOCAL_QUORUM (a majority in the local data centre) and others, and its docs call them "a version of Dynamo's R + W > N consistency mechanism" ({{Apache Cassandra docs, Dynamo architecture|https://cassandra.apache.org/doc/latest/cassandra/architecture/dynamo.html}}). Replicas that missed a write catch up by read repair (a read that sees an old version writes the new one back) and by anti-entropy: background comparison of Merkle trees, hash trees that let two replicas find differing ranges without sending all the data (Dynamo, Table 1).

R + W > N is not the same as strong consistency
It guarantees overlap, not linearisability (defined below). Abadi: by increasing R + W such systems "gain more consistency at the expense of latency (although they cannot achieve full consistency as defined by Gilbert and Lynch, even if R + W > N)" ({{Abadi, IEEE Computer, Feb 2012|https://www.cs.umd.edu/~abadi/papers/abadi-pacelc.pdf}}). The gaps: two concurrent writes, settled by timestamps (Cassandra uses "a simpler last-write-wins model where every mutation is timestamped", so a skewed clock picks the winner); a write that reached fewer than W replicas reports failure but is not rolled back where it landed; and a sloppy quorum, Dynamo's choice under failures, accepts writes on replicas outside the usual N ("hinted handoff") so the overlap no longer holds.

Discord, which read and wrote "with quorum consistency level" on Cassandra, also found that one slow replica in a busy partition slowed everyone ("discord-2023" in the parent's Case files).
