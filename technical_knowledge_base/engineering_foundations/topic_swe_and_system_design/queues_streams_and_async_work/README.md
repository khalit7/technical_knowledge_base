# Queues, streams and async work: delivery semantics, Kafka, the outbox pattern

Notion: https://app.notion.com/p/3ef5c17b0d0d81aebf91df927f215b6e (child of Topic: swe-and-system-design)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Taught from zero on the parent's chat-assistant example: why work goes async, queues against logs (SQS, RabbitMQ, Postgres SKIP LOCKED, Kafka, Kinesis, Redpanda), Kafka's topics, partitions, offsets, consumer groups and share groups, at-most-once, at-least-once and what Kafka's exactly-once really covers (idempotent producer, transactions, KIP-890, Jepsen), idempotent consumers, visibility timeouts and leases, dead-letter queues, backpressure and Little's law, the dual-write problem and the transactional outbox (polling relay, Debezium CDC, inbox, webhooks), sagas against two-phase commit, event-driven architecture, event sourcing and CQRS (and when not to), Python job queues (Celery, RQ, Arq, Dramatiq, Procrastinate) and durable workflows (Temporal, DBOS, Restate), cron, and async work around LLMs (resumable streaming, background mode, agent jobs, batch APIs). Includes three experiments on a real local PostgreSQL (SKIP LOCKED throughput, redelivery and duplicates under crashes, dual write against outbox). Tabs: Reading, Queue lab (a simulator checked against Python and against the measurements), Further reading. New page (2026-10-04); carries the queue and delivery facts of the old "Distributed Systems Basics" page; no child pages, databases or video.
