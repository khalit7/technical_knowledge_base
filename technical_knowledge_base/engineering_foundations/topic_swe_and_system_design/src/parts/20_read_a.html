The idea in one screen

A production service is one request path through a few layers (servers, data, slow work, failure handling, the model), and every building block on that path fixes one bottleneck at a price you can name; add it only when its bottleneck has arrived.

System design is the craft of keeping a product fast, correct and affordable as more people use it. The running example. A chat assistant powered by a large language model (LLM): people sign in, chat, upload documents and come back to their history. It starts on one machine with one user and grows to ten million registered users. Every child page of this topic uses the same product, so its numbers line up from page to page. The six steps below are the order in which its walls arrive; each names the building block that fixes it, what that block costs, and the child page that owns it.

1 user: everything on one machine

10 million users: each box has an owner

The number on each box is the step that introduces it; the last line names the page that owns it. A cache makes reads fast and data slightly stale; a queue makes requests fast and results late; a retry rescues one request and can sink the whole system: every box on the right is a fix with a price.

You need: nothing from other pages. The wire under Step 1 (DNS, TCP, TLS, HTTP) is {{Topic: protocols|n:3c65c17b0d0d81ec9355f4eecd6eed02}}, the database under Step 2 is {{Topic: databases|n:3cd5c17b0d0d815d8841ec845f5f3324}}, and the engine under Step 5 is {{Topic: inference-and-serving|n:3c65c17b0d0d81c08b3bc95ff45c7b13}}; this page needs only their one-line definitions, given where they are used.

New terms (each defined where it first appears, and only these):

Latency, throughput: how long one request takes; how many finish per second.
p50, p99: the latency that 50% or 99% of requests beat.
Stateless: a server that keeps nothing another server would need.
Replica, shard: a full copy of the database; a slice of it.
At-least-once, idempotent: no job is lost, so one can run twice; running twice has the effect of once.
SLO, error budget: the reliability target; the failures it allows.
Prefill, decode: reading the prompt at once; writing the reply one token per step.
Back-of-the-envelope estimate: arithmetic accurate to a factor of two that finds the hard part.

Three tools on this page span every child: the {{Scale simulator|#t-sim}} pushes traffic through the whole design and shows which part breaks first, {{Numbers to know|#t-num}} holds the latency, throughput and price figures every page estimates with, and {{Case files|#t-cases}} tells real outages and redesigns, each tagged with the step it belongs to.
