3. JSON: the body almost every API speaks

JSON (JavaScript Object Notation, {{RFC 8259|https://www.rfc-editor.org/rfc/rfc8259.html}}) is text with six kinds of value: objects {"key": value}, arrays [1, 2], strings in double quotes, numbers, true/false, and null. That is all: there is no date type, no distinction between integers and decimals, no comments. Three consequences every API designer meets:

  • Big integers break in browsers. JavaScript stores every number as a 64-bit float, exact only up to 253 − 1 = 9,007,199,254,740,991; RFC 8259 §6 warns about exactly this range. A 64-bit database ID above it silently changes in a JavaScript client. Send IDs as strings (the demo's are "chat_ae8136d1b896", like Stripe's cus_... prefixes, which also tell a human what kind of object an ID names).
  • Dates are strings by convention. Use one format everywhere: either Unix seconds (the demo's created_at) or an {{RFC 3339|https://www.rfc-editor.org/rfc/rfc3339.html}} timestamp with a time zone ("2026-10-04T19:06:35Z"). Mixing them is a classic support ticket.
  • Money is never a float. 0.1 + 0.2 is not 0.3 in binary floating point; send integer minor units (cents, or credits) as Stripe does with amount: 2000 for $20.00.

Content-Type: application/json tells the other side the body is JSON. Errors use the more specific application/problem+json (section 7), and streams use text/event-stream (section 14).

4. A minimal service in FastAPI, line by line

A Python web service has two layers. A server such as uvicorn owns the socket: it accepts connections, parses the bytes you saw above, and hands each request to your application through a standard Python interface called ASGI (asynchronous server gateway interface, {{asgi.readthedocs.io|https://asgi.readthedocs.io/en/latest/}}). FastAPI is the application framework: it routes a method and path to your function, parses and validates the input with pydantic, and turns your return value into a response ({{FastAPI docs|https://fastapi.tiangolo.com/}}). Flask and Django are the older alternatives; FastAPI is the common choice for new Python APIs and for model serving because validation and documentation come from type hints.

The whole demo is one file. To run it yourself: uv run --no-project --with fastapi --with uvicorn uvicorn app:app --port 8765 from src/service/, then curl localhost:8765/v1/health. Here are the parts that matter, with the explanation under each.

FastAPI(...) creates the application object that uvicorn will call. title and version end up in the generated OpenAPI document (section 16).
sqlite3.connect opens a database. SQLite ships with Python, so the demo runs anywhere; a real service uses Postgres (see {{Topic: databases|n:3cd5c17b0d0d815d8841ec845f5f3324}}) with the same tables. isolation_level=None means "I will say BEGIN and COMMIT myself", which the idempotency code needs.
idempotency_keys has primary key(owner, key): the database itself refuses a second row with the same pair. That one line is what makes the idempotency check safe under concurrency (section 10).
class ChatIn(BaseModel) declares the shape of a valid request body. FastAPI reads the body, parses the JSON, and builds a ChatIn or rejects the request with 422 before your function runs.
Field(min_length=1, max_length=200) are constraints. Limits on every string and number are not pedantry: an unbounded content field is how someone sends you 2 GB.
extra="forbid" rejects unknown fields (the capture's "colour": "blue"). Strict input catches client typos (max_token) that would otherwise be silently ignored; the cost is that clients cannot send fields from a newer version of your API. Anthropic's API, for one, rejects an unknown field with "Extra inputs are not permitted" ({{Claude API errors|https://platform.claude.com/docs/en/api/errors}}), which is pydantic's own wording.
Literal["small", "large"] is an enum: any other model name fails validation with a message listing the allowed values.
@app.post("/v1/chats") is a route: this function handles POST requests to that path.
body: ChatIn: because the parameter's type is a pydantic model, FastAPI takes it from the JSON body. authorization: Header() takes it from the Authorization header (FastAPI converts the parameter name, so idempotency_key reads Idempotency-Key).
who(authorization) turns the API key into a user, or nobody (section 11).
JSONResponse(..., 201, headers={"Location": ...}): 201 plus the URL of the new chat, as RFC 9110 §15.3.2 describes for created resources.
How fast is this layer?
Measured on this laptop (Apple M1 Pro, one uvicorn worker, loopback, keep-alive, 2,000 requests after 200 warm-up): GET /v1/health p50 ms, p99 ms; GET /v1/chats/{id} with a database read p50 ms, p99 ms. An LLM reply takes seconds (the root's Step 5), so the framework is almost never the bottleneck of an LLM product; the model, the database and the network are. Measure before rewriting a service in a "faster" framework.

async def or plain def? FastAPI runs plain def routes in a thread pool and async def routes on the event loop. Inside async def, never call something that blocks (a synchronous HTTP client, time.sleep, a slow database driver): it freezes every other request on that worker ({{FastAPI, async docs|https://fastapi.tiangolo.com/async/}}). The demo's message route is async because it awaits the (pretend) model call and streams.

5. Validation: parse, don't trust

Every byte from a client is untrusted: it may be malformed, malicious, or from an old app version. The rule pros follow is to turn it into typed objects at the edge, once, and reject anything that does not fit, so that code inside the service never sees a missing field or a string where a number should be. Alexis King's essay calls this "parse, don't validate": the result of checking should be a value whose type proves the check happened ({{lexi-lambda.github.io, 2019|https://lexi-lambda.github.io/blog/2019/11/05/parse-don-t-validate/}}). Pydantic models are exactly that.

The default shape exposes pydantic's internals (loc, ctx, the echoed input, which can leak a secret a user pasted into the wrong field); the rewritten one uses the standard error shape of section 7 with a JSON Pointer ({{RFC 6901|https://www.rfc-editor.org/rfc/rfc6901.html}}) to each bad field, as RFC 9457's own validation example does. What validation costs, and where it stops
Pydantic v2's validation core is written in Rust ({{pydantic docs|https://docs.pydantic.dev/latest/}}), so per-request cost is small next to network and database time. Validation checks shape (types, lengths, ranges, allowed values). It cannot check meaning that needs the database: whether the chat exists and belongs to the caller, whether the user has credits. Those are business rules, checked in the route, and they answer 404, 403 or 409 rather than 422. Do not pass pydantic models deep into the core of the program either: they belong at the boundary (the code-design half of this question is on {{Code design|n:3ef5c17b0d0d817b99a0ff9701ff30cd}}).
