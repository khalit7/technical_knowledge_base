3. pytest from zero

{{pytest|https://docs.pytest.org/en/stable/}} is the standard test runner for Python. A test runner finds your tests, runs each one in isolation, and reports which passed. pytest's rules are short: files named test_*.py, functions named test_*, and a plain assert statement as the check. When an assert fails, pytest rewrites it to show both sides ({{assertion introspection|https://docs.pytest.org/en/stable/how-to/assert.html}}), so you never need special assertEqual methods.

The first piece of the chat product under test is the chunker: before a document can be searched by meaning (retrieval, the R in RAG), it is cut into overlapping windows of text, each embedded separately. Here are the function and three ordinary tests.

real experiments/hyp/chunking.py
def chunk(text: str, size: int, overlap: int) -> list[str]:
    """Split text into windows of `size` characters; neighbours share `overlap` characters."""
    if not 0 <= overlap < size:
        raise ValueError("need 0 <= overlap < size")
    step = size - overlap
    return [text[i:i + size] for i in range(0, len(text) - size + 1, step)]

def unchunk(chunks: list[str], overlap: int) -> str:
    """Inverse of chunk: glue the windows back, dropping each repeated overlap."""
    if not chunks:
        return ""
    return chunks[0] + "".join(c[overlap:] for c in chunks[1:])
real experiments/hyp/test_chunking_examples.py
from chunking import chunk, unchunk

def test_splits_into_overlapping_windows():
    assert chunk("abcdefghij", size=4, overlap=1) == ["abcd", "defg", "ghij"]

def test_no_overlap():
    assert chunk("abcdef", size=2, overlap=0) == ["ab", "cd", "ef"]

def test_round_trip():
    text = "the quick brown fox jumps over the lazy dog!!"   # 45 characters
    assert unchunk(chunk(text, size=10, overlap=5), overlap=5) == text
$ pytest -q test_chunking_examples.py ... [100%] 3 passed in 0.53s

All green, and the function has a bug: look at len(text) - size + 1. Any document shorter than one window produces no chunks at all, so it silently vanishes from the search index. The three examples happen to use lengths where the windows fit exactly. Hold that thought; section 7 finds it without being told where to look.

Fixtures: setup that tests ask for by name

A fixture is a function that builds something a test needs (a database connection, a temporary folder, a fake server) and cleans it up afterwards. A test asks for it by naming it as an argument; pytest calls the fixture, passes in the value, and after the test runs the code after yield ({{fixtures docs|https://docs.pytest.org/en/stable/how-to/fixtures.html}}). The scope says how often it is rebuilt: function (default, once per test), module, or session (once per run, for expensive things). Fixtures shared by many files live in a conftest.py, which pytest loads automatically. These are the real fixtures behind the PostgreSQL tests in section 6:

real experiments/integ/conftest.py (timing code removed)
import sqlite3, tempfile
import pytest, psycopg, pgserver

@pytest.fixture
def sqlite_conn():
    conn = sqlite3.connect(":memory:")
    yield conn                      # the test runs here
    conn.close()                    # teardown, even if the test failed

@pytest.fixture(scope="session")    # start PostgreSQL once for the whole run
def pg_server():
    yield pgserver.get_server(tempfile.mkdtemp(prefix="pgtest"), cleanup_mode="stop")

@pytest.fixture
def pg_conn(pg_server):             # fixtures can use other fixtures
    with psycopg.connect(pg_server.get_uri(), autocommit=False) as conn:
        yield conn
        conn.rollback()             # every test's writes vanish: tests stay independent

pytest ships useful fixtures too: tmp_path (a fresh folder per test), monkeypatch (change an attribute, dict item or environment variable and undo it after the test; it fixes the order-dependent flake in section 13), capsys (capture printed output) and caplog (capture log records).

Parametrisation: one test, many cases

@pytest.mark.parametrize runs the same test body once per row, each reported as its own test (test_parse_retry_after[-3-0.0]), so one bad row does not hide the others ({{parametrize docs|https://docs.pytest.org/en/stable/how-to/parametrize.html}}). From the retry policy that the chat product uses when the model provider fails:

real experiments/mut/tests/test_strong.py (excerpt)
import pytest
from retrypolicy import should_retry, backoff_delay, parse_retry_after

@pytest.mark.parametrize("status", [408, 429, 500, 502, 503, 504])
def test_retryable_statuses_are_retried(status):
    assert should_retry(status, attempt=1)

@pytest.mark.parametrize("header,expected", [
    ("2", 2.0), ("1.5", 1.5), ("0", 0.0), ("-3", 0.0), (None, None), ("soon", None),
])
def test_parse_retry_after(header, expected):
    assert parse_retry_after(header) == expected

Checking errors, floats and slow tests

  • with pytest.raises(ValueError, match="overlap"): passes only if the block raises that exception type with a matching message. Assert the type and the condition, not merely that "something failed".
  • assert total == pytest.approx(0.3) compares floats with a tolerance (default relative 1e-6); 0.1 + 0.2 == 0.3 is false in binary floating point. Section 11 shows why this matters for ML code.
  • Markers label tests: @pytest.mark.slow, @pytest.mark.gpu. Declare them under markers in your config and add --strict-markers so a typo is an error, not a silently unselected test ({{markers docs|https://docs.pytest.org/en/stable/how-to/mark.html}}).
pyproject.toml (a sensible starting config)
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers --strict-config"
markers = [
  "slow: takes more than a second; skipped on every push",
  "gpu: needs a GPU runner",
]

4. Test behaviour, not implementation

The single most useful idea in test design: a test should check what the code promises (its outputs, its errors, its effects that others can see), not how it does it. A test tied to the how breaks every time you improve the code without changing what it does, which teaches people to stop refactoring. Google's testing book puts the goal as tests that are "unchanging": they only need to change when the requirements change ({{Software Engineering at Google, ch. 12|https://abseil.io/resources/swe-book/html/ch12.html}}).

brittle tests the implementation

def test_backoff_uses_min(mocker):
    spy = mocker.spy(builtins, "min")
    backoff_delay(3)
    spy.assert_called_once()

def test_retryable_set():
    assert 503 in retrypolicy.RETRYABLE

Illustrative (mocker comes from pytest-mock). Breaks if you rewrite the cap as an if; passes if the delay is wrong; reaches into a private detail.

robust tests the behaviour

def test_backoff_doubles_from_base_then_caps():
    assert [backoff_delay(a) for a in range(1, 7)] \
        == [0.5, 1, 2, 4, 8, 8]

def test_stops_at_max_attempts():
    assert not should_retry(503, attempt=3)

Survives any rewrite that keeps the promise; fails on any change a caller could notice.

How a good test reads

  • Arrange, act, assert: build the inputs, call the code once, check the result. If a test needs three acts, it is three tests.
  • One reason to fail, and a name that says the behaviour: test_retry_preserves_idempotency_key, not test_retry_2. When it goes red in CI, the name is the bug report.
  • Tiny literal inputs written in the test itself, so the expected output can be checked by eye.
  • Write the failing test before fixing a bug. It proves you reproduced the bug, and it stops the bug coming back (a regression test). Every production incident should leave one behind; for model behaviour, the equivalent is a new case in the golden set ({{Production eval engineering|n:3c65c17b0d0d81b39ad9e96193d21adc}}).
  • Design for testing: a function that takes its inputs as arguments and returns a value (a pure function) needs no setup at all. Anything that touches S3, a database or the clock goes behind an interface that a test can replace. {{Code design|n:3ef5c17b0d0d817b99a0ff9701ff30cd}} (sections 4 and 8: functional core, dependency injection) shows the refactoring on a real handler.
