13. Very large and AI-written changes: where tests are silent

A green suite says the behaviours someone thought to test still hold. It says nothing about the rest, and a big change travels straight through the rest. Nous Research's refactor of its Hermes agent codebase is a measured example: about nineteen active hours, 1,393 subagents (up to 218 at once) working on a repository of 1,063,826 non-test Python lines, cutting non-test source by 34.4% for about $19,300 in model costs for the main run (roughly $25k with follow-ups). Per-agent worktrees and a frozen baseline made the parallel edits integrable. Community review then caught public names that had been removed and a suppress() rewrite that changed exception handling at about 65 sites: "These were real regressions the existing tests had missed" ({{Nous Research, 2026|https://nousresearch.com/refactoring-hermes-with-1393-agents}}). What closes that gap:

  • Public-API diffing as a merge gate. List the exported surface (__all__, public classes, function signatures) before and after, and fail on any removal or signature change the change does not declare. Tests cover what someone called; the public surface is the promise.
  • Exception-contract tests. Assert the exception type and the condition that raises it (pytest.raises(RateLimited) on the 429 path), not only that an error happens. Broadened or swallowed exceptions are exactly the change a happy-path suite cannot see.
  • Frozen baselines. Compare behaviour against the pinned pre-change commit, not a moving main branch; run the old and new code on the same recorded inputs and diff the outputs.
  • Review by surface, not by file. Nobody reads a million-line diff. Spend human attention on the public interface, the error paths and the deleted code; mutation testing on the changed lines shows where the tests are silent.

The same rules apply to one AI-written pull request: read the tests first, and check they would fail if the code were wrong. {{Code design|n:3ef5c17b0d0d817b99a0ff9701ff30cd}} (section 13 and its Review lab) covers reviewing AI-written code.
