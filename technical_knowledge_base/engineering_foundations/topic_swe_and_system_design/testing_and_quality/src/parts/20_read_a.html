The page in one screen

A test is a small program that runs a piece of your code on an input you chose and checks the result. Its job is not to prove the code correct; it is to let you change the code tomorrow and find out in seconds whether you broke something. Everything below is a way to make that check cheaper, faster, or better at noticing bugs.

The habits that matter most
  • Test behaviour through the public interface, not how the code does it; then tests survive refactoring (section).
  • Prefer real things, then fakes, then mocks; a mock can pass while the code is broken (section).
  • Run the fast tests first and on every change; slow tests on merge or nightly (section).
  • Coverage tells you what never ran, not what is tested; mutation testing tells you whether a bug would be noticed (section).
  • A flaky test is a bug: measure it, quarantine it, fix it or delete it (section).
  • For ML and LLM code, test the code exactly, the data with schemas, and the model statistically; model quality belongs to evals, not unit tests (ML, LLM).
