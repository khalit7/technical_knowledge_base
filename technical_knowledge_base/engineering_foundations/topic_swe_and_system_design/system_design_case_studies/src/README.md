# System design case studies: source

`sh build.sh` writes `../index.html` from `parts/` (same build as the parent root: `{{text|url}}` links, `n:<id>` for Notion, `#t-<tab>` for tabs).

- Reading: `parts/20_read_a.html` (one screen, the method out loud, estimating toolkit) to `20_read_h.html` (one file per design: b URL shortener, c rate limiter, d chat, e feed, f LLM gateway, g RAG, h job scheduler), `20_read_i.html` (how to practise, traps, glossary; closes the tab). About 12,000 words, 60 minutes in full; each design reads alone in 8 to 10.
- JS: `21_js_rd_common.js` (step-animation controller, same as the root's), `22_js_dia.js` (build-up diagram renderer: lanes, nodes appearing by step, red bottleneck and green fix, counters with the naive value struck through; lane-skipping edges routed around boxes), `23_js_est_data.js` (generated), `24_js_est.js` (live estimate tables evaluating the same formula strings as Python), `26_js_designs.js` (the seven diagram specs, mounting, measured-result rendering), `31_js_drill.js` (Design drill), `99_js_tabs.js`.
- Estimates: `est_spec.json` holds every input (sourced or labelled illustrative) and every row as an expression. `python3 recompute.py` evaluates them, asserts the shared constants equal the root's `src/num/num_data.json`, runs 25 checks against published figures and arithmetic, writes `recompute_out.json` and `parts/23_js_est_data.js`.
- Measurement: `lab/measure_pg.py` (PostgreSQL 16.2 from the pgserver wheel, psycopg; about 2 minutes) -> `inputs/pg_measured.json`. Run from a scratch directory: `uv run --no-project --python 3.12 --with pgserver --with 'psycopg[binary]' python lab/measure_pg.py out.json`. Redis was not installed, so the rate-limiter race was measured on PostgreSQL (the page says so).
- Research: `inputs/research_a.json` (shortener, rate limiter), `research_b.json` (chat, feed), `research_c.json` (gateway, RAG, scheduler, notifications): verbatim quotes with URL, date and status, fetched 2026-10-04; `inputs/bitly_headers.txt` (a live `curl -I`).
- Checks: from the repo root, `node <this folder>/check_page.mjs [shots dir]` clicks every diagram step, every estimate button and an edited input, every drill prompt and reveal, at 390 dark and 920 light, fails on errors, NaN, undefined or sideways scroll, and compares `EST.evaluate` with `EST_EXPECT` (recompute.py) for every row.
- Shape: Part B of the topic method, departing where the content is a set of cases rather than one mechanism: the Reading tab is one template repeated seven times, so each design is self-contained; the standalone visual is a practice tool (the drill) rather than a lab, because the page's job is applying the siblings' techniques, which already have their labs.
