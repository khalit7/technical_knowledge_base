# System design case studies: source

`sh build.sh` writes `../index.html` from `parts/` (same build as the parent root: `{{text|url}}` links, `n:<id>` for Notion, `#t-<tab>` for tabs).

- Reading: `parts/20_read_a.html` (styles, the idea in one screen: core sentence, hero, you need, new terms, the one-screen table; the method out loud; estimating toolkit) to `20_read_h.html` (one file per design: b URL shortener, c rate limiter, d chat, e feed, f LLM gateway, g RAG, h job scheduler), `20_read_i.html` (how to practise, traps, glossary in a closed block; closes the tab). Each design: framing, requirements, live estimate, what the numbers say, the 3D build-up with its step list, the decisions that matter (core); API and data model, further deep dives, real companies, failure modes and interviewer notes (closed blocks).
- CSS: `02_split.html` (explainer-page template, unchanged; `build.sh` cats it after `01_head.html`); page additions (`.sc-pin`, `.sc-leg`, step tags) at the end of `20_read_a.html`'s style block.
- JS: `21_js_rd_common.js` (the explainer-page skill template, unchanged), `21_js_rd_fmt.js` (adds `RD.fmt`, which the template lacks), `23_js_est_data.js` (generated), `24_js_est.js` (live estimate tables evaluating the same formula strings as Python), `25_js_s3.js` (3D renderer v2, template, unchanged), `26_js_designs.js` (the seven build-up specs: lanes, parts, edges, the bottleneck at each step, counters; estimate mounting; measured-result rendering), `27_js_hero.js` (the hero), `31_js_drill.js` (Design drill), `33_js_sc_arch.js` (the shared 3D architecture stage, `window.ARCH`), `34_js_sc_designs.js` (each design's kinds of parts, camera and layer of numbers), `99_js_tabs.js` (skill template, storage key `sdcs-tab`).
- Estimates: `est_spec.json` holds every input (sourced or labelled illustrative) and every row as an expression. `python3 recompute.py` evaluates them, asserts the shared constants equal the root's `src/num/num_data.json`, runs 25 checks against published figures and arithmetic, writes `recompute_out.json` and `parts/23_js_est_data.js`.
- Measurement: `lab/measure_pg.py` (PostgreSQL 16.2 from the pgserver wheel, psycopg; about 2 minutes) -> `inputs/pg_measured.json`. Run from a scratch directory: `uv run --no-project --python 3.12 --with pgserver --with 'psycopg[binary]' python lab/measure_pg.py out.json`. Redis was not installed, so the rate-limiter race was measured on PostgreSQL (the page says so).
- Research: `inputs/research_a.json` (shortener, rate limiter), `research_b.json` (chat, feed), `research_c.json` (gateway, RAG, scheduler, notifications): verbatim quotes with URL, date and status, fetched 2026-10-04; `inputs/bitly_headers.txt` (a live `curl -I`).
- Checks: from the repo root, `node <this folder>/check_stages.mjs [shots dir]` (the 2026-11-07 section below) and `node <this folder>/check_page.mjs [shots dir]`, which clicks every stage step, every estimate button and an edited input, every drill prompt and reveal, at 390 dark and 920 light, fails on errors, NaN, undefined or sideways scroll (with reduced motion) and compares `EST.evaluate` with `EST_EXPECT` (recompute.py) for every row.
- Shape: Part B of the topic method, departing where the content is a set of cases rather than one mechanism: the Reading tab is one template repeated seven times, so each design is self-contained; the standalone visual is a practice tool (the drill) rather than a lab, because the page's job is applying the siblings' techniques, which already have their labs.

## The 2026-10-24 rebuild to the teaching contract
- **Top:** the core idea in one sentence (every design is the same seven steps; what differs is which number binds), a new static hero (`27_js_hero.js`: the steps to scale with the drill clock's minutes, and the binding number of each design grouped by constraint kind), "You need" (the root's Step 6 and Numbers, and the five sibling owners of the building blocks), five new terms; the one-screen table kept as the index. The old "what every design has in common" box and the reading-time note were cut (the hero and header carry them).
- **Each design keeps its core inline:** requirements, the live estimate, what the numbers say, the step diagram, and the decisions that matter, condensed to the choice and its reason. API and data model, the secondary deep dives (301 against 302, cache-aside, when to split; limiter placement and hot keys; ranking; the vector index; time zones), every "what real companies built" block with its quotes, the failure tables and "what interviewers listen for" moved into closed blocks, verbatim. Long quotes in core (Stripe's fail-open rule, the INCR leak warning, Google cron's reasoning) moved next to their source in the closed blocks, the claim staying in core.
- **Visuals:** hero added; the feed measurement is now bars (before/after on the same graph, each pair on its own linear scale) with the table closed; the seven step diagrams stay inline and no longer start playing on first scroll (skill `RD.anim`).
- **Glossary** moved into a closed block: every term is defined at first use, and the hero's "New terms" lists only this page's own.
- **Kept as a tab:** the Design drill, a practice tool across all designs (the page owns the interview method), not the explanation of one mechanism.
- **Ownership:** building blocks stay linked, not taught: partitioning and leases (distributed systems fundamentals), delivery semantics (queues), retries, breakers and limiter algorithms (reliability), Little's law and caching (capacity planning), the gateway's mechanisms (gateways and routing), retrieval and its evaluation (the RAG topic and RAG evaluation).

## Length judgement
| | Before (audit 2026-10-23) | After (2026-10-24) |
|---|---|---|
| Reading, core (230 words a minute, `html_utils/audit_pages.mjs`) | 59.2 min | 32.4 min |
| Reading, closed details | 3.6 min | 27.8 min |
| Design drill, Further reading | 1.0, 3.2 min | 1.0, 3.2 min |
| Visuals drawn in Reading | 7 | 9 |

Why 32 minutes is right: the page owns the act of combining the siblings' building blocks, which can only be shown on whole designs, and seven designs each cost about 3.5 core minutes (requirements, estimate, interpretation, a stepper, the decisions); about a third of those words are the estimate tables, requirements boxes and diagram captions that the method itself consists of. No case was cut: each exercises a different binding constraint (storage, connections, coordination, fan-out, money, memory, a burst), which the hero makes visible; cutting one would remove that constraint from the page. Everything a first read does not need (APIs, schemas, sources quoted at length, failure tables, rehearsal checklists) is closed and optional.
