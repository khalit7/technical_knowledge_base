# Concurrency: threads, locks, futexes, deadlock, and event-driven I/O

Notion: https://app.notion.com/p/3f05c17b0d0d8112ad1af99308fa913f (child of Topic: operating-systems)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Threads and what `clone` shares, races, atomic instructions and memory order (Peterson's lock failing on arm64), spin, yield and sleeping locks measured seven ways, the futex in depth (glibc's 0/1/2 protocol, the kernel's compare-and-sleep, private and shared keys, wake-up costs), condition variables (Mesa semantics, measured), semaphores, reader-writer locks, barriers, deadlock and the other concurrency bugs, lock-free basics, the GIL as an OS lock (convoy latency measured), select/poll/epoll/io_uring (costs measured, edge vs level, io_uring on 5.10 in a container), how asyncio, libuv and tokio are built on them, and the training job's threads (gdb and py-spy) plus NCCL and PyTorch's threads from source. Tabs: Reading, Interleaving lab (be the scheduler: futex mutex, lost wake-up, condition variables; every schedule counted and checked against Python), Event loop lab (eight connections through five designs; measured costs scaled up), Further reading. New page; no child pages, databases or video.
Real runs: Docker Desktop's Linux VM on an Apple M1 Pro (5.10.104-linuxkit, arm64, 5 CPUs), 2026-10-05, image `kb-os-conc:1` (`src/runs/Dockerfile`: kb-os-lab:1 plus liburing). Not privileged; `--cap-add SYS_PTRACE` for strace, py-spy and gdb; `--ulimit memlock=-1` for io_uring.
