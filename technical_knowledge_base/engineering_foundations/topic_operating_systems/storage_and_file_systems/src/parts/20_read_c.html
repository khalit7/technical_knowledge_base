2. Files, names and inodes: the VFS and ext4's layout

Programs want named files with sizes, owners and times, and they want the same open, read, write to work on ext4, XFS, tmpfs, NFS or /proc. The VFS (virtual file system switch) gives every file system one set of objects and calls to implement ({{kernel docs: VFS|https://docs.kernel.org/filesystems/vfs.html}}). Below, mke2fs built a 64 MiB ext4 file system inside an ordinary file and debugfs (which reads the image directly, so no mount and no privileges) copied in a 3,000,000-byte "checkpoint" and a small file with two names measured. The figure is that real image seen through the kernel's objects.

A name points at an inode; the inode, not the name, is the file

Inode numbers, link counts and the extent are copied from the debugfs output (in the closed block below). struct file, struct dentry and struct inode are the kernel's objects (include/linux/fs.h lines 916 and 610, include/linux/dcache.h line 89, v5.10).

Four objects. The superblock, one per mounted file system: its type, block size, and the operations on its inodes (struct super_block, fs.h line 1416). The inode, one per file whatever its names: type, permissions, owner, size, times, link count, where its data lives, and an address_space (line 451) holding that file's pages in the page cache. The dentry, one per name in a path, cached: "the name ckpt.pt in directory X is inode 13"; a negative dentry caches "this name does not exist". The file, one per open(): offset, open flags, pointers to dentry and inode; file descriptors index a per-process table of these ({{Processes and the system-call API|n:3f05c17b0d0d811e99f7cb8c15d12697}} section 7 draws the three tables).

Names are not files. A directory is itself a file whose content is a table of (name, inode number). A hard link is a second entry for the same inode (hello.txt and hardlink.txt are both inode 14, Links: 2); a symbolic link is a small file containing a path. The inode is freed when its link count is zero and no process has it open, so deleting a checkpoint that a running process still holds open frees no space until it closes; lsof +L1 lists such deleted-but-open files.

Extents. Inode 13's data is one extent: logical blocks 0 to 732 stored in physical blocks 2066 to 2798, contiguous. That is 733 blocks of 4,096 bytes, the fewest that hold 3,000,000 bytes (3,000,000 / 4,096 = 732.4), and Blockcount: 5864 counts the same space in 512-byte sectors (733 x 8). ext2 and ext3 listed every block number; an extent says "start, length" once, so a large file costs ext4 almost no metadata. ext4 also groups inodes and their data into block groups so a file's inode sits near its data (OSTEP ch. 41 credits the idea to FFS). The journal (section 7) is itself an inode, 4 MiB here.

What metadata costs: the same 40 MiB as 10,240 files or one

Orange: 10,240 files of 4 KiB; blue: one file of 40 MiB, on ext4 measured. Creating the small files took 7.2x as long, reading them warm 10.6x, cold 56x. Cold means each file's pages were dropped with posix_fadvise(DONTNEED) after an fsync.

Every small file pays for a path lookup, an inode, a directory entry, a share of a journal transaction and its own block allocation; every cold read of one is at least one device request that readahead (section 3) cannot merge with its neighbours. On a network file system each open and stat is also a round trip to a server (section 9), so the gap grows from tens to thousands of times.

The debugfs output, path lookup, and the commands (depth)


Read it from the bottom up: the directory out is a table (ckpt.pt is inode 13; hello.txt and hardlink.txt are inode 14), inode 13's EXTENTS line is the extent, and the journal is an inode of its own.


Path lookup. open("/data/out/ckpt.pt") walks the path one component at a time, looking each name up in the dentry cache and asking the file system only on a miss (fs/namei.c). The root's Syscall tracer shows import torch making hundreds of newfstatat calls that fail with ENOENT: Python searching its path. Each failure leaves a negative dentry, so the second import is cheap.
