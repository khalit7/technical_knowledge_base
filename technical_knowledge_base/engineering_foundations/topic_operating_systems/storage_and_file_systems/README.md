# Storage and file systems: the page cache, fsync, journaling, and checkpoints

Notion: https://app.notion.com/p/3f05c17b0d0d8141be7acc1313570cbf (child of Topic: operating-systems)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). Devices (HDD, flash and the FTL, NVMe queues, device caches, FLUSH and FUA), the block layer (bios, blk-mq, schedulers, queue depth with Little's law), the VFS (superblock, inode, dentry, file; a real ext4 inode and extent tree read with debugfs; metadata cost of small files), the read path and readahead (window sizes measured and reproduced from mm/readahead.c), dirty pages and writeback (thresholds, throttling, cgroup writeback domains, measured timelines), fsync, fdatasync, O_DSYNC and sync_file_range (inside ext4_sync_file; costs measured; errseq_t), atomic replace (rename, directory fsync, O_TMPFILE, ALICE, auto_da_alloc), jbd2 and ext4's data modes, XFS and copy-on-write file systems, O_DIRECT and io_uring, NFS, Lustre, object stores, FUSE mounts and GPUDirect Storage, and ML checkpoints (torch.save, torch.distributed.checkpoint read from source at v2.14.1, async_save) and data loading; measured on Docker Desktop's Linux 5.10 VM, kernel source quoted at v5.10 with line numbers. Tabs: Reading, Crash lab (seven checkpoint write protocols from real traces, crashed at every point under POSIX-only and ext4 models), Further reading. A new page: no old text, child pages, databases or video.
