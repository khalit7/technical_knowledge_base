# Processes and the system-call API: fork, exec, signals, file descriptors

Notion: https://app.notion.com/p/3f05c17b0d0d811e99f7cb8c15d12697 (child of Topic: operating-systems)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). The process as the kernel sees it (task_struct, PID and TGID, states, the running job's /proc), the system-call mechanism (arm64 and x86-64 ABIs, glibc's real `read` wrapper, kernel entry, errno, EINTR, the cost of a crossing and of strace), fork, vfork, clone and posix_spawn with measured costs against parent size (including NumPy's huge pages), what exec keeps, exit, wait, zombies, orphans, subreapers and PID 1, signals in depth (pending and delivery, coalescing, masks, async-signal safety, Python's deferred handlers with measured latency, decoded masks), the three descriptor tables, pipes, close-on-exec, descriptors passed between processes, process groups and sessions, rlimits and credentials, and the training job: start methods by Python version, the DataLoader worker lifecycle, torchrun's shutdown, graceful preemption on Kubernetes and Slurm. Tabs: Reading, Process lab (descriptor-table stepper and process-tree simulator checked against OSTEP's fork.py), Shutdown lab (ten real ways of starting the job and what docker stop did), Further reading. New page (2026-10-05); no child pages, databases or video.
