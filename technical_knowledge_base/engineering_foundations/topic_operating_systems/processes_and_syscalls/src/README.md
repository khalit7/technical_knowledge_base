# Processes and the system-call API: sources and how to rebuild

`sh build.sh` writes `../index.html` from `parts/`. `sh run_all.sh` re-records every measurement (Docker, image `kb-os-lab:1`, about 15 minutes), rebuilds the data and the page, and runs the checks.

## Shape
A child page of Topic: operating-systems (method: `html_utils/methods/topic_pages.md`, Part B). Reading follows the subject's own order (the process, system calls, creation, exec, ending and PID 1, signals, descriptors, groups and limits, the training job, mistakes and questions), with the root's training job as the running example. Two standalone tabs: **Process lab** (descriptor-table stepper and process-tree simulator) and **Shutdown lab** (ten real start-up variants). It links the root's Syscall tracer, OS simulators and Debug lab rather than repeating them, and uses the root's numbers where they exist (syscall ladder, start-method timings).

## Parts
- `01_head.html` (shared CSS, copied from the root), `10_header.html`, `20_read_a.html` .. `20_read_k.html` (Reading; `_a` carries the Reading styles), `20_read_z.html` (closes the tab).
- `21_js_rd_common.js` (RD helpers and the step-animation controller, from the root), `22_js_data.js` (generated by `build_data.py`), `23_js_rd_misc.js` (drills, disassembly), `24_js_rd_syscall.js`, `25_js_rd_proc.js`, `26_js_rd_fork.js`, `27_js_rd_signals.js`, `30_js_fdsim.js` (descriptor model and scripts), `31_js_rd_fd.js`, `33_js_lab.js` (lab, including `TREESIM`), `34_js_stop.js`, `99_js_tabs.js`.
- `31_tab_lab.html`, `32_tab_stop.html`, `39_tab_more.html`.

## Measurements (`runs/`)
All in containers named `os-proc-*`, capped with `--cpus` and `--memory`, `--rm` (the Shutdown lab removes its own named containers), on Docker Desktop's linuxkit VM (Linux 5.10.104, arm64, 5 CPUs), 2026-10-05. No privileged containers, no added capabilities.
- `run_c.sh` → `out/c_runs.txt`: E1 `spawn_cost.c`, E2 `sigqueue.c`, E3 `pipes.c`, E4 `fdshare.c`, E5 `cloexec.c`, E6 `lifecycle.c`, E9 `sysc.c` (plain and under strace), Python `os.getppid`, gdb disassembly of glibc `read`. The `== E14` block in `c_runs.txt` is a superseded first version (it exec'd `/bin/sh`, whose startup clears the mask and installs handlers); the page uses `run_exec.sh` → `out/c_exec.txt` (`exec_keep.c` + `showself.c`). `in_container_c.sh` no longer runs E14.
- `run_reparent.sh` → `out/c_reparent.txt`; `run_clones.sh` → `out/clone_flags.txt`; `run_meta.sh` → `out/strace_meta.txt` (strace traced by strace; per-call costs are differences between N = 1000 and 2000).
- `run_py.sh` → `out/py_handler_latency.txt` (`py/handler_latency.py`), `out/py_spawn.txt` (`py/py_spawn.py`).
- `run_proc.sh` → `out/proc_snapshot.txt` (the job's `/proc` while training).
- `run_shutdown.sh` → `out/shutdown/<variant>_<rep>.txt`: the root's `src/trace/job/train.py` (mounted read-only, unchanged) under ten start-up variants, 3 runs each; `py/ignore_term_in_workers.py` is the fix wrapper for variant 10. A first full series (before full logs were kept) was overwritten by this one; its results agreed except that one `--init` group-signal run logged "got signal".
- `inputs/ostep_fork_cases.json`: OSTEP `fork.py` final trees for seeds 1 to 12 (default, -R, -L), made by `inputs/ostep_fork_gen.py` from the homework repository (fork.py itself not copied).
- Kernel source cited at tag v6.12 (the root page's pin); glibc 2.36 and CPython 3.11.2 sources at their tags; torch 2.14.1 read inside the image.
