Ten ways to start the same training job in a container, and what docker stop did to each. docker stop -t 10 sends SIGTERM to the container's PID 1, waits 10 s, then sends SIGKILL: the same sequence as a Kubernetes pod deletion or a Slurm cancellation, with a shorter grace period.

The job is the root's running example (src/trace/job/train.py: SIGTERM handler that sets a flag, checkpoint after the step, exit 0) with 2 fork DataLoader workers, 2 CPUs, in kb-os-lab:1 (Debian 12: dash 0.5.12 as sh, bash 5.2.15; Docker 20.10.17, whose --init is tini). Each variant ran 3 times, 2026-10-05: started, waited for training step 5, recorded the process tree with ps, then timed docker stop and read the exit code and the log. Script: src/runs/run_shutdown.sh; raw records: src/runs/out/shutdown/.

What the ten runs teach

  • Whether your process is PID 1 decides everything. Same image, same script: the exec form, sh -c "exec ...", and bash -c (bash replaces itself with a single simple command) made Python PID 1 and stopped cleanly in under a second; plain sh -c left dash as PID 1, which neither forwards SIGTERM nor dies from it (section 5 of the Reading tab), so every run waited out the 10 s and was killed.
  • An init process is not a fix by itself. --init forwards the signal to its one child. When that child is a shell, the shell dies at once (it is not PID 1, so the default action applies), tini exits with the shell's status 143, and the kernel kills everything left in the namespace: no checkpoint, in a third of a second. Signalling the whole group (TINI_KILL_PROCESS_GROUP=1) does not help, because the shell still dies first. With Python as tini's direct child, everything works, and orphans are reaped too.
  • torchrun signals process groups. Its SIGTERM reaches the DataLoader workers, whose torch-installed handlers kill them; the trainer's SIGCHLD handler then raises before the checkpoint. Ignoring SIGTERM in the workers fixed it in all three runs; torchrun still exits 1 after a death signal by design.
Predict: docker run --init image sh -c "python train.py; echo done", then docker stop. The Python script has a correct SIGTERM handler. Checkpoint written?
