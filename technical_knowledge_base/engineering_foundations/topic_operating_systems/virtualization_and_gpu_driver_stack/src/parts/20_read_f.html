6. Devices without the exits: virtio

36

The problem. An emulated real disk means the guest's normal driver pokes device registers, and every poke exits to the hypervisor: several exits per 4 KiB read, plus an emulated interrupt with its own exits (section 5).

How virtio works. virtio is a device interface made for VMs: guest and hypervisor share a virtqueue in guest memory, in three parts:

Descriptor tableentries of (guest address, length, flags, next): "here is a buffer" (struct vring_desc)
Available ringwritten by the guest: "these descriptor chains are ready for you" (struct vring_avail)
Used ringwritten by the device: "I finished these, this many bytes" (struct vring_used)

A request is three descriptors (header "read sector N", data buffer, status byte). The guest adds them, bumps the available index, and only then kicks the device: one register write, one exit. The device reads the request straight out of guest memory, does the I/O, writes the used ring and injects one interrupt. With the event index feature each side says "notify me only when your index passes N", so a busy queue needs neither a kick per request nor an interrupt per completion.

Reading it. At queue depth 1, every request pays its own kick and its own interrupt, each with its exits; at depth 32, the event index lets one interrupt report about nine completions and the rate nearly quadruples. This is the I/O version of section 5's lesson: in a VM, notifications are the expensive part, and batching is how you buy them back.

The four device paths in more detail (depth)
Device in QEMU (here)The kick exits to QEMU in user space, which does the I/O with ordinary system calls on the disk image.
vhostThe device's data path moves into the host kernel (vhost-net; this kernel builds it as a module, CONFIG_VHOST_NET=m): the kick wakes a kernel thread, no trip to QEMU.
vhost-userThe data path runs in another user-space process polling the rings (DPDK for networks, SPDK for storage): no notifications at all while busy.
vDPA, passthroughThe NIC itself implements virtqueues (vDPA), or the guest gets a real device or a slice of one (sections 7, 8): the hypervisor leaves the data path.
When it bites in ML
  • Small random reads from a virtual disk at queue depth 1 (a dataset of millions of small files read one at a time) pay the notification costs on every file. Shards read sequentially with several outstanding requests do not.
  • The network of a cloud VM is a virtio or vendor paravirtual NIC unless RDMA NICs are passed through: the data path for checkpoints to object storage, not for NCCL on GPU clusters (section 7).
