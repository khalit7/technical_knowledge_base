Reference: the interfaces themselves

The Linux man pages 5 min per page

Maintained by Michael Kerrisk; the exact contract of every system call (section 2) and library function (section 3), with the edge cases. This page quotes fsync(2), rename(2), mmap(2), fork(2), futex(2), epoll(7), proc_pid_maps(5), mallopt(3) and more.Whenever you need the precise promise of one call.

The Linux Programming Interface Kerrisk, No Starch, October 2010; dip in by chapter

The complete, careful book on the Linux and POSIX system-call API: processes, signals, threads, memory mappings, file I/O, sockets. Old but the interfaces it covers have barely changed.After OSTEP, for the real API behind each idea.

The Linux kernel documentation rolling; 10 to 30 min per document

Admin guides for the knobs this page uses: cgroup v2, transparent huge pages, EEVDF, overcommit, vm sysctls.When you change or read one of those files.

Computer Systems: A Programmer's Perspective (CS:APP) Bryant and O'Hallaron, 3rd ed., 2015

The machine underneath the OS from a programmer's side: data representation, assembly, caches, linking, exceptions and processes, virtual memory, system-level I/O.If you want the hardware half that OSTEP assumes (chapters 6, 8 and 9 especially).

Performance and debugging

Systems Performance, 2nd edition Brendan Gregg, Addison-Wesley, 2020

The method and the tools for finding why a Linux system is slow: the USE method, CPU, memory, file system, disk and network chapters, perf and eBPF.The first time a job is slow and you cannot see why.

brendangregg.com free; 10 to 20 min per article

Flame graphs, the Linux performance tools map, eBPF tools, and many short articles on specific measurements.Alongside the book, or instead of it for one tool.

Julia Evans' zines 20 to 30 min each

Illustrated, short, accurate: Bite Size Linux!, Linux debugging tools you'll love, How Containers Work!, So you want to be a wizard.First, as a map of the tools; again before section 8.
