14. In ML: the mechanisms put to work

Each recipe applies a section above; what is new here is the sizing and the alerting.

Datasets: map, do not load

One or a few large files (a NumPy array, Arrow, a packed binary with an index), np.memmap-ed as the running job does: workers share one page-cache copy and pay only faults. Shuffled access to a dataset larger than RAM wants MADV_RANDOM or pread (section 5); replace mapped files by write and rename (SIGBUS).

DataLoader workers: keep the parent lean

Metadata in NumPy or Arrow, gc.freeze() before the iterator forks, USS per worker on the dashboard (sections 7, 13). Spawn or forkserver avoid the sharing at the cost of start-up: the root measured 0.021 s fork against 0.836 s spawn to the first batch.

/dev/shm: size it and count it

Give the container --shm-size (or --ipc=host) of at least workers × prefetch factor × batch bytes, and remember it is charged to the memory limit and survives a killed process (section 12).

Limits: log which one kills you

Log memory.max, memory.events and memory.stat from inside the job; exit code 137 with oom_kill incremented is the cgroup, not your code. Leave headroom for page cache and /dev/shm. If swap is allowed, alert on memory.swap.current: a swapping training job is a stalled one.

NUMA: when some memory is farther away not run here

A server with two CPU sockets has memory attached to each; a CPU reaches its own node's memory faster than the other's (non-uniform memory access). This lab has one node (numactl --hardware reports none). The policies, from {{set_mempolicy(2)|https://man7.org/linux/man-pages/man2/set_mempolicy.2.html}} and {{mbind(2)|https://man7.org/linux/man-pages/man2/mbind.2.html}}:

PolicyWhere pages goUse
MPOL_DEFAULT (local)the node of the CPU that first touches the page ("first touch")the default; why the thread that initialises a buffer decides where it lives
MPOL_BINDonly the given nodesnumactl --membind; strict, can OOM while another node is free
MPOL_PREFERREDthe given node if possiblesoft placement

Automatic NUMA balancing (kernel.numa_balancing) periodically makes pages inaccessible so the next access faults (do_numa_page, the pte_protnone branch in {{handle_pte_fault, line 4380|https://github.com/torvalds/linux/blob/v5.10/mm/memory.c#L4380}}), notes which node touched it, and migrates pages or tasks to match; each migration is a TLB shootdown (section 3) ({{sysctl kernel docs, numa_balancing|https://docs.kernel.org/admin-guide/sysctl/kernel.html#numa-balancing}}). Cgroups restrict nodes with cpuset.mems.

In ML. Each GPU hangs off one socket's PCIe; nvidia-smi topo -m prints each GPU's CPU and NUMA affinity. A data loader and pinned buffers on the other socket send every batch across the inter-socket link. Launch per-GPU processes with matching numactl --cpunodebind=N --membind=N (or the launcher's affinity options).
