Type any virtual address, or pick one of the running job's real addresses (from its /proc/PID/maps, recorded by the root page), and see how the hardware cuts it into page-table indices on five real configurations. Then size the tables and the TLB reach for a given amount of memory. The geometry follows the kernel's own formulas (arm64: (VA_BITS - 4) / (PAGE_SHIFT - 3) levels; x86-64: 4 or 5 levels), quoted in the Reading tab's section 2.

1. One address, cut into indices

Try: the dataset address on arm64 with 4 KiB pages (4 levels, 12 offset bits), then 16 KiB (the top level shrinks to one bit) and 64 KiB (3 levels). Then 0x900000000000 on x86-64 with 4 levels: it is above 247, so it is not canonical and the CPU faults before walking anything, while on arm64 the same number is an ordinary user address.
