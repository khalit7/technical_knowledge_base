11. The CPU budget of a training job: threads, workers, pinning

A training process gets some CPUs (a quota, a cpuset, a node) and every thread it starts spends from them. The defaults are sized for the whole machine, so they overspend whenever the job gets less, and a GPU waiting for its next batch is the symptom. The data pipeline itself is {{Storage and loading at scale|n:3f95c17b0d0d81398782efcb29d950d4}}'s; here is what its threads cost.

What the grid says, quota by quota (depth)

The default (5 threads, sized from the machine) was the worst or near the worst choice at every quota smaller than the machine. With one CPU, workers did not help at all; with two or four, the best was a couple of compute threads plus a couple of workers, about one busy thread per CPU of quota. The best point depends on your decode against your model step; the rule does not.

Recipes

  1. Read the budget, then set every pool: cpu.max[0] / cpu.max[1] (or the cpuset size, or the Kubernetes limit) divided by the training processes on the node; compute threads + busy workers ≈ budget.
  2. Keep workers alive with persistent_workers=True (section 1).
  3. A starving GPU's signature: rising nr_throttled, involuntary switches in the thousands, the main thread waiting on a run queue, or py-spy dump showing it in next(it) (the root's Debug lab case "The training loop waits for data: DataLoader-bound").
  4. Multi-socket GPU nodes: torchrun --numa-binding=node (section 8).
  5. Noisy neighbours: weights help only under contention and in proportion (section 9); exclusive cores are the only real isolation.
  6. Background work yields: nice -n 10 or SCHED_BATCH, SCHED_IDLE for uploads (section 6); never real-time.
# size PyTorch's pools from the container's quota (or affinity), not from os.cpu_count()
import os, math, torch
def cpu_budget():
    n = len(os.sched_getaffinity(0))                    # cpuset / taskset
    try:
        q, p = open("/sys/fs/cgroup/cpu.max").read().split()
        if q != "max": n = min(n, max(1, math.floor(int(q) / int(p))))
    except OSError: pass                              # cgroup v1 or no cgroup
    return n
b = cpu_budget() // int(os.environ.get("LOCAL_WORLD_SIZE", "1"))
torch.set_num_threads(max(1, b // 2)); num_workers = max(0, b - b // 2)

The split between threads and workers in the last line is a starting point, not a rule; measure your own step the way the grid above did.
