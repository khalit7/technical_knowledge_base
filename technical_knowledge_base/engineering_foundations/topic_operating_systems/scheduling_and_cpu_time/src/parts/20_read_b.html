In one screen

A CPU core runs one thread at a time. The scheduler is the kernel code that decides which runnable thread gets each core next and for how long; a context switch is the act of swapping one thread out and another in. On Linux, ordinary threads share CPUs fairly by weight (CFS until kernel 6.5, EEVDF from 6.6), a few classes jump the queue (real-time, deadline), and containers add a second layer on top: a weight that decides how contended CPUs are split between groups, and a quota that stops a group cold when it has used its share of each 100 ms.

The root page, {{Topic: operating-systems|n:3f05c17b0d0d81c5a97ce991644af140}} section 3, gave the intuition, its OS simulators tab runs OSTEP's policies, and its Debug lab measured the two classic training-job failures (a CPU limit and too many threads). This page goes one level down: what the kernel actually does, line by line where it helps (Linux v5.10, the kernel these runs used, and v6.12 for EEVDF), what each step costs on a real kernel, and how it shows up in ML work. Each mechanism follows the same pattern: problem, how it works, what it costs here, when it bites in ML, the command that shows it, the fix.

Five things to remember
  1. A CPU limit is a quota, not fewer CPUs. Threads beyond the quota do not wait politely: the whole container runs flat out and then stops until the next period (section 9).
  2. Nothing inside a container tells PyTorch about the quota. os.cpu_count() and torch.get_num_threads() ignore cpu.max; only CPU affinity (cpuset) is seen. Set thread counts yourself (section 11).
  3. Fair means proportional to weight. Nice levels are weights spaced by 1.25 times; a cgroup's cpu.weight is the same idea one level up (section 4).
  4. A switch is cheap; waking across CPUs and losing caches are not. A switch between two threads on one CPU took about 1.5 us here; in this VM, waking a thread on another, idle CPU took 29 times longer (section 2).
  5. Load average is not CPU use. On Linux it also counts tasks blocked in uninterruptible waits, such as a stuck network file system (section 10).
