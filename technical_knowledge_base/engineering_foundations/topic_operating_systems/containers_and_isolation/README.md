# Containers and isolation: namespaces, cgroups v2, seccomp, sandboxes

Notion: https://app.notion.com/p/3f05c17b0d0d8156a841e4bf28f11293 (child of Topic: operating-systems)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). A container as processes plus restrictions, each built by hand and measured on Docker Desktop's Linux 5.10 VM: the eight namespaces (creation cost of each; nsproxy at v5.10), PID namespaces and PID 1 (the kill rule from kernel/pid_namespace.c, docker stop against seven launch styles, the tini and shell trap and its fixes), mount namespaces, pivot_root, overlayfs copy-up and whiteouts, OCI images, cgroups v2 (no internal processes, delegation, pids, io.max, the freezer), memory.max against memory.high with and without swap, memory.oom.group and Kubernetes' default, PSI from source, capabilities, user namespaces and rootless, seccomp-bpf (a hand-written filter, Docker's 20.10 and 25 profiles, per-call cost, io_uring blocked and charged per UID), LSMs, runtimes (containerd, shim, runc), sandboxes (gVisor, Firecracker, Kata), GPU containers and CDI, and Kubernetes requests and limits mapped to cgroup files. Tabs: Reading, Build a container (a 170-line C runtime run step by step), Pod to cgroup (QoS, cpu.weight under both runc maps, cpu.max, memory.max, oom_score_adj), Further reading. A new page: no old text, child pages, databases or video.
