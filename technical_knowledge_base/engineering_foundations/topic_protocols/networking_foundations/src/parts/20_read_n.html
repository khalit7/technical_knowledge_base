14. Where TCP still matters in a GPU job

An allreduce moves gigabytes between GPUs every step, and kernel TCP copies each byte from the NIC into kernel memory and then into the application, takes interrupts and backs off on any loss. At hundreds of gigabits per second per node that is too slow and too costly, so the heavy traffic uses RDMA (remote direct memory access: one machine's NIC reads and writes another's memory with no kernel stack copying, and with GPUDirect RDMA straight into GPU memory). It runs on InfiniBand, on RoCEv2 (RDMA inside UDP datagrams to port 4791 over routed Ethernet) and on AWS EFA (the SRD protocol). Each fabric in more detail (the port's IANA registration, where reliability lives, SRD's congestion control), how they are built, their topologies and what each collective costs on them are on {{Interconnects and scaling|n:3c65c17b0d0d81808563fd41fb163af0}}, section 4.

TCP is still on the critical path at start-up. NCCL picks NVLink and shared memory inside a server, the IB/RoCE transport across servers, and plain TCP sockets when nothing better exists (NCCL_IB_DISABLE=1 forces that fallback, {{NCCL environment variables|https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html}}). Even on InfiniBand it sets up its connections over TCP sockets first (the same page's "InfiniBand connection bootstrap sockets"), and PyTorch's rendezvous is a TCP store on MASTER_PORT (29500 unless set, {{torchrun source|https://github.com/pytorch/pytorch/blob/main/torch/distributed/run.py}}). When NCCL does fall back to sockets it opens several per peer, because one TCP connection cannot fill a fast NIC (sections 5 and 13): NCCL_SOCKET_NTHREADS helper threads with NCCL_NSOCKS_PERTHREAD sockets each, defaulting on AWS to 2 and 8, so 16 TCP connections for each network connection between two ranks, the product capped at 64 (same page).

When a distributed job hangs at start-up or on its first big collective, the network-layer causes
  1. Wrong interface. NCCL picked docker0, a loopback or a management NIC: NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=INIT,NET prints the choice; set NCCL_SOCKET_IFNAME, and GLOO_SOCKET_IFNAME for Gloo, a separate variable ({{PyTorch distributed docs|https://docs.pytorch.org/docs/stable/distributed.html}}).
  2. Firewall or security group. Only MASTER_PORT has a fixed number; NCCL's reference names no fixed port range for its own sockets, so opening one port between nodes is not enough. A silent hang in init_process_group is usually a dropped SYN (section 3).
  3. MTU mismatch between nodes: small messages pass, the first large one hangs (section 10).
  4. Accept queue or file descriptors at the rendezvous rank with thousands of ranks (section 8).
  5. Not the network at all. One straggler rank (a slow GPU, a data-loading stall) makes every other rank wait inside the collective, which looks exactly like a network hang. Compare per-rank progress and GPU utilisation before blaming the fabric.
