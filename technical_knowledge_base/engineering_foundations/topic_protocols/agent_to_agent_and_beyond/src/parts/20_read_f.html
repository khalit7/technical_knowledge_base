8. Authentication and authorization

Identity lives in HTTP, not in A2A messages: "Identity information is handled at the protocol layer, not within A2A semantics" (section 7). The card declares the schemes ({{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}'s: API keys, HTTP bearer, OAuth 2.0 flows, OpenID Connect, mutual TLS), the client gets a credential out of band and sends it on every request, and the server authenticates every request (sections 7.3, 7.4). Recorded: without a token the SDK client got HTTP 401 Unauthorized with WWW-Authenticate: Bearer realm="eval-agent" and raised A2AClientError: HTTP Error 401. Discovery carried no credential on purpose: a token sent to every URL you fetch is a token you may leak.

The SDK does not authenticate anyone for you
The official Python SDK takes the caller's identity from the web framework (Starlette's request.user) and scopes tasks by its name (resolve_user_scope returns user_name; {{owner_resolver.py|https://github.com/a2aproject/a2a-python/blob/v1.2.2/src/a2a/server/owner_resolver.py}}). With no authentication middleware every caller is the same unauthenticated user, whose name is the empty string ({{auth/user.py|https://github.com/a2aproject/a2a-python/blob/v1.2.2/src/a2a/auth/user.py}}), so all callers share one scope. The lab adds a bearer-token middleware; in production use your gateway or framework, and test that one caller cannot read another's task (the recorded Team C check).

Calling onward: never forward the token. Team A's orchestrator acts for a person; that person's token was issued for Team A's service, and forwarding it to Team B breaks audience binding. Team A instead trades it at the authorization server for a token whose audience is Team B and whose scope is only this call: token exchange ({{RFC 8693|https://www.rfc-editor.org/rfc/rfc8693}}; both ideas with recorded flows on {{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}; MCP states the same rule as "no token passthrough").

In-task authorization: auth-required

When the agent learns mid-task that it needs a permission the caller cannot give in a message ("read access to your bucket", "a human must approve this destructive step": the spec's examples, section 7.6), it moves the task to auth-required and gets the credential out of band, directly, not through the chain of agents. 9. Security: the other agent is not on your side


Whatever comes back from outside your system is untrusted input, and with A2A the outside is a whole agent, run by someone else, whose model read who knows what.
