10. A2A or MCP?

With MCP, Team B exposes its building blocks as tools and Team A's model drives them step by step. With A2A, Team B exposes an agent and Team A hands over the goal. The same evaluation, recorded both ways (both servers on the official SDKs, both clients scripted):

"Characters Team A's model must read": MCP, the tools/list schemas plus every tool result; A2A, the card's skills plus every status message and artifact. Ids and envelopes are not counted on either side.


A2A moved more bytes (every streamed event repeats the ids) yet put less than half as much text in front of Team A's model, text that does not grow with the number of shards, whereas each MCP shard is another round trip and another result in Team A's context. And with MCP Team A had to know Team B's internals (a handle, shard numbers); with A2A it did not, which matters when Team B changes its pipeline next month.




ChooseWhen



MCPyour agent should use capabilities directly (files, a database, an API), the steps are short, your model should plan them, you can see the tools


A2Athe other side is someone else's agent; the work is long, may ask questions or need approvals; you want only the outcome; the other side must stay free to change how it works


Boththe usual case, drawn in the hero: Team B's agent is an A2A server outward and an MCP client inward (the spec's Appendix B)




The overlap is growing. MCP's 2026-07-28 revision added input_required results for multi-round-trip requests and moved its long-running Tasks into an official extension (tasks/get, tasks/update) ({{MCP|n:3c65c17b0d0d813f9695dc4175c44cbb}}). What stays A2A's own: an agent as the unit (skills, not functions), multi-turn contexts, artifacts streamed in chunks, subscribe and push as first-class operations, and opacity as a design goal.

Provenance of the A2A and UCP rows
A2A was announced by Google on 9 April 2025 ({{Google Developers Blog|https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/}}) and became a Linux Foundation project on 23 June 2025 with "more than 100 leading technology companies" ({{Linux Foundation|https://www.linuxfoundation.org/press/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents}}); 0.3.0 followed on 30 July 2025. On 27 August 2026 it "has officially been accepted as a Growth Stage project at the Agentic AI Foundation (AAIF)" ({{A2A blog|https://a2a-protocol.org/latest/blog/}}), the Linux Foundation fund that holds MCP. IBM's Agent Communication Protocol repository reads "ACP is now part of A2A under the Linux Foundation!". AGNTCY's Open Agentic Schema Framework: {{agntcy/oasf|https://github.com/agntcy/oasf}}, pushed 29 Sep 2026; GitHub publishes no archive date for the ACP SDK. UCP's 21 co-developers on ucp.dev (read 5 October 2026) include Google, Shopify, Amazon, Meta, Microsoft, Walmart, Target, Etsy, Stripe and travel and food companies.


Corrected from the old overview
The old Topic: protocols page said AGNTCY "archived its ACP SDK in April 2026"; the repository's last push was 16 June 2025 and GitHub publishes no archive date, so the month is not confirmed. It put A2A at "150+ member organisations"; the only primary figure found is "more than 100" at the June 2025 launch.


Who governs them. The tool protocol and the agent protocol now share one neutral owner, the Agentic AI Foundation (AAIF), a Linux Foundation fund: MCP since December 2025, A2A since August 2026. On 22 October 2026 it took in four more projects: Agent Skills (Anthropic donated the format, its name, GitHub organisation and agentskills.io; {{Anthropic|https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation}}), Open Responses (OpenAI; an open specification for multi-provider LLM interfaces based on its Responses API), OpenEnv (Hugging Face; reinforcement-learning environments as shareable services) and OpenSandbox (Alibaba; a sandbox platform with Docker and Kubernetes runtimes). With AGENTS.md, goose, agentgateway and Agent Router that makes ten projects ({{AAIF announcement|https://aaif.io/news/agentic-ai-foundation-announces-four-new-projects}}). Read as a stack, one foundation now holds a standard for each layer of an agent: how it calls a model (Open Responses), what instructions it loads (Agent Skills, AGENTS.md), how it reaches tools (MCP) and how it delegates to another agent (A2A). The commerce protocols above stay with their own owners.


The practical rule: tool access on MCP, delegation between organisations on A2A, commerce on UCP or ACP depending on which platforms you sell through, and the rest as research unless a partner requires it.
