The idea

A2A lets one agent hand a whole job to another organisation's agent that it cannot see inside: the job becomes a task with an id and eight states that outlives any connection, while MCP stays the way each agent uses its own tools. Commerce, payment and device protocols then add the one thing every irreversible action needs: a protocol state where a person, a signature or a device limit, not text, says yes.

Fig. 1 · Agents talk to tools over MCP, to each other over A2A, to merchants over UCP, pay with AP2 or x402, and drive devices through MHS; orange marks where something outside the model must approve

  1. Team A's agent and its own tools. Team A's orchestrator is an MCP client: it calls its own tools directly, and every schema and result lands in its model's context. MCP is the agent-to-tool link.
  2. A2A to an opaque agent. For the evaluation it hands the whole job to Team B's agent over A2A. What comes back is a task with an id, states and artifacts; Team B's prompts, tools and model stay behind the glass (sections 2 to 7).
  3. A person grants, out of band. When Team B's agent needs access only someone on Team A's side can give, the task waits in auth-required and the grant goes straight to Team B, not through the agents' messages (section 8).
  4. UCP to a merchant. To buy, the agent drives the merchant's checkout; requires_escalation hands the buyer a continue_url to finish on the merchant's own page (section 12).
  5. Paying: AP2 or x402. AP2 carries mandates the user signed on a non-agentic trusted surface; x402 answers a request with HTTP 402 and a price, and the retry carries a signed payment (section 13).
  6. MHS to a lab device. Through MCP, a CLI or code, the agent reads and writes an instrument through a standard driver whose safety limits sit below the model (section 14).
  7. The orange gates. Every irreversible action passes a gate where a person, a signature or a device limit decides, never text from a model (section 15).

The running example

Team A trains a model; Team B owns the evaluation stack. Team A's orchestrator agent asks Team B's eval agent to "evaluate checkpoint step-4000". Team A never sees Team B's tools or prompts, only a task, its states and its results. Both agents are scripted; every message is real SDK output (a2a-sdk 1.2.2, mcp 2.3.0).

New terms on this page (12)
Opaque agent
one whose prompts, tools, memory and model you cannot see; you see only what it says.
Agent Card
the JSON an A2A agent publishes at /.well-known/agent-card.json: skills, endpoints, auth.
Task
A2A's unit of work: server-made id, a state, history, artifacts.
Artifact
a task's output, made of parts, streamable in chunks.
Context
an id grouping tasks into one conversation.
Interrupted state
input-required or auth-required: the task waits for someone.
Binding
one wire format for the same operations: JSON-RPC, gRPC, HTTP+JSON.
Push notification
the agent POSTs task updates to a webhook you registered.
Platform, business
UCP's names for the shopping agent and the merchant.
Mandate
AP2's signed proof of what a user approved.
Trusted surface
non-agentic code that shows the user what they sign.
Facilitator
x402's service that verifies and settles a payment for a server.
