The idea in one screen

Real-time means the server has news before the client knows to ask. Every way of delivering it is a choice of who opens the connection, which way bytes flow and how long it lives; and anything that lives long is cut by something on the path. So choose by direction (SSE when only the server talks, a WebSocket when both do, a webhook when the wait is hours), then design the heartbeat, the reconnect and the cancel.

The running example. The parent topic's chat app asks "What colour is the sky?" with one 117-byte POST /v1/messages; the answer is five tokens (The,  sky,  is,  blue, .) framed by message_start and message_stop: seven events in the shapes of Anthropic's Messages API. A stand-in model (no real model runs) waits 120 ms before the first token, standing in for prefill, then produces one every 50 ms. This page delivers that answer four ways, cuts it, resumes it, cancels it, and sends a webhook when a job ends. Everything marked measured was run on 5 October 2026 on an Apple M1 Pro (macOS, Python 3.13, aiohttp 3.14.3, websockets 17.2, nginx 1.31.6, Chrome 148, Node 22) against local servers, so every byte could be recorded.

You need HTTP requests, responses, headers, status codes and proxies ({{HTTP|n:3c65c17b0d0d811bb035fa3f158b0889}}), and TCP connections ({{Networking foundations|n:3c65c17b0d0d8117b21dcb9041879564}}). This page owns the push layer on top of them.

Server push: data sent when the server has it, not when the client asks.
Polling / long polling: ask on a timer / ask, and the server holds the request until there is news.
Server-Sent Events (SSE): one text/event-stream HTTP response that stays open and carries text events.
EventSource: the browser's built-in SSE client; GET only, reconnects by itself.
Last-Event-ID: the header a reconnecting SSE client sends with the last event id it saw.
WebSocket: an HTTP/1.1 request upgraded (101) into a two-way message channel of frames.
Heartbeat: traffic sent only to keep a quiet connection alive past middlebox idle timeouts.
Webhook: an HTTP POST a provider sends to your URL when an event happens, signed with an HMAC.
Time to first token (TTFT), client side: from sending the request to the first token event arriving.
Backpressure: a slow consumer making the producer wait instead of a queue growing without bound.
