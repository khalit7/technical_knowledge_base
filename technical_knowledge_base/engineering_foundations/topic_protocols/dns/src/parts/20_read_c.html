1. Names, zones and delegation

The problem. Packets go to addresses, but configuration uses names, and the machines behind a name change all the time. One central table of every name could never keep up (until the 1980s every host downloaded one file, HOSTS.TXT; {{RFC 1034 s2.1|https://www.rfc-editor.org/rfc/rfc1034#section-2.1}}). DNS splits the job by ownership: whoever owns a name runs, or rents, the servers that answer for it, and everyone else finds those servers by asking down a tree ({{RFC 1034|https://www.rfc-editor.org/rfc/rfc1034}} and {{RFC 1035|https://www.rfc-editor.org/rfc/rfc1035}}, November 1987, still the core of the protocol).

Names are read right to left. api.anthropic.com. is three labels under the root, the empty label written as the final dot; a label is at most 63 bytes and a name at most 255 ({{RFC 1035 s2.3.4|https://www.rfc-editor.org/rfc/rfc1035#section-2.3.4}}). A name ending in a dot is a fully qualified domain name (FQDN): absolute, never extended. Without the dot, your resolver library may first try to complete it with local suffixes, which is the whole story of section 7.

The same three-level tree in the lab and in the real DNS; each parent holds only the NS records (and glue) that hand the next zone down

Static diagram. Each shaded box is a zone, the part of the tree one set of servers answers for; each arrow is a delegation, NS records in the parent naming the child's servers, plus glue (their addresses) when those servers live inside the child, without which nobody could reach them. Left: the lab's zone files as served (measured). Right: the real tree; the com. line is copied from the root zone file InterNIC publishes ({{root.zone|https://www.internic.net/domain/root.zone}}, serial 2026100500), which delegates 1,437 top-level domains (measured: distinct names with NS records in that file); the anthropic.com lines are the root page's recorded lookups.

The servers that hold a zone's records are its authoritative servers. At the top are 13 root server identities, a to m.root-servers.net, run by 12 organisations; on 5 October 2026 they were served by 2,045 machines, each identity answering from many places on one address through anycast (one IP address announced from many sites; routing delivers to the nearest) ({{root-servers.org|https://root-servers.org/}}).

What delegation costs. A delegation is cached for as long as the parent says: 172,800 seconds (48 hours) for com. in the root zone file, and the same for the delegations inside .com, so moving a domain to new name servers can take two days to reach every cache. And every name under a zone depends on that zone's servers and the chain above them: when one record or one signature high up breaks, everything below it breaks at once (section 11).

The number 13 is a fossil: in the early 1990s the list of root servers had to fit in one 512-byte UDP answer, and renaming them all under root-servers.net let compression squeeze 13 into it ({{RSSAC023 s2.6|https://www.icann.org/en/system/files/files/rssac-023-04nov16-en.pdf}}).
