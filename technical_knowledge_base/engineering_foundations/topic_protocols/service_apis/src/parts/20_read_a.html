The idea in one screen

A service API is a contract for a call that can fail halfway. REST, gRPC and GraphQL write that contract down and put it on the wire differently, but every good API answers the same questions: what may be sent, how long the caller waits, what each failure means, whether a retry is safe, and which copy of the service answers.

Fig. 1 · One LLM request crosses three API styles before a token comes back

  1. Four parties, one request. Your app (curl, an SDK, a browser), the API front door (auth, rate limits, idempotency, translation), a router that picks a replica for each call, and three copies of the inference server. The running example is the root page's request, POST /v1/messages with "What colour is the sky?".
  2. Outside the front door: REST with SSE (sections 2 to 7), because anyone with curl must be able to call it. The body is 117 bytes of JSON; the root's HTTP/1.1 recording sent a 277-byte request and got 771 bytes of SSE payload for five tokens. Versions, errors, pagination, the OpenAPI contract, the Idempotency-Key, 429 and rate-limit headers and the provider's format all live on this hop.
  3. Inside: gRPC (sections 8 to 12), because both ends are yours and the calls are many, typed and streaming. The same request is 49 bytes of protobuf behind a 5-byte prefix on one HTTP/2 stream; a deadline that shrinks each hop rides in grpc-timeout, and the status comes last, in the trailers.
  4. Who answers (sections 12 and 13). The router reads each call and picks a replica: measured, 30 calls through an L7 balancer landed 10 / 10 / 10. An L4 balancer chooses once per connection and pinned all 30 to one replica.
  5. Later, the front door calls you (section 6). When a batch ends, it POSTs a signed event to a URL your app registered: a webhook, the same API problems with the roles swapped.
  6. Other faces of the same services (sections 14 to 16): gRPC-Web and Connect for browsers, GraphQL for many front ends that each name the fields they want, JSON-RPC for MCP and A2A, where a model or an agent is the caller.

You need: HTTP methods, status codes and HTTP/2 streams ({{HTTP|n:3c65c17b0d0d811bb035fa3f158b0889}}, sections 2 and 6), and what an SSE stream is ({{Streaming and real-time|n:3c65c17b0d0d812daa9fdb38719fc82b}}). Credentials on these calls are {{Auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}'s; MCP's own use of JSON-RPC is {{MCP|n:3c65c17b0d0d813f9695dc4175c44cbb}}'s.

New terms

Idempotent: doing it twice has the same effect as once.
Idempotency key: a client-chosen id that makes one POST safe to retry.
Cursor: an opaque token meaning "the rows after the last one you saw".
Schema or IDL: a machine-readable description of messages and operations (OpenAPI, .proto, GraphQL SDL).
Webhook: your server POSTs to a URL the client registered when an event happens.
Field number: the integer that names a protobuf field on the wire; names never travel.
Deadline: the moment after which the caller no longer wants the answer; gRPC passes what is left to each hop.
Trailers: header fields sent after the body; gRPC puts its result there.
Channel: a gRPC client's long-lived handle on a target: names, connections, calls.
L4 / L7 balancer: chooses a replica once per TCP connection / once per call.
Resolver: the GraphQL function that produces one field's value.
Replica: one running copy of a service.

1. What an API style decides

Two programs written by different teams must agree on what a request contains, how it becomes bytes, how the bytes travel, what shape a call has, and how it fails. An API style is a bundle of answers. Put the four styles you will meet side by side on those questions:

RPC (remote procedure call) makes a call on another machine look like a local one, stub.Generate(request): a generated stub turns it into bytes, a server-side servicer you fill in answers it. Its old trap is that a network call can be slow, half-done or lost in ways a local call never is, which is why sections 4, 10 and 11 exist. REST takes the other road: named things (resources) and a fixed set of verbs whose meaning (safe, idempotent, cacheable) every proxy already knows.
