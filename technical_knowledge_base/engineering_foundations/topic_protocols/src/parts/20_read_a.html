The idea

A protocol is an agreement about bytes, and one LLM request crosses about eight of them, stacked so that each solves one problem, costs round trips or guarantees, and fails in its own recognisable way.

One running example. A user types "What colour is the sky?" and the app sends one streaming request to an LLM API: a POST /v1/messages with a 117-byte JSON body, answered by five tokens streamed back one by one. To record every byte, the request goes to a local stand-in for an LLM API that answers in the event format of Anthropic's Messages API, trimmed (the {{On the wire|#t-wire}} tab built it, 5 October 2026, Apple M1 Pro, Python 3.13.16 with OpenSSL 3.5.9, curl 8.7.1). Step through its journey; each step names the page that owns it.

The whole path. Before the first token can arrive, the client pays for a name lookup (cached, or one round trip to a resolver), a TCP connection (one round trip), a TLS 1.3 handshake (one round trip) and the request itself (one round trip): about four round trips before the server even starts, which is why clients reuse connections and why HTTP/3 merges the TCP and TLS round trips. Press play or step.

DNS turns api.anthropic.com into 160.79.104.10. Free when cached (2.4 ms inside curl), one round trip to a resolver when not (212 to 451 ms for an uncached name, measured in the On the wire tab). Caching is DNS's whole failure surface: a "does not exist" answer is cached too, and nothing can push a change.

Owner: {{DNS: resolution, caching and the failure modes|n:3c65c17b0d0d812387d8f92b546f07af}}.

TCP opens a reliable, ordered byte stream with SYN, SYN-ACK, ACK: one round trip before the request can leave. IP underneath only does best effort; every guarantee is added above it. A silent drop (a firewall), a reset (nothing listening) and a connection a NAT forgot while idle are the three ways this step fails.

Owner: {{Networking foundations: IP, TCP, UDP and QUIC|n:3c65c17b0d0d8117b21dcb9041879564}}.

TLS 1.3 proves the server is who it claims and encrypts everything after. One more round trip and about 3.5 KB of handshake on this request (measured); the client offered a hybrid post-quantum key share and the server took it. A certificate the client cannot verify stops the request here.

Owner: {{TLS and certificates: the handshake, PKI, mTLS and post-quantum|n:3c65c17b0d0d8105a37ff2d2f602a421}}.

HTTP carries the meaning: method, path, headers, status code. Over HTTP/1.1 the request is 277 bytes of text, one TLS record of 299 bytes on the wire; over HTTP/2 the same request is a compressed HEADERS frame and a DATA frame on stream 1. Every proxy on the path has its own timeouts, and the smallest one wins.

Owner: {{HTTP: semantics, 1.1 vs 2 vs 3, proxies and timeouts for LLM APIs|n:3c65c17b0d0d811bb035fa3f158b0889}}.

The API decides whether this caller may do this. The request carries x-api-key; a 401 means the credential did not prove who you are, a 403 that it did and you are not allowed. Users and agents get scoped, short-lived OAuth tokens instead of keys.

Owner: {{Auth: API keys, OAuth 2.1, OIDC, JWTs, mTLS and agent-era auth|n:3c65c17b0d0d817692dcc8ebd59b5c2b}}.

Behind the front door the API calls its own services (rate limiting, a router, the inference servers), typically over gRPC with a deadline on every call, so that all of them give up together when the user leaves. A balancer that pins long-lived HTTP/2 connections sends one client's traffic to one replica.

Owner: {{Service APIs: REST, gRPC, GraphQL and load balancing|n:3c65c17b0d0d81cb88a3f1f63e85f27b}}.

The answer streams back as Server-Sent Events inside one HTTP response that does not end until the last token: status 200 first, then one event per token. On the wire each token was one TLS record of 146 to 148 bytes, about 51 ms apart. An error after the 200 can only arrive as an event, and a buffering proxy turns the stream into one burst.

Owner: {{Streaming and real-time: SSE, WebSockets, webhooks, long polling|n:3c65c17b0d0d812daa9fdb38719fc82b}}.

If the model asks for a tool, the host calls an MCP server (a JSON-RPC tools/call); to hand a whole task to someone else's agent it opens an A2A task. Either way the result comes back as text the model reads, so a tool's output is untrusted input.

Owners: {{MCP: building servers and clients, transports, auth and security|n:3c65c17b0d0d813f9695dc4175c44cbb}} and {{Agent-to-agent and beyond: A2A, agent commerce, agents driving devices|n:3f05c17b0d0d81199373d4d0b18706d8}}.

The one idea to keep

Every protocol trades round trips (waiting for the other side) against guarantees (order, delivery, privacy, identity). Most "slow" or "stuck" bugs are a round trip or a guarantee you did not know you were paying for.

A problem shows in another layer

No layer reads the others' headers, so a problem is visible only to the layer that owns it: a bad certificate is invisible to TCP, and a TCP stall is invisible to your JSON parser, which just sees a read that never returns. Section 11 maps symptoms to layers.

Agents add one new risk

MCP made tools pluggable, and with them every tool's output became text the model reads as if it were instructions (section 10).

New terms (the Glossary at the end of this tab has the rest):

  • Round trip (RTT): the time for a message to reach the other side and a reply to come back. About 0.1 ms on one machine, 1 ms in a data centre, 80 to 150 ms across an ocean.
  • Handshake: messages exchanged before useful data can flow, to agree on parameters. Each costs at least one round trip.
  • Header and payload: the few bytes of addressing and control a layer puts in front of the data it carries, and that data.
  • Stream: an ordered sequence of bytes or messages inside a connection; HTTP/2 and QUIC carry many in one connection.
  • Head-of-line blocking: one slow or lost item holding up everything queued behind it.
  • Bearer credential: a secret that works for whoever presents it, like cash (API keys, most access tokens).
