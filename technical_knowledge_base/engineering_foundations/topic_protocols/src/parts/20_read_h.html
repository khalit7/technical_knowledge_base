10. Agent protocols: MCP, A2A, and the trust boundary

A model on its own only produces text. Before 2024 every app wired every tool by hand, so N apps and M tools meant N × M integrations; agent protocols make it N + M: a tool or an agent is written once against a standard and any host can use it. Both main protocols speak JSON-RPC 2.0 (section 8), over HTTP with SSE for streaming (sections 6 and 7) and OAuth for remote callers (section 9): they are a new layer on the old stack, not a new stack.

MCP's current revision is 2026-07-28, which made the protocol stateless; A2A 1.0.0 is from March 2026. Both are governed by the Agentic AI Foundation under the Linux Foundation. The other agent protocols, with their dates and status, are on {{Agent-to-agent and beyond|n:3f05c17b0d0d81199373d4d0b18706d8}} (section 11), the one dated table of the topic.

The trust boundary: tool output is untrusted input. Whatever a tool returns enters the model's context next to the user's request, and the model cannot tell from the text alone which words came from the user and which from a stranger's web page. Instructions hidden in a tool result are indirect prompt injection, and no protocol can prevent it: it is what any tool that returns outside text does. It becomes data theft when private data, untrusted content and a way to send data out meet in one agent, which Simon Willison called the lethal trifecta ({{16 June 2025|https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/}}); remove any one leg and the attack has nowhere to go. When the tool moves money or a robot arm, an injected instruction is no longer a leak but an irreversible action, so limits must live below the model: in scopes, in device-level limits, in a human approval the conversation cannot fake.
