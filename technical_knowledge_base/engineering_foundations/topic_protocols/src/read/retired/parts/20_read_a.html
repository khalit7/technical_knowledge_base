Protocols in one screen

About 40 minutes for the prose; the tables, recorded outputs and animations are there to skim or skip. It starts from zero: every term is explained where it first appears and collected in the Glossary. Each section can be read on its own. Every exchange shown here was run for this page on 5 October 2026 (an Apple M1 Pro laptop, macOS 27, Python 3.13.16 with OpenSSL 3.5.9, curl 8.7.1) or is quoted from its specification with the section number. Numbers marked measured come from those runs; illustrative marks a picture that shows a shape rather than data; derived numbers show their formula.

A protocol is an agreement about bytes: who sends what, in what order, and what each side may then assume. Your chat app and an LLM API have never met, run different code on different machines, and talk across networks neither controls. They still understand each other because both follow the same dozen agreements, stacked so that each one solves a single problem and trusts the one below it to have solved the rest.

One running example. A user types "What colour is the sky?" and the app sends one streaming request to an LLM API. This page follows those bytes. To record every byte, the request goes to a local stand-in for an LLM API (the {{On the wire|#t-wire}} tab built it; it answers in the event format of Anthropic's Messages API, trimmed): a POST /v1/messages with a 117-byte JSON body, answered by five tokens streamed back one by one. The same request is the subject of every tab.

The one idea to keep

Every protocol trades round trips (waiting for the other side) against guarantees (order, delivery, privacy, identity). Most "slow" or "stuck" bugs are a round trip or a guarantee you did not know you were paying for.

Where things break

A missing or stale name (DNS), a connection that never opens or silently dies (TCP, firewalls, idle timeouts), a certificate the client cannot verify (TLS), a proxy that buffers or cuts a stream (HTTP), a token sent to the wrong place (auth). Section 10 maps symptoms to layers.

Agents add one new risk

MCP made tools pluggable, and with them every tool's output became text the model reads as if it were instructions. Section 9 shows one real tool call carrying a hidden instruction into the model's context.
