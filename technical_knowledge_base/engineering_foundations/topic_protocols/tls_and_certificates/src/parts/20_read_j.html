10. TLS where an ML engineer meets it

  • Handshakes, not bytes, are the cost. Bulk encryption runs at gigabytes per second per core (section 1); one ECDSA P-256 signature, the server's main handshake cost, at about per second per core. A client that builds a new HTTP client per inference call pays a handshake per call; with an LLM API across a continent that is two extra round trips (100 to 200 ms at 50 to 100 ms each) before the request leaves. One pooled client per process.
  • Long streams are what TLS 1.3 was built for. A multi-hour SSE stream or bidirectional gRPC stream stays within the AEAD's safe usage limits through KeyUpdate: either side ratchets its sending key forward, with no new handshake and no pause. RFC 9846 made updating before the limits a MUST and capped how often KeyUpdate may be sent ({{section 5.5|https://www.rfc-editor.org/rfc/rfc9846#section-5.5}}); libraries do it for you.
  • gRPC needs ALPN h2 on every TLS hop. gRPC runs on HTTP/2, and HTTP/2 over TLS is selected only by ALPN. A proxy or load balancer that terminates TLS without offering h2 breaks it: the parent's Failure lab case "ALPN mismatch: gRPC needs h2" shows the error text. On AWS that means an ALB target group with protocol version gRPC. Triton's and vLLM's gRPC endpoints are no exception.
  • Know which hops are encrypted: draw the section 7 figure for your own path, including model server to other GPUs, in your threat model.
  • Cluster frameworks are plaintext by default. Ray's internal gRPC channels have TLS only if you set RAY_USE_TLS=1 with certificates; the default is 0 and the docs warn of a performance cost ({{Ray docs|https://docs.ray.io/en/latest/ray-core/configure.html#tls-authentication}}). vLLM's --api-key protects only the /v1, /v2, /inference and /cohere paths, other endpoints stay open, and its multi-node traffic (PyTorch distributed, KV-cache transfer) is "insecure by default" ({{vLLM security|https://docs.vllm.ai/en/latest/usage/security.html}}). NCCL traffic between GPUs has no TLS. Treat a training or serving cluster as one trust zone on an isolated network, put real authentication and TLS at its edge, and say so explicitly in the threat model.
  • Private CAs for internal names. Internal services, notebooks and clusters should get certificates from a private CA (cert-manager with a private issuer, SPIRE, a cloud private CA), never from a public CA: public certificates publish every host name in CT logs (section 5) and can no longer carry clientAuth for mTLS (section 7).
  • Downloads and supply chain. Model and package downloads (huggingface_hub, pip, docker pull) fail first behind TLS-inspecting proxies (section 9). Fix the trust store; never disable verification for "just the download", because that is exactly where a tampered model file would come in.
