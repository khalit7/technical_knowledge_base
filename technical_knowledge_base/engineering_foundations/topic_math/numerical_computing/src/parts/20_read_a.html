The idea in one screen

A computer stores a real number as a sign, a power of two and a fixed number of binary digits. So it can only hold numbers from a finite grid: the grid is dense near zero and sparse far away, every result is snapped to the nearest grid point, and the grid ends (past it lies infinity). Exponent bits buy range; mantissa bits buy precision. Everything on this page follows from that picture: why \(0.1 + 0.2 \ne 0.3\), why softmax needs the max subtracted, why fp16 training needs loss scaling and bf16 does not, why adding a million numbers in 16 bits returns garbage, and why the same model gives different answers on different runs.

The one idea to keep
Every floating-point result is the true result times \((1 + \delta)\) with \(|\delta|\) at most half the format's epsilon, as long as nothing overflows or underflows. Trouble comes from three places only: leaving the range (overflow to infinity, underflow to zero), subtracting nearly equal numbers (cancellation), and piling up many small errors (long sums). Stable algorithms are rearrangements that avoid all three.

You need: nothing beyond calculus. The running example is the root page's tiny model ({{Topic: math|n:3c65c17b0d0d81cdb851c0835b25a538}}): logits \(z = (2, 1, 0)\) for the words cat, dog and sat, target sat, loss \(2.408\); and the same three words with logits \((1000, 999, 0)\), the case the root's Gradient lab uses for overflow. The condition number of a matrix is {{Linear algebra|n:3c65c17b0d0d81d89c26e1dab2fcb701}}'s; 8- and 4-bit formats for serving, block scaling and FP8 training recipes are {{Quantization and precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}}'s; this page owns the arithmetic underneath them.

ulp
the gap between a float and its neighbour: the value of the last stored bit.
\(\varepsilon\), \(u\)
machine epsilon (the gap above 1) and unit roundoff \(u = \varepsilon/2\), the worst relative error of one rounding.
Subnormal
a number below the smallest normal one, kept with fewer significant bits (gradual underflow).
Cancellation
subtracting nearly equal numbers, which leaves only their earlier rounding errors.
Condition number \(\kappa\)
how much a problem amplifies a relative error in its input, whatever the algorithm.
Log-sum-exp
\(\ln\sum_j e^{z_j}\), computed after subtracting the largest \(z\).
Kahan summation
a running sum plus a second number that carries what each addition lost.
Loss scaling
multiplying the loss by \(S\) so float16 gradients stay above underflow, dividing by \(S\) before the update.
Batch invariance
a kernel whose result for one row does not depend on what else is in the batch.
