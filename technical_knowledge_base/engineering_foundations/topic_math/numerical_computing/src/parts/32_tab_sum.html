Summation lab

Add \(N\) numbers in float16, bfloat16 or float32 with four algorithms and compare each with the exact sum (computed with Shewchuk's exact algorithm, as Python's math.fsum). Every addition is rounded to the chosen format exactly as the hardware would round it. The chart repeats the sum for every \(N\) up to your choice, so you can see each method's error grow (or not). It extends Reading {{section 7|#t-read}}, which shows the same experiment measured in NumPy and PyTorch on a million numbers.

Try: float16, uniform, \(N = 10{,}000\): the naive sum stalls at 2,048 (59% low) while pairwise and Kahan are within one rounding; then big first value: one 10,000 followed by small numbers, where naive loses almost all of them; then mixed signs: the exact sum is small compared with \(\sum|x_i|\), and every method's error bound is relative to \(\sum|x_i|\), not to the answer, so relative errors grow; then press Shuffle 20 orders.
A relative error of exactly 0 is drawn at the bottom edge, an infinite one (overflow) at the top.

The four algorithms
Naive: one running sum, \(s \leftarrow \operatorname{fl}(s + x_i)\); error bound \((N-1)u\sum|x_i|\). Pairwise: add neighbours, then pairs of pairs (a binary tree); bound \(\lceil\log_2 N\rceil u \sum|x_i|\). Kahan: a running sum plus a correction \(c\) holding what the last addition lost; bound \((2u + O(Nu^2))\sum|x_i|\), so it degrades once \(Nu^2\) is not small (bfloat16 at \(N \approx 10^5\)). fp32 accumulator: the 16-bit inputs added into a float32 running sum, what tensor cores do. "Best possible" is the exact sum rounded once to the format: no algorithm that returns a value in this format can do better. Data are generated by a seeded generator (mulberry32) and rounded to the format first, so only the summation rounds; recompute.py reproduces the uniform cases at \(N = 100\), 1,000 and 10,000 in NumPy.
