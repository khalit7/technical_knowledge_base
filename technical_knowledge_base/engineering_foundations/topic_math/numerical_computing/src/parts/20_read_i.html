10. The stable toolbox: logsigmoid, BCE with logits, softplus, epsilons

The question. Softmax is one function. Which other everyday formulas in ML overflow, underflow or cancel, and what is the stable rewrite of each?

One pattern covers almost all of them: split on the sign, so the exponential only ever sees a non-positive number, and use log1p for the log of one plus something small. The identity behind it is \(e^{-|x|} \le 1\) for every \(x\).

logsigmoid

The sigmoid \(\sigma(x) = 1/(1 + e^{-x})\) gives a probability from one logit. Its log appears in every binary loss. Naively, \(\ln\sigma(-100)\) in float32: \(e^{100}\) overflows (past \(e^{88.72}\)), \(\sigma = 1/\infty = 0\), \(\ln 0 = -\infty\) (measured); the true value is \(-100\). The stable form comes from two cases. For \(x \ge 0\), \(\ln\sigma(x) = -\ln(1 + e^{-x})\). For \(x \lt 0\), multiply top and bottom by \(e^{x}\): \(\sigma(x) = e^{x}/(1 + e^{x})\), so \(\ln\sigma(x) = x - \ln(1 + e^{x})\). Both are one formula:

\[ \ln \sigma(x) = \min(x, 0) - \operatorname{log1p}\bigl(e^{-|x|}\bigr) . \]

PyTorch's CPU kernel is that line, computed in float32 even for 16-bit inputs: min_vec - buffer_vec0.log1p() with buffer_vec0 = data_vec0.abs().neg().exp() (Activation.cpp, lines 33 to 48).

Binary cross-entropy with logits

For a logit \(x\) and a label \(y \in \{0, 1\}\) (or a soft label in \([0, 1]\)), binary cross-entropy is \(\ell = -[\,y \ln\sigma(x) + (1 - y)\ln(1 - \sigma(x))\,]\). Two facts make it stable: \(1 - \sigma(x) = \sigma(-x)\), and \(\ln\sigma(-x) = \ln\sigma(x) - x\) (from \(\sigma(-x) = e^{-x}\sigma(x)\)). Substitute:

\[ \ell = -y \ln\sigma(x) - (1 - y)\bigl(\ln\sigma(x) - x\bigr) = (1 - y)\,x - \ln\sigma(x) = \max(x, 0) - x y + \operatorname{log1p}\bigl(e^{-|x|}\bigr) . \]

The last form uses the logsigmoid line above. Worked: \(x = 2\), \(y = 1\) gives \(0 - 2 + 2 + \operatorname{log1p}(e^{-2}) = 0.1269\); \(y = 0\) gives \(2 + 0.1269 = 2.1269\) (derived). Naively in float32 with \(x = 30\), \(y = 0\): \(\sigma(30) = 1 - 9.4 \times 10^{-14}\) rounds to exactly 1, \(\ln(1 - 1) = -\infty\), loss \(\infty\) (measured); the stable form gives \(30 + \operatorname{log1p}(e^{-30}) = 30.0\). PyTorch v2.14.1 computes (1 - target).mul_(input).sub_(log_sigmoid_input), the middle form above (Loss.cpp, lines 349 to 364).

Why not Sigmoid then BCELoss?
Because the probability has already rounded to 0 or 1 before the loss sees it. PyTorch patches the symptom: "BCELoss clamps its log function outputs to be greater than or equal to -100", so the \(x = 30\) example returns 100 instead of 30, a finite but wrong loss with a wrong gradient. Under autocast it refuses outright: "binary_cross_entropy and BCELoss raise an error in autocast-enabled regions", and the docs say to combine the sigmoid and the loss with binary_cross_entropy_with_logits ({{loss.py|https://github.com/pytorch/pytorch/blob/v2.14.1/torch/nn/modules/loss.py}}, {{amp docs|https://github.com/pytorch/pytorch/blob/v2.14.1/docs/source/amp.md}}, v2.14.1).

softplus

\(\operatorname{softplus}(x) = \ln(1 + e^{x})\), a smooth ReLU and the negative of \(\ln\sigma(-x)\). Naively, float32 \(\operatorname{softplus}(100) = \ln(1 + \infty) = \infty\) (measured). Stable: \(\max(x, 0) + \operatorname{log1p}(e^{-|x|})\). PyTorch's nn.Softplus(beta=1.0, threshold=20.0) takes a shortcut instead: when \(\beta x \gt 20\) it returns \(x\) unchanged. What it drops, \(\operatorname{log1p}(e^{-20}) = 2.1 \times 10^{-9}\), is a thousand times smaller than float32's gap at 20 (\(1.9 \times 10^{-6}\)), so the shortcut is exact in float32 (derived).

Epsilons: the small numbers added on purpose

Many formulas divide by something that can be 0: a standard deviation, a norm, a square root of a second moment. Libraries add a small \(\epsilon\) (not machine epsilon, just a small constant):

  • LayerNorm: \(y = \dfrac{x - \operatorname{mean}(x)}{\sqrt{\operatorname{var}(x) + \epsilon}}\,\gamma + \beta\), default \(\epsilon = 10^{-5}\) (nn.LayerNorm, v2.14.1). For a constant row, \(\operatorname{var} = 0\): without \(\epsilon\) the result is \(0/0 =\) NaN; with it, \(0 \times 1/\sqrt{10^{-5}} = 0 \times 316.2 = 0\). It also caps the gain for nearly constant rows at 316.
  • RMSNorm: \(y = x / \sqrt{\epsilon + \tfrac1n\sum_i x_i^2}\). PyTorch's default \(\epsilon\) is now the machine epsilon of the compute type, \(1.19 \times 10^{-7}\) for float16, bfloat16 and float32 inputs (docstring, v2.14.1); model configs set their own (SmolLM2-135M: rms_norm_eps \(10^{-5}\)).
  • Adam: the update divides by \(\sqrt{\hat v} + \epsilon\) with default \(\epsilon = 10^{-8}\) (torch.optim.Adam, v2.14.1). In float16, \(10^{-8}\) is below the smallest subnormal (\(6 \times 10^{-8}\)) and becomes 0: one reason optimiser state stays in float32.
  • Even \(10^{-5}\) is not a normal float16 number: it is a subnormal (stored as \(1.0014 \times 10^{-5}\); smallest normal \(6.1 \times 10^{-5}\)). Autocast runs layer_norm, group_norm and norm in float32 for this kind of reason (amp docs).

What it is used for in ML
Classifiers (BCE with logits for multi-label heads, reward models trained with \(-\ln\sigma(r_w - r_l)\), which is exactly a logsigmoid), DPO's loss (also \(-\ln\sigma(\cdot)\)), gating functions, every normalisation layer, every optimiser.
