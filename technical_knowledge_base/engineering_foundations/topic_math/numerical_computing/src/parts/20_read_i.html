8. The stable toolbox: logsigmoid, BCE with logits, softplus, epsilons

One pattern covers almost every other everyday formula that overflows, underflows or cancels: split on the sign, so the exponential only ever sees a non-positive number, and use log1p for the log of one plus something small. The identity behind it is \(e^{-|x|} \le 1\) for every \(x\). Predict where the naive binary cross-entropy breaks in float16, then switch the format:

Naive formulas go infinite at a logit set by the format; the stable forms never do

Both curves computed with every operation rounded to the format by this page's emulator (log1p in float64, then rounded); the naive curve is cut where it first becomes infinite (the red marker). In float32 the naive BCE fails from \(x = 16.64 = 24 \ln 2\), where \(1 + e^{-x}\) already rounds to 1, a little before \(\sigma(x)\) itself would round to 1 (17.3, below the table). Derived.

logsigmoid. The sigmoid \(\sigma(x) = 1/(1 + e^{-x})\) gives a probability from one logit, and its log appears in every binary loss. Naively, \(\ln\sigma(-100)\) in float32: \(e^{100}\) overflows (past \(e^{88.72}\)), \(\sigma = 1/\infty = 0\), \(\ln 0 = -\infty\) (measured); the true value is \(-100\). Splitting on the sign gives one formula:

\[ \ln \sigma(x) = \min(x, 0) - \operatorname{log1p}\bigl(e^{-|x|}\bigr) . \]

Binary cross-entropy with logits. For a logit \(x\) and a label \(y \in \{0, 1\}\) (or a soft label in \([0, 1]\)), \(\ell = -[\,y \ln\sigma(x) + (1 - y)\ln(1 - \sigma(x))\,]\), and with \(1 - \sigma(x) = \sigma(-x)\):

\[ \ell = (1 - y)\,x - \ln\sigma(x) = \max(x, 0) - x y + \operatorname{log1p}\bigl(e^{-|x|}\bigr) . \]

Worked: \(x = 2\), \(y = 1\) gives \(0 - 2 + 2 + \operatorname{log1p}(e^{-2}) = 0.1269\); \(y = 0\) gives \(2 + 0.1269 = 2.1269\) (derived). Naively in float32 with \(x = 30\), \(y = 0\): \(\sigma(30) = 1 - 9.4 \times 10^{-14}\) rounds to exactly 1, \(\ln(1 - 1) = -\infty\), loss \(\infty\) (measured); the stable form gives \(30 + \operatorname{log1p}(e^{-30}) = 30.0\). PyTorch v2.14.1 computes (1 - target).mul_(input).sub_(log_sigmoid_input), the middle form (Loss.cpp, lines 349 to 364). softplus, \(\ln(1 + e^{x})\), is the same shape: naively \(\operatorname{softplus}(100) = \ln(1 + \infty) = \infty\) in float32 (measured); stably \(\max(x, 0) + \operatorname{log1p}(e^{-|x|})\).

Why not Sigmoid then BCELoss?
Because the probability has already rounded to 0 or 1 before the loss sees it. PyTorch patches the symptom: "BCELoss clamps its log function outputs to be greater than or equal to -100", so the \(x = 30\) example returns 100 instead of 30, a finite but wrong loss with a wrong gradient. Under autocast it refuses outright: "binary_cross_entropy and BCELoss raise an error in autocast-enabled regions", and the docs say to use binary_cross_entropy_with_logits ({{loss.py|https://github.com/pytorch/pytorch/blob/v2.14.1/torch/nn/modules/loss.py}}, {{amp docs|https://github.com/pytorch/pytorch/blob/v2.14.1/docs/source/amp.md}}, v2.14.1). Reward models trained with \(-\ln\sigma(r_w - r_l)\) and DPO's loss are exactly a logsigmoid.
The derivations, and the kernels PyTorch runs

logsigmoid. For \(x \ge 0\), \(\ln\sigma(x) = -\ln(1 + e^{-x})\). For \(x \lt 0\), multiply top and bottom by \(e^{x}\): \(\sigma(x) = e^{x}/(1 + e^{x})\), so \(\ln\sigma(x) = x - \ln(1 + e^{x})\). Both are the one formula above. PyTorch's CPU kernel is that line, computed in float32 even for 16-bit inputs: min_vec - buffer_vec0.log1p() with buffer_vec0 = data_vec0.abs().neg().exp() (Activation.cpp, lines 33 to 48).

BCE. Two facts: \(1 - \sigma(x) = \sigma(-x)\), and \(\ln\sigma(-x) = \ln\sigma(x) - x\) (from \(\sigma(-x) = e^{-x}\sigma(x)\)). Substitute: \(\ell = -y \ln\sigma(x) - (1 - y)\bigl(\ln\sigma(x) - x\bigr)\), which collects to \((1 - y)\,x - \ln\sigma(x)\), and the logsigmoid line gives the last form.

softplus is a smooth ReLU and the negative of \(\ln\sigma(-x)\). PyTorch's nn.Softplus(beta=1.0, threshold=20.0) takes a shortcut: when \(\beta x \gt 20\) it returns \(x\) unchanged. What it drops, \(\operatorname{log1p}(e^{-20}) = 2.1 \times 10^{-9}\), is a thousand times smaller than float32's gap at 20 (\(1.9 \times 10^{-6}\)), so the shortcut is exact in float32 (derived).

Epsilons. Formulas that divide by something that can be 0 (a standard deviation, a norm, the root of a second moment) add a small constant \(\epsilon\), not machine epsilon: LayerNorm's default \(10^{-5}\) turns a constant row's \(0/0\) into 0; Adam's \(10^{-8}\) is itself 0 in float16, one reason optimiser state stays in float32.

Epsilons in LayerNorm, RMSNorm and Adam, and why autocast keeps norms in float32
  • LayerNorm, \(y = \dfrac{x - \operatorname{mean}(x)}{\sqrt{\operatorname{var}(x) + \epsilon}}\,\gamma + \beta\), default \(\epsilon = 10^{-5}\) (nn.LayerNorm, v2.14.1). For a constant row, without \(\epsilon\) the result is \(0/0 =\) NaN; with it, \(0 \times 1/\sqrt{10^{-5}} = 0 \times 316.2 = 0\). It also caps the gain for nearly constant rows at 316.
  • RMSNorm, \(y = x / \sqrt{\epsilon + \tfrac1n\sum_i x_i^2}\): PyTorch's default \(\epsilon\) is now the machine epsilon of the compute type, \(1.19 \times 10^{-7}\) for float16, bfloat16 and float32 inputs (docstring, v2.14.1); model configs set their own (SmolLM2-135M: rms_norm_eps \(10^{-5}\)).
  • Adam divides by \(\sqrt{\hat v} + \epsilon\) with default \(\epsilon = 10^{-8}\) (torch.optim.Adam, v2.14.1). In float16, \(10^{-8}\) is below the smallest subnormal (\(6 \times 10^{-8}\)) and becomes 0: one reason optimiser state stays in float32.
  • Even \(10^{-5}\) is not a normal float16 number: it is a subnormal (stored as \(1.0014 \times 10^{-5}\); smallest normal \(6.1 \times 10^{-5}\)). Autocast runs layer_norm, group_norm and norm in float32 for this kind of reason (amp docs).
