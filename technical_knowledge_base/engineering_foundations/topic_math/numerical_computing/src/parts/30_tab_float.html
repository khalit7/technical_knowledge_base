Float explorer

Type any number, or move the slider, and see what each format stores: its bits (sign, exponent, mantissa), the value you get back, the rounding error, the gap to the neighbouring numbers, and what happens at the edges (subnormals, underflow to 0, overflow to infinity or, in FP8 E4M3, saturation or NaN). Click any bit to flip it: the number the new bits encode becomes the input. Every format is emulated exactly by this page's code, which matches ml_dtypes and NumPy on 17,610 test values (recompute.py). It extends Reading sections {{2 (IEEE 754)|#t-read}} to 4; block formats (MXFP4, NVFP4, NF4) are in the {{Quantization and precision|n:3c65c17b0d0d817b8f41ff66fba4cd0e}} page's Bit explorer.

Try: 0.1 (no format stores it exactly); 1e-8, a small gradient (float16 and both FP8s store 0, bfloat16 keeps it); 70000 (float16 overflows); 999 (bfloat16 stores 1000); 500 in E4M3 (saturates to 448 or becomes NaN, depending on the mode); 1+2^-8 (bfloat16 rounds the tie to 1); then type 1 and, in float16, flip the last exponent bit (the value halves to 0.5) and then the first (the exponent becomes all ones: infinity).

"Gap here" is one ulp at this magnitude; "relative error" is \(|\text{stored} - x| / |x|\), at most \(u = 2^{-(m+1)}\) for normal numbers. TF32 is shown as the 19 bits a tensor core reads, rounded to nearest even here; in memory it is a float32, and PyTorch's notes say the tensor core reads "only the first 10 bits of the input mantissa", which would truncate instead and can differ by one step. float64 is JavaScript's own number type, so it is exact by construction. Neighbour buttons step to the next representable number down or up.
