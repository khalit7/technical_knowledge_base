5. The error of one operation, and how errors travel

The question. If each operation is rounded, how wrong can a whole computation get, and how do you tell a hard problem from a bad algorithm?

Because IEEE 754 rounds each basic operation once, correctly, every operation obeys the standard model ({{Higham 2002|https://doi.org/10.1137/1.9780898718027}}, chapter 2):

\[ \operatorname{fl}(x \circ y) = (x \circ y)(1 + \delta), \qquad |\delta| \le u, \qquad \circ \in \{+, -, \times, \div\} \]

In words: the computed result is the exact result of the exact inputs, nudged by a relative error of at most \(u\) (\(5.96 \times 10^{-8}\) in float32), as long as the result neither overflows nor underflows. One operation is therefore almost perfect. Problems come from what happens to errors already present in the inputs, and from many operations in a row. The fused multiply-add (FMA, required since IEEE 754-2008) computes \(a \times b + c\) with a single rounding instead of two; matrix-multiply units are built from it.

Two ways to measure how wrong an answer is. The forward error is the distance from the true answer. The backward error asks a different question: is the computed answer the exact answer for a slightly different input, and how different? An algorithm whose answers are always exact answers to inputs perturbed by a few \(u\) is backward stable. The two are linked by the condition number of the problem:

\[ \text{forward error} \lesssim \kappa \times \text{backward error} . \]

So there are two separate ways to get a bad answer: a badly conditioned problem (large \(\kappa\): any algorithm loses digits) or an unstable algorithm (large backward error on a well-conditioned problem: a better algorithm fixes it). The naive softmax of section 9 is the second kind.

6. Cancellation and the condition number of a computation

The question. Why does \((1 + 10^{-8}) - 1\) come out as exactly 0 in float32, and why does a textbook variance formula return a negative variance?

Catastrophic cancellation

Subtracting two nearly equal numbers is exact (the Sterbenz lemma: if \(y/2 \le x \le 2y\), then \(x - y\) is a float), but it exposes the rounding errors the two numbers already carried, now measured against a tiny result. Measured, \(x = 10^{-8}\):

  • float32: \(1 + 10^{-8}\) rounds to 1 (the gap above 1 is \(1.2 \times 10^{-7}\)), so \((1 + x) - 1 = 0\): 100% error.
  • float64: \((1 + x) - 1 = 9.99999993922529 \times 10^{-9}\), a relative error of \(6.1 \times 10^{-9}\), which is \(5 \times 10^{7}\) times the format's \(u = 1.1 \times 10^{-16}\). Eight of sixteen digits are gone, not because the subtraction was inexact but because \(1 + x\) was rounded first.

The general rule: when \(a \approx b\), the relative error of \(a - b\) is the relative error of the inputs multiplied by \(|a| / |a - b|\). The fix is always the same: rewrite the formula so the subtraction of nearly equal quantities never happens.

The condition number of a function

How much does a small relative change in the input \(x\) change the output \(f(x)\)? Divide the two relative changes and let the input change shrink to zero:

\[ \kappa_f(x) = \left|\frac{\Delta f / f}{\Delta x / x}\right| \to \left| \frac{x\, f'(x)}{f(x)} \right| . \]

Read it as an error amplifier: an input known to relative accuracy \(u\) gives an output known to about \(\kappa_f(x)\, u\), whatever algorithm you use. Worked values (derived):

log1p and expm1

For tiny \(x\), \(\ln(1 + x) \approx x\) and \(e^{x} - 1 \approx x\), but computing them as written rounds \(1 + x\) or produces \(e^{x} \approx 1\) and then cancels. The library functions log1p(x) and expm1(x) compute them directly from \(x\). Measured in float64 at \(x = 10^{-10}\): log(1 + x) gives \(1.000000082690371 \times 10^{-10}\) (relative error \(8.3 \times 10^{-8}\), about 8 correct digits), log1p(x) gives \(9.9999999995 \times 10^{-11}\) (all 16); exp(x) - 1 is off by the same \(8.3 \times 10^{-8}\) and expm1(x) is exact. Section 10 uses both inside softplus and BCE.

Variance: one pass, two passes, Welford

The variance of \(x_1, \dots, x_n\) with mean \(\bar{x}\) is \(\frac1n \sum_i (x_i - \bar x)^2\). Expanding the square gives the "computational formula" \(\frac1n \sum_i x_i^2 - \bar{x}^2\), which needs only one pass over the data and subtracts two huge, nearly equal numbers. Measured in float32 on three numbers near 10,000 (stored as \(10000.0996\), \(10000.2002\), \(10000.2998\); exact variance of the stored values \(0.0066797\)):

Welford's algorithm ({{Welford 1962|https://doi.org/10.1080/00401706.1962.10490022}}) keeps a running mean \(m_k\) and a running sum of squared deviations \(M_k\) after \(k\) values:

\[ m_k = m_{k-1} + \frac{x_k - m_{k-1}}{k}, \qquad M_k = M_{k-1} + (x_k - m_{k-1})(x_k - m_k), \qquad \operatorname{var} = M_n / n . \]

Every term is a deviation from a running mean, so nothing large is ever subtracted from something large. On the three numbers: \(m = 10000.0996, 10000.1504, 10000.2002\) and \(M = 0, 0.00501, 0.01989\), so \(\operatorname{var} = 0.01989 / 3 = 0.00663\) (measured, float32). It also merges partial results from two halves of the data exactly (Chan et al. 1979), which is what parallel hardware needs: PyTorch's reductions for variance and normalisation statistics use a WelfordOps accumulator ({{SharedReduceOps.h, v2.14.1|https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/native/SharedReduceOps.h}}).

What it is used for in ML
LayerNorm, BatchNorm and RMSNorm statistics; running means of metrics over a long evaluation; any "subtract the mean" in a loss. If a hand-written normalisation uses (x**2).mean() - x.mean()**2, it can go negative on large activations and turn \(1/\sqrt{\operatorname{var} + \epsilon}\) into NaN.
