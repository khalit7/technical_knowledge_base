7. The stable softmax, log-sum-exp and log-softmax

The softmax turns logits \(z_1, \dots, z_n\) into probabilities, and the loss is the negative log of the target's:

\[ p_i = \frac{e^{z_i}}{\sum_{j=1}^{n} e^{z_j}}, \qquad \text{loss} = -\ln p_y \ \text{ for the target } y . \]

For \(z = (2, 1, 0)\): \(e^2 = 7.389\), \(e^1 = 2.718\), \(e^0 = 1\), sum \(11.107\), so \(p = (0.665, 0.245, 0.090)\) and the loss for the target sat is \(-\ln 0.090 = 2.408\). Now take \(z = (1000, 999, 0)\). \(e^{1000}\) is about \(10^{434}\), past float32's largest value (\(e^{88.72}\)) and even float64's (\(e^{709.78}\)), so it rounds to \(\infty\); the sum is \(\infty\), \(p_{\text{cat}} = \infty/\infty = \) NaN, and one NaN makes the loss and every gradient NaN. The problem itself is easy (condition number 0.9994, section 4): the answer is \(p = (0.731, 0.269, e^{-1000.3})\). Only the algorithm fails.

The fix: subtract the largest logit

Multiply the top and bottom by the same \(e^{-m}\); the value is unchanged for any \(m\):

\[ \frac{e^{z_i}}{\sum_j e^{z_j}} = \frac{e^{z_i - m}}{\sum_j e^{z_j - m}}, \qquad m = \max_j z_j . \]

Then every exponent is at most 0, every \(e^{z_j - m}\) lies in \((0, 1]\), nothing can overflow, and the denominator lies between 1 (the largest term is exactly \(e^0\)) and \(n\). Terms that underflow to 0 are far below \(u\) relative to that 1, so dropping them changes nothing visible. The same move gives the log-sum-exp, the log of the denominator, and the log-softmax:

\[ \operatorname{LSE}(z) = m + \ln \sum_j e^{z_j - m}, \qquad \ln p_i = z_i - \operatorname{LSE}(z) = (z_i - m) - \ln \sum_j e^{z_j - m} . \]

For \((1000, 999, 0)\): \(\operatorname{LSE} = 1000 + \ln(1 + e^{-1} + e^{-1000})\), that is \(1000 + \ln 1.3679 = 1000.3133\) (derived; the old Topic: math child page's example, logits \((1000, 1001)\), gives \(1001.313\) the same way, rechecked). Never take the log of a softmax: \(p_{\text{sat}} = e^{-1000.31}\) underflows to 0 even in float64 (smallest about \(e^{-744}\)), and \(-\ln 0 = \infty\), while the log-softmax gives \(\ln p_{\text{sat}} = (0 - 1000) - 0.3133 = -1000.3133\): a huge, honest, finite loss, with gradient \(p - \text{onehot}(y) = (0.731, 0.269, -1)\). For the same reason every likelihood is a sum of logs: 1,000 tokens each with probability 0.1 have likelihood \(10^{-1000}\), which underflows even float64, while its log, \(-1000 \ln 10 = -2302.6\), is ordinary (derived). This is why CrossEntropyLoss takes "unnormalized logits" and runs log-softmax and the negative log-likelihood fused. (The probability side, why losses and likelihoods live in log space, is {{Probability|n:3c65c17b0d0d815f9a47d613409b5a0c}}'s section 12.)

Keep logits and softmax in float32: PyTorch's autocast lists softmax, log_softmax, cross_entropy, exp, log and sum among the "CUDA Ops that can autocast to float32" ({{amp docs, v2.14.1|https://github.com/pytorch/pytorch/blob/v2.14.1/docs/source/amp.md}}).

One pass instead of two: the online softmax

The stable softmax reads the logits twice (max, then sum). Milakov and Gimelshein update both in one pass ({{2018|https://arxiv.org/abs/1805.02867}}): keep the running max \(m_k\) and the running sum \(d_k = \sum_{j \le k} e^{z_j - m_k}\), and rescale the old sum when the max changes:

\[ m_k = \max(m_{k-1}, z_k), \qquad d_k = d_{k-1}\, e^{m_{k-1} - m_k} + e^{z_k - m_k} . \]

On \((1000, 999, 0)\): \(m = 1000, d = 1\); then \(d = 1 + e^{-1} = 1.368\); then \(d = 1.368 + e^{-1000} = 1.368\), the same denominator. This rescaling is the heart of FlashAttention ({{Dao et al. 2022|https://arxiv.org/abs/2205.14135}}; the {{FlashAttention paper page|n:3c65c17b0d0d81e4a3e8e7a2c4771381}} runs the kernel in its Run the kernel tab), which computes attention's softmax tile by tile without holding a full row of scores; the mask's \(-\infty\) entries go through the same formulas. The error analysis of the shifted formulas is {{Blanchard, Higham and Higham 2021|https://doi.org/10.1093/imanum/draa038}}.

What PyTorch actually runs (v2.14.1 source)

torch.logsumexp is exactly the formula above, with one extra guard: if the max is infinite (a row of all \(-\infty\), as in a fully masked attention row), it shifts by 0 instead, so the result is \(-\infty\) rather than NaN from \(-\infty - (-\infty)\):

// aten/src/ATen/native/ReduceOps.cpp, lines 1543-1558 (v2.14.1)
static Tensor& logsumexp_out_impl(Tensor& result, const Tensor& self, IntArrayRef dims, bool keepdim) {
  // can't take max of empty tensor
  if (self.numel() != 0) {
    ...
    auto maxes = at::amax(at::real(self), dims, true);
    auto maxes_squeezed = (keepdim ? maxes : at::squeeze(maxes, dims));
    maxes_squeezed.masked_fill_(maxes_squeezed.abs() == INFINITY, 0);
    at::sum_out(result, (self - maxes).exp_(), dims, keepdim);
    result.log_().add_(maxes_squeezed);
  } else { ... }

The CPU softmax kernel does the same three steps per row: reduce to the max, map \(x \mapsto e^{x - \max}\), sum and multiply by the reciprocal (SoftMaxKernel.cpp, lines 60 to 91). Excerpts are saved in src/inputs/pytorch_v2.14.1/excerpts.txt.
