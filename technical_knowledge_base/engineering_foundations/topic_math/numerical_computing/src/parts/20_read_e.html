4. The error of one operation, conditioning and cancellation

Because IEEE 754 rounds each basic operation once, correctly, every operation obeys the standard model ({{Higham 2002|https://doi.org/10.1137/1.9780898718027}}, chapter 2): the computed result is the exact result of the exact inputs, nudged by a relative error of at most \(u\) (\(5.96 \times 10^{-8}\) in float32), as long as it neither overflows nor underflows.

\[ \operatorname{fl}(x \circ y) = (x \circ y)(1 + \delta), \qquad |\delta| \le u, \qquad \circ \in \{+, -, \times, \div\} \]

One operation is almost perfect; problems come from errors already in the inputs and from many operations in a row. The fused multiply-add (FMA, required since IEEE 754-2008) computes \(a \times b + c\) with one rounding instead of two; matrix-multiply units are built from it. Two ways to measure a wrong answer: the forward error is the distance from the true answer; the backward error asks how much the input would have to change for the computed answer to be exact. An algorithm whose answers are exact for inputs perturbed by a few \(u\) is backward stable, and

\[ \text{forward error} \lesssim \kappa \times \text{backward error} . \]

So there are two separate ways to get a bad answer: a badly conditioned problem (large \(\kappa\): any algorithm loses digits) or an unstable algorithm (large backward error on a well-conditioned problem: a better algorithm fixes it). The naive softmax of section 7 is the second kind.

Catastrophic cancellation

Subtracting two nearly equal floats is exact (the Sterbenz lemma: if \(y/2 \le x \le 2y\), then \(x - y\) is a float), but it exposes the rounding errors the two numbers already carried, now measured against a tiny result:

Subtracting 1 keeps the rounding noise and throws away the digits that agreed

\(1.0001\) stored in float32 is \(1.000100016593933\) (bits 3f800347), relative error \(1.7 \times 10^{-8}\), within \(u\). Subtracting 1 is exact, but the four leading digits that agreed are gone and the result \(0.00010001659393310547\) has a relative error of \(1.66 \times 10^{-4}\): the input's own error times \(\kappa = 10{,}001\), within the bound \(\kappa u = 10{,}001 \times 2^{-24} = 6.0 \times 10^{-4}\). Green: correct digits; orange: digits that are rounding noise. Derived, src/derive_new_visuals.py.

The rule: when \(a \approx b\), the relative error of \(a - b\) is the inputs' relative error times \(|a| / |a - b|\), and the fix is always to rewrite the formula so the subtraction of nearly equal quantities never happens.

The same cancellation measured with \(x = 10^{-8}\), in float32 and float64

Measured with \(x = 10^{-8}\): in float32, \(1 + 10^{-8}\) rounds to 1 (the gap above 1 is \(1.2 \times 10^{-7}\)), so \((1 + x) - 1 = 0\), 100% error; in float64, \((1 + x) - 1 = 9.99999993922529 \times 10^{-9}\), a relative error of \(6.1 \times 10^{-9}\), which is \(5 \times 10^{7}\) times float64's \(u = 1.1 \times 10^{-16}\): eight of sixteen digits gone because \(1 + x\) was rounded first.

The condition number of a function

How much does a small relative change in \(x\) change \(f(x)\)? Divide the two relative changes and let the input change shrink to zero:

\[ \kappa_f(x) = \left|\frac{\Delta f / f}{\Delta x / x}\right| \to \left| \frac{x\, f'(x)}{f(x)} \right| . \]

An input known to relative accuracy \(u\) gives an output known to about \(\kappa_f(x)\, u\), whatever algorithm you use. Worked values (derived):

Variance: one pass, two passes, Welford

The variance \(\frac1n \sum_i (x_i - \bar x)^2\) expanded into the one-pass "computational formula" \(\frac1n \sum_i x_i^2 - \bar{x}^2\) subtracts two huge, nearly equal numbers. Measured in float32 on three numbers near 10,000 (stored as \(10000.0996\), \(10000.2002\), \(10000.2998\); exact variance of the stored values \(0.0066797\)):

Methodfloat32 resultWhat happened
one pass, \(\overline{x^2} - \bar x^2\)\(-8.0\)\(\sum x_i^2 \approx 3.0 \times 10^{8}\), where float32's gap is 32; the true difference, 0.02, is far below one gap. A variance cannot be negative: \(\sqrt{\cdot}\) of it is NaN.
two passes: mean first, then \(\sum (x_i - \bar x)^2\)\(0.0066799\)the subtraction happens before squaring, on numbers of size 0.1

Welford's algorithm ({{Welford 1962|https://doi.org/10.1080/00401706.1962.10490022}}) keeps a running mean \(m_k\) and sum of squared deviations \(M_k\), so nothing large is ever subtracted from something large:

\[ m_k = m_{k-1} + \frac{x_k - m_{k-1}}{k}, \qquad M_k = M_{k-1} + (x_k - m_{k-1})(x_k - m_k), \qquad \operatorname{var} = M_n / n . \]

It also merges partial results from two halves of the data exactly (Chan et al. 1979), which parallel hardware needs: PyTorch's reductions for variance and normalisation statistics use a WelfordOps accumulator ({{SharedReduceOps.h, v2.14.1|https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/native/SharedReduceOps.h}}). A hand-written (x**2).mean() - x.mean()**2 inside a LayerNorm, BatchNorm or RMSNorm can go negative on large activations and turn \(1/\sqrt{\operatorname{var} + \epsilon}\) into NaN.

\(m = 10000.0996, 10000.1504, 10000.2002\) and \(M = 0, 0.00501, 0.01989\), so \(\operatorname{var} = 0.01989 / 3 = 0.00663\) (measured, float32).
