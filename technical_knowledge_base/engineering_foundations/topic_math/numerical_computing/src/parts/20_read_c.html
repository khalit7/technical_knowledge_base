2. IEEE 754, bit by bit

The question. The root page's loss is \(2.4076\ldots\). Which 32 bits does PyTorch store for it, and how do you read them back?

The standard that fixes the answer is IEEE 754, first published in 1985 and revised in 2008 and 2019 ({{IEEE 754-2019|https://doi.org/10.1109/IEEESTD.2019.8766229}}; William Kahan, its main architect, received the 1989 {{Turing Award|https://amturing.acm.org/award_winners/kahan_1023746.cfm}} for it). Before it, every computer maker rounded differently and the same program gave different answers on different machines. It defines the formats, what every operation must return, and the special values. A 32-bit float (float32, fp32, "single precision") is three fields:

sign: 1 bitexponent field: 8 bitsfraction (mantissa) field: 23 bits
\[ x = (-1)^{s} \times \Bigl(1 + \frac{f}{2^{23}}\Bigr) \times 2^{\,e - 127} \qquad (1 \le e \le 254) \]
\(s\)
the sign bit: 0 for positive, 1 for negative.
\(e\)
the 8-bit biased exponent field, read as an unsigned integer 0 to 255. The true exponent is \(E = e - 127\); 127 is the bias (\(2^{8-1} - 1\)). Storing \(E + 127\) instead of a signed \(E\) makes the fields of positive floats sort in the same order as the numbers, so hardware can compare floats with integer comparisons.
\(f\)
the 23-bit fraction field, read as an integer 0 to \(2^{23} - 1\). The leading 1 of the significand is not stored (every normal number has one, so it is free: the hidden bit). A float32 therefore carries \(p = 24\) significant bits, the format's precision.
Decode a number. Pick a value and a format: the bits are computed, then read back with the formula above. The full version, with any number and bit flipping, is the {{Float explorer|#t-float}} tab.

Worked by hand, the loss in fp32. The exact loss is \(\ln(e^2 + e^1 + e^0) = 2.40760596444438\ldots\) (the root's tiny model, target sat). It lies between \(2^1 = 2\) and \(2^2 = 4\), so \(E = 1\) and the stored exponent is \(e = 1 + 127 = 128 = 10000000_2\). The significand is \(2.4076\ldots / 2 = 1.2038\ldots\); its fractional part times \(2^{23}\) is \(1{,}709{,}622.6\ldots\), which rounds to \(f = 1{,}709{,}623\). Reading back: \(x = (1 + 1{,}709{,}623 / 8{,}388{,}608) \times 2\), which is \(1.2038029432296753 \times 2\), which is \(2.4076058864593506\). The stored value is off by \(7.8 \times 10^{-8}\), a relative error of \(3.2 \times 10^{-8}\). Python's standard library agrees: struct.pack('>f', loss).hex() gives 401a1637, which is the same 32 bits in hexadecimal (measured).

Four kinds of bit pattern

The two extreme exponent fields are reserved. That gives four kinds of float, and every ML bug involving NaN starts in this table:

Why subnormals exist. Without them the gap between 0 and the smallest normal number, \(2^{-126}\), would be \(2^{23}\) times wider than the gap just above it, so two different tiny numbers could subtract to exactly 0. With them, numbers fade to zero in equal steps of \(2^{-149}\) (gradual underflow), and \(x - y = 0\) only when \(x = y\) ({{Goldberg 1991|https://doi.org/10.1145/103162.103163}}, its "Denormalized Numbers" subsection). The price is that a subnormal keeps fewer significant bits: \(10^{-40}\) in float32 has only 17 of them. Some hardware drops subnormals for speed (flush to zero): Google's TPU blog says "bfloat16 handles denormals differently from FP32: it flushes them to zero" ({{Wang and Kanwar 2019|https://cloud.google.com/blog/products/ai-machine-learning/bfloat16-the-secret-to-high-performance-on-cloud-tpus}}), and PyTorch's notes say AMD MI200's FP16 and BF16 matrix instructions "flush input and output denormal values to zero" ({{numerical accuracy notes, v2.14.1|https://github.com/pytorch/pytorch/blob/v2.14.1/docs/source/notes/numerical_accuracy.md}}).

The NaN rules that matter in practice. NaN spreads: one NaN in a matrix multiply's input makes every output that touches it NaN, and one NaN in the loss makes every gradient NaN. x != x is true only for NaN, which is how torch.isnan works conceptually. And NaN compares false with everything, so loss > 10 is false for a NaN loss: a divergence check written that way never fires (use not torch.isfinite(loss)).

What it is used for in ML
Reading a dtype: torch.finfo(torch.float32) prints exactly these constants (eps, max, smallest_normal, tiny). Debugging: a NaN is a bit pattern with an all-ones exponent, so a tensor dump that shows 7fc00000 is a NaN and 7f800000 is \(+\infty\).
