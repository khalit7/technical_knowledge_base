## Facts, verbatim in substance, with corrections
1. **Layouts.** For f: R^n -> R^m, numerator layout (Jacobian convention) gives an m x n derivative, rows indexed by outputs, chain rule J_f J_g left to right (MML book, most papers). Denominator layout (gradient convention) is the transpose, n x m; for scalar f, grad f is a column shaped like x, which is what optimisers want and what autodiff returns. In numerator layout the derivative of a scalar by a vector is a row. Neither is wrong; mixing them in one derivation is. Practical rule: derive in numerator layout, remember frameworks return gradients shaped like the parameter: grad_W L has the shape of W. **Verified.**
2. **Worked example.** f(x) = Wx, W in R^{3x2}: numerator layout df/dx = W (3 x 2), denominator W^T (2 x 3). L = ||Wx - y||^2 with y in R^3: grad_W L = 2(Wx - y)x^T, a 3 x 1 column times 1 x 2 row, shaped like W. **Verified.**
3. **Jacobian and VJPs.** J_ij = df_i/dx_j. Backprop never materialises J; it computes v^T J (v = gradient wrt the layer's output), at roughly the cost of the forward computation. **Verified.**
4. **Hessian.** H_ij = d^2 f / dx_i dx_j, symmetric when the second derivatives are continuous (Schwarz). At a stationary point, PD implies a strict local min; eigenvalues are curvatures along eigenvectors; for a PD Hessian, lambda_max/lambda_min is the condition number that sets gradient descent's speed. **Verified** (the linear algebra page states the spectral theorem and PD tests, sections 11 and 13).
5. **Gradients worth knowing (denominator layout):** grad_x(a^T x) = a; grad_x(x^T A x) = (A + A^T)x, = 2Ax for symmetric A; grad_X tr(AX) = A^T; grad_X ||X||_F^2 = 2X; grad_X log det X = X^{-T}; least squares grad_w ||Xw - y||^2 = 2X^T(Xw - y), giving normal equations X^T X w = X^T y. In numerator layout each is the transpose. **Verified** (rederived by hand).
6. **Resources:** Matrix Cookbook (Petersen and Pedersen, version 15 Nov 2012); matrixcalculus.org (tool) for symbolic checking; Parr and Howard, The Matrix Calculus You Need For Deep Learning (explained.ai, arXiv 1802.01528, 1.5 to 2.5 h). **Verified links (root sources_check.md).**
7. **Einsum cost.** A plain contraction does one multiply-add per combination of all distinct indices, so its count is the product of every index size; the output shape is the output indices in order. Worked: `bhqd,bhkd->bhqk` with b 2, h 8, q = k = 128, d 64: output (2, 8, 128, 128), cost 2*8*128*128*64 = 16,777,216 multiply-adds; doubling sequence length quadruples it. **Verified.** (The linear algebra page keeps reading einsum and the output shape; the count is yours.)
8. **Correction to carry:** the old page said GD on a quadratic shrinks the error by (kappa - 1)/(kappa + 1) per step without condition; that holds only at the optimal fixed step eta = 2/(lambda_max + lambda_min) (calculus_and_optimisation owns the derivation).
