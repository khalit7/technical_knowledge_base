15. Embeddings and attention, read as linear algebra

The question. The attention equation \(\operatorname{softmax}(QK^\top/\sqrt{d_k})V\) is the most-read line in ML. What is each piece, as an operation on vectors and matrices?

An embedding lookup is a matrix product

A token with id \(i\) can be written as a one-hot vector \(e_i\) (all zeros except a 1 in position \(i\)). With an embedding table \(E\) of shape \(V \times d\), one row per token, \(e_i^\top E\) picks out row \(i\). Libraries do the lookup by indexing because multiplying by a vector of zeros is wasteful, but the gradient is that of a matrix product: only the rows that were used get updated. GPT-2 small's table is \(50{,}257 \times 768\), and it is reused as the output matrix (section 6).

Real embeddings are not centred. Two random GPT-2 token embeddings have cosine similarity on average, not 0: the vectors share a common direction (the mean embedding's length is of the average embedding's length). That is why cosine similarities like cat to dog (0.55) must be read against that baseline, and why many retrieval systems subtract the mean or whiten embeddings before comparing them.

Attention, piece by piece

For a sequence of \(T\) token vectors stacked as the rows of \(H\) (\(T \times d\)), one attention head computes three projections and three products:

\[ Q = H W_Q,\quad K = H W_K,\quad V = H W_V, \qquad \text{out} = \operatorname{softmax}\!\Big(\frac{Q K^\top}{\sqrt{d_k}}\Big)\, V \]
  1. Projections (section 2): each token's vector is mapped to a query, a key and a value of \(d_k\) numbers each (\(d_k = 64\) in GPT-2 small).
  2. Scores: \(QK^\top\) is \(T \times T\), entry \((i, j)\) the dot product of query \(i\) with key \(j\) (row times column, section 3): how well token \(j\) matches what token \(i\) is looking for. Dividing by \(\sqrt{d_k}\) keeps the scores' spread near 1 when the entries of \(q\) and \(k\) have variance 1 (the variance of a sum of \(d_k\) products is \(d_k\)).
  3. Weights: softmax along each row turns scores into positive weights summing to 1.
  4. Output: multiplying by \(V\) makes each output row a weighted average of value vectors, a point inside their convex hull: the column picture of section 3, with the weights as coefficients.
The root's numbers
Treat the tiny model's input \(x = (2, 1)\) as a query and its three word rows as keys and values (\(d_k = 2\)): scores \(Wx/\sqrt{2} = (1.414, 0.707, 0)\), weights \((0.576, 0.284, 0.140)\), output \[0.576\,(1, 0) + 0.284\,(0, 1) + 0.140\,(1, -2) = (0.716, 0.004)\]. The same example is decoded symbol by symbol on the root's Reading tab ("Reading an equation in a paper").

The query-key product is a low-rank bilinear form

The score between hidden states \(h_i\) and \(h_j\) is \(q_i \cdot k_j = h_i^\top (W_Q W_K^\top) h_j\). The \(768 \times 768\) matrix \(W_Q W_K^\top\) is a product through a 64-wide middle, so its rank is at most 64 (rank of a product is at most the smallest inner size). Measured on GPT-2 small's layer 5, head 0: exactly nonzero singular values out of 768 (the 65th is \(3 \times 10^{-14}\), rounding). Each head compares tokens through a 64-dimensional "view" of the 768-dimensional residual stream; twelve heads give twelve such views. The same holds for \(W_V W_O\), the head's output map (Elhage et al., {{A Mathematical Framework for Transformer Circuits, 2021|https://transformer-circuits.pub/2021/framework/index.html}}, call these the QK and OV circuits).

Multi-head attention as block matrices. The \(768 \times 2304\) matrix c_attn holds \(W_Q, W_K, W_V\) side by side, and each is twelve \(768 \times 64\) blocks, one per head; "splitting heads" in code is a reshape from \((B, T, 768)\) to \((B, T, 12, 64)\) and a transpose of two axes, no arithmetic.

16. Einsum: reading every contraction in one line

The question. \(QK^\top\) for a batch of sequences with many heads is a 4-axis operation. How do you write and read it without losing track of which axis is which?

Einstein summation labels every axis with a letter. The rule: a letter that appears in the inputs but not in the output is summed over; every other letter is kept, in the order the output names them. torch.einsum, numpy.einsum and jax.numpy.einsum all read the same strings.

StringReads asMath

ij->jitranspose: relabel only\(A^\top\)
ii->trace: the diagonal, summed\(\operatorname{tr} A\)
btd,od->btoa linear layer on every token (PyTorch's (out, in) weight)\(XW^\top\)

bhqk,bhkd->bhqdattention output: weights times values, summed over keys k\(PV\)

Reading the shape off the string. In bhqd,bhkd->bhqk with \(b = 2\), \(h = 8\), \(q = k = 128\), \(d = 64\) (the old page's example): \(d\) is summed away and the output is \((2, 8, 128, 128)\). Counting the multiply-adds from the same string (one per combination of all distinct letters, here \(2 \cdot 8 \cdot 128 \cdot 128 \cdot 64\)) and seeing why attention is quadratic in length is done on {{Matrix calculus and backprop|n:3f05c17b0d0d817e9892e01088179c93}}.

The einops library adds named reshapes that document intent: rearrange(x, 'b t (h d) -> b h t d', h=12) is the head split of section 15.

  • Solving \(Ax = b\): factorise and solve (torch.linalg.solve, cholesky_solve); never form \(A^{-1}\), which is slower and less accurate.
  • Least squares: QR by default (lstsq); normal equations only when well conditioned; SVD when rank-deficient.
  • Top few singular directions of a big matrix: power iteration or a randomized SVD (torch.svd_lowrank), not a full SVD.
  • Eigen or SVD: eigen for symmetric matrices; SVD for anything about stretch, size or rank.
