13. The condition number: why some problems lose all their digits

The question. Two linear systems of the same size, solved by the same code. One gives an answer accurate to every digit, the other gives garbage. Why, and why does the same number decide how fast gradient descent converges?

The definition

\[ \kappa(A) = \frac{\sigma_{\max}(A)}{\sigma_{\min}(A)} \]

In plain words: the ratio of the most a matrix stretches any direction to the least. A circle becomes an ellipse with this aspect ratio. \(\kappa = 1\) for an orthogonal matrix (a circle stays a circle); \(\kappa = \infty\) for a singular one (some direction is squashed flat). For the running examples: \(\kappa(A) = 6.708/2.236 = 3\); \(\kappa(W) = \sqrt{6}/1 = 2.449\).

What it does to a linear solve, derived

Solve \(Ax = b\), but \(b\) carries a small error \(\delta b\) (measurement noise or rounding). The computed answer is off by \(\delta x = A^{-1}\delta b\). Two inequalities from the SVD: \(\lVert \delta x \rVert = \lVert A^{-1}\delta b \rVert \le \lVert \delta b \rVert / \sigma_{\min}\) (the inverse stretches by at most \(1/\sigma_{\min}\)), and \(\lVert b \rVert = \lVert Ax \rVert \le \sigma_{\max} \lVert x \rVert\). Divide the first by \(\lVert x \rVert \ge \lVert b \rVert / \sigma_{\max}\):

\[ \frac{\lVert \delta x \rVert}{\lVert x \rVert} \le \kappa(A)\, \frac{\lVert \delta b \rVert}{\lVert b \rVert} \]

In plain words: a relative error in the data can come out up to \(\kappa\) times bigger in the answer. Rule of thumb: you lose about \(\log_{10}\kappa\) decimal digits. float32 carries about 7 digits, bfloat16 about 3, so a problem with \(\kappa = 10^4\) is fine in float64, marginal in float32 and hopeless in bfloat16.

Worked: a nearly singular system
\(B = \begin{pmatrix} 1 & 1 \\ 1 & 1.001 \end{pmatrix}\) has \(\kappa = 4{,}002\). With \(b = (2, 2.001)\) the solution is \(x = (1, 1)\). Change \(b\) to \((2, 2.002)\), a relative change of 0.035%, and the solution jumps to \(x = (0, 2)\), a relative change of 100%: an amplification of 2,829, within the bound of 4,002.

The same thing happens inside a model fit. On {{Statistics for ML: estimation, bias and variance, bootstrap, hypothesis tests|n:3f05c17b0d0d810f896cf688ce9aed1b}}, section 11 and its Double descent lab tab plot the smallest singular value of a 40-row training matrix as the number of features \(p\) grows: at \(p = 40\) the matrix is square and that singular value collapses (median 0.086, against 3.55 at \(p = 10\)), so least squares divides the noise by almost zero and the test error peaks. That peak of double descent is ill-conditioning, seen from the statistics side.

Normal equations square it: a real float32 run

\(\kappa(X^\top X) = \kappa(X)^2\), because the singular values of \(X^\top X\) are the squares of those of \(X\). Section 9 had 2.92 against 8.55. On a harder problem the squaring is decisive. Fit a degree-6 polynomial to 50 evenly spaced points on \([0, 1]\) (true coefficients \(1, -2, 3, -4, 5, -6, 7\), no noise) in float32, computed with NumPy by this page's script:

MethodCondition number it works withRelative error in the coefficients
Normal equations \(X^\top X w = X^\top y\)\(\kappa(X)^2 \approx 3.9 \times 10^8\)0.77 (77%)
QR, then \(Rw = Q^\top y\)\(\kappa(X) \approx 1.98 \times 10^4\)0.000018

Same data, same precision, same library; only the algorithm differs. \(\kappa(X)^2\) exceeds 1 over float32's unit roundoff (\(2^{-24}\)), about \(1.7 \times 10^7\), so the normal equations lose every digit.

What it does to gradient descent

Near a minimum, a loss looks like a bowl \(\tfrac{1}{2} w^\top H w\) whose curvature matrix is the Hessian \(H\) (symmetric, PD at a strict minimum). Gradient descent's step size must stay below \(2/\lambda_{\max}\) to be stable in the steepest direction, but then it crawls along the flattest direction, which has curvature \(\lambda_{\min}\). With the best fixed step, \(\eta = 2/(\lambda_{\max} + \lambda_{\min})\), the error shrinks by \((\kappa - 1)/(\kappa + 1)\) per step, \(\kappa = \lambda_{\max}/\lambda_{\min}\). The old page stated this rate without the best-step condition; it holds only at that step size, and is slower at any other. The full derivation, with the root's diag(1, 10) bowl, is on {{Calculus and optimisation for ML|n:3c65c17b0d0d81eb8b49ed6a0f897f3b}}; the root's {{Gradient lab|n:3c65c17b0d0d81cdb851c0835b25a538}} tab animates it.

Fixing conditioning: preconditioning

  • Rescale the inputs. Standardising features (zero mean, unit variance) makes \(X^\top X\) closer to a multiple of \(I\); normalisation layers and careful initialisation do the same inside a network ({{Normalisation and initialisation|n:3c65c17b0d0d81369e1cc38ed4e11d48}}).
  • Regularise. Adding \(\lambda I\) lifts the smallest eigenvalue (ridge, section 9; damping in second-order methods).
  • Precondition the update. Multiply the gradient by an approximation of \(H^{-1}\): Newton's method uses \(H^{-1}\) itself; Adam divides each coordinate by the square root of an exponential moving average of its squared gradient, a diagonal preconditioner.
  • Orthogonalise the update. Muon takes the momentum update \(G = U\Sigma V^\top\) of a 2-D weight and replaces it by \(UV^\top\): every singular value set to 1, so the update has \(\kappa = 1\) and pushes equally in every direction it touches instead of being dominated by a few. A full SVD is too slow, so it runs five Newton-Schulz iterations \(X \leftarrow aX + (bA + cA^2)X\) with \(A = XX^\top\) and \((a, b, c) = (3.4445, -4.7750, 2.0315)\), which "can be stably run in bfloat16"; it applies only to the 2-D weights of hidden layers, with embeddings, the output layer and scalar parameters left to AdamW ({{Keller Jordan, Muon, 8 Dec 2024|https://kellerjordan.github.io/posts/muon/}}). How it behaves in training is on {{Optimisers and learning-rate schedulers|n:3c65c17b0d0d817080bbc90954681d09}}.
Orthogonalisation, worked on \(A\)
The simplest Newton-Schulz iteration is \(X \leftarrow 1.5X - 0.5\,XX^\top X\), which maps each singular value \(s\) to \(1.5s - 0.5s^3\) and leaves the singular vectors alone. Start from \(A/\lVert A \rVert_F\), whose singular values are 0.949 and 0.316. After each step the smaller one reads 0.459, 0.640, 0.829, 0.958, 0.997, 1.000 while the larger reaches 1.000 after two: six steps give \(UV^\top = \begin{pmatrix} 0.894 & -0.447 \\ 0.447 & 0.894 \end{pmatrix}\), the rotation by 26.6° that is the "nearest orthogonal matrix" to \(A\). Muon's quintic version uses tuned coefficients to push small singular values up faster, in five steps. Try it on any matrix in the {{Matrix playground|#t-play}}.
What it is used for in ML
Choosing solvers (QR or Cholesky, never an explicit inverse); choosing precision (mixed-precision training keeps some accumulations in float32 for this reason; {{Numerical computing for ML|n:3f05c17b0d0d81d6af0be4a9a2edba8d}} owns floating point); understanding why normalisation, warmup and adaptive optimisers help; and reading optimiser papers, which are mostly about preconditioning.
