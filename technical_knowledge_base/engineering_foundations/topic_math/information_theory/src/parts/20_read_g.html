5. Cross-entropy: the length of the wrong code, and the training loss

The question. Why is the loss of almost every classifier and language model called "cross-entropy", and what is it the cross of?

The words, then the formula

Outcomes come from the truth \(p\), but you built your code (or placed your bets) for \(q\). Each outcome \(x\) costs you \(-\log q(x)\), the surprise your model assigns to what really happened. Average that over what really happens:

\[ H(p, q) = \mathbb{E}_{x \sim p}\big[-\log q(x)\big] = -\sum_x p(x) \log q(x) \]
\(p\)
the truth: the distribution outcomes are really drawn from (for training data, the empirical distribution of the labels).
\(q\)
the model: the distribution the code, or the loss, is built from.
\(\mathbb{E}_{x \sim p}\)
the average is taken under the truth, because that is how often each outcome actually happens.

In plain words: cross-entropy is the average message length when you use the model's code on the real data. It is the "cross" of two distributions: the frequencies come from one, the code lengths from the other. \(H(p, p) = H(p)\), and \(H(p, q) \ge H(p)\) for every \(q\) (section 6).

Worked example: the forecaster who swaps sun and cloud
Truth \(p\) = (sun 0.5, cloud 0.25, rain 0.25); forecast \(q\) = (sun 0.25, cloud 0.5, rain 0.25). The code built for \(q\) is cloud 0, sun 10, rain 11. The weather still follows \(p\), so the average length is \[ H(p, q) = 0.5 \times 2 + 0.25 \times 1 + 0.25 \times 2 = 1.75 \text{ bits,} \] 0.25 bits per day worse than the 1.5 bits of the code built for the truth.

From cross-entropy to the training loss, step by step

  1. We do not know the true \(p\); we have \(n\) examples \((x_i, y_i)\). Use the empirical distribution: each observed example gets probability \(1/n\).
  2. The model gives a distribution over labels for each input, \(q_\theta(y \mid x)\), where \(\theta\) are the parameters.
  3. Cross-entropy of the empirical distribution against the model: \(H(\hat p, q_\theta) = -\sum_{i=1}^{n} \tfrac{1}{n} \log q_\theta(y_i \mid x_i)\). With a one-hot target, every term of \(-\sum_y p(y) \log q(y)\) except the true label is multiplied by 0.
  4. So the loss is the average negative log-probability of the correct answer, the negative log-likelihood (NLL): \[ \mathcal{L}(\theta) = -\frac{1}{n}\sum_{i=1}^{n} \log q_\theta(y_i \mid x_i) \]
  5. Minimising it maximises \(\prod_i q_\theta(y_i \mid x_i)\), the probability the model gives the whole dataset: cross-entropy minimisation is maximum-likelihood estimation. The {{Probability page|n:3c65c17b0d0d815f9a47d613409b5a0c}} starts from the likelihood side and arrives at the same loss.
A classifier in nats
Correct-class probability 0.7: loss \(-\ln 0.7 = 0.357\) nats (0.515 bits). At 0.99: 0.010 nats. At 0.01: 4.61 nats. The loss grows without bound as the correct-class probability goes to 0, so a few confidently wrong examples can dominate a batch. The tiny model on sat: \(-\ln 0.090 = 2.408\) nats, the root page's loss.

Soft targets. When the target is itself a distribution (a teacher's probabilities in distillation, or label smoothing), the loss is the full sum \(-\sum_y p(y) \log q(y)\), and it no longer reaches 0 at its best: its minimum is \(H(p)\). Say the data after "the cat" were sat 0.8, dog 0.2 illustrative: against the tiny model, \(H(p, q) = -0.2 \ln 0.245 - 0.8 \ln 0.090 = 2.207\) nats, of which \(H(p) = 0.500\) is the target's own entropy and 1.707 is removable. The gradient with respect to the scores is still "prediction minus target", \(q - p\) (derived on the {{root page, section 4|n:3c65c17b0d0d81cdb851c0835b25a538}}; try it in its {{Gradient lab|n:3c65c17b0d0d81cdb851c0835b25a538}} tab).

Binary cross-entropy is the same thing
For a yes/no label \(y \in \{0, 1\}\) and a predicted probability \(\hat y\) of yes, the two-outcome cross-entropy is \(-y \ln \hat y - (1 - y)\ln(1 - \hat y)\): one term survives for each label. PyTorch's BCEWithLogitsLoss and CrossEntropyLoss take scores (logits) rather than probabilities, so that they can compute \(\log\) of a softmax stably (the {{Numerical computing|n:3f05c17b0d0d81d6af0be4a9a2edba8d}} page shows why).
What it is used for in ML
Every classification and next-token loss; distillation (cross-entropy against a teacher's soft probabilities, {{Distillation and Small Language Models|n:3c65c17b0d0d81efa2a8c3b3b623eb09}}); calibration (cross-entropy is a proper scoring rule: its expected value is minimised only by reporting the true probabilities, so a model trained on it is pushed towards calibrated probabilities, not just correct rankings; see {{Evaluation metrics|n:3c65c17b0d0d81a29acef722e842a29b}}).
