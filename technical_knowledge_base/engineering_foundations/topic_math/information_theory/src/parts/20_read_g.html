6. Perplexity and bits per byte

GPT-2 (124M) read the 10,376-byte Darwin passage and paid a total of 7,212.5 nats (10,405 bits). That total is the size of the file it would compress the passage to (section 2). Divide the same total by different units:

Measured (src/data/score.py). The pair row is exact, not hypothetical: a tokenizer whose tokens are pairs of GPT-2 tokens gives each pair the product of the two conditional probabilities, so the total is unchanged and the count halves.

\[ \mathrm{PPL} = \exp\big(\text{CE in nats per token}\big), \qquad \mathrm{BPB} = \frac{n_{\text{tokens}} \cdot \mathrm{CE}_{\text{nats/token}}}{n_{\text{bytes}} \cdot \ln 2} \]

Perplexity is the number of equally likely options that would be as confusing as the model: 1 is perfect, a uniform guess over \(K\) tokens is \(K\), and the tiny model on sat is \(e^{2.408} = 11.1\), worse than a uniform guess over its 3 words. But it divides the total surprise by the number of tokens before exponentiating, so a tokenizer with fewer, longer tokens raises it without the model knowing anything less. Bits per byte (BPB) divides by something no tokenizer can change: GPT-2 cuts the passage into 2,117 tokens, 4.901 bytes per token; 3.407 nats per token is 4.915 bits per token; so \(3.407 / (0.6931 \times 4.901) = 1.003\) bits per byte, an eighth of the raw size.

Different tokenizers on the same texts (real)

Four small open models on three public-domain texts, float32 on CPU, sliding window (src/data/score.py). GPT-2 and OPT-125m share one tokenizer (OPT's paper, §2.3: "the GPT-2 byte level BPE tokenizer"), so only their perplexities compare. On C code GPT-2 scores perplexity 8.2 yet 1.51 bits per byte, against 30.2 and 1.00 on Darwin. Token by token in {{Real text, measured|#t-real}}.

Three things the table shows. Across texts, perplexity misleads: GPT-2's perplexity on the C code is far lower than on Darwin, yet it compresses the code worse, because 979 of its 3,331 tokens there are pure whitespace at 1.14 nats each against 2.51 for the rest (Qwen2.5's tokenizer needs only 284 such tokens); cheap tokens dilute the per-token loss without shortening the file. Across tokenizers, perplexity understates or overstates: on the French passage Qwen2.5 uses 1,670 tokens where SmolLM2 uses 2,131, so its perplexity advantage (13.3 against 16.6, a ratio of 1.24) is smaller than its compression advantage (1.048 against 1.450 bits per byte, a ratio of 1.38). Within one tokenizer, perplexity is fine: GPT-2 against OPT-125m ranks the same way under both measures on all three texts, and the remaining differences between models are model differences (Qwen2.5 is 0.5B parameters, the others 124M to 135M), which bits per byte measures cleanly. The rule: perplexity only within one tokenizer and one evaluation set; bits per byte or per character, saying which, across tokenizers. Pretraining reports and scaling laws use bits per byte or nats per token within one tokenizer; per-token perplexity under three tokenizers, token by token, is drawn on {{Evaluation metrics|n:3c65c17b0d0d81a29acef722e842a29b}}.

Bits per character, and two more conversions checked

Bits per character (BPC) divides by characters instead of bytes; it is the traditional unit on character-level benchmarks such as enwik8, the first \(10^8\) bytes of the 3 March 2006 English Wikipedia dump ({{Large Text Compression Benchmark|https://mattmahoney.net/dc/textdata.html}}). For plain English the two nearly coincide: the Darwin passage has 10,371 characters and 10,376 bytes (an "æ" takes 2 bytes in UTF-8 and a curly apostrophe 3), so GPT-2's 1.0028 bits per byte is 1.0033 bits per character. In accented French they part: the Hugo passage is 5,773 characters but 5,953 bytes, and Qwen2.5's 1.048 bits per byte is \(1.048 \times 5{,}953 / 5{,}773 = 1.081\) bits per character.

Illustrative (from the old page): one 4,000-byte text; tokenizer A gives 1,000 tokens at 2.0 nats each, tokenizer B 1,250 tokens at 1.6 nats. Both total 2,000 nats. Perplexity: A \(e^{2.0} = 7.39\), B \(e^{1.6} = 4.95\), so B looks much better; bits per byte: both \(2{,}000 / (4{,}000 \ln 2) = 0.721\). Real ratio: the Pile paper prefers bits per byte "due to its invariance to different tokenization schemes" and measures 0.29335 GPT-2 tokens per byte over the Pile, so 2.0 nats per token there is \(0.29335 \times 2.0 / \ln 2 = 0.846\) bits per byte ({{Gao et al. 2020|https://arxiv.org/abs/2101.00027}}).
