3. Codes: entropy is the shortest average message

The question. "Entropy is the minimum average number of bits" is quoted everywhere. Minimum over what, and how do you build a code that reaches it?

The picture: a code that matches the probabilities

You want to tell a friend, in 0s and 1s, what the weather was each day. Sun happens half the time, so give it the shortest word; cloud and rain share the rest. The code sun = 0, cloud = 10, rain = 11 works: no codeword is the beginning of another (a prefix code), so the stream 0100110 splits one way only: 0 10 0 11 0, sun, cloud, sun, rain, sun. Its average length is \(\tfrac12 \times 1 + \tfrac14 \times 2 + \tfrac14 \times 2 = 1.5\) bits per day, exactly the entropy, because each codeword is exactly \(-\log_2 p\) bits long.

The rule behind it: lengths are a budget

A codeword of length \(\ell\) uses up a fraction \(2^{-\ell}\) of all possible bit strings (every longer string that starts with it is no longer available). A prefix code with lengths \(\ell_1, \dots, \ell_K\) exists if and only if these fractions fit in the budget:

\[ \sum_{i=1}^{K} 2^{-\ell_i} \le 1 \]

This is the Kraft inequality ({{MacKay, ITILA, §5.2|https://www.inference.org.uk/mackay/itila/}}). Short codewords are expensive: a 1-bit word spends half the budget. So you can only afford short words for a few outcomes, and you should spend them on the frequent ones. Treat \(q_i = 2^{-\ell_i}\) as the probability the code "assumes" for outcome \(i\); a code is a probability distribution in disguise, and a distribution is a code.

Why entropy is the floor. Average length \(L = \sum_i p_i \ell_i\). Write \(\ell_i = -\log_2 q_i\) with \(q_i = 2^{-\ell_i}\), so \(L = -\sum_i p_i \log_2 q_i\), the cross-entropy \(H(p, q)\) of section 5. Section 6 proves \(H(p, q) \ge H(p)\) for any distribution \(q\) (and a sub-normalised \(q\) from Kraft only makes \(L\) larger). So no prefix code beats \(H(p)\) on average, and the code meets it exactly when \(\ell_i = -\log_2 p_i\). MacKay writes this as his equation 5.23: with lengths implying \(q\), "the average length is \(L = H(X) + \sum_i p_i \log p_i/q_i\)", "it exceeds the entropy by the relative entropy \(D_{\mathrm{KL}}(p \Vert q)\)". That single equation is the bridge from codes to losses.

Whole numbers of bits: Huffman's code, built on the tiny model's bet

The ideal lengths for the tiny model's bet are 0.588, 2.031 and 3.473 bits, not whole numbers. Huffman's algorithm finds the best whole-number lengths: repeatedly merge the two least likely items into one node, then read each codeword off the branches. Step through it:

The numbers
Huffman gives cat 0, dog 10, sat 11, average \(0.665 \times 1 + 0.245 \times 2 + 0.090 \times 2 = 1.335\) bits against the entropy 1.201: 0.134 bits wasted per word because cat deserves 0.588 bits and gets a whole one. The cruder rule "round each ideal length up" (a Shannon code, lengths 1, 3, 4) gives 1.760 bits. The guarantee for the best whole-number code is \[ H(p) \le L_{\text{Huffman}} < H(p) + 1 \] ({{MacKay, Theorem 5.1, eq. 5.19|https://www.inference.org.uk/mackay/itila/}}). The "+1" shrinks if you code several words at once: Huffman on pairs of words (9 outcomes) costs 1.2145 bits per word, on triples 1.2107, on blocks of four 1.2094, closing in on 1.2009.

Shannon's source coding theorem, stated plainly

Coding longer and longer blocks is the idea behind the theorem. In MacKay's words (§4.4): "N i.i.d. random variables each with entropy H(X) can be compressed into more than N H(X) bits with negligible risk of information loss, as N → ∞; conversely if they are compressed into fewer than N H(X) bits it is virtually certain that information will be lost." Shannon's original is Theorem 9 of {{the 1948 paper|https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf}}, stated for transmitting over a channel. Two things to keep: entropy is a limit on the average, not on every message; and reaching it needs long blocks, or a method that does not spend whole bits per symbol.

That method is arithmetic coding: it codes a whole message as one number and spends, in total, within two bits of the message's information content \(\sum_t -\log_2 q(x_t \mid x_{\lt t})\) ({{MacKay §6.2|https://www.inference.org.uk/mackay/itila/}}). So with arithmetic coding, the length of the compressed file is the model's total surprise, to within two bits. Section 11 animates it and uses it to turn language models into compressors.

On real text
Count the bytes of the 10,376-byte Darwin passage: 58 distinct byte values, with an entropy (ignoring all context) of 4.269 bits per byte; a Huffman code built on those counts spends 4.295 bits per byte, within 0.03 of the entropy, against 8 bits raw. Getting lower needs context: what came before predicts what comes next. That is conditional entropy (section 4) and, in the limit, a language model (section 11).
What it is used for in ML
The code-length reading is what makes a loss interpretable: 2.408 nats means the model would need 3.47 bits to transmit "sat". It is also why tokenizers are compressors (a BPE merge table shortens frequent strings, see {{Tokenizers|n:3c65c17b0d0d817187bcd94a1b0f15ea}}), and why "minimum description length" arguments treat a model plus its residual code as one message.
