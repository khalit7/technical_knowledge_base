2. Codes: entropy is the shortest average message

Tell a friend the weather each day in 0s and 1s with sun = 0, cloud = 10, rain = 11. No codeword is the start of another (a prefix code), so 0100110 splits one way only: sun, cloud, sun, rain, sun. The average length is \(\tfrac12 \times 1 + \tfrac14 \times 2 + \tfrac14 \times 2 = 1.5\) bits per day, exactly the entropy, because each codeword is exactly \(-\log_2 p\) bits long.

Lengths are a budget. A codeword of length \(\ell\) uses up a fraction \(2^{-\ell}\) of all bit strings, and a prefix code with lengths \(\ell_1, \dots, \ell_K\) exists if and only if

\[ \sum_{i=1}^{K} 2^{-\ell_i} \le 1 \]

(the Kraft inequality, {{MacKay, ITILA, §5.2|https://www.inference.org.uk/mackay/itila/}}). A 1-bit word spends half the budget, so short words can go to only a few outcomes, and they should go to the frequent ones. Read \(q_i = 2^{-\ell_i}\) as the probability the code assumes: a code is a probability distribution in disguise, and a distribution is a code. The average length is then \(L = \sum_i p_i \ell_i = -\sum_i p_i \log_2 q_i\), the cross-entropy \(H(p, q)\), and section 3 proves \(H(p, q) \ge H(p)\). So no prefix code beats the entropy on average, and it meets it exactly when \(\ell_i = -\log_2 p_i\). MacKay's equation 5.23: "the average length is \(L = H(X) + \sum_i p_i \log p_i/q_i\)", which "exceeds the entropy by the relative entropy \(D_{\mathrm{KL}}(p \Vert q)\)". That equation is the bridge from codes to losses.

Whole numbers of bits: Huffman's code on the tiny model's bet

The ideal lengths for the bet are 0.588, 2.031 and 3.473 bits. Huffman's algorithm finds the best whole-number lengths: merge the two least likely items, repeat, then read the codewords off the branches.

Huffman pays 0.134 bits per word for rounding to whole bits

Cat 0, dog 10, sat 11 average 1.335 bits per word against the entropy 1.201; the guarantee is \(H(p) \le L_{\text{Huffman}} \lt H(p) + 1\) ({{MacKay, Theorem 5.1, eq. 5.19|https://www.inference.org.uk/mackay/itila/}}). Coding longer blocks shrinks the "+1", and arithmetic coding removes it: it codes a whole message as one number and spends, in total, within two bits of the message's surprise \(\sum_t -\log_2 q(x_t \mid x_{\lt t})\) ({{MacKay §6.2|https://www.inference.org.uk/mackay/itila/}}). So the length of a compressed file is the model's total surprise, to within two bits; section 7 animates it.

On real text: the Darwin passage uses 58 distinct byte values with an entropy, ignoring all context, of 4.269 bits per byte; a Huffman code on those counts spends 4.295, against 8 raw. Going lower needs context, which is a language model (section 7). The code-length reading is also why tokenizers are compressors (a BPE merge table shortens frequent strings, {{Tokenizers|n:3c65c17b0d0d817187bcd94a1b0f15ea}}), and why minimum-description-length arguments treat a model plus its residual code as one message.

The Shannon code, block coding, and the source coding theorem as stated

The cruder rule "round each ideal length up" (a Shannon code, lengths 1, 3, 4) gives 1.760 bits on the bet. Huffman on pairs of words (9 outcomes) costs 1.2145 bits per word, on triples 1.2107, on blocks of four 1.2094, closing in on 1.2009.

The theorem, in MacKay's words (§4.4): "N i.i.d. random variables each with entropy H(X) can be compressed into more than N H(X) bits with negligible risk of information loss, as N → ∞; conversely if they are compressed into fewer than N H(X) bits it is virtually certain that information will be lost." Shannon's original is Theorem 9 of {{the 1948 paper|https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf}}, stated for transmitting over a channel. Entropy limits the average, not every message, and reaching it needs long blocks or a method such as arithmetic coding that does not spend whole bits per symbol.
