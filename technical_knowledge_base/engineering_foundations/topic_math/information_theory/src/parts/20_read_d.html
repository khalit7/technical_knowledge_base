3. Cross-entropy and KL: the wrong code, and the bits it wastes

Sixteen symbols drawn from \(p\) = (A 1/2, B 1/4, C 1/8, D 1/8), in exactly those proportions, go through two codes: the code built for \(p\) (A 0, B 10, C 110, D 111) and a code built for a wrong guess \(q\) = (A 1/8, B 1/2, C 1/4, D 1/8) (A 110, B 0, C 10, D 111). Predict before you step: the wrong code is shorter on B, so does it lose overall, and by how much per symbol?

The same symbols cost 28 bits with the right code and 38 with the wrong one

Own code: \(8 \times 1 + 4 \times 2 + 2 \times 3 + 2 \times 3 = 28\) bits, 1.75 per symbol \(= H(p)\). Wrong code: \(8 \times 3 + 4 \times 1 + 2 \times 2 + 2 \times 3 = 38\) bits, 2.375 per symbol, the cross-entropy \(H(p, q)\): frequencies from one distribution, code lengths from the other. The difference, 0.625 bits per symbol, is the Kullback-Leibler divergence (or relative entropy) \(D_{\mathrm{KL}}(p \Vert q)\). Every probability here is a power of one half, so the equality is exact.

\[ H(p, q) = -\sum_x p(x) \log q(x), \qquad D_{\mathrm{KL}}(p \,\Vert\, q) = \sum_x p(x) \log \frac{p(x)}{q(x)} = H(p, q) - H(p) \]

The identity is one line: split \(\log \frac{p}{q} = -\log q + \log p\) and average under \(p\). The weather agrees: a forecaster who swaps sun and cloud builds cloud 0, sun 10, rain 11, and the real weather costs 1.75 bits a day, \(= 1.5 + 0.25\). The ratio \(p(x)/q(x)\) is the likelihood ratio; the sum runs over outcomes with \(p(x) \gt 0\), and if \(q(x) = 0\) for any of them the divergence is infinite.

The training loss is a cross-entropy, so training minimises a KL

With \(n\) examples \((x_i, y_i)\), use the empirical distribution (each example gets \(1/n\)) as \(p\) and the model \(q_\theta(y \mid x)\) as \(q\). A one-hot target multiplies every term of \(-\sum_y p(y) \log q(y)\) by 0 except the true label, leaving the negative log-likelihood

\[ \mathcal{L}(\theta) = -\frac{1}{n}\sum_{i=1}^{n} \log q_\theta(y_i \mid x_i) = H(\hat p) + D_{\mathrm{KL}}(\hat p \,\Vert\, q_\theta) \]

Minimising it maximises \(\prod_i q_\theta(y_i \mid x_i)\): cross-entropy minimisation is maximum-likelihood estimation (the {{Probability page|n:3c65c17b0d0d815f9a47d613409b5a0c}} arrives at the same loss from the likelihood side), and because \(H(\hat p)\) does not depend on \(\theta\), it is exactly minimising \(D_{\mathrm{KL}}(\text{data} \Vert \text{model})\); the loss can never go below the data's own entropy. For the tiny model with the one-hot target sat, \(H(p) = 0\) and all 2.408 nats are KL. In nats, a correct-class probability of 0.7 costs 0.357 (0.515 bits), 0.99 costs 0.010, and 0.01 costs 4.61: the loss grows without bound, so a few confidently wrong examples can dominate a batch.

Soft targets (a teacher's probabilities, label smoothing) keep the full sum, and its minimum is \(H(p)\), not 0. Say the data after "the cat" were sat 0.8, dog 0.2 illustrative: against the tiny model \(H(p, q) = 2.207\) nats, of which \(H(p) = 0.500\) is the target's own entropy and 1.707 is removable. Cross-entropy and KL have the same gradient in the model (they differ by \(H(p)\)), "prediction minus target" \(q - p\) on the scores (derived on the {{Calculus and optimisation for ML, section 2|n:3c65c17b0d0d81eb8b49ed6a0f897f3b}}), but not the same value: report KL for "distance from the target", cross-entropy for "compressed length".

Binary cross-entropy, logits, and why cross-entropy rewards calibration
Binary cross-entropy, \(-y \ln \hat y - (1 - y)\ln(1 - \hat y)\), is the two-outcome case; PyTorch's BCEWithLogitsLoss and CrossEntropyLoss take logits so they can compute the log of a softmax stably. Cross-entropy is also a proper scoring rule: its expected value is minimised only by reporting the true probabilities, which pushes a model towards calibration, not just correct rankings ({{Evaluation metrics|n:3c65c17b0d0d81a29acef722e842a29b}}). Cross-entropy among the other losses, with label smoothing and focal loss, is on {{Loss functions|n:3c65c17b0d0d8161a72bc8c572f37d55}}.

Never negative, and not a distance

\(D_{\mathrm{KL}}(p \Vert q) \ge 0\), with equality only when \(q = p\) (Gibbs' inequality): on average you cannot beat the truth's own code. MacKay calls it "probably the most important inequality in this book" (§2.6, eq. 2.46); every "\(\ge\)" on this page (entropy below \(\log K\), conditioning reduces entropy, mutual information is non-negative, data processing, the ELBO) comes from it. It is not symmetric: a fair coin \(p = (0.5, 0.5)\) against a model \(q = (0.9, 0.1)\) gives \(D_{\mathrm{KL}}(p \Vert q) = 0.737\) bits but \(D_{\mathrm{KL}}(q \Vert p) = 0.531\); the stream above gives 0.625 one way and 0.5 the other; the weather gives 0.25 both ways only because \(q\) is \(p\) with two outcomes swapped. With no symmetry and no triangle inequality it is not a metric, despite the name "KL distance" (MacKay: it "is not strictly a distance"). Section 4 shows the direction changes the answer. Try your own pairs in the {{Entropy and KL lab|#t-lab}}.

Zero probability means infinite cost
A model that gives probability exactly 0 to something that happens has \(-\log 0 = \infty\): infinite cross-entropy and infinite forward KL. A softmax never outputs an exact 0 in exact arithmetic, but \(\log(\mathrm{softmax}(z))\) in floating point can underflow to \(\log 0\), which is why frameworks compute log_softmax directly as \(z_i - \log \sum_j e^{z_j}\) with the maximum subtracted ({{Numerical computing|n:3f05c17b0d0d81d6af0be4a9a2edba8d}}).
Proof that KL is never negative (Jensen's inequality)

Jensen: for a convex function \(f\) (curving upwards, like \(-\log u\)), \(\mathbb{E}[f(U)] \ge f(\mathbb{E}[U])\); the chord between two points of a bowl lies above the curve, and equality needs \(U\) constant. The same proof as MacKay's solution to exercise 2.26:

  1. Let \(U = q(x)/p(x)\) with \(x \sim p\), and \(f(u) = -\log u\). Then \(D_{\mathrm{KL}}(p \Vert q) = \mathbb{E}[f(U)]\).
  2. Jensen: \(\mathbb{E}[f(U)] \ge -\log \mathbb{E}_p\big[\tfrac{q(x)}{p(x)}\big]\).
  3. \(\mathbb{E}_p\big[\tfrac{q(x)}{p(x)}\big] = \sum_{x: p(x) \gt 0} q(x) \le 1\), so \(D_{\mathrm{KL}} \ge -\log(\text{something} \le 1) \ge 0\).
  4. Equality needs \(q/p\) constant and \(\sum q = 1\) on the support of \(p\): \(q = p\).
Where KL shows up in ML
The removable part of every log-loss; KL penalties that keep a fine-tuned model near its reference (section 10); the ELBO of VAEs and diffusion models (section 10 and {{Variational inference and generative-model maths|n:3f05c17b0d0d81aa9857eb5fa1bac530}}); trust regions in RL (TRPO constrains a KL between old and new policies); knowledge distillation (section 5).
