6. KL divergence: the bits you waste

The question. Cross-entropy mixes two things: how unpredictable the data is, and how wrong the model is. How do you separate them, and why can the second never be negative?

The picture: one stream, two codes

Sixteen symbols drawn from \(p\) = (A 1/2, B 1/4, C 1/8, D 1/8), in exactly those proportions. The top strip encodes them with the code built for \(p\) (A 0, B 10, C 110, D 111); the bottom strip encodes the same symbols with a code built for a wrong guess \(q\) = (A 1/8, B 1/2, C 1/4, D 1/8) (A 110, B 0, C 10, D 111). Every bit is drawn to the same scale. Watch the gap per symbol settle.

The numbers
Own code: \(8 \times 1 + 4 \times 2 + 2 \times 3 + 2 \times 3 = 28\) bits, 1.75 bits per symbol \(= H(p)\). Wrong code: \(8 \times 3 + 4 \times 1 + 2 \times 2 + 2 \times 3 = 38\) bits, 2.375 bits per symbol \(= H(p, q)\). The difference, \(0.625\) bits per symbol, is exactly \(D_{\mathrm{KL}}(p \Vert q)\). Every probability here is a power of one half, so the code lengths are exactly \(-\log_2\) of them and the equality is exact, not approximate.

The words, then the formula

The Kullback-Leibler divergence (or relative entropy) from \(q\) to \(p\) is the average extra surprise, or extra code length, paid for using \(q\) when the truth is \(p\):

\[ D_{\mathrm{KL}}(p \,\Vert\, q) = \sum_x p(x) \log \frac{p(x)}{q(x)} = \mathbb{E}_{x \sim p}\!\left[\log \frac{p(x)}{q(x)}\right] \]
\(\frac{p(x)}{q(x)}\)
the likelihood ratio: how many times more probable the truth makes \(x\) than the model does.
\(\Vert\)
a separator, read "from \(q\) to \(p\)" or "of \(p\) from \(q\)". The order matters.
the sum
runs over outcomes with \(p(x) > 0\); if \(q(x) = 0\) for any of them, the divergence is infinite.
Cross-entropy = entropy + KL, in three lines.
  1. Split the log of a ratio: \(\log \frac{p(x)}{q(x)} = -\log q(x) - \big(-\log p(x)\big)\).
  2. Average both sides under \(p\): \(D_{\mathrm{KL}}(p \Vert q) = \mathbb{E}_p[-\log q(x)] - \mathbb{E}_p[-\log p(x)]\) \(= H(p, q) - H(p)\).
  3. Rearranged: \(H(p, q) = H(p) + D_{\mathrm{KL}}(p \Vert q)\). Weather: \(1.75 = 1.5 + 0.25\). Stream above: \(2.375 = 1.75 + 0.625\).

Why KL is never negative: Gibbs' inequality, via Jensen

Jensen's inequality says: for a convex function \(f\) (curving upwards, like \(-\log u\)), the average of \(f\) is at least \(f\) of the average, \(\mathbb{E}[f(U)] \ge f(\mathbb{E}[U])\). Picture two points on a bowl-shaped curve: the straight chord between them lies above the curve, and the average of the two heights is a point on the chord. Equality needs \(U\) to be constant (or \(f\) to be straight there).

Proof that \(D_{\mathrm{KL}}(p \Vert q) \ge 0\) (the same proof as MacKay's solution to exercise 2.26):
  1. Let \(U = q(x)/p(x)\) with \(x \sim p\), and \(f(u) = -\log u\), which is convex.
  2. Then \(D_{\mathrm{KL}}(p \Vert q) = \mathbb{E}_p\big[-\log \tfrac{q(x)}{p(x)}\big] = \mathbb{E}[f(U)]\).
  3. Jensen: \(\mathbb{E}[f(U)] \ge f(\mathbb{E}[U]) = -\log \mathbb{E}_p\big[\tfrac{q(x)}{p(x)}\big]\).
  4. The average inside: \(\mathbb{E}_p\big[\tfrac{q(x)}{p(x)}\big] = \sum_{x: p(x) > 0} p(x) \tfrac{q(x)}{p(x)}\) \(= \sum_{x: p(x) > 0} q(x) \le 1\).
  5. So \(D_{\mathrm{KL}}(p \Vert q) \ge -\log(\text{something} \le 1) \ge 0\). Equality needs \(q(x)/p(x)\) constant and \(\sum q = 1\) over the support of \(p\): that is, \(q = p\).

In plain words: you cannot, on average, beat the truth's own code. MacKay calls this "probably the most important inequality in this book" (§2.6, eq. 2.46). Every "\(\ge\)" on this page (entropy below \(\log K\), conditioning reduces entropy, mutual information is non-negative, the data processing inequality, the ELBO) comes from it.

Not a distance: the order matters

Worked examples
  • Weather: \(D_{\mathrm{KL}}(p \Vert q) = 0.5 \log_2 \tfrac{0.5}{0.25} + 0.25 \log_2 \tfrac{0.25}{0.5} + 0.25 \log_2 1\) \(= 0.5 - 0.25 + 0 = 0.25\) bits. The reverse direction is also 0.25, but only because \(q\) is \(p\) with two outcomes swapped.
  • A fair coin \(p = (0.5, 0.5)\) against a model \(q = (0.9, 0.1)\): \(D_{\mathrm{KL}}(p \Vert q) = 0.737\) bits but \(D_{\mathrm{KL}}(q \Vert p) = 0.531\) bits.
  • The stream above: \(D_{\mathrm{KL}}(p \Vert q) = 0.625\) bits; \(D_{\mathrm{KL}}(q \Vert p) = 0.5\) bits.

KL is not symmetric and has no triangle inequality, so it is not a metric, despite the occasional name "KL distance" (MacKay notes it "is not strictly a distance"). Section 7 shows that the direction you minimise changes the answer, and section 12 gives symmetric relatives.

Zero probability means infinite cost
If the model gives probability exactly 0 to something that happens, \(-\log 0 = \infty\): infinite cross-entropy and infinite forward KL. A softmax never outputs an exact 0 in exact arithmetic, but \(\log(\mathrm{softmax}(z))\) computed in floating point can underflow to \(\log 0\). That is why frameworks compute log_softmax directly as \(z_i - \log \sum_j e^{z_j}\) with the max subtracted ({{Numerical computing|n:3f05c17b0d0d81d6af0be4a9a2edba8d}}).

The loss floor, in one line

Write the training loss as \(H(p, q_\theta) = H(p) + D_{\mathrm{KL}}(p \Vert q_\theta)\). \(H(p)\) does not depend on \(\theta\). So minimising cross-entropy over the parameters is exactly minimising \(D_{\mathrm{KL}}(\text{data} \Vert \text{model})\), and the loss can never go below the data's own entropy. For the tiny model with the one-hot target sat, \(H(p) = 0\) and all 2.408 nats are KL: all of it could be removed. On real text it cannot (section 11).

What it is used for in ML
The removable part of every log-loss; KL penalties that keep a fine-tuned model near its reference (section 13); the ELBO of VAEs and diffusion models (section 13 and {{Variational inference and generative-model maths|n:3f05c17b0d0d81aa9857eb5fa1bac530}}); trust regions in RL (TRPO constrains a KL between old and new policies); knowledge distillation (KL from teacher to student).
