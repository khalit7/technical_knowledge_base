Statistics for ML, in one screen

Probability starts from a known distribution and asks what data it produces. Statistics runs the other way: it starts from data and asks what the distribution was, and how sure we can be. Every ML number you report (a validation loss, a benchmark accuracy, "B beats A by 2 points") is computed from a finite sample, so it is a random number: run the experiment again on fresh data and it changes. Statistics says by how much, and whether a difference is bigger than that wobble.

The running example is the one from {{Topic: math|n:3c65c17b0d0d81cdb851c0835b25a538}} and {{Probability for ML|n:3c65c17b0d0d815f9a47d613409b5a0c}}: a tiny language model whose bet for the word after "the cat" is \(p = (0.665, 0.245, 0.090)\) over cat, dog, sat. Sample a word from that bet and record the model's loss on it, \(-\ln p(\text{word})\): 0.408 if cat comes out, 1.408 for dog, 2.408 for sat. The average loss over many draws is the model's entropy, 0.832 nats, and here (unlike in real life) we know it exactly. So we can watch every statistical tool try to recover a number we already know, and count how often it succeeds.

The one idea to keep
A statistic is a random variable. Before believing any number, ask what it would have been on a different sample of the same size. The standard error answers that for averages; the bootstrap answers it for anything; a test asks whether an observed difference is larger than that answer.
