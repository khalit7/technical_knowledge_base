This tab is a workbench for the part of the Reading where the model learns: you compute a loss, derive its gradient by hand, check it against the computer, follow it backwards through the network, and watch what the learning rate does with it. Every number on this tab is computed live by the page and was checked against an independent script (numpy, sympy and PyTorch autograd).

The tiny model used everywhere on this tab

Vocabulary of three tokens: cat, dog, sat. After "the cat", the correct next token is sat. The context is turned into a vector of two numbers (its embedding) \(x = (2, 1)\), the same as in the Reading. The Reading's one-matrix model and the two-layer network used in panel 2 both turn it into three scores, one per token, called logits: \(z = (2, 1, 0)\) for (cat, dog, sat). The softmax turns logits into probabilities \(p = (0.665, 0.245, 0.090)\), and the loss is \(-\ln p_{\text{sat}} = -\ln 0.090 = 2.408\). The model gets it wrong: it bets on cat (66.5%) and gives the right answer only 9.0%. Training should move probability to sat.

The weights are illustrative, chosen so the logits come out exactly (2, 1, 0), the running example of the Reading. The two-layer network's weights \(W_1\) and \(W_2\) are shown in panel 2.

Words used throughout: a gradient is the list of slopes of the loss, one per input number: how much the loss changes per unit nudge of that number. An analytic gradient comes from a formula derived by hand; a numerical gradient is measured by nudging each number a tiny step \(h\) up and down and timing how the loss moves. If the two disagree, the formula (or the code) is wrong. The Reading derives these ideas from zero: see its derivatives section, {{Reading|#t-read}}.

1. Loss explorer: three losses, one gradient

Pick a loss, move the model's raw output with the sliders, and compare the gradient from the formula with the gradient measured by nudging. The striking fact to find: for the three standard pairings (a plain number with squared error, a sigmoid with binary cross-entropy, a softmax with cross-entropy) the gradient with respect to the raw output is the same expression, prediction minus target. The two extra losses show what happens when you change the recipe.

Mean squared error with an identity output. Use it when the target is a real number (a price, a temperature). The model's raw output \(z\) is used directly as the prediction, \(\hat y = z\) (the "identity" output: nothing is applied). The loss is half the squared miss:

\[ L = \tfrac{1}{2}(\hat y - y)^2, \qquad \hat y = z \]

In words: square how far the prediction is from the target \(y\), then halve it (the half is a convention that makes the derivative tidy).

  1. Chain rule: the loss depends on \(z\) through \(\hat y\), so multiply the two slopes: \[ \frac{\partial L}{\partial z} = \frac{\partial L}{\partial \hat y}\cdot\frac{\partial \hat y}{\partial z} \]
  2. Slope of \(\tfrac12 u^2\) is \(u\), so \(\frac{\partial L}{\partial \hat y} = \hat y - y\); and \(\hat y = z\) has slope 1.
  3. Multiply: \[ \frac{\partial L}{\partial z} = (\hat y - y)\cdot 1 = \hat y - y \quad\text{(prediction minus target)} \]

Without the half, \(L = (\hat y - y)^2\) and the gradient is \(2(\hat y - y)\). Averaged over a batch of \(n\) examples, \(L = \frac{1}{n}\sum_i (\hat y_i - y_i)^2\), each example's gradient is \(\frac{2}{n}(\hat y_i - y_i)\) (the old page's "times \(2/n\)" is this convention). Worked example: \(z = 1.5\), \(y = 1\): \(L = \tfrac12 (0.5)^2 = 0.125\), gradient \(0.5\).

Binary cross-entropy with a sigmoid. Use it for a yes/no target \(y \in \{0, 1\}\) (spam or not). The raw output \(z\) is squashed into a probability by the sigmoid, and the loss is the negative log of the probability given to what actually happened:

\[ p = \sigma(z) = \frac{1}{1 + e^{-z}}, \qquad L = -\big[\,y \ln p + (1 - y)\ln(1 - p)\,\big] \]

In words: if \(y = 1\) the loss is \(-\ln p\); if \(y = 0\) it is \(-\ln(1 - p)\). Only one of the two terms is ever switched on.

  1. Slope of the sigmoid. Write \(\sigma = (1 + e^{-z})^{-1}\); the chain rule gives \[ \sigma'(z) = \frac{e^{-z}}{(1 + e^{-z})^2} = \sigma(z)\,\big(1 - \sigma(z)\big) = p(1 - p) \]
  2. Slope of the loss in \(p\) (slope of \(\ln u\) is \(1/u\)): \[ \frac{\partial L}{\partial p} = -\frac{y}{p} + \frac{1 - y}{1 - p} \]
  3. Multiply the two and simplify; the \(p(1-p)\) cancels the denominators: \[ \frac{\partial L}{\partial z} = \Big(-\frac{y}{p} + \frac{1 - y}{1 - p}\Big)\,p(1 - p) = -y(1 - p) + (1 - y)\,p = p - y \]

Worked example: \(z = 2\), \(y = 1\): \(p = 0.881\), \(L = -\ln 0.881 = 0.127\), gradient \(0.881 - 1 = -0.119\) (negative: raising \(z\) lowers the loss).

Softmax cross-entropy. The loss of the tiny model: three logits \(z = (z_1, z_2, z_3)\), one per token, turned into probabilities by the softmax; the loss is minus the log of the probability of the correct token \(t\) (here cat):

\[ p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}, \qquad L = -\ln p_t = -z_t + \ln \sum_j e^{z_j} \]

In words: exponentiate every score (all become positive), divide by the total (they now sum to 1), and pay \(-\ln\) of the share the right answer got. The second form comes from \(\ln(a/b) = \ln a - \ln b\) and \(\ln e^{z_t} = z_t\).

  1. Differentiate the second form with respect to one logit \(z_i\). The first term \(-z_t\) has slope \(-1\) if \(i = t\) and 0 otherwise; write that as \(-y_i\), where \(y\) is the one-hot target (1 for the correct token, 0 elsewhere).
  2. The second term: slope of \(\ln S\) is \(1/S\), times the slope of \(S = \sum_j e^{z_j}\) in \(z_i\), which is \(e^{z_i}\): \[ \frac{\partial}{\partial z_i}\ln\sum_j e^{z_j} = \frac{e^{z_i}}{\sum_j e^{z_j}} = p_i \]
  3. Add: \[ \frac{\partial L}{\partial z_i} = p_i - y_i \quad\text{(prediction minus target, per token)} \]

Worked example at the default: \(e^{z} = (7.389, 2.718, 1)\), sum 11.107, \(p = (0.665, 0.245, 0.090)\), \(L = -\ln 0.090 = 2.408\) nats (3.473 bits), gradient \((0.665,\ 0.245,\ 0.090 - 1) = (0.665, 0.245, -0.910)\): push cat and dog down, sat up. The entries sum to zero, because both \(p\) and \(y\) sum to 1. The old page's "four hats" example uses the same logits with cat correct: \(L = -\ln 0.665 = 0.408\) nats (0.588 bits), gradient \((-0.335, 0.245, 0.090)\); the button below the sliders loads it.

Label-smoothed cross-entropy (Szegedy et al. 2016, section 7). Replace the one-hot target by a softened one that gives a little probability \(\varepsilon\) to every token: with \(K\) tokens,

\[ q_i = (1 - \varepsilon)\,y_i + \frac{\varepsilon}{K}, \qquad L = -\sum_i q_i \ln p_i = \ln\sum_j e^{z_j} - \sum_i q_i z_i \]

The second form uses \(\ln p_i = z_i - \ln\sum_j e^{z_j}\) and \(\sum_i q_i = 1\).

  1. Same steps as plain cross-entropy: the first term gives \(p_i\), the second gives \(-q_i\).
  2. \[ \frac{\partial L}{\partial z_i} = p_i - q_i \]

Still prediction minus target, only the target is the smoothed \(q\). The loss can no longer reach zero: its floor is the entropy of \(q\). Worked example (\(\varepsilon = 0.1\), \(K = 3\)): \(q = (0.033, 0.033, 0.933)\), \(L = 2.308\), gradient \((0.632, 0.211, -0.843)\).

Focal loss (Lin et al. 2017, written there for two classes; here the usual softmax form). It multiplies cross-entropy by \((1 - p_t)^{\gamma}\) so that examples the model already gets right count less:

\[ L = -(1 - p_t)^{\gamma}\,\ln p_t \]
  1. Slope in \(p_t\) (product rule on \((1-p_t)^\gamma\) times \(\ln p_t\)): \[ \frac{\partial L}{\partial p_t} = \gamma(1 - p_t)^{\gamma - 1}\ln p_t - \frac{(1 - p_t)^{\gamma}}{p_t} \]
  2. Slope of the softmax output \(p_t\) in a logit \(z_i\): \(\frac{\partial p_t}{\partial z_i} = p_t\,(y_i - p_i)\).
  3. Multiply and collect: \[ \frac{\partial L}{\partial z_i} = w\,(p_i - y_i), \qquad w = (1 - p_t)^{\gamma} - \gamma\,p_t\,(1 - p_t)^{\gamma - 1}\ln p_t \]

The direction is still \(p - y\), but scaled by a weight \(w\) that shrinks as the model gets confident (\(w = 1\) at \(\gamma = 0\), which is plain cross-entropy). It is not one of the canonical pairs, so the tidy cancellation is gone. Worked example (\(\gamma = 2\)) at the default, where the correct token gets only \(p_t = 0.090\): \(w = 1.223\), \(L = 1.994\), gradient \((0.813, 0.299, -1.112)\). Here \(w\) is above 1: on a badly wrong example focal loss pushes harder than plain cross-entropy; move the sat logit up and watch \(w\) fall below 1.

Numerical gradient: \(\frac{\partial L}{\partial z_i} \approx \frac{L(z + h e_i) - L(z - h e_i)}{2h}\), where \(e_i\) nudges only input \(i\). Its error has two parts: the formula's own error, which shrinks like \(h^2\), and rounding error from subtracting two nearly equal numbers, which grows like \(10^{-16}/h\) in the page's 64-bit arithmetic. The best \(h\) sits between, near \(10^{-5}\) to \(10^{-6}\) here, matching the \(h \approx 10^{-5}\) advice in CS231n's gradient-check notes.

Why three different losses end at the same gradient

Each standard pair is a probability distribution with its "canonical" output function: a Gaussian with the identity, a Bernoulli with the sigmoid, a categorical with the softmax. For every such pair the slope of the output function cancels the slope of the log-likelihood exactly, leaving prediction minus target (Stanford CS229's generalised linear models chapter, main notes). Practical reading: a softmax followed by cross-entropy should never be coded as two separate steps, since the combined gradient \(p - y\) is both simpler and safer (see panels 5 and 6).

2. Backprop, step by step: the chain rule run backwards

Two versions of the model, both giving the same logits (2, 1, 0). The Reading's model is one matrix: \(z = Wx\), then softmax and the loss, with \(W\) rows cat (1, 0), dog (0, 1), sat (1, \(-2\)). Its backward pass is \(\bar z = p - y\), \(\bar W = \bar z\,x^{\top}\), \(\bar x = W^{\top}\bar z\), and one step at learning rate 0.1 takes the loss from 2.408 to 1.773, as in the Reading. The two-layer network below adds a hidden layer with a relu, which shows what a nonlinearity does to the backward pass. Its chain has five simple steps. The forward pass computes each value from the one before. The backward pass then walks the chain in reverse, and at each step asks one question: "if this value moved a little, how much would the loss move?" That number is the value's gradient. Each backward step only needs the gradient of the step after it and the local slope of its own operation; this product is called a vector-Jacobian product (VJP), the Jacobian being the table of local slopes, which is never built in full.

\[ \begin{aligned} a &= W_1 x, & h &= \operatorname{relu}(a), & z &= W_2 h, \\ p &= \operatorname{softmax}(z), & L &= -\ln p_{\text{sat}} \end{aligned} \]

\(x\): the embedding of "the cat" (2 numbers). \(W_1\): first weight matrix (3 rows, 2 columns), so \(a\) has 3 numbers. \(\operatorname{relu}(a) = \max(0, a)\) element by element: negative values become 0. \(W_2\): second weight matrix (3 by 3). Gradients are written \(\bar v = \partial L / \partial v\) ("v-bar"), with the same shape as \(v\).

\[ \begin{aligned} \bar z &= p - y \\ \bar W_2 &= \bar z\, h^{\top}, & \bar h &= W_2^{\top}\bar z \\ \bar a &= \bar h \odot [a > 0] \\ \bar W_1 &= \bar a\, x^{\top}, & \bar x &= W_1^{\top}\bar a \end{aligned} \]

\(\top\) is the transpose (rows become columns), \(\odot\) multiplies element by element, \([a > 0]\) is 1 where \(a\) is positive and 0 elsewhere. A matrix's gradient is always (gradient coming in) times (input that went in), transposed into the matrix's shape; an input's gradient is the matrix, transposed, times the gradient coming in. Each matrix product in the forward pass therefore becomes two in the backward pass.


Multiply-add count: a matrix with \(r\) rows and \(c\) columns costs \(r \times c\) multiply-adds to apply. The Reading's model: forward \(Wx\) is 6; backward \(\bar W\) 6 and \(\bar x\) 6, total 12, twice forward (6 if the embedding is held fixed). Two layers: forward \(W_1 x\) is 6, \(W_2 h\) is 9, total 15. Backward: \(\bar W_2\) 9, \(\bar h\) 9, \(\bar W_1\) 6, \(\bar x\) 6, total 30, exactly twice; 24 if the input is not trained (the first layer then needs no input gradient). Softmax, relu and the loss are a handful of extra operations, not counted. This factor of two is why training compute is usually counted as \(6N\) per token for a model with \(N\) parameters: \(2N\) forward and \(4N\) backward (Kaplan et al. 2020, section 2.1). The backward pass also needs the forward values (\(x\), \(a\), \(h\), \(p\)) kept in memory, which is why activations, not arithmetic, usually limit training memory.

3. Curvature and step size: why the learning rate has a ceiling

Close to a minimum, almost any loss looks like a bowl. With two parameters \(\theta = (\theta_1, \theta_2)\) the bowl is

\[ L(\theta) = \tfrac12\,\theta^{\top} H\,\theta, \qquad \nabla L = H\theta, \qquad \text{gradient descent: } \theta \leftarrow \theta - \eta\,H\theta \]

\(H\) is the Hessian, the 2 by 2 table of second derivatives (how fast each slope changes): it measures curvature. Its eigenvalues \(\lambda_{\max}\) and \(\lambda_{\min}\) are the curvatures along the bowl's steepest and flattest directions (the axes of the ellipses below), and \(\kappa = \lambda_{\max}/\lambda_{\min}\) is the condition number. \(\eta\) is the learning rate. Along a direction of curvature \(\lambda\), one step multiplies the distance to the minimum by \(1 - \eta\lambda\). So that direction shrinks smoothly if \(\eta\lambda < 1\), overshoots and flips side each step if \(1 < \eta\lambda < 2\), and grows (diverges) if \(\eta\lambda > 2\): the learning rate must stay below \(2/\lambda_{\max}\). Meanwhile the flat direction shrinks only by \(1 - \eta\lambda_{\min}\) per step, which is why a large \(\kappa\) means slow progress (Goh 2017, Why Momentum Really Works).

The same limit on the tiny model: at the Reading's starting point the steepest curvature of the loss along the weights \(W\) is \(\lambda_{\max} = 1.855\) (the largest eigenvalue of \(\operatorname{diag}(p) - pp^{\top}\), times \(\lVert x\rVert^2 = 5\)), so the local limit is about \(2/1.855 = 1.08\). The learning rates 0.1, 0.3 and 1 in panel 2 all sit below it (one step each: loss 1.773, 0.778, 0.011). It is a local limit: the curvature changes as the weights move.

Momentum keeps a running velocity, \(v \leftarrow \beta v - \eta\nabla L\), \(\theta \leftarrow \theta + v\) (\(\beta = 0.9\) here): steps that agree add up along the flat direction, steps that flip sign cancel across the steep one. On a bowl it is stable up to \(\eta\lambda < 2(1 + \beta) = 3.8\) (Goh 2017). Adam (Kingma and Ba 2014, defaults \(\beta_1 = 0.9\), \(\beta_2 = 0.999\)) divides each coordinate's averaged gradient by the root of its averaged square, so every coordinate moves by about \(\eta\) per step whatever its curvature. Intuition only: that evens out a valley lined up with the axes, helps less when the valley is diagonal (try the rotation slider), and is a rough per-coordinate scale, not a curvature estimate. Newton's method uses the curvature itself: step \(-H^{-1}\nabla L\), which on an exact bowl lands on the minimum in one step whatever \(\kappa\) is (Boyd and Vandenberghe, section 9.5); for a network with \(N\) parameters, \(H\) has \(N^2\) entries, which is why it is not used directly.

4. Bernoulli curvature: one number, three meanings

Take the binary cross-entropy of panel 1 and ask three different-sounding questions about it. The answer to all three is \(p(1 - p)\), where \(p = \sigma(z)\). The page computes each one by its own route (no shared formula), so the agreement below is a check, not a copy.

  • Curvature (Hessian): the second derivative of the loss in \(z\), measured by nudging \(z\) both ways: \(\frac{L(z+h) - 2L(z) + L(z-h)}{h^2}\). Done separately for \(y = 1\) and \(y = 0\): the label does not matter.
  • Variance of the label: if the label really is a coin with \(P(y = 1) = p\), its spread around its mean \(p\) is \(p\,(1-p)^2 + (1-p)\,(0-p)^2\), summed over the two outcomes.
  • Fisher information: the average squared score, the score being the slope of the log-likelihood in \(z\) (measured by nudging, for each outcome), averaged with weights \(p\) and \(1 - p\).

At \(z = 0\) all three are 0.25, the largest they get; at \(z = \ln 9 = 2.197\) (\(p = 0.9\)) all three are 0.09 (both values from the old page, recomputed). A confident prediction sits in a flat part of the loss: the gradient there barely changes as \(z\) moves. That curvature equals Fisher information for every canonical pair (the label drops out of the second derivative) is why natural-gradient methods and K-FAC can use the Fisher as their curvature: for the whole network it equals the Gauss-Newton form of the Hessian (Martens 2020, section 9.2).

5. Overflow and the log-sum-exp trick

Computers store numbers with a largest value. \(e^{z}\) passes it at \(z = 709.78\) in 64-bit floats, \(z = 88.72\) in 32-bit floats and \(z = 11.09\) in 16-bit floats (each is \(\ln\) of the format's largest number). Past it the computer returns infinity, and infinity divided by infinity is "not a number" (NaN). The fix uses a fact about the softmax: adding the same constant to every logit changes nothing, because \(e^{z_i - m} / \sum_j e^{z_j - m} = e^{z_i}/\sum_j e^{z_j}\) (the \(e^{-m}\) cancels). Subtract the largest logit \(m\) first, so the biggest exponent is \(e^0 = 1\):

\[ \ln\sum_j e^{z_j} = m + \ln\sum_j e^{z_j - m}, \qquad m = \max_j z_j \]

32-bit results are emulated by rounding every intermediate to 32 bits (JavaScript's Math.fround). The libraries do this for you only if you call the fused function: PyTorch's CrossEntropyLoss takes "unnormalized logits" (its docstring), and BCEWithLogitsLoss is "more numerically stable than using a plain Sigmoid followed by a BCELoss" because it uses "the log-sum-exp trick" (same file). Error analysis: Blanchard, Higham and Higham 2021.

6. Spot the bug: eight real gradient bugs and the symptom each leaves

Debugging runs from the symptom back to the line. Each card shows a symptom, produced live by running the buggy code's maths on the tiny model, and a short piece of code (numpy or PyTorch style).
