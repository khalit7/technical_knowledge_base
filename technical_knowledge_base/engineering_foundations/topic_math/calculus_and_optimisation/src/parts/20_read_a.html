Calculus and optimisation in one screen

About 45 minutes for the main line (about 10,500 words); the collapsible derivations add about 8 more. Every section can be read alone, and every symbol is defined where it first appears. Worked numbers come from the root page's tiny model (input \(x = (2, 1)\), weight rows cat \((1, 0)\), dog \((0, 1)\), sat \((1, -2)\), scores \(z = (2, 1, 0)\), true next word sat, loss 2.408), from small functions you can check by hand, and from two real runs made for this page: logistic regression on a real medical dataset, and a small neural network whose curvature is measured while it trains. All are recomputed by the scripts in this page's source folder.

A gradient is a local straight-line model of the loss; a Hessian is a local bowl-shaped model; every optimiser is a rule for how far to trust that model. Gradient descent trusts the straight line for a small step. Newton's method jumps to the bottom of the bowl. Momentum, Adam, L-BFGS and trust regions are compromises between the two, and convexity and constraints say when the answer they find is the right one.

The one idea to keep
Write the loss near where you stand as a Taylor model: \(L(\theta + \delta) \approx L(\theta) + g^\top \delta + \tfrac12 \delta^\top H \delta\). Every section of this page reads off something from it: which way is down (\(g\)), how sharply it curves (\(H\)), how big a step is safe (\(2/\lambda_{\max}\)), and where the bottom is (\(-H^{-1}g\)).
