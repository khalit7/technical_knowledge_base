Common mistakes

Mixing layouts inside one derivation.
Writing the chain rule in numerator layout and plugging in a gradient shaped like the parameter puts transposes in the wrong places. Pick one layout, and check every result's shape against the parameter (section 3).
A custom backward that ignores the incoming gradient.
A VJP must multiply by \(\bar y\). The bug is invisible when the function is the last step before .sum().backward() and wrong everywhere else; gradcheck catches it (section 11).
"Backward costs the same as forward."
Twice the FLOPs for every matrix product (section 8), plus the memory of every stored activation, which is usually what runs out first (section 9).
"Checkpointing costs one whole extra forward pass."
At most one. Non-reentrant checkpointing stops recomputing early (20.8% extra FLOPs measured, against 33% for a full forward of the step), and selective recomputation of only the attention core costs 2 to 3% ({{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}).
Building a Jacobian you only need to multiply by.
Softmax's Jacobian is \(K \times K\); its VJP is \(O(K)\) (section 5c). The same holds for every layer: frameworks never form Jacobians during training, and hand-written code should not either.
Using forward mode, or finite differences, to get a training gradient.
Both need one pass per parameter. Reverse mode needs one pass in total (section 7).
Modifying a saved tensor in place.
PyTorch's version counter raises an error, but only when the backward pass reaches that node, far from the line that caused it. torch.autograd.set_detect_anomaly(True) reports the forward operation responsible.
Forgetting that gradients accumulate.
Without zero_grad() each step adds to the last step's gradient. Deliberate accumulation over micro-batches is the same mechanism, used on purpose (divide the loss by the number of micro-batches).
Gradient-checking in float32.
A correct function fails. Check in float64 with central differences, away from kinks (section 11).
Breaking the graph without noticing.
.detach(), .item(), .numpy(), in-place writes to .data, and integer operations such as argmax and rounding all stop gradients: the parameters before them silently get zero or no gradient. A straight-through estimator (a custom backward that passes \(\bar y\) through unchanged) is the deliberate version.
Mean against sum in the loss.
With reduction="mean" each example's gradient carries a factor \(1/B\) (5d). Switching to a sum multiplies every gradient by the batch size, which acts like multiplying the learning rate by it.

Where research is going

Most current work attacks the two costs of reverse mode, memory and the strict backward ordering.

  • Not storing activations at all. Reversible networks reconstruct each layer's input from its output during the backward pass: RevNet is "a variant of ResNets where each layer's activations can be reconstructed exactly from the next layer's", so "the activation storage requirements are independent of depth" ({{Gomez et al. 2017|https://arxiv.org/abs/1707.04585}}).
  • Differentiating a solution instead of the steps that found it. Implicit differentiation applies the implicit function theorem at a fixed point or an optimum. Deep equilibrium models "analytically backpropagate through the equilibrium point using implicit differentiation", so training needs "only constant memory, regardless of the effective "depth" of the network" ({{Bai, Kolter and Koltun 2019|https://arxiv.org/abs/1909.01377}}); JAXopt made the technique modular ({{Blondel et al. 2022|https://arxiv.org/abs/2105.15183}}).
  • Gradients from forward mode alone. The "forward gradient" multiplies a random direction \(v\) by the JVP along it: "an unbiased estimate of the gradient that can be evaluated in a single forward run of the function, entirely eliminating the need for backpropagation" ({{Baydin et al. 2022|https://arxiv.org/abs/2202.08587}}). The variance grows with the number of parameters, which is why it has not replaced backpropagation for large models.
  • Splitting the backward pass. Section 5a's two products, \(\bar X\) (needed immediately by the previous layer) and \(\bar W\) (needed only by the optimiser), can be scheduled separately. Zero Bubble pipeline parallelism does exactly this, "to split the backward computation into two parts, one that computes gradient for the input and another that computes for the parameters", to fill pipeline bubbles ({{Qi et al. 2023|https://arxiv.org/abs/2401.10241}}; see {{Distributed Training|n:3c65c17b0d0d8103a916c4824abbd82e}}).
  • Letting the compiler choose what to save. torch.compile traces forward and backward together (AOTAutograd) and decides which activations to save and which to recompute by a min-cut computation over the joint graph: "a min-cut based recomputation pass with AOTAutograd + NVFuser that consistently improves both memory and runtime" ({{He 2022, PyTorch developer forum|https://dev-discuss.pytorch.org/t/min-cut-optimal-recomputation-i-e-activation-checkpointing-with-aotautograd/467}}). Cheap elementwise operations are recomputed, matrix products and random operations are saved.
The five things to take away
1. A gradient has the shape of its parameter. 2. Every layer's backward is a vector-Jacobian product, derived by writing one entry with indices or by the trace trick. 3. Reverse mode gets every slope of one loss in one pass, for about twice the forward FLOPs. 4. The price is stored activations; checkpointing buys memory back with recomputation. 5. Curvature is available as Hessian-vector products, at the cost of a gradient or two.
