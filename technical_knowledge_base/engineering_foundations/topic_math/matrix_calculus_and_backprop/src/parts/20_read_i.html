7. Automatic differentiation: forward mode against reverse mode

The question. A model has billions of parameters and one loss. How does a computer get all the slopes, exactly, for the price of a few forward passes?

Three ways to get a derivative

  • Symbolic: manipulate the formula, as in a computer algebra system. Exact, but the expression for a deep network's derivative grows explosively, and code with loops and branches has no single formula.
  • Numerical: finite differences, \((f(x + h) - f(x - h))/2h\). Easy, but approximate (section 11), and it needs two evaluations per input: \(2n\) forward passes for \(n\) parameters.
  • Automatic differentiation (AD, or autodiff): run the program, and apply the chain rule to each primitive operation as it runs, using that operation's known local derivative. Exact up to floating-point rounding, works through loops and branches, and costs a small multiple of one evaluation. The standard survey states the bound: computing the \(m \times n\) Jacobian costs "\(n\,c\,\text{ops}(f)\)" in forward mode and "\(m\,c\,\text{ops}(f)\)" in reverse mode, "where c is a constant guaranteed to be c < 6 and typically c ∼ [2, 3]" ({{Baydin et al. 2018, section 3.2, p. 13|https://arxiv.org/abs/1502.05767}}, citing Griewank and Walther 2008). Griewank calls the reverse-mode case, a gradient at a small constant multiple of the function's cost whatever \(n\), the "Cheap Gradient Principle", and adds that "there is no corresponding Cheap Jacobian Principle" ({{Griewank 2012, p. 391|https://ftp.gwdg.de/pub/misc/EMIS/journals/DMJDMV/vol-ismp/52_griewank-andreas-b.pdf}}).

AD sees a program as a computational graph: nodes are values, edges are primitive operations (a matrix product, an exponential, a sum), each with a known local derivative. The tiny model's graph is a chain: \(W, x \to z = Wx \to p = \operatorname{softmax}(z) \to L = -\ln p_{\text{sat}}\). The chain rule of section 4 says the derivative is a product of the local Jacobians; the two modes of AD are the two orders of multiplying it out.

Forward mode: Jacobian-vector products

Pick one input direction \(u\) and carry a tangent \(\dot v\) (how fast each value changes along \(u\)) alongside every value, in the same order as the computation: \(\dot z = J_1 u\), \(\dot p = J_2 \dot z\), ... One pass gives \(Ju\): how every output changes along one input direction. A full gradient over \(n\) inputs needs \(n\) passes.

Reverse mode: vector-Jacobian products

Run forward once, keeping what each local derivative will need. Then carry an adjoint \(\bar v\) (the gradient of one output with respect to \(v\)) backwards from that output: \(\bar p\), then \(\bar z = J_2^\top \bar p\), then \(\bar W\) and \(\bar x\). One backward pass gives the slope of one output with respect to every input. Backpropagation is reverse mode applied to a loss.

Forward mode has a neat algebraic form: dual numbers \(a + b\varepsilon\) with the rule \(\varepsilon^2 = 0\). Then \(f(a + b\varepsilon) = f(a) + f'(a)\,b\,\varepsilon\) for any smooth \(f\) (the Taylor series stops after the linear term), so evaluating with dual numbers carries the derivative along for free. PyTorch exposes it as torch.func.jvp and dual tensors in torch.autograd.forward_ad; JAX as jax.jvp.

Multiply-adds counted the same way in both modes: applying a matrix with \(r\) rows and \(c\) columns costs \(r \times c\); the forward pass that computes \(z\), \(p\) and \(L\) is shared and not counted. Why reverse mode wins for training, and when it does not

For \(f: \mathbb{R}^n \to \mathbb{R}^m\), the whole Jacobian costs \(n\) forward-mode passes or \(m\) reverse-mode passes, so the cheaper mode is the one whose count is smaller. Training has \(m = 1\) (one loss) and \(n\) in the billions: reverse mode, by a factor of \(n\). Forward mode wins when inputs are few and outputs many, for example the sensitivity of every output of a simulation to one hyperparameter. The price of reverse mode is memory. The backward sweep runs in the opposite order to the computation, so every value a local derivative needs must still exist when the sweep reaches it: it has to be stored during the forward pass, or recomputed. Forward mode carries its tangent along and can forget each value at once. Sections 8 and 9 measure both costs.

A little history
"Forward mode AD as a general method for evaluating partial derivatives was essentially discovered by Wengert (1964)"; the work of "Linnainmaa (1970, 1976) is often cited as the first published description of the reverse mode"; in machine learning it "has been reinvented several times ... until it was eventually brought to fame by Rumelhart et al. (1986)" ({{Baydin et al. 2018, section 3.3|https://arxiv.org/abs/1502.05767}}). Griewank's history adds that Ostrowski used the reverse idea some five years before Linnainmaa, in chemical engineering ({{Griewank 2012, p. 389|https://ftp.gwdg.de/pub/misc/EMIS/journals/DMJDMV/vol-ismp/52_griewank-andreas-b.pdf}}). As Baydin et al. put it, "the backpropagation algorithm is only a special case of AD" (section 4.2).
