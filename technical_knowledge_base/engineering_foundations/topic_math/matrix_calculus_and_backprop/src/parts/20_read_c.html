3. The chain rule as a product of Jacobians

Let \(y = g(x)\) and \(z = f(y)\). A small step \(\delta x\) moves \(y\) by about \(J_g\,\delta x\), and that moves \(z\) by about \(J_f\) times it:

\[ \delta z \approx J_f\,J_g\,\delta x \qquad\Longrightarrow\qquad J_{f \circ g}(x) = J_f\big(g(x)\big)\; J_g(x) \]

The Jacobian of a chain is the product of the Jacobians, in the order of the chain; entry by entry, \(\frac{\partial z_i}{\partial x_k} = \sum_j \frac{\partial z_i}{\partial y_j}\frac{\partial y_j}{\partial x_k}\), the effect of \(x_k\) on \(z_i\) through every intermediate \(y_j\). The shapes line up by themselves, \((m \times p)\) times \((p \times n)\), and \(J_f\) is evaluated at the value \(y\) that \(g\) actually produced, which is why the backward pass needs the forward pass's values.

For a scalar loss the last Jacobian is a single row, \(\partial L/\partial y\). Written as gradients shaped like the variables, the chain rule becomes the vector-Jacobian product:

\[ \bar x = J^\top \bar y \qquad\text{(row form: } \tfrac{\partial L}{\partial x} = \tfrac{\partial L}{\partial y}\,J \text{)}, \qquad \bar v := \nabla_v L \text{, shaped like } v \]
The tiny model: from the scores back to the input
\(\bar z = p - y = (0.665, 0.245, -0.910)\) and \(J = W\), so \(\bar x = W^\top \bar z\): \(1 \times 0.665 + 0 \times 0.245 + 1 \times (-0.910) = -0.245\) and \(0 \times 0.665 + 1 \times 0.245 + (-2) \times (-0.910) = 2.065\), so \(\bar x = (-0.245, 2.065)\). One step further back, from the loss to the probabilities to the scores: \(\bar p = (0, 0, -1/p_{\text{sat}}) = (0, 0, -11.107)\), and \(\bar z = J_{\text{softmax}}^\top \bar p\) is \(-11.107\) times the sat column of section 1's table: \(-11.107 \times (-0.0599, -0.0220, 0.0819)\) \(= (0.665, 0.245, -0.910)\). The famous "prediction minus target" is just two VJPs multiplied out.

Order matters: multiply from the loss end. For \(k\) layers, \(\frac{\partial L}{\partial x} = \frac{\partial L}{\partial h_k} J_k J_{k-1} \cdots J_1\). Any bracketing gives the same answer, not the same cost. From the loss end every product is a row times a matrix: \(d^2\) multiply-adds for width \(d\), \(k d^2\) in all. From the input end every product is a matrix times a matrix, \(d^3\) each: at \(d = 4096\) a factor of 4096 more. Section 4 turns the two orders into the two modes of automatic differentiation.

Several paths: gradients add. When one value feeds two places, the sum over intermediates becomes a sum over paths:

  • A residual connection \(y = x + F(x)\) has Jacobian \(I + J_F\), so \(\bar x = \bar y + J_F^\top \bar y\): the gradient arrives once through the identity path, untouched, and once through the block. That untouched copy is why very deep residual networks still train (section 10).
  • A weight used twice, such as an embedding tied to the output layer, gets the sum of the gradients from both uses. In PyTorch's graph of a transformer block (section 12), the embedding's accumulator is the very last node the engine runs, because it waits for both contributions.

4. Forward mode against reverse mode: why reverse wins for one loss

Automatic differentiation (AD) sees a program as a computational graph of primitive operations (a matrix product, an exponential, a sum), runs it, and applies the chain rule to each primitive operation as it runs, using that operation's known local derivative: exact up to rounding, works through loops and branches, and costs a small multiple of one evaluation. (Symbolic differentiation blows up in size and has no formula for code with branches; finite differences are approximate and need two evaluations per input, section 11.) The two modes are the two orders of section 3:

Forward mode: Jacobian-vector products

Pick one input direction \(u\) and carry a tangent \(\dot v\) (how fast each value changes along \(u\)) alongside every value, in the order of the computation: \(\dot z = J_1 u\), \(\dot p = J_2 \dot z\), ... One pass gives \(Ju\): how every output changes along one input direction. A full gradient over \(n\) inputs needs \(n\) passes.

Reverse mode: vector-Jacobian products

Run forward once, keeping what each local derivative will need. Then carry an adjoint \(\bar v\) backwards from one output: \(\bar p\), then \(\bar z = J_2^\top \bar p\), then \(\bar W\) and \(\bar x\). One backward pass gives the slope of one output with respect to every input. Backpropagation is reverse mode applied to a loss.
Predict: the tiny model has six weights. How many sweeps does each mode need for all six slopes, and how many multiply-adds? Then step through both.

Forward mode needs a sweep per weight; reverse mode one sweep for all

Multiply-adds counted the same way in both modes: applying a matrix with \(r\) rows and \(c\) columns costs \(r \times c\); the shared forward pass is not counted. Forward mode: 16 per sweep, 96 for six; reverse mode: 16 for \(\bar W\), 6 more for \(\bar x\). Values from parts/22b_js_core.js, checked against src/recompute.py.

The rule. For \(f: \mathbb{R}^n \to \mathbb{R}^m\) the whole Jacobian costs \(n\) forward-mode passes or \(m\) reverse-mode passes. The standard survey's bound: "\(n\,c\,\text{ops}(f)\)" in forward mode and "\(m\,c\,\text{ops}(f)\)" in reverse mode, "where c is a constant guaranteed to be c < 6 and typically c ∼ [2, 3]" ({{Baydin et al. 2018, section 3.2, p. 13|https://arxiv.org/abs/1502.05767}}, citing Griewank and Walther 2008). Training has \(m = 1\) and \(n\) in the billions, so reverse mode, by a factor of \(n\). Forward mode wins when inputs are few and outputs many, such as the sensitivity of every output of a simulation to one hyperparameter. The cheaper mode flips with the shape of the Jacobian

The price of reverse mode is memory. The backward sweep runs in the opposite order to the computation, so every value a local derivative needs must still exist when the sweep reaches it: stored during the forward pass, or recomputed. Forward mode carries its tangent along and can forget each value at once. Sections 8 and 9 measure both costs.

Dual numbers, JAX's cost notes, and a little history (2 min)

The cheap gradient principle. Griewank calls a gradient at a small constant multiple of the function's cost, whatever \(n\), the "Cheap Gradient Principle", and adds that "there is no corresponding Cheap Jacobian Principle" ({{Griewank 2012, p. 391|https://ftp.gwdg.de/pub/misc/EMIS/journals/DMJDMV/vol-ismp/52_griewank-andreas-b.pdf}}).

Dual numbers. Forward mode has a neat algebraic form: numbers \(a + b\varepsilon\) with \(\varepsilon^2 = 0\). Then \(f(a + b\varepsilon) = f(a) + f'(a)\,b\,\varepsilon\) for any smooth \(f\) (the Taylor series stops after the linear term), so evaluating with dual numbers carries the derivative along for free. PyTorch exposes it as torch.func.jvp and dual tensors in torch.autograd.forward_ad; JAX as jax.jvp.

JAX's documentation gives the same picture: for a VJP "the FLOP cost ... is only about three times the cost of evaluating f", and "though the FLOPs are friendly, memory scales with the depth of the computation"; for a JVP "the memory cost is independent of the depth of the computation"; and "jacfwd ... is more efficient for "tall" Jacobian matrices (more outputs than inputs), while jacrev ... is more efficient for "wide" Jacobian matrices" ({{JAX, The Autodiff Cookbook|https://docs.jax.dev/en/latest/notebooks/autodiff_cookbook.html}}).

History. "Forward mode AD as a general method for evaluating partial derivatives was essentially discovered by Wengert (1964)"; the work of "Linnainmaa (1970, 1976) is often cited as the first published description of the reverse mode"; in machine learning it "has been reinvented several times ... until it was eventually brought to fame by Rumelhart et al. (1986)" ({{Baydin et al. 2018, section 3.3|https://arxiv.org/abs/1502.05767}}). Griewank's history adds that Ostrowski used the reverse idea some five years before Linnainmaa, in chemical engineering ({{Griewank 2012, p. 389|https://ftp.gwdg.de/pub/misc/EMIS/journals/DMJDMV/vol-ismp/52_griewank-andreas-b.pdf}}). As Baydin et al. put it, "the backpropagation algorithm is only a special case of AD" (section 4.2).
