5. The layer gradients worth knowing cold, each derived

The question. Autograd computes these for you. Why derive them? Because reading a paper, writing a fused kernel, debugging a NaN or answering an interview question all start from them, and because each one teaches the same three moves: write one output entry with indices, differentiate, and recognise the result as a matrix product.

Every derivation below gives the backward rule of one layer: given \(\bar y\) (the gradient arriving at the output, same shape as \(y\)), return the gradient for each input. The {{Derivative workbench|#t-bench}} runs each one on numbers you can change and checks it against finite differences.

5a. Linear layer: \(y = Wx + b\)

Shapes: \(x\) has \(n\) entries, \(W\) is \(m \times n\), \(b\) and \(y\) have \(m\).

  1. One output entry: \(y_k = \sum_j W_{kj}\,x_j + b_k\).
  2. The weight \(W_{ij}\) appears only in output \(k = i\), multiplied by \(x_j\), so \(\partial y_k/\partial W_{ij} = \delta_{ki}\,x_j\). The chain rule sums over outputs: \(\bar W_{ij} = \sum_k \bar y_k\,\delta_{ki}\,x_j = \bar y_i\,x_j\).
  3. The input \(x_j\) appears in every output, multiplied by \(W_{kj}\): \(\bar x_j = \sum_k \bar y_k\,W_{kj}\).
  4. The bias \(b_k\) appears once with slope 1: \(\bar b_k = \bar y_k\).
  5. Recognise the matrix forms: \[ \bar W = \bar y\,x^\top \;(m \times n), \qquad \bar x = W^\top \bar y \;(n), \qquad \bar b = \bar y \;(m) \]

A batch. PyTorch's nn.Linear stores \(W\) as (out, in) and computes \(Y = XW^\top + b\) for a batch \(X\) of shape \(B \times n\), one example per row. The same three moves give

\[ \bar W = \bar Y^\top X \;(m \times n), \qquad \bar X = \bar Y\,W \;(B \times n), \qquad \bar b = \textstyle\sum_{\text{rows}} \bar Y \;(m) \]

In plain words: a weight's gradient is (gradient coming in) times (input that went in), summed over the batch; an input's gradient is the gradient coming in sent back through the transposed weights; a bias that was added to every row collects the sum of every row's gradient. \(\bar Y^\top X\) is the sum over examples of one outer product each, so one example's weight gradient has rank 1 and a batch's has rank at most \(B\).

The real code. PyTorch writes the backward rules of its built-in operators in one file, tools/autograd/derivatives.yaml. At v2.14.1, lines 1235 to 1238 hold the matrix product:

- name: mm(Tensor self, Tensor mat2) -> Tensor
  self: mm_mat1_backward(grad, mat2, self.sym_sizes(), self.sym_strides(), self.layout(), 1)
  mat2: mm_mat2_backward(grad, self, mat2.sym_sizes(), mat2.sym_strides(), mat2.layout(), 1)
  result: at::mm(self_t, mat2_p) + at::mm(self_p, mat2_t)

{{derivatives.yaml at v2.14.1, lines 1235-1238|https://github.com/pytorch/pytorch/blob/v2.14.1/tools/autograd/derivatives.yaml#L1235-L1238}}; the two helpers in {{torch/csrc/autograd/FunctionsManual.cpp, lines 1722-1758|https://github.com/pytorch/pytorch/blob/v2.14.1/torch/csrc/autograd/FunctionsManual.cpp#L1722-L1758}}.

For \(C = AB\) the helpers' general case is grad.mm(mat2.t()) for \(A\) and mat1.t().mm(grad) for \(B\): \(\bar A = \bar C B^\top\) and \(\bar B = A^\top \bar C\), the rules above. The result: line is the forward-mode rule (section 7): the tangent of \(AB\) is \(\dot A B + A \dot B\), the product rule.

5b. Elementwise nonlinearities: \(h = \phi(a)\)

Output \(i\) depends only on input \(i\), so the Jacobian is diagonal (section 2) and the VJP is an entry-by-entry product, written \(\odot\):

\[ \bar a = \bar h \odot \phi'(a) \]
\(\phi\)\(\phi'(a)\)what PyTorch saves for it (derivatives.yaml, v2.14.1, lines 2132, 1788, 1550, 2160)
ReLU, \(\max(0, a)\)1 where \(a > 0\), else 0its output: threshold_backward(grad, result, 0)
tanh\(1 - \tanh^2 a = 1 - h^2\)its output: tanh_backward(grad, result)
sigmoid \(\sigma(a) = 1/(1 + e^{-a})\)\(\sigma(a)(1 - \sigma(a)) = h(1 - h)\)its output: sigmoid_backward(grad, result)
GELU, \(a\,\Phi(a)\)\(\Phi(a) + a\,\varphi(a)\)its input: gelu_backward(grad, self, approximate)

\(\Phi\) is the standard normal cumulative distribution and \(\varphi\) its density. Functions whose derivative can be written from the output save the output; GELU's cannot, so it saves the input. Either way, one tensor the size of the layer stays in memory until the backward pass: section 9 measures how much that adds up to.

Numbers (the workbench defaults)
At \(a = (-1.5, -0.2, 0.4, 2.0)\) with \(\bar h = (0.5, -1, 0.25, 1)\): ReLU passes \((0, 0, 0.25, 1)\), the negative inputs blocked; GELU's slopes are \((-0.1275, 0.3425, 0.8027, 1.0852)\), so \(\bar a = (-0.0637, -0.3425, 0.2007, 1.0852)\). GELU's slope is negative below about \(-0.75\) and above 1 near \(a = 2\): it is not a monotone function.

5c. Softmax: the VJP without the Jacobian

Multiply the Jacobian of section 2 by an incoming gradient \(\bar p\) and simplify; it is symmetric, so \(J^\top = J\):

\[ \bar z = \big(\operatorname{diag}(p) - p\,p^\top\big)\,\bar p = p \odot \bar p - p\,(p \cdot \bar p) = p \odot \big(\bar p - (p \cdot \bar p)\,\mathbf{1}\big) \]

In plain words: subtract from each incoming gradient the probability-weighted average of all of them, then scale by the probability. Cost: one dot product and one pass over the \(K\) entries, \(O(K)\), against \(O(K^2)\) to build the Jacobian. For a 128,000-word vocabulary that is the difference between a vector and a table of 16 billion numbers per token. PyTorch's softmax node saves only its output \(p\) (_softmax_backward_data(grad, result, dim, ...), derivatives.yaml line 2237).

Numbers
\(z = (2, 1, 0)\), \(p = (0.665, 0.245, 0.090)\), \(\bar p = (0.5, -1, 0.25)\): \(p \cdot \bar p = 0.1104\), so \(\bar z = (0.665 \times 0.3896,\) \(0.245 \times (-1.1104),\) \(0.090 \times 0.1396)\) \(= (0.2592, -0.2717, 0.0126)\). The entries add up to 0, as they must (section 2).
