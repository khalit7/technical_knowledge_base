6. The layer gradients ML needs, each derived

Every block of a transformer is made of six backward rules. Each comes from the same three moves: write one output entry with indices, differentiate, and recognise the result as a matrix product. Each rule takes \(\bar y\), the gradient arriving at the output, and returns the gradient for each input. The workbench runs any of them on numbers you can change and checks it against finite differences, live; its defaults are the numbers in the text.

6a. Linear layer: \(y = Wx + b\)

\(W\) is \(m \times n\). One entry is \(y_k = \sum_j W_{kj}\,x_j + b_k\); \(W_{ij}\) appears only in output \(i\), times \(x_j\); \(x_j\) appears in every output, times \(W_{kj}\); \(b_k\) once, with slope 1. So

\[ \bar W = \bar y\,x^\top \;(m \times n), \qquad \bar x = W^\top \bar y \;(n), \qquad \bar b = \bar y \;(m) \]

A batch. PyTorch's nn.Linear stores \(W\) as (out, in) and computes \(Y = XW^\top + b\) for \(X\) of shape \(B \times n\), one example per row:

\[ \bar W = \bar Y^\top X \;(m \times n), \qquad \bar X = \bar Y\,W \;(B \times n), \qquad \bar b = \textstyle\sum_{\text{rows}} \bar Y \;(m) \]

A weight's gradient is (gradient coming in) times (input that went in), summed over the batch; an input's gradient is the gradient sent back through the transposed weights; a bias added to every row collects every row's gradient. \(\bar Y^\top X\) is a sum of one outer product per example, so one example's weight gradient has rank 1 and a batch's has rank at most \(B\).

The tiny model (\(b = 0\), \(\bar y = p - y\))
\(\bar W = (0.665, 0.245, -0.910)^\top (2, 1)\) has rows \((1.330, 0.665)\), \((0.489, 0.245)\), \((-1.820, -0.910)\); \(\bar x = (-0.245, 2.065)\); \(\bar b = (0.665, 0.245, -0.910)\). PyTorch autograd and jax.grad give the same to 15 digits (src/recompute.py).

6b. Elementwise nonlinearities: \(h = \phi(a)\)

The Jacobian is diagonal (section 1), so the VJP is an entry-by-entry product, \(\bar a = \bar h \odot \phi'(a)\):

\(\phi\)\(\phi'(a)\)what PyTorch saves for it (derivatives.yaml, v2.14.1, lines 2132, 1788, 1550, 2160)
ReLU, \(\max(0, a)\)1 where \(a > 0\), else 0its output: threshold_backward(grad, result, 0)

sigmoid \(\sigma(a) = 1/(1 + e^{-a})\)\(\sigma(a)(1 - \sigma(a)) = h(1 - h)\)its output: sigmoid_backward(grad, result)

\(\Phi\) is the standard normal cumulative distribution and \(\varphi\) its density. Functions whose derivative can be written from the output save the output; GELU's cannot, so it saves the input. Either way one tensor the size of the layer stays in memory until the backward pass (section 9). At \(a = (-1.5, -0.2, 0.4, 2.0)\) with \(\bar h = (0.5, -1, 0.25, 1)\): ReLU passes \((0, 0, 0.25, 1)\); GELU's slopes are \((-0.1275, 0.3425, 0.8027, 1.0852)\), so \(\bar a = (-0.0637, -0.3425, 0.2007, 1.0852)\). GELU's slope is negative below about \(-0.75\) and above 1 near \(a = 2\): it is not a monotone function.

6c. Softmax: the VJP without the Jacobian

Multiply section 1's Jacobian (symmetric, so \(J^\top = J\)) by an incoming \(\bar p\) and simplify:

\[ \bar z = \big(\operatorname{diag}(p) - p\,p^\top\big)\,\bar p = p \odot \big(\bar p - (p \cdot \bar p)\,\mathbf{1}\big) \]

Subtract from each incoming gradient the probability-weighted average of all of them, then scale by the probability. Cost: one dot product and one pass, \(O(K)\), against \(O(K^2)\) to build the Jacobian; for a 128,000-word vocabulary, a vector against a table of 16 billion numbers per token. PyTorch's softmax node saves only its output \(p\) (_softmax_backward_data(grad, result, dim, ...), derivatives.yaml line 2237). On \(z = (2, 1, 0)\) with \(\bar p = (0.5, -1, 0.25)\): \(p \cdot \bar p = 0.1104\), so \(\bar z = (0.2592, -0.2717, 0.0126)\), which adds up to 0, as it must.

6d. Softmax cross-entropy: two VJPs that collapse

\(L = -\ln p_y\) gives \(\bar p = -\mathbf{1}_y / p_y\) (the one-hot vector of the right word, divided by its probability, which can be tiny), so \(p \cdot \bar p = -1\), and softmax's VJP gives

\[ \bar z = p \odot (\bar p + \mathbf{1}) = p - \mathbf{1}_y \]

The division by \(p_y\) cancels exactly. Computed separately, a probability that underflows to 0 would give \(\bar p = -\infty\) and a NaN; fused, the gradient is just the probabilities minus the target. That is why F.cross_entropy takes logits, and why PyTorch's graph shows LogSoftmaxBackward0 feeding NllLossBackward0: log-softmax is computed stably once and saved. For a batch averaged over \(B\) examples (reduction="mean") each row's gradient is \((p - \mathbf{1}_y)/B\); with label smoothing or distillation targets \(q\), it is \(p - q\). The losses themselves, and the same result from \(L = -z_y + \ln \sum_j e^{z_j}\), are on {{Loss functions|n:3c65c17b0d0d8161a72bc8c572f37d55}} and {{Calculus and optimisation for ML, section 2|n:3c65c17b0d0d81eb8b49ed6a0f897f3b#rd-loss}}.

6e. Layer norm

Layer norm (Ba, Kiros and Hinton 2016) rescales each token's vector \(x\) (\(N\) entries) to mean 0 and variance 1, then applies a learned scale \(\gamma\) and shift \(\beta\): \(\hat x = (x - \mu)\,r\) with \(r = 1/\sqrt{\sigma^2 + \epsilon}\) (PyTorch's rstd; \(\epsilon\) defaults to \(10^{-5}\)), and \(y = \gamma \odot \hat x + \beta\). The backward rule, with \(\hat g = \bar y \odot \gamma\):

\[ \bar x = r\Big(\hat g - \operatorname{mean}(\hat g) - \hat x \odot \operatorname{mean}(\hat g \odot \hat x)\Big), \qquad \bar\gamma = \bar y \odot \hat x, \qquad \bar\beta = \bar y \]

Take the incoming gradient, remove its average (the output cannot respond to adding a constant to every entry of \(x\)), remove its component along \(\hat x\) (nor to scaling \(x\) up), and scale by \(1/\sigma\). The result always adds up to 0 and is orthogonal to \(\hat x\). On \(x = (2, 1, 0, -1)\), \(\gamma = (1, 0.5, -1, 2)\), \(\bar y = (0.3, -0.6, 0.9, 0.1)\): \(\mu = 0.5\), \(\sigma^2 = 1.25\), \(r = 0.8944\), and \(\bar x = (0.3041, -0.1521, -0.6082, 0.4562)\), the same as PyTorch's F.layer_norm.

Layer norm's backward, derived completely; PyTorch's kernel form; RMSNorm (4 min)
\[ \mu = \frac{1}{N}\sum_i x_i, \quad \sigma^2 = \frac{1}{N}\sum_i (x_i - \mu)^2, \quad r = \frac{1}{\sqrt{\sigma^2 + \epsilon}}, \quad \hat x_i = (x_i - \mu)\,r, \quad y_i = \gamma_i \hat x_i + \beta_i \]
  1. The easy ones: \(y_i = \gamma_i \hat x_i + \beta_i\) gives \(\bar\gamma = \bar y \odot \hat x\) and \(\bar\beta = \bar y\) (summed over the tokens of a batch), and passes \(\hat g := \bar{\hat x} = \bar y \odot \gamma\) to the normalisation.
  2. \(\hat x_i\) depends on \(x_j\) through three routes: directly, through \(\mu\) and through \(r\). The first two give \(r\,(\delta_{ij} - \tfrac{1}{N})\), because \(\partial \mu/\partial x_j = 1/N\).
  3. The variance: \(\partial \sigma^2/\partial x_j = \tfrac{2}{N}(x_j - \mu)\). (Its route through \(\mu\) contributes \(-\tfrac{2}{N^2}\sum_i (x_i - \mu) = 0\), because deviations from the mean add up to 0.)
  4. So \(\partial r/\partial x_j = -\tfrac{1}{2}(\sigma^2 + \epsilon)^{-3/2} \cdot \tfrac{2}{N}(x_j - \mu)\) \(= -\tfrac{r^3}{N}(x_j - \mu) = -\tfrac{r^2}{N}\hat x_j\).
  5. All three routes together: \[ \frac{\partial \hat x_i}{\partial x_j} = r\Big(\delta_{ij} - \frac{1}{N}\Big) + (x_i - \mu)\Big(-\frac{r^2}{N}\hat x_j\Big) = r\Big(\delta_{ij} - \frac{1}{N} - \frac{\hat x_i \hat x_j}{N}\Big) \]
  6. The VJP sums over \(i\), \(\bar x_j = \sum_i \hat g_i\,\partial \hat x_i/\partial x_j\), which gives the rule above.

On the numbers: \(\hat x = (1.3416, 0.4472, -0.4472, -1.3416)\), \(\hat g = (0.3, -0.3, -0.9, 0.2)\), \(\operatorname{mean}(\hat g) = -0.175\), \(\operatorname{mean}(\hat g \odot \hat x) = 0.1006\), so \(\bar x = 0.8944 \times (0.340, -0.170, -0.680, 0.510)\); it adds up to 0 and its dot product with \(\hat x\) is 0.

The real kernel writes the same thing with two sums per row. From PyTorch v2.14.1's CPU kernel (scale is \(1/N\), a is \(r\), ds \(= \sum_j \bar y_j x_j \gamma_j\), db \(= \sum_j \bar y_j \gamma_j\)):

const opmath_t b = (db * opmath_t(mean_data[i]) - ds) * a * a * a * scale;
const opmath_t c = -b * opmath_t(mean_data[i]) - db * a * scale;
// Scalar math:

RMSNorm (used by Llama and most 2026 open models) drops the mean: \(y = \gamma \odot x / \text{rms}\), \(\text{rms} = \sqrt{\operatorname{mean}(x^2) + \epsilon}\), and the same steps give \(\bar x = (\hat g - \tilde x \odot \operatorname{mean}(\hat g \odot \tilde x))/\text{rms}\) with \(\tilde x = x/\text{rms}\): only the scaling direction is removed. On the same numbers, \(\bar x = (0.2177, -0.2586, -0.7348, 0.1769)\). Why these norms are there is {{Normalisation and initialisation|n:3c65c17b0d0d81369e1cc38ed4e11d48}}'s subject.

6f. Attention, at the level of shapes

One head: \(Q\) is \(T_q \times d\), \(K\) and \(V\) are \(T_k \times d\); \(S = QK^\top/\sqrt d\), \(A = \operatorname{softmax}_{\text{rows}}(S)\), \(O = AV\). Backward, each line one of the rules above, given \(\bar O\):

  1. \(O = AV\) is a matrix product (6a): \(\bar V = A^\top \bar O\) and \(\bar A = \bar O V^\top\).
  2. Each row of \(A\) is a softmax (6c): \(\bar S_{ij} = A_{ij}\big(\bar A_{ij} - D_i\big)\) with \(D_i = \sum_j A_{ij}\bar A_{ij}\).
  3. \(S = QK^\top/\sqrt d\) is a matrix product again: \(\bar Q = \bar S K/\sqrt d\) and \(\bar K = \bar S^\top Q/\sqrt d\).

Only the blue T × T blocks grow with the square of the sequence

Drawn to scale for \(T = 8\) positions and head width \(d = 4\) illustrative sizes. Forward: \(Q\) and \(K^\top\) make \(S\), softmax makes \(A\), \(A\) times \(V\) makes \(O\). Backward: \(\bar O\) gives \(\bar V = A^\top \bar O\) and \(\bar A = \bar O V^\top\); with \(D\), one number per query (gold), \(\bar A\) becomes \(\bar S\); \(\bar S\) gives \(\bar Q\) and \(\bar K\). Every gradient has its variable's shape.

One identity makes attention's backward pass cheap in memory. Substituting \(\bar A = \bar O V^\top\):

\[ D_i = \sum_j A_{ij} \sum_c \bar O_{ic} V_{jc} = \sum_c \bar O_{ic} \sum_j A_{ij} V_{jc} = \sum_c \bar O_{ic}\,O_{ic} \]

\(D\) comes from the output and its gradient alone, one number per query, without the \(T \times T\) matrix \(A\). FlashAttention's backward pass uses exactly this \(D_i\) and recomputes \(A\) block by block instead of storing it (Dao et al. 2022 define \(D_i = do_i^\top o_i\) in Eq. 4 of appendix B.2 and compute "\(D_i = \operatorname{rowsum}(dO_i \circ O_i)\)" in Algorithm 4, line 19; they describe recomputing the attention matrix as "a form of selective gradient checkpointing", section 3.1: {{arXiv 2205.14135|https://arxiv.org/abs/2205.14135}}; {{FlashAttention paper page|n:3c65c17b0d0d81e4a3e8e7a2c4771381}}). In the 8-layer stack of section 9, the stored attention probabilities are 128 of the 422 MiB the backward pass keeps.
