3. Numerator and denominator layout: why papers disagree

The question. A paper writes \(\partial L/\partial W\) and its shape is the transpose of W.grad. Is one of them wrong?

Neither. The slopes are the same numbers; the disagreement is only about which way round to write the table. There are two conventions for \(\partial y/\partial x\) when \(y\) has \(m\) entries and \(x\) has \(n\):

Numerator layout (the Jacobian convention)

Rows follow the thing on top (the numerator, \(y\)): \(\partial y/\partial x\) is \(m \times n\), the Jacobian of section 2. The derivative of a scalar with respect to a vector is then a row (\(1 \times n\)). The chain rule reads left to right in the same order as the composition.

Denominator layout (the gradient convention)

Rows follow the thing underneath (the denominator, \(x\)): \(\partial y/\partial x\) is \(n \times m\), the transpose. The derivative of a scalar with respect to a vector is then a column shaped like \(x\), which is what an update \(x \leftarrow x - \eta \nabla_x L\) needs.

Why papers disagree. There is no field-wide standard, and many authors mix the two. Wikipedia's survey of the conventions puts it plainly: "even within a given field different authors can be found using competing conventions. Authors of both groups often write as though their specific conventions were standard", and "some choose denominator layout for gradients (laying them out as column vectors), but numerator layout for the vector-by-vector derivative" ({{Wikipedia, Matrix calculus, Layout conventions|https://en.wikipedia.org/wiki/Matrix_calculus#Layout_conventions}}). Two of the best-known ML texts use numerator layout and say so: Deisenroth, Faisal and Ong, "In this book, we use the numerator layout of the derivative" ({{Mathematics for Machine Learning, section 5.3, p. 150|https://mml-book.github.io/book/mml-book.pdf}}; they also write the gradient as a row vector, Eq. 5.40), and Parr and Howard, "We are using the so-called numerator layout but many papers and software will use the denominator layout" ({{The Matrix Calculus You Need For Deep Learning, section 4|https://arxiv.org/abs/1802.01528}}). Their reason is the chain rule: in numerator layout it reads left to right with no transposes.

\(\partial L/\partial W\)\(x\,(p - y)^\top\), \(2 \times 3\)\((p - y)\,x^\top\), \(3 \times 2\): what W.grad holds
Entry by entry they agree: \(\partial L/\partial W_{ij} = (p_i - y_i)\,x_j\), for example \(\partial L/\partial W_{\text{sat},1} = -0.910 \times 2 = -1.820\). Only the arrangement differs.

What frameworks do: a parameter's gradient (W.grad in PyTorch, jax.grad's output) always has the parameter's own shape, so for a scalar loss it matches the denominator layout. A full Jacobian, though, comes back outputs first: torch.func.jacrev(f)(x) and jax.jacrev return an array of shape (output shape, then input shape), which is the numerator layout. On this page gradients are written in the parameter's shape and Jacobians as outputs by inputs, the same choice PyTorch and JAX make.

Carried from the old Linear algebra page (checked)
For the squared error \(L = \lVert Wx - y \rVert^2\) with \(W\) of shape \(3 \times 2\), the gradient must be \(3 \times 2\), and it is \(\nabla_W L = 2(Wx - y)\,x^\top\): a \(3 \times 1\) column times a \(1 \times 2\) row. With the tiny model's \(W\) and \(x\) and a target \(y = (1, 0, 0)\): \(Wx - y = (1, 1, 0)\), so \(\nabla_W L\) has rows \((4, 2)\), \((2, 2)\), \((0, 0)\), the same as PyTorch's autograd (checked in src/recompute.py). The shapes alone nearly force the answer: the only way to make \(3 \times 2\) from a 3-vector and a 2-vector is the outer product.
The working rule
Derive in whichever layout you like, but never mix them in one derivation. Then check the shape: a scalar's gradient has the shape of the parameter. If yours is the transpose, transpose it and test one entry with a finite difference (section 11).
