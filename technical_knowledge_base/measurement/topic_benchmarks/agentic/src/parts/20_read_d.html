Terminal: Terminal-Bench and Terminal-Bench-Science

Terminal-Bench (Stanford and the Laude Institute; maintained in the {{harbor-framework|https://github.com/harbor-framework/terminal-bench}} organisation, Apache 2.0) gives the agent a shell in a Docker container and a task taken from real work: compile and fix builds, recover a database, train a small model, crack a hash, configure a server. Each task ships an environment, a human-written reference solution and tests that check the end state ({{paper, Jan 2026|https://arxiv.org/abs/2601.11868}}). Because Claude Code, Codex CLI, OpenHands and other agents run against it directly, it doubles as a harness benchmark, and the leaderboard lists each entry as an agent and model pair. Its versions are not one scale: each changed the tasks, the limits or the checker.

Five versions in 16 months, each a different scale: never splice them

Click a version. Task counts, timeouts and verifier modes are counted in this page from the task files at each tag ({{2.0 repository|https://github.com/harbor-framework/terminal-bench-2}}, {{3.0 and 4.0 tags|https://github.com/harbor-framework/terminal-bench/releases}}); dates are the GitHub tags and the {{tbench.ai news|https://www.tbench.ai/news}} posts; scores are the official boards unless marked as a lab's own run.

What changed at 4.0, in the task files. 8 tasks removed (2 saturated, 2 refused by models, 2 with public solutions, 2 for quality or platform problems), 19 fixed, and every task's agent timeout set to a flat 8 hours (65 of the 66 task files state 28,800 s; the announcement says all). "Saturated" was defined strictly: every model class in every family of the latest generation solves the task 5 times out of 5. Because time and memory limits are part of a task when the agent has a shell and a clock, 2.x and 4.0 scores are not comparable even on tasks that survived.

A saturated coding score says little here. Reflection's open-weight Beam 1.0 (October 2026) reports 81.6% on SWE-bench Verified on its own model card vendor-reported, and scores 3.0% on Terminal-Bench 4.0 in Artificial Analysis's run ({{Artificial Analysis|https://artificialanalysis.ai/articles/reflection-beam}}): a benchmark the frontier has saturated no longer separates models on long agentic work ({{Coding benchmarks|n:3ef5c17b0d0d81bfa09ad4ba5eef0c4e}} owns SWE-bench Verified).

Terminal-Bench-Science 0.1 ({{announcement, 27 Aug 2026|https://www.terminal-bench-science.ai/announcement}}) is the first agent benchmark built around research workflows rather than software engineering: 70 tasks across life, physical, Earth, mathematical and engineering sciences, graded by task-specific tests, three trials per task. At launch Claude Opus 5 led at 30.0%; within a week the {{official board|https://www.terminal-bench-science.ai/}} reached 68.1% (GPT-6 Astra (max) in Codex, dated 3 Sep, ±3.2). Lab and board figures disagree for the same model in both directions (section 3).

Corrections to the old page, 4.0's noise and token notes, and Terminal-Bench-Science's construction
Corrections
  • "4.0 (Sep 2026) is the current version, and there is no 3.x because the numbering jumped": {{Terminal-Bench 3.0|https://github.com/harbor-framework/terminal-bench/releases/tag/v3.0.0}} exists (tagged 23 Jul 2026, 74 tasks) and 4.0 was tagged 26 Aug 2026 (announced 28 Aug). The maintainers chose 4.0 over 3.1 because Terminal-Bench is now a continuous benchmark with semantic versioning, and changed resources and removed tasks are breaking changes that require re-running trials ({{4.0 announcement|https://www.tbench.ai/news/terminal-bench-4-0}}).
  • "2.0 ... reached ~92% (GPT-5.6-class) by Aug 2026": the 92% figures are lab numbers on 2.1 (OpenAI's GPT-5.6 Sol Ultra with four parallel agents 91.9%). The official tops are 84.7% on 2.0 and 83.8% on 2.1 (root Benchmark atlas, from Wayback captures of the boards).
  • "resets the scale to GPT-6 Astra 57.9% and Claude Fable 5.1 55.8%": those come from Anthropic's Opus 5.5 table. The official board reads GPT-6 Astra (max) 58.18%, Claude Fable 5.1 (max) 57.88%, Claude Opus 5 (xhigh) 53.94%, Grok 4.7 (xhigh) 37.58% (read 4 Oct 2026); Opus 5.5 was not on it at that reading (Anthropic's own run: 66.4%; Vals AI's fixed mini-swe-agent harness: 65.15%, 18 Oct 2026).
  • "stood at 52.6% for Claude Fable 5.1 one week later": 52.6% is Anthropic's own run, published five days after launch; the official Terminal-Bench-Science board lists Fable 5.1 at 40.0% and Artificial Analysis measured 43.3%.

The version chart in brief (task files and boards): 1.0 (19 May 2025, 80 tasks) saturated within months and its board froze at 64.5% (Apex2 agent with Claude Sonnet 4.5); 2.1 (6 May 2026) fixed 28 of the 89 tasks, and Opus 4.6 in Claude Code went from 58.0% on 2.0 to 70.1% on 2.1, so 2.0 and 2.1 are different scales; 3.0 launched at about 34% (GPT-5.6 Sol in Codex 34.4%, Claude Fable 5 in Claude Code 33.8%) and was replaced five weeks later.

The 4.0 announcement also notes fewer agent timeouts and errors than 3.0, so less measurement noise, and that Sonnet 5 used 21.6 billion tokens on the run against 6.5 billion for Opus 5.

Terminal-Bench-Science was built by Stanford with the Terminal-Bench and Harbor teams, from 376 contributors in 22 countries, reviewed by domain and technical reviewers plus a final "bar-raiser". At launch: Claude Opus 5 30.0%, GPT-5.6 Sol 22.4%, Claude Fable 5 21.4%, GPT-5.6 Luna 3.3%; the board later read 63.3% for Claude Opus 5.5 (max). Lab against board: Fable 5.1 52.6% against 40.0%; Opus 5.5 58.7% against 63.3%; Astra 64.6% against 68.1%. It is meant to be continuous: version 0.2 was taking task pull requests until 5 October 2026.

Computer use: OSWorld and its relatives

OSWorld ({{Xie et al., XLANG Lab, HKU, Apr 2024|https://arxiv.org/abs/2404.07972}}) runs the agent on a real Ubuntu virtual machine, seeing screenshots (and optionally the accessibility tree) and sending mouse and keyboard actions, across office apps, browsers, file managers, IDEs and workflows that span several apps. Each of its 369 tasks is a configuration file: an initial-state setup and an evaluation script that inspects the final state (a file's contents, a setting, a spreadsheet). At launch people completed 72.36% and the best model 12.24%. How such an agent perceives and acts is {{Personal agents|n:3c75c17b0d0d81bf9462fbeb09593e1c}}' subject (section 2); what matters here is the task file.

Correction: OSWorld 2.0 vendor figures are partial credit
Vendor cards quote OSWorld 2.0 at 72.6% (GPT-6 Astra), 74.0% (Claude Opus 5) and 81.8% (Claude Opus 5.5). These are partial-credit scores, from different task releases and harnesses; on the official board's default binary metric the best is 44.33%. A 2.0 figure without release, set and metric carries no information, and none of them compares with OSWorld-Verified.
Where each OSWorld 2.0 vendor figure comes from, and the launch numbers

OpenAI's 72.6% is release 2026.08.08, offline set ({{OpenAI|https://openai.com/index/gpt-6-astra/}}); GPT-6 Sol was quoted at 60.5% offline at extra-high effort. Anthropic's 74.0% and 81.8% are its own re-run on the 10 September task files with a new context harness, where the strict pass rates are 37.2% and 48.7% ({{Opus 5.5 system card, 8.13.3|https://www-cdn.anthropic.com/fc1b44717c85dc068bc6ba5024219938094694bd/Claude%20Opus%205.5%20System%20Card.pdf}}). The maintainers' own run of Opus 5 on release 2026.08.08 read 31.4% binary, 68.3% partial. OpenAI also notes that the Fable 5.1 system card used modified tasks and grading. At launch (26 Jun 2026) the best public model was Claude Opus 4.8 at 20.6% binary with batched tools.

Earlier, Claude 3.5 Sonnet's computer-use release in October 2024 scored 14.9% on the original OSWorld screenshot-only, 22.0% with more steps ({{Anthropic, 22 Oct 2024|https://www.anthropic.com/news/3-5-models-and-computer-use}}).

How OSWorld was broken. RDI's exploit agent reached 73%: it downloaded the public gold file straight into the path the checker reads ("the evaluator compares gold vs. gold"); state checks were met by setting the state directly (gsettings set, writing expected config files); the 29 tasks marked infeasible were answered "FAIL" for free points; and the grader called Python's eval() on a string read from the VM, so a crafted gsettings value ran code on the grading machine ({{RDI|https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/}}).

Relatives: Windows Agent Arena, OSWorld-Science, AndroidWorld

{{Windows Agent Arena|https://arxiv.org/abs/2409.08264}} (Microsoft, Sep 2024) adapts OSWorld's framework to 150+ Windows tasks, parallelised on Azure to finish in about 20 minutes; its Navi agent scored 19.5% against 74.5% for people. {{OSWorld-Science|https://arxiv.org/abs/2609.39903}} (Sep 2026) applies the same idea to scientific software: 146 expert-designed tasks (molecular drawing and retrosynthesis, pathology images, statistics, physical simulation) whose evaluators inspect the produced artifacts and give partial credit. {{AndroidWorld|https://arxiv.org/abs/2405.14573}} (Google, May 2024) has 116 programmatic tasks across 20 Android apps, parameterised so each run draws new instances; the best agent then completed 30.6%.

Web: WebArena, VisualWebArena and the live web

WebArena ({{Zhou et al., CMU, Jul 2023|https://arxiv.org/abs/2307.13854}}) self-hosts working copies of four kinds of site (an e-commerce store, a social forum, a GitLab, a content-management system) plus a map, a wiki and manuals, and poses 812 long-horizon tasks checked for functional correctness: the resulting site state, or the answer string. The best GPT-4 agent completed 14.41% against 78.24% for people. Self-hosting makes it reproducible, and its sites and tasks have been public since 2023. VisualWebArena ({{Koh et al., Jan 2024|https://arxiv.org/abs/2401.13649}}) adds tasks that need the page's images, where text-only agents fall short.

How WebArena was broken. RDI reached about 100% of 812 tasks: navigating the browser to a file:// URL opens the task's own configuration, gold answer included (file:///proc/self/cwd/config_files/{task_id}.json); its must_include check is substring containment, so a verbose answer passes; it calls eval() on agent-controlled strings; and its LLM-judged answers can be steered by text injected into the agent's reply.

The live web trades reproducibility for realism, and needs a judge model because no one controls the end state.

Live-web benchmarks: WebVoyager, Online-Mind2Web, Mind2Web 2

{{WebVoyager|https://arxiv.org/abs/2401.13919}} (Jan 2024) runs on 15 real websites with a GPT-4V judge that agreed with people 85.3% of the time. {{Online-Mind2Web|https://arxiv.org/abs/2504.01382}} ("An Illusion of Progress?", Apr 2025) has 300 tasks across 136 live websites and found earlier results over-optimistic; its LLM judge agrees with people about 85% of the time. {{Mind2Web 2|https://arxiv.org/abs/2506.21506}} (Jun 2025) has 130 long-horizon research tasks graded by task-specific judge agents with tree-structured rubrics for correctness and citations; OpenAI Deep Research reached 50 to 70% of human performance in half the time.
