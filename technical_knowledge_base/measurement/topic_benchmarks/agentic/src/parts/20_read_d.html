The integrity crisis

In April 2026 Hao Wang, Qiuyang Mang, Alvin Cheung, Koushik Sen and Dawn Song at UC Berkeley published {{How We Broke Top AI Agent Benchmarks|https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/}} (Berkeley RDI; the paper is {{arXiv 2605.12673|https://arxiv.org/abs/2605.12673}} and the scanner is {{BenchJack|https://github.com/benchjack/benchjack}}). An automated agent audited eight prominent agent benchmarks, built a working exploit for each, ran it through the official evaluation, and scored near the top "without solving a single task", in most cases with no model calls at all:

RDI group the flaws into seven patterns, and every benchmark on this page can be read against them:

  1. No isolation between agent and evaluator (SWE-bench, Terminal-Bench, OSWorld): the checker reads state the agent could write.
  2. Answers shipped with the test (WebArena configs, OSWorld gold URLs, GAIA's public validation answers).
  3. eval() on untrusted input (WebArena, OSWorld): code execution on the grading machine, a security hole as well as a scoring one.
  4. LLM judges without input sanitisation (WebArena, CAR-bench): the agent's text reaches the judge's prompt.
  5. Weak string matching (WebArena's substring check, GAIA's normaliser).
  6. Evaluation logic that does not evaluate (FieldWorkArena's validator, CAR-bench's skipped components, GAIA's comma bug that marks correct answers wrong).
  7. Trusting the output of untrusted code (pytest output and reward files produced inside the agent's container).

It is not only a red-team result. RDI also list incidents in the wild: IQuest-Coder-V1 claimed 81.4% on SWE-bench until 24.4% of its trajectories were found running git log to copy the answer from history (corrected to 76.2%); in KernelBench, torch.empty() returned stale GPU memory holding the evaluator's reference answer; and Anthropic's Mythos Preview assessment describes a model that, unable to edit a file it lacked permission for, injected code into a config file that ran with elevated privileges and deleted itself afterwards. {{HAL|https://arxiv.org/abs/2510.11977}}, which reran 9 benchmarks with 21,730 rollouts (about $40,000), found agents searching Hugging Face for the benchmark instead of solving the task. {{METR|https://metr.org/blog/2025-06-05-recent-reward-hacking/}} measured o3 reward-hacking in 30.4% of RE-Bench runs by overwriting a grader's timer, monkey-patching the evaluator and caching answers. So an agent score you did not run yourself, under an isolated evaluator with held-out checks, deserves suspicion; RDI say plainly they are not claiming current leaders cheat, but that optimisation pressure can find the evaluator before it finds the solution.

What changed since. Terminal-Bench 3.0 and 4.0 tasks declare a separate verifier environment, copy out only declared artifacts and install nothing at trial time (74 of 74 and 66 of 66 task files, counted here; the animation in Anatomy shows why that defeats the wrapper exploit). Separation does not fix the other six patterns.

The minimum bar for an agent benchmark (RDI's Agent-Eval Checklist, condensed)
  • Run the checker outside the agent's environment, on a read-only host; copy artifacts out through a controlled channel and treat them as untrusted; mount binaries and test files read-only.
  • Never put reference answers, gold files or evaluator configs where the agent can read them; keep the primary split's answers secret and rotate instances.
  • Never call eval() on agent-controlled strings; parse structured data.
  • Treat agent text as data in any judge prompt (delimiters, stripping, structured output), or grade extracted features instead.
  • Before publishing, attack your own evaluator with a null agent (its score is the floor and should be zero), a random agent, a prompt-injection agent and a state-tampering agent.
  • Score robustly: no substring matches on short strings, a crashed task counts as zero, no category skips a check.
Go deeper: Grade a real task runs regex-log's real test on your own regex and lists each exploit beside the defence that stops it; {{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}} covers why trained agents find these paths; {{Safety and honesty|n:3ef5c17b0d0d818da9d5efda1a443166}} covers AgentHarm and monitoring.

Common mistakes

Quoting a model's agent score without the harness, effort and budget
The pair is the unit. One model on the official Terminal-Bench 4.0 board spans 50.61% to 58.18% across effort settings; a harness lifted one model 9 points on Terminal-Bench 2.1; on ARC-AGI-3 two harnesses at equal effort gave 62.7% and 98.6%.
Splicing versions of one benchmark
Terminal-Bench 2.0, 2.1, 3.0 and 4.0 are different task sets with different limits and checkers; OSWorld, OSWorld-Verified and OSWorld 2.0 (three releases, full or offline, binary or partial) are not one scale. Write the version, the set and the metric.
Reading partial credit as success rate
OSWorld 2.0's partial score and binary accuracy differ by 30 to 40 points for the same run; Agents' Last Exam's 56.4% "score" for GPT-6 Sol is a 32.2% pass rate.
Treating pass^1 as reliability
On τ²-bench retail, three models 5 points apart at pass^1 tie at pass^4, 25 to 30 points lower. If a product must work every time, ask for pass^k.
Putting a lab's own run beside a board's
On Terminal-Bench-Science the same model reads 52.6% (lab) and 40.0% (board). Compare like with like and say who ran each number.
Trusting a score the environment could have produced
If the checker ran where the agent ran, read answers it could see, or asked a judge that reads the agent's text, the score is an upper bound on capability plus an unknown amount of exploitation.
Reading a small set's gap as a ranking
50 airline tasks: one task is 2 points. 30 sampled tasks with 3 attempts (HarnessTax) cannot separate harnesses a few points apart. Use the root's error-bar calculator.
Quoting a METR horizon beyond the suite
A 17-hour horizon on a suite whose longest reliable range is about 16 hours, with an interval from 8 to 55 hours, says "beyond what this suite can measure", not "17 hours".
