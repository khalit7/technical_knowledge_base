An agentic benchmark scores a system, not a model: the model inside a harness, at an effort and a budget, acting for many steps on an environment that a checker inspects afterwards. So a reported number means something only with four things stated beside it: the harness, how many tries per task were counted, whether the checker was out of the agent's reach, and which version and metric were used.

One agentic run, and the four places where the same weights get a different number

  1. 1Harness. Claude Opus 4.6 on Terminal-Bench 2.0's public board ranges from 58.0% (Claude Code) to 76.4% (Meta-Harness): about 18 points across nine agents, same weights (section 3).
  2. 2Tries counted. GPT-5.2 on τ²-bench retail: 81.58% when one try is averaged (pass^1), 51.75% when all four tries must succeed (pass^4), from the same 456 trials (section 2).
  3. 3Checker isolation. On Terminal-Bench 2.0 the checker ran inside the agent's container; an exploit agent scored 100% writing zero lines of solution (section 1).
  4. 4Version and metric. Claude Opus 5 on OSWorld 2.0, one run: 44.33% binary, 77.67% partial credit; vendor tables quote the partial figure (Computer use).

Checker (verifier, evaluator): the code, judge or person that decides success after the agent stops; the benchmark's real definition of the task.
Trial: one independent attempt at a task; boards run 3 to 5 per task.
pass^k ("pass hat k"): chance that all k tries of a task succeed. pass@k: chance that at least one does.
Separate verifier: the checker runs in a fresh environment that receives only declared output files.
Simulated user: an LLM playing the customer, with hidden instructions (τ-bench family).
Time horizon: the length of task, in skilled-human time, that a model completes with 50% success (METR).
Binary against partial credit: share of tasks fully solved, against the average fraction of a task's checks met.
Exploit agent: a program that maximises the score without solving tasks, used to audit a checker.
