Time horizon fit

How METR turns a task suite into one number in minutes, done here on METR's own released runs. Each of the 228 tasks in suite v1.1 has a human time (the geometric mean of skilled people's successful attempts, or an estimate); each model ran each task several times. For one model, the fit is a logistic curve of success against log2(human minutes), each task weighted by METR's diversity weight (task families with many members count less); the 50% horizon is where the curve crosses one half. Data: {{METR eval-analysis-public|https://github.com/METR/eval-analysis-public}}, reports/time-horizon-1-1/data/raw/runs.jsonl (24,008 runs), and the published {{results file|https://metr.org/assets/benchmark_results_1_1.yaml}}, read 4 Oct 2026. The repository states no licence; this page ships only per-task counts derived from it.

P(success | task) = σ( a + b · log2 minutes )     horizonp = 2( ln(p/(1−p)) − a ) / b
a, b
fitted by weighted maximum likelihood with an L2 penalty of 10−5 on b (scikit-learn's C = 105, METR's setting), solved here by Newton's method
p
0.5 for the 50% horizon, 0.8 for the 80% horizon
Try: step through the models in release order and watch the curve slide right; compare GPT-4o (about 7 minutes) with Claude Opus 4.6 (about 12 hours). Then in the trend chart, move the start year and see the doubling time change.

Dots: one task, at its human time, with the model's success rate over its runs (size: the task's weight). Line: the fitted curve. Squares: METR's weighted success rate within its time buckets (1 to 4, 4 to 16, 16 to 64, 64 to 256, 256 to 960 and 960 to 2,880 minutes).
