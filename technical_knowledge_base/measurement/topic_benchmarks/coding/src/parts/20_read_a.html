The idea in one screen

A coding benchmark runs what the model writes against tests, so the score also measures three things outside the model: the tests (do they reject wrong code), the tasks (were they, or their fixes, in the training data) and the harness (what the model was allowed to do). The field moved from one function, to dated contest problems, to whole repositories, each time one of the three broke.

Change one thing outside the model and the same model's score moves 11.2 to 18.5 points

pass@k
the chance that at least one of k sampled programs passes every test; pass@1 is the single-try rate.
Fail-to-pass (FAIL_TO_PASS)
tests that fail before the real fix and pass after it: the fix must flip them.
Pass-to-pass (PASS_TO_PASS)
tests that passed before and must still pass: the fix must not break them.
Gold patch, test patch
the fix the maintainers merged; the pull request's test changes, which the harness applies after the model's patch.
% resolved
the share of tasks where every fail-to-pass and pass-to-pass test passes.
Harness (scaffold)
the agent around the model: its tools, turn limit, cost cap, retries, and whether it may run tests.
Split
a subset with its own access rule: public, held-out (copyleft, unpublished problems) or private (licensed code never released).

Coding benchmarks in one screen

Three generations: one function against a few unit tests (2021), contest problems pinned to dates, and real issues in whole repositories (the SWE-bench family, 2023 onward), each forced by the previous one saturating and each with its own failure: weak tests, frozen leaderboards, leaked solutions, memorised repositories. By 2026 the answers to contamination have split three ways: new tasks by the calendar, private code by licence, familiar code transformed beyond recognition.
