Coding benchmarks in one screen

A coding benchmark gives a model a programming task and runs what it writes against tests. That makes code the most objectively graded skill there is, and also the easiest to overstate: a score is only as good as the tests, the tasks may already sit in the training data, and once the model is an agent in a repository the harness around it is part of the score.

The field moved in three steps. One function against a few unit tests (HumanEval, MBPP, 2021), measured by pass@k. Contest problems pinned to dates (LiveCodeBench, Codeforces ratings), so a model can be scored on problems published after it was trained. Real issues in whole repositories (the SWE-bench family, 2023 onward), where an agent edits a codebase and the repository's own tests decide. Each step was forced by the previous one saturating, and each brought its own failure: weak tests, frozen leaderboards, leaked solutions, memorised repositories. By 2026 the answers to contamination have split three ways: new tasks by the calendar, private code by licence, and familiar code transformed beyond recognition.

One function against unit tests: HumanEval, MBPP and pass@k

HumanEval came with OpenAI's Codex paper in July 2021: 164 hand-written Python problems, each a function signature and docstring, with "an average of 7.7 tests per problem" ({{Chen et al. 2021, section 2.2|https://arxiv.org/abs/2107.03374}}). Hand-written mattered because Codex was trained on 159 GB of GitHub Python, which already held solutions to most public puzzle sets. The model writes the function body; the tests run in a sandbox; a problem counts as solved if every test passes. At launch Codex-12B solved 28.8%, GPT-3 0% and GPT-J 11.4%; sampling 100 completions per problem and counting a problem solved if any one passed, Codex reached 70.2% ({{abstract|https://arxiv.org/abs/2107.03374}}).

MBPP (Google, August 2021) is the entry-level counterpart: 974 crowd-sourced tasks "designed to be solvable by entry-level programmers", each a one-sentence description with three assert statements; the largest model of the paper, 137B parameters, solved 59.6% few-shot ({{Austin et al. 2021|https://arxiv.org/abs/2108.07732}}).

pass@k, and why the obvious estimator is wrong

That 70.2% is a different metric from 28.8%. pass@k is the probability that at least one of k sampled programs passes. Drawing exactly k samples per problem and checking gives a noisy answer, so the Codex paper draws n ≥ k samples (it used n = 200, k ≤ 100), counts the c that pass, and estimates

pass@k = Eproblems [ 1 − C(n−c, k) / C(n, k) ]
n
samples drawn per problem; c of them pass every test
C(a, b)
binomial coefficient: the number of ways to choose b of a
C(n−c, k)/C(n, k)
the chance that k samples drawn without replacement from the n are all failures

The tempting shortcut is to estimate pass@1 as p̂ = c/n and plug it into 1 − (1 − p̂)k. The paper shows in its Appendix A that this "results in a consistent underestimate", and that "the gap doesn't fully close even when n > 5k" ({{Codex paper, section 2.1 and Appendix A|https://arxiv.org/abs/2107.03374}}). The reason is curvature: (1 − p̂)k is convex in p̂, so averaging it over the luck of the draw overstates the chance that all k fail. The paper also gives a numerically stable product form, 1 − ∏i=n−c+1..n(1 − k/i), which this page uses.

The animation draws 20 samples for one problem whose true pass rate is 15% illustrative and tracks both estimates of pass@5 as samples arrive. The final step replaces one lucky or unlucky draw by the exact average over every possible draw.

The 20 outcomes are one fixed draw at p = 0.15 illustrative; the true pass@5 is 1 − 0.855 = 55.6%. The last step's averages are exact sums over the binomial distribution of c, computed in the page and checked against src/recompute.py (for n = 10, p = 0.1, k = 5: 40.95% for the Codex estimator, the true value, against 34.85% for the plug-in). On real per-problem results from LiveCodeBench, the {{pass@k lab|#t-pk}} tab shows the gap for ten models.

Two reading rules follow. A pass@k figure needs its k, its n and its temperature (Codex sampled pass@1 at temperature 0.2 and pass@100 at 0.8), and a pass@10 is never comparable with a pass@1. And pass@1 is the number that matters for a user who runs the model once; pass@k with large k measures what a system that can run tests and pick a passing answer could reach, which is how AlphaCode and later contest systems used it.

Weak tests overstate correctness: EvalPlus and BigCodeBench

HumanEval's 7.7 tests per problem catch obvious mistakes, not edge cases. EvalPlus (Liu et al., 2023) generated new test inputs with "LLM- and mutation-based strategies", checked against the reference solution, and extended HumanEval's tests "by 80x" into HumanEval+; a 2024 release did the same for MBPP ("35x more tests" in MBPP+, 378 tasks after broken ones were removed; {{EvalPlus README|https://github.com/evalplus/evalplus}}). On 26 models it reduced pass@k "by up-to 19.3-28.9%" and reordered models: WizardCoder-CodeLlama and Phind-CodeLlama overtook ChatGPT on HumanEval+, which neither did on HumanEval ({{Liu et al. 2023|https://arxiv.org/abs/2305.01210}}). In the released v0.1.10 data, HumanEval's 164 problems carry 1,570 base inputs and 122,683 HumanEval+ inputs derived (counted from {{the release|https://github.com/evalplus/humanevalplus_release/releases/tag/v0.1.10}}).

Sample 6 is the lesson. It returns False only for 1, so it calls 0 and every negative number prime. HumanEval's tests never ask, so it was graded CORRECT; HumanEval+ asks 45 such questions and gets 45 wrong answers. Its loop also tries every divisor up to n, so the large inputs time out. Sample 4, the textbook square-root check, passes all 167. A weak test suite does not just add noise; it rewards a specific kind of wrong program, which is why EvalPlus's reorderings happened.


Where the two sets stand. OpenAI's simple-evals lists 99.3% for o4-mini (high) on HumanEval, a lab figure; the independent EvalPlus board tops out at 96.3% on base tests and 89.0% on HumanEval+ (o1-preview and o1-mini), and at 80.2% on MBPP+ against 95.5% on base MBPP (o1-preview) ({{EvalPlus leaderboard|https://evalplus.github.io/leaderboard.html}}; {{simple-evals|https://github.com/openai/simple-evals}}). GPT-4's technical report already estimated about 25% of HumanEval overlapping its training data ({{OpenAI 2023, Appendix C|https://arxiv.org/abs/2303.08774}}). No 2026 model card reports either set.

BigCodeBench (BigCode, June 2024) moved from puzzles to practical code: 1,140 tasks that call functions "from 139 libraries and 7 domains", with "5.6 test cases with an average branch coverage of 99%", in a Complete variant (docstring) and an Instruct variant (short instruction), plus a 148-task Hard subset added in July 2024 ({{README|https://github.com/bigcode-project/bigcodebench}}). At launch the best of 60 models scored "up to 60%" against human performance of 97% ({{Zhuo et al. 2024|https://arxiv.org/abs/2406.15877}}). The board's tops are 62.4% on Full (Gemini-Exp-1206, Complete, calibrated pass@1) and 40.5% on Hard, with no models added after April 2025 ({{BigCodeBench results|https://bigcode-bench.github.io/}}).
