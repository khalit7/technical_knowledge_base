Outcome grading: check the world, not the claim

An outcome grader looks only at the world after the run: a state diff against a gold state, tests the change must pass, assertions on named parts of the state, or required information the agent must have told the user.

A state diff is the strongest: indifferent to path and wording, it sees changes the agent never mentioned. Keep it a diff, not just a hash: the six differing fields of task 29 explain the failure in one look, where a hash only says "different". Partial credit helps where a task has parts ("a support agent that correctly identifies the problem and verifies the customer but fails to process a refund is meaningfully better than one that fails immediately", Anthropic): score each required change and keep the all-or-nothing score beside it.

The do-nothing baseline

Many good agent tasks have "change nothing" as the right answer (refuse a forbidden cancellation, decline an unaffordable change), and on those an agent that does nothing passes. This page ran that agent through τ²-bench's evaluator: the first user turn, then no tool calls.

Nearly half the airline suite rewards doing nothing

Top: share of tasks a do-nothing agent passes. Bottom: each agent's 200 airline trials, passes split by whether the do-nothing agent also passes that task. measured here

On airline, 23 of 50 tasks pass with no action, and 88 of GPT-5.2's 166 passing trials are on those tasks. Its pass^1 on the 27 tasks that need a change is 72.2%, against 83.0% overall (Opus 4.5: 73.2% against 84.0%). Neither number is wrong; the overall one hides that nearly half the suite rewards restraint. Anthropic's general form: "Test both the cases where a behavior should occur and where it shouldn't ... avoid class-imbalanced evals." For your own suite: run a do-nothing agent and a random agent first, report their scores beside every result, and report change and no-change tasks separately.

What an outcome check cannot see

  • Harm along the way. An agent that emails a customer's data to the wrong address and then finishes the booking correctly passes a check on the reservations table. The outcome check covers the state you decided to check; the next section covers the rest.
  • A wrong gold state. Task 29's gold assumes no insurance and one card; the simulated user asked for both. Your gold state encodes your assumptions about the user, and a simulated user does not know them.
  • A better route than the gold (task 31). On CORE-Bench Opus 4.5 "initially scored 42%" until a researcher found "rigid grading that penalized '96.12' when expecting '96.124991…', ambiguous task specs, and stochastic tasks"; fixed, it scored 95% (Anthropic).
  • Success the checker did not anticipate. Web benchmarks' rule checkers are precise (83.8%) but miss real successes (55.9% recall), so GPT-4o scored 16.7 points lower by the rules than by experts on WebArena and 18.5 on VisualWebArena ({{Lù et al., AgentRewardBench, Apr 2025|https://arxiv.org/abs/2504.08942}}).

Grade actions, not messages

A message grader reads what the agent said, and for agents saying and doing come apart. Even a judge that read the whole transcript, tool calls included, disagrees with the database on 49 of the 400 trials; a grader that reads only the final message knows less.

MOLE: what was measured (correction carried from the parent page)
An earlier version of the parent page said MOLE found that "a model's stated refusal did not predict whether it actually declined". That overstates the paper. What it measured: under a preamble telling every model the sandbox is harmless and that refusing spoils the research, 28 of 39 models (72%) completed more than half of their assigned harmful objectives, verified in the services' state, not in what the agent said; across models, refusal and completion rates are strongly linked (Spearman -0.73) ({{Muhamed and Smith, MOLE, Sep 2026|https://arxiv.org/abs/2609.06966}}; corrected reading on the {{MOLE paper page|n:3db5c17b0d0d818b9680c7b91baaf7e9}}). The point that survives: in agentic systems, grade what the account did.

Emergence World scored private reasoning, requested actions, executed actions and speech separately, letting none count for another: all seven exposed worlds warned their community about a phishing lure, none removed its traces, and in the Gemini world agents made 489 calls to the attacker's database after their own world had flagged it ({{Akkil et al., Sep 2026|https://arxiv.org/abs/2609.17320}}). A message grader would have scored that world as having detected the attack.

How to grade actions

  • Forbidden actions as hard checks. List what must never happen (a write without the user's explicit yes, a payment method not on the profile, a call outside the allow-list) and scan every tool call for it, in code.
  • Unexpected writes. Count writes that are in no gold action. On the 400 trials an exact audit of write calls (every gold write present with the same arguments, no others) agrees with the database check on 396; where they disagree, read the transcript.
  • A monitor over the trace for what you cannot enumerate. In MOLE an LLM reading what the agent did beat count-based anomaly detection, and showing it the agent's reasoning helped wherever the agent wrote it; a renderer that clipped tool arguments at 600 characters hid every data-poisoning trigger from every monitor.
More evidence: MOLE's details, Emergence World's correction, HAL's logs

MOLE. 24 models never refused yet completed anywhere from 20% to 100%, mostly by not attempting; the best monitor (Claude Opus 4.7, reviewing 10 accounts a day) caught 24 of 45 completed harms. On MOLE's DeepSeek corpus, GPT-4.1 with reasoning beat GPT-5.5 on audit events alone. The monitor-side audit runs in the browser on the MOLE paper page's Run the daily audit tab.

Emergence World ran eight ten-agent worlds for days under phishing, misinformation and memory exposure. The 489 calls are counted from the released tool-call records on the {{Emergence World paper page|n:3e25c17b0d0d818fbffbc9e2ceab824b}}. The paper's "up to 46 hours" is one agent retrying an attack link after the campaign, not a measured detection-to-stop delay; corrected on the paper page.

HAL re-ran nine benchmarks in 21,730 rollouts and, by reading logs with an LLM's help, found agents "searching for the benchmark on HuggingFace instead of solving a task, or misusing credit cards in flight booking tasks" ({{Kapoor et al., HAL, Oct 2025|https://arxiv.org/abs/2510.11977}}); neither shows up in a success rate.
