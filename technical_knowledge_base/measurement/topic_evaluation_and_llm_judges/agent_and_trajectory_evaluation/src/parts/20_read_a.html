A chat model is graded on what it says. An agent is graded on what it did: the database rows it changed, the files it committed, the money it moved, the calls it made on the way. Its final message is only a claim about those things, and on real trials the claim and the facts disagree often enough to matter.

This page is about evaluating your own agent: the one you are building, on your tasks, before you ship it and while it runs. Public agentic benchmarks (GAIA, OSWorld, WebArena, τ²-bench, Terminal-Bench, METR time horizons) and how each was broken in 2026 belong to {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}}, which also owns pass^k on real τ²-bench trials and the Terminal-Bench verifier exploit; this page links them and applies them. The parent, {{Topic: evaluation-and-llm-judges|n:3c65c17b0d0d8181b351e1b8fc6a1546}}, explains why any eval is a measuring instrument that has to be calibrated; this page is that idea for agents.

In one screen

There are three things you can grade, and they answer different questions. Every row below is measured on this page on 400 real τ²-bench airline trials (GPT-5.2 and Claude Opus 4.5, four trials of each of 50 tasks, the trajectory files Sierra released with its leaderboard), re-graded with τ²-bench's own evaluator.

The rule this page argues for
Grade the outcome first, with code, on a state you can diff. Grade actions (not messages) wherever an action can do harm the outcome check does not see. Use the path only for diagnosis or for actions that must never happen, never as an exact sequence to match. Read failing and suspiciously passing transcripts every time the number moves. This is close to Anthropic's own advice, "it's often better to grade what the agent produced, not the path it took" ({{Demystifying evals for AI agents|https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents}}, 9 Jan 2026), with one addition from the safety results below: what an agent did along the way is part of what it produced.

One trajectory, three graders

Pick a real trial and step through it. Each tool call lights up as it happens; the three panels show what each grader would say if the run stopped here. The message grader sees only the agent's replies; the outcome grader sees the database diffed against the gold database; the step grader matches each call against the task's gold actions. The default trial ends with all three disagreeing in an instructive way.

Trial
Highlight

Try: run the default trial to the end with "Message only", then switch to "Final state". Then pick the Claude Opus 4.5 trial of the same task, the only one of eight that passed, and compare who proposed insurance.

What the five trials show between them:

  • GPT-5.2, task 29, trial 1. The agent explains the policy, cancels and rebooks, and ends "All set." The transcript judge marks all three of its assertions met. The database disagrees on six fields: the gold booking has no insurance and one $282 card payment; the agent booked insurance and split the payment across a gift card and the card. But the simulated user asked for both ("Insurance on the new booking: Yes, please"; "use gift_card_6468981"); the task's instructions never mention either. Only the step view shows that the outcome check is enforcing the task author's unstated assumption against the simulated user's improvisation. Task 29 passed in 1 of 8 trials across the two models.
  • GPT-5.2, task 0, trial 3. The task is to refuse a cancellation the policy does not allow. The agent transfers to a human instead. Nothing in the database changes, so the outcome check passes and the trial scores 1; the transcript judge says the agent "did not refuse". Here the outcome grader is too lenient.
  • GPT-5.2, task 12, trial 1. The database is exactly right. The gold-action check still fails one step: the gold path calls calculate for the fare difference and the agent did the arithmetic itself. A path grader that demanded every gold call would fail a correct run.
  • GPT-5.2, task 31, trial 1. The user, unable to change a basic-economy flight, ends "this is exactly what I needed": the agent upgraded the cabin to economy and then moved the flight, for $47. The gold outcome is "no change", so the trial fails. Anthropic describes Opus 4.5 finding a policy loophole in a τ²-bench flight task that "'failed' the evaluation as written, but actually came up with a better solution for the user" ({{Anthropic, 9 Jan 2026|https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents}}); whether this is the same task is unconfirmed, but it is the same pattern.
  • Claude Opus 4.5, task 29, trial 2. All three graders agree. Here the agent proposed the booking without insurance, charged to the card on file, and the simulated user accepted ("no, please do not add travel insurance"): the gold reservation, so the database matches.
