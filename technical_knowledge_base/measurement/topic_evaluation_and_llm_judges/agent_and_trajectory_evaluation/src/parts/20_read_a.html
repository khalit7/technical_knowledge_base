The idea in one sentenceAn agent is judged by what it did, not by what it said: check the end state of the world with code, check the actions wherever they can do harm the end state does not show, use the exact path only to diagnose, and run every task several times, because one run is a sample.

Three graders read three different parts of the same run, and disagree

One τ²-bench airline trial as a grader sees it: the messages (what the agent said), the tool calls (what it did, reads and writes) and the database before and after (what changed). Each grader reads one layer, and here they split: the judge passes the trial, the other two fail it. ✓ matches a gold call, ≈ same tool with different arguments, + not in the gold path. measured here

Public agent benchmarks and their scores are on {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}}; this page is about evaluating your own agent, on your tasks, before you ship it and while it runs.

Task / trial: one test with inputs and success criteria / one attempt at it (Anthropic's vocabulary).
Transcript (trajectory): "the complete record of a trial, including outputs, tool calls, reasoning, intermediate results".
Outcome: "the final state in the environment at the end of the trial"; outcome grading checks it, process grading checks the steps.
Gold actions / gold state: the task author's reference tool calls, and the state they produce when replayed.
Simulated user: a model playing the customer from written instructions, so a conversation can be re-run without a person.
pass^k: the probability that all k trials of a task succeed; pass@k: that at least one does.
Process reward model (PRM): a trained model that scores each step rather than the end.

The rule this page argues for
Grade the outcome first, with code, on a state you can diff. Grade actions (not messages) wherever an action can do harm the outcome check does not see. Use the path only for diagnosis or for actions that must never happen, never as an exact sequence to match. Read failing and suspiciously passing transcripts every time the number moves. Anthropic's own advice is close: "it's often better to grade what the agent produced, not the path it took" ({{Demystifying evals for AI agents|https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents}}, 9 Jan 2026), with one addition from the safety results below: what an agent did along the way is part of what it produced.

Where the data comes from
Sierra's released trajectory files for the GPT-5.2 (high) and Claude Opus 4.5 (high) airline submissions (26 Feb 2026, user simulator GPT-5.2; {{GPT-5.2 file|https://sierra-tau-bench-public.s3.us-west-2.amazonaws.com/submissions/gpt-5-2_sierra_2026-02-26/trajectories/gpt-5.2_high_airline_gpt-5.2_4trials.json}}, {{Opus 4.5 file|https://sierra-tau-bench-public.s3.us-west-2.amazonaws.com/submissions/claude-opus-4-5_sierra_2026-02-26/trajectories/claude-opus-4-5_high_airline_gpt-5.2_4trials.json}}, MIT). The message verdicts are τ²-bench's own natural-language assertions, graded by an LLM judge over the transcript and stored in the files; airline does not count them toward the reward. The database diffs were computed for this page by replaying the agent's calls and the gold actions in {{τ²-bench's environment|https://github.com/sierra-research/tau2-bench}} (commit 5bfa7e3, 28 Sep 2026); re-grading all 200 GPT-5.2 airline trials with its evaluator reproduces every recorded reward (200 of 200). Long messages and tool results are clipped for display. Every trial with all five verdicts is in the {{Three graders, 400 trials|#t-grade}} tab.
