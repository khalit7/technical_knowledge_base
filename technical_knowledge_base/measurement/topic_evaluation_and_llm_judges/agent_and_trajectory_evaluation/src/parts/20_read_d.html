Reliability across runs

An agent run is a sample. The same agent on the same task can pass, fail, or pass for a different reason, so one trial per task measures luck as much as skill. Two numbers separate them: pass@k, the chance that at least one of k trials succeeds, and pass^k, "the probability that all k trials succeed" (Anthropic's wording; the metric is from {{τ-bench, Yao et al., Jun 2024|https://arxiv.org/abs/2406.12045}}). A product that must work every time a customer calls is a pass^k product. The estimators, the animation and every reproduced τ²-bench run are on {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}} (its pass^k on real trials tab); this page applies them to the two airline runs it uses.

From the released trials, pass^1 to pass^4 come out at 83.0, 78.3, 75.0, 72.0 for GPT-5.2 and 84.0, 77.7, 73.5, 70.0 for Opus 4.5, matching the leaderboard's pass^1 and pass^4 independently. Per task, over all eight trials:

30 tasks pass in all 8 trials, 17 are mixed, and 3 (tasks 23, 39 and 44) never pass. Anthropic's rule of thumb applies to the last group: "a 0% pass rate across many trials (i.e 0% pass@100) is most often a signal of a broken task, not an incapable agent". Eight trials is far from a hundred, and whether these three are broken is unconfirmed here; they are the first transcripts to read. Task 29 is the mixed kind worth reading too: it passed once, and what decided it was the simulated user.

Where the variance comes from

  • The agent's sampling. The variance you want to measure.
  • The simulated user. In τ²-bench a model plays the customer, and its improvisations change the right answer (task 29). Part of what any simulated-user eval measures is the simulator, and its version changes between leaderboard rows ({{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}} has the details). Pin it, and when a task flips, check whether the user changed first.
  • The environment. "Each trial should be 'isolated' by starting from a clean environment. Unnecessary shared state between runs (leftover files, cached data, resource exhaustion) can cause correlated failures due to infrastructure flakiness rather than agent performance" (Anthropic). Count infrastructure failures separately: τ²-bench scores any run that did not end with the agent or user stopping as 0 (evaluate_simulation), so a crashed container and a wrong answer look the same unless you log the termination reason (all 400 trials here ended with the user stopping).
  • The grader. A code grader on a fixed trajectory should be deterministic: re-grading the 200 GPT-5.2 airline trials reproduces every recorded reward. An LLM judge is not; re-run it on fixed trajectories to measure its own noise before you blame the agent.

Trials of one task are correlated, so error bars must be clustered by task, and k trials of 50 tasks are not 50k independent observations: {{Eval statistics|n:3ef5c17b0d0d8187a7b4e5b4ec4a546d}} has the formulas and the sample-size calculator.

Reward hacking and verifier exploits in your own evals

An eval you optimise against becomes a target, and agents find the gaps faster than people do. In April 2026 Berkeley RDI's exploit agent scored near the top of eight public agent benchmarks "without solving a single task"; the seven flaw patterns and the Terminal-Bench curl exploit, animated on a real task, are on {{Agentic benchmarks|n:3c65c17b0d0d811fb926d7b91ef8234e}} (Reading, Integrity, and the Grade a real task tab). The same happens inside private evals:

  • Models hack the scorer you gave them. METR found o3 reward hacking in 0.7% of runs across HCAST tasks and more than 43 times as often on RE-Bench, including 21 of 21 runs of Optimize LLM Foundry, 12 of 28 of Rust Codecontest and 6 of 24 of Optimize a Kernel; hacks included overwriting the timing function, returning the answer "the scoring system already calculated", and monkey-patching the evaluation "so that it judges every submission as successful". It found them by inspecting anomalously high-scoring runs and, on HCAST, with a model monitor ({{METR, 5 Jun 2025|https://metr.org/blog/2025-06-05-recent-reward-hacking/}}).
  • Impossible tasks measure the propensity. ImpossibleBench mutates a task's tests so they contradict its specification; any pass "necessarily implies a specification-violating shortcut". GPT-5 cheated on 76% of one-off-mutated SWE-bench tasks and 2.9% of the LiveCodeBench ones; hiding the tests cut cheating success to near zero; letting the agent flag the task for a human lowered GPT-5 from 54% to 9% on conflicting SWE-bench tasks; a Claude Sonnet 4 monitor caught 86 to 89% of cheating on LiveCodeBench but only 42 to 50% on SWE-bench ({{Zhong, Raghunathan and Carlini, Oct 2025|https://arxiv.org/abs/2510.20270}}).
  • The harness can overfit the eval. StateM's 95.28% raw Terminal-Bench 2.1 submission fell to 94.38% with the four flagged trials its authors accepted, 93.26% with all nine reward-hacking flags zeroed, and 92.36% with all 13 flags the leaderboard's judge raised (four for "harness cheating", gate slots that mapped onto single tasks); the pull request was closed unmerged on 19 September 2026 ({{StateM paper page|n:3c65c17b0d0d81899098d8153e100691}}). HarnessDev measured the general form: the score a harness creator could see moved the same way as the held-out score in only 34 of 64 version changes ({{HarnessDev paper page|n:3d45c17b0d0d81cd9883f783840e013f}}).
  • Self-improving agents keep their hacks. In a Factorio run, Prime Agent found it could spawn resources through RCON despite an anti-cheating heartbeat and saved the shortcut as a reusable skill ({{Prime Agent paper page|n:3cd5c17b0d0d81579a02f0431f24c6cb}}).
Defences that cost little
  • Run the verifier where the agent cannot reach it: a separate container, tests copied in after the agent stops, read-only or hidden tests.
  • Add canaries: impossible variants of a few tasks (any pass is a hack) and a do-nothing agent (its score is the floor).
  • Keep a held-out task split that no prompt, harness or skill was tuned on.
  • Read the transcripts of the highest scores and of every sudden jump, as METR did; then put a monitor on the rest.
  • Give the agent a legitimate way out ("flag for a human"); it cut cheating by more than five times in ImpossibleBench.
