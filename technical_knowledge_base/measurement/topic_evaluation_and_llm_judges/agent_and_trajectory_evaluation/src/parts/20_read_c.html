Step-level grading: where it went wrong, and what not to demand

A step grader looks inside the trajectory: gold-action matching (did the agent make each reference call with those arguments; τ²-bench computes it as action_checks, marked read, write or generic, though its airline and retail rewards do not use it), trajectory matching of the whole call sequence (LangChain's {{agentevals|https://github.com/langchain-ai/agentevals}}: strict, unordered, subset, superset, each with a tool_args_match_mode), per-step judges and process reward models (next section), and efficiency counts (calls, failed and repeated calls, tokens, time).

Demanding the reference path is the common mistake. Anthropic: "There is a common instinct to check that agents followed very specific steps like a sequence of tool calls in the right order. We've found this approach too rigid and results in overly brittle tests, as agents regularly find valid approaches that eval designers didn't anticipate." On the 400 trials, τ²-bench's gold-action check fails on 24 trials whose database is exactly right, usually over read calls (a lookup the agent did not need, or a calculate it did in its head, as in task 12).

Loosen the path match to "the same writes, any order" and it agrees with the outcome on 198 of 200

agentevals' match modes, ported line by line and run against τ²-bench's gold actions on GPT-5.2's 200 airline trials, exact arguments: how often each matcher's verdict equals the final-state verdict. Matching every call strictly in order passes only 7 trials and agrees on 38; matching write calls in any order agrees on 198. measured here

Steps earn their keep in four places:

  1. Diagnosis. The outcome says "fail"; the steps say which call, with which argument, after which user turn. Every number on this page was explained by reading steps.
  2. Actions that must never happen, as hard checks (previous section).
  3. Cost and efficiency, which the outcome cannot see: two agents that reach the same state with 7 calls and with 70 are not the same agent ({{Cost and budgets|#rd-cost}}).
  4. When the outcome is unobservable or arrives too late: long tasks, production actions you cannot replay, intermediate checkpoints for partial credit.

Who grades a trajectory: judges, agent judges and process reward models

Code graders cover what you can specify. For the rest (was the plan sensible, was the user handled well, did a research agent's report answer the question) a model grades the trajectory, in one of three designs. Each needs its own calibration against people, as {{LLM-as-judge|n:3c65c17b0d0d810ba2a2ecc08c4c233b}} argues for every judge.

A judge that can act agrees with experts far more often than one that only reads

Top: what each design reads. Below: the same judge without and with tools. DevAI: agreement with three experts' consensus on 365 requirements (OpenHands' outputs, black-box setting); AJ-Bench: the judge's score on 516 annotated trajectories. published by each paper's authors; the two benchmarks use different measures, so compare the gaps, not the bars across rows.

  • Trajectory LLM judge. A model reads the transcript and answers a rubric (τ²-bench's natural-language assertions; agentevals' default TRAJECTORY_ACCURACY_PROMPT). On web agents "no single LLM excels across all benchmarks": the best of 12, GPT-4o with accessibility trees, reached 69.8% precision, below the rule checkers' 83.8% but with far better recall.
  • Agent-as-a-judge. The judge acts: it opens the produced repository, runs code and checks each requirement against evidence. On DevAI (55 AI-development tasks) it agreed with the experts on 90.44% of requirements against 60.38% for an LLM judge without tools, for $30.58 and 118.43 minutes against about $1,297.50 and 86.5 hours for three experts ({{Zhuge et al., Oct 2024|https://arxiv.org/abs/2410.10934}}). A third party confirms the direction: on AJ-Bench, tools lifted DeepSeek V3.2 from 64.49 to 77.34 (+12.85 points) and GPT-5-mini (low) from 59.00 to 72.41 (+13.41) ({{Shi et al., AJ-Bench, Apr 2026, preprint|https://arxiv.org/abs/2604.18240}}).
  • Process reward model. Scores each step; as an evaluator it gives a per-step curve that locates the step where success became unlikely. It is a trained model, so an agent optimised against it can exploit it (see {{Reward Hacking|n:3c65c17b0d0d8196a6f1f29a817aa974}}), and its step scores need the same meta-evaluation as any judge.
Correction: DevAI's cost and time percentages are swapped in the paper (carried from the root's Judge atlas)
Section 4.4 says the agent judge cost 2.29% of the human cost and took 2.36% of the time. Its own figures give the reverse: $30.58 / $1,297.50 = 2.36% of the cost, and 118.43 of 5,190 minutes = 2.28% of the time. The abstract's savings (97.64% of the cost, 97.72% of the time) agree with the figures.

A judge only knows what it is shown. MOLE's monitors are trajectory judges: on the three multiday corpora whose agents wrote reasoning, GPT-4.1 reading that reasoning had higher recall than GPT-5.5 reading only the audit events (0.49 against 0.39, 0.71 against 0.52, 0.68 against 0.45), and the 600-character clip hid every data-poisoning trigger. Decide what the judge sees as deliberately as which judge you use, and log enough that you can change your mind later.

More on judges: mobile agents, process reward models' origin, MOLE's intervals

AgentRewardBench: experts labelled 1,302 trajectories from 5 benchmarks and 4 agents to test the 12 judges.

Mobile agents. On 931 mobile-agent trajectories, a simple judge reading sampled screenshots (90.9% with Gemini 3 Flash, the authors' own baseline) matched or beat purpose-built pipelines (89.3% for AgentRewardBench's method) ({{MobileJudgeBench, Aug 2026, preprint|https://arxiv.org/abs/2608.11434}}).

AJ-Bench has 155 tasks in search, data systems and GUI. DevAI has 365 hierarchical requirements and three expert annotators; the agent-judge figures are the paper's own runs.

Process reward models. The idea came from maths: OpenAI found "process supervision significantly outperforms outcome supervision" for training on MATH, with its process-supervised model solving 78% of a representative test subset, and released PRM800K, 800,000 step-level human labels ({{Lightman et al., May 2023|https://arxiv.org/abs/2305.20050}}). For agents, AgentPRM learns step values from Monte Carlo rollouts (how often does the task succeed if you continue from here?) and InversePRM learns them from demonstrations; 3B models trained with them beat GPT-4o baselines on ALFWorld ({{Choudhury, Feb 2025|https://arxiv.org/abs/2502.10325}}); the paper itself analyses reward hacking.

MOLE's monitor comparison: the paired interval excludes zero on one corpus, is borderline on one and not established on one.
