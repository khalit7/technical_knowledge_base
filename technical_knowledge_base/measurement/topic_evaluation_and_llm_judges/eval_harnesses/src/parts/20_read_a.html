The idea in one sentence. A benchmark score is the output of a chain of harness decisions (prompt template, few-shot examples, chat template, reading the answer by log-likelihood or by generation, answer extraction, normalisation), every harness makes them differently by default, and changing one link moves the same weights on the same questions by tens of points.

Every number on this chain was measured on one model with one link changed. Qwen2.5-0.5B-Instruct on 200 MMLU test items, ten harness settings (section 3, {{Why scores differ|#rd-why}}); the GSM8K line is this page's own lm-eval run, two filters on identical outputs. The one figure not from that model: LLaMA-65B, 63.6 under the original MMLU code against 48.8 under lm-eval-harness as of January 2023 (Hugging Face, 23 June 2023).

New terms

  • Harness: the program that turns a benchmark into a number (not the agent "harness" that runs a model in a loop, which is {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}}).
  • Shots: solved examples placed in the prompt before the question.
  • Log-likelihood scoring: compare the model's probabilities of given answers; generative scoring: let it write, then parse.
  • Extraction (lm-eval: filter): the code that finds the answer in generated text.
  • Solver and scorer (Inspect): a step that changes the sample's state; the function that grades the final state.
  • acc_norm: log-likelihood divided by the answer's length in characters.

The boundary rule
Model-level harnesses answer "is this checkpoint good?"; app-level tools answer "is this system change safe to ship?". A regression gate on a model swap is the second kind even when the trigger is a model: run a harness for the candidate's general capability, and app-level golden sets for the product surface ({{Production eval engineering|n:3c65c17b0d0d81b39ad9e96193d21adc}} owns gates and golden sets).
