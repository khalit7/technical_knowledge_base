1. Two designs: a list of requests, or a program per sample

Every harness loads items, gets the model to respond and turns the response into a number. What it treats as the unit of work decides what it can score, what it logs and whether it can run an agent safely.

  • lm-evaluation-harness builds requests. A YAML file says how to render each document into text; the harness builds every request up front (context plus a log-probability to compute or a generation with stop strings), sends them in batches to a backend that implements only three methods, then runs filters and metrics over the responses. Nothing happens per sample that the YAML did not declare: reproducible, and it scales to hundreds of fixed tasks.
  • Inspect runs a program per sample. A Sample becomes a TaskState; a chain of solvers transforms it (add a system message, fill a template, call the model, call a tool, critique, loop as an agent); a scorer grades the final state; every step is recorded as an event. It can express agents, sandboxes and judge batteries, and its logs are complete.
