When a number moves, the first three suspects are a real capability change, a broken extraction filter and a truncated completion; only per-sample logs separate them (tab {{Inside a run log|#t-logs}} walks both formats from the real runs).

Logs can misreport: token counts from Inspect's local provider
Inspect's local Hugging Face provider records each sample's usage as the padded batch shape: in this page's run every one of the ten samples logged 2,269 input and 494 output tokens, while the real prompts were 2,184 to 2,269 tokens and the outputs 146 to 493 ({{hf.py lines 651 to 652|https://github.com/UKGovernmentBEIS/inspect_ai/blob/9f6accda8dce5ccd754e6be1a22fbcee96042e82/src/inspect_ai/model/_providers/hf.py#L651-L652}}; counts in src/data/runs.json), and the stop reason was "unknown". API providers report real usage; for a local model, count tokens yourself before using the log to spot truncation.
  • Seeds and sampling. Greedy is not the default everywhere (Inspect's local provider samples, section 2). With sampling, run several epochs and report the spread; Inspect's Epochs reruns each sample and reduces with mean, median, mode, max, at_least_k or pass_at_k.
  • Serving. The same weights behind different providers or precisions are different instruments: Llama 3.1 8B Instruct through Together's FP8 endpoint scored 56.06 on HELM's MMLU against Meta's 69.4 (confounded with the prompt and token budget); lighteval's own example compares one model across three Inference Providers for this reason.

5. Running evals at scale: tokens, batching, caching

Cost and time are driven by tokens, and the harness decides most of them before the model runs. The page's own two runs, per GSM8K problem:

Inspect's prompt is 2.3 times lm-eval's, and 87% to 92% of it is the same system message every time. Real token counts with the model's tokenizer (src/data/runs.json); share of prompt characters in the identical 10-shot system message, measured on all ten prompts. lm-eval draws a different five shots per problem, so no two of its prompts share a prefix.

Derived for the full test set (1,319 problems, mean per problem times 1,319): lm-eval's prompt about 1.27 million input and 0.15 million output tokens; inspect_evals' about 2.93 million input and 0.42 million output, per epoch. Cost is items x (input tokens x input price + output tokens x output price) x epochs; prices are volatile and belong to the provider pages. Measured wall time for the ten problems on 2 CPU threads: 132 s (lm-eval, 256-token cap) against 763 s (Inspect, 512-token cap), confounded by prompt length, output length and batching, so not a speed comparison of the harnesses.

  • Shots dominate input cost. Ten shots made 87% to 92% of every Inspect prompt here. Fewer shots, or shots the model does not need, are the cheapest saving; check the effect on the score first (section 2).
  • A fixed prefix is cacheable. Inspect's identical system message is exactly what provider prompt caching and a serving engine's prefix cache reuse; lm-eval's per-problem shots defeat it. Whether a cache hit is billed less is the provider's rule.
  • Batching, lm-eval. --batch_size takes an integer, auto or auto:N (default 1), with --max_batch_size as the ceiling ({{interface.md|https://github.com/EleutherAI/lm-evaluation-harness/blob/d6de81643928d653435c431bae19945d41d32520/docs/interface.md}}). The Hugging Face backend sorts requests longest first, so "any OOMs will happen right away rather than near the end" and the first batch sets the padded length; on out-of-memory it halves the batch and retries. For multiple choice it groups requests that share a context and reuses one forward pass for one-token continuations, which "speeds up some multiple-choice tasks proportionally to the number of choices" ({{huggingface.py|https://github.com/EleutherAI/lm-evaluation-harness/blob/d6de81643928d653435c431bae19945d41d32520/lm_eval/models/huggingface.py#L1336-L1365}}). Serving engines (vLLM, SGLang backends) batch for you.
  • Concurrency, Inspect. Inspect is built around API calls in flight rather than local batches: adaptive concurrency by default "with a maximum of 100 concurrent connections per model", starting at 20, cutting the limit by a factor of 0.8 on a rate-limit error, and retrying recoverable errors indefinitely with exponential backoff unless --max-retries or --timeout caps it ({{model concurrency|https://inspect.aisi.org.uk/models-concurrency.html}}). max_samples follows the connection limit; one task runs at a time unless --max-tasks is raised ({{parallelism|https://inspect.aisi.org.uk/parallelism.html}}).
  • Caching responses. lm-eval's --use_cache keeps model responses in SQLite under a path prefix and --cache_requests caches the built prompts. Inspect's --cache (or cache=True) keys on the model and base URL, the message history, the epoch, the generate config and the active tools, and "will expire in 1 week" unless a CachePolicy says otherwise ({{caching|https://inspect.aisi.org.uk/caching.html}}). A cache makes reruns cheap and can replay a stale answer after a provider silently updates a model: a cached run measures the old one.
  • Subsets. --limit (both harnesses) runs the first n items for a smoke test; a number from it is not the benchmark's number, and how many items a difference needs is {{Eval statistics|n:3ef5c17b0d0d8187a7b4e5b4ec4a546d}}'s question.

6. Sandboxes for agentic evals

An agent eval lets model-written code and commands run. Inspect makes the environment part of the task: tools such as bash(), python() and text_editor() require a sandbox, each sample can get its own, and the environment is declared next to the task as a Dockerfile or compose.yaml ({{Sandboxing|https://inspect.aisi.org.uk/sandboxing.html}}). Nothing else here compares: lm-eval runs code tasks such as HumanEval on the host, gated by unsafe_code: true in the task and --confirm_run_unsafe_code; HELM, simple-evals and openai/evals have no sandbox layer; Braintrust connects agent code through "remote evals or sandboxes" ({{docs|https://braintrust.dev/docs/evaluate/remote-evals}}); promptfoo grades agent trajectories but does not isolate them. Inspect's local sandbox and lm-eval's flag both run model code as you on your machine.
