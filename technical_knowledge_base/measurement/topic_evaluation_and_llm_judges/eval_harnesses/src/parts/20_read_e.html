App-level tools: promptfoo and Braintrust

A different job: evaluating your application (prompt, model, retrieval, tools and code together) on your own cases, not a model on public tasks.

  • {{promptfoo|https://github.com/promptfoo/promptfoo}}: open source (MIT), command line and YAML first, local first. A promptfooconfig.yaml declares a matrix: prompts x providers x test cases, each test with assertions ({{getting-started example|https://github.com/promptfoo/promptfoo/blob/5fde786d0c296339be3fd189d1542157e1d4217a/examples/getting-started/promptfooconfig.yaml}}). At commit 5fde786 its docs list 44 deterministic assertion types (from equals, contains and regex to is-json, latency, cost, tool-call F1 and trajectory checks such as trajectory:tool-sequence) and 17 model-assisted ones (llm-rubric, g-eval, factuality, context-faithfulness, trajectory:goal-success and others) ({{assertions|https://github.com/promptfoo/promptfoo/blob/5fde786d0c296339be3fd189d1542157e1d4217a/site/docs/configuration/expected-outputs/index.md}}). It has a diff view, CI integration and a serious red-teaming and vulnerability-scanning mode. On 9 March 2026 Promptfoo announced it "has agreed to be acquired by OpenAI" and "will remain open source"; the README now says it "is now part of OpenAI" and remains MIT licensed ({{announcement|https://www.promptfoo.dev/blog/promptfoo-joining-openai/}}). Choose it for repository-local prompt regression tests and multi-model comparisons with the fastest setup.
  • {{Braintrust|https://www.braintrust.dev/docs/evaluate}}: a commercial platform. Every evaluation has three parts, data, task and scorers: Eval("My project", data=init_dataset(...), task=..., scores=[Factuality]), run with bt eval ({{run in code|https://braintrust.dev/docs/evaluate/run-in-code}}). Playground runs overwrite themselves; experiments are immutable snapshots meant for comparison and CI gates; datasets are versioned so experiments can pin a version; scorers come from its open-source {{autoevals|https://github.com/braintrustdata/autoevals}} library, code or LLM judges; online scoring rules grade production traces asynchronously, which, with no ground truth on live traffic, means judge scorers ({{online scoring|https://braintrust.dev/docs/evaluate/score-online}}). Human review is built in. Choose it when you want the loop from offline evaluation to production observability in one place and are willing to pay for it.

Alternatives in the same niche, named here without a review: {{Langfuse|https://github.com/langfuse/langfuse}}, {{Arize Phoenix|https://github.com/Arize-ai/phoenix}} and {{W&B Weave|https://github.com/wandb/weave}}. Observability of agent systems belongs to {{Topic: agentic-frameworks|n:3c65c17b0d0d81ab8432c54d65b7f8c7}}, and tracing used to evaluate an agent (OpenTelemetry GenAI conventions, trajectories graded step by step) to {{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}; how to build gates, golden sets and promotion paths with any of these tools belongs to {{Production eval engineering|n:3c65c17b0d0d81b39ad9e96193d21adc}}.

The boundary rule
Model-level harnesses answer "is this checkpoint good?"; app-level tools answer "is this system change safe to ship?". Khalid's regression-gate work is the second kind even when the trigger is a model swap. The pattern that works: a harness for the swap candidate's general capabilities, app-level golden sets for the product surface.

Reproducibility and logging

A score is reproducible only if every input to it is pinned and every output is kept. The harnesses differ most in the second.

What the logs are for: when a number moves, the first three suspects are a genuine capability change, a broken extraction filter, and a truncated completion. Only per-sample logs separate them. The tab {{Inside a run log|#t-logs}} shows both formats from real runs.

  • Seeds and sampling. Greedy decoding is not the default everywhere (Inspect's local Hugging Face provider samples, above). With sampling, run several epochs and report the spread; see {{Eval statistics|n:3ef5c17b0d0d8187a7b4e5b4ec4a546d}} for how many items and repeats a difference needs.
  • Token counts can be the batch's. Inspect's local Hugging Face provider records each sample's usage as the padded batch shape: in this page's run every one of the ten samples logged 2,269 input and 494 output tokens, while the real prompts were 2,184 to 2,269 tokens and the outputs 146 to 493 ({{hf.py lines 651 to 652|https://github.com/UKGovernmentBEIS/inspect_ai/blob/9f6accda8dce5ccd754e6be1a22fbcee96042e82/src/inspect_ai/model/_providers/hf.py#L651-L652}}; counts in src/data/runs.json). Its stop reason was logged as "unknown". API providers report real usage; for a local model, count tokens yourself before using the log to spot truncation.
  • Serving. The same weights behind different providers or precisions are different instruments; lighteval's own example compares one model across three Inference Providers for this reason.
  • Caching makes reruns cheap and can also replay a stale answer: lm-eval's --use_cache is keyed by model and task, and Inspect's generate(cache=True) by the model, its settings and the messages.

Sandboxes for agentic evals

An agent eval lets model-written code and commands run. Inspect makes that a first-class part of the task: tools such as bash(), python() and text_editor() require a sandbox, each sample can get its own, and the environment is declared next to the task as a Dockerfile or compose.yaml ({{Sandboxing|https://inspect.aisi.org.uk/sandboxing.html}}). Nothing else here compares. lm-eval runs code tasks such as HumanEval on the host, gated by unsafe_code: true in the task and --confirm_run_unsafe_code on the command line; HELM, simple-evals and openai/evals have no sandbox layer; Braintrust connects agent code to its playground through "remote evals or sandboxes" ({{docs|https://braintrust.dev/docs/evaluate/remote-evals}}); promptfoo grades agent trajectories but does not isolate them. How to grade what an agent did, rather than its last message, is {{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}; public agentic benchmarks (pass^k, METR horizons, Terminal-Bench exploits) are on Topic: benchmarks' {{Agentic|n:3c65c17b0d0d811fb926d7b91ef8234e}} page.

The opposite trade: a harness inside an enclave
Google DeepMind's August 2026 double-blind pilot ran a proprietary model and private items inside a confidential-computing enclave so neither side saw the other's secret; its cost is the thing Inspect's log viewer exists for: no one can read the transcripts, so a bad score cannot be attributed to capability, a broken extraction filter or a truncated completion.
