1. The five layers, cheapest to most faithful

Mature stacks run all five. Each one catches something the previous one cannot, at a higher price per judgment, and each has a page that owns it.

Static benchmarksFixed questions, scored by a program: exact match, a regex on the answer, unit tests, or the probability the model gives each option.Cost: cents per item, deterministic.Catches: capability changes on closed-form tasks, reproducibly.How a benchmark becomes a score: {{Eval harnesses|n:3c65c17b0d0d81ea9cd5eb65795ff5c9}}
LLM-as-judgeA model grades open-ended outputs: pointwise, pairwise, or against a rubric or reference.Cost: one model call per item.Catches what a regex cannot: quality, helpfulness, style, partial credit. A biased proxy for humans.{{LLM-as-judge|n:3c65c17b0d0d810ba2a2ecc08c4c233b}}
Human evaluationExperts against a gold standard, or crowds voting on pairs (Arena-style preference).Cost: minutes and dollars per item.Catches what the judge is blind to; it is the reference the judge is calibrated against, and it is noisy itself.{{Human evaluation and annotation|n:3ef5c17b0d0d819485bcc54a45d49420}}
Regression gatesFrozen golden sets, 100 to 500 items per product surface, run in CI on every prompt, model or retrieval change.Cost: minutes per change.Catches regressions on your product before release, which public benchmarks never see.{{Production eval engineering|n:3c65c17b0d0d81b39ad9e96193d21adc#rd-ci}}, sections 2 to 4
Online measurementShadow deployment on mirrored traffic, then canary and A/B tests with live metrics.Cost: real traffic and real risk.Catches what no curated set imagined: real traffic is uglier than any golden set.{{Production eval engineering|n:3c65c17b0d0d81b39ad9e96193d21adc#rd-online}}, sections 7 to 9

What the system is changes what you grade. A single model call is graded on its text. An agent is graded on the state its tool calls changed and on how reliably it does so across runs (pass^k): {{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}}. A RAG system has two halves that fail separately, retrieval (did the right passages arrive?) and generation (is the answer faithful to them?): {{RAG and retrieval evaluation|n:3ef5c17b0d0d8194a914d1843ee26f13}}.

Runtime guardrails (classifiers in the request path, before, during and after the model call) are evals too, measured with the same machinery. Their page moved to {{Topic: agentic-harnesses|n:3c65c17b0d0d81d881a8fe98b4cff7bb}} on 24 October 2026: {{Guardrails|n:3c65c17b0d0d819bbfa5dffa9246c297}}.

The one distinction that shows only across the children: the scoring method is part of the instrument. In June 2023 Hugging Face scored the same LLaMA-65B checkpoint on the same MMLU questions three ways: 0.636 with the original implementation (probability of the letters A to D), 0.637 with HELM's (the model generates a letter) and 0.488 with the evaluation harness of the time (probability of the full answer text) ({{Hugging Face, What's going on with the Open LLM Leaderboard?|https://huggingface.co/blog/open-llm-leaderboard-mmlu}}). A score from one harness cannot be set beside a score from another, whatever both call the benchmark. On a small chat model the chat template, the answer parser and one instruction line move the score far more than log-likelihood against generation does; the measured spread for one model across ten settings is in {{Eval harnesses, section 3|n:3c65c17b0d0d81ea9cd5eb65795ff5c9#rd-why}}.
