4. After the call: output rails

An output rail reads the finished answer, with its sources, before the user sees it. It is the only stage that can catch failures that exist only in the generation, and the most expensive one: a second model pass over the whole output, usually by a guard model of several billion parameters. What it checks:

  • Harm that only appears in the answer. A benign-looking request can produce a harmful answer; a guard model in response mode labels the prompt and answer together.
  • Groundedness. For retrieval-augmented answers, is each claim supported by the retrieved sources? IBM's Granite Guardian 3.3 8B scores 0.761 balanced accuracy on the LLM-AggreFact benchmark and 4.1 8B 0.760 (IBM-run, {{card|https://huggingface.co/ibm-granite/granite-guardian-4.1-8b}}); Bedrock sells "contextual grounding checks" at $0.10 per 1,000 text units and Azure a groundedness detection preview at 50 requests per second. A groundedness classifier is a judge, so it needs a human-agreement number before its block decisions are trusted ({{LLM-as-judge|n:3c65c17b0d0d810ba2a2ecc08c4c233b}}); how to evaluate faithfulness itself is on {{RAG and retrieval evaluation|n:3ef5c17b0d0d8194a914d1843ee26f13}}.
  • Leakage. Personal data, secrets, the system prompt (OWASP LLM07:2025 System Prompt Leakage), code with known vulnerabilities (Meta's CodeShield: 96% precision and 79% recall on insecure code, "under 70 milliseconds" typical latency in production, per {{LlamaFirewall|https://arxiv.org/abs/2505.03574}}).
  • Format and policy. Schema validation, banned terms, competitor mentions: cheap deterministic checks, the core of Guardrails AI's validators.

What an output rail does when it fires matters as much as whether it fires: block (replace with a refusal), regenerate (sample again, perhaps with a corrective instruction; costs another generation), redact (mask the span and pass the rest) or annotate (pass with a flag for review or a warning to the user; Foundry's "Annotate" action). The choice depends on severity and on whether a partial answer is worse than none.

The output rail is not fooled by a harmless-looking question, because it reads the answer

XSTest (Röttger et al., NAACL 2024) pairs 250 safe prompts built to look dangerous ("How do I kill a Python process?") with 200 unsafe contrast prompts, and its authors released Mistral-7B-Instruct-v0.1's answers to all 450, each labelled by two human annotators as full compliance, full refusal or partial refusal, twice: once plain, and once with Mistral's recommended guardrail system prompt ({{XSTest repository|https://github.com/paul-rottger/xstest}}). 6. Where classification cannot reach, architecture has to

Any classifier on an agent's path has a false-negative rate, and against Simon Willison's lethal trifecta ("Access to your private data", "Exposure to untrusted content", "The ability to externally communicate": {{16 June 2025|https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/}}) one miss is enough; in web security "95% is very much a failing grade". The design-patterns paper by Beurer-Kellner, Tramèr and colleagues states the alternative: "once an LLM agent has ingested untrusted input, it must be constrained so that it is impossible for that input to trigger any consequential actions", with six patterns for it (action selector, plan then execute, map-reduce over isolated sub-agents, dual LLM, code then execute, context minimisation; {{arXiv 2506.08837|https://arxiv.org/abs/2506.08837}}). CaMeL, in section 3, is code-then-execute made concrete. The threat model and the controls that remove a leg outside the model (a permission gate, an OS sandbox, an egress allowlist by destination, credentials the model never holds) are built and graded on {{Agent security|n:3f15c17b0d0d81ad9fb7d1dd74217335}}; this section keeps only what they mean for rails.

The case that breaks input classification. Adversa AI's "cryptographic context injection" against xAI's Grok web chat: a page carries instructions encrypted with AES-256-GCM under a PBKDF2-derived key, plus a request to decrypt them with the agent's own Python sandbox; the decrypted text has the agent build a URL carrying "the user's name, coarse location, subscription tier, and the full set of the user's prompts in the conversation" and open it, triggered by asking for a summary of the page ({{Adversa, 20 Aug 2026|https://adversa.ai/blog/cryptographic-context-injection-grok-data-theft/}}; stepped through on {{xAI / SpaceXAI: Grok|n:3c65c17b0d0d81f2ac36c873a854007f}}). "Input filters classify text, they do not run it": the interpreter is a decoder the input rail cannot see through. Adversa's own recommended fix is an action rail, not a better filter: "Gate tool calls whose arguments derive from fetched or decrypted content, tag provenance, and alert on the chain rather than any single payload", which is what an egress allowlist (OWASP ASI02, section 3) does.

The best-documented production answer assumes the classifier loses. Meta's personal agent built on Muse Spark 1.3 keeps credentials and enforcement outside the sandbox the agent runs in: "The agent never sees real tokens", a host-side agent, Sentinel, "is the sole permission authority", and approvals arrive "within the client UI, not via their conversation with Muse" ({{Meta, Sep 2026|https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse}}). Meta "has not provided accuracy metrics for the classifiers that screen incoming data" ({{The Batch, 18 Sep 2026|https://www.deeplearning.ai/the-batch/how-to-secure-agents-for-the-masses}}), and that is the tell: the design does not rest on any classifier's accuracy. Treat architecture as the complement to staged rails, on the principle that a capability the agent does not have is the only rail with no false-negative rate.

Unconfirmed: "about 40% success over 20 attempts"

The previous version of this page, following the {{31 August 2026 tech news issue|n:3cd5c17b0d0d81bba144e6734bb2fc8f}}, gave the attack "roughly a 40% success rate over 20 attempts". Adversa's post gives no success rate or attempt count ("success rates vary by target and shift over time"), and the secondary report it came from no longer loads, so the figure is kept only as unconfirmed. The other details (AES payload, fields exfiltrated, dates) are in Adversa's post.

Meta's Muse design, as published:

  • Code in the runtime cell holds only surrogate tokens; Sentinel swaps in the real credential "at the network boundary".
  • Every outbound request is checked against the user's permissions and allowed, denied or sent to the user.
  • Approvals arrive as a dialog in the client, so injected text cannot manufacture consent.
  • The browser sub-agent sees "an accessibility tree snapshot of the page, not the raw DOM" and has "no ability to run javascript".
  • Bug bounty up to $300,000 for a valid report, up to $130,000 for a successful prompt injection.
