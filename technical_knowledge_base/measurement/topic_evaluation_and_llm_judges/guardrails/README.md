# Guardrails: staged runtime safety for LLM systems

Notion: https://app.notion.com/p/3c65c17b0d0d819bbfa5dffa9246c297 (child of Topic: evaluation-and-llm-judges)

Interactive page: `index.html`, built from `src/` (`sh src/build.sh`; see `src/README.md`). The three stages (input rails: injection detectors, harmful-request classifiers, PII, scope; during the call: dialog, tool-call and action rails, streaming rails; output rails: harm, groundedness, leakage), the same 450 XSTest conversations through a guardrail system prompt and through classifier rails (animated), architecture beyond classification (lethal trifecta, CaMeL, Muse, the Grok encrypted injection), frameworks and managed services as of October 2026, guard models with their published numbers kept apart by runner, latency and cost per stage, and how to evaluate a rail (both errors, over-refusal, end-to-end leak, conformal thresholds). Tabs: Reading, Pipeline lab (every conversation, every switch, trade-off curve, conformal threshold, an injection set, refusal flag), Guard model scorecards, Further reading. Two guard models, a stream guard and a PII detector were run on released data for this page. Old written page carried in full (`src/live.md`, `src/coverage.json`); no child pages, databases or video.
