Title: How we evaluate AI models and LLMs for GitHub Copilot
Authors: Connor Adams & Klint Finley (GitHub). Date on page: January 17, 2025

"We run more than 4,000 offline tests, most of them as part of our automated CI pipeline."
"We also conduct live internal evaluations, similar to canary testing, where we switch a number of Hubbers to use a new model. We test all major changes to GitHub Copilot this way, not just potential new models."
"We have a collection of around 100 containerized repositories that have passed a battery of CI tests. We modify those repositories to fail the tests, and then see whether the model can modify the codebase to once again pass the failing tests."
"We have a collection of more than 1,000 technical questions we use to evaluate the quality of a model's chat capabilities." Complex ones: "we use another LLM to check the answers"
"We also run these tests against our production models every day. If we see degradation, we do some auditing to find out why"
Proxy: "We can easily change which API the proxy server calls for responses without any sort of change on the client side."
Trade-off: "what if a model shows a substantial bump in acceptance rates, but also increases latency?"
"Higher latency might actually lead to a higher acceptance rate because users might see fewer suggestions total."
