Title: How to Evaluate LLMs: A Complete Metric Framework
Authors: Widad Machmouchi, Somit Gupta (Microsoft Experimentation Platform, ExP). Date on page: "Published September 27, 2023"

Metric families: GPU utilization (cost), Responsible AI, performance, utility.
Cost: "Number of 429 responses received ... We recommend measuring the 95th or 90th percentile of the number of 429 responses"
"Total number of tokens ... This is the main utilization metric we recommend for tracking for GPU Utilization."
"Wasted Utilization per LLM": track completion tokens on "non-actionable or unused responses"
RAI: "% Prompts with HTTP 400 error"; "% Responses with "finish_reason": "content_filter""
Latency: "Time to first token render from submission of the user prompt, measured at multiple percentiles."; "Tokens rendered per second"
Retention: "important measure to detect any novelty effect where the usage drops after the initial engagement."
"A/B testing is the golden standard to causally measure the impact of any change to the product."
Shadow: "Shadow experiments allow you to compute the treatment and control response for the same user, but only show them the control response."
"Metrics are more sensitive than regular A/B tests as the treatment and control samples have exactly the same set of users leading to variance reduction."
0-1 experiment: controlled rollout "to ensure that you have enough GPU capacity and the product OEC and guardrail metrics" are not degraded (tail paraphrased; UNVERIFIED wording)
Limitation: "metrics that need user response cannot be evaluated in shadow experiments as no user experiences the treatment response."
