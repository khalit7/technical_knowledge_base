In one screen

Every change to a shipping LLM product (a prompt edit, a model swap, a retrieval or tool change) walks the same path, and each stage is cheaper than the failure it exists to stop. The incumbent configuration is the champion; nothing ships without beating it at every stage. That is the whole discipline; the rest of this page is how each stage is built and how each one fails.

StageQuestion it answersWhat trips itCost and timeCatches what the stage before cannot
1. Offline gate on frozen golden sets, in CIDid this change break anything we already know matters?A paired drop against the champion beyond a threshold in any slice; a hard floor on safety slices; a failing deterministic assertionMinutes per change; judge calls cost money (below)Regressions on your product, which public benchmarks never see
2. Budget gateCan we afford it, and is it fast enough?Tokens per request, p95 latency or projected spend above budget. A model swap that wins quality at 3 times the cost fails unless someone waives itSeconds (computed from stage 1's runs)A quality win that the business cannot pay for
3. Shadow deploymentDoes it hold on real traffic?Per-intent score distributions of candidate against champion on the same mirrored requests; errors; latencyDoubles inference for the mirrored share; nothing reaches usersInputs nobody imagined when building the golden set: real traffic is uglier than any curated set
4. Canary, then A/B testDo users and the business actually come out ahead?Guardrail metrics (errors, refusals, complaints, task completion) crossing a rollback trigger; the primary metric not improvingDays to weeks; real users exposedWhat only behaviour shows: whether people accept, retry, abandon or escalate
5. Monitoring after full rolloutIs it still good?Drift in sampled judge scores, implicit signals or input mix; silent provider-side changesContinuous; a sampled share of live tracesDecay after launch: traffic, product and the model behind an API all move

Keep every configuration pinned and logged (prompt hash, model version, judge model and prompt version, dataset version) so that any score can be reproduced, and so that a change in score can be traced to the one thing that changed. The root page's {{five layers of evaluation|n:3c65c17b0d0d8181b351e1b8fc6a1546}} (Reading, "Evaluation in one screen") put this path in context: these are its two most expensive layers, regression gates and online measurement.
