3. One model swap, two gates

The running example, on real released grades. The champion is claude-v1; the challenger is the cheaper claude-instant-v1, the cost-down swap every product team runs. The golden set is {{MT-Bench|https://arxiv.org/abs/2306.05685}}: 80 two-turn questions in 8 categories of 10, so 160 graded turns in 8 tagged slices, each graded 1 to 10 by GPT-4. Every grade is LMSYS's own released judgment ({{gpt-4_single.jsonl|https://huggingface.co/spaces/lmsys/mt-bench/tree/main/data/mt_bench/model_judgment}}, mid-2023), not a simulation. Predict first: the two means differ by a few hundredths of a point; will any slice fail? Then step through it with one aggregate threshold, and again with thresholds per slice.

Thresholds are illustrative and the same in both runs: the aggregate gate fails a mean paired drop of 0.25 points or more; the per-slice gate fails a slice whose mean paired drop is 0.5 points or more and whose 95% interval lies wholly below zero, and sends a drop of 0.5 or more whose interval still reaches zero to review instead of passing it. Paired t intervals over graded turns, a question's two turns treated as independent; across all 561 MT-Bench model pairs the clustered standard error is a median 1.10 times the paired one (range 0.90 to 1.26), but for this pair the ratio is 1.00, so the intervals stand (measured on {{Eval statistics|n:3ef5c17b0d0d8187a7b4e5b4ec4a546d}}). Every threshold and any pair of the 34 graded models: {{Gate designer|#t-gate}}.

The average hid a one-point writing regression. Over the 159 turns both models have a grade for, the swap moves the score by −0.03 points and the aggregate gate passes it. Split by the tags the set already carries: writing drops 0.95 points (95% interval −1.51 to −0.39) and fails; extraction drops 0.70 with an interval that still crosses zero and goes to review; math improves by about as much as writing falls, which is why the mean did not move. Per-slice thresholds cost nothing extra; they only need the tags.

A flaky judge, in the released data
One of the 320 judge calls in this run produced no grade: on question 128 (coding, turn 2) GPT-4 wrote 9,516 characters, repeating "The assistant's function does not correctly..." 63 times, and never emitted a [[rating]], so the file records −1. Across all 34 models, 4 of 5,440 judgments failed this way, all on second turns, all about 9,500 to 12,000 characters long. A gate must decide what an unparsable verdict means (here: drop the pair from both sides, and count it), never average it in as a score.
The same judge failure inside a published leaderboard number
The released file gives claude-instant-v1 a mean of 7.906 over its 159 valid grades, which is what FastChat's {{show_result.py|https://github.com/lm-sys/FastChat/blob/main/fastchat/llm_judge/show_result.py}} computes today (it drops grades of −1). The {{LMSYS leaderboard table|https://huggingface.co/spaces/lmsys/chatbot-arena-leaderboard/blob/main/leaderboard_table_20250804.csv}} prints 7.85 for Claude-Instant-1 (and 7.90 for Claude-1, which matches). Averaging the failed grade in as a score of −1 over all 160 turns gives exactly 7.850. So the published figure most likely counts a judge failure as the model's worst-ever answer and understates the model by about 0.06 points; whether the table was built with an older version of the script is not stated anywhere we found. 4. Regression gates in CI

The gate in section 3 combines four kinds of rule, run on every pull request:

  • A paired drop against the champion, per slice. Same items, both configurations, compared per item. Gating 8 or 20 slices at once means some fire by chance on every run: use a stricter level per slice, or gate on the aggregate and the slices that matter and treat the rest as diagnostics ({{Eval statistics|n:3ef5c17b0d0d8187a7b4e5b4ec4a546d}} has the arithmetic).
  • Hard floors on safety slices, where no trade is allowed: Vercel keeps refusal and safety evals at "a 100% pass rate" while other evals may move.
  • Deterministic assertions: the format parses, the tool call is valid, no forbidden string, the right citation. Cheap and exact, and the first of Hamel Husain's three levels (assertion tests on every code change, human and model evaluation on a cadence, A/B tests after significant product changes).
  • Budget limits computed from the same runs (section 6).

A gate result has three outcomes, not two: pass, fail, and "cannot tell", which escalates to more samples or a human. "Re-run until green" turns a gate into a random number generator with a bias toward shipping.

Flaky evals

A gate that fails on an unchanged configuration trains everyone to ignore it. Three sources are well documented:

  • Temperature 0 is not deterministic on a shared server. Thinking Machines sampled one prompt 1,000 times at temperature 0 and got "80 unique completions", the first divergence at token 103, because server load changes the batch size and the kernels are not batch-invariant ({{Defeating Nondeterminism in LLM Inference|https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/}}, 10 Sep 2025). Through a provider API you cannot fix this, only measure it: score each item K times and gate on the mean. OpenAI's seed is "best effort" ({{API reference|https://developers.openai.com/api/reference/resources/chat}}); Anthropic: "Even with temperature set to 0, the results will not be fully deterministic", and "Models released after Claude Opus 4.6 do not support setting temperature" ({{Messages API|https://platform.claude.com/docs/en/api/messages}}).
  • The judge is a model too. 4 of 5,440 GPT-4 judge calls in the MT-Bench file never emitted a grade. Parse failures need an explicit rule, and a judge model or prompt change is a new instrument that needs re-baselining (the root page's {{Calibration section|n:3c65c17b0d0d8181b351e1b8fc6a1546#rd-cal}} and {{LLM-as-judge|n:3c65c17b0d0d810ba2a2ecc08c4c233b}}).
  • Agents fail some trials and pass others. Report pass^k (every one of k trials succeeds) beside pass@k: Anthropic's example is a 75% per-trial success rate becoming (0.75)^3, about 42%, over three trials ({{Agent and trajectory evaluation|n:3ef5c17b0d0d81fdbabaf3582bff37f2}} owns this).

Practice: pin every version, cache champion outputs, re-score K times where decoding is nondeterministic, quarantine items that flip on an unchanged configuration and fix or remove them, and log every gate run with its configuration so a failure can be replayed.

Measured cost of making inference deterministic, and the deprecations
With batch-invariant kernels all 1,000 of Thinking Machines' completions were identical, at a cost of 26 s rising to 55 s for the run (42 s with an improved attention kernel). OpenAI's API reference adds "Determinism is not guaranteed" to the seed parameter. Anthropic's temperature parameter is now deprecated, so a gate that relied on temperature 0 for repeatability has to move to K samples.
